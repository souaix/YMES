# ES408 設備配件歷史資料查詢

## 範圍與來源

本功能以設備及設備配件為條件，唯讀查詢配件裝機／下機歷程。公司端完成 Vue DEV 假資料查詢頁；家用端已依同版來源 DDL 建立空白復刻表、完成唯讀 API 與正式資料頁串接。DEV 預覽仍只用虛構資料。

- 選單清冊：`EMS / ACC EXECUTION / EQP ACC STATE LOG QUERY`，FunctionNo `EQP ACC STATE LOG QUERY`、FunctionKey `ES408`。
- Form：`D:\iMES\CSiMES\STD\MESWin\EMS\ES_EquipmentAccStateLog\frmEquipmentAccStateLog.vb`。Designer 程式碼內嵌在同檔。
- 呼叫端：標準 `frmAccessoryStateMonitor` 與 `frmAccessoryStateMonitorByEQP` 可透過 ObjectFileHandler 開啟此 Form，並傳入目前的 AccessoryNo；Form 因此會在 Load 時先查詢該配件，再載入 lookup。從 EMS 選單直接開啟時沒有預設條件，也不自動查詢。
- Service：`wsEMS.LoadEquipmentAccStateLog`；選擇器另預載 `wsEQP.LoadAccessoryType/LoadAccessoryBasis/LoadEquipmentType/LoadEquipmentBasis`、`wsUSR.LoadUserSecurity`。
- Core：`kcEMS.clsAccState.LoadEquipmentAccStateLog`，直接查 `TBLEMSEQPACCSTATELOG`。

## WinForms 行為與欄位

查詢條件為 Equipment Type、Equipment No、User No、Accessory Type、Accessory No，以及 Start Time From/To、End Time From/To。五個文字欄各有啟用核取方塊和 lookup；輸入文字會自動勾選條件，取消勾選會清空文字；離開文字欄時轉大寫。日期時間的四個界限各有獨立核取方塊，初始皆未勾選。直接開啟畫面不會自動 Query；從配件監控帶入 AccessoryNo 時，Load 事件先執行查詢。

Lookup 使用 Form 預載的類別、設備、使用者及配件 lookup DataSet，再由共用 `frmCOMSearch` 選取。使用者 lookup 移除 Password／ResetPassword 欄位。配件類別由 `IssueState=2` 查詢。Form 在配件基本資料請求加入 `IssueState=2` 及 `CurVersion=defInteger`，但目前 `wsEQP.LoadAccessoryBasis` 對 CurVersion 的解析程式已註解，Core 亦沒有 CurVersion 參數，實際只依 IssueState 篩選，不會限制單一版本。DEV picker 以假資料清單替代共用 WinForms 選擇器。

Service 將有值條件解析後傳給 Core。Core 以 AND 組合精確相等條件；StartTimeFrom/End 與 EndTimeFrom/End 都是含邊界比較。起訖均可各自空白；未指定任何條件時，Core 仍會查整張 Log 表。Form 將結果以 StartTime、EquipmentType、EquipmentNo、AccessoryType、AccessoryNo 排序。

Grid 實際顯示七欄：EquipmentType、EquipmentNo、AccessoryType、AccessoryNo、StartTime、EndTime、UserNo；`AccSerialNo` 與 `AccessoryVersion` 保留在 DataSet，但隱藏。查無資料時 Legacy Form 會走 `ExceptionManager` 訊息分支，不會將空結果當正常空清單顯示；家用端 API/UI 應回傳空清單。

### Legacy 條件組合缺陷

`funQuery` 先累加 EquipmentType、EquipmentNo、UserNo，再以單一 `=` 指派 AccessoryType 參數，會覆蓋此前已組好的條件。因此同時勾選 Accessory Type 與前述任一條件時，Service 實際收不到前述條件。DEV 以預期的 AND 語意執行五個文字條件，並在本規格留下此修正差異；家用端應逐欄位測試，不能照搬 XML 拼接缺陷。原始 Service/Core 沒有強制日期區間或結果上限。

## DEV 頁

路由：`/YMES/EMS/EquipmentAccStateLogQuery`；在「配件_執行」選單顯示「設備配件歷史資料查詢」。頁面含五個文字條件、各欄 DEV lookup picker、四個獨立時間界限、Query、七欄結果 Grid、查詢筆數與 Close。首次由選單進入保持空白、等待 Query；符合／不符合條件的假歷程由固定 fixtures 篩選，未指定條件時查詢全部 fixtures。網址帶入 `?AccessoryNo=` 時會預填並立即查詢，對應原 Form 由配件監控帶入 AccessoryNo 的開窗情境。日期以完整本地時間字串含邊界比較。

所有設備、配件、序號、版本、人員與時間均為虛構，只存在頁面記憶體。DEV 按正確 AND 規則套用條件，並把空結果顯示為正常空狀態；Lookup modal、響應式表格及結果提示取代 WinForms 共用選擇器、UltraGrid 與訊息框。

## Oracle DDL 與 PostgreSQL schema

直接查詢表 `MESTEST.TBLEMSEQPACCSTATELOG` 的 Oracle 原始 DDL／資料字典及 PostgreSQL CREATE-only references 位於 `database/reference/mestest_accessory_basis_source_ddl.sql`、`database/reference/mestest_accessory_basis_create.sql`。主鍵為 `ACCSERIALNO`；表含設備類別／編號、配件類別／編號／版本、UserNo、StartTime、EndTime。

家用端以 PPK SSH 唯讀檢查遠端 `YMES` schema，確認目標表在所有 schema 均不存在；依來源欄位建立 migration `database/migrations/0066_ems_equipment_accessory_state_log.sql`，並建立 Start／End 時間查詢索引，只授予 `ymes_app` 此歷程表的 SELECT。migration 已在遠端成功執行；欄位、NULL 規則及權限已從 PostgreSQL catalog 複核。未匯入或修改業務資料；新表目前為空。

## 家用端 API handoff

- 唯讀 endpoint：`GET /api/ems/equipment-accessory-state-logs`，需登入；設備類別／編號、UserNo、配件類別／編號及四個時間界限均用參數化條件精確比對。空白文字條件視為未指定，文字正規化為大寫，沒有暴露 `AccSerialNo` 任意查詢欄位。
- 至少提供一個 Start／End 時間界限；完整 From／To 區間最多 366 天，From 不得晚於 To。來源 Oracle `DATE` 對應 PostgreSQL `timestamp without time zone`，API 將 `datetime-local` 當作本地時間值，比較含起訖端點。
- 使用穩定排序 `StartTime, EquipmentType, EquipmentNo, AccessoryType, AccessoryNo, AccSerialNo` 與 `page`／`pageSize` offset 分頁；每頁最多 100 筆，空結果以成功回應及空 `items` 陣列呈現。
- 正式 UI 改為文字條件輸入，避免依賴尚未提供的 lookup API；只呈現 WinForms 原本顯示的七欄，不傳回 Password／ResetPassword 或序號欄。
- API 使用 `[Authorize]` 與既有登入 cookie。依先前「角色／權限先不處理」的開發決策，目前未加 FunctionNo 細項授權；待共用功能權限架構建置時再接入 `EQP ACC STATE LOG QUERY` ACL。
