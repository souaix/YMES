# ES402 設備狀態記錄查詢（EQUIPMENT STATE LOG）

## 選單與來源

- 選單識別：Module `EMS`、FunctionNo `EQUIPMENT STATE LOG`、FunctionKey `ES402`、Form `frmEquipmentStateLog`、執行檔 `ES_EquipmentStateLog.dll`，分類為配件_執行。
- 公司端 DEV 路徑：`/YMES/EMS/EquipmentStateLog`。正式站仍由共用 wrapper 顯示未開放提示。
- THEIL Form：`D:\TP-iMes\iMES_THEIL_TP\STD\MESWin\EMS\ES_EquipmentStateLog\frmEquipmentStateLog.vb`。Form／Designer 在同一 VB 檔；Gantt 子窗為 `frmEQPStateLog_GanttChart.vb`。
- Service：`STD\MESws_STD\wsSTD\wsEMS\wsEMS.cs` 的 `LoadEquipmentStateLog`，將 XML 篩選條件傳給 Core `LoadEquipmentStateLogJoinStateBasis`。
- Core：`STD\MESkc\kcEMS\clsEMSEquipment.cs`。附加查詢主機台狀態歷程、狀態名稱、同設備使用關聯及生產批次／站點資訊。

## 查詢與畫面行為

- Form 載入設備類別、設備主檔、狀態基礎及使用者 lookup；設備類別、設備編號、使用者各有勾選條件及 `frmCOMSearch` 單筆選取。文字欄非空時會自動勾選；取消勾選會清空文字。
- 狀態以狀態名稱下拉選取、隱藏狀態碼送 Service；取消狀態條件會清掉選項。開始時間與結束時間各自有可勾選的 From／End datetime 條件，Core 使用 `>=`／`<=` 包含邊界。
- Form 初始日期控制全部勾選。一般進入時，StartTime From／End 都落在七天前同一日的 00:00:00／23:59:59；EndTime From／End 落在今日 00:00:00／23:59:59。若由設備狀態監控傳入 `strEquipmentNo`，設備條件預選並立即查詢，四個日期邊界改為今日全日。
- 查詢後 DataView 設 `EquipmentType, EquipmentNo, EQPSerialNo` 排序；Grid 又把 EquipmentType 標為 Descending，DEV 依明確的 DataView 排序複製，這個方向標記是否覆寫 DataView 順序需再於原 WinForms 執行環境確認。顯示 EquipmentType、EquipmentNo、StateName、EQPSerialNo、StartTime、EndTime、UserNo、Description；LotNo／OPNo、EquipmentState、LotSerial 回傳但畫面隱藏。Print／Find 按鈕在來源中隱藏；Gantt Chart 僅於有查詢結果時開啟。
- Gantt 子窗以 EquipmentNo 為 task、StartTime／EndTime 為區段、StateName 為 owner、EquipmentState 為識別碼，讀 `TBLEQPSTATEBASIS.StateColor` 上色並顯示起訖 tooltip。
- DEV 路徑用固定虛構資料，提供同一組條件、單筆 lookup、逐一日期邊界勾選、結果表及 Gantt 視圖；`strEquipmentNo` 可由 URL query string 傳入並自動查詢。資料只存在頁面記憶體，不呼叫 Service／API、寫資料或連 Oracle／PostgreSQL。狀態代碼、名稱、顏色及設備／人員都是示意值。

## SQL、資料表與家用端 handoff

- Core 主要資料表：`TBLEMSEQUIPMENTSTATELOG` inner join `TBLEQPSTATEBASIS`，並 left join `TBLWIPCONT_EQUIPMENT`、`TBLWIPLOTLOG` 取得狀態名稱與 LotNo／OPNo。設備類別、設備及使用者 lookup 分別呼叫共用 EQP／USR Service。
- Oracle／CREATE-only refs 重用 `mestest_wip_wp305_source_ddl.sql`／`mestest_wip_wp305_create.sql` 的狀態記錄與設備使用關聯、`mestest_equipment_state_create.sql` 的狀態基礎，以及 `mestest_qc409_wip_disposition_dependencies_source_ddl.sql` 的批次記錄。該 Oracle source 已存在，但以前沒有單獨的 PG CREATE-only，故補上 `database/reference/mestest_wip_lot_log_create.sql`。它只供家用端比較，不能當 migration 執行；同一表可能已由 YMES live schema 管理。
- 公司端受保護 Oracle profile 本次不可用；沿用 repo 已取得的唯讀 source DDL，沒有重連 Oracle、讀業務列或操作 YMES PostgreSQL。
- Oracle Core SQL 以 EquipmentNo／StartTime／EndTime 對應 `TBLWIPCONT_EQUIPMENT`；非 Oracle 分支漏掉 `EndTime` join 條件，兩端結果可能重複或錯配。Core 以字串串接查詢條件，且無分頁／最大日期區間；Service 未將 Form `ExeGroupControlPriv` 轉成 server-side authorization。正式 API 必須使用登入與 ES402 權限保護、參數化篩選、結果上限及穩定排序，並按 Oracle 的三欄關聯條件連結設備使用歷程，查詢範圍須受限。
- 建議唯讀 `GET /api/ems/equipment-state-logs`，支援 equipmentType、equipmentNo、userNo、equipmentState、startTimeFrom／To、endTimeFrom／To，套用授權範圍與分頁。Gantt 使用同一查詢回傳欄位即可；不要新增寫入 API 或專用表。
