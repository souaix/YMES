## WinForms 查詢行為

- 設備狀態為必選條件。Equipment Type、Equipment No、User No 為選填，各有 checkbox、文字輸入及 lookup；輸入非空會自動勾選，取消勾選會清空欄位。設備編號與人員離開欄位時轉大寫。
- 啟動時 StartTime From／To 預設為七天前同一日的 00:00:00／23:59:59；EndTime From／To 也初始化為今日完整日界，四個 checkbox 程式值初始皆勾選。Designer 將 `rdoEnd`、EndTime 標籤與兩個 EndTime 日期欄位設為隱藏，沒有可見控制項切換模式；一般畫面只送出 Status Start Time 條件。可見 From 與 To 各自勾選，範圍含端點。Form 程式碼仍有 `rdoEnd=True` 時送出 EndTime 的分支，但使用者無法透過此畫面開啟。
- `Query` 開啟 `frmEquipmentStateLogByStateData`；資料表欄位是 EquipmentState、StartTime、TotalTime，子窗另外複製 TotalTime 到翻譯用 `TotalTime_hr` 欄位。子窗 Print、Find 按鈕在 Designer 中隱藏。
- 可見的 `Trend Chart` 開啟 `frmEquipmentStateLogTrendChartLabel`，以 StartTime 日期為 X 軸、TotalTime 小時為 Y 軸，顯示長條數值。名稱為 `btnTrendChart_Unused` 的舊圖表入口在 Designer 中隱藏，因此 DEV 不提供該入口。
- DEV 頁使用固定虛構狀態歷程，可選狀態、模擬類別／設備／人員 lookup、可見的 StartTime 篩選、每日結果表及帶數值標籤的長條圖。圖表與表格在同頁切換，取代 WinForms 子窗；假資料及互動只留在頁面記憶體，不呼叫 API、Service、Oracle 或 YMES PostgreSQL。

## Service／Core 計算

- Service 要求 `EquipmentState`，解析可選 `EquipmentNo`、`EquipmentType`、`UserNo`、`StartTimeFrom`／`StartTimeEnd`、`EndTimeFrom`／`EndTimeEnd`，再呼叫 Core。一般 Form 畫面僅會傳 StartTime 條件；EndTime 參數只存在隱藏的程式分支。
- Core 直接查 `TBLEMSEQUIPMENTSTATELOG`，按選定 EquipmentState 篩選，套用可選設備／人員及含端點的開始或結束時間條件，原始歷程依 StartTime 排序。
- Oracle 分支以 `Round((EndTime - StartTime) * 24, 2)` 算每筆時數；非 Oracle 分支先取整數分鐘再換算小時，精度可能不同。Core 略過每筆 TotalTime 等於零的紀錄，依 StartTime 的日曆日合併累計，回傳 EquipmentState、StartTime（日）、TotalTime（小時）。歷史 SQL 使用字串串接，正式端需改參數化並統一時數及捨入規則。
- 原功能無日期跨度上限、全歷史掃描限制、分頁與顯示筆數上限。DEV 不新增來源未證實的結果限制；正式 API 應依登入者設備權限驗證，限制日期跨度與最大結果，並避免無條件全表掃描。

- 本次依本機 THEIL Source 及 repo 既有 DDL references 核對，沒有使用 Oracle profile 或讀取業務資料；未連 YMES PostgreSQL。
- 家用端先比對上述表的 live schema／現有 migration，再實作登入及設備可見範圍保護的唯讀 `GET /api/ems/equipment-state-log-by-state`。建議必填 `equipmentState`，支援 `equipmentType`、`equipmentNo`、`userNo`、`timeField`（`start`／`end`）、`from`、`to`；參數化所有條件，驗證起訖順序並限制日期跨度／結果數。回傳每日 `equipmentState`、`startTime`、`totalTimeHours`。不要直接照搬 Core 字串 SQL；採單一明確的小時計算與捨入契約。
