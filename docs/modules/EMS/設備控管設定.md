# ES101 設備控管設定

## 範圍與來源

本頁按設備類別維護哪些設備納入 EMS 的設備狀態控管。公司端完成 Vue DEV 假資料互動與家用端 API handoff，不直接連 Oracle 或 YMES PostgreSQL。

- 選單清冊：`EMS / EMS CONFIG / EMS CONTROL`，FunctionNo `EMS CONTROL`、FunctionKey `ES101`。
- Form：`D:\iMES\CSiMES\STD\MESWin\EMS\ES_EquipmentControl\frmEquipmentControl.vb`。設計器程式碼內嵌於同檔；來源樹沒有獨立 Designer 檔或同名 Customer Form。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsEMS\wsEMS.cs` 的 `LoadEquipmentStateDefine`、`UpdEquipmentState`。
- Core：`kcEQP.clsEQPBasis.ShowEquipmentType`、`kcEQP.clsEQPStateControl.GetStateControlType`、`kcEMS.clsEMSEquipment.LoadEquipmentNoneControl`、`ShowEquipmentState`、`AddEquipmentState`、`DelEquipmentState`。

## WinForms 行為

Form Load 建立新增／刪除暫存表，再呼叫 `LoadEquipmentStateDefine`。Service 依序回傳 `IssueState=2` 的設備類別、沒有 `TBLEMSEQUIPMENTSTATE` 現況列且 `IssueState=2` 的設備主檔，以及目前設備狀態。畫面依所選 EquipmentType 與 `ChamberFlag=0` 顯示兩個已排序、多選的清單：「Unselect Equipments」與「Selected Equipments」，以左右箭頭搬移選取設備。

搬移設備會先記入 `dtAdd`／`dtDel`，尚未寫回。加入父設備時，Form 也將同一父設備下的 Chamber 列加入新增暫存；移除已管制父設備時，將目前受控 Chamber 列加入刪除暫存。Apply 將差異送出後清空暫存、重新載入並保持視窗開啟；Confirm 送出同一差異後關閉；Close 直接關閉，因此捨棄未 Apply 的異動。

Service `UpdEquipmentState` 先逐筆呼叫 `DelEquipmentState`，再以 `GetStateControlType("Idle")` 取得預設 Idle 狀態並逐筆呼叫 `AddEquipmentState`。新增資料的 UserNo 來自請求身分、StartTime 使用 Core 預設的目前時間、Description 使用空白預設。缺少 Idle 設定時整次 Service 回報失敗。

Core 新增時以 `InitEQPSerialNo()` 產生 EQPSerialNo 並插入 `TBLEMSEQUIPMENTSTATE`。刪除時讀取目前設備狀態，將原列及目前時間作為 EndTime 寫入 `TBLEMSEQUIPMENTSTATELOG`，再刪除現況列。Legacy Service 對批次逐筆呼叫 Core；未見涵蓋整批刪除／新增的明確交易邊界。`GetStateControlType` 查無 Idle 時回傳空 DataRow，Service 以 `DBNull` 判斷結果的檢查與 Core 回傳型別不相符，家用端應以明確查無設定結果處理。

## DEV 頁

路由：`/YMES/EMS/EquipmentControl`，選單顯示「設備控管設定」。DEV 假資料頁包含 Equipment Type 下拉、未管制／已管制設備清單、多選及左右搬移、待新增／移除數量、Apply、Confirm、Close。父設備搬移時自動帶入 Chamber，Apply 只更新頁面內的假資料並保持開啟；Confirm 假套用後關閉；Close 捨棄尚未套用項目。設備編號、類別、控管狀態與 Chamber 關係均為虛構，只存在頁面記憶體；沒有 API／Service 呼叫。

此 UI 以核取列實作多選、以文字狀態取代原生 Form 的等待游標與訊息框；這是瀏覽器操作的呈現簡化，不更改來源所示的批次搬移規則。DEV 套用後的假資料只在目前頁面 instance 存續，關閉重進會回到固定 fixtures。

## Oracle DDL 與 PostgreSQL 交接

來源使用的表已有 repository DDL／CREATE-only references，無新增表：

| Oracle 表 | 用途 | 既有參考 |
|---|---|---|
| `TBLEQPEQUIPMENTTYPE` | IssueState=2 設備類別清單 | `database/reference/mestest_equipment_type_*` |
| `TBLEQPEQUIPMENTBASIS` | IssueState、EquipmentType、ChamberFlag、BelongEquipmentNo | `database/reference/mestest_equipment_basis_*` |
| `TBLEQPSTATECONTROL` | Idle 對應 EquipmentState | `database/reference/mestest_equipment_state_references_*` |
| `TBLEMSEQUIPMENTSTATE` | 目前受控設備與狀態 | `database/reference/mestest_equipment_state_references_*` |
| `TBLEMSEQUIPMENTSTATELOG` | 移出控管時封存舊狀態 | `database/reference/mestest_wip_wp305_*` |

本項重用已提交的 DDL/metadata references；沒有新增 Oracle 連線或業務資料查詢，也沒有提出新的 CREATE SQL。若正式 YMES live schema 與 references 不一致，家用端先依既有部署流程核對差異。

## 家用端 API／schema 要點

- 先核對上述現有表及約束，不重複建表；新增設備控管批次 API，要求登入與 FunctionNo `EMS CONTROL` 權限。
- 伺服器端依 IssueState=2／設備類別重新驗證 EquipmentNo；請求只能指定父設備（ChamberFlag=0），父設備所屬 Chamber 由伺服器查詢及展開，不接受 client 自行決定子設備或狀態代碼。
- 移除父設備時，鎖定／重讀父設備與受控 Chamber 的現況列，將舊列寫入狀態歷程後刪除；新增時從 `TBLEQPSTATECONTROL` 讀取唯一 Idle 設定並建立新序號。全部新增與移除、現況與歷程必須置於同一交易，任一筆錯誤即回滾。
- 以 expected current-state／版本比對避免更新期間遭其他操作者改變；回傳逐設備成功或整批明確失敗，並記錄目前使用者與稽核事件。
- Apply 與 Confirm 共用同一批次 command；兩者只在前端視窗是否關閉上不同。家用端自行判斷現有 API DTO、錯誤碼與 migration 需求；公司端未實作或驗收正式 API/schema。
