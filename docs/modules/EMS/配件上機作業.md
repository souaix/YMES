- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsEMS\wsEMS.cs` 的 `LoadAvailAccStatebyEquipmentType`、`LoadEQPACCState`、`UpdEQPACC`、`ReturnEQPACC`；設備 lookup 使用 `wsEQP.LoadEquipmentType`／`LoadEquipmentBasis`。

## WinForms 畫面與互動

- 上方欄位為 Equipment Type、Equipment No、Accessory No、`Available Only`、Confirm、Close。Equipment Type／No 用 `...` 查找；No 可按 Enter 查設備並帶出類別。Accessory No 可輸入／掃描後 Find，選到的配件會被勾選。`Available Only` 初始勾選，切換時在已有設備類別及編號時重新載入候選配件。
- 設備類別查找先讀 `LoadSystemFunction`，依 SEMI_WAFER 等 active module 決定顯示 EquipmentClass／EQPClassIndustry 欄；EquipmentNo 查找限 `ChamberFlag=0`，類別已指定時再依 EquipmentType 篩選。EquipmentType 空白時用設備清單查找，但仍由 Confirm 要求類別與設備編號都已填。
- 配件 Grid 的可見欄為 Check、AccessoryNo、AccessoryType、AccessoryCategory、ResidualLife、StateName。服務查找會以所選 EquipmentType 限定相容 AccessoryType，只列 `IssueState=2` 且目前狀態不是 `APPLY` 設定值的配件。ResidualLife 在 `LifeManage=1` 時計算 `RepairCycle - AccumulateQty`，否則顯示 `N/A`；StateName 來自狀態基礎表。勾選 Available Only 時，Core 另排除 `TBLEMSACCVIOLATESTATUSCHANGE` 中不允許轉到 APPLY 的目前狀態；取消則可查看所有相容且非 APPLY 的核准版本。
- Confirm 必須同時有 EquipmentType、EquipmentNo 及至少一筆配件。Form 先載入全部目前 `TBLEMSEQPACCSTATE` 關聯，逐筆檢查選取配件是否已屬於其他設備。若已關聯，詢問是否先下機；拒絕時略過該配件、繼續處理其他列，接受時先呼叫 `ReturnEQPACC`，再將剩餘清單一次送給 `UpdEQPACC`。
- `UpdEQPACC` 的每列 payload 含 EquipmentNo、EquipmentType、AccessoryCategory、AccessoryType、AccessoryNo、AccessoryVersion。Service 使用登入者與操作時間，Core 依 `(ControlType='EMS', ControlNo='APPLY')` 取得目標狀態，確認目前狀態可轉換後，建立設備配件關聯、寫入配件狀態舊值歷程、更新配件狀態及新 ACCSerialNo。配件壽命 helper 會回傳提醒文字；成功後 Form 顯示提醒、停用 Confirm 並關閉。
- Form 在先下機時呼叫 `funReturnEQPACC(drTmp)`，但 helper 實際讀取外層迴圈 `drSel(i)`，且送入的 EquipmentNo 是目標 `txtEquipmentNo`；已查到的原設備 `strEuipmentNo` 未使用。若配件關聯在其他設備且該設備有在製 Lot，這可能讓舊設備的 `TBLWIPCONT_ACCESSORY.EndTime` 未被回壓。先下機呼叫失敗後 Form 仍會將配件放進後續 Apply payload。**DEV 不複製這兩個缺陷：以假資料中的原關聯設備執行預先下機，並在下機被阻擋／取消時略過該配件。**

## Vue DEV 頁

- fallback 路由 `/YMES/EMS/ApplyEquipmentAccessory`，位於「設備管理 / 配件_執行」。DEV 頁包含假設備類別／設備選擇器、掃描編號 Find、預設啟用的 Available Only、多選候選 Grid、批次 Confirm、既有設備關聯的逐件先下機／略過提示、狀態互斥阻擋、壽命提醒及頁面內操作紀錄。
- 假資料含可上機、有限壽命、有互斥限制、未核准版本、不同設備類別相容及已存在設備關聯等情境。成功上機會更新頁面內假掛載與狀態；預先下機會先記錄假下機，再嘗試批次上機。批次互斥失敗時會保留已執行的預先下機並顯示部分流程結果。
- DEV 與來源略有簡化：保留成功訊息與模擬歷程供檢閱；實際 WinForms 成功後會關閉視窗。假 user／設備／狀態／壽命／相容關係只在目前頁面記憶體，未呼叫 Service/API、未讀 Oracle 或 YMES PostgreSQL、未寫正式資料。

## 資料表與 Oracle metadata

- `TBLEMSEQPACCSTATE`、`TBLEMSEQPACCSTATELOG`、`TBLEQPACCSTATECONTROL`、`TBLEMSACCESSORYSTATE`、`TBLEMSACCESSORYSTATELOG`、配件基礎／分類／類型／壽命與設備類型相容性表，均可沿用 repo 既有 Oracle source DDL／PostgreSQL CREATE-only references，主要集中於 `mestest_accessory_basis_*`、`mestest_accessory_state_*`、`mestest_accessory_type_dependencies_*` 與 `mestest_equipment_type_accessory_catalog_*`。本功能不新增或改寫這些 CREATE-only。
- Core 還讀取 `TBLEMSACCVIOLATESTATUSCHANGE`；預先下機可能讀寫 `TBLWIPCONT_ACCESSORY`，並檢查 `TBLWIPTEMP_EQUIPMENT`。Repo 缺前兩張表的同版 Oracle source DDL／metadata 及 PostgreSQL CREATE-only；`TBLWIPTEMP_EQUIPMENT` 沿用 WP201/WP302 references。桌機受保護 Oracle profile 不存在，本次沒有可用的 MESTEST profile，未執行查詢；不猜互斥或在製配件使用表欄位，不新增 CREATE SQL。家用端先比對 live schema／migration，缺表時取得可靠 metadata 後再補。
- `UpdEQPACCState` 把 mapping Insert、AccessoryStateLog Insert 及狀態 Update 收集後呼叫 `ExecuteSQLNoneQuery_UPD`；該 helper 實作不在可讀來源中，無法確認完整批次的交易／回滾保證。預先下機則在 Apply 批次之前先獨立呼叫 ES302，兩階段不是單一原子操作。Core SQL 字串串接，不可直接照搬。
- Oracle `TBLEMSEQPACCSTATE` 的 PK `ACCESSORYNO` 等 table/index 結構沿用已提交的 `database/reference/mestest_accessory_basis_source_ddl.sql` 與 PostgreSQL CREATE-only；沒有因本項新建 schema，也沒有查業務資料。

## 家用端正式 API／schema handoff

- Pull 最新 main，核對已知的掛載／配件狀態 references 與 live schema／migration；另外查 `TBLEMSACCVIOLATESTATUSCHANGE`、`TBLWIPCONT_ACCESSORY` 是否存在及其 Oracle 來源。欄位與索引未核實前不建表。若缺表，先補可靠 Oracle source DDL，再建 forward migration。
- 建議登入保護的相容配件 lookup 及 `POST /api/ems/equipment-accessory-applications`。伺服器由目標 EquipmentNo 重查 EquipmentType、ChamberFlag、配件 Compatibility、IssueState=2、Version、目前狀態、APPLY 控制值、互斥 pair、使用者狀態權限、已有掛載關聯與設備可見範圍，不信任瀏覽器送來的類別／版本／狀態。回傳候選資料要限量／分頁並使用參數化條件。
- Apply 交易需保護設備掛載唯一性及配件目前狀態／版本，以 expected state／row version 防止併發；原子新增 `TBLEMSEQPACCSTATE`、封存 `TBLEMSACCESSORYSTATELOG`、更新 `TBLEMSACCESSORYSTATE` 並配置安全 ACCSerialNo。依 life 設定回傳提醒，但不能讓提醒 helper 在正式寫入失敗前另行提交部分變更。
- 若允許從另一設備直接移轉，需先決定伺服器端如何原子處理舊設備掛載／掛載歷程、WIP accessory 使用 EndTime、配件狀態與新設備掛載。若沿用 ES302 再 ES301 的兩次操作，API 應明確回報已完成的下機列及尚未上機列，並提供安全重試／補償；不可把兩階段假稱為原子交易。
- 修正來源缺陷：下機要由 server 反查配件實際掛載設備，更新其 `TBLWIPCONT_ACCESSORY` 使用記錄；失敗時不可繼續將同一配件送入 Apply。多選要明確採原子批次或回傳逐筆結果。所有寫入參數化，拒絕客戶端指定的任意 `AdditionalXml`／SQL 條件；公司端不實作或驗收正式 API/schema。
