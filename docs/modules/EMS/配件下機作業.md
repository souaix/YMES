# ES302 配件下機（RETURN EQP ACCESSORY）

## 選單與來源

- 選單識別：Module `EMS`、FunctionNo `RETURN EQP ACCESSORY`、FunctionKey `ES302`、Form `frmReturnEQPAccessory`、執行檔 `ES_ReturnEQPAccessory.dll`，分類為配件_執行。
- 公司端 DEV 路徑：`/YMES/EMS/ReturnEquipmentAccessory`。正式環境使用共用 wrapper 顯示未開放提示。
- WinForms Form／內嵌 Designer：`D:\TP-iMes\iMES_THEIL_TP\STD\MESWin\EMS\ES_ReturnEQPAccessory\frmReturnEQPAccessory.vb`。THEIL、DEV_SILVA、CSiMES 三份 Form SHA-256 相同。
- Service：`STD\MESws_STD\wsSTD\wsEMS\wsEMS.cs` 的 `LoadDistinctEQPACCStateACCType`、`LoadEQPACCState`、`ReturnEQPACC`。
- Core：`STD\MESkc\kcEMS\clsEMSEquipment.cs` 的 `LoadDistinctEQPACCStateACCType`、`LoadEQPACCState`、`UpdEQPACCState_Return`；共用狀態權限與壽命提示在 `clsAccState.CheckACCPrivileged`、`ChkAccessoryLifeAlert`、`InitACCSerialNo`。
- 兩個配件監控 Form 均由 `funShowInterface` 反射設定 ES302 的 `AccessoryNo` 公用欄位及 `AccessoryState`，未傳設備類別、設備編號、配件版本；ES302 只使用 `AccessoryNo`。

## WinForms 畫面與流程

- 視窗為 `Return Equipment Accessory`，ClientSize 441×200。畫面有 Accessory Type、Accessory No、Creator、Create Date、Confirm、Close。Accessory Type／No 只能透過 `...` 查找；Creator 與 Create Date 唯讀。
- `LoadDistinctEQPACCStateACCType` 從目前 `TBLEMSEQPACCSTATE` 取不同配件類別；`LoadEQPACCState` 取 `EquipmentType IS NOT NULL` 的目前掛載配件。先選類別時配件查找按該類別過濾；查找清單欄位為 AccessoryNo、AccessoryType、EquipmentType、EquipmentNo。選取列才把 AccessoryVersion 和設備類別／編號寫到 Form 私有欄位；Version 欄位預設 `01` 並隱藏。
- Form 只檢查配件編號與版本非空，送 `AccessoryNo`、`AccessoryVersion`、登入者、AccessoryType、EquipmentType、EquipmentNo 到 `ReturnEQPACC`。成功時顯示 Core 回傳的壽命提醒並關窗；Form 在關窗之後仍顯示完成訊息並清欄位，該段是否可見取決於執行環境的 Close 行為。
- DEV 使用固定虛構掛載列：配件類別／配件查找、只讀版本、目前設備／使用狀態、在製 Lot、返回限制、壽命提醒與頁面內模擬下機歷程。成功模擬會從目前掛載清單移除配件，並記錄本頁虛構的 return 狀態時間；互斥狀態會阻擋。所有變更只留在頁面記憶體，不呼叫 Service／API、不連 Oracle／PostgreSQL、不寫正式資料。

## Service／Core 交易

- Service 要求 XML 中存在 AccessoryNo、AccessoryVersion、UserNo、AccessoryType、EquipmentType、EquipmentNo 欄位，但除 StartTime 外沒有再驗證值非空。Form 會送出這些欄位，即使監控入口帶入資料不完整。
- Core 從 `TBLEQPACCSTATECONTROL` 取 `(ControlType='EMS', ControlNo='RETURN')` 的目標 AccessoryState；以配件編號／版本從 `TBLEQPACCESSORYBASIS` 取得 AccessoryCategory；讀 `TBLEMSACCVIOLATESTATUSCHANGE` 和 `TBLEMSACCESSORYSTATE` 守門狀態互斥；檢查配件壽命提示及 `CheckACCPrivileged` 後再組交易。
- 下機交易會：
  1. 若傳入的 EquipmentNo 同時出現在此配件的 `TBLEMSEQPACCSTATE` 與 `TBLWIPTEMP_EQUIPMENT`，將匹配的 `TBLWIPCONT_ACCESSORY` 使用紀錄 EndTime 設為現在。
  2. 將目前 `TBLEMSEQPACCSTATE` 寫入 `TBLEMSEQPACCSTATELOG` 後刪除掛載現況。
  3. 將 `TBLEMSACCESSORYSTATE` 舊狀態寫入 `TBLEMSACCESSORYSTATELOG`，再更新 Return 狀態、StartTime、UserNo 與新 ACCSerialNo。
  4. 將上述使用紀錄、掛載歷程、配件狀態歷程與目前狀態變更放入同一 `CollectionSQL` 執行。
- `ChkAccessoryLifeAlert` 在主交易組合之前執行；若 LifeManage 的週期設定尚未起算，它會先獨立更新 `TBLEMSACCESSORYSTATE.TimeCycleStart`。這段可能在後續互斥／權限檢查失敗前已提交，因此正式端需重新定義檢查順序與原子性。壽命提示不阻擋下機；Core 忽略 helper 的 `success`／`fail` 字串，其餘文字作為 `stralert` 回傳。
- `InitACCSerialNo` 在 Oracle 路徑按年月建立／取用 `ACCSTATELOGyyMM` sequence；非 Oracle 路徑更新 `TBLSYSSERIALNO`。非 Oracle 的讀取／更新不是 Core 下機交易的一部分，正式端需以原子序號預約處理併發與唯一性。

## 表與 SQL handoff

- Core 直接使用：`TBLEQPACCSTATECONTROL`、`TBLEQPACCESSORYBASIS`、`TBLEMSACCVIOLATESTATUSCHANGE`、`TBLEMSACCESSORYSTATE`、`TBLEMSACCESSORYSTATELOG`、`TBLEMSEQPACCSTATE`、`TBLEMSEQPACCSTATELOG`、`TBLWIPCONT_ACCESSORY`、`TBLWIPTEMP_EQUIPMENT`。Helper 另使用 `TBLEQPACCESSORYLIFE`、`TBLEQPACCSTATEBASIS`、`TBLSYSPARAMETER`、`TBLUSRUSERGROUP`、`TBLUSRGroupPriv_Class` 及 `TBLSYSSERIALNO`／Oracle 月序列。
- 配件主檔、配件狀態／狀態歷程、設備掛載／掛載歷程、下機控制表的 MESTEST source DDL 與 PG CREATE-only 已在 `mestest_accessory_basis_source_ddl.sql`／`mestest_accessory_basis_create.sql`；`TBLEQPACCESSORYLIFE`、`TBLEQPACCSTATEBASIS`、`TBLWIPTEMP_EQUIPMENT`、系統與使用者權限表沿用 repo 既有 references。
- Repo 未找到 `TBLWIPCONT_ACCESSORY` 與 `TBLEMSACCVIOLATESTATUSCHANGE` 的同版 Oracle source DDL 或 PG CREATE-only。桌機受保護 Oracle profile 未備妥，本次只用現有來源程式與已提交 references，沒有連 MESTEST、讀業務資料或猜測建表欄位；因此不新增這兩表的 CREATE-only。家用端先比對 live schema／既有 migration，有核准的同版 DDL 再補參考。
- 本模組沒有新增可執行 SQL 或 migration。公司端不連 YMES PostgreSQL、不實作正式 API／schema。

## 家用端正式 API handoff 與來源缺口

- 建議以登入者權限保護 `POST /api/ems/equipment-accessories/{accessoryNo}/return`，body 至少有 `accessoryVersion`；伺服器從目前掛載資料查出設備／配件類別，不採信用戶端傳入設備欄位。以資料庫交易鎖住配件現況，重新檢查 Return 控制狀態、互斥規則、登入者類別權限和配件版本，再原子更新 Lot 使用紀錄 EndTime、掛載歷程／現況及配件狀態歷程／現況；序號需併發安全。壽命提示應在權限與互斥通過後計算，避免 legacy helper 的先提交副作用。
- 兩個 legacy 監控畫面呼叫 ES302 時只設定 `AccessoryNo`。Form 會隱藏查找鈕並載入目前列，但只回填 AccessoryType，沒有設定 hidden Version（維持 `01`）或 `strEquipmentType`／`strEquipmentNo`。服務仍接受這些空字串，故監控直接下機可能略過在製 Lot 的 `TBLWIPCONT_ACCESSORY.EndTime` 回壓，並可能用錯版本。DEV 以假資料列補齊設備與版本，未把此來源缺陷複製成生產行為；家用端 API 應以伺服器現況反查完整關聯。
- Core 使用字串串接 SQL；不能把 WinForms 的 XML 欄位／任意 Additional 條件直接沿用。下機是多表一致性交易，正式 API 需授權、參數化、版本／現況併發檢查、明確序號服務、稽核與警示回傳。
