# ES104 設備狀態互斥設定（VIOLATIVE STATE SETTING）

## 選單與來源

- 選單識別：Module `EMS`、FunctionNo `VIOLATIVE STATE SETTING`、FunctionKey `ES104`、Form `frmViolateStateChangeSetMatrix`、執行檔 `ES_ViolateStateChangeSetMatrix.dll`，分類為 EMS設定。
- CSiMES、THEIL 與 DEV_SILVA 的 `STD\MESWin\EMS\ES_ViolateStateChangeSetMatrix\frmViolateStateChangeSetMatrix.vb` 內容相同，SHA-256 為 `353ECAB52A8C8EC3AF45FD58DC27ADA725E36D3EB0E8BD1669037EFBEF481726`；Designer 程式碼內嵌在 Form 檔。
- Form 呼叫 `wsEQP.LoadEQPStateBasis` 和 `wsEMS.LoadViolateStateChange` 載入狀態基準及既有禁止轉換組合；Confirm 呼叫 `wsEMS.UpdViolatStateChangeData`。THEIL Service 在 `Customer\Production\MESws_STD\wsSTD\wsEQP\wsEQP.cs`、`...\wsEMS\wsEMS.cs`；Core 在 `STD\MESkc\kcEQP\clsEQPBasis.cs` 與 `STD\MESkc\kcEMS\clsEMSEquipment.cs`。

## 畫面與互動

- 視窗 1008×591，以 UltraGrid 畫完整設備狀態矩陣；欄標籤與列標籤各在左右重複一次。Y 軸是目前狀態，X 軸是禁止轉換到的狀態；列、欄順序由 EquipmentState 升冪排序的 `TBLEQPSTATEBASIS` 決定，標籤顯示代碼與 StateName，底色取 StateColor。
- 載入時取得全部 Equipment State Basis，再載入全部既有 `TBLEMSVIOLATESTATUSCHANGE` 關係；每個 `(EquipmentState, ViolativeState)` 關係在對應矩陣格顯示禁止圖示。雙擊內部格子切換圖示。Confirm 初始停用；第一次編輯後，若 Group 權限允許 Confirm，按鈕啟用。Confirm 儲存完成顯示成功訊息；Close 關閉。
- 原始碼有一個互動疑點：Grid 全域 `AllowUpdate=False`，而 `InitializeRow` 又將內部矩陣格設成 `Activation.Disabled`；同時 `DoubleClickCell` handler 卻處理內部格圖示切換。靜態來源無法確認 Infragistics 在該設定下是否仍會送出雙擊事件；DEV 按 handler 的預期行為允許雙擊切換，家用端需在 WinForms 執行環境確認。
- Confirm 對每個目前狀態逐列組出禁止目標狀態清單，連同 StateName 與同一個 ViolativeSerial 呼叫 `wsEMS.UpdViolatStateChangeData`。Service 先刪除該 EquipmentState 的所有設定，再逐筆新增目前矩陣設定。清空某列代表刪除該列所有互斥設定。
- DEV 頁在 `/YMES/EMS/ViolateStateChangeSetMatrix` 使用五個虛構狀態、彩色列欄、禁止標記、雙擊切換、未儲存格數和 Confirm 假儲存狀態；Confirm 只更新頁面記憶體，不寫資料、不呼叫 API／Service、Oracle 或 YMES PostgreSQL。DEV 簡化 MES 圖片資源、語系、使用者 Group 權限及資料庫交易。

## Service／Core、DDL 與家用端 handoff

- `wsEQP.LoadEQPStateBasis` 由 `clsEQPBasis.LoadEQPStateBasis` 讀取 `TBLEQPSTATEBASIS`；`wsEMS.LoadViolateStateChange` 由 `clsEMSEquipment.LoadViolateStateChange` 讀取 `TBLEMSVIOLATESTATUSCHANGE`。Core 使用字串組接 SQL。
- `wsEMS.UpdViolatStateChangeData` 驗證 EquipmentState／StateName，先呼叫 `DelViolateStateChange(EquipmentState)`，再逐筆呼叫 `AddViolateStateChange`；有關係時同時新增 `TBLEMSVIOLATESTATUSLOG` 記錄並寫系統 EventLog。這些刪除與多次新增跨越多次 Core 呼叫，沒有整列或整張矩陣的明確原子交易；中途失敗可能留下部分新設定。正式 API 應以單一伺服器端交易替換一個來源狀態的完整目標集合，並原子寫入歷程及稽核。
- Repo 有 `TBLEQPSTATEBASIS` 的 Oracle 來源 CREATE-only `database/reference/mestest_equipment_state_create.sql`。全 repo 未找到 `TBLEMSVIOLATESTATUSCHANGE`、`TBLEMSVIOLATESTATUSLOG` 的 Oracle source DDL 或 PostgreSQL CREATE-only。桌機沒有可用受保護 Oracle profile，這次未用 PowerShell 5.1／ODP.NET 查 metadata；不猜新增表結構。家用端開始正式 API/schema 前須取得並唯讀核對這兩張直接寫入表的 DDL、欄位、主鍵／索引和 log 欄位。
- 建議提供登入授權的 `GET /api/ems/equipment-state-transition-restrictions`，回傳完整狀態標籤與禁止轉換 pair；以 `PUT /api/ems/equipment-state-transition-restrictions/{equipmentState}` 原子替換單一目前狀態的完整目標集合。伺服器需驗證目標 state 存在、狀態範圍及 EMS 設定權限，使用參數化 SQL、併發版本或條件更新，寫一致的修改者／時間歷程；不能照搬 legacy 逐筆刪除／新增 SQL，也不要在取得來源 DDL 前猜建表。
