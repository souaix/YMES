# ES103 配件狀態控制設定（ACC STATE CONTROL SETTING）

- 清冊：Module `EMS`、FunctionNo `ACC STATE CONTROL SETTING`、FunctionKey `ES103`、Form `frmEQPACCStateControlSet`、執行檔 `ES_EQPACCStateControlSet.dll`、選單 `EMS設定`。
- DEV 路徑：`/YMES/EMS/AccessoryStateControlSet`。正式頁面尚未開放；DEV 使用頁面內的假資料，不呼叫正式 API／Service。
- Form 與 Designer 均在 `D:\iMES\CSiMES\STD\MESWin\EMS\ES_EQPACCStateControlSet\frmEQPACCStateControlSet.vb`。CSiMES、THEIL、DEV_SILVA 三份 Form 雜湊一致，Designer 為 Form 內嵌設定。
- Service：THEIL `wsEQP.cs` 的 `LoadEQPACCStateBasis`、`LoadACCStateControl`、`UpdACCStateControl`。
- Core：`clsAccBasis.LoadEQPACCStateBasis`、`clsEQPStateControl.LoadACCStateControl`／`DelACCStateControl`／`AddACCStateControl`，以及 `clsAccState.UpdEMSAccessoryState`。

## WinForms 欄位與互動

表單以唯讀狀態代碼、名稱呈現設定；「…」開啟 `frmCOMSearch`，資料來自 `TBLEQPACCSTATEBASIS`。開頁先查詢系統 Active Module `IC_FT_PKG` 與 `TBLEQPACCSTATECONTROL`，再以代碼查狀態名稱。Active Module 大於 0 時才顯示並要求 `I_SetupClose`。

| ControlType | ControlNo | 用途 |
| --- | --- | --- |
| `EMS` | `Initial` | 初始狀態 |
| `EMS` | `Apply` | 領用／上機 |
| `EMS` | `Return` | 退回 |
| `EMS` | `GetFromINV` | 從庫存領出 |
| `EMS` | `Repair` | 維修 |
| `EMS` | `I_SetupClose` | IC 封裝設置結案，僅 Active Module 啟用時出現 |
| `EMS` | `ReturnToINV` | 歸還庫存 |
| `EMS` | `Scrap` | 報廢 |

- 每個顯示中的控制項都必須有狀態代碼與對應名稱。選取狀態後啟用 Apply。
- Apply 與 Confirm 都將所有顯示中的控制項組成一個 `controlset` 多值欄位送至 `wsEQP.UpdACCStateControl`；Apply 成功後留在表單，Confirm 成功後關閉。Close 不送出。
- `IC_FT_PKG` 是動態模組資格，正式端應由伺服器授權資料判斷，不接受瀏覽器自行決定是否可寫 `I_SetupClose`。

## Service／Core 與資料影響

- `LoadACCStateControl` 讀取 `TBLEQPACCSTATECONTROL` 非空控制列；狀態選擇由 `LoadEQPACCStateBasis` 讀取 `TBLEQPACCSTATEBASIS`。
- `UpdACCStateControl` 逐列處理：先呼叫 `clsAccState.UpdEMSAccessoryState`，再刪除並新增該組 `(ControlType, ControlNo)` 設定。Core 不是一筆涵蓋所有設定列的批次交易，逐列失敗可能留下部分結果。
- Form 每次 Apply／Confirm 都送出整組可見設定。`UpdEMSAccessoryState` 會讀取該控制項原設定狀態，將目前處於舊狀態的配件寫入 `TBLEMSACCESSORYSTATELOG`，再更新 `TBLEMSACCESSORYSTATE` 並產生新 `ACCSerialNo`；它沒有先比較舊、新設定值。因此即使某一控制值未變，該控制列仍會重寫符合舊狀態的全部配件、記錄 log 並更新序號。修改控制設定也會連帶遷移使用舊設定狀態的配件，不只是改一個 lookup 值。
- Core 使用字串組 SQL；家用端實作須改用參數化查詢，只對實際變更的 ControlNo 遷移配件，並將控制表更新、配件現況遷移、歷程與序號配置納入明確交易及並發控制。先比對各舊／新狀態所影響筆數，回傳操作摘要，避免設定人員忽略大量配件同步變更；未變更設定不得重寫現況、重建 log 或換發序號。
- Oracle 原始 DDL／metadata 已在 repo 既有參照中：`database/reference/mestest_accessory_basis_source_ddl.sql`（`TBLEQPACCSTATECONTROL`）與 `database/reference/mestest_accessory_state_source_ddl.sql`（`TBLEQPACCSTATEBASIS`）；PostgreSQL CREATE-only 在 `database/reference/mestest_accessory_basis_create.sql` 與 `database/reference/mestest_accessory_state_create.sql`。本項無新表，未新增或猜測 DDL；本機受保護 Oracle profile 不可用，本次未重查 Oracle。

## DEV 與家用端 handoff

- DEV 頁呈現 7 個固定操作，並可切換模擬 `IC_FT_PKG` 以顯示第 8 列；選擇器以明確標示為假資料的狀態清單示範代碼／名稱選擇。Apply 更新頁面內假設定並保持開啟；Confirm 假儲存後關閉；Close 丟棄尚未 Apply 的頁面變更。沒有 localStorage 或網路寫入。
- 家用端沿用既有 `tbleqpaccstatecontrol` 與 `tbleqpaccstatebasis` schema，不新增 migration／CREATE-only。可提供授權保護的 `GET /api/ems/accessory-state-controls?controlType=EMS` 與批次 `PUT /api/ems/accessory-state-controls`；PUT 僅接受上述固定 ControlNo、有效狀態代碼及服務端核定的模組資格。
- PUT 須在交易中讀取目前控制狀態及將受影響配件，寫入狀態歷程、更新現況／序號並更新控制設定；失敗全部回滾。對無設定列應採 upsert，但需先對照 live schema、既有 migration 與唯一鍵。不得沿用 Service 的無條件 Delete+Insert，也不得讓任意 client 傳入控制鍵、SQL 條件或 AdditionalXml。
- DEV 使用的狀態代碼／名稱、資料列數與保存結果都不是 MESTEST 實際資料；`I_SetupClose` 的實際顯示由部署中的 `IC_FT_PKG` Active Module 決定。
