# ES407 設備配件現況查詢

## 範圍與來源

本頁唯讀查詢目前掛載於設備的配件。公司端完成 Vue DEV 假資料查詢與家用端 API handoff，不呼叫正式 API，不連 YMES PostgreSQL。

- 選單清冊：`EMS / ACC EXECUTION / EQP ACC STATE QUERY`，FunctionNo `EQP ACC STATE QUERY`、FunctionKey `ES407`。
- Form：`D:\iMES\CSiMES\STD\MESWin\EMS\ES_EquipmentAccState\frmEquipmentAccState.vb`，Designer 程式碼內嵌同檔。
- 呼叫端：`frmAccessoryStateMonitor` 與 `frmAccessoryStateMonitorByEQP` 可開啟此 Form，帶入目前的 AccessoryNo；Form 在 Load 時先按已帶入條件查詢，再載入 lookup。由 EMS 選單直接開啟時空白等待 Query。
- Service：`wsEMS.LoadEquipmentAccState`；lookup 使用 `wsEQP.LoadAccessoryType/LoadAccessoryBasis/LoadEquipmentType/LoadEquipmentBasis`、`wsUSR.LoadUserSecurity`。
- Core：`kcEMS.clsAccState.LoadEquipmentAccState`，直接讀 `TBLEMSEQPACCSTATE`。

## WinForms 行為與資料

查詢條件為 Equipment Type、Equipment No、User No、Accessory Type、Accessory No，以及 Start Time From／To。每個文字欄有核取方塊與共用 `frmCOMSearch` lookup；輸入文字會勾選條件、取消勾選會清空，離開欄位時轉大寫。兩個日期時間界限各有獨立核取方塊，初始皆未啟用。查詢以 StartTime 升冪範圍及五個文字欄完整相等條件組合；不提供 EndTime、State 或 SerialNo 查詢。

Core 的直接 SQL 為 `SELECT * FROM TBLEMSEQPACCSTATE WHERE EQUIPMENTTYPE IS NOT NULL`，再附加有值條件；沒有指定條件時會查整個現況表。Form 的 DataView 依 EquipmentType、EquipmentNo、AccessoryType、AccessoryNo 排序。Grid 明確排列 EquipmentType、EquipmentNo、AccessoryType、AccessoryNo、StartTime、UserNo；僅 `AccessoryVersion` 明確隱藏。`AccApplySerialNo` 欄在來源 Form 沒有隱藏，依 UltraGrid 預設也會顯示。查無資料時舊 Form 以 ExceptionManager 路徑處理，不是正常空清單狀態。

`TBLEMSEQPACCSTATE` 有 EquipmentType、EquipmentNo、AccessoryType、AccessoryNo、UserNo、StartTime、AccessoryVersion、AccApplySerialNo；Oracle 主鍵是單欄 `AccessoryNo`，另有 EquipmentNo 索引。版本欄雖從 Core `SELECT *` 傳回但不顯示；`AccApplySerialNo` 是現況行可見欄位。

### Legacy 條件組合缺陷

`funQuery` 依序累加 EquipmentType、EquipmentNo、UserNo，再以單一 `=` 指派 AccessoryType XML，會覆蓋前面已組好的條件。因此同時指定 Accessory Type 與前述條件時，Service 收不到前述條件。DEV 對所有文字條件採預期的 AND 精確比對，明確修正此缺陷；家用端不得複製此 XML assignment 行為。

原 Service/Core 不強制時間區間或結果上限。Form 為 `LoadAccessoryBasis` lookup 傳 `IssueState=2` 及 `CurVersion=defInteger`，但目前 `wsEQP.LoadAccessoryBasis` 對 CurVersion 的解析已註解，Core 也沒有 CurVersion 參數，故實際只依 IssueState 篩選並可能載入多版本。User lookup 雖經 `LoadUserSecurity`，Form 會先移除 Password／ResetPassword 欄位。

## DEV 頁

路由：`/YMES/EMS/EquipmentAccStateQuery`；在「配件_執行」選單顯示「設備配件現況查詢」。DEV 頁包含五個文字篩選、lookup 假選擇器、Start Time 起訖、Query、結果筆數與 Close。由選單進入先顯示空清單；網址提供 `?AccessoryNo=` 時會預填並立即查詢，以模擬配件監控帶條件開窗。查詢只對固定 fixtures 篩選，未指定條件時查詢全部 DEV 現況。

設備、配件、人員、版本、序號及時間均為虛構，只存在頁面記憶體。DEV 以 AND 條件、inclusive StartTime 邊界及正常空結果顯示模擬查詢；共用 WinForms picker、UltraGrid 與 ExceptionManager 訊息以瀏覽器 dialog、table 和狀態文字呈現。Grid 保留來源可見的 `AccApplySerialNo`，不顯示 `AccessoryVersion`。

## Oracle DDL 與 PostgreSQL handoff

`TBLEMSEQPACCSTATE` 的 Oracle DDL／data dictionary 與 PostgreSQL CREATE-only 已由既有 [配件設備狀態 references](../../../database/reference/mestest_accessory_basis_source_ddl.sql) 及 [CREATE-only](../../../database/reference/mestest_accessory_basis_create.sql) 保存。設備類別／主檔、配件類別／主檔及使用者 lookup 亦沿用 repository references；無新增表、不產生重複 CREATE SQL，也未查 Oracle 業務資料。

## 家用端 API handoff

- 核對 `TBLEMSEQPACCSTATE` live schema、PK 及 EquipmentNo 索引與現有 references；相同時不新增 migration。
- 實作登入及 FunctionNo `EQP ACC STATE QUERY` 授權的參數化唯讀查詢，僅接受明確白名單 filters，包含設備／配件類別與編號、UserNo 及 StartTime inclusive 區間。
- API 回傳前端可見 DTO：EquipmentType、EquipmentNo、AccessoryType、AccessoryNo、StartTime、UserNo、AccApplySerialNo；隱藏的 AccessoryVersion 不必對外輸出。空結果須回正常空陣列。
- 提供穩定排序、分頁／最大筆數與查詢範圍限制；不可無限制全表讀取。User lookup 僅傳回安全的 UserNo／顯示名稱，絕不包含 Password／ResetPassword。
- 若家用端的其它配件掛載 API 更新此表，查詢應可在提交完成後讀到同一來源資料；公司端不實作或驗收該寫入流程。
