# ES202 設備狀態監控_設備類別（SHOW EQP STATUS BY TYPE）

## 選單與來源

- 選單識別：Module `EMS`、FunctionNo `SHOW EQP STATUS BY TYPE`、FunctionKey `ES202`、Form `frmEquipmentStateQueryByType_THEIL_BU1`、執行檔 `ES_EquipmentStateQueryByType_THEIL_BU1.dll`，分類為設備_執行。
- CSiMES、THEIL 與 DEV_SILVA 三份 Customer Form 內容相同，SHA-256 為 `8A76DC85D2602E64A059D5C15D7809D8AC735E71511264EEEA1426D2BB2CF368`。Designer 程式碼內嵌在 `frmEquipmentStateQueryByType_THEIL_BU1.vb`，沒有獨立 `.Designer.vb`。
- 選擇器來源：`Customer\Production\MESWin\EMS\ES_EquipmentStateQueryByType_THEIL_BU1\frmEquipmentStateQueryByType_THEIL_BU1.vb`。THEIL Service：`Customer\Production\MESws_STD\wsSTD\wsEQP\wsEQP.cs` 的 `LoadEquipmentType`；Core：`STD\MESkc\kcEQP\clsEQPBasis.cs` 的 `LoadEquipmentType`。
- Confirm 會透過 `ObjectFileHandler` 開啟共用 `ES_EquipmentStateMonitor` 的 `frmEquipmentStateMonitor_THEIL_BU1`，傳入 `strEquipmentType` 和 `strMainVersion`。該監控視窗另有 Form／Service／Core，不是選擇器的 Designer 子畫面；本規格也核對其設備狀態讀取與操作流程。

## Form 與互動

- 選擇器視窗 1008×591，左上只有 `Equipment Type` 標籤與 DropDownList，初始不選類別；下方右側有 Confirm、Close。下拉項目由 `wsEQP.LoadEquipmentType` 取得，只加入 `EquipmentType` 欄位，WinForms `Sorted=True`。空白時按 Confirm 直接結束該事件，不顯示錯誤；Close 關閉視窗。
- Form 沒有傳入 IssueState；Service 預設 `IssueState=2`，Core 查詢 `TBLEQPEQUIPMENTTYPE` 中非空且核准的 EquipmentType。載入失敗時顯示 MES 例外視窗。
- Form Load 另讀取 `wsSYS.LoadParameter(SysInfo, MainVersion)`。Confirm 將 MainVersion 與選定設備類別交給共用監控窗；監控窗在狀態變更前再次比對用戶端／伺服器版本，不一致就要求重新啟動 MES。
- 共用監控視窗初始依 `EquipmentType` 載入現況設備，主要畫面以設備圖片、EquipmentNo 狀態色標籤呈現，每頁 10 台，可切頁、Refresh、Close。下方依 `TBLEQPSTATEBASIS` 顯示帶 StateColor 的狀態按鈕；`SysInfo.ChamberManage` 開啟時顯示子設備 Chamber 區。
- 設備選取後可按狀態按鈕提出變更。來源會守住沒有設備、目前已是目標狀態、未完成保養工單、互斥狀態、MainVersion 不一致等情況，並開啟說明／原因視窗；生產狀態可能另要求批號及子設備同步。Service `wsEMS.EditEquipmentState` 將設備、狀態、說明、原因、Lot 與 Chamber 明細傳給 `clsEMSEquipment.EditEquipmentState`。
- 設備右鍵提供 Equipment State Log、Production Data、Lot Info，分別開啟其他 MES 視窗。設備圖片由共用監控呼叫 `wsEQP.ShowEquipmentType_Picture` 取得。
- DEV 頁在 `/YMES/EMS/EquipmentStateByType` 先模擬設備類別選擇，再以對話框呈現共用監控窗的設備卡片、每頁 10 台、狀態色、頁次、Refresh、假 Chamber 區、狀態按鈕與右鍵預覽。狀態變更需輸入說明並只改本頁記憶體假資料。未載入真實圖片；假資料不模擬版本、登入權限、PM 工單、狀態互斥、批號流程、伺服器交易，也不呼叫 API／Service／Oracle／YMES PostgreSQL。

## 資料與家用端 API／DDL handoff

- 類別選單直接來源為 `TBLEQPEQUIPMENTTYPE`。既有 `database/reference/mestest_equipment_type_create.sql` 有 PostgreSQL CREATE-only（含 equipment type picture 參考結構），repo 沒有該設備類別表的原始 Oracle source DDL。桌機未找到受保護 Oracle profile，本次沒有用 PowerShell／ODP.NET 查 MESTEST metadata；未以現有 CREATE-only 猜補 Oracle DDL。
- 監控窗讀取 `TBLEQPEQUIPMENTBASIS`（IssueState=2，含 Chamber／BelongEquipmentNo；既有 Oracle source 在 `mestest_wip_wp201_unresolved_source_ddl.sql`，CREATE-only 在 `mestest_equipment_basis_create.sql`）、`TBLEMSEQUIPMENTSTATE`（Oracle source／CREATE-only 在 `mestest_equipment_state_references_source_ddl.sql`／`mestest_equipment_state_references_create.sql`）、`TBLEQPSTATEBASIS`（`mestest_equipment_state_create.sql`）。設備狀態互斥可沿用同一 references 中的 `TBLEQPSTATECONTROL`。本項不新增 CREATE SQL。
- 家用端可提供登入授權的 `GET /api/eqp/equipment-types?issueState=2&sort=equipmentType`，只回傳選擇器顯示的核准 EquipmentType；監控資料由 `GET /api/ems/equipment-state-monitor?equipmentType=&page=1&pageSize=10&includeChambers=` 回傳設備基本資料、現況、狀態名色與可見範圍內 Chamber。請以參數化查詢、服務端授權及穩定排序；狀態變更沿用 ES204／既有 EditEquipmentState handoff，伺服器仍需驗證版本、轉換互斥、PM／Lot／Chamber 規則並原子更新現況與歷程。圖片建議回傳授權資料 URL，不把 BLOB 塞入一般設備資料 DTO。右鍵其他視窗可連到既有 ES402 或相應正式模組。
