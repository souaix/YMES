# ES406 配件歷史資料查詢（ACC STATE LOG QUERY）

## 選單與來源

- 清冊：Module `EMS`、FunctionNo `ACC STATE LOG QUERY`、FunctionKey `ES406`、Form `frmAccessoryStateLog`、執行檔 `ES_AccessoryStateLog.dll`、選單 `配件_執行`。
- DEV 路徑：`/YMES/EMS/AccessoryStateLogQuery`。正式頁面尚未開放；DEV 只使用虛構歷程、使用者、配件類型與原因。
- CSiMES／THEIL／DEV_SILVA 的 `frmAccessoryStateLog.vb` SHA-256 完全相同：`A1798B490B32B1A1A1F887BF79510C3C5C5A9EF8D364AFA285BA2FDDE8DC189A`；Form 含內嵌 Designer。
- Service：THEIL `wsEMS.LoadAccessoryStateLog`、`wsEMS.LoadAccessoryReasons`；查詢選擇清單另呼叫 `wsEQP.LoadAccessoryType`、`wsEQP.LoadAccessoryBasis`、`wsUSR.LoadUserSecurity`。
- Core：THEIL `clsAccState.LoadAccessoryStateLog` 與 `clsAccState.LoadAccessoryReasons`。

## WinForms 畫面與互動

查詢區有四個勾選條件，未勾選時不送該條件：

| 條件 | 表單輸入／選擇器 | Service/Core 條件 |
| --- | --- | --- |
| Accessory Type | 可輸入或從配件類型選擇 | `ACCESSORYTYPE = value` |
| Accessory No | 可輸入或從配件基礎選擇 | `ACCESSORYNO = value` |
| User No | 可輸入或從使用者選擇 | `USERNO = value` |
| Start Time | 起迄日期時間 | `STARTTIME >= from AND STARTTIME <= to` |

- 開頁日期預設今日 00:00 至 23:59:59，但 Start Time 勾選預設關閉。若啟動 Form 時帶入配件類型或編號，會自動勾選並立即查詢。
- Query 從 `wsEMS.LoadAccessoryStateLog` 載入完整結果，依 `ACCESSORYTYPE, ACCESSORYNO, STARTTIME` 排序。Form 沒有分頁或筆數上限。
- 主 Grid 顯示 Accessory Type、Accessory No、State Name、Start Time、End Time、User No、Description、Apply Time、Accumulate Qty、Time Cycle Start；`AccessoryVersion`、`ACCSERIALNO` 隱藏。選取第一筆／其他歷程列後，以該筆 `ACCSERIALNO` 呼叫 `wsEMS.LoadAccessoryReasons`，明細 Grid 只顯示 `ReasonNo`、`ReasonName`。
- `LoadAccessoryStateLog` Core 將歷程與 `TBLEQPACCSTATEBASIS` 依 `AccessoryState` 做 inner join，`StateName` 是目前狀態主檔名稱，不是歷程當時的名稱快照。Service/Core 雖支援 EndTime 起迄參數，但此 Form 未傳送也沒有該篩選器。
- 配件編號選擇器的來源碼僅在 `txtAccessoryNo` 非空時才附上 `AccessoryType` 條件，可能無法依已選類型限縮清單；DEV 依使用者選取的類型提供較直覺的假清單。
- `funLoadData` 呼叫 `wsUSR.LoadUserSecurity` 取得使用者資料後才在 WinForms 刪除 `Password`／`ResetPassword` 欄位。正式 API 不得傳回密碼欄位，使用者選擇器只取授權範圍內的 UserNo／顯示名稱。

## Service／Core 與資料結構

- `LoadAccessoryStateLog` 可選 ACCSerialNo、UserNo、AccessoryType、AccessoryNo、StartTime 起迄、EndTime 起迄；Core 以字串串接 SQL、無頁數限制，並 join `TBLEQPACCSTATEBASIS` 取得 `StateName`。
- `LoadAccessoryReasons` 以選取歷程的 `ACCSerialNo` 查 `TBLEMSACCESSORYREASONS`。Form 使用時只傳一筆 ACCSerialNo；Core 另有最多 1000 筆分批組 IN 條件的路徑。
- `TBLEMSACCESSORYSTATELOG` Oracle source DDL 與 PostgreSQL CREATE-only 已有 repo 參照：`database/reference/mestest_accessory_basis_source_ddl.sql`、`database/reference/mestest_accessory_basis_create.sql`。`TBLEQPACCSTATEBASIS` DDL／CREATE-only 在 `database/reference/mestest_accessory_state_source_ddl.sql`、`database/reference/mestest_accessory_state_create.sql`。
- repo 尚無 `TBLEMSACCESSORYREASONS` Oracle source DDL／metadata 或 PostgreSQL CREATE-only。桌機受保護 Oracle profile 不可用，本次不連線、不猜該表欄位或鍵；家用端先取得核准唯讀 metadata，再依實際 schema 補 CREATE-only。

## DEV 與家用端 handoff

- DEV 提供類型／配件編號／使用者／Start Time 勾選篩選、選擇器、Query、按 AccessoryType／AccessoryNo／StartTime 排序的虛構歷程 Grid、列選取與原因明細 Grid。假資料含多日、多配件與空／多筆原因。沒有呼叫 Service/API、Oracle、YMES PostgreSQL 或 localStorage。
- 家用端可實作登入授權的 `GET /api/ems/accessory-state-logs?accessoryType=&accessoryNo=&userNo=&startTimeFrom=&startTimeTo=&page=1&pageSize=50` 與 `GET /api/ems/accessory-state-logs/{logId}/reasons`。空條件查詢應要求合理日期範圍或有上限的分頁，排序加 `accserialno` 作穩定次序；實際搜尋值用參數化 SQL，依登入者授權限制資料範圍。
- 主清單提供原因明細所需的 opaque `logId`（對應已核實的 `accserialno`），避免暴露或接受任意 SQL；回傳明確的狀態代碼／顯示名稱與記錄時間。需先決定歷史 StateName 取目前主檔或快照語意。
- 取得並核對 `TBLEMSACCESSORYREASONS` Oracle 欄位、PK／索引、外鍵與關聯，再新增相符 PostgreSQL CREATE-only；目前缺的是表格 DDL，不是主歷程表 DDL。家用端完成 migration/API 前不將 DEV fixture 視為正式資料。
