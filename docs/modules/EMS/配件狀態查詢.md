# ES405 配件狀態查詢（ACC STATE QUERY）

## 選單與來源

- 清冊：Module `EMS`、FunctionNo `ACC STATE QUERY`、FunctionKey `ES405`、Form `frmAccessoryState`、執行檔 `ES_AccessoryState.dll`、選單 `配件_執行`。
- 路徑：`/YMES/EMS/AccessoryStateQuery`。正式頁以登入保護的 PostgreSQL API 查詢現況；僅在本機 DEV 預覽模式使用虛構配件、壽命數值及原因。
- CSiMES／THEIL／DEV_SILVA 的 `frmAccessoryState.vb` SHA-256 完全相同：`A23AE2D804E480BE585179B95CD3BD1C54E4EF82231A6A9A2A90F9753BF81638`；Form 含內嵌 Designer。
- Service：THEIL `wsEMS.LoadAccessoryState`、`wsEMS.LoadAccessoryReasons`；選擇器另用 `wsEQP.LoadAccessoryType`、`wsEQP.LoadAccessoryBasis`。
- Core：THEIL `clsEMSEquipment.LoadAccessoryState` 與 `clsAccState.LoadAccessoryReasons`。

## WinForms 畫面與互動

- 查詢條件僅有 Accessory Type、Accessory No 兩個勾選式文字／選擇器；未勾選時不送條件。無其他條件時 Query 不拒絕，會查詢所有配件現況。若開窗參數帶有配件類型或編號，Form 自動勾選並查詢。
- 主 Grid 使用多層 Band；每筆現況列的 `ACCSERIALNO` 送 `LoadAccessoryReasons`，理由以子 Grid 展開，初次載入會展開所有有子列的現況列。
- 可見欄位：Accessory Type、Accessory No、State、Start Time、User No、Description、Apply Time、Accumulate Qty、Acc Spare Qty Limit、Acc Repair Qty、Acc Total Used Qty、Time Cycle Start。AccessoryVersion、AccessoryState、StateName、RepairCycle、AccSpareQty、ACCSerialNo 為隱藏欄位；State 欄由 `StateName` 表達式顯示。
- Core 以 `TBLEMSACCESSORYSTATE` 為主表，inner join `TBLEQPACCSTATEBASIS` 取得狀態名稱，left join `TBLEQPACCESSORYLIFE` 取得 RepairCycle。`Acc Spare Qty Limit` 對 null 保持空值，對 -1 保持 -1（DEV 顯示「不適用」），否則計算 `RepairCycle - AccumulateQty`。
- 查詢結果沒有分頁；Core 依 AccessoryNo 排序，Form 再依 `ACCESSORYTYPE, ACCESSORYNO, STARTTIME` 排序。Core 沒有限制 `CurVersion`，會回傳現況表中各 AccessoryVersion；Form 又隱藏版本，所以同一配件編號可能顯示多列而看不到版本差異。
- Service 另支援 AccessoryVersion、AccessoryState、UserNo 條件，但此 Form 沒有這些輸入欄。Form 的配件編號選擇器只有在 `txtAccessoryNo` 已有值時才將 AccessoryType 傳給 basis 查詢，可能不能按已選類型縮小清單；DEV 依使用者選取的類型提供直覺的假清單。

## Service／Core 與資料參照

- `LoadAccessoryState` Core 以 SQL 字串串接條件，查 `TBLEMSACCESSORYSTATE`、當前 `TBLEQPACCSTATEBASIS.StateName` 及 `TBLEQPACCESSORYLIFE.RepairCycle`，不分頁。Oracle 與非 Oracle 分支使用不同的空值／-1 計算式。
- Form 收集查詢結果全部 `ACCSERIALNO`，一次呼叫 `LoadAccessoryReasons` 載入子表；reason 查詢資料來自 `TBLEMSACCESSORYREASONS`。此表目前缺 repo Oracle source DDL／metadata 與 PostgreSQL CREATE-only；桌機受保護 Oracle profile 不可用，本次未連線也未猜 schema。
- 現況、狀態基礎、配件壽命的 Oracle DDL 與 CREATE-only 已在 repo：`TBLEMSACCESSORYSTATE` 見 `mestest_accessory_basis_source_ddl.sql`／`mestest_accessory_basis_create.sql`；`TBLEQPACCSTATEBASIS` 見 `mestest_accessory_state_source_ddl.sql`／`mestest_accessory_state_create.sql`；`TBLEQPACCESSORYLIFE` 見 `mestest_accessory_type_dependencies_source_ddl.sql`／`mestest_accessory_type_dependencies_create.sql`。

## DEV 與家用端 handoff

- DEV 預覽提供虛構類型、配件、壽命數值及多層 reasons 子列，只在本頁記憶體互動，不呼叫 API 或資料庫。正式頁以登入者 cookie 呼叫授權 API；查詢條件為配件類型／編號，支援穩定排序及 1–100 筆分頁，版本欄明確顯示。
