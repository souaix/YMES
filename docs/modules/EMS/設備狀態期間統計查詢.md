# ES409 設備狀態期間統計查詢（EQP STATE STATISTICS_EMS）

## 選單與來源

- 選單識別：Module `EMS`、FunctionNo `EQP STATE STATISTICS_EMS`、FunctionKey `ES409`、Form `frmEQPStateStatistics`、ExecutionFile `RT_EQPStateStatistics.dll`，分類為 `ACC EXECUTION`（配件_執行）。選單清冊另有 FunctionKey `RT414` 的同名歷史報表項目；本交付只實作 ES409，不把兩個選單鍵合併。
- 公司端 DEV 路徑：`/YMES/EMS/EquipmentStateStatistics`。正式頁面尚未開放，不呼叫 YMES API。
- WinForms Form 與 Designer 控制項配置同在 `D:\iMES\CSiMES\STD\MESWin\RPT\RT_EQPStateStatistics\frmEQPStateStatistics.vb`。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsRPT\wsRPT.cs` 的 `LoadEQPRealTimeReport`、`LoadEQPRealTimeReport_Chamber`。Form 用 `InvokeSrv` 呼叫，逾時設為 600 秒。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcRPT\clsReport.cs` 同名方法。兩者以 `ReportMode=True` 選擇報表資料庫連線；公司端只完成 DEV 假資料與規格交接。

## WinForms 篩選與互動

- 開啟時呼叫 `wsSYS.LoadParameter` 讀 `ChamberManage`；值為 `1` 才顯示 Chamber 選項。日期預設為昨天 00:00 至今天 00:00。
- 設備狀態和設備編號各有勾選條件、唯讀代碼／名稱欄及 `frmCOMSearch_Multi` 查找器。狀態 lookup 使用 `wsEQP.LoadEQPStateBasis`；設備 lookup 使用 `wsEQP.LoadEquipmentBasis(IssueState=2)`。多選後以逗號串接代碼；取消勾選會清空欄位。非 Chamber 設備查找清單只顯示 `ChamberFlag=0`，開啟 Chamber 後可查所有設備。
- 查詢只送已勾選的 `EquipmentState`、`EquipmentNo`，以及必填的 `StartTime`、`EndTime` 和 `ReportMode=True`。標準與 Chamber 模式分別呼叫兩支 RPT Service。
- 標準結果顯示 `AreaNo, EquipmentNo, Status, StartTime, Totaltime_Min, Reason, EndTime`；`EquipmentType`、`EquipmentState` 是隱藏識別欄。Form 把來源 `TotalTime` 欄重新命名為 `Totaltime_Min`。
- Chamber 結果另帶 `ChamberFlag`、`BelongEquipmentNo`，Form 將子設備的 `EquipmentNo` 投影為母設備欄，並以原子設備編號填 `ChamberNo`；母設備列的 `ChamberNo` 留白。Chamber 表格欄位順序為 `AreaNo, EquipmentNo, ChamberNo, Status, StartTime, Totaltime_Min, Reason, EndTime`，其餘識別欄隱藏。
- 關閉按鈕離開表單；沒有新增、修改或刪除資料的操作。

## Service／Core 查詢規則與資料來源

- Service 解析可選 `EquipmentState`、`EquipmentNo`、`AdditionalXml`、`ReportMode` 及日期，呼叫 `kcRPT.clsReport`，封裝 XML DataSet；失敗時寫 MES EventLog。Chamber Service 額外接受 `BelongEquipmentNo`，但此 Form 不傳該參數。
- Core 將 `TBLEMSEQUIPMENTSTATELOG` 歷史列與 `TBLEMSEQUIPMENTSTATE` 目前狀態 `UNION ALL`，以 `TBLEQPSTATEBASIS` 取得狀態名稱。標準模式以 `TBLSMDSMTAREAEQPMAP` 對應區域；Chamber 模式以 `TBLSMDAREARELATION`、`TBLEQPEQUIPMENTBASIS` 展開設備／Chamber 關係。
- 只取與查詢區間重疊的狀態列，起訖裁切在指定區間內；依區域、設備類型／編號、狀態、裁切起訖與原因分組，按區域、設備類型、設備編號、開始時間排序。Oracle 分支將每筆區間分鐘數向上取整（`CEIL`）；目前狀態以資料庫當下時間作為結束時間，再裁切到查詢結束時間。
- 查詢引用的 Oracle 來源結構沿用既有唯讀取得／核對資料：`database/reference/mestest_wip_wp305_source_ddl.sql`（設備狀態歷程）、`database/reference/mestest_equipment_state_references_source_ddl.sql`（設備目前狀態等）、`database/reference/mestest_equipment_state_create.sql`（狀態基礎）、`database/reference/mestest_equipment_group_smd_source_ddl.sql`／`mestest_equipment_group_smd_create.sql`（區域映射）、`mestest_equipment_basis_create.sql`（設備／Chamber 欄位）。本項重用既有 DDL/metadata，未查 Oracle 使用者資料、未新增 Oracle 查詢、沒有需補建表的 CREATE-only。
- Legacy Core 以字串串接日期與多選條件；正式查詢 API 應將時間與狀態／設備清單參數化，限制最大區間及清單長度，避免沿用字串拼接。檢查時區、資料庫日期精度和目前狀態邊界的轉換規則。

## Vue DEV 與家用端 handoff

- DEV 頁面提供預設昨日 00:00 至今日 00:00、設備狀態多選、設備多選、區間驗證、查詢、結果排序與空結果狀態；假資料模擬區間裁切與分鐘向上取整。DEV 的 `ChamberManage=1` 固定 fixture 讓人可切換標準／Chamber 結果，並展示母設備／腔體欄位轉換。頁面沒有呼叫正式 API，也沒有持久化。
- 建議家用端提供登入／ES409 權限保護的唯讀 `GET /api/ems/equipment-state-statistics`，參數為 `startTime`、`endTime`、`equipmentNos[]`、`stateCodes[]`、`showChambers`。回傳欄位使用上方結果欄位及 `totalTimeMinutes`；檢核起訖和使用者可查的設備範圍，分頁或設定合理最大查詢區間。
- 先比對 YMES live schema。查詢只讀既有狀態／設備／區域資料表，不需 ES409 專屬 migration 或寫入 API；正式 SQL 必須採參數化區間 overlap 與清單條件，重現時間裁切、`CEIL` 分鐘和穩定排序。Chamber 模式要保留原始 Chamber 與母設備編號，不可在資料查詢中遺失映射資訊。
- 公司端未連 PostgreSQL、未建 schema/migration、未實作或驗收正式 API、未遠端部署。
