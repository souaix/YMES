## 查詢與欄位

- 多選查詢先以 `wsEQP.LoadAccessoryBasis` 帶入 `IssueState=2`；核心現況讀取 `TBLEMSACCESSORYSTATE`，以 AccessoryNo+AccessoryVersion join `TBLEQPACCESSORYBASIS`，再以 AccessoryType left join `TBLEQPACCESSORYLIFE` 取得 RepairCycle／ScrapType／ScrapLife。
- `LoadAccessoryStateJoinLife` 只用 AccessoryNo 條件，沒有 `CurVersion=1` 限制，所以同一編號可帶出多版本現況。正式 API 應保留版本識別，不能默默合併版本。
- Grid 另有隱藏欄：AccessoryVersion、AccessoryState、AccumulateQty、AccSpareQty、AccRepairQty、AccTotalUsedQty、Select 等；提交以 AccessoryNo+Version 和提交前原值組成明細。

## 調帳與歸零規則

- 調帳：新累積量為使用者輸入值；`AccRepairQty` 不增加，`AccTotalUsedQty` 加上新舊累積量差，`AccSpareQty` 以「原備用量 + 原累積量 - 新累積量」更新並下限為 0。若編輯後 `TimeCycleStart` 為空則寫 Null，否則寫編輯值。
- ReturnZero：新累積量為 0，`AccRepairQty` +1，`AccTotalUsedQty` 不改，`AccSpareQty` 以相同差額公式補回且下限為 0，`TimeCycleStart` 設為現在。
- Form 在提交前禁止已處於 ES103 Apply 狀態的選取列；`funUpdate` 若任一選取列已是 ES103 Scrap 狀態，會在呼叫 Service 前跳到結尾，因此整次不送出。執行序列與單號缺失也會被擋下。
- 報廢條件由配件生命設定決定：`ScrapType=0`（重複使用次數）以 `AccRepairQty+1 > ScrapLife` 判定；`ScrapType=1`（總使用數量）以目前 `AccTotalUsedQty > ScrapLife` 判定，等於上限仍不報廢。Form 在呼叫 Core 前計算旗標；因此調帳時的「+1」判斷與 Core 不增加維修次數不一致，總使用數門檻也用調整前值。規格保留此 Legacy 行為，家用端需與業務確認是否照搬。
- 需要報廢時，Core 從 EMS 的 `TBLEQPACCSTATECONTROL` 讀 Scrap 狀態，並檢查目前類別／狀態至 Scrap 狀態的 ES105 禁止轉換，再呼叫共用狀態轉換流程。Form 載入時若未設定 Apply／Scrap 狀態會停用 Adjust／ReturnZero。
- Core 將維修明細、現況數量／維修次數／週期更新及可能的報廢狀態轉換加入 `CollectionSQL`，最後傳給 `ExecuteSQLNoneQuery_UPD`。該共用 helper 的實作未出現在可讀來源樹，故此處無法確認多語句交易／回滾語意。正式 API 必須定義並實作單一交易，連同維修紀錄、現況、狀態歷程原子提交。

## 資料表、DDL 與 API handoff

- 查詢／更新使用 `TBLEMSACCESSORYSTATE`、`TBLEQPACCESSORYBASIS`、`TBLEQPACCESSORYLIFE`、`TBLEQPACCSTATECONTROL`、`TBLEQPACCSTATEBASIS`、`TBLEMSACCVIOLATESTATUSCHANGE`；報廢轉狀態另走共用狀態歷程。現況、配件主檔、生命設定、狀態及互斥表沿用 repo 既有 Oracle DDL／CREATE-only references。
- `TBLEMSACCESSORYREPAIR` 是本功能新增寫入的直接維修紀錄表；repo 無 Oracle source DDL／metadata 或 PostgreSQL CREATE-only。桌機受保護 Oracle profile 目前不可用，本次未連線、未猜欄位／PK／索引；家用端先核對 live schema，取得核准 metadata 後再補 CREATE-only。
- 維修單號由 `GetAccessoryRepairNo` 透過 `InitAccessoryRepairNo` 取序號，要求系統已啟用對應 Serial Rule。實際序號規則設定也需家用端確認，不能由 DEV 號碼推測。
- 正式端建議讀取 API 回傳符合 IssueState 的候選編號與各版本現況；另提供受登入授權保護的序號預留及批次維修 endpoint。提交明確傳 `adjust`／`returnZero`、單號、說明、使用者由身分推導，以及每筆 AccessoryNo+Version、expected 原始 RepairQty／AccumulateQty／TotalUsedQty、新累積量與起算時間；在一個交易內鎖定／重讀現況和規則、驗證 ES103／ES105、寫 repair 明細、更新數量，必要時一併記錄報廢狀態歷程。對過期原值回傳衝突，禁止以 client 傳入的使用者或狀態名稱授權。
- DEV 頁的選擇器、單號、配件、數量、狀態轉換都只是虛構值並限本頁記憶體；正式環境仍顯示尚未開放。公司端沒有接 API／PostgreSQL，也沒有執行 Oracle 或正式資料寫入。
- DEV 夾具假設 Apply 狀態碼為 2、Scrap 狀態碼為 5，只為呈現表單守門與轉換互動；正式狀態碼需從 `TBLEQPACCSTATECONTROL` 讀取，不能沿用假數字。
