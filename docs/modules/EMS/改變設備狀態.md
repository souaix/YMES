# ES204 改變設備狀態（EQP STATE CHANGE）

## 選單與實作

- 選單識別：Module `EMS`，FunctionNo `EQP STATE CHANGE`，FunctionKey `ES204`；執行檔 `ES_EquipmentStateChange_THEIL_BU1.dll`。
- 公司端 DEV 路徑：`/YMES/EMS/EquipmentStateChange`。正式環境尚未開放，不會建立 API 或呼叫家用端服務。
- 本機 MES Form：`D:\iMES\CSiMES\Customer\Production\MESWin\EMS\ES_EquipmentStateChange_THEIL_BU1\frmEquipmentStateChange_THEIL_BU1.vb`。`InitializeComponent`／控制項配置與操作在同一 VB 檔，該專案沒有獨立 Designer 檔。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsEMS\wsEMS.cs` 的 `LoadEquipmentState`、`LoadViolateStateChange`、`EditEquipmentState`；Form 另呼叫 `wsEQP.LoadEQPStateBasis`、`LoadStateControlType`、`wsQC.LoadReasonSubTypeBasis`／`LoadReasonBasis`、`wsPM.LoadPMWoBasis`、`wsSMD.LoadAreaEQPMAP`、`wsWIP.LoadLotBasisJoinState`、`LoadEquipmentCheckInLot`。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcEMS\clsEMSEquipment.cs` 的 `LoadEquipmentState`、`LoadViolateStateChange`、`EditEquipmentState`。THEIL Form 呼叫共用標準 Service/Core。

## WinForms 欄位與流程

- 設備區：輸入／查找 `EquipmentNo`、目前狀態文字與顏色、變更後狀態下拉。設備可由傳入 EquipmentNo 帶入，或用設備清單查找。
- 狀態清單從設備狀態基礎資料載入；目前設備狀態不可再選，互斥矩陣中禁止的目標狀態會隱藏。Service/Core 仍會再次檢查互斥條件。
- 原因區分 `ReasonSubType` 清單及 `ReasonType=6` 的 Reason Basis 勾選 Grid，顯示 ReasonNo、ReasonName、ReasonLevel、Description。按 `Get Description` 會把已勾原因格式化到可編輯文字框；確認時至少需要一個原因及非空描述，原因列隨新 EQPSerialNo 寫入。
- 切到 `TBLEQPSTATECONTROL` 的 `WIP Tracking / CheckInConfirm` 狀態時，才展開 Lot Grid。候選為設備同 Area 且 `Status=1` 的執行中生產批；設備原有 CheckIn Lot 會預先勾選。參數 `ChangePRODEQPStateMode=1` 時至少需勾一批；模式 2 可免綁批。
- 確認前若目標不是 `PM Work Order / PMWoReleased` 設定狀態，會查詢設備是否有 `IssueState=2`、`WOStatus=2` 的未完成保養工單；有則阻擋。若目標為生產狀態，另要求存在有效生產批設定（參數可控制是否必須勾選）。
- Form 將設備編號、目標 EquipmentState、Description、Reasons 與選取 Lots 傳至 `wsEMS.EditEquipmentState`。文字描述再附上登入者識別字串。注意 Form 來源有字串組 XML，正式 API 必須使用型別化參數化輸入。

## Service 與 Core 行為

- Service 解析設備／狀態／原因／Lot 欄位，狀態值須為數字；依目前狀態再檢查互斥矩陣，然後呼叫 Core 並寫事件或錯誤紀錄。Form 驗證不能取代 API 的登入者、設備、原因及 Lot 重查。
- Core 確認 `CheckInConfirm` 狀態設定、目前設備狀態及設備主檔存在；狀態變更時封存舊現況至 `TBLEMSEQUIPMENTSTATELOG`、配置新的 EQPSerialNo、更新 `TBLEMSEQUIPMENTSTATE`，並將每筆原因寫入 `TBLEMSEQUIPMENTREASONS`。
- 變更至生產時，Core 依選取 Lot 與設備／區域／作業站維護 `TBLWIPTEMP_EQUIPMENT`、`TBLWIPCONT_EQUIPMENT`；把設備上以 MultiOperatorMode=2 登入的人員新增至 Lot Login State，並呼叫 Reverse helper。
- 離開生產狀態且 `pModule != KMI` 時，Core 結算設備資源、刪除設備暫存用料、結束設備在站記錄，並對設備登入人員寫入下工資料。Form 本身未傳 `pModule=KMI`。
- Core 把多筆 SQL 收集到 `CollectionSQL`，經 Adapter hook 後送往 `ExecuteSQLNoneQuery_UPD`。桌機取得的來源未能單獨證明該共用 helper 對此完整工作集合的交易／回滾範圍；家用端需核實後再訂正式交易邊界。來源亦未用預期 EQPSerialNo 做並發鎖定，正式服務須重讀／鎖定設備現況並保護 serial 配置、防止重複轉態。

## 來源表與 Oracle metadata

- 新識別到的原因歷程表 `TBLEMSEQUIPMENTREASONS` 已用桌機受保護連線、PowerShell 5.1 + ODP.NET 唯讀查詢 `ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_INDEXES`、`ALL_TRIGGERS`：四欄、EQPSERIALNO/EQUIPMENTNO 為 NOT NULL，其餘可 NULL；字典中沒有可見 PK、unique、FK、index 或 trigger。metadata snapshot 未記錄 `CHAR_USED`／`CHAR_LENGTH`，家用端套 migration 前需核對 Oracle BYTE／CHAR 長度語意。結果在 [metadata](../../../database/reference/mestest_es204_equipment_reasons_metadata.txt)，字典推導的 [PostgreSQL CREATE-only](../../../database/reference/mestest_es204_equipment_reasons_create.sql)。
- `DBMS_METADATA.GET_DDL` 本次回 `ORA-03135`；因此未取得原始 Oracle CREATE text。CREATE-only 僅按已取得字典欄位／NULL／限制重建，未猜 PK、索引或 FK。未讀業務資料列、未執行任何 Oracle DDL/DML，也未連 YMES PostgreSQL。
- 其他 Core／lookup 表已有既存 Oracle／CREATE-only references：`TBLEMSEQUIPMENTSTATE`、`TBLEMSEQUIPMENTSTATELOG`、`TBLEQPSTATECONTROL`、`TBLEQPSTATEBASIS`、`TBLEQPEQUIPMENTBASIS`、`TBLWIPTEMP_EQUIPMENT`、`TBLWIPCONT_EQUIPMENT`、`TBLWIPLOTLOGINSTATE`、`TBLWIPOPERATORSTATE`、`TBLUSRUSERBASIS` 及 PM／QC／Area／Lot 查詢表。本功能不另行複製這些 SQL。

## Vue DEV 與家用端交接

- DEV 實作設備查找、現況／目標狀態、互斥狀態、原因分類／多選／描述、保養工單阻擋、生產批綁定、確認與假歷程。互動只改目前瀏覽器記憶體中的明確 DEV fixtures，不呼叫正式 API、不使用 localStorage，也不代表正式資料寫入。
- DEV 中的狀態碼、互斥對、設備／Lot、保養單及 `ChangePRODEQPStateMode=1` 都是示意資料。正式狀態與生產狀態代碼必須由 `TBLEQPSTATEBASIS`／`TBLEQPSTATECONTROL` 及系統參數取得。
- 家用端先比對 PostgreSQL live schema／migration；若缺表，才依 CREATE-only 設計 forward migration。正式查詢需受登入保護，回傳有效設備、目前版本／serial、動態狀態及互斥選項、ReasonType=6 原因、未完成保養工單，以及同 Area 執行中 Lot 和目前 CheckIn Lot。
- 正式寫入需在單一交易邊界內重查設備現況／預期 EQPSerialNo、設備主檔、互斥狀態、原因有效性、PM 工單、CheckInConfirm 設定及每筆 Lot 的 Area／Status／OP／數量；依有效登入者設定新序號與原因，並完成生產關聯或離開生產的用料結算、在站關閉與 Lot 人員簽退。失敗要回滾整個設備狀態命令。舊 `InitEQPSerialNo` 的併發配置與 Adapter／SQL helper 交易語意須另外核實。
