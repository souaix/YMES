# 操作確認視窗

## 用途與檔案

- `web/src/components/ActionConfirmationDialog.vue`：Vue 站內確認視窗，沿用 KD 暖白、黃系與細框配色。
- `web/src/composables/useActionConfirmation.ts`：每個頁面獨立的 Promise 狀態，提供 `requestConfirmation(message)` 與 `resolveConfirmation(accepted)`。
- 2026-11-18 首批使用於 QC501 檢測儀器類別、QC502 檢測儀器基本資料的核准及刪除。

## 操作邏輯

呼叫後先顯示確認文字；只有按確定才回傳 true 並執行原 API。取消、Escape、點擊遮罩均回傳 false，不送出 API。預設焦點在取消；Tab/Shift+Tab 在視窗按鈕間循環，關閉後回復原焦點。元件使用 `role=alertdialog`、`aria-modal=true`，透過 Teleport 放到 body，避免頁面 overflow 裁切。

頁面卸載會以 false 結束待確認 Promise，不會因切頁繼續執行原操作。核准或刪除仍由 API 重驗狀態、DataStamp 及引用；視窗的確定不代表 API 已成功。

## 維護與驗證

原先 `window.confirm` 在 app-browser 的原生視窗造成操作逾時，改用此元件保留確認流程。正式 app-browser 已驗證 QC501 核准取消不改資料、確認後狀態轉已簽核；QC502 核准與刪除確認均正常。API 失敗應顯示 ProblemDetails 的 detail，不向使用者顯示原始 JSON。

新增使用頁面時需匯入 composable 與元件，在 template 綁定 message/resolve；不可把 Promise resolver 或狀態改成跨頁共用 singleton。
