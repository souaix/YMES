# PD102 產品設備能力項目（EQPCapItem）

## WinForms、Service 和 Core

- 入口為 `PD_ProductBasis_THEIL_BU1/frmProductBasis_THEIL_BU1.vb` 的 `btnEQPCapItem_Click`。它傳產品、版次、IssueState 及 `blnIsProduct=True` 給 `PD_OPCapItem`。該功能維護作業站的設備能力項目，與產品主檔的 EQPConstraint 各有獨立入口。
- `STD/MESWin/PRD/PD_OPCapItem/frmPRDOPCapItem.vb` 和 `frmPRDOPCapItemDef.vb` 的 Designer 在各自的 `InitializeComponent`。主 Grid 顯示 OPNo、CapItem、CapValue、Description、Creator／CreateDate、Reviser／ReviseDate。IssueState 非 0 時停用 Add、Edit、Delete、Copy。
- 新增與複製可在 lookup 改選 OPNo 及 CapItem，修改時鎖定兩欄。PD102 的 OP lookup 走 `wsOP.LoadOPBasis`，顯示 PSNo 和 OPNo；CapItem 走 `wsEMS.LoadEMSEQPCapBasis`。兩個 lookup 在此呼叫未指定 IssueState。OPNo、CapItem、CapValue 必填，CapValue trim 並轉大寫。
- 主窗透過 `wsPRD.LoadPRDOPCapItem` 查產品版次，寫入用 `AddPRDOPCapItem`／`EditPRDOPCapItem`／`DelPRDOPCapItem`。Copy 開啟定義窗並走新增，目的列須有不同的 OP＋CapItem 組合。Apply 儲存留窗，Confirm 儲存後關閉。主窗刪除先確認，舊版對選取列逐筆呼叫 Service。
- Service 沿用 `clsProduct` 的 Load／Add／Delete，Edit 走 `clsBasis_UPD.EditPRDOPCapItem`，依該列識別欄位及 DataStamp 條件更新，成功時遞增 DataStamp。另有產品層級複製的 Core 路徑會重建目的產品版次的完整設定。

## Oracle 來源與家用端交接

- 2026-11-18 使用 Windows PowerShell 5.1 + ODP.NET 及桌機受保護 profile，從 MESTEST 唯讀核對 `TBLPRDOPCAPITEM` 和 `TBLEMSEQPCAPBASIS` 的欄位、預設值、約束、索引與 trigger。主表的 `GET_DDL` 回 `ORA-03135`，以下參照依資料字典重建。查詢限 metadata。
- 主表 PK 為 `(PRODUCTNO, PRODUCTVERSION, OPNO, CAPITEM)`，CapValue 為必填 `VARCHAR2(20 BYTE)`。共用 EMS lookup PK 為 `CAPITEM`。各表只有 PK 唯一索引，資料字典未列外鍵或 trigger。OP lookup 沿用 `TBLOPBASIS`。
- [Oracle 邏輯 DDL](../../../database/reference/mestest_prd_eqp_cap_item_source_ddl.sql) · [PostgreSQL CREATE-only](../../../database/reference/mestest_prd_eqp_cap_item_create.sql)
- 家用端先比較 live schema、migrations 及共用 EMS lookup。建議登入保護的 `GET/POST /api/products/{productNo}/versions/{version}/equipment-cap-items` 和 `PUT/DELETE` 複合鍵明細路徑，按產品版本及線上授權核對 OP／CapItem。Copy 可用 POST，Edit 需 DataStamp CAS，錯誤要區分已重複、無權限、版本衝突及資料不存在。批次刪除先明訂部分成功或全部回滾語意。
