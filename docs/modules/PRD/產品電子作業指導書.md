# PD102 產品電子作業指導書（eSOP）

## WinForms、Service 和 Core

- `PD_ProductBasis_THEIL_BU1/frmProductBasis_THEIL_BU1.vb` 的 `btneSOP_Click` 將 ProductNo、ProductVersion、`blnIsProduct=True` 傳給 `PD_eSOPBasis`。主窗及定義窗為 `STD/MESWin/PRD/PD_eSOPBasis/frmPRDeSOPBasis*.vb`，Designer 內嵌於 `InitializeComponent`。主窗會用 IssueState 停用寫入按鈕，PD102 此入口未傳此參數，因此使用 VB Integer 預設值 0。正式存取仍須由功能權限判斷。
- 主表依產品版次顯示 OPNo、SubOPNo、PositionNo、SOPFile、PageNo、Description、Creator、CreateDate。操作為 Add／Edit／Copy／多選 Delete，定義窗有 Apply、Confirm 與 Close。Edit 鎖定 OP／SubOP／Position 與檔案選取。Copy 帶入來源值，另建新的鍵組合。
- 定義窗經 `wsSYS.LoadParameter` 取得 `Execute_eSOP`。1 使用 Position 查找與外部 eSOP 文件，SubOPNo 值為 `N/A`。0 使用 `wsPRD.LoadPRDOpSubOp` 查 SubOP 並以本機檔案對話框選擇文件，PositionNo 值為 `N/A`。OPNo 走 `wsOP.LoadOPBasis`。外部 eSOP 透過既有 `eSOPService`／EAI 呼叫 `station.get` 及 `sop.get`，依回傳欄位挑選站點及文件。
- `wsPRD.Load/Add/Edit/DelPRDeSOPBasis` 對應 `clsProduct` 同名 Core 路徑。必填 OPNo、SubOPNo、PositionNo、SOPFile，空白 PageNo 送字串 `1`。舊版多選刪除逐筆叫 Service。Edit 依完整主鍵更新，來源沒有 DataStamp。

## Oracle metadata 與 SQL 參照

- 2026-11-18 使用 Windows PowerShell 5.1 + ODP.NET，唯讀核對 MESTEST 的 `TBLPRDESOPBASIS` 及 SubOP lookup 欄位。主表 `GET_DDL` 回 `ORA-03135`，以資料字典重建欄位及主鍵。查詢限 metadata。
- 主表 10 欄，PK 為 `(PRODUCTNO, PRODUCTVERSION, OPNO, SUBOPNO, POSITIONNO)`，只有 PK 索引。資料字典未列其他 unique、FK 或 trigger。SOPFile、PageNo、Description 資料庫允許 NULL，表單仍驗文件必填。既有 first-phase 參照已含此表。

## Vue DEV 與家用端 handoff

- `ProductEsopSetup.vue` 完成兩種分流、Add／Edit／Copy／Delete、Apply／Confirm、主鍵重複檢查和頁碼預設，按產品版次存至 DEV localStorage。Position 與外部文件目錄為 DEV 假資料。SubOP 路徑可使用該版次的本地 SubOP 設定。選擇實體檔案只用瀏覽器提供的檔名，未讀取、上傳或開啟文件。
- 家用端先核對 YMES live schema、first-phase 及既有 migration，沿用 Product、OP、SubOP 及系統參數。建議以產品版次 eSOP GET／POST 及複合鍵 PUT／DELETE 契約實作，驗證 caller 的功能權限、OP、SubOP／Position 和 SOPFile 的存取許可。外部 Position／SOP lookup 由伺服器代理，文件應以授權的識別碼或路徑取得。確認批次刪除、版本衝突處理及保存稽核的需求。
- 已做 Vue 靜態型別及差異檢查。外部 eSOP、正式 API、檔案存取及瀏覽器驗收待接續。
