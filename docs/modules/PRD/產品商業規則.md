# 產品 OP Business Rule（PD102 子功能）

## 功能定位與 WinForms 來源

產品主檔 `frmProductBasis_THEIL_BU1` 的 `Business Rule` 按鈕開啟 `PD_ProductOPBusinessRule`。用途是為產品版次下的各作業站設定商業規則流程圖。入口帶入 ProductNo、ProductVersion、IssueState；產品需已有流程資料，清單依登入者的 Production Segment 權限篩選作業站。

| 用途 | WinForms 原始碼 |
| --- | --- |
| 主清單及預覽 | `STD/MESWin/PRD/PD_ProductOPBusinessRule/frmProductOPBusinessRule.vb` |
| 流程圖新增/修改 | `STD/MESWin/PRD/PD_ProductOPBusinessRule/frmProductOPBusinessRuleDraw.vb` |
| 入口及產品按鈕權限 | `Customer/Production/MESWin/PRD/PD_ProductBasis_THEIL_BU1/frmProductBasis_THEIL_BU1.vb` |
| Web Service | `STD/MESws_STD/wsSTD/wsPRD/wsPRD.cs`；客製執行入口 `Customer/Production/MESws_STD/wsSTD/wsPRD/wsPRD.cs` |
| DB/Core | `STD/MESkc/kcPRD/clsProduct.cs` |

此功能是 `PD_ProductOPBusinessRule`。名稱相近的 `PD_PRDOPRule_THEIL_BU1` 是另一套作業站法則設定，不可混用其 Form、服務或資料表語意。

## 主畫面與操作

- 主 Form `ClientSize=1008×591`，包含上方 `Product OP` Grid（984×187）和下方流程圖區（984×374）。
- Grid 的 Service DataSet 含 `ProductNo`、`ProductVersion`、`OPNo`、`RuleXmlString`、`OPName`；產品鍵/XML 是資料關聯或預覽用途。選取作業站列後，下方 AddFlow 以 RuleXmlString 顯示唯讀圖形。
- Grid 右側顯示 `ADD (&A)`、`EDIT (&E)`、`DEL (&D)`；`Find (&F)` 在 Designer 明確 `Visible=False`，舊 Find handler 也已註解，不顯示在 Web。
- 下方圖形區右上 `Default`、右下 `Close (&X)`。Default 會先提示確認，再以相同 OPNo 的作業站 `TBLOPBASIS` 預設商業規則覆蓋產品版次中的設定。
- DEL 以 Grid 多選列為目標；先提示確認，再逐筆呼叫 Service。某一筆失敗會停止後續項目，先前成功刪除不回滾。
- IssueState 非 0 時，ADD、EDIT、DEL、Default 全部停用；選列與預覽仍可用。產品主檔入口還會檢查產品流程資料及 PS 權限。

## Draw 表單

Draw Form `ClientSize=846×582`，`Product OP Business Rule Draw`。ADD 顯示 Process No、Process Version、OP No 查找按鈕；EDIT 隱藏 Process 欄位與查找按鈕，只顯示產品鍵及既有 OP。Process 選取後以產品流程資料載入該流程的 OP；OP 選取後載入既有作業站規則圖。

畫面欄位與工具：

- `TemplateFlowBR`：呼叫 `ObjectFileHandler.Execute("SS_PRDOPTemplateFlowBR")` 選取圖形樣板。
- `Business Rule No`：由 `wsOP.LoadBusinessRule` 的 Business Rule 主檔查找。
- `Phase Name`：唯讀欄位，使用 `wsSYS.LoadPhase` 查找；`Set Phase` 把所選 Rule Node 包成 Phase Group，`Un Set Phase` 移除所選 Phase Group。
- `Rule Action`：預設 `pass`，最多 10 字；新增連線時寫入連線文字，小寫呈現。
- `Node Distance`：30、40、50、60、70、80。
- 排列：`Arrange All`、`Top`、`Left`。
- AddFlow 工具列：Start/End、Business Rule Node、一般連線、VH、HV、VHV、HVH。可拖移節點；Delete 鍵刪除選取的節點或連線。
- `Confirm` 寫入成功後關閉；`Close` 丟棄尚未確認的圖形變更。ADD/EDIT 均以圖形 XML 與 relation rows 一起送出。

Phase Group 是 AddFlow 的視覺節點，使用隱藏 rigid links 將 Rule Nodes 包在一起；儲存時 Group 節點本身不寫入 RuleNode/Relation。每條 relation 的 PhaseNo 取其來源節點所屬 Phase；START 特例為 99。Rule Node 必須屬於一個 Phase，Group 只能包 Business Rule Node，連線不能以 Phase Group 為端點。

EDIT 會呼叫 `wsOP.LoadOPBasis` 查 `IsNetFlow`。若為 NetFlow，畫布不可修改；EDIT 模式另隱藏 Confirm。ADD 模式的 Confirm 不因 NetFlow 查詢而隱藏，仍須依 Service 驗證圖形。

## 服務與資料邏輯

| 操作 | WinForms / Service / Core | 行為 |
| --- | --- | --- |
| 載入產品 OP 規則 | `LoadPRDOPBusinessRule` → `clsProduct.LoadPRDOPBusinessRule` | 依 ProductNo/ProductVersion 查規則並補 OPName。WinForms 傳 `PSPrivilege=True`；Core 以登入者可用 PS 篩選 OP。 |
| 加入圖形 | `UpdAddPRDOPBusinessRule` → `clsProduct.UpdAddPRDOPBusinessRule` | 新增主列、寫 RuleXmlString、插入所有 Relation rows。 |
| 修改圖形 | `UpdEditPRDOPBusinessRule` → `clsProduct.UpdEditPRDOPBusinessRule` | 保留主鍵，先重建該產品/版本/OP 的 relation，再更新 XML。 |
| 刪除 OP 規則 | `DelPRDOPBusinessRule` → `clsProduct.DelPRDOPBusinessRule` | 刪除 Relation、規則主列；不支援 LONG 的環境同時刪 CLOB fallback 列。 |
| Default | `CopyBRFromOP` → `clsProduct.CopyBusinessRuleFromOP` | 先清除產品該 OP 現有規則，再複製 `TBLOPBASIS.RuleXmlString` 及 `TBLOPBUSINESSRULERELATION`。來源沒有規則時會清除產品規則。舊 Web Service 對 Core 複製呼叫有空 catch，API 不應吞掉錯誤。 |

Service 在 ADD/EDIT 解析圖形 XML 中非 Group 的 NodeNo 及所有 outgoing relations。LinkName 送入資料表前轉大寫。共用 `ChkRuleRelationValid` 驗證：

1. 必須且只能有一個 START，且至少有一個 END。
2. START 不可作為 ToNode；START 出線只能使用 PASS，且只能一條 PASS 出線。
3. END 不可作為 FromNode。
4. 每個一般 Rule Node 必須且只能有一條 PASS 出線，並至少有一條輸入線。
5. Draw Form 另要求每個 Rule Node 都在 Phase Group 內；`RuleAction`、From/To Node、非 START PhaseNo 不可缺。

舊 Draw Form 若提交時完全沒有 Node，會走清空 XML/Relation 的更新分支；本 Vue DEV 版選擇要求至少建立 START/END，清除整個 OP 設定請在主畫面 DEL。兩者操作語意有意識地不同，Production API 需在確認是否要支援「保留 OP 列但清空規則」後再定契約。

## Oracle 表與既有 SQL

此功能沿用 PD102 Parameter Setup 已唯讀查證的 Oracle 字典與 SQL 參照，不新增 Oracle 查詢、資料表或重複 CREATE SQL：

| Oracle 表 | 商業規則用途 | Oracle 欄位 / 主鍵 |
| --- | --- | --- |
| `TBLPRDOPBUSINESSRULE` | 產品/版次/OP 的圖形 XML | ProductNo VARCHAR2(50)、ProductVersion VARCHAR2(5)、OPNo VARCHAR2(20)、RuleXmlString LONG；PK `(ProductNo, ProductVersion, OPNo)`。 |
| `TBLPRDOPBUSINESSRULERELATION` | 圖中有向連線及來源 Phase | ProductNo、ProductVersion、OPNo、FromNode VARCHAR2(20)、ToNode VARCHAR2(20)、LinkName VARCHAR2(20)、PhaseNo NUMBER(2,0)；PK `(ProductNo, ProductVersion, OPNo, FromNode, ToNode, LinkName)`。 |
| `TBLPRDOPRULEXML_CLOB` | DB Provider 不支援 LONG 時的 Rule XML fallback | ProductNo、ProductVersion、OPNo 複合 PK，RuleXmlString CLOB；這是共用 fallback 表，非 Business Rule 專用新表。 |

三表 Oracle 字典未查到 FK 或額外索引；各自只有既有 PK 唯一索引。原始字典重建與 YMES 空表 CREATE-only 參照在：

- [Oracle source DDL](../../../database/reference/mestest_prd_parameter_setup_source_ddl.sql)
- [PostgreSQL CREATE-only 參照](../../../database/reference/mestest_prd_parameter_setup_create.sql)

CREATE SQL 僅供結構比對；家用端須先核對 YMES live schema/migrations，只對實際缺漏新增 forward migration。Oracle `LONG` 在 PG 對照用 `text`，但 Production API 仍要支援既有 XML 與 DB provider 的 fallback 語意。

Oracle 查詢紀錄見 [`DATABASE_CONNECTION.md`](../../DATABASE_CONNECTION.md) 的「PRD PD102 Parameter Setup Oracle 字典查詢」。該次以 PowerShell 5.1 + Oracle.ManagedDataAccess 直接查 MESTEST 字典；未讀業務列、未執行 Oracle DDL/DML、連線資訊未輸出或提交。DBMS_METADATA 呼叫遇 SocketException，欄位與 PK 由資料字典重建。

## YMES API handoff

目前 YMES 此功能尚無 Production API；`ProductBusinessRuleSetup.vue` 只在 DEV 預覽保存產品專用 localStorage。建議 API 使用產品/版次/OP 為 aggregate key，命名可配合 YMES 現有 route 慣例調整：

- `GET /api/products/{productNo}/versions/{version}/business-rules?opNo=`：回 OPNo、OPName、RuleXmlString、可供前端顯示的 Nodes/Relations。Server 依登入者 PS 權限篩選，不接受 client 傳 PSPrivilege。
- `POST /api/products/{productNo}/versions/{version}/operations/{opNo}/business-rule`：新增圖形。
- `PUT /api/products/{productNo}/versions/{version}/operations/{opNo}/business-rule`：以同一交易更新圖形 XML 與 relation rows。
- `DELETE /api/products/{productNo}/versions/{version}/operations/{opNo}/business-rule`：刪除主列、relations 及必要 CLOB fallback。
- `POST /api/products/{productNo}/versions/{version}/operations/{opNo}/business-rule/default`：用 OP Basis 的作業站規則覆寫產品規則；來源與錯誤都由 API 明確回報。
- 重用已存在的 Product Process、OP Basis、Business Rule、Phase、TemplateFlowBR 查找 API；NetFlow 編輯限制需由 OP lookup 回傳 IsNetFlow。不要為這些 lookup 建新表。

API 必須依已驗證的使用者、Function/PS 權限及 DB 重新讀取的 Product IssueState=0 執行修改；多筆寫入採 DB transaction，驗證 key 長度與關聯唯一性。圖形 JSON 只能作 YMES DTO，不能直接取代舊 MES `iMESXMLFlow.Serial.FlowToXML/XMLToFlow` 所使用的 RuleXmlString 格式。需實作往返 serializer 或經驗證的相容層，再接正式 API。

## 公司端 Vue DEV 範圍與限制

`web/src/components/ProductBusinessRuleSetup.vue` 已接入 PD102 `Business Rule` 按鈕。DEV 假資料可列 OP、Ctrl 多選/DEL、預覽流程、ADD/EDIT、節點及五種連線繪製、Phase 分組、Arrange/Top/Left、Template 假樣板、Default 假資料複製與刪除；寫入只保存至 `ymes.dev.prd-product-basis-relations.v1`。IssueState 非 0 或非 DEV 預覽時唯讀。

以下待 API/相容層完成前不可視為 MES 正式資料或完整等價：Business Rule/Phase/Process/OP/Template lookups 目前是 DEV 假資料；Default 是明確標示的 OP→DEV 樣板對照；畫面保存 JSON，不會產生舊版 XML；正式 API 尚未接線。NetFlow 編輯器鎖定支援 `isNetFlow` 欄位，但 DEV 假資料沒有載入正式 OP Basis 值。Phase Group 以 Rule Node 的 Phase 欄位和包圍框簡化呈現，不是 Lassalle AddFlow 的拖曳群組。

本階段只作 WinForms/Core/Service 與既有 Oracle metadata 的靜態核對；未執行 build、test 或 browser 驗收。
