# PD103 製程模組資料

## WinForms、Service 與 Core

- `PRD / MODULE BASIS`，Web 路徑 `/YMES/MasterData/ProductModules`。舊 Form 與內嵌 Designer 位於 `STD/MESWin/PRD/PD_ModuleBasis/frmModuleBasis.vb`、`frmModuleBasisDef.vb`、`frmModuleProcess.vb`。清單依狀態查詢，顯示模組主鍵、目前版、名稱、類別、PSNo、說明及稽核。
- `wsPRD.LoadModule`、`AddModule`、`EditModule`、`DelModule`、`ApproveModule`、`CopyModule` 使用 `TBLPRDMODULEBASIS` 與共用子表。`LoadModuleType` 依允許的區段從 `TBLPRDMODULEBASIS` 分組取得目前類別。主檔必填模組編號、版次、名稱、類別及區段。新增預設 `01`；修改鎖定模組編號與版次。
- `Version` 以 `IssueState=2 / CurVersion=1` 開啟；固定模組編號與類別，數字版次加一。可選同區段的其他模組版次複製明細。原 `ApproveModule` 檢查流程、排序、Business Rule 和作業區域，依簽核工作設定直接核准或送簽。核准須切換目前版。
- 流程 `Set …` 的 lookup 只顯示模組 PSNo 的流程。對每個 `ProcessNo` 只能加一次，最多一條預設流程，版次按目前版 `*` 或指定版保存。Confirm／Apply 以 `wsPRD.UpdModuleProcess` 整批儲存。`Expand All` 為唯讀結果。
- 共享子頁把 `ModuleNo/ModuleVersion` 傳作 `ProductNo/ProductVersion`，含 Property、Parameter、Business Rule、OPDescription、Recipe Group、Resource、Default、QC Item、SubOP。API 需區分產品與模組的權限及查詢上下文。
- `PD_ModuleDataImport` 讀 Process、Module Data、Module OP Data、OP Parameter、QC Item 五張工作表。Module Data 要求 `[Module Basis]`、`[Module Process]`、`[Module Property]`、`[Recipe Group]`，其餘標記見 Form。匯入呼叫 `DataImporter.ModuleDataImport.ModuleDataChecker`。

## 公司端 DEV 與家用端交接

- DEV 提供查詢、CRUD、複製／換版、目前版切換及上述子頁。流程、區段、類別、預設值和展開使用固定假資料；核准模擬直接核准，檢查流程及作業區域覆蓋。正式簽核、版本競爭、完整規則及 APS 仍待接入。
- DEV XLSX 匯入可檢查工作表區段、預覽流程並新增未核准模組主檔。流程與子表、`.xls`、公式重算、範本服務及取消待接入。
- Oracle 以 PowerShell 5.1 + ODP.NET 唯讀核對 `TBLPRDMODULEBASIS` 共 15 欄，主鍵 `(MODULENO,MODULEVERSION)`。`ISSUESTATE`、`CURVERSION`、`DATASTAMP` 預設值都是 `0`。附 [來源邏輯 DDL](../../../database/reference/mestest_prd_module_basis_source_ddl.sql) 與 [CREATE-only 比對](../../../database/reference/mestest_prd_module_basis_create.sql)。流程、屬性及作業表沿用 PD101／PD102 參考。
- 建議 `GET/POST /api/prd/modules`、`PUT/DELETE /api/prd/modules/{moduleNo}/versions/{moduleVersion}`，版次操作提供 `copy`、`version`、`approve` 與 `processes` 子資源。伺服器應檢查 PS 權限、狀態、DataStamp、複製來源及共用子表鍵；每組明細、換版及目前版切換在交易中完成。匯入先回傳檢查結果，按流程再模組順序交易式提交各群組。
