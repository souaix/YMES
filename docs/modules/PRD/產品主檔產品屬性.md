- 新增、編輯、複製：`STD/MESWin/PRD/PD_ProductProperty/frmProductPropertyDef.vb` 與 Designer。
- Web Service：`STD/MESws_STD/wsSTD/wsPRD/wsPRD.cs` 的 `LoadProductProperty`、`AddProductProperty`、`EditProductProperty`、`DelProductProperty`、`ApproveProductProperty`、`LoadProductPropertyDefine`。
- 資料庫邏輯：`STD/MESkc/kcPRD/clsProduct.cs` 的 ProductProperty CRUD/查詢，以及 SYS Element/Parameter 驗證。

## WinForms 清單視窗

`frmProductProperty` ClientSize 為 684×486。視窗標題 `Product Property`；頂端四個狀態選項 `UNFROZEN/PENDING/ACTIVE/UNUSED`，預設 UNFROZEN，分別篩選 IssueState `0/1/2/-1`。查詢 `Find` 按鈕在 Designer 設為隱藏，舊事件也已註解，不應顯示成可用功能。

Grid 在左側填滿並允許水平捲動；右側依序提供 `ADD`、`EDIT`、`DEL`、`Copy`、`Approve`，右下角為 `Close`。欄位順序與 WinForms 標題：

1. Product No（寬 150）
2. Product Version（100）
3. Property No（100）
4. Default Value（100）
5. Property Sequence（100）
6. Description（250，可多行）
7. Creator（80）
8. CreateDate（150，格式 yyyy/MM/dd HH:mm:ss）
9. Reviser（80）
10. ReviseDate（150，同日期格式）

IssueState、DataStamp 隨資料載入但隱藏；右鍵 Grid 不顯示通用變更簽核狀態選單。點列建立 ActiveRow，可 Ctrl/Meta 多選；Edit/Copy 使用 ActiveRow，Del/Approve 使用多選列；若沒有多選列，動作會將 ActiveRow 當作單筆。

## WinForms 定義視窗

`frmProductPropertyDef` ClientSize 為 496×276，標題 `Product Property Data Define` 並附 `(ADD)/(EDIT)/(Copy)`。中間 `Product Property Data` GroupBox 顯示：

- ProductType ProductNo：產品上下文，只讀。
- Version：產品版本，只讀；ProductType 情境可以空白。
- Property No：新增／複製可由 `...` 查找；編輯時查找按鈕停用且 PropertyNo 不可改。
- Property Value：DefaultValue；旁邊 `...` 依 PropertyNo 查 MES Parameter 有效值。
- Sequence：數字控制項，最大 99；Property Basis 查找會帶入 ElementSequence。
- Description：多行文字。
- Basis Data 稽核欄位：Creator/CreateDate/Reviser/ReviseDate，只讀。
- 底部 `Confirm`、`Close`、`Apply`。

Property No 查找呼叫 `LoadProductPropertyDefine(PropertyType=5)`，僅載入 IssueState=2 的 SYS Element。選取 ElementNo 時，Property Value、Sequence 帶入該 Element 的 DefaultValue、ElementSequence。Property Value 的 `...` 呼叫 `wsSYS.LoadElementValue(ElementNo)`；有有效 MES Parameter 值才開啟選單，無值時顯示訊息，文字欄位仍可手動輸入。

Confirm/Apply 檢查 ProductNo、PropertyNo；Sequence 必須是數字。新增/複製呼叫 Add，預設 IssueState=0；編輯僅允許 IssueState=0，送 IssueState 與 DataStamp 並保留 PropertyNo。編輯成功時 DataStamp 由資料層遞增。Apply 成功後保留視窗，Confirm 成功才關閉，Close 不送出未 Apply 的編輯。複製會帶入原列資料和建立人/日期，但新列 Creator/CreateDate 改為目前使用者/時間。

## 清單操作與簽核規則

- `ADD` 開啟空白定義視窗，帶入 ProductNo/ProductVersion。
- `EDIT` 只允許 IssueState=0。
- `Copy` 複製選取資料到新增模式；Property No 可重新查找。複製不沿用 IssueState、DataStamp 或原建立者資料。
- `DEL` 支援多選並逐列呼叫服務。狀態 0/-1 實體刪除；狀態 2 使用 DataStamp 將狀態改成 -1；狀態 1 禁止，遇到不允許狀態會停止後續列。Grid 操作需確認。
- `Approve` 支援多選但只允許 IssueState=0，逐列呼叫服務；任何其他狀態禁止。成功後重載資料。
- `ApproveProductProperty` 使用 IssueNo `PRD PROPERTY`。找不到簽核 Job，或 Job 沒有 Detail，會直接將屬性改成 ACTIVE (2)；有簽核設定時建立 Issue Master、暫存批准/退回 SQL、將狀態改為 PENDING (1)，由共用簽核 callback 完成後續狀態轉換並寄送第一關通知。
- Product Property 的 `Controlled` 不在 TBLPRDPRODUCTPROPERTY 欄位中，而來自 SYS Element Basis。Controlled=0 不控制；1 為 Check，核准產品時值空白會阻擋；2 為 Note，值空白會要求確認。產品主檔的 Controlled/CPASS 核准驗證應由 API 再查 SYS/產品流程資料，不接受 Vue 傳入的 Controlled 作為信任依據。

## Oracle 表欄位

`MESTEST.TBLPRDPRODUCTPROPERTY`：

| 欄位 | Oracle 型別 | 必填／用途 |
| --- | --- | --- |
| PRODUCTNO | VARCHAR2(50) | PK、必填 |
| PRODUCTVERSION | VARCHAR2(5) | PK、必填；ProductType/無版次情境使用其既有 sentinel |
| PROPERTYNO | VARCHAR2(20) | PK、必填 |
| DEFAULTVALUE | VARCHAR2(255) | 屬性預設值 |
| PROPERTYSEQUENCE | NUMBER(2,0) | 顯示順序 |
| DESCRIPTION | VARCHAR2(255) | 說明 |
| ISSUESTATE | NUMBER(1,0) | 必填，狀態 0/1/2/-1 |
| DATASTAMP | NUMBER(11,0) | DataStamp 樂觀併發欄位 |
| CREATOR | VARCHAR2(10) | 建立者 |
| CREATEDATE | DATE | 建立時間 |
| REVISER | VARCHAR2(10) | 修改/簽核者 |
| REVISEDATE | DATE | 修改/簽核時間 |

複合主鍵為 `(PRODUCTNO, PRODUCTVERSION, PROPERTYNO)`；目前 Oracle 字典未查得 FK 或 PK 外的索引。ProductNo 與 ProductVersion 範圍來自產品上下文，PropertyNo 由已核准 PropertyType=5 Element 查找。

- 資料只寫入 `ymes.dev.prd-product-basis-relations.v1`；正式 API 模式唯讀。

## 家用端 API / schema 接手

現有 Oracle 表已存在，先比較 YMES live schema/migrations；不要重建產品主檔已存在的 `TBLPRDPRODUCTPROPERTY` 等同名 API 模型，也不可直接執行 CREATE-only 參照。

- 提供 `GET/POST/PUT/DELETE /api/products/{productNo}/versions/{version}/properties` 與 `POST /api/products/{productNo}/versions/{version}/properties/{propertyNo}/approve`。List 查詢回傳產品/版本/屬性鍵、DefaultValue、Sequence、Description、IssueState、DataStamp、audit 欄位；控制值可作顯示/核准提示，但需由服務端重查 SYS Element。
- Add 寫入欄位限 ProductNo、ProductVersion、PropertyNo、DefaultValue、PropertySequence、Description；Creator/Date/IssueState/DataStamp 由登入身分/服務端設定。Edit 僅允許狀態 0、PropertyNo 不變，ProductNo+Version+PropertyNo+舊 DataStamp CAS，受影響列為零時回傳衝突。Sequence 對應 Oracle NUMBER(2,0)，WinForms 控制項範圍 0..99。
- Add/Edit 必須確認 Product/Property 定義存在，Property 定義限定 SYS `LoadElement(PropertyType=5, IssueState=2)`；對 DefaultValue 呼叫等價於 `ChkElementValueValid` 的服務端驗證。前端不能自行指定有效值清單或 Controlled。
- `LoadElementValue(ElementNo)` 對應的 MES Parameter 有效值需要 lookup API；Property Basis lookup 需提供 ElementNo、名稱、DefaultValue、ElementSequence 與受控規則 metadata。
- Delete 0/-1 實體刪除；ACTIVE(2) 用 DataStamp CAS 改 UNUSED(-1)；PENDING(1) 拒絕。多選逐筆操作需回報各鍵成功/失敗，符合舊程式遇到第一筆錯誤即停止。
- Approve 只接受狀態 0 並帶 DataStamp。簽核映射 `PRD PROPERTY` 無 Job 時即時轉 2；存在 Job 時建立共用 Issue Master/批准與退回 callback，轉 1 並通知簽核群組。由服務端寫 EventLog，不能以 Vue 的狀態變更代替。
- 產品主檔核准必須重新查 TBLPRDPRODUCTPROPERTY/SYS Element：Controlled=1 空值拒絕；Controlled=2 空值依 WinForms 確認規則處理；再執行流程 RulePhase/AttribPhase/CPASS 驗證。
- ProductType/無版本屬性的 PRODUCTVERSION sentinel、Oracle `''` 與空字串語意，需依現有資料和 YMES mapping 明確轉換。禁止把 `-1`、空字串、單一空白當作同義值自行推定。

API/schema 完成後，更新 `todolist_homepc.md` 實際 migration/API 狀態並回報公司端接正式服務；本 DEV 功能不要求新增 Oracle DDL。
