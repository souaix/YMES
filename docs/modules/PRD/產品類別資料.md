# PD101 產品類別資料

- MES 選單 `PRD / PRD TYPE`，Web 路徑 `/YMES/MasterData/ProductTypes`。主畫面與內嵌 Designer 位於 `STD/MESWin/PRD/PD_ProductTypeBasis/frmProductTypeBasis.vb`。新增、修改與複製視窗位於 `STD/MESWin/PRD/PD_ProductTypeDef/frmProductTypeDef.vb`。
- `wsPRD.LoadProductType` 讀取 `TBLPRDTYPE`。表格顯示 `ProductType`、`ProductTypeCode`、`Description` 及稽核欄。`EX_PRDTYPE1/2`、`IssueState` 與 `DataStamp` 欄隱藏於表格；DEV 以狀態篩選顯示未核准、簽核中、已核准、停用。
- `AddProductType`、`EditProductType`、`CopyProductType`、`DelProductType` 和 `ApproveProductType` 對應主畫面功能。類別必填、修改時類別鍵唯讀，核准不要求類別先定義流程。只允許 `0` 編輯或核准。刪除 `0/-1` 為實體刪除，`2` 轉成 `-1`，`1` 禁止。原 Service 的簽核、停用和修改轉交 `DataStamp`。
- `Set …` 與 `Property` 複用 `PD_ProductProcess`、`PD_ProductProperty`，類別代入 `ProductNo`，以 `ProductVersion='-1'` 存共用子表。`Parameter Setup` 需先有流程。原 `LoadProductProcess` 以 `PSPrivilege=True` 依區段權限查詢。
- DEV 提供查詢、批次核准／刪除、ADD／EDIT／Copy、Confirm／Apply 及三個子視窗。按類別保存假資料。Copy 複製流程、屬性及 DEV 參數，在同次本機儲存完成；舊 Service 另外複製 Recipe、Business Rule、Description、Area、QC Item、Sub OP 等共用設定，須在正式 Copy 接入。PD102 的 DEV 類別查找和工作簿匯入使用 PD101 已核准清單。

## Oracle 與家用端交接

- PowerShell 5.1 + ODP.NET 唯讀核對 `TBLPRDTYPE` 11 欄，主鍵 `PRODUCTTYPE`。沿用 [Oracle 邏輯 DDL](../../../database/reference/mestest_prd_product_type_source_ddl.sql) 和 [CREATE-only](../../../database/reference/mestest_prd_product_type_create.sql)。同次也核對流程／屬性表與 `TBLPRDOP`、`TBLPRDOPATTRIB`、`TBLPRDOPRULE`、`TBLPRDOPEQPRECIPE` 的欄數與鍵；沿用 [產品主檔](../../../database/reference/mestest_prd_product_basis_create.sql) 與 [參數設定](../../../database/reference/mestest_prd_parameter_setup_create.sql) 的 CREATE-only。
- 建議 `GET/POST /api/prd/product-types` 與 `PUT/DELETE /api/prd/product-types/{productType}`，另提供 `approve`、`copy` 與共用子資源。依工作站權限處理查詢與流程維護，依 `IssueState`、`DataStamp` 控制更新，在交易內建立完整副本或清理該類別自己的 `-1` 子資料。正式刪除前確認同名一般產品及參照處理，避免沿用舊 Core 單獨以 `ProductNo` 刪共用表的過寬條件。
