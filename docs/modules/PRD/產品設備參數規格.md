# PD102 產品設備參數規格（EquipmentSpec）

## WinForms、Service 與 Core

- `PD_ProductBasis_THEIL_BU1/frmProductBasis_THEIL_BU1.vb` 的 `btnEquipmentSpec_Click` 要求目前產品及流程列，查所選 PS 的 IsNetFlow，再傳 MOType、流程編號與版次給 `frmProductEquipmentSpec`。Form／Designer 位於同專案的 `frmPRDEquipmentSpec_THEIL_BU1*.vb`。
- 網狀流程呼叫 `wsWIP_NetFlow.LoadExpandProcess`，其他流程呼叫 `wsPRD.LoadExpandProcess`。逐作業站以 PS 權限載入 `wsPRD.LoadPRDOPArea`，再透過 `wsPRD.LoadAvailableEquipmentbyPRD` 取得設備。設備下拉清單去重。Core 路徑涵蓋產品作業區域、設備直掛與群組等共用關聯。
- 選擇設備後，`wsPRD.LoadProductEquipmentSpec`／`clsProduct.LoadProductEquipmentSpec` 由 `TBLEQPPARAMETERBASIS` 左連接該產品版次的規格。Grid 的 SeqNo、ParameterNo、SpecType 唯讀，數值欄全必填，必須符合 `MinValue < guideline_1 < guideline_2 < MaxValue`。
- Confirm 先驗表中每列，再呼叫 `wsPRD.UpdProductEquipmentSpec`，成功後留窗。Service 對明細逐列叫 Core，在產品版次、設備及參數範圍刪除舊值並寫入新值。來源允許前列成功後續列失敗，家用端正式 API 需明訂整批交易和並發語意。Close 關窗。

## Oracle metadata、Create SQL

- 使用 Windows PowerShell 5.1 + ODP.NET 唯讀核對 `TBLPRDEQUIPMENTSPEC` 和 `TBLEQPPARAMETERBASIS` 相關欄位。主表 `GET_DDL` 回 `ORA-03135`，以資料字典重建。只查 metadata。
- 主表 10 欄全為必填。四個數值欄皆為 `NUMBER(12,6)`。PK 為 `(PRODUCTNO, PRODUCTVERSION, EQUIPMENTNO, PARAMETERNO)`，只有 PK 唯一索引，字典未列外鍵或 trigger。設備目錄沿用 [既有參數主檔參照](../../../database/reference/mestest_equipment_parameter_basis_create.sql)。
- [Oracle 邏輯 DDL](../../../database/reference/mestest_prd_equipment_spec_source_ddl.sql) · [PostgreSQL CREATE-only](../../../database/reference/mestest_prd_equipment_spec_create.sql)

## Vue DEV 與家用端 handoff

- `ProductEquipmentSpec.vue` 依所選流程的 PS 從 DEV 產品 OP／區域關係找設備，並以固定設備類型參數做欄位疊加。DEV 以 PS 篩多筆 OP，未模擬網狀流程展開、設備可用狀態或正式權限。
- 四欄依 Oracle 精度及嚴格遞增順序驗證，先驗證完整清單再按設備存至該產品版次 DEV localStorage。設備切換重新載入其已儲存值。Production 提示 API 未接線，瀏覽器驗收待家用端執行。
- 依 live schema、migrations、first-phase 及參數主檔核對。建議登入保護的流程設備查詢、各設備參數規格 GET 與整批 PUT。伺服器重算流程／區域／設備與可用參數集合、校驗四值及精度、產生稽核值，並針對同一產品版次及設備確保原子性和並發一致性。
