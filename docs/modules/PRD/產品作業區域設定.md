# PRD PD102 產品作業區域（PD_ProductOPArea）

## WinForms 入口

PD102 的 frmProductBasis_THEIL_BU1.btnOPArea_Click (Handles btnResource.Click) 取得目前產品列的 ProductNo、ProductVersion、IssueState，透過 ObjectFileHandler("PD_ProductOPArea") 開啟 STD/MESWin/PRD/PD_ProductOPArea/frmProductOPArea。子功能不接收或顯示產品主檔欄位。

## 主畫面

- frmProductOPArea ClientSize 為 1008×591。
- 上方 Product OP 群組高 240 px，左側 UltraGrid、右側 ADD、EDIT、DEL。Find 按鈕在 Designer 中隱藏。
- 上方 Grid 隱藏 ProductNo、ProductVersion、AreaNo、DefaultArea，只顯示 OPNo。載入使用 wsPRD.LoadPRDOPArea，帶入產品編號/版次、DefaultArea=1、PSPrivilege=True；可見資料受登入者的 PS 權限範圍影響。
- 選取作業站列後，下方 Area Grid 載入該產品、版次、作業站的區域。隱藏產品編號、版次與作業站；顯示 AreaNo、DefaultArea。區域按 AreaNo DESC 排序，DefaultArea 使用 MES 的 Yes/No ValueList。
- 下方群組右側只有 Close。主畫面沒有核准或 Apply。
- IssueState != 0 時，WinForms 停用 ADD、EDIT、DEL。Edit 視窗固定目前 OP，不能從此視窗更換 OP。

### 主清單操作

- ADD：開啟 frmProductOPAreaDef 新增模式。成功後重載 OP 清單並選取新增 OP。
- EDIT：對目前作業站開啟定義視窗。成功後重載清單並選回該 OP。
- DEL：可選取多個 OP，一次確認後逐筆呼叫 wsPRD.DelPRDOPArea(ProductNo, ProductVersion, OPNo)；遇錯即停止，已成功的前筆不回復；只要有一筆成功便重載主/明細 Grid。此刪除以 OP 為範圍，會刪該產品版次該 OP 的區域設定。

## 新增／修改定義視窗

frmProductOPAreaDef ClientSize 為 784×561。上方顯示 Process No、Process Version、OP No 與查找按鈕；中間是 OP Area Map 雙 Grid；底部只有 Confirm、Close，沒有 Apply。

- 新增模式：wsPRD.LoadProductProcess(ProductNo, ProductVersion, PSPrivilege=True) 載入使用者可存取的產品流程。Process 查找顯示 ProductNo、ProductVersion、PSNo、ProcessNo、ProcessVersion、PSOrder、DefaultProcess、MOTypeNo。選取流程後呼叫 wsPRS.LoadNodeBasisJoinOP(ProcessNo, ProcessVersion, NodeType=0)；作業站查找依 ProcessNo 篩選。選 OP 後呼叫 wsOP.LoadOPResourceDefine(OPNo)，以 Area Basis 及該 OP 的 OP Area 對照初始化左右清單。
- 修改模式：隱藏 Process No、Process Version 及兩個查找按鈕，固定目前 OP；先載入目前產品版次 OP 區域，再載入區域主檔。已設定區域移至右側，其餘區域留在左側。
- 左 Grid 為未選區域，顯示 AreaNo、AreaName、FactoryNo；右 Grid 為已選區域，顯示 Select 勾選欄與上述三欄。AreaName、FactoryNo 是 lookup 顯示欄，不屬於產品區域關聯表。
- 左右 Grid 支援多選，以中間左右箭頭移動；雙擊列也會移動。兩側搜尋欄按 Enter 時，會以完整 AreaNo 將相符資料移至另一側。
- 每個已選區域的 Select 勾選用來標記 Default Area。Confirm 要求有 OP，且勾選數必須恰為一；零個或多個都會阻止儲存。
- Confirm 將所有選取 AreaNo 及其 DefaultArea 值組成 multivalue Area，呼叫 wsPRD.UpdEditPRDOPArea。新增與修改都呼叫同一個服務。原始碼註解指出以全刪全增更新才能避免錯誤；是否由服務端以交易原子執行，需家用端再查 Core/Service。

## 資料表與既有 SQL

| 用途 | MES Oracle 表 | 欄位／鍵 |
|---|---|---|
| 產品版次的 OP 區域設定 | TBLPRDOPAREA | ProductNo VARCHAR2(50)、ProductVersion VARCHAR2(5)、OPNo VARCHAR2(20)、AreaNo VARCHAR2(20) 為 NOT NULL；DefaultArea NUMBER(1,0) 可 NULL。複合 PK (ProductNo, ProductVersion, OPNo, AreaNo)。無 audit 欄、FK、trigger、額外 index。 |
| OP 的區域對照及新增預設值來源 | TBLOPAREA | OPNo VARCHAR2(20)、AreaNo VARCHAR2(20) NOT NULL；DefaultArea NUMBER(1,0) DEFAULT 0 可 NULL；Description VARCHAR2(255) 可 NULL。PK (OPNo, AreaNo)。 |
| 區域查找及顯示 | TBLSMDAREABASIS | 本功能顯示 AreaNo、AreaName、FactoryNo；共用區域主檔，不由 PD102 建立或擁有。 |

不用新增表或重複 CREATE SQL。既有 Oracle source DDL 與 PostgreSQL 空表參考：

- TBLPRDOPAREA：[Oracle source DDL](../../../database/reference/mestest_prd_parameter_setup_source_ddl.sql)、[PostgreSQL CREATE-only](../../../database/reference/mestest_prd_parameter_setup_create.sql)
- TBLOPAREA：[Oracle source DDL](../../../database/reference/mestest_operation_and_system_source_ddl.sql)、[PostgreSQL CREATE-only](../../../database/reference/mestest_operation_and_system_create.sql)
- TBLSMDAREABASIS：[Oracle source DDL](../../../database/reference/mestest_smd_area_basis_source_ddl.sql)、[PostgreSQL CREATE-only](../../../database/reference/mestest_smd_area_basis_create.sql)

CREATE-only 檔只供參照。家用端須先比對 YMES PostgreSQL live schema 與 migrations，不可直接重建既有表。

## Vue DEV 復刻

- ProductResourceSetup.vue 接至 PD102 的 Resource 按鈕。主畫面沿用 1008×591 結構；定義窗沿用 784×561 結構及區域雙 Grid、箭頭、Default Area 勾選、Confirm/Close。
- DEV 有流程、OP、Area lookup 假資料；支援多選移動、雙擊移動、AreaNo Enter 精確搜尋、多選 OP 刪除及 Default Area 驗證。
- 關聯假資料存入產品主檔既有 ymes.dev.prd-product-basis-relations.v1 localStorage 的 opAreas，不建立第二份產品關聯儲存，也不送到正式 API。
- Production API 尚未接線，正式模式唯讀。現有產品流程、OP 與 Area 選項不代表正式查找結果。

## 家用端待核對事項

目前可見 WinForms client 呼叫及 table schema，但不能由 client 單獨證明 Core/Service 實作細節。家用端需確認：

1. LoadPRDOPArea 的 DefaultArea=1 篩選、OP 清單與 PS 權限條件，以及 detail 查詢的實際回傳欄位。
2. LoadOPResourceDefine 的 Area Basis/OP Area 規則；新增預設帶入 TBLOPAREA 的哪些列，以及 Area 查找的 factory/authorization 範圍。
3. UpdEditPRDOPArea 的全刪全增是否在同一 DB transaction、空 multivalue 的處理方式、DataStamp/並行控制。
4. DelPRDOPArea 是否只刪指定產品、版次、OP 的列，以及產品 Copy/Version 是否呼叫 CopyPRDOPArea。

## API/schema handoff 要求

- GET 產品版次的 OP Area 清單及 OP 明細；查詢與 lookup 的 PS 權限由登入者決定，不信任 client 傳來的 PSPrivilege、IssueState。
- 提供產品流程 lookup、流程 OP (NodeType=0) lookup、OP Area lookup 及 Area Basis lookup；重用現有 PRS、OP、SMD 資料/API，不另建同義表。
- 以產品、版次、OP 為範圍的 PUT 全量取代該 OP 的區域設定；payload 至少含 AreaNo、DefaultArea。單一請求須交易原子更新、拒絕重複 AreaNo，並重新驗證產品狀態、OP/PS 權限、Area 存在及恰一個預設區域。
- DELETE 必須明確限定 ProductNo、ProductVersion、OPNo，刪除該 OP 的全部產品區域關聯。多選呼叫逐筆處理；遇錯停止並保留前筆已成功結果。
- 表中沒有 DataStamp 或 audit 欄位，不得新增此表不存在的欄位。跨表驗證及更新交易依 Core/Service 查核結果落實。
