# PRD PD102 產品程式指派（Program）

## 識別資訊

| 欄位 | 值 |
| --- | --- |
| 第一層 | 產品資料（PRD） |
| 主功能 | PD102 產品主檔內的 Program 子功能，沒有獨立第三層功能項 |
| WinForms Form | `PD_ProductBasis.frmProductProgram` |
| Web 元件 | `ProductProgramSetup.vue`，由 PD102 Program 按鈕開啟 |
| 實作狀態 | 公司端 DEV UI 與假資料流程完成；Production API/schema 待家用端 |

## WinForms 入口與畫面

PD102 `btnProgram_Click` 從作用中的產品列帶入 `ProductNo`、`ProductVersion`、`IssueState`，以 modal 開啟 `frmProductProgram`。按鈕入口沒有額外 `IssueState` gate。

- 標題 `Product Program`，ClientSize 684×486，置中顯示。
- 上方 Product No、Product Version 是唯讀欄位。
- `Programs` 群組內為單一可勾選 Grid，沒有新增、修改、刪除、搜尋或版本選擇按鈕。
- 可見欄位：Select checkbox、ProgramNo、ProgramType、Description；其他來源欄位隱藏。
- 底部只有 Confirm、Close；沒有 Apply 或 audit 區。
- Form 載入時呼叫 `LoadProductProgramsDefine`，一次載入 Program Basis 與目前產品版次的 Program 關聯。所有 Program Basis 列均供清單選擇，來源呼叫 `LoadProgram()` 未指定 IssueState 篩選。
- 已指派列依 ProgramNo 對應並勾選。Grid `AllowUpdate=True`；當產品 IssueState 不為 0 時，Confirm 停用，但 Grid checkbox 本身仍可暫時切換，關閉後不保存。

## 確認與資料更新

Confirm 收集目前勾選的 ProgramNo，呼叫 `wsPRD.UpdProductProgram`，Core `clsProgram.UpdProductPrograms` 會先刪除該 ProductNo/ProductVersion 的所有 `TBLPRDPRODUCTPROGRAMS` rows，再插入整份勾選清單，並透過 `ExecuteSQLNoneQuery_UPD` 執行 SQL collection。空清單也會執行刪除，所以代表清除該產品版次的所有 Program 指派。成功提示後關閉視窗；Close/X 不儲存。

Program Basis 候選列由 `TBLPRDPROGRAMBASIS` 提供，沒有在此 Form 過濾 IssueState。產品版次關聯表只有 ProductNo、ProductVersion、ProgramNo 三欄，沒有 audit/DataStamp 欄位。

## Oracle 結構

| Oracle 表 | 欄位與 PK |
| --- | --- |
| `TBLPRDPROGRAMBASIS` | ProgramNo VARCHAR2(50) NOT NULL PK；ProgramType VARCHAR2(10) NULL；IssueState NUMBER(1,0) DEFAULT 0 NOT NULL；Creator VARCHAR2(10) NULL；CreateDate DATE NULL；Description VARCHAR2(255) NULL |
| `TBLPRDPRODUCTPROGRAMS` | ProductNo VARCHAR2(50)、ProductVersion VARCHAR2(5)、ProgramNo VARCHAR2(50) 全部 NOT NULL；複合 PK `(ProductNo, ProductVersion, ProgramNo)` |

兩表各有 PK unique index；沒有 FK、trigger 或額外 index。雖然關聯表的 ProgramNo 對應 Program Basis，Oracle 未建立 FK。

- Oracle source DDL：`database/reference/mestest_prd_program_source_ddl.sql`
- PostgreSQL CREATE-only 對照：`database/reference/mestest_prd_program_create.sql`

`tblprdprogrambasis` 已出現在 YMES first-phase bootstrap SQL。家用端需先比對 live schema 和 migration；不可重建既有主檔，也不可因 CREATE-only reference 直接執行。只有確認關聯表或必要欄位不存在時才新增 forward migration。

## Vue DEV 復刻

`ProductProgramSetup.vue` 依 684×486 ClientSize 還原產品編號/版次、Programs 群組、四欄 Grid 與 Confirm/Close。DEV 可勾選/取消程式並以 Confirm 全量保存至產品關聯 localStorage。遵循舊畫面狀態行為：產品 IssueState 非 0 時仍可暫時切換 checkbox，但 Confirm disabled。Production API 尚未接線時只讀。

假資料限定 `import.meta.env.DEV && developmentPreview`，不呼叫正式 API、不寫正式資料庫。

## 家用端 API/schema handoff

1. 先 pull 最新 main，檢查 YMES live PostgreSQL schema、first-phase bootstrap、migration、既有 Program API/entity。`tblprdprogrambasis` 已在 bootstrap；先核對實際欄位是否吻合 Oracle，不可建立重複主檔。關聯 `tblprdproductprograms` 僅在 live schema 確認不存在時新增。
2. 提供登入保護的 Program options GET 與指定產品/版次 assignments GET；候選清單要依 WinForms 保留不過濾 Program IssueState 的行為。回傳欄位至少包含 ProgramNo、ProgramType、Description。
3. 提供 `PUT /api/products/{productNo}/versions/{version}/programs` 以完整清單取代關聯；在同一 transaction 內刪除該產品版次舊指派並新增新清單。空陣列表示清空。驗證每個 ProgramNo 存在、去重並驗證登入者有該產品版次的設定權限。
4. 只允許產品 IssueState=0 儲存，依伺服器的產品狀態與使用者權限驗證；不信任 client 傳來的 IssueState、產品識別或權限資訊。UI 舊行為在非 0 狀態仍可勾選但 Confirm disabled。
5. Program Basis 有獨立主檔功能，不在 PD102 子窗格新增/編輯主檔。完成 API/schema/migration 與文件後 push main，通知公司端接上正式 API。
