# PRD PD102 產品作業站子工序設定（SubOP）

## 識別資訊

| 欄位 | 值 |
| --- | --- |
| 第一層 | 產品資料（PRD） |
| 主功能 | PD102 產品主檔內的 SubOP 子功能，沒有獨立第三層功能項 |
| WinForms Form | PD_PRDSubOP.frmPRDSubOP |
| Web 元件 | ProductSubOpSetup.vue，由 PD102 SubOP 按鈕開啟 |
| 實作狀態 | 公司端 DEV UI 與假資料流程完成；Production API/schema 待家用端 |

## WinForms 入口與權限

PD102 的 frmProductBasis.btnSubOP_Click 取得作用中的產品列，傳入 strPRDNo、strPRDVer、strfromModule="PRD" 給 ObjectFileHandler("PD_PRDSubOP")。此子表單沒有接收 IssueState；按鈕事件也沒有依 IssueState 限制開啟。按鈕仍受共用功能權限控制。Web 不應自行為此子功能套用產品主檔的未核准狀態限制；API 仍須驗證登入者、產品與作業站 PS 權限。

Form 另支援 Module 來源：切換 Module No/Version 標籤；本次 PD102 入口固定使用產品編號/版次。

## 欄位與驗證

| 欄位 | 必填 | 來源／操作 |
| --- | --- | --- |
| ProductNo | 是 | PD102 作用中產品列；唯讀 |
| ProductVersion | 是 | PD102 作用中產品版次；唯讀 |
| OPNo | 是 | 新增時由 Lookup 從該產品已設定、且使用者有 PS 權限的產品 OP 選擇；修改/插入固定作用列 OP |
| SubOPSequence | 是 | ADD 為同產品/版次/OP 最大序號 + 1；INSERT 使用作用列序號並前移後續列；EDIT 固定作用列序號 |
| SubOPNo | 是 | 使用者輸入，VARCHAR2(20) |
| SubOPName | 是 | 使用者輸入，VARCHAR2(100) |
| Creator / CreateDate | 否 | 新增/插入由登入者與目前時間寫入；EDIT 保留 |
| Reviser / ReviseDate | 否 | EDIT 由登入者與目前時間寫入 |
| DataStamp | 否 | 隱藏；EDIT 傳目前值做並行版本檢查，資料表允許 NULL、DEFAULT 0 |

Confirm 僅檢查 OPNo、SubOPNo、SubOPName 不可空。表格限制 SubOPSequence 為 NUMBER(4,0)，PK 限制同一產品版次/OP 下序號唯一；WinForms 未見另外的輸入長度與重複編號驗證。

## 按鈕與操作流程

| 按鈕 | 操作 |
| --- | --- |
| ADD | 保留作用列 OPNo（若有），序號設為該 OP 最大值 + 1；清空 SubOPNo/Name，寫入 Creator/CreateDate。OP Lookup 可改選本產品的其他 OP。 |
| INSERT | 必須先有作用列；複製該列 OPNo 與 SubOPSequence，清空 SubOPNo/Name。儲存時將同 OP、序號 >= 插入點的資料序號加 1，再新增。 |
| EDIT | 固定 ProductNo/ProductVersion/OPNo/Sequence，只能修改 SubOPNo、SubOPName；保留建立資訊，更新修改資訊與 DataStamp。 |
| DEL | 未選取時以作用列為目標；可多選，一次確認後逐筆刪除。服務遇錯停止且保留此前已成功的刪除；成功至少一筆後呼叫 SortPRDOpSubOp，再重載清單。 |
| Cancel | 不寫資料，還原目前作用列內容並離開編輯模式。 |
| Confirm | 驗證三個必填欄位；ADD/INSERT/EDIT 立即寫入並重載資料、定位資料列。Apply 隱藏。 |
| Close | 關閉子表單。 |

刪除後 wsPRD.SortPRDOpSubOp 會載入該產品版次 Product OP，對每個 OP 呼叫 Core 排序；依原序號重新編成 1..N。INSERT 的序號前移與新增由 ExecuteSQLNoneQuery_UPD 一起提交。多列刪除不是全批次回復：WinForms 逐筆呼叫刪除，遇錯停止，成功部分保留，再執行排序。

## Service/Core 邏輯

- 主清單：wsPRD.LoadPRDOpSubOp → clsProduct.LoadPRDOPSubOP(ProductNo, ProductVersion)，讀取 TBLPRDOPSUBOP，並在畫面依 OPNo/Sequence 排序。
- 作業站 Lookup：wsPRD.LoadPRDOP(ProductNo, ProductVersion, PSPrivilege=True)；COM Search 只顯示目前 ProductNo/ProductVersion 的 OPNo。PSPrivilege 是 WinForms 呼叫參數；新 API 必須依登入者權限在 server 計算，不接受 client 自傳。
- Add：wsPRD.AddPRDOpSubOp → clsProduct.AddPRDOPSubOP；寫產品/版次/OP/序號/子工序編號名稱及建立者日期。
- Insert：wsPRD.InsertPRDOpSubOp → Core 先把相同產品/版次/OP 的 Sequence >= 目標值加 1，再新增；SQL collection 以 ExecuteSQLNoneQuery_UPD 執行。
- Edit：wsPRD.EditPRDOpSubOp → clsBasis_UPD.EditPRDOPSubOP；以 ProductNo、ProductVersion、OPNo、Sequence、DataStamp 作更新條件；寫入 Reviser/ReviseDate，DataStamp 非預設值時遞增。UI 隱藏 DataStamp。
- Delete：wsPRD.DelPRDOpSubOp → Core 以產品/版次/OP/Sequence 刪單列。UI 多選逐筆呼叫。
- Sort：wsPRD.SortPRDOpSubOp 查出該產品版次 OP 清單，逐 OP 呼叫 clsProduct.SortPRDOPSubOP 以 row_number 重排。
- PD102 SubOP 按鈕沒有依 IssueState 停用；子表單也未接 IssueState。API 應保留這項舊行為，除非另有明確規則。
- 本節描述舊 WinForms Service/Core，不代表已部署 YMES API。

## Oracle 資料表

PD102 子表單 CRUD 使用 MESTEST.TBLPRDOPSUBOP。WinForms 標頭也列 TBLOPSUBOPBASIS，但本子表單 Load/CRUD 實際指向產品關聯表；OP 主檔子工序表由 OP 功能及產品 Default/import 等流程使用，勿混為一張。

| 欄位 | Oracle 型別 | NULL / DEFAULT | 用途 |
| --- | --- | --- | --- |
| PRODUCTNO | VARCHAR2(50) | NOT NULL | 產品編號 |
| PRODUCTVERSION | VARCHAR2(5) | NOT NULL | 產品版次 |
| OPNO | VARCHAR2(20) | NOT NULL | 作業站 |
| SUBOPSEQUENCE | NUMBER(4,0) | NOT NULL | 子工序序號 |
| SUBOPNO | VARCHAR2(20) | NOT NULL | 子工序編號 |
| SUBOPNAME | VARCHAR2(100) | NOT NULL | 子工序名稱 |
| CREATOR | VARCHAR2(10) | NULL | 建立者 |
| CREATEDATE | DATE | NULL | 建立日期 |
| DATASTAMP | NUMBER(11,0) | NULL，DEFAULT 0 | 並行版本 |
| REVISER | VARCHAR2(10) | NULL | 修改者 |
| REVISEDATE | DATE | NULL | 修改日期 |

複合 PK：(PRODUCTNO, PRODUCTVERSION, OPNO, SUBOPSEQUENCE)。字典查得 6 個 NOT NULL constraint 與 1 個 PK unique index；無 FK、trigger 或其他 index。Oracle source DDL 與 PostgreSQL 空表 CREATE-only 參考：

- Oracle source DDL：database/reference/mestest_prd_subop_source_ddl.sql
- PostgreSQL CREATE-only：database/reference/mestest_prd_subop_create.sql
- 共用作業站子工序主檔沿用 database/reference/mestest_operation_and_system_source_ddl.sql 與 database/reference/mestest_operation_and_system_create.sql，不重複建立。

## 家用端 API/schema handoff

1. 先比對 YMES PostgreSQL live schema、現有 migration/API；即使 CREATE-only 檔存在，也只在確認缺表後新增 migration。Oracle 表 DDL 已由公司端 PowerShell 5.1 + ODP.NET 直連唯讀取得。
2. 專用表為 tblprdopsubop。不要另建同義表，也不要與 OP master tblopsubopbasis 混用；後者沿用現有 OP migration/reference。
3. 提供產品/版次 SubOP GET、尾端新增、指定序號修改、指定序號插入、多選/單列刪除及序號排序。插入須在一致交易內先移動後續序號再新增。刪除明確限定 ProductNo/ProductVersion/OPNo/Sequence；legacy 多選逐筆刪除、錯誤停止、已成功項目保留。
4. Product OP 查找重用 LoadPRDOP(..., PSPrivilege=True) 的權限範圍。PS 權限由登入者在 API server 計算；不得信任 client 自傳 PSPrivilege、IssueState、Creator/Reviser、DataStamp 更新值或任意 OPNo。
5. EDIT 以 DataStamp 作 optimistic concurrency 並回傳衝突；確認 nullable DataStamp 遺留資料處理，不可將 nullable 欄位誤轉 NOT NULL。Insert/Sort 僅更動 Sequence 的 legacy 行為也要保留。
6. 此表沒有 IssueState/Approval 欄；子表單未傳 IssueState、沒有核准流程。除非另有明確業務規則，維持舊操作範圍。
7. API/schema 完成後 push main，通知公司端 pull 並核對 Production API、錯誤及交易行為。
