# PD102 產品標準工時（RunTime）

## WinForms、Service 與 Core

- 產品主檔 `PD_ProductBasis_THEIL_BU1/frmProductBasis_THEIL_BU1.vb` 的 `btnRunTime_Click` 取目前選取列，經 `ObjectFileHandler.Execute("PD_ProductRunTime", ...)` 傳入 ProductNo、ProductVersion、IssueState。入口只要求選取產品，沒有 Default 按鈕的流程前置檢查。此入口載入 `STD/MESWin/PRD/PD_ProductRunTime/frmProductRunTime.vb` 及 `frmProductRunTimeDef.vb`，Designer 程式在各自的 `InitializeComponent`。
- 本功能對應 `Customer/Production/MESws_STD/wsSTD/wsPRD/wsPRD.cs` 的 `LoadProductRunTimeDefault`、`LoadProductRunTimeSetup`、`UpdProductRunTimeSetup`，三者呼叫 `STD/MESkc/kcPRD/clsProduct.cs` 的同名方法。`clsProductRunTime` 的 `*New*` 方法和 `PD_RunTimeSetup_THEIL_BU1` 是另一條功能路徑。
- 主窗先載入預設列和已儲存設定，依 AreaNo、OPNo、EquipmentNo、EquipmentType 套回六個數值，再按 OPOrder 由小到大顯示。設定表中的 OPOrder 值由 `TBLOPBASIS` join 得到。已儲存但不再對應預設清單的列不會在主表顯示。
- 預設 OP 數值來自 `TBLPRDOPAREA` 與 `TBLOPBASIS`。每個區域從 `TBLSMDAREARELATION` 展開直接設備（ObjectType 2）和設備群組（ObjectType 4，經 `TBLEQPGROUPDETAIL`），透過 `TBLEQPEQUIPMENTBASIS` 取設備型態，再由 `TBLEQPEQUIPMENTTYPE` 取設備類型工時。來源使用 `UNION ALL`，設備同時直掛與屬於群組時可能重複。沒有設備時，產生 EquipmentNo、EquipmentType 皆為 `N/A` 的一列，設備兩種工時為 0，CountEqpUnitQty 為 1。
- 主 Grid 可直接編輯 StdUnitRunTime、CountOpUnitQty、StdQueueTime、StdUnitEmpTime、StdUnitEQPTime、CountEqpUnitQty。EDIT 開啟單列定義窗，分為 OP RunTime 和 Equipment RunTime，`N/A` 時後者停用。工時單位為分鐘，定義窗工時允許 0，數量至少為 1。行身分欄位唯讀。
- Apply 送出畫面全量清單後留在主窗，Confirm 成功後關窗。Core 拒絕空清單，依 ProductNo、ProductVersion 批次刪除舊列並重建，Creator/CreateDate 由 Service 的使用者及伺服器受理時間填入。主窗會提示首次未套用或未儲存變更。RunTime Form 及上述三支 Service/Core 路徑未就傳入的 IssueState 設定專屬守門，Form 仍呼叫 `ExeGroupControlPriv`。
- 產品 Copy 的 Service 另會呼叫 `CopyProductRunTimeSetup`。刪產品版次及刪除個別產品 OP／區域也有清理 RunTime 的 Core 路徑。這些正式串接由家用端核對產品生命週期後一併驗證。

## Oracle metadata 與 SQL 參照

- 2026-11-18 以 Windows PowerShell 5.1 及 ODP.NET 使用桌機受保護 profile 登入 MESTEST。`DBMS_METADATA.GET_DDL` 查 `TBLPRDRUNTIMESETUP` 回 `ORA-03135`，因此以 `ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_CONS_COLUMNS`、`ALL_INDEXES`、`ALL_IND_COLUMNS`、`ALL_TRIGGERS` 重建邏輯 DDL。只讀資料字典。
- `TBLPRDRUNTIMESETUP` 有 20 欄和 10 個具名 `NOT NULL` 條件。資料字典沒有回傳 PK、unique key、FK、索引或 trigger。EquipmentNo、EquipmentType 可為 NULL。四個工時為 `NUMBER(6,2)`，兩個數量為 `NUMBER(6,0)`。Fix/Var Emp/Eqp time、WorkPriceType、WorkPrice 在表內但這支 PD102 更新方法沒有傳入，在來源批次重建時走欄位預設或 NULL。
- 已核對六張 lookup 表的相關欄位及索引。`TBLPRDOPAREA` 主鍵依序是 ProductNo、ProductVersion、OPNo、AreaNo。`TBLOPBASIS`、`TBLEQPEQUIPMENTBASIS`、`TBLEQPEQUIPMENTTYPE` 的主鍵各為 OPNo、EquipmentNo、EquipmentType。`TBLEQPGROUPDETAIL` 主鍵是 EquipmentGroup、EquipmentNo。`TBLSMDAREARELATION` 主鍵是 BaseAreaNo、ObjectNo，另有 ContainAreaNo、ObjectType 非唯一索引。這些是既有共用依賴，家用端比對 live schema 後沿用。

## Vue DEV 與驗收界線

- `ProductBasisMaster.vue` 的 RunTime 按鈕開啟 `ProductRunTimeSetup.vue`。DEV 由該產品版次的 Resource 假資料搭配固定的 OP／區域設備目錄產生預設列，並疊加已儲存的 RunTime。固定目錄簡化了 Oracle 的區域／群組展開，涵蓋多設備及 `N/A`，未模擬重複設備列。
- 支援表格編輯、EDIT 定義窗、稽核欄、Apply 留窗、Confirm 關窗及未儲存關閉提示。Web 在兩條編輯路徑統一驗證數值和 Oracle 精度，工時限制為 0–9999.99（最多兩位小數），數量限 1–999999 的整數。空清單無法儲存。
- DEV 僅保存到 `ymes.dev.prd-product-basis-relations.v1` 該產品版次的 `runTime`。未接正式 API 時展示未接線狀態。`vue-tsc --noEmit`、`git diff --check` 與 SQL 參照欄順序核對通過，瀏覽器與正式 API 驗收待家用端執行。

## 家用端 API、schema 與 Create SQL handoff

1. 先對照 YMES live schema、first-phase bootstrap 和 migration history，確認 `tblprdruntimesetup` 及六張共用 lookup 表。只補必要的 schema 差異。來源 RunTime 表沒有 PK 或 unique 約束，需先用 YMES 資料確認重複及 NULL／`N/A` 語意，才決定 API 去重策略及是否另設索引。CREATE-only 參照只供核對。
2. 建議 `GET /api/products/{productNo}/versions/{version}/run-time` 回傳 OPOrder、四個識別欄位和六個工時／數量欄位，沿用原生預設展開及已保存覆蓋的邏輯。Creator/CreateDate 如需回傳應從伺服器取值。對應 API 全路徑在 `/YMES/API` 下。
3. 建議同路徑 `PUT` 接完整、非空的列陣列，從 route 限定產品版次。以登入者及功能權限授權，從伺服器重算可用 OP／區域／設備、驗證欄位範圍和資料精度，審核資料由伺服器填入。避免允許過期或偽造的清單重建其他版次。舊方法批次替換未包含 Fix/Var、WorkPrice 欄，實作前須和共用的新版工時或計價流程確認此類欄位是否必須保留。
4. 先驗證完整請求，再以單一 transaction 在目標產品版次全量替換。對同版次的並發寫入須有序列化或等效的衝突處理，不能讓兩次刪除及寫入互相穿插。驗收至少涵蓋無設備、群組重複、首次設定、預設與覆蓋合併、空陣列拒絕、精度邊界、失敗回滾、並發、Copy／刪除與權限。
