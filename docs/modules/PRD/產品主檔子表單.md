# PRD PD102 產品流程與 BOM 子表單複刻

## 程式來源

- 產品流程：`STD/MESWin/PRD/PD_ProductProcess/frmProductProcess.vb`，服務端入口 `wsPRD.UpdProductProcessbyUser`。
- 產品 BOM：`Customer/Production/MESWin/PRD/PD_ProductBasis_THEIL_BU1/frmProductBOM_THEIL_BU1.vb`，服務端入口 `wsPRD.AddBOM`、`EditBOM`、`DelBOM`；替代料使用 `frmMaterialSubstitute`。
- Oracle 結構證據：`database/reference/mestest_prd_product_basis_source_ddl.sql`，主要表為 `TBLPRDPRODUCTPROCESS`、`TBLPRDBOM`、`TBLPRDBOMMATERIALGROUP`。

## 產品流程設定 `PD_ProductProcess`

WinForms 視窗大小 544×462。上方固定顯示 ProductNo/ProductVersion；資料區欄位為 MOType No、PS. No、PS. Order、Process No、ProcessVersion Current/Specified、Default Process Yes/No，按 `ADD` 加入暫存表；下方表格顯示 MOTypeNo、PSNo、PSOrder、ProcessNo、ProcessVersion、DefaultProcess、HaveComponent、HaveLevel、EquipmentGroup，可選取後 `DEL`。底部為 `Confirm`、`Close`、`Apply`。

- MOType、Production Segment、該 PS 下的 Process 以查找視窗選取；選 PS 後會帶入 PSOrder 並清除舊 Process。
- Current 儲存 ProcessVersion `*`；Specified 儲存選取到的明確版本。
- ADD 必填 MOType、PS、Process、版本模式、Default 選項；同一 MOType/PS/Process 不可重複，同一 MOType/PS 只允許一筆 Default Process。
- ADD/DEL 只改暫存明細。Apply 將整批現有與刪除的流程鍵送 `UpdProductProcessbyUser`，成功後保留視窗；Confirm 同樣送出，成功才關閉；Close 不送出尚未 Apply 的修改。
- Confirm 會檢查 Net Flow：Net Flow Production Segment 不可與其他 Production Segment 同時存在。
- 新增流程預設 Default=Yes；表格按 PSOrder、DefaultProcess DESC 排序。流程定義從核准的 Production Segment/Process 查找資料取得。

DEV Vue：`web/src/components/ProductProcessEditor.vue`。目前以 DEV 選項操作流程 ADD/DEL、版本模式、預設流程唯一性及 Net Flow 檢查；Apply/Confirm 寫入 DEV 專用 localStorage。正式 API 模式唯讀，避免未完成的 API 造成正式資料假成功。

## BOM 設定 `frmProductBOM_THEIL_BU1`

視窗大小 719×516。左側 304px BOM Tree，右側 413px Node Define。Tree 根節點右鍵只提供 Add；根層直接 BOM 節點右鍵提供 Edit、Del、View；只有直接層且 NodeType=Material、Specified=No 可 Set Substitute MTL。產品節點下的遞迴節點及替代料群組只供檢視。Tree 遞迴最多五層；同層排序 NodeType DESC（產品節點先、材料節點後）。材料文字為深紅、產品藍色、材料群組綠色。

Node Define 欄位：Product/Material、ProductNo 或 MaterialNo、Product Version Current/Specified、Input OPNo、Standard Use Qty、UnitNo、Decrease Rate (%)、Put In Place Type (WIP INV/MO)、Specified (No/Yes)、Description、Creator、CreateDate；操作按鈕 Confirm、Apply、Cancel，外層另有 Refresh、Close。

- 產品節點 NodeType=1；Current 寫 NodeVersion=`*`，Specified 寫明確產品版次。材料節點 NodeType=0、NodeVersion=`N/A`。
- 投料點寫入代碼：材料 WIP INV=2、產品 WIP INV 半成品=4、MO=3。
- Product/Material 查找只載入已核准資料，選取時帶 UnitNo 與預設投料點；Input OPNo 從產品流程作業站及 LOTCREATE 查找。
- 新增/修改必須選節點型別與料號、Input OPNo、投料點、Specified；Standard Use Qty 為數字且 >=0；Decrease Rate 為數字。相同 NodeNo+OPNo 不可重複。
- LOTCREATE 只能搭配 MO；Product 節點不可選 LOTCREATE；非 TS 企業的批號檢查材料不可在 LOTCREATE 投料。
- Apply 寫入目前 BOM 節點並保留視窗；Confirm 寫入並清除 Node Define 編輯狀態；Cancel 清除尚未送出的編輯。Del 直接刪除 BOM 節點與其替代料群組。替代料群組由 `TBLPRDBOMMATERIALGROUP` 保存。
- 樹文字呈現 NodeNo/Version、OPNo、StdQty/UnitNo、損耗率百分比、Specified 與 Description。產品節點再依該產品版次遞迴展開。

DEV Vue：`web/src/components/ProductBomEditor.vue`。提供右鍵樹選單、核准產品/假材料查找、節點增修檢視刪除、替代料選取、欄位檢核與五層樹；Apply/Confirm/Del/替代料寫入只更新 DEV 專用 localStorage。正式 API 模式唯讀。材料、操作站選項目前是明確標示的 DEV 假資料，不能當正式 lookup。

## 家用端 API/schema 接手

- 先比對 YMES migration/live schema 及 Oracle DDL，勿重複建立 `ym_product_process`、`ym_product_bom`；目前兩表模型不能代表 Oracle 預設流程、材料群組及巢狀 BOM 全語意。
- 流程 API 需支援查核准 MOType/PS/Process 選項，以及以產品版次為範圍的整批儲存；欄位保留 MOTypeNo、PSNo、PSOrder、ProcessNo、ProcessVersion (`*` current)、DefaultProcess、HaveComponent、HaveLevel。服務端驗證複合鍵唯一、每個 MOType/PS 唯一 Default、Net Flow 唯一段規則。
- BOM API 需支援節點查詢/新增/修改/刪除、已核准 Product/Material/OP lookup、PutInPlaceType 2/3/4、指定料、損耗率、遞迴五層樹與材料群組 CRUD。刪除節點時須按 WinForms 邏輯處理該節點的替代料群組。
- LOTCREATE 規則須服務端重驗，不能只依賴 Vue；核准狀態也由 server 查詢，不接受 client 宣告。
- 原始 DDL / API 完成後更新 `todolist_homepc.md`，再由公司端把 DEV component 接正式 API。Create-only SQL 僅作結構參照，不可直接執行。
