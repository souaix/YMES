# PD102 產品配件設定

## 功能入口與來源

- PD102 `frmProductBasis_THEIL_BU1.btnAccessory_Click` 取得目前產品列的 ProductNo、ProductVersion，並把已載入的產品流程表傳給 `frmPRDAccessory`。入口沒有傳 IssueState。
- THEIL BU1 表單：`Customer/Production/MESWin/PRD/PD_ProductBasis_THEIL_BU1/frmPRDAccessory_THEIL_BU1.vb`、同名 Designer，以及 `frmPRDAccessoryDef_THEIL_BU1.vb`。另一份標準 Form 在 `STD/MESWin/PRD/PD_ProductBasis/`；本規格以 PD102 實際開啟的 THEIL BU1 表單為準。
- 用到的 WinForms 呼叫：`wsPRD.LoadPRDAccessory`、`wsPRD.UpdPRDAccessory`、`wsPRD.DelPRDAccessory`、`wsEQP.LoadAccessoryType`、`wsEQP.LoadAccessoryBasis`、`wsOP.LoadOPBasis`、`wsPRD.LoadProductProcess`、`wsPRS.LoadNodeBasis`、`PD_ExpandProcess`。
- 本機 WinForms client source 沒有 wsPRD/clsProduct 的 server/Core 實作。因而本文件會標示可由表單確認的 request/互動，以及需要家用端從 API/Core 或服務部署來源核實的交易細節。

## WinForms 畫面

| 視窗 | ClientSize | 版面 |
|---|---:|---|
| `frmPRDAccessory` | 1067×568 | 上方配件類別摘要 Grid，下方配件編號明細 Grid；右側 ADD、EDIT、DEL，Close 固定右下。兩個 Grid 都隱藏 GroupByBox。 |
| `frmPRDAccessoryDef` | 637×453 | 作業站編號唯讀欄位與 `...` 查找；配件類別唯讀欄位與 `...` 查找；All / Specified 單選；配件編號可勾選 Grid；Confirm、Close、Apply。ProductNo/ProductVersion 為隱藏欄位。 |

主 Grid 以 `(OPNo, OPName, AccessoryType)` 去重顯示摘要與 Assign。明細 Grid 顯示該摘要列底下排序後的 AccessoryNo。若一個類別只有 `AccessoryNo='*'`，Assign 顯示 `N`；其他配件列顯示 `Y`。選取摘要列會更新下方明細。

## 查找及操作邏輯

1. 主視窗載入時呼叫 `LoadPRDAccessory(ProductNo, ProductVersion)`，把結果依作業站、作業站名稱、配件類別彙整成摘要 Grid。
2. ADD 開啟 Def；EDIT 傳入目前 OPNo、OPName、AccessoryType，並停用作業站與配件類別的查找按鈕。Def 的文字欄位唯讀。
3. 作業站查找先要求產品版本已有流程。它呼叫 `LoadProductProcess` 並傳 `PSPrivilege=True`，逐個 ProcessNo 呼叫 `LoadNodeBasis(ProcessNo, NodeType=0)`；以 NodeNo 對應 `LoadOPBasis` 取得 OPName，再透過 `PD_ExpandProcess` 展開產品流程節點。無可用流程時不能選 OP。
4. 配件類別查找由 `LoadAccessoryType` 提供類別、分類及說明。選到類別後，`LoadAccessoryBasis` 提供 AccessoryNo，並依該產品版本已存在的資料勾選已設定配件。
5. All 代表資料列 `AccessoryNo='*'` 並停用個別清單；Specified 顯示個別配件勾選。Specified 可為空集合，表單仍可送出，服務如何解讀空集合需由家用端核對。
6. 儲存前表單要求 OPNo、OPName、AccessoryType；將此類別設定與已標記 Set 的其他類別選取值序列化為 `Accessory` multivalue，連同 ProductNo、ProductVersion、單一 OPNo/OPName 呼叫 `UpdPRDAccessory`。表單會把已勾選的 `*` 作為該類別的全部設定。
7. Confirm 呼叫 Update，成功後關閉 Def；Apply 呼叫相同 Update，成功後留在 Def 並停用 Apply，Close 放棄尚未送出的變更。
8. 主畫面 DEL 可多選摘要列；確認後逐筆呼叫 `DelPRDAccessory(ProductNo, ProductVersion, OPNo, OPName, AccessoryType)`。遇錯即停止，先前成功刪除不回滾，最後重載主/明細資料。
9. 表單本身未收到產品 IssueState，也沒有以 IssueState 停用 ADD/EDIT/DEL。Production API 應驗證登入者對產品流程的 Function/PS 權限；是否增加產品狀態寫入限制屬新政策，不能記成 WinForms 既有規則。

### Service/Core 尚待確認

WinForms 只證明 Update 一次帶入單一 OPNo/OPName 和 Accessory multivalue，Delete 一次帶入單一 OPNo/OPName/AccessoryType。`wsPRD`/`clsProduct` 實作不在目前 client source，因此尚不能確認 Update 是否先清除整個 OP 的舊設定、是否採 transaction，以及空 multivalue 的刪除行為。家用端應先核對可用的服務/Core 實作；API 契約應明確定義單一 OP 的替換範圍、空集合語意和交易原子性。主 Grid 多選刪除保留逐筆、部分成功行為。

## Oracle 結構與 CREATE SQL

Oracle MESTEST 唯讀字典查詢取得 `TBLPRDACCESSORY`：

| 欄位 | Oracle 型別 | Null / Default |
|---|---|---|
| ProductNo | VARCHAR2(50) | NOT NULL |
| AccessoryType | VARCHAR2(50) | NOT NULL |
| AccessoryNo | VARCHAR2(50) | NOT NULL |
| ProductVersion | VARCHAR2(5) | PK 成員，實際 NOT NULL |
| OPNo | VARCHAR2(20) | DEFAULT `'*'`、NOT NULL |
| OPName | VARCHAR2(200) | NULL |

複合 PK 為 `(ProductNo, ProductVersion, OPNo, AccessoryType, AccessoryNo)`。來源只有此 PK unique index，沒有 FK、trigger 或其他 index。

- Oracle source DDL：[`mestest_prd_accessory_source_ddl.sql`](../../../database/reference/mestest_prd_accessory_source_ddl.sql)
- PostgreSQL 空表 CREATE-only 參照：[`mestest_prd_accessory_create.sql`](../../../database/reference/mestest_prd_accessory_create.sql)

Oracle DDL/欄位/constraint/index/trigger 由公司電腦 Windows PowerShell 5.1 + Oracle.ManagedDataAccess，使用本機受保護的 MESTEST profile 唯讀查詢。沒有讀業務資料列、沒有執行 Oracle DDL/DML；連線 IP/帳號/密碼/SID 未寫入 repository。CREATE-only 參照僅供家用端與 YMES live schema/migrations 比對，不能直接部署。

## DEV 畫面與家用端 API/schema handoff

- `ProductAccessorySetup.vue` 依 WinForms 主窗/Def 尺寸、上下雙 Grid、右側按鈕、All/Specified 與多選功能製作 DEV 預覽。只把假資料寫入產品關聯 localStorage；Production API 未接線時唯讀。
- 家用端先查 `YMES.tblprdaccessory` live schema、migration、entity/repository；只有確認缺表時才新增 migration。配件類別/配件主檔是設備配件功能共用資料，重用現有 `tbleqpaccessorytype`、`tbleqpaccessorybasis` API/table，不要重複建表。
- 建議 API 提供產品版本配件設定 GET、產品版本可用 OP lookup、配件類別 lookup、類別下可用配件編號 lookup，以及按單一產品版本/OP 更新設定與按 OP/AccessoryType 刪除。更新需能表達 `*` 全部與指定編號；空集合是否代表清空類別，需先對照舊 Core。
- 作業站 lookup 必須沿用產品流程與登入者 PS 權限；不可接受 client 自行宣告 `PSPrivilege=True`。Write/Delete 檢查產品、OP 與配件類別/編號存在及使用者權限。服務端決定 OPName/audit 值，不信任 request 身分欄位。
- Copy/Version 是否複製 `TBLPRDACCESSORY`，目前 client 呼叫鏈未包含 Core 實作，家用端需比對舊 `CopyPRD` 服務後保持相同行為。
