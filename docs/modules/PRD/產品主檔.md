## 主畫面

- WinForms 主窗 ClientSize 為 1008×591，最大化。上方共用 frmBasisTemplat 提供狀態選擇及 ProductNo 查詢；IssueState 為 0、1、2、-1（未核准、簽核中、已核准、不使用）。服務依 ProductNo 查詢，狀態 Radio 於載入後篩選，查詢使用包含式 wildcard 語意。
- 主表來源為 TBLPRDPRODUCTBASIS，服務以 ProductNo、ProductVersion DESC 排序。DataStamp、IssueState 等依 WinForms Grid Layout 隱藏，CreateDate/ReviseDate 顯示 yyyy/MM/dd HH:mm:ss。產品欄位依原 UltraGrid 欄位順序呈現，可水平捲動；隱藏欄位包括 IssueState、DataStamp、CartonQty、PalletQty、BoxQty、PackOIPath。
- 主表下方是 Process、BOM、EQPConstraint 三個頁籤。流程表格選取一列後，Expand All 傳入該列 PS/流程版本/MOType；BOM 是遞迴樹，WinForms 最多展開五層，依 NodeType 分別以產品或材料節點呈現，並顯示投入站、標準用量、單位、損耗率、指定用料與說明。EQPConstraint 是獨立明細表。
- 側邊按鈕依 WinForms 排列：ADD、EDIT、DEL、Copy、Version、Approve、Property、Parameter、Business Rule、OPDescription、RecipeGroup、Accessory、Resource、SubOP、Program、Default、RunTime、QC Item、Packing Set、EQPCapItem、eSOP、EquipmentSpec、APS Integration、Bin、GBOMImport、GBOMExport、Import、Close。DisApprove 在 Designer 設為 Visible=False 且沒有 handler；QTY Conversion 也在 Designer 設為 Visible=False，不顯示在 Web。
- APS Integration 只有 funShowBtnAPS("ExecuteAPS") 成立才顯示；eSOP 只有 Execute_eSOP 成立才顯示。Web DEV 預覽保留為遷移入口；正式權限顯示需接 YMES menu/function permission 與參數。
- Vue 已設產品專用頁；行選取由 Vue 狀態更新，不改 URL、不重新載入。DEV 假資料支援四種狀態、搜尋、多選、Add/Edit/Copy/Version、簽核規則示例、刪除及屬性/設備限制明細。正式模式讀取目前 YMES 已有產品、流程、BOM API；其餘子功能入口目前標明遷移中，不能視為完成。

## 新增、修改、複製、版本表單

- Def Form ClientSize 約 766×742，主要資料 GroupBox 於 (14,8)、約 740×578；Audit Group 於 (14,594)、約 742×70；Confirm、Close、Apply 在底部。Web 定義視窗沿用區塊、欄位分組與按鈕順序。
- 主要欄位包含 ProductNo、ProductVersion、ProductName、ProductType、ProductCode、UnitType、UnitNo、Description、SerialTypeNo_Lot、SerialTypeNo_Comp、PictureName、LotStdQty、SPECNo、SAP_KTEXT、SAP_BOMAENNR、SAP_AENNR、SAP_DATUV、XX_SOPSPEC、XX_SOPREV、SAP_PLNAL。Audit 顯示 Creator/CreateDate/Reviser/ReviseDate。
- Oracle ProductNo、ProductVersion、ProductName、ProductType、SAP_PLNAL 為必填；WinForms funAddorEdit 另驗 UnitType、UnitNo。產品編號與版本為複合主鍵。ProductVersion 離開欄位時轉大寫。SAP_PLNAL 選項碼 11/21/51/31/61，文字為 Homemade、Partial Process Outsourcing、Whole Process Outsourcing、Rework、Total Outsource Rework。
- ProductNo 最大 50 字元、ProductVersion 5、ProductName 300、ProductType 50；以來源 Oracle 欄位長度為準。DEF 表單的 TextBox 並非全部有 MaxLength，服務與 DB 仍須驗長度。
- LotStdQty 使用 Not Set/Std Qty 切換；Not Set 寫 0。圖片內容存於獨立 TBLPRDPRODUCT_PICTURE BLOB 表，不能只儲存檔名。
- Edit 僅 IssueState=0；ProductNo、ProductVersion 唯讀。Copy 預填所選產品並要求新產品鍵；Version 由使用者輸入新版號，WinForms 不自動推算版號。Copy/Version/新增可選 Detail Source：ProductType、Other Product、None。新增成功後，來源選擇才觸發 wsPRD.CopyProduct 複製子資料。
- Confirm 成功後關閉；Apply 成功後保留編輯窗並刷新 audit/DataStamp。產品版本、型別、單位、序號規則以 WinForms 選擇視窗查找；DEV 使用假選項。

## IssueState、資料驗證及交易邏輯

| IssueState | WinForms 狀態 | Edit | Delete |
| ---: | --- | --- | --- |
| 0 | 未核准 | 可修改 | 實體刪除 |
| 1 | 簽核中 | 不可修改 | 不允許 |
| 2 | 已核准 | 不可修改 | DataStamp 驗證後設為 -1 |
| -1 | 不使用 | 不可修改 | 實體刪除 |

- Approve 只處理狀態 0。WinForms 先檢查受控屬性：Controlled=1 無值則拒絕；Controlled=2 無值則要求確認。接著檢查產品每條流程作業站規則及 RulePhase/AttribPhase 對應屬性 CPASS，之後呼叫產品服務和共用 Issue/Job 流程。不能以目前 YMES API 僅檢查「有一條預設流程」取代 WinForms 規則或繞過 Issue/Job。
- Delete 對狀態 0、-1 實體刪除；狀態 2 軟停用為 -1；狀態 1 不可刪。來源 WinForms 多選時逐筆呼叫，出錯時先前成功項目不回滾。API 應逐筆執行並回報成功/失敗項目。
- Edit/Delete/Approve 必須以 DB 重新讀取的 IssueState 與 DataStamp 做狀態檢查及 CAS。DataStamp nullable，寫入時採 COALESCE(DataStamp,0)+1。不能相信 client 傳入 IssueState 來決定實體刪除或軟停用。
- AddProduct 檢查 ProductNo 是否與產品類別、模組衝突；若 TBLSYSPARAMETER.ProductMaterialcoexist 關閉，也檢查物料編號。API 應依既有 MES 共存設定處理，不得硬編碼允許同號。
- BOM 是遞迴階層；WinForms NodeType=0 為材料、NodeType=1 為產品；包含 TBLPRDBOMMATERIALGROUP 材料群組。產品 BOM 並非純扁平元件清單，不可將現有 YMES 簡化 BOM 欄位直接當成 MES 等價實作。
- Process Set 只允許狀態 0，開 PD_ProductProcess 並提供產品版本與流程 DataView；Expand All 需有已選流程、存在 Production Segment，並傳入區段 IsNetFlow。BOM Set 只允許狀態 0，開 frmProductBOM_THEIL_BU1 並傳入產品流程；成功後重建 BOM 樹。
- btnQTYConversion.Visible=False，故此頁不提供此按鈕。WinForms Print 產生產品包裝 BOM 報表；Vue window.print() 僅是 DEV 簡化，正式報表尚待實作。

## Oracle 表與 DDL 來源

公司電腦使用 Windows PowerShell 5.1、Oracle.ManagedDataAccess 與本機受保護 DatabaseConfigs.CS.Test.Mes 設定，只唯讀查 MESTEST 的資料字典與 DDL；未查業務資料，也未在 Oracle 執行 SQL 寫入。連線資訊與密碼不進 Git。

| Oracle 表 | 主要用途 | 主鍵 |
| --- | --- | --- |
| TBLPRDPRODUCTBASIS | 產品主檔與 ERP/序號/規格/稽核欄位 | (ProductNo, ProductVersion) |
| TBLPRDPRODUCTPROCESS | 產品版本與製造層別/流程對應 | (ProductNo, ProductVersion, MOTypeNo, ProcessNo, ProcessVersion) |
| TBLPRDBOM | 產品/材料節點及投入站、數量、損耗率 | (ProductNo, ProductVersion, NodeNo, OPNo) |
| TBLPRDBOMMATERIALGROUP | BOM 材料群組成員 | (ProductNo, ProductVersion, NodeNo, OPNo, MaterialNo) |
| TBLPRDEQPCONSTRAINT | 產品版本/作業站/限制設備 | (ProductNo, ProductVersion, OPNo, EquipmentNo) |
| TBLPRDPRODUCT_PICTURE | 產品圖片 BLOB | (PictureName) |
| TBLPRDPRODUCTPROPERTY | 產品版本屬性值及簽核狀態 | (ProductNo, ProductVersion, PropertyNo) |

Oracle 原始 DDL/字典摘要位於 database/reference/mestest_prd_product_basis_source_ddl.sql；PostgreSQL CREATE-only 參照位於 database/reference/mestest_prd_product_basis_create.sql。ProductProperty 的 DBMS_METADATA.GET_DDL 發生 ORA-03135，所以其 Oracle DDL 是根據 ALL_TAB_COLUMNS、ALL_CONSTRAINTS、ALL_CONS_COLUMNS、ALL_INDEXES、ALL_IND_COLUMNS 重建，已在 SQL 檔標示。來源表只有 PK unique index，查得無 FK。PostgreSQL CREATE 檔是結構參照，不是 migration，不能直接在正式 DB 執行。

## YMES 現有 API / 家用端待辦

YMES 已有 ProductDto、ProductWriteRequest、MasterDataController、PostgresMasterDataRepository.Products.cs，及 migration 0010_postgres_master_data_api.sql 的 ym_product_process、ym_product_bom。這些是先前 YMES 模型，不等於 Oracle 的所有產品欄位/關聯；本 Vue 頁正式模式目前只讀現有產品、流程、BOM API。家用端處理前應先比對 migration、PostgreSQL live schema、ProductDto 和本規格 DDL 參照。

現有路由：

| 方法 | 路徑 | 現況 |
| --- | --- | --- |
| GET | /api/products?keyword=&issueState= | 已有；keyword 可查產品編號/名稱 |
| GET | /api/products/{no}/versions/{version} | 已有 |
| POST | /api/products | 已有，但 DTO 欄位少於 Oracle |
| PUT | /api/products/{no}/versions/{version} | 已有，但 DTO 欄位少於 Oracle |
| POST | /api/products/{no}/versions/{version}/approve | 已有簡化核准，需補 WinForms 檢查與共用 Issue/Job |
| POST | /api/products/{no}/versions/{version}/new-version | 已有自動加一版；WinForms 允許輸入版本，需協調契約 |
| DELETE | /api/products/{no}/versions/{version}?issueState=&dataStamp= | 已有簡化狀態處理，需按來源確認 CAS/引用策略 |
| GET/POST/PUT/DELETE | /api/products/{no}/versions/{version}/processes... | YMES 自有 ym_product_process，需與 Oracle 表欄位/預設流程語意對照 |
| GET/POST/DELETE | /api/products/{no}/versions/{version}/bom... | YMES 自有扁平 ym_product_bom，尚不含 Oracle 節點樹、材料群組、圖片及所有限制 |

家用電腦接手：
1. 先 git pull，比較產品 DDL 參照、migration 0010、既有 PostgreSQL schema 及 API，避免重複建已存在表。決定 API 映射 MES 原生語意或調整 YMES 自有表，將決策寫入規格；Create-only SQL 不自動部署。
2. 完整對照 ProductDto/Request 欄位長度與 TBLPRDPRODUCTBASIS；增補 PictureName、SAP/SOP/ERP/serial/property 等欄位及圖片上傳/讀取；保持 DataStamp optimistic concurrency。
3. 實作產品屬性、設備限制、BOM 材料群組與真正遞迴 BOM API；確認每張關聯表是否採 Oracle 結構映射或 YMES 命名，為新表提供獨立 migration。
4. 調整產品流程服務 API，保留 MOTypeNo、PSNo/PSOrder、ProcessVersion、DefaultProcess、HaveComponent/HaveLevel 原生對應，核實 selector * 目前版本語意。
5. 核准補成 WinForms Controlled 屬性與 CPASS 規則驗證，並串共用 Issue/Job callback；目前 API 只有預設流程檢查，不能視為等價。
6. 對照 Add/Edit/Copy/Version/Apply、料號互斥設定、SAP_PLNAL、單位/序號 lookup、檔案與報表；修正目前自動加版與 WinForms 可輸入版號差異。
7. 提供 PRD BASIS/PD102 權限檢查、response DTO 與錯誤碼；完成 schema/API 後回報辦公室，讓 DEV 頁串 API。
8. 必要 schema 先比對後新增 migration/Create SQL handoff；不可把 Oracle raw DDL 原樣執行於 PostgreSQL，也不可將 DEV localStorage 假資料寫進正式 API/DB。
