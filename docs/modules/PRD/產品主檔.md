## 主畫面

- WinForms 主窗 ClientSize 為 1008×591，最大化。上方共用 frmBasisTemplat 提供狀態選擇及 ProductNo 查詢；IssueState 為 0、1、2、-1（未核准、簽核中、已核准、不使用）。服務依 ProductNo 查詢，狀態 Radio 於載入後篩選，查詢使用包含式 wildcard 語意。
- 主表來源為 TBLPRDPRODUCTBASIS，服務以 ProductNo、ProductVersion DESC 排序。DataStamp、IssueState 等依 WinForms Grid Layout 隱藏，CreateDate/ReviseDate 顯示 yyyy/MM/dd HH:mm:ss。產品欄位依原 UltraGrid 欄位順序呈現，可水平捲動；隱藏欄位包括 IssueState、DataStamp、CartonQty、PalletQty、BoxQty、PackOIPath。
- 主表下方是 Process、BOM、EQPConstraint 三個頁籤。流程表格選取一列後，Expand All 傳入該列 PS/流程版本/MOType；BOM 是遞迴樹，WinForms 最多展開五層，依 NodeType 分別以產品或材料節點呈現，並顯示投入站、標準用量、單位、損耗率、指定用料與說明。EQPConstraint 是獨立明細表。
- 側邊按鈕依 WinForms 排列：ADD、EDIT、DEL、Copy、Version、Approve、Property、Parameter、Business Rule、OPDescription、RecipeGroup、Accessory、Resource、SubOP、Program、Default、RunTime、QC Item、Packing Set、EQPCapItem、eSOP、EquipmentSpec、APS Integration、Bin、GBOMImport、GBOMExport、Import、Close。DisApprove 在 Designer 設為 Visible=False 且沒有 handler；QTY Conversion 也在 Designer 設為 Visible=False，不顯示在 Web。
- APS Integration 只有 funShowBtnAPS("ExecuteAPS") 成立才顯示；eSOP 只有 Execute_eSOP 成立才顯示。Web DEV 預覽保留為遷移入口；正式權限顯示需接 YMES menu/function permission 與參數。
- Vue 已設產品專用頁；行選取由 Vue 狀態更新，不改 URL、不重新載入。DEV 假資料支援四種狀態、搜尋、多選、Add/Edit/Copy/Version、簽核規則示例、刪除及屬性/設備限制明細。正式模式讀取目前 YMES 已有產品、流程、BOM API；其餘子功能入口目前標明遷移中，不能視為完成。

## IssueState、資料驗證及交易邏輯

| IssueState | WinForms 狀態 | Edit | Delete |
| ---: | --- | --- | --- |
| 0 | 未核准 | 可修改 | 實體刪除 |
| 1 | 簽核中 | 不可修改 | 不允許 |
| 2 | 已核准 | 不可修改 | DataStamp 驗證後設為 -1 |
| -1 | 不使用 | 不可修改 | 實體刪除 |

- Approve 只處理狀態 0。WinForms 先檢查受控屬性：Controlled=1 無值則拒絕；Controlled=2 無值則要求確認。接著檢查產品每條流程作業站規則及 RulePhase/AttribPhase 對應屬性 CPASS，之後呼叫產品服務和共用 Issue/Job 流程。不能以目前 YMES API 僅檢查「有一條預設流程」取代 WinForms 規則或繞過 Issue/Job。
- Delete 對狀態 0、-1 實體刪除；狀態 2 軟停用為 -1；狀態 1 不可刪。來源 WinForms 多選時逐筆呼叫，出錯時先前成功項目不回滾。API 應逐筆執行並回報成功/失敗項目。
- Edit/Delete/Approve 必須以 DB 重新讀取的 IssueState 與 DataStamp 做狀態檢查及 CAS。DataStamp nullable，寫入時採 COALESCE(DataStamp,0)+1。不能相信 client 傳入 IssueState 來決定實體刪除或軟停用。
- AddProduct 檢查 ProductNo 是否與產品類別、模組衝突；若 TBLSYSPARAMETER.ProductMaterialcoexist 關閉，也檢查物料編號。API 應依既有 MES 共存設定處理，不得硬編碼允許同號。
- BOM 是遞迴階層；WinForms NodeType=0 為材料、NodeType=1 為產品；包含 TBLPRDBOMMATERIALGROUP 材料群組。產品 BOM 並非純扁平元件清單，不可將現有 YMES 簡化 BOM 欄位直接當成 MES 等價實作。
- Process Set 只允許狀態 0，開 PD_ProductProcess 並提供產品版本與流程 DataView；Expand All 需有已選流程、存在 Production Segment，並傳入區段 IsNetFlow。BOM Set 只允許狀態 0，開 frmProductBOM_THEIL_BU1 並傳入產品流程；成功後重建 BOM 樹。
- btnQTYConversion.Visible=False，故此頁不提供此按鈕。WinForms Print 產生產品包裝 BOM 報表；Vue window.print() 僅是 DEV 簡化，正式報表尚待實作。

## 正式產品父主檔保存範圍（2026-11-19 已上版，後續多選修補另列）

- 父主檔 Create/Edit 支援欄位為 `productNo`、`productVersion`、`productName`、`productType`、`unitType`、`unitNo`、`description`、`specNo`、`productCode`、`serialTypeNoLot`、`serialTypeNoComp`、`lotStdQty`、`erpNo`、`sapPlnal`。IssueState/DataStamp 為狀態／版本條件，由伺服器管理；不能靠送入 Create 的狀態或稽核欄偽造已核准資料。前述既有長度與數量驗證仍生效，這不是 Oracle 全欄位 API。
- 本輪新增 `ProductDto.SapPlnal` 與可選 `ProductWriteRequest.SapPlnal`，映射既有 `tblprdproductbasis.sap_plnal`，不新增或修改 DB schema。五個來源選項為 `11` 自製、`21` 半委、`51` 全製程委外、`31` 重工、`61` 重工全委。新值只接受這五種；既有非標準值若原樣回傳允許保留，不能藉此改成其他未知碼。

## 家用端產品版本契約修正（2026-11-19，準備紀錄；正式實證見前節）

- 此段只修產品主檔的來源狀態與版本契約，不改設備、物料、流程等其他主檔的 DTO、`MasterDataCommandRequest` 或共用 `EnsureStamp/EnsureEditable/EnsureRemoval`。檔案範圍為產品專屬 `MES.Contracts/ProductDto.cs`、產品 repository/interface/controller 段落、`ProductBasisMaster.vue`，以及 Fake 產品段與舊 Razor 產品頁的相容調整。
- `ProductDto.IssueState` 改為 `int?`，`DataStamp` 改為 `decimal?`；ProductColumns/MapProduct 回原始 NULL/數字，不再 COALESCE stamp 成 0 或 `Convert.ToInt32`。來源 numeric(11,0) 的合法值（例如 3000000000）可完整讀取，不因超過 Int32 範圍而使主 list/get/Delete 回 500。CreatedAt 等其他既有 DTO 欄位不在這次 nullable 修正範圍，不能把此段理解成產品完整欄位遷移已完成。
- Get 與寫入同樣沿用共用 `ReadProductVersionContext`，先取得 canonical 產品/版本及來源 raw state/stamp；大小寫歧義回 409。讀取用 `FOR SHARE`，寫入用 `FOR UPDATE`，再以實際鍵投影產品 DTO；不把可信 context 再壓回舊 int/NULL 預設值。
- POST 新增仍使用 `ProductWriteRequest`，不要求不存在的舊版本。PUT 使用產品專屬 `ProductUpdateRequest`，要求 JSON 明確包含 `issueState` 和 `dataStamp`，兩欄允許明確 `null`；approve/set-current 改用同樣兩欄必填的 `ProductCommandRequest`。欄位省略由 JSON required 驗證回 400，明確 NULL 不當成 0。
- DELETE 必須同時提供兩個 query key：如 `?issueState=0&dataStamp=3000000000`；NULL stamp 用 `?issueState=0&dataStamp=`。NULL state 若需傳版本證據使用 `issueState=`，但該狀態仍不可寫入。省略任一 key 回 400，不再讓 ASP.NET 的 int 預設 0/0 成為刪除條件；其他主檔 Delete 契約沒有順帶改動。
- repository 寫入先驗 nullable state/stamp，`NULL != 0`；數字 stamp 只允許來源 11 位數範圍內整數。Update/Approve/SetCurrent/Delete SQL 以 canonical 鍵及 `issuestate IS NOT DISTINCT FROM @state`、`datastamp IS NOT DISTINCT FROM @stamp` 精確 CAS。真實版本不符回 409，資料不變。修改/狀態變更才用 `COALESCE(datastamp,0)+1` 產生新版本；到來源欄位上限時回 409，不寫出溢位。
- 狀態規則不因 nullable 修正放寬：Update/Approve 僅 0，SetCurrent 僅 2，Delete 2 軟停用、0/-1 才實刪，1/NULL 拒絕。SetCurrent 需鎖住同產品多個版本，先依 ProductNo/ProductVersion 固定順序取得父列鎖，再驗指定版本、清舊 current/設新 current，避免兩個版本同時切換時互相倒序持鎖。

- Vue 正式模式保存 raw NULL stamp/state；不再用 `Number(null)` 把 NULL 狀態當未簽核，也不把 NULL stamp正規化成 0。四種狀態 Radio 不顯示來源 NULL，NULL 不會啟用 Edit/Approve；送出 mutation 前若版本欄缺漏或數字無效會先提示重新載入。DELETE 明確以空 query 傳 NULL，PUT/Approve 以 JSON null 傳原值。

- 本輪只修正 `database/reference/mestest_prd_product_basis_create.sql`，權威為同目錄 raw Oracle `mestest_prd_product_basis_source_ddl.sql`；沒有執行參考 DDL、建立 migration、修改 live DB／API／Contracts。ProductProperty 的 Oracle DDL 仍是原檔已註明的字典重建結果，不偽稱本次重新從 Oracle 取得。
- 逐一核對全部7個 CREATE：ProductBasis 84欄、ProductProcess 16欄、BOM 17欄、BOMMaterialGroup 5欄、EQPConstraint 7欄、Product_Picture 2欄、ProductProperty 12欄，共143欄。補回前五張遺漏的第一欄 `productno varchar(50) NOT NULL`，及 Picture 表遺漏的第一欄 `picturename varchar(50) NOT NULL`；原本這六張 PK 指向不存在欄位。來源第一欄和開括號同一行，不得只掃描行首雙引號欄位，否則會再次漏欄。
- 另恢復來源明載的具名 `CHECK (boxqty IS NOT NULL)`；保留 BOXQTY 原 DEFAULT 0，不將 table-level check 悄悄當作可 NULL。`motypeno` 等由 PK 隱含不得為 NULL 的語意也納入比對，不擅自新增來源沒有的預設或欄位。
- 比對涵蓋欄名、次序、轉譯型別／長度／numeric precision及scale、inline nullable、PK／CHECK 導致的有效 nullable、default、PK名稱及欄位次序。採既有明示映射 VARCHAR2(n)→varchar(n)、NUMBER(p,s)→numeric(p,s)、DATE→timestamp without time zone、BLOB→bytea；Oracle 未標 CHAR/BYTE 的 VARCHAR2 不推定其語意，PG varchar 使用字元長度；PG timestamp 可存較細 precision，不能因正規化欄位比對0差異就聲稱所有Oracle儲存邊界完全相同。
- 本機可重跑 `python .tools/compare_prd_product_reference.py --output .tools/prd-product-reference-after.json`；parser 依平衡括號與字串／識別字引號切 CREATE body，輸出來源／目標 SHA256、逐欄 raw definition、正規化屬性及差異。修補前證據 `.tools/prd-product-reference-before.json` 為14個診斷（6漏欄、6未定義PK欄、BOXQTY有效nullable與CHECK各1）；修補後 `.tools/prd-product-reference-after.json` 為7表143欄、正規化差異0。此為靜態參照檔驗證，並非資料庫執行成功或現存table已遷移的證明。
