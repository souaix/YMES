# PD102 產品預設設定（Default）

## 範圍與來源

- WinForms 入口：`PD_ProductBasis_THEIL_BU1` 的 `btnDefault_Click`，開啟 `PD_ProductLoadDefault/frmProductLoadDefault`。
- 主要來源：`frmProductBasis.vb`、`frmProductLoadDefault.vb`/Designer、`wsPRD.UpdPRDOP_BatchDefault`、`clsProduct.UpdPRDOP_BatchDefault`。
- Vue DEV 頁：`web/src/components/ProductDefaultSetup.vue`，由 `ProductBasisMaster.vue` 的 Default 按鈕開啟。
- 本功能批次複製流程/作業站預設值到指定產品版次的產品作業站設定；它不是新建某一個獨立主檔。

## WinForms 畫面與操作

- 父畫面沒有產品流程時不開視窗，顯示 `PLEASE DEFINE PROCESSES OR CHECK YOUR PS PRIVILEGE`。開啟時傳入 ProductNo、ProductVersion、IssueState。
- 對話框 `frmProductLoadDefault` ClientSize 約 371×257。提供兩個 OP 範圍 Radio：`Product Process OP` 預設選取，送出 `DefaultOP=2`；`All PS OP` 送出 `DefaultOP=1`。
- 複製項目：Parameter、BusinessRule、Description、OPResource、QCItem、SubOP、APS。APS 只有全域參數 `ExecuteAPS=1` 才顯示；Designer 預設勾選 APS，即使隱藏仍保留勾選值。QCItem 初始勾選由 `PRDDefault_QCItemAutoChecked=1` 決定，其他值預設不勾。
- IssueState 非 0 時，所有項目 Checkbox 與 Apply 停用；OP 範圍 Radio 仍可切換。Apply 至少要有一項勾選；由於隱藏 APS 仍可能為勾選狀態，舊程式可能在所有可見項目都取消時仍通過此檢查。
- Apply 先顯示共用確認訊息 `ALLOWCHANGEDATA,PLEASECHECK`；確認後停用視窗控制項並呼叫 `wsPRD.UpdPRDOP_BatchDefault`。成功或錯誤訊息後都關閉對話框；Close 直接關閉，不儲存。
- UI 不傳自選 OP 清單；它傳產品、版本、DefaultOP、所選旗標及呼叫者。服務雖有選擇 OP 清單的參數，這個畫面不使用。

## DefaultOP 與複製規則

- `DefaultOP=1`（All PS OP）：從產品所用流程的 PS 範圍，取得已核准的作業站預設資料。
- `DefaultOP=2`（Product Process OP）：展開此產品實際設定的流程，取得去重後的作業站。
- Core 會為目標缺少的產品 OP 建立 `TBLPRDOP` 列，再依選取旗標更新相關資料。各項是批次取代/重建，不可當成只補缺值：Parameter/Attribute/Rule、BusinessRule 與 Relation/XML、OP Description、OP Resource/Area、QC Item、SubOP、APS setup/detail。Parameter 部分另有 ECN 狀態保留邏輯；BusinessRule XML 使用 CLOB 寫入路徑。
- 服務呼叫以一組產品版次與旗標為範圍；若 `collectionSQL` 傳入則 Core 附加 SQL，由外層統一執行。家用端需再對照部署版本 Core/Service 的實際 transaction 與錯誤回傳，不可由 Vue 假資料推定原子性。

## Oracle tables 與參照 SQL

Oracle MESTEST 以 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 唯讀查資料字典；本次 `DBMS_METADATA.GET_DDL` 發生 ORA-03135，因此兩張產品 APS 表的邏輯 DDL 依 `ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_CONS_COLUMNS`、`ALL_INDEXES` 重建。未查業務資料列，也未在 Oracle 執行 DDL/DML。

| 用途 | Oracle table | DDL / PostgreSQL CREATE 參照 |
| --- | --- | --- |
| 產品 OP 主資料 | `TBLPRDOP` | `mestest_prd_parameter_setup_source_ddl.sql` / `mestest_prd_parameter_setup_create.sql` |
| Parameter、Attribute、Rule、設備/Recipe | 相關產品 OP 表 | 同上 |
| BusinessRule、Relation、XML | 相關產品 OP/CPO 表 | 同上；Process/CPO 共用定義另見 `mestest_operation_and_system_source_ddl.sql` |
| OP Description | `TBLPRDOPDESCRIPTION` | `mestest_prd_op_description_source_ddl.sql` / `mestest_prd_op_description_create.sql` |
| Resource/Area | `TBLPRDOPAREA` | Parameter Setup SQL；共用 OP Area lookup 另見 operation/system SQL |
| QC Item | `TBLPRDQCITEM` | `mestest_qc213_attribute_item_group_prd_item_source_ddl.sql` / `mestest_qc213_attribute_item_group_create.sql` |
| SubOP | `TBLPRDOPSUBOP` | `mestest_prd_subop_source_ddl.sql` / `mestest_prd_subop_create.sql` |
| APS process defaults | `TBLPRSOPAPSBASE`, `TBLPRSOPAPSDETAIL` | `mestest_prs104_process_basis_source_ddl.sql` / `mestest_prs104_process_basis_create.sql` |
| APS product settings | `TBLPRDPRSOPAPSSETUP`, `TBLPRDPRSOPAPSSETUPDETAIL` | 本文件旁的 `mestest_prd_default_aps_source_ddl.sql` / `mestest_prd_default_aps_create.sql` |

兩張產品 APS 表的 PK 分別是 `(PRODUCTNO, PRODUCTVERSION, MOTYPENO, NODEID)` 與 `(PRODUCTNO, PRODUCTVERSION, MOTYPENO, NODEID, EQUIPMENTNO)`。只有 PK unique index；字典未回傳 FK、trigger 或其他 index。兩表在 Oracle 已存在。家用端先核對 YMES live schema、first-phase SQL 與 migration history；CREATE-only 檔只供比對，不能直接執行。

## 公司端 Vue DEV 實作與限制

- Vue 視窗保留 Default OP Radio、七項勾選、Apply/Close 與確認對話框；在 Development 模式只複製 `DEV-PRD-1001` 假樣板到目前產品版次 localStorage，依 OP 範圍篩選，更新選取的關聯集合。
- DEV 假系統參數目前 `PRDDefault_QCItemAutoChecked=false`、`ExecuteAPS=false`；正式畫面/執行仍唯讀，尚未接 API。不得將 localStorage 假資料送進正式 API。
- 「All PS OP」與「Product Process OP」使用 DEV 假資料集合近似舊 Core 範圍；正式實作須在 API 端依資料庫流程與登入者 PS 權限重新計算 OP，不能相信 client 傳入的 OP 範圍、IssueState 或 audit identity。

## 家用端 API / schema handoff

- 先 pull `main`，比對兩張 APS product 表、APS process 表以及所有相關表的 live schema/migrations；first-phase bootstrap 內 APS 欄位曾標為推測，不能直接當成正確 schema。
- 建議以受登入保護的批次命令 API 接收 ProductNo、ProductVersion、DefaultOP 與複製旗標；server 重新驗證產品 IssueState=0、產品流程、PS 權限、預設來源已核准及每張關聯表的範圍。
- OP 清單由 server 按 DefaultOP 算出。沿用現有表，不建立同義表；只在 live schema 確認缺少必要欄位/表後新增 forward migration。依 Core 證據決定一個交易涵蓋的所有表；BusinessRule XML 必須保留完整 CLOB。
- 逐項核對 Parameter ECN 保留條件、空來源時是否清空目標、未勾選項目的保留行為、APS hidden-but-checked 舊行為，以及錯誤後父表單關閉的舊流程。API 完成後更新此文件與 `todolist_homepc.md`，再 push GitHub。
