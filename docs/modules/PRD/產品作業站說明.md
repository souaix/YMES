# PD102 產品作業站說明（OPDescription）

## 功能身分與原始碼

- 這是產品主檔 PD102 側邊的 `OPDescription`，真實入口為 `PD_ProductBasis_THEIL_BU1.frmProductBasis_THEIL_BU1.btnDescription_Click`，透過 `ObjectFileHandler("PD_ProductOPDescription")` 開啟。
- 實際畫面是 `STD/MESWin/PRD/PD_ProductOPDescription/frmProductOPDescription.vb` 與 `frmProductOPDescriptionDef.vb`。不要把 `PD_ModuleDataImport` 匯入表格的 OP Description、製程 OP 自身的 `TBLOPBASIS.Description` 或產品 `Default` 按鈕混成同一個頁面。
- 資料服務在 `STD/MESws_STD/wsSTD/wsPRD/wsPRD.cs` 的 `LoadPRDOPDescription`、`AddPRDOPDescription`、`EditPRDOPDescription`、`DelPRDOPDescription`；讀取與刪除在 `STD/MESkc/kcPRD/clsProduct.cs`，新增/修改與 DataStamp 在 `STD/MESkc/kcBasis_UPD/clsBasis_UPD.cs`。

## WinForms 畫面

| 視窗 | WinForms 尺寸 | 版面與欄位 |
|---|---:|---|
| ProductOPDescription | 684×486 | UltraGrid 在左側，ADD、EDIT、DEL 在右側上方，Close 在右下。Find 控制項存在但 `Visible=False`，不顯示。 |
| Product OP Description Define | 496×276 | `OP Description` GroupBox 為 464×133。Process No、Process Version、OP No 為 KD 黃底唯讀欄；Description 為多行 RichTextBox。ADD 模式提供 Process/OP 的 `...` 查找；EDIT 隱藏兩個查找按鈕。底部沿用共用 Creator/CreateDate/Reviser/ReviseDate、Apply/Confirm/Close。 |

清單實際顯示 OP No、Description、Creator、CreateDate、Reviser、ReviseDate；DataStamp 和服務回傳的 OPName 不顯示。Description 儲存長度依 Oracle 欄位為 255；原 WinForms RichTextBox 沒設 MaxLength，Web/API 需按欄位長度明確檢查。

## 入口、查找與欄位規則

1. 入口要求目前產品至少有一筆產品流程；沒有流程時提示「Please define processes or check your PS privilege」並離開。
2. PD102 將目前產品、產品版本、IssueState、第一筆產品流程的 ProcessNo/ProcessVersion 傳入子視窗。清單載入時使用目前登入者的 PS 權限；WinForms 請求傳 `PSPrivilege=True`。
3. ADD 視窗先載入使用者可見的產品流程，可用 Process 查找切換。切換流程會清空 OP 與 Description。
4. OP 查找呼叫 `wsPRD.LoadExpandProcess`，傳目前產品/版本、ProcessNo/ProcessVersion、`MOTypeNo=-1`、`IsProduct=True`、`CheckMOTypeNo=False`。查找結果會排除目前產品版本已存在 OPDescription 的 OPNo；資料庫主鍵亦保證同產品/版本不能重複同一 OPNo。
5. 選定 OP 後，Description 預填展開流程回傳的 OP Description；使用者可自行修改。資料表不保存 ProcessNo/ProcessVersion，僅以 ProductNo、ProductVersion、OPNo 定位。
6. EDIT 固定 Process/OP，只能修改 Description。IssueState 不為 0 時 ADD/EDIT/DEL 停用，清單仍可讀取。

## 操作行為

- **ADD**：確認 OPNo 後呼叫 `AddPRDOPDescription`。成功後父畫面重新載入清單並選取該 OP。
- **EDIT**：修改 Description，呼叫 `EditPRDOPDescription`，回傳 DataStamp 供後續更新使用。Apply 儲存但留在視窗；Confirm 儲存並關閉；Close 放棄尚未套用的編輯。
- **DEL**：UltraGrid 支援多列選取；先確認，再逐列呼叫 `DelPRDOPDescription`。任一筆失敗即停止，之前成功的刪除保留；只要有成功筆數就重新載入清單。這不是單一整批交易。
- **Default**：不是此視窗的按鈕。PD102 另有 `Product Load Default`；`clsProduct` 預設處理在勾選 Description 時，先清掉目前產品版本的說明，再對流程 OP 呼叫 `AddPRDOPDescriptionDefault`。該 helper 只在 OP 說明尚不存在時，從 `TBLOPBASIS.Description` 建立。家用端不要把這段塞進本頁 ADD/EDIT。
- **Copy/Version**：PD102 產品 Copy/Version 的 Core 複製路徑使用 `CopyPRDOPDescription`，先刪目標版本的說明，再複製來源 OPNo/Description；此為產品複製流程，不是清單的 Copy 按鈕。

## 舊服務與驗證

- 清單讀取由 `clsProduct.LoadPRDOPDescription` 以 `TBLPRDOPDESCRIPTION A` 內連 `TBLOPBASIS B`，依 OPNo 取 OPName。`PSPrivilege=True` 時另以登入者授權的 Production Segment 過濾 OP。
- `wsPRD.AddPRDOPDescription` 必要欄位為 ProductNo、ProductVersion、OPNo；Description 可省略，Creator/CreateDate 由服務端身分與伺服器時間設定。
- `wsPRD.EditPRDOPDescription` 要求 ProductNo、ProductVersion、OPNo、DataStamp；服務端設定 Reviser/ReviseDate，`clsBasis_UPD.EditPRDOPDescription` 以複合鍵及 DataStamp 條件更新並將 DataStamp 加 1。新 API 應保留原子 CAS；DataStamp 為 nullable/default 0 時需定義 null-safe 行為。
- `wsPRD.DelPRDOPDescription` 由 UI 傳單一 OPNo；Core 實體刪除。OPNo 缺省時 Core 會刪除整個產品版本全部列，因此 Web API 必須要求明確 OPNo，不能意外暴露全版本刪除行為。
- WinForms 主要以 UI 停用寫入；新 API 仍需從資料庫重新檢查產品存在且 IssueState=0，並依登入身分檢查 PD102 權限及 OP 所屬 PS。不得信任 client 的 `IssueState`、`PSPrivilege` 或 audit 欄位。
- 舊 `frmProductOPDescriptionDef.btnApply_Click` 修改路徑在追加 DataStamp 後未重新組合 InXml；Confirm 路徑有組入 DataStamp。Web/API 應使用完整且一致的 DataStamp CAS，不複製 Apply 的舊缺陷。

## Oracle 結構與 YMES 參照

`TBLPRDOPDESCRIPTION` 是唯一需要此頁專用的持久化表。公司端已用 Windows PowerShell 5.1、Oracle.ManagedDataAccess 與受保護 MESTEST 連線，唯讀查 `DBMS_METADATA.GET_DDL`、`ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_CONS_COLUMNS`、`ALL_INDEXES`、`ALL_IND_COLUMNS`、`ALL_TRIGGERS`。沒有讀取 MES 業務列，沒有執行 Oracle DDL/DML。

| Oracle 欄位 | 型態 | NULL/default | 主鍵 |
|---|---|---|---|
| PRODUCTNO | VARCHAR2(50) | NOT NULL | 是 |
| PRODUCTVERSION | VARCHAR2(5) | NOT NULL | 是 |
| OPNO | VARCHAR2(20) | NOT NULL | 是 |
| DESCRIPTION | VARCHAR2(255) | NULL | 否 |
| DATASTAMP | NUMBER(11,0) | NULL，DEFAULT 0 | 否 |
| CREATOR | VARCHAR2(10) | NULL | 否 |
| CREATEDATE | DATE | NULL | 否 |
| REVISER | VARCHAR2(10) | NULL | 否 |
| REVISEDATE | DATE | NULL | 否 |

只有 `(PRODUCTNO, PRODUCTVERSION, OPNO)` PK unique index；無 FK、無 trigger、無其他 index。`TBLOPBASIS` 是讀 OPName、預設說明及 OP 查找所用共用表，不在本功能另建。Oracle source DDL 與 PostgreSQL CREATE-only 參照：

- [`mestest_prd_op_description_source_ddl.sql`](../../../database/reference/mestest_prd_op_description_source_ddl.sql)
- [`mestest_prd_op_description_create.sql`](../../../database/reference/mestest_prd_op_description_create.sql)

CREATE-only 參照不是 migration。家用端須先比對 YMES PostgreSQL live schema、migration、entity/repository；只有確定缺少對應結構才新增 forward migration，不可直接在 Oracle 執行參照檔。

## 家用端 API/schema handoff

建議依既有 YMES API 命名實作下列語意（endpoint 可按 controller 慣例調整並回寫本規格）：

- `GET /api/products/{productNo}/versions/{productVersion}/op-descriptions`：依登入者可讀 PS 範圍查清單，含 OPNo/Description/audit/DataStamp；OPName 如要回傳，應以目前 OP lookup join 取得，不寫入此表。
- `POST .../op-descriptions`：body 為 `opNo`、`description`；重查產品未核准、OP 屬於該產品已設定且使用者可讀的流程範圍，且產品版本沒有相同 OPNo。
- `PUT .../op-descriptions/{opNo}`：body 為 `description`、`dataStamp`；固定鍵值，只修改 Description/audit，CAS 衝突回 409。
- `DELETE .../op-descriptions/{opNo}`：要求明確 OPNo 並實體刪除。WinForms 多選依序呼叫；若提供 batch endpoint，需明確定義部分成功與回傳每筆結果。
- 查找沿用產品流程與 `LoadExpandProcess` 同等功能：由 server 根據 session 的 PD102/PS 權限取得流程與 OP，排除已設定 OPNo；Description 初值取 `TBLOPBASIS.Description`。避免用 client 傳入 `PSPrivilege` 來擴權。

目前 YMES repo 尚未看到 OPDescription 專用 endpoint/repository/table migration。正式 API、lookup 與 schema 尚待家用端；公司端此 Vue 頁僅 DEV 假資料寫入產品專用 localStorage，Production 模式唯讀，沒有使用 XML 或正式 API。
