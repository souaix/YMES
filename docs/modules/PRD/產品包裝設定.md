# PD102 產品包裝設定（Packing Set）

## WinForms、Service 與 Core

- `Customer/Production/MESWin/PRD/PD_ProductBasis_THEIL_BU1/frmProductBasis_THEIL_BU1.vb` 的 `btnPackingSet_Click` 先呼叫 `wsSYS.LoadParameter`。只有 `PackOperationMode` 的值等於 1 才開 `PD_ProductPackingRuleMap`，其他值開傳統 `PD_ProductPackingSet`。傳統 Form 收 ProductNo、ProductVersion、IssueState。多階 Map 開全體產品版次對應清單。
- 傳統主窗及 Designer 為 `STD/MESWin/PRD/PD_ProductPackingSet/frmProductPackingSet*.vb`。產品 IssueState 非 0 時停用數量 Set／Copy、配件 Add／Edit／Delete／Copy，以及包裝序號、Label Rule 的寫入按鈕。從 PD102 進入時鎖定產品選擇。
- Pack Setting 從產品主檔帶入 BoxQty、CartonQty、PalletQty、PackOIPath。BoxQty 大於 0，CartonQty、PalletQty 可為 0。CartonQty=0 時 PalletQty 必須是 0。Set 呼叫 `wsPRD.UpdProductPackSetting`，帶 DataStamp，路徑空白時舊 Form 不送 PackOIPath。Copy 選多個目的產品版次，呼叫 `wsPRD.CopyProductPackSetting` 及 `clsProduct.CopyProductPackSetting` 複製已儲存的四欄。
- 配件使用 `frmProductPackingAccessoryDef`／Designer 和 `frmProductPackingAccessoryCopy`。條碼 trim 後轉大寫，編輯時保留同一個條碼鍵。Service 為 `Load/Add/Edit/DelProductPackingAccessory` 和 `CopyProductPackAccessory`，對應 `clsProduct` 的明細 CRUD 與複製。複製會將每個目的產品版次的配件清單整批取代。
- 多階主窗與定義窗為 `PD_ProductPackingRuleMap/frmProductPackingRuleMap*.vb`，Designer 位於 Form 的 `InitializeComponent`。對應版次一組產品主鍵。規則 lookup 只取已核准規則。Current 存 `*`，Specified 必須選明確版次。Add／Edit／Copy／Delete 在 WinForms 會以 `wsWIP.LoadLotBasisJoinState` 檢查使用中的批次。新增、修改、刪除分別由 `wsPRD.Add/Edit/DelPRDPackingRuleMap` 處理，編輯另帶 DataStamp，由 `clsProduct`／`clsBasis_UPD` 執行。
- 包裝序號規則（SerialType 11 棧板、12 大箱、13 小箱）由 `frmProductSerialRuleDef` 維護，透過 `wsPRD.LoadProductSerialRuleBasis/Detail` 查主明細。標籤規則由 `frmProductLabelRuleDef` 與 Multi View 維護，有 basis、detail、multi detail。Preview 呼叫 `wsPRD.ExePRDLabelPreview`。

## Oracle metadata 與 Create SQL

- 使用 Windows PowerShell 5.1 + ODP.NET 從受保護 profile 唯讀查 MESTEST。Map 表的 `GET_DDL` 回 `ORA-03135`。七張設定表依 `ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_CONS_COLUMNS`、`ALL_INDEXES`、`ALL_IND_COLUMNS` 和 `ALL_TRIGGERS` 重建邏輯 DDL。未查業務資料。
- 七張表中有六張具 PK。序號主表 `TBLPRDPRODUCTSERIALRULEBASIS` 只有獨立唯一索引 `PK_PRDPRODUCTSERIALRULEBASIS`，欄序為 ProductNo、ProductVersion、SerialType，資料字典未列 PK constraint。Map 表的 PK 為 ProductNo、ProductVersion。七表均未回傳 FK 或 trigger。
- 產品主檔沿用既有 `TBLPRDPRODUCTBASIS`。本次另核對 BoxQty `NUMBER(8,4)` 可 NULL，CartonQty／PalletQty `NUMBER(8,0)` 必填，預設皆 0。PackOIPath 為可空 `VARCHAR2(500 BYTE)`。多階規則目錄沿用 `TBLPRDPACKINGRULEBASIS`，已查規則編號、版次、IssueState、CurVersion；目錄整表沿其主檔功能接續。

## DEV 檢查點與家用端 handoff

- `ProductPackingSet.vue` 接至 PD102，DEV 提供 PackOperationMode 切換。已完成三階數量 Set／多產品 Copy、包裝配件 Add／Edit／多選 Delete／整批 Copy、多階 Map Add／Edit／Copy／Delete 和 Current／Specified。DEV 使用同一產品版次的 localStorage。包裝規則及使用中批次以固定假資料示範。
- Serial Rule 可維護棧板、大箱及小箱規則與各段來源。DEV 驗證連續位置、固定來源長度、擷取起訖、自訂字串及一般流水號進位制，並將長度上限設為 99，符合 Oracle CodeStart／CodeEnd 的兩位數欄位。WinForms TotalLength 欄位接受 100，該邊界的正式相容性待家用端核對。
- Label Rule 支援 B1–B4、C1–C4、T1–T4、PrintCount、LabelPath、主明細、自訂／系統／組合來源與 Multi View。DEV Preview 以欄位值呈現固定文字、產品編號和組合結果，批次來源顯示代碼；暫不執行 `ExePRDLabelPreview`、讀取標籤模板或列印。
- DEV 的 PackOIPath 及 LabelPath 採用文字欄位。WinForms 的檔案對話框、2D 分隔符目錄及正式標籤引擎相容性待整合。Production 顯示 API 尚未接線。此檢查點以 Vue 靜態型別檢查和差異檢閱驗證，瀏覽器驗收待執行。
- 家用端先核對 live schema、first-phase 和 migrations。包裝主數量沿用產品主檔，配件與 Map 只補缺少欄位或表結構。對照序號主表的唯一索引與 live schema 後再安排 forward migration。
- 建議依現有產品版次路由新增 pack-settings、packing-accessories、packing-rules 契約。更新傳統設定時核對 IssueState、DataStamp 及欄位大小，Copy 自伺服器讀來源並明確驗證目的清單與交易。Map 由伺服器校驗已核准規則、版次與使用中批次，Edit 採 DataStamp CAS。序號、標籤及 Multi 的批次寫入與標籤路徑授權獨立驗證。
