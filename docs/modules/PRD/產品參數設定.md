# 產品 Parameter Setup（PD102 子功能）

## 功能定位

產品主檔側邊按鈕 `Parameter (&P)` 開啟 `PD_ParameterSetup`。這是依產品版本與產品流程作業站維護參數的階層編輯器，不是單表 CRUD。公司電腦頁面以 WinForms 真實操作方式呈現，DEV 假資料只寫入 `ymes.dev.prd-product-basis-relations.v1`；正式 API 模式唯讀。

## WinForms 原始碼依據

- Form/Designer：`STD/MESWin/PRD/PD_ParameterSetup/frmParameterSetup.vb`、`frmParameterSetup.resx`。
- 入口：`Customer/Production/MESWin/PRD/PD_ProductBasis_THEIL_BU1/frmProductBasis_THEIL_BU1.vb` 的 `btnParameter_Click`。傳入 ProductNo、ProductVersion、IssueState，要求先有產品流程資料並檢查 PS 權限。
- Service：`STD/MESws_STD/wsSTD/wsPRD/wsPRD.cs` 的 `LoadPRDOP`、`LoadPRDOPParameter`、`LoadPRDOPAttrib/Rule/EQPRecipe`、`Add/Edit/DelPRDOP*`、`UpdPRDOP`、`AddPRDOP`。
- Data/Core：`STD/MESkc/kcPRD/clsProduct.cs` 的產品 OP、Attrib、Rule、EQP Recipe 查詢及異動；作業站候選與流程限制由 `wsPRS`、`LoadExpandProcess` 等 lookup 提供。

## 畫面與操作

- WinForms ClientSize 約 947×591。左側約 359 px，右側約 582 px。
- 左側頂端標示 `Default OP`，可選 `Product Process OP`（預設）或 `All PS OP`，並有 Refresh 與流程樹。初始樹為 ProductNo[:Version] → PS → OP；右側資料依選取 OP 展開。
- OP 子樹包含 `Lot Attrib` → Key In/Calculate/System/Setup、（PS HaveComponent=1 時）`Component Attrib` → Key In/Calculate/System、Rule、Equipment。設備節點顯示 EquipmentNo(RecipeGroup)，Recipe Group 下顯示唯讀 RecipeNo:RecipeValue 明細。
- 右側 Tab 為 OP、Attrib、Rule、Equipment、Condition OP。QCItem Tab 在 Form Load 時被移除，WinForms 已取消產品參數的 QCItem 編輯功能，故本頁不重建。
- 主視窗右側有 Confirm、Cancel、Apply；視窗底部有 Refresh、Close。新增、修改、刪除呼叫服務後立即寫入 MES，不是整張樹的暫存交易。Apply 新增後清空欄位繼續新增；Confirm 執行後關閉；Cancel 取消尚未套用的目前編輯；Close 關閉視窗。
- 在產品 Root 上不提供右鍵新增。PS 節點提供 Add OP、Add Condition OP。OP 節點：條件 OP 可 Edit/Delete/View；沒有 NodeID/Script 的 Default OP 不可編輯，但可 Delete。IssueState 非 0 時，WinForms 依資料節點提供唯讀檢視。Lot/Component Attrib、Source、Rule、Equipment 分類節點提供對應新增；Attrib/Rule 明細提供 Edit/Delete/View；EquipmentNo(RecipeGroup) 節點提供 Add/Edit/Delete，Recipe Detail 節點唯讀。
- `Product Process OP` 限制到產品流程內可用 OP；`All PS OP` 顯示所有可用 PS/OP。新增 OP 以清單勾選，可一次加入多筆。Add Condition OP 從 PS 節點開啟，OPNo 必須選自該 PS 的 OP。

## 欄位與驗證規則

### Attrib

- AttribType：0 Lot、1 Component。AttribSource：0 Key In、1 Calculate、2 System、3 Setup；Component 不提供 Setup。
- AttribNo、AttribPhase、Sequence、AttribValue、AttribScript、SaveToLotPropertyNo、QCItemNo。Component Attrib 不顯示 QCItem 欄位。
- AttribNo 由 Element Basis lookup；Phase 來自 Phase Basis。值型態及允許值由 SYS Element/Parameter 定義，不可把前端選項當可信任規則。
- AttribNo 與 Phase 必填；Key In/Calculate 不允許 Phase=99 (All)；Calculate 必須有 Script；Setup 必須有預設值。非數值 Element 不得 SaveToQCItem。數值值超過四位小數會提示確認。
- 新增/修改服務為 `AddPRDOPAttrib` / `EditPRDOPAttrib`，刪除為 `DelPRDOPAttrib`。WinForms 執行時驗證 Element value、SaveToProperty 等 SYS 規則。

### Rule

- RuleNo、RulePhase、RuleScript、RuleType（Lot/Component）、RuleSequence；RuleClass 選項依該 OP 可用的 Control Rule/套件動態載入，CP/FT 專用規則另走 CP/FT Service，不可視為一般 Rule 欄位的等價實作。
- RuleNo、Phase、Script、Type 必填。一般 Rule 使用 `Add/Edit/DelPRDOPRule`；CP/FT 另有 `Add/Edit/DelCPPRDRule`、`Add/Edit/DelFTPRDRule`，其條件、通知與 XML/套件資料須由家用端按實際需求接續。

### Equipment / Recipe

- 在 OP 的 Equipment 分類新增時可複選設備並指定 RecipeGroup。設備候選由產品/OP 可用設備查詢提供。EquipmentNo + RecipeGroup 關聯存於產品 OP SerialNo；Recipe Detail 由 Recipe Group 主檔載入且唯讀，不在本畫面維護。
- 新增多筆使用 `UpdPRDOPEQPRecipe`；單筆 `Add/Edit/DelPRDOPEQPRecipe`。EquipmentNo、RecipeGroup 主檔需由 EQP lookup API 提供。

### OP 與 Condition OP

- TBLPRDOP 儲存產品版本、PS、OP、OPOrder、SerialNo；無 NodeID/Script 代表 Default OP。條件 OP 儲存 NodeID、OPScript（至少其中一項），樹節點名稱會註明 Condition。
- Product Process OP 新增使用 `UpdPRDOP`；Condition OP 使用 `AddPRDOP`，修改使用 `EditPRDOP`，刪除使用 `DelPRDOP`。SerialNo 應由 Server 產生，不能信任瀏覽器傳入值。
- Condition OP 的 OPNo 必填，NodeID 或 OPScript 至少一項。OPNo lookup 範圍依所選 PS。

## Oracle 資料表與字典核對

公司電腦以 Windows PowerShell 5.1、`Oracle.ManagedDataAccess`，透過本機受保護的既有 Oracle 連線設定連到 MESTEST；本次只查 `ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_CONS_COLUMNS`、`ALL_INDEXES`、`ALL_IND_COLUMNS` 與 `ALL_TRIGGERS`，未查業務資料列、未執行 Oracle DDL/DML。連線秘密保留在受保護本機設定，不寫入 Git。`DBMS_METADATA.GET_DDL` 在本次呼叫時回 SocketException；欄位、NULL、PK、索引由 Oracle 字典直接取得後重建邏輯 CREATE DDL，故來源檔不包含 Oracle tablespace/storage 實體屬性。

| Oracle 表 | 用途 | 欄位數 | PK | 其他索引 |
|---|---|---:|---|---|
| TBLPRDOP | 產品版本/PS/OP 與條件 OP | 8 | SerialNo | 非唯一 `(ProductNo, ProductVersion, OPNo)` |
| TBLPRDOPATTRIB | Lot/Component Attrib | 14 | `(SerialNo, AttribNo, ECNNo, EquipmentType)` | 無 |
| TBLPRDOPRULE | OP Rule | 9 | `(SerialNo, RuleNo)` | 無 |
| TBLPRDOPEQPRECIPE | 設備與 RecipeGroup 關聯 | 3 | 無 | 非唯一 `(SerialNo, EquipmentNo, RecipeGroup)` |
| TBLPRDOPRULEXML_CLOB | 產品 OP Rule XML | 4 | `(ProductNo, ProductVersion, OPNo)` | 無 |
| TBLPRDOPBUSINESSRULE | 產品 OP BusinessRule 舊版 XML | 4 | `(ProductNo, ProductVersion, OPNo)` | 無 |
| TBLPRDOPBUSINESSRULERELATION | BusinessRule 節點關聯 | 7 | `(ProductNo, ProductVersion, OPNo, FromNode, ToNode, LinkName)` | 無 |
| TBLPRDOPAREA | 產品 OP Area | 5 | `(ProductNo, ProductVersion, OPNo, AreaNo)` | 無 |

八表均未查到 FK 或 Trigger。前四表為本頁主要設定表；後四表是 Rule XML、Business Rule/OP Area 相鄰或套件支援資料，家用端應先依實際要接的功能核對，不要因本頁 SQL 參考而一併建立。

**重要待核差異：** `TBLPRDOPATTRIB.ECNNO`、`EQUIPMENTTYPE` 在 Oracle 欄位字典均為 NOT NULL，且位於複合 PK；本次確認無 Trigger。可讀到的 `wsPRD.AddPRDOPAttrib` / `clsProduct.AddPRDOPAttrib` payload 只顯示 Attrib 欄位及 QCItemNo AdditionalXml，沒有明確看到這兩欄來源。家用端開始寫 API 前，需再對照該產品客製組態、執行環境 Add XML/AdditionalXml 及其他版本 `wsPRD`，確認 Server 如何取得這兩個值；不得用空字串或前端自行填值猜過去。

Oracle 邏輯來源與 PostgreSQL CREATE-only 對照：

- `database/reference/mestest_prd_parameter_setup_source_ddl.sql`
- `database/reference/mestest_prd_parameter_setup_create.sql`

PG 檔依 Oracle 字典重建結構且只供比對，並非 migration；上線前必須檢查 YMES live PostgreSQL schema/migration，只新增真正缺少的表/欄位/索引。`TBLPRDOPATTRIB` PK 以及 `TBLPRDOPEQPRECIPE` 沒有 PK/唯一索引等語意不可被 ORM convention 改寫。

## YMES API handoff

建議提供一個組合式讀取端點 `GET /api/products/{productNo}/versions/{version}/parameters?scope=process|all`，回傳 PS/OP 樹、OP SerialNo/條件、Attrib、Rule、Equipment/RecipeGroup 及 Recipe Detail lookup；若既有 API 習慣分拆 endpoint，可依相同 DTO/交易語意拆開。異動契約至少涵蓋：

- OP assignments：新增現有製程 OP、Condition OP 新增/修改/刪除；SerialNo 由 Server 產生，驗證 ProductNo/Version、PS/OP lookup、產品 IssueState 與操作權限。
- Attrib：查詢 Element/Phase/Parameter lookup；新增、修改、刪除。以 Oracle 複合鍵對應，確保 ECNNo/EquipmentType 來源；重做 Element Value、Source/Phase、SaveToProperty/QC Item 規則。
- Rule：一般 Rule CRUD 與查詢 Control Rule/Phase；CP/FT Rule 若需支援，獨立定義套件 API 與交易，不能把 `RuleClass` 的三個數字直接當一般 Rule CRUD。
- Equipment Recipe：設備候選、RecipeGroup 候選/明細、EquipmentNo 多選關聯新增、RecipeGroup 編輯、設備關聯刪除；防止重複寫入無 unique index 的 Oracle 關聯語意。
- 所有寫入只接受未核准 IssueState=0；由 Server 驗證產品/PS 權限和 lookup，不接受前端傳來的已核准屬性或任意 SerialNo。Oracle 這四張主表沒有 DataStamp 欄位；YMES 若建立自有版本/Concurrency 欄位，需明確記錄不等同 MES 原生欄位。
