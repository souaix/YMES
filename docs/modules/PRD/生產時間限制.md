# PD106 生產時間限制（站與站）

- `PRD / LIMITED TIME CONTROL`，Web `/YMES/PRD/TimeLimits`。舊窗與內嵌 Designer 在 `STD/MESWin/PRD/PD_MaxTime/frmPRDMaxTime.vb`、`frmPRDMaxTimeDef.vb`。`wsPRD` 以 `Load/Add/Edit/Del/ApprovePRDLimitedTimeControl` 呼叫 `STD/MESkc/kcPRD/clsProduct.cs` 的主檔、Hold 與歷程方法。
- `Boundary` 存 `max`／`min`；`OPReference=0/1/2` 依序為產品／模組／流程；MOType `*` 存 `-1`。版次及起迄站由參照展開選取，BR 用於 CheckIn/CheckOut 或 `N/A`。同站用 CheckIn→CheckOut 且禁止中間站觸發 Hold；跨站兩端都須指定規則或都用 `N/A`。設備狀態檢核只在產品模式啟用。
- 修改鎖定複合鍵。`IssueState=0` 可修改與核准，`0/-1` 實體刪除，`2` 轉 `-1`，`1` 禁止刪除。正式核准依簽核工作設定和參照資料狀態。Core 編輯時將舊值寫入歷程，再保存主檔與 Hold 原因。
- DEV 已完成四狀態篩選、ADD／EDIT／Copy／Approve／DEL、起迄驗證、Hold 原因與本機保存。參照、站序、BR 和 Hold 分類使用固定假資料。分鐘依 Oracle `NUMBER(7,2)` 接受大於 0 的兩位小數；原視窗使用 `CInt` 判斷正值。DEV 依假流程的作業順序驗證；正式模式需按已展開節點和系統設定判斷。正式簽核、歷程讀取及設備檢核引擎待接入。

## Oracle 與家用端交接

- PowerShell 5.1 + ODP.NET 唯讀核對 `TBLPRDLIMITEDTIMECONTROL` 20 欄、`TBLPRDLIMITEDTIMECONTROLLOG` 13 欄、`TBLPRDLIMITEDTIMEHOLDREASON` 9 欄。附 [Oracle 邏輯 DDL](../../../database/reference/mestest_prd_time_limit_source_ddl.sql) 及 [CREATE-only](../../../database/reference/mestest_prd_time_limit_create.sql)。主鍵含 Boundary、參照編號與版次、MOType、起迄站及起迄 BR，未包含 OPReference。歷程另以建立時間入鍵，Hold 原因另含 HoldItemNo。
- Hold 原因的 Oracle `REFERENCEVERSION` 長 3 byte，主檔及歷程為 5 byte。家用端寫入前應核對 live schema，避免主檔可存但關聯列無法保存。
- 建議 `GET/POST /api/prd/time-limits` 與複合鍵的更新、刪除及核准操作。用已核准參照及已授權作業展開驗證起迄，核對 BR、Hold 類別、狀態及 DataStamp。編輯時把舊值歷程、主檔更新和 Hold 原因替換放進同一交易。
