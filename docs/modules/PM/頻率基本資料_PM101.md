## 畫面與資料規則

- 預設開啟 Unfrozen（`IssueState=0`），以 `FrequencyNo` 作搜尋欄位；狀態頁籤為 Unfrozen `0`、Pending `1`、Active `2`、Unused `-1`。
- Grid 顯示 FrequencyNo、FrequencyName、Priority、FixedType、FixedTypeValue、Period、Description、Creator／CreateDate、Reviser／ReviseDate；狀態用頁籤篩選，IssueState 與 DataStamp 不顯示。
- FrequencyNo 最長 30 字元；FrequencyName 最長 50 字元；Priority 的 WinForms NumericUpDown 範圍為 1–99。編輯時 FrequencyNo 唯讀。
- FixedType 編碼與值：

| FixedType | 意義 | FixedTypeValue | Period |
| ---: | --- | --- | --- |
| 0 | 無固定日期的期間 | 空字串 | 期間數值 |
| 1 | 每週 | 星期索引，星期日為 0，星期六為 6 | 空值 |
| 2 | 每月 | 日，1–31 | 空值 |
| 3 | 每年 | `月/日`，例如 `6/30` | 空值 |

- 舊驗證在 FixedType=0 時拒絕負數，但錯誤訊息說期間必須大於 0；程式條件本身仍接受 0。DEV 保留 0 可存並標出此差異，不自行改寫來源規則。
- 年度日期的舊表單以目前年份除以 4 是否整除決定 2 月可選 28 或 29 日；這不是完整閏年規則，DEV 保留來源行為並標示。

## 操作與狀態

- 新增與複製建立 `IssueState=0`；複製畫面沿用原 FrequencyNo，操作者需改成未使用的新代碼，否則會撞主鍵。
- 只有 Unfrozen 可修改；修改保留 FrequencyNo、Creator、CreateDate，更新 Reviser／ReviseDate，並遞增 DataStamp。
- 刪除允許 Unfrozen 與 Unused 硬刪；Active 轉成 Unused（`IssueState=-1`）；Pending 不允許刪除。硬刪可能因其他資料參照而失敗。
- 核准動作只接收 Unfrozen。Service 依 Issue Management 的 `FREQUENCY BASIS` job map 決定流程：沒有簽核設定／明細時直接轉 Active；設定簽核流程時送入 Pending 並通知簽核群組。DEV 以本機核取方塊模擬直接生效或送簽，不寄信、不呼叫簽核服務。
- State 變更更新 Reviser／ReviseDate 及 DataStamp。DEV 僅做本機 optimistic check，沒有跨使用者一致性保證。

## 已知來源限制與風險

- Core 的 Load/Add/Del 舊方法以 SQL 字串組合條件／欄值；查詢沒有穩定排序或頁數限制。正式 API 必須參數化、授權範圍查詢、穩定排序並限制頁數。
- 舊 Core 編輯／狀態更新 helper 使用 FrequencyNo + DataStamp，更新成功才回報成功；家用端需保留版本衝突語意，並以交易保護狀態變更。
- 選單快照能證明表名 `TBLPMFREQUENCYBASIS`，不能證明欄位型別、PK、索引、外鍵、預設值或完整約束。桌機受保護 Oracle profile 不存在，本輪沒有查 MESTEST 業務 DDL／metadata。

## 家用端 API／schema handoff

1. 先核對 PostgreSQL live schema 與既有 migrations；避免覆建既有表。缺表時才按已確認來源建立 CREATE-only migration，欄位型別、長度、PK、索引、FK 與 nullability 須由實際 schema／可用 DDL 證據確認；目前沒有足夠資料產生可信 CREATE SQL。
2. 提供登入授權的 FrequencyBasis 查詢，接受 `frequencyNo`、`issueState` 與分頁；固定排序，設定頁數上限。舊 UI 預設只搜 FrequencyNo，但 Web API 不應允許無界全表讀取。
3. 新增／修改 DTO 對應 FrequencyNo、FrequencyName、Priority、FixedType、FixedTypeValue、Period、Description；伺服器驗證編碼和值之間一致。修改以 FrequencyNo + DataStamp 做 optimistic concurrency，寫入 Reviser／ReviseDate。
4. 核准 command 在交易內重讀 IssueState／DataStamp，依已建置的 workflow 設定走 Active 或 Pending；正式簽核／郵件整合依家用端共用 workflow 能力實作，不能以 DEV 開關作正式設定。
5. 刪除 command 在交易內重查狀態與 DataStamp：0／-1 可嘗試硬刪，2 改成 -1，1 拒絕；需回傳引用限制或版本衝突，不可靜默成功。
