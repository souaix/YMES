# PM506 設備保養效率查詢

## 功能與來源

- FunctionNo：`PM PERFORMANCE QUERY`
- FunctionKey：`PM506`
- WinForms：`D:\iMES\CSiMES\STD\MESWin\PM\PM_Performance\frmPMPerformance.vb`（畫面與 Designer 初始化同檔）
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsPM\wsPM.cs` 的 `LoadPMPerformance`、`LoadSingleTableDistinceData`
- Core：`D:\iMES\CSiMES\STD\MESkc\kcPM\clsPMPlanLog.cs` 的 `LoadPMPerformance`、`LoadSingleTableDistinceData`
- Vue DEV：`/YMES/PM/Performance`，FunctionKey 為 `function:PM:PM PERFORMANCE QUERY`

此頁唯讀查詢已完工的保養與需求工單明細，將 SOP 預估工時與實際下線至完工耗時並列。PM506 直接業務表 DDL／metadata 尚未核實；公司桌機沒有可用的受保護 Oracle profile，故不提供猜測的 CREATE SQL。

## WinForms 條件與操作

Form 載入時以雙清單提供四組多選條件，清單初始全部位於 Available，使用者可透過方向按鈕或雙擊移到 Selected：

| 條件 | 舊程式載入來源 |
| --- | --- |
| Equipment No | `tblEQPEquipmentBasis.EQUIPMENTNO` distinct |
| PM WO No | `tblPMWODetail_His.WONO` distinct |
| Frequency No | `TBLPMFREQUENCYBASIS.FREQUENCYNO` distinct |
| PM Executor | `TBLPMWODETAIL.EXECUTOR` 與 `TBLPMWODETAIL_HIS.EXECUTOR` distinct 合併去重 |

另有兩組日期區間：Estimated PM Date、WO Finished Date。起訖端點可個別勾選，Designer 預設均未勾選。工單類型預設 All；`PM Work Order` 傳 `WOType=0`，`Required Work Order` 傳 `WOType=1`，All 不傳類型值。按 Query 後載入唯讀 Grid；Close 關閉視窗。

舊畫面先載入 `wsEQP.LoadEquipmentBasis(ChamberFlag=1)` 與 `wsSYS.LoadParameter(ChamberManage)`。當 ChamberManage 不等於 `1` 時，雙清單及結果 Grid 都排除子設備；DEV 假資料按未啟用子設備管理呈現。

## Service／Core 查詢邏輯

Service `wsPM.LoadPMPerformance` 解析設備、工單、頻率、執行人、兩組日期、WOType 與 AdditionalXml，再呼叫 Core `clsPMPlanLog.LoadPMPerformance`。四組文字條件由舊 Service 組成 SQL `IN (...)` 值；家用端 API 必須改用參數化清單，不可複製舊字串拼接方式。

Core 將三類資料合併：

1. `tblPMEQPMaintenancePlanLog` 與 `tblPMSOPBasis`、`tblPMWODetail` 內連：`ExecuteState=4`，以 PMWONo + PMWOItemNo 對工單明細，WOType 固定 0。
2. 同一保養計畫 Log／SOP 與 `tblPMWODetail_His` 內連：同樣要求 `ExecuteState=4`，WOType 固定 0。
3. `tblPMWOBasis_His`、`tblPMWODetail_His`、`tblPMSOPBasis` 內連：`A.WONo=B.WONo`、`B.PMSOPNo=C.PMSOPNo`，只取 `A.WOType=1` 的 Required Work Order；FrequencyNo 為空字串。

Equipment、PM WO No、Executor、Estimated PM Date、WO Finished Date 條件會分別套用至對應的 current、history 與 required 分支。選 Frequency 時，Required 分支因 FrequencyNo 為空而不會符合。All 合併三個分支，PM Work Order 合併前兩個分支，Required Work Order 只查第三個分支。

可見欄位依序為 Equipment No、Frequency、SOP、EST Date、WO No、Item No、Est Done、Act Done、Executor、Release Date、Finished Date、WO TYPE。Grid 將 `PMEQPSOPNO`、`PMSERIALNO`、Creator／Reviser、Create／Revise 日期、WO Create Date、ExecuteState、Log Creator／Log Create Date 隱藏。Est Done 來自 SOP `EstDoneTime`；Act Done 為小時、顯示兩位小數。Oracle Core 公式為 `Round((FinishedDate - ReleaseDate) * 24, 2)`；SQL Server 分支以分鐘差除以 60 並保留兩位小數。工單類型 ValueList 來自 `TBLPMWOBASIS_HIS.WOTYPE`。

## Vue DEV 與已知差異

Vue 頁在 `web/src/components/PmPerformance.vue` 與 `PmPerformanceDevPreview.vue`。以本機固定假資料呈現四組多選雙清單、兩組端點可獨立啟用的日期範圍、All／PM／Required 類型、Query 與 12 欄唯讀結果。空清單代表不限制；日期迄日包含整日。查詢結果以 Service/Core 三分支規則模擬，並套用 ChamberManage 關閉時排除子設備的規則。

靜態核對發現 Core 的 `WOFinishedDateEnd` 日期端點分支，在判斷是否將日期補到當日 23:59:59 時誤讀 `EstPMDateEnd`。Vue DEV 依畫面「WO Finished Date」的日期篩選意圖採整日含括；正式 API 應以可測試的日期邊界規則實作並由家用端確認是否修正此舊程式缺陷。

## 家用端 API／schema handoff

- 建議提供 `GET /api/pm/performance/filters` 回傳 equipment、歷史工單、frequency、current／history executor 清單，並依 ChamberManage 規則處理子設備。
- 建議提供唯讀 `GET /api/pm/performance`，接受 `equipmentNos[]`、`pmWoNos[]`、`frequencyNos[]`、`executors[]`、`estimatedPmFrom`、`estimatedPmTo`、`woFinishedFrom`、`woFinishedTo`、`workOrderType=all|pm|required` 與分頁參數；需回傳上述 12 個顯示欄位及 `totalCount`。
- 家用端 2026-11-27 以 SSH 唯讀檢查正式 PostgreSQL YMES catalog：`tbleqpequipmentbasis` 存在；`tblpmwodetail_his`、`tblpmfrequencybasis`、`tblpmwodetail`、`tblpmeqpmaintenanceplanlog`、`tblpmsopbasis`、`tblpmwobasis_his` 均不存在。repo 只有導覽種子提及表名，沒有可信 Oracle source DDL／metadata 或 PostgreSQL CREATE-only。未建立猜測性 schema。公司端須交付六表原生 DDL／metadata；詳 [公司端待辦](../../../todolist_officepc.md)。
- 收到同版來源後，再核欄位型別、主鍵／外鍵、明細連接唯一性、日期欄位可空性與 WOTYPE 值並提供可信 CREATE-only SQL；不要在公司端建立 schema 或連 PostgreSQL。
- 舊 Core 對時間、清單值採 SQL 字串拼接且沒有分頁；正式 API 應使用參數化查詢、明確分頁與上限。PMPerformance 的日期相減、空 Frequency 的 Required 工單與 ChamberManage 行為需保留並加入家用端驗收案例。
