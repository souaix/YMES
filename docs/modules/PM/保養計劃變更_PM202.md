# PM202 保養計劃變更

## 功能與來源

- 選單為「設備 PM 設定 → 保養計劃變更」，FunctionNo `PM PLAN CHANGE`、FunctionKey `PM202`。DEV 入口 `/YMES/PM/MaintenancePlanAdjust`。
- 已核對 `STD/MESWin/PM/PM_EQPMaintenancePlanAdjust/frmEQPMaintenancePlanAdjust.vb` 與 `frmEQPMaintenancePlanAdjustDef.vb`／Designer、`MESws_STD/wsSTD/wsPM/wsPM.cs`、`MESkc/kcPM/clsPMBasis.cs`。
- Service/Core 主要方法：`LoadEQPMaintenancePlan`、`EditEQPMaintenancePlan`、`MoveEQPMaintenancePlanToLog`；計畫頻率透過 `LoadFrequencyBasis` 載入。

## WinForms 行為

- 查詢條件為年度、月份、設備編號。年度可輸入民國年（少於四位時加 1911）；月份必須是有效日期的一部分；設備編號必填並在離開欄位時轉大寫。年度查找使用 `tblSYSYearDefinitionBasis`。
- Show 呼叫 `LoadEQPMaintenancePlan` 時只傳 EquipmentNo。Core 取得該設備所有 `PMSerialNo IS NOT NULL` 計畫，沒有傳年度或日期界限；Form 再於本機篩選當月、依 PM Serial 排序並畫月曆。月曆支援前／後月導覽；有計畫的日期以橘紅色標示並顯示有效頻率名稱及 Priority。
- 頻率清單呼叫 `LoadFrequencyBasis(IssueState=2)`，只顯示已生效頻率。設備清單由設備主檔載入，`ChamberManage` 會影響是否含子腔體。
- 雙擊有計畫的日期開啟變更視窗，選擇該日頻率後可調整預計保養日期，或取消該計畫。調整呼叫 `EditEQPMaintenancePlan`，只依 SerialNo 更新 `PMEstDateTime`、`Reviser`、`ReviseDate`；沒有 DataStamp／版本條件。
- 取消呼叫 `MoveEQPMaintenancePlanToLog`，傳 `ExecuteState=0`。舊表單在同日多筆資料時以日期資料列的第一筆 SerialNo 呼叫取消，未必是下拉選取的頻率；DEV 讓使用者明確選取 SerialNo，避免複製這個錯誤。
- 原始月份欄位 Leave 處理在比較新月份時拿 `tmpMonth` 與 `datePaint.Year` 比較，疑似比較錯欄位。DEV 依查詢與月份導覽直覺操作，未複製此問題。

## Core 資料與已發現問題

- 直接使用 `tblPMEQPMaintenancePlan`；取消會觸及 `tblPMEQPMaintenancePlanLog`。頻率參照為 `tblPMFrequencyBasis`，年度參照為 `tblSYSYearDefinitionBasis`；設備參照走設備主檔查找。
- `MoveEQPMaintenancePlanToLog` 依 SerialNo 讀取活動計畫，排入「新增 PlanLog、刪除活動計畫、再刪除同 SerialNo PlanLog」三個 SQL，且各自要求異動一列。按此序列執行時，剛新增的歷史列隨即被刪掉，無法保留取消紀錄。這是觀察到的舊 Core 缺陷；家用端取消 API 應以單一交易保留 `ExecuteState=0` 歷史列並移除活動列，不應照抄最後的 PlanLog 刪除。
- 舊 Edit 以 SerialNo 更新且不做版本檢查；正式 API 應在伺服器重新確認計畫存在與可調整狀態，並以版本欄位或條件式更新避免覆寫併發修改。

## 公司端 DEV 實作

- Vue 元件為 `web/src/components/PmMaintenancePlanAdjust.vue` 與 `PmMaintenancePlanAdjustDevPreview.vue`；入口已掛到「設備 PM 設定」選單。
- 使用 PM201 共用 localStorage `ymes.dev.pm.eqp-type-sop-basis.v1`，讓 PM 計畫與設備類型 SOP 假資料保持一致；頻率優先讀 PM101 共用 key `ymes.dev.pm.frequency-basis.v1` 的 IssueState=2 資料，沒有資料時顯示 DEV 頻率樣例。
- DEV 提供年度／月份／設備查詢、月曆前後導覽、計畫日期與頻率摘要、選取多筆計畫、日期調整及取消確認。取消會把計畫移至 `planLogs`，設 `ExecuteState=0` 並記錄 DEV 操作者／時間；這是修正後的預期互動，不模擬舊 Core 刪除歷史列的缺陷。
- 假設備、年度區間與少量排程供互動預覽，不是 MES 設備／年度資料。DEV 月曆僅載入所選設備的本機假計畫；不代表正式查詢可無界讀取全部設備資料。

## 家用端 API、schema 與 SQL handoff

- 建議查詢以設備與日期範圍限量：`GET /api/pm/maintenance-plans?equipmentNo={no}&from={date}&to={date}`；分頁並穩定排序。計畫調整可用 `PATCH /api/pm/maintenance-plans/{serialNo}`；取消可用 `POST /api/pm/maintenance-plans/{serialNo}/cancel`，在單一交易中檢查狀態、寫 PlanLog (`ExecuteState=0`) 並移除活動列。
- 相關實體為 `tblPMEQPMaintenancePlan`、`tblPMEQPMaintenancePlanLog`、`tblPMFrequencyBasis`、`tblSYSYearDefinitionBasis` 與設備主檔。先核對 live PostgreSQL schema、Oracle source metadata、主鍵／唯一索引／外鍵／日期精度，以及現有 YMES migration，再決定映射與版本欄位。
- 公司桌機上的受保護 Oracle profile 不存在，repo 亦未找到可核實的計畫／計畫歷史 DDL。本次沒有連 Oracle、沒有查業務資料、沒有猜測或新增 PostgreSQL CREATE-only SQL；需家用端取得可信 metadata 後再補 SQL handoff。
- 公司端未連 YMES PostgreSQL、未實作或驗收正式 API、未部署。未執行 build、test 或 browser；本次僅作程式碼靜態檢閱。
