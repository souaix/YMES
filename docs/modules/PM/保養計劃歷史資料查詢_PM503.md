## WinForms 行為

- Form Load 先呼叫 `funInitialize`，讀設備主檔及 `ChamberManage` 參數，然後分別載入歷史資料中的設備、Frequency No、EQP SOP No、SOP No distinct 清單。未啟用子設備管理時，設備清單及查詢結果都排除 Chamber 子設備；其他三組清單沒有額外狀態篩選。
- 查詢條件是四組多選雙清單（Equipment No、EQP SOP No、Frequency No、SOP No）、可各自勾選啟用的 Estimated PM Date From／To，以及五個 Execute State：0 Adjust To Cancel、2 WO Created、3 WO Released、4 WO Finished、5 Deleted。狀態全部未勾選時不加 ExecuteState 條件，會查所有狀態。`funCombin_Filter` 只被報表條件使用；一般 Query 以結構化 XML 參數呼叫 Service。
- Query 呼叫 `wsPM.LoadMaintenancePlanLog`，提交設備、EQP SOP、Frequency、SOP 清單、預估日期界限及狀態清單。Form 將迄日組成當日 `23:59:59`，XML 格式化成午夜；Core 會把純日期迄日補到 `23:59:59`。查詢結果再於 UI 排除子設備，並設定 `CreateDate` 升冪排序。
- Core 從 `tblPMEQPMaintenancePlanLog a` 取 `a.*`，並以 `FrequencyNo` 內連 `TBLPMFREQUENCYBASIS b`、以 `PMSOPNo` 內連 `tblPMSOPBasis c`，附加 `FREQUENCYNAME`、`PMSOPNAME`。沒有對應頻率或 SOP 主檔的歷史列不會出現在結果中。
- UltraGrid 欄位順序：`PMEQPSOPNo`、`EquipmentNo`、`PMSerialNo`、`FrequencyNo`、`PMEstDateTime`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`、`PMWONo`、`PMWOItemNo`、`WOCreateDate`、`WOReleaseDate`、`WOFinishedDate`、`ExecuteState`、`LogCreator`、`LogCreateDate`、`FrequencyName`、`PMSOPName`。日期欄位使用 `yyyy/MM/dd` 或 `yyyy/MM/dd HH:mm:ss`；ExecuteState 顯示上方狀態文字。
- Service／Core 還支援 Creator、建立／修改人日期、工單號／項次與工單建立／下線／完成日期、Log 建立日期等參數，但本 Form 沒有呈現或送出這些條件。不要把它們誤當成目前 UI 的查詢條件。
- 舊 Core 將清單及日期直接串入 SQL；家用端正式 API 必須使用參數化條件，並加分頁及上限。舊 distinct/query 呼叫也會分別連線查詢，可合併為受控唯讀 lookup。

## 家用端 API／schema handoff

- 建議唯讀分頁端點 `GET /api/pm/maintenance-plan-logs`，支援 `equipmentNos`、`pmEqpSopNos`、`frequencyNos`、`sopNos`、`pmEstDateFrom`、`pmEstDateTo`、`executeStates`、`page`、`pageSize`；日期迄日按使用者當地日期含當日處理。回傳上述 19 欄所需資料及 `totalCount`，穩定排序使用 `CreateDate, PMEQPSOPNo, PMSerialNo, LogCreateDate`。
- 基礎資料需求涉及 `tblPMEQPMaintenancePlanLog`、`TBLPMFREQUENCYBASIS`、`tblPMSOPBasis`；需核實 PM 計畫／工單號鍵、頻率與 SOP 關聯、歷史表保留方式、索引及 enum 對照。
- 公司桌機目前沒有可用的受保護 Oracle MESTEST profile，無法以 PowerShell 5.1 + Oracle.ManagedDataAccess 讀取這些表的 DDL／metadata。欄位型別、長度、PK／FK、索引及 PostgreSQL CREATE-only SQL 均待家用端核 live schema 與同版 MESTEST 後提供；未猜測或新增 CREATE SQL。公司端不連 PostgreSQL、不實作正式 API/schema。
