# PM203 設備定量保養設定

## 功能與來源

- 選單為「設備 PM 設定 → 設備定量保養設定」，FunctionNo `EQP FIXED QUANTITY SETUP`、FunctionKey `PM203`。DEV 入口 `/YMES/PM/FixedQuantitySetup`。
- 已核對 `STD/MESWin/PM/PM_FixedQuantitySetUp/frmFixedQuantitySetUp.vb`（含 inline Designer）、`frmFixedQuantityDef.vb`、`frmFixedQuantityDef_EQP.vb`，以及 `MESws_STD/wsSTD/wsPM/wsPM.cs`、`MESkc/kcPM/clsPMBasis.cs`、`MESkc/kcBasis_UPD/clsBasis_UPD.cs`。
- Service/Core 方法：`LoadFixedQtyPMBasis`、`AddFixedQtyPMBasis`、`EditFixedQtyPMBasis`、`DelFixedQtyPMBasis`、`UpdFixedQuantityPMBasis`。

## WinForms 畫面與資料規則

- 主畫面分成設備類型定量主檔與所選類型的設備定量明細兩個 Grid。查詢欄位是 EquipmentNo；類型列依 EquipmentNo 排序並只顯示 `TypeCode=1`，選取類型後，下方只顯示相同 EquipmentType 且 `TypeCode=0` 的設備列。
- `tblPMFixedQtyPMBasis` 同時存類型預設與設備個別值：類型列以 EquipmentNo=EquipmentType、TypeCode=1 表示；設備列以真實 EquipmentNo、TypeCode=0 表示。設備列可能覆寫類型預設。
- 類型主檔支援 Add、Edit、Copy、Delete、SET。Edit 以 DataStamp 更新；Copy 走新增模式。Delete 傳 TypeCode=1，Core 以 EquipmentType 刪除整個類型的設定，含設備子列。設備列支援 Edit／Delete，傳 TypeCode=0 與設備編號。
- SET 視窗以 EquipmentType 查 `LoadEquipmentBasis`，`ChamberManage` 參數決定是否納入腔體；左右多選清單維護適用 EquipmentNo。確認呼叫 `UpdFixedQuantityPMBasis`：先刪除該 EquipmentType 的既有設備列，再逐台新增 `TypeCode=0` 列，數量、單位、寬限、AutoCreateWO、SOP、鎖機狀態及 Email 均複製類型預設。空清單會清掉現有設備列。
- 定義欄位：Quantity、ToleranceQty（Grid 別名 ToleranceAccumQty）、UnitNo、AutoCreateWo、PMSopNo、LockEquipment、EquipmentState、AutoEmail 與 Creator／CreateDate／Reviser／ReviseDate／DataStamp。頻率／累計觸發本身由後續 PM 排程／工單流程使用，本表單只維護設定。
- 參照查找：`wsEQP.LoadEquipmentType`、`wsEQP.LoadEquipmentBasis`、`wsSYS.LoadUnit`（IssueState=2）、`wsEQP.LoadEQPStateBasis`、`wsPM.LoadSOPBasis`。AutoCreateWo 開啟時 SOP 必填；LockEquipment 開啟時 EquipmentState 必填。Quantity 必須大於 0；ToleranceQty 若啟用須大於 Quantity。舊 UI 的 Unit 必填驗證已註解；Service/Core 將 Quantity、ToleranceQty 轉整數。
- IssueVisable=False，沒有簽核狀態／Approve 工作流。

## Service/Core 注意事項

- 新增及刪除經 `clsPMBasis`；Edit 由 Service 呼叫 `clsBasis_UPD.EditFixedQtyPMBasis`，以 EquipmentNo + DataStamp 條件更新並把 DataStamp 加 1，要求異動一列。
- `UpdFixedQuantityPMBasis` 在 Service 先刪除同 EquipmentType 的 TypeCode=0 列，再逐一新增新列；Delete 與多筆 Insert 沒有共同交易，失敗時可能清空或部分重建設備設定。批次刪除 UI 也是逐筆呼叫，遇錯時之前已成功的列不回復。
- Edit 時若關閉 AutoCreateWo，Form 會送空 PMSopNo；Core `clsBasis_UPD.EditFixedQtyPMBasis` 僅在 PMSopNo 非空時更新欄位，可能留下舊 SOP 編號。家用端 API 應在 AutoCreateWo=0 時明確清除 SOP。
- 刪除類型會連刪該 EquipmentType 子設備列。家用端不可只刪主檔而遺留設備個別列。

## 公司端 DEV 實作

- Vue 元件為 `web/src/components/PmFixedQuantitySetUp.vue` 與 `PmFixedQuantitySetUpDevPreview.vue`；已接入「設備 PM 設定」選單。
- DEV 使用 localStorage `ymes.dev.pm.fixed-quantity.v1`，提供類型主檔 Add／Edit／Copy／Delete、設備列 Edit／Delete、類型 SET 左右多選、搜尋及確認提示。SET 依來源規則以類型預設重建所選設備列；全數取消選取會清空該類型的個別設備列。
- SOP 參照優先讀取 PM109 localStorage `ymes.dev.pm.sop-basis.v1`，沒有樣例時採 DEV 假 SOP；設備／類型、單位、狀態為假資料。DEV 編輯以本機 DataStamp 加一模擬樂觀併發。
- 假資料不代表 MESTEST 設備、單位、狀態或 SOP 主檔；DEV 對數量採正整數驗證，以符合 Service/Core 的整數轉型。

## 家用端 API、schema 與 SQL handoff

- 建議提供有界查詢 `GET /api/pm/fixed-quantity-settings?equipmentType={type}&equipmentNo={no}`；類型設定與設備例外列分開回傳或明確標註 TypeCode。類型 CRUD 可使用 `/api/pm/fixed-quantity-settings/equipment-types/{equipmentType}`；設備個別值使用 `/api/pm/fixed-quantity-settings/equipment/{equipmentNo}`。
- SET 建議使用 `PUT /api/pm/fixed-quantity-settings/equipment-types/{equipmentType}/equipment-assignments`，由伺服器在單一交易中鎖定／讀取類型預設、確認設備屬於該類型及允許範圍、替換設備列並回傳逐項結果。保留 DataStamp 併發條件；關閉 AutoCreateWo 時清空 PMSopNo，關閉 LockEquipment 時清空 EquipmentState；刪除類型時同步處理所有子設備列。
- 直接表為 `TBLPMFIXEDQTYPMBASIS`，並參照設備類型／設備、單位、設備狀態、SOP 主檔。桌機 Oracle profile 不存在，repo 沒有可核實的該表 DDL／索引／約束；本次未查 Oracle、未產生猜測的 PostgreSQL CREATE-only SQL。家用端須先核 live schema／migration 和 Oracle metadata，再決定正式欄位、鍵與參照。
- 公司端未連 YMES PostgreSQL、未實作或驗收正式 API/schema、未部署。未執行 build、test 或 browser；本次僅作靜態檢閱。
