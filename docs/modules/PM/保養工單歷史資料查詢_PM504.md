## 功能與來源

- MESTEST 選單清冊：FunctionNo `PMWO HISTORY`、FunctionKey `PM504`、Form `frmPMWoHistory`、ExecutionFile `PM_WOHistory.dll`，分類為查詢。
- 已核對 `D:\iMES\CSiMES\STD\MESWin\PM\PM_WOHistory\frmPMWoHistory.vb`（含 inline Designer）、`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsPM\wsPM.cs` 的 `LoadPMWoBasis_His`／`LoadPMWoDetail_His` 與 `wsEQP.LoadEquipmentBasis`，以及 `D:\iMES\CSiMES\STD\MESkc\kcPM\clsPMBasis.cs` 對應 Core。
- DEV 選單路徑 `/YMES/PM/WorkOrderHistory`。功能唯讀查詢主工單與明細，不寫入資料。

## WinForms 行為

- Form Load 讀取 `ChamberManage`，再透過 `wsEQP.LoadEquipmentBasis` 載入 Equipment 清單，附加 `IssueState in (2,-1)`；未啟用 Chamber 管理時另傳 `ChamberFlag=0`。雙清單均為多選、依設備編號排序，可用箭頭或雙擊移動條件。工單型態預設 All；PM Order 傳 `WOType=0`，REQ Order 傳 `WOType=1`。
- 查詢條件為 Equipment No 多選、Estimated PM Date From／To、Finished Date From／To、WO Type。日期條件各自勾選才送出；純日期迄日由 Core 補到當日 `23:59:59`。All 不送 WOType，Core 不限制型態。UI 不提供 WO No、IssueState、CreateDate 或 AdditionalXml 篩選，即使 Service 支援部分這些參數。
- 主查詢呼叫 `wsPM.LoadPMWoBasis_His`，Core 讀 `tblPMWOBasis_His`。WO Type 條件直接限制主檔；Equipment、Estimated PM Date、Finished Date 條件則放進 `tblPMWODetail_His` 的子查詢，再以符合條件的 `WONo` 限制主檔。結果依 `CreateDate` 升冪排序。UI 主 Grid 隱藏其餘欄，只顯示 `WONo`、`WOType`（依 `TBLPMWOBASIS_HIS.WOTYPE` ValueList 顯示）、`Description`、`Creator`、`CreateDate`。
- 主 Grid 的 `AfterRowActivate` 呼叫 `wsPM.LoadPMWoDetail_His`，以該 `WONo` 載入 `tblPMWODetail_His`。此第二次查詢不重送主查詢的日期／Equipment 條件；未啟用 Chamber 管理時，UI 依 Form Load 的非 Chamber 設備清單過濾明細。明細 Grid 顯示 `WoItemNo`、`EquipmentNo`、`PMSOPNo`、`PMEstDateTime`、`ReleaseDate`、`FinishedDate`、`Executor`、`ExecuteDesc`。
- Core 將篩選字串與日期直接拼接進 SQL。家用端需使用參數化查詢、分頁和結果上限；主檔與明細建議分開查詢，讓使用者選取工單後才載入明細，以符合 WinForms 的延遲載入方式。

## 公司端 DEV 實作

- `web/src/components/PmWorkOrderHistory.vue` 提供 DEV-only wrapper；`PmWorkOrderHistoryDevPreview.vue` 模擬 Equipment 雙清單、兩組可選日期範圍、All／PM Order／REQ Order、Query、主 Grid 選取及明細 Grid。查詢條件對明細套用 AND；有明細條件時，主檔只保留至少一筆符合明細條件的工單；選取主工單後顯示其全部符合 Chamber 規則的明細，與舊畫面兩次查詢的邏輯一致。

- 未執行 build、test 或 browser；僅做靜態差異檢閱。

## 家用端 API／schema handoff

- 建議唯讀分頁端點 `GET /api/pm/work-order-histories`，支援 `equipmentNos`、`pmEstDateFrom`、`pmEstDateTo`、`finishedDateFrom`、`finishedDateTo`、`woType`、`page`、`pageSize`；回傳 Grid 主檔欄位和 `totalCount`，以 `CreateDate, WONo` 穩定排序。主檔篩選應以明細 EXISTS 條件實作，日期迄日含整日。
- 建議延遲明細端點 `GET /api/pm/work-order-histories/{woNo}/items`，回傳明細 Grid 所需 8 欄；確認設備 Chamber 規則由 API 統一施行，或明確傳入可見範圍。兩端點皆唯讀及參數化。
- 涉及 `tblPMWOBasis_His` 與 `tblPMWODetail_His`，需核實 `WONo`／`WOItemNo` 鍵、主明細關聯、WOTYPE enum、Equipment FK、欄位型別／長度、歷史保留與索引。
- 公司桌機目前沒有可用的受保護 Oracle MESTEST profile，無法以 PowerShell 5.1 + Oracle.ManagedDataAccess 讀取兩表 DDL／metadata。可信 PostgreSQL CREATE-only SQL、欄位型別及 PK／FK／索引待家用端核 live schema 與同版 MESTEST 後提供；未猜測或新增 CREATE SQL。公司端不連 PostgreSQL、不實作正式 API/schema。
