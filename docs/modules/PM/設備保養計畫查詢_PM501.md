# PM501 設備保養計畫查詢

## 功能與來源

- MESTEST 清冊：FunctionNo `PM MAINTENANCE QUERY`、FunctionKey `PM501`、Form `frmPMMaintenancePlanQuery`、ExecutionFile `PM_MaintenancePlanQuery.dll`；畫面屬「設備 PM 設定」。
- 已核對 `D:\iMES\CSiMES\STD\MESWin\PM\PM_MaintenancePlanQuery\frmPMMaintenancePlanQuery.vb`（含 inline Designer）、`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsPM\wsPM.cs` 的 `LoadMaintenancePlan`／`LoadSingleTableDistinctData`，以及 `D:\iMES\CSiMES\STD\MESkc\kcPM\clsPMBasis.cs` 的 `LoadMaintenancePlan`。清單輔助方法在 `PM\PM_Kit\clsPMKit.vb`。
- DEV 路徑 `/YMES/PM/MaintenancePlanQuery`，由 `function:PM:PM MAINTENANCE QUERY` 選單項目進入。

## WinForms 行為

- Form Load 先以 `LoadEquipmentBasis(ChamberFlag=1)` 取得子設備清單，再讀 SYSParameter `ChamberManage`；接著以 `LoadSingleTableDistinctData` 從 `TBLPMEQPMAINTENANCEPLAN` 載入 EquipmentNo、FrequencyNo、Creator 三組雙清單選項。畫面打開後會立即執行一次無條件查詢。
- 三組條件初始全在未選清單。使用者可用方向按鈕或雙擊移動選項；每組至少選一個值時才形成篩選，全部未選代表不限制該欄。
- 預估日期 From／To 各有啟用核取方塊。From 傳當日 00:00；To 也先傳當日 00:00。Core 偵測迄日沒有時間後轉成當日 23:59:59，因此範圍含迄日整天。
- Form 呼叫 `wsPM.LoadMaintenancePlan`。Service 也能解析 PMEQPSOPNo、PMSerialNo、PMSOPNo 與 AdditionalXml，但本畫面沒有提供這些條件。Core 由 `tblPMEQPMaintenancePlan` 內連 `tblPMFrequencyBasis`（FrequencyNo）及 `tblPMSOPBasis`（PMSOPNo），再套用設備、頻率、SOP、建立者與預估日期條件。
- 結果在 Form 端以 PMESTDATETIME 升冪排序。Grid 明確指定 EquipmentNo、FrequencyNo、FrequencyName、PMSOPNo、PMSOPName、PMESTDATETIME 六欄及順序；明確隱藏 PMEQPSOPNO、PMSERIALNO、CREATEDATE、REVISEDATE。Creator、Reviser 等其餘欄位未被這段 Layout 隱藏。
- `ChamberManage` 不等於 1 時，設備篩選清單先排除 Chamber，查詢結果的 Grid 也以設備主檔本機過濾排除 Chamber。日曆按鈕是否可用則看 Core 原始 DataTable 是否有列；開啟時把整份 DataTable Copy 傳給外部 `PM_PlanCalendar`，不是只傳 Grid 的過濾檢視，故被 Grid 隱藏的 Chamber 列仍可能交給日曆。
- 外部日曆視窗來自 FunctionKey PM502 `PM CALENDAR`。本次 PM501 DEV 以唯讀月份清單預覽外部視窗的資料交接，PM502 本身依清冊接續復刻。

## 公司端 DEV 實作

- Vue 元件：`web/src/components/PmMaintenancePlanQuery.vue`、`PmMaintenancePlanQueryDevPreview.vue`；掛入 `web/src/App.vue` 的設備 PM 設定選單。

- DEV 以 `-CH` 加數字尾碼識別樣例 Chamber，模擬 `ChamberManage=0` 時設備選項與 Grid 排除 Chamber 的規則；日曆預覽仍用原始查詢結果集。這是樣例近似，不代表正式 EquipmentBasis 判斷方式。

## Core 風險與家用端 API／schema handoff

- Core 以字串串接 `IN (...)` 及 `To_Date(...)` 條件，沒有使用 SQL 參數；Service 把逗號分隔值轉成引號清單。正式 API 必須驗證每個篩選值、使用參數化查詢，不能沿用字串串接。
- 建議提供限量分頁唯讀端點 `GET /api/pm/maintenance-plans`，條件採可選 `equipmentNo`、`frequencyNo`、`creator`、`from`、`to`；回傳計畫識別值、設備、頻率及名稱、SOP 及名稱、預估日期、建立／修改者和日曆預覽所需的 Chamber 標記。排序需穩定（`PMEstDateTime`, `EquipmentNo`, `PMSerialNo`），日曆如需未過濾 Chamber 列，應明確定義該端點的資料範圍與權限。
- 直接參照表為 `tblPMEQPMaintenancePlan`、`tblPMFrequencyBasis`、`tblPMSOPBasis`；設備與 Chamber 設定另參照設備主檔及 `SYSParameter.ChamberManage`。公司桌機目前沒有可用的受保護 Oracle profile，故未用 PowerShell 5.1／ODP.NET 連線查詢；repo 也找不到可核實的這些表 DDL／metadata。本次不猜欄位型別、鍵或 PostgreSQL CREATE-only SQL。家用端須先核 live PostgreSQL 與同版 MESTEST metadata，再提交可信 CREATE-only SQL／欄位映射。
- 本次未連 YMES PostgreSQL、未實作或驗收正式 API/schema、未部署。僅作程式碼靜態檢閱；未執行 build、test 或 browser。
