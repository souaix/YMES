# PM502 保養日曆設定

## 功能與來源

- MESTEST 清冊：FunctionNo `PM CALENDAR`、FunctionKey `PM502`、Form `frmPMPlanCalendar`、ExecutionFile `PM_PlanCalendar.dll`。
- 已核對 `D:\iMES\CSiMES\STD\MESWin\PM\PM_PlanCalendar\frmPMPlanCalendar.vb`（含 inline Designer）、`frmCustomAppointmentDialog.vb`、`wsPM.LoadMaintenancePlan`／`LoadEQPPMPlanByEQPType`／`LoadSingleTableDistinctData`、`clsPMBasis.LoadMaintenancePlan`／`LoadEQPPMPlanByEQPType`。
- DEV 選單路徑 `/YMES/PM/PlanCalendar`。PM501 的 `ObjectFileHandler.Execute("PM_PlanCalendar", parameters, pFormName:="frmPMPlanCalendar")` 會以 `dtPMPlan` 傳入完整 MaintenancePlan DataTable；獨立由 PM502 選單開啟時，沒有這個呼叫端資料，需按 Query 載入日曆。

## WinForms 行為

- 左側條件有 Equipment Type、Frequency No、Equipment No 雙清單，以及 Clear、Query。Equipment Type 與 Frequency No 的 `...` 開啟 MES 搜尋視窗；Equipment Type 選定後以 `LoadEQPPMPlanByEQPType` 重載設備選項。EquipmentNo 文字欄及選擇按鈕在 Designer 設為隱藏。
- Form Load 讀 `ChamberManage`、用 `LoadEquipmentBasis(ChamberFlag=1)` 取得 Chamber 代碼，並從 `TBLPMEQPMAINTENANCEPLAN` distinct EquipmentNo 建立未選設備清單；未啟用 Chamber 管理時先排除子設備。若呼叫端有傳 `dtPMPlan`，直接綁成日曆預約；否則畫面等使用者按 Query。
- Query 把已選 EquipmentNo 轉為 `equipmentno` 清單、Frequency No 轉為 `frequencyno`；Equipment Type 以 Additional XML 限定設備主檔中的 EquipmentType。沒有 Equipment Type 且 ChamberManage 不等於 1 時，Additional XML 排除 Chamber。程式中的 EquipmentNo 文字欄條件與日期範圍條件都已註解，不會送出。Clear 只清條件並重載未選設備，不會清除目前日曆或自動重查。
- Query 呼叫 `wsPM.LoadMaintenancePlan`。Core 以 `tblPMEQPMaintenancePlan` 內連 `tblPMFrequencyBasis`、`tblPMSOPBasis`；Equipment Type 的選項清單另由 `LoadEQPPMPlanByEQPType` 從計畫表 left join `tblEQPEquipmentBasis` 取得 distinct 設備及類型。頻率查找呼叫 `LoadFrequencyBasis`。
- 日曆區有 Day View、Week View、Month View 三個共用 CalendarInfo 的檢視；右側 `UltraMonthViewMulti` 一次顯示兩個月。事件由計畫資料逐列建立、以 PMESTDATETIME／EquipmentNo 排序，Subject 為 `EquipmentNo-FrequencyName`；Start／End 都設成 PMESTDATETIME 當日，AllDayEvent 預設 True。Description 使用 `FrequencyNo:FrequencyName-PMSOPName:PMSOPName`，SOP 名稱被重複串接，屬舊程式缺陷。
- 點既有事件會開自訂明細對話框；Subject／Description 唯讀、Start time disabled、End time 與標籤隱藏。建立新事件的對話框在程式一開始就取消並退出。沒有呼叫維護計畫更新 Service；日曆元件的 Appointment 即使被拖曳或改動，也只存在記憶體資料集，沒有持久化。DEV 以唯讀事件明細呈現，未復刻拖曳改期。
- TabControl／Day View 的右鍵選單包含 Page Setup、Print Preview、Print，以及 Daily／Weekly／Monthly／Memo Style。Page Setup 根項目的 Click handler 為空；列印／預覽使用 `UltraSchedulePrintDocument`。Recurrence 欄位有建立但計畫事件未填重複週期。
- 查詢若無資料會顯示 Data Not Found 並離開重建流程；原先已綁定的 `scheduleData` 不會被替換，因此日曆仍可能留著前次事件。

## 公司端 DEV 實作

- Vue 元件：`web/src/components/PmPlanCalendar.vue`、`PmPlanCalendarDevPreview.vue`；掛入設備 PM 設定選單。PM501 DEV 的 PM Calendar 按鈕也會用同一元件，並傳入當次原始查詢結果，對應 WinForms 傳 `dtPMPlan`。
- DEV 讀取 PM201／PM202 共用 localStorage `ymes.dev.pm.eqp-type-sop-basis.v1`，頻率與 SOP 名稱使用共用 DEV 主檔或 fixture。獨立頁面進入時先呈現篩選條件，按 Query 後載入日曆；PM501 進入時直接顯示傳入計畫。提供 Equipment Type／Frequency 查找、Equipment No 雙清單、Clear／Query、日／週／月切換、前後期間、雙月小日曆、事件唯讀明細與列印預覽；操作只改本機視圖，不新增或修改 MES 計畫。
- DEV 以 `-CH` 加數字尾碼辨認樣例 Chamber，`ChamberManage` 固定模擬未啟用；類型查詢時仍依來源條件可包含樣例子設備。設備類型與 Chamber 只按假資料對照，不代表正式主檔規則。

## Core 風險與家用端 API／schema handoff

- Core 的 `LoadMaintenancePlan` 與 `LoadEQPPMPlanByEQPType` 使用字串串接 SQL 條件；Additional XML 也承載 EquipmentType／Chamber 條件。正式端點必須驗證條件並用參數化查詢，避免照抄字串拼接。
- Calendar 本身沒有寫入 API。可與 PM501 共用限量分頁唯讀端點 `GET /api/pm/maintenance-plans`，支援 EquipmentNo、EquipmentType、FrequencyNo、Chamber 規則及 PMEstDate 範圍；回傳日曆事件所需的計畫鍵、設備／類型、頻率、SOP 及預估日期。日期範圍是 Web 端新增的限量保護，不是 PM502 WinForms 條件。建議穩定排序 `PMEstDateTime, EquipmentNo, PMSerialNo`。
- 家用端 2026-11-27 以 SSH 唯讀檢查 YMES catalog：`tbleqpequipmentbasis` 存在，`tblpmeqpmaintenanceplan`、`tblpmfrequencybasis`、`tblpmsopbasis` 缺少。repo 僅有設備表的 trusted DDL；三張 PM 表沒有 Oracle source DDL／metadata 或 PostgreSQL CREATE-only。頻率與 SOP 表已列在共用 PM506 DDL 要求；PM Plan 的原生 DDL 另列於 [公司端待辦](../../../todolist_officepc.md)。沒有讀業務資料或猜建表。
- 收到來源後再核 PM Plan 主鍵／欄位型別、頻率與 SOP 關聯及 Chamber 規則，建立可信空表並實作 PM501／PM502 共用的限量參數化唯讀 API；沒有 Calendar 寫入端點。
