# PM204 設備定次定時保養設定

## 功能與來源

- 選單為「設備 PM 設定 → 設備定次定時保養設定」，FunctionNo `EQP FIXED TIME SETUP`、FunctionKey `PM204`。DEV 入口 `/YMES/PM/FixedTimesSetup`。
- 已核對 `STD/MESWin/PM/PM_FixedTimesSetUp/frmFixedTimesSetUp.vb`（含 inline Designer）、`frmFixedTimesDef.vb`、`frmFixedTimesDef_EQP.vb`，以及 `MESws_STD/wsSTD/wsPM/wsPM.cs`、`MESkc/kcPM/clsPMBasis.cs`、`MESkc/kcBasis_UPD/clsBasis_UPD.cs`。
- Service 方法：`LoadFixedTimesPMBasis`、`AddFixedTimesPMBasis`、`EditFixedTimesPMBasis`、`DelFixedTimesPMBasis`、`UpdFixedTimesPMBasis`；Core 分別由 `clsPMBasis` 與 `clsBasis_UPD` 執行資料存取。

## WinForms 畫面與資料規則

- 主畫面分設備類型預設與設備明細兩個 Grid。類型主檔支援 Add／Edit／Copy／Delete／SET；設備明細提供個別 Edit／Delete。兩個 Grid 可依 EquipmentNo 查找；類型 Grid 顯示 `QtyType`，設備 Grid 隱藏 `QtyType`，並顯示設備、數量、累計寬限量、自動開立工單、鎖定狀態、建立／修改者、SOP 與 Email 等欄位。
- 直接資料表為 `TBLPMFIXEDTIMESPMBASIS`。`TypeCode=1` 且 `EquipmentNo=EquipmentType` 是類型預設；`TypeCode=0` 是設備個別列，設備列以 EquipmentType 關聯類型。設備列可由 SET 從類型預設批次建立／覆寫。
- `QtyType` 為 0=Times、1=Hours、2=Minutes；主檔編輯時必選。Quantity 必須大於 0；ToleranceQty 可留空，若輸入必須是正數且大於 Quantity。WinForms 將空寬限量傳 0。自動開立保養工單需要 SOP；鎖定設備需要 EquipmentState。
- 查找來源包括 `wsEQP.LoadEquipmentType`、`wsEQP.LoadEquipmentBasis`、`wsEQP.LoadEQPStateBasis`、`wsPM.LoadSOPBasis`；設備候選清單依 EquipmentType 與 ChamberManage 過濾。設備列 Grid 雖不顯示 QtyType，但每個設備列仍保存該欄位。
- 類型 Edit 透過 `clsBasis_UPD.EditFixedTimesPMBasis` 依 EquipmentNo + DataStamp 條件更新，並增加 DataStamp。新增與刪除走 `clsPMBasis`；類型刪除會清除相同 EquipmentType 的類型及設備列。

## Service/Core 注意事項

- `UpdFixedTimesPMBasis` 先呼叫 `DelFixedTimesPMBasis(EquipmentType, 2)` 刪除該類型現有 TypeCode=0 設備列，再逐台呼叫 `AddFixedTimesPMBasis` 重建；未使用共同交易。空設備清單會清空所有個別列；中途失敗會留下空集合或部分集合。家用端正式 API 應在單一交易中驗證候選設備所屬類型並替換清單。
- `EditFixedTimesPMBasis` 在 `LockEquipment=0` 時會同步清除 EquipmentState；但只有 `PMSopNo` 非空才更新該欄位。Form 關閉 AutoCreateWo 會送空 SOP，因此舊 Core 可能保留舊 PMSopNo。正式 API 應依 AutoCreateWo 狀態明確清除或要求 SOP，並在一個交易／條件更新中維持欄位一致。
- 類型列改動不會自動更新既有設備個別值，只有 SET 會按類型預設重建設備清單。家用端應呈現這個覆寫效果並要求明確確認。

## 公司端 DEV 實作

- Vue 元件為 `web/src/components/PmFixedTimesSetUp.vue` 與 `PmFixedTimesSetUpDevPreview.vue`，已接入「設備 PM 設定」選單。
- DEV localStorage key 為 `ymes.dev.pm.fixed-times.v1`。提供類型 Add／Edit／Copy／Delete、設備列 Edit／Delete、搜尋、QtyType 選擇、SOP／狀態假資料和 SET 左右多選套用；SET 明確確認後以類型設定重建所選設備個別列。DEV 編輯以本機 DataStamp 加一模擬樂觀併發。
- SOP 優先讀 PM109 localStorage `ymes.dev.pm.sop-basis.v1`，無資料時使用 DEV 假 SOP；設備、EquipmentType 和狀態都是假資料，不代表 MESTEST 主檔。DEV 中的設備明細刻意不顯示 QtyType，以符合 WinForms Grid。

## 家用端 API、schema 與 SQL handoff

- 建議提供有界查詢 `GET /api/pm/fixed-time-settings?equipmentType={type}&equipmentNo={no}`；類型 CRUD 可用 `/api/pm/fixed-time-settings/equipment-types/{equipmentType}`，設備個別列使用 `/api/pm/fixed-time-settings/equipment/{equipmentNo}`。SET 使用 `PUT /api/pm/fixed-time-settings/equipment-types/{equipmentType}/equipment-assignments`，在單一交易中確認類型、候選設備與 SET 清單，再替換 TypeCode=0 列並回傳結果。
- 建議正式 schema 保留 TypeCode、EquipmentNo、EquipmentType、Quantity、ToleranceQty、QtyType、AutoCreateWo、LockEquipment、EquipmentState、AutoEmail、PMSopNo、稽核欄位與 DataStamp。依 AutoCreateWo／LockEquipment 一致清除或要求 SOP／EquipmentState；以 DataStamp 條件更新避免覆寫併發值。
- 桌機沒有可用的受保護 Oracle profile，repo 未找到可核實的 `TBLPMFIXEDTIMESPMBASIS` DDL／索引／約束；本次沒有查 MESTEST metadata，也未猜測 CREATE-only SQL。家用端先核 live schema、既有 migration 與可信 Oracle metadata，再補 SQL handoff。
- 公司端未連 YMES PostgreSQL、未實作或驗收正式 API／schema、未部署。未執行 build、test 或 browser；本次以來源靜態檢閱完成 DEV 與文件。
