## WinForms 主畫面

- `frmComputerArea` ClientSize 為 1008×591，簽核控制列隱藏。沿用共用查詢列，查詢欄位為 ComputerNo、FactoryNo；查詢結果依 ComputerNo、FactoryNo 排序。
- Grid 隱藏 GroupByBox，只顯示 ComputerNo（寬100）、FactoryNo（80）、Creator（80）、CreateDate（150）、Reviser（80）、ReviseDate（150）；日期格式 `yyyy/MM/dd HH:mm:ss`。DataStamp 隨資料回傳但不顯示。
- 右側按鈕：ADD、Edit、DEL、Copy、Close。沒有 IssueState、核准、停用或其他簽核狀態。
- Edit、Copy 使用作用列。Delete 可多選；先顯示確認視窗，依選取順序逐筆呼叫 Delete，遇第一個錯誤停止，至少一筆成功後重新載入。

## 定義視窗與操作規則

- `frmComputerAreaDef` ClientSize 為 559×400，包含 ComputerNo、FactoryNo、區域選擇 Grid、建立/修改稽核區，以及確定、關閉、套用按鈕。
- ComputerNo 必填，離開欄位時轉大寫。資料庫上限 20 字元；Web 表單依來源欄位長度驗證。
- FactoryNo 為唯讀欄位，透過「…」查找已簽核工廠（`LoadFactoryBasis(IssueState=2)`）；查找 Grid 顯示 FactoryNo、Description。Edit/Copy 禁用工廠查找；修改時複合主鍵不變。
- Factory 選定後載入該工廠已簽核且 `AreaClass=0` 的 Area Basis（`LoadAreaBasis(IssueState=2, FactoryNo, AreaClass=0)`）。Grid 顯示可勾選欄、AreaNo、AreaName、Description；其他欄位隱藏且不可編輯。既有明細會預勾。
- Copy 模式不允許改 Factory 或區域勾選；只可輸入新的 ComputerNo，舊 Core 會複製來源全部區域明細。
- Add、Edit、Copy 均要求 ComputerNo、FactoryNo，且至少選一個 AreaNo。新增/修改寫入主表與整組明細；修改先刪該主檔全部明細，再重建勾選明細。
- Copy 預填來源 ComputerNo、FactoryNo 及區域；使用者改成新 ComputerNo 後新增一筆主/明細資料。現行 Core 以 FromComputerNo 單欄找來源，沒有 FactoryNo 條件；由於資料表主鍵是複合鍵，若不同工廠有相同 ComputerNo，舊 Copy 來源可能不唯一。YMES API 契約以來源 `(ComputerNo,FactoryNo)` 複合鍵明確指定，避免任選資料。
- Add/Copy 建立 Creator/CreateDate；Edit 更新 Reviser/ReviseDate。WinForms 有傳 DataStamp，但本 checkout 的 `clsSMDBasis.EditComputerArea` 方法簽章沒有 DataStamp 參數，與 `wsSMD.EditComputerArea` 的呼叫不一致；舊 Core 的 Edit SQL 也未將 DataStamp 作 compare-and-swap。YMES API 應使用 DataStamp 做 CAS 並由伺服器產生稽核欄位。
- `Apply` 成功後保留視窗；`Confirm` 成功後關閉。主清單刪除在一組 SQL 中先刪明細再刪主檔；舊 Service 沒有額外引用檢查。

## 資料表與直接查證結果

公司端使用 Windows PowerShell 5.1 + Oracle.ManagedDataAccess，透過本機受保護連線唯讀取得 DBMS_METADATA DDL，並查詢 `ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_INDEXES`、`ALL_IND_COLUMNS`。只查結構，未讀業務資料，未在 Oracle 執行 DDL；憑證未輸出或寫入 Git。

| Oracle table | 欄位 | 主鍵 | NULL / DEFAULT 摘要 |
| --- | --- | --- | --- |
| `TBLSMDCOMPUTERAREABASIS` | ComputerNo varchar2(20), FactoryNo varchar2(20), Creator varchar2(10), CreateDate DATE, Reviser varchar2(10), ReviseDate DATE, DataStamp number(11,0) | `(ComputerNo,FactoryNo)` | ComputerNo、FactoryNo NOT NULL；DataStamp DEFAULT 0、可 NULL；其餘可 NULL |
| `TBLSMDCOMPUTERAREADETAIL` | ComputerNo varchar2(20), FactoryNo varchar2(20), AreaNo varchar2(20) | `(ComputerNo,FactoryNo,AreaNo)` | 三欄皆 NOT NULL |

兩表都只有 PK unique index，沒有 FK 或額外索引。Oracle DATE 對應 PostgreSQL `timestamp without time zone`。來源 DDL 是邏輯定義，省略 tablespace/storage 等實體配置。PostgreSQL SQL 是空表結構，不含 MES 資料；家用端須先對照現有 YMES schema/migrations，再決定是否新增或補欄位。

## YMES API 契約（家用端實作）

所有端點需驗證登入。依使用者目前指示，角色／SMD 功能權限暫不實作；PostgreSQL `ymes_app` 表級權限則依端點需要最小授權。DTO 使用 camelCase：主表欄位 `computerNo, factoryNo, creator, createDate, reviser, reviseDate, dataStamp, areas`；`areas` 是該主檔的 AreaNo 字串陣列。

| Method | Endpoint | 行為 |
| --- | --- | --- |
| GET | `/api/smd/computer-areas?computerNo=&factoryNo=` | 查主檔與其 AreaNo 明細；欄位可空，依值篩選 |
| POST | `/api/smd/computer-areas` | 新增主檔與至少一筆區域明細；同一交易內完成 |
| PUT | `/api/smd/computer-areas/{computerNo}/{factoryNo}?dataStamp=` | 以 DataStamp CAS 更新稽核欄位並整組替換明細；複合鍵不可變 |
| DELETE | `/api/smd/computer-areas/{computerNo}/{factoryNo}` | 同一交易先刪明細再刪主檔；不存在回 404 |
| POST | `/api/smd/computer-areas/copy` | body `{fromComputerNo, fromFactoryNo, toComputerNo}`；同交易複製工廠及全部區域，Creator/CreateDate 由伺服器設定 |

新增及修改的 `factoryNo` 必須存在且 IssueState=2；`area-basis/options` 的 `factories` 項目需提供 `factoryNo, description`（也可同時保留 SD104 使用的 `factoryName`）；每個 `areaNo` 必須屬於該工廠、IssueState=2、AreaClass=0。驗證重複主鍵、區域明細鍵及欄位長度；操作主/明細要用 PostgreSQL transaction。DataStamp 原值可為 NULL，CAS 要支援 `IS NULL` 並以 `COALESCE(DataStamp,0)+1` 更新。多筆刪除由 UI 逐筆呼叫，遇錯停止並回報成功筆數。
