## WinForms 主畫面

- `frmAreaInventory` ClientSize 為 1008×591。頂部是唯讀 BaseAreaNo 輸入框及「…」查找按鈕；選定 Base Area 後即載入對應資料。
- Grid 單一資料帶、GroupByBox 隱藏。顯示 AreaNo（寬190）、InventoryNo（110）、BaseAreaNo（130）、Default（90）、Creator（80）、CreateDate（150）、Reviser（80）、ReviseDate（150）；日期格式 `yyyy/MM/dd HH:mm:ss`。DataStamp 隨資料回傳但不顯示。
- 右側按鈕：ADD、EDIT、DEL、Copy、Close。Find、Print 雖存在 Designer，但 `Visible=False`，畫面不顯示。
- Add 需先選 Base Area。Edit 使用作用列；Copy 以作用列預填但採新增。Delete 支援多選，逐筆呼叫服務，遇第一筆錯誤停止後重新載入。
- Base Area picker 透過 `wsSMD.LoadBaseArea` 載入 Base Area；定義表單的 Area/Inventory picker 使用 `wsSMD.LoadAreaRelation`，分別過濾 `ObjectType=0` 區域與 `ObjectType=1` 庫房。候選項目必須在所選 Base Area 的配置中。

## 定義視窗與資料驗證

定義視窗 ClientSize 508×307；群組框內依序顯示 Base Area No、Area No、Inventory No、Default；底部沿用建立/修改稽核資訊與確定、關閉、套用按鈕。

| 欄位 | 規則 |
| --- | --- |
| BaseAreaNo | 必填；由主視窗選取的 Base Area 固定帶入 |
| AreaNo | 必填；唯讀 picker，從該 Base Area 配置中的 ObjectType=0 選取；Edit 時 picker disabled |
| InventoryNo | 必填；唯讀 picker，從該 Base Area 配置中的 ObjectType=1 選取；Edit 時 picker disabled |
| DefaultINV | 必填、僅 0=No / 1=Yes；新增預設 No |
| DataStamp | 隱藏欄位；Edit 帶入並用於新版 API 的併發檢查 |

新增/複製時 Creator/CreateDate 顯示登入者與目前時間；修改顯示來源建立資訊與既有修改資訊。按 Apply 成功後留在視窗並停用 Apply，Confirm 成功後關閉。

## Service / Core 行為

- 查詢 `LoadAreaInventory` 以 BaseAreaNo 過濾 `TBLSMDAREAINVENTORY`；也可用 AreaNo、InventoryNo、DefaultINV 選擇性過濾。
- Add 必須傳 BaseAreaNo、AreaNo、InventoryNo、DefaultINV；DefaultINV 僅接受 0/1。新增 DefaultINV=1 時，Core 查詢相同 BaseAreaNo、AreaNo 是否已有預設庫房；已存在則拒絕。
- Edit 不允許修改 AreaNo/InventoryNo/BaseAreaNo，只修改 DefaultINV；改為 Yes 時會檢查同一 BaseAreaNo、AreaNo 是否已有另一筆 default。舊程式 Edit 檢查未帶 BaseAreaNo，與 Add 範圍不一致；YMES API 明確收斂至同一 BaseArea 範圍，避免不同 Base Area 的同號 Area 互相阻擋。
- 新增與修改均需檢查主鍵 `(AreaNo,InventoryNo)` 唯一。Oracle 沒有 FK，API 應檢查兩個選項都存在於目前 Base Area 的 AreaRelation。
- Delete 每列以 BaseAreaNo、AreaNo、InventoryNo 刪除。Oracle PK 實際為 `(AreaNo,InventoryNo)`，BaseAreaNo 是額外範圍條件；不可把 BaseAreaNo 加成資料表 PK。
- Service 呼叫與目前 Core 簽章有版本差異：wsSMD Add 傳 Creator/CreateDate，Edit 傳 DataStamp/Reviser/ReviseDate，但目前檢視的 Core 方法簽章只含 AdditionalXml。YMES API 要按畫面意圖由伺服器明確產生稽核欄位，並新增 DataStamp compare-and-swap；不要照搬未落入 Core SQL 的參數。
- 此功能沒有 IssueState 欄位，也沒有核准流程。

## Oracle 結構

`TBLSMDAREAINVENTORY` 在 SD104 直接查 DDL 時已由 PowerShell 5.1 + Oracle.ManagedDataAccess 唯讀查過，不必再次查詢：9 欄；`(AreaNo,InventoryNo)` PK；唯一索引僅 PK；沒有 FK/其他索引。AreaNo、InventoryNo、BaseAreaNo 為 VARCHAR2(50) NOT NULL；DefaultINV NUMBER(1,0) DEFAULT 0 NOT NULL；Creator/CreateDate/Reviser/ReviseDate 可 NULL；DataStamp NUMBER(11,0) DEFAULT 0 可 NULL。完整來源 DDL、PostgreSQL 空表結構在 `database/reference/mestest_smd_area_basis_source_ddl.sql` 與 `mestest_smd_area_basis_create.sql`。Oracle DATE → PostgreSQL timestamp without time zone。

家用端先比對 YMES schema 與 migration；缺表才新增，保留 YMES 已有擴充欄位。不要執行 Oracle source DDL，也不要把 DEV mock rows 匯入正式資料庫。

## Vue 與 API handoff

Development Preview 使用 `localStorage` DEV rows；Production 只呼叫 API。

| 方法 | Endpoint | 行為 |
| --- | --- | --- |
| GET | `/api/smd/area-basis/options` | 沿用 SD104 API；回傳 `factories` 並新增已簽核 Base Area（AreaClass=1）的 `baseAreas` |
| GET | `/api/smd/areas/{baseAreaNo}/layout` | 沿用 SD104 API；Vue 僅取 relations 中 ObjectType 0/1 做 Area/Inventory picker |
| GET | `/api/smd/area-inventories?baseAreaNo=` | 查選定 Base Area 的完整映射清單 |
| POST | `/api/smd/area-inventories` | 建立映射；body 包含 `baseAreaNo, areaNo, inventoryNo, defaultInv`，伺服器建立 Creator/CreateDate/DataStamp |
| PUT | `/api/smd/area-inventories/{areaNo}/{inventoryNo}?dataStamp=` | 只更新 defaultInv；伺服器設定 Reviser/ReviseDate 並做 CAS |
| DELETE | `/api/smd/area-inventories/{areaNo}/{inventoryNo}?baseAreaNo=&dataStamp=` | 依複合主鍵及 BaseArea 範圍刪除，做 DataStamp CAS |

DTO camelCase：`areaNo, inventoryNo, baseAreaNo, defaultInv, creator, createDate, reviser, reviseDate, dataStamp`。DefaultINV=1 的唯一規則由 API 在交易中驗證；新增/修改/刪除要求登入，依使用者指示尚未實作角色或功能權限判斷。資料列更新與刪除依 DataStamp compare-and-swap（舊值為 NULL 時視同 0）。Multi-delete 是 UI 逐筆請求，首錯停止並回報成功筆數。`ymes_app` 僅取得此資料表所需 CRUD。
