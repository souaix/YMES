## WinForms 主畫面

- frmPDLineBasis ClientSize 為 1008×591。載入後查詢全狀態資料，預設顯示未簽核 0；狀態選項為未簽核 0、簽核中 1、已簽核 2、不使用 -1，切換狀態是在已載入資料上做本機篩選。
- 查詢欄位為 PDLineNo，查詢列顯示百分比符號；表單透過共用 CombineXMLQueryCondition 傳 SearchFieldName/SearchFieldValue，畫面提供部分字串查詢。Core 另有 PDLineNo 完全相等的參數條件。
- Grid 隱藏 IssueState、DataStamp，顯示欄位順序與寬度：PDLineNo 100（升冪）、PDLineName 110、PDLineStatus 110、Description 250（多行）、Creator 80、CreateDate 150、Reviser 80、ReviseDate 150；日期為 yyyy/MM/dd HH:mm:ss。PDLineStatus 顯示文字取自 ValueListProvider 的 TBLSMDPDLINEBASIS.PDLINESTATUS。
- 右側按鈕順序：新增(A)、修改(E)、刪除(D)、複製(C)、核准(Y)、關閉。修改只允許 IssueState=0；複製可由作用列開啟。刪除與核准可多選，沒有選取列時先將作用列納入；批次逐筆執行，第一筆錯誤即停止，已成功筆數不回滾。
- 刪除依 wsSMD.DelSMDPDLineBasis 實際分支：IssueState 0、1、-1 實體刪除；IssueState 2 更新為 -1 並保留資料。此頁的 WinForms Service 接受簽核中 1 實體刪除，Production API 規格需明確決定是否維持相同相容行為。
- 核准只接受 IssueState=0。IssueNo 為 SMD PDLINE BASIS；沒有 Job 或 Job 沒有 Detail 時直接改為 2。有流程時建立 Issue Master，主檔轉為 1，通過後為 2、退回後為 0，並通知第一個簽核群組。

## 定義表單與互動

- frmPDLineBasisDef ClientSize 為 511×400，置中。主資料 GroupBox 大小 487×256；下方稽核區 487×70；底部有確定、關閉、套用。
- 欄位為 PDLineNo、PDLineName、PDLineStatus、Description。PDLineNo 與 PDLineName 必填，PDLineStatus 必須選取；編號最多 50 字元且輸入自動轉大寫，名稱最多 50，Description 最多 255。
- PDLineNo、PDLineName、PDLineStatus 使用 KD 黃色欄位；Description 是白底多行文字。Edit 時 PDLineNo 唯讀，只有 IssueState=0 可開啟。
- Add 預設 PDLineStatus=1、IssueState=0；Copy 帶入編號、名稱、狀態、說明，但以新編號新增並建立新稽核資訊。Edit 使用 DataStamp、修改人及修改日期。
- 狀態值只允許 0、1、2。舊 wsSMD 驗證訊息列出 0=Production、1=Stop、2=Change Line；主 Grid/表單的顯示名稱由正式 ValueListProvider 提供，不能把舊註解文字當成正式繁中翻譯。
- 舊 Core Edit 僅在 Description 非空時加入更新 SQL，清空說明不會清除既有值；Vue DEV 編輯亦保留此行為，Production API 欄位契約需避免空字串意外清除。
- 確定儲存後關閉；套用儲存後保留表單。Vue DEV 在新增第一次套用成功後轉為 Edit 模式，避免重複新增同一主鍵。

## Oracle 表與字典查證

公司端於 2026-11-16 使用 Windows PowerShell 5.1 + Oracle.ManagedDataAccess，經本機受保護連線唯讀取得 DBMS_METADATA.GET_DDL、ALL_TAB_COLUMNS、ALL_CONSTRAINTS、ALL_INDEXES、ALL_IND_COLUMNS。只查資料字典，沒有讀取業務資料或在 Oracle 執行 DDL；連線資料未輸出或存入 Git。

主鍵為 PDLineNo，PK unique index 名稱 PK_TBLSMDPDLINEBASIS；沒有 Oracle FK 或其他索引。Oracle DATE 在 YMES PostgreSQL 對應 timestamp without time zone。原始 Oracle table/index DDL 與 PostgreSQL 空表定義已分開保存。此表已存在 first-phase bootstrap；家用端需對照已套用的 schema/migration，缺漏才新增 forward migration，保留現有資料與 YMES 擴充欄位。

## YMES API 契約與部署狀態

所有 API 驗證登入。依使用者目前指示，角色／SMD 功能權限暫不實作；PostgreSQL `ymes_app` 表級權限則按端點需要最小授權。JSON 使用 camelCase；Creator/CreateDate/Reviser/ReviseDate、IssueState、DataStamp 由伺服器控制。更新/狀態操作需交易及 DataStamp compare-and-swap；DataStamp 在 Oracle 可 NULL，NULL 需使用 IS NULL 比對，更新以 COALESCE(DataStamp,0)+1 遞增。

| Method | Endpoint | 行為 |
| --- | --- | --- |
| GET | /api/smd/pd-line-basis?pdLineNo= | 回傳全部 IssueState，依 PDLineNo 排序；pdLineNo 按共用查詢列支援不分大小寫部分查詢。 |
| GET | /api/smd/pd-line-basis/options | 回傳 { pdLineStatuses: [{ value, label }] }，值依舊系統 ValueListProvider。 |
| POST | /api/smd/pd-line-basis | 建立 IssueState=0；必填編號/名稱/狀態；編號大寫，Add 的 PDLineStatus 預設 1；稽核與 DataStamp 由伺服器設定。 |
| PUT | /api/smd/pd-line-basis/{pdLineNo}?issueState=0&dataStamp= | 只接受目前 IssueState=0；編號唯讀；更新名稱、狀態及非空說明，寫入修改稽核並做 CAS。 |
| DELETE | /api/smd/pd-line-basis/{pdLineNo}?issueState=&dataStamp= | 按舊 Service 規則：0、1、-1 實體刪除；2 改為 -1 並更新稽核/DataStamp。採 transaction/CAS，批次由 UI 逐筆呼叫、首錯停止。若要限制刪除簽核中資料，需先明確列為行為修正。 |
| POST | /api/smd/pd-line-basis/{pdLineNo}/approve?issueState=0&dataStamp= | 僅接受 0；使用共用 Issue/Job 簽核服務，IssueNo=SMD PDLINE BASIS；回傳實際狀態及 DataStamp。 |

目前 `GET/POST/PUT/DELETE /api/smd/pd-line-basis` 已由家用端實作並部署；`ymes_app` 對主表具備端點所需 CRUD 權限。`GET /options` 暫回 503，直到公司端交付正式 ValueList 標籤；`POST .../approve` 暫回 503，直到 Issue/Job 結構與 Service 流程完成交付。這兩項在 Production 均 fail closed，不使用 DEV 標籤或直接變更 IssueState。

Edit、Delete、Approve 的舊 WebService 與 Core 版本透過更新版 clsBasis_UPD 傳遞 DataStamp/audit；舊 Core 的 Del SQL 沒有 DataStamp 條件。新 API 應採伺服器稽核、明確 CAS 與交易，不照搬舊版缺漏。DEV 核准直接模擬 0→2，不代表 Production 可略過 Issue/Job。
