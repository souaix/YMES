## WinForms 主畫面

- 主視窗 ClientSize 為 1008×591。載入後呼叫 `funLoadSysActiveModule("IC_FT_PKG")`、載入資料，預設選取 IssueState=0「未簽核」。
- 查詢欄位只有 FactoryNo；表單用 `%` 提示可輸入部分編號。狀態選項為未簽核 0、簽核中 1、已簽核 2、不使用 -1。WinForms 先取符合查詢條件的資料，再由狀態選項切換本地 Grid 篩選。
- Grid 依 FactoryNo 排序，只顯示 FactoryNo（寬120）、FactoryName（啟用 IC_FT_PKG 時顯示，寬160）、FabCode（90）、Description（200、多行）、Creator（80）、CreateDate（150）、Reviser（80）、ReviseDate（150）。IssueState 與 DataStamp 隨資料載入但隱藏。日期格式 `yyyy/MM/dd HH:mm:ss`。
- 右側按鈕順序為新增、修改、刪除、複製、核准；關閉位於右下。新增不要求先選資料；修改/複製使用作用列；刪除/核准可多選。批次作業逐筆執行，遇第一個錯誤即停止，已成功的資料保留並重新載入。
- 只有 IssueState=0 可修改。Delete 對 0、2、-1 執行實體刪除；IssueState=1 不允許刪除。刪除前顯示確認視窗。
- Approve 只接受 IssueState=0，先顯示確認視窗。IssueNo 為 `FACTORY BASIS`。沒有 Issue Job 或該 Job 沒有 Detail 時直接改為 2；存在簽核工作時建立 Issue 流程並先改為 1，流程核准後改 2、退回後回 0。Service 會通知第一個負責群組。
- Copy 將 FactoryName、FabCode、Description 複製到新增表單；FactoryNo 也先帶來源值，使用者需改成唯一新編號。建立的新資料 IssueState=0，並由登入者建立稽核資訊。

## 定義表單與互動

- `frmFactoryBasisDef` ClientSize 為 485×319，欄位為 FactoryNo、FactoryName、FabCode、Description，另有唯讀 Creator/CreateDate/Reviser/ReviseDate 區和確定、關閉、套用按鈕。Description 使用 RichTextBox 支援多行。
- FactoryNo 為唯一必填欄位；離開欄位時轉大寫。FabCode 離開時轉大寫。長度依來源表限制：FactoryNo 20、FactoryName 50、FabCode 10、Description 255。
- Add/Copy 設 Creator/CreateDate，IssueState 預設 0；Edit 僅能修改 IssueState=0 的資料，FactoryNo 唯讀，更新修改稽核與 DataStamp。Copy 新增一筆資料，不複製 IssueState 或舊稽核欄位。
- FactoryName 非空時才由舊表單送出；空白時舊 Service/Core 不會更新該欄，因此舊畫面無法藉清空欄位清除既有 FactoryName。Vue 沿用此行為。Description/FabCode 可用空值清除。
- 套用成功保留表單；確定成功後關閉。套用按鈕初始停用，欄位改動後才啟用。Vue 在新增/複製第一次套用成功後切換成該筆 Edit 狀態，避免再次套用時重複新增。

## 資料表與來源查證

`TBLSMDFACTORYBASIS` 的 DBMS_METADATA DDL 與欄位/約束/索引字典已於 2026-11-16 由公司端使用 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 直接唯讀查得，當時與 EP303 載具基本資料選項依賴一併查詢。此功能沿用既有結果，沒有重複連線查詢或新增重複 SQL。

| 欄位 | Oracle 型別 | NULL / DEFAULT |
| --- | --- | --- |
| FactoryNo | VARCHAR2(20) | NOT NULL；PK |
| Description | VARCHAR2(255) | NULL |
| Creator | VARCHAR2(10) | NOT NULL |
| CreateDate | DATE | NOT NULL |
| IssueState | NUMBER(1,0) | DEFAULT 0、NOT NULL |
| FabCode | VARCHAR2(10) | NULL |
| FactoryName | VARCHAR2(50) | NULL |
| Reviser | VARCHAR2(10) | NULL |
| ReviseDate | DATE | NULL |
| DataStamp | NUMBER(11,0) | DEFAULT 0、NULL |

只有 FactoryNo 主鍵 unique index；沒有 Oracle 外鍵或額外索引。Oracle DATE 對應 PostgreSQL `timestamp without time zone`。目前 first-phase CREATE 已包含此表與來源 DEFAULT；家用端仍須比對實際 YMES schema/migrations，缺表或欄位才新增 migration，保留既有 YMES 擴充欄位。

## YMES API 契約與家用端實作

API 部署於 `/YMES/API`，端點需登入驗證；目前不檢查角色或 SMD 功能權限，符合現階段先不處理角色權限的決定。DTO 使用 camelCase。稽核欄位、IssueState 與 DataStamp 由伺服器控制；修改使用 DataStamp compare-and-swap，支援來源 nullable DataStamp，更新以 `COALESCE(DataStamp,0)+1` 遞增。`YMES.tblsmdfactorybasis` 的 live schema 已與來源 DDL 核對一致，沒有新增表或修改業務資料；migration 0083 僅授予 `ymes_app` 本表 CRUD 權限。

| Method | Endpoint | 行為 |
| --- | --- | --- |
| GET | `/api/smd/factory-basis?factoryNo=` | 搜尋 FactoryNo（大小寫不敏感、包含查詢字串），回傳四種 IssueState 的工廠清單與隱藏欄位 DataStamp；空字串回傳全部，最多 5,000 筆。 |
| GET | `/api/smd/factory-basis/options` | 回傳 `{ "factoryNameEnabled": boolean }`。目前讀取 `YMES_IC_FT_PKG_ENABLED` 設定，預設 `false`；正式端實測回 `{ "factoryNameEnabled": false }`。公司端須補核 legacy `funLoadSysActiveModule("IC_FT_PKG")` 的實際設定來源，再決定是否改接同一設定來源。 |
| POST | `/api/smd/factory-basis` | 新增 FactoryNo/FactoryName/FabCode/Description；FactoryNo 必填、轉大寫且唯一，IssueState=0；Creator/CreateDate/DataStamp 由伺服器建立。 |
| PUT | `/api/smd/factory-basis/{factoryNo}?issueState=0&dataStamp=` | 只接受目前狀態 0；FactoryNo 不可變更。欄位更新、Reviser/ReviseDate、DataStamp CAS 在一筆交易完成。 |
| DELETE | `/api/smd/factory-basis/{factoryNo}?issueState=&dataStamp=` | 僅允許目前狀態 0、2、-1，做 CAS 後實體刪除；狀態 1 或狀態不符回 409。 |
| POST | `/api/smd/factory-basis/{factoryNo}/approve` | Body `{ "issueState": 0, "dataStamp": number }`。目前只核對資料狀態與版本，因尚無已核實的 YMES Issue/Job provider 與映射，不會修改資料，回 503。取得來源實作並完成 provider 前，不可宣稱簽核可用，也不可改成直接更新 IssueState。 |

來源 Function Catalog 中 `FACTORY BASIS` 的 `IssueOption=1`，但正式 YMES 尚未找到可核實的 Issue/Job 服務與關聯映射。因此 Production Approve 保持安全封鎖 503，且不更新資料。取得來源實作與所需資料表 DDL 後，再依來源規則完成 provider。不要將 Vue DEV 的直接核准狀態轉換套用到 Production。批次 Delete/Approve 由 UI 逐筆呼叫並在第一個錯誤停止；回報已完成筆數。舊 WinForms Service/Core 的部分版本存在 DataStamp/audit 方法簽章差異；新 API 應明確以登入者產生稽核資料並實作 CAS，不照搬簽章不一致。
