## WinForms 主畫面

- frmINVLocatorBasis ClientSize 為 1008×591。查詢列含四種狀態單選：未簽核 0、簽核中 1、已簽核 2、不使用 -1；預設未簽核。輸入 InventoryNo 後按查詢，舊 Core 以 InventoryNo 完全相等篩選；清單資料按 InventoryNo、LocatorNo 排序。父視窗若預先傳入 InventoryNo，也會帶入定義窗。
- Grid 隱藏 GroupByBox，顯示 InventoryNo、LocatorNo（寬100）、LocatorName、Capacity（寬100、右對齊、格式 0.######）、Description（寬174、多行）、Creator（80）、CreateDate（150）、Reviser（80）、ReviseDate（150）。IssueState、DataStamp、ERPNo 不顯示。
- 右側按鈕依序為 ADD、EDIT、DEL、Copy、Approve、Close。Add/Copy/Approve/Close 以主畫面按鈕操作；Edit 僅允許作用列 IssueState=0。雖然 Service/Core Edit 還接受 IssueState=2，WinForms 按鈕會阻止已核准資料進入編輯。
- Delete 會包含作用列及多選列，依序逐筆呼叫，遇到第一個錯誤停止。狀態 0 或 -1 實體刪除；狀態 2 改為 -1；狀態 1 不允許刪除。Approve 僅允許狀態 0，多筆逐筆執行。

## 定義視窗與欄位規則

- frmINVLocatorBasisDef ClientSize 為 508×345。包含 InventoryNo、LocatorNo、LocatorName、Capacity、Description 多行欄位、建立/修改稽核資料，以及確定、關閉、套用。LocatorNo 使用 MES 淡黃色（RGB 255,255,192）；其他可編輯欄位白底。
- InventoryNo 必填，最大 20 字元；LocatorNo 必填，最大 20 字元。複合鍵為 InventoryNo + LocatorNo。新增時可從已核准庫存挑選；WinForms 透過 wsSMD.LoadInventoryBasis(IssueState=2) 取得資料，再 distinct InventoryNo。既有父視窗已提供 InventoryNo 時直接帶入，欄位不可改。Edit/Copy 的 InventoryNo 不可改；Edit 的 LocatorNo 不可改；Copy 的 LocatorNo 可修改。
- LocatorName 最長 50 字元，Description 最長 255 字元，Capacity 可空；有輸入時必須為數值且 >=0。Oracle 欄位為 NUMBER(12,4)，API 應限制最多 4 位小數及其數值範圍。
- Add/Copy 產生新的 Creator/CreateDate，新增後 IssueState=0。Edit 傳 IssueState 與 DataStamp，更新 Reviser/ReviseDate/DataStamp。Edit 僅 UI 允許狀態 0。
- 舊定義窗只在 LocatorName、Capacity、Description 非空時送出這些欄位。Edit 將欄位清空不會清除資料庫舊值；新 API/UI 延續「空值不更新」語意。ERPNo 存在於資料表但此畫面不顯示、不編輯；Edit 必須保留原值。
- Copy 預填來源資料，InventoryNo 固定；使用者輸入新 LocatorNo 後新增另一筆資料，不複製來源的 Creator、CreateDate、Reviser、ReviseDate、IssueState 或 DataStamp。
- Apply 儲存後保持定義窗開啟，Confirm 儲存並關閉；資料未變更時 Apply 不可用。主清單重新載入後選取剛新增/修改的複合鍵。

## 狀態、簽核與版本差異

- Service 簽核編號為 INV LOCATOR。若沒有對應簽核 Job/Detail，舊流程可直接將狀態改為 2；若有流程設定，建立 Issue Master，先轉為 1，後續簽核為 2、退回為 0，並通知第一關負責群組。
- DataStamp 在 Oracle 為 NUMBER(11,0) DEFAULT 0 nullable。更新版 Core 使用 DataStamp 做 compare-and-swap，成功後遞增；舊版 clsInventory 方法簽章沒有 DataStamp，ws 與 Core 版本有差異。YMES API 應以資料庫目前 DataStamp 做 CAS，並以 COALESCE(datastamp,0) 處理 NULL。
- DEV 假資料核准直接轉為狀態 2，僅為 UI 預覽簡化。Production API 必須依正式 Issue/Job 設定走直接核准或 Issue 流程，不能採用 DEV 直轉。

## 資料表與直接查證

公司端於 2026-11-16 使用 Windows PowerShell 5.1、Oracle.ManagedDataAccess 與本機受保護連線，唯讀查詢 MESTEST.TBLINVLOCATORBASIS 的 DBMS_METADATA DDL、ALL_TAB_COLUMNS、ALL_CONSTRAINTS、ALL_INDEXES、ALL_IND_COLUMNS。未讀取業務資料，未在 Oracle 執行 DDL，連線憑證未輸出或保存到 Git。

- 欄位：INVENTORYNO VARCHAR2(20) NOT NULL、LOCATORNO VARCHAR2(20) NOT NULL、DESCRIPTION VARCHAR2(255) NULL、CREATOR VARCHAR2(10) NOT NULL、CREATEDATE DATE NOT NULL、ISSUESTATE NUMBER(1,0) DEFAULT 0 NOT NULL、CAPACITY NUMBER(12,4) DEFAULT 0 NULL、LOCATORNAME VARCHAR2(50) NULL、ERPNO VARCHAR2(50) NULL、REVISER VARCHAR2(10) NULL、REVISEDATE DATE NULL、DATASTAMP NUMBER(11,0) DEFAULT 0 NULL。
- 複合主鍵 (INVENTORYNO, LOCATORNO)。唯一索引只有 PK index；沒有 Oracle 外鍵或其他索引。
- 庫存挑選資料沿用既有 TBLINVInventoryBasis，查詢 IssueState=2 並 distinct InventoryNo。LocatorBasis 與 InventoryBasis 在 Oracle 沒有 FK，YMES 不新增外鍵。
- PostgreSQL 空表 CREATE 與原始 Oracle DDL 分別存於上述兩個 reference SQL。第一階段 bootstrap 亦已校正 IssueState、Capacity、DataStamp 預設值並移除未核實的欄位猜測註解。

## 家用端 API/schema 契約

- 先比對已部署 YMES schema；如舊 bootstrap 已建立此表，新增 forward migration 修正欄位預設，不重建或覆蓋資料。欄位型別、NULL、複合 PK 依 mestest_smd_locator_basis_create.sql。
- GET /api/smd/locator-basis?inventoryNo= 回傳匹配資料的四種 IssueState，按 InventoryNo、LocatorNo 排序；狀態由前端本地切換。GET /api/smd/locator-basis/options 回傳 { approvedInventories: [{ inventoryNo }] }，來源為 TBLINVInventoryBasis 的 IssueState=2。
- POST /api/smd/locator-basis 新增；PUT /api/smd/locator-basis/item?inventoryNo=&locatorNo=&issueState=0&dataStamp= 修改；DELETE 同一路徑並傳當前 IssueState/DataStamp；POST /api/smd/locator-basis/item/approve?inventoryNo=&locatorNo=&issueState=0&dataStamp= 執行舊核准流程。
- DTO 欄位使用 camelCase；伺服器設定 Creator/CreateDate、Reviser/ReviseDate，忽略用戶端稽核值。POST 新資料 IssueState=0。PUT 僅接受狀態 0；複合鍵不可修改；可空欄位為空時省略更新，符合舊 WinForms。
- DELETE 狀態 0/-1 實體刪除、狀態 2 改成 -1 並更新稽核/DataStamp、狀態 1 回衝突。Approve 僅收狀態 0，並沿用正式 IssueNo=INV LOCATOR 與 Issue/Job 規則。多筆操作由 UI 逐筆呼叫，第一筆失敗即停止並保留部分成功結果。
- API 要驗證登入與 SMD 權限；DataStamp nullable compare-and-swap，更新時以 COALESCE(datastamp,0)+1 遞增。庫存選項只回傳已簽核列；不新增 Oracle 未定義的外鍵或索引。
