# 工位基本資料（SMD SD109）

## 功能來源與畫面

- MES FunctionNo：POSITION BASIS；模組 SMD；FunctionKey SD109；WinForms：STD/MESWin/SMD/SD_PDLinePositionBasis/frmSMDPDLinePositionBasis.vb 及 frmSMDPDLinePositionBasisDef.vb。
- 主視窗 ClientSize 1008×591，沒有 IssueState 篩選或簽核。查詢列欄位 PDLineNo、PositionNo；Grid 依兩欄排序。欄位順序及寬度：PDLineNo 120、PositionNo 150、Description 300（多行）、Creator 80、CreateDate 150、Reviser 80、ReviseDate 150；DataStamp 隱藏。
- 右側按鈕 Add、Edit、Delete、Copy；底部 Close。支援列選取、多選刪除。刪除以反向選取順序逐筆呼叫，首筆錯誤後停止。
- 定義視窗 ClientSize 511×312，主 GroupBox 487×168，下方稽核區 487×70，底部 Confirm、Close、Apply。

## 欄位與操作規則

- 複合鍵為 (PDLineNo, PositionNo)；兩欄最多 50 字元，PositionNo 離開欄位時 Trim 並轉大寫。
- PDLineNo 是唯讀選擇欄，按「...」載入已核准的一般作業區：AreaClass=0、AreaType=0、IssueState=2。選取 AreaNo 後帶入 PDLineNo。
- PositionNo 在新增/複製可輸入；可選 eSOP station.get 回傳值。eSOP 選擇器僅在 SYS Parameter Execute_eSOP=1 啟用，並使用 eSOP_WebService_URL/既有 ERP EAI 設定。Web UI 不應從瀏覽器直連 eSOP；由家用 API 代理呼叫。
- Description 可空，來源欄位最多 50 字元。Add 與 Copy 預填目前登入者及建立時間。
- Edit 模式 PDLineNo/PositionNo 唯讀；只更新 Description、Reviser、ReviseDate，使用 DataStamp 做版本條件。
- Copy 保留來源欄位作為初始值，但必須由使用者變更複合鍵再新增；重複複合鍵由資料庫 PK/API 拒絕。
- 確定寫入並關閉；套用寫入並留在表單；關閉不寫入。沒有狀態欄或簽核流程。
- Delete 是實體刪除，複合鍵識別；多筆操作逐筆執行、首錯停止。

## 資料表結構

Oracle MESTEST.TBLSMDPDLINEPOSITIONBASIS 已由 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 直接唯讀查詢。欄位如下：

| 欄位 | Oracle 型別 | NULL / DEFAULT |
|---|---|---|
| PDLineNo | VARCHAR2(50) | NOT NULL |
| PositionNo | VARCHAR2(50) | NOT NULL |
| Description | VARCHAR2(50) | NULL |
| Creator | VARCHAR2(10) | NOT NULL |
| CreateDate | DATE | DEFAULT SYSDATE、NOT NULL |
| Reviser | VARCHAR2(10) | NULL |
| ReviseDate | DATE | NULL |
| DataStamp | NUMBER(11,0) | DEFAULT 0、NULL |

PK/唯一索引為 (PDLineNo, PositionNo)；沒有 FK 或其他索引。Oracle DATE 轉 timestamp without time zone。原始邏輯 DDL及 PostgreSQL 空表 CREATE SQL：database/reference/mestest_smd_pdline_position_basis_source_ddl.sql、mestest_smd_pdline_position_basis_create.sql。first-phase bootstrap 中此表曾缺 Createdate/DataStamp defaults，已按來源校正。

## Production API handoff（家用電腦）

| 方法 | 路徑 | 規則 |
|---|---|---|
| GET | /api/smd/pd-line-positions?pdLineNo=&positionNo= | 可選條件不分大小寫部分查詢；回傳全部顯示欄位，依複合鍵排序。 |
| GET | /api/smd/pd-line-positions/options | 回傳 Execute_eSOP 開關。 |
| GET | /api/smd/pd-line-positions/esop-options?pdLineNo= | 僅在 Execute_eSOP=1 時由伺服器呼叫既有 eSOP station.get，回傳 PositionNo 清單；不可讓瀏覽器直連企業 eSOP。 |
| POST | /api/smd/pd-line-positions | 新增；驗證長度、必填、PDLineNo 為已核准一般作業區、複合鍵唯一；Creator/CreateDate/DataStamp 由伺服器產生。 |
| PUT | /api/smd/pd-line-positions/{pdLineNo}/{positionNo}?dataStamp= | 更新 Description、Reviser/ReviseDate；PK 唯讀，CAS 更新並遞增 DataStamp。若來源 DataStamp 為 NULL，前端傳 `dataStamp=0&dataStampIsNull=true`，API 以 `DataStamp IS NULL` 比對；非 NULL 則比對實際數值。 |
| DELETE | /api/smd/pd-line-positions/{pdLineNo}/{positionNo}?dataStamp= | CAS 實體刪除；DataStamp 為 NULL 時傳 `dataStamp=0&dataStampIsNull=true` 並以 `IS NULL` 比對；若已有下游使用限制，查明舊 Service 的引用規則後以 409 回報，不可默默改為軟刪除。 |

API 驗證登入者與 SMD 權限，使用參數化 SQL。Migration 前先比對 YMES schema；目前 repo first-phase SQL 有表，仍需確認家用端實際資料庫 columns/defaults。
