## WinForms 主清單

- 表單最大化；查詢列以區域編號查詢，狀態 Radio 預設「未簽核」0，另有簽核中1、已簽核2、不使用-1。
- 主 Grid 欄位：AreaNo、AreaName、AreaType、AreaClass、AreaCompose、FactoryNo、DepartmentNo、BaseAreaNo、Description、Creator/CreateDate、Reviser/ReviseDate、IssueState。DataStamp 為隱藏併發欄位。日期顯示 `yyyy/MM/dd HH:mm:ss`；Description 多行。
- 主按鈕：新增、修改、刪除、複製、核准、區域配置、關閉。區域配置僅在選取 Base Area（AreaClass=1）時開啟；WinForms 的 IssueState 儲存限制程式碼已註解，配置可在非未簽核狀態編輯。
- 列選取支援多選；修改只允許 IssueState=0。複製沿用所選欄位並清空 AreaNo，新增為未簽核狀態。
- 刪除可多選：IssueState 0/-1 實體刪除；2 轉為 -1；1 不可刪除。實體刪除前 Core 檢查 `TBLSMDAREARELATION.ContainAreaNo` 是否仍有區域配置關聯。
- 核准只能批次選取 IssueState=0，IssueNo=`AREA BASIS`。若沒有 Issue Job/Detail 設定，直接轉為 2；有簽核設定時建立簽核資料並轉為 1，核准轉 2、退回轉 0。

## 定義表單

欄位以兩欄 WinForms 群組呈現，底部顯示建立/修改者與時間，按鈕為確定、關閉、套用。新增、複製寫入 Creator/CreateDate；修改寫入 Reviser/ReviseDate 並帶 DataStamp。

| 欄位 | WinForms 規則 |
| --- | --- |
| AreaNo | 必填、最多 20 字元；儲存前大寫；修改唯讀 |
| AreaName | 必填、最多 50 字元 |
| AreaClass/AreaType/AreaCompose | 由四種 Radio 組合指定（見下表） |
| FactoryNo | Base Area 必填，從已簽核工廠選取 |
| BaseAreaNo | 一般區域必填，從已簽核 Base Area 選取；選取後帶入 FactoryNo |
| DepartmentNo | 必填，從部門基本資料選取 |
| Description | 選填、最多 255 字元 |

| Radio | AreaClass | AreaType | AreaCompose |
| --- | ---: | ---: | ---: |
| Base Area | 1 | 2（其他） | 0（功能型） |
| 離散型功能區 | 0 | 0（作業區） | 0（功能型） |
| 連續性生產線 | 0 | 1（生產線） | 1（線型） |
| 其他區域 | 0 | 2（其他） | 0（功能型） |

BaseArea、Factory 與 Department 查找來源分別為已簽核 `TBLSMDAREABASIS`、`TBLSMDFACTORYBASIS` 及 `wsUSR.LoadDepartmentBasis`。一般區域的 FactoryNo 必須由所屬 Base Area 繼承，不由使用者任意指定。

## 區域配置視窗

WinForms 使用 Lassalle AddFlow 畫布，支援節點新增/編輯、拖曳、群組/多選、背景圖片、巢狀區域關係及保存。配置節點型別包含區域、庫房、設備、設備類別與設備群組；關聯寫入 `TBLSMDAREARELATION`，並衍生更新 `TBLSMDAREAMAP`、`TBLSMDAREAINVENTORY`、`TBLSMDSMTAREAEQPMAP`。背景圖保存於 `TBLSMDAREABASIS.BackgroundImage`。

Web 目前以 Vue 畫布拖曳節點，並可編輯位置、寬高、顏色、順序、包含區域，另提供背景圖片設定/清除（最大 10 MB）。這是明確的第一版簡化：尚未重製 AddFlow 群組選取、節點 resize handle、連續生產線的完整巢狀推導與 WinForms Node Define 全部屬性。家用 API 必須按原 Service 的關係推導規則，將四張關聯表與背景 BLOB 在同一 transaction 更新；不能只保存 Vue 傳入的 relation rows。舊 Service 沒有更新 AreaBasis 的 Reviser/ReviseDate；新版可用 DataStamp CAS 作併發保護，但需沿用舊稽核顯示行為。需由家用端閱讀 `frmAreaLayout.vb`、`frmNodeDef.vb`、`funSaveAreaData` 後完成 Production 行為。

## Oracle 結構核對

以下為公司端 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 直連 MESTEST 的只讀資料字典查詢結果。來源 logical DDL 及 YMES 空表 PostgreSQL SQL 已附檔；三張主/關聯表僅有 PK unique index，沒有 Oracle FK 或額外索引。

| Oracle 表 | 欄位與主鍵 | 重要 NULL / DEFAULT |
| --- | --- | --- |
| `TBLSMDAREABASIS` | 16 欄；PK `AreaNo` | `AreaType`, `AreaClass`, `IssueState`, `AreaCompose` 為 NUMBER(1) DEFAULT 0 NOT NULL；AreaNo/AreaName/FactoryNo/Creator/CreateDate NOT NULL；`BackgroundImage` BLOB；`DataStamp NUMBER(11) DEFAULT 0` 可 NULL |
| `TBLSMDAREAINVENTORY` | 9 欄；PK `(AreaNo, InventoryNo)` | AreaNo/InventoryNo/BaseAreaNo NOT NULL；DefaultInv NUMBER(1) DEFAULT 0 NOT NULL；DataStamp DEFAULT 0 可 NULL |
| `TBLSMDAREAMAP` | 6 欄；PK `(BaseAreaNo, ParentAreaNo, ChildAreaNo)` | BaseAreaNo/ParentAreaNo/ChildAreaNo/ParentAreaType/ChildAreaType NOT NULL；TopPDLineAreaNo 可 NULL |
| `TBLSMDAREARELATION` | 15 欄；PK `(BaseAreaNo,ObjectNo)`；索引 `(ContainAreaNo,ObjectType)` | 來源 DDL/CREATE SQL 在 `mestest_equipment_group_smd_source_ddl.sql`、`mestest_equipment_group_smd_create.sql` |
| `TBLSMDSMTAREAEQPMAP` | 5 欄；PK `(BaseAreaNo,AreaNo,EquipmentNo)` | 來源 DDL/CREATE SQL 同上；沒有 FK |

使用者畫面上的 DepartmentNo 為必填，但 Oracle 主表欄位可 NULL；API 要遵守 WinForms 業務驗證，同時讓資料庫結構仍精確反映 Oracle。Oracle DATE 在 PostgreSQL 對應 timestamp without time zone，BLOB 對應 bytea。家用端先比對現有 YMES schema；只補缺少的表/欄位，不刪除 YMES 擴充欄位。

## Vue 與 API 契約

本頁在 Vite Development Preview 且選擇 Development 環境時使用 localStorage 假資料；Production 不使用假資料。後端尚未交付時，API 404 顯示明確未建置訊息。

| 方法 | Endpoint | 行為 |
| --- | --- | --- |
| GET | `/api/smd/areas?issueState=&areaNo=` | 依狀態必要篩選，AreaNo 可選關鍵字查詢；回傳含完整欄位及 DataStamp 的清單 |
| GET | `/api/smd/area-basis/options` | 回傳 active factories、部門與已簽核 Base Areas |
| POST | `/api/smd/areas` | 新增 Area Basis；API 設 Creator/CreateDate、IssueState=0、DataStamp；驗證欄位及 parent/factory/department |
| PUT | `/api/smd/areas/{areaNo}?dataStamp=` | 只更新 IssueState=0；伺服器設定 Reviser/ReviseDate 並 CAS 遞增 DataStamp |
| DELETE | `/api/smd/areas/{areaNo}?issueState=&dataStamp=` | 0/-1 實體刪除（先檢查配置關聯）；2 軟刪除成 -1；1 回 409 |
| POST | `/api/smd/areas/{areaNo}/approve?dataStamp=` | 走 Issue/Job 簽核及 IssueNo `AREA BASIS`；不得在 Production 直接假核准 |
| GET | `/api/smd/areas/{areaNo}/layout` | 回傳 relation nodes 與背景圖片 Data URL/可下載內容 |
| GET | `/api/smd/areas/{areaNo}/layout-options` | 回傳目前 Base Area 可加入的區域/庫房/設備/設備類別/設備群組 |
| PUT | `/api/smd/areas/{areaNo}/layout?dataStamp=` | CAS 更新，交易同步 relation、area map、inventory map、SMT equipment map 及背景 BLOB；回傳更新後完整 Area DTO（含新 DataStamp） |

Area DTO 使用 camelCase：`areaNo, areaName, areaType, areaClass, baseAreaNo, factoryNo, departmentNo, description, creator, createDate, issueState, areaCompose, reviser, reviseDate, dataStamp`。資料表的 NOT NULL、欄位長度/精度與唯一鍵都由 API 驗證；多筆核准/刪除按舊 UI 逐筆處理，首筆錯誤停止並回報已完成筆數。所有端點檢查登入及 SMD 權限，更新/刪除支援來源 DataStamp NULL，使用 compare-and-swap。
