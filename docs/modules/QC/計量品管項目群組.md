## 主畫面與查詢

- 上方有 IssueState 單選：未凍結 `0`、簽核中 `1`、已核准 `2`、未使用 `-1`；預設未凍結。主 Form 先呼叫 `LoadQCItemGroupBasis` 取資料，再由用戶端依狀態過濾及按 GroupNo 排序。
- 搜尋條件為 GroupNo，空白不加條件。主 Grid 隱藏 GroupByBox、以單格選取。點選主 Grid 列會立即載入該群組的 Detail，不需重載整頁。
- 一般模式可見主 Grid 欄位順序：GroupNo、GroupName、LotIsValid、ComponentCollect（畫面欄名 ComCol）、PlanNo、FormName、WebURL、UnionERF、Description、Creator、CreateDate、Reviser、ReviseDate、CursorMode、GetFilePath。IssueState、DataStamp 隱藏；ErrorReportName、NoticeReportName、ExecutionFile、QCClass 不在主 Grid 顯示欄內。
- 下方 Detail Grid 顯示 QCItemNo、QCItemName、ShowOrder、ScriptIsValid。資料由 `LoadQCItemGroupDetail` 取回，名稱來自變數型品管項目資料；ScriptIsValid 是前端依群組與項目的計算腳本是否有內容計算。
- 主 Grid 右側功能依序為 Add、Edit、Delete、Copy、Approve、Parameter、Op、Add QC、Memo；Remove QC 位於主 Grid 下方。Detail 區另有 Calculate Script。原視窗有共用 Close；Web 頁面提供關閉功能。

## 新增、修改、複製

- Define Form 欄位：GroupNo、GroupName、LotIsValid、ComponentCollect、抽樣計畫連結/PlanNo、FormName、WebURL、UnionERF、Description、QCClass、CursorMode（Down/Right）、GetFilePath；建立/修改人及日期唯讀顯示。
- GroupNo、GroupName 必填；LotIsValid、ComponentCollect、CursorMode 必須選擇。勾選 Union Plan 時 PlanNo 必填；取消時會清空 PlanNo。UnionERF 初始勾選。抽樣計畫查找依 ComponentCollect 選一般計畫或 Wafer 計畫，僅載入已核准計畫。FormName 選項由 WinSPC Interface 清單載入，ExecutionFile 一併送 Service。
- Add 設定 Creator/CreateDate。Edit 鎖定 GroupNo、帶 DataStamp，並先執行 `ExeIssueControl`；修改時寫入 Reviser/ReviseDate。Confirm 儲存並關閉，Apply 儲存後保留視窗，Close 不儲存。
- Copy 以 Add 建新主檔，再呼叫 `CopyQCItemGroup` 複製來源群組的 QC Item detail。Core 的 `CopyQCItemGroupDetail` 只複製明細及 ShowOrder；來源沒有同步複製群組計算腳本的邏輯。複製資料新狀態為未凍結，Creator/CreateDate 重設。

## 按鈕邏輯與狀態限制

- **Delete** 支援多選並逐筆處理。狀態 `0`、`-1` 呼叫硬刪除；狀態 `2` 只改成 `-1` 並更新 DataStamp/Reviser/ReviseDate；狀態 `1` 不允許刪除。Core 硬刪除前檢查 `TBLWIPTEMP_QCITEM` 是否仍有使用中資料，接著刪除主檔、群組明細、該 GroupNo 計算腳本、QC Item Parameter 及程式列出的 QC 使用關聯。Legacy Core 沒有刪除 `XX_TBLQCITEM_MEMO` 的語句，可能留下 Memo 孤兒資料，YMES API 應明確決定保留相容或補完整清理並記錄差異。
- **Approve** 要求目前 Detail Grid 有資料，並只處理選取列中 IssueState=0 的群組。Service 使用 Issue Function `QCITEM_G`：若未設定簽核 Job，直接轉狀態 `2`；若有簽核流程，轉為 `1` 並建立簽核單。WinForms 檢查的是目前顯示的明細筆數，而非逐一確認每個被選群組都有明細；批次核准時可能因而放行另一筆空群組，屬來源行為需家用端決策是否保留。
- **Add QC** 僅在主群組 IssueState=0 可用。Include 子視窗列出 IssueState=2 的計量品管項目，並只顯示 ComponentCollect 與群組相同者；左右清單移動、上/下移排序。Confirm 呼叫 `UpdQCItemGroupDetail`，以完整清單替換該 GroupNo 全部明細及 ShowOrder，並刪除該群組中已不在明細的群組腳本。
- **Remove QC** 可多選 Detail，只允許主群組 IssueState=0。Legacy 逐筆呼叫 `DelQCItemGroupDetail`，失敗可能留下已完成部分；Core 同時清除不再被一般或 PMI 群組明細引用的 orphan 計算腳本。
- **Parameter** 傳入 GroupNo/GroupName 作為共用 QC Item Parameter 編輯器的 QCItemNo/QCItemName。若 PlanNo 有值，先查已核准抽樣計畫並將 PlanType 傳入子視窗。
- **Op** 傳 `QCType=2`、IssueState、LotIsValid。IssueState=0 或 `1` 時禁止修改；其他狀態才開啟共用作業站對應視窗。
- **Calculate Script** 需選一筆 Detail，傳入該 QCItemNo/Name、GroupNo、群組所有 QCItemNo。腳本資料以 `(QCITEMNO,GROUPNO)` 區分群組；空 Script 不算有效。Script 最長 255 字元。
- **Memo** 開啟 THEIL 客製參數清單，來源查 `TBLMESPARAMETER` 的 IssueState=2、ParameterClass=1。儲存時以 QCItemNo=GroupNo、QCItemType=1 呼叫 `THEIL.wsQC.UpdQCItemMemo`，以勾選清單完整替換該群組 Memo 設定，並記錄設定者與日期。

## 資料表、Oracle DDL 與 PostgreSQL Create

| 用途 | Oracle 資料表 | 已保存的 Oracle DDL | YMES PostgreSQL CREATE |
|---|---|---|---|
| 群組主檔 | `TBLQCITEMGROUPBASIS` | `database/reference/mestest_mtl_qc_item_tables_source_ddl.sql` | `database/reference/mestest_mtl_qc_item_tables_create.sql`；遷移 `0019_mtl_qc_item_library_api.sql` 已含此表 |
| 品管項目明細與順序 | `TBLQCITEMGROUPDETAIL` | `database/reference/mestest_qc205_variable_dependencies_source_ddl.sql`，亦見 `mestest_qc_item_attributes_source_ddl.sql` | `database/reference/mestest_qc212_item_group_create.sql` |
| 計算腳本 | `TBLQCCALCULATESCRIPT` | `database/reference/mestest_qc205_variable_dependencies_source_ddl.sql` | `database/reference/mestest_qc212_item_group_create.sql` |
| Memo 欄位 | `XX_TBLQCITEM_MEMO` | `database/reference/mestest_qc205_theil_custom_source_ddl.sql` | `database/reference/mestest_qc205_theil_custom_create.sql` |
| 共用參數/作業站關聯 | `TBLQCITEMPARAMETER` / `TBLOPQCITEM` | `mestest_qc_item_attributes_source_ddl.sql`、`mestest_operation_and_system_source_ddl.sql` | `mestest_qc_item_attributes_create.sql`、`mestest_operation_and_system_create.sql` |

- `TBLQCITEMGROUPBASIS` 主鍵為 GroupNo；`TBLQCITEMGROUPDETAIL` 主鍵為 `(GROUPNO,QCITEMNO)`；`TBLQCCALCULATESCRIPT` 主鍵為 `(QCITEMNO,GROUPNO)`。以上表均沒有 Oracle FK。
- Memo DDL 的必填欄位為 QCITEMNO、QCITEMTYPE、MEMO_ITEM、RESVITOR、DATETIME；Oracle source 沒有 PK/索引。既有 YMES Create 參考額外以 `(qcitemno,qcitemtype,memo_item)` 建唯一鍵，這是 YMES 建議，不是 Oracle 原始約束。
- QC212 用到的主檔和 Memo DDL 均已在先前 PowerShell 5.1 + Oracle.ManagedDataAccess 直接唯讀查詢紀錄中保存。本次重用既有 Oracle DDL；沒有再次連 Oracle、沒有查業務資料。
- CREATE 檔只供家用端比對 YMES live schema；不得直接在 MES Oracle 執行。`CREATE TABLE IF NOT EXISTS` 不會替既有表補欄位，家用端需先查實際 schema / migrations 再決定是否建立 migration。

## Vue 頁面與 API handoff

- Vue 3 路徑：`/YMES/QC/VariableItemGroup`。DEV 使用功能專屬 localStorage 假資料；頁面包括四狀態查詢、主/Detail Grid、Define、左右 Include 排序、Parameter、Op、計算腳本、Memo、Copy/Approve/Delete，畫面採 WinForms 上下 Grid 與右側按鈕布局，KD 黃橘色系。
- 建議登入保護 API（FunctionKey `QC212`）：
  1. `GET /api/qc/item-groups?functionNo=QCITEM_G` 回傳主檔與 DataStamp；`GET /api/qc/item-groups/{groupNo}/details` 回傳有序明細、QCItemName、ScriptIsValid。
  2. `POST /api/qc/item-groups` 新增；`PUT /api/qc/item-groups/{groupNo}` 修改。驗證字數、唯一 GroupNo、PlanNo/ComponentCollect 關聯與來源狀態。使用伺服器端身份寫 Creator/Reviser 日期，不信任前端提供的審計人員。
  3. `DELETE /api/qc/item-groups/{groupNo}` 由伺服器讀真實 IssueState/DataStamp 後決定硬刪或轉 -1；檢查 WIP 使用中資料。批次呼叫逐筆回報結果，單筆失敗不可中止後續列。未凍結硬刪應在同一 transaction 處理群組明細、群組腳本及 legacy 會刪的關聯表；Memo 是否一併清理需記錄相容決策。
  4. `POST /api/qc/item-groups/{groupNo}/approve`：只允許真實狀態 0，確認至少一個 detail，依 QCITEM_G Issue Job 設定直接生效或建立待簽核。
  5. `POST /api/qc/item-groups/{groupNo}/copy-details` body `{targetGroupNo}`：以來源 detail 和排序建立目標資料；不得假定會複製計算腳本。
  6. `PUT /api/qc/item-groups/{groupNo}/details` body `{items:[{qcItemNo,showOrder}]}`：驗證所有項目已核准且 ComponentCollect 匹配，transaction 完整替換明細、排序並刪除此群組不再使用的腳本。`DELETE /api/qc/item-groups/{groupNo}/details/{qcItemNo}` 對應 Remove QC。
  7. 共用子功能：`GET/PUT /api/qc/item-groups/{groupNo}/parameters`（沿用 QC Item Parameter 行為，PlanType 用查得值）、`GET/PUT .../operations`（固定 QCType=2）、`GET/PUT .../details/{qcItemNo}/script`（TBLQCCALCULATESCRIPT）、`GET/PUT .../memo-fields`（固定 QCItemType=1，限定已核准 ParameterClass=1 的系統參數）。
  8. Lookup：沿用 `GET /api/qc/variable-qc-items?issueState=2`、`GET /api/qc/sampling-plans?componentCollect=0|1&issueState=2`、`GET /api/process/operations`、`GET /api/system/mes-parameters?issueState=2&parameterClass=1`，以及 WinSPC Interface/QCClass 選項。
- 所有 SQL 使用參數化查詢；狀態轉換與主/明細/腳本寫入要用交易及並行更新檢查。公司端不連 YMES PostgreSQL、不建立 API；由家用端查 live schema 並實作。
