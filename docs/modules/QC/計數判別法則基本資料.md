## WinForms 主畫面

- 主清單為 1008×591。預設 IssueState=0，四個狀態為未簽核 0、簽核中 1、已簽核 2、不使用 -1。WinForms 一次載入主檔，再於用戶端依狀態篩選，依 RuleNo 排序。
- 查詢欄只使用 RuleNo；Core 條件為 `RuleNo LIKE '<search>'`，`%` 和 `_` 為萬用字元。
- 主 Grid 顯示 RuleNo、ComponentCollect（0=No、1=Yes）、Creator、CreateDate、Reviser、ReviseDate。IssueState 不顯示；主表沒有 DataStamp。
- 選取/啟用主檔列時載入該 RuleNo 的明細 Grid，依 Action、ReasonType 排序。明細欄位為 Action、ReasonType、ReasonLevel、RejectNum、Rate、RuleType；自訂 AQL 開啟時再顯示 ChangeAQL；明細稽核欄位存在於 dataset，Grid layout 預設隱藏。
- 主畫面右側垂直按鈕：Add、Edit、DEL、Copy、Approve；底部 Close。沒有 Import/Download/Print。
- RuleNo 主鍵最多 20 字元，離開欄位轉大寫。新增/複製需使用不同 RuleNo；修改時唯讀。

## 新增/修改/複製視窗

- 定義視窗分成主檔、明細與明細編輯三區。主檔欄位為 RuleNo、ComponentCollect 是/否；明細 Grid 可選多列刪除，並透過編輯區新增或修改目前規則。
- 一筆明細的唯一鍵為 `(RuleNo, Action, ReasonType, ReasonLevel)`。編輯明細時 Action、ReasonType、ReasonLevel 三個鍵欄位唯讀。新增若已存在相同三鍵，WinForms 會覆寫該列的 RejectNum、Rate、RuleType、ChangeAQL，不新增重複列。
- Action 選項依 `TBLQCATTRULEDETAIL.ACTION` ValueList；來源舊轉換註解列出 0 Warning、1 Wait、2 Hold、3 Alert。正式值與翻譯應由 YMES options API 供應。
- ReasonType 選項取 `GetValueList("TBLQCATTRULEBASIS","REASONTYPE",True)`；舊 VB 註解僅列出 0 Scrap、1 Defect，不是可信的完整正式選項。
- ReasonLevel 為 -1 到 9 的整數，-1 為舊系統 sentinel。
- 規則類型 RuleType：0 Number（RejectNum 必填、數值至少 1 且為整數）；1 Rate（Rate 必填、數值大於 0，資料欄位為 varchar(10)）；2 AQL Reject Number（RejectNum/Rate 清空，ChangeAQL 下拉可空白；WinForms 沒有對 ChangeAQL 做必填驗證）。RejectNum Oracle 欄位為 NUMBER(14,4)，但 WinForms 額外限制整數且大於等於 1。Rate 只驗數值正數，長度最終受資料庫 varchar(10) 限制。
- ChangeAQL 只有 `wsSYS.LoadParameter(ParameterType=SysInfo,ParameterNo=UserDefineAQL,ParameterValue=1)` 時顯示；候選為 `TBLQCAQL` 中 `AQLType IS NOT NULL` 的 distinct AQL。未開啟時隱藏選項與 Grid 欄位。
- 新增/複製建立 IssueState=0、Creator/Date；修改套用共用 `ExeIssueControl`，RuleNo 唯讀，狀態 1 唯讀，狀態 0 可編輯，其餘狀態僅 Issue Control 的 EditFlag 控制項可編輯，缺設定應 fail closed。
- Confirm 關閉視窗並保存；Apply 保存後視窗保持開啟；Close 時如明細有未保存變更，舊程式會提示是否保存。

## 查詢、資料寫入與狀態行為

- `LoadQCAttRuleBasis` 載入主表，`LoadQCAttRuleDetail(RuleNo)` 載入所選主檔明細。IssueState 篩選在前端；空值 IssueState 不符合四個狀態篩選。
- Add/Copy 呼叫 `AddQCAttRuleData`，整筆主檔和明細一次寫入；Edit 呼叫 `UpdQCAttRuleData`，以 RuleNo 刪除既有主/明細再重建。Web API 應以單一交易實作 aggregate 保存，避免刪除後部分失敗；舊 Oracle 無 FK。
- 舊 WinForms 的 Def 表單會設定 Reviser/ReviseDate，但 SOAP payload 不傳這兩欄；實際 `clsQCBasis.UpdQCAttRuleData` 刪除重建主/明細時只帶回 Creator/CreateDate，沒有寫入 Reviser/ReviseDate，明細 audit 也未傳。規格記錄此舊行為；YMES API 若需維持既有相容性，應先不宣稱舊端有修改 audit。可由後端另行決定是否在 Web 寫入時補 audit，並記錄為 YMES 明確差異。
- 主表 IssueState 是 nullable、DEFAULT 0；無 DataStamp，來源 API/Core 也未使用樂觀鎖。YMES 若新增併發保護屬 YMES 擴充，需另記，不可假稱 Oracle 已有 DataStamp。
- Delete 多選逐筆執行，state 0/-1/2 均實體刪主檔與明細；state 1 不允許。首筆失敗停止，之前成功不回復。API 刪除時應同交易刪 detail 與 basis。
- Approve 只接受 state 0；若目前啟用主檔明細為 0 筆，UI 不呼叫核准。依 Issue Job Map `QCITEM_A RULE DATA`：無 Job/Detail 時 0→2；有簽核 Detail 時建立 Issue，轉 1 並通知第一簽核群組，後續核准 2、退回 0。回傳真實狀態；不可假設一律立即 Active。
- 多選 Approve 逐筆執行，第一筆失敗停止並保留之前已成功項目。舊 UI 只先檢查目前明細 Grid 非空，API 應對每個待核准 RuleNo 再驗明細，拒絕沒有規則的空主檔。

## Vue DEV 頁與 API handoff

DEV 頁以標明 DEMO 的 localStorage 假資料呈現主檔/明細雙 Grid、四個狀態、RuleNo LIKE 查詢、主檔新增/修改/複製/刪除/核准、整筆明細編輯、ComponentCollect、三種 RuleType、AQL 選項開關、Issue Control 與多筆首錯停止。Production 不得讀 localStorage 假資料。

建議登入並以 FunctionKey `QC107` 授權所有 endpoint，SQL 參數化：

- `GET /api/qc/attribute-rule-bases?searchFieldName=RuleNo&searchFieldValue=`：回四個狀態的主檔、audit、IssueState、editableFields。只接受 RuleNo LIKE 條件。
- `GET /api/qc/attribute-rule-bases/{ruleNo}/details`：回 `(Action,ReasonType,ReasonLevel)` 明細與規則值、audit；父子表沒有 FK，API 要驗父檔與欄位型別。
- `GET /api/qc/attribute-rule-bases/options/actions`、`.../reason-types`：依 MES ValueList 等價設定回 `{value,label}`；Action 可沿用共用 ValueList；ReasonType 不使用舊註解寫死。
- `GET /api/qc/attribute-rule-bases/options/aql`：先讀 SysInfo/UserDefineAQL；關閉則回功能停用或空清單，開啟才從 YMES `tblqcaql` 查 distinct AQL 且 AQLType 非空。
- `POST /api/qc/attribute-rule-bases` 與 `PUT /api/qc/attribute-rule-bases/{ruleNo}?issueState=`：Aggregate body `{ ruleNo, componentCollect, issueState?, details:[{ action, reasonType, reasonLevel, rejectNum, rate, ruleType, changeAql }] }`。POST 設 state0 與登入者/伺服器時間；PUT RuleNo 唯讀並檢查 Issue Control。兩者單一交易保存 basis + details，校驗唯一鍵及規則種類的欄位互斥/必填。
- PUT 欄位白名單含 ComponentCollect、ruleDetails；state0 可編輯、state1 唯讀、state2/-1 依 Issue Control EditFlag；缺少設定則唯讀。沒有 Oracle DataStamp；如果 YMES 使用 row version，需明示屬 YMES 擴充。
- `DELETE /api/qc/attribute-rule-bases/{ruleNo}?issueState=`：僅 state 0/-1/2；交易內刪 detail 與 basis。state1 回 409。
- `POST /api/qc/attribute-rule-bases/{ruleNo}/approve?issueState=0`：至少一筆明細；按 Issue Job Map 建 Issue 或直接核准，回實際 IssueState。通知與 Issue 整合使用 YMES 共用流程服務。
- 多選刪除/核准 UI 逐筆 API 呼叫、第一個錯誤停止並回報先前完成筆數。資料稽核差異依本規格上節處理。
