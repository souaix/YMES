# QC406 第一處理群組

## 功能識別

- 第一層：品質資料（`QC`）
- 第二層：異常設定
- 第三層：第一處理群組
- FunctionNo：`FIRST GROUP`
- FunctionKey：`QC406`
- WinForms：`frmFirstGroup`、`frmFirstGroupDef`
- WinForms 專案：`STD/MESWin/QC/QC_FirstGroup`
- Service/Core：`wsQC.LoadFirstGroup*`、`wsQC.*FirstGroup`、`clsHoldBasis`、`clsBasis_UPD`
- 主表：`MESTEST.TBLQCFIRSTGROUP`
- Vue DEV 路徑：`/YMES/QC/FirstGroup`

## WinForms 主畫面

主表單 `ClientSize=1008×591`，繼承 `frmBasisTemplat`。Grid 位於 `(12,53)`、尺寸 `890×532`；右側垂直按鈕為新增、修改、刪除、複製、核准；右下角有關閉。查詢狀態為未簽核 0、簽核中 1、已簽核 2、不使用 -1，預設未簽核。查詢欄位下拉選單只有 `MClassNo`、`OPNo`，以 WinForms 共用查詢條件送給 Service。Service 載入全部狀態，再由 WinForms 對資料集篩選狀態。

Grid 顯示 `MClassNo`、`OPNo`、`GroupNo`、`Description`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`。`IssueState` 與 `DataStamp` 隱藏。日期格式為 `yyyy/MM/dd HH:mm:ss`；Description 欄允許多行。主 Grid 支援多列選取；刪除、核准逐列執行，首筆失敗停止並重新載入已成功變更的資料。新增/修改/複製以活動列的複合鍵 `(MClassNo, OPNo)` 定位。

## 定義視窗與欄位邏輯

`frmFirstGroupDef` ClientSize 為 `632×454`。上方主分類區選取 `MClassNo`；下方處理群組區含作業站 Grid、`GroupNo` 選取器與 Description；底部顯示建立/修改者與日期，並提供確定、關閉、套用。

### 查找選項

- 主分類候選：`LoadFirstGroupDefine` 呼叫 `LoadMClassBasis(IssueState=2)`，來源 `TBLQCMCLASSBASIS`。僅列已核准主分類。
- 作業站候選：同一 Service 呼叫 `LoadOPBasis(IssueState=2)`，來源 `TBLOPBASIS`。新增/複製模式可多選；WinForms 額外插入 `OPNo='*'` 特殊列，代表通用作業站設定。
- 異常處理群組候選：呼叫 `LoadHoldDispGroupBasis(IssueState=2)`，來源 `TBLQCHOLDDISPGROUPBASIS`。選擇器顯示 `GroupNo`、`GroupName`、`Description`。
- 三張查找表在原生 Oracle 均以直接唯讀 metadata 查過；這個功能只新增 `TBLQCFIRSTGROUP`，不因查找器重複建表。API 可重用 YMES 既有主分類、作業站、異常處理群組查找端點；尚未存在時由家用端提供受 QC406 權限保護的選項端點。

| 查找表 | 此功能使用欄位 | Oracle key / 狀態 | YMES 空表 CREATE 參考 |
| --- | --- | --- | --- |
| `TBLQCMCLASSBASIS` | MClassNo、Description | MClassNo PK；IssueState | `mestest_qc_first_group_lookups_create.sql` |
| `TBLOPBASIS` | OPNo、OPName | OPNo PK；IssueState | `mestest_operation_and_system_create.sql` |
| `TBLQCHOLDDISPGROUPBASIS` | GroupNo、GroupName、Description | GroupNo PK；IssueState | `mestest_qc_first_group_lookups_create.sql` |

資料庫 CREATE 檔只有在家用端確認 YMES live table 缺失時才參考；先比對 migrations 與 YMES 專屬欄位。

### 新增、修改、複製

- 新增與複製：`MClassNo`、`GroupNo` 必填；至少選一個作業站。每個選取的 OP 建立一筆主檔，狀態為 0。多選可包含特殊 OP `*`。建立人/時間由 Service 設定，DataStamp 使用來源 DEFAULT。
- 修改：以原 `MClassNo` 與 `OPNo` 定位；主分類及作業站不可變，允許重選 `GroupNo`、修改 Description。WinForms `ExeIssueControl` 依 IssueState 及系統設定控制欄位；Service/Core 僅在狀態 0 或 2 接受修改，狀態 1/−1 不更新。Active 狀態 UI 的欄位開放仍受 Issue Control 設定影響。
- 複製：帶入來源主分類、群組及說明；作業站清單限來源 OP 與 `*` 特殊列，沒有預先勾選。保存時按勾選 OP 建立新列，不能沿用來源主鍵。
- Description 最長 255；主分類 30、OP 20、群組編號 20；三個 key 欄位必填。主要欄位由唯讀文字框搭配 `...` 搜尋視窗選取。
- Add/Copy 的 Core 以一組 SQL collection 寫入多筆；API 應將批次新增放在單一交易，避免部分成功。若需完全重現舊 Core 的失敗回滾範圍，家用端移植時再核實底層 `ExecuteSQLNoneQuery_UPD` 交易實作。

## 狀態、刪除與核准

| IssueState | 畫面 | 修改 | 刪除 | 核准 |
| ---: | --- | --- | --- | --- |
| 0 | 未簽核 | 可修改群組/說明 | 實體刪除 | 可送核准 |
| 1 | 簽核中 | 不可修改 | 拒絕 | 不可重複送出 |
| 2 | 已簽核 | Service 接受修改；WinForms 欄位另受 Issue Control 設定 | 狀態改為 -1 | 不可送出 |
| -1 | 不使用 | 不可修改 | 實體刪除 | 不可送出 |

核准呼叫 Issue Job Map `FIRST GROUP`。找不到 Job 或沒有 Job Detail 時直接改成 2；存在簽核明細時建立 Issue，Issue 核准 SQL 將狀態改為 2，退回 SQL 改回 0，當前列設為 1；同時處理附件並通知第一簽核群組。正式 API 必須依登入者和資料庫 Issue/Job 設定執行，DEV 假資料只模擬無簽核工作流程的直接核准。

刪除主 Grid 選取列逐筆執行：0/−1 實體刪除，2 由 `SetFirstGroupIssueState` 改為 −1，1 拒絕。WinForms 將 DataStamp 傳入 Service；舊 Core 實體刪除本身未使用 DataStamp，軟停用與一般更新使用 DataStamp 比對並遞增。YMES API 應對實體刪除也採 DataStamp CAS，並支援來源欄位為 NULL 的舊列。

下游 `LoadFirstGroupJoinUserGroup` 以 `tblQCFirstGroup` join 異常處理群組表取群組名稱；指定 OP 查找時會同時查該 OP 與 `OPNo='*'`，並依 OPNo DESC 排序。沒有 Oracle FK 約束；API 不可依賴 FK/cascade，主分類/作業站/群組有效性須在新增時以核准候選驗證。

## YMES 前端/API handoff

Vue 元件 `web/src/components/QcFirstGroupMaster.vue`；Fallback 選單 QC → 異常設定 → 第一處理群組。DEV localStorage key 為 `ymes-dev-mock:qc-first-group:v1`；正式資料不使用 localStorage。建議契約：

- `GET /api/qc/first-groups?searchFieldName=&searchFieldValue=`：回傳全部四種狀態，使用複合鍵，包含 nullable audit/DataStamp；前端沿用狀態篩選。
- `GET /api/qc/first-groups/options/machine-classes?issueState=2`、`/options/operations?issueState=2`、`/options/hold-disposition-groups?issueState=2`：只回傳已核准候選；可由對應既有 YMES master endpoint 取代，但需維持欄位與權限。
- `POST /api/qc/first-groups`：body `{mClassNo, operationNos, groupNo, description}`，一次為每個 OP 建列；伺服器驗證主分類/群組已核准、普通 OP 已核准、特殊 `OPNo='*'` 明確允許，避免複合鍵衝突，設定 Creator/CreateDate/IssueState。批次以交易寫入。
- `PUT /api/qc/first-groups/{mClassNo}/{opNo}?dataStamp=`：只更新 GroupNo/Description、Reviser/ReviseDate/DataStamp；舊來源允許狀態 0/2，資料修改使用 CAS。
- `DELETE /api/qc/first-groups/{mClassNo}/{opNo}?issueState=&dataStamp=`：狀態 0/−1 實體刪除；2 改 −1；1 回 409。多筆由 UI 逐筆呼叫、遇錯停止並回報部分成功。
- `POST /api/qc/first-groups/{mClassNo}/{opNo}/approve`：確認狀態/DataStamp 後，按 `FIRST GROUP` Issue Job Map 直接啟用或建立簽核流程；回傳目前狀態與 DataStamp。

全部端點驗證登入與 FunctionKey `QC406`，SQL 參數化；`DataStamp` CAS 明確區分 NULL 與 0。來源 DDL 無 FK；不得自動 cascade 刪除主分類、OP 或異常處理群組。Production API/schema 未部署前，此頁只有 DEV 假資料。
