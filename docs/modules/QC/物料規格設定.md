# QC304 物料規格設定（Material QC Specification）

## 功能與 WinForms 來源

- MES 選單：第一層「品質資料」→ 第二層「計量規格設定」→ 第三層「物料規格設定」。FunctionNo=`MTLQCITEM`、FunctionKey=`QC304`。
- WinForms Form：`frmQCMaterialSpec`，來源 `D:\iMES\CSiMES\STD\MESWin\QC\QC_MaterialSpec\frmQCMaterialSpec.vb`。查詢/資料存取：`wsQC.LoadMaterialType`、`LoadMaterialBasisJoinMTLQC`、`LoadMTLQCItemJoinForVariables`、`LoadMTLQCItemJoinQCChart`、`UpdMTLQCChartData`；核心 SQL 位於 `STD\MESkc\kcQC\clsQCBasis.cs` 的「物料規格設定」區塊。
- Web DEV 頁：`/YMES/QC/MaterialSpec`，Vue 元件 `web/src/components/QcMaterialSpecMaster.vue`。DEV 以記憶體假資料呈現互動，不寫正式資料。
- QC304 沒有獨立規格主表；它維護 QC302 的 SPC Chart Basis/Detail，並追加 DetailLog 歷程。

## WinForms 版面

- 視窗 ClientSize 1008×591，啟動最大化。畫面由上到下為 Query、MaterialData、QCItem Spec、MEMO/Confirm/Close 四區；上方查詢區約 86px，MaterialData 與 QCItem Spec 各約一半剩餘高度，底列約 45px。
- Query 欄位：Material Type、Material No（依編號前綴查詢），各有 `...` 查找鈕，按 Query 執行。Material Type 查詢既有核准類別；Material No 查找沿用目前輸入條件。
- MaterialData Grid 欄位：Selected、MaterialType、MaterialNo、MaterialName、SPEC。上方有 SelectAll、UnSelectAll。點某列 SPEC 按鈕才載入該物料目前的 QC Item 規格，並將該物料列設成 Selected；Selected 可再勾選多筆，Confirm 將目前 detail 同時套用到已勾選物料。
- QCItem Spec Grid 欄位：QCItemNo、QCItemName、SPCID、US、CS、LS、UCL、CL、LCL。SPCID 以 Trend Chart、Xbar Chart、R Chart、S Chart、Rm Chart、X Chart 顯示。上方包含 CS、Tolerance、Edit、六種圖表篩選 CheckBox 與 Paste；預設只勾 Trend Chart。
- 下方 MEMO 為淡黃色欄位；按 Confirm 前必填修改原因。Close 關閉表單。QC 規格表格的 SpecLineType 必填格採淡黃色；X-Rm 中不可編輯的 Xbar 列採灰色。

## 查詢與載入規則

- MaterialType 與 MaterialNo 至少輸入一項；MaterialNo 以 `LIKE prefix%` 搜尋。`LoadMaterialBasisJoinMTLQC` 僅列 `MaterialBasis.IssueState=2` 的物料，並限 QC Item FactorSpec 組合計數符合來源條件（`QC_Count=1`）。UI 為 Material 加上本地 Selected=false 欄與 SPEC 動作欄，再依 MaterialNo 排序。
- `LoadMTLQCItemJoinForVariables` 從 `TBLMTLQCITEM` 讀物料直接綁定的計量 QC Item，也展開 QC Item Group 明細；同時讀 QC Item FactorSpec。只有恰好一個 FactorSpec 且 FactorNo=`MATERIAL` 的 QC Item 才會形成可編輯 Chart Spec rows。
- 點 SPEC 時 `LoadMTLQCItemJoinQCChart` 讀指定物料已存在的 `TBLSPCQCCHARTBASIS` 與 Detail；只找 FactorSpec 唯一值為 MATERIAL，且 Basis 的 MATERIAL 因子值等於該 MaterialNo 的資料。資料未依 Chart Basis IssueState 篩選。沒有既有物料專屬 Basis 時，仍建立對應的空白 Detail rows。
- ChartType 對應：0→SPCID 0/1/2（Trend/Xbar/R）、1→0/1/3（Trend/Xbar/S）、2→1/4/5（Xbar/Rm/X；Xbar 列唯讀，沒有 Trend 列）。ChartType=2 的 X Chart 以 SPCID=5 顯示，寫入 Oracle 時轉回 SPCID=0；讀取時把 SPCID=0 轉成 X Chart。其他 ChartType=-1 不產生可編輯列。
- CheckBox 僅過濾畫面顯示列，不縮小 Confirm 的 Detail payload。未勾任何圖表時 Grid 顯示空結果，但資料來源仍保留完整規格集合。

## 修改、貼上與驗證

- 點選 Detail row 後，輸入 CS 與非負 Tolerance 按 Edit，計算 `US=CS+Tolerance`、`LS=CS−Tolerance`、`CS=CS`，然後清空兩個輔助欄。Grid 的 US/CS/LS/UCL/CL/LCL 可直接逐格編輯。
- SPCID=0（Trend）依 SpecLineType 標示必填：0 要 US+LS、1 要 US、2 要 LS。Confirm 會檢查所有規格 rows 中淡黃色必填格、非空數字欄、US≥UCL≥CL≥LCL≥LS。SPCID=0/5 的 US/LS 若有值也必須為數值；CS/UCL/CL/LCL 非空時均須是數值。數值界限順序以有值欄位比較。
- Paste 讀剪貼簿 CSV 資料，從目前啟用的格開始逐列/逐欄填入；超過現有 rows/columns 即停止。Web 用戶需在使用者明確點擊 Paste 後讀取剪貼簿；若瀏覽器拒絕剪貼簿權限，提供 textarea 讓使用者 Ctrl+V，再套用 tab/comma 分隔值。
- Confirm 必須有 Selected Material 並且 MEMO 不可空；表單把選取的 MaterialNo 清單與全部 QCItem 規格 Detail 一次送給 `wsQC.UpdMTLQCChartData`。成功後重新執行 Query，清空 Detail Grid。

## Core 寫入行為與相容性重點

- Core 對每個 Material、每個 QCItemNo 先查 `TBLMTLQCITEM` 是否有該 Material+QCItem 的直接綁定，沒有就略過；再驗證 FactorSpec 唯一值必須為 MATERIAL，並確認 `TBLQCITEMFORVARIABLES` 存在。
- 若 `(QCItemNo, MaterialNo)` 尚無 Chart Basis：產生新 FactorSerial，新增 Basis，SampleSize 取 QC Item、Memo 取表單 MEMO、Material 因子設為物料編號、Creator/CreateDate 取目前使用者/時間、IssueState=0。若已存在，沿用其 FactorSerial，不更新 Basis IssueState 或欄位。
- 每次寫入都刪除該 FactorSerial 的既有 `TBLSPCQCCHARTDETAIL` rows，再依所有 Detail rows 重建；每一列同時新增 `TBLSPCQCCHARTDETAILLOG`，寫 Creator/StartTime 與本次界限快照。Core 將多個 Material 的 SQL 收集後一次交給更新 helper；YMES API 應在單一交易內保護 Basis/Detail/DetailLog 一致，並重新驗證 Material、QC Item 綁定及 FactorSpec 白名單。
- 舊 Core 對由 QC Item Group 展開的子 QC Item 也會送至更新流程，但寫入時只查物料對該子 QC Item 的直接 `TBLMTLQCITEM` 綁定；未直接綁定者會被略過。這是舊程式實際行為，API 應明確回報略過數/原因，避免 UI 顯示整批完全套用。
- 舊 Core 的既有 Basis 更新只重建 Detail/DetailLog，不改 Basis 的 MEMO、IssueState 或 Reviser/DataStamp；新 Basis 才寫入 MEMO/Creator/IssueState。表單雖要求每次輸入 MEMO，但舊服務沒有把既有 Basis 的修改原因寫進 Basis。YMES 應把 MEMO 收進服務端操作稽核，且不要因套用界限而把已核准 Basis 自動改為 UNFROZEN，除非共用 QC Issue 規則另有明確規定。
- QC Chart 的初始建檔有舊全域 helper `InitFactorSerial`；YMES 應沿用 Chart Basis 的伺服器端 serial 產生器，不接受瀏覽器產生 FactorSerial。

## 資料表與 DDL

- QC304 寫入的三張表已由既有 QC302 遷移涵蓋：Oracle 來源 DDL `database/reference/mestest_qc302_spc_qc_chart_source_ddl.sql`；PostgreSQL CREATE 對照 `database/reference/mestest_qc302_spc_qc_chart_create.sql`；YMES migration `database/migrations/0024_qc302_chart_data_import.sql`。Basis 的 dynamic factor 在 YMES 是 `factorvalues JSONB`，Material key 為 `MATERIAL`；CREATE reference 也保留舊 physical `material` 欄，實作須核對 QC302 API 實際查詢方式，必要時一致更新 JSONB 與相容欄位。
- 查詢相依表沿用既有資料：物料與 `TBLMTLQCITEM` 的 Oracle/PG schema 在 `mestest_mtl_master_source_ddl.sql`、`mestest_mtl_master_create.sql` 及 migration 0013；`TBLQCITEMFORVARIABLES`、Factor 與 QC Item Group 的 DDL/CREATE 參照分別在 QC205/QC201/QC212 規格與 `mestest_qc212_item_group_create.sql`；家用端仍須核對目前 live YMES schema 和 migration 是否完整部署。
- QC304 沒有獨立新表；本次不新增 QC304 專屬 CREATE SQL。若家用端查 live schema 發現 QC304 相依表缺漏，沿用其 Oracle source DDL 與現有 CREATE reference 建 forward migration，不另造相同用途資料表。
- Oracle DDL 由先前公司端 PowerShell 5.1 + Oracle.ManagedDataAccess 直接唯讀取得並保存在上述來源 reference；本次讀 WinForms/Service/Core 原碼並沿用 reference，沒有查業務列、沒有在 Oracle 執行 DDL，也沒有輸出連線資訊。

## YMES API handoff（家用端）

本頁的建議契約；如現有路由能提供相同資料，應沿用現有 API 並同步 Vue/spec。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/materials/lookups/options` | 重用既有核准 MaterialType lookup |
| GET | `/api/qc/material-spec/materials?materialType={type}&materialNoPrefix={prefix}` | 搜尋 ACTIVE 物料與 QC_Count 合格條件 |
| GET | `/api/qc/material-spec/{materialNo}/qc-items` | 物料直接綁定及群組展開的計量 QC Item 與 FactorSpec metadata |
| GET | `/api/qc/material-spec/{materialNo}/chart-details` | 讀物料專屬 Basis/Detail；X-Rm SPCID=0 轉換顯示 X Chart |
| POST | `/api/qc/material-spec/batch-update` | 一次套用 materialNos、完整 detail rows、memo；服務端重查資格、以 MATERIAL 因子 upsert Basis，交易式替換 Detail 並追加 DetailLog |

- API 登入保護，所有 SQL 參數化；拒絕非 ACTIVE 物料、無效 QC Item、FactorSpec 不唯一/不是 MATERIAL、無效 SPCID 或非數值/錯序界限。`factorvalues` 必須由伺服器建立安全 JSONB，不可動態拼接 Factor 欄位。
- Save command 以 MaterialNo 清單+完整 detail payload 作為一個業務操作；服務端應在 transaction 中重查直接 QC Item 綁定、Chart Basis serial/狀態、DataStamp（若適用）、寫 Detail 及 DetailLog。回傳 `{updatedCount,skippedCount,failedCount,results:[{materialNo,qcItemNo,status,message}]}`；每個 material/item 的跳過或失敗必須明確回傳，不能 HTTP 200 卻只更新部分項目而讓 UI 顯示整批成功。
- 家用端先核對 MTL/QC Chart/QC Item Group table 的 YMES live schema、migration 0013/0019/0024 及 QC301/302 API；確認完成後在 `todolist_homepc.md` 更新部署結果，公司端再 pull 對接 Production API。
