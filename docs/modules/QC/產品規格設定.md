# QC305 產品規格設定（Product QC Specification）

## 功能與 WinForms 來源

- MES 選單：第一層「品質資料」→ 第二層「計量規格設定」→ 第三層「產品規格設定」。FunctionNo=`PRDQCITEM`、FunctionKey=`QC305`。
- WinForms Form：`frmQCProductSpec`，來源 `D:\iMES\CSiMES\STD\MESWin\QC\QC_ProductSpec\frmQCProductSpec.vb`。核心 SQL 位於 `STD\MESkc\kcQC\clsQCBasis.cs`「產品規格設定」區塊；產品類別 lookup 呼叫 `wsPRD.LoadProductType`。
- Web DEV 頁：`/YMES/QC/ProductSpec`，Vue 元件 `web/src/components/QcProductSpecMaster.vue`。本機 DEV 假資料只保存在頁面記憶體，不寫正式資料庫。
- QC305 沒有專屬資料表；它維護 QC302 的 SPC Chart Basis、Detail、DetailLog，並讀取產品、產品 QC Item、變數 QC Item、Factor 與 QC Item Group。

## WinForms 畫面與操作

- 表單約 1008×591，三區垂直排列：Query（Product Type、Product No、... lookup、Query）、ProductData（SelectAll、UnSelectAll、產品清單及 SPEC 按鈕）、QCItem Spec（CS、Tolerance、Edit、六種 Chart checkbox、Paste、規格 Grid），底部為必填修改原因 MEMO、Confirm、Close。
- Product Type 的 `...` 呼叫 `LoadProductType`；Product No 的 `...` 從目前產品查詢結果挑選產品。兩個條件至少輸入一個；ProductNo 用前綴比對。
- Query 清除既有規格 Grid，取得 ACTIVE 產品及其可設定的計量 QC Item 數量，舊程式只顯示 `QC_Count = 1` 的產品。ProductData 欄位為 ProductType、ProductNo、ProductName、SPEC 按鈕與 Selected。
- 點某筆產品的 SPEC，載入此產品的變數 QC Item 與既有 chart 規格，初始化空白 Chart rows，再將已保存界限帶入。點 SPEC 同時把該產品標為 Selected；SelectAll/UnSelectAll 控制套用目標。
- QC Item 直接關聯與產品 QC Item Group 展開都會列入候選；僅 `FactorSpec='Y'` 因子唯一且 `FactorNo='PRODUCT'` 的變數 QC Item 可編輯。群組展開列要保留 `GroupNo`，保存時用它確認產品綁定。
- Chart rows：ChartType 0→SPCID 0/1/2（Trend/Xbar/R）；1→0/1/3（Trend/Xbar/S）；2→1/4/5（Xbar/Rm/X，其中 Xbar 唯讀）；ChartType=-1 不建立規格列。ChartType=2 的 SPCID 5 顯示 X Chart，讀寫 chart detail 時映射為儲存 SPCID 0。
- 六種 checkbox 僅過濾 Grid 顯示，不刪除或縮小 Confirm 的明細 payload。CS/Tolerance 的 Edit 依目前選取列計算 CS、US=CS+Tolerance、LS=CS−Tolerance；Paste 從目前儲存格起點把剪貼簿資料填入可編輯欄位。

## 儲存與驗證

- Confirm 要求目前有選取的規格列、至少一個 Selected Product、非空 MEMO。畫面標示必填的 US/LS 需填值；適用欄位須為數字，界限比較順序為 US≥UCL≥CL≥LCL≥LS。舊 Core 對非數值的可選界限也會拒絕；留空欄位不參與排序。
- 儲存時，表單傳入選取 ProductNo 清單、完整 QCItem/GroupNo/SPCID/US/CS/LS/UCL/CL/LCL 明細、MEMO 與使用者。勾選的圖表 filter 不影響送出的規格 rows。
- Core 對每個產品及 QCItem 先確認 `TBLPRDQCITEM` 綁定：一般項目確認 QCItemNo；群組展開項目以 GroupNo 確認群組綁定。沒有綁定時略過該產品/QCItem；FactorSpec 因子必須恰好一個且為 PRODUCT，`TBLQCITEMFORVARIABLES` 必須存在。
- 查詢已存在 Basis 使用 `(QCItemNo, Product)`，不依 ProductVersion 或 OPNo 篩選。產品查詢也以 ProductNo 關聯產品 QC Item；YMES API 應忠實記錄此舊行為與多版本/多 OP 風險，不能在未決定規則前靜默換成另一套選擇條件。
- 沒有 Basis 時，Core 產生 FactorSerial 並新增 Basis：SampleSize 取 QC Item、Product 因子值為 ProductNo、MEMO/Creator/CreateDate 設為本次值、IssueState=0。已有 Basis 時沿用 FactorSerial，不修改 Basis MEMO、IssueState 或修訂欄位。
- 每個產品/QCItem 的既有 Chart Detail 先刪除，再按完整規格重建 Detail，且每列新增 DetailLog（MEMO、Creator、StartTime 及界限快照）。跨多產品更新必須在 YMES transaction 內維持 Basis/Detail/DetailLog 一致；逐項略過或失敗需在結果中可見。
- 舊 Core 以 `(QCItemNo, Product)` 定位 Basis，GroupNo 不在 Basis key 中；同一產品若經不同群組重複帶入同一 QCItem，舊服務可能重複覆寫同一份 chart detail。API 應避免重複 payload 並回報不一致綁定，不可假設群組會產生獨立 Basis。

## 資料表與 DDL

- Chart Basis/Detail/DetailLog Oracle DDL：`database/reference/mestest_qc302_spc_qc_chart_source_ddl.sql`；PostgreSQL CREATE 對照 `mestest_qc302_spc_qc_chart_create.sql`；YMES migration `0024_qc302_chart_data_import.sql`。
- 產品 Basis：Oracle 來源 `database/reference/mestest_qc218_tblprdproductbasis_source_ddl.sql`。`TBLPRDQCITEM`、QC Item Factor/Variable 來源 DDL 沿用 `database/reference/mestest_qc205_variable_dependencies_source_ddl.sql`；QC Item Group PostgreSQL CREATE 參照 `database/reference/mestest_qc212_item_group_create.sql`。
- QC305 不新增 CREATE SQL 或 migration。`TBLPRDTYPE` 是舊 `LoadProductType` lookup 依賴，但本 repo 未保存其獨立 Oracle DDL；家用端先查 YMES live schema 和現有產品 lookup/API，確認缺物件後再請公司端取得原始 DDL並新增 forward migration。不要複製已存在的產品、QC Item 或 SPC Chart 表。
- Basis 要因在 YMES 以 `factorvalues JSONB` 儲存 PRODUCT；查詢及寫入需核對 QC302 API 是否也使用舊 physical `product` 相容欄，必要時同步兩種表示。
- 本回合直接閱讀 WinForms Form/Core 與既有 DDL reference，未讀 Oracle 業務資料列、未執行 Oracle DDL、未查 YMES PostgreSQL；沒有將連線資訊寫入 Git。未執行 build、測試或瀏覽器驗收。

## YMES API handoff（家用端）

API 要求登入，並依既有授權機制檢查 FunctionNo=`PRDQCITEM` / FunctionKey=`QC305`。若既有 API 已有同等路由，沿用並同步本頁和 Vue 元件。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/qc/product-spec/product-types` | `LoadProductType` 對應的 ProductType 選項 |
| GET | `/api/qc/product-spec/products?productType={type}&productNoPrefix={prefix}` | ACTIVE 產品清單及舊 `QC_Count=1` 過濾 |
| GET | `/api/qc/product-spec/{productNo}/qc-items` | 產品直接/群組計量 QC Item、GroupNo、ChartType、SpecLineType、FactorSpec |
| GET | `/api/qc/product-spec/{productNo}/chart-details` | 讀 Product 因子值符合 ProductNo 的既有 Basis/Detail；Basis key 不含 GroupNo |
| POST | `/api/qc/product-spec/batch-update` | 批次套用產品規格、寫 Detail 與 DetailLog |

`batch-update` request：`{productNos:string[], details:[{qcItemNo,groupNo,spcId,us,cs,ls,ucl,cl,lcl}], memo:string}`。`spcId=5` 由 UI 映射成 0。回應 `{updatedCount,skippedCount,failedCount,results:[{productNo,qcItemNo,status,message}]}`。服務端須以參數化 SQL，在交易中重查 ACTIVE 產品、產品/QC Item 或 Group 綁定、FactorSpec 白名單和既有 Basis，不能信任瀏覽器傳來的因子、SampleSize、serial、Creator、IssueState 或時間。對同一 `(productNo,qcItemNo)` 去重；Basis 的 Product 因子寫入 `factorvalues` 並按既有 QC302 寫法處理 physical `product` 相容欄。既有 Basis 不得因改 Detail 而被自動改成 UNFROZEN；MEMO 必須保留在新增 Basis/DetailLog 或 YMES audit。交易失敗不得回報部分成功。
