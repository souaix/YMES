# QC303 品管項目規格（QC Spec Basis）

## 功能與來源

- MES 選單：第一層「品質資料」→ 第二層「計量規格設定」→ 第三層「品管項目規格」。FunctionNo=`QC SPEC BASIS`、FunctionKey=`QC303`。
- WinForms：`frmQCSpecBasis`、`frmQCSpecBasisDef`、`frmQCSpecCopy`。主要程式位於 `D:\iMES\CSiMES\STD\MESWin\QC\QC_SpecBasis`；資料服務與核心邏輯為 `STD\MESws_STD\wsSTD\wsQC\wsQC.cs`、`STD\MESkc\kcQC\clsQCBasis.cs`。
- Vue 頁：`/YMES/QC/SpecBasis`，元件 `web/src/components/QcSpecBasisMaster.vue`。DEV Preview 使用明確的本地假資料；正式環境走 YMES API。
- 本頁不含 QC301 的 Rule 編輯器，也不含 Rule 資料表維護。

## WinForms 版面與操作

- 主窗 ClientSize 約 1008×661。上方計量 QC Item Grid 顯示 QCItemNo、QCItemName、QCDataType、ChartType、SpecLineType、ComponentCollect、Unit、LotIsValid。
- QC Item 下方有四個 IssueState 篩選：UNFROZEN=0、PENDING=1、ACTIVE=2、UNUSED=-1。中段主 Grid 隨 QC Item 的 FactorSpec=Y 動態顯示因子值；若因子有 MES Parameter ShowName，另顯示對應名稱。末端顯示 Creator/CreateDate。Factor Serial、狀態、DataStamp、Description、修訂者與修訂時間供操作或編輯使用，部分不顯示於主 Grid。
- 主 Grid 下方 Detail 顯示 SPCIDShow、US、CS、LS、UCL、CL、LCL。選取主檔列後載入該 serial 的 Detail。
- 右側按鈕順序為 ADD、EDIT、DEL、Copy、Approve、Disapprove、Copy2、Close；DEL/Approve/Disapprove 支援多選。Copy 編輯單筆並新增同 QC Item 副本；Copy2 開啟跨 QC Item 複製視窗。
- `frmQCSpecBasisDef` 內有 QC Item/Serial/狀態欄、Factor 清單、Description、QCItem Spec Detail、MEMO 與 Creator/CreateDate/Reviser/ReviseDate。新增/複製後狀態為 UNFROZEN；Apply 儲存但保留編輯視窗，Confirm 儲存並關閉。修改時 Confirm 要求 MEMO 作為原因；Apply 可不填。
- FactorSpec=Y 的 Factor 按 ParameterType 決定輸入方式：ParameterType=2 為自由文字；其他類型開啟既有參數選取視窗。可清除值。主畫面與編輯表單不會動態建立資料庫欄位。

## 圖表與規格邏輯

- 計量 QC Item 由 `wsQC.ShowQCItemForVariables` 載入；因子由 `wsQC.ShowQCItemFactor` 取得。主清單依 IssueState 篩選，但 QC Item 清單沿用 WinForms 查詢條件，不由本頁額外只限 ACTIVE。
- ChartType 產生 Detail 列：`-1` Trend(0)；`0` Trend(0)、Xbar(1)、R(2)；`1` Trend(0)、Xbar(1)、S(3)；`2` UI 顯示 X Chart(5) 與 Rm(4)，舊資料儲存 X 的 SPCID=0，讀取時若同一規格有 SPCID=4 則將 SPCID=0 顯示為 X Chart。API 應把此相容規則集中轉換，不可因此新增一個 SPCID=5 資料列。
- 每列包含 US、中心值 CS、LS、UCL、CL、LCL。Above 是畫面輔助值，不存入資料庫；有 CS 與 Above 時 US=CS+Above、LS=CS−Above。啟用的數值需符合 US ≥ UCL ≥ CL ≥ LCL ≥ LS；來源表的 UCL/CL/LCL 是字串欄，表單按數值處理。
- SpecLineType：0 雙邊需首個圖表的 US、LS；1 需 US；2 需 LS；3 不強制規格界限。沿用實際 WinForms 驗證；因子值可為空或 `*`，不可自行加上全因子必填規則。
- `TBLQCSPECBASIS` 的因子來源欄位為 MO、PRODUCT、EQUIPMENT、CUSTOMER、OP、PROCESS、EQPTYPE、MATERIAL、POSION、EMPLOYEE、THINKNESS、THICKNESS、VERSION、DEVICE。Oracle 欄名中的 `POSION`、`THINKNESS` 是原始拼字；YMES JSONB key/DTO 要明確維持既有參數代碼，不能默默改名。
- `GetSpecSerial` 以 QC Item 與因子值尋找可用規格，支援 `*` wildcard 作為通用值。這是執行期規格匹配邏輯；編輯 API 的重複檢查仍須依核心 duplicate 條件，以同一 QC Item 與 Spec 因子組合阻擋重複。

## 新增、修改、刪除、簽核與複製

- 新增由伺服器產生 QCSpecSerialNo（沿用 `QCSN` 序號服務），新增 Basis 及各 SPCID Detail。duplicate 檢查涵蓋相同 QC Item 與全部規格因子，不以 IssueState 排除既有資料。serial 不可由瀏覽器產生或用來執行動態 SQL。
- 修改只允許 IssueState=0，帶 DataStamp；以樂觀併發檢查更新 Basis/audit，並交易式替換 Detail。Creator/CreateDate/Reviser/ReviseDate 由登入身份與伺服器時間管理。MEMO 是修改原因，依 WinForms 確認/套用按鈕規則處理。
- 刪除：狀態 0/-1 實體刪除 Basis 與 Detail；狀態 2 改標 UNUSED(-1)；狀態 1 拒絕。舊 Core 未執行量測資料引用檢查，YMES 若加保護須先查正式 PostgreSQL/API 參照，不能為了模仿流程而刪除量測資料或建立假引用表。
- Approve 僅允許 0。依 Issue Job 設定，沒有簽核明細時可直接 ACTIVE(2)；有簽核流程時先 PENDING(1)，完成 Issue callback 後成為 ACTIVE 或退回。Disapprove 僅 ACTIVE(2) 可退回 0。API 必須重查狀態、DataStamp、重複條件並呼叫共用 Issue service，不信任前端傳入的狀態或 audit。
- Copy 複製單筆規格成新 serial、新狀態 0；保留因子值與 Detail。Copy2 的來源/目標 QC Item Spec Factor 名稱集合必須一致；CopyType=3 複製來源狀態 0+2，=0 只複製 0，=2 只複製 2。目標端已存在相同因子組合者略過；成功副本均以新 serial、狀態 0 建立，並複製 Detail。

## 資料表與 DDL

- 功能直接維護 `MESTEST.TBLQCSPECBASIS`、`MESTEST.TBLQCSPECDETAIL`。Oracle DDL 先前已由公司電腦 PowerShell 5.1 + Oracle.ManagedDataAccess 直連 MESTEST 唯讀查詢，存於 `database/reference/mestest_qc205_variable_dependencies_source_ddl.sql`（Basis 區塊約第 710 行、Detail 區塊約第 679 行）。本次沿用該已保存結果，沒有用 DBeaver 畫面推估，沒有讀業務列或在 Oracle 執行 DDL。
- Basis：QCITEMNO VARCHAR2(25) NOT NULL、QCSPECSERIALNO VARCHAR2(35) NOT NULL PK、ISSUESTATE NUMBER(1) DEFAULT 0 NOT NULL、DATASTAMP NUMBER(11) DEFAULT 0、DESCRIPTION、Creator/Date、Reviser/Date；因子為十四個 VARCHAR2(61) DEFAULT `'*'` 欄。僅 Serial PK unique index，無 FK。
- Detail：SPCID NUMBER(2) DEFAULT 0 NOT NULL、US/LS/CS NUMBER(12,4)、QCSPECSERIALNO VARCHAR2(35) NOT NULL、UCL/CL/LCL VARCHAR2(15)、MEMO VARCHAR2(255)；PK=(QCSPECSERIALNO,SPCID)，無 FK 或額外索引。
- PostgreSQL CREATE-only 對照：`database/reference/mestest_qc303_spec_basis_create.sql`。這是 Oracle schema 到 YMES 的適配參考，將十四個動態因子欄放進 `factorvalues JSONB`，不是 migration，也不可直接在公司端執行。先比對 YMES live schema、migrations 與既有 API；僅缺少時才由家用端建立 forward migration。
- QC Item、Factor、MES Parameter、Issue/Job、`QCSN` 序號均沿用共用既有資源，不要另建一套表。

## YMES 實作與運行方式（2026-11-18）

已完成並部署以下 endpoint：

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/qc/spec-bases/qc-items` | 計量 QC Item 與因子 metadata（FactorSpec、ParameterType、ShowName） |
| GET | `/api/qc/spec-bases?qcItemNo={no}&issueState={state}` | 指定 QC Item/狀態的規格主檔 |
| GET | `/api/qc/spec-bases/{serial}/details` | 選取 serial 的 Detail |
| GET | `/api/qc/spec-bases/factors/{factorNo}/options` | 因子參數選項；自由文字欄位不需選項 |
| POST | `/api/qc/spec-bases` | 新增 Basis+Details，服務端產生 serial/state/audit |
| PUT | `/api/qc/spec-bases/{serial}` | 僅修改 UNFROZEN，檢查 DataStamp，交易式更新 Basis+Details |
| DELETE | `/api/qc/spec-bases/{serial}` | 依當前合法狀態實體刪除或改 UNUSED |
| POST | `/api/qc/spec-bases/{serial}/approve` | 驗證狀態/併發/簽核工作並回傳實際狀態 |
| POST | `/api/qc/spec-bases/{serial}/disapprove` | ACTIVE 退回 UNFROZEN |
| POST | `/api/qc/spec-bases/copy` | Copy2，body 含 FromQcItemNo、ToQcItemNo、CopyType，回傳 CopiedCount |

- API 受登入保護；目前依使用者先前指示尚未實作角色／FunctionKey ACL。Factor JSONB key 僅接受該 QC Item 的 FactorSpec 白名單，資料值採參數化 SQL，FactorNo 不會組成資料庫識別字。
- Basis/Detail 新增、修改、刪除與 Copy2 使用資料庫交易；修改採 DataStamp 比對，Creator/Reviser、時間、狀態由服務端管理。
- YMES PostgreSQL 原先缺少 QC303 Basis/Detail，已套用 `database/migrations/0026_qc303_spec_basis.sql`；套用前備份 `/opt/ymes/backups/ymes_before_0026_qc303_20261118.dump` 已通過 `pg_restore --list`。Migration 只建立 QC303 兩表、索引與 `ymes_app` CRUD 權限，未建立共用 QC Item/Factor/Parameter/Issue/Job/QCSN 表。
- Live schema 沒有共用 QCSN 序號服務，現階段 serial 使用服務端 `QCSN` 前綴加 GUID 的 35 字元 fallback；接入共用序號服務前應保留 API 與欄位契約。
- Live schema 沒有 `tblsysmesparameter`、Issue/Job 共用流程或 QC measurement-reference table。自由文字 Factor 可操作；需參數目錄的選項查詢會明確回報未提供。Approve 在確認沒有已知 Issue/Job 表時直接轉 ACTIVE；若日後發現流程表，端點會停止並回報未支援，不會假裝完成簽核。硬刪未加虛構的量測引用表檢查。
