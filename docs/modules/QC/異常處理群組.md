## WinForms 畫面

- 主窗體 `frmHoldDispGroupBasis` 客戶區約 1008×591。繼承共用主檔篩選列：狀態預設未簽核，四狀態為 0 未簽核、1 簽核中、2 已簽核、-1 不使用；搜尋欄只有 GroupNo，按查詢後依群組編號排序。
- 主區域是上下 SplitContainer。上半部群組清單約 225px，右側縱向按鈕為新增、修改、刪除、複製、核准；底部為關閉。
- 群組 Grid 可見 GroupNo、GroupName、Description、Creator、CreateDate、Reviser、ReviseDate；DepartmentNo、IssueState、DataStamp 隱藏。點選一列會直接載入下方人員，不重整頁面。
- 下半部人員維護區分三個 Grid：左側未選擇使用者；右側上方主處理群組（GroupType=5）；右側下方副知群組 CC（GroupType=6）。中間四個移動按鈕分別將使用者加入主處理、移回未選擇、加入 CC、移回未選擇。每張 Grid 顯示 DepartmentNo、UserNo、UserName，支援多選。
- 人員移動先只更新畫面暫存。按「確定」才一次替換該 GroupNo 的 5/6 類成員；空清單也代表清空既有成員。完成後重新載入群組，回到相同資料列。
- 使用者候選呼叫 `wsUSR.LoadUserSecurity(IssueState=2)`，只載入已核准使用者。群組成員由 `wsQC.LoadHoldDispGroupDetail(CCGroup=True, IssueState=2, GroupNo=..., AgentOf='NA')` 載入，組織/姓名再與使用者清單合併。

## 編輯視窗與操作規則

- `frmHoldDispGroupBasisDef` 約 484×322，分群組編號、群組名稱、說明三欄，另有建立/修改人與日期稽核欄，以及套用、確定、關閉按鈕。
- GroupNo、GroupName 必填；GroupNo 在離開欄位時轉大寫。來源欄位長度分別 20、50；Description 最長 255。修改時 GroupNo 唯讀；新增與複製會建立新主檔並設定狀態 0。
- 修改視窗可編輯 GroupName、Description；Service 只允許 IssueState 0 或 2 更新，1/-1 不允許。
- 複製視窗預帶來源的 GroupNo、GroupName、Description，使用者輸入新 GroupNo 後建立狀態 0；`CopyHoldDispGroupBasis` 會在同一交易複製群組與 `TBLUSRUSERGROUP` 的 5/6 類人員關聯。
- 刪除支援多選、逐列呼叫並於第一筆失敗時停止。IssueState 0/-1 實體刪主檔及 GroupType 5/6 關聯；狀態 2 將主檔改成 -1 並保留成員；狀態 1 不接受刪除。
- 核准只處理未簽核資料。多選逐筆執行，第一筆錯誤即停止。Production Issue Job Map key 是精確字串 `HOLD DISP GROUP`：沒有 Job 或 Job 無明細時直接改為 2；有明細時建立 Issue、改為 1、通知第一簽核群組，核准轉 2、退回轉 0。

## Oracle 資料表與 CREATE SQL

### `MESTEST.TBLQCHOLDDISPGROUPBASIS`

DDL 來源已由公司端透過 PowerShell 5.1 + Oracle.ManagedDataAccess 直連受保護 Oracle 設定唯讀取得，並記錄在 QC406 共用 lookup 檔；本功能不需要再建立重複 SQL 檔：

- Oracle source DDL：`database/reference/mestest_qc_first_group_lookups_source_ddl.sql`
- PostgreSQL 空表 CREATE 參考：`database/reference/mestest_qc_first_group_lookups_create.sql`

欄位：

| 欄位 | Oracle 型別 | Null / Default | 用途 |
| --- | --- | --- | --- |
| GroupNo | VARCHAR2(20) | NOT NULL | PK |
| GroupName | VARCHAR2(50) | NOT NULL | 群組名稱 |
| DepartmentNo | VARCHAR2(20) | NULL | 舊表欄位；此 Form 隱藏且 Service 未提供編輯欄 |
| Description | VARCHAR2(255) | NULL | 說明 |
| Creator / CreateDate | VARCHAR2(10) / DATE | NULL | 建立稽核 |
| IssueState | NUMBER(1,0) | NOT NULL DEFAULT 0 | 簽核狀態 |
| DataStamp | NUMBER(11,0) | NULL DEFAULT 0 | 版本值 |
| Reviser / ReviseDate | VARCHAR2(10) / DATE | NULL | 修改稽核 |

來源只有 GroupNo 主鍵及其 unique index，沒有其他 index 或 FK。

### `MESTEST.TBLUSRUSERGROUP`

- Oracle source DDL：`database/reference/mestest_equipment_engineer_group_member_source_ddl.sql`
- PostgreSQL 空表 CREATE 參考：`database/reference/mestest_equipment_engineer_group_member_create.sql`
- 欄位為 UserNo VARCHAR2(10) NOT NULL、GroupNo VARCHAR2(20) NOT NULL、GroupType NUMBER(1,0) NOT NULL DEFAULT 0、AgentOf VARCHAR2(10)、AgentDate DATE、AgentCreateDate DATE。PK `(UserNo, GroupNo, GroupType, AgentOf)` 會令 AgentOf 實際上不可為 NULL；來源無 FK/額外索引。
- QC405 使用 GroupType 5 主處理、6 CC。畫面代表的直接成員以 `AgentOf='NA'` 儲存；更新主處理成員時還會呼叫 `clsUSRSecurity.AddUserAgentToGroup(UserNo, GroupNo, 5)` 同步代理人關聯。
- 兩張表的 Oracle DDL 均已直接查得，PG CREATE 檔也已存在。家用端先比對 YMES live schema/migrations；只有資料表缺漏時才新增 migration，不在 Oracle 執行 CREATE，也不要新建另一張 QC405 成員表。

## 家用端 API / Schema 待辦

所有端點要求登入及 FunctionKey `QC405`，查詢/更新採 SQL 參數化；版本更新需以 GroupNo + DataStamp CAS，DataStamp 為 NULL 時用 `IS NULL` 條件。

1. `GET /api/qc/hold-disposition-groups?searchFieldName=GroupNo&searchFieldValue=`：回傳四狀態群組及稽核欄；搜尋欄白名單僅 GroupNo。
2. `GET /api/qc/hold-disposition-groups/options/users?issueState=2`：對應 `wsUSR.LoadUserSecurity(IssueState=2)`，回傳 DepartmentNo、UserNo、UserName。
3. `GET /api/qc/hold-disposition-groups/{groupNo}/members`：回 `{ primary: string[], cc: string[] }`；依 GroupType 5/6 與 AgentOf='NA' 讀取直接成員，保留缺失或已停用使用者的舊關聯供畫面移除。
4. `POST /api/qc/hold-disposition-groups`：body `{groupNo, groupName, description}`；GroupNo 大寫、長度 20，GroupName 必填/長度 50，Description 上限 255；伺服器寫 Creator/CreateDate、IssueState=0、DataStamp 初值。
5. `PUT /api/qc/hold-disposition-groups/{groupNo}?dataStamp=`：只更新 GroupName/Description，僅接受狀態 0/2；伺服器更新 Reviser/ReviseDate/DataStamp。
6. `POST /api/qc/hold-disposition-groups/copy`：body `{sourceGroupNo, groupNo, groupName, description}`；單一交易新增主檔及複製舊服務所讀的 GroupType 5/6 關聯，使用新 GroupNo。舊 `ShowHoldDispGroupDetail` 未限制 AgentOf，且 `AddHoldDispGroupDetail` 以 AgentOf='NA' 寫入，需維持此相容行為或在 API 規格標註有意修正。
7. `DELETE /api/qc/hold-disposition-groups/{groupNo}?issueState=&dataStamp=`：0/-1 實體刪主檔與 GroupType 5/6 關聯；2 轉 -1 並保留關聯；1 拒絕。交易內處理 CAS。
8. `POST /api/qc/hold-disposition-groups/{groupNo}/members?dataStamp=`：body `{primaryUserNos: string[], ccUserNos: string[]}`。一個交易內用群組 DataStamp CAS、遞增主檔版本、刪除該 GroupNo 全部 5/6 類關聯、重建所選直接成員 (AgentOf='NA')；各主處理人呼叫既有代理人同步邏輯。相同 UserNo 不可同時出現在 primary/cc；空陣列表示清空。
9. `POST /api/qc/hold-disposition-groups/{groupNo}/approve?issueState=0&dataStamp=`：Issue Job Map 精確使用 `HOLD DISP GROUP`；無 Job/Detail 直轉 2，有流程建立 Issue、轉 1、通知第一簽核群組，核准 2/退回 0。

`TBLQCHOLDDISPGROUPBASIS`、`TBLUSRUSERGROUP` 的空表參考已存在；不新增 Oracle DDL，不盲目套 CREATE。家用端先比對 YMES PostgreSQL schema、migration、索引與 ymes_app 權限，再依缺漏新增 forward migration。
