# QC502 檢測儀器基本資料（Inspection Machine Parameter）

## 功能與 WinForms 來源

- MES 選單：第一層「品質資料」→ 第二層「檢測儀器」→ 第三層「檢測儀器基本資料」。FunctionNo=`INSPMACHINE PARAMETER`、FunctionKey=`QC502`、IssueTable=`TBLQCINSPMACHINEPARAMETER`。
- 主畫面：`STD/MESWin/QC/QC_InspMachineParameter/frmInspMachineParameter.vb`；Def 畫面：同目錄 `frmInspMachineParameterDef.vb`；資料操作：`STD/MESkc/kcQC/clsInspMachine.cs` 的 `Load/Add/Edit/DelInspMachineParameter`；Web Service：`STD/MESws_STD/wsSTD/wsQC/wsQC.cs`。依 WinForms/Service/Core 程式碼還原，不以截圖代替。
- Web DEV 頁 `/YMES/QC/InspectionMachine`：`web/src/components/QcInspectionMachineMaster.vue`。預覽使用瀏覽器 localStorage 假資料；正式模式呼叫 YMES API。
- 本頁實際主檔為 `TBLQCINSPMACHINEPARAMETER`。會查 QC501 的儀器類別與 Driver；Designer 中 Property 按鈕預設隱藏。QC502 不維護 `TBLQCINSPMACHINEBASIS`，該表雖在共用來源 DDL 中存在，但此 Form/Core 的 Add/Edit/Delete 都針對 Parameter 表。

## WinForms 畫面與流程

- 主 Form 約 1008×591，IssueState 四狀態篩選 0 未簽核、1 簽核中、2 已簽核、-1 不使用，預設 0；搜尋欄為 InspMachineNo。載入 Core 取回所有資料，Form 依 IssueState 篩選；來源未設定明確排序。
- Grid 顯示欄位：InspMachineNo、InspMachineName、InspType（0 RS232、1 UserDefine）、BaudRate、DataBit、StopBit、Description、Creator、CreateDate、Reviser、ReviseDate；IssueState、DataStamp 隱藏。右側按鈕 ADD、EDIT、DEL、Copy、Approve、Close；Property 預設隱藏。主列點選只設定 ActiveRow，核准/刪除沒有 checkbox 選取時會自動以 ActiveRow 執行，也可多選逐筆處理；首筆服務失敗後停止後續列。
- Def Form 約 560×547。欄位有 InspMachineNo、InspMachineName、是否套用 InspMachineType、InspType、RS232/UserDefine 設定分頁、Description、建立/修改人與日期；按鈕確定、關閉、套用。新增/複製保存後可重查定位新資料；修改欄位 InspMachineNo 唯讀。
- `InspMachineNo` 必填，離開欄位轉大寫；InspMachineName、Description 可空。InspType 必填。勾選 InspMachineType 後按 `...` 從 `LoadInspMachineParameterType` 全部資料選取類別，帶入該類別的 InspType、RS232 欄位或 InspDriverNo，並停用本機 InspType/通訊欄位；此 lookup 未帶 IssueState，不限狀態。勾選但未選類別不能儲存。
- 未套用類別時，可直接選 InspType 並維護本機參數。RS232 必填 BaudRate、ParityBit、DataBit、StopBit、EndCode、Format1；BaudRate 600/1200/2400/4800/9600/19200，ParityBit None/Odd/Even/Mark，DataBit 7/8，StopBit 1/2，EndCode 0/3/10/13。Format2、ChNo 可空，儲存成 `NA`。UserDefine 必須以 Driver lookup 選 InspDriverNo；Driver lookup 呼叫 `LoadInspDriver` 時不指定 IssueState。
- EndCode 對照：0=NUL、3=ETX、10=LF、13=CR。Format1/Format2 離開欄位轉大寫。Oracle `ChNo` 為 VARCHAR2(3)，但舊 TextBox MaxLength=10；Vue 保留舊輸入上限，API 需依 live schema 清楚回傳超長錯誤，不能截斷。InspMachineName 為 `AdditionalXml` 欄位，長度 50；Description 長度 255。
- 編輯時 InspMachineNo 鎖定、InspType 下拉鎖定；InspMachineType 欄位唯讀但 `...` lookup 仍可選擇類別。Core Edit 僅在傳入非空 InspMachineType 時更新，舊服務不能藉清空欄位解除既有關聯。QC502 Vue 防止把已連結類別清空；改選其他類別會更新其通訊參數。
- Edit 呼叫共用 `ExeIssueControl`：0 全欄可編輯；1 Pending 唯讀；2 Active 與 -1 Unused 依表單/控制項設定判斷。YMES API 必須接共用 Issue Control 設定，不能硬編碼成所有欄位全開。
- 核准只接受 IssueState=0，傳 InspMachineNo、IssueState、Creator、DataStamp 到 `ApproveInspMachineParameter`。wsQC 查共用 IssueManagement：沒有可用 Job 時直接改為 IssueState=2；有 Job 時啟動簽核並改為 1。最終狀態不能由前端指定。刪除允許 0、2、-1，帶 IssueState/DataStamp；Core 只刪 `TBLQCINSPMACHINEPARAMETER` 單筆，沒有額外屬性清理。

## 資料表與既有 DDL

- Oracle 原始 DDL、PostgreSQL 空表 CREATE 對照沿用 QC501 已取得檔案：`database/reference/mestest_qc501_inspection_machine_source_ddl.sql`、`database/reference/mestest_qc501_inspection_machine_create.sql`。其中 QC502 主表 `TBLQCINSPMACHINEPARAMETER` PK 為 `InspMachineNo`；`InspMachineType` 可 NULL；IssueState 與 DataStamp 有 DEFAULT 但允許 NULL。沒有重查 Oracle，也沒有在 Oracle 執行 DDL。
- QC502 查詢/寫入主表欄位：InspMachineNo、InspMachineType、InspType、BaudRate、ParityBit、DataBit、StopBit、EndCode、Format1、Format2、ChNo、InspDriverNo、Description、Creator/CreateDate、IssueState、InspMachineName、DataStamp、Reviser/ReviseDate。
- QC501 類別資料使用 `TBLQCINSPMACHINEPARAMETERTYPE`；Driver 選擇使用 `TBLQCINSPDRIVER`。QC502 的 Property 按鈕預設隱藏；本頁不為它新增功能或 CREATE SQL。
- 舊 Add 寫入 QC502 主表並設 IssueState=0；Edit 依非預設參數逐欄更新、InspMachineName 由 AdditionalXml 更新，並以 DataStamp/IssueState 條件限制；Delete 依版本條件硬刪單列。YMES API 必須改為參數化 SQL，維持欄位來源與語義並採交易/CAS。

## YMES API handoff（家用端）

登入保護所有端點；按現行 YMES 授權安排檢查 FunctionNo=`INSPMACHINE PARAMETER` / FunctionKey=`QC502`。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/qc/inspection-machines?issueState={state}&inspMachineNo={query}` | 主清單；回 `{items:[...]}`，欄位含 DataStamp/IssueState |
| GET | `/api/qc/inspection-machine-parameter-types` | QC501 類別 lookup；舊服務未限制 IssueState |
| GET | `/api/qc/inspection-drivers` | UserDefine Driver lookup；舊服務未限制 IssueState |
| POST | `/api/qc/inspection-machines` | 新增，伺服器建立 Creator/CreateDate/IssueState=0/DataStamp |
| PUT | `/api/qc/inspection-machines/{inspMachineNo}` | 更新；Body 傳 IssueState/DataStamp，主鍵不可改；類別關聯只允許有效類別，不可把空字串靜默忽略後回報已清除 |
| DELETE | `/api/qc/inspection-machines/{inspMachineNo}?issueState={state}&dataStamp={stamp}` | 刪除允許狀態的單筆主資料；狀態/版本不符回 409 |
| POST | `/api/qc/inspection-machines/{inspMachineNo}/approve` | 送入既有 Issue Job 流程；按設定直接 ACTIVE 或轉 PENDING，由 API 回傳實際狀態 |

API 要檢查狀態、DataStamp、欄位長度、類別/Driver 存在性及 InspType 設定一致性；服務端維護 audit 欄位，使用交易/CAS。QC501 API 路徑已在 QC501 規格中交接，兩頁應共用 DTO/lookup/簽核邏輯。
