# QC204 刪除計數型品管項目量測記錄

## 功能識別

| 項目 | 來源 |
|---|---|
| FunctionNo / FunctionKey | `QCITEM_ADELETE` / `QC204` |
| FunctionName | 刪除計數型品管項目量測記錄 |
| Menu | 品質資料 → 品管設定 → 刪除計數型品管項目量測記錄 |
| WinForms Form / DLL | `frmQCItemDeleteForAttributes` / `QC_ItemDeleteForAttributes.dll` |
| IssueOption / IssueTable | `0` / 無 |
| 主要來源 | `frmQCItemDeleteForAttributes.vb`, `wsQC.LoadQCItemForAttributes`, `wsQC.DelQCItemForAttributes`, `clsQCBasis.LoadQCItemForAttributes`, `clsQCBasis.DelQCItemForAttributes` |

## WinForms 畫面

- Form 尺寸為 1008×591。左側/中央是一個可選取多列的 UltraGrid，GroupByBox 隱藏；右上有 `DEL (&D)`，右下有 `Close (&X)`。沒有搜尋列、編輯視窗或新增功能。
- Form Load 依序呼叫 `LoadQCItemForAttributes`，先載入 `IssueState=-1` 再載入 `IssueState=0` 並合併。畫面只列不使用與未審核的計數型 QC Item；核准狀態 2 不會出現在此頁。
- Grid 的資料來自 `TBLQCITEMFORATTRIBUTES A.*`，可保存使用者 Grid layout。來源欄位以 QC Item 編號/名稱、狀態、抽樣計畫、法則、建立/修改資訊等為主；Vue 顯示主要欄位並提供橫向捲動。
- 刪除按鈕使用 Ok/Cancel 確認，預設焦點是 Cancel。點選目前列可單筆刪除；Selected.Rows 可多選。
- 送出的每筆參數為 QCItemNo、IssueState、`Log=Log`；只有 `FormName=frmAtt_OnlineControlMeasureDataForTape` 時才會另外傳 FormName。
- 關閉按鈕關閉此功能頁。

## 刪除邏輯與注意事項

### 來源 Core 規則

1. `wsQC.DelQCItemForAttributes` 必須接收 IssueState 和 QCItemNo。IssueState 為 0 或 -1 時進入量測資料刪除；2 則改設為不使用（IssueState=-1），其他狀態拒絕。此 WinForms 頁只載入 0/-1。
2. `Log=Log` 是此頁的模式旗標。它略過一般 QC Item 主檔刪除路徑，不刪除 QC Item、Parameter、Factor 或其他設定；也會略過「目前被線上 OP 使用」的檢查。
3. Core 先以 QCItemNo 查 `TBLSPCATTBASISLOG` 是否有量測資料。沒有資料時回 `0000-200003`（No Measurement records Exist）。
4. 有資料時刪除 `TBLSPCATTBASISLOG`、`TBLSPCATTDETAILLOG`、`TBLSPCATTEDITLOG` 中該 QCItemNo 的資料。若 FormName 是 Tape 專用表單，額外刪除 `TBLSPCATTDETAILLOG_TAPE`。
5. 歷史 Core 在刪除後丟出 `0000-000001`（All Measure Data have been deleted）作為成功訊息，但 WebService 會將它包成失敗結果；WinForms 顯示訊息並停止處理剩餘多選列，且可能不刷新 Grid。這是來源實作的不一致。YMES API 應將已提交的刪除正常回傳成功，Vue 逐筆處理並顯示成功數/首個失敗項目。
6. Core 對一般 Master Delete 的 WIP/綁定檢查與三表主檔刪除不屬於本頁 `Log=Log` 流程，不得在 QC204 呼叫中刪除 QC Item 主檔。

### YMES 行為要求

- 每筆刪除以資料庫交易包住 BasisLog、DetailLog、EditLog，以及適用時的 Tape DetailLog；所有條件使用參數化 SQL。先確認 QC Item 仍存在且其真實 IssueState 與請求相符，限定 IssueState 0/-1。
- 即使來源不檢查 OP/WIP 使用狀態，API 仍只執行使用者明確確認的量測日誌刪除，不擴大到 QC Item 設定或其他 QC log tables。
- 多選依 Grid 順序逐筆呼叫；遇到第一筆錯誤停止，回報已完成筆數與失敗 QCItemNo。這保留來源的「部分完成不可回復」語義，同時讓成功結果可辨識。
- 此功能不新增資料表。來源 Oracle DDL 已收錄於 `database/reference/mestest_qc_item_attributes_source_ddl.sql`，含 QC Item master、BasisLog、DetailLog、EditLog 及 Tape DetailLog；家用端須先比對 YMES 現有 migration/schema，只對缺少的表補 forward migration。

## Vue 與 API handoff

- Vue 頁 `/YMES/QC/AttributeMeasurementDelete` 使用 DEV 專用 localStorage 假資料；沒有功能資料時不讀取 Production API 假資料。
- 清單沿用 QC201 預定 API，分別呼叫 `GET /api/qc/attribute-qc-items?issueState=-1`、`GET /api/qc/attribute-qc-items?issueState=0`，合併成 WinForms 順序。回應需含此頁 Grid 欄位，特別是 `formName`、`issueState`。
- 新增命令端點：`POST /api/qc/attribute-qc-items/{qcItemNo}/measurement-log-deletions`，body `{ issueState }`。以登入使用者、QC204 功能權限執行；伺服器不信任呼叫端狀態，需重讀 QC Item 後校驗，Tape 特例 FormName 從資料庫主檔取得。
- 成功回傳刪除結果（至少包含 `qcItemNo`、刪除表與筆數）；查無 BasisLog 時回可辨識的 404/409 與錯誤訊息。伺服器須寫操作/錯誤事件，不可把 legacy `0000-000001` 成功例外轉成 API 失敗。
- 使用者瀏覽器只提交 QCItemNo 資源識別與 IssueState；FormName 由伺服器讀取，不接受用戶端傳入的 table name、SQL、資料庫連線資訊或任意條件欄位。

## 未涵蓋

- QC Item 主檔刪除與核准/作廢管理屬 QC201，不在 QC204 操作。
- 本規格只涵蓋計數型 SPC 量測記錄；計量型、其他量測表或整個 Lot 的刪除不在此 API 範圍。
- 公司端未執行 build、測試或瀏覽器驗收；Production API/schema 由家用端完成後再回公司端驗收。
