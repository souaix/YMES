## WinForms 主畫面

frmSamplingTable 的 ClientSize 是 1008×591，繼承 frmBasisTemplat。上方共用查詢列的欄位選擇為 SamplingTable、MinNum、MaxNum，輸入值後按 Query 或 Enter 查詢；文字框旁顯示百分比符號。來源 IssueVisable=False，此功能沒有狀態選項、簽核欄或 Approve 按鈕。

主 Grid 位於 (11,51)，設計尺寸 891×507，可多選，依 SamplingTable、MinNum、MaxNum 升冪排列。欄位順序為 SamplingTable、MinNum、MaxNum、SampleNum、RejectNum、Creator、CreateDate、Reviser、ReviseDate；DataStamp 隱藏。數字靠右，日期格式 yyyy/MM/dd HH:mm:ss。

右側按鈕順序及功能：

1. Add：開啟空白定義視窗。
2. Edit：要求選取一列，以三欄複合鍵載入。
3. Delete：多選逐筆刪除；取消確認即停止，第一筆錯誤即停止，已成功筆仍保留，最後重載。
4. Copy：複製目前一列到新定義視窗；SamplingTable、MinNum、MaxNum、SampleNum、RejectNum 全部先帶入，按保存時仍依複合鍵檢查是否重複。
5. CopyTable：另開 frmSamplingTableCopy，來源名稱唯讀、輸入目的名稱；將來源名稱的所有區間複製到目的表，目的端相同 MinNum/MaxNum 已存在時略過，其他區間逐筆新增。
6. Close：關閉功能頁。

複製整張表是順序處理而非單一資料庫交易：Web Service 對每筆呼叫 Add，遇到第一個錯誤即停止，先前成功新增不回滾。

## 定義視窗與資料驗證

frmSamplingTableDef ClientSize 為 484×325；主資料 GroupBox 為 458×185，輸入欄為 KD 黃色。欄位垂直順序是 SamplingTable、MinNum、MaxNum、SampleNum、RejectNum；下方顯示建立者/時間及修改者/時間，底部按鈕依序為 Confirm、Close、Apply。

- SamplingTable 必填、最多 25 字；離開欄位轉大寫。
- MinNum、MaxNum 必填且須為數字；MinNum 不可大於 MaxNum。來源欄位容許 NUMBER(12,4)，表單未限制區間不可重疊，也未限制 MinNum 必須非負。
- SampleNum 必填、非負整數。
- RejectNum 可空；有值時必須為非負整數且不大於 SampleNum；空值寫成 NULL。
- 新增/複製以 (SamplingTable, MinNum, MaxNum) 查重；只有完全相同區間視為重複，不檢查區間交疊。
- 修改模式鎖定三個複合鍵欄位，只能更新 SampleNum、RejectNum。
- Add/Copy 的 Apply 成功後視窗保持開啟，MinNum 自動設為前一 MaxNum + 1，MaxNum 清空；SampleNum/RejectNum 保留，方便連續建立區間。Edit 的 Apply 則保留視窗並可繼續修改。
- 新增由服務設定 Creator/CreateDate，Oracle DataStamp 使用 DEFAULT。修改由 clsBasis_UPD.EditQCSamplingTable 更新 Reviser/ReviseDate、DataStamp + 1，並以舊 DataStamp 限制更新列；複合鍵不變。
- CopyTable 目的名稱必填、轉大寫；來源名稱不可編輯。只複製區間及抽樣/拒收數，建立者與日期改成目前登入者/現在時間，DataStamp 使用 DEFAULT。

## YMES 前端/API handoff

Vue DEV 頁以 localStorage key ymes-dev-mock:qc-sampling-tables:v1 假資料操作；正式環境不讀寫 localStorage。已建立 UI 預期的端點如下，家用端先比對 PostgreSQL live schema/migrations 與既有 API，再實作缺項；不要直接盲跑 CREATE SQL。

- 來源功能識別為 FunctionKey QC101；YMES 依目前使用者決策要求登入，尚未套用 FunctionKey/角色 ACL。此功能沒有 IssueState、簽核或 Issue Job。SQL 一律參數化，更新/刪除使用 DataStamp CAS。
- GET /api/qc/sampling-tables?searchFieldName=SamplingTable&searchFieldValue=：回傳所有抽樣區間及 nullable audit/DataStamp。搜尋欄位白名單為 SamplingTable、MinNum、MaxNum，無狀態過濾。WinForms 將欄位名/值交給共用查詢條件，再由 Core 的 AdditionalXml helper 套用；此頁 DEV 假資料使用大小寫不敏感包含比對，家用端需核對舊 helper 實際比對方式後讓正式 API 一致。依 SamplingTable、MinNum、MaxNum 排序。
- POST /api/qc/sampling-tables body { samplingTable, minNum, maxNum, sampleNum, rejectNum }：校驗 required、長度、數字/整數/RejectNum 上限、MinNum ≤ MaxNum 及複合 PK 唯一。SamplingTable 轉大寫；服務設定 Creator/CreateDate，讓 DataStamp 使用 DEFAULT；RejectNum 空值寫 SQL NULL。
- PUT /api/qc/sampling-tables/{samplingTable}/{minNum}/{maxNum}?dataStamp=&dataStampIsNull= body { sampleNum, rejectNum }：複合鍵不可變；更新兩個數值、Reviser/ReviseDate、DataStamp + 1。若舊 DataStamp 為 NULL，使用 IS NULL CAS；若有值則用相等條件。
- DELETE /api/qc/sampling-tables/{samplingTable}/{minNum}/{maxNum}?dataStamp=&dataStampIsNull=：依複合鍵與 DataStamp CAS 實體刪除。多選由 UI 逐列呼叫，首個失敗即停止並回報已完成筆數。
- POST /api/qc/sampling-tables/copy body { sourceSamplingTable, targetSamplingTable }：讀來源表區間，目的已存在的相同 MinNum/MaxNum 略過，其餘依序插入；建立者/建立時間取當前登入者/伺服器時間，DataStamp 用 DEFAULT。為保持 WinForms 行為，逐筆處理、首錯停止但保留先前成功列；回傳 { insertedCount, skippedCount, error? } 以呈現部分成功。/copy 靜態路由需先於複合鍵路由解析。
- 所有端點只操作 tblqcsamplingtable；沒有 lookup、匯入、匯出、簽核或 FK/cascade 需求。

以上為公司端原始交付契約；目前家用端維護實作與差異見下節，驗證狀態須依實際部署紀錄另記。

## 家用端維護實作（2026-11-18）

### 檔案與資料邊界

- API：`src/YMes.Api/Quality/Qc101Controller.cs`、`Qc101Models.cs`、`Qc101Repository.cs`。Controller 使用既有 `NpgsqlDataSource` 與登入 principal，不需另註冊 Repository；不信任 request 的建立人、修改人、日期或版本初值。
- UI：`web/src/components/QcSamplingTableMaster.vue`。正式模式只呼叫 API；只有明確的 DEV 預覽使用本模組 localStorage，正式 API 失敗不回退假資料。
- 唯一資料表為 `YMES.tblqcsamplingtable`，複合 PK 為 `(samplingtable,minnum,maxnum)`；forward migration 為 `database/migrations/0032_qc101_sampling_table.sql`，依 source CREATE 參照比對建立。此維護段不代表 migration 已套用或 browser 驗收已完成。
- 這是抽樣主檔維護功能，沒有 IssueState/簽核端點，也未實作依 Population 執行的抽樣 engine。

### 正式查詢與版本契約

- GET 回傳原始陣列，不包 `items`。搜尋白名單僅 `SamplingTable`、`MinNum`、`MaxNum`，省略欄位時預設 SamplingTable；未知欄位回 400，SQL 僅使用固定對應表達式及參數值。
- **YMES 明確決策：** 對齊目前 Vue 的大小寫不敏感「文字包含」；`%`、`_` 為一般字元，不作 LIKE 萬用字元。MinNum/MaxNum 以不含多餘尾端小數零的 canonical 數字文字比對，例如 10.0000 用 `10` 搜尋，1.2500 用 `1.25` 搜尋。這不是已證實的 legacy AdditionalXml helper 行為；取得來源 helper 後再比對差異並同步前後端與文件。
- PUT/DELETE 必須明確提供版本查詢：DB NULL 使用 `?dataStampIsNull=true`；數字 0 使用 `?dataStampIsNull=false&dataStamp=0`。省略旗標、false 卻未給數字，或 true 同時給數字，均回 400。NULL 與 0 不互換。
- 修改/刪除先以完整複合鍵 `FOR UPDATE` 鎖定，再精確比對 nullable DataStamp；SQL 使用 `IS NOT DISTINCT FROM @stamp`。版本不符回 409；修改成功用 `COALESCE(datastamp,0)+1`，並由 server 設 Reviser/ReviseDate。回傳完整正式 DTO，新增由資料庫 DEFAULT 提供 DataStamp=0。
- SamplingTable Trim/大寫、長度 1–25；MinNum/MaxNum 為 ±99,999,999.9999 內、最多 4 位小數且 Min≤Max。SampleNum 為 0–99,999,999 整數；RejectNum 可 NULL，有值則為非負整數且≤SampleNum。允許區間重疊，只拒絕完全相同複合鍵；主鍵修改不在 PUT body 中開放。
- 尋找/查重忽略 SamplingTable 大小寫；若既有資料出現僅大小寫不同的重複複合鍵，修改/刪除回 409，不任意選取其中一筆。

### Apply、複製及錯誤處理

- POST/PUT 成功後，Vue 使用 server 回傳 DTO 選回完整複合鍵；Edit Apply 直接更新 source 與 DataStamp，不以其他目前作用列或前端自行加一的假版本替代。
- Vue reactive rows 可能是 Proxy，不能直接以 `structuredClone` 複製。此頁 `clone<T>()` 已改用 JSON round-trip；資料限字串、數字、NULL 等 DTO 值，保留 nullable stamp，避免開啟編輯/複製視窗時出現 DataCloneError。
- Add/Copy Apply 保留來源的連續區間流程：仍是新增/複製模式，以剛保存的 MaxNum+1 作下一筆 MinNum、清空 MaxNum、保留數值。不是將新增一律轉成修改；Copy 原列的 source 會清除，下一筆仍由 server 建新 audit/default 版本。
- 單列 Copy 走 POST；CopyTable 走 `/copy`。整表複製先讀來源區間快照，再逐筆 transaction 插入目的區間；相同目的 MinNum/MaxNum 略過。第一筆失敗即停止，前面成功列保留；HTTP 成功回應中的 `error` 表示部分成功，須同時呈現 `insertedCount`/`skippedCount`，不可當成整批 rollback。
- 刪除使用共用頁內確認窗，預設可取消；多選仍逐筆 CAS，首錯停止且重載已完成結果。API ProblemDetails 取 detail/message/title 顯示；上游 HTML 或過長錯誤改顯示簡潔 HTTP 狀態，短純文字保留，404 不再一律誤報成 API 尚未建立。
- 寫入維護 server audit 欄位並記錄操作、複合鍵、登入者與版本；硬刪除不建立未經來源定義的 cascade 或額外業務表。
