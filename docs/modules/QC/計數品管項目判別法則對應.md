# QC203 計數品管項目判別法則對應

## 功能識別

| 項目 | 內容 |
| --- | --- |
| MES 選單 | 品質資料 → 品管設定 → 計數品管項目判別法則對應 |
| FunctionNo / FunctionKey | QCITEM_A RULE MAP / QC203 |
| WinForms | QC_AttRuleMap.dll：frmQCAttRuleMap、frmQCAttRuleMapDef、frmQCAttRuleMapParameter、frmQCAttRuleMapParameterDef |
| Vue | /YMES/QC/AttributeRuleMap，QcAttributeRuleMapMaster.vue |
| Oracle 主從表 | TBLSPCQCATTRULEMAPBASIS、TBLSPCQCATTRULEMAPDETAIL、TBLSPCQCATTRULEMAPPARAMETER |
| UI 狀態 | Vue DEV 使用獨立 localStorage 假資料；Production 需家用端完成 API/schema 後再驗收 |

## WinForms 畫面與操作

### 主畫面 frmQCAttRuleMap

- 設計尺寸 1008×591，置中開啟。最上方以「…」開啟共用快速查找視窗，來源是 IssueState=2 的計數品管項目。選取後顯示 QCItemNo/QCItemName，並記住該項目的 RuleNo、ComponentCollect 及所有 FactorOnline='Y' 的要因。
- 主畫面四個狀態單選：Unfrozen=0（預設）、Pending=1、Active=2、Unused=-1。清單依選定 QCItemNo 與狀態篩選。
- 主 Grid 隱藏 QCAttSPSerial、IssueState，只顯示目前 QC Item 的線上要因欄、Creator、CreateDate。點選列會即時載入其 Detail 及 Parameter 子資料。
- 右側按鈕為 Add、Edit、Delete、Copy、Approve、Close。Delete 支援多選；狀態 0、-1、2 呼叫刪除服務，狀態 1 不刪除。Approve 按鈕對選取列逐筆呼叫簽核服務。
- 下方 Detail Grid 顯示 RetestLot、PlanNo、LotRuleNo、ComRuleNo；RetestLot=0 顯示 First，其他值顯示重測次數。
- 新增/複製要求先選 QC Item、至少一個 FactorOnline 要因，且 QC Item 的 RuleNo 不可空白。新增的主檔 IssueState=0；複製沿用來源因子值、Detail、Parameter，但產生新的 QCAttSPSerial。

### 編輯視窗 frmQCAttRuleMapDef

- Factor Grid 只顯示該 QC Item 的線上要因；新增/複製可輸入因子值。ParameterType=2 可直接輸入並轉大寫；其他型別經 wsSYS.LoadMESParameterRef 的值清單查找。編輯模式因子值唯讀。
- 每筆 Detail 以 RetestLot 為鍵；0 是首批，正整數是重測批次。可新增、修改、刪除 Detail；修改既有明細時不允許變更 RetestLot。
- ComponentCollect=0 使用已核准一般抽樣計劃 TBLQCSAMPLINGPLAN；其他值使用已核准元件抽樣計劃 TBLQCSAMPLINGPLAN_WAFER。PlanNo 必填。
- LotRuleNo 從已核准 TBLQCATTRULEBASIS 中 ComponentCollect=0 的法則選取；ComRuleNo 選取 ComponentCollect=1 的法則。ComponentCollect=0 時，PlanType=2 的 AQL 計劃可不選 LotRuleNo；其他一般計劃必須選。元件收集模式下 LotRuleNo 與 ComRuleNo 至少設定一項。
- Take Plan Parameter 開啟參數視窗，先由 PlanNo 載入該計劃的 ParameterNo/ParameterValue，再可新增、修改、刪除參數。每一個 RetestLot 至少要有一筆 Parameter；同一 RetestLot 的 ParameterNo 不可重複。
- 儲存前檢查 QCItemNo、每個線上要因值、至少一筆 Detail，以及每筆 Detail 的 PlanNo、法則與參數。新增時要因值空白不會自動當成萬用值；若不限制，應選 *。
- 按「完成」只將明細與參數保存到編輯暫存；最後按 Confirm 才寫資料庫。Close 時若已有明細變更，WinForms 會詢問是否儲存。
- Pending=1 時 ExeIssueControl 將編輯控制項唯讀；Active=2、Unused=-1 的可編輯控制項依 TBLSYSISSUECONTROL 設定，沒有設定即唯讀；Unfrozen=0 可編輯。

### 參數視窗

- frmQCAttRuleMapParameter 管理當前 RetestLot 的參數清單，提供 Add、Edit、Delete、Confirm、Cancel。
- frmQCAttRuleMapParameterDef 以 PlanNo、ParameterNo、ParameterValue 編輯單筆；ParameterNo 可查找，ParameterValue 可由 wsSYS.LoadMESParameterRef 查值。Confirm/Apply/Close 會回寫視窗暫存，最終仍由父表單 Confirm 一次寫入主從資料。

## WinForms Service/Core 與業務邏輯

- 主表清單：LoadQCAttRuleMapBasis(QCItemNo, IssueState)；Detail 與 Parameter 分別由 LoadQCAttRuleMapDetail(QCAttSPSerial)、LoadQCAttRuleMapParameter(QCAttSPSerial) 載入。
- 新增：AddQCAttRuleMapData 取得新的 QCAttSPSerial，新增主表及全部 Detail/Parameter。舊 serial 格式為 SP + 8 位數，透過 TBLSYSSERIALNO.FunctionName='QCAttSPSerial' 遞增。
- 新增重複檢查以 QCItemNo 與目前 QC Item 的全部線上要因值比對；表上不屬於目前項目的其他動態要因欄須為 * 才算相同組合。因子欄位來自 FactorOnline 清單，API 必須白名單驗證，不能把用戶傳入的 FactorNo 直接拼接成欄位名稱。
- 修改：因子不可改；Core 先刪除該序號的所有 Detail/Parameter，再整批重寫，並更新主表 IssueState、Creator、CreateDate。來源沒有 Reviser、ReviseDate 或 DataStamp 欄位；舊 Core 在未提供 CreateDate 時以目前時間重設 CreateDate，Creator 則取表單保留的原值。
- 刪除：WinForms 可刪狀態 0、-1、2，Pending=1 不處理。舊 DelQCAttRuleMapData 刪除 Basis 和 Detail，未刪 TBLSPCQCATTRULEMAPPARAMETER，在沒有 FK 的來源資料庫可能留下孤兒列。YMES API 應在同一交易清理 Basis、Detail、Parameter，這是完整性修正，須在 API handoff 中保留此差異。
- 簽核 IssueNo=QCITEM_A RULE MAP。找不到簽核 Job/Detail 時直接轉 IssueState=2；有簽核流程時先轉 1，核准後 2，退回後 0，並寫事件與通知第一簽核群組。主畫面會對 0 與 -1 呼叫服務，但舊 Service 實際只在傳入狀態 0 時執行簽核；-1 呼叫會回成功但不改狀態。
- 來源表無 DataStamp。API 若不新增 YMES 專用版本欄位，至少要以交易鎖住主檔並完整替換子表；不要虛構 Oracle Reviser/ReviseDate 欄位。

## Oracle DDL 與 YMES 建表參考

- 公司端於 2026-11-17 使用 Windows PowerShell 5.1、既有受保護的 MESTEST 連線設定及 Oracle.ManagedDataAccess 直連資料庫，只查 DBMS_METADATA.GET_DDL、ALL_TABLES 與 index metadata；沒有讀取業務列，也沒有在 Oracle 執行 DDL。連線資料未輸出或寫入 Git。
- Oracle source DDL：database/reference/mestest_qc_attribute_rule_map_source_ddl.sql。同三張表亦已存在於早期 QC DDL 擷取：database/reference/mestest_qc_item_attributes_source_ddl.sql。
- Basis 欄位：QCAttSPSerial VARCHAR2(50) PK、QCItemNo VARCHAR2(25) NOT NULL、Creator VARCHAR2(10)、CreateDate DATE、IssueState NUMBER(1) DEFAULT 0 nullable，以及來源當時已有的動態要因欄位 MO、PRODUCT、EQUIPMENT、PROCESS、MATERIAL、MTLVENDOR、EQPTYPE、EMPLOYEE、SHIFT、OP、VERSION、THICKNESS（各欄 DEFAULT *）。目前來源表另有非唯一索引 I_TBLSPCQCATTRULEMAPBASIS_01(QCITEMNO)。
- Detail 欄位：QCAttSPSerial VARCHAR2(50)、RetestLot NUMBER(2) DEFAULT 0、PlanNo VARCHAR2(25)、LotRuleNo/ComRuleNo VARCHAR2(20)，PK (QCAttSPSerial, RetestLot)。
- Parameter 欄位：QCAttSPSerial VARCHAR2(50)、RetestLot NUMBER(2) DEFAULT 0 NOT NULL、ParameterNo VARCHAR2(20) NOT NULL、ParameterValue VARCHAR2(255)，PK (QCAttSPSerial, RetestLot, ParameterNo)。
- 三表沒有 Oracle FK；Detail、Parameter 不應在 Oracle source DDL 外假設 FK 存在。
- PostgreSQL CREATE 參考：database/reference/mestest_qc_attribute_rule_map_create.sql。Basis 使用 factorvalues JSONB 取代因子動態欄位，並以 (qcitemno, factorvalues) 唯一約束做精確組合防重；額外 serial sequence 是 YMES 建議，套用前必須檢查家用端共用 serial service 與 live schema。此檔不是 migration，不可盲目執行。
- 因子值 JSONB 的 keys 必須等於該 QC Item 已核准的 FactorOnline=Y FactorNo；API options 必須從 QC Item、MES Parameter Reference、已核准抽樣計劃及已核准屬性法則取得，不能把 DEV 範例當正式選項。

## Vue DEV 與 Production API handoff

- DEV 頁保留主畫面四狀態、QC Item 查找、動態要因 Grid、Detail Grid、右側 CRUD/Copy/Delete/Approve，以及編輯視窗的因子、RetestLot、Plan/Rule 選取、抽樣參數設定與 Confirm/Close。假資料與 localStorage key 為 ymes-dev-mock:qc-attribute-rule-map:v1。
- Production 不使用 localStorage。頁面沿用既有 QC201：
  - GET /api/qc/attribute-qc-items?issueState=2
  - GET /api/qc/attribute-qc-items/{qcItemNo}/factors?factorOnline=Y
- 家用端新增下列 API，全部檢查登入、QC203 功能權限、參數長度、狀態及交易完整性；SQL 參數化。完整替換明細時，必須保留一個交易邊界。
  1. GET /api/qc/attribute-rule-maps?qcItemNo=&issueState=：回傳主 Grid 所需欄位與 factorValues，另回傳 canEdit（依 ExeIssueControl/TBLSYSISSUECONTROL 計算）供表單唯讀判斷。
  2. GET /api/qc/attribute-rule-maps/{qcAttSpSerial}：回傳 { basis, details, parameters }，明細依 RetestLot 排序。
  3. GET /api/qc/attribute-rule-maps/options?qcItemNo=：回傳 QCItem RuleNo、ComponentCollect、已核准屬性法則、一般/元件抽樣計劃、MES Parameter Reference 因子選項，以及 { planNo: [{ parameterNo, parameterValue }] } 抽樣參數。
  4. POST /api/qc/attribute-rule-maps：body { qcItemNo, factorValues, details, parameters }；伺服器產生 SP########、強制 IssueState=0，白名單驗證線上因子，檢查與所有既有狀態資料的組合重複，再原子新增三表。
  5. PUT /api/qc/attribute-rule-maps/{qcAttSpSerial}：request body 僅含 details/parameters；因子鍵值唯讀，驗證 IssueState/TBLSYSISSUECONTROL 權限，交易內完整替換子列並保留來源狀態。來源 Core 修改會重設 CreateDate、保留原 Creator；若 API 採伺服器 audit 改寫，需在部署文件明確標示差異。
  6. DELETE /api/qc/attribute-rule-maps/{qcAttSpSerial}?issueState=：來源只接受狀態 0、-1、2；阻擋狀態 1。YMES 同一交易刪除 basis、detail、parameter，回傳單筆結果；Vue 多選逐筆呼叫並回報已成功筆數。
  7. POST /api/qc/attribute-rule-maps/{qcAttSpSerial}/approve?issueState=：使用共用 Issue/Job 簽核流程與 IssueNo QCITEM_A RULE MAP；不可在 Production 直接把狀態設為 2。來源對 IssueState=-1 的簽核呼叫是成功 no-op，API 應拒絕或明確回報未變更，不可回報已核准。
- 建議以既有 YMES sequence service 產生 serial；若需新增 PostgreSQL sequence，先核對既有 SP######## 最大值與其他功能共用規則，不可無條件從 1 開始。
- WinForms 的值查找視窗在 Vue DEV 以 API options 下拉選單承接；實際值清單和計劃參數由 Production API 提供。此項為互動外觀簡化，資料規則不簡化。
