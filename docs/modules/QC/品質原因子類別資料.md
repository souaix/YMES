## WinForms 清單畫面

- 主表單為 1008×591。上方沿用共用查詢與 IssueState 狀態列，預設選「未簽核」；狀態為 0/1/2/-1，分別代表未簽核、簽核中、已簽核、不使用。
- 查詢欄位只設定 `ReasonSubType`，清單依 `ReasonSubType` 排序。WinForms 先載入全部狀態，再在前端套用狀態篩選。共用查詢控制項顯示 `%` 比對提示；正式 API 應維持此欄位的舊查詢語意。
- Grid 可見欄位順序為 `ReasonType`（透過 ValueList 顯示文字）、`ReasonSubType`、`ReasonSubTypeName`、`Description`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`。欄位皆不可直接在 Grid 編輯；IssueState、DataStamp 和原始 ReasonType 數值不顯示。
- 右側直排按鈕為新增、修改、刪除、複製、核准；底部右側為關閉。來源 Form 沒有獨立「檢視」、匯入、Download 或 Print 按鈕。
- `ReasonType` 清單來自 `ValueListProvider.GetValueList("tblQCReasonSubTypeBasis", "ReasonType", True)`，並用 ValueList 將數值顯示成文字。來源程式的舊註解列出過不同版本的代碼，不能視為完整、現行選項；正式值必須由 YMES API 提供。DEV 選項僅以舊註解示例製作，均標示 DEMO。

## 新增／修改視窗與驗證

- 編輯窗為 484×326，包含 `Reason Type` 下拉、`ReasonSubType`、`ReasonSubType Name`、`Description` 及建立／修改者、日期欄位；沿用 WinForms 淡黃色必填欄位。視窗提供確定、關閉、套用。
- 新增與複製時 `ReasonType`、`ReasonSubType`、`ReasonSubTypeName` 必填。ReasonSubType 和名稱離開欄位時轉大寫；依 Oracle 欄位長度，ReasonSubType 最長 50、ReasonSubTypeName 最長 100、Description 最長 255。
- 修改時 ReasonSubType 唯讀，ReasonType、名稱、說明可依 Issue Control 設定編輯。簽核中（狀態 1）所有欄位唯讀；已簽核／不使用資料依共用 Issue Control 設定的 EditFlag 開放欄位。若正式 API 無法取得該設定，應採唯讀，不得自行假定可編輯。
- 複製會先帶入來源的類別、編號、名稱、說明，並以新增服務建立狀態 0 的新列；使用者需改成唯一的新 ReasonSubType。套用會儲存但留在視窗；確定儲存後關閉。
- 新增由服務設定 IssueState=0，Creator/CreateDate 使用登入者與伺服器時間。修改保留主鍵並更新 Reviser/ReviseDate；來源 DataStamp 可為 NULL，並由更新流程遞增與檢查。

## 按鈕與狀態邏輯

- 清單預設未簽核；單筆修改／複製以目前作用列為準，刪除／核准可多選。作業逐筆呼叫服務，遇第一筆失敗即停止；此前已成功的項目不回復，完成後重新載入清單。
- 刪除狀態 0 或 -1 為實體刪除；狀態 2 改為 -1，並更新修改者、修改日期及 DataStamp；狀態 1 不允許刪除。
- 核准只接受狀態 0。Service 查找 Issue Job Map `ReasonSubType BASIS`：沒有 Job 或 Job 沒有 Detail 時直接改成狀態 2；有簽核明細時建立 Issue 流程，改成狀態 1，通知第一簽核群組；後續核准改成 2、退回回到 0。
- 清單採客戶端狀態篩選；切換狀態後原選取列清空。修改／刪除／核准均應以 DataStamp 做併發檢查，並保留舊系統對 NULL DataStamp 的處理語意。

## Oracle 欄位與限制

Oracle 原始 DDL 由公司端使用 Windows PowerShell 5.1、Oracle.ManagedDataAccess 與本機受保護連線唯讀取得；只讀取資料字典／DDL，未讀取 MES 業務資料，也未在 Oracle 執行 DDL。

| 欄位 | Oracle 型別 | NULL / 預設 | 用途 |
| --- | --- | --- | --- |
| ReasonType | NUMBER(1,0) | NULL | ValueList 類別代碼 |
| ReasonSubType | VARCHAR2(50) | NOT NULL | 主鍵 |
| ReasonSubTypeName | VARCHAR2(100) | NULL | 顯示名稱；WinForms 必填 |
| Description | VARCHAR2(255) | NULL | 說明 |
| Creator | VARCHAR2(10) | NULL | 建立者 |
| CreateDate | DATE | NULL | 建立日期 |
| IssueState | NUMBER(1,0) | NOT NULL DEFAULT 0 | 簽核狀態 |
| DataStamp | NUMBER(11,0) | NULL DEFAULT 0 | 併發版本 |
| Reviser | VARCHAR2(10) | NULL | 修改者 |
| ReviseDate | DATE | NULL | 修改日期 |

唯一索引只有 `PK_TBLQCREASONSUBTYPEBASIS`，對應主鍵 `(ReasonSubType)`；沒有外鍵或額外索引。來源 DDL：[`mestest_qc_reason_subtype_basis_source_ddl.sql`](../../../database/reference/mestest_qc_reason_subtype_basis_source_ddl.sql)；YMES PostgreSQL 空表 CREATE 參考：[`mestest_qc_reason_subtype_basis_create.sql`](../../../database/reference/mestest_qc_reason_subtype_basis_create.sql)。家用端先比對 YMES live schema 與既有資料，再決定是否需要 forward migration；不得 drop/recreate 現存表。

## Vue DEV 頁與 API 契約

公司端 Vue 頁以 localStorage 中標示 `DEV` 的假資料示範四種狀態、ReasonSubType 查詢、單選／多選、CRUD、複製、直接核准、刪除／停用及稽核欄位。API 尚待家用端完成；正式環境不使用假資料。

建議 API 全部要求登入並檢查 FunctionKey `QC105`，使用參數化 SQL，將登入者與伺服器時間作為 audit：

- `GET /api/qc/reason-subtypes?searchFieldName=ReasonSubType&searchFieldValue=`：只接受 ReasonSubType 查詢，保留舊查詢值中的 `%`／`_` LIKE 萬用字元語意；回傳四狀態所有欄位、DataStamp 及伺服器計算的 `editableFields`。清單狀態由 UI 篩選。
- `GET /api/qc/reason-subtypes/reason-types`：回傳舊 ValueList 對應的 `{ value, label }` 選項；此靜態路由需優先於 `/{reasonSubType}`。不得把 DEV 註解示例當正式 ValueList。
- `POST /api/qc/reason-subtypes`：接收 `{ reasonType, reasonSubType, reasonSubTypeName, description }`；驗證必填、長度、ReasonType 有效性及主鍵唯一，將鍵值與名稱轉大寫，設定狀態 0、Creator/CreateDate、DataStamp 預設值。重複鍵回 409。
- `PUT /api/qc/reason-subtypes/{reasonSubType}?issueState=&dataStamp=`：接收 `{ reasonType, reasonSubTypeName, description }`；主鍵唯讀。僅依 `frmReasonSubTypeDef` 對應的 Issue Control EditFlag 更新允許欄位；狀態 1 拒絕。更新 Reviser/ReviseDate，對 nullable DataStamp 做 compare-and-swap，衝突回 409。
- `DELETE /api/qc/reason-subtypes/{reasonSubType}?issueState=&dataStamp=`：狀態 0/-1 實體刪除；狀態 2 原子更新為 -1；狀態 1 拒絕。更新需做 DataStamp 檢查。
- `POST /api/qc/reason-subtypes/{reasonSubType}/approve?issueState=0&dataStamp=`：只接受狀態 0，按 Issue Job Map `ReasonSubType BASIS` 執行直接核准或建立 Issue/通知首簽核群組；回傳實際狀態及最新 DataStamp。
