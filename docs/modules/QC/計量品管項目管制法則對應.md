# 計量品管項目管制法則對應（QC209）

## 功能識別與來源

- FunctionNo：`QCITEM RULE MAP`
- FunctionKey：`QC209`
- 選單：品質資料 → 品管設定 → 計量品管項目管制法則對應
- WinForms：`STD/MESWin/QC/QC_ItemRule/frmQCItemRule.vb`、`frmQCItemRuleDef.vb`
- Service：`STD/MESws_STD/wsSTD/wsQC/wsQC.cs`，方法 `LoadQCItemForVariables`、`LoadQCItemRule`、`LoadQCRule`、`UpdQCItemRule`
- Core：`STD/MESkc/kcQC/clsQCBasis.cs`，對應上述 Load/Update 方法
- 本規格依標準 `QC_ItemRule.dll` 原始碼整理；此項目沒有另外找到 THEIL BU1 客製 Form。

## 主畫面（frmQCItemRule）

WinForms ClientSize 為 1008×591。上方列顯示唯讀 QCItemNo/QCItemName 與 `...` 查詢按鈕。查詢呼叫 `LoadQCItemForVariables`，service 預設 IssueState=2，因此清單只含已核准計量品管項目。選取 QC Item 後呼叫 `LoadQCItemRule(QCItemNo)`，結果依 SPCID/RuleNo 顯示在 Grid。

Grid 顯示欄位依序為 SPCID、RuleNo、Action、RuleName。SPCID 對照：0 Trend Chart、1 Xbar Chart、2 R Chart、3 S Chart、4 Rm Chart；Action 對照：0 Warning、1 Wait、2 Hold、3 Alert。RuleName 由 `TBLQCRULEBASIS` LEFT JOIN 取得，法則資料已刪除時名稱可為空。右側 `SET (&S)` 開啟設定視窗；`Close (&X)` 關閉頁面。

## 設定視窗（frmQCItemRuleDef）

ClientSize 為 644×681。上方顯示唯讀 QCItemNo/QCItemName 與 SPCID 下拉選單。ChartType 限制可選 SPCID：

| 計量 QC Item ChartType | 可選 SPCID |
| --- | --- |
| 0（Xbar-R） | 0 Trend、1 Xbar、2 R |
| 1（Xbar-S） | 0 Trend、1 Xbar、3 S |
| 2（X-Rm） | 0 Trend、4 Rm |
| 其他/null | 沒有可選 SPCID |

下方是五個清單：左側 Unselected Rule，右側依序 Warning、Wait、Hold、Alert。每個動作區有 Rule 多選清單及唯讀 Description；左右箭頭可將多筆法則加入指定動作或移回 Unselected。已選項目載入 `RuleNo (RuleName)` 顯示字串，清單選取時顯示 Description。所有候選規則只載入 IssueState=2 的 `TBLQCRULEBASIS`。既有對應即使找不到目前核准的 Rule Basis，也會留在原 Action 清單，避免編輯其他法則時被 UI 丟棄。

企業 `SPK` 會停用 Wait 標題、清單與移動按鈕；其他企業可使用 Wait。Confirm 完整保存目前 QCItemNo + SPCID 的四個分類並關閉；Apply 完整保存後留在視窗；Close 直接關閉、不保存目前尚未 Apply 的變更。切換 SPCID 會重新載入該 SPCID 的設定；來源 WinForms 未提醒尚未 Apply 的變更，本 Web UI 在切換前提示，確認後捨棄該 SPCID 草稿。

## 資料邏輯

1. 主畫面選取有效計量 QC Item 後，載入該 QCItem 所有 SPCID 的 `TBLQCITEMRULE` 對應。
2. 開啟設定時依 `ChartType` 建立可選 SPCID；預設第一個可用 SPCID。切換 SPCID 時顯示該組既有 Action 分類。
3. 可選規則來源是 `TBLQCRULEBASIS` IssueState=2。依 RuleNo 將目前所選 SPCID 的規則分入四種 Action，其餘列在 Unselected。
4. Confirm/Apply 不是逐筆新增或刪除：WinForms `UpdQCItemRule` 先刪除此 QCItemNo + SPCID 的所有 `TBLQCITEMRULE` 列，再依四個清單重建整組 `(RuleNo, Action)`。Core 將 delete 與 inserts 一起交給 `ExecuteSQLNoneQuery_UPD`。
5. 舊 Core 只寫 QCItemNo、SPCID、RuleNo、Action。`TBLQCITEMRULE` 的 EquipmentState、ERFState、EmailState 其他欄位不在此表單維護；整組重寫時來源程式未傳入這些值，會成為 NULL。不要在文件中誤稱 QC209 表單會維護這三欄。
6. WinForms 沒有 Rule 對應獨立刪除按鈕、核准流程、IssueState 或 DataStamp；刪除/移出是把整組草稿重寫。主 QC Item 與候選 QCRule 是已核准資料。
7. 新增對應要避免同一 QCItemNo + SPCID 下同一 RuleNo 出現在多個 Action；API 以複合主鍵及 transaction 維持整組一致。`TBLQCITEMRULE.RULENO` 是 VARCHAR2(20)，雖 QCRuleBasis.RuleNo 可長 30，超過 20 字元的法則在來源儲存時會失敗；API 應於保存時回傳可讀的長度錯誤。

- `TBLQCITEMRULE` Oracle DDL/PK 已存在 `database/reference/mestest_qc205_variable_dependencies_source_ddl.sql`；該檔由公司端 PowerShell 5.1 + Oracle.ManagedDataAccess 直連 MESTEST、唯讀 DBMS_METADATA/字典取得，不使用 DBeaver 螢幕、不查業務列、不執行 Oracle DDL。
- `TBLQCRULEBASIS` Oracle source 與 PostgreSQL Create 參考分別在 `database/reference/mestest_qc_variable_rule_basis_source_ddl.sql`、`mestest_qc_variable_rule_basis_create.sql`，由先前 QC108 來源查詢取得。
- QC Item 主表與 ChartType 來源參考 `mestest_mtl_qc_item_tables_source_ddl.sql`、`mestest_mtl_qc_item_tables_create.sql`。
- 本頁唯一新增的 PostgreSQL Create 參考是 `database/reference/mestest_qc209_variable_item_rule_map_create.sql`。Oracle `TBLQCITEMRULE` 沒有 FK；Create 保留 PK `(QCItemNo,SPCID,RuleNo)` 與三個來源選擇欄位，不加外鍵。家用端須先查 YMES live schema/migration；表若已存在則不得重建或覆蓋資料。

## YMES API handoff

- `GET /api/qc/variable-qc-items?issueState=2`：沿用 QC205 已定義的 QC Item 清單，lookup 至少含 QCItemNo、QCItemName、ChartType、IssueState。
- `GET /api/qc/rule-bases`：沿用 QC108 法則主檔 API；QC209 只使用 IssueState=2 候選，但已存在的未核准/刪除法則對應仍需在 assigned lists 回傳以便保留。
- `GET /api/qc/variable-item-rules/options`：回傳 `waitEnabled`（依伺服器企業設定；SPK=false）。
- `GET /api/qc/variable-item-rules/{qcItemNo}`：回傳所有 SPCID 對應列及可用 RuleName，排序建議 SPCID、Action、RuleNo。
- `PUT /api/qc/variable-item-rules/{qcItemNo}/{spcId}` body `{rules:[{ruleNo,action}]}`：完整替換該 QCItemNo + SPCID 的對應，Action 限 0..3、SPCID 必須符合 QC Item ChartType；transaction 內重查已核准 QC Item、SPCID 與新增 RuleNo 狀態，並驗證 RuleNo 不重複。保留既有但已非核准的對應列，除非使用者明確將其移出清單。遵循舊核心完整重寫語義，EquipmentState/ERFState/EmailState 按來源行為為 NULL。
- 所有 endpoint 驗證登入及 FunctionKey `QC209`，沿用參數化 SQL 與共用 API 錯誤格式。核心替換須單一資料庫交易，避免先刪除後部分插入造成空/半套設定。

## 頁面實作狀態

- Vue 3 DEV 頁：`/YMES/QC/VariableItemRuleMap`，已接三層選單。
- DEV 頁使用獨立 localStorage 假資料，模擬核准計量 QC Item、已核准法則、SPCID/Action 對應、查詢、四分類多選移動、Confirm/Apply。
- Production API 尚待家用端依上方契約實作；本頁尚未執行 build、測試或瀏覽器驗收。
