- MES 選單：品質資料 → 異常設定 → 次分類基本資料。
- 目錄資料：FunctionNo `SCLASS BASIS`、FunctionKey `QC402`、Form `frmSClassBasis`、ExecutionFile `QC_SClassBasis.dll`；資料表 `MESTEST.TBLQCSCLASSBASIS`。
- WinForms：`STD/MESWin/QC/QC_SClassBasis/frmSClassBasis.vb`、`frmSClassBasisDef.vb`。
- 獨立匯入視窗：`STD/MESWin/QC/QC_SClassDataImport/frmSClassDataImport.vb`；檢查器 `STD/MEStc/DataImporter/SClassDataImporter.cs`。

- 規則根據 WinForms、Service、Core、Importer 原始碼與公司端 Oracle 資料字典查詢結果整理。

## 主清單畫面

- WinForms `frmSClassBasis` ClientSize 為 1008×591。上方沿用共用狀態列：未簽核 0、簽核中 1、已簽核 2、不使用 -1，初始選未簽核。
- 查詢條件只有 SClassNo；主表 Service 載入所有狀態，WinForms 於本機套用狀態篩選，依 SClassNo 排序。
- Grid 顯示 SClassNo、MClassNo、Description、Creator、CreateDate、Reviser、ReviseDate；MClassNo 顯示位置緊接 SClassNo。IssueState、DataStamp 隱藏。Description 多行/寬 150；人員欄寬 80；日期欄寬 150，格式 `yyyy/MM/dd HH:mm:ss`。
- 操作按鈕為新增、修改、刪除、複製、核准；右下另有 `SClassImport` 與關閉。主清單支援多選，刪除及核准逐筆呼叫 Service；第一筆失敗即停止並重載資料。
- Vue DEV 頁 `/YMES/QC/SClassBasis` 對照四狀態、SClassNo 查詢、含 MClassNo 的主 Grid、多選、同一組操作鈕、匯入與筆數。列點選只更新 Vue 狀態，不改 URL、不重新載入頁面。標頭和輸入欄採 KD 黃色系。

## 新增、修改、複製表單

- `frmSClassBasisDef` ClientSize 為 484×312。SClassNo 區塊位於 (12,6)，尺寸 460×50；MClassNo 與說明區塊位於 (12,61)，尺寸 460×119；建立/修改資訊位於 (12,188)，尺寸 460×70。底部按鈕為確定、關閉、套用。
- SClassNo 必填、最多 30 字；MClassNo 必填、最多 30 字，但欄位唯讀，透過 `...` 搜尋選取；候選 MClass 必須已簽核。Description 可空、最多 255 字。
- 新增與複製預設 IssueState=0，建立者/時間顯示目前使用者/現在時間。複製會帶入原 SClassNo、MClassNo、Description，作為新增處理，使用者需改成新的 SClassNo。
- 修改時 SClassNo 唯讀；MClassNo 欄位本身唯讀，但旁邊查找按鈕會依 `ExeIssueControl` 權限/狀態啟用。Service/Core 接受 MClassNo 與 Description 的更新；只有 IssueState 0/2 可寫入。簽核中與不使用列以唯讀方式呈現。
- 確定儲存後關閉；套用保存後保留視窗。資料表 Create/Revise audit 與 DataStamp 由 API 依登入者/伺服器時間維護。
- YMES 的新增／複製按套用成功後會切為修改，使用剛保存列的主鍵、伺服器 DataStamp 與 audit 繼續編輯，避免相同編號再次新增；這是 YMES 對來源新增模式的調整。

## 狀態及操作規則

- 刪除前顯示確認。IssueState 0、-1：實體刪除；2：保留資料列並改為 -1，更新 Reviser、ReviseDate、DataStamp；1：拒絕刪除。
- 核准只接受 IssueState=0，可多選逐筆處理。Issue Job Map 使用 `SCLASS BASIS`：找不到 Job 或沒有 Job Detail 時直接核准為 2；有簽核設定則建立 Issue、進入簽核中，核准後轉 2、退回轉回 0，並通知第一簽核群組。
- 更新與狀態異動以 SClassNo、IssueState、DataStamp 做樂觀版本檢查；Production API 衝突應回 409，不可接受前端送來的 audit 欄位。
- DEV 核准目前只演示無 Job 的 0→2 分支；正式 Issue Job/Issue/通知/退回必須由 API 串接共用簽核機制。

| 欄位 | Oracle 型別 | Nullable / 預設 | 備註 |
| --- | --- | --- | --- |
| SClassNo | VARCHAR2(30) | NOT NULL | Primary Key |
| Description | VARCHAR2(255) | NULL | 說明 |
| Creator | VARCHAR2(10) | NULL | 建立人 |
| CreateDate | DATE | NULL | 建立時間 |
| IssueState | NUMBER(1,0) | NOT NULL DEFAULT 0 | 簽核狀態 |

## 次分類資料匯入

- 主清單用 ObjectFileHandler 開啟 `QC_SClassDataImport`。匯入 UI/檢查器為 `frmSClassDataImport` 與 `SClassDataImporter.SClassDataChecker`。
- 支援 `.xls`、`.xlsx`，讀第一個工作表；略過第一列，不驗證標題文字。第 1 欄 SClassNo 必填、第 2 欄 MClassNo 必填、第 3 欄 Description 可空；第 4 欄起不讀。公式會求值，數值/日期轉成字串。缺少任一必填 cell 時 Excel 解析即失敗。
- 選檔預覽以 `(SClassNo, MClassNo)` distinct，結果 Grid 顯示 SClassNo、MClassNo、Description、Message。實際匯入會把原始資料依 SClassNo 分組；每組資料超過一列時整組回報 duplicate data，因此相同 SClassNo 即使 MClassNo/Description 相同也可能在 preview 摺疊、匯入時失敗。不同 SClassNo 各自執行，可部分成功。
- Checker 以大小寫不敏感方式拒絕已存在 SClassNo；MClassNo 必須存在且 IssueState=2。成功新增時 SClassNo/MClassNo 轉大寫、IssueState=0、Creator 使用登入者、Description 空白時由 Core 略過欄位寫入。每筆 SClassNo 回傳 Message；可取消後續列，完成後若有成功列則重載主畫面。
- 範本副檔名透過 `wsSYS.funLoadFileExtension`，範本二進位透過 `wsSYS.GetTemplateFile`，FunctionNo 為 `SCLASS BASIS`；範本更新按鈕隱藏。來源樹沒有找到範本 binary，Production 需遷移 SYS template storage。DEV 下載 CSV 只供假資料操作，不能當作官方 Excel 範本。

## YMES API 契約（家用端已實作，正式操作驗證待完成）

- `GET /api/qc/s-class-basis?searchFieldName=SClassNo&searchFieldValue=`：查全部狀態，僅接受 SClassNo 搜尋；回傳主鍵、MClassNo、Description、IssueState、DataStamp 與 audit 欄位。
- `GET /api/qc/s-class-basis/m-class-options`：同一已登入 QC402 API 回傳 IssueState=2 的 MClassNo/Description lookup，避免另外呼叫 QC401 路由；不新增 lookup table。靜態子路由優先於 `/{sClassNo}` 解析。
- `GET /api/qc/s-class-basis/{sClassNo}`：載入單筆完整 DTO，資料不存在回 404。
- `POST /api/qc/s-class-basis` body `{ sClassNo, mClassNo, description }`：兩編號必填/最多 30 字；Description 最多 255 字；SClassNo 大小寫不敏感唯一；MClassNo 必須存在且已簽核。伺服器設定 Creator/CreateDate、IssueState=0。
- `PUT /api/qc/s-class-basis/{sClassNo}?issueState=&dataStamp=` body `{ mClassNo, description }`：SClassNo 唯讀；只允許 IssueState 0/2；MClassNo 必須是已簽核主分類；更新 Reviser/ReviseDate/DataStamp，使用精確 nullable CAS。
- `DELETE /api/qc/s-class-basis/{sClassNo}?issueState=&dataStamp=`：0/-1 實體刪除、2 改為 -1 並更新 audit/DataStamp、1 拒絕。
- `POST /api/qc/s-class-basis/{sClassNo}/approve?issueState=0&dataStamp=`：重新確認主分類已簽核；沒有已知 Issue/Job 表時直接轉 2，若偵測到流程表則回 503、資料不變，待接入共用簽核服務。
- `POST /api/qc/s-class-basis/import/preview` 及 `/import` 接受 `.xls/.xlsx` multipart file；第一 sheet/前三欄解析、distinct preview、按 SClassNo 分組並拒絕多列組、驗已核准 MClass、每組交易與逐組部分成功結果必須依來源碼實作。支援取消後續處理。
- `GET /api/qc/s-class-basis/import/template`：提供 YMES 自有固定表頭 `.xlsx`，已登入時回 200，檔名 `YMES-SClassBasis.xlsx`；原始 `SCLASS BASIS` binary 與 SYS template storage 尚未遷移，兩者差異見下節。
- 全部端點要求登入。FunctionNo=`SCLASS BASIS`、FunctionKey=`QC402` 保留為功能識別；依使用者先不處理角色／權限的決策，本輪未加入 FunctionKey ACL。使用參數化 SQL、檔案大小/格式限制與 DataStamp CAS，API 不接受前端指定 Creator、CreateDate、Reviser、ReviseDate 或核准結果。

清單、lookup、preview、import 都回傳原始 JSON 陣列，CRUD／approve 回傳真實單筆 DTO。DTO 使用 camelCase，含 `sClassNo`、nullable `mClassNo`／`description`、`issueState`、nullable `dataStamp` 與完整 audit。PUT、DELETE、approve 必須提供 `issueState` 及 `dataStamp` query：版本 NULL 要明確傳 `dataStamp=`，省略版本參數回 400；NULL 只匹配資料庫 NULL，不等同 0。資料不存在回 404，狀態／版本衝突回 409，缺表或一般資料庫操作失敗回 503；Vue 顯示 ProblemDetails 的中文 detail，不顯示 JSON 物件字串。

DEV 頁元件為 `web/src/components/QcSClassBasisMaster.vue`，localStorage key `ymes-dev-mock:qc-s-class-basis:v1`，只在 DEV 且明確開啟 developmentPreview 時使用。Production 頁不使用 localStorage。以上前段 Oracle／DEV 交付是公司端來源紀錄；家用端 API 實作與限制如下。

## 家用端實作與維護（2026-11-18）

- API 檔案為 `src/YMes.Api/Quality/Qc402Controller.cs`、`Qc402Models.cs`、`Qc402Repository.cs`。主表固定為 `"YMES".tblqcsclassbasis`；主分類候選重用 `"YMES".tblqcmclassbasis`，不新增 lookup table，也不複製 QC401 路由。資料表建立、live 權限、備份與部署由家用端主流程核對，本節不將公司端 CREATE 參考檔當成已套用 migration。
- 新增、修改、核准保存前，以 `FOR SHARE` 重新鎖定並驗證主分類為已簽核，和 QC401 對主分類的列鎖協調，避免主分類同時被刪除／停用。既有主分類若有大小寫不同的重複編號會拒絕寫入；SClassNo 新值轉大寫並作大小寫不敏感的重複檢查，DB PK 保護同鍵併發新增。
- 修改／刪除／核准每筆獨立交易，先 `FOR UPDATE` 讀最新主檔，再核對 IssueState 和 nullable DataStamp；SQL 使用 `IS NOT DISTINCT FROM` CAS，更新後版本遞增。建立／修改人員來自登入 principal，時間由 server 產生，不接受請求覆寫 audit。狀態 0/2 可修改；1/-1 只讀；刪除 2→-1、0/-1 實體刪除、1 拒絕。
- 實體刪除只檢查已核實的 `tblqcholditembasis.sclassno` 引用（該表存在時），有引用回 409；不自行 cascade 到 QC/WIP。之後加入引用此表的 child writer 時，須在指派 SClass 時對次分類列使用 `FOR SHARE`，與此刪除列鎖協調；來源沒有 FK，因此不能只靠一次查詢取代所有寫入端的協調。
- Vue 刪除、核准與匯入使用共用站內確認視窗，取消不送出寫入。修改、選取只使用當前狀態的可見列；儲存採 API 回傳 DTO 保留精確版本與 audit。新增／複製 Apply 切為修改；成功新增會清搜尋、切到未簽核並選取新列。批次刪除／核准途中失敗會重載清單，保留錯誤，之前成功的單筆交易不回滾。

### 正式 Excel 匯入

- 使用既有 ExcelDataReader 實際解析 `.xls/.xlsx`，不以假資料回應正式端。第一個 sheet、略過標題、固定前兩欄必填／第三欄可空、其餘欄忽略；任一資料列缺必要 cell（包括讀到的整空白列）會在 preview／解析階段拒絕整個檔案。標題文字不作驗證。
- Preview 依大小寫不敏感的 `(SClassNo, MClassNo)` 去重，Description 不參與去重；實際 Import 重讀原始檔並按 SClassNo 分組。原始組超過一列即整組失敗，即使 preview 曾摺疊成一筆仍會拒絕。每個 SClassNo 各自交易，鍵／長度／主分類不合法只影響該組並繼續其他組。
- 檔案上限 5 MiB、資料列最多 10,000；xlsx 解壓內容上限 64 MiB、最多 2,048 個 archive entries。無效／加密／無法讀取的檔案回明確 400。數值採 invariant 字串，日期採 `yyyy/MM/dd HH:mm:ss`。
- 和來源即時計算公式的差異：目前讀取 Excel 檔案已儲存的 formula cached value，不執行公式重新計算。含公式的匯入檔須先由 Excel 計算並存檔；不能將此能力描述為與來源公式 evaluator 完全相同。
- 每筆結果格式 `{ sClassNo, mClassNo, description, result: "success"|"fail", message }`。資料錯誤各組回 fail；若中途遇 DB／503，保留之前 success、回傳當筆錯誤，後續組以 fail 加「尚未處理」標記後停止。資料庫連線或 commit 中斷時當筆結果可能無法確認，訊息會要求重查，不偽稱已回滾。已解析檔案的這類部分結果仍以 HTTP 200 陣列回傳，不能把整個請求當全批失敗後直接重試。
- 取消旗標在各組之間檢查，尚未處理的組標記取消；Vue 以 AbortController 中止等待，已提交列不會回滾，也不能保證伺服器立即停止或瀏覽器收到最後結果。取消／網路失敗後仍會重查目前查詢範圍的主清單；無完整結果時預覽列標示「結果未確認，請重查」，不假稱尚未處理或整批回滾。此處沒有背景匯入工作或結果重取機制，重查後仍可能有稍晚提交，應核對再決定重試。
- Vue 保留已收到的逐筆結果；所有匯入結束路徑皆重新查詢主清單，收到完整結果時才列成功／失敗或未處理數。重查失敗保留結果、未知狀態及實際錯誤，不回退上次成功訊息。正式下載改提供 YMES 自有 `.xlsx` 範本；DEV CSV 僅供本機假資料流程，正式選檔僅接受 `.xls/.xlsx`，DEV CSV 說明只在 mock 預覽顯示。
