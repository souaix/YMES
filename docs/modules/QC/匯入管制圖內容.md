## WinForms 畫面與操作

表單初始 ClientSize 為 784×561，`WindowState=Maximized`，標題 `Import QC Chart Basis`。左上為 `Defined Format To:` 勾選框與 1–13 的 NumericUpDown（預設 1、未勾選時停用）；左側 UltraGrid 從 x=10、y=36 起，初始大小 678×515。右側固定按鈕為 `File`、`Save`、`Template DownLoad`、`Close`，大小約 80×32。Grid 的 `Execute` 欄固定在第一欄，寬 50；Excel 資料欄與匯入後回填的 `FactorSerial` 其餘顯示。表單沒有 Check、Select 或勾選匯入按鈕。

Grid 綁定 DataTable，來源沒有將欄位設成唯讀；可修改列資料並刪除整列。刪列後呼叫 `AcceptChanges`。按 Save 一次會送出目前全部列；Service 整體回應成功後本表單標記已執行，再按 Save 會提示另選檔案。每列的結果仍在 `Execute` 欄回報；因此 HTTP/Service 整體成功不代表每列都成功。

## Excel 解析、範本與數值格式

- File 對話框只列 `.xls`，讀第一個工作表。第 1 列為欄名，資料從零起始索引 2（Excel 第 3 列）開始；遇到第一個全空白列即停止。欄名間若存在空洞會報 `Column name not found`；空欄名轉為 `unknow{欄位索引}`。讀入後附加 `Execute` 與 `FactorSerial` 欄。
- Template FunctionNo=`IMPORT QC CHART DATA`，檔名 `QCChart_Template`；副檔名由 `wsSYS.funLoadFileExtension` 決定 `.xls` 或 `.xlsx`。下載完成後舊 WinForms 會開啟檔案。
- Defined Format 勾選後，將符合舊規則的數值欄轉成指定小數位數：`CL`、`Target`、`CPKGoal`、包含 `YAxis` 的欄位、三字元且尾碼為 `US/CL/LS` 的欄位、四字元且尾碼為 `LCL/UCL` 的欄位。零值依所選位數格式化，例如預設 1 位為 `0.0`。其餘欄不改格式。
- 可辨識資料欄：`QCItemNo`、`SampleSize`、`Creator`、`CreateDate`、`ChartTitle`、`KeyNode`、`Sponsor`、`PlanNo`、`ChartUnit`、`MEMO`；管制值欄 `TUS/TCS/TLS`、`UCL/CL/LCL`、`Target`、`CPKGoal`、`TYAxisTo/TYAxisFrom`；`XUS/XCS/XLS/XUCL/XCL/XLCL/XYAxisTo/XYAxisFrom`；`RUS/RCS/RLS/RUCL/RCL/RLCL/RYAxisTo/RYAxisFrom`；`SUS/SCS/SLS/SUCL/SCL/SLCL/SYAxisTo/SYAxisFrom`；`MUS/MCS/MLS/MUCL/MCL/MLCL/MYAxisTo/MYAxisFrom`；規則欄 `TRule/XRule/RRule/SRule/MRule`。線上管制因子欄依已核准 QC Item 的 FactorOnline 動態加入，欄名由範本提供。

## Core 驗證與轉換

| 欄位／條件 | 舊程式邏輯與 YMES 規則 |
| --- | --- |
| QCItemNo | 必填；必須查到已核准的計量 QC Item（`IssueState=2`），並取得 `SampleSize`、`SpecLineType` 等主檔屬性。 |
| SampleSize | 有提供且為數字時轉整數；空白或非數字時舊 Core 回退使用 QC Item 的 SampleSize。YMES 應回報非數字輸入錯誤，避免靜默忽略使用者值；同時驗證整數範圍。 |
| 線上 Factor | 從該 QC Item 取已核准 `FactorOnline='Y'` 的因子。每個因子都必須在匯入列有非空同名欄；若因子 `FactorSpec='Y'`，值不可為 `*`。其他未核准的上傳欄名不可以成為 SQL identifier。 |
| TUS/TLS | 先轉為趨勢圖 detail 的 US/LS，非空值必須為數字。依 QC Item `SpecLineType`：0 雙邊需同時有 TUS/TLS；1 上限單邊需 TUS；2 下限單邊需 TLS。 |
| 其餘圖表界限 | 非空值須為數字。對趨勢、Xbar、R、S、Rm 五組界限，所有同列存在的 `US/UCL/CL/LCL/LS` 值需維持由大至小；每組 YAxisFrom 與 YAxisTo 同時有值時須 `From < To`。來源錯誤訊息會標出對應圖表名稱。 |
| ChartTitle、KeyNode、Sponsor、PlanNo、ChartUnit、MEMO | 可空白；有值時更新主檔。`Creator`、`CreateDate` 舊程式會接受檔案提供值或預設 system/Now；YMES 必須一律改用登入者與伺服器時間。 |
| TRule/XRule/RRule/SRule/MRule | 每組以分號分隔，項目格式 `RuleNo,Action`。Action 對應：warning=0、wait=1、hold=2、alert=3；少逗號會丟出格式錯誤，未知 action 舊程式會略過該列。YMES 應嚴格拒絕未知 action、空 RuleNo、不存在/未核准的規則及重複 `(SPCID, RuleNo)`。 |

各圖表 SPCID 對應：Trend=0、Xbar=1、R=2、S=3、Rm=4。每列建立五筆圖表 detail 草稿，再依輸入欄位填入有值的界限與軸範圍。注意來源 `TBLSPCQCCHARTDETAIL` 沒有 MEMO 欄；Core 只有在 detail MEMO 非空時才會嘗試寫入該欄，因此 YMES 的主檔 MEMO 應寫 chart basis，不要把它誤存到 detail。

## 新增、更新與重複處理

- Core 以 `QCItemNo + 全部 FactorOnline 因子值` 搜尋現有 `TBLSPCQCCHARTBASIS`。0 筆則新增；1 筆則更新同一 `FactorSerial`；超過 1 筆回 `QCChartBasis Duplicate`。搜尋 SQL 舊程式直接把 FactorNo 當欄名，YMES 必須以核准因子 whitelist 建立結構化 JSONB 條件，不可把匯入表頭拼進 SQL。
- 新增後直接設定 `IssueState=2`。更新既有 chart 時，完成主檔與界限更新；若舊狀態不是 2，改成 2。這個匯入功能沒有另外的審核步驟。
- 新增 Chart Rule 時，Core 先複製 `TBLQCITEMRULE` 對應項目規則到 Chart Rule。若匯入列含任何非空 TRule/XRule/RRule/SRule/MRule，則依 SPCID 刪除該 FactorSerial 的既有 Chart Rule 並改寫解析結果；五欄皆空時不呼叫覆寫程序，既有圖表規則保留。
- 每筆 chart 及其 detail、detail history、rule 變更先收集 SQL，再由 Core 執行；Web Service 對檔案每列呼叫一次 Core，單列錯誤寫回 Execute，Service 外層仍常回整體 success。YMES 必須將一列所有主檔/明細/歷程/規則寫入放在同一交易，並回列級結果。查重與寫入要交易內序列化或採等效併發控制，避免兩個請求同時新增相同 QCItem/要因組合。
- 新增值 `FactorSerial` 必須由伺服器產生。Client 提供的 `FactorSerial`、Creator、CreateDate、Execute 欄均忽略。匯入上傳限制檔案、工作表列數/欄數及欄名長度；公式不得執行，資料值全部參數化。

## YMES API 契約

1. `POST /api/qc/chart-data-import/preview`：multipart 欄位 `file`；解析 `.xls/.xlsx` 第一工作表，依範本相容規則回 `{columns:[...],rows:[{...}]}`。`Select/Result/Execute/FactorSerial` 系統欄忽略。DEV 預覽另外支援 `.xlsx/.csv`，CSV 僅為開發輔助格式。
2. `POST /api/qc/chart-data-import/import`：body `{rows:[{recognizedColumns...}]}`，一次送出所有列。回 `{rows:[{rowNo,qcItemNo,succeeded,execute,factorSerial}]}`；rowNo 是本次提交陣列的一起始 1 的列序號。每列獨立交易並重新驗證核准 QC Item、Factor whitelist、引用資料、重複 key 與規則；允許部分成功。
3. `GET /api/qc/chart-data-import/template`：登入且 FunctionKey=`QC302` 後，依 FunctionNo=`IMPORT QC CHART DATA` 提供 `QCChart_Template.xls/.xlsx`，用 Content-Disposition 回傳檔名。

所有 API 檢查登入與 QC302 功能權限。匯入成功後前端照 WinForms 鎖定本批資料，要求載入另一個檔案再執行；API 明確回列級結果，前端不把 HTTP 200 當成全列成功。
