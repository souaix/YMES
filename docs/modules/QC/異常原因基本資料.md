## Oracle DDL 與 YMES CREATE

- Oracle source DDL：`database/reference/mestest_qc_hold_item_basis_source_ddl.sql`
- PostgreSQL 空表 CREATE 參考：`database/reference/mestest_qc_hold_item_basis_create.sql`
- Oracle 欄位/constraint/index 由 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 使用本機受保護連線唯讀查得；只查 metadata/DDL，未查業務列，未在 Oracle 執行 DDL，連線內容未寫入檔案。
- PK 為 `HOLDITEMNO`。只有 PK unique index，沒有其他 index 或 FK。不要額外建立 `(MCLASSNO,SCLASSNO,HOLDITEMNO)` 唯一限制或 FK。
- Oracle `DATE` 對應 PostgreSQL `timestamp without time zone`；`NUMBER(p,0)` 對應 `numeric(p,0)`。`CREATEERF` 與 `DATASTAMP` 可 NULL；其餘 DDL 中標為 NOT NULL 的欄位必須保留。

## WinForms 畫面

### 清單

- 主 Form client size 為 1008×591。上方沿用 `frmBasisTemplat` 的四種狀態單選與查詢列；狀態預設 `Unfrozen`（0），可用的查詢欄位為 `HoldItemNo`、`MClassNo`、`SClassNo`。
- 清單 Grid 位於 `(12,53)`，大小約 `890×526`；右側按鈕寬 88、高 32，依序為新增、修改、刪除、複製、核准；匯入置底，關閉在右下。
- Grid 顯示欄位順序：HoldItemNo、MClassNo、SClassNo、HoldItemName、CreateERF、OCAPNo、HoldSystem、Description、Creator、CreateDate、Reviser、ReviseDate。IssueState、DataStamp 隱藏；預設按 HoldItemNo、MClassNo、SClassNo 排序。
- CreateERF 顯示 `0=Not Create`、`1=Create`；HoldSystem 從 MES ValueList 取得，來源 enum 對照為 `0=MES`、`1=EAP_Exception`、`2=EDA_Exception`。

### 新增/修改/複製表單

- Def Form client size 為 654×519。編號列在上方；中間分左右欄：名稱、主分類、次分類、Create ERF、OCAP、通知群組、HoldSystem、描述；底部為建立/修改資訊。操作按鈕為確定、關閉、套用。
- 新增預設 Create ERF=true、HoldSystem=0、IssueState=0，編號轉大寫；建立人/時間由登入者與現在時間帶入。
- 修改時 HoldItemNo、MClassNo、SClassNo 唯讀；可編輯名稱、Create ERF、HoldSystem、OCAP、通知群組、描述。待簽核狀態會唯讀；已簽核/不使用狀態的欄位則由舊系統 `ExeIssueControl` 設定控制，須在 Production 依同等權限規則保護。
- 複製會帶入來源欄位但要求新 HoldItemNo，並建立一筆新的未簽核資料；建立人/時間更新為目前使用者/時間。
- 必填：HoldItemNo、HoldItemName、MClassNo、SClassNo。若勾選「Send Mail to HoldDispGroup」，HoldDispGroup 必填。OCAP 可空白；有值時必須是已簽核清單中的編號。分類選擇器僅提供 IssueState=2；次分類選項依目前主分類篩選。群組選擇器限 IssueState=2。OCAP 清單限 IssueState=2 且 CURVERSION=1。
- 勾選/取消寄信會清空目前 HoldDispGroup；未勾選時不送群組值（Core 編輯將它設為 NULL）。儲存 OCAPVersion 使用 `*`，不採 picker 上的版本文字。
- `Apply` 儲存但保留表單；`Confirm` 儲存並關閉。更新帶 DataStamp 並寫 Reviser/ReviseDate。

## 按鈕與狀態規則

- 查詢載入符合查詢條件的資料，再以四個狀態在前端 Grid 篩選。狀態值：`0=未簽核`、`1=簽核中`、`2=已簽核`、`-1=不使用`。
- 新增/複製以 IssueState=0 建立。HoldItemNo 是主鍵，重複值由資料庫拒絕。
- 修改時 HoldItemNo 不可變更；DataStamp 用於防止覆寫他人更新。待簽核列不可編輯。Active/Unused 欄位由舊系統的 IssueControl 設定表決定可修改欄位，不可以假設所有欄位永遠可寫。
- 刪除允許狀態 0、-1、2；0/-1 實體刪除，2 改成 -1 並保留資料/關聯欄位；狀態 1 拒絕。已簽核轉不使用需以 DataStamp 條件更新，並記錄修改人/時間。
- 核准只處理狀態 0。Issue Job Map key 為 `HOLDITEM BASIS`。若沒有 Job/Detail，舊 Service 直接核准轉狀態 2；有流程時依共用 Issue/Job 建立流程、狀態轉 1、通知第一簽核群組，再由流程核准或退回。Production API 必須沿用 YMES 共用簽核服務，不能把直接 0→2 假資料分支當成正式簽核。
- 多選刪除/核准逐筆處理；第一筆錯誤停止，前面已成功列不回滾。Vue 必須回報已完成筆數並重新查詢。

## 匯入

- 清單「匯入」透過 `ObjectFileHandler.Execute("QC_HoldItemDataImport", ...)` 開啟獨立匯入 Form；WinForms 支援 `.xls`/`.xlsx`，讀第一個工作表。
- 欄位依欄序讀取：`HOLDITEMNO`、`MCLASSNO`、`SCLASSNO`、`HOLDITEMNAME`、`CREATEERF`、`HoldSystem`、`OCAPNo`、`HOLDDISPGROUP`、`DESCRIPTION`。前五欄必須有值；後四欄允許空白。HoldSystem 接受大小寫相符的 MES/EAP_Exception/EDA_Exception；空白預設 MES (0)。CreateERF 轉成整數後寫入 NUMBER(1,0)。
- 檢查異常原因編號不可重複；MClass、SClass 必須存在且已簽核；群組須存在；OCAP 有值時須已簽核。各列獨立處理，結果 Grid 顯示 HoldItemNo、HoldItemName、Message，並有進度/取消。
- `HoldItemDataChecker` 一次僅接受一列，匯入視窗逐列呼叫，因此批次可能部分成功。正式 API 應逐列獨立交易並回傳每列結果。公司端 DEV 預覽接受 CSV 以免新增 Excel parser 依賴；Production UI/API 仍需支援舊系統 `.xls`/`.xlsx` 範本流程。

## Vue DEV 頁與 Production API 契約

- QC → 異常設定 → 異常原因基本資料掛載 `/YMES/QC/HoldItemBasis`。DEV 使用獨立 localStorage 假資料，提供四狀態、三欄查詢、Grid 選取、CRUD/複製、套用/確定、分類/群組/OCAP picker、多選刪除/核准及 CSV 匯入結果。輸入欄為 KD 黃色；查詢/按鈕/資料 Grid 保持共用樣式。
- Production 必須要求登入及 FunctionKey `QC403`；所有查詢/寫入做欄位白名單、參數化及權限檢查。401 沿用 App 登入流程。
- 建議 `GET /api/qc/hold-item-basis?searchFieldName=&searchFieldValue=` 回傳符合條件的全部狀態資料；searchFieldName 僅允許 `HoldItemNo`、`MClassNo`、`SClassNo`。狀態 radio 在 Vue 本地篩選。
- `GET /api/qc/hold-item-basis/lookups` 回傳已簽核 MClass、與 MClass 對應的已簽核 SClass、已簽核 HoldDispGroup、已簽核且目前版本的 OCAP，以及 HoldSystem ValueList（0/1/2）。
- `POST /api/qc/hold-item-basis` 建立資料，伺服器設定 IssueState=0、Creator/CreateDate、DataStamp。欄位長度與 NOT NULL 規則依 Oracle DDL；不接受客戶端傳入 audit 欄位。
- `PUT /api/qc/hold-item-basis/{holdItemNo}?issueState=&dataStamp=` 僅允許修改 HoldItemName、CreateERF、HoldSystem、HoldDispGroup、OCAPNo/Version、Description；MClassNo/SClassNo/HoldItemNo 必須維持原值。限制待簽核狀態與 IssueControl 可編欄位，CAS 後由伺服器更新 Reviser/ReviseDate/DataStamp。
- `DELETE /api/qc/hold-item-basis/{holdItemNo}?issueState=&dataStamp=`：0/-1 實體刪除；2 CAS 軟停用為 -1；1 拒絕。
- `POST /api/qc/hold-item-basis/{holdItemNo}/approve` 使用 Issue Job Map `HOLDITEM BASIS`；透過共用簽核服務處理 bypass、建立流程、通知第一群組、核准/退回。
- `POST /api/qc/hold-item-basis/import` 接收舊 Excel 範本，依第一工作表逐列驗證並回傳 `{ results: [{ holdItemNo, holdItemName, result, message }] }`；逐列交易可部分成功。檔案大小/格式需受限，禁止執行試算表公式。
- 此功能沒有新增 lookup 表。家用端先核對 YMES live schema/migrations；只有主表缺漏才加 forward migration。主表與 lookup API 的授權檢查都須驗證 QC403。
