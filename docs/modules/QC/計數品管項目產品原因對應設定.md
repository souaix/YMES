# 計數品管項目產品原因對應設定（QC218）

## 功能識別

| 項目 | 來源 |
| --- | --- |
| FunctionNo / FunctionKey | `QCITEM PRD REASON MAP` / `QC218` |
| WinForms 選單 | 品質資料 → 品管設定 → 計數品管項目產品原因對應設定 |
| WinForms Form | `frmItemPRDReasonMap`、`frmItemPRDReasonDef`、`frmItemPRDReasonMapImport` |
| Importer | `DataImporter.QCItemRPDReasonSOPFileImporter.QCItemPrdReasonChecker` |
| Service / Core | `wsQC.LoadItemPRDReasonMap`、`wsQC.UpdItemPRDReasonMap`；`clsQCBasis` 同名方法 |

本規格依 WinForms Form/事件、Designer、wsQC、clsQCBasis、Importer 及 MESTEST Oracle metadata 整理。Vue DEV 僅使用本機假資料；API 尚待家用端實作。

## WinForms 主畫面與操作

- 主畫面上方以 QCItemNo 做模糊查詢，送 `IssueState=2`，只列已核准的 `TBLQCITEMFORATTRIBUTES` 計數品管項目。Enter 與 Query 執行相同查詢；初次開啟載入全部已核准項目。
- 上方 Grid 顯示 QCItemNo、QCItemName、LotIsValid、ComponentCollect、PlanNo、IsSampleSizeInteger、RuleNo、Creator/CreateDate、Reviser/ReviseDate。IssueState、ExecutionFile、DataStamp 隱藏。LotIsValid/ComponentCollect ValueList 為 0=N、1=Y；IsSampleSizeInteger 為 0=Y、1=N。ZKT/KYT 企業會調整 QCClass 欄寬/顯示；欄位來源以 API 版本契約處理。
- 點選 QC Item 後，下方載入該 QCItemNo 的全部產品原因對應。下方 UltraGrid 以 ProductNo 建立主從群組，群組列只顯示 ProductNo，展開後顯示 ReasonNo、ReasonName、ReasonType、ReasonLevel；不顯示子列 QCItemNo/ProductNo。
- 下方 ProductNo 輸入框按 Enter 套用篩選：空白顯示全部；`*` 顯示全產品共用原因；其他文字使用 `%文字%` 模糊篩選。`...` 從目前 QC Item 已有的 ProductNo 清單挑選，不是產品主檔的全清單。
- `ReasonMap` 依下方目前選取的產品群組/子列開啟編輯；選取某個產品時編輯該產品，選取群組列或目前沒有對應列時以 `*` 編輯共用原因。每次儲存後重載目前 QC Item 對應。`Import` 開啟獨立匯入視窗；`Close` 關閉主畫面。

## ReasonMap 編輯視窗

- QCItemNo、QCItemName 唯讀；ProductNo 可輸入或用 `...` 從已核准、目前版本產品 (`IssueState=2 AND CurVersion=1`) 選取。`*` 表示全產品共用原因，儲存端直接把資料寫入全域對應表。
- ReasonType 下拉固定 `0 Scrap`、`1 Defect`；ReasonLevel 是 0–9 數字，初始 0。左側 UnSelected 只列已核准品質原因中符合目前 Type/Level 且尚未選取的資料；右側 Selected 列出目前全部已選原因。按左右箭頭移動多列；雙擊列等同移動。
- 改變 ProductNo 後按 Enter，重載該 QCItemNo / ProductNo 已選原因，再重新初始化左右清單。`Confirm` 以 `|` 串接 ReasonNo 後送出；空清單有效，代表清除該組所有對應。`Cancel` 關閉；有未儲存的選取變更時詢問儲存或放棄。
- ProductNo 必須是有效核准中的目前版本產品，除 `*` 全域值外；所有 ReasonNo 應是已核准原因。舊 WinForms 在儲存前也呼叫產品查找，並直接用輸入文字檢查結果，可能使 `*` 被當成產品編號而拒絕。Core 與 Importer 明確把 `*` 當全域鍵，因此新 API/UI 應允許 `*` 並寫入 `TBLQCITEMREASONMAP`，不要複製此畫面缺陷。

## 匯入視窗與舊程式行為

- 檔案選擇支援 `.xlsx`、`.xls`，只讀第一張工作表。第 0 列視為欄名列；資料依欄位位置 0/1/2 讀 QCItemNo、ProductNo、ReasonNo，三欄均需有值。範本透過 `wsSYS.AddTemplateFile`，FunctionNo=`QCITEM PRD REASON MAP`，支援系統設定的檔案副檔名。
- 預覽後按 Import；每一組 `(QCItemNo, ProductNo, ReasonNo)` 分開驗證、寫入及顯示 success/fail/message，允許部分成功並可取消。WinForms 將相同三欄鍵的列先聚合；一組若有超過一列，Importer 以 duplicate data 拒絕。正式 API 應明確回報重複與逐筆結果，不接受前端傳入 Creator。
- `QCItemPrdReasonChecker` 檢查 QC Item 已核准、Reason 已核准；ProductNo 不等於 `*` 時，產品必須已核准且 `CurVersion=1`。`*` 寫入 `TBLQCITEMREASONMAP`，其他產品寫 `TBLQCITEMPRDREASONMAP`。Creator 由舊 WinForms 呼叫端帶入，新 API 必須從登入者身分與伺服器時間產生。
- 舊 Excel 迴圈條件 `rowId <= LastRowNum - 1` 會跳過工作表最後一列；Web parser 不應保留此錯誤。舊 duplicate existence helper 會吞掉查詢例外且呼叫端未檢查 helper 回傳值；由 PK 最後攔截重複。API 應使用參數化 SQL、明確查重並在資料庫唯一鍵衝突時回傳可理解的逐列失敗。
- DEV 匯入預覽目前接受 UTF-8 CSV 以免依賴瀏覽器端 Excel 套件；Production API 契約支援 `.xlsx/.xls`，需解析工作簿第一張工作表且保留所有資料列。DEV template 下載 CSV；Production template 由系統範本服務提供。

## Service/Core 資料邏輯

- `LoadItemPRDReasonMap(QCItemNo, ProductNo, ReasonNo, blnAllData)` Join 對應表至 `TBLQCREASONBASIS` 取得 ReasonName/Type/Level。`ProductNo='*'` 或 `blnAllData=true` 時先取 `TBLQCITEMREASONMAP` 全域資料，再合併至回傳結果並將 ProductNo 設為 `*`；另載入產品對應表。主畫面使用 `blnAllData=true`，以 ProductNo 主從 Grid 顯示全資料。
- `UpdItemPRDReasonMap` 是整組替換：一般 ProductNo 先刪除該 QCItemNo/ProductNo 的所有 `TBLQCITEMPRDREASONMAP`，再逐筆新增 ReasonNo；`*` 則刪除該 QCItemNo 的 `TBLQCITEMREASONMAP` 後重建。空 ReasonNoSet 只執行刪除，因此允許清空。Core 將 SQL collection 交由共用更新交易執行。
- 舊編輯表單在更新時只傳 Reviser/ReviseDate；Core 刪除舊列後重建新列，故重建後的 Creator/CreateDate 可能為 NULL。Importer 則新增 Creator/CreateDate。API 應在整組替換交易中保留既有鍵的建立稽核資料，新增鍵使用登入者與伺服器時間，更新稽核由伺服器產生。
- 兩張 mapping 表的 PK 分別防止重複 `(QCItemNo,ProductNo,ReasonNo)` 與 `(QCItemNo,ReasonNo)`。Oracle 未宣告 FK；API 仍需於交易中確認核准 QC Item/Reason/Product 狀態及目前版本。

## Oracle DDL 與 PostgreSQL CREATE 參考

Oracle DDL 由 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 使用本機受保護唯讀連線查 MESTEST DBMS_METADATA / data dictionary 取得；僅查 metadata，未讀業務資料列、未在 Oracle 執行 DDL，也未把連線憑證寫入文件。

| 表 | 用途 | Oracle source DDL | PostgreSQL CREATE-only |
| --- | --- | --- | --- |
| `TBLQCITEMPRDREASONMAP` | 指定產品原因 | `database/reference/mestest_qc218_tblqcitemprdreasonmap_source_ddl.sql` | `database/reference/mestest_qc218_item_product_reason_map_create.sql` |
| `TBLQCITEMREASONMAP` | `*` 全域原因 | `database/reference/mestest_qc218_tblqcitemreasonmap_source_ddl.sql` | 同上 |
| `TBLQCITEMFORATTRIBUTES` | 共用核准 QC Item 查詢 | `database/reference/mestest_qc218_tblqcitemforattributes_source_ddl.sql` | 不重建；既有 QC Item 共用表 |
| `TBLQCREASONBASIS` | 共用原因選項 | `database/reference/mestest_qc218_tblqcreasonbasis_source_ddl.sql` | 不重建；既有 QC reason 共用表 |
| `TBLPRDPRODUCTBASIS` | 核准/目前版本產品查詢 | `database/reference/mestest_qc218_tblprdproductbasis_source_ddl.sql` | 不重建；既有產品共用表 |

兩張 mapping 表的欄位為 QCItemNo、ProductNo（產品表才有）、ReasonNo、Creator、CreateDate、Reviser、ReviseDate。主鍵是前述組合；每張表只找到 PK unique index，沒有其他 index 或 FK。共用表的 source DDL 僅供欄位核對，不是建立副本的授權。PostgreSQL SQL 是空結構參考，不是 migration；家用端先比對 YMES live schema 和既有 migrations，只新增缺少的 forward migration，不覆蓋現存表。

## Production API 契約（家用端待建）

所有端點需登入保護及授權 FunctionKey `QC218`。所有查詢/寫入使用參數化 SQL；API 端重新確認資料狀態，不信任 UI 選項與 audit payload。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/qc/item-product-reasons/qc-items?issueState=2&qcItemNo=` | 已核准計數 QC Item，QCItemNo 模糊查詢 |
| GET | `/api/qc/item-product-reasons?qcItemNo=&allData=true` | 主畫面全域/產品對應，提供 ProductNo 分組 |
| GET | `/api/qc/item-product-reasons/{qcItemNo}/products` | 該 QC Item 已有對應的 distinct ProductNo，含 `*` |
| GET | `/api/qc/item-product-reasons/reasons?issueState=2` | 已核准原因清單及 ReasonType/Level/Description |
| GET | `/api/qc/item-product-reasons/products?issueState=2&currentVersion=1&search=` | 編輯視窗產品選取器 |
| GET | `/api/qc/item-product-reasons/{qcItemNo}/{productNo}/reasons` | 精確目標 QC Item/Product 的已選原因；`*` 僅回全域 mapping |
| PUT | `/api/qc/item-product-reasons/{qcItemNo}/{productNo}` | 完整替換 reasonNos；空陣列清空。`*` 寫全域表，其他寫產品表 |
| POST | `/api/qc/item-product-reasons/import/preview` | multipart 上傳 `.xlsx/.xls`，回傳第一工作表預覽列與格式錯誤 |
| POST | `/api/qc/item-product-reasons/import` | 單列 `{ qcItemNo, productNo, reasonNo }`，獨立驗證/插入並回成功或失敗 |
| GET | `/api/qc/item-product-reasons/template` | 下載 FunctionNo 對應系統範本 |

`PUT` 必須在一筆交易內驗證目標 QC Item、所有核准 Reason、ProductNo=核准目前版本或 `*`，再替換目標 mapping。用戶端不可任意變更另一個產品組。Import 每一列原子處理、逐列回傳錯誤；audit 一律從登入者/伺服器時間取得。家用端需在共用 QC217 後核對 API 命名衝突與既有 QC 原因/產品服務，必要時以同一契約語意調整路徑並更新此文件。
