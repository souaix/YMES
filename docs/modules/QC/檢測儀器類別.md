# QC501 檢測儀器類別（Inspection Machine Parameter Type）

## 功能定位與來源

- MES 選單：第一層「品質資料」→ 第二層「檢測儀器」→ 第三層「檢測儀器類別」。FunctionNo=`INSPMACHINE PARAMETER TYPE`、FunctionKey=`QC501`、IssueTable=`TBLQCINSPMACHINEPARAMETERTYPE`。
- WinForms 主畫面：`STD/MESWin/QC/QC_InspMachineParameterType/frmInspMachineParameterType.vb`；編輯畫面：同目錄 `frmInspMachineParameterTypeDef.vb`。資料操作核心：`STD/MESkc/kcQC/clsInspMachine.cs` 的 `Load/Add/Edit/DelInspMachineParameterType`。舊表單透過 `wsQC` service 呼叫核心。
- Web DEV 頁：`/YMES/QC/InspectionMachineParameterType`；Vue 元件 `web/src/components/QcInspMachineParameterTypeMaster.vue`。預覽假資料儲存在瀏覽器 localStorage；production 才呼叫本文件列出的 API。
- 此功能是 QC501–QC503「檢測儀器類別、檢測儀器、檢測 Driver」共用資料群的第一頁；不在 QC501 頁內維護儀器屬性。WinForms 的 Property 按鈕在 Designer 預設 `Visible=False`。

## WinForms 畫面與互動

- 主 Form 約 1008×591。上方沿用基礎表單的四種 IssueState 篩選（0 未簽核、1 簽核中、2 已簽核、-1 不使用），預設未簽核；搜尋欄位為 InspMachineType，按查詢重新呼叫 `LoadInspMachineParameterType`。Service 取回 `InspMachineType IS NOT NULL` 的資料，主表單依狀態篩選並按 InspMachineType 排序。
- Grid 顯示欄位順序：InspMachineType、InspMachineTypeName、InspType（0=RS232、1=UserDefine）、BaudRate、DataBit、StopBit、Description、Creator、CreateDate、Reviser、ReviseDate。IssueState、DataStamp 隱藏。支援目前列與多列選取；雙擊目前列等同修改。
- 主畫面按鈕為 ADD、EDIT、DEL、Copy、Approve、Close；Property 預設隱藏。新增與複製完成後重查並定位到新資料；修改完成後重查並定位到原資料。刪除與核准可逐列處理目前選取列，發生第一筆失敗會停止後續處理。
- 新增/複製表單以 InspMachineType 作為唯一識別；複製時保留原資料欄位，但新識別碼需重新輸入。修改時 InspMachineType 與 InspType 鎖定。表單有「確定、關閉、套用」；套用成功後不關閉視窗。
- `InspType=0` 顯示 RS232 分頁：BaudRate 選項 600/1200/2400/4800/9600/19200、ParityBit 選項 None/Odd/Even/Mark、DataBit 7/8、StopBit 1/2、EndCode 0/3/10/13、Format1、Format2、ChNo。EndCode 對照 0=NUL、3=ETX、10=LF、13=CR。必填為 BaudRate、ParityBit、DataBit、StopBit、EndCode、Format1；Format2 與 ChNo 空白時存成字串 `NA`。
- `InspType=1` 顯示 UserDefine 分頁；InspDriverNo 為唯讀欄位，透過 `LoadInspDriver` 搜尋視窗選取。舊呼叫沒有傳 IssueState，因此 Driver 清單不限定簽核狀態。InspDriverNo 必填。
- InspMachineType、InspType 必填；InspMachineTypeName 與 Description 可空。InspMachineType 離開欄位時轉大寫；Format1/Format2 轉大寫；Description 長度 255。RS232 選項、端碼及 Format1 驗證依舊表單。`ChNo` WinForms TextBox 的 MaxLength=10，但 Oracle 欄位只有 VARCHAR2(3)：舊 UI 可輸入超過資料庫長度的內容，儲存可能失敗；Vue 保留 10 字元 UI 上限，API 必須依 live schema 回傳明確欄位錯誤，不能截斷。
- 修改頁呼叫共用 `ExeIssueControl`：IssueState=0 全欄可編輯；1 簽核中唯讀；2 已簽核與 -1 不使用依表單/控制項設定資料決定允許編輯欄位。API 需套用相同 Issue Control 設定，不能把狀態 2/-1 硬編碼成整表可改或不可改。DEV 預覽提供欄位編輯流程，但不代表 production Issue Control 已完成。
- 核准操作只允許未簽核資料，逐筆呼叫 `ApproveInspMachineParameterType`；此操作進入 MES 共用簽核流程，狀態由簽核服務決定。刪除只允許狀態 0、2、-1；呼叫時帶 IssueState、DataStamp，舊 Core 以 AdditionalXml 狀態/版本條件刪除。

## 資料表、Oracle DDL 與 PostgreSQL 參考

- 直接從使用者既有受保護連線，以 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 唯讀取得 MESTEST DDL，未讀業務列、未在 Oracle 執行 DDL。來源檔：`database/reference/mestest_qc501_inspection_machine_source_ddl.sql`。擷取記錄見 `docs/DATABASE_CONNECTION.md`。
- PostgreSQL 空表 CREATE 對照：`database/reference/mestest_qc501_inspection_machine_create.sql`。它依 Oracle 欄位與主鍵改寫為 YMES 參考，不是 migration；家用端先比較 YMES live schema/migrations，再只補缺表。
- DDL 涵蓋 QC501–QC503 共用的六表：`TBLQCINSPMACHINEPARAMETERTYPE`、`TBLQCINSPMACHINETYPE`、`TBLQCINSPMACHINEBASIS`、`TBLQCINSPMACHINEPARAMETER`、`TBLQCINSPMACHINEPROPERTY`、`TBLQCINSPDRIVER`。來源 DDL 的 PK unique index 均為資料表 PK，未宣告 FK 或額外索引。
- `TBLQCINSPMACHINEPARAMETERTYPE` 的實際 PK 只有 `InspMachineType`，不是 `(InspMachineType, InspType)`；雖然舊 Core 的查詢/更新額外按 InspType 過濾，不能自行擴大 PK。此表 `IssueState`、`DataStamp` 在來源 DDL 可為 NULL（有 DEFAULT 但沒有 NOT NULL）；CREATE 參考保留此差異。
- QC501 寫入的 RS232 欄位為 BaudRate、ParityBit、DataBit、StopBit、EndCode、Format1、Format2、ChNo；UserDefine 寫 InspDriverNo。舊 Add Core 以 `InspMachineType` 作主欄，IssueState=0，並儲存建立人/日期；Edit 依傳入的非預設值欄位更新，Name 以 AdditionalXml 更新；Delete 為硬刪除，不會清除儀器資料或 Property。家用端需在服務端處理跨頁引用與交易安全，不能照搬裸 SQL 的參數拼接。

## YMES API handoff（家用端）

所有端點要求登入；依現行 YMES 授權安排檢查 FunctionNo=`INSPMACHINE PARAMETER TYPE` / FunctionKey=`QC501`。以下為 Vue 本次使用的 API 契約；可對接已存在的同等路由，但需同步更新元件或規格。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/qc/inspection-machine-parameter-types?issueState={state}&inspMachineType={query}` | 狀態/識別碼清單；回 `{items:[...]}`，按 InspMachineType 排序 |
| GET | `/api/qc/inspection-drivers` | UserDefine Driver 查找；依舊程式不限制 IssueState |
| POST | `/api/qc/inspection-machine-parameter-types` | 新增，伺服器指定 Creator、CreateDate、IssueState=0、DataStamp 初值 |
| PUT | `/api/qc/inspection-machine-parameter-types/{inspMachineType}` | 修改可編欄位；Body 帶 IssueState/DataStamp 作版本檢查；不可改主鍵/InspType |
| DELETE | `/api/qc/inspection-machine-parameter-types/{inspMachineType}?issueState={state}&dataStamp={stamp}` | 依允許狀態與版本條件硬刪；回 409 表示狀態或 DataStamp 已變 |
| POST | `/api/qc/inspection-machine-parameter-types/{inspMachineType}/approve` | 送入共用核准流程；Body 帶 IssueState=0、DataStamp、操作者識別，不由 UI 直接指定最終狀態 |

API 必須參數化 SQL、使用交易/CAS、由服務端建立稽核欄位，並沿用共用 Issue Job/Issue Control。新增/修改需驗證 RS232 必填值、UserDefine Driver、欄位實際長度與 EndCode；勿將空 Format2/ChNo 存 NULL，舊程式存 `NA`。刪除需檢查已被儀器類別/儀器/Property 關聯時的 YMES 規則；來源 Core 僅刪類別列，舊服務行為不提供完整引用保護。核准後重查資料，不可在 UI 假設一定轉成哪個狀態。

QC501 DEV mock 核准只示範送簽後出現簽核中狀態；正式 API 必須依共用 Issue Job 真實狀態回應。家用端需先檢查六張表於 YMES 是否已存在；`CREATE IF NOT EXISTS` 參考不可直接部署，也不可覆蓋既有結構。
