## 主畫面

- Form ClientSize 為 1008×591。最上方有作業站與品管項目兩組唯讀編號/名稱欄位及 ... 查找鈕；右上是 Query。UltraGrid 從 y=75 延伸至表單底部，右側依序為 Add、Edit、Delete、Copy，右下為 Close。
- Form Load 隱藏 Grid GroupByBox、設定單格選取。來源把初次 funLoadSamplingFor2ndInsp() 呼叫註解掉；進入頁面後先按 Query 才載入資料。
- Query 固定帶 QCItemType=1，按作業站編號及品管項目編號篩選；空白條件不加入查詢。主列表不依 IssueState 過濾。
- 可見欄位順序：OPNo、QCItemNo、QCItemName、OldSamplePlan、NewSamplePlan、Creator、CreateDate、Reviser、ReviseDate。QCItemType、DataStamp 隱藏。日期顯示至秒。
- 作業站查找使用 wsOP.LoadOPBasisHaveQCItem，依 OPOrder 排序。品管項目查找使用 wsOP.LoadOPQCItem，QCItemType=1、IssueState=2。
- 刪除前顯示 Ok/Cancel 確認；支援多選後逐筆呼叫刪除，單筆失敗會顯示錯誤並繼續處理其餘選取列。

## 新增、修改、複製

- Add 以 QCItemType=1 開啟空白定義視窗。先選作業站；作業站變更會清空品管項目與兩個抽樣計畫。選擇品管項目使用 wsOP.LoadOPQCItemJoinBasis，限制 IssueState=2，並由結果的 ComponentCollect 決定抽樣計畫種類。選項為元件抽樣時載入 Wafer 抽樣計畫，否則載入一般抽樣計畫。
- Edit 從選取列開啟定義視窗；作業站、品管項目、原抽樣計畫均不可更換，只能選擇 NewSamplePlan。
- Copy 複製目前列並以新增方式儲存；原始 WinForms 允許透過查找鈕變更作業站、品管項目及抽樣計畫。
- 原始主表對 Edit/Copy 設定 ComponentCollect 的程式碼已註解；Define 的預設值為 False，所以 Edit/Copy 的抽樣計畫查找走一般計畫。Add 選 QC Item 時則會依 ComponentCollect 分流至一般或 Wafer 計畫。Vue DEV 保留此來源行為。
- OldSamplePlan、NewSamplePlan、OPNo 均為必填。來源註解中的「新舊計畫不可相同」檢查已停用，因此不限制相同值。
- 定義視窗大小為 534×308。上方是作業站及品管項目；下方 GroupBox 為原抽樣計畫與變更後抽樣計畫；底部沿用共用編輯表單的建立/修改人、日期，以及 Confirm、Close、Apply。
- Add/Copy 寫入 Creator/CreateDate；Edit 表單載入 Reviser/ReviseDate 與 DataStamp。原始 Core 的 Edit 方法只更新 NewSamplePlan，方法簽章也沒有 DataStamp/Reviser/ReviseDate 參數；但 wsQC 呼叫端傳入這些命名參數。此處存在 Service/Core 來源不一致，家用端實作 API 時應以有效的交易、稽核及並行更新設計處理，不可假設舊 Core 已落實 DataStamp。

## 資料表及鍵值

- 主表 TBLQCSAMPLINGFOR2NDINSP 欄位及 Oracle 型別見 database/reference/mestest_qc211_second_inspection_sampling_source_ddl.sql。
- 唯一索引鍵順序為 (QCITEMNO, QCITEMTYPE, OPNO, OLDSAMPLEPLAN)。Oracle 沒有宣告 PK constraint，也沒有 FK 或其他索引。NewSamplePlan 不屬於唯一鍵。
- Add 撞到同一組唯一鍵時應回傳可理解的重複資料錯誤。Delete 使用上述四欄定位；Edit 以同一組四欄定位，只改 NewSamplePlan。
- PostgreSQL 空表參考為 database/reference/mestest_qc211_second_inspection_sampling_create.sql。這是參考結構，不是 migration；家用端須先比對 live schema，保留 YMES 現有資料及擴充欄位。
- 關聯選項沿用既有 QC Item、OP、一般抽樣計畫及 Wafer 抽樣計畫 API/表，不為 lookup 重建重複資料表。

## Vue 頁面與 API handoff

- Vue 3 DEV 頁路徑：/YMES/QC/SecondInspectionSampling；畫面沿用 WinForms 上方兩組查找條件、大型資料 Grid、右側 Add/Edit/Delete/Copy 與右下 Close。表頭、選列及表單欄位採 KD 黃橘色系。
- DEV 預覽使用此功能專屬 localStorage 假資料。正式環境使用登入中的 API，不把資料列選取狀態放在 URL。
- 建議 API（均要求登入及 FunctionKey QC211）：
  - GET /api/qc/second-inspection-sampling?opNo=&qcItemNo=：清單。
  - POST /api/qc/second-inspection-sampling：新增 { qcItemNo, qcItemType: 1, opNo, oldSamplePlan, newSamplePlan }。
  - PUT /api/qc/second-inspection-sampling/{qcItemType}/{qcItemNo}/{opNo}/{oldSamplePlan}：修改 { newSamplePlan, dataStamp }。
  - DELETE /api/qc/second-inspection-sampling/{qcItemType}/{qcItemNo}/{opNo}/{oldSamplePlan}：刪除唯一鍵對應資料。
  - GET /api/qc/second-inspection-sampling/options/operations、GET /api/qc/second-inspection-sampling/options/variable-qc-items?issueState=2&opNo=、GET /api/qc/second-inspection-sampling/options/sampling-plans?componentCollect=：作業站、已核准計量項目及一般/Wafer 抽樣計畫查找。來源已有共用 OP/QC/Plan loader，家用端可以連接既有 API。
- API 需在交易內檢查組合唯一鍵、鍵值存在及 QC Item/OP/抽樣計畫關聯；Update 應採 DataStamp concurrency 並正確寫入 Reviser/ReviseDate，或記錄與舊 Core 落差一致的 YMES 稽核決策。多選刪除由前端逐筆呼叫，單筆失敗不得阻止後續列。
