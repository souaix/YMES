## 主畫面

WinForm 主表單 ClientSize 為 1008×591。頁面包含基礎查詢列、資料 Grid、右側直排功能按鈕。查詢列的簽核狀態為「未簽核、簽核中、已簽核、不使用」，預設未簽核；查詢欄位為 QCItemNo。舊程式一次載入各狀態資料，再依選取狀態篩選並依 QCItemNo 排序。Web 頁以 API 狀態條件查詢，點選列只更新 Vue 狀態，不改 URL、不重載頁面。

Grid 顯示欄位及順序：

1. QCItemNo
2. QCItemName
3. ChartType
4. SpecLineType
5. ComponentCollect
6. LotIsValid
7. PlanNo
8. ChartControl
9. CollectType
10. LimitLotNum
11. SampleSize
12. Unit
13. QCDataType
14. MinValue
15. MaxValue
16. Description
17. Roundoff_Num
18. Creator
19. CreateDate
20. Reviser
21. ReviseDate

舊 Grid 隱藏欄位：LotIsValid、IssueState、ComponentCollect、CalType、WebUrl、ErrorReportName、NoticeReportName、ExecutionFile、DataStamp。另有顯示用轉換欄位 LotIsValidShow、ComponentCollectShow、CalTypeShow；QCClass 只有企業代碼 ZKT/KYT 顯示。Web Grid 將狀態和 DataStamp 保留在 DTO，不必顯示。

右側按鈕順序：ADD、EDIT、DEL、Copy、Approve、Parameter、Factor、Simulation、OP、Memo。Calculate Script 和 Find 在 WinForms Designer 中隱藏。視窗底部有 SamplePlanChange、Close。

## IssueState 與主檔操作

| IssueState | 畫面 |
| --- | --- |
| `0` | 未簽核 |
| `1` | 簽核中 |
| `2` | 已簽核 |
| `-1` | 不使用 |

- 新增建立 IssueState=0。QCItemNo 必填、不可含逗號；新增時不得與計數品管項目編號或群組編號衝突。
- 修改時 QCItemNo 唯讀；可編輯狀態由 `ExeIssueControl` / TBLSYSISSUECONTROL 決定。編輯送出原 DataStamp；API 應在交易中做狀態與 DataStamp 比對。
- Copy 產生新的 QCItemNo，主要欄位先複製來源。可勾選複製 Parameter、Factor、Rule、SamplePlanChange。CalculateScript 勾選框目前隱藏。若 QCItem 參數與目標抽樣計畫參數或數值不一致，WinForm 開啟 `QC_ItemCopyParameterSelector` 讓操作者選擇參數來源；取消時中止複製。未複製 QCItem Parameter 時，由服務依抽樣計畫參數建立新項目。
- 未簽核項目核准前，WinForm 先讀 Factor，沒有 Factor 時禁止核准。核准送 `IssueNo=QCITEM_V` 進共用 Issue/Job 流程；無 Job 或無 Job Detail 時直接設為已簽核，否則進入簽核中並由 Issue Process 核准或退回。此處不是單純將狀態改成 2。
- 刪除只接受狀態 0、-1、2；狀態 1 不允許。狀態 2 轉為 -1，不刪除主檔；0/-1 執行實體刪除。
- 實體刪除前檢查 WIP 使用、量測資料、材料/材料類別/作業站/產品綁定、QC 群組與 PMI 群組綁定；任一引用存在時拒絕刪除。已有變數量測資料時由一般主檔畫面拒絕刪除。成功刪除會清理 Parameter、Factor、GroupDetail、Rule、Spec Detail/Basis、CalculateScript、SamplePlanChange 等子資料。
- 舊核心刪除清單未包含 `XX_TBLQCITEM_MEMO`；YMES API 實體刪除時應同一交易清除孤兒 Memo 設定。

## 編輯表單欄位與驗證

表單大小 710×743，欄位採 KD 淡黃色可編輯底色；Edit 的 QCItemNo 唯讀。欄位包含：

- QCItemNo、QCItemName
- Lot Valid Check、Component Collect
- Calculate Type（By Lot / By Component）
- Plan No（依 ComponentCollect 查一般或 Wafer 已核准抽樣計畫）
- Special Form Name（介面清單）
- Description、Roundoff_Num
- Chart Control、Chart Type、SpecLineType、Collect Type、QCDataType
- Min/Max Reasonable Value、Limit Lot Num、Sample Size
- Unit、MClass No（只查已核准 MClass）
- QCClass（僅 ZKT/KYT 企業顯示且必填）
- Creator/CreateDate/Reviser/ReviseDate 稽核欄位

規則：

1. QCItemNo、QCItemName、Lot Valid Check、Component Collect、PlanNo、ChartType、SpecLineType 為必填。
2. ComponentCollect=0 時 CalType 固定 ByLot；=1 才能選 ByLot/ByComponent。
3. LimitLotNum 必須是數值；ChartControl=Yes 時必須大於 0。
4. MinValue、MaxValue 都必填且為數值；允許範圍為 -1,000,000 至 1,000,000，且 MinValue 不可大於 MaxValue。舊程式檢查 Min 下限與 Max 上限，YMES API 應同時限制兩者上下界。
5. SampleSize 可空白；輸入時須為大於等於 0 的整數。ChartType=X-Rm 時必須等於 1；SampleSize=1 而 ChartType 非 X-Rm 時，舊程式顯示提示並停止儲存。
6. 新增時 Creator/CreateDate 由登入者與伺服器時間寫入；修改時 Creator 保留，Reviser/ReviseDate 更新。不可信任瀏覽器傳來的稽核身分。

## 子功能

### Parameter

開啟共用 `QC_ItemParameter`，傳入 `QCType=1`。維護此計量 QCItem 的抽樣/量測參數；計畫參數查找使用已核准抽樣計畫資料。

### Factor

開啟共用 `QC_ItemFactor`，傳入 `QCType=1` 及 QCItem DataRow。Approve 前至少要有一筆 Factor。

### Simulation

開啟 `QC_SamplingParameterSimulation`，參數 `PlanOrQCItem=1`、QCItemNo、PlanNo。用途為依抽樣參數預覽模擬結果，不應寫入正式量測日誌。

### OP

開啟共用 `QC_ItemOp`，傳 `QCType=1`、IssueState、LotIsValid。狀態 0/1 時主畫面直接拒絕開啟。LotIsValid=0 不可加入 InLine；作業站包含 ExecuteOrder 及 InLine 的 FAI/IPQC/PQC 檢驗時機。

### SamplePlanChange

開啟共用 `QC_SamplePlanChange`，傳 `QCItemType=1` 與 ComponentCollect。欄位包含 Old/New SamplePlan、AccLotQty、RejLotQty、FactorNo、LotRange、AQLChkForSPlanChg。

### Memo（THEIL BU1 客製）

`frmQCItemMemoSetting_THEIL_BU1` 載入 `wsSYS.LoadMesParameter(IssueState=2, ParameterClass=1)`，顯示 ParameterNo/ParameterName 與勾選欄。支援全選、全不選、將 Grid 多選列勾選、確定整批儲存、取消。

需要特別保留實際來源行為：此視窗呼叫 `UpdQCItemMemo` 時固定傳 `QCItemType=0`，即使 QC205 的 Parameter/Factor/OP 等共用頁面使用 `QCType=1`。讀取目前 Memo 設定只以 QCItemNo 查詢。Oracle 欄位 `RESVITOR` 是舊拼字，儲存的是登入 UserID；`DATETIME` 是建立時間。

WinForms 共用核心會先刪除該 QCItemNo/QCItemType 的舊 Memo 列，再按勾選內容插入新集合。每個 ParameterNo 還會被拼成 SQL 欄位識別字，若缺欄位就對 `TBLSPCVARDETAILLOG` 及 `XX_TBLSPC_TEMPDATA_VAR` 執行 `ALTER TABLE ADD (ParameterNo VARCHAR2(500))`。YMES 不可接受客戶端欄名、不應動態 ALTER 任意資料表；API 必須確認 ParameterNo 是已核准、ParameterClass=1 的 MES Parameter，使用參數化 SQL，Memo 對應存正規化關聯列。變數量測值的彈性欄位由量測 API 以 JSONB/結構化值處理，不以任意欄位名稱改表。

## 資料表與 DDL

- 主表 `TBLQCITEMFORVARIABLES` Oracle DDL / PG Create 已在 `database/reference/mestest_mtl_qc_item_tables_source_ddl.sql`、`mestest_mtl_qc_item_tables_create.sql`。
- 共用 `TBLQCITEMPARAMETER`、`TBLQCITEMFACTOR`、`TBLQCSAMPLEPLANCHANGE` 已在 `database/reference/mestest_qc_item_attributes_source_ddl.sql`、`mestest_qc_item_attributes_create.sql`。
- 本次用 Windows PowerShell 5.1 + Oracle.ManagedDataAccess，透過受保護的本機 MESTEST 連線設定，只讀取 `ALL_TABLES`、`DBMS_METADATA.GET_DDL` 與索引字典，未查業務列、未在 Oracle 執行 DDL。
- `database/reference/mestest_qc205_theil_custom_source_ddl.sql`：直接讀取 `XX_TBLQCITEM_MEMO`、`XX_TBLSPC_TEMPDATA_VAR`、`TBLSPCVARDETAILLOG` DDL/索引。
- `database/reference/mestest_qc205_theil_custom_create.sql`：Memo 對應的 YMES PostgreSQL 建表參考。Oracle 原表沒有 PK/索引；此 PG 參考加上 `(qcitemno,qcitemtype,memo_item)` 唯一鍵以防止重複設定。家用端先核對 live YMES schema/migrations，再決定是否需要 migration。
- `database/reference/mestest_qc205_variable_dependencies_source_ddl.sql`：直接刪除/複製/引用檢查涉及的 MESTEST 來源 DDL。MESTEST 查無 `TBLSPCQCHARTDETAIL`、`TBLSPCQCHARTDETAILLOG`、`TBLSPCQCHARTRULE`、`TBLSPCQCHARTBASIS`；舊核心仍有對這四表的刪除語句。先查 YMES 等價結構/執行路徑，不要只為不存在的來源表臆造 Create SQL。
- 建立真正的 migration 前，家用端需比對 PostgreSQL live schema、保留既有欄位與資料，只新增缺少結構。

## YMES API 交接契約

所有端點需驗證登入及 FunctionKey `QC205`，SQL 參數化；狀態、綁定、資料存在與 DataStamp 需由 API/資料庫重新確認。由登入 session 寫入 audit，不接受前端指定 Reviser/Creator。

1. `GET /api/qc/variable-qc-items?issueState={0|1|2|-1}&qcItemNo={optional}`：回傳以上 Grid 欄位、隱藏狀態欄、FormName、ExecutionFile、DataStamp。
2. `GET /api/qc/variable-qc-items/options`：提供已核准一般/Wafer 抽樣計畫、表單介面、MClass、ParameterClass=1 參數、可用 Factor、OP，以及是否需要 QCClass。
3. `POST /api/qc/variable-qc-items`：新增，後端核對重複編號與跨類型/群組衝突，狀態設為 0。
4. `PUT /api/qc/variable-qc-items/{qcItemNo}`：修改唯讀編號外欄位；檢查 IssueState 控制與 DataStamp，交易內更新。
5. 複製前呼叫 `POST /api/qc/variable-qc-items/copy-preview`，body `{fromQcItemNo,planNo}`，回傳 `{qcItemParameters,samplingPlanParameters}`。兩邊內容不同時 Vue 顯示 WinForms `QC_ItemCopyParameterSelector`；確認後呼叫新增端點，帶 `fromQcItemNo`、`copyFlags`（parameters/factors/rules/samplePlanChanges）及 `parameterSource=qcItem|samplingPlan`。伺服器需在同一交易建立主檔並複製勾選的子資料；parameters 未勾選時依目標 Plan 建立參數。取消來源選擇即取消複製，不可靜默覆蓋。
6. `DELETE /api/qc/variable-qc-items/{qcItemNo}?issueState=&dataStamp=`：狀態 2 改 -1；0/-1 只在無量測列、無 WIP 使用、無材料/作業站/產品/群組綁定時做交易式清理。參照 QC201 關聯 API 的 YMES 正規表，不可假定 Oracle 關聯表已存在。
7. `POST /api/qc/variable-qc-items/{qcItemNo}/approve` body `{issueState:0,dataStamp}`：先檢查至少一個 Factor，再走 IssueNo=QCITEM_V 的 Issue/Job 核准流程。按核准後實際 state 回傳 1 或 2。
8. Parameter、Factor、OP、SamplePlanChange 使用子資源 GET/PUT：
   - `/{qcItemNo}/parameters`
   - `/{qcItemNo}/factors`
   - `/{qcItemNo}/operations`
   - `/{qcItemNo}/sample-plan-changes`
   內容帶 `QCType/QCItemType=1`，檢查 IssueState 控制；OP 狀態 0/1 拒絕，LotIsValid=0 禁止新增 InLine。
9. `GET /{qcItemNo}/memos` 回傳已核准 ParameterClass=1 選項及目前勾選；`PUT /{qcItemNo}/memos` body `{qcItemType:0,parameterNos:[...]}`。交易內驗證參數後全量替換 Memo 關聯。不要把 ParameterNo 當 SQL 欄位名，也不要在資料表上執行動態 ALTER。
10. `GET|POST /{qcItemNo}/simulation` 回傳模擬值；禁止寫正式量測日誌。

## 頁面實作

- `/YMES/QC/VariableQcItem` 已接入 Vue 3 三層選單及路由。
- DEV 預覽使用獨立 localStorage 假資料，含四種 IssueState、欄位查詢、單列/多列選取、新增/修改/複製/刪除/核准，以及 Parameter/Factor/Simulation/OP/SamplePlanChange/Memo 子視窗。
- UI 使用淺灰 WinForms Grid 標題、KD 黃色可編輯欄位；列表點選採 Vue 狀態更新。
- Production API 尚待家用端實作。此頁尚未執行 build、測試或瀏覽器驗收。
