# QC202 計數管制內容

## 功能識別

| 項目 | 內容 |
| --- | --- |
| MES 選單 | 品質資料 → 品管設定 → 計數管制內容 |
| FunctionNo / FunctionKey | SPC ATT LIMIT / QC202 |
| WinForms | QC_SPCAttLimit.dll：frmSPCAttLimit、frmSPCAttLimitDef |
| Vue 路徑 | /YMES/QC/AttributeControlLimit |
| 資料來源 | MESTEST.TBLSPCATTLIMIT；項目與因子沿用 QC201 主檔 |

## WinForms 畫面與操作

### 主畫面 frmSPCAttLimit

- 表單設計尺寸 1008×661，置中開啟。上方約 1008×256 的 Grid 顯示已核准計數品管項目：QCItemNo、QCItemName、Creator、CreateDate。載入時固定帶 IssueState=2，主畫面沒有狀態 Radio 或文字查詢欄。
- 點選上方項目列會直接載入該 QCItem 的管制內容及 FactorOnline=Y 要因。
- 下方區域包含左側管制內容 Grid、右側 RuleSet Grid，以及右側垂直按鈕：新增(A)、修改(E)、刪除(D)、複製(C)、關閉(X)。管制 Grid 顯示 US、LS、UCL、LCL、CL、線上動態要因、Creator/CreateDate、Reviser/ReviseDate；DataStamp 隱藏。點選管制列會把 RuleSet 拆成右側 RuleNo / RuleAction 列。
- 刪除可多選；使用者確認後逐列呼叫 DelSPCAttLimit，以 QCItemNo 與所有線上因子值定位。完成後重載目前項目。
- 新增需要先選一個 QCItem。修改與複製需要先選管制列。複製沿用同一 QCItem、界限、因子值及 RuleSet，因此儲存前必須改成未存在的因子組合。

### 編輯視窗 frmSPCAttLimitDef

- 設計尺寸 1008×591；QCItemNo 唯讀。左側上方為 Factor Grid，列出該 QCItem 所有 FactorOnline=Y 的因子；左側下方依序提供 US、UCL、CL、LCL、LS。右側為判別法則 Grid；底部沿用 COM_Kit.frmDefTemplat 的建立/修改人、日期，以及確定、套用、關閉按鈕。
- 新增、複製時可改因子值。ParameterType=2 允許直接輸入並轉大寫；其他類型透過 wsSYS.LoadMESParameterRef 查找值，並可 Clear。修改時因子值唯讀，界限與判別法則可編輯。Vue 目前以依 API 選項產生的下拉選單承接 WinForms 快搜視窗；正式可選值由 API 提供。
- 法則只載入 IssueState=2 的 LoadQCRule。逐列可勾選；RuleAction 選項是 Warning、Hold、Alert（Wait 為舊碼註解，不提供）。未選法則不寫入。RuleSet 格式為 RuleNo,RuleAction;RuleNo,RuleAction。
- UCL 必填；其餘四個界限可留白，但填入值必須為數字。按 US、UCL、CL、LCL、LS 順序比較已填值，必須由大到小；US 與 LS 同時有值時 US 必須嚴格大於 LS。每個線上要因空白會存成 *；至少須有一個 FactorOnline 要因。
- 新增/複製先以 QCItemNo + 全部線上因子值查重。修改把 DataStamp 作為並行版本，更新 Reviser/ReviseDate 並遞增 DataStamp。Apply 保存但留在視窗；Confirm 保存後關閉。

## WinForms 程式依據

- STD/MESWin/QC/QC_SPCAttLimit/frmSPCAttLimit.vb：載入已核准 QC Item、依選取列載入動態因子與管制列、主 Grid 欄位、Add/Edit/Delete/Copy、RuleSet 解析。
- STD/MESWin/QC/QC_SPCAttLimit/frmSPCAttLimitDef.vb：因子與法則選取、參數查找、界限驗證、Apply/Confirm、Factor 組合重複檢查。
- STD/MESws_STD/wsSTD/wsQC/wsQC.cs：LoadSPCAttLimit、AddSPCAttLimit、EditSPCAttLimit、DelSPCAttLimit；另載入已核准 QC Rule。
- STD/MESkc/kcQC/clsQCBasis.cs、STD/MESkc/kcBasis_UPD/clsBasis_UPD.cs：主表 CRUD。舊式 SQL 依 FactorNo 動態組成欄名；Edit 以 DataStamp 及 QCItemNo/因子組合更新。
- AddSPCAttLimitField 會在 Oracle 主表動態新增 FactorNo 欄位。API 不可把 request 傳來的 FactorNo 直接當 SQL 欄名執行；必須由該 QCItem 已核准的 FactorOnline 清單白名單驗證。

## 資料表與 Oracle DDL

- 主表 MESTEST.TBLSPCATTLIMIT 沿用 QC201 已透過 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 直接查 Oracle DBMS_METADATA.GET_DDL、ALL_TAB_COLUMNS、ALL_CONSTRAINTS、ALL_INDEXES 的結果，沒有用 DBeaver 操作畫面查 DDL，也沒有讀取業務列。
- Oracle 原始結構：database/reference/mestest_qc_spc_att_limit_source_ddl.sql；亦可在 database/reference/mestest_qc_item_attributes_source_ddl.sql 的 QC201 區塊核對。
- 固定來源欄位：QCITEMNO VARCHAR2(25) NOT NULL、UCL/LCL/CL/US/LS VARCHAR2(15)、RULESET VARCHAR2(500)、CREATOR VARCHAR2(10)、CREATEDATE DATE、DATASTAMP NUMBER(11,0) DEFAULT 0 nullable、REVISER VARCHAR2(10)、REVISEDATE DATE。來源沒有 PK、FK、唯一鍵；唯一索引外的索引為 I_TBLSPCATTLIMIT_01(QCITEMNO)。
- Oracle DDL 同時包含當時已建立的動態因子欄位（例如 MO、PRODUCT、EMPLOYEE、EQUIPMENT、CUSTOMER、MATERIAL、OP 等，VARCHAR2(61) DEFAULT *）。實際因子欄位由 QC Item 的 FactorOnline 動態新增，因此 DDL 清單不是封閉集合。
- QC Item 與 Factor 沿用 QC201 的 TBLQCITEMFORATTRIBUTES、TBLQCITEMFACTOR；法則沿用 TBLQCRULEBASIS；因子名稱/值選取沿用 TBLSYSMESPARAMETER 與 wsSYS.LoadMESParameterRef，不新建來源表。
- PostgreSQL 空表參考：database/reference/mestest_qc_spc_att_limit_create.sql。此 YMES 適配以 factorvalues JSONB 保存動態因子，而不是依使用者輸入新增資料表欄位；另外以 (qcitemno, factorvalues) 唯一鍵實現 WinForms 的新增查重。這是固定 schema 的 YMES 參考，不是 Oracle 原生欄位逐字轉換，也不是 migration；家用端須先核對 live schema 和既有 API 設計再決定是否沿用。

## Vue 與 API handoff

- Vue 頁依 WinForms 建立已核准 QC Item 清單、管制列、右側按鈕及 RuleSet 檢視；編輯視窗分為因子、界限、法則三區，保留 Apply/Confirm、複製、批次刪除及 DataStamp。DEV 使用獨立 localStorage 假資料，不連 MES Oracle。
- 既有 QC201 API 提供 GET /api/qc/attribute-qc-items?issueState=2 與 GET /api/qc/attribute-qc-items/{qcItemNo}/factors?factorOnline=Y。
- 新增 GET /api/qc/attribute-control-limits?qcItemNo={qcItemNo}，回傳限值列 {qcItemNo,factorValues,us,ls,ucl,lcl,cl,ruleSet,creator,createDate,reviser,reviseDate,dataStamp}。factorValues 是 {FactorNo: string}，空值正規化為 *。
- 新增 GET /api/qc/attribute-control-limits/options?qcItemNo={qcItemNo}，回傳目前 QC Item 的 FactorOnline 欄位名稱、FactorName、ParameterType、可選值，以及 IssueState=2 的 RuleNo/RuleName。ParameterType=2 可自由輸入；其他類型使用既有 MES Parameter reference 查找。
- 新增 POST /api/qc/attribute-control-limits，body 含 qcItemNo、factorValues、US/LS/UCL/LCL/CL、ruleSet；伺服器以登入者與時間建立稽核欄位。FactorNo 必須依已核准 FactorOnline 清單驗證；同一 QCItemNo + factorValues 不可重複。
- 新增 PUT /api/qc/attribute-control-limits/{qcItemNo}，body 含 originalFactorValues、界限、ruleSet、dataStamp；使用來源複合識別值與 DataStamp 做 CAS，更新 Reviser/ReviseDate 並遞增 DataStamp。來源 DataStamp nullable；NULL 必須以 IS NULL CAS，不能一律轉為 0。
- 新增 DELETE /api/qc/attribute-control-limits/{qcItemNo}，body {factorValues,dataStamp}；前端多選時逐筆呼叫，第一筆錯誤即停止並回報已成功刪除筆數。
- 所有端點要求登入及 FunctionKey QC202 權限。SQL 值須參數化；JSONB 因子鍵只接受核准白名單，不使用動態 SQL 欄名。確認 TBLQCITEMFORATTRIBUTES.IssueState=2，並在交易內執行新增/修改/刪除與重複/CAS 檢查。
- 家用端先比對 YMES live schema/migrations；mestest_qc_spc_att_limit_create.sql 僅在缺表且接受 JSONB 適配後參考，不能直接對 Oracle 或生產環境執行。QC202 規格和 API/SQL 待辦見 todolist_homepc.md。
