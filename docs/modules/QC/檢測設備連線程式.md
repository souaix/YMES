# QC503 檢測設備連線程式（Inspection Machine Driver）

## WinForms 定位與來源

- 功能路徑：品質資料 → 檢測儀器 → 檢測設備連線程式。FunctionNo=`INSPMACHINE DRIVER`、FunctionKey=`QC503`、IssueTable=`TBLQCINSPDRIVER`。
- 主 Form：`STD/MESWin/QC/QC_InspDriver/frmInspDriver.vb`；編輯 Form：`frmInspDriverDef.vb`。服務位於 `STD/MESws_STD/wsSTD/wsQC/wsQC.cs`；資料存取位於 `STD/MESkc/kcQC/clsInspMachine.cs` 與 `STD/MESkc/kcBasis_UPD/clsBasis_UPD.cs`；Function 選項由 `STD/MESud/udDriverFunction/clsDriverFunction.cs` 提供。
- Vue DEV 頁：`/YMES/QC/InspectionDrivers`，檔案 `web/src/components/QcInspDriverMaster.vue`。開發預覽寫入獨立 localStorage 假資料；正式模式使用下方 API contract。

## 主畫面

- WinForms 主畫面尺寸約 1008×591。共用 Form 上方提供 IssueState radio：未簽核(0)、簽核中(1)、已簽核(2)、不使用(-1)，初始為 0；搜尋欄固定為 InspDriverNo。查詢服務載入資料後由畫面依狀態過濾；來源未設排序。
- Grid 對 `TBLQCINSPDRIVER` 自動欄位顯示：InspDriverNo、FunctionName、Description、Creator、CreateDate、Reviser、ReviseDate；IssueState、DataStamp 隱藏。Description 欄寬 180、可多行；日期格式 `yyyy/MM/dd HH:mm:ss`。
- 右側按鈕 ADD、EDIT、DEL、Copy、Approve、Close。Find 按鈕在 Designer 預設隱藏。列點選作為目前資料；Delete/Approve 可用目前列或多選列。批次逐列呼叫服務，遇到第一筆錯誤停止，已成功的列保留結果並重新載入。
- 新增/複製後，主畫面重查並在未簽核狀態定位新增的 DriverNo。Edit 以目前列打開。

## 新增／修改／複製

- Def Form 尺寸 484×301；基本資料 GroupBox 約 460×157，欄位為 DriverNo、Function Name 下拉、Description 多行文字。下方顯示共用 Template 的建立/修改資料；按鈕為套用、確定、關閉。DriverNo 欄位離開時轉大寫。Edit 時 DriverNo 唯讀；Copy 清空新 DriverNo，保留 FunctionName 與 Description。
- DriverNo、Function Name 為必填。WinForms TextBox 沒有設定 MaxLength；資料庫限制 DriverNo 25、FunctionName 50、Description 255，Vue/API 依 schema 長度驗證。Description 可空。
- Function Name 並非任意輸入。`LoadInspDriverFunction` 以 reflection 列出 `clsDriverFunction` 的 private instance 方法名，只保留名稱包含 `FUNDR` 的方法。此版程式精確選項為 `funDrv_Thick`、`funDrv_Channel`、`funDrFunctionC`；三個方法目前都回傳 default string，僅是可選名稱，並非本分支已有有效的資料解析實作。API 必須從允許清單提供/驗證，不可接受任意函式名稱。
- Add/Copy 以新 DriverNo 建立 IssueState=0，Creator 由登入者取得、CreateDate 由 Core 使用伺服器目前時間。Edit 僅在 IssueState=0 執行；DriverNo 不可更換。FunctionName/Description 更新帶 DataStamp、Reviser、ReviseDate 條件並令 DataStamp + 1。舊 WinForms 呼叫以 Apply 留在表單，Confirm 儲存並關閉。
- `ExeIssueControl` 依狀態/控制項設定表單可編輯性。簽核中(1)不可編輯；已簽核(2)與不使用(-1)依共用 Issue Control 設定決定，API 應沿用同一規則；狀態不允許編輯時回傳衝突，不要仿照舊 ws 在非 0 狀態靜默成功但不更新。

## 核准、刪除、狀態

- 核准只接受 IssueState=0，必須帶 DataStamp；舊服務使用 IssueNo=`INSPMACHINE DRIVER` 查 IssueManagement。若沒有對應 Job 或沒有 Job Detail，直接改 IssueState=2；有 Job Detail 時建立 Issue Process，改為 Pending(1)，核准後轉 Active(2)、退回後回 Unfrozen(0)。前端不指定核准結果。
- Delete 在狀態 0 或 -1 時硬刪 `TBLQCINSPDRIVER` 單筆；狀態 2 時改成 -1，並更新 Reviser/ReviseDate/DataStamp；狀態 1 不允許。硬刪沿用 DriverNo、IssueState、DataStamp 條件。舊 `DelInspDriver` 沒有自行檢查 QC502 儀器是否引用 Driver，也沒有 Oracle FK；YMES API 需先檢視 live schema 關聯與現行 YMES 行為，若拒絕刪除被引用 Driver，應回清楚衝突並記錄這是較舊 MES 的保護行為差異。
- 刪除/核准為多筆逐筆處理，失敗即停止後續，不做整批交易回滾。

## 資料表與 DDL

- QC503 主表為 `TBLQCINSPDRIVER`，PK=`INSPDRIVERNO`。欄位：InspDriverNo VARCHAR2(25) NOT NULL、FunctionName VARCHAR2(50)、Description VARCHAR2(255)、Creator VARCHAR2(10)、CreateDate DATE、IssueState NUMBER(1,0) DEFAULT 0 NOT NULL、DataStamp NUMBER(11,0) DEFAULT 0（可 NULL）、Reviser VARCHAR2(10)、ReviseDate DATE。Oracle 表無 FK。
- Oracle source DDL 與 PostgreSQL 空表 CREATE-only 參考已隨 QC501–QC503 共用 DDL 建立於 `database/reference/mestest_qc501_inspection_machine_source_ddl.sql`、`database/reference/mestest_qc501_inspection_machine_create.sql`。QC503 不新增表、不新增重複 DDL。來源 SQL 不是可直接在 Oracle 執行的遷移；家用端只先比對 YMES live schema/migrations，確認缺表才設計 forward migration。

## YMES API handoff

登入保護端點，按 YMES 授權規約檢查 FunctionNo=`INSPMACHINE DRIVER` / FunctionKey=`QC503`。QC501/502 已共用下列 lookup，勿重複建立另一份資源。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/qc/inspection-drivers?issueState={state}&inspDriverNo={query}` | 狀態與 DriverNo 搜尋；回傳主 Grid/audit 欄位及隱藏的 IssueState/DataStamp |
| GET | `/api/qc/inspection-drivers/functions` | 回傳允許的 private `funDr*` 方法名稱；不可由 request 動態反射呼叫未核准方法 |
| POST | `/api/qc/inspection-drivers` | 新增；Creator/CreateDate/IssueState=0/DataStamp 由 server 維護 |
| PUT | `/api/qc/inspection-drivers/{inspDriverNo}` | 編輯 FunctionName/Description；body 帶 IssueState/DataStamp，主鍵不可修改 |
| DELETE | `/api/qc/inspection-drivers/{inspDriverNo}?issueState={state}&dataStamp={stamp}` | 狀態 0/-1 硬刪、狀態 2 軟刪為 -1；其他狀態拒絕 |
| POST | `/api/qc/inspection-drivers/{inspDriverNo}/approve` | 送 IssueNo=`INSPMACHINE DRIVER` 簽核；server 回傳直接 Active 或 Pending 的實際狀態 |

SQL 參數化；更新與狀態改變以主鍵+預期 IssueState+DataStamp CAS，audit 使用登入者。來源 DataStamp nullable+default；實作需核對 live data，妥善處理舊 NULL stamp，不得默默忽略 CAS。Create/Edit/Approve/Delete 寫入 YMES 操作稽核，Issue Job 建立與狀態更新應使用一致交易策略。QC502 共用 Driver lookup `GET /api/qc/inspection-drivers` 未指定 IssueState 時需保留舊服務可取得全狀態資料的能力。
