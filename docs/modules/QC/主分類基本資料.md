# QC401 主分類基本資料

## 功能來源

- MES 選單：品質資料 → 異常設定 → 主分類基本資料。
- Oracle 選單目錄：FunctionNo MCLASS BASIS、FunctionKey QC401、Form frmMClassBasis、ExecutionFile QC_MClassBasis.dll。
- WinForms 原始碼：STD/MESWin/QC/QC_MClassBasis/frmMClassBasis.vb、frmMClassBasisDef.vb；服務 STD/MESws_STD/wsSTD/wsQC/wsQC.cs；資料存取 STD/MESkc/kcQC/clsHoldBasis.cs。
- 主資料表：MESTEST.TBLQCMCLASSBASIS。
- 本規格根據 WinForms、Service/Core 原始碼與既有 Oracle 資料字典 DDL，不以畫面截圖推測資料規則。

## 主清單畫面

- frmMClassBasis ClientSize 為 1008×591，沿用 frmBasisTemplat 上方四種狀態單選與查詢列，預設未簽核 IssueState=0。
- 查詢欄位只有 MClassNo。Service 取回全部狀態，WinForms 再依狀態在本機篩選，按 MClassNo 排序。
- Grid 顯示 MClassNo、Description、Creator、CreateDate、Reviser、ReviseDate；IssueState、DataStamp 隱藏。Description 多行、欄寬 150；人員欄寬 80；日期欄寬 150，格式 yyyy/MM/dd HH:mm:ss。
- 右側按鈕順序：新增（ADD）、修改（EDIT）、刪除（DEL）、複製（Copy）、核准（Approve）；下方另有 MClassImport 與關閉。主清單可多選，以逐筆呼叫 Service 處理刪除與核准，第一筆失敗即停止並重載。
- Vue DEV 頁 /YMES/QC/MClassBasis 對照四狀態、單一 MClassNo 查詢、多選 Grid、右側同序按鈕和資料總筆數；表格標頭與輸入欄使用 KD 黃色系，稽核欄與狀態/DataStamp 不改成可編輯欄位。點選資料列只更新 Vue 狀態，不改 URL、不重新載入頁面。

## 新增／修改／複製表單

- frmMClassBasisDef ClientSize 484×282。主分類區位於 (12,5)、尺寸 460×50；說明區 (12,61)、尺寸 460×89；建立/修改資訊 (12,158)、尺寸 460×70；確定、關閉、套用按鈕位於表單底部。
- 欄位只有 MClassNo 與多行 Description。MClassNo 必填、Oracle 欄位上限 30；Description 可空、上限 255。新增時 IssueState=0，建立人/日期由表單提供；複製帶入來源編號與說明，但以新增處理，使用者需輸入不同的新編號。
- 修改時 MClassNo 唯讀，只更新 Description；建立資訊沿用原列，修改人/時間更新為目前使用者/時間。WinForms 呼叫 ExeIssueControl(IssueState, Me) 控制狀態欄位。Service/Core 實際只在 IssueState 0 或 2 更新；Vue 對簽核中及不使用列採唯讀，避免送出不會落庫的修改。
- 確定儲存並關閉；套用儲存並留在表單。DEV 頁使用本機假資料；Production 只送 MClassNo/Description，Creator、日期、IssueState、DataStamp 由 API 依來源規則維護。

## 刪除與簽核

- 刪除可多選；未簽核 0、不使用 -1 直接刪除；已簽核 2 不刪列，改為 -1，並寫入 Reviser、ReviseDate、DataStamp；簽核中 1 不允許刪除。WinForms 在刪除前提示確認。
- 核准只接受未簽核 0，可多選逐筆處理。Issue Job Map 使用 MCLASS BASIS：找不到 Job 或 Job 沒有 Detail 時直接改為已簽核 2；有簽核流程時建立 Issue，資料先改為簽核中 1，寄信通知第一簽核群組。流程核准後改為 2，退回後回到 0。
- DEV 假資料核准僅模擬無 Job 的直接 0→2 分支；Production 必須保留 Issue/Job/Detail、第一群組通知與退回語意。
- 刪除、修改、核准以 MClassNo、目前 IssueState 與 nullable DataStamp 做版本比對；版本衝突回 409，不能以使用者送來的資料覆寫 audit 欄位。

## Oracle 資料表與 CREATE SQL

此功能不需要新增 DDL 檔：TBLQCMCLASSBASIS 已由 PowerShell 5.1 + Oracle.ManagedDataAccess，透過公司端既有受保護連線唯讀查得，DDL 共用於 QC406 查找表檔案：

- Oracle 原始 DDL：[mestest_qc_first_group_lookups_source_ddl.sql](../../../database/reference/mestest_qc_first_group_lookups_source_ddl.sql)。
- YMES PostgreSQL 空表 CREATE SQL：[mestest_qc_first_group_lookups_create.sql](../../../database/reference/mestest_qc_first_group_lookups_create.sql)。

| 欄位 | Oracle 型別 | Nullable / 預設 | 用途 |
| --- | --- | --- | --- |
| MClassNo | VARCHAR2(30) | NOT NULL | 主鍵 |
| Description | VARCHAR2(255) | NULL | 說明 |
| Creator | VARCHAR2(10) | NULL | 建立人 |
| CreateDate | DATE | NULL | 建立時間 |
| IssueState | NUMBER(1,0) | NOT NULL DEFAULT 0 | 簽核狀態 |
| DataStamp | NUMBER(11,0) | NULL DEFAULT 0 | 樂觀版本 |
| Reviser | VARCHAR2(10) | NULL | 修改人 |
| ReviseDate | DATE | NULL | 修改時間 |

來源僅有 MClassNo 主鍵的 unique index，無外鍵及額外索引。Oracle DATE 在 YMES 對應 timestamp without time zone。既有 PostgreSQL CREATE SQL 已包含此表，不要再建立重複表；家用端先比對 live schema 與 migrations，只在缺漏時新增 forward migration，保留 YMES 擴充欄位。

## 匯入功能

WinForms 主檔透過 ObjectFileHandler.Execute("QC_MClassDataImport", ...) 開啟獨立的 frmMClassDataImport。該匯入器原始碼及資料檢查器已在以下位置核對：

- UI：STD/MESWin/QC/QC_MClassDataImport/frmMClassDataImport.vb 與 frmMClassDataImport.Designer.vb。
- 資料檢查器：STD/MEStc/DataImporter/MClassDataImporter.cs，方法 MClassDataChecker / ChkMClassNo。
- 匯入視窗 ClientSize 784×562；有唯讀檔案路徑、選檔、匯入、下載範本、進度/取消及結果 Grid。Template Update 隱藏。
- 接受 .xls/.xlsx，使用 NPOI 讀第一個工作表。跳過第 1 列；接著固定讀第 1 欄 MClassNo（必填）及第 2 欄 Description（可空），不檢查標題文字。公式會求值，數值/日期會轉成字串。
- 選檔後先按 MClassNo + Description 去除完全重複列。匯入時逐個 MClassNo 呼叫 checker；同一編號若有不同 Description，該組會因一次送入多列而失敗。已存在的 MClassNo 以大小寫不敏感方式拒絕；新編號轉大寫，狀態 0，Creator 為目前使用者，Description 空白時留用 Core 預設。每個 MClassNo 獨立執行，其他列失敗不會回滾已成功的列。
- 結果 Grid 顯示 MClassNo、Description、Message；存在成功列時主表單重載。使用者可取消尚未處理的後續列。
- Template Download 透過 wsSYS.funLoadFileExtension / GetTemplateFile 取得系統儲存範本；本次找到匯入程式，但沒有找到範本二進位檔。Production 應將原本系統範本經 YMES template service 提供，不可把 DEV 範例冒充官方檔。
- Vue DEV 暫以同欄序 CSV 預覽及 localStorage 假資料演示；.xls/.xlsx 解析、正式範本及 row-by-row server checking 由 API 提供。

## Vue 與 API 契約

- GET /api/qc/m-class-basis?searchFieldName=MClassNo&searchFieldValue=：回傳符合主分類編號搜尋條件的全部狀態與 audit/DataStamp；只允許 MClassNo 搜尋欄位，狀態由 UI 篩選。
- POST /api/qc/m-class-basis body { mClassNo, description }：驗證必填與長度，主鍵重複回 409；伺服器設定 Creator/CreateDate、IssueState=0，DataStamp 使用來源 DEFAULT。
- PUT /api/qc/m-class-basis/{mClassNo}?issueState=&dataStamp= body { description }：只更新 Description；僅 IssueState 0/2 執行，pending/unused 拒絕。MClassNo 不可修改；Reviser/ReviseDate 由伺服器設定，nullable DataStamp CAS。Update、Delete、Approve 都必須明確帶入 dataStamp query key；舊值為 NULL 時傳 `dataStamp=`，舊值為 0 時傳 `dataStamp=0`，省略時回 400，不得把漏傳當成 NULL。數字版本限 11 位數範圍內的整數。
- DELETE /api/qc/m-class-basis/{mClassNo}?issueState=&dataStamp=：0/-1 實體刪除、2 轉為 -1 並更新 audit/DataStamp、1 拒絕。
- POST /api/qc/m-class-basis/{mClassNo}/approve?issueState=0&dataStamp=：僅接受狀態 0，依 MCLASS BASIS Issue Job 規則直接核准或進入 Issue 流程，回傳實際 IssueState/DataStamp。
- POST /api/qc/m-class-basis/import/preview 接受 .xls/.xlsx multipart file，按 WinForms 第一工作表、首列跳過、前兩欄 mapping 與 distinct pair 規則回傳預覽列。
- POST /api/qc/m-class-basis/import 接受同一 Excel 檔並回傳每個 MClassNo 的 success/fail/message。逐編號單獨 transaction；大小寫不敏感檢查已存在主鍵；同編號多種 Description 回報重複資料；其餘筆照舊逐筆處理並保留部分成功。MClassNo 先以大寫辨識同一編號，Description 以原文字精確區分，`ABC` 與 `abc` 不會摺疊。新增 MClassNo 轉大寫、IssueState=0、Creator 為登入者。
- GET /api/qc/m-class-basis/import/template 提供舊系統 SYS template storage 中 MCLASS BASIS 的原始範本和設定副檔名；若 YMES 尚未遷移 template storage，需明確列為部署前置。
- 全部 API 要求登入與 FunctionKey QC401 功能權限；參數化 SQL、檔案大小/格式限制，不能把多列匯入包成全檔交易，並保留逐筆結果與部分成功。

## YMES 家用端實作

- API：`src/YMes.Api/Quality/Qc401Controller.cs`、`Qc401Models.cs`、`Qc401Repository.cs`；前端：`web/src/components/QcMClassBasisMaster.vue`；forward migration：`database/migrations/0029_qc401_m_class_basis.sql`。此 migration 從上述共用 DDL 只建立 QC401 的主分類表，不因此一次部署其他 QC 查找表；遠端套用與 live schema 核對由家用端部署流程確認。
- 全部端點明確使用 `[Authorize]`。依使用者目前決定，先提供登入後操作，不實作角色／FunctionKey ACL；上方來源規格的 QC401 功能權限仍是未來共用權限服務的接點。SQL 使用參數；主鍵必填、最長 30 字、轉大寫；Description 最長 255 字，空白保存為 NULL。服務依登入帳號與伺服器時間維護 audit，新增時使用來源 DataStamp DEFAULT，不接受前端任意指定 audit 或狀態。
- 清單回傳原始列陣列及全部狀態，由 Vue 篩選四種狀態。查詢只接受 MClassNo，採大小寫不敏感的文字包含比對，不把查詢值當 SQL wildcard。新增、修改、刪除、核准與匯入記錄操作帳號及結果；API 錯誤以 ProblemDetails 回傳，不暴露 SQL 或連線機密。
- 修改／刪除／核准先鎖定主分類列 `FOR UPDATE`，比對 IssueState 與 nullable DataStamp；SQL 以 `IS NOT DISTINCT FROM` 保留 NULL 與 0 的差別。修改或狀態變更後以 `COALESCE(datastamp,0)+1` 遞增版本；衝突回 409。0/-1 實體刪除前，在取得主列鎖後檢查已存在的次分類、品質異常原因、異常說明、首件群組、末件群組、計數／計量檢驗項目等引用表。引用資料存在時回 409；尚未部署的引用表不虛構資料。後續子表寫入 API 必須在指派主分類時取得同一主列的共用鎖，才能與刪除檢查協作。
- 核准目前只完成無 Issue/Job 表時的 0→2 分支。如果發現 Issue/Job 相關表存在，回 503 並保持資料不變，等待真正的共用簽核服務接入；尚未實作 Job Map、Issue 建單、通知、退回，不宣稱完整簽核流程。
- Vue 使用共用確認對話框。保存採 API 回傳的真實 DTO／DataStamp；新增或複製後按套用會切換修改模式，避免再次套用重複新增，這是與來源表單操作的明確差異。修改模式的套用持續沿用新版本。表單複製只處理 JSON DTO，使用 JSON round trip 避免直接 structuredClone Vue reactive proxy 產生 DataCloneError。多筆刪除／核准遇第一筆失敗即停止，再重載已完成的變更，保留原始錯誤訊息。

## 正式匯入範圍與限制

- 使用現有 ExcelDataReader 讀 `.xls/.xlsx` 第一個工作表，跳過首列、不驗證標題，讀前兩欄，忽略其他欄。檔案上限 5 MiB、資料列上限 10,000；無效、加密或不可讀的檔案回 400，非 Excel 副檔名回 415，超過檔案大小回 413。預覽不寫入資料庫。
- 預覽按「編號大小寫不敏感＋說明文字精確相同」去除重複列；同編號而說明只差大小寫仍保留為兩列，匯入時整組失敗。一般欄位或重複編號錯誤以逐筆 `fail/message` 回報，其他編號繼續處理，各自交易，不回滾已完成列。
- 如果處理到某組時發生資料庫例外或 503，停止後續寫入，仍以同一結果陣列保留先前 `success`、本次錯誤列及後續未處理列。未處理列使用 `result=fail`，Message 明確標示「尚未處理」；不回整批 503 而遺失已完成結果。資料庫連線若在提交時中斷，本列可能無法確認提交結果，Message 要求重新查詢確認，不假稱已回滾。Vue 列出成功及失敗／未處理筆數，存在成功列時重載主清單。
- 伺服器在各組間檢查 request cancellation，取消後列為尚未處理，已完成資料保留；目前 Vue 沒有來源匯入器的獨立取消按鈕，瀏覽器中斷連線也無法保證能收到結果陣列，應重新查詢確認。此項仍屬來源操作差異。
- Excel 公式只讀取檔案已儲存的計算結果（cached value），不會在伺服器重新計算。這與來源 NPOI 公式求值不同；匯入前須用 Excel 重新計算並儲存，不能宣稱完整重現來源公式引擎。
- 官方 `MCLASS BASIS` 原始 Excel 範本 binary 與 SYS template storage 尚未交付，`GET import/template` 明確回 503 及原因。DEV CSV 僅供本機假資料，不作正式範本或正式匯入替代品；Vue 會顯示 API 的實際 ProblemDetails。
