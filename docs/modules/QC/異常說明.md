# QC404 異常說明

## 功能識別

- 第一層：品質資料（`QC`）
- 第二層：異常設定
- 第三層：異常說明
- FunctionNo：`HOLD DESCRIPTION`
- FunctionKey：`QC404`
- WinForms：`frmHoldDescription`、`frmHoldDescriptionDef`
- WinForms 專案：`STD/MESWin/QC/QC_HoldDescription`
- Service/Core：`wsQC.LoadHoldDescription`、`AddHoldDescription`、`EditHoldDescription`、`DelHoldDescription`、`ApproveHoldDescription`；`clsHoldBasis`、`clsBasis_UPD`
- 主表：`MESTEST.TBLQCHOLDDESCRIPTION`
- Vue DEV 路徑：`/YMES/QC/HoldDescription`

## WinForms 主畫面

`frmHoldDescription` ClientSize 為 `1008×591`，Grid 位於 `(12,53)`，尺寸 `890×532`；右側垂直按鈕為新增、修改、刪除、複製、核准，右下角關閉。狀態篩選為未簽核 0、簽核中 1、已簽核 2、不使用 -1，預設未簽核。查詢欄位只有 `MClassNo`；Service 回傳全部狀態，WinForms 本機按狀態篩選。

Grid 顯示 `MClassNo`、`HoldDescription`、`Description`、Creator/CreateDate、Reviser/ReviseDate；`HoldDescriptionID`、`IssueState`、`DataStamp` 隱藏。`HoldDescription`、`Description` 可多行，前者欄寬 120，後者 150，日期格式 `yyyy/MM/dd HH:mm:ss`。Grid 支援多列選取；刪除、核准逐列呼叫，遇到第一筆失敗即停止並重載資料。

## 定義視窗與資料行為

`frmHoldDescriptionDef` ClientSize 為 `484×403`。上方 `異常說明` 群組含主分類編號與 `...` 查找、可多行的異常說明；下方 Description 多行欄位；底部顯示建立/修改人與時間，並有確定、關閉、套用。

- 新增/複製：主分類必填，來源候選透過 `wsQC.LoadMClassBasis` 載入。該 Service 未傳 IssueState 時預設為 2，因此只列已核准主分類。異常說明必填；Description 可空。
- 新增時 Core 以 `Guid.NewGuid().ToString()` 產生 `HoldDescriptionID`，狀態設 0；`MClassNo + HoldDescription` 沒有唯一限制，可存在相同文字的不同列。
- 複製會帶入 MClassNo、HoldDescription、Description，但按新增處理並產生全新 GUID，不沿用原 ID。
- 修改時 MClassNo 與 HoldDescription 設為唯讀/停用，只能修改 Description。`ExeIssueControl` 依狀態與系統設定控制欄位；Service/Core 更新接受狀態 0 或 2，拒絕 1、-1。
- MClassNo 最長 30，HoldDescription 最長 4000，Description 最長 255。前兩欄必填。建立/修改者與日期由表單及 Service 設定。
- 套用成功後留在視窗；修改時本機 DataStamp 加 1，新增/複製每次套用都建立新資料。

## 狀態、刪除與核准

| IssueState | 畫面 | 修改 | 刪除 | 核准 |
| ---: | --- | --- | --- | --- |
| 0 | 未簽核 | 可修改 Description | 實體刪除 | 可送核准 |
| 1 | 簽核中 | 不可修改 | 拒絕 | 不可重複送出 |
| 2 | 已簽核 | Service 接受修改；畫面欄位另受 Issue Control 控制 | 設為 -1 | 不可送出 |
| -1 | 不使用 | 不可修改 | 實體刪除 | 不可送出 |

多列刪除依主畫面選取順序逐筆執行：0/-1 實體刪除；2 呼叫 `SetHoldDescriptionIssueState` 設為 -1；1 拒絕。舊 Core 實體刪除未比對 DataStamp，狀態更新及一般編輯會用 DataStamp CAS 並遞增。YMES API 對實體刪除也應採 CAS，且支援來源 nullable DataStamp。

核准 Issue Job Map key 為 `HOLD DESCRIPTION`。找不到 Job 或 Job Detail 時直接設為 2；有簽核明細時建立 Issue，狀態設為 1，核准 SQL 設為 2、退回 SQL 設回 0，處理附件並通知第一簽核群組。Production API 應沿用 YMES Issue/Job 流程；DEV 假資料只模擬無 Job/Detail 時直接核准。

## YMES 前端/API handoff

Vue 元件 `web/src/components/QcHoldDescriptionMaster.vue`；三層選單 QC → 異常設定 → 異常說明。DEV localStorage key 為 `ymes-dev-mock:qc-hold-description:v1`。建議契約：

- `GET /api/qc/hold-descriptions?searchFieldName=MClassNo&searchFieldValue=` 回傳全部狀態與 audit/DataStamp；搜尋只允許 MClassNo，遵循 WinForms 共用查詢條件語意。
- `GET /api/qc/hold-descriptions/options/machine-classes?issueState=2` 只回已核准主分類；可重用 QC406 主分類查找實作，但需驗證 QC404 FunctionKey 權限。
- `POST /api/qc/hold-descriptions` body `{mClassNo, holdDescription, description}`；驗證欄位長度/必填與主分類已核准，伺服器產生 GUID `HoldDescriptionID`、設定 Creator/CreateDate、IssueState=0、DataStamp 初始值，回傳新建列（含 ID）。不加 MClassNo/HoldDescription 唯一限制。
- `PUT /api/qc/hold-descriptions/{holdDescriptionId}?dataStamp=` 僅更新 Description、Reviser/ReviseDate/DataStamp；ID/MClassNo/HoldDescription 保持不變。舊 Service 僅接受狀態 0/2，使用 DataStamp CAS，nullable 值以 `IS NULL` 比對。
- `DELETE /api/qc/hold-descriptions/{holdDescriptionId}?issueState=&dataStamp=`：狀態 0/-1 實體刪除，2 軟停用為 -1，1 回 409。多選由 UI 逐筆呼叫，首筆失敗即停止並回報已完成筆數。
- `POST /api/qc/hold-descriptions/{holdDescriptionId}/approve`：檢查狀態/DataStamp，依 `HOLD DESCRIPTION` Issue Job Map 直接啟用或啟動 Issue 流程；回傳目前 IssueState/DataStamp。

所有端點驗證登入及 FunctionKey `QC404` 權限、使用參數化 SQL；來源無 FK，不得 cascade 刪除主分類。Production API/schema 未部署前，此頁只使用 DEV 假資料。
