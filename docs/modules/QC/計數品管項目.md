# QC201 計數品管項目

## 功能識別

- 選單：品質資料 → 品管設定 → 計數品管項目；FunctionNo `QCITEM_A`、FunctionKey `QC201`。
- 主表單 `frmQCItemForAttributes`，DLL `QC_ItemForAttributes.dll`；主要來源 Form/Designer：`STD/MESWin/QC/QC_ItemForAttributes/frmQCItemForAttributes.vb`、`frmQCItemForAttributesDef.vb`、`frmQCItemReason.vb`。
- Service/Core：`STD/MESws_STD/wsSTD/wsQC/wsQC.cs`、`STD/MESkc/kcQC/clsQCBasis.cs`。主畫面還呼叫 `QC_ItemParameter`、`QC_ItemFactor`、`QC_SamplingParameterSimulation`、`QC_ItemOp`、`QC_SamplePlanChange` 共用功能。

## 主畫面 `frmQCItemForAttributes`

- ClientSize 1008×591；左側 Grid 為 890×531，右側垂直按鈕由 y=53 起，寬 88、高 32，間距約 8。功能按鈕順序：ADD、EDIT、DEL、Copy、Approve、Parameter、Factor、Reason、Simulation、Op、SamplePlanChange、Close。
- 頂端沿用共用 IssueState 四狀態選項：未簽核 0、簽核中 1、已簽核 2、不使用 -1；預設未簽核。查詢欄為 QCItemNo，WinForms 共用 Query Condition 可支援條件式搜尋。
- Grid 可見欄位順序：QCItemNo、QCItemName、LotIsValid、ComponentCollect、PlanNo、IsSampleSizeInteger、RuleNo、Creator、CreateDate、Reviser、ReviseDate。IssueState、ExecutionFile、DataStamp 隱藏；ZKT/KYT 才顯示 QCClass 欄，其他系統模式隱藏。
- 點 ADD 開啟新增表單；EDIT/COPY 對目前列開啟同一維護表單。修改後重新載入，並在未簽核清單中定位該列。
- DEL 可多選。未簽核/不使用資料實體刪除；已簽核資料依 service 規則轉為不使用。簽核中資料不提供刪除。舊 service 會先檢查 WIP、物料/物料類別、作業站、產品、計數群組綁定及 SPC 量測記錄；有引用或量測資料時拒絕刪除。通過後才清除 QC Item 子資料與特定關聯。這些檢查必須在 API 伺服器端執行，不能只在 Vue 隱藏按鈕。
- Approve 只接受未簽核列；舊 UI 逐列檢查該 QCItemNo 至少有一筆 Factor 定義及一筆 Reason 對應，再呼叫簽核服務。多選逐筆執行，遇第一筆錯誤即停止；每筆使用 DataStamp。
- Parameter、Factor、Reason、Simulation、Op、SamplePlanChange 需選中資料列才開啟。Parameter/Factor/Op/Simulation/SamplePlanChange 由共用功能 DLL 處理；Factor 以 `QCType=0` 開啟，Simulation 傳 `PlanOrQCItem=1`、QCItemNo/PlanNo，Op 傳目前項目狀態。

## 維護視窗 `frmQCItemForAttributesDef`

- ClientSize 662×527，欄位分在兩個 GroupBox，右下有 Confirm、Close、Apply。模式為 ADD、EDIT、Copy。
- 欄位：QCItemNo、QCItemName、Lot Valid Check（Yes/No）、Component Collect（Yes/No）、PlanNo（唯讀，按查找鈕選計劃）、RuleNo（查找）、Special Form Name、Description、MClassNo（唯讀查找）、Limit Lot Num、整數抽樣數選項及 QCClass。QCClass 僅 ZKT/KYT 顯示，選項 SPC/IPQC；SPK 模式隱藏 Lot Valid Check 與 Component Collect。
- 必填：QCItemNo、QCItemName、LotValidCheck、ComponentCollect、PlanNo、LimitLotNum；LimitLotNum 必須為正整數。ZKT/KYT 另要求 QCClass。輸入 MClassNo 後必須查到唯一有效主分類。EDIT 時 QCItemNo 唯讀並套用 Issue Control，DataStamp 用於 concurrency check。
- 新增時 IssueState=0，Creator/CreateDate 由登入者/系統時間帶入；Copy 產生新 QCItemNo，ComponentCollect 不允許變更。Copy 可勾選是否複製 Parameter、Factor、Reason、SamplePlanChange，WinForms 預設四項皆勾選；Parameter 與 Sampling Plan 參數不一致時會要求使用者選來源。
- ADD/COPY 呼叫 `wsQC.AddQCItemForAttributes`，EDIT 呼叫 `wsQC.EditQCItemForAttributes`；Apply 留在視窗並增加本地 DataStamp，Confirm 儲存後關閉。後端需以 transaction 保存主表與被勾選子表。

## 原因對應視窗 `frmQCItemReason`

- 兩側清單顯示 Selected/UnSelected ReasonNo/ReasonName，提供 ReasonType ValueList 及 ReasonLevel 條件、左右移動、多選、雙擊、Confirm、Close。
- Reason master 只載入 `IssueState=2`；Selected 由 `wsQC.LoadQCItemReason(QCItemNo)` 取得。Confirm 呼叫 `wsQC.UpdQCItemReason`，以交易替換 `TBLQCITEMREASONMAP` 中該 QCItemNo 的全部原因對應；取消不保存。
- ReasonType 選項使用系統 ValueList，不能將另一張表單硬編碼的代碼集合當正式清單。

## 來源資料與 DDL

- 主表 `TBLQCITEMFORATTRIBUTES`：QCItemNo PK；欄位含 QCItemName、LotIsValid、PlanNo、RuleNo、FormName、IssueState、Description、Creator/CreateDate、SampleSize、LimitLotNum、ComponentCollect、QCClass、MClassNo、IsSampleSizeInteger、ExecutionFile、DataStamp、Reviser/ReviseDate。原生表定義已在物料/QC 共用 DDL 檔。
- 主要子表：`TBLQCITEMPARAMETER` PK `(QCITEMNO,PARAMETERNO)`；`TBLQCITEMFACTOR` PK `(QCITEMNO,FACTORNO)`；`TBLQCITEMREASONMAP` PK `(QCITEMNO,REASONNO)`；`TBLQCSAMPLEPLANCHANGE` PK `(QCITEMNO,OLDSAMPLEPLAN,ACCLOTQTY,REJLOTQTY,LOTRANGE)`。本次四表僅有 PK unique index、無 FK；SamplePlanChange 的 LOTRANGE/AQLCHKFORSPLANCHG 使用 CHECK IS NOT NULL。
- Oracle raw DDL 與欄位/constraint/index metadata：[`database/reference/mestest_qc_item_attributes_source_ddl.sql`](../../../database/reference/mestest_qc_item_attributes_source_ddl.sql)。含主表、四張主要子表，以及舊 Delete cascade 會檢查/清理的相依資料表；僅查結構，未查業務列。
- YMES 主要子表 PG CREATE 參考：[`database/reference/mestest_qc_item_attributes_create.sql`](../../../database/reference/mestest_qc_item_attributes_create.sql)。主表另見 `mestest_mtl_qc_item_tables_create.sql`。這些 SQL 僅供家用端比對 live schema；不可在 Oracle 執行，也不可不經 schema 核對就全部套用。
- 舊刪除流程亦參照 `TBLQCITEMPRDREASONMAP`、`TBLQCITEMGROUPDETAIL`、`TBLSPCQCATTRULEMAP*`、`TBLQCSAMPLEPLANCHANGE`、`TBLSPC*LOG`、`TBLOPQCITEM` 等表。它們可能由 QC203/QC204/OP/歷史資料功能共用；家用端只重用或補必要缺項，不可為了 QC201 整批重建/清空。

## Vue/API handoff

- Vue 路徑 `/YMES/QC/AttributeQcItem`，選單階層為「品質資料 → 品管設定 → 計數品管項目」；WinForms FunctionNo `QCITEM_A`，權限 FunctionKey `QC201`。DEV 頁以獨立 localStorage 假資料執行，不連 API。
- 前端 API 契約：
  - `GET /api/qc/attribute-qc-items?issueState={0|1|2|-1}&search={QCItemNo}` 回傳清單；`POST /api/qc/attribute-qc-items` 新增；`PUT /api/qc/attribute-qc-items/{qcItemNo}` 修改並以 DataStamp 做版本檢查。
  - `DELETE /api/qc/attribute-qc-items/{qcItemNo}` body `{issueState,dataStamp}`；未簽核/不使用為實體刪除，已簽核改為不使用，簽核中拒絕。伺服器須重做舊 Core 的引用檢查並以交易處理 cascade。
  - `POST /api/qc/attribute-qc-items/{qcItemNo}/copy` body 為主資料欄位加 `copyParameters`、`copyFactors`、`copyReasons`、`copySamplePlanChanges`；新資料及所選關聯須同一交易新增。
  - `POST /api/qc/attribute-qc-items/{qcItemNo}/approve` body `{issueState,dataStamp}`；前端逐筆呼叫並在遇到第一筆失敗時停止。API 仍須在同一交易重驗狀態、DataStamp、Factor/Reason 前置條件及 Issue Job，不能信任 UI 預檢。
  - `GET /api/qc/attribute-qc-items/options` 回傳 `samplingPlans`、`attributeRules`、`mClasses`、`interfaces`、`showQcClass`、`showLotValid`、`showComponentCollect`；QCClass 是否顯示依 ZKT/KYT，Lot/Component 選項依 SPK 隱藏規則。`GET /api/qc/attribute-qc-items/options/reasons?issueState=2` 回傳可選原因；`GET /api/qc/attribute-qc-items/options/reason-types` 回傳 MES ValueList 的 `{value,label}`，不得以畫面 demo 值代替正式清單。
  - 子資源 `GET/PUT /{qcItemNo}/parameters`、`GET/PUT /{qcItemNo}/factors`、`GET/PUT /{qcItemNo}/reasons`、`GET/PUT /{qcItemNo}/operations`、`GET /options/operations?qcType=0&lotIsValid={0|1}`、`GET/PUT /{qcItemNo}/samplePlanChanges`、`POST /{qcItemNo}/simulate`。Reasons/Operations PUT 都以交易替換完整對應；Operations 必須保留 Inline、ExecuteOrder、QCItemType、FAI/IPQC/PQC、Reviser/ReviseDate。
- API 全部端點需登入與 QC201 權限；共用子功能若已有更細權限，保留原授權規則。SQL 必須參數化；DataStamp 過期回衝突；Copy、approve、delete cascade、多表保存以 server-side transaction 執行。
- Vue 已還原主 Grid、狀態查詢、右側 WinForms 按鈕、ADD/EDIT/COPY、Apply/Confirm、刪除/核准、Parameter/Factor/Reason/Op/SamplePlanChange 維護視窗及 Simulation 結果區。Op 使用左右清單；只有 IssueState=2 可調整，LotIsValid=0 時禁止加入 InLine，InLine 每筆必須勾選至少一種 FAI/IPQC/PQC 檢驗時機。Plan/Rule/MClass 查找鈕目前為簡化選取器，正式資料由 options API 提供；Op Production API 尚待家用端。
- 家用端處理 schema 前，先比對 `database/reference/mestest_mtl_qc_item_tables_source_ddl.sql`、`mestest_mtl_qc_item_tables_create.sql`、`mestest_qc_item_attributes_source_ddl.sql`、`mestest_qc_item_attributes_create.sql` 與 YMES live schema/migrations。主表 CREATE 已在 MTL 共用 SQL；本次 CREATE 只含四張直接維護子表。Raw DDL 中其餘刪除關聯表不得整批建立或清空，只有 API 必要且 YMES 確認缺少時才新增 forward migration。
