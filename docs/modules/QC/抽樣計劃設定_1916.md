# QC102 抽樣計劃設定_1916

## 功能識別與來源

- MES 第一層：品質資料 → 第二層：基本資料 → 第三層：抽樣計劃設定_1916。
- FunctionNo：`SAMPLING 1916`；FunctionKey：`QC102`；IssueOption=0，沒有簽核狀態或 Issue Job。
- WinForms：`STD/MESWin/QC/QC_Sampling1916/frmSampling1916.vb`、`frmSampling1916Def.vb`。
- Service/Core：`wsQC.LoadSampling1916`、`AddSampling1916`、`EditSampling1916`、`DelSampling1916`；`STD/MESkc/kcQC/clsQCBasis.cs`；修改採用 `STD/MESkc/kcBasis_UPD/clsBasis_UPD.cs`。
- 主表：`MESTEST.TBLQCSAMPLING1916`。Oracle DDL 及 PostgreSQL 空表 CREATE 參考位於 `database/reference/mestest_qc_sampling_1916_source_ddl.sql`、`mestest_qc_sampling_1916_create.sql`。

## WinForms 畫面與操作

### 清單 `frmSampling1916`

- ClientSize 為 1008×591。上方只有 `Attributes`、`Variables` 兩個 RadioButton，初始為 Attributes；沒有查詢條件、狀態篩選、匯入、Download 或 Print。
- 開啟時一次載入全表，RadioButton 只在前端依 `SamplingType` 篩選：0=Attributes（計數），1=Variables（計量）。
- Grid 欄位順序：`SamplingType`（隱藏）、`SLevel`、`MinNum`、`MaxNum`、`SampleNum`、`KValue`、`FValue`、`RejectNum`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`、`DataStamp`（隱藏）。Attributes 模式隱藏 K/F；日期格式為 `yyyy/MM/dd HH:mm:ss`。
- 右側按鈕由上而下：ADD、EDIT、DEL、Copy；Close 固定在右下。ADD 開啟空白定義窗；EDIT/COPY 以目前作用列開窗；雙擊資料列在 Web 版可進入 EDIT。
- DEL 會把作用列加入選取集合，允許多選；確認視窗預設取消。逐列呼叫刪除，第一筆失敗即停止，之前成功的刪除不回復，最後重新載入清單。

### 定義窗 `frmSampling1916Def`

- ClientSize 為 489×398，標題 `Sampling 1916`。Sampling 群組包含唯讀的 Attributes/Variables 模式與 SLevel、MinNum、MaxNum、SampleNum、RejectNum、KValue、FValue；下方顯示建立/修改人與時間。
- Edit 時 SLevel、MinNum、MaxNum 唯讀；Add/Copy 可輸入。Attributes 模式停用 KValue/FValue，Variables 模式啟用。
- SLevel 離開欄位時轉大寫；Add/Copy 預設 RejectNum=1。Add/Copy 按 Apply 成功後保留表單，MinNum 設為前筆 MaxNum+1、清空 MaxNum，方便連續新增區間。Edit 按 Apply 成功後保留表單並更新 DataStamp；Confirm 成功後關閉。
- Apply 初始停用，欄位異動後啟用；表單不追蹤「值是否真的不同於原值」，而是追蹤欄位是否曾觸發變更事件。

## 欄位與資料庫結構

| Oracle 欄位 | PostgreSQL 參考型別 | Nullable / 預設 | UI / 規則 |
| --- | --- | --- | --- |
| SamplingType | varchar(25) | NOT NULL | 0=Attributes，1=Variables；畫面由模式 RadioButton 帶入 |
| MinNum / MaxNum | numeric(8,0) | NOT NULL | 必填數字；MinNum 不得大於 MaxNum；定義唯一區間上下界 |
| SLevel | varchar(6) | NOT NULL | 必填；離開欄位轉大寫 |
| SampleNum | numeric(6,0) | NULL | UI 必填、不得小於 0；Service 傳入 Integer |
| RejectNum | numeric(6,0) | NULL | UI 必填、不得小於 0，且不得大於 SampleNum；Add/Copy 預設 1 |
| KValue / FValue | numeric(10,3) | NULL | 僅 Variables 必填且須為數字；Attributes 不使用 |
| Creator / Reviser | varchar(10) | NULL | 由伺服器以登入者維護 |
| CreateDate / ReviseDate | timestamp without time zone | NULL | 由伺服器維護 |
| DataStamp | numeric(11,0) | NULL DEFAULT 0 | Edit 以舊值比對，成功後遞增 1 |

- Oracle 有四個 NOT NULL 欄位約束；`PK_TBLQCSAMPLING1916` 是 `(SamplingType, MinNum, MaxNum, SLevel)` 的獨立 unique index。Oracle `ALL_CONSTRAINTS` 沒有 P/PK constraint，沒有 FK 或其他 index。因此 PostgreSQL CREATE 參考保持為獨立 unique index，不額外宣告 PRIMARY KEY 或 FK。
- 不要把來源 DDL 參考直接當 migration 執行；家用端先比對 YMES 現有 schema/migrations，保留 YMES 擴充欄位。

## 驗證與舊系統邏輯

- 儲存前依序檢查 SLevel 必填、MinNum/MaxNum 必填且為數字、MinNum≤MaxNum、SampleNum/RejectNum 必填且為數字/非負，RejectNum≤SampleNum。
- Variables 另外要求 KValue/FValue 必填且為數字；WinForms 沒有替兩者設定額外正負範圍。
- 唯一索引防止相同 SamplingType、MinNum、MaxNum、SLevel 重複。Web 表單也會先提示重複；API/資料庫仍須作為最終檢查。
- Core 抽樣解析 `ShowParameter_Sampling1916`：Population=1 時直接回 SampleQty=1、RejectQty=1，不查區間表；其他情況依 SamplingType、忽略大小寫的 SLevel 及含端點區間 `MinNum <= Population <= MaxNum` 配對。若 SampleNum 大於 Population 且系統旗標 `SQtyCanBBiggerThenPQty=0`，SampleQty 截為 Population。Variables 模式另回傳 KValue/FValue；找不到區間會丟出錯誤。API 若供檢驗流程使用，需實作相同解析規則，不可只把主檔 CRUD 當作完整抽樣邏輯。

## Vue DEV 頁與 Production API 契約

- Vue 頁：`web/src/components/QcSampling1916Master.vue`；路由 `/YMES/QC/Sampling1916`；fallback 選單掛在 QC → 基本資料。
- 開發預覽資料只存在 `localStorage` key `ymes-dev-mock:qc-sampling-1916:v1`；不讀 MES 業務資料。Production 透過獨立 API base URL 和 Cookie 認證呼叫 API。
- API 建議：
  - `GET /api/qc/sampling-1916`：回傳全表及 audit/DataStamp；UI 依 `samplingType` 在前端切換。
  - `POST /api/qc/sampling-1916`：body `{ samplingType, minNum, maxNum, sLevel, sampleNum, rejectNum, kValue, fValue }`。Creator/CreateDate 由登入者與伺服器時間建立。
  - `PUT /api/qc/sampling-1916/{samplingType}/{minNum}/{maxNum}/{sLevel}?dataStampIsNull=&dataStamp=`：body `{ sampleNum, rejectNum, kValue, fValue }`；複合鍵唯讀，CAS 成功後維護 Reviser/ReviseDate/DataStamp。由於來源 DataStamp 可空，需保留 NULL 與 0 的差別。
  - `DELETE /api/qc/sampling-1916/{samplingType}/{minNum}/{maxNum}/{sLevel}`：依完整複合鍵刪除；多筆刪除由 UI 逐筆呼叫，首錯停止並保留先前已成功刪除的結果。
- 所有 API 必須驗證登入和 FunctionKey `QC102`，使用參數化 SQL；不需要 IssueState/簽核 API。重複複合鍵回傳明確衝突，DataStamp 不符回傳 409。
