## WinForms 畫面與資料

- Form ClientSize 為 1008×591。UltraGrid 位於 (9,9)，大小 904×572，四邊錨定；右上為 DEL (&D)，右下為 Close (&X)，兩按鈕寬 80、高 32。
- Grid 的 GroupByBox 隱藏、使用固定欄位標頭，CellClickAction=CellSelect。使用者可點選單列或多選列；本頁沒有新增、修改、搜尋或核准按鈕。
- Form Load 依序呼叫 LoadQCItemForVariables(IssueState=-1)、LoadQCItemForVariables(IssueState=0) 並合併資料。因此清單只列「不使用」及「未審核」的計量型品管項目，不列簽核中或已核准資料。
- Grid 可見欄位順序：QCItemNo、QCItemName、ChartType、SpecLineType、ComponentCollect、LotIsValid、PlanNo、ChartControl、CollectType、LimitLotNum、SampleSize、Unit、QCDataType、Creator、CreateDate、Reviser、ReviseDate。IssueState、CalType、DataStamp 為隱藏欄。
- 原始碼對 SpecLineType 欄位也設定 ChartType 標題；Vue 頁保留這個重複標題，以符合 WinForms 顯示。欄位值仍依 SpecLineType 顯示。
- ValueList：ChartType 0=X-R、1=X-S、2=X-Rm；SpecLineType 0=Upper/Lower Control、1=Upper Control、2=Lower Control、3=Not Control；ComponentCollect、LotIsValid、ChartControl 0=N、1=Y；CollectType 0=Manual、1=Automatic；QCDataType 0=Particle、1=InLine、2=OffLine。
- 刪除前以 Ok/Cancel 確認。使用者可只點目前列作單筆刪除，也可選取多列；表單依選取列順序逐筆呼叫 Service，完成後重新載入清單。

## WinForms 刪除邏輯

### Service 狀態判斷

- 此頁每筆傳 QCItemNo、IssueState 和 Log=Log。
- Service 僅在 IssueState=0 或 -1 時呼叫 Core 的量測記錄刪除模式。IssueState=2 會走另一條「設為不使用」路徑，但本頁載入條件不會帶出 2；其他狀態拒絕。
- Log=Log 是服務端模式旗標，代表只刪量測記錄。Vue 呼叫專用 API，不接受瀏覽器傳任意旗標、表名或 SQL。

### Core 刪除表與順序

Core 先查 TBLSPCVARFACTORLOG 是否存在該 QCItemNo 的記錄；查詢大小寫不敏感。若筆數為 0，回傳 0000-200003（No Measure records Exist），不執行刪除。若有記錄，刪除以下資料：

1. TBLSPCVARSTATISTICLOG：依 QCItemNo。
2. TBLSPCVARLIMITCONTENT：依 SPCSerial，序號取自 TBLSPCVARDETAILLOG 中相同 QCItemNo 的資料。
3. TBLSPCVARVIOLATIONCONTENT：同上。
4. TBLSPCVARDETAILLOG、TBLSPCVARDETAILONLINE、TBLSPCVARFACTORLOG、TBLSPCVARFACTORONLINE、TBLSPCVAREDITLOG：依 QCItemNo。
5. TBLQCSAMPLEPLANCHANGE、TBLSPCLOGFORSPLANCHANGE：依 QCItemNo。

Log=Log 分支不刪 QC Item 主檔、Parameter、Factor 或其他設定，也不執行一般主檔刪除的線上 OP/WIP 綁定檢查。

### 舊程式訊息落差

- Core 刪除完成後會丟出 0000-000001（All Measure Data have been deleted）作為成功訊息，但 Service 將例外包成 fail；WinForms 會把訊息顯示出來並繼續處理其他已選列，最後重新載入。
- YMES API 應把已提交的刪除回傳成功；找不到量測資料回可辨識的 404/409。每個 QCItemNo 各自使用單一 DB transaction，避免某個項目的刪除只完成一部分。

## Vue 頁面與 API handoff

- Vue 3 頁面：/YMES/QC/VariableMeasurementDelete，DEV 預覽使用獨立 localStorage 假資料。表格標頭及選取底色使用使用者指定的黃橘色系；其餘結構比照 WinForms 的大 Grid、右側刪除及右下關閉。
- 清單沿用 QC205 的 GET /api/qc/variable-qc-items?issueState=-1 與 ?issueState=0。回應需含本規格所列可見欄位及 IssueState；IssueState、DataStamp 不顯示。
- 新增 POST /api/qc/variable-qc-items/{qcItemNo}/measurement-log-deletions，JSON body 為 { "issueState": 0 | -1 }。使用者瀏覽器只提交資源識別碼及顯示狀態；伺服器重新讀取 QC Item、核對真實 IssueState、確認 FunctionKey QC210 權限後執行。
- Service 端固定採量測日誌刪除模式。忽略或拒絕任何用戶端傳入的 Log、資料表名稱、SQL 或任意條件。
- 單筆 API 呼叫須在同一 transaction 驗證 QC Item 狀態、確認 TBLSPCVARFACTORLOG 有資料、刪除上述關聯表並寫入操作稽核。回應至少含 QCItemNo、各表刪除筆數及結果。多選由 Vue 逐筆呼叫；一筆失敗不阻止其餘選取項目，頁面分別顯示成功及失敗項目，與 WinForms 逐筆處理一致。
- PostgreSQL 空表 CREATE 參考為 database/reference/mestest_qc210_variable_measurement_log_delete_create.sql，包括 9 張量測日誌表的來源欄位、PK 與非 PK 索引。TBLQCSAMPLEPLANCHANGE 沿用 mestest_qc_item_attributes_create.sql，不可重複建立。
- Oracle source DDL 沿用先前以 PowerShell 5.1 + Oracle.ManagedDataAccess 直連 MESTEST 唯讀擷取的 mestest_qc205_variable_dependencies_source_ddl.sql、mestest_qc205_theil_custom_source_ddl.sql 與 mestest_qc_item_attributes_source_ddl.sql；本次只重新核對保存的結構參考，未再連 Oracle、未讀業務資料。
- 家用端須先比對 YMES live PostgreSQL schema 與已部署 migration。參考檔不是已套用的 migration；只為缺少的表或欄位新增 forward migration，保留現存資料，Oracle 端不得執行任何 CREATE。
