## WinForms 畫面與互動

- Form ClientSize 為 784×561。上方參數 Grid 群組約 784×160；下方資料 Grid 群組約 784×398；底部 24px StatusBar 顯示 UserNo、SystemDateTime、狀態。
- 上方 Grid 顯示 `ParameterNo`、`ParameterName`、`TableName`。使用者選取或啟用一列後，程式立即載入該參數的資料表；此 Form 沒有 QC109 的 `DetailData` 按鈕。
- 下方 Grid 根據 Table metadata 動態產生欄位，可在底部新增列、直接編輯儲存格及刪除選取列。右側 80px 操作欄依序為 `Delete`、`Import`、`Paste`、`Save`、`Close`。
- `IS_NULLABLE=false` 的儲存格以 KD 淡黃色標示。每個儲存格編輯完成會轉成大寫。欄位名稱在 Save 前驗證：首字元為英文字母，其餘只允許英文字母、數字及底線。
- 切換參數時若有未儲存變更，詢問是否放棄；選擇放棄後載入新參數。Close 按鈕亦會確認未儲存資料。Save 前詢問確認，成功後重新讀取目前參數資料。
- `Import` 接受 CSV、XLS、XLSX；匯入只更新 Grid，仍須按 Save。`Paste` 將剪貼簿的欄列資料從作用中儲存格貼入，超出現有列時新增列。Delete 只先刪除 Grid 的作用中列，直到 Save 才提交整份內容。
- Save 使用 `wsQC.UpdFactorMaintain`，參數為 `ParameterNo`、DataSet Schema/Data 與 `FirstData=true`。舊 Core 依參數目錄的 `TableName`/`Condition` 刪除指定範圍，再 array binding 插入目前 Grid 全部資料；沒有 DataStamp。Web API 必須用單一 transaction 包住刪除與插入，空 Grid 代表清空 Condition 範圍，任何插入錯誤都 rollback。

## 資料來源與查詢條件

Form 載入時呼叫 `wsSYS.LoadMesParameter`，篩選 `IssueState=2`、`ParameterType=0`、`ParameterClass=0`，另加 `TableName LIKE 'FC_%'`。選取參數後以 `ParameterNo` 呼叫 `LoadMesParameterRef` 取得該參數資料，再以 TableName 呼叫 `LoadTablesConstraints` 取得欄位 metadata。

API 必須從登入者授權範圍內重新讀取 ParameterNo 設定；不得信任瀏覽器傳入 TableName、FieldName、Condition、schema 或 SQL。只允許經伺服器 metadata 驗證的 YMES schema/table/columns。QC110 的 `ParameterClass=0` 與 QC109 的 `ParameterClass=1` 必須分別套用並各自驗證 FunctionKey。

## Oracle DDL 與 YMES schema

QC110 和 QC109 共用 `FC_%` 動態資料表機制。本次已從 Oracle metadata 取得的三張表 DDL 已隨 QC109 規格交付，無須複製或重新建立另一份 DDL：

- Oracle 原始 DDL：[`mestest_qc_factor_maintain_source_ddl.sql`](../../../database/reference/mestest_qc_factor_maintain_source_ddl.sql)
- PostgreSQL 空表參考：[`mestest_qc_factor_maintain_create.sql`](../../../database/reference/mestest_qc_factor_maintain_create.sql)
- 參數目錄：`TBLSYSMESPARAMETER`（`ParameterNo` PK；`ParameterClass` 決定此功能的目錄範圍）
- 動態表：`FC_POSIONLIST`、`FC_QCFORMCALLBACKITEMMAP`、`FC_THICKNESS`。各表完整 nullable/default/key 以既有 DDL 為準。

上述 Oracle 查詢只讀取表名、DDL 及資料字典 metadata，沒有讀取 MES 業務列，也沒有在 Oracle 執行 DDL。家用端需先比對 YMES live schema/migrations，只有實際缺少時才新增 forward migration；不可 drop/recreate 已存在資料表或匯入 MES 資料。

## Vue DEV 頁與 API handoff

公司端頁面以本地 DEV 假資料展示同一組三表 metadata，使用獨立 localStorage key，參數編號加上 `DEV-QC110-` 前綴，與 QC109 假資料隔離。Production 不使用假資料，頁面以參數列選取事件立即載入下方 Grid，沒有 DetailData 按鈕；欄位名稱驗證、KD 黃色必填格、大小寫轉換、Import/Paste/Delete/Save/Close 與 StatusBar 對應 WinForms。

建議以 FunctionKey `QC110` 保護以下獨立 API 路徑：

- `GET /api/qc/special-basis-maintain/parameters`：回傳 `IssueState=2`、`ParameterType=0`、`ParameterClass=0` 且 TableName 符合 `FC_%` 的參數清單。
- `GET /api/qc/special-basis-maintain/parameters/{parameterNo}/data`：依已授權的 ParameterNo 回傳 tableName、metadata 欄位與依舊設定排序/Condition 範圍內的資料列。
- `PUT /api/qc/special-basis-maintain/parameters/{parameterNo}/data`：驗證欄位名稱、完整欄位集合、型別、長度及 NOT NULL；單一 transaction 先刪除 Condition 範圍再插入整份 Grid，錯誤 rollback，空列清單表示清除此 Condition 範圍。
- `POST /api/qc/special-basis-maintain/parameters/{parameterNo}/import-preview`：解析 WinForms 支援的 Excel 檔並只回傳 preview rows，不寫入資料庫。CSV 可由 Vue 本地解析。Paste/Import 都先修改前端 Grid，再由使用者按 Save。

後端不可執行目錄中未驗證的任意 Condition SQL；若舊 Condition 無法安全轉換，使用 server-side 固定 predicate 對照，並記錄環境差異。完整套用 YMES 登入與 QC110 功能授權於清單、metadata、資料讀取、匯入預覽及更新端點。
