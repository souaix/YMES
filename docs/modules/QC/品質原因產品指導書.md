# QC112 品質原因產品指導書

## 功能識別

- WinForms 選單：品質資料 → 基本資料 → 品質原因產品指導書。
- FunctionNo：`QC REASON PRD SOP FILE`；來源表單：`frmReasonPrdSOPFile`；來源元件：`QC_ReasonPrdSOPFile.dll`。
- 關聯表：Oracle `MESTEST.TBLQCREASONPRDSOPFILE`；YMES PostgreSQL 目標名稱建議 `"YMES".tblqcreasonprdsopfile`。
- 來源程式：`STD/MESWin/QC/QC_ReasonPrdSOPFile/frmReasonPrdSOPFile.vb`、`frmReasonPrdSOPFileMaintain.vb`、`frmReasonPrdSOPFileImport.vb` 及 Designer。

## WinForms 畫面與互動

### 主畫面 `frmReasonPrdSOPFile`

- ClientSize 為 1008×591。左側上方是品質原因 Grid，下方是所選原因的產品指導書 Grid；右側有 `PrdSOPFileMaintain`、`Import`、`Close`。
- 上方清單只載入 `IssueState=2` 的品質原因，呼叫 `wsQC.LoadReasonBasis`。欄位包括 ReasonNo、ReasonName、ReasonLevel、ReasonType、ReasonSubType、Description、Creator、CreateDate、Reviser、ReviseDate；IssueState、DataStamp 不顯示。
- ReasonType 顯示值來自 `TBLQCREASONBASIS.REASONTYPE` ValueList。WinForms 維護對話框對代碼 0/1/5/6 顯示 Scrap/Defect/Adjust/EQP；`ReasonSubType` 在 SPK 系統模式隱藏。
- 使用者選取品質原因後呼叫 `wsQC.LoadReasonPrdSOPFile(ReasonNo)` 更新下方 Grid。顯示 ProductNo、SOPFileName、PRDSOPFilePath；服務回傳的 SOPFilePath 不直接當作畫面欄位。
- 主畫面不提供獨立 Save；維護視窗的新增/移除立即呼叫服務。Close 關閉功能頁。

### 維護視窗 `frmReasonPrdSOPFileMaintain`

- ClientSize 為 858×536。所選 ReasonNo、ReasonName、ReasonType、ReasonLevel 唯讀；ProductNo 查詢輸入與 Search；File Path 選檔；左右兩個清單 `UnSelected`、`Selected` 和移動按鈕。
- Search 呼叫產品主檔服務，僅找 `IssueState=2`、`CurVersion=1` 的產品；ProductNo 使用包含式查詢，輸入 `*` 表示不限制產品編號。空白查詢會提示錯誤。
- UnSelected 清單顯示 ProductNo；Selected 清單顯示 ProductNo、檔名。支援多選、左右箭頭及雙擊移動。
- 新增前必須選檔及至少一筆產品。允許 JPG、JPEG、JPE、JFIF、PNG、BMP、PDF。每個 `(ReasonNo, ProductNo)` 建立一筆關聯，SOPFileName 儲存檔名，SOPFilePath 儲存伺服器檔案路徑。
- 移除會逐筆呼叫舊 `DataImporter.QCItemRPDReasonSOPFileImporter.ReasonPrdSOPFileRemoveChecker`。舊端依結果決定是否也刪除實體檔案；來源樹沒有該 DataImporter 實作，無法確認共用檔案的完整判斷規則。YMES API 必須先確認其他關聯是否仍引用同一路徑，再決定刪檔。
- 來源使用檔案服務參數名稱 `FILESERVICETYPE`、`FILESERVICEHOST`、`FILESERVICEUSERNAME`、`FILESERVICEPASSWORD`、`REASONPRDSOPFILEPATH`。只記錄參數名稱；值屬環境設定，不可送到瀏覽器、文件或 Git。

### 匯入視窗 `frmReasonPrdSOPFileImport`

- ClientSize 為 704×530。提供工作簿選擇、Template DownLoad、Import、Close；匯入期間顯示進度及 Cancel。表格欄位為 ReasonNo、ProductNo、FileName、FilePath、Message。
- 舊版讀取第一張工作表，首列作欄名，依序讀取 ReasonNo、ProductNo、FileName、FilePath；前三欄必填，FilePath 可空。每列分別執行檢查及上傳，結果回寫 Message，並顯示進度。
- 範本使用 FunctionNo `QC REASON PRD SOP FILE`；舊版以 `wsSYS.LoadTemplateFile` 下載。Designer 的 Template Upload 按鈕維持隱藏。
- WinForms 工作簿接受 XLS/XLSX；舊 Importer 的來源實作不在本來源樹，檔案檢查、重複/核准規則需家用端對照 YMES 現有服務後落實。
- Web 安全限制：瀏覽器不能把 Excel 中任意 `FilePath` 當成伺服器可讀路徑。Web 頁要求使用者另外選取附件，依 FileName 配對；API 解析工作簿、驗證列並逐筆回傳成功/失敗。不得讓 API 任意讀取用戶端提供的伺服器路徑。

## Oracle 結構與 YMES SQL

- Oracle DDL 由公司端 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 直接唯讀取得，來源為 MESTEST 資料字典，未查詢 MES 業務資料、未執行 Oracle DDL。
- `TBLQCREASONPRDSOPFILE` 欄位：`REASONNO VARCHAR2(20) NOT NULL`、`PRODUCTNO VARCHAR2(50) NOT NULL`、`SOPFILENAME VARCHAR2(100) NULL`、`SOPFILEPATH VARCHAR2(2000) NULL`。
- PK `(REASONNO, PRODUCTNO)`，只有 PK unique index；沒有 FK、DataStamp 或其他索引。
- 原始來源 DDL：[`database/reference/mestest_qc_reason_prd_sop_file_source_ddl.sql`](../../../database/reference/mestest_qc_reason_prd_sop_file_source_ddl.sql)；PostgreSQL 結構參考：[`database/reference/mestest_qc_reason_prd_sop_file_create.sql`](../../../database/reference/mestest_qc_reason_prd_sop_file_create.sql)。套用前由家用端核對 YMES live schema/migrations，只補實際缺少結構並保留 YMES 擴充。
- 不需要為 QC112 複製品質原因或產品主檔；沿用 YMES 已有 QC106 品質原因與產品主檔資料/API。

## Vue 頁與 API handoff

- Vue 頁：`/YMES/QC/ReasonProductSOPFile`；FunctionKey 使用 `QC112`，正式頁所有清單、附件、範本、匯入及修改端點均需登入與功能授權。
- 主畫面載入已核准原因，選列後以 ReasonNo 動態載入關聯；DEV 預覽僅用標示清楚的 localStorage 假資料，不讀寫正式 MES 資料。
- 建議 API 契約：
  - `GET /api/qc/reason-product-sop-file/reasons?issueState=2`
  - `GET /api/qc/reason-product-sop-file/reasons/{reasonNo}/files`
  - `GET /api/qc/reason-product-sop-file/products?issueState=2&currentVersion=1&search=...`
  - `POST /api/qc/reason-product-sop-file/reasons/{reasonNo}/products/{productNo}/file`（multipart：file、sopFileName）
  - `DELETE /api/qc/reason-product-sop-file/reasons/{reasonNo}/products/{productNo}/file`
  - `POST /api/qc/reason-product-sop-file/import/preview`（multipart 工作簿；回傳預覽列）
  - `POST /api/qc/reason-product-sop-file/import/item`（multipart 單列與附件；逐筆驗證、寫入並回傳結果）
  - `GET /api/qc/reason-product-sop-file/import/template`
- 檔案只由 API 存取既有 YMES 檔案儲存服務。憑證及內部實體路徑只留在伺服器端；刪除關聯與實體檔案需安全處理共用引用及交易失敗情況。
- 主畫面仍保留 WinForms 的檔案路徑欄；API 應回傳可顯示的邏輯路徑/別名，不能把內部實體儲存路徑或憑證回給瀏覽器。
- 目前表單/前端已建立 API 呼叫契約；家用端需核對實際 schema、存檔服務、模板來源、權限目錄及舊 checker 規則，正式 API 尚待實作和驗收。

## 家用端 live audit（2026-11-17）

- YMES 已有 QC112 `tblsysfunction.functionkey` 與「品質資料 → 基本資料」menu item；`tblprdproductbasis` 已存在。
- YMES 缺少 `tblqcreasonbasis` 與 `tblqcreasonprdsopfile`，尚未載入 MES 業務資料。
- Production `tblsyselementbasis` 找不到五個檔案服務設定名稱；`ymes-api` 沒有 file-service 設定或程式碼，容器只有 Data Protection 持久卷，主機沒有 NFS/CIFS 掛載。實際舊檔案 checker、服務端儲存/範本服務及使用者功能授權資料表仍待查明。
- 初步盤點使用者/系統表未發現 user-function 權限對照表；新增功能先需沿用現有登入保護並查明 YMES 權限模型，不能假稱已做 QC112 function ACL。
