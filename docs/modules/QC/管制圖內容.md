# QC301 管制圖內容（QC Chart Basis）

## 功能與來源

- MES 第一層：品質資料；第二層：計量規格設定；第三層：管制圖內容。
- WinForms：`frmQCChartBasis`（`QC_ChartBasis.dll`），資料編輯 Form：`frmQCChartBasisDef`，跨 QC Item 複製 Form：`frmQCChartCopy`。Rule 編輯開啟 QC Chart Rule 模組的 `frmQCChartRuleDef`。功能碼 QC301。
- 專案程式來源：`D:\iMES\CSiMES\STD\MESWin\QC\QC_ChartBasis`、`D:\iMES\CSiMES\STD\MESWin\QC\QC_ChartRule`、`D:\iMES\CSiMES\STD\MESkc\kcQC\clsQCBasis.cs`、`D:\iMES\CSiMES\Customer\Production\MESws_STD\wsSTD\wsQC\wsQC.cs`。
- 公司端 Web：`/YMES/QC/ChartBasis`，Vue 元件 `web/src/components/QcChartBasisMaster.vue`。Development Preview 使用本地假資料，Production API 尚待家用端建置。

## WinForms 版面

- 主視窗 ClientSize 為 1008×591。上方是計量 QC Item Grid（QCItemNo、QCItemName、QCDataType、ChartType、SpecLineType、ComponentCollect、Unit、LotIsValid、PlanNo）；選取 QC Item 後載入其管制圖。
- 狀態列提供 `UNFROZEN`、`PENDING`、`ACTIVE`、`UNUSED` 四個 RadioButton，IssueState 對應 0、1、2、-1。主畫面右側垂直操作鈕為 Add、Edit、Del、Copy、Approve、Disapprove、Rule、Copy2、Close。
- 中段管制圖 Grid 依 QC Item 的 `FactorOnLine='Y'` 動態顯示要因欄，再顯示 SampleSize、PlanNo、KeyNode、ChartTitle、Sponsor、Creator、CreateDate、ChartUnit、Memo、Reviser、ReviseDate 等欄位。Grid 依 CreateDate 遞減排序；FactorSerial、IssueState、DataStamp 等欄位供操作使用。
- 下方有 `Detail` 與 `Rule` 頁籤。Detail 顯示 SPCID、US/CS/LS、UCL/CL/LCL、Target、CpkGoal、YAxisFrom/YAxisTo；Rule 顯示 SPCID、RuleNo、RuleName 與 Action。選取主檔列時會重新載入兩組明細。
- `frmQCChartBasisDef` ClientSize 為 844×591，含 QC Chart Basis 與 QC Chart Detail 群組。基本欄位為 QCItem、Factor、Serial No、SampleSize、KeyNode、ChartTitle、Unit、Sponsor、PlanNo、MEMO；FactorSerial 由系統管理。Sampling Plan 區可載入/清除參數列。下方依 ChartType 顯示圖表規格與控制界限，並有 Clear、Get Plan Parameter、PlanNo/Factor 選取按鈕及確定/關閉/套用。
- `ChartType` 來自已核准 QC Item，不在編輯表單改選：0=Xbar-R（Trend、Xbar、R）、1=Xbar-S（Trend、Xbar、S）、2=X-Rm（X、Rm）。SPCID：0=Trend/X，1=Xbar，2=R，3=S，4=Rm。

## 查詢、欄位與資料邏輯

### QC Item 與管制圖

- QC Item 清單由 `wsQC.ShowQCItemForVariables` 提供。WinForms 不傳 IssueState 篩選，因此清單不應只限 ACTIVE QC Item；包含 ChartType、SpecLineType、ComponentCollect、Unit、LotIsValid、PlanNo、SampleSize 等欄位。
- QC Item 的 FactorOnline 清單由 `wsQC.ShowQCItemFactor` 提供。FactorOnLine=Y 的欄位作為動態要因值；FactorSpec=Y 的要因用於規格組合/核准重複檢查。建立/修改時，舊 Form 要求每個顯示的 Factor 值皆有輸入；核准時不得將 `*` 當作實際要因值。YMES 必須用已核准 FactorNo 白名單與 JSONB，不可把 FactorNo 拼成 SQL 欄名或動態 ALTER TABLE。
- WinForms 讀取 `ShowQCChartBasis(QCItemNo, IssueState=全部)`，接著在前端依 Radio 狀態過濾。Web API 可直接帶 `issueState` 篩選，但必須維持各狀態語意。
- Detail 由 FactorSerial 讀 `TBLSPCQCCHARTDETAIL`；Rule 由 FactorSerial 讀 `TBLSPCQCCHARTRULE` 並 LEFT JOIN `TBLQCRULEBASIS` 顯示 RuleName。Sampling Plan 參數由 `TBLSPCQCCHARTSAMPLANPARAMETER` 依 FactorSerial 讀取。

### 新增與修改

- 新增從目前選取 QC Item 帶入 QCItemNo/Name、SampleSize、Unit、PlanNo、ChartType、SpecLineType、FactorOnline、FactorSpec 與 ComponentCollect；新資料預設 IssueState=0，FactorSerial 由伺服器產生。
- Core 新增成功時會讀 `TBLQCITEMRULE`，將該 QC Item 已設定的 SPCID/RuleNo/Action 複製到新 `TBLSPCQCCHARTRULE`。YMES POST 必須在同一筆新增交易內套用既有 QC Item Rule 對應；`TBLQCITEMRULE` 為共用既有表，不新增 CREATE SQL。
- 編輯載入既有要因值、基本欄位、各 SPCID Detail 以及 Sampling Plan Parameter。表單送出主檔欄位、要因、圖表 Detail、MEMO 與參數資料；修改帶 FactorSerial、IssueState、DataStamp，舊 Form 的確定按鈕要求填寫修改原因 MEMO。
- SampleSize 必須為大於 0 的整數；ChartType=2 的 X-Rm SampleSize 必須等於 1。數值欄位只接受數字；各圖表 YAxisFrom 小於 YAxisTo。SpecLineType=0 時 Trend 的 US/LS 必填，=1 時 US 必填，=2 時 LS 必填。舊 Form 對 UCL/CL/LCL/CS/Target/CpkGoal/Y 軸欄位執行數值檢查。
- 若指定 PlanNo 且 ComponentCollect=0，需載入至少一筆抽樣計畫參數；PlanNo 不可只以文字假設為有效，API 要確認抽樣計畫存在且核准。
- Update 主檔/要因/Detail/抽樣參數須使用單一資料庫交易及 DataStamp 樂觀併發檢查。Audit Creator/Reviser 與時間由登入身份及伺服器時間產生。

### 核准、取消核准、刪除

- Approve 僅對 UNFROZEN 項目執行。Core 依 QC Item、Factor 要因組合查重；重複時拒絕核准。若 Issue Management Job 沒有 Detail，直接更新為 ACTIVE(2) 並新增 Detail Log；有簽核 Job 流程時先建立 Issue，再進 PENDING(1)，完成簽核後才 Active。控制界限修訂亦會新增 Detail Log。
- Disapprove 僅接受目前 ACTIVE(2) 或 UNUSED(-1)，回到 UNFROZEN(0)，並更新 DataStamp/Reviser/ReviseDate。Web API 須呼叫 YMES 共用 Issue 流程，避免直接改狀態略過簽核紀錄。
- Delete：0 或 -1 為實體刪除；2 為改標 UNUSED(-1)；其他狀態拒絕。實體刪除前 Core 檢查 `TBLSPCVARDETAILLOG` 是否已有此 FactorSerial 的量測資料，有資料時不得刪除。硬刪範圍含 QC Chart Basis、Detail、Detail Log、Rule、Chart Sampling Plan Parameter；所有刪除需在同一交易中完成。
- 舊 UI 在多選列逐筆呼叫刪除/簽核服務。Vue 保留單筆選取互動；Production API 可以提供批次 endpoint，但每筆結果須明確回報，錯誤不可被整批成功掩蓋。

### 複製與 Rule

- Copy 將選取的同一 QC Item 管制圖複製成新 FactorSerial；可調整要因值及圖表設定，副本 IssueState=0。
- Copy2 開啟 `frmQCChartCopy`，指定 From/To QC Item 和 Copy Type：3=UNFROZEN+ACTIVE、0=UNFROZEN、2=ACTIVE。來源與目標的規格 Factor 清單必須完全相同；舊 Core 複製 basis、Detail、Rule 與 Sampling Plan Parameter。複製後依舊系統流程產生新 serial，不能覆蓋目標原資料。
- `Rule` 按鈕開啟 `frmQCChartRuleDef`。Rule 對每個 SPCID 設定已核准的計量 RuleNo 與 Action（0 Warning、1 Wait、2 Hold、3 Alert）；同一 FactorSerial/SPCID/RuleNo 不重複。`wsQC.UpdQCChartRule` 會依 FactorSerial+SPCID 更新規則集合。

## 資料表與 DDL

- Oracle MESTEST chart basis、detail、detail log、rule 的 DDL/index 已由 QC302 透過 PowerShell 5.1 + Oracle.ManagedDataAccess 直接唯讀取得：`database/reference/mestest_qc302_spc_qc_chart_source_ddl.sql`。QC301 所需抽樣參數表另於本次直接查 Oracle metadata：`database/reference/mestest_qc301_chart_sampling_parameter_source_ddl.sql`。
- 本次新增抽樣參數表的 PostgreSQL 空表 CREATE 參考：`database/reference/mestest_qc301_chart_sampling_parameter_create.sql`；QC Chart 四張表的 PostgreSQL CREATE 參考：`database/reference/mestest_qc302_spc_qc_chart_create.sql`。這些檔案是 schema 對照參考，不是已部署 migration。
- `TBLSPCQCCHARTSAMPLANPARAMETER` Oracle 欄位為 FactorSerial VARCHAR2(50)、ParameterNo VARCHAR2(20)、ParameterValue VARCHAR2(50)，PK=(FactorSerial,ParameterNo)，沒有 FK/額外索引。
- `TBLSPCQCCHARTBASIS` 的 FactorOnline 欄在 Oracle Core 動態管理；YMES 用 `factorvalues JSONB` 承接。家用端先比對現有 PostgreSQL schema/migrations 與 API 查詢，確認缺少結構才建立 migration。QC301 須沿用 QC302 對 `(qcitemno,factorvalues)` 查重的資料一致性分析。
- 核准/刪除還會讀寫 QC Rule、Issue/Job 與 SPC 量測日誌等共用表。不可因本規格有 CREATE 參考就重建共用資料表；先查 YMES schema 與既有 QC API。
- Oracle 查詢僅使用受保護本機連線查 DDL/index metadata；未讀業務資料列，也未在 Oracle 執行 DDL。IP、帳號、密碼、SID 不寫入文件或 Git。本次公司端不連 YMES PostgreSQL。

## YMES API handoff（家用端）

下列是 Vue 元件目前採用的建議契約；若家用端已有相同資源，請沿用現有路由並同步修正元件與規格。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/qc/chart-bases/qc-items` | WinForms 原查詢不限制 IssueState；回傳計量 QC Item 與 FactorOnline/FactorSpec 欄位 |
| GET | `/api/qc/chart-bases?qcItemNo={no}&issueState={state}` | 一個 QC Item 下指定狀態的管制圖 |
| GET | `/api/qc/chart-bases/{factorSerial}/detail` | 圖表規格/控制界限 |
| GET | `/api/qc/chart-bases/{factorSerial}/rules` | RuleNo、RuleName、SPCID、Action |
| POST | `/api/qc/chart-bases` | 新增 basis、FactorValues、Detail、SamplingPlanParameters |
| PUT | `/api/qc/chart-bases/{factorSerial}` | 修改 basis、FactorValues、Detail、SamplingPlanParameters；要求 DataStamp |
| DELETE | `/api/qc/chart-bases/{factorSerial}` | 0/-1 實體刪除、2 標 UNUSED；body 帶目前 IssueState/DataStamp |
| POST | `/api/qc/chart-bases/{factorSerial}/approve` | 查重並送 Issue Job；回傳實際 IssueState 0/1/2 |
| POST | `/api/qc/chart-bases/{factorSerial}/disapprove` | ACTIVE/UNUSED 退回 UNFROZEN |
| PUT | `/api/qc/chart-bases/{factorSerial}/rules` | 交易式替換 Rule 集合 |
| POST | `/api/qc/chart-bases/copy` | 跨 QC Item 複製；body 有 FromQCItemNo、ToQCItemNo、CopyType(3/0/2)，回傳 CopiedCount |
| GET | `/api/qc/sampling-plans?issueState=2&componentCollect={n}` | 只列核准且 ComponentCollect 相符的 PlanNo |
| GET | `/api/qc/sampling-plans/{planNo}/parameters?issueState=2` | 核准抽樣計畫參數 |

- 所有 endpoint 要求登入；依使用者目前指示，FunctionKey/角色 ACL 暫緩。Audit 身份由伺服器登入資訊取得，不信任 request 的 Creator/Reviser。
- FactorSerial、IssueState、DataStamp 都要由伺服器重查。Approve/Disapprove/Delete/Copy 需套用 YMES 共用 Issue、量測資料存在檢查與權限服務；FactorNo/ParameterNo 一律作為值參數化處理，不得組成 SQL identifier。
- 新增與修改一律單交易寫入 Basis/Detail/抽樣參數；新建同交易複製已存在 `TBLQCITEMRULE` 的預設 Rule。Rule 編輯以獨立交易更新 Rule 集合；刪除一律單交易。Copy 的來源與目標 QC Item FactorSpec 必須完全相符，並由伺服器管理新 FactorSerial。
- 現有四張 chart 表的 CREATE 參考包含 FactorValues JSONB 及 QCItem/FactorValues 建議唯一限制；套用前查 live duplicates 及 schema。不能直接在既有 populated schema 上套 reference CREATE。

## 家用端 YMES API/schema 實作狀態（2026-11-17）

- QC301 API 已實作 Vue 所需的 chart item/list/detail/rules CRUD、狀態、Copy2 與 sampling-plan lookup 路徑；HTTP controller 由 API 全域登入政策保護。新增時使用交易建立 Basis/Detail/DetailLog/Rule/抽樣參數；修改使用 DataStamp CAS。FactorNo 只作為 FactorOnline 白名單內的 JSONB key，不作為 SQL identifier。Rule 儲存完成回傳新 DataStamp，Vue 會更新目前列的快取。
- QC301 專屬抽樣參數表 migration `database/migrations/0025_qc301_chart_sampling_parameter.sql` 已套用 YMES PostgreSQL。套用前備份 `/opt/ymes/backups/ymes_before_0025_qc301_20261117.dump` 已通過 `pg_restore --list`；live schema 已核對欄位、複合主鍵及 `ymes_app` SELECT/INSERT/UPDATE/DELETE 權限。
- Live YMES 尚缺共用 `TBLQCITEMRULE`、`TBLQCRULEBASIS`、`TBLQCSAMPLINGPLAN`、`TBLQCSAMPLINGPARAMETER`、`TBLSPCVARDETAILLOG` 及 Issue/Job workflow tables。需要預設規則/抽樣計畫的新增、規則編輯、Sampling Plan options 和需要量測資料保護的實體刪除，會回 503 並指出缺少相依資料；不略過規則複製、不把缺少量測表當成無量測資料。已有 chart 表和 QC Item/Factor 表不會被重建。
- Issue/Job table 目前全數缺少，故 approve 在確認沒有任一流程表時直接切至 ACTIVE 並新增 DetailLog；若之後部署流程表，approve/disapprove 會先回 503，待接上共用 Issue/Job service 後才允許操作。QC audit 現階段記錄於 API service log，尚無專用耐久操作 audit table。
- `GET /api/qc/sampling-plans?componentCollect=n` 只有當 live plan schema 能提供並驗證該分類時才會回資料；目前 plan master 缺少，endpoint 回 503。遠端 `ymes-api`、`ymes-web` 已部署且 healthy；API readiness=200、QC301 Web route=200、未登入 API=401。app-browser 已登入檢視 QC301 頁及四種 IssueState 篩選，頁面正常載入。Live 計量 QC Item 清單為空，新增/修改/核准等按鈕無可用對象，因此業務 CRUD 尚未端到端驗證；需等 QC Item 與共用 Rule/Plan/measurement schema/資料可用後補驗。
