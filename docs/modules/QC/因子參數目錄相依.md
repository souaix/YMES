# 因子參數目錄相依：TBLSYSMESPARAMETER

## 狀態與共用範圍

此文件記錄共用參數目錄的結構相依，沒有另建一套要因資料維護功能。既有業務規格為 [QC109 要因資料維護](要因資料維護.md)、[QC110 特殊主檔維護](特殊主檔維護.md)；選單 inventory 中的系統「MES參數」為 `MES PARAMETER / SS202`。`QC105` 是品質原因子類別資料，不是本表的系統維護功能碼。

`0051_qc_parameter_reference.sql` 已由家用端於 2026-11-19 在確認缺表、備份並驗證備份可讀後套用。只補真實結構及參照鎖定所需權限；建表不代表已交付 provider 或已有正式參數資料。

## 原生 DDL 與轉譯核對

- 權威為 `database/reference/mestest_qc_factor_maintain_source_ddl.sql` 的 `MESTEST.TBLSYSMESPARAMETER`；同檔另外三張 FC 表不在本次 migration 範圍。
- 逐欄對照 `mestest_qc_factor_maintain_create.sql` 與本次草稿，完整16欄且首欄 ParameterNo 未遺漏。原欄位次序、長度／數值 precision-scale、NULL、DEFAULT 與 PK 相同；沒有直接搬入 Oracle storage／tablespace 設定。
- `VARCHAR2(n)` 依專案既有參照映為 `varchar(n)`，不按未知 bytes 設定自行擴欄。Oracle `DATE` 映為既有參照的 `timestamp without time zone`；這是邏輯轉譯，PG 型別可接受小數秒，並不宣稱 Oracle DATE 的儲存格式／精度完全相同。此草稿不更改既有日期、時區或其他表。

## 家用端只讀 live audit（2026-11-19）

PPK／SSH 僅在 `BEGIN READ ONLY` 查 `pg_catalog`、角色與 ACL；未連 Oracle、未讀業務列、未執行 DDL／DML。跨 schema 且不分 relation 名稱大小寫搜尋 `tblsysmesparameter`，結果沒有 table／partitioned table／view／materialized view／foreign table。缺表不是「表有0筆資料」，本次未執行業務 COUNT。

- `YMES` schema存在；`ymes_app` CONNECT／USAGE=true，CREATE=false，非 superuser、不可 createdb／createrole、無 bypass RLS、NOINHERIT。
- `ymes_app` 不是 `pg_read_all_data`／`pg_write_all_data` 成員；postgres在全域及YMES沒有表級 default ACL。因此以本次核對的 postgres 身分套用時，不會藉其預設ACL額外授予CRUD；若改用其他建表角色，須先重查該角色的 default ACL。
- 表不存在，現有 table／column grant 不適用，不能記為已授權或已完成 lookup。草稿僅授予表級 SELECT、欄級 `UPDATE(parameterno)` 供 row-locking SELECT；不授予 INSERT、DELETE 或表級 UPDATE，不授予其他欄位 UPDATE。真正維護 writer 的 DML 由其 owner 在實作與驗證時另外提出。
- 可重讀的 metadata SQL：`.tools/qc_parameter_reference_live_audit.sql`；實際結果：`.tools/qc_parameter_reference_live_audit_20261119.json`。DDL 三方逐欄比對結果：`.tools/qc_parameter_reference_schema_comparison_20261119.json`。前一次 audit helper 因 schema字串重複引號而查詢失敗，修正後重跑成功；兩次都為只讀交易，沒有套用 SQL。

## ParameterType 與 provider 界線

已交付文件可證實的語意：QC109 的 Form 明確以 `ParameterType=0`（Table）、`ParameterClass=1`、`IssueState=2` 且 TableName符合 `FC_%` 查詢；QC110 使用相同 Table 型別但 ParameterClass=0。[QC302 計數品管項目判別法則對應](計數品管項目判別法則對應.md)等因子使用文件另明載 `ParameterType=2` 為自由文字。尚未交付完整 SS202／SYS enum、Type1及其他代碼的 provider switch；不能只看到 FunctionName 欄便猜 Type1 可執行任意函式。

建表不會產生任何核准參數，也不會提供 `LoadMesParameterRef` 的候選值、Table／Function provider 或 Condition 解譯。未建三張 FC 表、未補 ValueList 猜測欄位、未新增 Type2 示範列、未匯入 MES 業務參數。

目前部分消費端為相容清單使用 `COALESCE(parametername,factorno)`、`COALESCE(parametertype,0)`。當表或對應 ParameterNo 列不存在時，顯示出的名稱與0是程式 fallback，不是已查到真實 metadata；不能因此把該因子認定為已核准 Table 型別或開放候選／寫入。0051 只準備真實結構，不修改目前已部署 QC source；各消費端仍須區分「目錄未提供／列缺少／列未核准／已核實的型別」，不得以空表或 fallback 宣稱相依已完整。

後續 provider 必須由 server 按已授權 ParameterNo 查回核准目錄，驗證 TableName／FieldName 的 schema allowlist及 Condition 對應；不直接接受前端 SQL，也不將未核實的 Condition字串當任意SQL執行。此為後續服務工作，本草稿沒有新增 API／前端、沒有取得額外資料，也不宣稱 GUI或抽樣引擎已通過。
