# 計數品管項目匯入（QC215）

## 功能識別

- WinForms FunctionNo：`IMPORT QCITEM ATTRIBUTES`
- FunctionKey：`QC215`
- Form：`frmImport_QCItem_Attributes`
- DLL：`QC_Import_QCItem_Attributes.dll`
- 選單：品質資料 → 品管設定 → 計數品管項目匯入
- 原始碼：
  - `STD/MESWin/QC/QC_Import_QCItem_Attributes/frmImport_QCItem_Attributes.vb`
  - `STD/MESws_STD/wsSTD/wsQC/wsQC.cs` 的 `ImportQCItem_Attributes`
  - `STD/MESkc/kcQC/clsQCBasis.cs` 的 `ImportQCItem_Attributes`、`DelQCItemForAttributes`

## WinForms 畫面與操作

表單 ClientSize 為 1008×591，標題 `Import Attributes QCItem`，置中顯示。左側約 902×569 的 UltraGrid 填滿表單，右側固定按鈕順序：`File`、`Check Data`、`Save`、`Template DownLoad`、`Select All`、`UnSelect All`、`MultiSelect`、`Close`。按鈕大小約 80×32。

Grid 匯入欄位唯讀；`Select` 勾選欄可編輯，`Execute` 顯示每列執行結果，內部 `Result` 欄隱藏並控制底色。錯誤列粉紅色；儲存成功列取消勾選、唯讀並呈灰色。Grid 支援刪除資料列；只有 `Select=True` 的列會送到 Service。

## Excel 欄位與範本

- File 對話框篩選 `.xls`，讀第一個工作表。範本由 `wsSYS.GetTemplateFile` 依 FunctionNo=`IMPORT QCITEM ATTRIBUTES` 提供，檔名 `AttributesQCItem_Template`，副檔名依 MES 設定為 `.xls` 或 `.xlsx`。
- 工作表第 1 列是欄名；舊程式自第 3 列起讀資料，因此第 2 列是被跳過的範例/說明列；遇第一個全空白列停止。`QCItemNo`、`PlanNo`、`MClassNo` 大寫化，其餘值去除前後空白；所有輸入儲存格以字串傳送。
- 核心欄位：`QCItemNo`、`QCItemName`、`LotIsVaild`、`PlanNo`、`ComponentCollect`、`RuleNo`、`Description`、`LimitLotNum`、`MClassNo`、`FactorNo`、`FactorOnline`、`InlineOP`、`OfflineOP`、`INSPTYPE_FAI`、`INSPTYPE_IPQC`、`INSPTYPE_PQC`、`Reason`、`Creator`、`CreateDate`。Factor、OP、Reason 清單用分號 `;` 分隔。
- Web production 的 `/preview` 必須解析 `.xls/.xlsx` 第一工作表並保留這個範本相容規則；DEV 本機頁支援 `.xlsx/.csv`，CSV 是 Web 開發輔助格式。`Select`、`Result`、`Execute` 若出現在上傳檔會忽略；空欄名轉為 `unknow{欄位索引}`。

## Core 驗證規則

每列依序驗證並回傳第一個錯誤：

| 欄位／條件 | 規則 |
| --- | --- |
| QCItemNo | 必填；若 `TBLSPCATTBASISLOG` 已有量測記錄，拒絕匯入。舊 Core 允許同 QCItemNo 在其他引用檢查通過時覆寫現存主檔。 |
| QCItemName | 必填。 |
| LotIsVaild | 必填，整數 0 或 1（來源欄位拼字）。 |
| PlanNo | 必填。`ComponentCollect=0` 時一般抽樣計畫必須有抽樣參數；`ComponentCollect=1` 時必須是存在的 Wafer 抽樣計畫。 |
| ComponentCollect | 可空白，預設 0；只能 0 或 1。設為 1 時 LotIsVaild 必須為 1。 |
| RuleNo | 可空白；有值時須是已核准計數型法則，且 ComponentCollect=0/1 必須與法則的收集類型相符。 |
| Description | 可空白，預設空字串。 |
| LimitLotNum | 必填正整數。 |
| MClassNo | 可空白；有值時需存在於 `TBLQCMCLASSBASIS`。 |
| FactorNo / FactorOnline | 兩欄必須一起填或一起空。FactorNo 必須存在於已核准 `TBLSYSMESPARAMETER`、`ParameterClass=1`；FactorOnline 必須是 FactorNo 子集合。舊 Core 即使兩欄皆空，也要求已核准 Class 1 Parameter 查詢結果非空。 |
| InlineOP / OfflineOP | 可空白；作業站須已核准。InlineOP 要求 LotIsVaild=1；同一 OP 不可同時在 Inline/Offline。Inline 檢驗旗標預設 FAI=0、IPQC=0、PQC=1，輸入值需可轉數字；Offline 三個旗標固定 0。 |
| Reason | 可空白；分號分隔的每個 ReasonNo 都必須存在於已核准 `TBLQCREASONBASIS`。同一列不接受重複 ReasonNo。舊 Core 建立了重複檢查 DataTable，卻未把已讀 Reason 加入其中，故其重複檢查實際失效；YMES API 必須正確阻擋重複值。 |

## 覆寫限制與資料副作用

Save 對已存在 QCItemNo 不是普通 UPDATE，而是先呼叫 `DelQCItemForAttributes` 清理舊定義，再重建未簽核主檔：`IssueState=0`、`SampleSize=0`、`FormName` 空白。`ComponentCollect=0` 時，將一般抽樣計畫參數複製到 QC Item Parameter；元件收集不複製這些參數。成功後建立 Factor、OP 對應及 QC Item Reason Map。

刪除流程檢查 WIP 使用、量測記錄、Material QC Item、Material Type QC Item、OP QC Item、Product QC Item 與 `TBLQCITEMATTGORDERDETAIL` 引用。若有這些引用則拒絕。舊程式接著會刪除 `TBLQCITEMGROUPDETAIL` 群組關聯，卻沒有在該流程先檢查一般群組是否使用；API 必須再檢查 QC212/其他實際的 group detail 綁定，存在引用即拒絕覆寫，不能跟著舊程式靜默拔除群組成員。檢查與寫入之間要在每列交易中重查並鎖定相關鍵值。

覆寫清除範圍包含 QC Item Parameter、主檔、Factor、Reason Map、一般 Group Detail、SPC Attribute Rule Map Detail/Parameter/Basis、QC Sample Plan Change、SPC Log For Sample Plan Change、SPC Attribute Chart Limit；特殊 Tape Form 另清除 Tape detail log。API 必須對照 YMES 正規化關聯資料，所有主/子表變更放在該列的同一交易。

舊 Core 最後會按 Factor 呼叫動態新增欄位方法（Attribute Rule Map、SPC Att Factor/Limit、Plan Change Log 與 Chart Limit 等）。YMES 不可由上傳字串當 SQL 欄名或呼叫任意 `ALTER TABLE`；Factor 必須經核准 Parameter 白名單驗證，量測資料沿用 YMES 結構化 Factor 儲存模式。

Creator/CreateDate 是舊範本可輸入欄位，但 Web API 必須忽略其客戶端內容，稽核資料改用登入者與伺服器時間。所有 API 驗證登入及 FunctionKey=`QC215`，SQL 一律參數化。

## Check / Save 與逐列回報

- `Check Data` 呼叫 Core `OnlyCheck=true`，不寫入；成功檢查列仍可編輯及再次儲存。
- `Save` 呼叫 `OnlyCheck=false`，逐列處理勾選資料。成功列設為 `success`、取消勾選並鎖定；失敗列顯示錯誤並可修正重試。
- Web Service 會逐列呼叫 Core，個別列即使失敗，外層常仍回傳整體 Service success。因此 API 必須回傳列結果，不可把外層 HTTP 200 當每列都成功；允許部分成功。

## YMES API 契約

建議 API，路徑如需符合現有 controller 習慣，需同步調整 Vue 與本規格：

1. `POST /api/qc/attribute-item-import/preview`：multipart 欄位 `file`；解析 Excel 第一工作表並回 `{rows:[{recognizedColumns...}]}`。限制檔案大小/列數/欄數，不執行公式，不保存用戶端路徑。
2. `POST /api/qc/attribute-item-import/check`：body `{rows:[{recognizedColumns...}]}`；唯讀驗證並回 `{rows:[{rowNo,qcItemNo,succeeded,result,execute}]}`。
3. `POST /api/qc/attribute-item-import/import`：相同欄位；每列在獨立交易重跑驗證、引用檢查與覆寫。各列結果格式同 Check；不得由異常列回滾已成功的其他列。
4. `GET /api/qc/attribute-item-import/template`：依 FunctionNo=`IMPORT QCITEM ATTRIBUTES` 提供 `AttributesQCItem_Template.xls/.xlsx`，以 `Content-Disposition` 回傳實際檔名。

## 資料表與 SQL

QC215 是匯入既有 QC201 計數品管資料，沒有 QC215 專用資料表，故不新增 CREATE SQL。家用端先核對 PostgreSQL live schema/migrations，再為真缺漏新增 migration：

- `TBLQCITEMFORATTRIBUTES` 主檔：Oracle source `database/reference/mestest_mtl_qc_item_tables_source_ddl.sql`；PostgreSQL CREATE `database/reference/mestest_mtl_qc_item_tables_create.sql`。
- Parameter、Factor、Reason Map、SamplePlanChange 來源 Oracle DDL：`database/reference/mestest_qc_item_attributes_source_ddl.sql`；PostgreSQL CREATE 參考 `database/reference/mestest_qc_item_attributes_create.sql`。
- WIP/量測及共享 Material/OP/Product/Group 引用沿用 `database/reference/mestest_qc205_variable_dependencies_source_ddl.sql`、QC210/ QC204 的既有 source/CREATE 參考，以及 QC213 群組訂單明細 DDL/CREATE。不要為 QC215 複製重建 QC201 子表。
- 上述 Oracle DDL 是公司端先前以 PowerShell 5.1 + Oracle.ManagedDataAccess 直接唯讀查 MESTEST 後保存；本次不重新查 Oracle、不讀業務列、不執行 Oracle DDL。連線 IP/帳號/密碼/SID 不記錄在 Git。
