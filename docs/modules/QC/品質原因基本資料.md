| 項目 | 內容 |
| --- | --- |
| WinForms 功能 | `品質資料 → 基本資料 → 品質原因基本資料` |
| FunctionNo / FunctionKey | `REASON BASIS` / `QC106` |
| Form | `frmReasonBasis`；編輯窗 `frmReasonBasisDef` |

## WinForms 清單畫面

- 主表單為 1008×591。上方使用共用查詢與 IssueState 狀態列，預設「未簽核」；狀態 0/1/2/-1 分別為未簽核、簽核中、已簽核、不使用。
- 搜尋欄只設定 `ReasonNo`。WinForms 將搜尋值直接傳給 Core 的 `ReasonNo LIKE '<value>'`；使用者可輸入 `%`／`_` 萬用字元。清單依 ReasonNo 排序，狀態是在已載入資料上由前端篩選。
- 主要欄位依序為 ReasonNo、ReasonName、ReasonLevel、ReasonType、ReasonSubType、Description、Creator、CreateDate、Reviser、ReviseDate。`gSYSmode=SPK` 時隱藏主 Grid 的 ReasonSubType；Vue 頁支援可選的 `systemMode=SPK` prop，但目前 Web shell 沒有提供此模式值，整合端補入後即可套用。ReasonType 用 `ValueListProvider` 顯示文字；IssueState 和 DataStamp 隱藏。`gSYSmode=SPK` 時主 Grid 隱藏 ReasonSubType 欄。
- 右側直排按鈕為新增、修改、刪除、複製、核准；底部右側為關閉。沒有獨立檢視、匯入、Download 或 Print 按鈕。
- ReasonType 的合法選項來自 `GetValueList("TBLQCREASONBASIS", "REASONTYPE", True)`。來源檔舊註解列出的類型值不完整且版本間不一致，正式 UI 必須使用 API 提供的 MES ValueList，不能把歷史註解寫死。

## 新增／修改視窗與資料驗證

- `frmReasonBasisDef` 為 484×387。欄位有 ReasonNo、ReasonName、ReasonType、ReasonLevel、ReasonSubType、Description，以及建立／修改者與日期。視窗提供確定、關閉、套用。
- ReasonNo、ReasonName、ReasonType 必填；ReasonLevel 為 0–9 整數。ReasonNo 離開欄位轉大寫；確定時禁止 ASCII 逗號及全形逗號。ReasonNo 長度依 Oracle 為 20；ReasonName 100；ReasonSubType 50；Description 255。
- ReasonSubType 在表單唯讀，透過 `...` 開啟共用搜尋視窗；搜尋欄顯示 ReasonSubType、ReasonSubTypeName。資料先以 `IssueState=2` 載入，再依目前 ReasonType 篩選。ReasonType 改變時清空已選 ReasonSubType。資料表允許 ReasonSubType 為 NULL，所以這個欄位不是必填。
- 修改時 ReasonNo 唯讀；ReasonSubType 一律唯讀。其餘欄位依共用 `ExeIssueControl`：狀態 0 可編輯；狀態 1 全部唯讀；狀態 2/-1 只開放該表單 Issue Control 設定中 EditFlag=1 的控制項。正式 API 應回傳允許編輯欄位；找不到設定時採唯讀。
- 新增由後端設定 IssueState=0、Creator/CreateDate。修改更新 Reviser/ReviseDate，Core 以 DataStamp compare-and-swap 更新。複製帶入原欄位並走新增服務；ReasonNo 必須改為未使用過的唯一值。
- ReasonSubType lookup 不是主表外鍵。正式 API 應回傳 ReasonType 相同且已簽核的子類別；不得用未簽核或不使用的子類別建立主檔。

## 按鈕與簽核狀態

- 修改／複製使用目前作用列；刪除／核准可多選。多筆作業逐筆執行，遇首筆失敗停止，先前已成功的列不回復，之後重新載入清單。
- 刪除狀態 0 或 -1 為實體刪除；狀態 2 改為 -1 並更新 Reviser、ReviseDate、DataStamp；狀態 1 不允許刪除。
- 核准只接受狀態 0。Service 查找 Issue Job Map `REASON BASIS`：沒有 Job 或 Job 沒有 Detail 時直接轉 2；有簽核明細時建立 Issue 流程、轉 1 並通知第一簽核群組；後續核准轉 2、退回回 0。
- 新增、修改、刪除及核准皆保留狀態和 DataStamp 語意。DataStamp 欄位允許 NULL 並預設 0，正式 API 必須區分 NULL 與 0 的 CAS 條件。

## Oracle 欄位與限制

Oracle DDL 由公司端使用 Windows PowerShell 5.1、Oracle.ManagedDataAccess 與本機受保護連線唯讀取得。查詢限資料字典／DDL，沒有讀取 MES 業務列或在 Oracle 執行 DDL。

| 欄位 | Oracle 型別 | NULL / 預設 | 用途 |
| --- | --- | --- | --- |
| ReasonNo | VARCHAR2(20) | NOT NULL | 主鍵 |
| ReasonName | VARCHAR2(100) | NOT NULL | 原因名稱 |
| ReasonType | NUMBER(1,0) | NOT NULL | ValueList 類別代碼 |
| ReasonLevel | NUMBER(1,0) | NOT NULL | 原因層級；WinForms 輸入 0–9 |
| Description | VARCHAR2(255) | NULL | 說明 |
| Creator | VARCHAR2(10) | NULL | 建立者 |
| CreateDate | DATE | NULL | 建立日期 |
| IssueState | NUMBER(1,0) | NOT NULL DEFAULT 0 | 簽核狀態 |
| ReasonSubType | VARCHAR2(50) | NULL | QC105 子類別編號；Oracle 無 FK |
| DataStamp | NUMBER(11,0) | NULL DEFAULT 0 | 併發版本 |
| Reviser | VARCHAR2(10) | NULL | 修改者 |
| ReviseDate | DATE | NULL | 修改日期 |

唯一索引只有 `PK_TBLQCREASONBASIS`，對應主鍵 `(ReasonNo)`；沒有外鍵或額外索引。Oracle source DDL：[`mestest_qc_reason_basis_source_ddl.sql`](../../../database/reference/mestest_qc_reason_basis_source_ddl.sql)；YMES PostgreSQL 空表 CREATE 參考：[`mestest_qc_reason_basis_create.sql`](../../../database/reference/mestest_qc_reason_basis_create.sql)。家用端先比對 YMES live schema 與既有資料，再決定是否建立 forward migration；不要 drop/recreate 現存表。

## Vue DEV 頁與 API 契約

公司端 DEV 頁以明確標示 DEV 的 localStorage 假資料示範四狀態清單、ReasonNo LIKE 查詢、單筆修改／複製、選擇已核准子類別、CRUD、核准、刪除／停用、ReasonType 改變清空 ReasonSubType、稽核欄位及多選部分成功行為。Production 不使用假資料。

建議 API 全部要求登入並檢查 FunctionKey `QC106`，使用參數化 SQL，將登入者與伺服器時間作為 audit：

- `GET /api/qc/reason-basis?searchFieldName=ReasonNo&searchFieldValue=`：只接受 ReasonNo 搜尋值；將 `%`／`_` 作為 LIKE 萬用字元，回傳四狀態資料及 DataStamp、`editableFields`。狀態由 UI 篩選。
- `GET /api/qc/reason-basis/reason-types`：回傳舊 ValueList 等價的 `{ value, label }`。
- `GET /api/qc/reason-basis/subtype-options?reasonType=`：限定 IssueState=2，回傳 ReasonSubType、ReasonSubTypeName；ReasonType 需符合參數。此 Lookup 依 QC106 權限授權，路由需放在 `/{reasonNo}` 前面。
- `POST /api/qc/reason-basis`：接收 `{ reasonNo, reasonName, reasonLevel, reasonType, reasonSubType, description }`；驗證 ReasonNo/ReasonName/ReasonType 必填、欄位長度、ReasonLevel 0–9、ReasonNo 禁逗號且轉大寫、ReasonType 合法、子類別狀態/類別相符、主鍵唯一。設定 IssueState=0 及登入者 audit；重複主鍵回 409。
- `PUT /api/qc/reason-basis/{reasonNo}?issueState=&dataStamp=`：ReasonNo 唯讀；僅允許該狀態的 Issue Control 欄位更新。ReasonSubType 不接受直接輸入，須驗證所選值為同 ReasonType 的已簽核 QC105 子類別。更新 Reviser/ReviseDate，DataStamp nullable CAS；版本衝突回 409。
- `DELETE /api/qc/reason-basis/{reasonNo}?issueState=&dataStamp=`：狀態 0/-1 實體刪除；狀態 2 原子改為 -1；狀態 1 拒絕。需做 DataStamp 檢查。
- `POST /api/qc/reason-basis/{reasonNo}/approve?issueState=0&dataStamp=`：只接受狀態 0，按 Issue Job Map `REASON BASIS` 執行直接核准或建立 Issue/通知首簽核群組；回傳實際狀態與最新 DataStamp。
