## WinForms 畫面與操作

- 主畫面有四種 IssueState 單選：0 未簽核、1 簽核中、2 已簽核、-1 不使用；預設 0。群組編號可輸入部分字串查詢。
- 第一區 `GroupBox1` 約 984×256，顯示群組主檔 Grid 和主檔按鈕：新增、修改、刪除、複製、核准、Parameter、Op、Add QC。群組列選取時載入同一群組的明細及扣除基準。
- 第二區 `GroupBox2` 約 984×112，顯示 QCItemNo、QCItemName、ShowOrder、DeductionItem；Calculate Script 按鈕在 Designer 設為不可見，不列入 Web 功能。
- 第三區 `GroupBox3` 約 984×146，顯示扣除基準。欄位包含 DeductionSerial、目前啟用的動態 Factor、NormalTimes、DeductionTimes、CurPass、CurStatus、Creator/CreateDate、Reviser/ReviseDate。新增、修改、刪除、複製扣除基準只在所選群組 IssueState=2 時可用。
- 群組主檔欄位包含 GroupNo、GroupName、LotIsValid、PlanNo、UnionERF、Description、Creator/CreateDate、Reviser/ReviseDate、CursorMode、GetFilePath；有些歷史欄位在主 Grid 或 Define Form 隱藏。編輯時需保留 ComponentCollect、FormName、WebURL、ErrorReportName、NoticeReportName、QCClass、CursorMode 等未顯示值。
- 群組 Define Form 可見 GroupNo、GroupName、LotIsValid 是/否、Union Plan、PlanNo、UnionERF、Description、GetFilePath、建立/修改稽核欄位。GroupNo 最長 25、GroupName 最長 50、Description 最長 255、GetFilePath 最長 50。LotIsValid 僅 0/1；勾選 Union Plan 時 PlanNo 必填，取消時清空 PlanNo。計量/元件抽樣計畫依隱藏 ComponentCollect 選擇相符的已核准計畫。
- 群組修改表單呼叫共用 `ExeIssueControl`：IssueState=0 不限制欄位；1 將編輯控制項設為唯讀；2/-1 依 `wsSYS.LoadIssueControlForm` 為 `frmPMI_QCItemGroupDef` 回傳的 EditFlag 逐欄允許修改，若沒有設定資料則全唯讀。GroupNo 在修改模式固定唯讀。Vue 應取得同等欄位政策；Production API 要再次驗證，不能只信任前端。

## 品管項目明細

- `frmPMI_QCItemGroupInclude` 提供左右清單新增/移除及 ShowOrder 上下排序。右側明細可標記 DeductionItem 減項；來源將此欄映射至 Boolean 欄位供 UI 顯示。
- 可新增項目僅限 IssueState=2 的計量品管項目，並須與群組的 ComponentCollect 相同；同 GroupNo 不可重複 QCItemNo。
- 儲存由 `UpdQCItemGroupDetail_PMI` 以整組明細更新 (GroupNo, QCItemNo, ShowOrder, DeductionItem)。資料至少要保留一筆非減項明細；簽核前至少要有一筆群組明細。
- Vue DEV 頁在對話框內維護項目、減項旗標與順序，按確定一次提交整組，不以導覽或 query string 傳遞選取列。

## 扣除基準與要因

- 扣除基準主鍵為 DeductionSerial，新增序號由 MES Serial 服務產生；以 GroupNo 關聯群組。欄位含 NormalTimes、DeductionTimes、CurPass、CurStatus、建立/修改稽核及 DataStamp。
- NormalTimes 與 DeductionTimes 必須大於 0，Oracle `NUMBER(2,0)` 範圍為 1–99；CurPass 為 `NUMBER(3,0)`，範圍 0–999；CurStatus：0 Normal、1 Deduction、2 Deduction Retest。
- 要因欄位由目前已啟用的 FactorOnline 動態決定。舊 Oracle 表會由 Core 依 FactorNo 動態新增欄位，欄位預設值為 `*`。表單對 ParameterType=2 的因子開放文字輸入，其他類型使用對應查找清單；每個作用中的因子均需有值。Core 會檢查因子值組合是否重複。
- YMES 使用 `factorvalues JSONB` 儲存因子代碼和值；只允許由 API 的已核准 FactorOnline 白名單產生/接受 JSON key，禁止把前端傳來的因子名串成動態 SQL 欄位。保留 `*` 作為不限條件。新增/修改使用 DataStamp 並行檢查。
- 複製扣除基準新增另一筆序號，沿用計數及因子值；修改、刪除只針對選取列。

## 狀態、簽核、刪除

- 新增群組的 IssueState 為 0。新增/修改需檢查 GroupNo 唯一性，來源 Add 會避免與計數/計量 QC Item 群組互撞；API 同時核對 `TBLQCITEMFORATTRIBUTES`、`TBLQCITEMFORVARIABLES`、一般 `TBLQCITEMGROUPBASIS` 與 PMI 群組主檔，並使用大小寫無關比較。
- 核准使用 Issue Job `QCITEM_G_PMI`。未設定 Job 時狀態直接為 2；有 Job 時先改為 1，簽核通過為 2、退回為 0。核准前必須有品管項目明細。API 對批次中的每個群組分別檢查明細和狀態。
- 刪除狀態 0、-1 走硬刪；狀態 2 改成 -1 並更新 Reviser/ReviseDate/DataStamp；狀態 1（簽核中）拒絕刪除。硬刪前檢查 `TBLWIPTEMP_QCITEM` 是否有該群組項目正在使用；符合條件後舊 Core 交易式清除主檔、明細、QC Item Parameter、OP/MTL/PRD 關聯與三種 SPC 表單對應。刪除最後一筆一般或 PMI 明細後，只清理已不再被任一群組明細引用的孤兒 Calculate Script。
- 來源 `DelQCItemGroupData_PMI` 沒有刪 `TBLQCGROUPDEDUCTIONBASIS_PMI` 的 SQL；該表沒有 FK，對狀態 0/-1 的硬刪會留下扣除基準孤兒資料。為忠實相容，YMES API 預設保留此舊行為，並以此作已知 legacy 缺陷記錄；不要在硬刪時悄悄清除。若日後決定修正孤兒資料，須作為明確規格變更處理。狀態 2 僅停用，因此保留扣除資料符合來源行為。
- Parameter 開啟共用 `QC_ItemParameter`，以 GroupNo/GroupName 作為 QCItemNo/QCItemName；PlanNo 有值時需查得已核准抽樣計畫與 PlanType。Op 開啟共用 `QC_ItemOp`，`QCType=4`；IssueState 非 2 時移動按鈕停用，LotIsValid=0 時只能加入 OffLine。畫面分「可選作業站」及「已選作業站」兩個清單，可批次加入 InLine/OffLine、移除；已選清單顯示 ExecuteStatus、OpNo、OpName、INSPTYPE_FAI/IPQC/PQC。每筆 InLine 必須至少勾選一種檢驗時機，OffLine 不使用檢驗時機。
- API 必須使用交易、參數化查詢及 DataStamp/CAS；不得信任前端提供的使用者稽核欄位或 IssueState。

## Oracle 資料表與 DDL

Oracle 原始 DDL 由公司端 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 使用本機受保護連線，唯讀呼叫 DBMS_METADATA 與 ALL_* 字典取得；沒有查 MES 業務列、沒有在 Oracle 執行 DDL。

| 用途 | MESTEST Oracle 表 | PostgreSQL 空表參考 | 主鍵與結構摘要 |
| --- | --- | --- | --- |
| PMI 群組主檔 | `TBLQCITEMGROUPBASIS_PMI` | `mestest_qc216_variable_item_group_pmi_create.sql` | GroupNo；無 FK/額外索引 |
| PMI 群組明細 | `TBLQCITEMGROUPDETAIL_PMI` | 同上 | (GroupNo, QCItemNo)；無 FK/額外索引 |
| PMI 扣除基準 | `TBLQCGROUPDEDUCTIONBASIS_PMI` | 同上 | DeductionSerial；無 FK/額外索引；Oracle 動態因子欄位改 JSONB |
| SPC FQC 關聯 | `TBLSPCFQCFORMQCITEMMAP` | 同上 | (QCFormNo, QCItemNo) |
| SPC Incoming 關聯 | `TBLSPCINCOMINGQCFORMQCITEMMAP` | 同上 | (QCFormNo, QCItemNo) |
| SPC OQC 關聯 | `TBLSPCOQCFORMQCITEMMAP` | 同上 | (QCFormNo, QCItemNo) |
| 在線使用檢查 | `TBLWIPTEMP_QCITEM` | 已有 QC205 reference | 不另立 PMI 專屬表 |

每表 Oracle source DDL 分檔在 `database/reference/mestest_qc216_*_source_ddl.sql`。三張 SPC map 與其他 QC 共用依賴可能已存在 YMES；家用端只核對 live schema/migration，不能因參考 CREATE 檔存在便重建既有資料。PMI 主檔、明細表欄位 nullable/default 以 Oracle source DDL 為準；其中 IssueState、DataStamp、DeductionItem 等 Oracle 欄位允許 NULL，CREATE 參考保留原語意。DDL 未宣告 FK。

PostgreSQL 對照 SQL 是空結構參考，不是已部署 migration，也不可在 MESTEST Oracle 執行。參考檔中的 `IF NOT EXISTS` 不會補齊既有表欄位；家用端應先比對 YMES live schema、migration 與共用表。

## API 契約（家用端待建）

所有 `/api/qc/pmi-item-groups` 端點使用登入保護及 FunctionKey `QC216`，查詢/寫入均以伺服器權限、實際 IssueState 和 DataStamp 為準。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/qc/pmi-item-groups?issueState=&groupNo=` | 主檔查詢 |
| POST / PUT / DELETE | `/api/qc/pmi-item-groups[/{groupNo}]` | 主檔 CRUD；刪除 0/-1 硬刪、2 停用、1 拒絕；硬刪先做 WIP 使用檢查 |
| GET | `/api/qc/pmi-item-groups/{groupNo}/edit-policy` | 對照舊 `wsSYS.LoadIssueControlForm` 回傳可編輯欄位；1 回傳空清單 |
| POST | `/api/qc/pmi-item-groups/{groupNo}/approval` | `QCITEM_G_PMI` Issue Job 核准 |
| GET / PUT | `/api/qc/pmi-item-groups/{groupNo}/details` | 查詢/完整替換項目、ShowOrder、DeductionItem |
| GET | `/api/qc/pmi-item-groups/{groupNo}/deductions` | 扣除基準清單 |
| POST | `/api/qc/pmi-item-groups/{groupNo}/deductions` | 取得新序號並新增扣除基準 |
| PUT / DELETE | `/api/qc/pmi-item-groups/{groupNo}/deductions/{deductionSerial}` | 修改/刪除扣除基準 |
| GET | `/api/qc/pmi-item-groups/options/factors?issueState=2` | 已核准 FactorOnline 欄位、ParameterType、合法 lookup options |
| GET / PUT | `/api/qc/item-parameters?qcItemType=4&qcItemNo={groupNo}` | 沿用 Parameter 共用功能 |
| GET | `/api/process/operations?issueState=2` | 共用 Op 左側可選之已核准作業站清單 |
| GET / PUT | `/api/qc/item-operations?qcType=4&qcItemNo={groupNo}` | 沿用 Op 共用功能；GET 回已選作業站與 Inline/FAI/IPQC/PQC，PUT 完整替換 |

DTO 至少帶回來源欄位、稽核欄位及 DataStamp；刪除/核准批次回傳逐筆結果。Edit Policy API 將舊 Form 控制名稱映射到 Web 欄位，並在 PUT 再驗證欄位 ACL。Delete body 傳當前 IssueState/DataStamp 供 API 作舊式狀態操作的並行提示，但伺服器仍須重讀 DB，不信任 body 狀態。硬刪時按來源保留 PMI deduction rows，並記錄孤兒列相容性。Detail PUT 在單一 transaction 驗證已核准 QC Item、ComponentCollect、唯一性及非減項保留規則。Deduction API 驗證在線因子白名單、必要值、數值精度範圍、61 字元欄位舊限制等價語意、組合重複、CurStatus 範圍與 DataStamp。參數與 Op API 仍須以 `QC216` 授權，不能因共用端點繞過權限。

## Vue 與驗收狀態

- 新增 QC 品管設定第三層 fallback 選單項目 `QCITEM_G_PMI`，路由 `/YMES/QC/PmiItemGroup`。
- Vue DEV 頁包含四狀態查詢、群組 CRUD/複製/核准/刪除、Detail 左右選取與排序/減項旗標、動態扣除因子表單、扣除基準 CRUD/複製、Parameter 及 Op 雙清單/批次加入/移除/檢驗時機；DEV 假資料與其他 QC 群組頁隔離。非 ParameterType=2 的因子只能由 lookup 選取，避免用文字輸入略過 WinForms ValueList。
- Production API 契約已寫出但尚未建立；公司端未連 YMES PostgreSQL。沒有執行 build、test 或瀏覽器驗收。
