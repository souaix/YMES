# QC103 抽樣計劃

## 功能識別與來源

- 選單：品質資料 → 基本資料 → 抽樣計劃；FunctionNo `SAMPLING PLAN`、FunctionKey `QC103`。
- WinForms：`STD/MESWin/QC/QC_SamplingPlan/frmSamplingPlan.vb`、`frmSamplingPlanDef.vb`；另有 Parameter/Simulation 子視窗，Parameter 按鈕在主窗預設隱藏，Simulation 按鈕顯示。
- Service/Core：`STD/MESws_STD/wsSTD/wsQC/wsQC.cs` 的 Load/Add/Edit/Del/Approve/UpdSamplingParameter/ChkQCSamplingParameter；`STD/MESkc/kcQC/clsQCBasis.cs` 與 `STD/MESkc/kcBasis_UPD/clsBasis_UPD.cs`。
- 來源表：`MESTEST.TBLQCSAMPLINGPLAN`、`MESTEST.TBLQCSAMPLINGPARAMETER`。Oracle source DDL 與 PostgreSQL 空表 CREATE 參考：`database/reference/mestest_qc_sampling_plan_source_ddl.sql`、`mestest_qc_sampling_plan_create.sql`。

## WinForms 畫面

### 清單 `frmSamplingPlan`

- ClientSize 1008×591；承襲共用主檔框架的狀態篩選及 PlanNo 查詢，預設狀態為未簽核，結果依 PlanNo 排序。
- 狀態：0 未簽核、1 簽核中、2 已簽核、-1 不使用。上方查詢只設定 PlanNo。
- 清單欄位由主表載入；PlanType 顯示 ValueList 名稱；IssueState、DataStamp、SQtyCanBBiggerThenPQty 隱藏；建立/修改時間格式 `yyyy/MM/dd HH:mm:ss`。
- 右側由上而下：ADD、EDIT、DEL、Copy、Approve、Parameter（預設隱藏）、Simulation、Attribute（預設隱藏）、Close（右下）。Web 頁保留可見的 Simulation；隱藏的 Parameter/Attribute 不加到可見選單。
- 選取列可多選。Approve 僅允許未簽核；Delete 在狀態 0/-1 實體刪除參數與主檔，狀態 2 改為 -1，狀態 1 不允許。多筆逐筆呼叫，首筆失敗即停止，先前成功結果不回復。

### 定義窗 `frmSamplingPlanDef`

- ClientSize 491×561，含 PlanNo、PlanName、PlanType、FunctionName、Description、`Sample Qty Can Be Bigger Than Population Qty` Yes/No、動態 Sampling Parameter Grid，以及 Creator/CreateDate/Reviser/ReviseDate。
- Edit 時 PlanNo 唯讀；PlanNo 離開欄位轉大寫。PlanNo/PlanName/PlanType 必填；PlanType=3 時 FunctionName 必填。
- Parameter Grid 包含 ParameterNo、ParameterValue、ShowFlag 及選項查找按鈕；可新增/刪除參數列。部分欄位使用 `wsSYS.LoadElementValue` 提供選項；User Define Function 名稱由 `udSamplingFunction` 中私有方法名稱篩選 `FUNSA` 取得。
- Add/Edit/Copy 儲存主檔後再更新參數。舊 WinForms 這兩次 Service 呼叫並非同一請求；Web API 應用單一交易儲存主檔與所有參數，避免只寫入其中一半。
- Apply 留在表單，Confirm 儲存並關閉；Edit 主檔以 DataStamp 舊值 CAS，成功後 Reviser/ReviseDate 更新、DataStamp+1。

## PlanType 與參數規則

PlanType 顯示值由共用 ValueListProvider 提供。程式碼確認有 0–7 的分支：0 Fixed Sample Size、1 Fixed Sample Rate、2/7 AQL、3 User Define Function、4 No Definition、5 Sampling Table、6 Sampling 1916。正式 UI 應由 API 提供 ValueList，不要把猜測的顯示文案當成資料庫代碼。

| PlanType | WinForms 預設參數 | 儲存時重點 |
| ---: | --- | --- |
| 0 | PopulationQty、SampleQty | SampleQty 必填；數值不得小於 0 |
| 1 | PopulationQty、SampleQty、SampleRate | SampleRate 必填；數字在 0–1 之間 |
| 2、7 | AcceptQty、AQLType、PopulationQty、QCLevel、RejectQty、SampleQty、AQL | AQLType/QCLevel/AQL 使用選項；核心檢查參數名稱是否齊全 |
| 3 | 由 FunctionName 決定 | FunctionName 必填；執行指定 `FUNSA*` 抽樣函式 |
| 4 | PopulationQty、SampleQty | No Definition；來源會標記成可輸入參數 |
| 5 | SamplingTable、PopulationQty、SampleQty、RejectQty | SamplingTable 使用有效值查找 |
| 6 | SamplingType、VLevel、PopulationQty、SampleQty、KValue、FValue、RejectQty | Sampling 1916 參數列；必要值由 ShowFlag/核心檢查決定 |

- 表單要求所有 `ShowFlag=1` 的參數值必填；`SampleQty` 必須是非負數；`SampleRate` 若為數字需介於 0–1。Service `ChkQCSamplingParameter` 再依 PlanType 檢查必要參數名稱。
- Simulation 由 `QC_SamplingParameterSimulation` 子程式依 PlanType 呼叫相應的 `ShowParameter_*` 計算。DEV 頁目前可完整操作輸入/結果框，僅固定抽樣型別做本地示範；正式環境須由 API 使用原 Core 規則計算。

## 簽核、刪除與核心流程

- 新增主檔 IssueState=0。Approve 先讀取所有參數並呼叫 `ChkQCSamplingParameter`；不合規就不進入簽核。
- Issue Job Map key 是 `SAMPLING PLAN`。沒有 Job 或 Job Detail 時直接由 0 轉 2；有流程則建立 Issue master、IssueState 轉 1、寄信給第一簽核群組，核准 SQL 將狀態轉 2，退回 SQL 回 0。
- IssueState=0 或 -1 刪除時，`clsQCBasis.DelSamplingPlan` 以同一交易先刪 `TBLQCSAMPLINGPARAMETER` 再刪主檔。IssueState=2 刪除會以 DataStamp CAS 轉為 -1；狀態 1 拒絕。
- Simulation 的計算規則需按 PlanType 呼叫舊 Core 對應方法；不能以 UI 的 DEV 固定抽樣示範取代正式結果。

## Vue 與 YMES API 契約（家用端已實作獨立主檔）

- Vue 頁：`web/src/components/QcSamplingPlanMaster.vue`；路由 `/YMES/QC/SamplingPlan`；選單 QC → 基本資料。
- DEV 假資料只存在 `localStorage` key `ymes-dev-mock:qc-sampling-plans:v1`，不讀取 MES 業務資料。
- 所有端點要求登入；保留 FunctionNo=`SAMPLING PLAN`、FunctionKey=`QC103` 識別。依使用者先不處理角色／權限的決策，本輪未加 FunctionKey ACL。
- Web API base 為 `/YMES/API`，下列為相對 API 路徑：

| 方法／路徑 | 實際回傳與用途 |
| --- | --- |
| GET `/api/qc/sampling-plans?issueState=&searchFieldName=PlanNo&searchFieldValue=` | `{ items: [主檔DTO] }`；預設全部狀態，PlanNo 大小寫不敏感包含查詢並排序。保留 QC301 的可選 issueState、componentCollect 篩選。 |
| GET `/api/qc/sampling-plans/{planNo}` | 完整主檔 DTO，含 `parameters[]`；同一 repeatable-read snapshot 讀主檔版本和參數，供修改／複製使用。 |
| GET `/api/qc/sampling-plans/{planNo}/parameters?issueState=` | `{ items: [{ parameterNo, parameterValue, showFlag }] }`；保留 QC301 envelope 與 null 值轉空字串的既有契約，指定狀態已改變時回 409。 |
| GET `/api/qc/sampling-plans/options/plan-types` | 原始 `{ value, label }[]`；依本文件已核實的 0–7 分支對應碼提供名稱，不宣稱已遷移原 SYS ValueList storage。 |
| GET `/api/qc/sampling-plans/options/parameters/{parameterNo}?samplingType=` | 原始字串陣列；SamplingTable 讀 QC101 真實表，SamplingType／VLevel 讀 QC102 真實表，可按 SamplingType 限定 VLevel。其他普通自由文字參數回空陣列。AQLType／QCLevel／AQL 的 SYS 選項尚未遷移，回明確 503。 |
| GET `/api/qc/sampling-plans/options/functions` | 原 FUNSA 方法名單／實作未交付，明確 503；不回猜測或 DEV 函式名稱。 |
| POST `/api/qc/sampling-plans` | body 含 planNo、planName、planType、functionName、description、sQtyCanBBiggerThenPQty、parameters；同一交易新增主檔及參數，回完整 DTO。 |
| PUT `/api/qc/sampling-plans/{planNo}?issueState=&dataStampIsNull=&dataStamp=` | body 同上，planNo 可省略但不可改；主檔及整組 parameters 原子保存，回完整 DTO。YMES 本輪只允許 0/2 修改，1/-1 只讀。 |
| DELETE `/api/qc/sampling-plans/{planNo}?issueState=&dataStampIsNull=&dataStamp=` | 0/-1 同交易先刪參數再刪主檔；2 保留兩表並 CAS 轉 -1；1 拒絕，不推論其他 QC/WIP cascade。 |
| POST `/api/qc/sampling-plans/{planNo}/approve?issueState=0&dataStampIsNull=&dataStamp=` | 重新讀取參數並驗證。已知可驗證的 0/1/4/5，且無共用 Issue/Job 表時直接 0→2。2/3/6/7 仍缺原 Core／SYS 選項／函式驗證，回 503；若存在 Issue/Job 表亦回 503，主檔不變。 |
| POST `/api/qc/sampling-plans/{planNo}/simulate` | 現有主檔回明確 503，說明原 sampling Core 未遷移。沒有用 DEV 算式產生正式 SampleQty/AcceptQty/RejectQty/K/F。 |

主檔 DTO 使用 camelCase，含來源全部欄位及 nullable `dataStamp`、audit。Create/Update/Get/狀態異動的完整 DTO 附 `parameters[]`；集合清單不額外載入全部參數。參數為 `{ parameterNo, parameterValue, showFlag }`，ShowFlag 是計算 metadata、不存 DB。已核實的必要輸入為 1、計算／非必要欄位為 0；PlanType6 與未核實的自訂參數回 null，UI 顯示「待確認」，不以 DEV 的全部必填推定原規則。

PUT／DELETE／approve 必須提供有效 issueState 和明確版本條件：`dataStampIsNull=true` 表示只匹配 DB NULL，不能同時提供數字；`false` 必須提供 11 位數範圍內的整數 dataStamp。省略或互相矛盾回 400，版本／狀態競爭回 409。所有 SQL 參數化，audit 與新建 IssueState 由 server 決定；請求不可設定建立／修改人員或核准結果。

## 家用端實作與維護（2026-11-19）

- 程式為 `src/YMes.Api/Quality/Qc103Controller.cs`、`Qc103Models.cs`、`Qc103Repository.cs`。固定使用 `"YMES".tblqcsamplingplan`、`"YMES".tblqcsamplingparameter`；新增／修改主檔及替換參數共用一個交易，不沿用舊 UI 的兩個不一致寫入請求。
- 選項使用 `options/plan-types`、`options/functions`、`options/parameters/{parameterNo}` 路徑，避免單層 literal GET 搶走合法的 PlanNo=`PLAN-TYPES`／`FUNCTION-OPTIONS`，也避免 PlanNo=`PARAMETER-OPTIONS` 的 parameters GET 被舊選項路由搶走。不增加來源未定義的保留字限制。
- 相依表／Issue Job／引用表存在性使用 `pg_catalog.pg_namespace/pg_class`，欄位使用 `pg_attribute`，不依 `information_schema` 的角色可見性判斷「缺表」。存在但缺權限仍拒絕／回 503，不能誤當沒有流程而直接核准，或誤當沒有引用而刪除；這項 metadata 修正同時套用本輪 QC107／QC108，QC301 原有 `to_regclass` 表存在性維持、分類欄位查找改用相同 catalog。
- 主檔寫入以 `FOR UPDATE` 鎖列，核對目前狀態及 nullable DataStamp，SQL 以 `IS NOT DISTINCT FROM` 精確 CAS，成功異動才遞增版本。NULL 不當成 0。主檔和參數保存的任何一步失敗會回滾整筆；多選各列則獨立交易，不宣稱全批原子化。
- PlanType、`sQtyCanBBiggerThenPQty` 與 parameters 均須明確出現在 aggregate body；省略回 400，避免修改名稱時將原本 Yes 旗標靜默變成預設 No。Nullable DataStamp、參數值與 audit 不先轉成非空預設。
- PlanNo Trim／大寫／最多 25，PlanName 必填／最多 50，PlanType 只接受 0–7，旗標只接受 0/1；FunctionName 最多 50，Type3 必填；多行 Description 最多 255。參數名最多 20、值最多 255，parameters 陣列必須明確提供、最多 256 列；參數鍵不分大小寫去重，已知名稱正規化為來源拼寫，空值存 NULL。既有同名大小寫主檔衝突時拒絕寫入，不暗選其中一筆。
- 已實作來源明確的必要參數名稱、ShowFlag=1 必填、SampleQty 非負、SampleRate 0–1 檢查。Type5 SamplingTable 在保存／核准時對 QC101 真實列以 `FOR SHARE` 重查，不接受不存在的表。Type6 預設名稱已核實，精確 ShowFlag 與完整抽樣驗證仍待公司端原 Core；Type3 可維護 FunctionName 文字及參數，但不執行任意函式，也不假造可用函式名單。
- QC101／QC102 查找直接讀相同來源表 `tblqcsamplingtable`、`tblqcsampling1916`，不建第二份 lookup／Fake repo。這些選項代表已維護的真實表／代碼／層級，不等同完成區間解析或 sampling engine。
- Vue `QcSamplingPlanMaster.vue` 適配 `{ items }`，修改／複製先讀完整主檔與參數 snapshot。移除會對 Vue proxy 失敗的 structuredClone；列表操作只取目前可見狀態，切換狀態重設選取。刪除／核准使用共用確認視窗，取消不寫入；批次中途失敗重載清單，保留錯誤及已完成筆數。
- Add/Copy Apply 成功後轉為修改，鎖定已保存主鍵，保存 API 回傳的精確版本、參數與 audit；繼續保存會更新同一列。新增後清查詢並切到未簽核以選取新筆；既有 NULL 日期／人員保持空白。這是 YMES 對來源新增模式的調整。
- 保存期間停用主檔／參數輸入，防止回應覆蓋等待期間的新輸入。參數選項請求以表單世代及各參數的 request sequence 忽略舊回應；切換 PlanType 或關閉表單後，上一個 AQL／FUNSA 錯誤不會蓋到新表單。Type6 改 SamplingType 時，VLevel 會按該模式重新查真實 QC102 候選，仍保留既有文字值供維護，不代表已完成 engine 驗證。
- Production 不再載入 DEV 的 AQL、SamplingType、VLevel 或表名選項。已存在的文字值即使不在候選中仍會顯示並保留；SYS 選項／FUNSA 不可用時顯示實際 ProblemDetails，仍可維護文字資料，核准與模擬保留上表限制。DEV 假資料及固定抽樣示範只有 DEV + developmentPreview 時啟用。

### 與 QC301 的路由相容

- 既有 GET 集合與參數路由仍由 `Qc301Controller.cs` 內的 `Qc301SamplingPlanLookupController` 暴露，改轉接 QC103 repository；新 QC103Controller 沒有再宣告相同兩個 GET。QC301 管制圖呼叫路徑、`{ items }` envelope、PlanNo/PlanName 與參數空字串契約維持相容，新增主檔欄位與 ShowFlag 可由既有呼叫端忽略。
