# QC103 抽樣計劃

## 功能識別與來源

- 選單：品質資料 → 基本資料 → 抽樣計劃；FunctionNo `SAMPLING PLAN`、FunctionKey `QC103`。
- WinForms：`STD/MESWin/QC/QC_SamplingPlan/frmSamplingPlan.vb`、`frmSamplingPlanDef.vb`；另有 Parameter/Simulation 子視窗，Parameter 按鈕在主窗預設隱藏，Simulation 按鈕顯示。
- Service/Core：`STD/MESws_STD/wsSTD/wsQC/wsQC.cs` 的 Load/Add/Edit/Del/Approve/UpdSamplingParameter/ChkQCSamplingParameter；`STD/MESkc/kcQC/clsQCBasis.cs` 與 `STD/MESkc/kcBasis_UPD/clsBasis_UPD.cs`。
- 來源表：`MESTEST.TBLQCSAMPLINGPLAN`、`MESTEST.TBLQCSAMPLINGPARAMETER`。Oracle source DDL 與 PostgreSQL 空表 CREATE 參考：`database/reference/mestest_qc_sampling_plan_source_ddl.sql`、`mestest_qc_sampling_plan_create.sql`。

## WinForms 畫面

### 清單 `frmSamplingPlan`

- ClientSize 1008×591；承襲共用主檔框架的狀態篩選及 PlanNo 查詢，預設狀態為未簽核，結果依 PlanNo 排序。
- 狀態：0 未簽核、1 簽核中、2 已簽核、-1 不使用。上方查詢只設定 PlanNo。
- 清單欄位由主表載入；PlanType 顯示 ValueList 名稱；IssueState、DataStamp、SQtyCanBBiggerThenPQty 隱藏；建立/修改時間格式 `yyyy/MM/dd HH:mm:ss`。
- 右側由上而下：ADD、EDIT、DEL、Copy、Approve、Parameter（預設隱藏）、Simulation、Attribute（預設隱藏）、Close（右下）。Web 頁保留可見的 Simulation；隱藏的 Parameter/Attribute 不加到可見選單。
- 選取列可多選。Approve 僅允許未簽核；Delete 在狀態 0/-1 實體刪除參數與主檔，狀態 2 改為 -1，狀態 1 不允許。多筆逐筆呼叫，首筆失敗即停止，先前成功結果不回復。

### 定義窗 `frmSamplingPlanDef`

- ClientSize 491×561，含 PlanNo、PlanName、PlanType、FunctionName、Description、`Sample Qty Can Be Bigger Than Population Qty` Yes/No、動態 Sampling Parameter Grid，以及 Creator/CreateDate/Reviser/ReviseDate。
- Edit 時 PlanNo 唯讀；PlanNo 離開欄位轉大寫。PlanNo/PlanName/PlanType 必填；PlanType=3 時 FunctionName 必填。
- Parameter Grid 包含 ParameterNo、ParameterValue、ShowFlag 及選項查找按鈕；可新增/刪除參數列。部分欄位使用 `wsSYS.LoadElementValue` 提供選項；User Define Function 名稱由 `udSamplingFunction` 中私有方法名稱篩選 `FUNSA` 取得。
- Add/Edit/Copy 儲存主檔後再更新參數。舊 WinForms 這兩次 Service 呼叫並非同一請求；Web API 應用單一交易儲存主檔與所有參數，避免只寫入其中一半。
- Apply 留在表單，Confirm 儲存並關閉；Edit 主檔以 DataStamp 舊值 CAS，成功後 Reviser/ReviseDate 更新、DataStamp+1。

## PlanType 與參數規則

PlanType 顯示值由共用 ValueListProvider 提供。程式碼確認有 0–7 的分支：0 Fixed Sample Size、1 Fixed Sample Rate、2/7 AQL、3 User Define Function、4 No Definition、5 Sampling Table、6 Sampling 1916。正式 UI 應由 API 提供 ValueList，不要把猜測的顯示文案當成資料庫代碼。

| PlanType | WinForms 預設參數 | 儲存時重點 |
| ---: | --- | --- |
| 0 | PopulationQty、SampleQty | SampleQty 必填；數值不得小於 0 |
| 1 | PopulationQty、SampleQty、SampleRate | SampleRate 必填；數字在 0–1 之間 |
| 2、7 | AcceptQty、AQLType、PopulationQty、QCLevel、RejectQty、SampleQty、AQL | AQLType/QCLevel/AQL 使用選項；核心檢查參數名稱是否齊全 |
| 3 | 由 FunctionName 決定 | FunctionName 必填；執行指定 `FUNSA*` 抽樣函式 |
| 4 | PopulationQty、SampleQty | No Definition；來源會標記成可輸入參數 |
| 5 | SamplingTable、PopulationQty、SampleQty、RejectQty | SamplingTable 使用有效值查找 |
| 6 | SamplingType、VLevel、PopulationQty、SampleQty、KValue、FValue、RejectQty | Sampling 1916 參數列；必要值由 ShowFlag/核心檢查決定 |

- 表單要求所有 `ShowFlag=1` 的參數值必填；`SampleQty` 必須是非負數；`SampleRate` 若為數字需介於 0–1。Service `ChkQCSamplingParameter` 再依 PlanType 檢查必要參數名稱。
- Simulation 由 `QC_SamplingParameterSimulation` 子程式依 PlanType 呼叫相應的 `ShowParameter_*` 計算。DEV 頁目前可完整操作輸入/結果框，僅固定抽樣型別做本地示範；正式環境須由 API 使用原 Core 規則計算。

## 簽核、刪除與核心流程

- 新增主檔 IssueState=0。Approve 先讀取所有參數並呼叫 `ChkQCSamplingParameter`；不合規就不進入簽核。
- Issue Job Map key 是 `SAMPLING PLAN`。沒有 Job 或 Job Detail 時直接由 0 轉 2；有流程則建立 Issue master、IssueState 轉 1、寄信給第一簽核群組，核准 SQL 將狀態轉 2，退回 SQL 回 0。
- IssueState=0 或 -1 刪除時，`clsQCBasis.DelSamplingPlan` 以同一交易先刪 `TBLQCSAMPLINGPARAMETER` 再刪主檔。IssueState=2 刪除會以 DataStamp CAS 轉為 -1；狀態 1 拒絕。
- Simulation 的計算規則需按 PlanType 呼叫舊 Core 對應方法；不能以 UI 的 DEV 固定抽樣示範取代正式結果。

## Oracle 結構

### `TBLQCSAMPLINGPLAN`

| 欄位 | 型別 | Nullable / 預設 |
| --- | --- | --- |
| PlanNo | varchar(25) | NOT NULL，PK |
| PlanName | varchar(50) | NOT NULL |
| PlanType | number(1,0) | NOT NULL |
| FunctionName | varchar(50) | NULL |
| Description | varchar(255) | NULL |
| Creator / Reviser | varchar(10) | NULL |
| CreateDate / ReviseDate | DATE | NULL |
| IssueState | number(1,0) | NOT NULL DEFAULT 0 |
| SQtyCanBBiggerThenPQty | number(1,0) | NOT NULL DEFAULT 0 |
| DataStamp | number(11,0) | NULL DEFAULT 0 |

PK `PlanNo`，只有 PK unique index，無 FK/其他 index。

### `TBLQCSAMPLINGPARAMETER`

| 欄位 | 型別 | Nullable / 預設 |
| --- | --- | --- |
| PlanNo | varchar(25) | NOT NULL，複合 PK |
| ParameterNo | varchar(20) | NOT NULL，複合 PK |
| ParameterValue | varchar(255) | NULL |

PK `(PlanNo, ParameterNo)`，只有 PK unique index，無 FK/其他 index。來源沒有資料庫 FK；Web API 應在交易中保證主檔/參數同步並清除孤兒資料。

## Vue DEV 頁與 Production API 契約

- Vue 頁：`web/src/components/QcSamplingPlanMaster.vue`；路由 `/YMES/QC/SamplingPlan`；選單 QC → 基本資料。
- DEV 假資料只存在 `localStorage` key `ymes-dev-mock:qc-sampling-plans:v1`，不讀取 MES 業務資料。
- API 建議以登入者/FunctionKey `QC103` 保護：
  - `GET /api/qc/sampling-plans?issueState=&searchFieldName=PlanNo&searchFieldValue=`：回傳主檔與 DataStamp；UI 複製 WinForms 一次載入並按狀態/PlanNo 篩選。
  - `GET /api/qc/sampling-plans/plan-types`：由系統 ValueList 返回正式 PlanType 代碼/名稱；`GET /function-options` 回傳 `FUNSA*` 方法；`GET /parameter-options/{parameterNo}` 供表單下拉選項。
  - `GET /{planNo}/parameters` 回傳 ParameterNo/ParameterValue；ShowFlag 由 PlanType 規則計算，不必新增 Oracle 欄位。
  - `POST /api/qc/sampling-plans` 及 `PUT /{planNo}?issueState=&dataStampIsNull=&dataStamp=` 以 Aggregate body 儲存主檔和 `parameters[]`，同一交易替換參數；Create/Revise audit、IssueState/DataStamp 由 API 維護。
  - `DELETE /{planNo}?issueState=&dataStampIsNull=&dataStamp=`：0/-1 交易刪參數與主檔；2 依 CAS 設 -1；1 拒絕。
  - `POST /{planNo}/approve?dataStamp=`：先執行核心參數驗證，再依 `SAMPLING PLAN` Job Map 直接核准或啟動 Issue 工作流程、通知第一簽核群組。
  - `POST /{planNo}/simulate` body `{ populationQty, ... }`：以原 Core 的 PlanType 方法回傳 SampleQty/AcceptQty/RejectQty/K/F。
- 全部 SQL 使用參數化查詢；重複 PlanNo/參數鍵回 409；DataStamp 競爭回 409。PlanNo 主檔與參數寫入必須原子化。
