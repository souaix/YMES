# 計量品管項目匯入（QC214）

## 功能識別

- WinForms FunctionNo：`IMPORT QCITEM VARIABLES`
- FunctionKey：`QC214`
- Form：`frmImport_QCItem_Variables`
- DLL：`QC_Import_QCItem_Variables.dll`
- 選單：品質資料 → 品管設定 → 計量品管項目匯入
- 原始碼：
  - `STD/MESWin/QC/QC_Import_QCItem_Variables/frmImport_QCItem_Variables.vb`
  - `STD/MESws_STD/wsSTD/wsQC/wsQC.cs` 的 `ImportQCItem_Variables`
  - `STD/MESkc/kcQC/clsQCBasis.cs` 的 `ImportQCItem_Variables`、`DelQCItemForVariables`

## WinForms 畫面與操作

表單 ClientSize 為 1008×591，標題 `Import Variables QCItem`，置中顯示。左側約 902×569 的 UltraGrid 填滿表單；右側固定 80×32 功能按鈕直排：

1. `File`（載入匯入檔）
2. `Check Data`（只檢查勾選列）
3. `Save`（儲存勾選列）
4. `Template DownLoad`（下載伺服器範本）
5. `Select All`
6. `UnSelect All`
7. `MultiSelect`（把 Grid 多選列標記為匯入列）
8. `Close`

Grid 依範本欄位顯示匯入資料。`Select` 是可編輯勾選欄；`Execute` 顯示逐列結果；內部 `Result` 欄隱藏，用來控制底色。失敗列呈粉紅色；成功儲存列取消勾選、轉唯讀並呈灰色。使用者可以在 Grid 刪除列。資料列只處理 `Select=True` 的項目。

## 檔案讀取與範本

- WinForms File 對話框篩選 `.xls`，讀第一個工作表。範本下載副檔名依系統設定為 `.xls` 或 `.xlsx`，檔名 `VariablesQCItem_Template`；下載內容由 `wsSYS.GetTemplateFile` 依 FunctionNo=`IMPORT QCITEM VARIABLES` 提供。
- 工作表第 1 列為欄名，舊程式從第 3 列開始讀資料，因此第 2 列保留作範例/說明列；遇到第一個全空白列即停止。Web production 的 `/preview` 解析 `.xls/.xlsx` 時須沿用這項範本相容規則，並回傳預覽資料列。
- 欄名 `Select`、`Result`、`Execute` 會被略過。空欄名會轉成 `unknow{欄位索引}`。`QCItemNo`、`PlanNo`、`MClassNo` 轉大寫，其餘字串去除前後空白。
- 核心辨識欄位：`QCItemNo`、`QCItemName`、`LotIsVaild`、`PlanNo`、`SampleSize`、`SpecLineType`、`ComponentCollect`、`CalType`、`ChartType`、`MaxValue`、`MinValue`、`Unit`、`Description`、`LimitLotNum`、`MClassNo`、`Roundoff_Num`、`FactorNo`、`FactorOnline`、`FactorSpec`、`InlineOP`、`OfflineOP`、`INSPTYPE_FAI`、`INSPTYPE_IPQC`、`INSPTYPE_PQC`、`Creator`、`CreateDate`。
- 三個 Factor 欄位與 Inline/Offline OP 清單用分號 `;` 分隔。WinForms 將表格資料一律當字串傳給 Service。
- Vue 頁面提供 `.xls/.xlsx` 檔案選擇；production 由 API 解析。DEV 本機預覽支援 `.xlsx/.csv`，不安裝試算表函式庫。DEV 範本保留第 2 列空白相容列。CSV 是 Web 開發輔助格式，不是 WinForms 原功能。

## 核心驗證

每筆所選資料依序驗證，第一個錯誤作為該列 `Execute`：

| 欄位／條件 | 規則 |
| --- | --- |
| QCItemNo | 必填；不得已存在於 `TBLQCSPECBASIS`、`TBLSPCQCCHARTBASIS` 或 `TBLSPCVARFACTORLOG`。注意此處是禁止已有 Spec/Chart/量測記錄，不代表現存 Variable Item 一律禁止匯入。 |
| QCItemName | 必填。 |
| LotIsVaild | 必填，整數 0 或 1（來源拼字如此）。 |
| PlanNo | 必填。`ComponentCollect=0` 時必須能讀到一般抽樣計畫參數；`ComponentCollect=1` 時必須能讀到 Wafer 抽樣計畫。 |
| SampleSize | 必填且可轉整數；來源程式未額外限制正負範圍。 |
| SpecLineType | 必填整數 0–3。 |
| ComponentCollect | 可空白，預設 0；輸入只能 0 或 1。 |
| CalType | 可空白，預設 0；輸入只能 0 或 1。 |
| ChartType | 必填整數 0–2；`SampleSize=1` 必須且只能搭配 `ChartType=2`（X-Rm）。 |
| MinValue / MaxValue | 可空白，預設 -999 / 999；須為數值且 MaxValue 大於 MinValue。 |
| Unit / Description | 可空白，預設空字串。 |
| LimitLotNum | 必填正整數。 |
| MClassNo | 可空白；有值時必須存在於 `TBLQCMCLASSBASIS`。 |
| Roundoff_Num | 可空白；輸入整數 0–99，空白使用 Core 預設值。 |
| FactorNo / FactorOnline / FactorSpec | 三欄必須一起填寫或一起空白。FactorNo 必須是已核准 `TBLSYSMESPARAMETER` 的 `ParameterClass=1`；FactorOnline 必須是 FactorNo 子集合；FactorSpec 必須是 FactorOnline 子集合。來源依分號拆分。舊 Core 即使三欄空白，也要求已核准 Class 1 Parameter 查詢非空。 |
| InlineOP / OfflineOP | 可空白；每個作業站都必須存在於已核准 OP。相同 OP 不可同時列在兩欄。Inline 對應保存 FAI/IPQC/PQC 旗標；Offline 的三個旗標強制 0。旗標預設 FAI=0、IPQC=0、PQC=1，輸入需可轉數字。 |
| LotIsVaild 與 ComponentCollect | Core 中「元件收集時 LotIsVaild 必須為 1」檢查已註解，不應誤將它當作現行阻擋規則。 |

另需保留使用中限制：匯入現存 QCItem 前，`DelQCItemForVariables` 會檢查 WIP 中是否正在使用，以及 Material QC Item、Material Type QC Item、OP QC Item、Product QC Item、一般 QC Item Group、PMI QC Item Group 的綁定。任何引用存在時拒絕覆寫。量測記錄亦禁止一般匯入覆寫。檢查與實際寫入之間可能有競爭條件；production API 必須在交易內重查，避免刪除新建立的引用。

## 儲存副作用與安全要求

成功匯入會先呼叫 `DelQCItemForVariables`，清除符合條件的既有 Variable Item 及其 Parameter、Factor、QC Item Group Detail、Rule、QC Spec、QC Chart、Calculate Script、PMI Group Detail、SamplePlanChange 等資料，再建立新的 Variable Item。其後：

- 主檔固定 `ChartControl=1`，建立預設 IssueState=0 的計量 QC Item。
- 即使同一 QCItemNo 已有主檔，只要通過引用檢查，舊流程仍會刪除舊定義再重建，並回到未簽核狀態；API/UI 必須在 Save 前明確提示覆寫，不能默默當成一般更新。
- `ComponentCollect=0` 時依 Plan 複製抽樣參數到 QC Item Parameter；元件計畫不新增這些參數列。
- 建立 QC Item Factor 與作業站對應，Audit Reviser 取登入者。
- 舊 Core 最後會依 Factor 對多張 SPC 資料表呼叫動態新增欄位方法；YMES 不可讓匯入值觸發任意 `ALTER TABLE`。Factor 欄名必須經系統參數白名單驗證，動態量測值應由 YMES 既有的結構化資料設計承接。
- 舊程式以一列為單位呼叫 Core，回傳每列 `success` 或錯誤；整體 Service 通常仍回傳成功，不能把個別列錯誤誤判成整批失敗。API 應逐列回報成功/失敗並在每列內交易提交。
- 舊 Core 的 Creator/CreateDate 可由匯入檔指定。Web API 必須忽略客戶端這兩欄，Creator/Reviser 使用登入者，時間用伺服器時間；保留欄位只為舊範本相容。
- `Check Data` 使用 `OnlyCheck=true`，不寫資料；Save 使用 `OnlyCheck=false`。Check 只回報所選列，成功檢查列仍可編輯/再次儲存。Save 成功列鎖定並取消勾選，失敗列保持可修正與重試。
- 所有 production 端點驗證登入及 FunctionKey=`QC214`。所有 SQL 參數化；不可接受任意欄名、任意 Factor 欄名或上傳路徑作伺服器檔案路徑。

## YMES API 契約

建議下列端點；若家用端沿用既有匯入 API 命名，需同步更新此文件與 Vue：

1. `POST /api/qc/variable-item-import/preview`：`multipart/form-data` 欄位 `file`；安全解析 `.xls/.xlsx` 第一工作表，回傳 `{ rows: [{ ...recognizedColumns }] }`。限制檔案大小、列數、欄數，拒絕公式執行/外部連結；不可寫入資料庫。
2. `POST /api/qc/variable-item-import/check`：JSON `{ rows: [{ ...recognizedColumns }] }`；只驗證，不寫入。回傳 `{ rows: [{ rowNo, qcItemNo, succeeded, result, execute }] }`。
3. `POST /api/qc/variable-item-import/import`：同一 DTO，只匯入本次提交的列。每列在獨立交易重新執行所有驗證及使用中/關聯檢查，成功列單獨提交；失敗列回報可讀錯誤，允許部分成功。每筆覆寫沿用來源清除/重建語意，但只清理經規格核准且無外部引用的 QC205 子表；禁用任意動態 DDL。
4. `GET /api/qc/variable-item-import/template`：依 FunctionNo=`IMPORT QCITEM VARIABLES` 提供 Excel 範本，檔名 `VariablesQCItem_Template`；以 `Content-Disposition` 回傳實際 `.xls/.xlsx` 檔名，讓瀏覽器保留設定的副檔名。

前端一次只送出已勾選且尚未鎖定的列；後端結果依 `rowNo` 對回 Grid。`succeeded=true` 表示該列成功；OnlyCheck 的通過列不鎖定，Import 成功列鎖定。Creator/CreateDate 永遠由伺服器填入。

## 資料表／DDL

QC214 是匯入操作，沒有 QC214 專屬持久化表，不新增 CREATE SQL。需要家用端核對的既有 Oracle 結構與 PostgreSQL 空表參考：

- `TBLQCITEMFORVARIABLES` 主檔：`database/reference/mestest_mtl_qc_item_tables_source_ddl.sql`、`database/reference/mestest_mtl_qc_item_tables_create.sql`。
- SPC/OP/材料/產品/群組引用及刪除關聯：`database/reference/mestest_qc205_variable_dependencies_source_ddl.sql`、`database/reference/mestest_qc210_variable_measurement_log_delete_create.sql`、`database/reference/mestest_qc_item_attributes_create.sql`。
- `TBLQCITEMPARAMETER`、`TBLQCITEMFACTOR` 等與 QC205 共用的主檔/子表沿用 QC205/QC201 DDL 和 CREATE 參考；不要為 QC214 複製建立第二套表。
- 舊 Core 查重寫 `TBLSPCQCCHARTBASIS`，而現有 QC205 Oracle dependency reference 記錄不存在的是不同拼字 `TBLSPCQCHARTBASIS`。兩者不能視為同一個已核實結論；家用端需先以 PostgreSQL schema/migration 與 API SQL 確認實際 chart table，不能只因拼字猜測而新增表。
- Oracle DDL 已由公司端 PowerShell 5.1 + Oracle.ManagedDataAccess 直連 MESTEST 唯讀查詢並保存在上述 reference。本次沿用已查結構，不重新連 Oracle、不讀業務列。家用端先比較 YMES PostgreSQL live schema/migrations，只對確實缺少的結構新增 forward migration；不可執行 Oracle DDL。

## Vue 復刻狀態

- `/YMES/QC/VariableItemImport` 已接到 Vue 3 的品質資料 → 品管設定選單。
- DEV 使用隔離 localStorage 假資料，提供 Excel/CSV 載入、範本、Select All/UnSelect All/MultiSelect、Check Data、Save、逐列色彩與結果、Close。
- DEV 假資料包含兩筆通過與一筆失敗範例；DEV 的成功結果僅變更瀏覽器假資料，未寫入 API/資料庫。
- Production API 尚待家用端實作。本頁尚未執行 build、測試或瀏覽器驗收。
