# QC213 計數品管項目群組

## 功能識別

- MES 第一層：品質資料
- 第二層：品管設定
- 第三層：計數品管項目_群組
- WinForms Form：frmQCItemAttOrderGroup；Define Form：frmQCItemAttOrderGroupDef
- FunctionNo：QCITEM_G_A_ORDER；FunctionKey：QC213
- Vue route：/YMES/QC/AttributeItemGroup
- WinForms 尺寸：主畫面 1008×591；定義表單 484×365
- 公司端先以 DEV 假資料完成 UI。非 DEV 預覽使用 YMES API，API/schema 由家用端接手。

## 畫面與操作

### 主畫面

- 上方提供未簽核、簽核中、已核准、不使用四種狀態及 GroupNo 模糊查詢；預設未簽核。
- 主 Grid 顯示 GroupNo、GroupName、LotIsValid、Description、Creator/CreateDate、Reviser/ReviseDate。來源欄位未顯示者不額外放入主畫面。
- 主檔按鈕：新增、修改、刪除、複製、核准、Op。Add QC 位於下方明細區；主畫面 Remove QC 控制項在 WinForms Designer 設為隱藏。
- 點選主檔列會載入該群組明細。明細 Grid 顯示 GroupNo、QCItemNo、QCItemName、ShowOrder。
- LotIsValid ValueList：0=N、1=Y。

### 新增／修改／複製

- Define Form 標題 QCItem Group Define，欄位為 GroupNo、GroupName、Lot Valid Check（No/Yes）、Description，並顯示唯讀建立/修改人員與時間。
- GroupNo 最長 25 字元、GroupName 最長 50 字元、Description 最長 255 字元；GroupNo 離開欄位時轉大寫。GroupNo、GroupName、Lot Valid Check 必填。
- 新增與複製均建立 IssueState=0；新增/複製由目前登入者建立 audit 欄位。修改時 GroupNo 唯讀，更新 Reviser/ReviseDate/DataStamp。
- 複製視窗帶入來源群組的名稱、LotIsValid、Description，但建立新 GroupNo；WinForms 只儲存新主檔，不複製來源明細。
- Lot Valid Check 預設 No。SPK 系統模式下 WinForms 隱藏 Lot Valid Check。

### Add QC 明細設定

- Add QC 僅允許 IssueState=0。開啟共用雙清單挑選視窗，左側只列 IssueState=2 的計數（Attribute）品管項目；已加入該群組的項目不會再出現在可選清單。
- 可多選加入、移除項目，雙擊列也會移動項目；右側清單可逐筆上移/下移。順序以 ShowOrder 0 起算，重排後連續編號。
- 確認時 UpdAttQCItemOrderGroupDetail 先刪除該 GroupNo 的明細，再依新順序整批新增。API 應以單一 transaction 實作完整替換；新增時驗證群組仍未簽核、品管項目仍已核准且為 Attribute 類型，禁止重複 QCItemNo。
- Core 讀明細時以 Attribute QC Item 表連結，沒有對應 Attribute 品管項目的 orphan 明細不會顯示在清單；Oracle 沒有 FK。

### 核准、刪除與作業站

- 核准只處理 IssueState=0 的群組；WinForms 會先要求目前群組至少有一筆明細。多選時舊 Form 的明細檢查只讀取目前作用中群組，API 應逐筆檢查每個群組都有明細。
- Issue Job 名稱為 ATTQCITEM_G_ORDER。若有簽核 Job，送入簽核流程並改為 IssueState=1；流程核准後設為 2，退回後回到 0。找不到 Job 時直接核准為 2。
- 刪除 IssueState=0 或 -1 資料時硬刪；IssueState=2 改為 -1；IssueState=1 拒絕。硬刪前 Core 會查 `TBLWIPTEMP_QCITEM`，若該 GroupNo 正在使用則拒絕；通過後清理群組明細及 `TBLQCITEMPARAMETER`、`TBLOPQCITEM`、`TBLOPGQCITEMDETAIL`、`TBLPRDQCITEM` 中對應的 QCType=3 關聯。家用端需在 YMES transaction 中核對這些表的實際欄位與刪除順序，避免留下引用資料。
- Op 開啟共用 QC_ItemOp，傳入 QCItemNo=GroupNo、QCType=3、IssueState、LotIsValid。只有已核准項目可維護作業站；LotIsValid=0 時不能新增 InLine 對應。共用畫面有 InLine/OffLine 及 FAI、IPQC、PQC 檢驗時機欄位；InLine 至少勾選一種檢驗時機。沿用既有 OP/QC Item Operation 資源，不新建 QC213 專屬 operation 表。

## YMES API 實作

所有端點要求登入；依目前專案決定尚未啟用 FunctionKey/RBAC 授權。選單識別仍為 FunctionNo `QCITEM_G_A_ORDER`、FunctionKey `QC213`。API 使用參數化 SQL、以資料庫 IssueState/DataStamp 為準，主檔、明細、核准、刪除及作業站整組更新都在交易中執行。

| Method / route | 實作行為 |
| --- | --- |
| GET `/api/qc/attribute-item-groups?functionNo=QCITEM_G_A_ORDER` | 回傳主檔及 audit/DataStamp；可選 `issueState`、`groupNo` 篩選，最多 2000 筆。 |
| POST `/api/qc/attribute-item-groups` | 新增或複製主檔，狀態固定 0；核對 25/50/255 長度、LotIsValid 0/1，並以大小寫無關方式避免與 Attribute/Variable QC Item、一般 QC 群組、PMI 群組撞號。 |
| PUT `/api/qc/attribute-item-groups/{groupNo}` | 只更新 IssueState=0；驗證 DataStamp 並寫入 Reviser/ReviseDate。 |
| DELETE `/api/qc/attribute-item-groups/{groupNo}` | 以 DB 狀態處理：0/-1 硬刪，2 改為 -1，1 拒絕；要求 DataStamp。硬刪時先防止 GroupNo 與其他 QC Item/群組共用，再檢查 WIP QCType=3 使用狀態，最後依來源清理明細、Parameter、OP、OP Group、PRD 關聯。 |
| POST `/api/qc/attribute-item-groups/{groupNo}/approval` | 驗證狀態 0、DataStamp 及至少一筆仍核准的 Attribute 明細。YMES 目前沒有 Issue/Job 表，故依來源行為直接核准為 2；若日後出現標準 Issue/Job 表，API 會先回 503，不會略過簽核流程。 |
| GET `/api/qc/attribute-item-groups/{groupNo}/details` | 依 ShowOrder 回傳 Attribute 明細及 QCItemName；孤兒明細不顯示。 |
| PUT `/api/qc/attribute-item-groups/{groupNo}/details` | 只允許狀態 0；單一交易完整替換明細，驗證 Attribute Item 已核准、不可重複，ShowOrder 為連續 0..N-1，最多 1000 筆。 |
| GET `/api/qc/attribute-qc-items?issueState=2` | 沿用 QC201 已核准 Attribute 品管項目 lookup。 |
| GET/PUT `/api/qc/item-operations?qcItemType=3&qcItemNo={groupNo}` | 讀寫共用 `tblopqcitem` 的 QCType=3 對應；只允許已核准群組寫入，作業站須已核准，依 UI 順序寫入 ExecuteOrder 0..N-1（最多 100 個）。LotIsValid=0 不可設 Inline；Inline 必須勾選 FAI/IPQC/PQC 至少一種。 |
| GET `/api/process/operations?issueState=2` | 沿用已核准作業站 lookup。 |

## YMES schema、部署與驗收

- 正式 YMES 已有 `tblqcitemattgrouporderbasis`，欄位、型別、長度、nullable/default 與來源一致；亦已有 WIP guard、Attribute/Variable QC Item、一般/PMI 群組及 QC 共用 Parameter/OP tables。沒有重建或覆寫這些表。
- Migration `0090_qc213_attribute_item_group.sql` 僅建立缺少的 `tblqcitemattgorderdetail`、`tblopgqcitemdetail`、`tblprdqcitem` 三張空表。`ymes_app` 對群組主/明細具 CRUD，對 OP Group/PRD 清理表只具 DELETE；既有 WIP guard 僅 SELECT。Rollback 會先確認三表仍空才移除。
- 遠端套用前資料庫備份：`/opt/ymes/backups/ymes-before-qc213-0090-20261127.dump`，797,396 bytes，SHA-256 `6b11ec45708589bafce3a5a4cf1c1014cc8bd53bf6e7ed0a109582d11906cb00`；`pg_restore --list` 驗證成功。Migration SHA-256 `5a4e4fd879d49a7656b7d952997d0f6cbb4adf5200f55bcef7045e4009ef3815`。

## 後續維護界線

- Issue/Job table 出現時，先查原生 `ATTQCITEM_G_ORDER` provider、狀態映射及核准/退回通知，再接共用簽核服務；不要直接移除 API 的安全阻擋。
- 正式表與 lookup 均為空時，不以假資料代替資料庫驗收。待有核准項目和安全測試群組後，再驗證新增、修改、複製、明細排序、作業站、核准、停用及硬刪完整往返。
- `database/reference/mestest_qc213_attribute_item_group_create.sql` 是來源結構對照用；不得整份重跑到已包含共用資料的 YMES，也不可在 MES Oracle 執行。
