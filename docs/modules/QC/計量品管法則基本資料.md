## WinForms 主畫面

- 主畫面 ClientSize 為 1008×661；預設「未簽核」(IssueState=0)，可切換簽核中 1、已簽核 2、不使用 -1。SPK 模式隱藏「簽核中」。
- WinForms 載入全表後在前端篩選 IssueState，另外固定排除 `RuleType=2` 與 `WEType<>0`，依 `RuleSerial, RuleNo` 排序。這頁沒有搜尋欄。
- 主 Grid 顯示 RuleNo、RuleName、Description、RuleType（0=System、1=User Define）、FunctionName、Creator、CreateDate、Reviser、ReviseDate；RuleSerial、IssueState、WEType、DataStamp 不顯示。
- 按鈕為新增、修改、刪除、複製、核准、關閉；沒有匯入、下載或列印。新增/修改/複製開啟 624×509 的定義視窗。
- 刪除與核准可多選，逐筆呼叫服務；首筆錯誤停止，先前成功資料保留。修改與複製以作用列為準。

## 定義視窗與法則欄位

- RuleNo 必填，離開欄位時轉大寫，最多 30 字；RuleName 必填，最多 50 字；Description 最多 255 字。新增時 `RuleSerial=RuleNo`。Oracle 只以 RuleSerial 為主鍵；服務另以大寫 RuleNo 檢查重複。
- RuleType：0 System、1 User Define。User Define 必須選 FunctionName；舊服務由 `udQCRule.clsQCRule` 的私有方法名稱篩出包含 `FUNQR` 的函式。Web API 應提供安全的函式目錄選項，不應在 Web 端反射 MES DLL。
- System 會載入 `GetValueList("TBLQCRULEBASIS", "RULEOPTION")`，依選項切換下方分頁。畫面選項值與 Oracle 欄位值並非完全相同：

| WinForms 選項/分頁代碼 | 顯示名稱 | Oracle RuleOption |
| ---: | --- | ---: |
| 0 | Value | 0 |
| 1 | Value Range | 3 |
| 2 | Sigma | 1 |
| 3 | Line | 2 |
| 4 | Sigma Range | 4 |
| 5 | Other | 5 |
| 6 | Special Value | 6 |

- 舊資料 RuleOption=9 也會載入 Other 分頁；Web 頁讀取此值時應顯示為 Other，修改既有 9 時保留 9。新建 Other 使用 5。舊程式的 Rank (7) 已由 ValueList 移除，不納入新建選項。
- 法則欄位共用 `TestOutof`、`TestCount`、`CompareValue1`、`CompareValue2`、`Relation`：

| 選項 | 編輯欄位與選項 | WinForms 驗證重點 |
| --- | --- | --- |
| Value | TestOutof、TestCount、數值 CompareValue1、Relation | 欄位必填；TestOutof/TestCount 為 1–99，TestCount 為整數；TestOutof ≥ TestCount |
| Value Range | TestOutof、TestCount、上下限 CompareValue1/2、Relation | TestOutof/TestCount 必須整數；上下限為數字；下限不得大於上限；數量 1–99 且 TestOutof ≥ TestCount |
| Sigma | TestOutof、TestCount、數值 CompareValue1、Relation | 數量 1–99 且 TestOutof ≥ TestCount |
| Line | TestOutof、TestCount、CompareValue1=`US/UCL/CL/LCL/LS`、Relation | 數量 1–99 且 TestOutof ≥ TestCount |
| Sigma Range | TestOutof、TestCount、數值 CompareValue1、Relation | 數量 1–99 且 TestOutof ≥ TestCount |
| Other | TestOutof、TestCount、Relation=`Increase/Decrease/Alternate` | 數量 1–99 且 TestOutof ≥ TestCount |
| Special Value | CompareValue1=`CpkGoal/US/UCL/CL/LCL/LS/SpecLimit`、TestCount、Relation | CpkGoal 固定 TestOutof/TestCount=1 並隱藏 TestCount；SpecLimit 使用 Between/Beyond，其他值使用比較運算子 |

- Value/Sigma/Line/Sigma Range 的一般 Relation 為 `>`、`>=`、`<`、`<=`、`=`、`<>`。Special Value 的一般 Relation 不含 `=`；SpecLimit 改用 Between/Beyond。Value Range 使用 Between/Beyond。
- Add/Copy 初始為 System/Value。Copy 會帶入既有資料，使用者必須改成新 RuleNo。切成 User Define 時下方 System 規則控制停用；必須選 FunctionName。
- 編輯時執行 `ExeIssueControl`；狀態 0 可修改，狀態 1 不可修改，狀態 2/-1 依 Issue Control 的欄位設定控制。API 缺少欄位權限資料時應唯讀。

## CRUD、簽核與 DataStamp

- Add/Copy 建立 IssueState=0、RuleSerial=RuleNo，帶入 Creator/CreateDate。
- Edit 以 RuleNo 定位，寫入 Reviser/ReviseDate，並以 `DataStamp` 比對後遞增。原 WinForms 對未傳入欄位採 sparse update：空白/未選取欄位通常不會清除既有資料；YMES 若改成清空非目前 RuleOption 欄位，需在 API 規格明示差異。
- `RuleNo` 大小寫不敏感重複檢查由服務執行；DB 主鍵是 `RuleSerial`。新增時兩者預期相同，但需保留兩欄及其不同限制。
- Delete：state 0/-1 實體刪除；state 2 以 DataStamp CAS 改為 -1 並更新 Reviser/ReviseDate；state 1 不允許。
- Approve 僅處理 state 0，Issue Job Map 為 `QC RULE BASIS`。無 Job/Detail 時直接 0→2；有簽核流程時建立 Issue、改為 1 並通知首簽核群組，之後核准 2、退回 0。狀態寫入帶 Reviser/ReviseDate/DataStamp；API 回傳實際狀態。

## Oracle 結構與索引

來源 DDL 由公司端 PowerShell 5.1 + Oracle.ManagedDataAccess 經本機受保護設定唯讀查詢；未讀取 MES 業務列，也沒有在 Oracle 執行 DDL。

| 欄位 | Oracle 型別/限制 |
| --- | --- |
| RuleSerial | VARCHAR2(30) NOT NULL PK |
| RuleNo | VARCHAR2(30) NOT NULL |
| RuleName | VARCHAR2(50) NOT NULL |
| FunctionName | VARCHAR2(50) NULL |
| RuleType / IssueState | NUMBER(1,0) DEFAULT 0 NULL |
| Creator / Reviser | VARCHAR2(10) NULL |
| CreateDate / ReviseDate | DATE NULL |
| Description | VARCHAR2(255) NULL |
| RuleOption | NUMBER(1,0) NULL |
| TestOutof / TestCount | NUMBER(2,0) NULL |
| CompareValue1 / CompareValue2 / Relation | VARCHAR2(10) NULL |
| WEType | NUMBER(1,0) DEFAULT 0 NULL |
| DataStamp | NUMBER(11,0) DEFAULT 0 NULL |

- 唯一索引只有 PK(RuleSerial)；沒有外鍵或額外索引。RuleNo 沒有 DB unique constraint。
- Oracle DDL：[`mestest_qc_variable_rule_basis_source_ddl.sql`](../../../database/reference/mestest_qc_variable_rule_basis_source_ddl.sql)。PostgreSQL 空表參考：[`mestest_qc_variable_rule_basis_create.sql`](../../../database/reference/mestest_qc_variable_rule_basis_create.sql)。家用端需先核對 YMES live schema/migrations，只建立必要 forward migration。

## Vue DEV 頁與 API handoff

DEV 頁以標示 DEMO 的 localStorage 假資料呈現 WinForms 狀態篩選、欄位與按鈕、System/User Define、七種 RuleOption、欄位驗證、RuleOption 舊值映射、複製、刪除、核准及 Issue Control。Production 不讀 localStorage 假資料。

建議以 FunctionKey `QC108` 授權所有 endpoint，SQL 參數化：

- `GET /api/qc/rule-bases`：回傳主檔欄位、audit、IssueState、DataStamp、editableFields；UI 依狀態、`RuleType<>2`、`WEType=0` 過濾並排序 `RuleSerial,RuleNo`。
- `GET /api/qc/rule-bases/options/rule-options`：回傳 ValueList 原始儲存值及顯示名稱；UI 依上表轉為分頁代碼。`GET /api/qc/rule-bases/options/functions`：提供有效的 `FUNQR*` 函式目錄。
- `POST /api/qc/rule-bases`：建立 RuleSerial=RuleNo、state0、登入者與伺服器時間 audit；驗證必填/長度、RuleNo 大寫不重複、RuleType、FunctionName、RuleOption、各分頁欄位、1–99 範圍、TestOutof≥TestCount、比較上下限與 DataStamp 初值。
- `PUT /api/qc/rule-bases/{ruleNo}?issueState=&dataStamp=`：RuleNo 不可改；依 Issue Control 欄位白名單更新，使用 nullable DataStamp CAS，衝突回 409。API 要保留來源 sparse update 語義，或把清除舊選項欄位記錄成明確 YMES 差異。
- `DELETE /api/qc/rule-bases/{ruleNo}?issueState=&dataStamp=`：state 0/-1 實體刪除；state2 改 -1 並更新 audit/DataStamp；state1 拒絕。
- `POST /api/qc/rule-bases/{ruleNo}/approve?issueState=0&dataStamp=`：依 Issue Job Map `QC RULE BASIS` 執行 bypass 核准或共用 Issue 流程。
- 多選刪除/核准逐筆呼叫，首錯停止並回報已完成筆數。所有資料寫入和欄位權限檢查由 API 執行。
