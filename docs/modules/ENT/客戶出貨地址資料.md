# 客戶出貨地址資料（ET106）

## 功能來源

- 第一層：客戶資料（ENT）；第二層：客戶資料設定；第三層：客戶出貨地址資料。
- FunctionNo：`ET106`；FunctionName：`CUSTOMER SHIP ADDRESS`；WinForms Form：`frmCustomerShipAddr`；資料表單：`frmCustomerShipAddrDef`、`frmCustomerShipDeclarationDef`。
- 來源程式：`STD/MESWin/ENT/ET_CustomerShipAddr`、`STD/MESws_STD/wsSTD/wsENT/wsENT.cs`、`STD/MESkc/kcENT/clsCustomerBasis.cs`。
- Vue 元件：`web/src/components/CustomerShipAddressMaster.vue`；路徑：`/YMES/Customer/ShipAddresses`。

## 主畫面與操作

WinForms 視窗最大化。上方以 `...` 選取客戶，選擇器明確只載入已簽核 `IssueState=2` 的客戶。上半部群組為 Ship To Code（出貨地點），下半部群組為 Ship To Declaration（出貨報關）；Print 在 Designer 設為隱藏。

出貨地點清單隱藏分組框及 DataStamp，欄位順序：CustomerNo、Flow、ShipCustomerName、Country、OverseaFlag、DeclarationFlag、ContactorName、TelNo、FaxNo、Email、ShipAddr、ShipAddr2、CompanyName、TakerNo、ForwarderNo、Broker、Description、Creator、CreateDate、Reviser、ReviseDate。清單按 ShipAddr 排序。

報關清單也隱藏分組框及 DataStamp，按 ShipTo 排序。載入條件只有 CustomerNo，所以顯示該客戶全部報關列；目前選取的出貨地點不會過濾報關清單。選取出貨地點只作為「新增報關」的預設來源：ShipTo 取自該列 ShipCustomerName，並帶入 OverseaFlag、DeclarationFlag。

- 出貨地點按鈕：新增、修改、刪除、複製。刪除支援多選、逐筆呼叫，第一筆失敗即停止；成功列不回復。新增/修改後重載兩個清單。
- 報關按鈕：新增、修改、刪除；新增必須先選單筆出貨地點，修改只需選取單筆報關列，刪除支援多選並逐筆處理。
- 關閉按鈕離開此 WinForm；Vue 版清除目前客戶與兩份清單。
- Vue Development 使用明確 DEV 假資料及 localStorage；Production 只呼叫 API，缺少 API 時顯示待建訊息。

## 出貨地點表單

表單欄位：CustomerNo、ShipCustomerName、Flow、ShipAddr、Country、OverseaFlag、DeclarationFlag、ContactorName、TelNo、FaxNo、Email、ShipAddr2、CompanyName、TakerNo、ForwarderNo、Broker、Description，以及 Creator/CreateDate/Reviser/ReviseDate 稽核欄位。TakerNo、ForwarderNo、Broker 為唯讀欄位，使用 `...` 分別呼叫取貨公司、貨運行、報關行查找。

- 新增/複製必填 ShipCustomerName、ShipAddr。Confirm 對空白 Flow 自動代入 `N/A`；Apply 則要求 Flow 不可空白。
- Contact、電話、傳真、Email、Country、CompanyName、Taker、Forwarder、Broker、Description 的必填檢查在 WinForms 中是註解，實際可空白。
- Edit 將 CustomerNo、Flow、ShipCustomerName 設唯讀並鎖 DeclarationFlag；ShipAddr 可編輯（它是 `(CustomerNo, ShipAddr)` 主鍵欄位），OverseaFlag 與其餘資料可編輯。
- Copy 會帶入原列所有欄位，包括 ShipAddr；沒有自動清空主鍵欄位，使用者要自行改地址以避免重複主鍵。
- 只有 `gEnterpriseNo.ToUpper="YUHSIN"` 時，新資料預填 Flow、CompanyName、Broker、Forwarder、Taker 為 `N/A`。Vue DEV 預覽採用這組示例預設；正式 API/部署需依 YMES 企業設定決定，不以瀏覽器假設企業代碼。
- 原始 WinForms UI 對多數欄位沒有設定 MaxLength；API 最終仍須依 Oracle DDL 長度驗證。例：ContactorName 的 UI 允許 50 字，Oracle 欄位只有 25 字。
- Taker/Forwarder/Broker 選擇器分別呼叫 `wsENT.LoadTakerBasis`、`LoadForwarderBasis`、`LoadBrokerBasis`，舊程式只顯示 `IssueState=2`；Vue DEV 使用假選項，Production 需由對應 ENT API 提供清單。

## 報關資料表單

欄位：CustomerNo、ShipTo、Flow、OverseaFlag、DeclarationFlag、BondFlag、HandCarryFlag、DeclarationWay，以及稽核欄位。ShipTo、Flow、DeclarationWay 必填。新增時 ShipTo/海外/報關旗標從所選出貨地點帶入；BondFlag 預設 1（是），HandCarryFlag 預設 0（否），Flow 與 DeclarationWay 由使用者輸入。

Edit 模式將 ShipTo、Flow 設唯讀，Oversea/Declaration/Bond/HandCarry 四個旗標群組皆鎖定，只能修改 DeclarationWay。Apply 儲存後保留視窗；Confirm 儲存後關閉。舊刪除/修改用 CustomerNo、ShipTo、Flow、OverseaFlag、DeclarationFlag、BondFlag、HandCarryFlag 作為定位欄位；沒有 Copy 按鈕。

## Oracle 結構與 Create SQL

出貨地點 `TBLENTCUSTOMERSHIPADDR` 的 22 欄 DDL/空表 SQL 已隨 ET101 交付；本功能另於 2026-11-16 使用 Windows PowerShell 5.1 + Oracle.ManagedDataAccess，透過受保護連線直接唯讀查詢報關表 `MESTEST.TBLENTCUSTOMERSHIPDECLARATION` 的 DBMS_METADATA DDL 及資料字典。沒有查詢業務資料、沒有在 Oracle 執行 DDL。

- Oracle logical DDL：`database/reference/mestest_customer_basis_source_ddl.sql`
- PostgreSQL 空表 CREATE SQL：`database/reference/mestest_customer_basis_create.sql`

報關表欄位：

| 欄位 | Oracle 型別 | NULL / DEFAULT |
| --- | --- | --- |
| CUSTOMERNO | VARCHAR2(50) | NOT NULL |
| SHIPTO | VARCHAR2(10) | NOT NULL |
| FLOW | VARCHAR2(10) | NOT NULL |
| OVERSEAFLAG | VARCHAR2(1) | NOT NULL |
| DECLARATIONFLAG | VARCHAR2(1) | NOT NULL |
| BONDFLAG | VARCHAR2(1) | NOT NULL |
| HANDCARRYFLAG | VARCHAR2(1) | NOT NULL |
| DECLARATIONWAY | VARCHAR2(50) | NOT NULL |
| CREATOR | VARCHAR2(10) | NULL |
| CREATEDATE | DATE | DEFAULT SYSDATE，nullable |
| DATASTAMP | NUMBER(11,0) | DEFAULT 0，nullable |
| REVISER | VARCHAR2(10) | NULL |
| REVISEDATE | DATE | NULL |

資料字典沒有回傳 PK、unique index、一般 index 或 FK；八個 NOT NULL 是唯一 constraint。`CREATE SQL` 不加 PK/唯一索引/FK，避免把來源沒有的唯一性引入。舊 Core 將七個值當作報關資料的自然定位條件；資料表允許完全重複的列，故 API 需保留舊服務對相同鍵列的處理行為，不能虛構單一主鍵。

出貨地點表本身有 PK `(CUSTOMERNO, SHIPADDR)`，無 FK/其他索引。舊刪除出貨地點只刪地址列，沒有同步刪 `TBLENTCUSTOMERSHIPDECLARATION`；修改 ShipAddr 也可能留下舊 ShipTo 值。沒有 FK，因此不應假設 Oracle 會級聯處理。此為原系統可觀察行為，API 文件需明確寫出。

## YMES API 契約（交家用電腦）

| Method | Endpoint | 用途 |
| --- | --- | --- |
| GET | `/api/ent/customer-basis` | 客戶查找；Vue 僅保留 IssueState=2 |
| GET | `/api/ent/customer-basis/{customerNo}/ship-addresses` | 出貨地址清單，按 ShipAddr 排序 |
| POST | `/api/ent/customer-basis/{customerNo}/ship-addresses` | 新增地址；伺服器填 Creator/CreateDate/DataStamp |
| PUT | `/api/ent/customer-basis/{customerNo}/ship-addresses/{oldShipAddr}` | 修改地址；body 可更新 ShipAddr，使用舊鍵與 DataStamp |
| DELETE | `/api/ent/customer-basis/{customerNo}/ship-addresses/{shipAddr}?flow=&shipCustomerName=&declarationFlag=&dataStamp=` | 逐筆刪地址 |
| GET | `/api/ent/customer-basis/{customerNo}/ship-declarations` | 客戶全部報關資料，按 ShipTo 排序 |
| POST | `/api/ent/customer-basis/{customerNo}/ship-declarations` | 新增報關資料 |
| PUT | `/api/ent/customer-basis/{customerNo}/ship-declarations?shipTo=&flow=&overseaFlag=&declarationFlag=&bondFlag=&handCarryFlag=&dataStamp=` | 依原七欄定位修改報關資料 |
| DELETE | `/api/ent/customer-basis/{customerNo}/ship-declarations?shipTo=&flow=&overseaFlag=&declarationFlag=&bondFlag=&handCarryFlag=&dataStamp=` | 依原七欄逐筆刪報關資料 |
| GET | `/api/ent/taker-basis?issueState=2`、`/api/ent/forwarder-basis?issueState=2`、`/api/ent/broker-basis?issueState=2` | 地址表單三個選擇器；共用主檔 API 僅回傳已簽核選項，選項名稱使用 ContactorName |

寫入依 DDL 長度驗證；新資料 Creator/CreateDate、更新 Reviser/ReviseDate 由伺服器產生。DataStamp 作 YMES 樂觀鎖，來源表可為 NULL。Core 宣告的 `EditCustomerShipAddr`、`EditCustomerShipDeclaration` 目前沒有 DataStamp/Reviser/ReviseDate 參數，但 `wsENT` 呼叫卻傳入同名參數，與客戶連絡人相同，顯示被檢視的 Service/Core 來源版本不一致；Modern API 請依表欄位明確實作稽核及併發保護。
