# ENT ET105 取貨公司基本資料

## 功能來源

- 第一層：客戶資料；第二層：客戶資料設定；第三層：取貨公司基本資料。
- FunctionNo／IssueNo：`TAKER BASIS`；FunctionKey：`ET105`；FunctionName：`取貨公司基本資料`。WinForms Forms：`frmTakerBasis`、`frmTakerBasisDef`；程式位於 `STD/MESWin/ENT/ET_TakerBasis`。
- Oracle 主表：`MESTEST.TBLENTTAKERBASIS`；YMES PostgreSQL：`"YMES".tblenttakerbasis`（正式schema大小寫依Root實際字典）。
- Vue 元件（正式API／隔離DEV）：`web/src/components/TakerBasisMaster.vue`；路徑：`/YMES/Customer/Takers`。
- 規格根據 WinForms Form/inline Designer、`wsENT`、`kcENT.clsCustomerBasis` 與 Oracle 資料字典；沒有讀取 Oracle 業務資料。

## WinForms 主清單

- 主視窗最大化（設計尺寸 1008×591），預設 IssueState=0。狀態選項：未簽核 0、簽核中 1、已簽核 2、不使用 -1。
- 搜尋欄位只有 TakerNo。舊程式載入清單後在 DataView 本機套用狀態篩選；Web 狀態切換與點選資料列皆為前端動態更新。
- Grid 由 `SELECT *` 綁定；顯示 TakerNo、ContactorName、TelNo、FaxNo、Email、Address、BankNo、Creator、CreateDate、Reviser、ReviseDate；IssueState/DataStamp 隱藏但供按鈕判斷。日期格式 `yyyy/MM/dd HH:mm:ss`。
- 右側按鈕：ADD、EDIT、DEL、Approve、Close；Print 隱藏。主畫面沒有 Copy 按鈕（DefMode 有 Copy 分支但無可見入口）。
- 多選刪除/核准逐筆呼叫 WebService，遇第一錯誤停止，先前成功項目不回滾；有成功刪除時重載清單。新增成功後重載並在 IssueState=0 篩選下選取新 TakerNo。
- EDIT 僅允許 IssueState=0；其他狀態不進編輯表單。

## WinForms 編輯表單

- 固定單一視窗、置中、507×284。欄位順序/排版：TakerNo（必填、Add 時 KD 淡黃色、Edit 唯讀）、Contactor、TEL、Fax、Email、Address、Bank No；右下按鈕 Confirm、Close、Apply。
- 只有 TakerNo 必填。Add/Copy 模式的 TakerNo 離開欄位時轉大寫；資料欄位沒有 WinForms MaxLength，Web 輸入依 Oracle 長度驗證，超長拒絕、不截斷。
- Apply 儲存後留在表單並停用 Apply，變更欄位後重新啟用；Confirm 儲存成功後關閉。Add 後連續 Apply 的舊模式會重複呼叫新增；Vue 第一次 Apply 成功後轉成 Edit 以避免重複新增。
- Edit 時 TakerNo 唯讀，其他欄位可編輯。建立/修改人與時間為唯讀稽核欄。

## 刪除與簽核

- 刪除接受 IssueState 0、-1、2：0/-1 實體刪除，2 軟刪除改為 -1；狀態 1 不允許。
- 核准只接受 IssueState=0，IssueNo=`TAKER BASIS`。無 Job 或 Job 無 Detail 時直接轉 2；有 Detail 時建立簽核單、狀態轉 1，核准 SQL 轉 2、退回 SQL 回 0，並通知第一簽核群組。Production API 必須走 YMES 共用簽核服務；DEV 僅直接模擬 0→2。
- 舊 `wsENT` 呼叫 `EditTakerBasis`、`SetTakerBasisIssueState` 時傳入 DataStamp/Reviser/ReviseDate named arguments，但此份 `kcENT.clsCustomerBasis` 方法宣告沒有這些參數；來源版本不一致。Core 的 Edit SQL 也沒有寫 audit/DataStamp；狀態 helper 只更新 IssueState。新 API 依現代契約實作 server audit、DataStamp compare-and-swap 與交易，不照搬缺漏。
- 核准流程完成後的 Raw ApproveSQL/RejectSQL 只更新 IssueState，舊實作未同步 audit/DataStamp；Production 簽核仍需透過既有 YMES issue service，並在可擴充的交易位置維持 audit/concurrency 一致。

### 狀態、nullable CAS、稽核與交易

`issueState`原NULL／未知仍可讀，不當0。Edit只state0；Approve只state0；Delete依上表0／-1／2，state1拒絕。JSON缺少token與明確NULL不同，`JsonRequired`使缺property回400；資料庫比對`IS NOT DISTINCT FROM`，NULL token不可用0代替。來源`numeric(11,0)`stamp範圍為整數`-99999999999..99999999999`；非整數／超界回400。遞增`COALESCE(stamp,0)+1`，支援NULL→1及-1→0。最大值無法再Edit／Approve／停用而回409，但匹配最大值的硬刪不遞增，可執行。

各writer使用ReadCommitted交易，先取得`hashtextextended('YMES:ENT:Taker:' || lower(btrim(key)),0)` advisory lock，再核對真registry／來源形狀，已有列使用`FOR UPDATE`並重讀實際狀態／stamp；Create同namespace查重後才新增。持鎖至commit，跨大小寫／空白相同identity的新建、修改、核准、刪除共用鎖序。所有SQL參數化，不以UIdisabled或瀏覽器token代替server驗證。

Creator／Reviser由登入claims取值、依來源10字元限制，不接受body spoof；new write／revision用`now() AT TIME ZONE 'UTC'`寫入timestamp without time zone。API將已知UTC audit回ISO Z，前端轉本地顯示；既有NULL creation audit、raw key及未改動來源值原樣保留。400為缺欄／malformed，401未登入，404缺列，409 stale／duplicate／alias／禁止狀態／最大stamp，422來源欄位／不可變鍵／NULL或未知狀態，503必要來源或provider不可用。資料庫例外回乾淨ProblemDetails，server log不輸出SQL、連線或密碼。

### 引用與簽核邊界

已核對registry目前只有本表TakerNo。Repository只從非system `r/p/v/m/f` catalog查`takerno/taker/takerassigned`及本表名稱／型別／欄位形狀；index attributes不當引用。任何新實體引用未列入已審registry時回503，不任意讀取未知業務表、不把缺依賴當空成功。這是明載YMES保守完整性規則，不宣稱原Core有FK／cascade或相同刪除guard。

原生未來ET106的`tblentcustomershipaddr.takerno`已在來源DDL出現，但本批metadata audit時實體表不存在；ET105不建該表或grant不存在的引用。ET106出現時必須另核形狀／權限、啟用真引用reader，並讓ET106 writer取得相同Taker namespace→唯一已核准parent`FOR SHARE`→child鎖至commit，和ET105 parent刪除／停用協作。現階段不能宣稱ET106整合或跨模組引用保護已交付。

原生簽核來源有Job／Detail分支；目前只完成「實際沒有任何known／pattern Job候選」的direct state2。偵測到任何Job候選就503，不能將缺provider、空Job或未知Detail規格當簽核成功；不發原生通知或偽造簽核單。來源Job真provider、通知、回簽／退回及角色ACL仍待後續來源與共用服務，不因這些未提供項目偽造其他資料。
