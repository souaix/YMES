# ENT ET202 外包項目設定

## HOME正式API與UI契約 2026-11-21

HOME負責PostgreSQL復刻、API與SSH發行；Office維持原生Oracle唯讀來源與UI。下文原生表單／來源說明完整保留；舊「YMES API 契約」的path-key與query stamp是早期草案，本次正式實作採以下query-key及JSON nullable stamp，請勿再使用舊PUT／DELETE路徑。

| 方法 | `/YMES/API` 後的路徑 | 契約 |
|---|---|---|
| GET | `/api/ent/os-items?osItemNo=` | literal contains，不將百分號當wildcard；回`{items: DTO[]}`，C排序 |
| GET | `/api/ent/os-items/item?osItemNo=` | 全11欄單張；404為真缺列 |
| POST | `/api/ent/os-items` | 六個業務欄位全部required；200回真saved DTO |
| PUT | `/api/ent/os-items/item?osItemNo=` | 六業務欄位＋required nullable `dataStamp`；200回真saved DTO |
| DELETE | `/api/ent/os-items/item?osItemNo=` | JSON `{dataStamp:number|null}`；200回`{osItemNo:actualRaw,deletedCount:1}` |

DTO為`osItemNo,osItemName,planDays,processNo,returnType,description,creator,createDate,dataStamp,reviser,reviseDate`。Description保留NULL與空字串差異，audit NULL保留；actor與UTC時間由server產生，Edit保留建立欄。新No由PG upper/btrim後重驗2個Unicode scalar，既有raw身份不可變；Name50、Process30、Description255按scalar計，PlanDays0–999、ReturnType0／1，讀取不擅改舊未知值。

DataStamp支援原生signed11位整數及NULL，missing與NULL不同；PUT用`IS NOT DISTINCT FROM` CAS，NULL→1、負值正常遞增，正max更新409；matching max可刪。案例中的斜線、百分號、引號、原始大小寫／padding都用query編碼；邏輯同名多raw別名409，不任選。

每次save重查Process所有版本，至少一版IssueState2且ProcessClass3，不限制CurrentVersion。父流程共用identifier鎖→所有matching父列SHARE→外包項目鎖／表ROW EXCLUSIVE→fresh native guard→own row CAS；CreateVersion／SetCurrent也配合同namespace。Parent硬刪在表absent時保持既有行為，present時查真引用而409保留；退休2→−1仍可保留引用。另窄修舊Process硬刪SQL只接受0導致−1無法清理的缺漏，只允0／−1及當前state／既有CAS，未知／pending狀態拒刪。既有Process int／NULL-coalesced token語意未在本模組改造。

正式UI保KD、單App標題、表格內捲動、回空白Home、原生Add／Copy Apply後仍Add／Copy；儲存採真完整saved DTO。多選逐筆刪除，以實際count累計、遇首錯停。未知寫入結果停止送出，需明確重新查詢核對，不自動重放。用Vue確認框；焦點A2補上原Copy／Add已disabled時回Query的備援。原公司DEV元件bytes完整保留，只有DEV且preview=true才lazy載入，正式不fallback假資料。

## WinForms 主畫面

`frmENTOSItem` 最大化，ClientSize 設計值 1008×591。表格由 x=12、y=53 起，寬 892、高 510；右側按鈕寬 88、高 32，依序新增、修改、刪除、複製，右下方關閉。底部狀態列有四個 Panel，顯示使用者/狀態及時間。繼承的查詢列只設定 `OSItemNo` 為搜尋欄位；此功能不顯示簽核狀態篩選，沒有核准按鈕。

主畫面動作：

- 新增開啟 `frmENTOSItemDef` 的 Add 模式。
- 修改及複製使用目前資料列；修改時編號唯讀，複製時清空編號並沿用其他欄位。
- 刪除可多選，先詢問確認，再逐筆呼叫刪除 Service；遇第一筆錯誤即停止，已有成功刪除時重新載入。
- 新增/修改/複製成功後重新載入，並選取剛建立或更新的 OSItemNo。
- 關閉關閉目前 WinForms 表單。Web 頁對應回主選單。

## Service/Core 行為與差異

- `LoadENTOSItem` 可選擇依 OSItemNo 搜尋；核心 SQL 排除空編號，`GetSamplingTableXml` 參數雖存在，主畫面未要求 sampling XML。
- Add/Copy 以 `AddENTOSItem` 寫入 OSItemNo、OSItemName、PlanDays、ProcessNo、ReturnType、Description 與 Creator/CreateDate。
- Edit 由 WinForms/ws 傳 DataStamp；目前檢視的舊版 `clsCustomerBasis.EditENTOSItem` 方法簽章不含 DataStamp/Reviser/ReviseDate，舊 Core SQL 也沒有相應的樂觀鎖與 audit 更新。新 API 契約需自行補齊資料版本檢查與伺服器端 audit，不能直接照搬舊 Core 的缺漏。
- Delete 的舊 Core 依 OSItemNo 實體刪除，沒有 DataStamp compare-and-swap。新 API 應加入 DataStamp 併發檢查；前端保留 WinForms 的多選逐筆、遇錯停止行為。
- 本功能沒有 IssueState 欄位、簽核按鈕或簽核流程。

## 歷史API契約草案（以下path-key已被頁首正式契約取代）（家用端）

- `GET /api/ent/os-items?osItemNo=`：取得清單；空值列出全體，有值依 OSItemNo 搜尋。
- `POST /api/ent/os-items`：新增，JSON 欄位 `osItemNo, osItemName, planDays, processNo, returnType, description`。
- `PUT /api/ent/os-items/{osItemNo}?dataStamp=`：更新允許修改的欄位並執行 DataStamp compare-and-swap。
- `DELETE /api/ent/os-items/{osItemNo}?dataStamp=`：實體刪除，DataStamp 不一致回 409。
- 欄位必填與長度依 Oracle DDL；PlanDays 為 0–999 整數，ReturnType 限 0/1。OSItemNo 寫入前大寫；ProcessNo 必須參照 IssueState=2、ProcessClass=3 的流程。所有寫入的 Creator/CreateDate/Reviser/ReviseDate 由 API 設定。API 使用 YMES PostgreSQL schema；部署前對照實際大小寫命名及 migration。

公司端 Vue DEV 頁只在 Development 使用 localStorage 假資料；正式/測試環境只呼叫 API，404 明確提示家用端 API 尚未建立，不會 fallback 假資料。本次未執行 build、測試或瀏覽器驗收。
