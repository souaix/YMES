## WinForms 主畫面

`frmENTOSItem` 最大化，ClientSize 設計值 1008×591。表格由 x=12、y=53 起，寬 892、高 510；右側按鈕寬 88、高 32，依序新增、修改、刪除、複製，右下方關閉。底部狀態列有四個 Panel，顯示使用者/狀態及時間。繼承的查詢列只設定 `OSItemNo` 為搜尋欄位；此功能不顯示簽核狀態篩選，沒有核准按鈕。

Grid 依 OSItemNo 升冪排序，欄位不允許直接編輯：

| 欄位 | WinForms 寬度 | 顯示/格式 |
| --- | ---: | --- |
| OSItemNo | 100 | 固定欄 |
| OSItemName | 120 | 名稱 |
| PlanDays | 120 | 靠右對齊 |
| ProcessNo | 80 | 外包流程編號 |
| ReturnType | 150 | ValueList 顯示退回原製程語意 |
| Description | 400 | 多行 |
| Creator / CreateDate | 80 / 150 | 建立稽核；日期 `yyyy/MM/dd HH:mm:ss` |
| Reviser / ReviseDate | 80 / 150 | 修改稽核；日期 `yyyy/MM/dd HH:mm:ss` |
| DataStamp | — | 隱藏 |

主畫面動作：

- 新增開啟 `frmENTOSItemDef` 的 Add 模式。
- 修改及複製使用目前資料列；修改時編號唯讀，複製時清空編號並沿用其他欄位。
- 刪除可多選，先詢問確認，再逐筆呼叫刪除 Service；遇第一筆錯誤即停止，已有成功刪除時重新載入。
- 新增/修改/複製成功後重新載入，並選取剛建立或更新的 OSItemNo。
- 關閉關閉目前 WinForms 表單。Web 頁對應回主選單。

## 新增/修改/複製表單

`frmENTOSItemDef` 固定大小、置中，ClientSize 540×443。主要 GroupBox 標題為 Sampling Table，包含：

| 欄位 | 限制與規則 |
| --- | --- |
| OSItemNo | 必填，最大 2 字元；離開欄位轉大寫。Edit 模式不可改；Copy 可輸入新編號。 |
| OSItemName | 必填，最大 50 字元。 |
| PlanDays | 必填數字、整數、不得小於 0；資料庫 NUMBER(3,0)。 |
| ProcessNo | 必填；WinForms 輸入最大 25 字元，旁有 `...` 查找。資料庫 VARCHAR2(30)。 |
| ReturnType | Radio：0 = 不回原製程；1 = 回原製程；新增預設 0。 |
| Description | 選填，多行，最大 255 字元。 |

底部沿用共用表單的建立人/建立日期、修改人/修改日期與「確定、關閉、套用」。新增及複製建立人/日期取目前使用者與時間；修改保留建立欄並預填修改人/時間。確定儲存後關閉；套用儲存後停留。WinForms 在 Add 套用後仍維持 Add 模式，重複套用同一編號會得到重複鍵錯誤；複刻頁沿用此模式的操作特性。

流程查找由 `funLoadProcessBasis` 呼叫 `wsPRS.LoadProcess`，條件為 IssueState=2、ProcessClass=3、CurVersion 傳預設值（未要求僅目前版本）。查找視窗移除 TuningProcess、PARTIALTYPE 欄，依 ProcessNo 選取。儲存時也以載入的流程清單檢查 ProcessNo 存在。Web 頁用既有 `GET /api/processes?issueState=2`，再限定 ProcessClass=3；Development 使用標示清楚的本地流程假資料。

## Service/Core 行為與差異

- `LoadENTOSItem` 可選擇依 OSItemNo 搜尋；核心 SQL 排除空編號，`GetSamplingTableXml` 參數雖存在，主畫面未要求 sampling XML。
- Add/Copy 以 `AddENTOSItem` 寫入 OSItemNo、OSItemName、PlanDays、ProcessNo、ReturnType、Description 與 Creator/CreateDate。
- Edit 由 WinForms/ws 傳 DataStamp；目前檢視的舊版 `clsCustomerBasis.EditENTOSItem` 方法簽章不含 DataStamp/Reviser/ReviseDate，舊 Core SQL 也沒有相應的樂觀鎖與 audit 更新。新 API 契約需自行補齊資料版本檢查與伺服器端 audit，不能直接照搬舊 Core 的缺漏。
- Delete 的舊 Core 依 OSItemNo 實體刪除，沒有 DataStamp compare-and-swap。新 API 應加入 DataStamp 併發檢查；前端保留 WinForms 的多選逐筆、遇錯停止行為。
- 本功能沒有 IssueState 欄位、簽核按鈕或簽核流程。

## YMES API 契約（家用端）

- `GET /api/ent/os-items?osItemNo=`：取得清單；空值列出全體，有值依 OSItemNo 搜尋。
- `POST /api/ent/os-items`：新增，JSON 欄位 `osItemNo, osItemName, planDays, processNo, returnType, description`。
- `PUT /api/ent/os-items/{osItemNo}?dataStamp=`：更新允許修改的欄位並執行 DataStamp compare-and-swap。
- `DELETE /api/ent/os-items/{osItemNo}?dataStamp=`：實體刪除，DataStamp 不一致回 409。
- 欄位必填與長度依 Oracle DDL；PlanDays 為 0–999 整數，ReturnType 限 0/1。OSItemNo 寫入前大寫；ProcessNo 必須參照 IssueState=2、ProcessClass=3 的流程。所有寫入的 Creator/CreateDate/Reviser/ReviseDate 由 API 設定。API 使用 YMES PostgreSQL schema；部署前對照實際大小寫命名及 migration。

公司端 Vue DEV 頁只在 Development 使用 localStorage 假資料；正式/測試環境只呼叫 API，404 明確提示家用端 API 尚未建立，不會 fallback 假資料。本次未執行 build、測試或瀏覽器驗收。
