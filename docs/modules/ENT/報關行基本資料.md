# 報關行基本資料（ET103）

## 功能與來源

- 第一層：客戶資料（ENT）；第二層：客戶資料設定；第三層：報關行基本資料。
- FunctionNo：`BROKER BASIS`；FunctionKey：`ET103`；FunctionName：`報關行基本資料`（0012清冊）；WinForms：`frmBrokerBasis`、`frmBrokerBasisDef`；程式位於 `STD/MESWin/ENT/ET_BrokerBasis`。
- 資料服務：`wsENT.LoadBrokerBasis/AddBrokerBasis/EditBrokerBasis/DelBrokerBasis/ApproveBrokerBasisIssuestate`；資料存取位於 `kcBasis_Query`、`kcBasis_UPD`、`kcENT.clsCustomerBasis`。
- Vue 元件：`web/src/components/BrokerBasisMaster.vue`；路徑：`/YMES/Customer/Brokers`。

## WinForms 主畫面

- 視窗大小 1008×591。狀態列與搜尋欄由共用清單基底表單提供；啟動預設選「未簽核」（IssueState=0），搜尋欄位固定為 BrokerNo，查詢條件透過服務傳入。
- Grid 使用單一資料列檢視、隱藏 GroupBy 區；`IssueState` 和 `DataStamp` 欄位隱藏。可見欄依來源 SELECT * 順序為 BrokerNo、ContactorName、TelNo、FaxNo、Email、Address、BankNo、Creator、CreateDate、Reviser、ReviseDate；建立/修改日期格式 `yyyy/MM/dd HH:mm:ss`。
- 按鈕：ADD、EDIT、DEL、Approve、Close。Print 在 Designer 設為隱藏。主畫面沒有 Copy 按鈕；雖然 Def 表單仍有 DefMode=Copy 的載入分支，使用者無法從此畫面啟動複製。
- 新增完成後重載清單，若目前仍篩選未簽核，將游標選到新增 BrokerNo。修改只可從 IssueState=0 的資料啟動；其他狀態不可修改。
- 刪除與核准先把作用列納入選取，再逐筆呼叫服務；多筆執行遇到第一筆錯誤就停止，已成功資料不回復並在成功後重載。

## 新增／修改表單

- 固定視窗 503×291、置中。欄位為 Broker No、Contactor、TEL、Fax、Email、Address、Bank No，以及共用建立人/建立時間/修改人/修改時間稽核欄。
- 唯一必填欄位為 Broker No。新增與修改都允許其他欄位留白；Broker No 離開欄位時轉大寫。修改時 Broker No 唯讀。
- WinForms Designer 沒有對這些文字欄位設定 MaxLength；Oracle DDL 的實際上限由資料庫執行。新 API 應依欄位上限回傳欄位驗證錯誤，不可截斷。
- Add/Copy 表單顯示 Creator 與 CreateDate；Edit 顯示原建立資料並預填目前 Reviser/ReviseDate。Confirm 儲存後關閉，Apply 儲存後留在表單。
- 舊表單在 Add 後按 Apply 仍留在 ADD 模式，第二次按 Apply 會再次送 Add，可能遇到 BrokerNo PK 衝突。Vue 在第一次 Apply 成功後轉成 Edit，避免重複插入。

## 狀態、刪除與簽核邏輯

| IssueState | 畫面 | 編輯 | 刪除 | 核准 |
| ---: | --- | --- | --- | --- |
| 0 | 未簽核 | 可 | 實體刪除 | 可送簽核 |
| 1 | 簽核中 | 不可 | 不允許 | 不允許 |
| 2 | 已簽核 | 不可 | 改為 -1（不使用） | 不允許 |
| -1 | 不使用 | 不可 | 實體刪除 | 不允許 |

- 舊 Delete WebMethod 必須傳 IssueState。0/-1 呼叫 `DelBrokerBasis` 實體刪除；2 更新為 -1，並以 DataStamp 條件更新 Reviser/ReviseDate/DataStamp。1 回不允許刪除。
- UI 對實體刪除也傳 DataStamp，但舊 WebMethod 的 0/-1 路徑沒有把 DataStamp 傳進 Delete SQL。YMES API 應維持刪除/停用結果，同時對兩種路徑都做 server-side DataStamp 比對，以免刪除過期資料。
- 核准只接受狀態 0，IssueNo=`BROKER BASIS`。沒有 Issue Job 或 Job 沒有 Detail 時直接改為 2；設定簽核 Detail 時建立簽核單、主檔改為 1，簽核通過轉 2、退回回 0，並寄信通知第一簽核群組。Production API 必須重用 YMES 既有簽核服務；DEV 假資料將 0→2 直接核准，僅供畫面互動預覽。
- 直接核准/送簽核/軟刪除呼叫 `SetBrokerBasisIssueState` 時，來源會比對並遞增 DataStamp，同時寫 Reviser/ReviseDate。簽核引擎完成後執行的舊 ApproveSQL/RejectSQL 只更新 IssueState，沒有遞增 DataStamp 或更新稽核欄；新 API 應在既有簽核服務可擴充的位置維持一致的 server-side audit/concurrency。
- 來源欄位允許 DataStamp 為 NULL；新 API 的條件更新需同時正確比對 NULL 與數值。
