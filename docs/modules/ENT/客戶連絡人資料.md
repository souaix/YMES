# 客戶連絡人資料（ET102）

## 功能來源

- 第一層：客戶資料（ENT）。
- 第二層：客戶資料設定。
- 第三層：客戶連絡人資料。
- FunctionNo：`ET102`；FunctionName：`CUSTOMER CONTACTOR`；Form：`frmCustomerContactor`；資料編輯 Form：`frmCustomerContactorDef`；來源目錄：`STD/MESWin/ENT/ET_CustomerContactor`。
- Vue 頁：`web/src/components/CustomerContactorMaster.vue`；路徑：`/YMES/Customer/Contactors`。
- 來源行為追查：Form/Def、`wsENT.Load/Add/Edit/DelCustomerContactor`、`kcENT.clsCustomerBasis`。

## 主畫面

WinForms 主視窗最大化，左上先選客戶編號，旁邊以 `...` 開啟 `LoadCustomerBasis` 查找視窗；搜尋欄位是 CustomerNo。選定後載入該客戶連絡人，依 ContactorName 排序。未選客戶時不載入連絡人，也不能新增或刪除。

UltraGrid 隱藏分組區，顯示資料表欄位（DataStamp 隱藏）：

| Oracle 欄位 | 用途 |
| --- | --- |
| ContactorName | 連絡人姓名／複合主鍵之一 |
| CustomerNo | 客戶編號／複合主鍵之一 |
| TelNo | 電話 |
| FaxNo | 傳真 |
| EMail | Email |
| Title | 職稱 |
| DeptName | 部門 |
| Creator | 建立人 |
| CreateDate | 建立日期 |
| Description | 說明 |
| Reviser | 修改人 |
| ReviseDate | 修改日期 |

操作按鈕依來源順序為新增、修改、刪除、複製、關閉；Print 控制項在 Designer 設為隱藏，沒有可用列印流程。Grid 初始化程式把 Reviser/ReviseDate 的 Caption 設成 `Creator`/`CreateDate`，因此後兩個稽核欄位標題會重複顯示建立人/建立日期；Vue 也保留這個來源畫面行為。新增、修改、複製、刪除均在前端更新完成後重新載入目前客戶資料；Vue 版以狀態更新，不整頁重載。關閉按鈕在 Vue 清除客戶與清單，回到等待選取客戶的狀態。

## 編輯視窗與資料規則

- 固定大小視窗；欄位依序為 CustomerNo（唯讀）、ContactorName、TelNo、FaxNo、Title、DeptName、EMail、Description。CustomerNo 顯示目前所選客戶。
- ContactorName 必填，最多 50 字元；CustomerNo 必填且最多 50 字元。
- Edit 模式將 ContactorName 設為唯讀，因它是複合主鍵的一部分，來源 Edit API 不提供更換主鍵的流程。
- TelNo/FaxNo 最多 25 字元，EMail 最多 50 字元，DeptName 最多 25 字元，Description 使用多行文字；WinForms 沒有替 Description 設定 MaxLength，Oracle 欄位為 255 字元。
- Designer 將 Title 的 MaxLength 設為 50，但 Oracle 欄位為 `VARCHAR2(25)`；保留來源 UI 限制以復刻畫面，輸入超過 DB 長度的值會由資料庫拒絕。API 應回傳可讀的欄位驗證錯誤，不應默默截斷。
- Add/Copy 由目前客戶編號建立新資料；Copy 複製電話、傳真、Email、職稱、部門與說明，清空 ContactorName，並建立新的稽核欄位；不複製 DataStamp。
- Edit 帶原始 DataStamp。舊 `wsENT` 解析並傳遞 DataStamp、Reviser、ReviseDate；目前檢視的 `kcENT.clsCustomerBasis.EditCustomerContactor` 方法宣告未包含這些命名參數，來源檔與服務呼叫存在版本不一致，家用端需在 Modern API 採用明確的伺服器稽核欄位與樂觀鎖定。
- Confirm 儲存後關閉視窗；Apply 儲存後保留視窗開啟。刪除支援多選，WinForms 逐筆刪除並在第一筆錯誤時停止；Vue Production 依此順序逐筆呼叫 API，若中途錯誤重新載入目前清單。
- Vue Development 以具名 DEV 假資料與 `localStorage` 操作；Production 僅呼叫 API，API 未建時顯示待建訊息，不將假資料送入 Production。

## Oracle 結構

本功能使用 `MESTEST.TBLENTCUSTOMERCONTACTOR`。此表已由 ET101 客戶基本資料工作用 PowerShell 5.1 + ODP.NET 直接查過，原始 DDL 與 PostgreSQL 空表 CREATE SQL 位於：

- Oracle logical DDL：`database/reference/mestest_customer_basis_source_ddl.sql`
- PostgreSQL CREATE SQL：`database/reference/mestest_customer_basis_create.sql`

欄位：

| 欄位 | Oracle 型別 | NULL / DEFAULT | 備註 |
| --- | --- | --- | --- |
| CUSTOMERNO | VARCHAR2(50) | NOT NULL | PK 第一欄；無 Oracle FK |
| CONTACTORNAME | VARCHAR2(50) | NOT NULL | PK 第二欄 |
| TELNO | VARCHAR2(25) | NULL | |
| FAXNO | VARCHAR2(25) | NULL | |
| EMAIL | VARCHAR2(50) | NULL | |
| TITLE | VARCHAR2(25) | NULL | UI MaxLength 為 50，與資料庫不同 |
| DEPTNAME | VARCHAR2(25) | NULL | |
| CREATOR | VARCHAR2(10) | NULL | |
| CREATEDATE | DATE | NULL | |
| DESCRIPTION | VARCHAR2(255) | NULL | |
| DATASTAMP | NUMBER(11,0) | NULL，DEFAULT 0 | Grid 隱藏 |
| REVISER | VARCHAR2(10) | NULL | |
| REVISEDATE | DATE | NULL | |

唯一索引為 PK `(CUSTOMERNO, CONTACTORNAME)`；沒有其他索引或 Oracle 外鍵。`database/reference/mestest_customer_basis_create.sql` 已包含這張表，本功能不新增重複 Create SQL。雖來源無 FK，YMES API 寫入時應確認 CustomerNo 存在，避免建立孤兒連絡人。

## YMES API 契約（交家用電腦）

沿用設備供應商聯絡人的巢狀資源模式：

| Method | Endpoint | 用途 |
| --- | --- | --- |
| GET | `/api/ent/customer-basis` | 客戶查找視窗；保留所有 IssueState，支援 CustomerNo/名稱搜尋 |
| GET | `/api/ent/customer-basis/{customerNo}/contactors` | 依客戶載入連絡人，按 ContactorName 排序 |
| POST | `/api/ent/customer-basis/{customerNo}/contactors` | 新增；伺服器設定 Creator/CreateDate/DataStamp |
| PUT | `/api/ent/customer-basis/{customerNo}/contactors/{contactorName}` | 修改；複合鍵定位，帶 DataStamp，更新 Reviser/ReviseDate |
| DELETE | `/api/ent/customer-basis/{customerNo}/contactors/{contactorName}?dataStamp=` | 刪除單筆；DataStamp 作為 YMES 併發保護 |

API 驗證字數須服從 Oracle DDL（尤其 Title 25）；DataStamp 為 nullable source 欄位，YMES 寫入建議正規化新資料為 0 並在每次修改遞增。來源沒有 FK，刪除客戶主檔的 API/交易需先刪除出貨地址與客戶連絡人，再刪客戶主檔；連絡人 API 只刪指定連絡人。
