## WinForms 清單畫面

- 預設 IssueState=0；四個狀態篩選：未簽核 `0`、簽核中 `1`、已簽核 `2`、不使用 `-1`。狀態切換在已載入的資料集上篩選。
- 搜尋欄位只有 CustomerNo，使用共用 BasisTemplate 查詢列及百分比提示。
- Grid 隱藏分組框、固定首欄 CustomerNo，允許多列選取；畫面欄位順序：CustomerNo、CustomerName、CustomerSName、CustomerEName、Director、TelNo、Country、FaxNo、WWW、TaxCode、Address、Address2、Description、Creator、CreateDate、Status、Currency、InvTypeNo、InvAddr、InvAddr2、InvCustNo、InvRemark、CustType、ARType、FreightTerms、PaymentTerms、ACCTNo、DeliveryTerm、BrokerAssigned、InsuranceCoverage、ForwarderAssigned、Reviser、ReviseDate。CreateDate/ReviseDate 顯示年月日時分秒；Status、InvTypeNo、CustType、ARType 顯示 ValueList 中文標籤。
- 按鈕：新增、修改、刪除、複製、核准、匯入、關閉。Print 在 Designer 內設為隱藏。
- 修改可用於各 IssueState。若狀態不是 0，CustomerNo、CustomerName、CustomerSName、TelNo、FaxNo、WWW、Director、Description、Country、TaxCode、Address、Address2 設為唯讀；其他交易/發票欄位仍可修改。原始程式沒有鎖 CustomerEName。
- 刪除及核准可批次逐筆執行；遇第一筆錯誤即停止，已成功的前筆不回復。刪除只接受 0、-1、2；核准只接受 0。

## 新增/修改/複製表單

- 基本欄位：CustomerNo、CustomerName、CustomerSName、CustomerEName、TelNo、FaxNo、WWW、TaxCode、Address、Address2、Director、Country、Description。
- 交易欄位：Status、Currency、InvTypeNo、InvAddr、InvAddr2、InvCustNo、InvRemark、CustType、ARType、FreightTerms、PaymentTerms、ACCTNo、DeliveryTerm、ForwarderAssigned、BrokerAssigned、InsuranceCoverage。
- Status 選項：O 有效、C 失效、B 呆帳、P 暫停；InvTypeNo：0 內銷、1 外銷；CustType：0 國內、1 國外；ARType：0 入庫計價、1 出貨計價。空白允許。
- CustomerNo 離開欄位時轉大寫；新增/複製狀態初始為 0。CustomerNo、CustomerName 為必填；確定按鈕另要求 CustomerSName 必填。Apply 的舊程式只檢查前兩欄，但 Oracle CustomerSName 為 NOT NULL，API 仍應拒絕空值並回傳欄位錯誤。
- 複製視窗填入來源主檔欄位，但 CustomerNo 清空；其他關聯資料不複製。新增及複製提交後狀態為 0。
- 修改時 CustomerNo 唯讀；稽核欄位顯示建立/修改人與日期。新 API 應從登入上下文取得操作者，以伺服器時間建立稽核日期，不採信瀏覽器提供的 Creator/Reviser。
- UI 輸入長度主要依 `frmCustomerBasisDef` Designer；Oracle 欄位長度及 NOT NULL 以 CREATE SQL 為後端驗證準據。兩者不一致處包括 CustomerName/CustomerSName、InvCustNo、InvRemark、Currency。

## 狀態與 Service 規則

- 新增：`wsENT.AddCustomerBasis` 呼叫 `clsCustomerBasis.AddCustomerBasis`，主檔 IssueState=0，並寫入 Revision/Audit 欄位。CustomerNo 唯一。
- 修改：`wsENT.EditCustomerBasis` 更新主檔欄位及 Reviser/ReviseDate，傳入 DataStamp；API 需以 DataStamp compare-and-swap 防止覆寫並行修改。舊 `clsCustomerBasis.EditCustomerBasis` 以非空參數組合更新欄位；新 API 應支援明確的 null/空字串更新，避免舊 sentinel 契約造成欄位無法清空。
- 核准：IssueNo=`CUSTOMER BASIS`。狀態為 0 才執行。找不到簽核 Job，或 Job 沒有 Detail，直接設 2；有簽核 Detail 時建立簽核主檔並設 1，核准後設 2，退回設 0，並通知第一簽核群組。正式 API 應沿用 YMES 共用簽核服務。
- 刪除狀態 0/-1：舊 Service 以同一批次 SQL 先刪 `TBLENTCUSTOMERSHIPADDR`、`TBLENTCUSTOMERCONTACTOR`，再刪 `TBLENTCUSTOMERBASIS`；三步需在一個交易中完成。狀態 2：改為 -1 並更新 Reviser/ReviseDate/DataStamp。狀態 1 拒絕。來源 Oracle 沒有外鍵，因此新 API 必須明確維護這個依賴順序。
- 舊 Service 的實體刪除路徑沒有把 DataStamp 條件傳入 Core；新 API 即使保留相同刪除結果，也應先驗證 DataStamp，避免誤刪同時更新的紀錄。

## 匯入視窗

- 主表按鈕呼叫共用 `ET_ETDataImport`，標題 ENT Data Import。檔案選擇支援 `.xlsx`/`.xls`，只讀第一個工作表；欄位位置固定為 CustomerNo、CustomerName、CustomerSName，資料從第二列開始，三欄都必須有值。
- 結果欄：CustomerNo、CustomerName、Message。匯入依 CustomerNo 組批，呼叫 `DataImporter.CustomerDataImport.CustomerDataChecker`；錯誤逐組顯示。可取消背景處理。範本呼叫 `wsSYS.GetTemplateFile`，FunctionNo=`ENT BASIS`；副檔名由 `wsSYS.funLoadFileExtension` 決定。
- 舊父表在匯入視窗關閉時只回傳 `success` 字串，而主畫面嘗試以該字串作為 CustomerNo 尋找列；因此匯入後重載成功，但選取列定位邏輯不可靠。
- Vue Development 目前只解析 CSV 並用瀏覽器假資料模擬必要欄位/重複編號檢查；沒有模擬正式 DataChecker。Production 需由 API 解析 Excel 並逐組執行等價檢查，不可用此簡化假裝正式匯入完成。

## Vue/API 遷移狀態

- Vue 元件：`web/src/components/CustomerBasisMaster.vue`；路徑：`/YMES/Customer/Basis`。
- Development 只使用 `localStorage` 的 `DEV-*` 假資料；Production 只呼叫 API，沒有 API 時顯示明確錯誤。
- 建議 API 契約：GET `/api/ent/customer-basis`；POST 同路徑新增；PUT `/{customerNo}` 修改；DELETE `/{customerNo}?issueState=&dataStamp=`；POST `/{customerNo}/approve?dataStamp=`；POST `/import/preview` multipart 並回傳 token/分組預覽；POST `/import/commit` 依 token 執行舊 DataChecker 等價邏輯；GET `/import/template` 範本。預覽 token 需綁定登入者且短期有效，提交時重新驗證資料。
- Development 核准僅假造狀態 0→2；不模擬已設定簽核 Job 時的 Pending/核准/退回程序。
- 公司端尚未做瀏覽器人工驗收，未執行 build/test；Production API/migration 未完成。資料庫實際 YMES schema 由家用端核對，不可把 CREATE SQL 直接執行在來源 Oracle，也不可刪 YMES 已有額外欄位。
