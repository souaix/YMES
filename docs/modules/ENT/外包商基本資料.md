## WinForms 主畫面

- `frmSubcontractor` 最大化，設計尺寸 1008×591；上下兩個資料 Grid：上方外包商主檔，下方目前選取外包商的連絡人明細。選主檔列時透過 `AfterRowActivate` 載入該外包商連絡人。
- 初始狀態為未簽核 0；狀態篩選為未簽核 0、簽核中 1、已簽核 2、不使用 -1。舊版先載入主檔，再在前端 DataView 篩選；排序依 SubcontractorNo。
- 查詢條件只有 SubcontractorNo，查詢工具列帶 `%` 提示；查詢後依目前狀態重新套用資料。選列及狀態變更在 Vue 以響應式狀態處理，不用 query string 或整頁重載。
- 主 Grid 欄位：SubcontractorNo、SubcontractorName、Description、Creator、CreateDate、Reviser、ReviseDate；IssueState、DataStamp 隱藏供按鈕/併發判斷。ERPNo 由 `SELECT *` 取得，但舊 Grid 沒有明確設定欄位格式；Vue 顯示 ERPNo 供檢視。日期格式為 `yyyy/MM/dd HH:mm:ss`。
- 主檔按鈕：新增(A)、修改(E)、刪除(D)、複製(C)、核准、關閉。
- 明細 Grid 欄位：SubcontractorNo、ContactorName、TelNo、FaxNo、Title、Address、EMail、Description、Creator、CreateDate、Reviser、ReviseDate；DataStamp 隱藏。Email 顯示為可點選樣式。
- 明細按鈕：新增、修改、刪除、複製、Mail。Mail 使用目前連絡人 EMail 開啟 `mailto:`。
- 主檔與明細 Grid 都支援多列選取。批次刪除/核准逐筆呼叫舊 WebService；遇第一筆錯誤即停止，已成功的前面資料不回滾。

## 主檔表單 `frmSubcontractorDef`

- 固定置中，ClientSize 503×309；外包商資料 GroupBox 含外包商編號、外包商名稱、說明，底部顯示建立/修改稽核欄並有確定、關閉、套用。
- 新增、複製可輸入 SubcontractorNo、SubcontractorName、Description；編輯時 SubcontractorNo 唯讀。必填欄位只有編號與名稱。編號離開欄位時轉大寫。
- 新增/複製初始 IssueState=0，建立人/日期由登入者與伺服器時間寫入；編輯只允許 IssueState=0，帶入 DataStamp，修改人/日期為登入者/目前時間。
- 確定儲存後關閉；套用儲存並留在表單。Web 版新增第一次套用後轉為編輯模式，避免連續新增造成相同主鍵衝突。
- Copy 從所選主檔帶入名稱與說明，編號也帶入原值，使用者須改成新編號；Copy 不複製連絡人明細。

## 連絡人表單 `frmSubcontractorContDef`

- 固定置中，ClientSize 496×446；欄位依序為 SubcontractorNo（唯讀）、ContactorName、TelNo、FaxNo、Title、Address、EMail、Description；建立/修改稽核欄唯讀，底部有確定、關閉、套用。
- 必填只有 ContactorName；SubcontractorNo 固定為目前主檔。編輯時 ContactorName 唯讀，新增/複製可輸入。姓名離開欄位時轉大寫；若姓名非空且 Email 空白，舊程式先帶入「姓名@」作為提示值。
- Copy 沿用目前主檔，複製選取連絡人欄位，使用者需更換姓名以避開複合主鍵衝突。明細操作在舊 Form 沒有檢查主檔 IssueState；API 權限仍需檢查登入者及資料一致性。
- 確定/套用及稽核欄行為與主檔相同。舊程式套用新增後會清空 Email 並仍停留新增模式；Vue 改成同筆資料持續編輯並保留 Email，避免重複新增與輸入遺失。

## 按鈕及狀態規則

| 操作 | WinForms 規則 | Web DEV 行為 |
| --- | --- | --- |
| 新增主檔 | 必填編號/名稱；IssueState=0 | localStorage 假資料；重複編號拒絕 |
| 修改主檔 | 僅 IssueState=0；編號唯讀 | 僅未簽核列可開啟表單 |
| 複製主檔 | 任意狀態列可開啟 Copy 表單；明細不隨主檔複製 | 帶入名稱/說明，編號帶原值待修改 |
| 刪除主檔 | 0/-1 實體刪除主檔及其連絡人；2 改為 -1；1 拒絕 | 批次逐筆處理，0/-1 刪兩表，2 只改狀態及稽核/DataStamp |
| 核准 | 僅 IssueState=0；IssueNo=`SUBCONTRACTOR BASIS` | DEV 直接模擬 0→2，不建立簽核單 |
| 明細新增/修改/複製/刪除 | 綁定目前 SubcontractorNo；主鍵 `(SubcontractorNo, ContactorName)` | 對目前主檔操作；姓名大寫；以複合鍵定位 |
| 明細 Mail | 以選取列 EMail 開啟 mailto | Email 缺值時提示 |

### 舊簽核細節

- `ApproveSubcontractor` 只接受狀態 0。若 `IssueNo=SUBCONTRACTOR BASIS` 沒有 Job，直接改為 2；Job 沒有 Detail 也直接改為 2。
- 有簽核 Detail 時建立 Issue Master，核准 SQL 把 IssueState 設成 2、退回 SQL 設回 0，送出後狀態成 1，並通知第一簽核群組。
- 舊 Raw ApproveSQL/RejectSQL 只更新 IssueState；本代碼庫的 wsENT 呼叫 Core 時帶入 `DataStamp/Reviser/ReviseDate` named arguments，但當前 `clsCustomerBasis` 對應方法宣告未包含這些參數，反映來源版本不一致。YMES API 需使用現有簽核服務，並在交易內補齊稽核及 DataStamp compare-and-swap。
- 舊 WebService 刪除 0/-1 分支沒有把 DataStamp 傳給實體刪除 SQL。Production API 需在刪除/停用時比對資料庫實際狀態與 DataStamp，避免覆蓋並行修改。

## YMES API 契約（家用端待完成）

| Method | Endpoint | 規則 |
| --- | --- | --- |
| GET | `/api/ent/subcontractor-basis?subcontractorNo=` | 回傳主檔欄位、IssueState、DataStamp；SubcontractorNo 可選，給清單查詢使用 |
| POST | `/api/ent/subcontractor-basis` | 新增主檔；編號大寫、必填名稱；由登入上下文/伺服器寫 Creator/CreateDate，IssueState=0、DataStamp=0 |
| PUT | `/api/ent/subcontractor-basis/{subcontractorNo}?dataStamp=` | 僅修改 IssueState=0 的名稱/說明；編號唯讀；server 寫 Reviser/ReviseDate 並比較遞增 DataStamp |
| DELETE | `/api/ent/subcontractor-basis/{subcontractorNo}?issueState=&dataStamp=` | 0/-1 在單一交易中實體刪連絡人再刪主檔；2 改 -1 並更新稽核/DataStamp；1 回 409 |
| POST | `/api/ent/subcontractor-basis/{subcontractorNo}/approve?dataStamp=` | 僅接受 0；使用 YMES 共用 Issue/Job 流程、IssueNo=`SUBCONTRACTOR BASIS` |
| GET | `/api/ent/subcontractor-basis/{subcontractorNo}/contacts` | 載入單一主檔的連絡人，依姓名排序 |
| POST | `/api/ent/subcontractor-basis/{subcontractorNo}/contacts` | 新增連絡人；姓名大寫，必填，欄位長度依 Oracle DDL |
| PUT | `/api/ent/subcontractor-basis/{subcontractorNo}/contacts/{contactorName}?dataStamp=` | 修改電話/傳真/職稱/地址/Email/說明；複合鍵不可改，server audit/CAS |
| DELETE | `/api/ent/subcontractor-basis/{subcontractorNo}/contacts/{contactorName}?dataStamp=` | 以複合鍵刪除並比較 DataStamp；回傳明確 404/409 |

所有端點需檢查登入者 ENT 功能權限、欄位長度、主檔存在、資料庫唯一鍵及並行更新。DataStamp 在 Oracle 可 NULL 且 DEFAULT 0；若 YMES 保持 nullable，NULL 必須以 `IS NULL` CAS，遞增使用 `COALESCE(DataStamp,0)+1`。Oracle 無 FK，API 需明確實作父子刪除交易。批次操作由前端逐筆送出，首錯停止並提示先前已完成筆數。
