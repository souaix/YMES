# ENT ET104 貨運行基本資料

## 來源與功能位置

- 第一層：客戶資料；第二層：客戶資料設定；第三層：貨運行基本資料。
- FunctionNo：`FORWARDER BASIS`；WinForms Forms：`frmForwarderBasis`、`frmForwarderBasisDef`；原始程式：`STD/MESWin/ENT/ET_ForwarderBasis`。
- 主表：Oracle `MESTEST.TBLENTFORWARDERBASIS`；YMES PostgreSQL 正式對應表：`"YMES".tblentforwarderbasis`；reference 的小寫 schema 是轉譯來源，不能直接對正式庫重跑。
- Vue 元件（DEV 預覽與正式 API 分流）：`web/src/components/ForwarderBasisMaster.vue`；路徑：`/YMES/Customer/Forwarders`。
- 本規格根據 WinForms Form/inline Designer/WebService/Core 與 Oracle 資料字典。未查詢 Oracle 業務資料。

## WinForms 主清單

- 主視窗最大化；上方簽核狀態單選：未簽核 `0`、簽核中 `1`、已簽核 `2`、不使用 `-1`；預設 `0`。
- 搜尋欄位只有 ForwarderNo。舊程式先載入清單，再以目前狀態在本機 DataView 篩選；新 UI 以動態狀態篩選，不因選列而改 URL 或重新載入。
- Grid 顯示：ForwarderNo、ContactorName、TelNo、FaxNo、Email、Address、BrokerNo、BankNo、Creator、CreateDate、ACNo、Reviser、ReviseDate。IssueState、DataStamp 供操作使用、不顯示；稽核日期顯示日期與時間。
- 右側按鈕：新增、修改、刪除、核准、關閉；Print 在 WinForms 設為隱藏。沒有 Copy 按鈕；Def Form 雖留有 Copy 分支，但主清單沒有入口。
- 可多選刪除與核准。逐筆呼叫服務，遇到第一筆錯誤即停止；之前成功的操作不回滾，清單重載。
- Add 完成後重載並在未簽核篩選下選取新增的 ForwarderNo。Edit 入口只接受 IssueState `0` 或 `2`。

## WinForms 編輯表單

- 欄位：ForwarderNo（必填）、BrokerNo（必填，唯讀文字框加 `...` 選擇器）、ContactorName、TelNo、FaxNo、Email、Address、BankNo、ACNo，以及唯讀建立/修改人與時間。
- Add 時 ForwarderNo 離開欄位會轉大寫。Edit 時 ForwarderNo 與 BrokerNo 唯讀，其餘欄位可編輯。來源未設定欄位 MaxLength；Web 依 Oracle 長度驗證，超長回傳錯誤、不截斷。
- Broker 選擇器呼叫 `wsENT.LoadBrokerBasis`，只列出 IssueState=2 的報關行，使用 BrokerNo 作為搜尋欄。
- 必填檢查只要求 ForwarderNo、BrokerNo。Confirm 儲存成功後關閉表單；Apply 儲存後留在表單並停用 Apply，若再次修改才重新啟用。Add 後連續 Apply 會沿用新增模式而可能撞 PK；Vue 在第一次新增成功後轉成 Edit，避免重複新增。
- 修改 IssueState=2 的 UI 路徑存在服務端缺陷：`wsENT.EditForwarderBasis` 只有 IssueState=0 才呼叫 Core 更新，狀態 2 可能回傳成功但資料未更新。YMES API 契約保留 UI 明確允許的編輯意圖：狀態 0、2 可更新聯絡明細，主鍵與 BrokerNo 不可改；狀態 1、-1 拒絕。這是已標記的舊程式不一致處，不是 Oracle 約束。

## 狀態、刪除與簽核

- 刪除接受狀態 0、-1、2；0/-1 實體刪除，2 轉為 -1；狀態 1 不允許。來源會多筆逐筆呼叫，遇首錯即停。
- 核准只接受 IssueState=0，呼叫 `wsENT.ApproveForwarderBasisIssuestate`，IssueNo 為 `FORWARDER BASIS`。未設定 Issue Job 或 Job 無 Detail 時依舊流程直接轉 2；有簽核 Detail 時建立簽核單、轉 1，通過轉 2、退回回 0，並通知第一簽核群組。Production 必須使用 YMES 共用簽核服務；DEV 的 0→2 只用於 UI 預覽。
- 舊簽核設定的 Raw ApproveSQL/RejectSQL 只更新 IssueState，可能不更新 DataStamp/稽核欄位；直接狀態操作則由 Core 更新這些欄位。新 API 統一使用交易、伺服器時間、登入身分及併發檢查。
- Oracle `BROKERNO` 為 NOT NULL，但沒有 FK。新增時必須驗證所選報關行存在且 IssueState=2；資料庫本身不會防止報關行之後被停用。

## YMES API 契約（待家用端實作）

| 方法 | 路徑 | 行為 |
| --- | --- | --- |
| GET | `/api/ent/forwarder-basis?forwarderNo=&issueState=` | 清單；兩個查詢參數皆選填，回傳 IssueState/DataStamp 與完整 DTO；ET106 的 lookup 傳 IssueState=2 |
| GET | `/api/ent/broker-basis?issueState=2` | Broker 選擇器只取已簽核報關行；ET103 GET 必須支援 IssueState filter |
| POST | `/api/ent/forwarder-basis` | 新增；ForwarderNo/BrokerNo 必填，大寫代碼，IssueState=0；伺服器驗證 BrokerNo 為已簽核報關行 |
| PUT | `/api/ent/forwarder-basis/{forwarderNo}?dataStamp=` | 更新連絡人、電話、傳真、Email、地址、銀行編號、AC No；主鍵、BrokerNo 不可改；目前 IssueState 必須為 0 或 2 |
| DELETE | `/api/ent/forwarder-basis/{forwarderNo}?issueState=&dataStamp=` | 狀態 0/-1 實體刪除；2 停用成 -1；1 拒絕；以資料庫狀態與 DataStamp compare-and-swap |
| POST | `/api/ent/forwarder-basis/{forwarderNo}/approve?dataStamp=` | 只接受狀態 0，使用既有 `FORWARDER BASIS` 簽核服務 |

所有端點需驗證登入者 ENT 權限；Creator/CreateDate、Reviser/ReviseDate 以登入上下文與伺服器時間產生。Oracle DataStamp/IssueState 可為 NULL，更新比較與遞增須明確支援 NULL（例如 `IS NULL` 與 `COALESCE(DataStamp,0)+1`）。批次 UI 逐筆執行且遇第一錯停止；API 單筆失敗回 404/409，前端重載以呈現部分成功。

### 併發、引用與簽核界線

新建固定同交易鎖序：Broker PG lower(btrim) advisory namespace → 唯一真 parent FOR SHARE／state2 → Forwarder namespace → duplicate／INSERT，持有到 commit；與已交付 ET103 Broker writer 的同 namespace 協作。既有 Update／Delete／Approve 只取 Forwarder namespace → 真 own row FOR UPDATE，避免反向取得 parent 鎖。查詢／引用 metadata 只把 r/p/v/m/f 當資料關聯，索引欄不是引用。

CAS 保留 nullable signed numeric11，合法範圍 ±99999999999。明確 JSON null 與省略不同；NULL 不等0；`IS NOT DISTINCT FROM` 真比較。成功遞增 NULL→1、-1→0；需遞增且正上限時409，匹配上限的硬刪仍可。DELETE／Approve 同時比較 state，PUT 只接受實際0／2並比較 token。新增／變更聯絡欄驗原生長度，Address 允許 CR/LF/TAB，不增加未證實的 email／銀行演算法。

硬刪檢查真 Customer.forwarderassigned logical 引用，命中409；retirement 允許保留引用。這是明載 **YMES 防孤兒延伸**，不冒稱原 Core 已有此 guard 或 DB FK。未知／不可讀的真引用依賴503，不當成沒有引用；未來 ET101 Customer writer 要使用同 Forwarder namespace＋唯一 parent FOR SHARE 到 commit，不能宣稱它已交付。

本地 relevant metadata 完全沒有 known／pattern IssueJob 候選才直接0→2；若存在候選而沒有真 provider，503且不寫入。不以空表、猜測設定或其他 schema 的單一 absence 冒充完整無 Job。完整簽核單／通知／群組 provider 未交付。錯誤400／404／409／422／503回清楚 ProblemDetails，不帶 catalog／連線內容。
