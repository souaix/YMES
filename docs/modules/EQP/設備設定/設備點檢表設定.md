## 功能範圍

此功能維護設備點檢表的主資料與檢查項目，供設備點檢及設備狀態處置引用。主檔畫面不顯示 IssueState、不提供核准按鈕。點檢表類型及設備狀態選項由 MES ValueList/設備狀態主檔提供。

公司電腦 Development 使用 DEV 假資料與 localStorage；Production 只呼叫 YMES API，不使用假資料。

### 正式 ValueList

公司端以 PowerShell 5.1 + ODP.NET 唯讀查詢 MESTEST `TBLSYSVALUELIST`，並以繁中資源檔確認翻譯。主檔 QCType 只有兩個合法值；`SelectedIndex=1` 是排序後第二筆，儲存值為 2：

| 欄位 | 值 | 原始顯示文字 | 繁中顯示 |
| --- | ---: | --- | --- |
| QCType | 0 | CHECK IN FOR EQPQC | 開始生產時點檢 |
| QCType | 2 | QC MANUAL | 手動點檢 |
| AfterEventQC | 0 | No | 否 |
| AfterEventQC | 1 | Yes | 是 |

明細 Type 為 WinForms Form 內定義值：0=標準值、1=範圍、2=顯示訊息、3=輸入資料。`UnValidAction` 選項為 -1「不動作」加上設備狀態主檔的實際狀態；公司端未讀取 MES 業務狀態資料，正式 API 應由 YMES 設備狀態 API 提供。

### 主檔 Grid 欄位順序

QCListNo、QCListName、QCType、UnValidAction、AfterEventQC、Description、Creator、CreateDate、Reviser、ReviseDate。

QCType、UnValidAction、AfterEventQC 顯示 ValueList 對應文字；其餘欄位直接顯示。查詢結果排序 QCListNo。

### 明細 Grid 欄位順序

QCOrder、CheckItem、InspectionMethod、InspectionStandards、Type、InputDataCount、StdValue、MiniValue、MaxiValue。清單把資料庫欄位 QCItem 顯示為 CheckItem。

## 主檔新增 / 修改 / 複製表單

來源 Form：frmEQPQCListBasisDef。

| 欄位 | 行為 / 驗證 |
| --- | --- |
| QCListNo | 必填，最長 100；Edit 唯讀；Add/Copy 可輸入 |
| QCListName | 必填，最長 100 |
| QCType | ValueListProvider 讀 TBLEQPQCLISTBASIS.QCTYPE；合法值只有 0「開始生產時點檢」與 2「手動點檢」；新增初始 SelectedIndex=1，即值 2 |
| UnValidAction | 必填；預設 -1「不動作」，其他選項來自設備狀態 |
| AfterEventQC | 僅 QCType=0 時啟用；其他類型清除且停用 |
| Description | 最長 255，nullable |

Creator/CreateDate 由使用者與當下時間帶入；Edit 保留原建立者/時間，更新 Reviser/ReviseDate。Edit 帶 DataStamp，新增與複製走新增服務。Copy 複製主資料和完整點檢明細，但 QCListNo 必須重新輸入。

主檔 Confirm / Apply 必填檢查：QCListNo、QCListName、QCType、UnValidAction，且至少有一筆點檢項目。儲存前將每一筆明細的 QCListNo 更新為目前主檔編號。

## 點檢項目編輯

一張點檢表最多 99 項（QCOrder 為 NUMBER(2,0)）。CheckItem 不可空白、長度最多 1000，同一張清單中不可重複。InspectionMethod、InspectionStandards nullable，各最多 100。InputDataCount NumericUpDown 範圍為 1–10，預設 1。

| QCType | 顯示名稱 | 驗證與儲存 |
| --- | --- | --- |
| 0 | StdValue / 標準值 | StdValue 必填且須為數字；其他範圍值清空 |
| 1 | Range / 範圍 | Maximum、Minimum 至少填一個；有填者須為數字；兩者都有值時 Maximum 必須大於 Minimum；未填的邊界儲存為星號 * |
| 2 | Message / 顯示訊息 | 不需要 StdValue/範圍值 |
| 3 | InputData / 輸入資料 | 不需要 StdValue/範圍值；InputDataCount 可設定 1–10 |

WinForms value 欄位 MaxLength 設為 13，但 Oracle 資料欄位只有 VARCHAR2(12)。Vue 依資料庫長度限制 12，API 也需按 Oracle 欄位 12 長度驗證。

明細操作在編輯 Form 的記憶體 DataTable 完成，存主檔時整組送出。新增時 QCOrder 依序增加；刪除後重新編號；上移/下移交換相鄰 QCOrder；Edit 更新目前列。刪除可多選並先確認。

## 按鈕與資料流程

| 操作 | WinForms 行為 |
| --- | --- |
| 新增 | 開啟空白主檔/明細編輯窗；Confirm 呼叫 AddEQPQCListBasisAndDetail；完成後重載主檔並定位 |
| 修改 | 載入選取主檔及明細；QCListNo 唯讀；Edit 帶 DataStamp；呼叫 EditEQPQCListBasisAndDetail |
| 複製 | 載入來源主檔與完整明細，清除/改輸入新 QCListNo，使用新增服務 |
| 刪除 | 多選主檔，確認後逐筆呼叫 DelEQPQCListBasis；Service 先刪明細再刪主檔；逐筆失敗時已完成的前筆不會由畫面自動回復 |
| Apply | 驗證後保存但留在編輯窗；Edit 成功會遞增本地 DataStamp |
| Confirm | 驗證、保存並關閉編輯窗 |
| 關閉 | 關閉主畫面 |

Service 將主檔和明細 SQL 收集後送入 ExecuteSQLNoneQuery_UPD。新 API 應以一個資料庫交易保存主檔、取代所有明細；刪除亦應在同一交易刪除明細和主檔，避免部分資料。

## API 契約（家用電腦待建）

Vue 頁面目前採用：

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | /api/equipment/qc-lists?qcListNo= | 查詢主檔，依 QCListNo 排序 |
| GET | /api/equipment/qc-lists/options | 回傳 qcTypes 與 equipmentStates 選項 |
| GET | /api/equipment/qc-lists/{qcListNo}/items | 讀取明細，依 QCOrder 排序 |
| POST | /api/equipment/qc-lists | 新增主檔與完整 items 集合 |
| PUT | /api/equipment/qc-lists/{qcListNo} | DataStamp 並行檢查後更新主檔並完整取代 items |
| DELETE | /api/equipment/qc-lists/{qcListNo} | 交易刪除明細及主檔 |

POST / PUT DTO 包含 qcListNo、qcListName、qcType、unValidAction、afterEventQc、description 及 items。明細項目 DTO 使用 qcOrder、qcItem、qcType、inputDataCount、stdValue、miniValue、maxiValue、inspectionMethod、inspectionStandards。錯誤請用 409 回報 DataStamp 衝突；欄位驗證用 400；未找到用 404。`options.qcTypes` 必須只回傳 0「開始生產時點檢」及 2「手動點檢」；`equipmentStates` 由 YMES 設備狀態主檔提供，並包含 -1「不動作」呈現規則。
