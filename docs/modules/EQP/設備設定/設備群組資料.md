## WinForms 畫面與互動

來源：frmEquipmentGroup.vb。

- WinForms 表單標題為 Equipment Group，工作區上下排列：上方設備群組主檔清單，下方目前群組的 EquipmentNo 明細清單；兩個 UltraGrid 均隱藏 GroupByBox。
- 上方狀態篩選預設未審核 0，支援審核中 1、已審核 2、不使用 -1；搜尋欄位為 EquipmentGroup。
- 上方清單顯示 EquipmentGroup、Description、Creator、CreateDate、Reviser、ReviseDate；IssueState、DataStamp 為隱藏欄位。
- 上方操作：ADD、EDIT、DEL、Approve、Close。Copy 按鈕在 Designer 明確設為 Visible=False；雖然定義 Form 有 Copy mode，使用者目前無法從此清單觸發，Web 不顯示 Copy。
- 選取上方群組列後，下方自動載入該群組的設備明細；沒有有效作用列時清空明細。
- 下方清單只顯示 EquipmentNo；Add 開啟共用多選設備查詢，Del 支援多選；兩者都要求目前群組為 IssueState=0。
- 刪除群組或明細前顯示確認；成功後重新載入群組/明細及可加入設備清單。

## 設備群組明細規則

來源：frmEquipmentGroup.vb、clsEQPBasis.cs 的 LoadEquipmentBasis_NotInGroup/AddEQPGroupDetail/DelEQPGroupDetail。

- 可加入清單先查設備主檔 IssueState=2，且 EquipmentNo 尚未存在任何 TBLEQPGROUPDETAIL；WinForms 再以 ChamberFlag=0 排除 Chamber。
- 因可加入查詢以所有群組明細作排除，正常流程下一台設備最多隸屬一個設備群組。原表 PK 只限制同一群組內重複；API 必須在交易/適當鎖定下再次檢查跨群組唯一性，避免並行加入造成重複。
- 只有目前設備群組 IssueState=0 可以新增/移除明細。新加入多選項目由前端逐筆呼叫舊 Service；Web API 可提供批次端點，但應以單一交易完整處理。
- 明細表 TBLEQPGROUPDETAIL 只有 EquipmentGroup、EquipmentNo，PK 為兩欄組合；沒有 IssueState 或 DataStamp。
- 舊 AddEQPGroupDetail 查 TBLSMDAREARELATION 中 ObjectType=4、ObjectNo=EquipmentGroup，讀取 BaseAreaNo 與 ContainAreaNo。找到兩個非空值時，若 TBLSMDSMTAREAEQPMAP 尚無相同 EquipmentGroup/EquipmentNo，便在同一批 SQL 新增映射列；EQPSequence 留空。
- 舊 DelEQPGroupDetail 會刪明細並刪除相同 EquipmentGroup/EquipmentNo 的 SMD 映射列。
- 舊 DelEQPGroupBasis 只在同一批 SQL 刪除群組所有明細及主檔，不刪 TBLSMDSMTAREAEQPMAP。Production API 為相容舊行為，群組刪除不得額外清除該表映射。
- 兩張 SMD 表的 Oracle DDL 與 PostgreSQL 空表 CREATE SQL 已於 2026-11-16 查得並交付；目標 YMES schema 仍待家用端比對。

## 核准、刪除及狀態

- 核准只接受 IssueState=0，傳 EquipmentGroup、IssueState、DataStamp。
- wsEQP.ApproveEQPGroupBasis 使用 IssueNo EQP GROUP BASIS：
  - 沒有核准 Job，或 Job 沒有 Detail 時直接改成已核准 2。
  - 有簽核明細時建立 Issue 流程並改為審核中 1；流程核准後改成 2，退回改回 0，並通知第一關簽核群組。
- 刪除主檔支援多選，只有狀態 0、-1、2 可以刪除，傳 DataStamp；狀態 1 不接受直接刪除。
- 群組刪除連同其所有群組明細，但不清除 TBLSMDSMTAREAEQPMAP；這是舊 Service 已確認的相容行為。

## Oracle DDL 與 SQL

Oracle 原始 DDL/資料字典及 PostgreSQL 空表 CREATE SQL 均不含 MES 業務資料。

| 表 | 欄位/主鍵/索引 |
| --- | --- |
| TBLEQPGROUPBASIS | EquipmentGroup varchar2(50) NOT NULL PK；Description varchar2(255)；Creator/Reviser varchar2(10)；CreateDate/ReviseDate DATE；IssueState NUMBER(1,0) DEFAULT 0 NOT NULL；DataStamp NUMBER(11,0) DEFAULT 0 |
| TBLEQPGROUPDETAIL | EquipmentGroup varchar2(50) NOT NULL、EquipmentNo varchar2(50) NOT NULL；PK (EquipmentGroup, EquipmentNo) |
| TBLSMDAREARELATION | 15 欄；PK (BaseAreaNo, ObjectNo)；額外非唯一索引 I_TBLSMDAREARELATION_01 (ContainAreaNo, ObjectType) |
| TBLSMDSMTAREAEQPMAP | 5 欄；PK (BaseAreaNo, AreaNo, EquipmentNo)；沒有額外索引 |

`TBLEQPGROUPBASIS`/`TBLEQPGROUPDETAIL` 的 PostgreSQL CREATE SQL 為 `database/reference/mestest_equipment_group_create.sql`，已包含於 75 表 bootstrap。兩張 SMD 表 Oracle 原始 DDL 為 `database/reference/mestest_equipment_group_smd_source_ddl.sql`；空表 PostgreSQL CREATE SQL 為 `database/reference/mestest_equipment_group_smd_create.sql`。Oracle DATE 轉 PostgreSQL timestamp without time zone，NUMBER 轉 numeric。四表均無 Oracle FK；套用前由家用端先比對 YMES schema，IF NOT EXISTS 不會修正既有表。

## YMES API 契約（家用電腦待實作）

使用登入 Cookie 與 /YMES/API 同源路由；授權、輸入檢查、DataStamp 與跨群組設備唯一性由 API 強制執行。

| 方法 | 路徑 | 說明 |
| --- | --- | --- |
| GET | /api/equipment/groups?equipmentGroup= | 回傳群組清單，可選 EquipmentGroup 搜尋；需含四種狀態、DataStamp、稽核欄位。 |
| POST | /api/equipment/groups | 新增設備群組；檢查必要編號、長度、PK 及 ChkObjectForSMDLayout 等價規則。 |
| PUT | /api/equipment/groups/{equipmentGroup} | 修改 Description；Body 包含 IssueState、DataStamp，僅允許 IssueState=0。 |
| DELETE | /api/equipment/groups/{equipmentGroup}?issueState=&dataStamp= | 只接受狀態 0/-1/2；交易刪主檔與明細；保留舊 Service 不清 SMD 映射的行為。 |
| POST | /api/equipment/groups/{equipmentGroup}/approve | JSON { issueState, dataStamp }；使用 EQP GROUP BASIS 簽核規則。 |
| GET | /api/equipment/groups/{equipmentGroup}/equipment | 回傳群組 EquipmentNo 明細。 |
| GET | /api/equipment/groups/{equipmentGroup}/available-equipment | 回傳已核准、未加入其他群組且 ChamberFlag=0 的設備；前端可搜尋 EquipmentNo/設備類別/名稱。 |
| POST | /api/equipment/groups/{equipmentGroup}/equipment | JSON { equipmentNos: [] }；要求群組狀態 0，批次檢查單一群組限制，新增明細並依需要同步 SMD 映射。 |
| DELETE | /api/equipment/groups/{equipmentGroup}/equipment | JSON { equipmentNos: [] }；要求群組狀態 0，刪除明細及對應 SMD 映射。 |

可選設備 DTO 至少提供 equipmentNo、equipmentType、equipmentName、issueState、chamberFlag；明細 DTO 提供 equipmentGroup、equipmentNo。群組 DTO 提供 equipmentGroup、description、issueState、dataStamp、creator/createDate、reviser/reviseDate。

## Vue 遷移狀態

- 設備群組 Vue 3 頁已接到設備設定選單，Development 以 DEV-* 假資料呈現上下雙清單、狀態篩選、編號查詢、群組新增/修改/刪除/核准、設備多選加入/移除。
- Development 資料只存在本機 localStorage，沒有呼叫正式 API，也沒有連 MES/Production。
- 關鍵字查詢會清除舊勾選；狀態切換及重新載入會丟棄目前篩選畫面之外的勾選，Delete/Approve 只作用於目前顯示的清單列。設備群組編號在欄位失焦時轉大寫。
- Development 核准假資料直接切到狀態 2，不模擬 MES Issue Job/Detail 的審核中、退回及通知；正式行為由 Production API 實作。
- Web 元件路由比對已改為最長路徑優先，讓 /Equipment/Groups 等巢狀設備頁不會誤派到 /Equipment 基本資料頁。
- Production 端點尚未實作；兩張 SMD 映射表 DDL 已交付，家用端需比對 YMES 目標表。設備群組新增的 `ChkObjectForSMDLayout(ObjectType=4)` 歷史檢查條件已從 modKC.vb 註解版本追出，active helper 的部署版本仍由家用 API 實作時核對。
- 未提供 Copy，因 WinForms Copy 控制項實際隱藏。
- 本次未執行 build 或測試。
