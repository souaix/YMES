## WinForms 畫面與操作

- 開啟時帶入唯讀 EquipmentNo，載入該設備目前參數及可用參數名稱。
- 參數名稱候選由 `wsSYS.LoadElement` 載入，條件為 IssueState=2、ElementType=6；SpecType 候選由 `ValueListProvider.GetValueList("TBLEQPPARAMETERBASIS", "SPECTYPE", True)` 取得。
- Grid 以 SeqNo 升冪排列；SeqNo 唯讀，ParameterName 與 SpecType 可下拉選取。ParameterNo、ParameterValue、Reviser、ReviseDate、EQPParamDate 為隱藏資料欄。
- Move Up / Move Down 交換作用列順序並重排 SeqNo；Delete 僅刪除目前編輯 Grid 的作用列並即時重排，尚未寫回資料庫。
- Confirm 檢查每列 ParameterName、SpecType 必填；ParameterName 不可重複；任一列名稱未選則停止保存。保存時重新編為 1..N 並填入 Reviser。
- 不提供 Apply、Approve 或 IssueState 操作。關閉不保存；Confirm 才呼叫 `UpdEquipmentParameterBasis`。
- Service 在收到 SeqNo=1 時先刪除設備原有參數，再逐列插入新資料；此替換動作應以一個資料庫交易完成。舊 Service 在清空全部列時不會收到 SeqNo=1，無法只靠目前呼叫清除既有資料，API 應明確提供空陣列代表清空。

## 資料表與 CREATE SQL

WinForms Service 明確使用 `TBLEQPPARAMETERBASIS`。使用者於 2026-11-13 提供原始 Oracle CREATE TABLE 與 PK 唯一索引 DDL；已轉為 [設備參數 CREATE SQL](../../../../database/reference/mestest_equipment_parameter_basis_create.sql)，bootstrap 同步修正並移除先前推測欄位註解。Oracle DDL 未宣告 FK；PK 為 `(EquipmentNo, ParameterNo)`，`SeqNo` 是 NOT NULL 欄位但不在 PK。Oracle tablespace/storage 子句省略。

欄位約束：EquipmentNo `VARCHAR2(50)`、SeqNo `NUMBER(2,0)`、ParameterNo `VARCHAR2(20)`、SpecType `NUMBER(1,0)`、Reviser `VARCHAR2(10)`、ReviseDate 均為 NOT NULL；ParameterValue 為 `NUMBER(12,6)` 可為 NULL，EQPParamDate 為 Oracle DATE 可為 NULL。

## API 契約待辦

- `GET /api/equipment/{equipmentNo}/parameters` 回傳目前值並按 SeqNo 排序。
- `GET /api/equipment/parameter-options` 回傳有效參數名稱與 SpecType 選項。
- `PUT /api/equipment/{equipmentNo}/parameters` 接受完整清單；單一交易取代舊資料，空陣列表示清空。伺服器驗證名稱、SpecType 必填及 ParameterName 唯一，順序由 API 正規化。
- 不依舊 Service 的「首列才刪除」漏洞保留空清單無法清除的行為。
