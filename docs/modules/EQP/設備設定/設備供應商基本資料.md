## WinForms 清單畫面

來源：STD/MESWin/EQP/EP_EQPVendor/frmEQPVendor.vb。

- 預設狀態為 Unfrozen / 未簽核（IssueState=0）；可切換未簽核 0、簽核中 1、已簽核 2、不使用 -1。
- 查詢欄位為 VendorNo；按「查詢」重新取得符合條件的供應商。
- 上方供應商清單選列後，呼叫 LoadEQPVendorContactor，將該供應商的聯絡人載入下方清單。
- 主清單顯示供應商編號、名稱、說明及建立/修改人員與日期。
- 主表單操作：新增、修改、刪除、複製、核准、關閉。
- 修改只允許 IssueState=0；核准只允許 IssueState=0。
- WinForms 刪除允許 IssueState 為 0、-1、2；核准中不允許刪除。刪除供應商時，Service 先刪除其聯絡人，再刪除供應商。
- 核准成功後狀態轉為已簽核，回到清單重新載入。

## 供應商定義表單

來源：STD/MESWin/EQP/EP_EQPVendor/frmEQPVendorDef.vb。

| 欄位 | 必填 | 編輯規則 |
| --- | --- | --- |
| VendorNo | 是 | 新增及複製可編輯；修改唯讀。新增預設編號依現存資料從 ES0001 起取第一個可用編號 |
| VendorName | 是 | 最長依 Oracle 欄位 220 字元 |
| Description | 否 | 多行說明，最長 255 字元 |

建立/修改人員與日期由基底定義表單顯示。新增/複製寫入建立者與建立時間；修改傳入 IssueState 與 DataStamp。新增/複製表單提供「...」按鈕，帶入開啟表單時主畫面計算的下一個可用編號，使用者仍可手動修改並於離開欄位時轉大寫。表單按鈕依序為「確定」（儲存並關閉）、「關閉」、「套用」（儲存後保留表單）。

## 聯絡人清單與定義表單

來源：frmEQPVendor.vb、frmEQPVendorContactorDef.vb。

- 選取供應商後顯示聯絡人清單。操作有新增、修改、刪除、複製及 Mail。
- 聯絡人新增/修改/複製不以供應商 IssueState 限制；舊程式中相關狀態限制是註解。
- 聯絡人欄位：VendorNo、ContactorName、TelNo、FaxNo、Title、Address、EMail、Description。
- VendorNo 與 ContactorName 必填；修改時 ContactorName 唯讀。
- 離開 ContactorName 欄位時，若 EMail 空白，預填 ContactorName + @。
- Mail 操作開啟所選聯絡人的 mailto 位址。
- 聯絡人定義表單按鈕為「確定」（儲存並關閉）、「關閉」、「套用」（儲存後保留表單）；套用後更新目前 DataStamp 與稽核資料。
- 修改聯絡人傳入 DataStamp；舊 WinForms 刪除聯絡人以 VendorNo + ContactorName 識別，沒有傳 DataStamp。YMES API 可額外採 DataStamp 衝突保護，但需在 API 規格明確記錄這項安全性差異。

## Oracle 資料表

依即時 MES Oracle MESTEST 資料字典擷取，PostgreSQL 型別轉換與完整欄位在 [設備供應商 CREATE SQL](../../../../database/reference/mestest_equipment_vendor_create.sql)。

### TBLEQPVENDOR

- PK：VendorNo
- 欄位：VendorNo varchar2(20) NOT NULL、VendorName varchar2(220) NOT NULL、Description varchar2(255)、Creator varchar2(10)、CreateDate DATE、IssueState number(1,0) DEFAULT 0 NOT NULL、ERPNo varchar2(50)、DataStamp number(11,0) DEFAULT 0、Reviser varchar2(10)、ReviseDate DATE。
- Oracle DDL 未定義 VendorNo 以外的外鍵。

### TBLEQPVENDORCONTACTOR

- PK：(VendorNo, ContactorName)
- 欄位：VendorNo varchar2(20) NOT NULL、ContactorName varchar2(50) NOT NULL、TelNo/FaxNo/Title varchar2(20)、Address/EMail varchar2(50)、Description varchar2(255)、DataStamp number(11,0) DEFAULT 0、Creator varchar2(10)、CreateDate DATE、Reviser varchar2(10)、ReviseDate DATE。
- Oracle DDL 未定義外鍵；Service 的供應商刪除流程明確先刪子表資料。

## YMES API 契約狀態

下列為 Vue 頁面預定呼叫的契約，家用電腦需建立 schema、migration、DTO 與 API 後才可讀寫：

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | /api/equipment/vendors | 依 `issueState` / `keyword` 查詢清單 |
| GET | /api/equipment/vendors/{vendorNo}/contactors | 載入指定供應商聯絡人 |
| POST | /api/equipment/vendors | 新增供應商 |
| PUT | /api/equipment/vendors/{vendorNo} | 修改供應商；帶 DataStamp |
| DELETE | /api/equipment/vendors/{vendorNo}?issueState=&dataStamp= | 刪除供應商與聯絡人，交易處理 |
| POST | /api/equipment/vendors/{vendorNo}/approve?dataStamp= | 核准未簽核供應商 |
| POST | /api/equipment/vendors/{vendorNo}/contactors | 新增聯絡人 |
| PUT | /api/equipment/vendors/{vendorNo}/contactors/{contactorName} | 修改聯絡人；帶 DataStamp |
| DELETE | /api/equipment/vendors/{vendorNo}/contactors/{contactorName}?dataStamp= | 刪除聯絡人；DataStamp 為 YMES API 新增的併發保護 |

刪除/核准/修改必須重新驗證伺服器端 IssueState、DataStamp 與主鍵。建立/修改/核准/刪除不可回傳假成功。Production API 僅使用 PostgreSQL；API 404 會明確顯示待建置訊息。

## 遷移狀態

- Vue 清單、供應商/聯絡人表單、狀態篩選、列選取、按鈕、Mail 與稽核欄位：已實作；供應商與聯絡人皆提供 WinForms 確定/關閉/套用流程，新增/複製供應商有「...」編號帶入按鈕。
- 假資料只在本機 Development 環境且使用者選取 Development 時啟用；切換環境時重新載入，Test/Production 使用 API。
- PostgreSQL 建表 SQL 依 MESTEST 原始 DDL 轉換；migration `0015_equipment_vendor_schema.sql` 已於 2026-11-14 套用 YMES，套用前備份 `/opt/ymes/backups/ymes_before_0015_equipment_vendor_20261114.dump`。
- 供應商與聯絡人 API、DTO、欄位驗證、IssueState/DataStamp 衝突檢查、交易與設備/物料引用刪除限制已部署於 Production。
- FunctionNo/MenuNo `EQP VENDOR`、FunctionKey `EP101` 已由來源 inventory 核實；Production 導覽仍依既有 0012 目錄資料提供。
- 2026-11-14 app-browser 驗證新增/修改供應商、聯絡人新增/修改、重複編號拒絕、預設編號 `ES0001`；發現並修正新增後清單未更新。驗證用 `ZZCODQA-V` 與聯絡人已由 SSH 以唯一欄位條件清除，確認兩表均無殘留。
- `dotnet build src/YMes.Api/YMes.Api.csproj --no-restore` 與 `npm run build` 通過；API readiness 與 Web 健康檢查正常。
