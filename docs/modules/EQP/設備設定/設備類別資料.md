## 原 WinForms 清單

來源：frmEquipmentType.vb。

### 查詢與資料列

- 狀態篩選沿用標準主檔狀態：未審核 0、審核中 1、已審核 2、不使用 -1；畫面初始狀態為未審核。
- 查詢欄位是 EquipmentType，使用者輸入值以包含式搜尋。
- 清單顯示設備類別、分類顯示名稱、圖片名稱、工程群組、產能、標準人時、標準機時、機時單位批量、說明、建立/修改人與日期。IssueState、EquipmentPicture、EquipmentClass、EquipmentClassNo、DataStamp 為隱藏欄位。
- 點選列只選取資料；ADD、EDIT、DEL、Copy、Approve、Property、ACC Type、Consume、匯入、Close 為主要操作。
- Find、Print 在舊 Form 中隱藏。
- 刪除、核准支援多選並先確認；修改、複製、Property、ACC Type、Consume 以目前作用列為對象。

### 設備類別定義表單

新增、修改、複製共用 frmEquipmentTypeDef：

| 欄位 | 規則 |
| --- | --- |
| EquipmentType | 必填，最多 50 字元；存檔時轉大寫。新增/複製可輸入；修改時鍵值不可改。 |
| EquipmentClass / EquipmentClassNo | 下拉選擇。WinForms 由 ValueListProvider 依 tblEQPEquipmentBasis.EQPClassIndustry 取值；SEMI Wafer 設定時改用 EquipmentClass。類別值要由正式 API/主檔選項確認，不可把 Development 內的固定選項當成資料庫權威值。 |
| PictureName | 選擇或輸入圖片名稱，最多 50 字元。 |
| EquipmentPicture | 圖片檔上傳/預覽；Web Service 以獨立 PictureBody 傳送。 |
| EngineerGroupNo | 必填，最多 20 字元；支援工程群組查詢。 |
| Capacity | 整數，預設 -1；-1 表示不限制，不可小於 -1。 |
| StdUnitEmpTime | 標準人時，預設 0，不得小於 0。 |
| StdUnitEQPTime | 標準機時，預設 0，不得小於 0。 |
| CountEqpUnitQty | 機時單位批量，預設 1，整數且至少 1。 |
| Description | 選填，最多 255 字元。 |
| Creator/CreateDate、Reviser/ReviseDate | 系統稽核欄位；新增/複製寫入建立者，修改寫入修改者與時間。 |
| DataStamp | 隱藏併發版本；修改、核准、刪除需使用讀取到的版本。 |

- EDIT 僅接受 IssueState=0。
- COPY 預設帶入來源欄位但清空新 EquipmentType。clsEQPBasis.AddEquipmentType 會複製來源設備類別的 ACC Type 關聯；不得因此推定耗材、屬性或圖片二進位也會複製。
- 新增與複製結果狀態為 0。

### 核准、刪除與狀態

- 核准只處理 IssueState=0，每筆傳送 EquipmentType、IssueState、DataStamp 及目前使用者。
- wsEQP.ApproveEquipmentType 會檢查核准工作流程設定：未設定待簽工作時可直接進入已核准 2；有工作流程時先進入審核中 1，後續依流程結果成為 2 或退回 0。Development 假資料目前採直接變成 2，API 必須實作並記錄正式流程，不可照搬此簡化。
- 刪除舊 Form 僅對 IssueState 為 0、-1、2 的選取列呼叫 Service，並傳 DataStamp；1 不允許直接刪除。API 還需依原 Service 保留設備引用檢查與跨表交易。
- 狀態篩選由清單切換，不應以 URL query 保存目前選取列。

### ACC Type 配置

來源：frmEQPTypeACCType.vb、clsEQPBasis.cs。

- 以雙清單方式配置可用與已指定的配件類別，可篩選、勾選多筆並移入/移出；確認時提交該設備類別完整的配件編號集合。
- 主關聯表為 TBLEQPEQUIPMENTTYPEACCTYPE，PK 為 (EquipmentType, AccessoryType)。
- 設備類別主檔表與關聯表的 Oracle DDL 已確認；可選配件類別的目錄表原始名稱與 DDL 尚未確認。Web UI Development 使用 DEV-ACC-* 假資料；不可將這些假值當成正式目錄。
- API 必須在交易中以完整集合取代關聯列，並以正式 MES 目錄規則取得可選項目。

### Consume 耗材設定

來源：frmEQPTypeConsumeBasis.vb、frmEQPTypeConsumeBasisDef.vb、clsEQPBasis.cs。

| 欄位 | 規則 |
| --- | --- |
| ConsumeNo | 必填，最多 25 字元，轉大寫；同一 EquipmentType 不可重複。 |
| Quantity | 整數且 >=0。 |
| ToleranceQty | 整數且 >=0，不可大於 Quantity。 |
| Period | 整數且 >=-1；-1 表示不限週期。 |
| TolerancePeriod | 整數且 >=-1；只有 Period=-1 時才可為 -1。 |
| Creator/CreateDate | 新增時寫入；資料表沒有 IssueState/DataStamp 欄位。 |

Consume 主表 TBLEQPCONSUMEBASIS 的 PK 是 (EquipmentType, ConsumeNo)。CRUD 與複製以設備類別為範圍。

### Property 屬性設定

設備類別主表的 Property 按鈕以 Equipment=EquipmentType 啟動共用 EP_EQPProperty Form。雖然資料表欄位命名為 Equipment，這條呼叫路徑實際用設備類別編號作為鍵值；API/UI 必須保留此歷史語意，不可改成設備實體編號。

- 清單預設未審核 IssueState=0，搜尋欄位為 PropertyNo，狀態選單在此 Form 隱藏。
- 欄位為 Equipment（唯讀）、PropertyNo（由屬性定義查詢選取，修改時唯讀）、Property Value/DefaultValue、Sequence/PropertySequence（0–99）、Description。
- 修改只允許 IssueState=0；刪除 Service 傳入 Equipment、PropertyNo、IssueState、DataStamp。
- TBLEQPEQUIPMENTPROPERTY PK 為 (Equipment, PropertyNo)，另有 IssueState/DataStamp 及稽核欄位。
- 屬性定義選項由舊系統 ValueList/Element 資料提供。tblsyselementbasis 的目前 bootstrap 欄位仍標為推測，正式 API 在採用前須先用 MES Oracle DDL/呼叫程式確認其欄位及 PropertyType=1 篩選方式。

### 圖片選擇與匯入

- frmSearchEqpPicture 提供圖片清單、預覽、選取與 Remove；主定義表單可選本機圖片檔上傳。
- TBLEQPEQUIPMENTTYPE 的 PICTURENAME 為圖片名稱；Oracle 另有 EQUIPMENTPICTURE RAW(1000) 欄位。圖片庫二進位獨立存放於 TBLEQPEQUIPMENTTYPE_PICTURE.PICTUREBODY BLOB。不要把圖片二進位塞進設備類別 JSON DTO。
- WinForms 匯入畫面支援 Excel .xls/.xlsx、範本下載及逐筆結果；原始程式使用 EquipmentTypeDataImport.EquipmentTypeDataChecker。API 需解析原格式、逐筆回傳成功/失敗與原因，遵循與手動新增相同的驗證。
- Vue Development 假資料匯入目前提供 CSV 預覽及寫入本機 localStorage；XLS/XLSX 與完整 Checker 規則是已知簡化。正式環境只呼叫匯入 API，不會用 localStorage 假成功。

## Oracle 已確認資料表與 SQL

database/reference/mestest_equipment_type_create.sql 是由公司電腦已取得的 MESTEST 原始 DDL 轉換而來，只建空表，不含 MES 業務資料：

| Oracle 表 | 用途 |
| --- | --- |
| TBLEQPEQUIPMENTTYPE | 設備類別主檔 |
| TBLEQPEQUIPMENTTYPEACCTYPE | 設備類別/配件類別關聯 |
| TBLEQPEQUIPMENTTYPE_PICTURE | 圖片名稱與 BLOB |
| TBLEQPEQUIPMENTPROPERTY | 設備/設備類別屬性 |
| TBLEQPCONSUMEBASIS | 設備類別耗材基準 |

此五表在目前 mestest_first_phase_create_tables.sql 尚未找到；單表檔以 CREATE TABLE IF NOT EXISTS 建立在 ymes schema。執行前仍要先核對家用電腦 YMES 是否已有同名表與欄位，因為 IF NOT EXISTS 只略過建表，不會校正既有結構。原 DDL 沒有明確外鍵，因此本轉換不自行新增 FK。

## YMES API 契約（家用電腦待實作）

Cookie 登入沿用既有 /YMES/API 同源反向代理。前端 fetch 帶 credentials；API 必須做伺服器端授權、輸入驗證、DataStamp 併發檢查及適用的 CSRF 保護。

| 方法 | 路徑 | 目的/契約 |
| --- | --- | --- |
| GET | /api/equipment/types?equipmentType= | 以類別編號包含式查詢；回傳類別列表與 IssueState/DataStamp/稽核欄位。前端依狀態切換顯示。 |
| POST | /api/equipment/types | multipart form：dto JSON 欄位及可選 pictureBody 檔案；新增後回傳完整 DTO。 |
| PUT | /api/equipment/types/{equipmentType} | 同上 multipart；dto 帶 dataStamp，只允許狀態 0。 |
| POST | /api/equipment/types/{equipmentType}/copy | multipart；新編號在 dto，依舊 Service 規則複製 ACC 關聯。 |
| DELETE | /api/equipment/types/{equipmentType}?issueState=&dataStamp= | 只允許狀態 0/-1/2，做版本與使用中引用檢查。 |
| POST | /api/equipment/types/{equipmentType}/approve | JSON { issueState, dataStamp }；由 API 執行核准工作流程。 |
| GET | /api/equipment/types/{equipmentType}/accessory-types | { available: string[], selected: string[] }；可選項必須取自核實過的正式目錄。 |
| PUT | /api/equipment/types/{equipmentType}/accessory-types | JSON { accessoryTypes: string[] }；交易式取代關聯集合。 |
| GET/POST | /api/equipment/types/{equipmentType}/consumes | 列表與新增；欄位依 Consume 表及上方規則。 |
| PUT/DELETE | /api/equipment/types/{equipmentType}/consumes/{consumeNo} | 修改/刪除指定耗材；Consume 表無 DataStamp。 |
| GET | /api/equipment/types/{equipmentType}/properties?issueState=0 | 預設回傳未審核屬性，含 IssueState/DataStamp 及 ElementName。 |
| POST | /api/equipment/types/{equipmentType}/properties | 新增屬性；API 將路由設備類別編號映射到舊表欄位 Equipment。 |
| PUT/DELETE | /api/equipment/types/{equipmentType}/properties/{propertyNo} | 修改 DTO 帶 DataStamp；DELETE query 帶 IssueState/DataStamp。 |
| GET | /api/system/elements?elementType=1 | 屬性編號/名稱查詢。採用前先確認 Oracle 字典與舊 ValueList 規則。 |
| GET | /api/equipment/types/pictures | 回傳可選圖片名稱陣列。 |
| GET | /api/equipment/types/pictures/{pictureName} | Vue 目前預期 JSON { dataUrl: string }，由 BLOB 轉成含正確 MIME 的 data URL。 |
| DELETE | /api/equipment/types/pictures/{pictureName} | 圖片仍被類別引用時拒絕刪除；成功時刪除圖片庫內容。 |
| POST | /api/equipment/types/import | multipart file；讀取 WinForms .xls/.xlsx，逐筆回傳 { results: [{ equipmentType, result, message }] }。 |

主 DTO 至少包含：equipmentType、equipmentClass、equipmentClassNo、pictureName、engineerGroupNo、capacity、description、stdUnitEmpTime、stdUnitEqpTime、countEqpUnitQty、issueState、creator/createDate、reviser/reviseDate、dataStamp。新增/修改圖片使用 multipart，不在 DTO 傳 base64。

## Vue 遷移狀態

- /YMES/Equipment/Types 已接入 Vue 3 主選單，Development 使用明確標示的 DEV-* localStorage 假資料。
- 清單動態選列、狀態/編號查詢、CRUD/核准/複製、ACC Type 雙清單、Consume、Property、圖片清單/預覽/刪除及匯入視窗已建立。

- 設備分類目前以來源常用值提供預覽；正式環境選項應由舊 MES ValueList 規則供應。
- 不含正式業務資料，不會把 mock 回報成 MES 成功寫入。
