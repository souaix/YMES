| 欄位 | 值 |
| --- | --- |
| 第一層 / 第二層 | 設備資料 / 設備設定 |

## WinForms 畫面與流程

- 表單包含檔案路徑與瀏覽按鈕、Import、Close、範本下載、進度列、Cancel，以及逐筆結果 Grid。
- 支援 `.xls` 與 `.xlsx`，只讀第一個工作表；使用者選取檔案後先解析資料與建立結果列，再按 Import 才開始檢查及寫入。
- 匯入前提示使用者先關閉 Excel；背景平行處理，逐筆顯示 EquipmentNo、EquipmentType、結果、訊息與進度，支援取消。
- 範本下載按鈕在此版本顯示；範本更新按鈕隱藏。
- 驗證/寫入呼叫 `DataImporter.EquipmentDataImport.EquipmentDataChecker`，按設備編號與設備類別組合批次；API 應回傳每組成功/失敗及訊息，不能只回單一總結果。

## 工作表欄位

依第一張工作表固定讀取前八欄，依序為：

| 順序 | 欄位 | 是否必填 |
| --- | --- | --- |
| 1 | EquipmentType | 是 |
| 2 | EquipmentNo | 是 |
| 3 | EquipmentName | 是 |
| 4 | Description | 否 |
| 5 | EngineerGroupNo | 是 |
| 6 | VendorNo | 是 |
| 7 | ChamberFlag | 是 |
| 8 | BelongEquipmentNo | 否（Chamber 應有父設備） |

資料列至少讀取前七欄；欄位標題名稱需依原始範本核對，不以自行建立的 CSV 欄名代替正式 Excel 範本。

## API / DB 規格

- 新增 `POST /api/equipment/import` multipart/form-data；Production 由 API 解析 `.xls/.xlsx` 第一張工作表、執行與單筆設備相同的欄位/關聯/父子設備驗證，並以設備編號/類別為組回報結果。
- 匯入 API 回傳每組 EquipmentNo、EquipmentType、Result、Message 及總進度/取消狀態；需要明確說明多筆匯入是逐筆提交或整批交易，需以舊 DataChecker 實作確認。
- 匯入直接建立/更新設備主檔及 Chamber 共表資料；沒有已確認的獨立匯入資料表。`TBLEQPEQUIPMENTBASIS` Oracle 原始 DDL仍待核實。
- DEV UI 支援 CSV 預覽與 localStorage 假資料寫入，清楚標示簡化範圍；先處理主設備，再處理 Chamber；DEV 檢查設備編號重複、必填欄位及所屬設備存在。這些檢查只供畫面驗收，不取代 DataChecker。
- Production UI 接受 `.xls/.xlsx` 並送至 API 解析，顯示逐列結果及進度；不在瀏覽器保存正式資料。
