## 功能範圍

設備配方以群組與版本管理，每個版本有多筆設備參數明細。主畫面上方顯示 Recipe Basis，下方依選取的群組/版本載入明細。來源 WinForms 主窗體尺寸為 1008×591，主清單與明細各有獨立 UltraGrid 和操作按鈕。

## WinForms 畫面

### 查詢與主清單

- 簽核狀態選項：未簽核 `0`、簽核中 `1`、已簽核 `2`、不使用 `-1`；初始選擇未簽核。
- 查詢欄位為 Recipe ID（`RecipeGroup`），點「查詢」後重新載入主清單。
- 主清單欄位順序：Recipe ID、Version、Current、Description、Creator、CreateDate、Reviser、ReviseDate。`IssueState`、`CurVersion`、`DataStamp` 為隱藏資料欄。
- `Current` 是由 `CurVersion=1` 顯示 Yes，`CurVersion=0` 顯示 No。
- 選取主列時，讀取相同 `RecipeGroup`、`RecipeVersion` 的明細。明細來源 SQL 沒有指定排序，頁面不假設資料庫順序代表 Sequence。
- 主畫面按鈕：ADD、EDIT、DEL、Copy、Version、Approve、Close。主窗體右側垂直排列；下方明細另有 ADD、EDIT、DEL。

### Recipe Basis 表單

- 表單欄位：Recipe ID、Version、Description；另顯示建立人/日期與修改人/日期。
- Recipe ID 最長 50；新增預設 Version=1。RecipeGroup 失焦時轉大寫。
- Edit 時 Recipe ID、Version 唯讀，只能修改 Description；新增版本時 Recipe ID 唯讀；Copy 時 Recipe ID 可改、Version 預設 1。
- 按鈕為確定、關閉、套用。

### Recipe Detail 表單

- 欄位：Recipe ID、Version、Recipe No、Recipe Value、Sequence、Type、StdValue、Minimum、Maximum、Description，以及建立/修改稽核欄位。
- Recipe ID、Version 唯讀。Recipe No 由 `...` 選擇 Element，選取結果帶入 ElementNo、DefaultValue、ElementSequence；Edit 時 Recipe No 唯讀。
- Type 選項：`-1=None`、`0=Value`、`1=Range`。Value 僅編輯 StdValue；Range 編輯 Minimum/Maximum；None 不編輯這三個數值欄位。
- StdValue 離開欄位時，Recipe Value 帶入 StdValue；Minimum/Maximum 離開欄位時，Recipe Value 帶入 `Minimum ~ Maximum`。Recipe Value 仍為必填。
- Recipe No 來源是 `wsSYS.LoadElement(ElementType=9)`，使用共用元素主檔，不新增元素資料表。

## 欄位與驗證

| 欄位 | Oracle 型別 | NULL / DEFAULT | WinForms 規則 |
| --- | --- | --- | --- |
| RecipeGroup | VARCHAR2(50) | NOT NULL | 主檔必填，最大 50；新增/複製可編輯；改為大寫 |
| RecipeVersion | NUMBER(2,0) | DEFAULT 0、NOT NULL | 新增預設 1；修改唯讀；建立 Version 時選取版本 + 1 |
| Description | VARCHAR2(255) | NULL | 主檔/明細描述，最大 255 |
| IssueState | NUMBER(1,0) | DEFAULT 0、可 NULL | -1、0、1、2 |
| CurVersion | NUMBER(1,0) | DEFAULT 0、NOT NULL | 0/1；核准時維護同群組唯一目前版 |
| DataStamp | NUMBER(11,0) | DEFAULT 0、可 NULL | 主檔/明細修改時做並行版本檢查 |
| RecipeNo | VARCHAR2(20) | NOT NULL | 明細必填；資料庫主鍵欄位，Edit 唯讀 |
| RecipeValue | VARCHAR2(255) | NOT NULL | 明細必填 |
| Sequence | NUMBER(2,0) | DEFAULT 0、可 NULL | WinForms 驗證最大值 99 |
| Type | NUMBER(1,0) | NULL | `-1=None`、`0=Value`、`1=Range` |
| StdValue / Maximum / Minimum | NUMBER(8,4) | NULL | Value 必須有數值；Range 至少一個界限，最大值需大於最小值（依來源表單邏輯） |

**稽核欄位**：兩表皆有 Creator/Reviser VARCHAR2(10)、CreateDate/ReviseDate DATE。這些欄位可 NULL。Recipe Detail 的 DataStamp DEFAULT 0 且可 NULL。

## 按鈕與操作流程

| 按鈕 | 規則 |
| --- | --- |
| ADD | 新增 RecipeGroup，Version=1、IssueState=0、CurVersion=0；明細另行新增 |
| EDIT | 僅 IssueState=0 可修改 Description；以 DataStamp 防止覆蓋他人修改 |
| Copy | 複製主檔到可編輯 RecipeGroup、Version=1；呼叫 CopyRecipe 建立主檔及複製明細 |
| Version | 僅 IssueState=2 且 CurVersion=1 可用；目標 RecipeGroup 不變、Version=目前選取版本+1、IssueState=0、CurVersion=0 |
| DEL 主檔 | 可刪 IssueState `0/-1/2`，`1` 不允許；Core 先刪此群組/版本的所有明細，再刪主檔，兩個 SQL 以同一批次執行 |
| Approve | 僅 IssueState=0 可核准。IssueNo=`RECIPE BASIS`；沒有簽核 Job/Detail 時直接核准，有流程時改成 Pending 並建立簽核工作 |
| ADD/EDIT/DEL 明細 | 只有主檔 IssueState=0 可維護。主鍵為 RecipeGroup/RecipeVersion/RecipeNo；明細刪除可多選 |

### Copy/Version 明細的來源行為

`wsEQP.CopyRecipe` 呼叫 `AddRecipeDetail` 時，只傳 RecipeNo、RecipeValue、Sequence、Description。Type、StdValue、Maximum、Minimum、Creator、CreateDate 不會複製，新增的明細這些欄位為 NULL。Web API 若要忠實相容此舊行為，COPY/VERSION 也需只複製上述四欄；若日後改成完整複製，應另列需求差異。

## 狀態、簽核與交易規則

- 狀態碼：`-1` 不使用、`0` 未簽核、`1` 簽核中、`2` 已簽核。
- EDIT 與明細 CRUD 僅接受狀態 0。主檔刪除只接受 0/-1/2。
- 直接核准時先把同 RecipeGroup 的 CurVersion 設為 0，再將指定版本設 IssueState=2、CurVersion=1。
- 有簽核流程時，核准 SQL 在工作完成後設定目前版本；送簽時狀態為 1，退回時回到 0。不可把 Production 核准固定實作成直接 0→2。
- 建立 Version 的程式使用目前選取的 `RecipeVersion + 1`；原始註解雖寫「最大版本+1」，實際程式並未查最大版。
- Oracle 沒有在主/明細表間宣告 FK。資料庫/ API 刪除主檔時需明確在同一交易刪明細，避免孤兒資料。

## 資料庫

### `MESTEST.TBLEQPRECIPEBASIS`

- PK：`(RECIPEGROUP, RECIPEVERSION)`。
- NOT NULL：RecipeGroup、RecipeVersion、CurVersion。
- RecipeVersion DEFAULT 0；IssueState DEFAULT 0（可 NULL）；CurVersion DEFAULT 0；DataStamp DEFAULT 0（可 NULL）。
- 唯一索引為 PK；額外非唯一索引 `I_TBLEQPRECIPEBASIS_01(RECIPEGROUP,CURVERSION)`；無 FK。

### `MESTEST.TBLEQPRECIPEDETAIL`

- PK：`(RECIPEGROUP, RECIPEVERSION, RECIPENO)`。
- NOT NULL：RecipeGroup、RecipeVersion、RecipeNo、RecipeValue。
- RecipeVersion DEFAULT 0；Sequence DEFAULT 0；DataStamp DEFAULT 0，其餘欄位沒有 DEFAULT。
- 唯一索引為 PK；額外非唯一索引 `I_TBLEQPRECIPEDETAIL_01(RECIPEGROUP,RECIPENO)`；無 FK。
- `TBLSYSVALUELIST` 中 `TBLEQPRECIPEDETAIL.TYPE`：-1 NONE、0 TYPEVALUE、1 RANGE。

Oracle 原始 DDL：`database/reference/mestest_equipment_recipe_source_ddl.sql`。供家用端比對的 PostgreSQL 空表 CREATE SQL：`database/reference/mestest_equipment_recipe_create.sql`。第一階段 bootstrap `database/reference/mestest_first_phase_create_tables.sql` 已校正這兩張表的 DEFAULT、NOT NULL 與索引。CREATE SQL 不含任何 MES 業務資料；執行前仍需比對 YMES 實際結構，`IF NOT EXISTS` 不會修補既有欄位。

## API 契約（家用電腦待建）

建議使用以下 camelCase DTO；目前 Vue Production API 尚未接通。

| 方法與路徑 | 用途/必要規則 |
| --- | --- |
| `GET /api/equipment/recipes?issueState=0&recipeGroup=` | 依狀態及 RecipeGroup 查詢；回傳主清單、隱藏狀態/CurVersion/DataStamp 及稽核欄位 |
| `POST /api/equipment/recipes` | 新增 RecipeGroup/RecipeVersion/Description；狀態 0、CurVersion 0；操作者/時間由登入上下文與伺服器時間取得 |
| `PUT /api/equipment/recipes/{recipeGroup}/{recipeVersion}` | 只允許狀態 0；更新 Description，要求 DataStamp compare-and-swap |
| `DELETE /api/equipment/recipes/{recipeGroup}/{recipeVersion}?dataStamp=` | 只接受狀態 0/-1/2；在同一交易刪明細及主檔，1 回 409；DataStamp 不符回 409 |
| `POST /api/equipment/recipes/{recipeGroup}/{recipeVersion}/approve` | IssueNo `RECIPE BASIS`；接 YMES 簽核 Job/Detail，支援直接核准、Pending、核准/退回 |
| `POST /api/equipment/recipes/copy` | Body 含 from/to RecipeGroup、RecipeVersion、Description；新增主檔與明細需原子提交；不得 source=target |
| `GET /api/equipment/recipes/{recipeGroup}/{recipeVersion}/details` | 讀取此版本所有明細及 DataStamp |
| `POST /api/equipment/recipes/{recipeGroup}/{recipeVersion}/details` | 新增明細；RecipeNo 必填/唯一、RecipeValue 必填、Sequence 0..99、Type/數值相符 |
| `PUT /api/equipment/recipes/{recipeGroup}/{recipeVersion}/details/{recipeNo}` | 只允許父主檔狀態 0；用 DataStamp compare-and-swap |
| `DELETE /api/equipment/recipes/{recipeGroup}/{recipeVersion}/details/{recipeNo}` | 只允許父主檔狀態 0；相容來源刪除不帶明細 DataStamp 的行為 |
| `GET /api/system/elements?elementType=9` | Recipe No 選取器，回傳 ElementNo、Description、DefaultValue、ElementSequence；使用既有元素表，不新增表 |

## Vue 實作與狀態

- `EquipmentRecipeBasisMaster.vue` 對齊上/下雙清單、簽核狀態篩選、RecipeGroup 查詢、右側操作按鈕、主檔/明細新增修改刪除、Type/Range 表單、Element 選擇器、稽核欄位與 KD 黃色欄位。
- Development Preview 使用 `localStorage` 假資料，可操作新增、修改、複製、建版本、刪除及直接核准。DEV 核准簡化為即時核准，提示文字說明正式簽核待 API。
- Production 不讀取 localStorage；API 尚未提供時顯示尚未建置，不假裝寫入成功。
- 尚未由使用者以瀏覽器人工驗收；本次未執行 build 或測試。
