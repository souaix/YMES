# 載具基本資料（EP303）

## 識別資訊

| 欄位 | 值 |
| --- | --- |
| ModuleNo / 第一層 | EQP / 設備資料 |
| MenuNo / 第二層 | 載具 |
| FunctionNo / 第三層 | CARRIER BASIS / 載具基本資料 |

| WinForms Form | frmCarrierBasis；編輯窗 frmCarrierBasisDef |

## 功能目的與範圍

維護載具編號及其載具分類、載具類別、廠區、描述與簽核狀態。主檔資料表為 TBLEQPCARRIERBASIS；新增、刪除與分類/類別修改會同步影響 TBLWIPCarrierState。載具分類、載具類別與廠區選擇器只提供已核准資料。

## WinForms 畫面

### 主清單 frmCarrierBasis

- 繼承 COM_Kit.frmBasisTemplat，ClientSize 1008×591；狀態篩選列沿用共用基底。
- 狀態選項：未簽核（0，預設）、簽核中（1）、已簽核（2）、不使用（-1）。
- 查詢欄位只有 CarrierNo；按查詢使用部分符合條件。資料載入時不限定 IssueState，狀態切換以本機資料檢視篩選。
- UltraGrid 位於 (12,53)，尺寸 894×532；只隱藏 IssueState、DataStamp。其餘資料欄位顯示：CarrierNo、CarrierCategory、CarrierType、Description、Creator、CreateDate、FactoryNo、Reviser、ReviseDate、GetGroupNo、GetAnsNo、MaintenanceTime、BeGroupMainten。CreateDate、ReviseDate 使用 yyyy/MM/dd HH:mm:ss。
- 右側按鈕依序：新增(A)、修改(E)、刪除(D)、複製(C)、核准；關閉位於右下。
- 批次刪除/核准會自動納入目前列；逐筆呼叫服務，遇到第一筆失敗即停止，已成功的前筆不回滾。

### 定義窗 frmCarrierBasisDef

- ClientSize 504×363；主欄位群組 480×221、建立/修改資訊群組 480×70。
- 欄位順序：Carrier No、Carrier Category、Carrier Type、Factory No、Description。
- Carrier No、Carrier Category、Carrier Type、Factory No 欄位本身為唯讀；Category、Type、Factory 旁的 ... 選擇按鈕仍可操作。Description 可編輯。
- Add/Copy 要輸入 Carrier No，離開欄位時轉大寫。Category、Type、Factory No、Carrier No 為必填；Description 可空白。
- 選取不同 Carrier Category 時清空 Carrier Type；開啟 Carrier Type 選擇器前必須先有 Category，且只列該 Category 的已核准類別。Factory 選擇器只列 IssueState=2。
- EDIT 時 Carrier No 不可改；分類、類別、廠區可透過選擇按鈕變更，Description 可編輯。僅 IssueState=0 可進入修改。
- Audit 區顯示建立人/日期、修改人/日期。底部按鈕順序：確定、關閉、套用；資料變更前套用不可用，套用儲存後窗體保持開啟。
- COPY 預填來源列欄位，Carrier No 可編輯，使用者需改為未重複的編號。

## 欄位與驗證

| 欄位 | 必填 | 長度 | 規則 |
| --- | --- | ---: | --- |
| CarrierNo | 是 | 50 | 新增/複製時可編輯；失焦轉大寫；主鍵 |
| CarrierCategory | 是 | 50 | 由已核准載具分類選取 |
| CarrierType | 是 | 50 | 由所選分類下已核准載具類別選取 |
| FactoryNo | 是 | 20 | 對應廠區選項，使用 FactoryNo 儲存 |
| Description | 否 | 255 | 多行文字 |

## 按鈕與操作流程

| 操作 | 規則 |
| --- | --- |
| 查詢 | CarrierNo 部分符合；IssueState 切換只改變前端顯示範圍，不重載頁面 |
| 新增 | 驗證五個欄位；主檔 IssueState=0，並在同一資料庫交易新增 WIP 狀態列（CarrierState=0） |
| 修改 | 僅 IssueState=0；CarrierNo 不可改；更新分類、類別、FactoryNo、Description 及稽核欄位。分類/類別變動需同步 WIP 列的 CarrierCategory/CarrierType |
| 複製 | 以新增方式保存；主鍵重複時拒絕 |
| 刪除 | 0/-1：在同一交易實體刪除主檔與 TBLWIPCarrierState 列；2：只將主檔 IssueState 改為 -1 並更新稽核/DataStamp；1：拒絕 |
| 核准 | 只接受 IssueState=0；IssueNo 為 CARRIER BASIS。沒有對應簽核 Job/Detail 時直接轉 2；有簽核設定時建立簽核工作並轉 1、通知第一簽核群組，核准後轉 2、退回後轉 0 |

Legacy UI 對多筆 Delete/Approve 逐筆處理、第一筆錯誤即停止，前筆成功保留。API 需每筆原子化並以並行版本檢查防止覆寫；批次流程的部分成功結果必須回報。

### 交易/選項依賴

- MESTEST.TBLWIPCarrierState：CARRIERNO VARCHAR2(50) NOT NULL（PK）、CARRIERCATEGORY VARCHAR2(50) NOT NULL、CARRIERTYPE VARCHAR2(50) NOT NULL、CARRIERSTATE NUMBER(1,0) nullable、DESCRIPTION VARCHAR2(255) nullable、LOTNO VARCHAR2(50) nullable。只有 PK unique index，無 FK。
- MESTEST.TBLSMDFactoryBasis：FACTORYNO VARCHAR2(20) NOT NULL（PK）、DESCRIPTION VARCHAR2(255) nullable、CREATOR VARCHAR2(10) NOT NULL、CREATEDATE DATE NOT NULL、ISSUESTATE NUMBER(1,0) DEFAULT 0 NOT NULL、FABCODE VARCHAR2(10) nullable、FACTORYNAME VARCHAR2(50) nullable、REVISER VARCHAR2(10) nullable、REVISEDATE DATE nullable、DATASTAMP NUMBER(11,0) DEFAULT 0 nullable。只有 PK unique index，無 FK。WinForms wsSMD.LoadFactoryBasis 預設取已核准列。
- CarrierCategory、CarrierType、FactoryNo 均為程式邏輯關聯，來源 Oracle 沒有 FK。

## API 契約

以下是提供 Vue 的 Production API 契約，家用端需依現有控制器/認證方式調整實作，但保留欄位與流程語意。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | /api/equipment/carrier-basis?carrierNo= | 回傳所有簽核狀態列，CarrierNo 部分符合；前端切狀態 |
| POST | /api/equipment/carrier-basis | 新增主檔與 WIP 狀態列，同一交易 |
| PUT | /api/equipment/carrier-basis/{carrierNo} | 僅修改未簽核資料，DataStamp compare-and-swap；同步 WIP 分類/類別 |
| DELETE | /api/equipment/carrier-basis/{carrierNo}?issueState=&dataStamp= | 按 IssueState 執行實體刪除或停用，檢查 DataStamp |
| POST | /api/equipment/carrier-basis/{carrierNo}/approve | 執行 CARRIER BASIS 簽核規則 |
| GET | /api/equipment/carrier-categories?issueState=2 | Category 選項 |
| GET | /api/equipment/carrier-types?issueState=2&carrierCategory= | 所選 Category 的 Type 選項；EP302 API 增加可選 carrierCategory 篩選 |
| GET | /api/master-data/factories?issueState=2 | FactoryNo 選項，來源 tblsmdfactorybasis |

Create/Copy body：carrierNo、carrierCategory、carrierType、factoryNo、description。Edit body：carrierCategory、carrierType、factoryNo、description、issueState、dataStamp。Audit 人員由 API 驗證後的使用者身分取得；日期由伺服器產生。新增初始 DataStamp=0；修改/核准/停用檢查 DataStamp，衝突回 409。批次動作由 Vue 逐筆呼叫並顯示部分成功。
