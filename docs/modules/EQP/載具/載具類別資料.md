| 欄位 | 行為 / 驗證 |
| --- | --- |

| Carrier Category | 必填、唯讀；旁邊 `...` 開啟選取視窗，只載入 IssueState=2 已核准的載具分類。欄位 VARCHAR2(50)，來源沒有外鍵。 |
| Use Layer | 必須選 Not Use(0) 或 Use(1)。 |
| Carrier Layer / Carrier Capacity | Use=1 時啟用且都要正整數，資料欄位 NUMBER(3,0)。Use=0 時自動設 1 並停用。 |
| Start Position | 必填正整數；Use=1 時可編輯，Use=0 時自動設 1 並停用；資料欄位 NUMBER(3,0)。 |
| Description | RichTextBox 多行；欄位 VARCHAR2(255)，WinForms 沒有設定 MaxLength。 |
| Creator / CreateDate | Add/Copy 帶入登入者及當下時間；Edit 保留原值。 |
| Reviser / ReviseDate | Edit 顯示登入者及當下時間，成功儲存更新；唯讀稽核欄。 |

Add 預設 Start Position=1，Use Layer 未選，Carrier Layer/Capacity 空白。Copy 會帶入原分類、Use Layer、各數值及 Description；當 Use Layer=0 時表單把 Layer/Capacity/Start Position 顯示並儲存為 1。Edit 僅允許 IssueState=0。

套用起初停用，資料改變後啟用。成功 Apply 留在原表單模式、保留目前值並停用 Apply；Confirm 儲存後關閉。舊服務在 Description 為空字串時不執行 Edit SQL，即使其他欄位有變也可能回報成功未更新；新 API 應支援空 Description 並以欄位差異完成更新。

## 狀態、刪除與核准邏輯

- Delete 會把作用列加入多選列：IssueState 0 與 -1 實體刪除；2 轉為 -1，並更新 Reviser、ReviseDate、DataStamp；1 簽核中不可刪除。
- 舊 `wsEQP.DelCarrierType` 讀取 DataStamp，但實體刪除呼叫 `clsCarrierBasis.DelCarrierType` 時沒有 DataStamp 條件；新 API 建議所有分支檢查 DataStamp，避免刪除舊資料版本。
- Approve 只允許 IssueState=0。`wsEQP.ApproveCarrierType` 使用 IssueNo `CARRIER TYPE` 查簽核設定：沒有 Job，或 Job 沒有 Detail 時直接改成 IssueState=2；有簽核明細則建立 Issue 主檔、狀態改 1、通知第一簽核群組；簽核完成改 2，退回改 0。
- Development preview 的核准先簡化為 0→2，畫面註明簡化；Production API 必須依正式 YMES Issue/Job 規則實作，未支援時應回報，不能偽回核准成功。
- `clsCarrierBasis` 對載具類別主檔刪除只刪 `TBLEQPCARRIERTYPE`，沒有額外刪除子表；Oracle 表沒有 FK。

## Oracle DDL 與 PostgreSQL CREATE SQL

公司端於 2026-11-16 使用 Windows PowerShell 5.1 + Oracle.ManagedDataAccess，從本機受保護設定直接唯讀取得 MESTEST `DBMS_METADATA.GET_DDL`，並查 ALL_TAB_COLUMNS、ALL_CONSTRAINTS、ALL_INDEXES、ALL_IND_COLUMNS。未查業務資料、未在 Oracle 執行 DDL。

- Oracle 原始 DDL / 主鍵索引：`database/reference/mestest_carrier_type_source_ddl.sql`
- PostgreSQL 空表 CREATE SQL：`database/reference/mestest_carrier_type_create.sql`
- 欄位：CarrierType VARCHAR2(50) NOT NULL；CarrierCategory VARCHAR2(50) NOT NULL；UseLayer NUMBER(1,0) NOT NULL；CarrierLayer/CarrierCapacity/StartPosition NUMBER(3,0) DEFAULT 1 nullable；Description VARCHAR2(255)；Creator/Reviser VARCHAR2(10)；CreateDate/ReviseDate DATE；IssueState NUMBER(1,0) DEFAULT 0 NOT NULL；DataStamp NUMBER(11,0) DEFAULT 0 nullable。
- PK 為 CarrierType；唯一索引只有 PK index；無其他索引/FK。CarrierCategory 只是應用層關聯。PG CREATE SQL 只建立空表，不含 MES 業務資料。
- 此表不在既有 75 張第一階段 CREATE SQL；家用端先核對 YMES schema/migration，缺表才新增 migration，保留 YMES 現有額外欄位。

## API 契約（家用電腦待建）

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/equipment/carrier-types?carrierType=&carrierCategory=&issueState=` | 查詢所有簽核狀態；CarrierType 部分符合、排序；回傳完整顯示欄位、IssueState、DataStamp、稽核欄位。支援選擇器以 CarrierCategory 篩選；issueState 可選，但 Vue 狀態列在客戶端即時切換。 |
| GET | `/api/equipment/carrier-categories?issueState=2` | Carrier Category picker，只回傳已核准分類。 |
| POST | `/api/equipment/carrier-types` | 新增未簽核資料；伺服器設定 Creator/CreateDate、IssueState=0、DataStamp=0。 |
| PUT | `/api/equipment/carrier-types/{carrierType}` | 僅修改 IssueState=0；必須檢查 DataStamp。 |
| POST | `/api/equipment/carrier-types/{carrierType}/approve` | 檢查 IssueState=0、DataStamp，依正式 Issue/Job 設定核准或建立簽核流程。 |
| DELETE | `/api/equipment/carrier-types/{carrierType}?issueState=&dataStamp=` | 0/-1 實體刪除；2 改為 -1；1 拒絕。建議所有分支均檢查 DataStamp。 |

新增 DTO：`carrierType`、`carrierCategory`、`useLayer`、`carrierLayer`、`carrierCapacity`、`startPosition`、`description`。修改 DTO 另含 `issueState`、`dataStamp`。UseLayer 僅 0/1；UseLayer=0 強制 Layer/Capacity/StartPosition=1；UseLayer=1 三值均為 1–999 正整數。CarrierType Trim/ToUpper、最長 50；CarrierCategory 必須存在且狀態為 2；Description 最長 255。重複 PK、DataStamp 衝突及狀態不允許回 409，欄位驗證回 400，不存在回 404。

批次操作由 UI 逐筆呼叫，API 單筆應原子完成。DEV localStorage 不連 YMES/MES；測試/正式環境走 API。
