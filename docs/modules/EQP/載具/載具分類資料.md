## 狀態、刪除與核准邏輯

- Edit 只允許 IssueState=0。
- Delete 會將作用列併入多選列並逐筆執行：0 未簽核與 -1 不使用為實體刪除；2 已簽核改成 -1 停用並更新 Reviser、ReviseDate、DataStamp；1 簽核中拒絕刪除並停止後續處理。
- 舊 WebService 刪除方法會解析 DataStamp；停用路徑以 DataStamp 更新，實體刪除呼叫 `clsCarrierBasis.DelCarrierCategory` 時沒有傳入 DataStamp 條件。新 API 應對所有刪除做 DataStamp 檢查，避免 UI 讀取後資料已變更。
- Approve 只接受 IssueState=0。`wsEQP.ApproveCarrierCategory` 讀取 EQP 簽核設定：沒有可用簽核工作時直接轉成 2；有簽核 Job 時建立簽核主檔、狀態轉 1、通知第一簽核群組；簽核完成轉 2，退回轉 0。此流程依賴既有 Issue/Job 設定與服務。
- Development preview 的核准先簡化為 0→2，畫面明確標示簡化狀態；Production API 仍需依正式 YMES 簽核設計落實或回報未支援，不能把 DEV 結果當正式簽核。
- `clsCarrierBasis` 對此主檔刪除只刪除 `TBLEQPCARRIERCATEGORY`，沒有額外刪除明細或 Service 引用檢查。Oracle 本表無外鍵。

## Oracle DDL 與 PostgreSQL CREATE SQL

公司端以 Windows PowerShell 5.1 + Oracle.ManagedDataAccess，從本機受保護設定直接查 MESTEST `DBMS_METADATA.GET_DDL`，並查 ALL_TAB_COLUMNS、ALL_CONSTRAINTS、ALL_INDEXES、ALL_IND_COLUMNS；只讀結構，未查詢 MES 業務資料。

- Oracle DDL / 主鍵索引：`database/reference/mestest_carrier_category_source_ddl.sql`
- PostgreSQL 空表 CREATE SQL：`database/reference/mestest_carrier_category_create.sql`
- 欄位：CarrierCategory VARCHAR2(50) NOT NULL；Description VARCHAR2(255)；Creator/Reviser VARCHAR2(10)；CreateDate/ReviseDate DATE；IssueState NUMBER(1,0) DEFAULT 0 NOT NULL；DataStamp NUMBER(11,0) DEFAULT 0 NULL。
- 主鍵為 CarrierCategory；唯一索引僅 PK index；無其他索引或外鍵。PostgreSQL 的 CREATE SQL 只建立空表，不含 MES 業務資料。
- 此表不在既有 `mestest_first_phase_create_tables.sql` 75 表初始 SQL 中；家用端先核對 YMES schema/migration，只有缺表才新增 migration。

## API 契約（家用電腦待建）

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/equipment/carrier-categories?issueState=0&carrierCategory=` | 依狀態與分類編號部分符合查詢，按 CarrierCategory 排序；回傳狀態、DataStamp 及稽核欄位 |
| POST | `/api/equipment/carrier-categories` | 新增未簽核分類；伺服器設定 Creator/CreateDate、IssueState=0、DataStamp=0 |
| PUT | `/api/equipment/carrier-categories/{carrierCategory}` | 僅修改 IssueState=0 的 Description；必須檢查 DataStamp |
| POST | `/api/equipment/carrier-categories/{carrierCategory}/approve` | 檢查 IssueState=0、DataStamp，依既有簽核設定直接核准或建立簽核流程 |
| DELETE | `/api/equipment/carrier-categories/{carrierCategory}?issueState=&dataStamp=` | 0/-1 實體刪除；2 更新為 -1；1 拒絕。建議所有分支均檢查 DataStamp |

POST DTO：`carrierCategory`、`description`。PUT DTO：`description`、`issueState`、`dataStamp`。Approve DTO：`issueState`、`dataStamp`。編號儲存前 Trim/ToUpper，長度不得超過 50；Description 最長 255。重複 PK 回 409、欄位驗證回 400、資料不存在回 404、DataStamp 衝突回 409、非允許狀態回 409。

UI 逐筆呼叫 Delete/Approve；API 每一請求需原子完成單筆狀態更新。舊簽核流程需複用既有 YMES Issue/Job 機制；若尚未完成，不得在 Production 直接偽回核准成功。
