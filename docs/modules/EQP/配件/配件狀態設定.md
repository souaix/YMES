## 主畫面

主視窗約 1008×591，左側資料 Grid 填滿工作區，右側縱向排列按鈕，Close 固定在右下。沒有簽核狀態列、查詢列、核准、匯入或匯出按鈕。

| 欄位 | 顯示方式 |
| --- | --- |
| AccessoryState | 整數，靠右；依編號升冪 |
| StateType | ValueList：0 System、1 User Define |
| StateName | 狀態名稱 |
| StateColor | 顯示色塊，使用資料列的 ARGB 色彩值 |
| Description | 說明 |
| Creator / CreateDate | 建立者、建立日期 |
| Reviser / ReviseDate | 修改者、修改日期 |

DataStamp 不顯示。狀態色塊由 StateColor 的 .NET Color.FromArgb 顯示。

## 編輯表單與欄位規則

編輯視窗標題依模式顯示 ADD、EDIT、Copy；群組標題為 EQP ACC State Data。表單包含 AccessoryState、StateType、StateName、StateColor、Description，底部有稽核資訊和 Confirm、Close、Apply。

| 欄位 | 行為/限制 |
| --- | --- |
| AccessoryState | 必填整數；NUMBER(2,0)，值域 -99 至 99；新增/複製可編輯，修改唯讀；主鍵不得重複 |
| StateType | 必填選項 0 System、1 User Define；新增預設 0 |
| StateName | 必填；資料表欄寬 50 |
| StateColor | 按 Set Color 開啟色彩選擇器；儲存 .NET Color.ToArgb() 的有號整數 |
| Description | 選填，最多 255 字元 |
| Creator / CreateDate | 新增/複製時由登入者與伺服器時間產生 |
| Reviser / ReviseDate | 修改時由登入者與伺服器時間產生 |

表單檢查 AccessoryState 必須為整數。StateType=1 時不可使用 0 至 10；負數及 11 以上的值可使用，但仍受 NUMBER(2,0) 值域限制。StateName 必填。新增及複製若主鍵已存在，由資料庫唯一鍵拒絕。

Apply 儲存後保留視窗；新增/複製可繼續輸入另一筆，修改更新 DataStamp。Confirm 儲存後關閉。Close 不保存未套用變更。

## 主畫面按鈕

| 按鈕 | 行為 |
| --- | --- |
| ADD (A) | 開啟新增表單；StateType 初始為 0 |
| EDIT (E) | 編輯目前列；AccessoryState 唯讀 |
| DEL (D) | 可多選，確認後逐筆呼叫刪除 Service；只刪狀態主檔列 |
| Copy (C) | 以目前列開啟複製表單；需修改編號以建立新主鍵 |
| Close (X) | 關閉頁面 |

無簽核狀態欄位，因此本頁沒有核准/停用流程。舊 Service 的 Delete 直接刪除 TBLEQPACCSTATEBASIS 指定列，沒有 cascade、簽核或引用檢查；舊 Oracle 物件亦無 FK。配件分類狀態定義會使用此表的狀態編號，API 不應未經確認而 cascade 刪除子資料。為保護既有關聯，Production DELETE 建議在被 TBLEQPACCCATEGORYSTATEBASIS 引用時回傳 409；此檢查是 YMES 的完整性保護，不是舊 WinForms 行為。

## Oracle 資料表結構

公司端已用 PowerShell 5.1 + ODP.NET 唯讀呼叫 DBMS_METADATA.GET_DDL 取得原始 DDL，無需再次查詢或新增重複表：

- Oracle 原始 DDL：database/reference/mestest_accessory_state_source_ddl.sql
- PostgreSQL 空表 CREATE SQL：database/reference/mestest_accessory_state_create.sql
- database/reference/mestest_first_phase_create_tables.sql 已含本表 block。

| 欄位 | Oracle 型別 | NULL/default |
| --- | --- | --- |
| ACCESSORYSTATE | NUMBER(2,0) | NOT NULL |
| STATETYPE | NUMBER(2,0) | DEFAULT 1、NOT NULL |
| STATENAME | VARCHAR2(50) | NOT NULL |
| STATECOLOR | NUMBER(11,0) | NOT NULL |
| DESCRIPTION | VARCHAR2(255) | NULL |
| DATASTAMP | NUMBER(11,0) | DEFAULT 0，可 NULL |
| CREATOR | VARCHAR2(10) | NULL |
| CREATEDATE | DATE | NULL |
| REVISER | VARCHAR2(10) | NULL |
| REVISEDATE | DATE | NULL |

主鍵為 ACCESSORYSTATE；只有 PK 唯一索引，沒有 Oracle FK 或額外索引。UI 新增預設 StateType=0，與資料表 default 1 不同，API 應遵循明確傳入的 UI 值。

## Vue Development 頁與 API 契約

- Vue 元件：web/src/components/AccessoryStateBasisMaster.vue
- 開發假資料儲存於 ymes-dev-mock:accessory-state-basis:ep205:v1，僅在 Development Preview 使用。
- Production API 未部署前不回退 localStorage；404 顯示 API 尚未建立。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | /api/equipment/accessory-states | 讀取全狀態及稽核欄位；EP204 也用它作狀態選項 |
| POST | /api/equipment/accessory-states | 新增或複製 |
| PUT | /api/equipment/accessory-states/{accessoryState} | 修改並驗證 DataStamp |
| DELETE | /api/equipment/accessory-states/{accessoryState} | 刪除單筆；被分類狀態定義引用時建議回 409 |

GET 項目採 camelCase，至少回傳 accessoryState、stateType、stateName、stateColor、description、dataStamp、creator、createDate、reviser、reviseDate。stateColor 保留資料庫中的 signed ARGB integer，EP204 的 lookup DTO 至少包含 accessoryState、stateName、stateColor。

新增/修改 Request 欄位為 accessoryState、stateType、stateName、stateColor、description；修改另含 dataStamp。Creator/Reviser 及時間必須由登入身分與伺服器時鐘寫入，不能信任用戶端欄位。並行修改依 DataStamp 回 409。

## 家用端接手

1. Pull 本規格後，先比對 YMES PostgreSQL 的 tbleqpaccstatebasis 欄位、型別、NULL/default、PK、index 及既有 migration；既有表有額外欄位時保留。
2. 不要重建本表。來源 Oracle DDL 與 PostgreSQL 空表 SQL 已存在；僅在實際 YMES schema 缺表或欄位不符時新增 forward migration。
3. 為 ymes_app 配置最小必要讀寫權限。
4. 建立上述 GET/POST/PUT/DELETE API，與 EP204 共用同一狀態 lookup；DataStamp、稽核資訊、色彩 signed integer 及唯一鍵要逐欄對齊。
5. DELETE 不 cascade；若 TBLEQPACCCATEGORYSTATEBASIS 引用該狀態，回 409，避免舊表無 FK 時留下孤兒狀態定義。舊 WinForms 直接刪除的差異記在 API 文件。
6. 回寫 migration/API 部署結果至本規格和 todolist_homepc.md，再通知公司端 pull 對接 Production。
