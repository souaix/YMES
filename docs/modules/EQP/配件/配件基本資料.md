## 清單與查詢

- 初始選擇「未簽核」；狀態為 0 未簽核、1 簽核中、2 已簽核、-1 不使用。
- WinForms 載入時傳 IssueState、CurVersion 的不限值及基礎查詢條件；再由前端狀態篩選，依 AccessoryType、AccessoryNo 排序。查詢欄位只有 AccessoryNo。
- Grid 隱藏欄位只有 IssueState、CurVersion、AccessoryVersion、DataStamp。其他 TBLEQPACCESSORYBASIS 欄位均出現在可橫向捲動的 Grid，包括 24 個 XX_PARA 欄位、三個檔案路徑欄及維護/群組欄。
- 新增、修改、複製、刪除、核准、屬性、匯入、關閉均有按鈕。版本按鈕在原 Form 中隱藏，Web 不顯示。
- 可使用作用列或多選列。修改只接受 IssueState=0；核准只接受 0；刪除接受 0/-1/2，遇到 1 拒絕。無多選時，按鈕依作用列處理。

## 新增、修改與複製

- 新增/複製建立一筆新主檔，版本預設 01。修改鎖定 AccessoryNo 和版本；配件編號、版本、配件類別、供應商必填。
- AccessoryType 由已核准的配件類別 lookup 選取，選取後帶入該類別的 AccessoryCategory；供應商由已核准供應商 lookup 選取。ModelNo、AssetNo、Description 可空。
- Oracle 欄位長度：AccessoryNo/AccessoryType/VendorNo/AccessoryCategory/ERPNo 50；AccessoryVersion 3；ModelNo/AssetNo 50；Description 255。AccessoryNo 與版本在舊表單送出時轉大寫；其他欄位不強制大寫。
- 新增狀態為 0；修改帶 IssueState 與 DataStamp。API 使用登入者作為 Creator/Reviser，伺服器產生日期並用 DataStamp 做並行檢查。
- 複製先新增目標資料，再呼叫 CopyAccessory；來源已簽核的配件屬性才複製到目標版本，目標屬性重設為 IssueState=0。舊程式可能忽略屬性複製錯誤；新 API 應在同一交易內處理並回報失敗。
- 標準廠別要求 VendorNo；舊表單對特殊 Enterprise SP 的 Confirm 有 N/A 回退，但 Apply 驗證仍要求供應商。DEV 預覽採必填，Production 規則應按既有廠別設定落實。

## 刪除與核准

- 刪除 0/-1：舊服務先刪配件目前狀態/設備目前配件狀態，再刪配件屬性及主檔；來源刪屬性依 AccessoryNo 涵蓋所有版本。需以 API transaction 保持多表一致。
- 刪除 2：不做物理刪除，更新 IssueState=-1 並更新 DataStamp、Reviser、ReviseDate。狀態 1 不允許刪除。
- 核准只接受狀態 0。舊 ApproveAccessoryBasis 依配件類別的初始狀態設定，必要時 fallback 到 TBLEQPACCSTATECONTROL 的 Initial/EMS 控制；亦會讀取 TBLEQPACCESSORYLIFE 的 RepairCycle，維護配件目前狀態與狀態歷程。若簽核 Job/Detail 有設定，會走舊簽核流程，可能先進入簽核中，不能假設呼叫後立即為 2。
- 必要來源表：TBLEQPACCCATEGORYSTATEBASIS、TBLEQPACCSTATEBASIS、TBLEQPACCESSORYLIFE、TBLEQPACCESSORYPROPERTY、TBLEQPACCSTATECONTROL、TBLEMSACCESSORYSTATE、TBLEMSACCESSORYSTATELOG、TBLEMSEQPACCSTATE、TBLEMSEQPACCSTATELOG。前三張 EP201/EP202 已交付；本次 Oracle 新查主表及後五張狀態/設備關聯表。Oracle DDL 未宣告外鍵。

## 配件屬性子視窗

- 以 AccessoryNo + AccessoryVersion 載入 TBLEQPACCESSORYPROPERTY，並 join TBLSYSELEMENTBASIS 取得 ElementName。Grid 顯示 PropertyNo、ElementName、DefaultValue、Description、Creator/CreateDate、Reviser/ReviseDate；隱藏版本/IssueState/DataStamp 等控制欄位。
- 新增、修改、複製、刪除、核准。修改與核准只接受 IssueState=0；刪除 0/-1/2 物理刪除，狀態 1 拒絕。Property PK 為 (ACCESSORY, PROPERTYNO, ACCESSORYVERSION)。
- PropertyNo 由 LoadACCPropertyDefine(PropertyType=1) 選取；欄位順序 0–99，DefaultValue 可用元素值選擇器，另有 Description。API 需提供 accessory-properties/definitions?propertyType=1、元素名稱及元素值選項。
- TBLEQPACCESSORYPROPERTY 的來源 DDL/CREATE SQL 已在 EP202 配件類別依賴檔；TBLSYSELEMENTBASIS 為共用系統表，先查 YMES 現有結構，不在此新增替代表。

## 匯入

- WinForms 讀取 Excel 第一工作表，略過第 0 列標題，欄位依固定位置：AccessoryNo、AccessoryType、AccessoryCategory、VendorNo、ModelNo、AssetNo、Description。前四項必填；其餘可空。
- 舊 DataChecker 依 (AccessoryNo, AccessoryType) 分組且每組只接受一筆，檢查編號未存在、配件類別已核准、分類隸屬核准的配件類別、供應商已核准；成功插入版本 01、IssueState=0。範本取系統 FunctionNo ACC BASIS。
- 原始 Reader 迴圈可能有略過最後一實體資料列的 off-by-one；API 不應複製此缺陷，需用明確列數及逐筆結果回報。
- 公司端 DEV 假資料可預覽 CSV；Production UI 透過 API 預覽 .xls/.xlsx，再確認匯入。此為前端明確簡化，正式 API 必須實作 Excel 第一工作表及上述完整 checker。

## Oracle DDL 與 PostgreSQL CREATE SQL

- 直接使用 Windows PowerShell 5.1 + ODP.NET，從本機受保護的 Oracle 連線設定呼叫 DBMS_METADATA.GET_DDL；另以 ALL_INDEXES 取得 index 名稱並查各 index DDL。唯讀查結構，未讀 MES 業務資料。
- 原始 DDL：database/reference/mestest_accessory_basis_source_ddl.sql（六張表及八個 index DDL）。
- PostgreSQL 空表 SQL：database/reference/mestest_accessory_basis_create.sql。另已修正 mestest_first_phase_create_tables.sql 的 EP203 主表區塊，移除錯誤標記為推測的欄位註解。
- 六張表：TBLEQPACCESSORYBASIS、TBLEMSACCESSORYSTATE、TBLEMSACCESSORYSTATELOG、TBLEQPACCSTATECONTROL、TBLEMSEQPACCSTATE、TBLEMSEQPACCSTATELOG。
- 獨立非 PK index：TBLEQPACCESSORYBASIS(GETGROUPNO)、TBLEMSEQPACCSTATE(EQUIPMENTNO)；其餘六個 index 是各表 PK index。DDL 沒有 FK。
- 表格欄位、NULL、DEFAULT、PK 與索引須在家用電腦逐欄比對 YMES schema；缺表才新增 migration，既有表有差異以 forward migration 處理，不直接覆寫。

## Vue 與 API 交接

- Vue 頁面為 web/src/components/AccessoryBasisMaster.vue，路徑 /YMES/Equipment/AccessoryBasis，FunctionNo ACC BASIS。DEV 假資料獨立存 localStorage；Production 不得 fallback 到假資料。
- GET api/equipment/accessory-basis?issueState=all&currentOnly=false 回傳完整 Grid 欄位及控制欄位。另需提供已核准的配件類別與供應商 lookup。
- POST collection 新增；PUT /{accessoryNo}/{version} 修改並驗 IssueState/DataStamp；POST /approve、/delete 接受多筆 key/state/DataStamp 並回逐筆結果；POST /copy-properties 應與新增流程合併成原子交易或提供單一 Copy endpoint。
- 屬性：GET/POST /{accessoryNo}/{version}/properties、PUT/DELETE /{accessoryNo}/{version}/properties/{propertyNo}、POST .../{propertyNo}/approve；需帶 DataStamp 並回傳 ElementName/元素值。
- 匯入：POST /import/preview 接收 multipart file，解析 Excel 第一工作表、回傳 previewToken 及逐列檢核結果；POST /import/commit 接受 previewToken 並重新驗證後寫入。CSV 開發預覽若需 Production API，另提供 JSON rows 契約。範本 GET api/system/template-files?functionNo=ACC%20BASIS。
- 驗證錯誤回 400；不存在 404；重複鍵、DataStamp 衝突、狀態不允許或被關聯資料阻擋回 409。伺服器須從登入 session 取得操作者，不信任 UI 傳入的 Creator/Reviser。
- 簽核流程 API 尚待家用端實作；公司端 DEV 核准簡化為 0→2，只供檢查畫面互動，不等同舊 MES 的正式簽核。
