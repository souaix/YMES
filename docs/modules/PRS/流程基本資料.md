## 功能範圍

流程主檔的版本、類別、區段、流程類別代碼、簽核狀態與流程圖。主頁上的 Property 另開流程屬性維護；Import 開啟 Excel 流程匯入器；Exclude OP 顯示產品流程漏設作業站參數；APS Integration 按鈕舊畫面預設隱藏。

## WinForms 畫面

來源為 `STD/MESWin/PRS/PS_ProcessBasis/frmProcessBasis.vb` 和 Designer。主 Form ClientSize 為 1008×591。主資料 Grid 約 874×352，右側按鈕區 97×365，流程圖摘要 AddFlow 約 874×139；按鈕區可以垂直捲動。

- 狀態選項：Unfrozen `0`、Pending `1`、Active `2`、Unused `-1`；初始選 Unfrozen。
- 查詢欄位為 ProcessNo。載入時先要求所有 IssueState/CurVersion，再依狀態切換篩選；AdditionalXml 固定只取 ProcessClass `0,2,3`，不顯示 Engineering `1`。
- Grid 可見欄位順序：ProcessNo、ProcessVersion、CurVersionShow、ProcessClass、ProcessType、PSNo、Description、Creator、CreateDate、Reviser、ReviseDate。日期格式 `yyyy/MM/dd HH:mm:ss`。IssueState、ProcessClassShow、CurVersion、NodeXmlString、TuningProcess、DataStamp 為隱藏欄位；PARTIALTYPE 存在 DataSet 但舊畫面隱藏。
- 選取資料列會在同一 Form 下方預覽流程圖；不是導頁或重載頁面。
- APS Integration 在 Form 初始化為 `Visible=False`，只有系統參數允許時才顯示。

## 主檔欄位與驗證

| 欄位 | 必填 | 上限/來源 | 規則 |
| --- | --- | --- | --- |
| ProcessNo | 是 | Oracle `VARCHAR2(30)` | 新增/複製必填；不可含 `&`、`<`、`>`、逗號；複合鍵不可重複。編輯/換版不可更改。 |
| ProcessVersion | 是 | Oracle `VARCHAR2(3)` | 新增預設 `01`；編輯唯讀。Version 動作只接受兩位數字版本並加 1，非兩位數數字會留空要求補正。 |
| ProcessClass | 是 | `0/1/2/3` | ValueList 提供語系名稱；Rework `2` 只在 SP/HUGA/AUO 顯示；主 Grid 只查 `0,2,3`。 |
| PSNo | 是 | Oracle `VARCHAR2(50)` | 從已核准生產區段選取；編輯和換版不可改。 |
| ProcessType | 是 | Oracle `VARCHAR2(20)` | 從已核准流程類別選取；編輯和換版不可改。 |
| Description | 否 | Oracle `VARCHAR2(255)` | 可空。 |

Def Form 尺寸 506×388，按鈕為 Confirm、Apply、Close。Apply 寫入後保持表單開啟；Add/Copy 可接續新增。Creator/CreateDate/Reviser/ReviseDate 由登入使用者及伺服器時間產生。DataStamp 在 Edit、Delete、Approve 使用。

## 主頁按鈕與狀態

| 按鈕 | 規則與結果 |
| --- | --- |
| ADD | 開啟 Def mode 0；Version 預設 `01`，狀態為 0。 |
| EDIT | 只允許 IssueState=0；ProcessNo/Version 唯讀，PSNo/ProcessType 不可改。 |
| COPY | 複製主檔、流程圖節點/連線、屬性與 APS 資料；新主鍵由使用者輸入，新建狀態 0。Core 會重新指派流程圖 NodeID。 |
| DELETE | 多選逐筆處理。狀態 0/-1 硬刪主檔與子資料；狀態 2 改成 -1 並保留歷史；狀態 1 禁止。子資料包含 NodeBasis、NodeRelation、NodeXml_CLOB、ProcessProperty、OP APS base/detail。來源沒有 FK，API 必須在 transaction 內明確維護引用。 |
| APPROVE | 只允許狀態 0，核准前必須有非空流程圖，另檢查已引用產品的流程作業站缺少產品 OP 設定。沒有 Issue Job/Detail 時可直接變 Active；有流程時透過共用 IssueManagement，以 IssueNo=`PRS BASIS` 建立 Pending/簽核/通知，不得由 API 自行跳過。 |
| PROPERTY | 開啟 `PS_ProcessProperty`。該功能有獨立四狀態、多選、Add/Edit/Copy/Delete/Approve；修改僅狀態 0，刪除狀態 0/-1 實體刪除、2 標示 -1、1 禁止。資料來自 TBLSYSELEMENTBASIS 中已核准、ElementType 0 或 4 的 Element；MES Parameter 值可由 `wsSYS.LoadElementValue` 載入。 |
| VERSION | 只允許 IssueState=2 且 CurVersion=1；新版本維持原 ProcessNo/PSNo/ProcessType，新增一筆狀態 0 的版本，複製流程圖、屬性及相關資料；舊版本 Current flag 清除。 |
| EXCLUDE OP | 顯示使用此流程但缺產品 OP 設定的節點。資料類型 1=產品、0=產品類別、2=模組。狀態 0/1 對產品流程版本 `*` 過濾；Unused 或已核准非目前版按明確版本過濾。 |
| DRAW | 只允許狀態 0。打開流程圖 Form，成功後重載主檔並定位該列。 |
| IMPORT | 呼叫 `PS_ProcessDataImport`，獨立逐流程顯示結果與進度，可取消。接受單一 xls/xlsx，支援下載系統範本；匯入完成後重載主 Grid。 |
| APS Integration | 預設隱藏。若啟用，使用 APS base/detail 資料與獨立整合視窗。 |

## 流程圖行為

`frmProcessDraw` 允許開始/結束、作業站、巢狀流程、模組、AND/OR 群組節點；連線支援一般及四種水平/垂直折線路徑，提供縮放 100/150/75/50%、新增/移除節點連線、群組/解散、排列、移動、節點屬性與語系顯示。節點模型包含 NodeNo、NodeType、GroupNo、StageNo、Sequence、NodeVersion、Description 及 SAP/客製欄位。

舊畫面用外部 `iMESXMLFlow.dll` 的 `FlowToXML`/`XMLToFlow` 序列化。資料同時落在 NodeBasis、NodeRelation、NodeXml_CLOB 或 ProcessBasis.NodeXmlString；LONG 不可用時走 CLOB 表。外部 serializer 原始碼不在來源樹，Vue 產生的 JSON/結構化節點**不是**舊 XML 相容格式。公司端 Vue 僅允許 DEV 編輯，Production 未取得相容 serializer 前不可儲存流程圖。

## Excel 匯入器

WinForms Form `frmProcessDataImport` ClientSize 784×562。選取單一 `.xlsx` 或 `.xls`，只讀第一個工作表；欄位為 ProcessType、ProcessNo、ProcessVersion、Segment、Desc、Sequence、FromOP、ToOP。空白列/必填儲存格檢查由 NPOI 前端處理；每組 ProcessNo/Version 顯示一列結果，再把該流程所有 Excel 列 JSON 傳至外部 `DataImporter.DataImport.ProcessDataChecker`，平行逐流程執行並顯示進度/結果，可取消。模板透過 `wsSYS.funLoadFileExtension`、`GetTemplateFile` 下載，上傳更新入口舊畫面預設隱藏。

舊碼註解列出的後端檢核包括：模板欄位順序、線性流程、作業站已核准且同一區段、流程類別存在、ProcessNo/Version 不可重複。`ProcessDataChecker` 實作位於外部 DLL，未找到其原始碼；家用端需確認實際可取得的 DLL/規則後再完成 API。Vue DEV 頁有選檔/結果區，刻意不宣稱能解析或匯入 Excel。

## Oracle 資料表與結構證據

以 Windows PowerShell 5.1 + Oracle.ManagedDataAccess，使用本機受保護既有連線唯讀查 MESTEST 的 `DBMS_METADATA.GET_DDL`、`ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_INDEXES`。沒有查業務列，沒有在 Oracle 執行 DDL/DML，連線秘密未輸出。原始 DDL 與 PostgreSQL CREATE-only 對照：

- [`mestest_prs104_process_basis_source_ddl.sql`](../../../database/reference/mestest_prs104_process_basis_source_ddl.sql)
- [`mestest_prs104_process_basis_create.sql`](../../../database/reference/mestest_prs104_process_basis_create.sql)

| Oracle 表 | 主鍵 | 直接用途 |
| --- | --- | --- |
| TBLPRSPROCESSBASIS | (PROCESSNO, PROCESSVERSION) | 流程主檔、狀態、版本與舊 XML |
| TBLPRSNODEBASIS | (NODEID) | 流程節點 |
| TBLPRSNODERELATION | (FROMNODEID, TONODEID, LINKNAME) | 節點連線 |
| TBLPRSNODEXML_CLOB | (PROCESSNO, PROCESSVERSION) | 大型流程圖 XML 備援 |
| TBLPRSPROCESSPROPERTY | (PROCESSNO, PROCESSVERSION, PROPERTYNO) | 流程屬性 |
| TBLPRSOPAPSBASE | (NODEID) | APS 作業站設定 |
| TBLPRSOPAPSDETAIL | (NODEID, EQUIPMENTNO) | APS 設備明細 |
| TBLPRSPRODUCTIONSEGMENT | (PSNO) | 生產區段/PS lookup |
| TBLPRSTYPE | (PROCESSTYPE) | 流程類別 lookup |

來源九表均只有 PK unique index，沒有 FK 或其他索引。Oracle `VARCHAR2(n CHAR)` 的 DDL 已以字元數對照 PostgreSQL varchar(n)；`ALL_TAB_COLUMNS.DATA_LENGTH` 顯示的是位元組數（例如 4 CHAR 可顯示 16 bytes），不能誤當成欄位字元上限。

家用端 first-phase CREATE 參考目前已有前三表定義，但 `CREATE TABLE IF NOT EXISTS` 不會改既有表。Oracle 來源還要求以下預設值；部署前先查 YMES live schema/migrations，僅缺的欄位預設值建立 forward migration：

- TBLPRSPROCESSBASIS：IssueState、TuningProcess、CurVersion、PartialType、DataStamp 預設 0（其中 TuningProcess/PartialType/DataStamp 仍可 NULL）。
- TBLPRSNODEBASIS：NodeType 預設 0；NodeVersion 預設 `'N/A'`。
- TBLPRSOPAPSDETAIL：ApsFixEqpTime、ApsVarEqpTime、BatchOP 預設 0；BatchMaxQty 預設 999999。

**不能重建既有前三表。** 新增 PS104 專屬的 NodeRelation、NodeXml_CLOB、ProcessProperty、OPAPSBASE、ProductionSegment 五表前，先比對 YMES live schema；`TBLPRSTYPE` 由 PS103 建立、供本功能 lookup 重用。PostgreSQL CREATE 檔僅供結構對照，不是可以直接部署的 migration。

## YMES API 契約（家用端待建）

Vue 預期相對 API base `/YMES/API`：

| Method / 路徑 | 用途 |
| --- | --- |
| GET `/api/process-basis?issueState=&processNo=` | 查詢清單與可見 Grid 欄位，保留 hidden IssueState/CurVersion/DataStamp |
| POST `/api/process-basis` | 新增未核准主檔 |
| PUT `/api/process-basis/{processNo}/{processVersion}` | 編輯狀態 0 主檔；以 DataStamp CAS，衝突回 409 |
| DELETE `/api/process-basis/{processNo}/{processVersion}` | 狀態 0/-1 硬刪及子表交易清理；狀態 2 CAS 改 -1；狀態 1 禁止 |
| POST `/api/process-basis/{processNo}/{processVersion}/approve` | 流程圖與產品 OP 完整度檢查，再呼叫共用 IssueManagement `PRS BASIS` |
| POST `/api/process-basis/copy` | 新增/複製/換版；以交易複製所有必要子表、重配 NodeID/Relation |
| GET `/api/process-basis/{processNo}/{version}/properties` | 讀流程屬性與狀態 |
| POST/PUT/DELETE `/api/process-basis/{processNo}/{version}/properties/...` | 流程屬性 CRUD、DataStamp 和 Issue Job |
| GET `/api/process-basis/{processNo}/{version}/exclude-operations` | 產品/產品類別/模組的缺漏 OP 診斷 |
| GET `/api/process-basis/lookups/production-segments?issueState=2` | 已核准 PS lookup |
| GET `/api/process-basis/lookups/process-types?issueState=2` | 已核准流程類別 lookup |
| POST `/api/process-basis/import` | xls/xlsx 範本/檢核/逐流程匯入工作與結果 |

API audit 欄位只能使用登入 principal/server 時間；不能信任前端傳入的 Creator、Reviser、IssueState 或 DataStamp。主/子表及版本複製、刪除須使用資料庫交易。狀態核准不可由 UI 假造。
