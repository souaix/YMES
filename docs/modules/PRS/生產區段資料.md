## 主清單畫面與操作

- 主表單 ClientSize `1008×591`，標題 `Production Segment`，進入時取全部狀態資料，預選 Unfrozen（0）。共用 `frmBasisTemplat` 提供狀態 Radio、查詢條件和資料筆數。
- 搜尋欄位是 `PSNo`；按 Query 重新呼叫 `LoadProductionSegment`，狀態 Radio 在已載入 Dataset 上切換篩選。
- Grid 位置 `(12,53)`、大小 `890×526`，停用 GroupByBox。顯示欄位順序：`PSNo`（110）、`PSName`（190）、`PSOrder`（90、靠右）、`HaveComponent`（100、0/No、1/Yes）、`HaveLevel`（100、0/No、1/Yes）、`Description`（300、多行）、`SerialTypeNo_Lot`（150）、`Creator`（80）、`CreateDate`（150、`yyyy/MM/dd HH:mm:ss`）、`Reviser`（80）、`ReviseDate`（150、同格式）。`IssueState`、`SerialTypeNo_Comp`、`IsPartial`、`IsNetFlow`、`DataStamp` 隱藏。
- 右側按鈕依序 ADD、EDIT、DEL、Copy、Approve；Close 在右下。Find、Print 的 Designer 設為隱藏。
- 多選刪除與核准是按列逐筆呼叫；遇第一個錯誤即停止，之前成功的列不回滾。Vue/Production API 應回報逐筆結果，不可偽稱一整批原子交易。
- 主表呼叫 `LoadProductionSegment` 時未設定 `PSPrivilege=True`，所以這個視窗不會套 `LoadProductionSegmentbyUser` 的區段清單限制；仍受 FunctionNo/使用者介面權限控制。其他呼叫端若啟用 PSPrivilege，區段權限需由受信任的服務端身份計算，不能接受任意用戶提交的布林值。

## 定義視窗與欄位

- ClientSize `1008×591`、固定視窗、不可最大化，置中。主要 GroupBox `Production Segment Data` 位於 `(12,12)`，大小 `984×454`；下方為共用建立/修改資訊與 Confirm、Close、Apply。
- 欄位：`PS. No`（黃色、最多 50、離開欄位轉大寫）、`PS. Name`（黃色、最多 50）、`PS. Order`（數值 1–99、初值 1）、`Have Component`（No/Yes）、`Have Level`（No/Yes）、`Description`（多行，最多 255）。PSNo、PSName 必填；兩個旗標不得同時為 Yes。
- `Serial Rule Config` 區塊顯示唯讀 `SerialTypeNo_Lot` 和 `...` 選擇按鈕。按鈕呼叫 `wsSYS.LoadSerialRuleBasis`，只傳 `SerialType="LOTNO"`，沒有指定 Enable，故舊 UI 會列出該類型的停用和啟用規則；選擇器只顯示序號規則編號。取消選擇會清空 Lot 序號類型。
- `SerialTypeNo_Comp` 的欄位、標籤與選擇按鈕在 Designer 都是 Hidden；既有值雖不顯示，Edit/Copy 載入後仍保留並傳回。一般畫面編輯不可意外清空此值。
- `IsPartial`、`IsNetFlow` 沒有使用中的表單欄位；新增沿用 Oracle 預設，Edit 不應改寫。`IsNetFlow` 是可為 NULL 的舊欄位。
- WAHHONG 客戶客製：`Have Component` 與 `Have Level` 強制 No 並停用選項。服務可從已驗證的登入設定提供企業代碼；不可讓使用者透過一般表單自行切換此客製設定。
- Add/Copy 建立人與日期由登入者/伺服器時間寫入。Edit 的 PSNo 唯讀，只更新其他可編輯欄位並記錄 Reviser/ReviseDate。
- WinForms 來源行為：Confirm 成功後關閉；Apply 成功後保持視窗開啟並清除 dirty 狀態。Add/Copy Apply 後仍是新增模式；若再次提交相同 PSNo，會回報重複鍵。YMES 已調整為 Apply 成功後接續修改該筆，詳見下方家用端實作。
- Copy 預填來源的 PSNo、PSName、排序、說明、Component/Level、Lot 序號及隱藏的 Component 序號，當作新資料新增。`IsPartial`、`IsNetFlow` 不由 UI 複製，留給 DB 預設。

## 欄位與狀態規則

| 欄位/狀態 | 規則 |
| --- | --- |
| `PSNO` | `VARCHAR2(50) NOT NULL` PK；表單輸入轉大寫。新 API 也應正規化大寫、驗證長度與唯一鍵。 |
| `PSNAME` | `VARCHAR2(50) NOT NULL`；Add/Edit 必填。 |
| `PSORDER` | `NUMBER(2,0) DEFAULT 0 NOT NULL`；舊服務驗證 1–99，UI 初值 1。 |
| `HAVE COMPONENT` / `HAVE LEVEL` | 各為 `NUMBER(1,0) DEFAULT 0 NOT NULL`，值只能 0/1；不允許同時為 1。 |
| `DESCRIPTION` | `VARCHAR2(255) NULL`。 |
| Lot/Component 序號類別 | 各為 `VARCHAR2(50) NULL`；Lot 由 `TBLSYSSERIALRULEBASIS` 的 `SerialType=LOTNO` 選取；Component 欄位隱藏但舊值要保留。 |
| `ISPARTIAL` | `NUMBER(1,0) DEFAULT 0 NOT NULL`，主畫面/定義視窗未使用。 |
| `ISNETFLOW` | `NUMBER(1,0) DEFAULT 0 NULL`，網狀流程功能已下架，欄位隱藏。 |
| `DATASTAMP` | `NUMBER(11,0) DEFAULT 0 NULL`；Edit、停用、核准使用 compare-and-swap。Oracle 原服務用 `PSNO + DataStamp` 比對後遞增。新 API 要支援 NULL-safe CAS，衝突回 409。 |
| `ISSUESTATE` | 0 未核准、1 簽核中、2 已核准、-1 不使用。Edit 僅允許 0。 |

### 刪除

- 狀態 0 或 -1：實體刪除 `TBLPRSPRODUCTIONSEGMENT`。
- 狀態 2：不實體刪除；DataStamp CAS 更新為 -1，並更新 Reviser/ReviseDate。
- 狀態 1：拒絕刪除。
- 舊 `clsProcess.DelProductionSegment` 只刪這張主表，沒有在同一方法清除其他表，也沒有依賴資料清理。Oracle DDL 沒有 FK；新 API 不可自行推論 cascade。若要新增使用中區段檢查，須先從 WinForms/Core 找到依據並另行記規格。

### 核准

- 只允許狀態 0，IssueNo=`PS BASIS`。
- `GetIssueJobMap("PS BASIS")` 找不到 Job，或 Job 沒有 Detail：直接將 IssueState 0→2。
- 有簽核明細：建立 IssueMaster/Issue Process，寫入核准後 2、退回後 0 的 callback SQL；主檔先轉 1，更新 Reviser/ReviseDate/DataStamp，寄送第一關通知。API 必須重用共用 IssueManagement，不能直接略過已設定的工作流程。
- 舊 WinForms 多選核准逐筆呼叫；只接受 0，其餘狀態停止後續處理。

## YMES API 契約（家用端已實作，正式操作驗證待完成）

前端相對 API base `/YMES/API`：

| Method / 路徑 | 用途 |
| --- | --- |
| GET `/api/production-segments?psNo=` | 依 PSNo 大小寫不敏感的包含條件查全部狀態，依 PSNo 排序；回傳 `{ items: [...] }`，含主清單、隱藏欄位、IssueState、nullable DataStamp 與 audit。狀態 Radio 由前端篩選。 |
| POST `/api/production-segments` | 新增；登入 principal/server 設 Creator/CreateDate、IssueState=0，DB 預設 IsPartial/IsNetFlow/DataStamp。 |
| PUT `/api/production-segments/{psNo}` | JSON body 是新增欄位加必須明確提供的 `dataStamp`（可為 null）；PSNo 不可改，僅狀態 0 可寫。更新 Name、Order、Description、旗標與 Lot serial，隱藏的 Component serial 保留資料庫原值。精確 CAS 衝突回 409。 |
| DELETE `/api/production-segments/{psNo}` | JSON body `{ "dataStamp": 版本或null }`；服務端重新讀取目前 IssueState，再按 0/-1 硬刪、2 CAS 軟刪到 -1、1 拒絕。每列獨立交易，不清除其他表。 |
| POST `/api/production-segments/{psNo}/approve` | JSON body `{ "dataStamp": 版本或null }`；只接受狀態 0。沒有已知 Issue/Job 表時直接轉 2；只要偵測到流程表就回 503、資料不變，待接入共用簽核服務。 |
| GET `/api/system/serial-rule-basis?serialType=LOTNO` | 共用 SYS 路由重用 `"YMES".tblsysserialrulebasis`，依 WinForms 不加 Enable 篩選；回傳 `{ items: [{ serialTypeNo, description, enable }] }`，包含 Enable 0/1，不另建 lookup table。 |

所有端點使用 `[Authorize]` 要求登入，SQL 參數化；Creator、Reviser、時間及目前 IssueState 由服務端控制。FunctionNo=`PS BASIS`、FunctionKey=`PS101` 保留為功能識別；依使用者「帳號權限角色先不管」的決策，本輪未加入 FunctionKey ACL。列表不使用 PSPrivilege 過濾；未來若其他 API 要套區段權限，須由伺服器身份及群組權限求值。企業 WAHHONG 規則由服務端設定 `YMES_ENTERPRISE_NO=WAHHONG` 強制兩旗標為 0，普通表單不能切換此設定。

新增、修改、刪除、核准均回傳真實單筆 DTO。DataStamp 的 JSON 欄位以 `[JsonRequired]` 區分「省略」與「明確 null」：省略回 400；明確 null 只匹配資料庫 NULL，不等同版本 0。資料不存在回 404，版本／狀態衝突回 409，缺表或資料庫無法操作回 503，錯誤用 ProblemDetails 的中文 detail 呈現。

## 家用端實作與維護（2026-11-18）

- API 程式為 `src/YMes.Api/Processes/Ps101Controller.cs`、`Ps101Models.cs`、`Ps101Repository.cs`；主表固定為 `"YMES".tblprsproductionsegment`。`database/migrations/0030_ps101_production_segment.sql` 依公司端 CREATE 參考建立缺表，保留 PK、nullable/default，不加未核實的 FK、cascade 或額外 index，並列入主表 CRUD 與 SYS 序號表 SELECT 授權。遠端備份、migration 套用與部署狀態由家用端主流程另外核對記錄；此節不宣稱已完成正式驗收。
- 寫入使用交易及主檔 `FOR UPDATE` 列鎖，CAS SQL 使用 `datastamp IS NOT DISTINCT FROM @stamp`，成功異動後才遞增版本。來源 NULL 不先改成 0；稽核人員來自登入 principal、時間來自 server，請求不能指定 audit 或核准結果。
- 服務端驗證 PSNo 大寫／最多 50、PSName 必填／最多 50、PSOrder 為 1–99 整數、兩旗標只能 0/1 且不得同時為 1、多行 Description 最多 255。非空 Lot serial 必須仍存在於 LOTNO 規則，保存時以 `FOR KEY SHARE` 重查；Enable 0 的來源規則仍可選。Update 一律保留 Component serial；Copy 可沿用來源隱藏值作新增，IsPartial/IsNetFlow 使用 DB 預設。
- Vue `ProductionSegmentMaster.vue` 使用共用 `ActionConfirmationDialog`，不再使用 native confirm；定義與 LOTNO 選擇器保留可存取的 dialog role。切換狀態清除選取，修改及多選操作只取目前可見列，避免操作上一狀態的隱藏列。
- YMES 的 Add/Copy Apply 成功後切為 Edit，保存伺服器回傳／重載的主鍵、nullable DataStamp 與 audit，後續保存更新同一列。成功新增會切回未簽核並清查詢，以選取新筆；audit 不以目前時間覆蓋既有建立／修改時間。
- 多選刪除／核准逐筆請求；若前面成功、後面失敗，先前交易不回滾。Vue 會重新載入已變更的清單，並保留原錯誤／成功訊息。此行為不是全批交易。
- 共用 Issue/Job、簽核中、通知、退回 callback 尚未整合；偵測到已知流程表即拒絕直接核准。正式頁使用 PostgreSQL API，Fake 僅於 DEV 且明確開啟 developmentPreview 時使用獨立 localStorage。
- 本輪程式已交由家用端主流程進行合併與建置；本節尚未填入 PS101 正式 app-browser 操作、nullable CAS、批次部分成功或遠端資料清理的通過紀錄，須以實際驗證結果補登。
