## WinForms 畫面與操作

### 主清單 `frmProcessType`

- Form ClientSize 1008×591，預設最大化；主 UltraGrid 位於 (12,53)，900×532；右側操作鈕從 x=920 起，每顆 80×32。
- Grid 單一資料列樣式，停用 GroupByBox。顯示欄位及順序：`ProcessType`（寬 100）、`Description`（寬 200、多行）、`Creator`（80）、`CreateDate`（150、`yyyy/MM/dd HH:mm:ss`）、`Reviser`（80）、`ReviseDate`（150、同格式）。`IssueState`、`DataStamp` 隱藏。
- 主視窗由共用 `frmBasisTemplat` 提供狀態選擇、查詢及底部建立/修改資訊。查詢欄位設定為 `PROCESSTYPE`；啟動畫面選 `Unfrozen`（0）。狀態值：0 Unfrozen、1 Pending、2 Active、-1 Unused。
- 可見按鈕：ADD (A)、EDIT (E)、DEL (D)、Copy (C)、Approve (Y)、Property (S)、Close (X)。Find 和 Print 在 Designer 設為隱藏，不需在主功能頁顯示。
- 點選列會把該列設為 ActiveRow；多選按鈕按流程類別逐筆執行，失敗時舊程式可能已完成前幾列，API/UI 應回報每筆結果，不宣稱批次原子性。

### 定義視窗 `frmProcessTypeDef`

- ClientSize 496×276，標題 `Process Type Define (ADD/EDIT/Copy)`。`Process Type Data` GroupBox 472×136，位置 (12,8)。欄位為 `Process Type` TextBox（黃色底、資料庫上限 20）與 `Description` RichTextBox（255 字元）。繼承基礎表單下方建立/修改人與日期區及 Confirm、Close、Apply 按鈕。
- Add/Copy：Process Type 可編輯；Edit：Process Type 唯讀，只改 Description。新增/複製 Creator 使用登入使用者，CreateDate 使用伺服器時間；Edit 顯示原建立資訊並更新 Reviser/ReviseDate。
- Process Type 離開欄位時轉大寫。Confirm 寫入成功後關閉；Apply 寫入成功後保留視窗，Edit 更新本地 DataStamp 並將焦點移到 Description，Add/Copy 將焦點移回 Process Type。
- 必填只有 Process Type。資料庫限制 `ProcessType` 20、`Description` 255；API 必須驗證長度、PK 唯一，並做大小寫不敏感的跨表檢查：ProcessType 不得與 `TBLPRSPROCESSBASIS.PROCESSNO` 相同。此檢查由舊 `clsProcess.AddProcessType` 明確執行。
- Copy 只帶入 Process Type/Description 做為新增。舊程式呼叫 `AddProcessType`；不複製 `TBLPRSProcessProperty` 子資料。

## 狀態、刪除、核准與並行控制

| 操作 | 舊行為與 API 必須遵守的規則 |
| --- | --- |
| 查詢 | `LoadProcessType` 可查全部狀態；WinForms 先取資料，再用狀態 Radio 篩選。ProcessType 查詢條件沿用共用查詢條件。 |
| 修改 | 僅 IssueState=0。修改 Description，更新 Reviser/ReviseDate，依 PK 與 DataStamp 比對後遞增 DataStamp。DataStamp 欄位允許 NULL，API 採 null-safe compare-and-swap，零筆更新回 409。 |
| 刪除 0/-1 | 實體刪除；`clsProcess.DelProcessType` 在同一資料庫命令集合先刪 `TBLPRSPROCESSPROPERTY` 中 `PROCESSNO=ProcessType` 的屬性，再刪 `TBLPRSTYPE`。YMES 必須在單一 transaction 內完成，不可假設 Oracle 有 FK/cascade。 |
| 刪除 2 | 不實體刪除；使用 DataStamp CAS 將 IssueState 改成 -1，並更新 Reviser/ReviseDate、遞增 DataStamp。 |
| 刪除 1 | 拒絕。多選也應逐筆回報簽核中項目未執行。 |
| 核准 | 只處理 IssueState=0。沿用共用 IssueManagement，IssueNo=`PRS TYPE`。沒有 Job，或 Job 沒有 Detail，直接 0→2；有簽核明細則建立 IssueMaster/Issue Process，狀態改 1、通知第一關；核准回呼改 2，退回改 0。不得由 API 直接略過簽核設定。 |

舊簽核的建立待簽狀態會更新 Reviser/ReviseDate 與 DataStamp；其核准/退回 SQL 只改狀態欄位。新 API 應保留相同 Issue Job 流程，同時讓 callback 寫入也具備可追蹤的並行控制，且所有 status 變更都必須由服務端確認目前狀態，而非信任 request body。

## Property 子功能

主表 Property 按鈕透過 `ObjectFileHandler.Execute("PS_ProcessProperty", parameters)` 啟動獨立功能，僅傳 `ProcessNo=ProcessType`，未設定 `ProcessVersionM`。該畫面本身有四狀態清單、ADD/EDIT/DEL/Approve、Property 欄位編輯；實際資料放在共用 `TBLPRSPROCESSPROPERTY`，其複合 PK 為 `(PROCESSNO, PROCESSVERSION, PROPERTYNO)`。開啟 Property 子功能時沒有指定版本，所以列表查詢不加版本條件，顯示該 ProcessNo 下各版本資料。Property 編輯畫面將空白版本序列化為 `-1`；新增必須將 `PROCESSVERSION=-1` 存入複合鍵，列表顯示仍維持空白，修改/刪除以實際鍵值 `-1` 傳回。新增/修改 DefaultValue 會呼叫 `ChkElementValueValid`；新增還會執行 `ChkPRSProcess(ProcessNo, ProcessVersion)`，Property No 必填。核准 IssueNo=`PRS PROPERTY`，採共用 Issue Job/Job Detail；刪除 0/-1 實體刪除、2 改 -1、1 拒絕。不可把 Property 複製行為暗中加到 Copy ProcessType。

Vue 的 Property 視窗是 DEV 版 shared-module 操作模型，localStorage 只保存假資料。正式資料須由共享 ProcessProperty API 和 `TBLSYSELEMENTBASIS` 核准屬性選項提供；規格參考 [PS104 流程基本資料](流程基本資料.md)。

## Oracle DDL 與 PostgreSQL 對照

Oracle 原始 DDL 由本機受保護連線使用 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 直連唯讀查 `DBMS_METADATA.GET_DDL`、`ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_INDEXES`。只讀結構 metadata，未讀業務資料、未執行 Oracle DDL/DML、未輸出連線秘密。

- Oracle source：[`mestest_prs103_process_type_source_ddl.sql`](../../../database/reference/mestest_prs103_process_type_source_ddl.sql)
- PostgreSQL CREATE-only：[`mestest_prs103_process_type_create.sql`](../../../database/reference/mestest_prs103_process_type_create.sql)

`TBLPRSTYPE` 欄位：

| 欄位 | Oracle 定義 | PostgreSQL 對照 |
| --- | --- | --- |
| PROCESS TYPE | `VARCHAR2(20) NOT NULL` | `varchar(20) NOT NULL` |
| DESCRIPTION | `VARCHAR2(255) NULL` | `varchar(255) NULL` |
| CREATOR / REVISER | `VARCHAR2(10) NULL` | `varchar(10) NULL` |
| CREATEDATE / REVISEDATE | `DATE NULL` | `timestamp without time zone NULL` |
| ISSUESTATE | `NUMBER(1,0) DEFAULT 0 NOT NULL` | `numeric(1,0) DEFAULT 0 NOT NULL` |
| DATASTAMP | `NUMBER(11,0) DEFAULT 0 NULL` | `numeric(11,0) DEFAULT 0 NULL` |

PK 是 `PROCESS TYPE` 單欄；只有 PK unique index，無 FK 或其他 index。DDL 參考是 CREATE-only，不是 migration。家用端須先查 YMES live schema/migrations，已存在即沿用；若不存在才新增 forward migration，不重建資料表、不覆寫資料。

## YMES API 契約（家用端待建）

前端相對 API base `/YMES/API`：

| Method / 路徑 | 用途 |
| --- | --- |
| GET `/api/process-types?issueState=&processType=` | 清單、狀態篩選、查詢；回傳六個顯示欄及隱藏 IssueState/DataStamp |
| POST `/api/process-types` | Add/Copy 新增未核准類別；Creator/CreateDate 取登入 principal/server |
| PUT `/api/process-types/{processType}` | 僅更新狀態 0 的 Description；DataStamp CAS，零筆更新回 409 |
| DELETE `/api/process-types/{processType}` | 由 DB 狀態分流：0/-1 交易刪除主檔與屬性，2 CAS 改 -1，1 拒絕；以逐筆結果支援多選 |
| POST `/api/process-types/{processType}/approve` | 狀態 0 核准；走共用 IssueManagement IssueNo=`PRS TYPE` |
| GET `/api/process-properties?processNo=&processVersion=&issueState=` | 共用 Property 清單；PS103 列表不傳版本以載入該 ProcessNo 下所有版本；空白版本的新增資料鍵值為 `-1` |
| POST `/api/process-properties` | 新增 ProcessProperty；Property 編輯器空白版本須以 `PROCESSVERSION=-1` 傳送；驗證 ProcessNo/版本存在及 Element Value |
| PUT `/api/process-properties` | 以 body 內的 ProcessNo/ProcessVersion/PropertyNo 為鍵更新；DataStamp CAS，空白 sentinel 以 `-1` 傳送 |
| DELETE `/api/process-properties` | 以 body 內複合鍵及狀態分流刪除；空白 sentinel 以 `-1` 傳送 |
| POST `/api/process-properties/approve` | body 帶複合鍵/DataStamp，透過 IssueManagement IssueNo=`PRS PROPERTY` |

所有 SQL 必須參數化；Creator/Reviser/日期及狀態由服務端控制。ProcessType 長度 20、Description 255；Add/Copy 須檢查 PK 與大小寫不敏感的 ProcessBasis.ProcessNo 衝突。現有 Oracle 沒有 FK，勿新增資料庫外鍵或額外索引。`TBLPRSTYPE` 同時供 PS104 的已核准 ProcessType lookup 使用。
