- ClientSize 496×276，標題 `Process Type Define (ADD/EDIT/Copy)`。`Process Type Data` GroupBox 472×136，位置 (12,8)。欄位為 `Process Type` TextBox（黃色底、資料庫上限 20）與 `Description` RichTextBox（255 字元）。繼承基礎表單下方建立/修改人與日期區及 Confirm、Close、Apply 按鈕。

- Copy 只帶入 Process Type/Description 做為新增。舊程式呼叫 `AddProcessType`；不複製 `TBLPRSProcessProperty` 子資料。

## 狀態、刪除、核准與並行控制

| 操作 | 舊行為與 API 必須遵守的規則 |
| --- | --- |
| 查詢 | `LoadProcessType` 可查全部狀態；WinForms 先取資料，再用狀態 Radio 篩選。ProcessType 查詢條件沿用共用查詢條件。 |
| 修改 | 僅 IssueState=0。修改 Description，更新 Reviser/ReviseDate，依 PK 與 DataStamp 比對後遞增 DataStamp。DataStamp 欄位允許 NULL，API 採 null-safe compare-and-swap，零筆更新回 409。 |
| 刪除 0/-1 | 實體刪除；`clsProcess.DelProcessType` 在同一資料庫命令集合先刪 `TBLPRSPROCESSPROPERTY` 中 `PROCESSNO=ProcessType` 的屬性，再刪 `TBLPRSTYPE`。YMES 必須在單一 transaction 內完成，不可假設 Oracle 有 FK/cascade。 |
| 刪除 2 | 不實體刪除；使用 DataStamp CAS 將 IssueState 改成 -1，並更新 Reviser/ReviseDate、遞增 DataStamp。 |
| 刪除 1 | 拒絕。多選也應逐筆回報簽核中項目未執行。 |
| 核准 | 只處理 IssueState=0。沿用共用 IssueManagement，IssueNo=`PRS TYPE`。沒有 Job，或 Job 沒有 Detail，直接 0→2；有簽核明細則建立 IssueMaster/Issue Process，狀態改 1、通知第一關；核准回呼改 2，退回改 0。不得由 API 直接略過簽核設定。 |

舊簽核的建立待簽狀態會更新 Reviser/ReviseDate 與 DataStamp；其核准/退回 SQL 只改狀態欄位。新 API 應保留相同 Issue Job 流程，同時讓 callback 寫入也具備可追蹤的並行控制，且所有 status 變更都必須由服務端確認目前狀態，而非信任 request body。

## Property 子功能

主表 Property 按鈕透過 `ObjectFileHandler.Execute("PS_ProcessProperty", parameters)` 啟動獨立功能，僅傳 `ProcessNo=ProcessType`，未設定 `ProcessVersionM`。該畫面本身有四狀態清單、ADD/EDIT/DEL/Approve、Property 欄位編輯；實際資料放在共用 `TBLPRSPROCESSPROPERTY`，其複合 PK 為 `(PROCESSNO, PROCESSVERSION, PROPERTYNO)`。開啟 Property 子功能時沒有指定版本，所以列表查詢不加版本條件，顯示該 ProcessNo 下各版本資料。Property 編輯畫面將空白版本序列化為 `-1`；新增必須將 `PROCESSVERSION=-1` 存入複合鍵，列表顯示仍維持空白，修改/刪除以實際鍵值 `-1` 傳回。新增/修改 DefaultValue 會呼叫 `ChkElementValueValid`；新增還會執行 `ChkPRSProcess(ProcessNo, ProcessVersion)`，Property No 必填。核准 IssueNo=`PRS PROPERTY`，採共用 Issue Job/Job Detail；刪除 0/-1 實體刪除、2 改 -1、1 拒絕。不可把 Property 複製行為暗中加到 Copy ProcessType。

Vue 的 Property 視窗是 DEV 版 shared-module 操作模型，localStorage 只保存假資料。正式資料須由共享 ProcessProperty API 和 `TBLSYSELEMENTBASIS` 核准屬性選項提供；規格參考 [PS104 流程基本資料](流程基本資料.md)。

Oracle 原始 DDL 由本機受保護連線使用 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 直連唯讀查 `DBMS_METADATA.GET_DDL`、`ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_INDEXES`。只讀結構 metadata，未讀業務資料、未執行 Oracle DDL/DML、未輸出連線秘密。

- Oracle source：[`mestest_prs103_process_type_source_ddl.sql`](../../../database/reference/mestest_prs103_process_type_source_ddl.sql)

`TBLPRSTYPE` 欄位：

| 欄位 | Oracle 定義 | PostgreSQL 對照 |
| --- | --- | --- |
| PROCESS TYPE | `VARCHAR2(20) NOT NULL` | `varchar(20) NOT NULL` |
| DESCRIPTION | `VARCHAR2(255) NULL` | `varchar(255) NULL` |
| CREATOR / REVISER | `VARCHAR2(10) NULL` | `varchar(10) NULL` |
| CREATEDATE / REVISEDATE | `DATE NULL` | `timestamp without time zone NULL` |

### ProcessNo／ProcessType 共用 namespace 與鎖順序

- 來源明確禁止與任何狀態／任何版本的 ProcessNo 重名，並非只檢查已核准流程。PS103 Create 與既有 `CreateProcess` 都先以 `PrsIdentifierGuard` 取得同一 transaction advisory lock：識別碼經資料庫 lower 後，在固定 YMES/PRS namespace 中計算鎖鍵，才進行跨表查重／主列與子表操作。兩邊都查全部狀態，大小寫不敏感，避免只單側查重留下兩表同名插入競態。
- Type Create 先檢查真實 ProcessBasis.ProcessNo；Process Create 先檢查真實 Type.ProcessType。若另一可選表實際未部署，該表沒有已儲存識別碼，namespace 查重可略過；不將「有表但缺權限」誤認不存在（存在性用 pg_catalog）。類別主檔本身仍須存在才可提供主檔 CRUD。
- 既有 `CreateProcess` 新流程建立會在相同交易及識別碼鎖後，以選擇的類別 `FOR SHARE` 重查存在性、歧義及狀態 2，並使用資料庫實際儲存鍵；缺表 503、找不到或未核准 422、歧義409。這是來源 PS104 已核准類別選擇的 server-side 重驗，不會掃描或強制修補舊流程的 NULL optional 欄位。Create 原本已要求 ProcessType；Approve／Version 的舊資料語義未於本批改寫。
- Type Update/Delete/Approve 也統一先 namespace 再類別主列鎖。Type 實體刪除與新流程選擇該類別的 `FOR SHARE` 互斥，刪除方重查引用後才處理 Property。後續 PS104／共享 Property writer 必須依相同順序協作，不可先鎖子列再回頭鎖 namespace／主列。
- 已核對 [PS104 流程基本資料](流程基本資料.md) 的來源欄位規則與 EDIT 規則：`frmProcessBasisDef` 編輯時 ProcessType 不可改，並非本輪自行新增限制。現存 `UpdateProcess` 改為同一交易先取得 ProcessNo namespace 鎖，再 `FOR UPDATE` 重讀流程／版本並驗證原狀態和 stamp；若請求 ProcessType 與真實原值不同（忽略大小寫）回 400，UPDATE 不再寫 `processtype`，大小寫相同的輸入也不會改寫儲存鍵。成功 DTO 在流程列鎖仍保留時讀取，再 commit 回傳。
- Edit 不建立新類別關係，因此不用在流程列鎖之後回頭取得類別鎖，沒有引入與 Create「namespace → 類別 → 新流程」相反的跨表鎖序。這可避免舊 Edit 與類別硬刪交錯而新增孤兒引用；既有引用仍由類別硬刪檢查拒絕。此項只修 ProcessType 的既有 writer，未擴充 PS104 nullable DTO、PSNo 等其他來源欄位規則。
- 本批覆蓋 PS103 CRUD、現存 `CreateProcess` 新增 writer 與 `UpdateProcess` 類別不可變。其他 Version/Copy／未建置的 shared Property／外部直接 DB writer 也不因此自動受到 advisory lock 保護；不能宣稱整個 PS104 的 namespace、參照、圖形、簽核已完成。

### Vue、套用與批次結果
