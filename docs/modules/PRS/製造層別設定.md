## 主清單畫面

- 主畫面 ClientSize `1008×591`、最大化啟動。共用 `frmBasisTemplat` 提供 IssueState Radio、`StageNo` 查詢欄和 Query。資料服務未帶 IssueState 時載入全部狀態，四個 Radio 只在用戶端 Dataset 篩選；清單依 `StageNo` 排序。
- Grid 位於 `(8,53)`、設計大小 `904×532`；隱藏 GroupByBox。顯示順序由查詢資料欄順序和 Designer layout 組成：`StageNo`、`StageName`、`StageType`、`Sequence` 靠右、`Creator`（80）、`CreateDate`（150，`yyyy/MM/dd HH:mm:ss`）、`Reviser`（80）、`ReviseDate`（150，同格式）。`IssueState`、`DataStamp` 隱藏。前四欄未指定固定寬度，沿用 UltraGrid 個人 layout/default。
- 右側按鈕：ADD、EDIT、DEL、Copy、Approve、Close；Print 在 Designer 隱藏，事件為空。Edit 只有 IssueState=0 可用。
- 查詢範圍由 `StageNo` 組成的 Additional Query Condition 決定；不在 SQL/API 契約中加入 Radio 狀態條件，除非保留能讓狀態切換不重新載入的等效行為。
- Copy 以目前列預填四個欄位，作為新資料新增；操作者需改 StageNo，且 Sequence 必須是全表唯一值。

## 新增/修改/複製視窗

- Def Form 固定單視窗、置中，ClientSize `496×276`，不可最大化/最小化。`FABPRSStageBasis` GroupBox 位置 `(8,8)`、大小 `480×138`；下方共用 Audit GroupBox `(8,154)`、大小 `480×70`；Confirm/Close/Apply 依序位於底部。
- 欄位順序：`StageNo`（黃色，離開時轉大寫，Edit 唯讀）、`StageName`（黃色）、`StageType`（黃色自由輸入）、`Sequence`（黃色、靠右數字文字欄）。WinForms 沒有為前三欄設定 TextBox MaxLength；實際字長受資料表 VARCHAR2(50) 限制。Sequence 欄位也沒有 NumericUpDown。
- 四欄 Confirm 必填。StageNo、StageName、StageType 由 Oracle NOT NULL/欄位長度限制；Sequence 必須是整數且 >=1。Oracle `NUMBER(4,0)` 將最大值限制為 9999。Sequence 在整張表（含不同 IssueState）唯一，不是只在目前 Radio 篩選結果中唯一。
- WinForms Confirm 的 DataTable duplicate check 未排除目前 Edit 列，故原序號不變時會被誤判重複；Apply 路徑未做同一個 duplicate check。Web UI 以 Oracle unique constraint 為準：Edit 排除自身後檢查全表，新增/複製/修改皆不能和其他 Stage 共用 Sequence。
- Add/Copy 的 Creator/CreateDate 由用戶資訊/目前時間送出，IssueState、DataStamp、CreateDate 也有資料庫預設。新 API 應改由已驗證 principal/server 時間填 audit，IssueState=0。Edit StageNo 唯讀，只改 Name/Type/Sequence，寫 Reviser/ReviseDate 並以 DataStamp CAS 遞增。
- Confirm 寫入成功後關閉視窗；Apply 寫入成功後留在視窗、更新本地 DataStamp 並清除 dirty。Add/Copy Apply 後仍是 Add/Copy 模式；再次套用同 StageNo 會碰到 PK。

## 狀態、刪除和簽核

| IssueState | WinForms 顯示 | Edit | Delete |
| ---: | --- | --- | --- |
| 0 | 未核准 | 可修改 | 實體刪除 |
| 1 | 簽核中 | 不可修改 | 多選時略過；單筆呼叫服務會拒絕 |
| 2 | 已核准 | 不可修改 | 以 DataStamp CAS 軟停用為 -1 |
| -1 | 不使用 | 不可修改 | 實體刪除 |

- Approve 僅處理 IssueState=0。共用 IssueManagement IssueNo=`STAGE BASIS`：沒有 Job 或沒有 Detail 時直接設為 2；存在完整簽核明細時建立 Issue Process、資料狀態設 1、通知第一關，Issue callback 核准為 2、退回為 0。不能讓 API 繞過共用簽核流程。
- 舊 `SetFABPRSStageBasisIssueState` / Edit 以 StageNo、DataStamp 條件更新並在更新時 `DataStamp+1`；DataStamp nullable。YMES API 要 null-safe CAS，衝突回 409。Insert 的 IssueState/Date/DataStamp DEFAULT 分別是 0/SYSDATE/0，但欄位可為 NULL；API新增建議明確設 IssueState=0 和 server audit。
- Oracle 主表無 FK/子表，也沒有 Delete cascade；StageNo 被流程資料使用時，舊服務仍只刪本表。家用端先保留此行為，不自行刪除 PS104 NodeBasis 或建立未核實的 cascade。
- 主畫面多選 Delete/Approve 按列逐筆呼叫，遇錯誤即停止，前面成功列不回滾。Web API 一列一個請求，頁面回報已完成與失敗/略過項目。

## YMES API 契約（家用端待建）

API 需由登入授權保護並檢查 FunctionNo=`STAGE BASIS`、FunctionKey=`PS102`。頁面 DEV 模式僅用 `ymes.dev.ps102-stage-basis.v1` localStorage 假資料，不呼叫 MES/正式 API 寫入。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/fab-prs-stages?stageNo=` | 載入全部狀態，按 StageNo 搜尋；IssueState 由 Vue Radio 篩選 |
| POST | `/api/fab-prs-stages` | 新增 |
| PUT | `/api/fab-prs-stages/{stageNo}` | 修改 IssueState=0 資料，DataStamp CAS |
| DELETE | `/api/fab-prs-stages/{stageNo}` | 依資料庫狀態實體刪除/軟停用 |
| POST | `/api/fab-prs-stages/{stageNo}/approve` | IssueManagement 核准流程 |

DTO 使用 camelCase `stageNo`, `stageName`, `stageType`, `sequence`, `issueState`, `creator`, `createDate`, `reviser`, `reviseDate`, `dataStamp`。新增 audit 與 IssueState 必須由 server 設定。DELETE/Approve body 只需 `dataStamp`，不可依 client IssueState 決定刪除類型；server 必須重新讀取狀態並 CAS。API Sequence 驗證 1–9999 整數，對全表唯一；依 Oracle nullable 定義，不得把 IssueState、CreateDate、DataStamp 強制改成 NOT NULL。

PS104 的 `tblprsnodebasis.StageNo` lookup 應重用 PS102 master，只允許 IssueState=2 的層別供正式流程節點選取；不要另建一張 stage lookup table。
