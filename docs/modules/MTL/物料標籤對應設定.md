## WinForms 畫面與操作

### 主畫面

- WinForms 主視窗為 1008×591；上方 Filter 區、中央 Grid 與右側直排按鈕，底部 StatusBar。進入頁面時 `funLoadMTLLabelMAP()` 呼叫被註解，所以初始 Grid 空白，按 Query 才查詢。
- 搜尋欄有 MaterialType、MaterialNo、LabelNo 三組「勾選框＋文字＋… lookup」。輸入文字會自動勾選；清空會取消勾選。Query 將已勾選欄位組成 `LIKE '%文字%'` 條件，未勾選不作為篩選。Enter 會觸發查詢。
- MaterialType 與 MaterialNo 搜尋輸入為大寫字元；LabelNo 不強制大寫。各 lookup 開啟 `frmCOMSearch`，查完需另外按 Query。
- 主 Grid 依 `MaterialType`、`MaterialNo`、`LabelType` 顯示。欄位順序：MaterialType、MaterialNo、MaterialTypeName、MaterialName、LabelType、LabelNo、Creator、CreateDate、Reviser、ReviseDate。LabelSource 與 DataStamp 隱藏；日期格式 `yyyy/MM/dd HH:mm:ss`。
- Load Core 的 SQL 條件為 `MaterialNo IS NOT NULL`，未限定 LabelSource；新增、修改與刪除則明確限定 `LabelSource=5`。Web GET 應保留這個差異，不能直接假設清單只回傳來源 5。來源 5 以外的列不應被錯誤改寫成來源 5。
- 右側按鈕順序：Add、Edit、Delete、Copy、Close。Grid 支援多列選取；Delete 顯示確認視窗，依選取列逐筆刪除，遇第一筆錯誤即停止；若之前已成功刪除部分列，重新載入清單。
- 主畫面 MaterialType lookup 使用 `LoadMaterialType(IssueState=2)`；MaterialNo lookup 使用 `LoadMaterialBasis(IssueState=2)`；LabelNo lookup 使用 `LoadPRDLabelBasis` 並附 `LabelSource=5`。
- StatusBar 顯示 `UserNo:<目前使用者>` 與表單啟動時的時間（`yyyy/MM/dd H:mm:ss`）。

### 新增／修改／複製表單

- 表單標題 `Material Label Map Define`，視窗 520×360。欄位為 MaterialType、MaterialTypeName、MaterialNo、MaterialName、LabelType、LabelNo，另有建立/修改稽核欄與 Confirm、Close、Apply。
- MaterialType 必填，由已核准（IssueState=2）類別 lookup 選取；選新類別會清除 MaterialNo/MaterialName。MaterialType 欄位本身唯讀。
- MaterialNo 必填，先選 MaterialType 後才可開啟 lookup；候選是已核准物料中相同 MaterialType，再額外加入 `MaterialNo='*'` 虛擬列（僅當候選物料至少一筆時）。MaterialNo、MaterialName 欄位唯讀。
- LabelType 必填，由標籤 lookup 帶入。Label lookup 只讀 `LabelSource=5`，顯示 LabelSource、LabelType、LabelNo、FormatFileName、Description、PrinterNo。新增/複製可選任意標籤類別；修改時 lookup 只提供目前 LabelType 的 LabelNo。LabelNo 可手動輸入，選 lookup 可帶入 LabelNo（新增/複製也會帶入 LabelType）。
- Add/Copy 需 MaterialType、MaterialNo、LabelType、LabelNo 全部非空。Add 建立新對應；Copy 將四欄帶入來源資料但呼叫 Add，必須改成不重複的複合鍵才能新增。LabelSource 寫入固定值 5。
- Edit 時 MaterialType、MaterialNo、LabelType 鎖定，只能修改 LabelNo；DataStamp 以原值 compare-and-swap，成功時加 1，Reviser/ReviseDate 使用目前登入者與伺服器時間。建立人/日期沿用舊值。
- Apply 儲存後保持表單開啟；Confirm 儲存後關閉；Apply 僅在欄位變更後啟用。成功後主畫面重查並選取 `(MaterialType, MaterialNo, LabelType)`。
- 無 IssueState、審核或停用流程。Delete 使用 `(MaterialType, MaterialNo, LabelType, LabelSource=5)`；舊 UI 不送 DataStamp。

## 資料表與 Oracle 結構

| Oracle table | 用途 | 主鍵 | 來源核對 |
| --- | --- | --- | --- |
| `MESTEST.TBLMTLLABELMAP` | 物料對標籤的對應主檔 | `(MATERIALTYPE, MATERIALNO, LABELSOURCE, LABELTYPE)` | 本次直連查 DBMS_METADATA 與資料字典；僅 PK unique index，無其他索引/FK |
| `MESTEST.TBLPRDLABELBASIS` | LabelSource=5 的標籤選擇目錄 | `LABELNO` | 本次直連查 DBMS_METADATA 與資料字典；僅 PK unique index，無其他索引/FK |
| `MESTEST.TBLMTLMATERIALBASIS` | MaterialNo/MaterialName lookup | `MATERIALNO` | 已在物料主檔來源 DDL 查核 |
| `MESTEST.TBLMTLMATERIALTYPE` | MaterialType/Name lookup | `MATERIALTYPE` | 已在物料主檔來源 DDL 查核 |

`TBLMTLLABELMAP` 欄位：

| 欄位 | Oracle 型態 | Null/default/限制 | Web 對應 |
| --- | --- | --- | --- |
| MATERIALTYPE | VARCHAR2(50) | enabled NOT NULL constraint；PK | `materialType` |
| MATERIALNO | VARCHAR2(50) | enabled NOT NULL constraint；PK | `materialNo` |
| LABELSOURCE | NUMBER(1,0) | enabled NOT NULL constraint；PK；物料來源固定 5 | `labelSource` |
| LABELTYPE | VARCHAR2(50) | enabled NOT NULL constraint；PK | `labelType` |
| LABELNO | VARCHAR2(50) | enabled NOT NULL constraint | `labelNo` |
| CREATOR | VARCHAR2(10) | enabled NOT NULL constraint | `creator` |
| CREATEDATE | DATE | enabled NOT NULL constraint | `createDate` |
| DATASTAMP | NUMBER(11,0) | DEFAULT 0，nullable | `dataStamp` |
| REVISER | VARCHAR2(10) | nullable | `reviser` |
| REVISEDATE | DATE | nullable | `reviseDate` |

`TBLPRDLABELBASIS` 結構與 PostgreSQL 空表參考也放在上述 SQL 檔案。此表在 ML107 只讀，不由 ML107 新增/修改標籤模板。兩張表在 Oracle 都沒有 FK；DDL 與空表 SQL 是供家用端比對，並非直接執行指令。

## Service/Core 邏輯

- `LoadMTLLabelMAP` 讀取 `TBLMTLLabelMap A WHERE MaterialNo IS NOT NULL`，子查詢補 `MaterialTypeName`、`MaterialName`；Additional condition 由主畫面以 Like 條件傳入。
- `AddMTLLabelMAP` 插入 MaterialType、MaterialNo、LabelSource=5、LabelType、LabelNo、Creator、CreateDate；DataStamp 使用 DB DEFAULT 0。複合主鍵防止同一物料同一 LabelType 重複對應。
- `EditMTLLabelMAP` 在 `clsBasis_UPD` 只更新 LabelNo、Reviser、ReviseDate，並執行 `DataStamp=DataStamp+1`；WHERE 包含三個 UI key、LabelSource=5、原 DataStamp，舊資料若版本不符會報錯。
- `DelMTLLabelMAP` 依 MaterialType、MaterialNo、LabelType、LabelSource=5 刪除；不刪標籤模板，不修改物料/類別主檔。
- `LoadPRDLabelBasis` 查詢條件含 LabelType 非空，表單再用 `LabelSource=5` 過濾；Edit picker 再限目前 LabelType。標籤模板唯一鍵只有 LabelNo；來源表沒有指向 label map 的外鍵。
- `*` 是 WinForms 在 lookup 加入的虛擬 MaterialNo，不是資料表物料記錄；API 不得對 `*` 要求物料 FK。
- 新 API 使用參數化 SQL，不能拼接舊 Additional XML/SQL。新增由 API 設 Creator/CreateDate；修改由伺服器寫 Reviser/ReviseDate。ML107 沒有審核或狀態欄位。

## YMES API 契約（家用端待實作）

1. `GET /api/material-label-maps?materialType=&materialNo=&labelNo=`：回傳所有 `materialNo IS NOT NULL` 的列，可用三個可選欄位作 contains/LIKE 篩選，排序 MaterialType、MaterialNo、LabelType；需回傳隱藏的 LabelSource、DataStamp 及稽核欄。
2. `GET /api/material-types?issueState=2`：已核准類別選擇器；使用 `TBLMTLMATERIALTYPE`。
3. `GET /api/materials?issueState=2&materialType={exact}`：已核准物料選擇器；精確限制 MaterialType。UI 在非空候選尾端附加虛擬 `*`。
4. `GET /api/product-labels?labelSource=5`：讀取 `TBLPRDLABELBASIS` 標籤候選；回傳 LabelType、LabelNo、FormatFileName、Description、PrinterNo、LabelSource。修改頁依 LabelType 再篩選。此端點可能供 PRD label 功能共用。
5. `POST /api/material-label-maps` body `{ materialType, materialNo, labelSource: 5, labelType, labelNo }`：必填及長度驗證，伺服器建立 audit/DataStamp；資料庫複合 PK 衝突回 409。保留 `materialNo='*'` 特例。
6. `PUT /api/material-label-maps/{materialType}/{materialNo}/{labelType}?dataStamp=` body `{ labelNo }`：只更新 LabelNo；key 不能改，且 WHERE 固定 LabelSource=5、舊 DataStamp，成功更新 Reviser/ReviseDate/DataStamp。DataStamp 為 NULL 時用 `dataStamp=0&dataStampIsNull=true`，由 API 以 `IS NULL` 比對；版本不符回 409。
7. `DELETE /api/material-label-maps/{materialType}/{materialNo}/{labelType}`：依上述 key 加 LabelSource=5 刪除；支援 UI 逐筆刪除及部分成功後停止。可在 YMES API 增加 DataStamp 保護，但 UI/WinForms 舊版刪除不傳 DataStamp。
8. 所有 API 驗證登入與 `MTL LABEL MAP BASIS` 功能權限；對外不提供 Oracle 帳密。Production 不得使用 Vue localStorage。

## Vue Development 頁面

- Development Preview 有獨立 localStorage 假資料，標籤 lookup 只提供 LabelSource=5；Production 使用 API，API 未部署時明確顯示錯誤。
- 保留 WinForms 初始不查詢的行為；三欄可輸入 contains 查詢並由 checkbox 啟用，lookup 將值帶回但不自動執行查詢。
- Grid 支援即時 row selection、多選刪除與雙擊修改；按鈕 Add/Edit/Delete/Copy/Close；表單有 Lookup、Audit、Apply/Confirm。資料列透過 Vue 更新，不改 URL query，也不整頁重載。
- UI 使用中性灰色框線與 KD 淡黃色可編輯欄位，維持 WinForms 控制項布局；LabelSource/DataStamp 隱藏。
