# 物料供應商基本資料（MTL ML101）

## 功能來源

- MES 第一層模組：MTL「物料資料」；FunctionNo：MTL VENDOR；FunctionKey：ML101；WinForms：STD/MESWin/MTL/ML_MaterialVendor/frmMaterialVendor.vb。
- 主畫面 1008×591，包含上下兩個群組：上方物料供應商主檔 Grid，下方所選供應商的連絡人 Grid。IssueState 四狀態篩選與 VendorNo 查詢由共用 frmBasisTemplat 提供；預設未簽核，搜尋欄位 VendorNo。
- 主檔按鈕：新增、修改、刪除、複製、核准、關閉。連絡人按鈕：新增、修改、刪除、複製、Mail。選取主檔列即重載該供應商連絡人。
- 主 Grid 顯示 VendorNo、VendorName、Description、ERP No、Creator/CreateDate、Reviser/ReviseDate；IssueState 與 DataStamp 隱藏。連絡人 Grid 顯示 ContactorName、TelNo、FaxNo、Title、Address、EMail、Description 及 audit；VendorNo、DataStamp 隱藏，EMail 為可點選 URL。
- 主資料編輯窗 frmMaterialVendorDef 550×262，欄位 VendorNo、VendorName、Description；下方 audit。新增/複製可改 VendorNo；修改時 VendorNo 唯讀。新增/複製建立 IssueState=0；複製只複製主檔欄位，不複製連絡人。VendorNo 離開欄位時 Trim 並轉大寫；VendorName Trim。
- 連絡人編輯窗 frmMaterialVendorContactorDef 752×434，欄位 VendorNo、ContactorName、TelNo、FaxNo、Title、Address、EMail、Description 及 audit。VendorNo 唯讀；修改時 ContactorName 唯讀，複製時可改連絡人姓名。VendorNo 與 ContactorName 必填；各欄位長度依 Oracle DDL。欄位離開時 Trim；若 ContactorName 已填且 EMail 空白，舊表單自動填入 ContactorName@。Mail 按鈕以 mailto: 開啟目前連絡人地址。
- 主檔 Apply 儲存後留在編輯窗；Confirm 儲存後關閉。連絡人舊程式的 funConfirmApply 成功時無條件呼叫 Close，因此 Apply 與 Confirm 都會關閉；Web 版保留此行為並在 UI 提示。

## 業務規則

1. IssueState：0 未簽核、1 簽核中、2 已簽核、-1 不使用。主檔修改只允許 0。
2. 新增/複製產生狀態 0。核准僅接受狀態 0，IssueNo=MTL VENDOR。無 Issue Job 對應或 Job 沒有明細時直接改 2；有簽核明細時啟動共用 Issue 流程，狀態先改 1，通過改 2、退回改 0，並通知第一簽核群組。
3. 刪除主檔：狀態 0/-1 實體刪除；狀態 2 改為 -1；狀態 1 禁止。實體刪除在同一交易刪除該 VendorNo 的連絡人、物料供應商對應 TBLMTLMATERIALVENDORMAP，再刪主檔。畫面多選逐筆執行，遇錯停止並保留先前已完成的筆數。
4. 連絡人依複合鍵 (VendorNo, ContactorName) 新增/修改/實體刪除。主檔狀態操作不直接改變連絡人。
5. 兩表 DataStamp 為 nullable 且 DEFAULT 0。Production API 的修改/刪除需 CAS；若讀取版本為 NULL，呼叫端用 dataStamp=0&dataStampIsNull=true 表示並以 IS NULL 比對；非 NULL 比對傳入數值。audit 由 API 伺服器設定。
6. 舊 WS 對物理刪除會接收 DataStamp，但核心刪除沒有用它做條件；Web API 交付需補上交易與 CAS，避免 stale write。
7. TBLMTLMATERIALVENDORMAP 的舊 LoadMaterialVendorMapWithVendorName 使用 TBLMTLMATERIALVENDOR Join；目前 YMES PostgresMasterDataRepository.MaterialFeatures.cs 查詢仍 Join tbleqpvendor。家用端實作本功能時一併核對並修正 MTL 供應商名稱來源，不能把 EQP Vendor 取代 MTL Vendor。

## Oracle 結構與 PostgreSQL 空表 SQL

Oracle 結構於 2026-11-17 使用 Windows PowerShell 5.1、Oracle.ManagedDataAccess、本機受保護連線直接唯讀查詢：

| Oracle 表 | 欄位數 | 主鍵 | 其他索引/FK |
|---|---:|---|---|
| MESTEST.TBLMTLMATERIALVENDOR | 10 | VendorNo | 無額外索引/FK |
| MESTEST.TBLMTLMATERIALVENDORCONTACTOR | 13 | VendorNo + ContactorName | 無額外索引/FK |

完整欄位、NULL/default 與限制見 database/reference/mestest_mtl_material_vendor_source_ddl.sql。PostgreSQL 空表 CREATE SQL 見 database/reference/mestest_mtl_material_vendor_create.sql。Oracle DATE 對應 timestamp without time zone；DataStamp DEFAULT 0 但 nullable。SQL 僅含結構，不含 MES 業務資料。

## Production API handoff（家用電腦）

| 方法 | 路徑 | 行為 |
|---|---|---|
| GET | /api/material-vendors?issueState=&vendorNo= | 按狀態及 VendorNo 不分大小寫部分查詢；依 VendorNo 排序。 |
| POST | /api/material-vendors | 建立狀態 0；VendorNo/VendorName 必填，長度依 DDL；API 寫 Creator/CreateDate/DataStamp。 |
| PUT | /api/material-vendors/{vendorNo}?dataStamp= | 只允許狀態 0；更新 VendorName/Description，鍵唯讀並寫 Reviser/ReviseDate/DataStamp。NULL 版本用 dataStampIsNull=true。 |
| DELETE | /api/material-vendors/{vendorNo}?issueState=&dataStamp= | 0/-1 CAS 後同交易刪 contactor、material vendor map、主檔；2 CAS 後軟刪為 -1；1 回 409。 |
| POST | /api/material-vendors/{vendorNo}/approve?dataStamp= | 經 MTL VENDOR 共用 Issue/Job 流程核准；由 API 查 Issue mapping/detail，發起簽核並通知第一群組；不可由 Vue 直接切狀態。 |
| GET | /api/material-vendors/{vendorNo}/contactors | 列出連絡人，依 ContactorName 排序。 |
| POST | /api/material-vendors/{vendorNo}/contactors | 新增 VendorNo/ContactorName 及聯絡欄位；audit/DataStamp 由 API 建立。 |
| PUT | /api/material-vendors/{vendorNo}/contactors/{contactorName}?dataStamp= | 更新非鍵欄位，CAS 並寫 audit/DataStamp。 |
| DELETE | /api/material-vendors/{vendorNo}/contactors/{contactorName}?dataStamp= | CAS 實體刪除；多選逐筆，首錯停止。 |

所有端點需驗證登入與 MTL ML101 權限、唯一鍵、欄位長度及有效狀態；使用參數化 SQL。Migration 前先逐欄比對 YMES schema/migrations；缺表才建立 forward migration，勿直接執行 CREATE TABLE IF NOT EXISTS 覆蓋差異。
