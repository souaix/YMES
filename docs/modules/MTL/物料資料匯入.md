# 物料資料匯入

## 遷移狀態

Vue 已有 WinForms 匯入視窗的主要互動，Development 使用瀏覽器假資料；可讀 CSV 與 `.xlsx`、下載開發用 `.xlsx` 範本、以物料編號/名稱分組、模擬逐組結果及取消。Production 目前沿用 JSON 匯入 API；正式範本下載與舊版 `.xls` 預覽 API 尚未提供，因此本功能尚未完整遷移。

## WinForms 來源

- Form：`STD/MESWin/MTL/ML_MaterialDataImport/frmMaterialDataImport.vb`
- Designer：`STD/MESWin/MTL/ML_MaterialDataImport/frmMaterialDataImport.Designer.vb`
- 後端檢查：呼叫外部 `DataImporter.MaterialDataImport.MaterialDataChecker`，實作原始碼未在目前 `CSiMES` 原始碼樹找到。
- 範本服務：`wsSYS.funLoadFileExtension`、`wsSYS.GetTemplateFile`、`wsSYS.AddTemplateFile`；Production 範本由系統 FunctionNo=`MTL BASIS` 的附件設定提供。

## 表單與互動

- WinForms 視窗初始大小 784×562；顯示唯讀檔案路徑、瀏覽按鈕、結果 UltraGrid、匯入、範本下載與關閉。取消與進度條平時隱藏，匯入背景工作期間顯示；期間瀏覽、匯入、範本與關閉按鈕停用。
- 瀏覽只可選一個 `.xlsx` 或 `.xls`。讀檔成功後，結果清單以 `(MaterialNo, MaterialName)` 去重，每組一列，初始訊息空白。
- 匯入前檢查已選檔，並顯示「關閉 Excel 檔案後繼續」確認視窗；取消確認不送出。
- 範本下載先讀取系統設定的檔案副檔名，再下載 `MTL BASIS` 範本；範本更新按鈕在預設畫面隱藏。
- 背景工作依每組物料編號/名稱呼叫一次 `MaterialDataChecker`，回填成功或錯誤訊息並更新進度；允許使用者取消尚未處理的組別。任一組成功時，關閉表單回傳成功旗標，讓主頁重新載入。

## Excel 欄位與解析

`funImport` 使用 NPOI 的 `WorkbookFactory`，只讀第一個工作表；不以 Excel 標題文字決定欄位，依固定位置讀取。第 1 列作為標題/略過列，資料從第 2 列開始：

| 0 起算欄位索引 | 欄位名 | 必填 |
| ---: | --- | --- |
| 0 | MaterialType | 是 |
| 1 | MaterialNo | 是 |
| 2 | MaterialName | 是 |
| 3 | PutInPlace | 是 |
| 4 | CountWay | 是 |
| 5 | CheckLotNo | 是 |
| 6 | UnitType | 是 |
| 7 | UnitNo | 是 |
| 8 | ERPUnitNo | 否 |

UserNo 不在檔案欄位中，WinForms 以目前登入者補入。公式儲存格由 NPOI 評估；日期儲存格轉成 `yyyy/MM/dd HH:mm:ss`，其他數值/文字轉字串並去除首尾空白。解析失敗會清空檔名及結果清單。

舊程式對空白儲存格的處理有不一致之處：實際存在但值空白的儲存格會跳過該整列；缺少的欄位 cell（除 ERPUnitNo）則中止整份讀取並顯示欄位錯誤。Vue 將整列空白略過，部分列在結果訊息指出缺欄；這是為了保留可操作的逐組預覽，正式解析/寫入規則仍應由 API 與舊 checker 核對。

## API 契約與資料處理

目前 Production `POST /api/materials/import` 收 JSON 陣列，逐列呼叫主檔建立，回傳 `{ row, materialNo, success, message }[]`。這與 WinForms 每個 `(MaterialNo, MaterialName)` 群組一次呼叫 checker 的交易/錯誤邊界尚未證明等價；不要把前端進度呈現當成伺服器逐筆交易或可取消保證。

家用端需完成：

1. `GET /api/materials/import/template`：回傳系統設定的正式範本位元組與原始副檔名/檔名；不可用前端自行生成的範本取代正式範本。
2. `POST /api/materials/import/preview`：multipart `file`，至少支援 `.xls`；讀第一個工作表，依上述欄序回傳正規化的 `rows`，讓 UI 能逐組預覽。檔案大小、列數與錯誤回應需有限制。
3. 擴充 `MaterialImportRowRequest` 接收 `ErpUnitNo`；現在 DTO 沒有這個 WinForms 欄位，Production 送入後會遺失。
4. 核實同一物料編號多列的 checker 規則與交易邊界，再決定 API 是接受群組批次，或保持逐列結果。不可只靠 `MaterialNo` 對應回傳結果，因同編號可能多列。
5. 如需完整保留背景進度/取消，採伺服器匯入工作 ID、狀態查詢及取消端點；HTTP client abort 不能當作資料庫工作已取消。現有 Production API 是同步請求，Vue 不顯示會誤導的取消按鈕。

此功能不新增資料表；沒有新的 Oracle DDL 或 CREATE SQL 需求。

## Vue 實作差異

- `web/src/components/MaterialFeatureDialog.vue` 使用與 WinForms 相近的路徑列、右側匯入/範本按鈕、三欄結果表及進度列。瀏覽器安全限制不允許讀取完整本機路徑，所以只顯示檔名。
- `web/src/components/materialImportWorkbook.ts` 在瀏覽器讀 CSV/`.xlsx` 第一個工作表；Development 可下載依 9 欄順序生成的 `.xlsx` 示範範本，並以 localStorage 假資料逐組模擬匯入/取消。同組多列會顯示「尚未模擬 checker 規則」並停止寫入，避免假成功；Production 也會在 API 群組語意確認前擋下多列同組匯入。
- Production 可在正式 API 提供後下載正式範本，並將 `.xls` 上傳到預覽端點。現有 API 不支援取消；正式匯入期間不提供取消按鈕。
- 前端仍需後續補公式無快取 `.xlsx`、保護/加密活頁簿與巨大檔案等錯誤處理；NPOI 的完整相容性由正式 API 負責。
