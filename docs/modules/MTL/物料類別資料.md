# 物料類別資料（MTL ML102）

## WinForms 來源與畫面

- 第一層模組：MTL「物料資料」；FunctionNo=`MTL TYPE`、FunctionKey=`ML102`、Form=`frmMaterialType`。
- 主清單 Form 初始大小 1008×591；篩選器由共用 `frmBasisTemplat` 提供，IssueState 預設未簽核，搜尋欄為 `MaterialType`。
- 主 Grid 顯示 MaterialType、MaterialTypeName、Description、Creator/CreateDate、Reviser/ReviseDate；IssueState、DataStamp 隱藏。按鈕有新增、修改、刪除、複製、核准、Property、GumHour、Close。可多選後逐筆刪除/核准；只有未簽核資料可修改。
- `frmMaterialTypeDef` 496×276：MaterialType、MaterialTypeName、Description 與建立/修改資訊。MaterialType 必填，離開欄位 Trim 並轉大寫；修改時鍵唯讀，新增/複製可輸入。Apply 儲存後留窗，Confirm 儲存後關閉。複製會連同來源的類別級 GumHour（若存在）建立新設定，不複製屬性或 QC 明細。
- MaterialType 不可和 `TBLMTLMATERIALBASIS.MaterialNo` 同碼；新增服務檢查此跨表唯一性。名稱非必填。
- 刪除 IssueState=0/-1 為實體刪除；IssueState=2 軟刪除為 -1；IssueState=1 不允許。舊核心將屬性、類別主檔、類別 QC 範本及類別時效資料一併刪除。
- 核准僅接受狀態 0，IssueNo=`MTL TYPE`。依 Issue Job map/detail 決定直接改為 2 或啟動共用簽核（狀態 1）；簽核完成改 2，退回改 0，寄信給第一簽核群組。若類別屬於系統參數 `GumMaterialType`，核准前必須已有類別級 GumHour 設定。
- Property 按鈕啟動外部 `ML_MaterialProperty` 視窗，帶入 MaterialType 作為 Material。該視窗使用 `TBLMTLMATERIALPROPERTY`，主鍵 `(Material, PropertyNo)`，含四狀態、CRUD/Copy/Approve；簽核 IssueNo=`MTL PROPERTY`。
- GumHour 按鈕在 `MATERIALMULTITIMECTRL != 0` 時才顯示；只對 `GumMaterialType` 清單中的列啟用。`frmMaterialGumType` 為 484×464，MaterialType 與名稱唯讀；編輯 ACCMin/ACCMax、回冰旗標/FROZENMIN/ReForzenTimes、再次回溫旗標/REACCMIN/REACCMAX，並顯示 audit。`MaterialNo='*'` 代表整個物料類別。
- GumHour 驗證：ACCMin/ACCMax 必填、數值且 0–999.99；非全 0 時 ACCMax > ACCMin。回冰啟用時 FROZENMIN 必填且 0–999.99、次數為 1–999 整數。再次回溫啟用時兩值必填且 0–999.99；非全 0 時 REACCMIN < REACCMAX。Apply 儲存留窗，Confirm 儲存後關閉；狀態非 0 時整個 Gum 設定唯讀。

## 資料表與 DDL

- `TBLMTLMATERIALTYPE`：MaterialType PK；MaterialType varchar2(50) NOT NULL、IssueState number(1,0) DEFAULT 0 NOT NULL、Description varchar2(255)、Creator/CreateDate、MaterialTypeName varchar2(50)、DataStamp number(11,0) DEFAULT 0 nullable、Reviser/ReviseDate。
- Property 使用 `TBLMTLMATERIALPROPERTY`；類別 QC 範本使用 `TBLMTLTYPEQCITEM`；GumHour 使用 `TBLMTLTYPEACCLIMATION`，複合 PK `(MaterialType, MaterialNo)`，類別級鍵為 `MaterialNo='*'`。
- 上述四表的 Oracle MESTEST DDL 與 PostgreSQL 空表 CREATE SQL 已包含於 `database/reference/mestest_mtl_master_source_ddl.sql`、`database/reference/mestest_mtl_master_create.sql`。物料主檔 migration 0013 已處理這批既有表；此功能不新增表或重複建立 SQL。家用端仍須以實際 YMES migration/schema 核對，不覆蓋 YMES 擴充欄位。
- DataStamp nullable 且 DEFAULT 0；Production PUT/DELETE 使用 CAS。NULL 版本參數使用 `dataStamp=0&dataStampIsNull=true`；audit 由伺服器登入者設定。

## Production API handoff（家用電腦）

| 方法 | 路徑 | 行為 |
|---|---|---|
| GET | `/api/material-types?issueState=&materialType=` | 依狀態及編號部分查詢，依 MaterialType 排序。 |
| POST | `/api/material-types` | 新增 IssueState=0；檢查和 material basis 的 MaterialNo 跨表不重複；設定 audit/DataStamp。 |
| POST | `/api/material-types/{sourceMaterialType}/copy` | 以來源的類別級欄位建立新編號；單一交易新增物料類別，若來源有 `MaterialNo='*'` GumHour 則一併複製並重設簽核與 audit；不複製 Property/QC 明細。 |
| PUT | `/api/material-types/{materialType}?dataStamp=` | 僅可更新 IssueState=0 的名稱/說明，MaterialType 不可改；CAS 與 audit。 |
| DELETE | `/api/material-types/{materialType}?issueState=&dataStamp=` | 狀態 0/-1 同交易刪除屬性、Type QC、GumHour、主檔；狀態 2 軟刪為 -1；狀態 1 回 409。 |
| POST | `/api/material-types/{materialType}/approve?dataStamp=` | 驗證登入/ML102 權限；檢查 GumMaterialType 設定後走 MTL TYPE Issue/Job 核准流程。 |
| GET/POST | `/api/material-types/{materialType}/properties` | 讀取或新增共用 `TBLMTLMATERIALPROPERTY`，Material 固定為類別編號。 |
| PUT/DELETE/POST | `/api/material-types/{materialType}/properties/{propertyNo}`、`.../{propertyNo}/approve` | Property CRUD/刪除/MTL PROPERTY 核准；Composite key 與 DataStamp CAS。 |
| GET/POST/PUT | `/api/material-types/{materialType}/acclimation` | 讀取、新增或更新類別級 `TBLMTLTYPEACCLIMATION`，固定 MaterialNo=`*`；欄位精度、旗標與必填依來源 DDL/WinForms 驗證，PUT 使用 DataStamp CAS。 |

Production 不得將核准或系統參數檢查留在 Vue；API 必須使用參數化 SQL、檢查唯一鍵、IssueState、權限及跨表 MaterialNo 衝突。刪除的多表處理需單一資料庫交易。`GumMaterialType`、`MATERIALMULTITIMECTRL` 需由 YMES 系統參數服務取得，不能把 DEV 假設定當正式值。

## Vue Development 頁

- `web/src/components/MaterialTypeMaster.vue` 對應 `/YMES/MTL/MaterialTypes`，由 MTL 三層選單的 `MTL TYPE` 開啟。
- 開發預覽使用獨立 localStorage 假資料，實作狀態/編號查詢、多選、Add/Edit/Copy/Delete/Approve、屬性視窗與 GumHour 編輯；Production 呼叫上表端點，缺 API 時明確提示，不回退假資料。
- DEV 預設的 GumMaterialType 與多時效開關僅為 UI 測試假設定；Production 必須接系統參數 API。
- GumHour 主視窗中舊程式未使用的系統參數/傳輸型別控制未納入；保留實際使用的類別級時效、回冰及再次回溫欄位。
