# 物料品管項目設定（ML106）規格

## 功能識別

- WinForms 第一層：物料資料；第三層功能：物料設定 → 物料品管項目設定。
- FunctionNo：MTL QCITEM；來源 Form：frmMaterialQCItemSet。
- WinForms 程式：STD/MESWin/MTL/ML_MaterialQCItemSet/frmMaterialQCItemSet.vb 與同目錄 Designer。
- Web 路由：/YMES/MTL/MaterialQCItems；Vue 頁：web/src/components/MaterialQCItemMaster.vue。
- 本頁是逐一指定物料的 QC 項目，不是 ML105 的物料類別範本設定。

## WinForms 畫面與操作

表單約 1008×591。上方 Query 區有 MaterialType、MaterialNo 及查詢按鈕；右側各有查找按鈕。中間第一個 Grid 顯示 MaterialType、MaterialNo、MaterialName。選取物料列後，下方左側依序顯示三個候選 Grid：MTL QCItem for Attributes、MTL QCItem for Variables、MTL QCItem Group；右側顯示該物料已綁定的 MTLQCITEM，欄位為 QCItemNo、QCItemName、QCItemType、Reviser、ReviseDate。候選列與已綁定列可多選；箭頭按鈕移入/移出，雙擊列也執行相同動作。底部 Confirm 儲存目前選取物料，Close 關閉。

### 查詢及選取

1. MaterialType 與 MaterialNo 至少填一項；MaterialType 作精確比對，MaterialNo 以輸入值加 % 作前綴查詢。
2. 舊程式以 IssueState=-1 呼叫 LoadMaterialBasis，意義是查詢不限制狀態。API 不傳 issueState 篩選時也必須回傳所有狀態。
3. MaterialType 查找提供物料類別清單；MaterialNo 查找可查物料並回填編號前綴。查找後需再按 Query 才載入主清單。
4. 點選 Material Grid 的列才載入該物料 QC 項目資料；只變更當前編輯目標，不會立即保存。
5. 三個候選來源只取 IssueState=2 的有效 QC 項目：Attributes 讀 TBLQCITEMFORATTRIBUTES 的 QCItemNo/QCItemName；Variables 讀 TBLQCITEMFORVARIABLES；Group 讀 TBLQCITEMGROUPBASIS 的 GroupNo/GroupName。
6. 已綁定清單來自 TBLMTLQCITEM，依 QCItemNo 對應三種目錄取得名稱，按 QCItemType 分為 0=Attributes、1=Variables、2=Group。清單讀取包含物料目前全部已綁定項目，不依物料 IssueState 篩除。
7. Add/Remove 在表單記憶體中調整；Confirm 才送出目前選取 MaterialNo 的完整清單。空清單代表刪除該物料全部 QC 綁定，不得將載入失敗誤認成空清單保存。

### 舊 Service/Core 儲存副作用

- Form funUpdMTLQCItem 呼叫 wsMTL.UpdMTLQCItem，送出 MaterialNo、完整 QC 清單及目前執行者。
- clsMTLBasis.UpdMTLQCItem 以 MaterialNo 刪除舊 TBLMTLQCITEM 後寫入新列；缺少的 TBLOPQCITEM 項目會新增為虛擬站 OPNo='IQC'、InLine=0、ExecuteOrder=0。
- 儲存同時呼叫 clsQCBasis.UpdQCItemBindLog("tblMTLQCItem", ...)。BindType=2；舊有關聯被移除記 ExecuteStatus=2，新關聯記 ExecuteStatus=0；使用 TBLQCITEMBINDLOG。LogSerial 由日期時間、ThreadId 與亂數組成，不依賴 Oracle sequence。
- Reviser/ReviseDate 由登入者與伺服器時間補齊；資料寫入、IQC 項目與異動記錄應在 PostgreSQL 交易內一致提交。
- 原 WinForms Core 將記錄寫入與主資料寫入拆成不同呼叫；Web API 應以單一交易改善一致性，不改動 BindType/ExecuteStatus 的舊意義。

## 資料表與 DDL

| 用途 | Oracle table | YMES 參考檔/狀態 |
| --- | --- | --- |
| 物料主檔與查詢 | TBLMTLMATERIALBASIS | 已存在於物料主檔 CREATE SQL |
| 物料直接綁定 | TBLMTLQCITEM | 已存在於物料主檔 CREATE SQL；PK (MTLNO, QCITEMNO) |
| Attributes 候選 | TBLQCITEMFORATTRIBUTES | 本功能由 MESTEST 直查 DDL，新增 source DDL/PG CREATE |
| Variables 候選 | TBLQCITEMFORVARIABLES | 同上 |
| Group 候選 | TBLQCITEMGROUPBASIS | 同上 |
| IQC 虛擬站 | TBLOPQCITEM | 已存在作業站 CREATE SQL；PK (OPNO, QCITEMNO) |
| 綁定變更記錄 | TBLQCITEMBINDLOG | 本功能由 MESTEST 直查 DDL，新增 source DDL/PG CREATE |

新查詢結果保存於 database/reference/mestest_mtl_qc_item_tables_source_ddl.sql；PostgreSQL 空表參考定義為 database/reference/mestest_mtl_qc_item_tables_create.sql。來源表均只有 DDL 中列出的 PK，沒有 FK 或其他索引。CREATE 檔供家用端先比對 YMES 實際 schema 與 migration，再只建立真正缺漏的表/欄位；不可直接在 Oracle 執行，也不可用 IF NOT EXISTS 取代 schema 差異核對。

## Vue 頁與 API 契約

- Development Preview 使用明確標示的假資料；物料清單沿用其他物料頁的 DEV localStorage key，物料 QC 草稿採 MaterialFeatureDialog 共用的物料 key。
- 點列以 Vue 狀態更新，不改 URL、不整頁重新載入。載入中或 API 失敗時 Confirm 停用；快速換選物料只接受最後一次讀取結果。
- Production 物料查詢：GET /api/materials?materialType=&materialNoPrefix=，主畫面 Query 至少輸入一項；但 API 需允許兩者皆空，因 WinForms MaterialNo 查找會載入完整物料清單。MaterialNo 必須前綴搜尋且不限制 IssueState。
- 類別查找：GET /api/material-types。
- 新增 ML106 專用讀取：GET /api/materials/{materialNo}/qc-item-library，回傳 { available, assigned }。兩者 DTO 欄位為 qcItemNo, qcItemName, qcItemType；assigned 再含 reviser, reviseDate。available 只含三個 QC 目錄中 IssueState=2 的列；已綁定列以目錄 Join 名稱，保留無法 Join 的舊綁定供畫面移除。
- 為相容 MaterialFeatureDialog，現有 GET /api/materials/{no}/qc-items 的物料類別範本語意維持不變；不要把其 available 清單改成全部 QC 目錄。
- 保存沿用 PUT /api/materials/{materialNo}/qc-items，Body 為 { items: [{ qcItemNo, qcItemType }] }。伺服器須確認物料存在、類型為 0/1/2、每個 QC Item 在對應目錄存在且 IssueState=2；以交易替換 TBLMTLQCITEM、補 TBLOPQCITEM IQC 關聯、寫 TBLQCITEMBINDLOG BindType=2 的增刪事件並更新 audit。不要讓既有 MaterialFeatureDialog 的 PUT 契約失效。
- 已有 API 目前只以 TBLMTLTYPEQCITEM 作為 GET 候選，且 PUT 沒有上述 IQC 與 bind-log 副作用；家用端要擴充專用 GET、補齊共同儲存副作用。既有 PUT 若維持未簽核物料限制，需先與 WinForms 舊行為核對；不可在 UI 載入錯誤時送空清單。
