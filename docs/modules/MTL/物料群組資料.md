## WinForms 畫面與操作

### 主畫面

- 啟動時 `IssueVisable=False`，因此主畫面沒有四種簽核狀態 radio。搜尋欄只有 `GroupNo`，按 Query 或 Enter 重新讀取群組主檔。
- 主 Grid 依 `GroupNo` 升冪。顯示 `GroupNo`、`MaterialType`、`Description`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`；`DataStamp` 隱藏。建立/修改日期格式為 `yyyy/MM/dd HH:mm:ss`。
- 右側按鈕：Add、Edit、Delete、Copy、Close。Grid 支援多列選取；Delete 逐筆刪除所選群組，重新載入清單。
- 下方 `Group-MaterialNo` 區域是兩欄清單：左側 `UnSelectData`、右側 `SelectData`，兩側都支援多選。中間方向按鈕移動所選項目；雙擊項目也會移動。
- 清單上方的編號輸入框按 Enter 時，輸入值會 Trim 並轉大寫，再對目前清單做精確比對；找到才移到另一側，否則保留輸入供修改。
- 選取主 Grid 群組後，先載入該 GroupNo 的既有明細，再載入相同 MaterialType、`IssueState=2` 的物料。兩側都按 `MaterialNo` 升冪；已指派項目從左側候選清單排除。既有明細即使物料後續不再核准，仍會留在右側供移除。
- `Confirm` 將右側全部 MaterialNo 一次送出替換；右側空集合表示清除該群組全部成員。成功後顯示成功訊息。Close 關閉表單。

### 新增／修改／複製表單

- 表單標題 `Material Group Basis Define`，WinForms 尺寸 523x276；主資料區為 GroupNo、MaterialType、Description，另有建立/修改稽核區及 Confirm、Close、Apply。
- `GroupNo` 必填，最多 50 字元，離開欄位 Trim 並轉大寫。`MaterialType` 必填，由 `wsMTL.LoadMaterialType` 載入完整類別清單，透過 `...` 搜尋選取；編輯時不可變更 GroupNo 或 MaterialType。
- Description 多行，資料表上限 255 字元。
- Add 與 Copy 都新增一筆群組主檔；Copy 將來源的 GroupNo、MaterialType、Description 帶入，GroupNo 可編輯且應改為新值，不複製群組明細。
- Edit 只更新 Description；以來源 DataStamp 作為版本條件。建立人/建立日期沿用，修改人/修改日期為目前使用者與目前時間。
- Apply 初始停用，欄位變更後啟用；儲存但保持表單開啟。Confirm 儲存後關閉。欄位必填失敗時顯示提示並停留在表單。
- 本功能沒有 IssueState、核准或停用流程。

## 資料表與 Oracle 結構

| Oracle table | 用途 | 主鍵 | 來源核對 |
| --- | --- | --- | --- |
| `MESTEST.TBLMTLMATERIALGROUPBASIS` | 群組主檔 | `GROUPNO` | 本次直連讀取 DBMS_METADATA 與資料字典；只有 PK unique index，無 FK/其他索引 |
| `MESTEST.TBLMTLMATERIALGROUPDETAIL` | 群組成員 | `(GROUPNO, MATERIALNO)` | 已在物料主檔來源 DDL；PK unique index，無 FK/其他索引 |

主檔欄位如下：

| 欄位 | Oracle 型態 | Null/default/限制 | Web 對應 |
| --- | --- | --- | --- |
| GROUPNO | VARCHAR2(50) | 啟用 CHECK constraint `N_TBLMTLMATERIALGROUPBASIS_01` 強制 NOT NULL；PK | `groupNo` |
| MATERIALTYPE | VARCHAR2(50) | 啟用 CHECK constraint `N_TBLMTLMATERIALGROUPBASIS_02` 強制 NOT NULL | `materialType` |
| DESCRIPTION | VARCHAR2(255) | nullable | `description` |
| CREATOR | VARCHAR2(10) | nullable | `creator` |
| CREATEDATE | DATE | nullable | `createDate` |
| DATASTAMP | NUMBER(11,0) | `DEFAULT 0`，nullable | `dataStamp` |
| REVISER | VARCHAR2(10) | nullable | `reviser` |
| REVISEDATE | DATE | nullable | `reviseDate` |

Oracle 資料字典將 GROUPNO、MATERIALTYPE 的 column nullable 顯示為 Y，但同表有 ENABLED CHECK constraint 分別保證欄位非 NULL。PostgreSQL 空表定義採語義等價的 `NOT NULL`。Oracle `DATE` 對應 YMES `timestamp without time zone`。群組明細沒有外鍵；刪除主檔時 API 應在交易內先刪明細再刪主檔。

`database/reference/mestest_first_phase_create_tables.sql` 的歷史 bootstrap 參考已同步補上 MaterialType NOT NULL、DataStamp DEFAULT 0 及正確欄位註解。家用端不可盲目重跑 bootstrap 或直接拿空表 CREATE 覆蓋既有 YMES 表；先比對 live schema/migration，缺漏才做 forward migration。

## Service/Core 業務邏輯

- `LoadMaterialGroupBasis` 依共用 query condition 查主檔；主 Grid 按 GroupNo 排序。
- `AddMaterialGroupBasis` 建立主檔。`EditMaterialGroupBasis` 只允許寫 Description，並以 GroupNo + DataStamp 作更新條件。
- `DelMaterialGroupBasis` 刪除群組明細後刪主檔；Web API 要把兩個刪除和版本檢查放在一個 PostgreSQL transaction，避免留下孤兒明細。
- `LoadMaterialGroupDetail` 讀取一個群組的成員；候選物料由 `LoadMaterialBasis` 限定 MaterialType 與 IssueState=2。
- `UpdMaterialGroupDetail` 會先刪除群組既有成員，再逐筆插入傳入的 MaterialNo；未傳成員即清空。舊 Service 的刪除與逐筆新增可能留下部分結果，YMES API 要以單一 transaction 原子替換。
- 舊 Service 對刪除及成員更新有 EventLog；YMES 端沿用既有伺服器稽核/event log 機制，不新增 Oracle 或 YMES event table。

## YMES API 契約

1. `GET /api/material-groups?groupNo=` 回傳所有群組，或依 GroupNo 查詢；排序 GroupNo。此功能沒有 IssueState 篩選。
2. `GET /api/material-types`（不帶 IssueState）提供新增/複製表單的 MaterialType lookup，對應 WinForms `LoadMaterialType` 全清單。
3. `POST /api/material-groups` body `{ groupNo, materialType, description }`。檢查必填、50/50/255 長度與 GroupNo 唯一；GroupNo 大寫。Creator/CreateDate/DataStamp 由伺服器設定，DataStamp 初始 0；回傳完整 DTO。
4. `PUT /api/material-groups/{groupNo}?dataStamp=...` 僅更新 Description，主鍵/MaterialType 不可改；做 compare-and-swap，nullable DataStamp 需支援 `dataStampIsNull=true`。Reviser/ReviseDate/DataStamp 由伺服器更新。成功回傳完整更新 DTO。
5. `DELETE /api/material-groups/{groupNo}?dataStamp=...` 在同一交易內檢查 DataStamp、刪除 `tblmtlmaterialgroupdetail`、刪除 `tblmtlmaterialgroupbasis` 並寫伺服器事件記錄。不存在或版本衝突回 404/409。
6. `GET /api/material-groups/{groupNo}/materials` 回傳已指派 MaterialNo 字串陣列。
7. UI 候選清單使用 `GET /api/materials?issueState=2&materialType={exact}`，只顯示相同 MaterialType 的已核准物料並排除既有成員。
8. `PUT /api/material-groups/{groupNo}/materials` body `{ materialNos: [...] }` 是整組替換，空陣列代表清空。使用單一 transaction；拒絕重複、不存在、MaterialType 不符的新增成員。為允許整理歷史資料，既有但已非 IssueState=2 的成員若保持不變可保留，使用者移除後不得重新加入。成功寫 event log 並回傳更新後成員。
9. 所有端點檢查登入與 `MTL GROUP` 權限；API 不接受客戶端提供的 audit。此功能沒有核准端點。

## Vue DEV 頁

- 公司端 Development Preview 使用明確的 MTL 群組 localStorage 假資料，物料清單讀取物料主檔共用 DEV localStorage key；Production 不讀寫假資料，只呼叫 API。
- 頁面使用即時 Vue row selection，不在 URL 放 GroupNo，也不因點選資料列整頁重新載入。表單 Copy 預填來源 GroupNo/MaterialType/Description，Apply 會在欄位有變更時啟用並保持目前新增/複製模式。
- UI 含 GroupNo 查詢、單/多選 Grid、Add/Edit/Copy/Delete/Close、稽核欄、物料類別 lookup、雙清單多選/雙擊/精確 Enter 移動與替換式 Confirm；欄位沿用 KD 淡黃色、表格與控制項使用中性灰框。
- Production API 尚待家用端完成並部署；未連線前不得用 DEV localStorage 冒充正式資料。
