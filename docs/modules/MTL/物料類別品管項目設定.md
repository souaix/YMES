# 物料類別品管項目設定（MTL ML105）

## WinForms 來源與畫面

- MES 第一層模組：MTL「物料資料」；FunctionNo=`MTL TYPE QCITEM`、FunctionKey=`ML105`、WinForms Form=`STD/MESWin/MTL/ML_MaterialTypeQCItem/frmMaterialTypeQCItem.vb`。
- Form 客戶區 1008×591。頂部 MaterialType 查詢區含編號輸入與 Query；舊程式因類別資料量大，啟動時不載入清單，使用者輸入前綴後查詢。未輸入時載入全部類別。這頁沒有 IssueState 篩選。
- 上方類別 Grid 顯示 MaterialType、Description、Creator、CreateDate；建立日期格式 `yyyy/MM/dd HH:mm:ss`。選取一列會載入該類別已設定項目及三種可用 QC 清單。
- 下方為左右兩區：左側垂直排列 `MTL QCItem for Attributes`、`MTL QCItem for Variables`、`MTL QCItem Group` 三個候選 Grid；各 Grid 顯示 QCItemNo/QCItemName 或 GroupNo/GroupName，提供多選及右向加入按鈕，雙擊候選列也會加入。已設定的編號會從候選清單排除。
- 右側 `MTLQCITEM` Grid 顯示 QCItemNo、QCItemName、QCItemType、Reviser、ReviseDate，依 QCItemType 分組排序；QCItemType 對應 0=Attributes、1=Variables、2=Group。Attributes 類型不能編輯，Variables/Group 可改類型。選取一筆或多筆後可移除，雙擊已設定列也會移除。
- 底部有 Confirm/Cancel。Cancel 關閉且不儲存暫存變更。Confirm 先提示設定會套用到該類別下的物料，再儲存類別範本並更新所有該類別物料的 QC Item。

## 舊程式資料與儲存邏輯

- 查詢使用 `wsMTL.LoadMaterialType`，MaterialType 後綴 `%`，即編號前綴查詢；沒有 IssueState 條件。
- 選取類別時呼叫 `wsMTL.LoadMTLTypeQCItem`，並載入 `wsQC.LoadQCItemForAttributes`、`wsQC.LoadQCItemForVariables`、`wsQC.LoadQCItemGroupBasis`。候選 QC 清單呼叫以 `IssueState=-1` 取得所有狀態資料；UI 再依編號排除已指派項目。
- Add/Remove 只修改畫面暫存集合；候選與已選清單之間可以多選移轉。TypeQC 範本主鍵只含 `(MaterialType, QCItemNo)`，因此同一類別不能重複加入相同 QCItemNo。
- Confirm 呼叫 `wsMTL.UpdMTLTypeQCItem`，以刪除該 MaterialType 舊範本後再寫入新清單的方式整批替換 `TBLMTLTYPEQCITEM`，並寫 QC Item 綁定異動記錄。隨後查出所有屬於該類別的物料，逐筆呼叫 `wsMTL.UpdMTLQCItem` 替換 `TBLMTLQCITEM`；舊方法也會為缺少的項目補入 `TBLOPQCITEM` 的 `OPNo='IQC'` 記錄並寫異動記錄。舊 WinForms 是多次呼叫，途中失敗可能留下部分更新。
- Vue 呼叫一個 API 完成相同整體效果；Production API 應將類別範本、所有所屬物料 QC Item、必要 IQC 項目及異動記錄放在單一資料庫交易，避免部分更新。新增項目的 Reviser/ReviseDate 由 API 登入者設定；既有項目沿用資料庫中原 audit，不能接受用戶端任意覆寫 audit 值。

## 資料表與 SQL

- `TBLMTLTYPEQCITEM` 欄位：`MATERIALTYPE varchar2(50) NOT NULL`、`QCITEMNO varchar2(25) NOT NULL`、`QCITEMTYPE number(1,0) NOT NULL`、`REVISER varchar2(10)`、`REVISEDATE date`；PK `(MATERIALTYPE, QCITEMNO)`。
- 儲存時同步既有 `TBLMTLQCITEM`；沿用舊 `UpdMTLQCItem` 時也會確保 `TBLOPQCITEM` 的虛擬 IQC 項目存在。
- Oracle MESTEST 原始 DDL 與 PostgreSQL CREATE SQL 已存在於 `database/reference/mestest_mtl_master_source_ddl.sql`、`database/reference/mestest_mtl_master_create.sql`；`TBLMTLTYPEQCITEM`、`TBLMTLQCITEM` 已納入 MTL migration 0013。此頁不需要新表或額外 CREATE SQL。家用端仍須比對實際 YMES schema/migration，保留既有 YMES 擴充。

## Production API handoff（家用電腦）

| 方法 | 路徑 | 行為 |
|---|---|---|
| GET | `/api/material-types?materialType=` | 略過 IssueState 條件即回傳所有狀態；有輸入時用 MaterialType prefix 搜尋，回傳 MaterialType/Description/Creator/CreateDate。 |
| GET | `/api/material-types/{materialType}/qc-items` | 回傳 `attributes`、`variables`、`groups`、`assigned` 四組資料；候選欄位為 QCItemNo/QCItemName、已設欄位另含 QCItemType/Reviser/ReviseDate。 |
| PUT | `/api/material-types/{materialType}/qc-items` | 接收 `{ items: [{ qcItemNo, qcItemType }] }`；驗證類別與 QC 項目存在、編號唯一、型別為 0/1/2，整體套用類別範本及該類別所有物料，並保持 WinForms 的 IQC 補項及異動記錄行為。單一 DB transaction。 |

候選目錄應使用與 WinForms 相同的 QC 屬性、計量、群組服務和欄位來源；不要把三種 QC Item 當成同一組分類資料。Production 端點需驗證登入及 MTL ML105 功能權限，查詢/寫入用參數化 SQL。

## Vue Development 頁

- `web/src/components/MaterialTypeQCItemMaster.vue`，路徑 `/YMES/MTL/MaterialTypeQCItems`，由 MTL 三層選單 `MTL TYPE QCITEM` 開啟。
- DEV 頁沿用物料類別頁的 localStorage 假類別，候選 Attributes/Variables/Group、雙向移轉、多選移除、型別限制、Confirm 提示與假資料儲存。Production 使用上述 API；API 不存在時顯示明確錯誤，不回退假資料。
