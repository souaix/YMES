## 畫面與來源行為

- 主畫面以 KPITreeNo、KPITreeName 模糊包含條件查詢，可空白並回傳全部資料，依 KPITreeNo 排序，沒有分頁。表格顯示編號、名稱、說明、FreezeState、建立／修改人與日期。選取列後，下方預覽 NodeXmlString；Preview 另開 `RT_KPITreeView`。
- `FreezeState=0` 是 Freeze，唯讀；`FreezeState=1` 是 UnFreeze，可編輯。Edit、Delete、Draw 僅允許狀態 1；Freeze 僅能 1→0，Unfreeze 僅能 0→1。Copy 可選任一狀態，Core 複製來源狀態。Core Add 未明確指定新狀態，正式資料庫 default 尚待查證。
- Delete 對選取列逐筆呼叫 `wsRPT.DelKPITreeBasis`；遇到 Freeze 列會拒絕。前面已刪除的列不會由 Form 還原，故可能部分成功。Core 會清除明細後刪主檔；底層 `CollectionSQL` 的交易範圍未確認。
- 主檔 Add／Edit／Copy 必填 KPITreeNo、KPITreeName，長度上限 50，Description 可空；Copy 會複製節點及其 KPI、Report Market Index、容忍值設定。Edit 傳 DataStamp。
- Draw 畫面依序載入 `tblEKBDetail`、`tblEKBKPIDetail`、`tblEKBLimiteDetail`、`tblEKBReportMarketIndex` 與 NodeXmlString。KPI Control 以一組三個視覺區塊呈現 KPI 名稱、說明、Target；Descript Control 可編輯文字及文字／背景／框線色、透明背景。支援 Straight、VH、HV、VHV、HVH 連線樣式、拖曳、縮放與 Delete。
- KPI 定義要求 KPI No、名稱、說明；KPINo 唯一。TargetType 的 ValueList 註解有 Number、Percentage，但實際值清單需待查。TargetValue 與上下限須為數字；有範圍時 low／up 成對、up 不小於 low；目標值需在範圍內；沒有範圍時至少要有目標值；百分比不接受負值。LimiteState 關閉時不使用容忍值規則列。
- KPI 可選 ReportID／ChartID 與 ReportMarket Database／Table／Column。ActualValueScript 舊路徑會執行並要求一列數值結果；DEV 不執行腳本，家用端不得提供任意 SQL 執行入口。`LimiteOperator` 顯示值清單需待查。
- Save 將圖形 XML 與完整 EKB Detail、KPI Detail、Report Market Index、Tolerance 明細送入 `wsRPT.UpdKPITreeDetail`，並更新 DataStamp。Core 先刪再插多組明細並更新 NodeXmlString；此多表保存的原子交易邊界待確認。

## 已知來源差異與未確認事項

- Form 呼叫 `LoadKPITreeBasis` 時帶 `GetXML_CLOB=False`，Service 解析該參數後沒有傳給 Core，因此 Core 仍採預設 `GetXml_CLOB=true`。Core 的 false 分支又選取 `KPINo/KPIName` 等與主檔不符欄位，需釐清是否為未使用分支或來源缺陷。
- 舊 Service／Core 多處以字串串接 SQL。正式 API 必須參數化並限制查詢範圍。
- 本次找到的直接資料表：`tblEKBBasis`、`tblEKBDetail`、`tblEKBKPIDetail`、`tblEKBLimiteDetail`、`tblEKBReportMarketIndex`。repo 未找到這五張表的可信 Oracle source DDL／metadata；公司桌機受保護 Oracle profile 不存在，未連 Oracle、未推測欄位或新增 CREATE-only SQL。`tblEKBKPILog` 是 RT906 歷史查詢用途，不是 RT904 樹圖編輯直接寫入表。

## 家用端 API／schema handoff

1. 先比對 live PostgreSQL schema 與所有既有 migration；取得可信 DDL／metadata 後再決定五張表的 key、型別、NULL、default、FK 與 index。不以本文 DEV 欄位或未驗證的 first-phase SQL 建表。
2. 建議拆分登入保護的 basis 查詢／CRUD、basis 狀態轉換，以及指定樹的完整 detail 讀寫 API。查詢需限制必要條件或上限、參數化、穩定排序與分頁；狀態轉換檢查 0／1 允許邊並用 DataStamp CAS。
3. Copy 與 Delete 應由單一交易完成 basis、node、KPI、Report Market Index、tolerance 全部相關列的複製／移除；Save 以一次交易完整替換 detail 並更新 XML／DataStamp，回傳明確衝突與逐項驗證錯誤。不得重現 Form 多筆 Delete 的不可回復部分成功。
4. 新增主檔 FreezeState default 必須依 live schema／產品決策確認；Copy 是否複製凍結狀態也需明確定義。UI 端仍需服務端授權與狀態檢查。
5. `ActualValueScript` 不得直接交給一般 DB 連線執行。應先追出既有受限執行環境、參數／權限及 Report／Chart lookup 的合法來源；未確認前只保存／顯示，不提供執行 API。取得實際 TargetType、LimiteOperator ValueList 後再核對 UI 選項。
