# RT202 作業站現況看板_產品類別

## 模組識別

- FunctionNo：`BILLBOARD OPSTATE_PRDTYPE`；FunctionKey：`RT202`；FunctionName：作業站現況看板_產品類別。
- Vue 入口：`/YMES/RPT/OpStateProductTypeBoard`，目前只在 DEV 假資料模式開放。
- RT202 為 RT201 作業站現況看板的產品類別版，使用獨立 `SetupType=2` 設定，以多個 ProductType 系列堆疊 Queue／Run／Hold／Wait 數量。

## 圖表及互動

- Form 對目前電腦 HostName 載入 SetupType 2 的 RefreshTime、FontSize、OP 清單。Setup 會暫停 Timer，呼叫共用設定頁並於儲存後重建圖表；沒有設定時不載入看板資料。
- 每個 OP 一張 `StackColumnChart`，X 軸四個狀態 Queue／Run／Hold／Wait，系列為 ProductType，值為 CurQty；同一頁所有 OP／狀態共用 Y 軸最大值。色彩由 ProductType 系列順序配色，並非固定業務狀態色。滑鼠提示顯示 ProductType、Lot 與 CurQty。
- 圖表上方標示 OPNo 與總 Lot／Qty；指到圖表上緣附近時顯示 OPName。雙擊總 Lot 與 Qty 不同時為 0 的圖表，會開放大 Type 2 子圖；該路徑把 totals annotation 當作 `strOPName` 傳入，子視窗標題可能誤顯總數，保留為 Legacy 疑點。
- 左鍵點非零 ProductType 色塊呼叫 ProductNo 鑽取，傳 OPNo、ProductType、RefreshTime、FontSize；Type 3 子圖依相同四種狀態呈現產品編號。右鍵 Copy To Clipboard／Lot Detail；總 Lot 與 Qty 同時為 0 時隱藏 Lot Detail 與分隔線。Copy 僅在 DEV 顯示提示，不存取系統剪貼簿。
- Lot Detail 用 WIP LotBasis／LotState 與 OP、Process、Product、Customer 關聯，Status 限制 0、1、2、3，依 Status 與 ProductNo 排序展開。DEV 列顯 LotNo、ProductType、Status、CurQty、CurUnitNo。

## Service／Core 資料規則與風險

- Config 由共用 `LoadBillBoardOPStateConfig(HostName, SetupType=2)` 讀取；獨立於 RT201 的 SetupType 1。OP 資訊排序為 PSNo、OPOrder、OPNo。
- `LoadBillBoard_OPState_PRDType(OPNo)` 用 `tblWIPLotState A` join `tblWIPLotBasis B`（BaseLotNo）與 `tblPRDProductBasis C`（ProductNo、ProductVersion）；四個查詢分別依 Status 0、1、3、2，計 `COUNT(A.LotNo)` 與 `SUM(A.CurQty)`，依 OPNo／ProductType 群組。沒有 WIP 的類別不會出現在該次資料集。
- 舊 Core 先將 OPNo 逗號字串直接拼成 SQL `IN (...)`，而 Web Service 只檢查參數存在；家用 API 必須以登入者授權 OP 範圍及參數化查詢，不能沿用字串拼接。
- 舊 ChartClick 雙擊的 `strOPName` 取自 totals annotation，而資料點點擊取自 OPName annotation。放大子圖標題可能顯示總數，是來源程式疑點。

## MESTEST DDL／metadata 現況

- `tblWIPLotState`／`tblWIPLotBasis` 可先比對 [WP101 source DDL](../../../database/reference/mestest_wip_wp101_source_ddl.sql) 與 [QC409 dependency DDL](../../../database/reference/mestest_qc409_wip_disposition_dependencies_source_ddl.sql)；Product Basis 可比對 [PRD product basis DDL](../../../database/reference/mestest_prd_product_basis_source_ddl.sql)。這些是既有 MESTEST reference，不代表 YMES PostgreSQL live schema 完全相同。
- 共用 Setup 的 `tblRPTBillBoardOPStateConfig`／`tblRPTBillBoardOPStateContent` DDL、PK／索引未找到。桌機可確認的 Codex Oracle attachment 不存在，因此本次沒有以 PowerShell 5.1／ODP.NET 新查 metadata，也沒有猜 CREATE SQL。
- 公司端不連 PostgreSQL、不建 schema／migration、不實作或驗收正式 API、不 SSH／部署；未執行 build／test／browser。

## 家用端 API／schema handoff

- RT202 可延用 RT201 建議的 `GET /api/reports/op-state-breakdown?opNo=...&groupBy=productType`，並允許 SetupType 2 一次傳多個受授權 `opNos`；回傳 OPNo、ProductType 及 Queue／Run／Hold／Wait 各自 LotCount／CurrentQty。查詢以受授權 OP 範圍為界、參數化處理 OPNo；限制最大 OP 數及結果列數。
- RT203 產品編號可延用同 endpoint 的 `groupBy=productNo&productType=...`，或採批次唯讀 ProductNo endpoint。Lot 明細延用受授權、分頁及筆數上限的 `/api/reports/op-state-lots`。
- SetupType 2 共用看板設定表；先核 live schema、PK／索引與 user/device scope。不要以舊 PCNo 作為使用者授權，也不要從缺失的 Oracle config DDL 推測 PostgreSQL CREATE。
- 目前有 LotState、LotBasis、ProductBasis MESTEST DDL refs；家用端需比對 YMES live PostgreSQL 的欄位、資料量、關聯及索引，再決定唯讀查詢計畫。公司端沒有連 PostgreSQL 或產生未核實 CREATE-only SQL。
