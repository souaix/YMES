# RT201 作業站現況看板

## 模組識別

- FunctionNo：`BILLBOARD OPSTATE`；FunctionKey：`RT201`；FunctionName：作業站現況看板。
- Vue 入口：`/YMES/RPT/OpStateBoard`，RPT「報表管理 → 看板」。目前僅 DEV 假資料可用，正式環境保持未開放。
- RT201 用每個設定的 OP 顯示在製批次狀態：Queue、Run、Hold、Wait 的 Lot 數與 CurQty；支援 Column／Pie 切換和產品類別／產品編號鑽取。

## 主畫面、圖表與操作

- 有 SetupType 1 設定才載入圖表及啟動 Timer。設定傳回 RefreshTime、FontSize 與 OP 清單。Setup 暫停刷新、透過共用畫面儲存後重建圖表，再按秒數更新。設定尚無資料時 Setup Form 欄位預設 RefreshTime=30 秒、FontSize=18，OP 清單為空；主看板不會因此載入圖表。每個設定 OP 一張卡，每列最多四張。
- 預設 ColumnChart。Queue／Run／Hold／Wait 的顏色依序為綠／藍／紅／黃；依序對應 `tblWIPLotState.Status=0/1/3/2`。每柱顯示 Lot 數／CurQty；滑鼠提示亦顯示該狀態 Lot／Qty。Y 軸數量最大值跨所有 OP／狀態共用且隱藏數字標籤。
- PieChart 對同四種狀態按 Qty 顯示切片及百分比；tooltip 顯示 Lot／Qty。標題顯示 OPNo，右上角顯示總批數／總數量；OPName 在圖上方游標附近顯示。
- 點資料值為 0 的 Bar／Pie 不鑽取。點非零資料會開 Type 2 產品類別圖；Type 2 點產品類別會開 Type 3 產品編號分布。Type 1／2／3 子視窗依 RefreshTime 更新。
- DEV 子視窗以狀態堆疊條呈現各 ProductType／ProductNo 數量，並附逐狀態 Lot／Qty 表格；選 ProductType 進入 ProductNo，提供返回類別／關閉。
- 雙擊總批數與總數量皆為 0 的 OP 不動作；否則開接近螢幕大小的 Type 1 圖表。右鍵包含 Copy To Clipboard、Lot Detail；總批數與總數量皆為 0 時隱藏 Lot Detail。
- Lot Detail 呼叫 `wsWIP.LoadLotBasisJoinState`，Status 傳 `0|1|2|3`，依 Status、ProductNo 排序並展開群組。

## Service／Core 資料規則

- `LoadBillBoardOPStateConfig(HostName, SetupType=1)` 從 `tblRPTBillBoardOPStateConfig`／`tblRPTBillBoardOPStateContent` 取得 RefreshTime、FontSize、OPNo，join `tblOPBasis` 取得 OPOrder、PSNo；Form 依 PSNo／OPOrder／OPNo 排序。Update 先依 PCNo、SetupType 刪除舊 config/content，再寫入設定與 OP 清單。Core 的 LEFT JOIN 後續又將 Content.OPNo 條件放在 WHERE，可能令沒有 OP Content 的 config 不回傳；空 OP 選取應視為無看板資料。
- `LoadBillBoard_OPState(OPNo)` 從 `tblOPBasis` 取 OPNo、OPName、OPOrder，分別將 `tblWIPLotState` 依 Status 0、1、3、2 聚合 `COUNT(*)` 與 `SUM(CurQty)`，結果欄位為 QueueLot／Qty、RunLot／Qty、HoldLot／Qty、WaitLot／Qty。沒有該狀態的 OP 以 0 顯示。
- `LoadBillBoard_OPState_PRDType(OPNo)` 將各 Status 的 WIP LotState join `tblWIPLotBasis` 與 `tblPRDProductBasis`，依 OPNo、ProductType 聚合 Lot／Qty。`LoadBillBoard_OPState_ProductNo(OPNo, ProductType)` 延續相同狀態分組到 ProductNo，ProductType 為可選條件。
- Type 6 Lot detail 由 WIP `LoadLotBasisJoinState` 取得 LotBasis + LotState，Status 限制為 0、1、2、3；Core 並 join OP、Process、Product、Customer basis。Grid 依 Status、ProductNo 排序並展開。DEV 以 LotNo、ProductNo、Status、CurQty、CurUnitNo 呈現。

## 家用端 API／schema handoff

- 批次唯讀 `GET /api/reports/op-state?opNos=...`，回傳 OPNo／OPName／OPOrder／PSNo 與 Queue、Run、Hold、Wait 各自 `lotCount`／`currentQty`，UI 共用數量軸取所有狀態的最大值。
- 鑽取 `GET /api/reports/op-state-breakdown?opNos=...&groupBy=productType|productNo&productType=...`，依 OP 與產品分類／編號回傳狀態 Lot／Qty。明細 `GET /api/reports/op-state-lots?opNos=...&statuses=0,1,2,3&page=...&pageSize=...`，只接受存在的 OP，並限制狀態、每頁筆數及頁數。
- SetupType 1 對應讀寫 `RefreshTime`、`FontSize`、OPNo 及排序；家用端需先決定 user/device 設定 scope，建立受登入授權保護的設定 API，再依 live schema 產生 CREATE-only SQL。不可把 Legacy PCNo 當作使用者授權。
- 現有 `tblWIPLotState`／`tblWIPLotBasis`／`tblOPBasis`／Product／Process／Customer source DDL 可先核欄位；`tblRPTBillBoardOPStateConfig`／Content 的完整鍵／索引及所有 tables 的 YMES live PostgreSQL schema 仍需家用端核實。本次不提供未核實表的 CREATE SQL。

- 公司端只完成 WinForms／Designer／Service／Core 核對、DEV 假資料及 API/schema handoff；未連 YMES PostgreSQL、未實作／驗收正式 API/schema，也未 SSH／部署。

## 家用端唯讀 API 實作（2026-11-27）

- 登入保護並以唯讀、Repeatable Read 交易提供：
  - `GET /api/reports/op-state?opNos=OP01,OP02`：每個作業站回傳名稱、流程／排序欄位及 Queue／Run／Hold／Wait 的 LotCount、CurrentQty。
  - `GET /api/reports/op-state-breakdown?opNos=OP01,OP02&groupBy=productType|productNo&productType=TYPE1`：依作業站及產品類別／編號彙總四種狀態；`productType` 僅供 `groupBy=productNo` 篩選。
  - `GET /api/reports/op-state-lots?opNos=OP01&statuses=0,1,2,3&productType=TYPE1&productNo=PROD1&page=1&pageSize=50`：批次明細依狀態、產品編號、LotNo 穩定排序並提供 `hasMore`。
- 僅接受已存在的 OPNo；最多 100 個作業站、2,000 個 breakdown 群組、每頁最多 100 筆／最多 10,000 頁。Status 固定支援 0 Queue、1 Run、2 Wait、3 Hold。查詢參數均參數化，無自由 SQL 條件。
- 正式 YMES live schema／`ymes_app` SELECT 與既有索引已核對：LotState 的 `i_tblwiplotstate_04(opno)`、`i_tblwiplotstate_01(baselotno)`；LotBasis PK `baselotno`、ProductBasis PK `(productno, productversion)`、OPBasis PK `opno`。四段 SQL 在正式資料庫以 `ymes_app` 唯讀 `PREPARE`／`EXPLAIN` 通過並採用可用查詢索引；目前沒有證據要求額外 index migration。
- `tblPRDProductBasis.producttype` 是分類來源，LotBasis 與 ProductBasis 依 ProductNo＋ProductVersion 關聯。`tblRPTBillBoardOPStateConfig`／Content 在 live YMES 與 repo refs 均無可信結構；未建表、未提供設定 CRUD，也不信任 PCNo 作為使用者權限。
- API 套用登入授權、驗證 OP 存在與查詢上限；每位使用者的 OP 白名單及 SetupType 1／2／3 的保存 scope 尚無可信來源規格，需公司端交付原生設定表結構後再決定。現有報表權限架構未提供 per-OP 授權表，因此不可把用戶輸入的 OP 清單宣稱為角色授權。
- 本輪未寫入正式資料列。正式 `tblopbasis` 為 0 筆，所以有效 OP／有資料正向查詢尚待來源同步；正式設定載入／儲存及 RT201–RT203 UI 接線另依公司端待辦追蹤。
