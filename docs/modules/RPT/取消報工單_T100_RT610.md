# RT610 取消報工單_T100

## 功能與入口

- RPT FunctionNo ERPWORKREPORT CANCEL_T100、FunctionKey RT610、Form frmERPWorkReport_Cancel_T100。Vue DEV 入口：/YMES/RPT/ErpWorkReportCancelT100。
- 查詢條件為 MO No 與報工 DataStartTime 起訖，至少勾選一項；選 Summary 後直接顯示 EAI Detail。此功能沒有啟用 Equipment Summary Grid。
- DEV 用虛構資料模擬條件查詢、Summary／Detail、T100 單據取消失敗及 MES 狀態更新、重拋排程。所有操作只改本機記憶體，不呼叫 T100、MES Service、Oracle 或 PostgreSQL。

## WinForms、Service、Core

- Form／Designer 同檔：D:/iMES/CSiMES/STD/MESWin/RPT/RT_ERPWorkReport_Cancel_T100/frmERPWorkReport_Cancel.vb。載入時起訖日期預設昨日及今日（日期欄位），MO 文字有值便自動勾選，離開欄位轉大寫，Enter 移至下一欄。日期查詢要求起訖必填且結束晚於開始（精確到秒）；查詢至少需要 MO 或日期條件。
- Summary 呼叫 wsRPT.LoadERPWorkRPT_Summary_T100／clsReport.LoadERPWorkRPT_Summary_T100，讀 TBLERPWorkRPT_SUMMARY，MO 由 TBLERPWorkRPT_DETAIL_EAI 的 WorkReportID 子查詢精確比對，日期以 DataStartTime >= from AND <= to 篩選。Form 不傳 Service/Core 可收的 ERPFlag；Core SQL 字串串接、沒有排序或分頁，Core 本身也允許無條件全表查詢。
- Summary Grid 顯示 ItemNo、DataStartTime、DataEndTime、ERPFlag，其餘欄隱藏。選 Summary 後呼叫 wsRPT.LoadERPWorkRPT_Detail_EAIJoinERPDocumentLog／clsReport.LoadERPWorkRPT_Detail_EAIJoinERPDocumentLog，以 WorkReportID 並可帶當前 MONo 查 TBLERPWORKRPT_DETAIL_EAI。Detail 顯示 ItemNo、EquipmentNo、MONo、EQP_RESValue、EMP_RESValue、ERPNo；欄位來源以查詢回傳資料為準，無設備中間層。
- Cancel WorkRPT 僅允許 Summary ERPFlag=1。Form 對目前 Detail 每一列逐筆呼叫 wsERP_T100.ERPWorkReport_Cancel_T100，不先去重 ERPNo；Service 從 ERP service 設定取 URL，以 EAI wo.work.report.data.process／report_no 發送取消，回應 code 不是 0 即視為失敗並寫交易 Log。Form 會記錄失敗 ERPNo、繼續其餘列，之後仍呼叫 wsRPT.ExeUndoERPWorkReport_T100。
- Undo Service 呼叫 clsReport.ExeUndoERPWorkReport_T100。Core 清除 TBLWIPCONT_EQUIPMENT、TBLWIPCONT_EMPLOYEE_MULTIUSER 的 ERPFlag、SummaryFlag、WorkReportID，並將 TBLERPWORKRPT_SUMMARY.ERPFlag 設為 -1；Resource／ResourceShare 的更新是註解狀態。Core 從 Detail EAI 以 GROUP BY ERPNo 讀取，但只 Read() 第一列，之後僅將 TBLWIPLOTLOG_REPORT 中該 ERPNo、EndTime 非空的列 ERPNo 清為 null。若同一 WorkReportID 有多個 ERPNo，其他 ERPNo 對應回報記錄可能保留；而且即使 T100 取消失敗，Form 仍會進入 MES Undo，存在 ERP／MES 狀態不一致風險。
- ReSum ReTurn 僅允許 ERPFlag=-1；Form 傳 WorkReportID、DataStartTime、DataEndTime 至 wsRPT.ExeReRunERPWorkReport_T100／clsReport.ExeReRunERPWorkReport_T100。Core 尋找 JobName=funCreateWOWorkReportData_EAI；找到時插入一筆 Standby 到 TBLMESAutoRunQueue，Parameter03 填 DataStartTime 的日期；DataEndTime 未使用。無論是否找到 Job，Core 都將 Summary ERPFlag 設為 2；不更新 Detail EAI 的 Flag。狀態文字來自 ValueListProvider，Form 未定義對照；DEV 顯示來源數值。

## DDL 與家用端 API／schema handoff

- 尚缺可信 MESTEST source DDL／metadata：TBLERPWORKRPT_SUMMARY、TBLERPWORKRPT_DETAIL_EAI、TBLWIPCONT_EMPLOYEE_MULTIUSER、TBLMESAutoRunJob、TBLMESAutoRunQueue。桌機受保護 Oracle attachment 不存在，未連 Oracle、未猜 CREATE-only SQL。
- 可沿用 repo refs：TBLWIPCONT_EQUIPMENT（WP305）；TBLWIPLOTLOG_REPORT（WP201 dependency source DDL）。這些 references 不涵蓋上述缺表，也不能確認正式 PostgreSQL 同步狀態。
- 2026-11-27 家用端以 PPK／SSH 唯讀查正式 `ymes` PostgreSQL catalog：上述五張目標表在所有 schema 均不存在，無欄位／鍵／索引或資料可供比較；未執行 migration，也未讀寫業務資料。連線紀錄記於 [DATABASE_CONNECTION.md](../../DATABASE_CONNECTION.md)。
- 家用端先核對 YMES live schema、同步來源、ERPNo／WorkReportID 關聯及 Detail EAI 正式資料。若資料足夠，唯讀 API 需登入與 RT610 ACL、參數化查詢、至少 MO 或 DataStartTime 條件、日期跨度／筆數上限、穩定排序；Detail 必須以已授權 WorkReportID 驗證父子關係，不接受前端 SQL／AdditionalXml。
- 取消／重拋是跨 T100 與 MES 的寫入流程。正式實作前需設計逐 ERPNo 冪等、部分失敗補償／對帳、清除多個 ERPNo 的明確規則，以及 AutoRun Job 缺失時不可把狀態誤標為已排程的處理；不可直接暴露舊 Core SQL 為寫入 API。
