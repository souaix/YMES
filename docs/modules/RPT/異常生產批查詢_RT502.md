# RT502 異常生產批查詢

## 選單與來源

- 選單：RPT → 生產批 →「異常生產批查詢」，FunctionNo `HOLD LOT`、FunctionKey `RT502`、Form `frmLotState_Hold`、執行檔 `RT_LotState_Hold.dll`。
- Form／Designer：`STD/MESWin/RPT/RT_LotState_Hold/frmLotState_Hold.vb`；Designer 程式碼內嵌在同一檔，沒有獨立 Designer 檔。CSiMES、THEIL、DEV_SILVA 三份內容一致。
- Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `LoadLotBasisJoinState`。
- Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `LoadLotBasisJoinState`。
- 來源 Form 與 RT501 共用同一個查詢 Service／Core，但 RT502 的狀態條件不同，不能套用 RT501 固定 `LotState=1` 及 AdditionalXml 庫存狀態判斷。

## Form 條件與操作

- 查詢固定傳 `Status=3`（Hold）及 `ReportMode=True`；不傳 `LotState` 條件，也沒有額外條件必填檢查。空條件仍執行查詢。
- 八個可勾選條件：RO No、MO No、Product No（同時傳 ProductVersion）、Customer No、Lot No、OP No、Org Lot No、PS No。文字輸入 RO／MO／Lot／Org Lot 會自動勾選；清空文字時取消勾選。關閉 checkbox 會清空對應值。
- Customer、Product、PS、OP 為唯讀欄位並有單選 lookup。Lookup 分別呼叫 `wsENT.LoadCustomerBasis(IssueState=defInteger)`、`wsPRD.LoadProduct(IssueState=defInteger, CurVersion=defInteger)`、`wsPRS.LoadProductionSegment(IssueState=2)`、`wsOP.LoadOPBasis(IssueState=defInteger)`。Product lookup 回填 ProductNo、ProductVersion、ProductName。
- MO／Lot 的 lookup 方法仍存在，但各自按鈕在 Designer 設為 `Visible=False`；畫面上的欄位可直接輸入。隱藏的 Lot lookup 會先用 `wsWIP.LoadLotState(Status=3)` 載入 Hold Lot 清單。
- Query 不阻擋空條件；Form 不提供日期、狀態選單、明細視窗或寫入操作。Close 返回主畫面。

## Service／Core 查詢

- Service 解析 Status 與 RO／MO／Product／ProductVersion／Customer／Lot／OP／OrgLot／PS 條件後呼叫 Core。ReportMode 會令 Core 使用 report connection。
- Core 主查詢從 `tblWIPLotState A` join `tblWIPLotBasis B`（BaseLotNo），left join `tblOPBasis C`（OPNo）、`tblPRSProcessBasis D`（ProcessNo／ProcessVersion）、`tblENTCustomerBasis F`（CustomerNo），並 inner join `tblPRDProductBasis E`（ProductNo／ProductVersion）。固定條件另有 `A.LotNo IS NOT NULL`。
- Status 篩選作用於 `A.Status`，此 Form 固定為 3；沒有 RT501 的 `B.LotState=1` 限定或 Status 11／12 庫存條件。
- RONo、MONo、ProductNo、OrgLotNo 使用 `LIKE`；ProductVersion 使用 `IN`，CustomerNo、OPNo、PSNo 使用等值；LotNo 以 `|` 分隔多值後使用 `IN`。Core 直接串接 SQL，沒有分頁、結果上限或排序。
- Form 移除多餘欄位，只保留 ProductNo、ProductName、ProductVersion、LotNo、OPNo、BRNo、Status、CurQty、CurUnitNo，再加入 StatusShow；Grid 隱藏數字 Status 並顯示文字，CurQty 格式為 `0.####` 靠右，LotNo／OPNo 設升冪排序。ProductName 與 ProductNo 在來源 Layout 都指定 visible position 0，DEV 以清楚的九欄順序呈現並保留這個來源差異。
- 查詢結果為唯讀 Hold Lot 清單，沒有自訂列選取後的按鈕或 Detail 呼叫。`StatusShow` 對 3 顯示 `Hold`。

## DDL 與家用端交接

- 主查詢 `TBLWIPLOTBASIS`、`TBLWIPLOTSTATE` 的 MESTEST source DDL 沿用 `database/reference/mestest_wip_wp101_source_ddl.sql`；Product、Customer、Process 的 DDL references 亦可在 `database/reference` 對應 source 檔找到。本項不需新增 CREATE-only 表。
- `TBLOPBASIS` 的資料表字典 source DDL 未找到；`mestest_first_phase_create_tables.sql` 對其欄位有推測標記，不可當作 Oracle source CREATE-only。桌機目前沒有受保護 Oracle profile，本次未查 Oracle metadata。家用端先核對 YMES live catalog 與 lookup API，不因假資料建立 lookup schema。
- 家用端建議提供登入／RPT FunctionNo `HOLD LOT` 授權保護的唯讀 `GET /api/reports/hold-lots`。伺服器固定套 `A.Status=3` 且不加 RT501 的 LotState 條件；支援 roNo、moNo、productNo、productVersion、customerNo、lotNo、多值 LotNo、opNo、orgLotNo、psNo。實作需參數化、穩定排序、分頁及筆數上限；不能接受前端 SQL／AdditionalXml，也不照搬空條件全量查詢。
- 家用端先確認 `TBLWIPLOTSTATE`／`TBLWIPLOTBASIS` 正式同步來源及 live schema，再核實 lookup 所需 join 欄位、索引與權限。公司端未連 YMES PostgreSQL、未實作正式 API/schema、未部署。
