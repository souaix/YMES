# RT601 生產批使用物料查詢

## 功能與入口

- 清冊 FunctionNo `MATERIAL QUERY BY LOT`、FunctionKey `RT601`、Form `frmCont_Material_byLot`，標題為 `Material Content`，分類「資源」。Vue 入口：`/YMES/RPT/ContMaterialByLot`。
- 唯讀查詢。DEV 頁以虛構資料展示原生 16 欄 Grid、Lot No 輸入、Query、欄位排序與 Close；不連 API／Service、Oracle 或 PostgreSQL。初始不查詢。

## WinForms、Service、Core

- Form／Designer 內嵌於 `D:\iMES\CSiMES\STD\MESWin\RPT\RT_Cont_Material_byLot\frmCont_Material_byLot.vb`。載入只設定 Grid 使用者／Layout identity，不自動載資料。畫面只有 Lot No 輸入、Query、Close；Lot 選取按鈕存在但 `Visible=False`。離開 Lot 欄位時轉大寫。
- Query 呼叫 `wsWIP.LoadCont_Material_JoinLog`，傳 `LotNo` 與 `ReportMode=True`。Service 也能讀 OPNo、MaterialType、MaterialNo、MaterialLevel、AdditionalXml、StartDeductDate、EndDeductDate，但本 Form 沒有這些篩選欄位。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcWIP\clsLot.cs` 的 `LoadCont_Material_JoinLog`。ReportMode 使用 report connection。LotNo 有值時以 `TBLWIPCONT_MATERIAL`、`TBLWIPCONT_MATERIALLOT`、`TBLWIPLOTLOG_REPORT` 各自的 `LogGroupSerial LIKE LotNo + '%'` 限縮，再以 `LotLog_Report.LotNo = LotNo` 精確比對；連接作業站、目前 IssueState=2 的物料及同產品版次的產品名稱。
- Core 將 SQL 條件字串直接串接。LotNo 空白時進入未限 Lot 分支，只保留 `LogGroupSerial IS NOT NULL`，會讀大量資料；新 UI/API 必須要求 LotNo 並採參數化、結果上限及穩定排序。Form 的 Lot picker 隱藏，不應為了 DEV 增加未在畫面提供的 lookup。
- `TBLWIPCONT_MATERIALLOT` join 只用 `(LogGroupSerial, MaterialNo)`，未含 LotSerial／MaterialLotNo。該來源表沒有 PK／unique，可能使資料列展開或重複；正式 API 應核對來源結果與鍵值，不能在 UI 任意去重。

## Grid 欄位

Form 從 Core 回傳資料只保留並依序顯示：

`OPNo`、`OPName`、`MONo`、`MaterialType`、`MaterialNo`、`MaterialName`、`UseQty`、`UnitNo`、`MaterialLotNo`、`ProductNo`、`ProductName`、`LotQty`、`EquipmentNo`、`Description`、`CheckInTime`、`CheckOutTime`。

`UseQty` 來自物料耗用表；`LotQty`／`MaterialLotNo` 來自物料批次關聯；其餘工單、Lot、作業站、產品與設備欄位依 Core join 回傳。日期顯示格式為 `yyyy/MM/dd hh:mm:ss`，`UseQty`／`LotQty` 靠右。

## DDL 與家用端 API handoff

- 已有可沿用的 Oracle source DDL／PostgreSQL CREATE-only references：`database/reference/mestest_wip_wp201_dependency_source_ddl.sql`（`TBLWIPCONT_MATERIAL`、`TBLWIPLOTLOG_REPORT`）、`database/reference/mestest_wip_wp112_tblwipcont_materiallot_source_ddl.sql`／`mestest_wip_wp112_create.sql`、`mestest_mtl_master_source_ddl.sql`／`mestest_mtl_master_create.sql`、`mestest_prd_product_basis_source_ddl.sql`／`mestest_prd_product_basis_create.sql`、`mestest_operation_and_system_source_ddl.sql`／`mestest_operation_and_system_create.sql`。本項沒有缺少的直接表 DDL，因此公司端未另連 Oracle，亦不新增 CREATE SQL。
- 建議家用端提供登入保護、參數化、唯讀 `GET /api/reports/lot-materials?lotNo=...&page=1&pageSize=100`。LotNo 必填且精確比對；拒絕空白／萬用字元；限制每頁筆數並穩定排序。回傳上述 16 欄及 `hasMore`／分頁資訊；若來源無唯一資料列鍵，需先定義可重現的 row identity，避免假設 sort 能消除 join 重複。
- 公司端未連 YMES PostgreSQL、未實作／驗收正式 API／schema、未 build／test／browser。正式業務列及 API 錯誤處理由家用端取得 live schema 後確認。
