# RT410 設備稼動查詢

## 功能與入口

- 清冊項目：`EQP DAILY REPORT`，顯示名稱「設備稼動查詢」，分類 RPT／在製品，Function No `RT410`。
- Vue DEV 入口：`/YMES/RPT/EqpDailyReport`。假設備、狀態百分比、產量、查詢與 lookup 都在瀏覽器記憶體中模擬；不呼叫正式 API、Oracle 或 PostgreSQL。
- 唯讀報表。Form 的 Info 按鈕另開 `RT_Information`，不屬於設備稼動查詢資料流程。

## WinForms、Service、Core

- Form：`D:\iMES\CSiMES\STD\MESWin\RPT\RT_EQPDailyReport\frmEQPDailyReport.vb`，Designer 內嵌同檔。載入時不自動查詢；起訖時間預設為昨天 00:00 到今天 00:00，載入設備狀態主檔與 `ChamberManage` 系統參數，並依狀態主檔的 StateType／EquipmentState 排序建立色彩圖例。
- 篩選條件：可勾選 AreaNo（`wsSMD.LoadAreaBasis(AreaClass=0)` 單選）及 EquipmentNo（`wsEQP.LoadEquipmentBasis(IssueState=2)` 多選、逗號分隔；`ChamberManage=0` 時 lookup 限 `ChamberFlag=0`），設定 StartTime／EndTime 後按 Query。輸入設備編號自動勾選，取消勾選清空；設備編號離開欄位轉大寫。AreaNo／EquipmentNo 值由選取窗回填。
- 初始化資料 Service：`wsEQP.LoadEQPStateBasis`、`wsSYS.LoadParameter(ParameterNo="ChamberManage")`。Query 呼叫 `wsRPT.LoadEQPDailyReport`，送入可選 AreaNo／EquipmentNo、StartTime／EndTime 與 `ChamberFlag=0`。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcRPT\clsReport.cs` 的 `LoadEQPDailyReport`。以 `tblEQPEquipmentBasis` 為設備列；透過 `tblSMDAreaRelation` 的 ObjectType=2 查 AreaNo；依 `tblEQPStateBasis` 動態產生各 StateName 欄。狀態百分比為每個狀態重疊秒數除以查詢區間秒數，四捨五入兩位。狀態來源為 `tblEMSEquipmentStateLog UNION ALL tblEMSEquipmentState`；目前狀態以 SysDate 作結束時間。另以 `tblWIPCont_Equipment.LogGroupSerial` join `tblWIPLotLog_Report.LogGroupSerial`，將區間內已結束記錄的 GoodQty 加總為 Moves。
- Core 以字串串接 AreaNo、EquipmentNo、日期和狀態值；EquipmentNo 被組成 SQL `IN (...)`。家用端 API 必須用參數化查詢，並將設備編號拆為受驗證的清單。Core 未做分頁，也未限制期間長度。
- `ChamberManage=1` 時 Form 再呼叫 `wsRPT.LoadData_SonEQPData`，以 `ChamberFlag=1` 載入子設備，依主設備 EquipmentNo 與子設備 BelongEquipmentNo 建立巢狀資料列。主設備額外新增 `LotQty_EQP` 欄，值複製自 Moves。點選設備列後顯示各狀態圓餅圖；未滿 100% 的差額以 Loss 顯示，無狀態資料時顯示 NoData。ChamberManage=0 時只顯示主設備狀態圓餅圖。
- SQL 邊界疑點：主設備 `LoadEQPDailyReport` 的狀態子查詢限定 `A.EndTime <= 查詢 EndTime` 且 `A.EndTime > 查詢 StartTime`，因此結束於區間之後的進行中狀態不會納入；子設備 `LoadData_SonEQPData` 則使用 `A.StartTime <= 查詢 EndTime` 且 `A.EndTime > 查詢 StartTime`。主、子設備的區間條件不同，且查詢區間秒數若為 0 會發生除數問題。請家用端先核對這是舊程式缺陷或刻意規則，不要默默改成其他口徑。

## Vue DEV 行為

- 查詢條件版面仿原 Form：AreaNo 選取窗、EquipmentNo 多選／可輸入逗號清單、日期時間範圍、Query／Close。日期預設昨天至今天 00:00；初始不查詢，起訖無效時顯示錯誤。
- DEV 假 lookup 提供 3 個區域、主設備及 Chamber 子設備。狀態圖例、動態狀態欄、設備 Moves、點列選取後的環形占比圖均以固定假資料顯示；`ChamberManage` 用 DEV 開關模擬系統參數，啟用後可以展開子設備，並顯示舊 Form 的 LotQty_EQP 欄。
- DEV 的篩選、排序與百分比使用固定樣本，不代表實際產線結果或資料庫計算。空狀態樣本可展示 NoData／Loss；正式 API 應驗證 StartTime < EndTime、限制最大查詢期間及回傳列數。

## MESTEST DDL 與家用端 API handoff

- Repo 已有 Oracle MESTEST 參照：`database/reference/mestest_wip_wp201_unresolved_source_ddl.sql`（`tblEQPEquipmentBasis`）；`database/reference/mestest_equipment_state_create.sql`（檔頭註明來源為 `MESTEST.TBLEQPSTATEBASIS` DBMS_METADATA DDL）；`database/reference/mestest_wip_wp305_source_ddl.sql`（`tblEMSEquipmentStateLog`、`tblEMSEquipmentState`、`tblWIPCont_Equipment`）；`database/reference/mestest_wip_wp201_dependency_source_ddl.sql`（`tblWIPLotLog_Report`）；`database/reference/mestest_equipment_group_smd_source_ddl.sql`（`tblSMDAreaRelation`）。
- 本桌機沒有可用的受保護 Oracle profile，因此本項沒有新連 MESTEST 或補查索引；以上使用 repo 已存在的 Oracle 參照。這是唯讀報表，不新增本模組 CREATE／migration；家用端仍需比對目前 live schema、欄位、索引與查詢計畫。
- 建議唯讀 API：`GET /api/reports/equipment-daily-utilization`，輸入 startTime、endTime、可選 areaNo、equipmentNos[] 和 chamberManage；服務端驗證時間順序與最大區間，使用授權範圍、參數化 SQL、受限設備清單、穩定 EquipmentNo 排序及分頁／上限。主／子設備均需固定伺服器端 `ChamberFlag`，不接受前端 SQL 條件。
- 回傳主設備欄位：areaNo、equipmentNo、equipmentType、moves、statePercentages；啟用 ChamberManage 時另回傳 belongEquipmentNo 與 child equipment rows。狀態名稱／顏色可由既有設備狀態 master API 提供。主設備與子設備時間區間邏輯的差異須先核對後再決定是否相容。
- 公司端未連 PostgreSQL、未實作或驗收正式 API／schema，未 build／test／browser。
