# RT602 物料用於生產批查詢

## 功能與入口

- 清冊 FunctionNo `MATERIAL QUERY BY MATERIAL`、FunctionKey `RT602`、Form `frmCont_Material_byMaterial`，分類「資源」。Vue DEV 入口：`/YMES/RPT/MaterialUsageByMaterial`。
- RT602 是依物料／產品條件反查生產批物料耗用；它與 RT604「物料用於元件查詢」是不同 FunctionNo、不同 Form／Core 查詢，不共用同一頁。
- DEV 保留 Material No／Product No radio、萬用字元提示、獨立 DeductTime From／To 核取、lookup、11 欄 Grid、排序及 Close。資料與 lookup 都是固定虛構值，只在頁面記憶體篩選。

## WinForms、Service、Core

- Form／Designer 內嵌於 `D:\iMES\CSiMES\STD\MESWin\RPT\RT_Cont_Material_byMaterial\frmCont_Material_byMaterial.vb`。Material No 預設選取；radio 切換會清除兩個輸入，並唯讀／停用非作用中的欄位及 picker。載入時 From 預設一年以前、To 預設現在，兩個日期核取預設皆未選。時間上下界各自獨立。
- Material No picker 以 `frmCOMSearch_Page` 搜 `tblMTLMaterialBasis`，限 `IssueState=2`；Product No picker 呼叫 `wsPRD.LoadProduct_Dist`，IssueState 固定 2。Product picker 要求至少 3 個非 `%` 字元；選取後自動切至對應 radio。離開 Material／Product 輸入框時轉大寫。Form 顯示 `%` 萬用字元提示。
- Query 呼叫 `wsWIP.LoadCont_Material_JoinLog`，傳 `MaterialNo`、`MaterialLevel`、可選 `StartDeductDate`／`EndDeductDate`、`ReportMode=True`。Material No 模式傳 MaterialLevel=0；Product No 模式把 ProductNo 文字放入同一個 `MaterialNo` 欄位並傳 MaterialLevel=1。
- Core 為 `D:\iMES\CSiMES\STD\MESkc\kcWIP\clsLot.cs` 的 `LoadCont_Material_JoinLog`。ReportMode 使用 report connection。MaterialNo 以等號比對 `TBLWIPCONT_MATERIAL.MaterialNo`，MaterialLevel 亦以等號比對；時間只對 `EventTime` 套用啟用的上下界，兩端含界值。舊 Core 沒有處理 `%` LIKE；UI 的萬用字元提示與實際查詢不一致。
- **Product No 來源差異／疑似缺陷：**Product No 模式將 ProductNo 當成 `MaterialNo` 傳給 Core；Core 仍查 `A.MaterialNo = 輸入值 AND A.MaterialLevel = 1`，沒有依 `TBLWIPLOTLOG_REPORT.ProductNo` 篩選。因此該模式依舊程式可能查無資料或回傳與畫面意圖不一致的資料。DEV 依畫面預期以 ProductNo 篩選，並在頁面／本文件明示簡化差異；家用端 API 應以 ProductNo join/report 欄位實作預期語意，不要複製錯誤參數映射，並等待來源資料核實。
- Form 未驗證查詢文字非空或日期起迄順序；新 UI 對空白條件與反向日期顯示錯誤，避免延續可能的空條件大範圍報表。DEV 的 Material／Product `%` 篩選是依畫面提示模擬，與現有 Core 的等號條件不同。

## Grid 欄位

Form 只保留並顯示 11 欄：`LotNo`、`OPNo`、`MaterialType`、`MaterialNo`、`UseQty`、`UnitNo`、`MaterialLotNo`、`LotQty`、`EquipmentNo`、`Description`、`EventTime`。預設依 LotNo 升冪；UseQty／LotQty 靠右；EventTime 顯示 `yyyy/MM/dd HH:mm:ss`。

## DDL 與家用端 API handoff

- 所需直接表／lookup 已有 repo refs：`database/reference/mestest_wip_wp201_dependency_source_ddl.sql`（`TBLWIPCONT_MATERIAL`、`TBLWIPLOTLOG_REPORT`）、`mestest_wip_wp112_tblwipcont_materiallot_source_ddl.sql`／`mestest_wip_wp112_create.sql`、`mestest_mtl_master_source_ddl.sql`／`mestest_mtl_master_create.sql`、`mestest_prd_product_basis_source_ddl.sql`／`mestest_prd_product_basis_create.sql`、`mestest_operation_and_system_source_ddl.sql`／`mestest_operation_and_system_create.sql`。本項沒有缺少的直接表 DDL，未新查 Oracle、未新增 CREATE SQL。
- 建議登入保護唯讀 API：`GET /api/reports/material-usage?mode=material|product&keyword=...&deductFrom=...&deductTo=...&page=1&pageSize=100`。mode/keyword 必填；時間上界各自可選且以 EventTime 含界值。Material／Product 應各用正確來源欄位與參數化條件；需給穩定排序、bounded paging 及回傳總筆數／hasMore。不要沿用 ProductNo 傳成 MaterialNo 的 legacy 缺陷。Lookup 只載 IssueState=2，ProductNo picker 的三個固定字元限制照 Form 保留。
- 本機受保護 Oracle 設定在本任務不需使用（直接表 DDL refs 已有）。公司端未連 YMES PostgreSQL、未實作／驗收正式 API／schema、未 build／test／browser；正向資料與 API 語意由家用端比對 live schema 後確認。
