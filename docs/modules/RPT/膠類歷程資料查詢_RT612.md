# RT612 膠類歷程資料查詢

## 功能與入口

- RPT FunctionNo GUM LOG QUERY、FunctionKey RT612、Form frmGumLogQuery。Vue DEV 入口：/YMES/RPT/GumLogQuery。
- 查詢膠料原始歷程快照，結果以 InventoryNo／MaterialNo／MaterialLotNo／UnitNo／MaterialType 分組，展開後看 EventTime、GumTypeStatus、Qty 歷程列。
- DEV 使用固定虛構庫房、材料、批號、狀態及歷程；MaterialNo lookup 的 GumMaterialType 也是假設定。只在瀏覽器記憶體做唯讀篩選，不呼叫 MES API、Oracle 或 PostgreSQL。

## WinForms、Service、Core

- Form／Designer 同檔：D:/iMES/CSiMES/STD/MESWin/RPT/RT_GumLogQuery/frmGumLogQuery.vb。啟動時讀系統參數 GumMaterialType、載入 IssueState=2 且 InventoryType=6 的庫房清單、初始化 GumTypeStatus ValueList。選庫房後 MaterialNo 欄才可輸入且開啟「...」lookup；lookup 查 TBLMTLMATERIALBASIS，條件為 MaterialNo 非空、IssueState=2、MaterialType 屬於 GumMaterialType。
- Query 不要求至少一項條件，也沒有日期起訖驗證。InventoryNo、MaterialNo 一律傳入；勾選 GumTypeStatus 才傳狀態；批號欄有勾且文字非空才傳前綴；勾選 Event Time 才傳起訖日期。LotNo 文字變成非空會自動勾選，清空文字時 Form 不會自動取消勾選，但空值不送批號條件。
- Inventory lookup 呼叫 wsSMD.LoadInventoryBasis，使用 IssueState=2、InventoryType=6。參數 lookup 呼叫 wsSYS.LoadParameter。查詢呼叫 wsINV.LoadWIPInventory_RawLog；Service 解析 InventoryNo、MaterialNo、GumTypeStatus、MaterialLotNoForLike、FromDate、EndDate 後轉給 clsInventory.LoadWIPInventory_RawLog。
- Core 使用主要 MES connection，先從 TBLINVWIPINVENTORY_RAWLOG 依 InventoryNo／MaterialNo／MaterialLotNo／UnitNo／MaterialType 分組建立 INVENTORY parent，再以相同條件讀明細建立 TIME child；DataRelation Relation1 使用前三個欄位作為 join key。兩段 SQL 都是字串串接，無排序及分頁。前端只將 TIME child 依 EventTime 降冪排列；ValueListProvider 的 GumTypeStatus 顯示名稱尚未由來源資料確認，DEV 顯示數值。
- Core 日期條件為 EventTime Between FromDate AND EndDate（含界值）；Form 只傳 yyyy/MM/dd，時間被轉成當日 00:00:00，因此結束日只查到該日午夜，未含結束日其餘時間。正式 API 應明確採用半開區間或完整日含界值，不能意外複製這個截斷。
- Form 的主資料 Grid 綁定 iugINVWIPInventory_RawLog，Relation1 隱藏三個 join key，顯示 EventTime／GumTypeStatus／Qty。Rows.ExpandAll 呼叫卻指向未加入 Form、未綁資料的 iugRAWInventory；DEV 以明確展開按鈕呈現 parent／child。程式內 funEdit_IVN_Raw_Split、funSetInventoryRawFrozen 雖呼叫寫入 Service，但 Form 沒有任何事件呼叫它們；本功能是歷程查詢，DEV 不提供回溫／回冰寫入操作。

## DDL 與家用端 API／schema handoff

- TBLINVWIPINVENTORY_RAWLOG 的可信 MESTEST source DDL／metadata 不在 repo；桌機受保護 Oracle attachment 不存在，未連 Oracle、未從讀寫 SQL 反推 CREATE-only。INV/IV212 handoff 也記錄此表缺 DDL。庫房及材料 lookup 可沿用既有 InventoryBasis／MTL master references，但不能代替 RawLog DDL。
- 家用端先核對 YMES PostgreSQL live schema、同步來源、複合父子 key、日期型別、GumTypeStatus 代碼和正向資料。若可支持，設計登入／RT612 ACL 保護的唯讀 API，回傳 parent＋歷程 child，child 依 EventTime 降冪；採參數化查詢、穩定 parent 排序、bounded paging／最大日期跨度。
- Legacy Core 無條件守門，空條件會查全表。正式 API 應要求庫房、材料、批號前綴、狀態或日期範圍中至少一項有效條件，並設合理資料上限；MaterialLotNo 是前綴比對。不要接受前端 SQL／AdditionalXml。
- 依權限回傳實際 GumMaterialType 與 GumTypeStatus lookup label。DEV 的 MaterialType／狀態資料、InventoryNo、MaterialNo 都是虛構值。
