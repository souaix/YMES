# RT607 預計完工查詢

## 功能與入口

- Menu FunctionNo PLAN FINISH TIME、FunctionKey RT607、Form frmPlanFinishTime_byLot。Vue DEV 入口：/YMES/RPT/PlanFinishTimeByLot。
- 使用者輸入 Lot No 查詢目前產品／版本、在製數量／單位及流程 Run Card 預計完成時間。Lot No 必填；離開欄位或送出時轉大寫，Enter 送出。Form 無 Lot picker。
- DEV fixture 僅有 LOT-RT607-001、LOT-RT607-002；固定虛構資料、本機記憶體估算，不連 API、Oracle 或 PostgreSQL。DEV 會呈現標準工時缺列時空白的來源情形。

## WinForms、Service、Core

- Form／Designer 同檔：D:\iMES\CSiMES\STD\MESWin\RPT\RT_PlanFinishTime_byLot\frmPlanFinishTime_byLot.vb。Query 清除前一筆 grid 及產品／數量資訊後呼叫服務；第一列回傳的 ProductNo、ProductVersion、CurQty、CurUnitNo 填入 Lot Information。
- Grid 顯示 ItemNo、OP No、OP Name、Queue Time、Run Time、Plan Finish Time、Module No、Module Version、Area No。時間欄格式 yyyy/MM/dd HH:mm:ss，時間值格式 0.##；其餘 Run Card 隱藏欄位不顯示。
- Service：D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsWIP\wsWIP.cs 的 wsWIP.LoadPlanFinishTime_byLot。解析必填 LotNo；ReportMode=True 時呼叫 clsLot.LoadPlanFinishTime_byLot(..., blnReportMode:true)，回傳 loadplanfinishtime_bylot DataTable XML。
- Core：D:\iMES\CSiMES\STD\MESkc\kcWIP\clsLot.cs 的 clsLot.LoadPlanFinishTime_byLot。用 LotNo 從 TBLWIPLotBasis／TBLWIPLotState 取 Product、Process、目前 OP／Node、CurQty、CurUnitNo、Module 與 OPReference；不存在的 Lot 會丟 MESException。ReportMode 使用 report connection。
- Core 接著呼叫 LoadRunCardData，以當前 Node／OP 展開 PASS 流程、跨後續 Process／Module 取得 Run Card；清除 TBLOPBASIS.PRINTOUTONRUNCARD=0 的作業站，再依流程 ItemNo 重排。後續流程從 TBLWIPLotProcess 依 ProcessOrder 取得；Run Card 展開還會查 TBLPRSProcessBasis、TBLPRSNodeBasis、TBLPRSNodeRelation、TBLOPBASIS、TBLPRDOPDescription、TBLPRDModuleBasis、TBLPRDProductProcess 等路由／作業資料。
- OPReference=0 時標準工時參照 Lot 的 ProductNo／ProductVersion；OPReference=1 時參照該列 ModuleNo／ModuleVersion；其他值跳過工時計算。查 TBLPRDRunTimeSetup 的條件只有 ProductNo、ProductVersion、OPNo。RunTime = StdUnitRunTime（CountOPUnitQty<=0）或 StdUnitRunTime×CurQty/CountOPUnitQty；逐站累加 StdQueueTime+RunTime（分鐘），起點為 Core 執行當下的 DateTime.Now。
- 工時設定不存在時，Core 保留 Run Card 列但 QueueTime、RunTime、PlanFinishTime 為空，且不推進累計時間，因此後續預估可能低估；這是 legacy 行為，DEV 保留並以空值顯示。OPReference 非 0／1 亦不進行計算。
- AreaNo 先查 TBLWIPLotOPArea (LotNo, NodeId)，無列時查 TBLPRDOPArea (產品／模組、版本、OPNo、DefaultArea=1)，仍無則填 *。工時設定缺列會先跳至下一列，該列 AreaNo 也留空。

## DDL 與家用端 API／schema handoff

- 可沿用已在 repo 的 MESTEST source DDL：TBLWIPLotBasis／TBLWIPLotState／TBLWIPLotProcess（database/reference/mestest_wip_wp101_source_ddl.sql）；TBLPRSProcessBasis／TBLPRSNodeBasis／TBLPRSNodeRelation（mestest_prs104_process_basis_source_ddl.sql）；TBLOPBASIS（mestest_operation_and_system_source_ddl.sql）；TBLPRDOPDescription（mestest_prd_op_description_source_ddl.sql）；TBLPRDRunTimeSetup（mestest_prd_run_time_source_ddl.sql）；TBLPRDOPArea（mestest_prd_parameter_setup_source_ddl.sql）；TBLWIPLotOPArea（mestest_wip_wp201_dependency_source_ddl.sql）；TBLPRDModuleBasis／TBLPRDProductProcess（mestest_prd_module_basis_source_ddl.sql、mestest_prd_product_basis_source_ddl.sql）。
- 現有 runtime source DDL 顯示 TBLPRDRUNTIMESETUP 必填 AREANO，且無已報告 PK／unique/index；Core 工時查詢卻不含 AreaNo，僅讀第一列。多 Area 設定時預估不確定，須由家用端依 live PostgreSQL schema、同步資料及正式資料決定是否按 AreaNo 精確取值或沿用此 legacy 差異。
- Core 逐站以固定 CurQty 套用每個 OP 的比例工時，沒有班別／日曆／設備容量／等待排程計算；估算起點是當次請求時間。舊查詢條件以字串組合，正式 API 不應照搬。
- 建議家用端核對上述資料表與正式同步後，實作登入及 RT607 FunctionKey ACL 保護的唯讀 GET /api/reports/plan-finish-time?lotNo=...。LotNo 必填且參數化；回傳 lot header 與依 Run Card ItemNo 排序的列。確認 AreaNo 語意、缺少 runtime setup 的可見狀態與累加策略，再決定正式預估是否保留 legacy undercount。不可接受前端 SQL／AdditionalXml。
- 本次未新增資料表，沒有 CREATE-only SQL 需求；公司端未連 PostgreSQL、未實作／驗收正式 API／schema、未執行 Oracle 查詢。上述依賴的 source DDL 均已有 repo reference；沒有無法取得的 DDL。
