# RT501 生產批狀態查詢

## 家用端正式唯讀 API 與 schema（2026-11-27）

- 正式端點：登入保護 `GET /YMES/API/api/reports/confirm-lots`。接受 `roNo`、`moNo`、`productNo`、`productVersion`、`customerNo`、`lotNo`、`opNo`、`orgLotNo`、`psNo`、`page`、`pageSize`；文字 pattern 以參數化 `ILIKE` 比對，Lot No／Product Version 可用 `|` 傳多值。
- 固定條件為 Basis `LotState=1`；Status 只列 0–5、11、12。Status 11 按 BaseLotNo 彙總 SEMI Qty 後判斷總量大於零；Status 12 按 BaseLotNo 彙總 ScrapQty／LossQty，或存在 FailBin／ComponentScrap。所有篩選與庫存條件均在 SQL 內參數化，前端不能傳 SQL。
- API 必須至少提供一項條件；每頁最多 100 筆、頁碼上限 10,000，以 `hasMore` 回報後續頁，排序固定 LotNo／OPNo／Status。採 RepeatableRead 唯讀交易。回傳 ProductNo、ProductName、ProductVersion、LotNo、OPNo、BRNo、Status、CurQty、CurUnitNo。
- 正式 YMES catalog 確認 WIP／Product／Operation／Process／Customer 主檔與 `tblinvwipinventory_semi` 已存在，`ymes_app` 有 SELECT；缺少 `tblinvwip_scrap`、`tblinvwip_failbin`、`tblinvwip_componentscrap`，其他 schema 也無同名來源表或衝突索引。依 WP201／WP603 PostgreSQL CREATE-only refs 套用 [0078 migration](../../../database/migrations/0078_rpt_rt501_confirm_lot_read_schema.sql)：只建立三張空表、來源索引與 BaseLotNo 查詢支援索引，僅授 `ymes_app` SELECT，沒有複製／新增 MES 業務資料列。正式庫未以報表 API 回傳真實生產批正向資料。
- migration 前備份 `/opt/ymes/backups/ymes-before-rt501-20261127.dump`，758,044 bytes、SHA-256 `bdb5a6b93fdef18e0a972f5ed79ea236b67727a6cae0e7416c7f870812d56583`，`pg_restore --list` 通過；0078 SQL SHA-256 `b6c993e5fc2b6bb8f73c2ff3e6db1711926c16181aff10fce9211335fe4650d6`。候選／狀態彙總 SQL 已在正式 PostgreSQL `EXPLAIN` 驗證。
- .NET 9 Release 發布成功；只有 NuGet vulnerability feed 無法連線的 `NU1900` 警告。API image `ymes-api:rt501-20261127-a2`，ID `sha256:b78ebdafce04e378b9697768af2ef9e68e0ade9f82db6090efcf8dc174606880` 已更新正式 `ymes-api`。上一版 a1 image 以 `ymes-api:before-rt501-a2-20261127-a1` 保留；readiness=200、未登入 endpoint=401，Web／master Web／其他服務 image 未變。
- 正式 app-browser Demo session：帶不可能命中的 MO 查詢回 200 `items=[]`；Lot No `|` 多值查詢回 200；空條件、每頁 101 筆與超長 Product Version 均回 400。DEV app-browser 驗證選單入口、無條件假資料、MO 條件、Customer／Product／PS／OP 四種 lookup、自動勾選與取消清空、Lot No 多值、OrgLot wildcard、排序、Status 11／12 篩選、列選取、LotProperty／CompProperty 視窗及 Close 返回主頁。DEV 查詢僅用合成資料。
- 正式 `ConfirmLot.vue` 目前仍顯示未開放 placeholder，DEV 頁也尚未呼叫正式 API。公司端後續需將同一表單接上此端點及既有 lookup API；使用者／API/schema 工作交接詳 `todolist_officepc.md`。

## 範圍與入口

- 功能清冊：`CONFIRM LOT`，顯示名稱「生產批狀態查詢」，分類 RPT／生產批，Function No `RT501`。
- Vue DEV 入口：`/YMES/RPT/ConfirmLot`。結果和 lookup 都使用有限記憶體假資料，不呼叫正式 API、Oracle 或 PostgreSQL。
- 這是唯讀報表。表單的兩個屬性按鈕只開 Lot Property／Component Property 視窗，沒有在此 Form 執行寫入。

## WinForms、Service、Core

- Form：`D:\iMES\CSiMES\STD\MESWin\RPT\RT_LotState\frmLotState.vb`。Designer 程式碼內嵌在同一 `.vb`；標題 Confirm Lot，最大化。初始只初始化 Grid 與狀態 ValueList，不自動查詢；使用者按 Query 才載入資料。
- 查詢條件有 Customer No、RO No、Product No／Product Version、MO No、PS No、Org Lot No、OP No、Lot No。各條件旁有 CheckBox；編號有值會自動勾選，取消勾選會清空該值。Customer／Product／PS／OP 使用 lookup 視窗；RO／MO／OrgLot／LotNo 可直接輸入。MO／Lot 的 `btnGet`／`btnGet1` 在 Designer 設為隱藏。RO、MO、OrgLot、LotNo 離開欄位時轉大寫。Product／Customer／PS／OP 欄唯讀，依 lookup 選取。
- Lookup Service：MO 使用 `wsWIP.LoadMOBasis(MOState="3")`；Customer 使用 `wsENT.LoadCustomerBasis`；Product 使用 `wsPRD.LoadProduct`（選取視窗可挑 ProductNo／Version／Name）；PS 使用 `wsPRS.LoadProductionSegment`；OP 使用 `wsOP.LoadOPBasis`。這些只供條件選取，主結果查詢仍由 WIP Service 完成。
- 主查詢固定傳 `LotState="1"`（Confirm）與 `ReportMode=True`；只在勾選且有值時傳送表單欄位。Form 同時附加 LotState 表 Status 條件：Status 0–5 一律可列；Status 11 須 `tblINVWIPInventory_SEMI` 有 Qty>0；Status 12 須 `tblINVWIP_Scrap` 有 ScrapQty／LossQty，或存在於 `tblINVWIP_FailBin`／`tblINVWIP_ComponentScrap`。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsWIP\wsWIP.cs` 的 `LoadLotBasisJoinState`，解析通用 Lot 查詢參數和 AdditionalXml，呼叫 `kcWIP.clsLot.LoadLotBasisJoinState`。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcWIP\clsLot.cs` 的 `LoadLotBasisJoinState`。Report Mode 使用 report connection。主查詢從 `tblWIPLotState A` join `tblWIPLotBasis B`（BaseLotNo），left join `tblOPBasis C`（OPNo）與 `tblPRSProcessBasis D`（ProcessNo／ProcessVersion），inner join `tblPRDProductBasis E`（ProductNo／Version），再 left join `tblENTCustomerBasis F`（CustomerNo）。結果為 `A.*`、`B.*` 和 OP／Process／Product／Customer 顯示資料，套用 Form 的 LotState、Status、各條件及 AdditionalXml。
- Core 字串串接查詢條件。RONo、MONo、ProductNo、OrgLotNo 使用 `LIKE`（只有使用者輸入 `%`／`_` 時才有 pattern 行為）；CustomerNo、OPNo、PSNo 使用等值；LotNo 支援以 `|` 分隔多值；ProductVersion 亦以 `|` 分隔。家用端必須將篩選值參數化，並將 AdditionalXml 改成固定的狀態／庫存條件，不接受前端 SQL。
- Form 保留 `ProductNo`、`ProductName`、`ProductVersion`、`LotNo`、`OPNo`、`BRNo`、`Status`、`CurQty`、`CurUnitNo`，其餘 Core 欄位移除。Grid 欄位設 ProductNo 與 ProductName 都為 visible position 0（來源重複設定）；ProductVersion、LotNo、OPNo、BRNo、Status、CurQty、CurUnitNo 後續指定 position 1–7。LotNo／OPNo 都標為遞增排序；CompQty 顯示同類數量格式 `0.####` 並靠右。Status ValueList 由 `TBLWIPLOTSTATE.STATUS` 動態載入。
- Form 註解列出狀態 0 Queue、1 Running、2 Wait、3 Hold、4 Complete、5 OS、11 INV、12 Scrap Inv、99 Closed。另有程式註解說明狀態 6 可由 ValueList 顯示，但本 Form 的 AdditionalXml 仍只允許 0–5、11、12，因此 6 不會通過目前查詢條件；DEV 遵照實際條件排除 6／99，並把差異留給家用端。
- 選取結果後 `LotProperty` 透過 ObjectFileHandler 執行 `RT_Property`，傳 LotNo 和 `blnReportMode=True`；`CompProperty` 也執行 `RT_Property`，傳 LotNo、Status、ReportMode，目標 form 為 `frmComponentProperty`。DEV 以選取列的假資料顯示兩種唯讀明細提示，不重做這兩個獨立屬性模組。

## Vue DEV 行為

- 提供八個可勾選的篩選條件、Customer／Product／PS／OP 假 lookup、Product Version／Name 顯示、CheckBox 自動隨編號輸入勾選及取消時清空值。按 Query 後固定套用 Confirm LotState=1 和上述 Status／庫存條件；各條件按 Core 語意比對。空白條件仍回傳有限 DEV 假資料並提醒 Legacy 會執行較大的查詢，正式 API 應要求至少一個限制條件或強制分頁／筆數上限。
- Grid 顯示九個來源欄位；DEV 以 ProductNo、ProductName、ProductVersion、LotNo、OPNo、BRNo、Status、CurQty、CurUnitNo 固定呈現（將原始 duplicate visible position 簡化為可讀順序）。依 LotNo、OPNo 遞增排序，點列選取後可開 LotProperty／CompProperty 假資料詳情。查詢結果唯讀；Close 返回主畫面。
- DEV 固定假資料涵蓋狀態 1–5、11／12 庫存條件，以及 Status=99 被排除；不模擬實際附件、報表資料庫或批屬性資料。

- 回傳欄位：productNo、productName、productVersion、lotNo、opNo、brNo、status、curQty、curUnitNo。Lookup 使用既有受授權的 Master API 或等價選取端點；Lot／Component Property 另依各自模組接續，不把假明細當正式屬性 schema。
- 公司端未連 PostgreSQL、未實作或驗收正式 API／schema，未 build／test／browser。
