# RT604 物料用於元件查詢

## 範圍與入口

- 功能清冊：`COMP MATERIAL BY MATERIAL`，顯示名稱「物料用於元件查詢」，模組 RPT／資源，Function No `RT604`。
- Vue DEV 入口：`/YMES/RPT/ContMaterialByMaterial`。本頁使用記憶體假資料，不呼叫 Oracle、正式 API 或資料庫。
- RT604 與 RT603 共用 WIP 查詢 Service/Core，但條件、欄位排序和可見 Grid 欄不同，兩者是不同功能。

## WinForms、Service、Core

- Form：`D:\iMES\CSiMES\STD\MESWin\RPT\RT_Cont_CompMaterial_byMaterial\frmCont_CompMaterial_byMaterial.vb`。`InitializeComponent`／Designer 程式碼內嵌在 `.vb`，沒有獨立 Designer 檔。畫面最大化；查詢區含 Material No／Product No Radio、兩個編號文字欄與「…」選取鈕、MaterialLot No、Query；結果區為 iMESUltraGrid 與 Close。
- 預設 Material No Radio。切換 Radio 會清空兩種編號欄位，將非作用欄設為 ReadOnly，並停用其選取鈕。來源沒有在 Load 中明確初始化這組狀態；DEV 依預設 Radio 對應的邏輯初始化 Material 可編輯、Product 唯讀。
- Material No 的「…」呼叫 `wsMTL.LoadMaterialBasis`，帶 `IssueState=defInteger`，並用 `frmCOMSearch` 依 `MaterialNo` 選取；Product No 的「…」呼叫 `wsPRD.LoadProduct_Dist`，同樣帶 `IssueState=defInteger`，依 `ProductNo` 選取。選取結果會切到對應 Radio 並填入編號。
- 編號欄與 MaterialLot No 欄 Enter 時全選、Leave 時轉大寫。Query 在 Material No 模式傳 `MaterialLevel=0`，Product No 模式傳 `MaterialLevel=1`；ProductNo 值仍傳給 Service 的 `MaterialNo` 參數，沒有獨立 ProductNo 查詢條件。MaterialLotNo 非空才傳入；兩模式都傳 `ReportMode=True`。來源沒有空值驗證或分頁。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsWIP\wsWIP.cs` 的 `LoadCont_MaterialLotComp_JoinLog`，解析 `MaterialNo`、`MaterialLevel`、可選 `MaterialLotNo` 及 `ReportMode` 後呼叫 `tcWIP_IC.clsLot`。
- Core：`D:\iMES\CSiMES\STD\MEStc\tcWIP_IC\clsLot.cs` 的 `LoadCont_MaterialLotComp_JoinLog`。與 RT603 共用 `tblWIPLotBasis A`、`tblWIPLotLog B`、`tblWIPCont_MaterialLotComp C`，join 為 `A.BaseLotNo = B.BaseLotNo`、`B.LotSerial = C.LotSerial`；條件非預設時加 `C.MaterialNo`、`C.MaterialLevel`、`C.MaterialLotNo`。
- Core 回傳 MONo、BaseLotNo、LotNo、OPNo、MaterialType、MaterialNo、MaterialLotNo、ComponentNo、CompQty、UnitNo。Form 對 DataView 套用 `MONo, BaseLotNo, OPNo, ComponentNo` 排序。Grid 可見欄依序為 MO No、BaseLot No、OP No、Component No、MaterialLot No、Comp Qty、Unit No、Material Type；`LotNo`、`MaterialNo` 隱藏。CompQty 顯示 `0.####` 並靠右，GroupBy 區隱藏。
- Core 以字串串接 SQL；正式 API 必須用參數化查詢。MaterialNo 空白時 Core 仍依傳入的 MaterialLevel 篩選，但可能回傳該層級的大量資料；正式 API 應要求編號非空並設回傳筆數上限。

## Vue DEV 行為

- 初始選 Material No；Radio 切換時清空 Material No 與 Product No。只有作用中的編號欄與「…」按鈕可用；物料和產品選取窗以有限假清單模擬 `LoadMaterialBasis`／`LoadProduct_Dist`。選擇後填入編號。MaterialLot No 可選，離開欄位轉大寫。
- Query 依 MaterialLevel 0／1 及可選 MaterialLotNo 篩選假資料。空白編號會顯示該層級有限的假資料並解釋 Legacy Core 的條件行為；DEV 提示不代表正式 API 接受空值。按 MO No、BaseLotNo、OPNo、ComponentNo 排序；行點選模擬 Grid 選取，Close 返回主畫面。
- MaterialNo／LotNo 依原 Grid 設定隱藏。查詢結果唯讀，沒有新增／修改／刪除。選取窗與按 Enter 查詢以外的互動依來源控制設計；本 DEV 未新增 Enter 即 Query 行為。

## 資料字典與家用端 API/schema handoff

- RT603／RT604 共用上述三張表；repo 的 `database/reference` 未找到 `tblWIPLotBasis`、`tblWIPLotLog`、`tblWIPCont_MaterialLotComp` 的可信 MESTEST 原始 DDL／metadata。桌機受保護 Oracle profile/attachment 不存在，因此未執行 Oracle 查詢，也沒有猜測 PostgreSQL 型別、主鍵、nullability、索引或 CREATE-only SQL。
- 建議唯讀 API：`GET /api/reports/material-component-usage?materialNo={value}&materialLevel=0|1&materialLotNo={optional}`。驗證授權使用者資料範圍、要求 MaterialNo 非空及 MaterialLevel 僅限 0／1，使用參數化三表 join，支援可選 MaterialLotNo、固定穩定排序與分頁／最大筆數。
- 回傳欄位沿用 Core 的十個輸出欄位；確認 YMES live schema 的欄位大小、數值精度和資料來源後再定 DTO／SQL。從可信 DDL／metadata 及 live schema 確認三表關聯鍵與查詢計畫後，才決定 join/filter 索引；DDL 未取得前不可提供 CREATE-only SQL。
- 公司端未連 PostgreSQL、未實作或驗收正式 API／schema，未 build／test／browser。
