# RT417 生產批下線後歷程總表

## 選單與原始來源

- 選單：RPT → 在製品 →「生產批下線後歷程總表」，FunctionNo `LOT RELEASE LOG`、FunctionKey `RT417`，Form `frmRPTLotReleaseLog`，執行檔 `RT_LotReleaseLog.dll`。
- Form／Designer：`STD/MESWin/RPT/RT_LotReleaseLog/frmRPTLotReleaseLog.vb`。Form 與版面控制項寫在同一檔，沒有獨立 `.Designer.vb`。CSiMES、THEIL、DEV_SILVA 三份 Form 的 SHA256 相同：`B768D9D54EABEF51393EFD7461A6E07FABB76502D2E47288243B512F0FA9F9CC`。
- 主查詢：`wsRPT.LoadReleaseLog_Report` → `kcRPT.clsReport.LoadReleaseLog_Report`。
- 明細：`wsWIP.LoadReleaseLog` → `kcWIP.clsLot.LoadReleaseLog_Component`／`LoadReleaseLog_BIN`；分併批另呼叫 `LoadSplitContent`／`LoadMergeContent`。

## Form 查詢與操作

- 條件：Lot No、MONo、ProductNo、OP No、User No、UserActiveID、ProcessDate 起迄、Show ERF、Show Wait。Lot/MO/User 可輸入；ProductNo、OPNo、UserActiveID 由多選視窗回填逗號分隔值。Customer、Equipment、Accessory、Component 等欄位在此 Form 已註解，沒有可用查詢控制項。
- 起始時間預設為今天 07:30；若載入時間早於今天 07:30，預設改昨天 07:30。結束時間為現在。ProcessDate checkbox 初始未勾選，使用者需勾選日期，或輸入 LotNo／MONo 以略過日期必填檢查。勾選日期時仍送起訖時間。開始必須早於結束，未設最大區間。
- 若 Form 建構時帶入 LotNo 或 OPNo，會預設最近一年、立即查詢並鎖住查詢條件區。一般查詢以 ProcessDate checkbox 作為是否加 EventTime 條件；LotNo／MONo 被勾選且非空時跳過日期檢查。
- UserActiveID 候選來自系統 `TBLWIPRELEASELOG.USERACTIVEID` value list；Form 建立選擇清單時排除代碼 20。代碼 0–19 分別為 START、CI、CO、SPC、SPLIT、MERGE、CHANGEPRD、DELETE、REVERSE、HOLD、HOLDRELEASE、WAIT、WAITRELEASE、INVENTORY、INVCANCEL、TURNINVENTORY、RERUN、CLOSE、QTYADJUST、INVDELETE。
- 選取主 Grid 列會呼叫 `wsWIP.LoadReleaseLog`，用 LotSerial、LogGroupSerial、Component=1、Bin=1 讀取 Component 與 BIN 明細；主 Grid 依 EventTime、SysActiveSequence 排序。
- Form 的 `btnDetail_Click` 以 DType 分流：9 為 OP 歷程，1 為 ERF，2 為 Wait，3/4 為 Split From/To，5/6 為 Merge From/To。Split/Merge Form 呼叫 Service/Core 查資料，但結果 Grid 的 DataSource 綁定程式碼已註解，舊畫面不呈現該結果表。ERF／Wait 資訊表單由 `ObjectFileHandler` 載入；兩個 click handler 在此 Form 未找到明確事件綁定。

## Service／Core 與 SQL 條件

- `wsRPT.LoadReleaseLog_Report` 解析 ProductNo、OPNo、UserActiveID、MONo、LotNo、UserNo、ShowType、StartDateTime／EndDateTime 與 Additional XML，再傳給 `clsReport.LoadReleaseLog_Report`。
- Core 以 `TBLWIPRELEASELOG A` 為主，LEFT JOIN `TBLOPBASIS`、`TBLPRDPRODUCTBASIS`、`TBLWIPLOTBASIS`、`TBLPRSNODEBASIS`、`TBLPRSNODERELATION`，輸出批歷程欄位與 OP／產品／工單／製程名稱。依 EventTime、SysActiveSequence 排序。
- LotNo、MONo、UserNo 為精確條件；OPNo／UserActiveID 為逗號分隔的精確值集合。ProductNo 與 CustomerNo 雖用 `LIKE`，沒有加入 `%` 萬用字元，實際上仍等同精確比對。ProcessDate 篩選 EventTime。Form 本身不傳 Additional XML。
- ShowType 有舊註解與實際程式分歧：Form 未勾 ERF/Wait 傳 0，單勾 ERF 傳 9，單勾 Wait 傳 11，兩者都勾傳 3；Core 的實際條件是 0 選 UserActiveID 0–19、9 僅選 9/10、11 僅選 11/12、3 不加類型條件。因此「未勾」與「兩者都勾」都查全部，單勾則只查該類別。DEV 暫按實際 Core 分支模擬，API handoff 不應依註解推測。
- Core 另外接收 EquipmentNo 等參數，但 Form 控制項已註解；Core 只在 Oracle dialect 建立 Equipment 子查詢，非 Oracle dialect 未套 EquipmentNo 條件。AccessoryNo／ComponentNo 相關 SQL 也已註解。這些不能直接照搬成 YMES API 的有效篩選。
- Core 將篩選串成 SQL 字串，沒有分頁或日期跨度上限。正式 API 應參數化、限制日期範圍／頁大小並套用 RT417 授權，不能接受任意 Additional SQL。

- 家用端於 2026-11-27 以 PPK／SSH 只讀查正式 PostgreSQL catalog，確認上述五張表在所有 schema 均不存在；未讀業務列、未建表。可信 DDL／metadata 仍待公司端交付。
- 家用端先核對 YMES PostgreSQL live catalog、資料同步來源與權限，再決定空表 migration。唯讀 API 建議 `GET /api/reports/lot-release-log`，支援日期、LotNo、MONo、ProductNo、OPNo、UserNo、UserActiveID 及明確 ERF／Wait 條件，採參數化、分頁、日期／條件數上限與 Function ACL。ShowType 若採舊程式相容行為，須保留本節記載的實際分支；若修正為符合 checkbox 標籤的語意，需明確視為 bug fix。
