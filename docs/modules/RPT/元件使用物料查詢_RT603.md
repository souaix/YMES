# RT603 元件使用物料查詢

## 範圍與入口

- 功能清冊：`COMP MATERIAL BY COMPONENT`，顯示名稱「元件使用物料查詢」，模組 RPT／資源，Function No `RT603`。
- Vue DEV 入口：`/YMES/RPT/ContMaterialByComponent`；只使用記憶體假資料，不呼叫 Oracle、正式 API 或資料庫。
- 本次只復刻依 Component No 查詢的 RT603。相鄰的 RT604「物料用於元件查詢」是另一支表單，未包含在本項。

## WinForms、Service、Core

- 主表單：`D:\iMES\CSiMES\STD\MESWin\RPT\RT_Cont_CompMaterial_byComp\frmCont_CompMaterial_byComp.vb`。表單的 `InitializeComponent`／Designer 程式碼內嵌於同一 `.vb`，沒有獨立 Designer 或定義表單檔。
- 畫面為最大化視窗；查詢區只有 `txtComponentNo`、`btnQuery`；結果區為 `iugResult` 與 `btnClose`。輸入欄 Enter 時全選，Leave 時轉大寫。Query 呼叫 `funLoadCont_MaterialLotComp`，Close 關窗。來源沒有空值驗證或分頁。
- 表單組 XML 只傳 `ComponentNo` 和 `ReportMode=True`，呼叫 `wsWIP.LoadCont_MaterialLotComp_JoinLog`。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsWIP\wsWIP.cs`，可解析 ComponentNo、LotNo、OPNo、MaterialType、MaterialNo、MaterialLevel、MaterialLotNo、ReportMode；RT603 表單只傳 ComponentNo 與 ReportMode。Service 以 `tcWIP_IC.clsLot` 呼叫 Core。
- Core：`D:\iMES\CSiMES\STD\MEStc\tcWIP_IC\clsLot.cs` 的 `LoadCont_MaterialLotComp_JoinLog`。Report Mode 使用 report connection，將查詢結果包成 `MaterialLotComp` DataSet XML。
- Core 查詢 `tblWIPLotBasis A`、`tblWIPLotLog B`、`tblWIPCont_MaterialLotComp C`，連結條件為 `A.BaseLotNo = B.BaseLotNo`、`B.LotSerial = C.LotSerial`；ComponentNo 非空時追加 `C.ComponentNo = ...`。查詢沒有 `ORDER BY`，亦沒有分頁或 `DISTINCT`。
- Core 輸出 `MONo`、`BaseLotNo`、`LotNo`、`OPNo`、`MaterialType`、`MaterialNo`、`MaterialLotNo`、`ComponentNo`、`CompQty`、`UnitNo`。Grid 將 `ComponentNo`、`LotNo` 隱藏；可見欄依序為 OP No、Material Type、Material No、MaterialLot No、Comp Qty、Unit No、MO No、BaseLot No。Grid 只指定 OPNo 遞增排序；CompQty 顯示 `0.####` 並靠右，GroupBy 區隱藏。
- Core 以字串串接 SQL 條件；家用端不得照搬，必須參數化。空 ComponentNo 會省略條件，造成整個報表來源查詢；API 應要求非空 ComponentNo，避免無界全量讀取，這是相對於舊表單的安全限制。

## Vue DEV 行為

- 以 RT603 假 ComponentNo 列出不同 OP、物料、物料批、數量、單位、MO 及生產批資料；輸入欄 Leave 時轉大寫，按 Query 或 Enter 查詢，依 OP No 遞增排序，點列可模擬 Grid 選取，Close 返回主畫面。
- 初始結果留白；輸入存在於假資料的 ComponentNo 顯示對應資料，未匹配時顯示空結果。空白 Query 依舊 Core 行為顯示所有有限的假資料，並提醒舊程式沒有追加元件條件。空白結果僅為 DEV 模擬，正式 API handoff 要求拒絕空值。
- Service/Core 回傳的 ComponentNo、LotNo 在原 Grid 隱藏；DEV 頁不額外呈現。Grid 是唯讀查詢，沒有新增／修改／刪除操作。
- 沒有使用原 WinForms 的第三方 Infragistics 控件；以 Vue HTML table 呈現欄位、排序、選取和空結果狀態。Enter 直接查詢是 DEV 的鍵盤便利行為，WinForms 來源只明確處理 Enter 全選及 Query 按鈕。

## 資料字典與家用端 API/schema handoff

- SQL 來源可確認上述三表名稱、join 欄位、篩選欄位及輸出欄位。可信參照已存在：`tblWIPLotBasis` 使用 WP101 Oracle DDL／PostgreSQL CREATE-only，`tblWIPLotLog` 使用 QC409 dependency Oracle DDL／`mestest_wip_lot_log_create.sql` CREATE-only。唯獨 `tblWIPCont_MaterialLotComp` 尚無可信 MESTEST DDL／metadata／CREATE-only；家用端不連原生 Oracle，已列公司端唯讀交付。
- YMES live catalog 顯示 `tblwiplotbasis` 已存在 38 欄且 `ymes_app` 有 SELECT；`tblwiplotlog` 與 `tblwipcont_materiallotcomp` 原本缺少。依可信參照套用 migration `0081_rpt_wip_lot_log_schema.sql` 建立空的 21 欄 `tblwiplotlog`，含來源 PK 與兩個來源索引，僅授 `ymes_app` SELECT，未載入業務列。資料庫備份、migration SHA、欄位／索引／權限回讀詳 [資料庫連線紀錄](../../DATABASE_CONNECTION.md)。
- 建議唯讀 API：`GET /api/reports/component-materials?componentNo={value}`；使用授權使用者的資料範圍及參數化查詢，拒絕空白／過長輸入，設定最大回傳筆數或分頁，回應穩定依 OPNo 排序（可加 LotNo、MaterialNo、MaterialLotNo 作穩定次排序）。
- 建議回傳欄位：`moNo`、`baseLotNo`、`lotNo`、`opNo`、`materialType`、`materialNo`、`materialLotNo`、`componentNo`、`compQty`、`unitNo`。確認 YMES 實際欄位大小、數值精度與命名對照後再實作 DTO／SQL。
- API 實作前仍須取得 `tblWIPCont_MaterialLotComp` 原始 DDL、欄位 metadata、主鍵／索引，並核對 live schema 中三表 join/filter 欄位、權限及查詢計畫；依查詢計畫決定必要支援索引。不得從 Core SQL 推測缺少表的結構。
- 公司端未連 PostgreSQL、未實作或驗收正式 API／schema，未 build／test／browser。
