# RT905 指標樹查詢

## 範圍與來源

- 選單清冊：`FunctionNo=KPI Tree Query`、Form `frmKPITreeQuery`、DLL `RT_KPITreeQuery.dll`、FunctionKey `RT905`。專案目錄名稱有拼字 `RT_KPITreeQuerty`。
- 查詢清單：`D:\iMES\CSiMES\STD\MESWin\RPT\RT_KPITreeQuerty\frmKPITreeQuery.vb`（Form 與 inline Designer）。
- 樹圖檢視：`D:\iMES\CSiMES\STD\MESWin\RPT\RT_KPITreeView\frmShowTreeQuery.vb`。從查詢清單以 `ObjectFileHandler.Execute("RT_KPITreeView", Parameters)` 開啟，傳 KPI Tree No／Name。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsRPT\wsRPT.cs`，呼叫 `LoadKPITreeBasis`、`LoadQueryKPITreeDetail`、`LoadQueryToleranceSetting`、`AddEKBKPILog`；ActualValueScript 另呼叫 `wsReportEngine.LoadScriptConditionData`。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcRPT\clsRPTBasis.cs` 的 `ShowKPITreeBasis`、`ShowQueryKPITreeDetail`、`ShowQueryToleranceSetting`、`AddEKBKPILog`。`RT_KPITreeLog\frmKPITreeLog.vb` 與 `LoadEKBKPILog` 是後續 RT906 歷程查詢。

## 查詢清單行為

- Form 開啟時立即執行 Query。KPITreeNo／Name 以 `%` 提示，支援各自或同時輸入；兩者皆空時 Core 查全部 basis。查詢結果先依 KPITreeNo 排序，再由 Form 移除 `FreezeState<>0` 列，因此 RT905 只顯示 `FreezeState=0` 的已凍結版本。FreezeState、NodeXmlString 隱藏；畫面顯示 KPITreeNo、KPITreeName、Description、Creator、CreateDate。沒有分頁。
- Tree Query 將目前選取列的編號／名稱開啟 `RT_KPITreeView`；Form 檢查結果集非空，但沒有明確驗證 ActiveRow，使用者需先選取一列。
- Viewer 將 NodeXmlString 還原成唯讀圖形，支援縮放、KPI 節點雙擊、Export 與 Save KPI Log。KPI 節點雙擊呼叫 `RT_Script` 並傳入 TargetValue／上下限、名稱／說明、ReportID／ChartID。
- Viewer 依有 ActualValueScript 的 KPI 呼叫 `wsReportEngine.LoadScriptConditionData` 取實績，按容忍值規則計算 CompareResult、節點顏色與顯示值；腳本失敗或結果無法轉成數值時可顯示 `(ERROR)`。沒有腳本時不呼叫公式服務。容忍值 operator code：0 `>`、1 `<`、2 `>=`、3 `<=`、4 `=`、5 範圍內（含上下限）。
- Save KPI Log 將目前每筆 KPI 的 tree／KPI／目標／實績／script／人員資料送入 `wsRPT.AddEKBKPILog`，Core 逐筆新增 `tblEKBKPILog`。Export 產生 XLSX，包含 11 欄 KPI 標準值、實績、公式、TreeOperator 與建立時間；目前程式的 TreeOperator 欄實際寫入 `dsTemp` 第一筆的 Creator，屬來源映射疑點。

## Service／Core 差異與風險

- `ShowQueryKPITreeDetail` 將 `tblEKBDetail` 與 `tblEKBKPIDetail` 依 KPITreeNo、KPINo join；KPITreeNo、KPINo 都是字串串接。雖然方法接受 KPIType，SQL 沒有依 KPIType 篩選。沒有穩定排序或分頁。
- `LoadQueryToleranceSetting` Service 要求 KPITreeNo，但未解析傳入的 KPINo，也未傳 `AdditionalXml`；Core 因此依樹讀取全部容忍值。Core 接受空樹號時會查所有非空 KPITreeNo，但該 Service 入口會拒絕缺少樹號。
- RT905 清單在 client side 過濾 FreezeState；正式 API 應在 server query 中限定 `FreezeState=0`，避免大量回傳未凍結設定。
- `ShowEKBKPILog` 對可選樹名使用等號；StartDateTime 使用嚴格 `CreateDate > StartDateTime`，EndTime 使用嚴格 `CreateDate < EndTime`。沒有條件可讀全部非空 KPITreeName，沒有分頁／排序。Form 要求至少勾選樹名或日期；勾日期時要求 Start < End。
- `AddEKBKPILog` 把多筆 INSERT 收集後呼叫 `ExecuteSQLNoneQuery_UPD`；共同交易與失敗回滾範圍需確認。實績公式經 Report Engine 執行，是 server-side 執行路徑，不可改成 browser 傳入任意 SQL。
- 涉及資料表為 `tblEKBBasis`、`tblEKBDetail`、`tblEKBKPIDetail`、`tblEKBLimiteDetail`、`tblEKBKPILog`。repo 未找到這些表的可信 Oracle source DDL／metadata；公司桌機受保護 Oracle profile 不存在，未連 Oracle、未猜欄位或新增 CREATE-only SQL。

## Vue DEV 與路徑

- 路徑 `/YMES/RPT/KpiTreeQuery`，由 `function:RPT:KPI TREE QUERY` 對應。查詢清單進頁立即顯示假資料；支援編號／名稱模糊條件、排序、FreezeState 篩選、Tree Query、唯讀圖形、縮放、KPI detail、CSV 匯出及本頁記憶體 Save Log。
- 節點實績／容忍值結果由 fixtures 提供。ActualValueScript 只顯示，不呼叫 `wsReportEngine`／`RT_Script`／資料庫；Save Log 不呼叫 `AddEKBKPILog`。CSV 是 DEV 匯出簡化，正式來源 XLSX。刷新頁面會還原假資料。

## 家用端 API／schema handoff

1. 先比對 live catalog／migrations 的五張 basis／detail／tolerance／log 表；缺少可信 Oracle DDL 的表不可依 DEV fixture 或推測欄位建表。公司端未連 PostgreSQL。
2. 清單 API 在伺服器限定 FreezeState=0，支援 KPITreeNo／Name 模糊條件但要求至少一個條件或設定嚴格上限；回傳穩定排序與分頁。樹圖讀取須限制指定 KPITreeNo，只回傳 NodeXml、KPI detail、容忍值必要欄位。
3. detail Service 舊實作未用 KPIType；正式端需先裁決 Description node 如何與 KPI detail 對應，不可忽略 KPIType 後把 description 當 KPI。依可信 DDL 參數化所有 filter，並確保 KPITreeNo 是必填。
4. 實績計算應由有授權的 server-side 報表／公式機制執行，使用固定／白名單 script 或 ReportID／ChartID，限制執行時間、資料範圍與單列數值回傳。不得接受 browser 任意 SQL、連線字串或資料來源名稱。
5. 歷程查詢 API 至少要求 KPITreeName 或完整有效日期區間，參數化並限制跨度／頁數、穩定排序；日期條件若要與 legacy 一致須明示兩端嚴格不含界。Save Log 以單一交易寫入同次結果，使用 server identity 與 DB 時間並回傳逐筆狀態；不得由 browser 指定 Creator／CreateDate。先比對 `tblEKBKPILog` live schema／權限，避免用「查詢頁」名義賦予無界 writer。
