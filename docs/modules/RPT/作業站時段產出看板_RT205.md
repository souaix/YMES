## 畫面與互動

### 主看板

- 舊 Form 先以 `gComputerName` 去掉最後一段 `/` 建立 HostName，再讀取該 PC 的設定。設定不存在時不載入看板、不啟動 Timer；由 Setup 儲存後再載入。
- 設定存在時依序載入作業站與時段摘要，然後按 RefreshTime 秒數週期重新查詢。開啟設定時暫停 Timer，關閉後重新載入並恢復。
- Grid 以每個 OP 五列顯示 `GoodQty`、`ScrapQty`、`DefectQty`、`Accumulate GoodQty`、`Yield`。OPNo 合併五列，OPName 隱藏於資料但用作 OPNo 提示文字；每五列交替底色。
- 時段欄由啟用中的 `tblRPTTimeStepBasis` 動態產生，標題含歸屬日期、FromTime、ToTime。未開始的時段不填數值。
- 產出數字使用 `0.##` 格式；良率顯示 `##0.#%`。`wsOP.LoadOPAttrib(OPNo, AttribNo=StdYield, IssueState=2)` 的良率標準大於 0 且時段 Yield 低於標準時，該格紅字。

### 設定

- 列出 `wsOP.LoadOPBasis(IssueState=2)` 作業站；篩選 `IssueState Not in (0,1)`，依 `OPOrder, OPNo` 排序，支援多選。
- 欄位：RefreshTime 秒數、ColumnWidth、RowHeight、FontSize、選取 OPNo。舊 Form 檢查非空／數字後轉整數，未限制正值範圍；DEV 為避免不可用畫面，另限制全部數值為正整數且至少選一個 OP。
- 舊設定依 HostName 儲存；Vue DEV 設定只存在當前頁面狀態，不寫瀏覽器儲存區或後端。

### 歷史查詢

- 接受一個 BelongDate 及逗號分隔的多個 OPNo，重用 `LoadBillBoardOPOutputSummary`；結果依 OPNo 排序，欄位及 Yield 標紅規則與主看板一致。
- 舊視窗在選取 OP、修改日期時會觸發查詢，亦有 Query 按鈕。Vue DEV 以明確 Query 按鈕提交日期與所選 OP，提供唯讀假資料。

## Core 計算規則

1. 讀取 `tblRPTTimeStepBasis` 中 `IssueState=2` 的時段，按 `TimeStepNo` 排序；無時段時 Core 回報設定錯誤。
2. 未指定 BelongDate 時以目前日期時間決定歸屬日。若現在在每日第一個時段開始前，Core 將歸屬日回推一天；班別跨午夜時，時段起訖時間依第一時段起始時間調整到歸屬日或隔日。
3. 以啟用 OP 清單查 `tblWIPLotLog_Report`，只納入 `Status=1` 且 `EndTime` 落在整個時段範圍的紀錄；資料欄位為 `GoodQty`、`FailQty`、`DefectQty`、`EndTime`、`OPNo`。名稱另查 `tblOPBasis.OPName`。
4. 每段 GoodQty、ScrapQty、DefectQty 分別加總 `GoodQty`、`FailQty`、`DefectQty`；Accumulate GoodQty 僅累加 GoodQty，不含報廢或缺點。
5. 若 `GoodQty + ScrapQty` 非 0，Yield 分母為 GoodQty + ScrapQty。系統參數 `YieldContainDefect=0` 時分子為 GoodQty - DefectQty；其他值時分子為 GoodQty。分母為 0 時顯示 `-`。
6. Core 回傳 `NowTimeStep` 與 `BelongDate`；WinForms 目前依資料列時間順序直接呈現時段，未用 NowTimeStep 隱藏已開始時段以外欄位。

## 家用端 API handoff

### 建議唯讀查詢契約

`GET /api/reports/op-output-summary?opNos=OP10,OP20&belongDate=2026-11-26`

- `opNos` 必填、多值 allowlist；`belongDate` 選填，未提供則依已核實的廠區時區與班別第一時段起點推算。
- 回傳 `belongDate`、`nowTimeStep`、`intervals[]`（timeStepNo/from/to/label）及 `operations[]`（opNo/opName/stdYield/buckets[]）。每 bucket 回傳 goodQty、scrapQty、defectQty、accumulateGoodQty、yield；分母為 0 時 yield 為 null。
- SQL 必須參數化 OP 與日期範圍，分批／限制 OP 清單長度，直接以左閉右開 `[from,to)` 切片，避免舊 Core 以 `<= ToTime` 造成時段交界的同一筆 LotLog 重複計入。正式資料結果仍須與舊版 MESTEST 實際輸出比對後定稿。
- 只讀使用以下來源候選：`tblRPTTimeStepBasis`、`tblWIPLotLog_Report`、`tblOPBasis`、OP 屬性資料與系統參數來源。系統參數表名、有效時間段／時區、LotLog 唯一鍵及歷史資料保留方式待家用端核實。

### 看板設定

舊系統 Service 為 `LoadBillBoardOPOutputConfig(HostName)` 與 `UpdBillBoardOPOutputConfig(HostName, RefTime, FontSize, RowHeight, ColumnWidth, OPNo)`。資料表名稱為 `tblRPTBillBoardOPOutPutConfig` 及 `tblRPTBillBoardOPOutPutContent`，欄位從 Core SQL 可見 `PCNo, RefreshTime, FontSize, RowHeight, ColumnWidth, OPNo`；目前沒有可信 DDL。

- 先決定 YMES 設定屬於使用者、看板裝置或瀏覽器端；不要直接信任 client 傳來的 PCNo 作為跨使用者設定授權依據。
- 如採持久化設定，建議獨立設定 API 讀取目前使用者／裝置的 refresh、尺寸及 OP 清單；不可與產出查詢混成可寫業務端點。
- PostgreSQL CREATE-only SQL 暫不提供：repo 沒找到此兩張設定表、時段主檔、LotLog 報表表的可信 CREATE／完整欄型別／鍵索引，桌機亦無已驗證的 Oracle MESTEST profile metadata。不可依名稱推測建立 schema。

## 待家用端核實

- 同版 MESTEST 的四類資料來源 DDL／owner、型別、主鍵／索引、LotLog `Status` 語義、`EndTime` 是否含邊界記錄及歷史保留區間。
- 時段跨日定義（第一段／最後一段配置）、歸屬日廠區時區、第一段起點恰逢午夜的 legacy 日期邊界行為。
- 系統參數 `YieldContainDefect` 的合法值與缺值預設，以及 OP `StdYield` 儲存尺度（0–1 或百分值）。舊 Core 以十進位比例直接比較。
- 舊 Core 將 OPNo 直接串 SQL，對單一批次的時間範圍先整體查詢，再以包含兩端的條件切片；須參數化並確認來源時間精度及重複計數處理。
- `LoadBillBoardOPOutputConfig` 的 LEFT JOIN 又在 WHERE 限制 `C.OPNo=B.OPNo`，可能讓沒有 OP Content 的 config 不回傳資料；需要確認是否為舊程式缺陷。
- `clsLot` 寫入 `tbl_NBWIPOPOutputSummary` 使用動態時段欄；這不是目前 RT205 報表 Core 的讀取來源。確認是否另供 RT206／RT207 使用，再獨立核對，不要將其混入 RT205 query API。

## Oracle / schema 查核狀態

- 以 repo `docs`、`database`、`src` 搜尋上述資料表 CREATE 未找到可信 DDL；Oracle profile 在目前工作環境未確認可用，因此本模組未執行 Oracle metadata 查詢，也未猜測 PostgreSQL CREATE。
- 此功能以 MES MESTEST 為舊來源；公司桌機保持只讀 Oracle 範圍，不連 YMES PostgreSQL，不實作正式 API/schema。
