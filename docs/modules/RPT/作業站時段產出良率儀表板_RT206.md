# RT206 作業站時段產出_良率儀表板

## 復刻範圍

- FunctionNo：`BILLBOARD OPOUTPUT SUMMARY GAUGE`；FunctionKey：`RT206`；FunctionName：作業站時段產出_良率儀表板。
- Vue 入口：`/YMES/RPT/OpOutputYieldGauge`，RPT「報表管理 → 看板」。僅 DEV 假資料可用，正式環境維持未開放。
- RT206 與 RT205 共用時段產出查詢 Service／Core；差異是 RT206 將每個已開始時段及 OP 摘要顯示為圓形 Gauge 卡片，支援依 OP 或時段排序。

## WinForms 畫面與操作

- 初次載入先去掉 `gComputerName` 最後一段 `/` 形成 HostName；依此 HostName 與 `SetupType=4` 載入 OP 選擇、RefreshTime、FontSize。無設定資料時不載入 Gauge、不啟動 timer。
- 設定按鈕暫停 timer，透過共用 `RT_BillBoard` 設定畫面更新 OP 多選、更新秒數及字級，再重載 config／摘要並恢復 timer。設定檢查欄位非空與數字，至少需選一個 OP；舊 Form 不限制數值上下界。
- 頂部顯示歸屬日，`Order By` 可切換 `OPNo`／`TimeStep`。預設依 OP；兩種排列都以 OP 設定順序及時間先後排序。
- 每個已開始時段 × 已選 OP 建一張卡。從目前可用工作區估算單卡大小，4 欄排列、超出可捲動；新時段開始令 `NowTimeStep` 改變時重建所有卡，其餘刷新只更新數值。
- 每卡標示 OPNo、時段、GoodQty、ScrapQty、DefectQty、Accumulate GoodQty 與 Yield 圓形針盤及數位百分比；OPName 放在 OPNo tooltip。
- 顯示 `YieldContainDefect=0` 時含 DefectQty 欄；其他值時隱藏 DefectQty 並調整欄位位置。Yield 本身由共用 Core 按此參數計算。
- Gauge 數值是 0–100，固定色帶 0–60 紅、60–80 黃、80–100 綠。雖然每張卡呼叫 `LoadOPAttrib(StdYield)`，傳入 Gauge helper 的 `stdYield` 沒被用於畫面；依 StdYield 調色的程式已註解，故不能把低於 StdYield 標紅當作舊版規則。
- 更新週期為 RefreshTime 秒。刷新時先停 Timer、取共用 `LoadBillBoardOPOutputSummary(OPNo)`、重載結果、更新 Gauge，再啟動 Timer。

## Core 資料與計算

- Core 與 RT205 一致：用 `tblRPTTimeStepBasis` 的 `IssueState=2` 時段建立欄位，按 `TimeStepNo` 排序；按 OP 查 `tblWIPLotLog_Report` 的 `Status=1`、`EndTime`、`GoodQty`、`FailQty`、`DefectQty`，以 `tblOPBasis.OPName` 供 tooltip。
- 每 OP 每時段依序取 Core 五列資料：GoodQty、ScrapQty、DefectQty、Accumulate GoodQty、Yield。RT206 用 `NowTimeStep` 決定當前要建立多少張卡，已開始時段才建立；下一個刷新若已進入新時段就重建卡片集合。
- Good／Scrap／Defect 彙總、累計 Good、Yield 分母及 `YieldContainDefect` 分子算法詳 [RT205 規格](作業站時段產出看板_RT205.md)。
- 原碼 `funLoadOPAttrib` 會逐卡取得 StdYield，但只傳給 helper；helper 內用 StdYield 設色的區段是註解。現行實際色帶是 Designer 固定設定的 0–60／60–80／80–100。

## DEV 實作

- [OpOutputYieldGauge.vue](../../../web/src/components/OpOutputYieldGauge.vue) 與 `OpOutputYieldGaugeDevPreview.vue`：DEV 假 OP／時段，圓弧色帶、指針和數位 Yield；Good／Scrap／Defect／累計 Good；依 OP／時段排序切換、SetupType 4 對應的秒數／字級／OP 設定、更新倒數與立即更新。
- 預設假參數 `YieldContainDefect=0`，因此 DEV 顯示 DefectQty 並從 Yield 分子扣除。假 OP、時段、數值、StdYield、色帶皆非正式資料；無後端呼叫或持久化。

## 家用端 API/schema handoff

RT206 不需另外建立業務查詢。共用 RT205 的唯讀查詢契約，UI 取 `operations[].buckets[]`，依 `nowTimeStep`／當前本地班別時間截出已開始時段，再展開成每個 OP × interval 的卡片。每卡需有 `goodQty`、`scrapQty`、`defectQty`、`accumulateGoodQty`、`yield`；`opName` 可供 tooltip，`stdYield` 是設定顯示資訊但不要改變固定 60／80 色帶。共用 API／資料表及歷史邊界詳 [RT205 handoff](作業站時段產出看板_RT205.md)。

- RT206 的設定另用 `tblRPTBillBoardOPStateConfig`／`tblRPTBillBoardOPStateContent`，含 `PCNo`、`SetupType`、`RefreshTime`、`FontSize`、`OPNo`；`SetupType=4`。Core config lookup 還回傳 `OPOrder`、`PSNo`。repo 沒有這些表可信 CREATE／完整鍵索引；家用端決定 YMES 設定用 user/device scope 後再設計設定 API及 CREATE-only SQL，不要將未授權 PCNo 當作授權依據。
- 舊 Core config 的 LEFT JOIN 又以 `C.OPNo=B.OPNo`、`B.SetupType=4` 放 WHERE，可能使沒有 OP Content 的 config 不回資料；與 RT205 同樣有 OP 清單不可空的實務要求。

## 待家用端核實／舊碼疑點

- `LoadBillBoardOPOutputSummary` 的時段邊界、歸屬日期、yield 分子與動態時段 DDL／時區待查，沿用 RT205 handoff。
- `tblWIPLotLog_Report` 的 MESTEST CREATE 已存在於 [WP201 dependency DDL](../../../database/reference/mestest_wip_wp201_dependency_source_ddl.sql)，內含本功能引用的 OPNo、Status、EndTime、GoodQty、FailQty、DefectQty 欄位；此檔由 2026-11-19 的 PowerShell 5.1／ODP.NET Oracle READ ONLY session 抽取，不代表其他 RT206 config/time-step 表已有 DDL。
- 桌機目前未確認受保護 Oracle profile 可用，故本模組未直接查 Oracle metadata。`tblRPTBillBoardOPStateConfig`／`Content`、`tblRPTTimeStepBasis` DDL／PK／索引仍缺；不得猜 CREATE。
- StdYield 查詢結果在 Gauge helper 未使用；`YieldContainDefect` 非 0 時隱藏 DefectQty，原碼仍依同參數回傳的 Yield 計量顯示。
- 每次產生卡片會呼叫一次 `LoadOPAttrib`；多選 OP、時段多時會放大 Service 呼叫數。家用端查詢宜批次載入 OP 標準屬性。

## 範圍界線

- 公司端完成來源核對、DEV 假資料 UI 與此 handoff；不連 YMES PostgreSQL、不實作正式 API／schema、不 SSH／部署。
- 公司端只可透過已配置的 MESTEST 受保護唯讀連線查 Oracle metadata；設定不可用時維持待查，不將帳密輸出或寫入 repo。
