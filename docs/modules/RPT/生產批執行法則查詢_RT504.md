# RT504 生產批執行法則查詢

## 選單與來源

- 選單：RPT → 生產批 →「生產批執行法則查詢」，FunctionNo `RULE LOG QUERY`、FunctionKey `RT504`、Form `frmRT_RuleLogQuery`、執行檔 `RT_RuleLogQuery.dll`。
- Form／Designer：`STD/MESWin/RPT/RT_RuleLogQuery/frmRT_RuleLogQuery.vb`；Designer 內嵌同檔。CSiMES、THEIL、DEV_SILVA 三份檔案雜湊一致。
- 查詢 Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `LoadWIPRuleCheckLog`；Rule No lookup Service：`STD/MESws_STD/wsSTD/wsPRD/wsPRD.cs` 的 `LoadPRDOPRule`。
- 查詢 Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `LoadWIPRuleCheckLog`；Rule No lookup Core：`STD/MESkc/kcPRD/clsProduct.cs` 的 `LoadPRDOPRule`。

## Form 條件與操作

- 五組可勾選條件：Lot No、Component No、Rule No、Rule Action、Event Time 起迄。Lot No／Component No 輸入非空時自動勾選並在離開欄位時轉大寫；Rule No 為唯讀欄位，透過一個可見按鈕開啟 lookup。Rule Action 選項為 `PASS`、`HOLD`、`WAIT`、`WARNING`，選值後自動勾選。取消各自 checkbox 會清空對應的文字或選項。
- Event Time checkbox 預設未勾選；勾選才會傳起迄時間。Form 預設起始為當日 07:30；若現在早於 07:30，則用前一日 07:30。結束預設為現在，兩個欄位格式含時分秒。
- 查詢至少要一個有效條件，否則顯示 `Please select one condition` 訊息而不呼叫 Service。已勾選但空白的文字／選單不算有效條件；日期區間 checkbox 勾選即算一項條件。
- Rule No lookup 呼叫 `wsPRD.LoadPRDOPRule`，載入 `TBLPRDOPRULE`；選取窗以 RuleNo 去重並升冪排序。Source 另留有 Lot basis／Lot state helper，但此 Form 沒有 Lot lookup 按鈕，Lot No 為直接輸入欄。
- Form 沒有明細視窗或寫入操作。Close 關閉查詢頁。

## Service／Core 查詢

- `wsWIP.LoadWIPRuleCheckLog` 解析 LotNo、ComponentNo、RuleNo、RuleAction、StartEventTime、EndEventTime 與 Additional XML，再呼叫 `clsLot.LoadWIPRuleCheckLog`。RT504 Form 只傳前五種畫面條件，不傳 Additional XML。
- Core 查詢 `TBLWIPRULECHECKLOG`，固定 `LOGGROUPSERIAL IS NOT NULL`。LotNo、ComponentNo 使用前綴 `LIKE 'value%'`；RuleNo 使用等值；RuleAction 使用包含式 `LIKE '%value%'`；EventTime 使用起迄範圍。若 EndEventTime 是純日期，Core 將上限延伸至當日 23:59:59；此 Form 的 datetime control 傳入時分秒。
- Core 直接串接 SQL，使用一般 MES connection；沒有分頁、筆數上限或排序。Form 端將 EventTime 欄位改名為 `PROCESSDATE1`，並在 DataView 排序 `LotNo, ComponentNo, PROCESSDATE1, RuleSequence`。
- Grid 隱藏其他資料欄，只顯示八欄：LotNo、ComponentNo、RuleNo、RuleSequence、RuleAction、PROCESSDATE1、RuleScript、BREventTime。Form 對日期時間格式化；RuleSequence 靠右。
- Designer 的日期 checkbox 文字為 `StartEventTimeTime`，疑似 legacy 標籤錯字；DEV 改顯示 `Event Time`。Grid 原欄名 `PROCESSDATE1` 在 DEV 顯示為易讀的 `Process Date`，Rule Script 欄以截斷呈現避免撐寬表格，這些是純顯示簡化。

## DDL 與家用端交接

- `TBLWIPRULECHECKLOG` 的 Oracle source DDL／metadata 未在 `database/reference` 找到；桌機目前沒有受保護 Oracle profile，本次未查 Oracle，也不猜欄位或 CREATE-only SQL。`XX_TBLPRDOPRULELOG_THEIL` 是另一張表，不能替代此主查詢表。
- Rule No lookup 使用的 `TBLPRDOPRULE` source DDL 已在 `database/reference/mestest_prd_parameter_setup_source_ddl.sql`；不要重建這張 lookup 表。
- 家用端先核 YMES PostgreSQL live schema、資料同步來源與 `TBLWIPRULECHECKLOG` 欄位型別。若可支持，建議提供登入與 RPT FunctionNo `RULE LOG QUERY` 授權保護的唯讀 `GET /api/reports/wip-rule-check-logs`，參數 lotNo、componentNo、ruleNo、ruleAction、startEventTime、endEventTime、page、pageSize。伺服器至少要求一個有效條件；查詢需參數化、穩定排序、分頁及筆數上限，不接受前端 SQL／AdditionalXml。
- 保留 Form／Core 篩選語意：Lot／Component 前綴、RuleNo 等值、RuleAction 包含、EventTime 起迄。公司端不連 YMES PostgreSQL、不做正式 API/schema、不部署。
