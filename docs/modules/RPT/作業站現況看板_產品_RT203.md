# RT203 作業站現況看板_產品

## 模組識別

- FunctionNo：`BILLBOARD OPSTATE_PRODUCTNO`；FunctionKey：`RT203`；FunctionName：作業站現況看板_產品。
- Vue 入口：`/YMES/RPT/OpStateProductNoBoard`，目前只在 DEV 假資料模式開放。
- RT203 使用獨立 `SetupType=3`，每個設定 OP 顯示當前 WIP 的 ProductNo 系列堆疊數量；可在不同 OP 間比較 Queue／Run／Hold／Wait。

## 圖表與操作

- Form 對目前電腦 HostName 載入 SetupType 3 的 RefreshTime、FontSize 與 OP 清單。Setup 暫停 Timer、開共用設定頁，儲存後重建圖表。沒有 SetupType 3 設定時不載資料、不啟動 Timer。
- 每個 OP 使用 `StackColumnChart`；X 軸為 Queue／Run／Hold／Wait，ProductNo 為堆疊系列，CurQty 為數值。所有 OP／狀態共用 Y 軸最大值。ProductNo 色彩依資料集順序動態配色，不代表固定狀態。滑鼠提示顯示 ProductNo、Lot 與 CurQty。
- 標題顯示 OPNo，圖表右上標總 Lot／Qty；游標在圖表上緣時顯 OPName。雙擊總 Lot、總 Qty 不同時為 0 的圖表會開放大 Type 3 圖；Timer 在子視窗期間仍按設定更新。
- 右鍵 Copy To Clipboard／Lot Detail。總 Lot 與 Qty 同為 0 時隱藏 Lot Detail 與分隔線。DEV copy 僅顯示 toast，不操作系統剪貼簿；Lot Detail 模擬 OP 所有狀態批次，以 Status、ProductNo 排序。
- RT203 Form 沒有 ProductNo 點擊後續鑽取。共用 Service 的 ProductType 參數為 optional；RT203 自身查詢只送 OPNo，不傳 ProductType，其他共用子視窗可用該參數縮小到某一產品類別。

## Service／Core 資料規則與風險

- `LoadBillBoardOPStateConfig(HostName, SetupType=3)` 沿用 RT201／RT202 的共用 config 表；OP 依 PSNo、OPOrder、OPNo 排序。
- Form 註解掉舊 `funLoadProductNo()`／`wsPRD.LoadProduct_Dist` lookup。實際系列從 RPT 查詢傳回的 Queue／Hold／Run／Wait 產品清單取 distinct，因此沒有目前 WIP 的 ProductNo 不會出現。
- `LoadBillBoard_OPState_ProductNo(OPNo, ProductType=optional)` join `tblWIPLotState A`、`tblWIPLotBasis B`、`tblPRDProductBasis C`，以 BaseLotNo、ProductNo、ProductVersion 關聯。Status 0／1／3／2 各自 `COUNT(A.LotNo)`、`SUM(A.CurQty)`，依 OPNo／ProductNo 分組；ProductType 有值才追加 `C.ProductType` 條件。
- 舊 Core 將 OPNo 清單及可選 ProductType 直接拼入 SQL；家用端需參數化，並按登入者授權限定 OPNo。ProductNo series 數目可能較大，查詢及圖表需限制 OP 清單／輸出筆數並確認 live schema 索引。
- 舊 WIP Lot Detail 以 OPNo／Status 查全部相關批次，不保留 ProductNo 系列 filter；DEV 按此行為模擬。

## MESTEST DDL／metadata 現況

- `tblWIPLotState`／`tblWIPLotBasis` 可比對 [WP101 source DDL](../../../database/reference/mestest_wip_wp101_source_ddl.sql) 與 [QC409 dependency DDL](../../../database/reference/mestest_qc409_wip_disposition_dependencies_source_ddl.sql)；Product Basis 可比對 [PRD product basis DDL](../../../database/reference/mestest_prd_product_basis_source_ddl.sql)。這些是既有 MESTEST refs，不表示與 YMES PostgreSQL live schema 同版同構。
- 共用 `tblRPTBillBoardOPStateConfig`／`tblRPTBillBoardOPStateContent` 的可信 CREATE／PK／索引尚未找到。桌機可確認的 Codex Oracle attachment 不存在，因此本次沒有用 PowerShell 5.1／ODP.NET 新查 metadata，沒有猜 CREATE SQL。
- 公司端不連 PostgreSQL、不建 schema／migration、不實作或驗收正式 API、不 SSH／部署；未執行 build／test／browser。

## 家用端 API／schema handoff

- 延用已實作的 `GET /api/reports/op-state-breakdown?opNos=...&groupBy=productNo`，回傳每個 OPNo、ProductNo 及四種狀態 LotCount／CurrentQty。共用子視窗可帶 `productType=...`；RT203 standalone 設定看板不帶 ProductType。
- 端點要求登入、參數化 OPNo／ProductType，限定最大 OP 數及結果列數；目前沒有 per-user OP 授權來源。Lot detail 使用 `/api/reports/op-state-lots`，要求 OPNo 並提供 Status、ProductType／ProductNo 篩選及分頁筆數上限。
- SetupType 3 使用共用看板設定表；先確定登入者或 device scope，再決定正式設定 API。不可用 Legacy PCNo 取代使用者授權。RT203 沒有新增資料表，也不提供缺乏依據的 CREATE-only SQL。
