# RT606 生產批資源檢視

## 功能與入口

- Menu FunctionNo `RESOURCE QUERY`、FunctionKey `RT606`、Form `frmResourceQuery`，RPT「報表管理」的資源項目。Vue DEV 入口：`/YMES/RPT/LotResourceQuery`。
- 以必填 Lot No 查詢兩份結果：Resource（勞務／設備／外包）與 Material；可切換 `by Lot` 或 `by Lot + OP`。預設 `by Lot`。資料均為固定虛構值，只在本機記憶體查詢。

## WinForms、Service、Core

- Form 與 Designer 內嵌於 `D:\iMES\CSiMES\STD\MESWin\RPT\RT_ResourceQuery\frmResourceQuery.vb`。使用者輸入 Lot No，離開欄位轉大寫；Enter 會直接查詢。Form 必須先有 Lot No。沒有 lookup picker。
- `by Lot` 呼叫 `wsWIP.LoadSumOfResource_Valid` → `clsLot.SHR_CalculateResource_Valid`；`by Lot + OP` 呼叫 `wsWIP.LoadSumOfResource_Valid_ByOP` → `clsLot.SHR_CalculateResource_Valid_OP`。兩者都傳 `LotNo` 與 `ReportMode=True`，Core 使用 report connection。Service 要求有 LotNo XML 欄位和值；缺值回錯誤。
- Core 檢查 `TBLWIPLOTSTATE` 是否有該 LotNo；依 Split／Merge 時間遞迴展開資源與物料，計算 `TBLWIPCONT_RESOURCE`、`TBLWIPLOTLOG_REPORT`／`TBLWIPCONT_MATERIAL`／`TBLWIPCONT_MATERIALLOT`，並讀取 `TBLWIPSUM_MATERIALSTATE` 的物料批資訊。Lot 模式聚合至 Lot；Lot＋OP 模式保留 `OPNo`／`OPName`。舊 Core 條件 SQL 字串串接，查詢無分頁／時間範圍。不存在 Lot 會回錯誤；Core 註解要求已結批耗用應由持久化 Resource 歷程提供，實際正式資料口徑由家用端核 live schema 後確認。
- Form 解析 `loadresource`／`loadmaterial`，或 `loadresource_op`／`loadmaterial_op` XML 節點，DataSet 名稱由回傳 XML 的 `name` 欄位提供。Resource 依 `RESClass, RESType` 排序；Material 依 `MaterialLevel, MaterialNo, MaterialLotNo` 排序。Lot＋OP 模式分別在前面顯示 OPNo／OPName，Resource 排序加 OPNo，Material 排序加 OPNo。
- Resource 只顯示 `RESClass`（0 EMP、1 EQP、2 OS）、`RESType`、`RESValue`、`StdValue`、`InputQty`；Lot＋OP 額外顯示 OPNo／OPName。Resource footer 依存在類別計算 RESValue 加總。Material 顯示 `MaterialLevel`（0 Material、1 Product）、`MaterialNo`、`MaterialLotNo`、`RESValue`、`StdValue`、`UnitNo`；Lot＋OP 額外顯示 OPNo／OPName。DEV 頁以兩個上下排列的 Grid 模擬原畫面，保留切換、排序、類別合計、空批與錯誤狀態。

## DDL 與家用端 API handoff

- 可沿用的 Oracle MESTEST source DDL refs：`database/reference/mestest_wip_wp101_source_ddl.sql`（LotBasis／LotState）、`mestest_wip_wp201_dependency_source_ddl.sql`（LotLog_Report／Cont_Material）、`mestest_wip_wp112_tblwipcont_materiallot_source_ddl.sql`、`mestest_wip_wp403_source_ddl.sql`（Cont_Resource）及 `mestest_operation_and_system_source_ddl.sql`（OPBasis）。
- 仍缺 Core 直接依賴的 `TBLWIPSPLITCONTENT`、`TBLWIPMERGECONTENT`、`TBLWIPSUM_MATERIALSTATE` 原生 Oracle DDL／metadata。WP209／WP213 refs 只有 BIN 子表，不能代替。桌機可用的受保護 Oracle attachment/profile 不存在；未查 Oracle、未猜 CREATE SQL。
- 建議登入與 RT606 權限保護唯讀 API，例如 `GET /api/reports/lot-resource-usage?lotNo=...&mode=lot|operation&page=1&pageSize=100`。LotNo 必填且精確比對；API 以參數化查詢、穩定排序、bounded paging 分別回傳 Resource／Material rows 與類別合計。確認 Split／Merge 及 closed-lot Resource 歷程來源後，對計算範圍／Lot 歷程長度設上限並驗證資料量；不可將舊 Core 無界遞迴查詢直接公開。
- 公司端僅完成 DEV 假資料與來源 handoff，未新查 Oracle、未連 YMES PostgreSQL、未實作／驗收正式 API／schema、未 build／test／browser。正式資料口徑、索引與批次歷程分併展開由家用端核 live schema 後確認。
