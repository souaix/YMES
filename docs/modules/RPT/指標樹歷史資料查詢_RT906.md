# RT906 指標樹歷史資料查詢

## 範圍與來源

- 選單清冊：`FunctionNo=KPI TREE LOG`、Form `frmKPITreeLog`、DLL `RT_KPITreeLog.dll`、FunctionKey `RT906`。
- WinForms：`D:\iMES\CSiMES\STD\MESWin\RPT\RT_KPITreeLog\frmKPITreeLog.vb`（Form 與 inline Designer）。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsRPT\wsRPT.cs::LoadEKBKPILog`，解析 KPITreeName／StartDateTime／EndTime 後呼叫 Core。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcRPT\clsRPTBasis.cs::LoadEKBKPILog`／`ShowEKBKPILog`，讀取 `tblEKBKPILog`。
- 共用 KPI TargetType 顯示值清單來自 `ValueListProvider.GetValueList("TBLEKBKPIDETAIL", "TARGETTYPE", True)`。

## 畫面行為

- Form Load 預設 StartDateTime 為目前日期往前兩天的 00:00:00；EndTime 為今天 23:59:59。預設值不會自行執行查詢。
- 查詢可勾選 KPITreeName、Save Date 其中一種或同時勾選。至少要有一種；勾樹名時欄位必填；勾日期時 Start 必須早於 End。輸入樹名稱會自動勾選該條件；取消勾選會清除名稱。
- 舊 Form 送入完整 KPITreeName（Core 等號比對）及／或時間端點。查詢後將 `TargetValue` 欄改名為 `TargetValue2`，依 `KPITreeNo, KPINo, KPITreeName` 排序並呈現單層 Grid。
- 可見欄位順序：KPITreeNo、KPITreeName、KPINo、KPIName、TargetType、TargetValue2、TargetValueLow、TargetValueUp、ActualValue、ActualValueScript、Creator、CreateDate。TargetType 套用 ValueList；數值靠右；CreateDate 格式 `yyyy/MM/dd HH:mm:ss`。
- 本功能只有查詢與 Close，沒有編輯或新增。`ActualValueScript` 是歷程欄位原樣顯示，不在 RT906 查詢畫面執行。

## Service／Core 查詢語意與限制

- Core 基礎條件為 `KPITreeName Is Not Null`。KPITreeName 有值時用等號篩選；StartDateTime 有值時使用 `CreateDate > StartDateTime`；EndTime 有值時使用 `CreateDate < EndTime`。兩個端點都嚴格排除，不是含界區間。
- 舊 SQL 以字串串接樹名稱及日期，沒有 ORDER BY、分頁、最大日期跨度或筆數上限。若 Service 兩個條件皆未傳，Core 會讀取所有非空樹名紀錄；Form 雖防止此情況，server 端沒有同等防線。
- Form 只在資料取得後做穩定性不足的三欄排序；同一樹／KPI／名稱的多筆歷程在沒有 CreateDate 次排序時仍可能前後不定。
- 直接查詢表為 `tblEKBKPILog`。repo 未找到其可信 Oracle source DDL／metadata；公司桌機受保護 Oracle profile 不存在，未查 Oracle、未推測欄位或新增 CREATE-only SQL。

## Vue DEV 與路徑

- 路徑 `/YMES/RPT/KpiTreeLog`，由 `function:RPT:KPI TREE LOG` 對應。只使用固定 DEV 假歷程；模擬樹名精確比對、Start／End 嚴格不含界、至少一條件驗證、欄位順序與 Form 排序。使用者可水平捲動完整欄位。
- TargetType labels 與 ActualValueScript 均為預置示意，不讀 ValueList API、不執行 script，不連 Oracle／PostgreSQL。刷新頁面還原 fixtures。

## 家用端唯讀 API handoff

1. 先查 live catalog／migration 與 `ymes_app` 權限；缺少可信 Oracle DDL 時不得從 DEV fixtures 猜建 `tblEKBKPILog`。確認歷程資料同步來源與目前正式表是否有資料。
2. 只提供登入／FunctionKey 授權的唯讀 API。必須要求完整樹名或完整 Start／End；採參數化等號樹名與日期查詢，設定最大跨度／每頁列數，使用 `CreateDate, KPITreeNo, KPINo` 等穩定排序，並回報 page metadata。避免回傳全表。
3. legacy 日期條件是 `CreateDate > Start` 且 `< End`；若產品改為含界／半開區間，需明示行為變更並同步 UI，不可在 API 與 DEV 預覽間產生默默差異。
4. `ActualValueScript` 可能含資料查詢腳本；按功能權限限制讀取，確認是否真的需暴露於 browser。不得將欄位內容送回 API 執行，也不可接受 browser 指定的身份、任意 SQL 或資料來源。
5. FunctionKey ACL／路由權限尚待核 live claim。公司端未連 PostgreSQL、未實作正式 API/schema。
