# OE202 工單刪除

- 選單為「工單管理 → 工單 → 工單刪除」，FunctionNo `MO DELETE`，FunctionKey `OE202`。Vue 入口為 `/YMES/OE/ManufacturingOrderDelete`。
- 已核對 `STD/MESWin/OE/OE_MODelete/frmMODelete.vb` 及內嵌 Designer、`wsOE.LoadMOBasis`／`DelMOBasis`、`clsOEBasis.DelMOBasis` 和 `clsBasis_UPD.SetMOBasisIssueState`。主檔 DDL、鍵和索引用 [OE201](工單基本資料.md)。

## 篩選與批次操作

- 原 Form 依查詢條件組合 RONo/ItemNo、CustomerNo、ProductNo/Version、MONo 前綴、ENGNo/Version、MOTypeNo、MOSource、MOState。MOState 未選時預設 0／1／2／3；IssueState 可為任一狀態。
- Form 確認一次後逐筆處理，傳 MONo、IssueState、DataStamp，可能附 FromERP、挑片來源和 AdditionalXml。待簽核不通過。MOState=6 或 99 不可刪，TS 還擋 MOState=3。原表單同時含現行 FromERP 和舊說明前綴判定，只有 FromERP 真值被傳為該 Service 旗標。
- Service 若收到 FromERP=true，改以 CAS 停用；一般工單先重讀 IssueState，0／-1 進 Core 硬刪，2 停用。Core 硬刪前查 `TBLWIPLOTBASIS` 生產批與 `TBLOEMOMATERIALSTATE` 正量，另涉及元件 booking、屬性、用料、流程及訂單未開量。

## DEV 與家用端交接

- DEV 使用 OE201 的 localStorage。前綴與欄位篩選後可多選，取消確認不會寫入。一般未簽核／不使用硬刪，已簽核或 ERP 示範列停用。假資料可示範生產批阻擋，發料阻擋由相同模型判定。DEV 一律擋已發放工單，採用 TS 的保守限制。首筆失敗後停止，回報成功筆數，先前成功資料在同一次本機寫入保留。
- 正式查詢共用 OE201 DTO 並支援上述條件。沿用 OE201 DELETE 路由，由伺服器以交易重查 IssueState、MOState、FromERP、版本、批號與用料狀態。客製 ERP、廠別、挑片狀態與庫房回復需依原 Core 補齊，避免接收 UI 傳入狀態作為權威。硬刪採交易及一致鎖順序，409 回報競態，批次遇錯保留前序的獨立成功筆數。
