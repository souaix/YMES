# OE102 訂單結案

- 選單為「工單管理 → 訂單 → 訂單結案」，FunctionNo `RO CLOSE`，FunctionKey `OE102`。Vue 入口為 `/YMES/OE/ReceivingOrderClose`。
- 已核對 `STD/MESWin/OE/OE_ROClose/frmROClose.vb` 及內嵌 Designer、`wsOE.LoadROBasis`／`SetROBasisState`、`clsOEBasis.SetROBasisState`。舊表單載入 IssueState=2、ROState=2 或 99，從 `TBLOEROBASIS.ROSTATE` ValueList 取名稱。確認後逐筆轉 99，遇到不可結案或 Service 錯誤時停止。
- `wsOE.SetROBasisState` 依請求的 IssueState=2 呼叫 Core，Core 只按 RONo 更新 ROState。結案不更改 IssueState，未見連動寫明細或屬性。資料來自 OE101 已查證的 `TBLOEROBASIS`。結構與 CREATE-only 參考見 [OE101](訂單基本資料.md)。

## DEV 與正式接續

- DEV 與 OE101 使用同一份 localStorage 訂單。可按 RONo 查詢、多選待結案訂單、取消或確認。結案後該筆仍顯示，且不能重選。DEV 以單次本機寫入更新選取筆數，搜尋文字做不分大小寫的字面包含。
- 家用端沿用 OE101 DTO 與查詢，支援 `issueState=2&roState=2,99`，以 `POST /api/oe/receiving-orders/{roNo}/close` 執行。更新時以實際狀態及 nullable DataStamp 檢查，交易內重新確認 IssueState=2、ROState=2，只有符合才轉 99。409 時由 UI 重新載入。保持與 OE101 的刪除、停用、核准和結案互斥。
- 正式多選先確認一次，再按列依序呼叫單筆操作。第一筆失敗時回報已完成筆數及失敗訂單。此畫面保留結案狀態彙整，現場 ValueList 由正式字典提供。
