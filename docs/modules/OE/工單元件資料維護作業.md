# OE209 工單元件資料維護作業

- 選單為「工單管理 → 工單 → 工單元件資料維護作業」，FunctionNo `MO COMPDATA MAINTAIN`、FunctionKey `OE209`。Vue 入口為 `/YMES/OE/ManufacturingOrderComponents`。
- 依 `STD/MESWin/OE/OE_MOComponentMaintain/frmMOComponentMaintain.vb` 及內嵌 Designer，`wsOE.LoadMOBasis_Component`、`LoadMOComponent`、`UpdMOComponentMaintain`，以及 `clsOEBasis` 元件增刪與紀錄方法。

## 操作規則

- Form 可依產品／客戶及工單查詢，候選傳 IssueState=2、MOState=2/3。表單查詢確認工單流程可帶元件、存在既有元件、且未含庫房 InventoryNo 的元件。異動前讀序號設定及單位轉換，自動取料號時呼叫 `wsSYS.GetComponentNo_Multiple`。
- 新增元件筆數受工單量限制。每列分現存、新增、刪除；刪除新增列直接移除，刪除舊列標記後一起保存。已發放元件 ReleaseState=1 無法刪除。保存前檢查編號空白及重複，手動編號另查既有元件。
- `UpdMOComponentMaintain` 讀 `ComponentNew` 和 `ComponentDel`，執行同次增刪及 `AddMOComponentLog` 中的流水紀錄，再一起執行 SQL。異動紀錄 Oracle 名稱為 `TBLOEMOCOMPMANTAINLOG`，保留來源拼字。

## Oracle 結構及 API 交接

- 現行元件 `TBLOEMOCOMPONENT` 的鍵是 (MONO, COMPONENTNO)，見 [OE201](工單基本資料.md) DDL。公司端以 PowerShell 5.1 + ODP.NET 讀取異動紀錄表 DDL、唯一索引。紀錄鍵為 (MONO, COMPONENTNO, EVENTTIME)，來源 DATE 到秒，須特別處理同秒異動。
- [Oracle 異動紀錄 DDL](../../../database/reference/mestest_oe_mo_component_log_source_ddl.sql)
- [家用端 PostgreSQL CREATE-only 參考](../../../database/reference/mestest_oe_mo_component_log_create.sql)
- 建議使用 `GET/PATCH /api/oe/manufacturing-orders/{moNo}/components`。PATCH 以新增／刪除差量、原 DataStamp，於同交易重查工單及元件資格、主要鍵、ReleaseState 與全域重複規則，保存差量與稽核。正式取號、預留、轉換、庫房排除與撤銷均需保留伺服器契約。避免信任前端送出的發布狀態及稽核身分。

## 公司端 DEV

- 與 OE201 使用同一工單與元件集合。提供候選工單、異動草稿、剩餘元件數、手動或 DEV 編號、新增、刪除／復原及確認。保存後更新本機 DataStamp。已發放示範列唯讀。DEV 編號未接正式序號，單位採工單既有元件示例。異動紀錄表與正式稽核由家用端接續。
