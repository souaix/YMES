# OE201 工單基本資料

- 選單為「工單管理 → 工單 → 工單基本資料」，FunctionNo `MO BASIS`，FunctionKey `OE201`。Vue 入口為 `/YMES/OE/ManufacturingOrders`。
- 以 `Customer/Production/MESWin/OE/OE_MOBasis_THEIL_BU1` 的 `frmMOBasis_THEIL_BU1.vb`、`frmMOBasisDef_THEIL_BU1.vb` 及內嵌 Designer 為畫面與流程依據。Service 讀 `STD/MESws_STD/wsSTD/wsOE/wsOE.cs` 與 `Customer/Production/wsTHEIL/wsOE/wsOE.cs`，Core 讀 `STD/MESkc/kcOE/clsOEBasis.cs`、`kcBasis_UPD.clsBasis_UPD`。

## 原 MES 行為

- 主清單依 MONo 查詢，使用 `wsOE.LoadMOBasis_Product` 合併版本化產品，分開顯示 IssueState 與 MOState。原表單有增修刪、複製、核准、發放、用料清單、屬性。
- Def 四種來源以 MOSource 保存。0 訂單及 3 參考訂單帶 RONo 與 ItemNo，1 退貨帶 ReturnNo，2 無來源。退貨與無來源使用 RONo `N/A`、ItemNo `-1`。產品及版本、工程及版本、廠別、工單量及單位、工單類型、優先序和計畫完工日由主檔保存。
- Def 新增／複製呼叫 `wsOE.AddMOBasis`，表單另組 ChildMO、MOProcess、MOComponent、MOProperty、WaferSource 和 MOAutoSemiOut。Edit 使用 `wsOE.EditMOBasis` 帶 IssueState、舊 DataStamp；原客製表單另區分是否重新挑片。Core 可能同時處理訂單未開量、庫存元件 booking、子工單、用料及接收屬性。這些須一起處理交易、回復與業務鎖。
- Form 核准前檢查流程、需要的元件與數量、受控屬性、GBOM 版本及 THEIL 檢視結果，再呼叫 `ApproveMOBasis`。無 Job 時 IssueState、MOState 轉為 2，有 Job 時走簽核及 callback，並有子工單遞迴處理。
- 發放要求 MOState=2、檢查用料、流程及元件數量，呼叫 `SetMOBasisState` 傳 MOState=3 與舊 DataStamp。刪除另有客製旗標及跨表守門。標準 Service 有 0／-1 硬刪、2 停用的分支；Core 硬刪涉及工單流程、元件、屬性、用料、庫房與訂單引用。

## 家用端 API 與公司端 DEV 範圍

- 建議路由 `/api/oe/manufacturing-orders`，集合支援 MONo、IssueState，單筆附流程、元件、接收屬性及版本資訊。主檔更新以 nullable DataStamp 和實際狀態作 CAS。正式新增、更新、複製、核准、發放、停用或硬刪須使用伺服器鎖定的 aggregate。工單引用訂單時，要與 OE101 用一致鎖次序，防止訂單刪除與工單開立競爭。
- 正式流程另需核對 `TBLOEMOMATERIALLIST`、`TBLOEMOMATERIALSTATE`、`TBLOEMOSEMIOut`、訂單明細、產品版本／流程／GBOM、庫房與 THEIL 服務的寫入契約。這些跨模組表和回調不在五張 CREATE 參考內。請依家用端待辦先核對 PostgreSQL 現況及 migration history。
- DEV 實作工單搜尋、四種狀態、增修刪、複製、流程／元件／屬性、用料預覽、核准及發放。DEV 使用單筆選取、手動輸入訂單／退貨引用、固定產品和示範用料。確認取代正式簽核；核准與發放檢查流程、元件存在及數量，再更新假資料狀態。正式用料計算、跨模組 booking／數量扣回、ERP、挑片、子工單、GBOM 版本與多選批次未接入。
