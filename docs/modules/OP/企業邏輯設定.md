# 企業邏輯設定（OP102）

## 功能識別

| 項目 | 內容 |
| --- | --- |
| FunctionNo / FunctionKey | BR BASIS / OP102 |
| 三層選單 | 作業站資料 → 作業站設定 → 企業邏輯設定 |
| WinForms 清單 / 定義 Form | frmBusinessRuleBasis / frmBusinessRuleBasisDef |
| WinForms DLL | OP_BusinessRuleBasis.dll |
| Vue 元件 / URL | web/src/components/BusinessRuleBasisMaster.vue / /YMES/OP/BusinessRules |
| Oracle 主表 | MESTEST.TBLOPBUSINESSRULEBASIS |
| DT 情境 lookup | MESTEST.TBLOPSCENARIOBASIS |
| 主鍵 | BRNO |
| 公司端狀態 | Vue DEV 假資料操作完成；Production API 與 YMES schema 比對交由家用端 |

## WinForms 程式來源

已直接檢視 STD/MESWin/OP/OP_BusinessRuleBasis/frmBusinessRuleBasis.vb、frmBusinessRuleBasisDef.vb、STD/MESws_STD/wsSTD/wsOP/wsOP.cs、STD/MESkc/kcOP/clsOpBasis.cs 及 STD/MESkc/kcBasis_UPD/clsBasis_UPD.cs。Oracle 原始結構透過 Windows PowerShell 5.1、Oracle.ManagedDataAccess 與本機受保護連線唯讀查詢 DBMS_METADATA、ALL_INDEXES、ALL_CONSTRAINTS；沒有查詢 MES 業務資料列，也沒有在 Oracle 執行 DDL。

這個 OP102 是全域企業邏輯定義。它與 OP101 可重用的作業站法則定義、作業站主檔中 OP rule 指派資料是不同功能。

## 清單畫面

- 主 Form ClientSize 為 1008×591、WindowState=Maximized，標題為 Business Rule Basis。Grid 靠左並隨視窗縮放，操作按鈕靠右；共用 frmBasisTemplat 提供簽核狀態與查詢列。
- 查詢欄位只有 BRNo。預設顯示 IssueState=0 未簽核；狀態列含未簽核 0、簽核中 1、已簽核 2、不使用 -1。WinForms 載入全部狀態後在用戶端切換 Grid filter。
- 右側按鈕：ADD (A)、EDIT (E)、DEL (D)、Copy (C)、Approve (Y)、Close (X)。Print 與 Find 按鈕存在於 Form，但設為不可見。
- Grid 欄位順序：BRNo、BRName、RuleType、RuleMethod、FunctionName、InterfaceName、InterfaceURL、Description、Creator、CreateDate、AllowTimeLimitControl、BRProdType、Reviser、ReviseDate。IssueState 和 DataStamp 不顯示；時間格式 yyyy/MM/dd HH:mm:ss。
- RuleType 顯示 System=0 / Customer=1；RuleMethod 顯示 Automatic=0 / Manual=1 / DT=2。AllowTimeLimitControl 與 BRProdType 標籤由 MES ValueListProvider 動態供應，不應把下方 DEV 標籤當成生產環境正式名稱。

## 定義視窗與欄位

frmBusinessRuleBasisDef ClientSize 為 490×591，置中顯示；主要群組框 Business Rule Basis Define 尺寸 466×451。底部沿用基底 Form 建立/修改資訊。按鈕由左到右是確定、關閉、套用。

| 欄位 | 行為與驗證 | Oracle 欄位 |
| --- | --- | --- |
| BR No | 必填；離開欄位時轉大寫；Edit 唯讀；新增/複製可輸入 | BRNO VARCHAR2(20) NOT NULL |
| BR Name | 必填 | BRNAME VARCHAR2(50) NOT NULL |
| BR Prod Type | ValueListProvider 依 BRPRODTYPE 載入；Form 載入後 disabled；選值代碼以 ValueList index + 1 儲存 | BRPRODTYPE NUMBER(1,0) |
| Rule Type | 必選 System=0 或 Customer=1；新增沒有預設選項 | RULETYPE NUMBER(1,0) DEFAULT 0 |
| Rule Method | 必選；Automatic=0、Manual=1、DT=2；新增沒有預設選項 | RULEMETHOD NUMBER(1,0) DEFAULT 0 |
| Function Name | Automatic 必填；Manual 可單獨使用；選項由 BR plugin/function catalog 載入 | FUNCTIONNAME VARCHAR2(50)、EXECUTIONFILE VARCHAR2(50) |
| Interface Name | Manual 介面分支可選 | INTERFACENAME VARCHAR2(50)、EXECUTIONFILE VARCHAR2(50) |
| Interface URL | 僅 Manual 可輸入，最多 100 字元；Manual 可只填 URL | INTERFACEURL VARCHAR2(100) |
| DT ScenarioNo | 僅 DT 可用；選項從核准的 Scenario Basis 載入，依 ScenarioNo 排序 | 以 INTERFACENAME VARCHAR2(50) 儲存，不是獨立欄位 |
| AllowTimeLimitControl | Yes=1 / No=0；新增預設 No；GroupBox 在 Form 載入後 disabled，既有值保留 | ALLOWTIMELIMITCONTROL NUMBER(1,0) DEFAULT 0 |
| Description | 可空多行文字 | DESCRIPTION VARCHAR2(255) |

### Rule Method 欄位切換

| 方法 | WinForms 互動及資料映射 |
| --- | --- |
| Automatic | 清空 Function/Interface/URL/Scenario 欄；只啟用 Function Name。儲存 FunctionName 和所選功能的 ExecutionFile。 |
| Manual | 清空上述欄位；啟用 Function Name、Interface Name、Interface URL。可選 FunctionName，或用 InterfaceName/URL；不得同時填 FunctionName 和 InterfaceName/URL。InterfaceName 與 URL 可一起填。 |
| DT | 清空上述欄位；只啟用核准 ScenarioNo。儲存時 FunctionName 與 URL 為空，ScenarioNo 寫入 InterfaceName。 |

Rule Method 切換時會清除方法欄位。BR Prod Type 與 AllowTimeLimitControl 雖在清單和定義視窗顯示，WinForms 定義窗會停用它們；修改時保留載入值，不把 disabled 當作 null 清空。

### 選項來源

- LoadBRFunctionName 會呼叫 PluginManager_BR.BuildPluginControllingList，並加入傳回的 FunctionName、ExecutionFile；另有 plugin manager 擴充點。Production API 必須從受控的函式註冊/外掛 catalog 提供 allow-list，不得執行用戶端傳入的函式或依任意資料列反射載入 DLL。
- Interface Name 是 WinForms 端掃描可執行檔中的 FRMBR Form 後建立的名稱/檔案配對，不是 Oracle lookup 表。正式 API 應回傳已部署且允許使用的介面選項與 ExecutionFile。
- Scenario lookup 呼叫 LoadScenarioBasis，Web Service 未傳狀態時預設 IssueState=2；因此只列核准情境。舊 Core 對 tblOPScenarioBasis 查詢不取 Scenario XML，OP102 只需 ScenarioNo/ScenarioName。
- BRProdType 使用 ValueListProvider.GetValueList(TBLOPBUSINESSRULEBASIS, BRPRODTYPE, False)；AllowTimeLimitControl 顯示清單使用 TBLOPBUSINESSRULEBASIS/TIMELIMITCONTROL 的系統 ValueList。YMES API 需沿用其實際已部署設定；不要把 DEV 示意選項寫回生產資料。

## 操作、簽核與刪除

| 動作 | WinForms 規則 |
| --- | --- |
| ADD | 空白新增；IssueState=0，由服務設定 Creator/CreateDate。 |
| EDIT | 只允許 IssueState=0；BRNo 唯讀；以 DataStamp 編輯。 |
| Copy | 將來源商業欄位帶入新增模式，BRNo 可改；使用新的 Creator/CreateDate、IssueState=0/DataStamp，不複製來源稽核。 |
| DEL | 可多選並逐筆處理；未簽核 0、不使用 -1 實體刪除；已簽核 2 改成不使用 -1；簽核中 1 不可刪除。前面已成功的多筆操作不會因後續失敗回復。 |
| Approve | 可多選，但只處理 IssueState=0。IssueNo 為 BR BASIS。未設定 Issue Job 時直接改為已簽核 2；設定簽核工作時先改為簽核中 1，Issue Job 核准 callback 改 2、退回改 0。 |
| 套用 | 執行與確定相同的 Add/Edit 業務欄位寫入；成功後視窗保持開啟。修改成功後本機 DataStamp 加一。 |
| 確定 | 執行相同 Add/Edit 後關閉定義窗。 |
| 關閉 | 放棄尚未送出的修改並關閉。 |

EditBusinessRule 與 SetBusinessRuleIssueState 使用 BRNo + 傳入 DataStamp 作更新條件，修改後 DataStamp + 1；更新也寫 Reviser/ReviseDate。家用端應檢查受影響列數，零列視為資料過期/並發衝突，不應沿用舊 Core 回傳 success 的盲點。

多筆 Approve/Delete 是逐筆呼叫服務，不是跨全部列的一個交易。API/前端需回報已完成與失敗編號，不能假設所有列全成或全敗。簽核中的 Issue Job、Issue Job Detail、共用 Issue Master/Control 是簽核功能依賴，不是 OP102 新表。

## Oracle 資料結構

- 主表原始 DDL：database/reference/mestest_op102_business_rule_basis_source_ddl.sql。
- 主表 PostgreSQL CREATE-only 對照：database/reference/mestest_op102_business_rule_basis_create.sql。
- DT 情境 lookup 原始 DDL：database/reference/mestest_op102_scenario_basis_lookup_source_ddl.sql。
- DT 情境 lookup PostgreSQL CREATE-only 對照：database/reference/mestest_op102_scenario_basis_lookup_create.sql。
- TBLOPBUSINESSRULEBASIS 的唯一主鍵為 PK_TBLOPBUSINESSRULEBASIS(BRNO)。ALL_INDEXES/ALL_CONSTRAINTS 確認僅一個 PK unique index、沒有 FK/額外 index。
- TBLOPSCENARIOBASIS 唯一主鍵為 PK_TBLOPSCENARIOBASIS(SCENARIONO)，僅一個 PK unique index、沒有 FK/額外 index。它是 OP102 的共享查詢依賴，不代表要再建立 Scenario CRUD。
- OP 主表其餘欄位包括 KernelModule、KernelFunctionName、ActiveModule、SEMI_WAFER、IC_CP_PKG、IC_FT_PKG、DISCRETE_PKG、LED_PKG、IC_INGOT、EPI_WAFER、IC_SMT。畫面沒有編輯它們；PUT 必須只改允許欄位並保留它們。
- PostgreSQL 對照保留 Oracle NULL/default/PK；Oracle DATE 映射為 timestamp without time zone，NUMBER(p,0) 映射 numeric(p,0)。CREATE-only 不是 migration。家用端先比對 live schema/migrations，缺表才新增 forward migration，不要將參考檔直接套在正式資料庫。

## Production API handoff

以下是公司端 Vue 的需求契約，家用端實作前需核對 YMES live schema、既有 API、共用登入/權限/Issue Service：

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | /api/operation-business-rules?issueState=all&brNo= | 回傳完整四狀態集合供前端切換狀態；BRNo 空值為全部，非空按 WinForms 查詢語意搜尋；包含 Grid 欄位及隱藏 IssueState/DataStamp。 |
| GET | /api/operation-business-rules/options | 回傳 functions(name/executionFile)、interfaces(name/executionFile)、核准 scenarios(no/name)、brProductTypes(code/label)、allowTimeLimitControl(code/label)。 |
| POST | /api/operation-business-rules | 新增 OP102 定義；伺服器設 Creator/CreateDate、IssueState=0、初始 DataStamp。只接受 OP102 編輯欄位，不接受 audit/IssueState/Kernel/Module flags。 |
| PUT | /api/operation-business-rules/{brNo} | 只允許未簽核列；body 含 DataStamp，DB 條件以 BRNo + 舊 DataStamp CAS，成功遞增並更新 Reviser/ReviseDate。忽略或拒絕未暴露欄位，避免清除其他產品線 flags。 |
| DELETE | /api/operation-business-rules/{brNo} | Body 帶 IssueState/DataStamp；0、-1 實體刪除；2 以 CAS 設 -1 並更新 audit；1 拒絕。多選仍逐筆回報結果。 |
| POST | /api/operation-business-rules/{brNo}/approve | Body 帶 IssueState=0 與 DataStamp；依 IssueNo BR BASIS 和現行 Issue Job/Issue Control 決定立即 active 或進入簽核；server 寫 EventLog/audit。 |

API 必須要求登入並驗證 OP102 FunctionKey/權限，採參數化 SQL；簽核 callback 需檢查 DataStamp 與受影響列數。不得信任用戶端 Creator、Reviser、IssueState 或 DataStamp 作為實際權限依據。不得由資料庫中的 FunctionName/ExecutionFile 自動載入或執行任意 DLL。

## 公司端 DEV 頁

- 路徑 /YMES/OP/BusinessRules，掛在作業站資料 → 作業站設定 → 企業邏輯設定。
- 僅 DEV 開發區使用 localStorage key ymes.dev.op-business-rule-basis.v1。假資料含四種狀態；操作只變更瀏覽器假資料，不呼叫生產 API。
- 提供 BR No 即時查詢、四狀態切換、多選、ADD/EDIT/DEL/Copy/Approve/Close、欄位條件切換、Apply/Confirm/Close、長度/互斥驗證與 audit 展示。
- 函式、介面、情境、ValueList 是標記為 DEV 的範例。尚未執行 build、test 或瀏覽器驗收；原生 plugin 控制清單、業務 DLL 執行能力、簽核等 production API 由家用端接手。
