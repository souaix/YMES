# 作業站主檔（OP Basis）

## 識別資訊

| 欄位 | 值 |
| --- | --- |
| 第一層 | OP／作業站資料 |
| 第二層 | 作業站設定（需以 Oracle 選單資料核實） |
| WinForms 主畫面 | `frmOPBasis` |

## WinForms 主畫面

來源：`STD/MESWin/OP/OP_OPBasis/frmOPBasis.vb`。

- 預設 IssueState=0；狀態列提供未簽核 0、簽核中 1、已簽核 2、不使用 -1。
- 查詢欄位為 OPNo，輸入條件透過共用查詢條件組合器送出。
- 清單含 OPNo、OPName、OPShortName、OPType、OPClass、PSNo、OPOrder、CountOpUnitQty、StdUnitRunTime、StdQueueTime、PrintOutOnRunCard、SPCInspAbnormalHoldLot、MaterialOption、MultiOperatorMode、OSOption，以及 Creator/CreateDate/Reviser/ReviseDate。IssueState、RuleXMLString、DataStamp 等欄位供程式使用並隱藏；依版本及欄位設定仍需畫面核對。
- OPClass 顯示值固定為 0 一般作業站、1 品質管理、2 其他作業站。MaterialOption、MultiOperatorMode、OSOption 由 ValueListProvider 載入，精確值/文字需從來源系統選項資料核實。DEV 預覽暫用舊 `GenerateMaterialOptionValueList` / `GenerateMultiOperatorModeValueList` 的來源碼文字，需 Oracle ValueList 對照後才能視為正式規則。

### 主畫面按鈕

| 按鈕 | WinForms 行為 / 限制 |
| --- | --- |
| 新增、修改、複製 | 共用 `frmOPBasisDef`；複製依原程式檢查製程段一致，並依表單設計清除新 OPNo。 |
| 刪除 | 對仍被 `TBLOPGROUPDETAIL` 引用的 OPNo 先阻擋。未簽核/不使用資料實際刪除；已簽核資料改為不使用；其他狀態不允許。服務會清除多張作業站附屬表，正式 API 須在單一交易中重現。 |
| 核准 | 僅 IssueState=0，帶 DataStamp。若作業商業規則使用 `LC_CO_MEASURE`，必須有 `CPass` 屬性。核准後若規則使用 `L_SPC_GEN`、`L_SPC_FAI`、`L_SPC_IPQC`，分別檢查對應 QC 檢驗機會；缺項顯示警告。 |
| 屬性 | 動態呼叫 `OP_OPProperty`，帶 OPNo。 |
| 資源 | 開啟 `frmOPResource`；支援 By Area / By EQPType、區域映射及左右選取清單。 |
| 商業規則 | 開啟 `frmOPBusinessRuleDraw`；IsNetFlow=1 時停用 AddFlowBR 並隱藏 Confirm。 |
| 參數 | 開啟 `frmOPParameterSetup`；需有選取 OPNo 與 PSNo。表單有 Attrib、Rule、EQPRecipe 等區塊。 |
| QC Item | 開啟 `frmOPQCItem`，帶 OPNo/OPName；包含 Inline/Offline 的 Group、Attribute、Variable 關聯。 |
| Error | 開啟 `frmOPError`，帶 OPNo/OPClass，支援全選/全不選。 |
| 複製作業資料 | 開啟 `frmOPCopyOPDataBasis`。各資料種類的複製勾選與交易行為需再逐段對照程式。 |
| SubOP | 開啟 `frmOPSubOP`，維護子作業站關聯。 |
| Import | 開啟 `frmOPDataImport`；成功後重載清單。 |
| Abnormal / Recipe Temp | 在目前主畫面 Designer 中隱藏，不列為可見主畫面按鈕；其 Form 原始碼仍存在。 |

## 新增 / 修改表單

來源：`frmOPBasisDef.vb`；資料服務：`STD/MESkc/kcOP/clsOpBasis.cs`。

| 欄位 | 規則 / 來源 |
| --- | --- |
| OPNo | 必填；不可含逗號；不允許 `LOTCREATE`；不可與現有 OPType 重複。 |
| OPName、OPType、PSNo | OPName 必填；OPType 與 PSNo 由來源主檔挑選，精確選項/驗證需對照共用選擇器。 |
| OPClass | 0 一般作業站、1 品質管理、2 其他作業站。 |
| OPShortName、OPOrder、Description | 簡稱、工序順序、說明。 |
| StdUnitRunTime | 空白預設 0；必須為數字且 >=0。 |
| CountOpUnitQty | 空白預設 1；必須為整數且 >=1。 |
| StdQueueTime | 空白預設 0；必須為數字且 >=0。 |
| MaterialOption、MultiOperatorMode、OSOption | ValueListProvider 提供；不可依程式註解自行推定目前可選值。 |
| PrintOutOnRunCard、SPCInspAbnormalHoldLot | 以 0/1 儲存；清單顯示否/是。 |
| ErrorQtyToSPC | Designer 中對應控制項目前隱藏；API/schema 是否仍需支援，依來源 DDL 與其他讀寫點查證。 |
| PartialMode | Net Flow 條件下由表單設定；不是一般使用者可任意輸入欄位。 |

新增預設 IssueState=0；新增/修改需保存 Creator/CreateDate/Reviser/ReviseDate。所有修改及核准須使用 DataStamp 防止舊資料覆寫。

## 服務資料表與刪除範圍

`clsOpBasis.DelOPBasis` 明確刪除/操作下列關聯後再刪 `TBLOPBASIS`：`TBLOPABNORMAL`、`TBLOPERROR`、`TBLOPPROPERTY`、`TBLOPBUSINESSRULERELATION`、`TBLOPAREA`、`TBLOPEQUIPMENTTYPE`、`TBLOPATTRIB`、`TBLOPRULE`、`TBL_CPOPRULE`、`TBL_CPOPRULECONDITION`、`TBL_FTOPRULE`、`TBL_FTOPRULECONDITION`、`TBLOPEQPRECIPE`、`TBLOPQCITEM`、`TBLOPRULEXML_CLOB`（依資料庫 Long 型別支援條件）、`TBLOPSUBOPBASIS`。作業站群組引用 `TBLOPGROUPDETAIL` 會先阻止刪除。

以上為 WinForms Service 程式碼引用證據。18 張表的 Oracle 原始 DDL 已由公司端 PowerShell 5.1 透過 DBMS_METADATA.GET_DDL 唯讀擷取；來源檔與轉換後的空表 CREATE SQL 如下。實際外鍵仍以 DDL 內容為準，不能只按 Service 引用推定。

- Oracle 原始 DDL：database/reference/mestest_operation_and_system_source_ddl.sql
- PostgreSQL 空表 CREATE SQL：database/reference/mestest_operation_and_system_create.sql
- 本批作業站表：TBLOPBASIS、TBLOPGROUPDETAIL、TBLOPABNORMAL、TBLOPERROR、TBLOPPROPERTY、TBLOPBUSINESSRULERELATION、TBLOPAREA、TBLOPEQUIPMENTTYPE、TBLOPATTRIB、TBLOPRULE、TBL_CPOPRULE、TBL_CPOPRULECONDITION、TBL_FTOPRULE、TBL_FTOPRULECONDITION、TBLOPEQPRECIPE、TBLOPQCITEM、TBLOPRULEXML_CLOB、TBLOPSUBOPBASIS。
- Oracle index 字典另行核對 21 張作業站/系統表各只有一個主鍵唯一索引，沒有獨立額外索引；表的 PK 約束已隨 CREATE TABLE 保留。這些表在 Oracle constraint 字典中沒有 FK 類型約束。

## API 契約（交家用電腦建置）

建議正式端點：

- `GET /api/operations?issueState=&keyword=`：依狀態與 OPNo 查詢，回傳清單欄位及 DataStamp。
- `GET /api/operations/{opNo}`：讀取主檔與編輯所需選項。
- `POST /api/operations`、`PUT /api/operations/{opNo}`：新增/修改及驗證；PUT 檢查 DataStamp。
- `POST /api/operations/{opNo}/approve`：執行 CPass、SPC/QC 檢查及核准流程。
- `DELETE /api/operations/{opNo}`：套用群組引用檢查與 IssueState 刪除/停用規則。
- 子功能按各原表拆成 `/resources`、`/business-rules`、`/parameters`、`/qc-items`、`/errors`、`/sub-operations`；複製設定及 Import 另走明確命令/工作端點。

這些是依 WinForms 行為整理的待建契約；尚非目前 API 已實作狀態。多表操作需交易，引用衝突使用 409，DataStamp 衝突使用 409 或 412 並回傳可辨識錯誤碼。

## Vue 實作與待辦

- 主清單目前共用 `MasterDataMaster.vue`，有狀態篩選、OPNo 查詢、主檔 CRUD 按鈕和基本表單。
- OP 子功能按鈕已接到 DEV 專用互動視窗：Property/Resource/Business Rule/Parameter/QC Item/Error/SubOP 可增刪與修改 localStorage 假資料；複製作業資料有來源與類別勾選；Import 有 CSV 預覽。它們仍是簡化版，尚未逐項對照所有 WinForms 欄位/檢查；正式環境按鈕在 API 未提供時維持停用。
- 畫面須保留 WinForms 欄位/按鈕語意，KD 色系按鈕與欄位；DEV 寫入限瀏覽器本機假資料，正式環境不可回報假成功。
- PostgreSQL CREATE SQL 是依實際 MESTEST 原始 DDL 轉換；Oracle tablespace/storage 實體儲存子句已省略，不含 MES 業務資料。家用電腦先逐欄比對 YMES 現有表，缺表才建立，既有表差異以 migration 處理。

## 同模組主檔關聯

「作業站類別資料」OP103 規格見 [作業站類別資料.md](./作業站類別資料.md)。OPType 是 OP Basis 的分類 lookup；舊 Core 會保護 TBLOPBASIS.OPNO 與 TBLOPTYPE.OPTYPE 的大小寫不敏感共用 namespace。OPType 屬性也沿用 TBLOPPROPERTY，家用端需在 API 中一致處理。「作業站法則設定」OP101 規格見 [作業站法則設定.md](./作業站法則設定.md)：OP101 的 TBLOPCONTROLRULE 是標準版可重用法則定義；OP Basis 每個作業站上的法則指派另存 TBLOPRULE/TBL_CPOPRULE，兩者用途與 CRUD 範圍不同。
