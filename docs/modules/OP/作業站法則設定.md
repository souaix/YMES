# 作業站法則設定（OP Control Rule）

## 功能識別

| 項目 | 內容 |
| --- | --- |
| FunctionNo / FunctionKey | `OP RULE BASIS` / `OP101` |
| 三層選單 | 作業站資料 → 作業站設定 → 作業站法則設定 |
| WinForms 清單 / 定義 Form | `frmOPControlRule` / `frmOPControlRuleDef` |
| WinForms DLL | `OP_ControlRule.dll` |
| Vue 元件 / 路由 | `web/src/components/OperationControlRuleMaster.vue` / `/YMES/OP/ControlRules` |
| Oracle 主表 | `MESTEST.TBLOPCONTROLRULE` |
| 主鍵 | `RULENO` |
| 公司端狀態 | Vue DEV localStorage 假資料完成；Production API 待家用端實作 |

## WinForms 來源與行為

已直接閱讀 `STD/MESWin/OP/OP_ControlRule/frmOPControlRule.vb`、`frmOPControlRuleDef.vb`、`STD/MESws_STD/wsSTD/wsOP/wsOP.cs`、`STD/MESkc/kcOP/clsOpBasis.cs` 與 `STD/MESkc/kcBasis_UPD/clsBasis_UPD.cs`。原生 Oracle DDL 以 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 從本機受保護連線唯讀取得；沒有讀取業務資料列，也沒有在 Oracle 執行 DDL。

## 清單畫面

- WinForms ClientSize `1008×591`，標題 `OP Control Rule Define`，群組框 `OP Control Rule`。沿用共用 `frmBasisTemplat` 查詢區，搜尋欄位只有 `RuleNo`；此頁設定 `IssueVisable=False`，沒有簽核狀態篩選。
- Grid 在左、操作按鈕在右、Close 在右下。按鈕為 `ADD (A)`、`EDIT (E)`、`DEL (D)`、`Copy (C)`、`Close (X)`；本功能沒有 Approve、Property 或 IssueState。
- `LoadOPControlRule` 取回 `tblOPControlRule` 後，WinForms 在前端套用 `RuleClass = 0`。wsOP 的新增預設 RuleClass 0，服務註解 1=CP、2=FT；OP101 標準頁不列出其他 RuleClass。
- Grid 顯示欄位順序：RuleNo、RuleName、RuleScript、Description、Creator、CreateDate、SendMail、HoldDispGroup、RuleType、Reviser、ReviseDate。日期格式 `yyyy/MM/dd HH:mm:ss`。RuleClass、RuleMode、RuleModeQty、DataStamp 不顯示。
- 「查詢」只依 RuleNo 搜尋；百分號提示沿用共用查詢列。DEV 頁使用前端即時篩選並保留空白查詢的全清單行為。

## 定義視窗及驗證

`frmOPControlRuleDef` ClientSize `519×496`，中央 `OP Control Rule Data` 群組，底部顯示建立/修改人與時間，按鈕依原視窗由左至右為「確定」「關閉」「套用」。欄位：

| 欄位 | WinForms 行為 | Oracle 限制 |
| --- | --- | --- |
| RuleType | Lot=0、Component=1；新建預設 Component | NUMBER(1,0) NOT NULL DEFAULT 0 |
| RuleNo | 必填；離開欄位時轉大寫；Edit 唯讀 | VARCHAR2(20) NOT NULL |
| RuleName | 必填 | VARCHAR2(50) NOT NULL |
| RuleScript | 必填、唯讀多行區；按 Define Script 呼叫動態物件 `OP_Script` 編輯 | VARCHAR2(3000) NOT NULL |
| Description | 多行文字，可空 | VARCHAR2(255) |
| Send Mail | Yes=1 / No=0，新建預設 No | NUMBER(1,0) DEFAULT 0 |
| Hold Disp Group | 唯讀欄位，按 `...` 開啟群組查詢；依 GroupNo 排序 | VARCHAR2(50) |

- 基本檢查依序要求 RuleNo、RuleName、RuleScript；Send Mail 必須選 Yes/No。Send Mail=Yes 時 Hold Disp Group 必填。網頁依正式欄位長度明確限制輸入，避免 Oracle 超長資料被截斷或等到資料庫才失敗。
- `Define Script` 的 MES 端是動態載入 `OP_Script` 物件。公司端網頁以純文字編輯器替代，保存原文字，不執行或評估腳本；該專用視覺化/結構化腳本編輯器尚未重製。
- `Hold Disp Group` 由 `wsQC.LoadHoldDispGroupBasis` 載入 `TBLQCHOLDDISPGROUPBASIS`，使用共用搜尋視窗依 GroupNo 排序選取。Def Form 雖建立 IssueState 參數，但組 InXml 時傳入空參數字串，因此舊行為沒有篩 IssueState；API lookup 應重用 QC405 的全狀態 GroupNo 查詢，不另造群組表。DEV 以明確標記的假群組供操作。
- 建立時服務寫入 Creator/CreateDate；修改時透過 `clsBasis_UPD.EditOPControlRule` 傳入 DataStamp、Reviser、ReviseDate。資料庫 DataStamp nullable 且 DEFAULT 0；API 要以舊值做並發檢查，再遞增版本。不要由前端信任或更新 audit 欄位。

## 按鈕與儲存細節

| 操作 | 舊系統行為 |
| --- | --- |
| ADD | 開空白定義視窗；成功後重新載入並定位新增 RuleNo。RuleClass 使用服務預設 0。 |
| EDIT | 依目前選取的 RuleNo 載入；RuleNo 唯讀；送 DataStamp 做版本檢查。 |
| Copy | 帶入來源欄位開啟新增模式；RuleNo 保留且可修改；儲存時新增新 RuleNo，不複製 audit/DataStamp。 |
| DEL | 可多選；先顯示確認；逐筆呼叫刪除服務，第一筆失敗即停止，成功後重新載入。Core 對 `tblOPControlRule` 做實體刪除，沒有 IssueState 軟刪或簽核流程。 |
| 套用 | 成功後保持視窗開啟。Legacy Apply payload 只傳 RuleNo、RuleName、RuleScript、Description、RuleType，新增時另帶 Creator/CreateDate，修改時另帶 DataStamp；**不傳 SendMail 與 HoldDispGroup**。 |
| 確定 | 使用相同的 Add/Edit 服務後關閉視窗；payload 另外傳 SendMail 與 HoldDispGroup。 |
| 關閉 | 關閉定義視窗或清單頁。 |

DEV 頁刻意保留 Apply 與 Confirm 的 legacy payload 差異。這表示選 Yes 後只按 Apply，郵件群組設定不會被寫入；新增/複製模式 Apply 後仍留在新增模式，再次儲存相同 RuleNo 會撞主鍵。這些是 WinForms handler 的既有行為，家用端 API 不可自行把 Apply payload 解讀成「未提供欄位=清空」。

## 資料表與結構

- Oracle 原始 DDL：[mestest_op101_control_rule_source_ddl.sql](../../../database/reference/mestest_op101_control_rule_source_ddl.sql)。
- PostgreSQL 結構參考：[mestest_op101_control_rule_create.sql](../../../database/reference/mestest_op101_control_rule_create.sql)。CREATE-only 對照不是 migration；家用端先比對 YMES live schema 及 migrations，再決定是否新增 forward migration。
- 欄位完整清單：RuleNo VARCHAR2(20) NOT NULL、RuleName VARCHAR2(50) NOT NULL、RuleScript VARCHAR2(3000) NOT NULL、Description VARCHAR2(255)、Creator VARCHAR2(10)、CreateDate DATE、HoldDispGroup VARCHAR2(50)、SendMail NUMBER(1,0) DEFAULT 0、RuleClass NUMBER(1,0) DEFAULT 0 NOT NULL、RuleType NUMBER(1,0) DEFAULT 0 NOT NULL、RuleMode NUMBER(1,0) DEFAULT 0、RuleModeQty NUMBER(2,0)、DataStamp NUMBER(11,0) DEFAULT 0、Reviser VARCHAR2(10)、ReviseDate DATE。
- DBMS_METADATA 原始 DDL 與資料字典確認唯一 index 為 `PK_TBLOPCONTROLRULE(RULENO)`；無 FK、無額外索引。PostgreSQL 對照保留 nullable DataStamp，Oracle DATE 轉 timestamp without time zone。
- OP101 表單沒有編輯 RuleMode、RuleModeQty、RuleClass。修改 API 必須保留未暴露欄位，不得把它們重設為 UI 預設。

## Production API handoff

公司端沒有 OP101 Production API。家用端先查 YMES live schema/現有 API 後再實作；下列路由是前端需求契約：

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/operation-control-rules?ruleClass=0&ruleNo=` | 回傳標準版 RuleClass=0 清單；RuleNo 空值回全部，非空依 legacy 查詢條件過濾。欄位需包含清單欄及 DataStamp/RuleClass。 |
| POST | `/api/operation-control-rules` | 新增 {ruleNo,ruleName,ruleScript,description,ruleType}；只有 Confirm 另外帶 sendMail/holdDispGroup。未提供欄位沿用 Oracle DEFAULT/legacy Add 行為。RuleClass=0、audit 由伺服器設定。 |
| PUT | `/api/operation-control-rules/{ruleNo}` | 以 DataStamp 做 CAS；更新傳入欄位，未提供 sendMail/holdDispGroup 時不得清空。增量 DataStamp、更新 Reviser/ReviseDate。保留 RuleClass、RuleMode、RuleModeQty。 |
| DELETE | `/api/operation-control-rules/{ruleNo}` | 依舊 Core 實體刪除；多選時前端逐筆呼叫，部分成功須明確回報。 |
| GET | `/api/qc/hold-disposition-groups?searchFieldName=GroupNo&searchFieldValue=` | 重用 QC405 群組查詢 endpoint；回傳全狀態群組候選，OP101 只取 GroupNo。若該 API 未完成，家用端沿 QC405 handoff 實作一次即可，不新增表或重複 endpoint。 |

API 必須沿用登入驗證及 OP101 FunctionKey/權限檢查；SQL 參數化。RuleScript 僅儲存字串，不在 API 任意執行資料庫或 OS 命令。刪除應確認僅處理 RuleNo；不得 cascade 刪除與 OP Basis `TBLOPRULE`、`TBL_CPOPRULE` 等不同用途的流程規則資料。

## 開發區實作

- 菜單路徑：作業站資料 → 作業站設定 → 作業站法則設定；URL `/YMES/OP/ControlRules`。
- 僅在 DEV + 開發區使用 `ymes.dev.op-control-rule-master.v1` localStorage 假資料。假資料含 `RuleClass=1` 的 CP 範例，用來核對頁面只呈現 RuleClass=0；假 RuleScript 不會執行。
- Web 清單支援 Ctrl/Command 多選；沒有用 URL query string 保存選取列。窄螢幕可橫向捲動完整 Grid。
- 正式資料讀寫、簽章腳本編輯器、QC Hold Disp Group lookup 仍由家用端 API/共用服務接手。
