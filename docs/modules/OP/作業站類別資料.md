## 來源程式

- 清單及按鈕：STD/MESWin/OP/OP_OPType/frmOPType.vb、Designer。
- 定義視窗：STD/MESWin/OP/OP_OPType/frmOPTypeDef.vb、Designer。
- 資料服務：STD/MESws_STD/wsSTD/wsOP/wsOP.cs 的 Load/Add/Edit/Delete/ApproveOPType；STD/MESkc/kcOP/clsOpBasis.cs 的 AddOPType/EditOPType/DelOPType。
- 原生 Oracle 結構直接透過 Windows PowerShell 5.1、Oracle.ManagedDataAccess 和本機受保護連線唯讀取得；沒有讀 MES 業務列，沒有在 Oracle 執行 DDL。

## 清單畫面

WinForms ClientSize 為 1008×591。共用 frmBasisTemplate 提供 IssueState 篩選與 OPType 查詢；資料 Grid 位於左側主區，右側垂直按鈕為 ADD、EDIT、DEL、Copy、Approve、Property，右下角為 Close。網頁保留四種狀態篩選、OP Type 查詢、左側資料表、右側縱向操作鈕，窄螢幕才改為按鈕格狀排版。DEV 欄位使用 MES/KD 黃色系。

Grid 顯示 OPTYPE、DESCRIPTION、CREATOR、CREATEDATE、REVISER、REVISEDATE；ISSUESTATE 與 DATASTAMP 作為操作資料，不顯示為 Grid 欄。日期格式為 yyyy/MM/dd HH:mm:ss。預設狀態是未簽核 0；查詢服務可取得全部狀態後由畫面篩選，搜尋欄位為 OPType。

## 定義視窗

frmOPTypeDef ClientSize 為 497×277，中央顯示 OP Type Data 群組，欄位為 OP Type 黃底文字框及 Description 多行文字框；下方顯示建立/修改資訊；按鈕為確定、關閉、套用。

- Add：OPType 必填、轉大寫；Description 可空。成功後 IssueState=0，由服務設定 Creator/CreateDate。
- Edit：只有 IssueState=0 可開啟；OPType 唯讀，只修改 Description；送入 DataStamp 做更新版本檢查。
- Copy：帶入來源 OPType 與 Description，但 OPType 可改；寫入一筆新的 UNFROZEN 類別。
- WinForms 沒有明確 MaxLength；資料庫欄位限制 OPType 20、Description 255，網頁/API 須明確拒絕超長輸入，不能截斷。
- Apply 與 Confirm 共用 Add/Edit 服務；Apply 留在視窗，Confirm 成功後關閉。Audit 欄由服務管理，瀏覽器不得將 Creator/Reviser/時間當成可信輸入。

## 操作與狀態規則

狀態碼：0 未簽核、1 簽核中、2 已簽核、-1 不使用。

| 操作 | 規則 |
| --- | --- |
| Delete | 狀態 0 或 -1 硬刪；狀態 2 改為 -1，帶 DataStamp；狀態 1 拒絕。舊 Core 硬刪前先刪 TBLOPPROPERTY 中 OPNO=OPTYPE 的屬性資料，再刪 TBLOPTYPE。家用端須在單一交易重現並以實際 live schema 核對共用屬性資料刪除範圍。 |
| Approve | 僅狀態 0；IssueNo=OP TYPE。Issue Job/Detail 不存在時直接改為 2；存在簽核流程時建 Issue Master、狀態改 1、通知第一關群組；流程通過改 2、退回改 0。此狀態轉移由 API/共用 Issue Service 管理，不由前端自行假定。 |
| Property | 呼叫 OP_OPProperty，以 OPType 作為 OPNo 維護屬性。Production 子功能 API 未完成時必須清楚提示，不可把 DEV localStorage 假資料送到正式 API。 |

OPTYPE 與 TBLOPBASIS.OPNO 共用作業站屬性 namespace：舊 AddOPType 會先以不分大小寫方式拒絕任何已存在的 OPNo。不得只依 TBLOPTYPE PK 驗證唯一；新增端點應同時檢查已存在的 OPNo。TBLOPTYPE 本身無 FK；刪除屬性前先確認 YMES 的屬性表及其他 OPType/OPBasis 使用規則。

## Oracle 結構

- 原始 DDL：[Oracle source DDL](../../../database/reference/mestest_op103_optype_source_ddl.sql)。
- PostgreSQL 結構參考：[CREATE SQL](../../../database/reference/mestest_op103_optype_create.sql)。這只是 CREATE-only 對照，家用端須先比對 YMES live schema/migrations，再新增 forward migration；不可直接在 Oracle 執行。
- 欄位：OPTYPE VARCHAR2(20) NOT NULL、DESCRIPTION VARCHAR2(255)、CREATOR VARCHAR2(10)、CREATEDATE DATE、ISSUESTATE NUMBER(1,0) DEFAULT 0 NOT NULL、DATASTAMP NUMBER(11,0) DEFAULT 0 NULL、REVISER VARCHAR2(10)、REVISEDATE DATE。
- 唯一索引只有主鍵 PK_TBLOPTYPE(OPTYPE)；沒有其他 index 或 FK。PostgreSQL 對照沿用 nullable DataStamp 與 Oracle DATE 對應 timestamp without time zone 語意。

## Production API handoff

尚未在公司端建立 API。家用端先確認既有 YMES 作業站端點與 live schema 後沿用/擴充；若尚無端點，再依以下契約實作：

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | /api/operation-types?issueState=-1&opType= | 載入全部狀態資料；UI 依選取狀態篩選。搜尋參數可空。 |
| POST | /api/operation-types | 新增 {opType, description}；伺服器大寫/驗證 OPType、檢查 TBLOPBASIS.OPNO namespace 衝突，設定 audit/state/DataStamp。 |
| PUT | /api/operation-types/{opType} | 修改 Description，帶 {description,dataStamp}；僅允許 UNFROZEN，DataStamp 不一致回 409。 |
| DELETE | /api/operation-types/{opType} | body 帶 {issueState,dataStamp}；依狀態硬刪/停用，並交易式清理相關 Property；不可接受 UI 狀態作唯一授權依據，須重查資料庫。 |
| POST | /api/operation-types/{opType}/approve | 帶 {dataStamp}，接 IssueNo=OP TYPE 共用簽核流程。 |

Production API 要求既有登入，SQL 參數化；Actor、狀態、時間、DataStamp 由 server 控制。若 YMES 缺少 TBLOPTYPE 才建立 migration；不要重建 TBLOPBASIS、TBLOPPROPERTY 或共用 Issue/Job 表。

## 開發區行為

- /YMES/MasterData/OperationTypes 從 OP → 作業站設定 → 作業站類別資料開啟。
- 只有 import.meta.env.DEV 且環境切換為開發區時使用 ymes.dev.op-type-master.v1 localStorage；清單、Add/Edit/Copy/Delete/Approve 可操作假資料。
- 網頁不以 URL query string 保存選取列；使用 Vue reactive state。
- Production 尚未有 OP103 API；Property 正式子功能亦待家用端完成 API。這不是正式資料 CRUD 已完成。
