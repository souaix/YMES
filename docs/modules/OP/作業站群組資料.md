## 主檔新增、修改、複製與刪除

### 主檔定義視窗

WinForms ClientSize 566×431，標題 OP Group Basis Define，資料框包含：

- OPGroupNo：必填，Oracle VARCHAR2(20)；離開欄位轉大寫。修改時唯讀；Copy/新增可輸入新編號。
- OPGroupName：必填，VARCHAR2(50)。
- PSNo：必填，VARCHAR2(50)；由既有生產區段選擇視窗帶入。修改時仍可更改。
- OPGroupOrder：整數 NumericUpDown，預設 0、範圍 0–999999。
- Description：多行文字，VARCHAR2(255)。
- 底部顯示建立/修改人及日期；按鈕為確定、關閉、套用。

Confirm 與 Apply 均檢查群組編號、名稱、生產區段必填。Add/Copy 呼叫 AddOPGroupBasis；Edit 呼叫 EditOPGroupBasis 並帶 DataStamp。複製只建立新的群組主檔資料，不會複製原群組的明細成員。API 必須核對欄位長度及 PK，並由登入使用者建立 audit 欄位。

### 刪除主檔

支援選取多筆，操作前顯示確認。WinForms clsOpBasis.DelOPGroupBasis 先將該群組的 TBLOPGROUPDETAIL 刪除，再刪除 TBLOPGROUPBASIS；兩個 SQL 陳述式被收集後一次交給 ExecuteSQLNoneQuery_UPD。新 API 應在同一資料庫交易中完成明細與主檔刪除，以避免留下半套資料。這是實體刪除，沒有 IssueState 軟刪除流程。

## 群組作業站明細

WinForms ClientSize 484×381，標題 OP Group Detail Define：

- OPGroupNo：由目前選取的主檔帶入，唯讀。
- OPNo：由選擇視窗帶入；修改時唯讀。
- 作業站選擇服務只載入 IssueState=2 已核准 OP，且依群組 PSNo 限定；群組 PSNo='*' 時可載入全部已核准 OP。
- OPRoleFlag 必須選一種：General=0、Entry OP=1、Exit OP=2。
- WeightRate 必填、數值範圍 0–100；來源欄位 NUMBER(5,2)。
- Add 呼叫 AddOPGroupDetail；Edit 只可修改角色與權重，呼叫 EditOPGroupDetail 並帶 DataStamp。主鍵 (OPGroupNo, OPNo) 不可重複。
- Delete 支援多筆選取和確認，呼叫 DelOPGroupDetail 實體刪除。
- Audit 欄位由服務寫入；瀏覽器不得自行決定 Production 的 Creator/Reviser/日期。

## Check 按鈕規則

WinForms 在清單端以目前群組載入的所有明細檢核，不呼叫資料庫服務：

1. 同一群組的 Entry OP (OPRoleFlag=1) 最多一筆。
2. 同一群組的 Exit OP (OPRoleFlag=2) 最多一筆。
3. WeightRate 合計必須等於 100。
4. 舊 Form 在沒有 active 主檔或沒有 active 明細列時不執行檢核；網頁保留此選取條件。它沒有要求 Entry/Exit 必須各有一筆。

檢核只回報結果，不會阻止明細儲存，也不會改變資料。

## API 契約（家用端實作）

Vue Production 模式已依下列路徑呼叫 API；各端變更時需同步本文件與 component：

| 方法 | 路徑 | 行為 |
| --- | --- | --- |
| GET | /api/operation-groups?opGroupNo=&psNo= | 查群組清單；兩個條件可個別使用 |
| GET | /api/operation-groups/{opGroupNo}/members | 取該群組明細 |
| GET | /api/operation-groups/lookups/production-segments | 主檔 PSNo 選擇清單，映射舊 LoadPSDefine |
| GET | /api/operation-groups/lookups/operations?psNo=&issueState=2 | 明細作業站選擇；只回核准站，按 PSNo 過濾，* 不限區段 |
| POST | /api/operation-groups | 新增群組主檔 |
| PUT | /api/operation-groups/{opGroupNo} | 修改名稱、區段、順序、說明；帶 DataStamp CAS |
| DELETE | /api/operation-groups/{opGroupNo} | 交易內刪除其明細與主檔 |
| POST | /api/operation-groups/{opGroupNo}/members | 加入作業站、角色、權重 |
| PUT | /api/operation-groups/{opGroupNo}/members/{opNo} | 修改角色、權重；帶 DataStamp CAS |
| DELETE | /api/operation-groups/{opGroupNo}/members/{opNo} | 移除成員 |

Production API 需登入驗證並授權 FunctionNo=OP GROUP BASIS。伺服器負責資料長度、數值範圍、已核准作業站/PSNo、PK 重複、DataStamp 衝突 (409；來源欄位 nullable 且 DEFAULT 0，舊值為 NULL 時必須以 null-safe CAS 比對)、audit 及群組刪除交易。Check 是前端即時檢核；API 仍應對角色/權重限制做資料驗證。不要建立重複的生產區段、作業站、使用者或簽核表。

## Oracle 結構與 PostgreSQL CREATE

| 表 | Oracle 欄位及主鍵 | PostgreSQL 對照 |
| --- | --- | --- |
| TBLOPGROUPBASIS | OPGROUPNO VARCHAR2(20) PK；OPGROUPNAME VARCHAR2(50) NOT NULL；DESCRIPTION VARCHAR2(255)；CREATOR/REVISER VARCHAR2(10)；CREATEDATE/REVISEDATE DATE；PSNO VARCHAR2(50)；OPGROUPORDER NUMBER(6,0) DEFAULT 0；ERPNO VARCHAR2(50)；DATASTAMP NUMBER(11,0) DEFAULT 0 nullable | tblopgroupbasis；Oracle DATE 對應 timestamp；保留 ERPNo、nullable DataStamp/default |
| TBLOPGROUPDETAIL | OPGROUPNO VARCHAR2(20)、OPNO VARCHAR2(20) 組合 PK；OPROLEFLAG NUMBER(1,0) DEFAULT 0 NOT NULL；WEIGHTRATE NUMBER(5,2) DEFAULT 0 NOT NULL；DATASTAMP NUMBER(11,0) DEFAULT 0 nullable；audit 欄位同上 | tblopgroupdetail；角色/權重保留來源預設值及 NOT NULL |

- 原始 Oracle DDL：[mestest_op105_group_basis_source_ddl.sql](../../../database/reference/mestest_op105_group_basis_source_ddl.sql)。

- ALL_INDEXES 顯示唯一索引只有兩表的 PK index；ALL_CONSTRAINTS 只有 PK/NOT NULL check，沒有 FK。
- 原 first-phase PG bootstrap 的 OP105 表缺漏上述 DEFAULT 0；已修正 database/reference/mestest_first_phase_create_tables.sql，新建資料庫會保留 Oracle 預設值。家用端若 YMES live table 已存在，CREATE TABLE IF NOT EXISTS 不會補預設值，需比對實際 schema/migrations 後再決定是否建立 forward migration；不可重建或覆蓋既有資料。
