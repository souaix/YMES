## 清單畫面

- WinForms 主 Form `ClientSize=1008×591` 並最大化；繼承 `COM_Kit.frmBasisTemplat`。Issue 狀態列隱藏，查詢欄位由 `SetSearchFieldName({CustomerNo, CustomerOPNo})` 設定。
- 上方主檔 GroupBox 約在 `(12,53)`、大小 `984×274`；下方明細 GroupBox 約在 `(12,333)`、大小 `984×213`。兩個 UltraGrid 均隱藏 GroupByBox，主檔選取列後依複合鍵動態載入明細。
- 主 Grid 順序：CustomerNo、CustomerOPNo、CustomerOPName、PSNo、CustomerOPSeq、Description、Creator、CreateDate、Reviser、ReviseDate；DataStamp 隱藏。日期格式 `yyyy/MM/dd HH:mm:ss`。
- 主檔按鈕：ADD、EDIT、DEL、Copy；下方明細：ADD、EDIT、DEL；頁面底部 Close。沒有 Check、Approve 或 Print 功能。
- Vue 保留上下兩個資料框、Grid 左側與右側按鈕、主列選取後動態載入明細、可多選刪除；查詢只用 CustomerNo 或 CustomerOPNo。DEV 假資料以 `DEV-` 開頭並存在獨立 localStorage key。

## 主檔新增、修改、複製

主編輯 Form `ClientSize=616×341`，欄位如下：

| 欄位 | WinForms 行為 | Oracle 欄位 |
| --- | --- | --- |
| CustomerNo | 由已核准客戶 lookup 帶入；文字唯讀。Edit 不可變更 | `VARCHAR2(50) NOT NULL` |
| CustomerOPNo | 必填；離開欄位轉大寫；Edit 唯讀 | `VARCHAR2(20) NOT NULL` |
| Customer OP Name | 必填 | `CUSTOMEROPNAME VARCHAR2(50) NOT NULL` |
| PS No | 由 IssueState=2 的生產區段 lookup 帶入；Edit 有明細時鎖定，無明細可更換 | `VARCHAR2(50) NOT NULL` |
| OP Group Order | NumericUpDown 預設 0，WinForms 範圍 0–999999 | `NUMBER(3,0) NOT NULL` |
| Description | 多行文字 | `VARCHAR2(255)` nullable |

欄位名稱 `OP Group Order` 是 WinForms Designer 原文；資料庫實存 `CustomerOPSeq`。**來源 UI 可輸入至 999999，但 Oracle NUMBER(3,0) 僅能儲存三位整數**。Vue 保留舊畫面的 0–999999 輸入範圍；Production API 應在寫入前依實際 Oracle 欄寬回清楚驗證錯誤（不得讓轉型錯誤冒充成功）。家用端請依 YMES live 欄位與既有資料再決定相容遷移，不能直接擴欄或截斷。

- Add：CustomerNo 與 PSNo 由 lookup 選擇，CustomerOPNo / 名稱 / 序號 / Description 輸入；必要欄位 CustomerNo、CustomerOPNo、Name、PSNo。
- Edit：CustomerNo、CustomerOPNo 固定；若已有任何明細，PSNo 也不可改。主鍵欄位不在 Edit 修改 API 中。
- Copy：以舊主檔欄位預填後新增一筆主檔；不複製明細。使用者需透過 lookup/輸入更改複合 PK，重複 PK 由資料庫拒絕。
- 確定與套用均呼叫相同主檔 Add/Edit 並關閉視窗（依 Form event 實作）。關閉取消未儲存編輯。

## 明細新增、修改、刪除

Detail Form `ClientSize=484×333`，欄位為 CustomerNo、CustomerOPNo、PSNo（均唯讀，來自主檔）、OPNo、CustOPProcessCode、CustStepName、SendTranSactionData checkbox，以及 audit 欄位。

- OPNo 由 `wsOP.LoadOPBasis` lookup 載入 IssueState=2 且 PSNo 等於主檔 PSNo 的作業站；輸入離開欄位時轉大寫。
- OPNo、CustOPProcessCode、CustStepName 必填。來源表限制前三者分別為 `VARCHAR2(20)`、`VARCHAR2(20)`、`VARCHAR2(20)`；TransactionFlag 為必填 `NUMBER(1,0)`，checkbox False/True 寫 0/1。
- Detail PK 為 `(CustomerNo, CustomerOPNo, OPNo)`。新增前 WinForms 重新查明細並拒絕重複三欄組合。
- Edit 可變更 OPNo。WinForms 將舊 OPNo 作為查詢鍵、新 OPNo 作為更新值；同時僅更新 ProcessCode、StepName、TransactionFlag，並以 DataStamp 更新 revision/audit。
- 明細新增寫 Creator/CreateDate；修改寫 Reviser/ReviseDate。Production API 不信任前端送來的 audit 欄位。
- 明細可多選刪除，為實體刪除。主檔多選刪除時舊服務每筆先刪該主檔全部 Detail，再刪 Basis；新 API 對每一主檔應在同一 transaction 做兩階段刪除。WinForms 批次遇第一筆錯誤即停止。

## Oracle schema 精確欄位

`TBL_BOPCUSTOPMAPBASIS`：CustomerNo VARCHAR2(50)、CustomerOPNo VARCHAR2(20)、CustomerOPName VARCHAR2(50)、CustomerOPSeq NUMBER(3,0)、PSNo VARCHAR2(50)、Description VARCHAR2(255)、Creator VARCHAR2(10)、CreateDate DATE、DataStamp NUMBER(11,0) DEFAULT 0 nullable、Reviser VARCHAR2(10) nullable、ReviseDate DATE nullable。前七個識別/必要欄與 Creator/CreateDate 均 NOT NULL；PK `(CustomerNo, CustomerOPNo)`。

`TBL_BOPCUSTOPMAPDETAIL`：CustomerNo VARCHAR2(50)、CustomerOPNo VARCHAR2(20)、PSNo VARCHAR2(50)、OPNo VARCHAR2(20)、CustOPProcessCode VARCHAR2(20)、CustStepName VARCHAR2(20)、TransactionFlag NUMBER(1,0)、Creator VARCHAR2(10)、CreateDate DATE、DataStamp NUMBER(11,0) DEFAULT 0 nullable、Reviser VARCHAR2(10) nullable、ReviseDate DATE nullable。CustomerNo/CustomerOPNo/PSNo/OPNo/ProcessCode/StepName/TransactionFlag/Creator/CreateDate 均 NOT NULL；PK `(CustomerNo, CustomerOPNo, OPNo)`。

來源沒有定義 FK。不可自行宣稱資料庫會級聯刪除；API 明確執行 detail-first transaction。資料庫沒有 IssueState。DataStamp 可 NULL 且 DEFAULT 0；既有 NULL 值須由 API 使用 null-safe compare-and-swap，不能直接當 0。

## API 與家用端實作契約

Vue Production 呼叫路徑：

| Method | Path | 用途 |
| --- | --- | --- |
| GET | `/api/customer-op-mappings?customerNo=&customerOPNo=` | 主檔查詢 |
| GET | `/api/customer-op-mappings/{customerNo}/{customerOPNo}/details` | 指定主檔明細 |
| POST | `/api/customer-op-mappings` | 新增主檔 |
| PUT | `/api/customer-op-mappings/{customerNo}/{customerOPNo}` | 修改主檔；body 帶 DataStamp |
| DELETE | `/api/customer-op-mappings/{customerNo}/{customerOPNo}` | transaction 刪 Detail 再刪 Basis |
| POST | `/api/customer-op-mappings/{customerNo}/{customerOPNo}/details` | 新增明細 |
| PUT | `/api/customer-op-mappings/{customerNo}/{customerOPNo}/details/{oldOpNo}` | 修改明細，可 body 傳新 OpNo；帶 DataStamp |
| DELETE | `/api/customer-op-mappings/{customerNo}/{customerOPNo}/details/{opNo}` | 刪除單一明細 |
| GET | `/api/customer-op-mappings/lookups/customers?issueState=2` | 重用已核准 Customer Basis |
| GET | `/api/customer-op-mappings/lookups/production-segments?issueState=2` | 重用已核准 Production Segment |
| GET | `/api/customer-op-mappings/lookups/operations?psNo=&issueState=2` | 重用已核准 OP Basis，依 PSNo 篩選 |

每一 endpoint 都必須登入及授權 FunctionNo=`B_CUSTOMER OP MAPPING`；不要為 lookup 新建客戶、區段或作業站表。API 參數化 SQL；由 authenticated principal 設 Creator/Reviser/日期，忽略 request audit 值。Edit 主檔/明細必須 DataStamp CAS，0 筆更新回 409；對舊 NULL stamp 執行 `IS NULL` CAS 並將新值設 1。Delete 來源未採 DataStamp 條件，先核對 YMES schema 與一致刪除策略。

## 公司端與家用端界線

公司端只提供 DEV 假資料畫面與本規格；未連 YMES PostgreSQL、未實作 Production API/migration，未執行 build/test/browser。家用端先核對 live schema/migrations；[`mestest_opb03_customer_op_mapping_create.sql`](../../../database/reference/mestest_opb03_customer_op_mapping_create.sql) 只作空表參照，僅在表確定不存在時使用 migration 建立；`CREATE TABLE IF NOT EXISTS` 不會修正現存欄位。優先保留現有 YMES schema 與資料，主/明細刪除需交易化，完成後回公司端整合驗收。
