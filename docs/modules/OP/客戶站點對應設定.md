## 主檔新增、修改、複製

主編輯 Form `ClientSize=616×341`，欄位如下：

| 欄位 | WinForms 行為 | Oracle 欄位 |
| --- | --- | --- |
| CustomerNo | 由已核准客戶 lookup 帶入；文字唯讀。Edit 不可變更 | `VARCHAR2(50) NOT NULL` |
| CustomerOPNo | 必填；離開欄位轉大寫；Edit 唯讀 | `VARCHAR2(20) NOT NULL` |
| Customer OP Name | 必填 | `CUSTOMEROPNAME VARCHAR2(50) NOT NULL` |
| PS No | 由 IssueState=2 的生產區段 lookup 帶入；Edit 有明細時鎖定，無明細可更換 | `VARCHAR2(50) NOT NULL` |
| OP Group Order | NumericUpDown 預設 0，WinForms 範圍 0–999999 | `NUMBER(3,0) NOT NULL` |
| Description | 多行文字 | `VARCHAR2(255)` nullable |

欄位名稱 `OP Group Order` 是 WinForms Designer 原文；資料庫實存 `CustomerOPSeq`。**來源 UI 可輸入至 999999，但 Oracle NUMBER(3,0) 僅能儲存三位整數**。Vue 保留舊畫面的 0–999999 輸入範圍；Production API 應在寫入前依實際 Oracle 欄寬回清楚驗證錯誤（不得讓轉型錯誤冒充成功）。家用端請依 YMES live 欄位與既有資料再決定相容遷移，不能直接擴欄或截斷。

- Add：CustomerNo 與 PSNo 由 lookup 選擇，CustomerOPNo / 名稱 / 序號 / Description 輸入；必要欄位 CustomerNo、CustomerOPNo、Name、PSNo。
- Edit：CustomerNo、CustomerOPNo 固定；若已有任何明細，PSNo 也不可改。主鍵欄位不在 Edit 修改 API 中。
- Copy：以舊主檔欄位預填後新增一筆主檔；不複製明細。使用者需透過 lookup/輸入更改複合 PK，重複 PK 由資料庫拒絕。
- 確定與套用均呼叫相同主檔 Add/Edit 並關閉視窗（依 Form event 實作）。關閉取消未儲存編輯。

## 明細新增、修改、刪除

Detail Form `ClientSize=484×333`，欄位為 CustomerNo、CustomerOPNo、PSNo（均唯讀，來自主檔）、OPNo、CustOPProcessCode、CustStepName、SendTranSactionData checkbox，以及 audit 欄位。

- OPNo 由 `wsOP.LoadOPBasis` lookup 載入 IssueState=2 且 PSNo 等於主檔 PSNo 的作業站；輸入離開欄位時轉大寫。
- OPNo、CustOPProcessCode、CustStepName 必填。來源表限制前三者分別為 `VARCHAR2(20)`、`VARCHAR2(20)`、`VARCHAR2(20)`；TransactionFlag 為必填 `NUMBER(1,0)`，checkbox False/True 寫 0/1。
- Detail PK 為 `(CustomerNo, CustomerOPNo, OPNo)`。新增前 WinForms 重新查明細並拒絕重複三欄組合。
- Edit 可變更 OPNo。WinForms 將舊 OPNo 作為查詢鍵、新 OPNo 作為更新值；同時僅更新 ProcessCode、StepName、TransactionFlag，並以 DataStamp 更新 revision/audit。
- 明細新增寫 Creator/CreateDate；修改寫 Reviser/ReviseDate。Production API 不信任前端送來的 audit 欄位。
- 明細可多選刪除，為實體刪除。主檔多選刪除時舊服務每筆先刪該主檔全部 Detail，再刪 Basis；新 API 對每一主檔應在同一 transaction 做兩階段刪除。WinForms 批次遇第一筆錯誤即停止。

## Oracle schema 精確欄位

`TBL_BOPCUSTOPMAPBASIS`：CustomerNo VARCHAR2(50)、CustomerOPNo VARCHAR2(20)、CustomerOPName VARCHAR2(50)、CustomerOPSeq NUMBER(3,0)、PSNo VARCHAR2(50)、Description VARCHAR2(255)、Creator VARCHAR2(10)、CreateDate DATE、DataStamp NUMBER(11,0) DEFAULT 0 nullable、Reviser VARCHAR2(10) nullable、ReviseDate DATE nullable。前七個識別/必要欄與 Creator/CreateDate 均 NOT NULL；PK `(CustomerNo, CustomerOPNo)`。

`TBL_BOPCUSTOPMAPDETAIL`：CustomerNo VARCHAR2(50)、CustomerOPNo VARCHAR2(20)、PSNo VARCHAR2(50)、OPNo VARCHAR2(20)、CustOPProcessCode VARCHAR2(20)、CustStepName VARCHAR2(20)、TransactionFlag NUMBER(1,0)、Creator VARCHAR2(10)、CreateDate DATE、DataStamp NUMBER(11,0) DEFAULT 0 nullable、Reviser VARCHAR2(10) nullable、ReviseDate DATE nullable。CustomerNo/CustomerOPNo/PSNo/OPNo/ProcessCode/StepName/TransactionFlag/Creator/CreateDate 均 NOT NULL；PK `(CustomerNo, CustomerOPNo, OPNo)`。

來源沒有定義 FK。不可自行宣稱資料庫會級聯刪除；API 明確執行 detail-first transaction。資料庫沒有 IssueState。DataStamp 可 NULL 且 DEFAULT 0；既有 NULL 值須由 API 使用 null-safe compare-and-swap，不能直接當 0。

## API 與家用端實作契約

2026-11-20 家用端新增 `Operations/OpB03Controller.cs`、`OpB03Models.cs`、`OpB03Repository.cs`。以下是本批實作契約，替換公司端原先以複合主鍵拼 URL path 的接線提案；不變更上方原型來源規格。所有識別碼放 query key，以 `URLSearchParams` 編碼，允許 slash、pipe、星號等合法字面值。正式 base 為 `/YMES/API/api/customer-op-mappings`。

| Method | 相對路徑／query | body／結果 |
| --- | --- | --- |
| GET | `?customerNo=&customerOPNo=` | 兩條件均為不解讀萬用字元的 contains；回 `{items}` |
| GET | `/item?customerNo=&customerOPNo=` | 回十一欄主檔 DTO |
| POST | base | 主檔欄位；回真實主檔 DTO |
| PUT | `/item?customerNo=&customerOPNo=` | 主檔欄位及明確 `dataStamp`；回主檔 DTO |
| DELETE | `/item?customerNo=&customerOPNo=` | `{dataStamp}`；明細先刪、主檔後刪，同交易；成功 204 |
| GET | `/details?customerNo=&customerOPNo=` | 回 `{parent,items}`；主檔 SHARE 鎖下讀取一致的父 token 與明細 |
| POST | `/details?customerNo=&customerOPNo=` | `{opNo,custOPProcessCode,custStepName,transactionFlag,parentDataStamp}`；回 `{parent,item}` |
| PUT | `/details/item?customerNo=&customerOPNo=&opNo=` | query 為舊 OPNo；body 同新增加明確 `dataStamp`，可帶新 OPNo；回 `{parent,item}` |
| DELETE | `/details/item?customerNo=&customerOPNo=&opNo=` | `{dataStamp,parentDataStamp}`；回 `{parent}` |
| GET | `/lookups/customers` | 真實已核准客戶，`{items:[{customerNo,customerName,issueState}]}` |
| GET | `/lookups/production-segments` | 真實已核准區段，`{items:[{psNo,psName,issueState}]}` |
| GET | `/lookups/operations?psNo=` | 真實已核准且 PS 字面相等的 OP，`{items:[{opNo,opName,psNo,issueState}]}` |

主檔 DTO 僅原生十一欄：`customerNo, customerOPNo, customerOPName, customerOPSeq, psNo, description, creator, createDate, dataStamp, reviser, reviseDate`。明細 DTO 僅原生十二欄：`customerNo, customerOPNo, psNo, opNo, custOPProcessCode, custStepName, transactionFlag, creator, createDate, dataStamp, reviser, reviseDate`。不增 `issueState`、`hasDetails` 或假版本欄。HeaderWrite 包含前六個主檔業務欄位；`customerOPSeq` 明確必填且 API 限 0–999，依 numeric(3,0) 避免原 UI 範圍造成資料庫溢位。新 CustomerOPNo 依原 UI 轉大寫；既有複合鍵固定，回傳資料庫實際大小寫／空白，不由 DTO 重建識別值。

全部 endpoint 個別 `[Authorize]` 登入保護；依目前專案決策，尚未實作 FunctionNo／角色 ACL，不能將登入保護描述為已完成原生功能權限引擎。Creator/Reviser 只取 authenticated principal（來源十字元上限），新日期明確寫 `now() AT TIME ZONE 'UTC'`，既有 timestamp 不改寫；API 指定 UTC 後回 ISO Z，nullable revision 原樣。忽略前端自填 audit。

兩個原生 `dataStamp` 保留 nullable，所有 UPDATE／DELETE 的 token 都 JSON-required，明確 NULL 合法、缺少 property 400、NULL 不等於 0。每次 child write 另需主檔 `parentDataStamp`，同交易先鎖主檔、檢查父 CAS，成功後遞增父 stamp 與 revision，回父 DTO；child UPDATE 另檢查與遞增自己的 stamp。SQL 用 `IS NOT DISTINCT FROM`；NULL 首次修改變 1。任何需要遞增的 numeric(11,0) 最大值回 409；主檔硬刪不遞增，可接受匹配的最大值。明細刪除仍須可遞增的父 token。

每個 writer 為明確 ReadCommitted transaction，固定以 PG trim/lower 的複合 JSON array 雜湊取得 parent namespace advisory lock，接著真主檔 UPDATE 鎖、需要的真 lookup SHARE 鎖，再取得明細 UPDATE 鎖，最後父 stamp bump。以 JSON array 編碼避免 `a|b/c` 等合法鍵碰撞。主檔新增拒絕同邏輯複合鍵及既有無主檔明細；讀寫拒絕父／子 owner 大小寫或空白別名、同 owner 下 OP 別名歧義，409 保留原資料，不能把沒讀到的舊列當空明細接管。這些 namespace／CAS 刪除保護為 YMES 完整性延伸，非宣稱原 Core 已逐條提供。

新增主檔的 Customer 與 PS，以及真正變更 PS，須真實唯一 state2 lookup，SHARE 持續到 commit。主檔有任何明細時，真正改 PS 由伺服器拒絕 409。新增／真正改 OP 時同樣檢查真實唯一 state2 OP，且其 PS 與父 PS 字面相等；`*` 不是萬用值。OP 可用於其他 mapping，沒有 OPB02 的全域 OP PK／排除規則。未變的失效、缺失、舊大小寫或空白 Customer／PS／OP 保留原 raw 值，metadata edit 不強迫改選；明細 Edit 依原 Core 不更新既有 PSNo。TransactionFlag 是實際 integer，新增或變更只接受 0／1，既有其他 raw 值可明確原樣保留，不默改為 checkbox 的 0／1。

Header Apply 與 Confirm 均成功關窗；Copy 僅以主列建立新主檔，不複製明細。Detail Apply 留窗並轉 Edit、採用新 OP PK／子 token／父 DTO，是本批明載 YMES 整合選擇；不可把舊 token 重新放回已提交草稿。批次刪除每列各自交易，後列失敗需保留前列已提交成功並呈現部分完成，不宣稱全批 rollback。

錯誤回乾淨 ProblemDetails：400 欄位／範圍／缺 token、404 不存在、409 重複／別名／stale／有明細不可改 PS、422 真 lookup 不符資格、503 真來源結構或權限不可用。缺資料庫、來源或權限不回假空清單；沒有本模組不需要的 Element、Property、IssueJob 假 provider。

本段為已準備 source contract；2026-11-20 撰寫時尚未 build／正式 API／app-browser 驗收，不宣稱實測通過。兩表與 Customer 最小鎖權限由 root 另行核對備份／migration，API 作者不直接套表。
