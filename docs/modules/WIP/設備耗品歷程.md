# WP304 設備耗品歷程

## 範圍與來源

- MES menu: WIP → 設備與載具 → 設備耗品歷程；FunctionNo `EQP CONSUME STATUS LOG`，WinForms `WP_EQPConsumeStatusLog.dll`。
- WinForms：`STD/MESWin/WIP/WP_EQPConsumeStatusLog/frmEQPConsumeStatusLog.vb`。
- Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `LoadEQPConsumeLog`；設備及耗品 lookup 分別走 `wsEQP.LoadEquipmentBasis`、`wsEQP.LoadEQPTypeConsumeBasis`。
- Core：`STD/MESkc/kcWIP/clsWIP.cs` 的 `LoadEQPConsumeLog`。
- YMES Vue DEV：`web/src/components/WipEquipmentConsumeStatusLog.vue`，入口位於 `web/src/App.vue`。

## WinForms 畫面

- ClientSize 1008×591，置中顯示。上方 `Query` 群組約 984×81；下方 UltraGrid 約 892×479；右下角只有 `Close (&X)`。
- 第一列條件：Equipment No 核取方塊、文字欄、`...` lookup；Consume No 核取方塊、文字欄、`...` lookup。
- 第二列條件：From Date、End Date，各為顯示 `yyyy/MM/dd HH:mm:ss` 且帶勾選框的 DateTimePicker；右側 Query 按鈕。
- 畫面初始化會載入 IssueState=2 設備與全部 Equipment Type Consume Basis 供 lookup，但不自動查歷程，初始 Grid 為空。
- 勾選設備／耗品 lookup 會將結果填入文字欄並自動勾選對應條件。取消勾選會清掉文字；文字欄可自行輸入。EquipmentNo 離開欄位時轉大寫。ConsumeNo lookup 搜尋全部耗品基準，不隨 EquipmentNo 篩選。
- 按 Query 才呼叫 `wsWIP.LoadEQPConsumeLog`。只送出勾選且非空的 EquipmentNo／ConsumeNo；From／End Date 勾選時才送日期。畫面沒有 ConsumeSeq 條件，雖然 Service/Core 支援 ConsumeSeq。
- Grid 欄位順序：EquipmentNo、ConsumeNo、ConsumeSeq、AccQty、AccPeriod、Creator、CreateDate。AccQty／AccPeriod 靠右且寬 100；CreateDate 寬 130、格式 `yyyy/MM/dd HH:mm:ss`。其他回傳欄位隱藏。

## 查詢邏輯

- Core 從 `TBLWIPEQPCONSUMELOG` 取 `EquipmentNo IS NOT NULL` 的資料；設備、耗品、序號條件分別為等值比對。
- StartTime 條件為 `CreateDate >= StartTime`；EndTime 為 `CreateDate <= EndTime`，都是傳入的完整日期時間，不是整日自動補界線。
- Core 查詢沒有 `ORDER BY`，WinForms 沒有承諾結果順序；正式 API 為分頁需要穩定排序時，應以明確排序鍵並註記為 API 實作要求。
- 此表單只提供設備、耗品與時間範圍，因此不會傳 ConsumeSeq。所有條件均可不勾；來源因此允許不帶條件查整張歷程表。WinForms 沒有明確分頁或筆數限制。
- 所有結果唯讀；主表單沒有 Add/Edit/Delete/Reset 操作。耗品更換與序號重置由 WP303 寫入這張 log 表。

## 資料表與 DDL

- 本頁只讀 `TBLWIPEQPCONSUMELOG`，不新增 Oracle 專用資料表；Oracle source DDL、metadata 及 PostgreSQL CREATE-only 已在 [WP303 設備耗品現況](設備耗品現況.md) 與 `database/reference/mestest_wip_wp303_*` 交付。家用端先查 live PostgreSQL，發現 Log、Status 與耗品基準表缺失後，分別用 0101／0102 migration 建立空表。
- 表欄位為 EquipmentNo、ConsumeNo、ConsumeSeq、Creator、CreateDate、AccQty、AccPeriod；PK 是 EquipmentNo+ConsumeNo+ConsumeSeq。WP303 重置會先以舊序號新增歷程，再更新 ConsumeStatus。
- 設備 lookup 使用既有 `TBLEQPEQUIPMENTBASIS` reference；耗品基準來源為 `TBLEQPCONSUMEBASIS`，其 source DDL 在設備類別 reference。此表原先不在 live YMES，已由 0102 建立空表並只授予 API SELECT。

## Vue DEV 與家用端 API handoff

- DEV 頁 `/YMES/WIP/EquipmentConsumeStatusLog`，掛在 WIP → 設備與載具 → 設備耗品歷程。只按 Query 後顯示結果；讀取 WP303 假資料 localStorage key `ymes.dev.wp303-consume-status.v1` 的 `logs`，因此在 WP303 Reset 後回來查詢能看見新增歷程。未呼叫 API 或資料庫。
- 正式端建議登入保護的唯讀 GET，支援 EquipmentNo、ConsumeNo、StartTime、EndTime 的參數化條件及分頁；日期上下界與來源相同，皆為含界值。ConsumeSeq 可保留為 API 可選條件，但不是本 WinForms 頁面的 UI 欄位。
- WinForms 原始查詢可無條件讀完整歷程。正式 API 不應無上限回傳全部歷程；以伺服器最大頁數／筆數和使用者資料權限限制回傳量，未指定條件時提供安全分頁或要求日期條件，並記錄這項資安／效能調整。
- 家用端以 0101／0102／0103 建立缺少的 live table 與唯讀 lookup 索引；細節見本文件 2026-11-28 維護紀錄及 `docs/DATABASE_CONNECTION.md`。API 不回傳 WP303 Status，也不提供修改歷程的操作。

## 2026-11-28 家用端 API／schema／DEV 驗收紀錄

- live PostgreSQL 缺少 `tblwipeqpconsumestatus`、`tblwipeqpconsumelog`、`tbleqpconsumebasis`。0101 依 MES source DDL 建立 Status／Log 空表；0102 依 equipment type source DDL 建立 consumable basis 空表；0103 新增設備查找部分索引。0101／0102 的欄位、型別、NULL、PK 均與來源相符。三表都是 0 列，沒有匯入 MES 業務資料。
- `ymes_app` 僅能 SELECT Log、Consumable Basis 及既有 Equipment Basis；Status 不授任何權限，Log／Basis 沒有 INSERT、UPDATE、DELETE 權限。0101 的三個 Log 查找索引、0102 的 Basis 排序索引、0103 的設備排序索引均為 YMES-only 查詢支援索引，不是 Oracle source index。
- API：登入保護唯讀 `GET /api/wip/equipment-consume-status-logs`，查詢條件為 EquipmentNo、ConsumeNo、StartTime、EndTime。EquipmentNo／ConsumeNo 精確比對；StartTime／EndTime 皆含界並依台北時間轉為 PostgreSQL timestamp。至少須提供設備、耗品其中一項，或同時提供完整日期範圍；有設備／耗品條件時可另加單側日期。起日不可晚於迄日。參數化查詢、RepeatableRead／READ ONLY、固定排序；預設每頁 50、上限 100、頁碼上限 10,000，JSON array 搭配 `X-Page`、`X-Page-Size`、`X-Has-More`，並設定 no-store。
- Lookup：`GET /api/wip/equipment-consume-status-logs/lookups/equipment` 只列 IssueState=2 且非 Chamber 設備，依 EquipmentType／EquipmentNo 排序；`GET /api/wip/equipment-consume-status-logs/lookups/consumables` 搜尋全部 Equipment Type Consume Basis，不依已選設備類別縮小。兩者都支援 keyword、分頁，預設 50、最多 100，唯讀交易。
- `.NET 9` API build 成功，0 errors；NU1900 是本機無法連 NuGet vulnerability feed。以 `ymes_app` 的 READ ONLY transaction／`EXPLAIN` 核對設備、耗品、設備篩選與日期範圍查詢；確認對應 YMES 索引可用，未讀取既有 Equipment 業務列。
- 本機 app-browser 使用 Vite DEV 與 WP303 共用 localStorage 假資料；測過設備搜尋／選取、跨類別耗品搜尋／選取、設備／耗品／日期範圍查詢、無條件提示、反向日期提示、空結果顯示及 Close 返回首頁。DEV 頁未呼叫新 API；未寫入正式資料。反向日期與無條件查詢前端提示已補入此元件，與 API 防護一致。
