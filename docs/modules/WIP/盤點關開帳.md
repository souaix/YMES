## 復刻範圍

公司端對照本機標準來源 `D:\iMES\CSiMES\STD\MESWin\WIP\WP_InvCountState\frmInvCountState.vb`。Designer 初始化程式內嵌於 Form，沒有獨立 `.Designer.vb`。Service 為 `wsWIP.LoadInvCountState`、`ExeInvCountClose`、`ExeInvCountOpen`、`ChkInvCountAdjust`；Core 為 `clsINVCount`、`clsSYSParameter`。

## 畫面狀態

- Form Load 以 `LoadInvCountState(State=0)` 讀取進行中關帳批次。State=0 代表已關帳、盤點中；State=1 代表已開帳。Grid 不顯示 State 欄。
- 查到一筆 State=0：啟用 InvCount Open 與 Print，停用 InvCount Close 和 Close Option。查無 State=0：啟用 InvCount Close 和 Close Option，停用 Open。多筆 State=0 時 Form 仍顯示／啟用 Open，但 Service 會拒絕多筆。
- Grid 欄位依序為 CountSerial、CountDate、CloseWIP、CloseRAW、CloseFGD、CloseSEMI、CloseMTLWIP、CloseSEMIWIP、Creator、CreateDate。Close flag 以 `Not Close`／`Close` 顯示；日期顯示 `yyyy/MM/dd HH:mm:ss`。
- Form Designer 將 Print 按鈕設為 `Visible=False`；盤點清冊列印由 WP607 負責。DEV 顯示目前關帳批次和六種選項所建立的快照筆數，以便閱讀模擬結果。

## InvCount Close

Form 要求六種 Close Option 至少勾一種，並在呼叫 Service 前要求使用者確認。Service 解析六個 0／1 旗標，檢查目前沒有 State=0 批次；接著將 SYS parameter `AllowExecuteLot` 設為 0，產生 `yyMMddNNN` CountSerial，新增 State=0 主檔和選取的盤點 detail，再記錄事件。

| Close Option | Snapshot source 與條件 | 寫入 detail |
| --- | --- | --- |
| WIP | `vwWIPLotState_INV` join `TBLWIPLOTBASIS`；LotState=1、Status 0–5 | `TBLWIPINVCOUNTDETAIL` |
| RAW | `TBLINVRAWINVENTORY` join `TBLINVRAWINVENTORYLOC`；LocQty>0 | `TBLWIPINVCOUNTDETAIL_MTL` |
| FGD | `TBLINVFGDINVENTORY`；InventoryNo 非空、LocQty>0 | `TBLWIPINVCOUNTDETAIL_PRD` |
| SEMI | `TBLINVSEMIINVENTORY`；InventoryNo 非空、LocQty>0 | `TBLWIPINVCOUNTDETAIL_PRD` |
| MTLWIP | `TBLINVWIPINVENTORY_RAW`；InventoryNo 非空、Qty>0 | `TBLWIPINVCOUNTDETAIL_MTL` |
| SEMIWIP | `TBLINVWIPINVENTORY_SEMI` join LotState／LotBasis；Qty>0 | `TBLWIPINVCOUNTDETAIL` |

Core 把 State 主檔和所選的 detail INSERT SQL 放入 collection 後呼叫 `objLot.ExecuteSQL(CollectionSQL)`。未勾選類型不產生明細。

## InvCount Open

Form 先呼叫 `ChkInvCountAdjust`；Core 對三個 detail 表的 `AdjustState=1` 做 UNION，任一未 Confirm 調帳即擋住開帳。查詢失敗亦由 Form 預設值採 fail-closed。通過後要求使用者確認，再呼叫 Service。

Service 要求 State=0 恰好一筆：0 筆回「已開帳」，超過 1 筆回「關帳資料超過一筆」。符合時先以 `EditInvCountState` 將該 CountSerial 改成 State=1，寫入 OpenUserNo／OpenDate，再將 `AllowExecuteLot` 改為 1，最後記錄事件。查詢只取 State=0，所以開帳成功後 Grid 變空，Form 重新啟用 Close Option。

## 靜態檢閱發現

- `AllowExecuteLot=0` 在新增 State／detail snapshot collection 前以獨立 SQL 寫入；若後續 INSERT／collection 失敗，Service 沒有把參數補回 1，也沒有 State 0 主檔可由 Form 開帳，會讓生產批過站持續受阻。
- Open 的 State=1 更新先於 `AllowExecuteLot=1`。若參數更新失敗，State 已離開 State=0，Form 重新載入後會允許再關帳，但批次過站仍可能被鎖住。
- 關帳前的「不存在 State=0」查詢與 CountSerial 產生、寫入之間沒有可見的資料庫鎖／CAS。並發關帳可能同時通過檢查或競爭同一 YYMMDDNNN 序號。
- Form 檢查至少一個 Close Option，但 `ExeInvCountClose` Service 只檢查每個旗標存在且非負，沒有拒絕六個旗標全為 0 的 request。正式 API 必須由伺服器驗證。
- `ChkInvCountAdjust` 跨全部 CountSerial 查 AdjustState=1；它不是只檢查目前 State=0 的批次。
- Close／Open 將 `Creator`／`OpenUserNo` 從 request 傳入；正式 API 必須使用登入者身分，不接受瀏覽器自報操作者。

DEV 提供兩種起始狀態、六類 Close Option、未確認調帳守門，以及 Snapshot SQL／AllowExecuteLot 回寫失敗情境。這些情境展示的是來源流程可能的失敗位置，不代表公司端執行過資料庫更新。
