# WP501 立即異常設定

## 原生來源與範圍

- 選單：在製品管理 → 異常與等待 → 立即異常設定；`FunctionNo=IMMEDIATE HOLD SET`、`FunctionKey=WP501`、`WP_ImmediateHoldSet.dll`。公司 Vue DEV 路徑 `/YMES/WIP/ImmediateHoldSet`，元件 `web/src/components/WipImmediateHoldSet.vue`。
- 查詢主視窗：`STD/MESWin/WIP/WP_ImmediateHoldSet/frmImmediateHoldSet.vb`，Designer 與事件程式同檔。共用異常單視窗：`STD/MESWin/WIP/WP_BRERFCreate/frmBRERFCreate.vb`，Designer 也在同檔；Set 以 `ObjectFileHandler.Execute("WP_BRERFCreate", {LotNo,ERFType=2,OPNo,Status})` 開它。
- Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `LoadLotBasisJoinState`、`CheckLotPackage`、`ChkLotStamp`、`Exe_ERF_Create`；`wsSYS.GetERFNo` 負責異常單號。Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `UpdERF_Create` 與相關 Lot/Reverse/Log helper；`udWIP.clsWIP.UpdERF_Create` 是可擴充鉤子，正式端仍須查部署實作。

## 畫面與查詢

原主視窗標題 `Immediate Hold Set`，ClientSize 1008×729，最大化。上方 `Query` 是 Area No、PS No、OP No、Customer No、Product No、Lot No 六欄；前五欄有 `...` 查找，右側 Query。下方 `Lot` Grid 顯示 LotNo、Status、LotSerial、AreaNo、PSNo、ProcessNo、OPNo、NodeID、BRNo、CurQTY、CurUnitNo、SysQTY、SysUnitNo、BaseLotNo，底部 Set／Close。公司頁沿用黃色輸入與資料格、框線與共用按鈕樣式。

Query 至少填一欄；輸入去空白轉大寫。WinForms 依系統參數 `ERFMultipleHold`：值 0 時查 Status `0|1|4`，非 0 時查 `0|1|3|4`。另固定 `A.CurQty > 0`；回傳後刪掉 `PartialMode=1 且 Status<>0`，只顯示 `LotState<>0`。Set 需選列，先 `CheckLotPackage` 拒絕已包裝批，再檢查 Partial/Status；關閉共用視窗後重查。Grid 狀態 0 Queue、1 Running、3 Hold、4 Complete。

共用 `WP_BRERFCreate` 約 5,000 行，有 Lot State、Release EQP／Equipment State、ERF No、主／次分類、Hold Description、HoldItem 與 HoldReason 雙 Grid、Add／Remove、Lot／Component、Area All/T1–T5、附件、Confirm／Close。Lot 模式且有元件時，All 對每個元件展開 T1–T5；無元件用 `N/A/N/A`；Component 模式按選取元件展開。相同 `(HoldItemNo,ComponentNo,AreaNo)` 不重複加入。分類變更會清除已選原因。

Confirm 至少要 ERFNo、MClassNo、非空 HoldDescription、至少一筆 HoldReason。HoldReason 的 OCAPNO 必須全空或全有。Release EQP=Yes 必選狀態。若預設 ScrapQty 與原因 Qty 總和不等，原 Form 問使用者是否繼續。它在提交前重新保留 ERFNo、檢查 LotStamp、處理附件與報表，然後呼叫 `Exe_ERF_Create`；成功後禁用 Confirm，避免視窗內重複提交。`ERFType=2` 是 Immediate Hold；`ERFSource=0` 是 WIP。

### Release EQP 分支來源核對（2026-11-20）

- `frmBRERFCreate.vb:4153–4234` 在 Yes 時呼叫 `wsEQP.LoadEQPStateBasis`，以 `TBLEQPSTATEBASIS.EquipmentState` **數字**作下拉值、`StateName` 作顯示字。No 時清空選擇。原 Lot State 還有唯讀 `Vendor No`、`Material No`，已補 DEV 頁；WinForms 畫面未直接顯示 Equipment No。
- `frmBRERFCreate.vb:1300–1314,4784–4832` → `wsWIP.LoadWIPTemp_Equipment` → `clsLot.LoadWIPTemp_Equipment`（`clsLot.cs:183479–183531`）：Core 對本 Lot 的 `TBLWIPTEMP_EQUIPMENT.EquipmentNo`，只回傳**沒有任何其他 Lot 共用**的 `TBLEMSEQUIPMENTSTATE` 行。Form 把「回傳 0 行」設 `blnTemp_Equipment=True`，顯示「其他 Lot」警告；0 行也可能代表本 Lot 根本未在機。此分支沒有 `Exit Sub`/`GoTo`，警告後仍繼續組參數及送 `Exe_ERF_Create`，不能視為正式阻擋。舊訊息與實際查詢條件不完全等價。
- `clsLot.UpdERF_Create`（約 `clsLot.cs:89978,90314–90360`）在 ReleaseEQP 時要求非空狀態，並呼叫 `SHR_COEquipment` 下機／結算；表單層警告無法取代 Core 交易中的設備佔用檢查。正式 API 應先以設備關聯驗證本 Lot 確有在機設備且無其他 Lot 佔用，鎖住關聯後再更新；並將設備狀態代碼作整數驗證。不要複製 Form 的「警告仍提交」行為。

## Service／Core 交易語義

`Exe_ERF_Create` 把 LotNo、ERFNo、LotStamp、ERFType、ERFSource、MClassNo、HoldDescription、HoldReason、附件、CreateERF、ReleaseEQP、Status 等傳給 `clsLot.UpdERF_Create`。Core 先查同 Lot 是否已有 `ERFBasis.Status=11` 的生產批處置；若 `CreateERF=false`，另拒絕已有 0/1/2/3 未處理 ERF 的 Dummy 開單。若 Lot 已 Status=3，僅在傳入的 `ImmediateStatus=3` 時允許續開；Partial Lot 只允許 Queue 並按 OPNo 定位。正式 API 要在鎖內重查，不信任瀏覽器傳入的原狀態。

Core 逐原因寫 `TBLWIPERFHOLDREASON` 與 `TBLWIPERFHOLDREASONDISP`，Qty 合計寫入 `TBLWIPERFBASIS.SCRAPQTY`；依 CreateERF、QCFirstGroup／HoldDispGroup 與 OCAP 規則決定 ERF 狀態、處置與 OCAP state。它更新 `TBLWIPLOTSTATE` 與 LotLog／LoginState／Reverse／ReleaseLog；若本來已 Hold，保留既有 Status、GoStatus、LogGroupSerial，但仍換 LotSerial、事件欄。附件先上傳再把 `TBLWIPERF_ATTACHFILE.Status` 設為 1。既存 `TBLWIPERFCREATEDATA` 會移至 `BKTBLWIPERFCREATEDATA` 後刪除。最後 `ChkLotStamp`、檢查 ERFNo 未佔用，再執行成組 SQL；成功後通知群組（郵件／訊息，依部署設定）。

正式 API 建議：帶登入與功能權限的候選查詢（六篩選、至少一個、分頁限制）及查找；建立表單資料查詢提供 Lot／版本、分類／HoldItem、元件、Area、OCAP、Equipment State。單一 POST `immediate-holds` 請求收 LotNo、OPNo、LotStamp、原因陣列、說明、Release EQP 選擇及可選附件暫存 token／冪等鍵。後端重讀 Lot/ERF/包裝/元件/設備狀態，驗證 `ERFMultipleHold`、Partial、狀態、Qty 精度及原因唯一鍵，server 分配 ERFNo 和使用者，於單一交易寫 ERF 主從、Lot／History／Reverse／OCAP 與附件關聯；衝突回可辨識錯誤。附件位元組與 PDF／通知若在交易外，需明確補償或 outbox，不能回報整筆成功後留下半份 ERF。`BKTBLWIPERFCREATEDATA` 無 PK，不能自行假設 RepairNo 唯一。

原 Core 使用串接 SQL 的舊實作，Web API 必須用參數化 SQL 並限制授權範圍；避免沿用可注入的查詢字串。原 Form Set 對 `drSel(0)` 沒有檢查空陣列，清單變動時可能例外；API 應回 409/NotFound。原 UI 只用欄位/系統參數保護，並非正式 server-side 驗證證據。

## 表結構與 CREATE SQL

公司端用受保護 Oracle MESTEST 連線，PowerShell 5.1 + ODP.NET **唯讀** `DBMS_METADATA.GET_DDL`／`ALL_TAB_COLUMNS`／`ALL_CONSTRAINTS`／`ALL_INDEXES`／`ALL_TRIGGERS` 取得 `TBLWIPERFCREATEDATA`（15 欄，PK RepairNo）、`TBLWIPERFHOLDREASON`（9 欄，PK ERFNo+ComponentNo+HoldItemNo+AreaNo，另有 LotSerial 非唯一 index）及 `BKTBLWIPERFCREATEDATA`（15 欄、無 PK、LotNo 非唯一 index）。三者均無 trigger；Backup 表 `HOLDUSER varchar(50)`，原表是 `varchar(10)`。本次 source DDL、index DDL、metadata 在 `database/reference/mestest_wip_wp501_source_ddl.sql`、`mestest_wip_wp501_source_indexes.sql`、`mestest_wip_wp501_metadata.txt`。

另三張直接相關表的 Oracle source DDL 已存於 `database/reference/mestest_qc409_wip_disposition_dependencies_source_ddl.sql`：`TBLWIPERFBASIS`（PK ERFNo，LotSerial index）、`TBLWIPERFHOLDREASONDISP`（同原因複合 PK，LotSerial index）、`TBLWIPERF_ATTACHFILE`（PK LotNo+ERFNo+AttachName，BLOB 欄）。六張表的 PostgreSQL **CREATE-only 結構參考**集中於 `database/reference/mestest_wip_wp501_create.sql`。它不是 migration，也不是已在 YMES PostgreSQL 建好的證據。家用端須先核 live schema/history、資料、權限，僅補真正缺少的 forward migration。不要重建已有表、猜測 FK/PK 或執行整份參考 SQL。

其餘共用 LotBasis/State/Log/LoginState、ComponentState、QCFirstGroup/HoldItem/OCAP、ERF OCAP state、System Parameter 等依先前 WP101、WP305、QC409、QC HoldItem 與系統表 references。Release EQP 的 `TBLWIPTEMP_EQUIPMENT` Oracle DDL／PostgreSQL CREATE-only 已在 `mestest_wip_wp201_dependency_source_ddl.sql`／`mestest_wip_wp201_create.sql`；`TBLEMSEQUIPMENTSTATE` 已在 `mestest_equipment_state_references_source_ddl.sql`／`mestest_equipment_state_references_create.sql`；`TBLEQPSTATEBASIS` PG CREATE-only 在 `mestest_equipment_state_create.sql`。這些均是既有參考，沒有新缺的直接表，不重複產生 CREATE。`TBLWIPREVERSEHISTORY` 已有 WP215 source/CREATE；LotLog/LoginState 亦已有 QC409/WP305 參考。`iMESWIPReleaseLogHandler.dll` 在公司原碼樹只有編譯 DLL，未找到對應標準版原始碼；家用端仍需追其 ReleaseLog 間接表以及 User Define hook 的部署實作，不能只以本六表完成正式交易。

## 公司 DEV 實作與限制

DEV localStorage 鍵 `ymes-dev-mock:wip-immediate-hold:state:v1`，包含五筆假 Lot。`DEV-HOLD-001` 展示元件／Area 原因，與 `DEV-HOLD-HELD` 共用 `DEV-EQP-01` 以展示設備共用拒絕；`DEV-HOLD-SOLO` 獨佔 `DEV-EQP-02`，可展示成功解除設備；`DEV-HOLD-PACK` 展示包裝拒絕，`DEV-HOLD-PARTIAL` 被查詢排除。既存 v1 假資料載入時補齊新增欄位／第五筆，不清除原有假交易。查詢、假查找、Set、分類與原因、Confirm 後產生本機 ERFNo 並更新假 LotStatus/LotStamp；Release EQP=Yes 時先核對同設備其他 Lot，成功後移除本 Lot 假設備關聯。可在重載後保留；正式 non-DEV 入口禁用資料與交易。

DEV 只記附件**檔名**，不傳位元組、無 PDF/郵件/訊息、真 ERFNo 保留、真持久化或所有 Core 副作用。Equipment State 由既有設備狀態主檔 DEV localStorage 讀取數字代碼／名稱，尚未存檔時用其 81/82/83 預設假資料。設備關聯亦只在 WP501 localStorage 中模擬，沒有跨 WP201/WP204 的全域設備占用交易。`ERFMultipleHold` 在 DEV 固定為 1。未連 YMES PostgreSQL、未執行 Oracle DDL/DML 或查業務列。依既有交接要求，此輪只做來源與靜態檢查，未執行 build/test/browser；正式功能須由家用端完成 API/schema 並驗收。
