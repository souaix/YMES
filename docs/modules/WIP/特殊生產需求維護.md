## WinForms 主窗

原 Form `ClientSize=919×574`：上方 Query 群組，中間 SWR Basis Grid，右側垂直按鈕，下面唯讀 `SWRDescription`。Query 有七組「勾選才套用」條件：`SWRType`、`CustomerNo`、`LotNo`、`DeviceNo`、`OPNo`、`CustomerLotNo`、`MONo`。勾了但未填要提示；`SWRType` 0=作業站指示、1=包裝作業說明。LotNo 與 OPNo 支援逗號多值，其餘為等值；MONo 查詢轉大寫。Core 的 `LoadSWRBasis` 以 `TBLWIPSWRBASIS A LEFT JOIN TBLWIPSWRDETAIL B` 查 `A.*` 與 `B.LotNo`，按 `A.SWRNO` 升序。因此一張有多個 Lot 的 SWR 會出現多列；按 LotNo 篩選時返回符合的明細列。原 SQL 字串拼接，正式 API 必須使用參數，並限定查詢筆數／權限範圍。

Grid 上方四個狀態 radio：`UNFROZEN=0`（預設）、`PENDING=1`、`ACTIVE=2`、`UNUSED=99`；原 Form 取回查詢結果後以 DefaultView RowFilter 分狀態。可見 14 欄依序為 `SWRNO, SWRTYPE, CUSTOMERNO, DEVICENO, OPNO, LOTNO, MONO, STATUS, STARTTIME, ENDTIME, CUSTOMERLOTNO, CREATOR, CREATEDATE, HaveAttachFile`。最後一欄是 Form 由 `AttachFilePath` 非空算出的 Y/N，**不是** Oracle 真實 BLOB 是否非空；正式端應同時處理舊資料中兩者不一致。選取單列顯示下方說明；Grid 可多列選取，因 JOIN 重複列，命令應以 SWRNo 去重。

右側 `ADD`、`EDIT`、`Copy`、`Approve`、`Void`、`DownLoad File`、`Close`。編輯僅限狀態 0。核准只允許狀態 0→2；若 StartTime 存在，需 EndTime > StartTime。原 Form 對選取列逐筆送 `UpdSWRBasis`，遇錯即停止，先前成功不回滾；其 `PassSWRNo` 僅保存當次 SWRNo，對三筆以上重複 JOIN 列的防重不完整。新 UI/API 以 SWRNo 去重，批次回覆要列出逐筆成功／失敗／未處理。

作廢先確認；`InputAbortLog=1` 時透過 `SS_InputAbortLog` 要求原因，否則仍傳空原因。Service `AbortSWRBasis` 對 `ACTIVE=2` 改成 99 並寫 SYS EventLog；對 0/99 刪主／明細並寫 EventLog。**狀態 1 既沒有處理分支又回 success**，是原始缺陷；新端必須明確拒絕 PENDING，不得顯示假成功。原 Form 同樣逐列呼叫，中途錯誤可能部分成功。下載先檢 HaveAttachFile，再按 SWRNo 讀 BLOB 並開 SaveFileDialog（預設 PDF）；新 API 應回附件 bytes 與安全檔名，不返回原伺服器路徑。

## 新增／編輯／複製窗

`DefMode=0/1/2` 分別 ADD/EDIT/Copy。欄位 `SWRNo` 唯讀、`SWRType`、`CustomerNo`、`OPNo`、`MONo`、`CustomerLotNo`、`DeviceNo`、逗號 LotNo、可勾選的 StartTime/EndTime、AttachFile、SWRDescription，底部 Creator/CreateDate 與 Confirm/Close。Customer、OP、MO、Device、Lot 由既有 lookup 開 `frmCOMSearch`/Multi；Lot 明細由 `LoadSWRDetail` 填入。Copy 會取新號、複製表單文字與 Lot 明細，清空附件，建立人/日改成目前使用者/現在；Edit 保留原單號和 audit，僅狀態 0 可儲存。

必要欄位 SWRNo、CustomerNo、OPNo、SWRDescription、SWRType；Start/End 要一起設定且 End > Start。每個選取 Lot 的 `TBLWIPLOTBASIS.BASELOTNO` 必須屬於表單 CustomerNo。Add/Copy 預覽號格式 `SWRyyMMdd001`，核心透過 `TBLSYSSERIALNO` 的 `FUNCTIONNAME='SWRyyMMdd'` 讀下一序號；新增時再比對號碼、同批寫流水號、明細、主表。正式 API 必須在交易內鎖定／原子配置序號，不能相信前端預覽號，也要處理每日 999 後格式。Edit 先查 status=0，替換全部明細，再更新主表與附件；正式 API 要在交易內重驗狀態和 Lot/Customer 關係。

原 Form 的 OpenFileDialog 只選 `*.pdf`，並用系統 `FileSizeLimit`（MB）限制大小；具體值由參數表提供，不能從此 Form 猜測。上傳用 `fs.Read(abytBuffer, 0, fs.Length - 1)`，分配完整長度卻少讀最後一 byte；空檔還可能出錯。新 API 須完整讀取 stream、按系統設定檢查大小並驗證檔案型別，不移植這個問題。Oracle `ATTACHFILE BLOB` 與 `ATTACHFILEPATH VARCHAR2(200)` 同時存在；後者是舊用戶端路徑，正式端只回可用檔名/下載資源，不洩漏路徑。原 Core SQL 以字串組合且直接拼 SWRDescription、LotNo 等；新 API 全面參數化。

## Oracle MESTEST 只讀結構與 CREATE-only

公司端透過受保護 Oracle profile、Windows PowerShell 5.1、`Oracle.ManagedDataAccess.dll`，唯讀查 `DBMS_METADATA.GET_DDL` 與 `ALL_TAB_COLUMNS`／`ALL_CONSTRAINTS`／`ALL_INDEXES`／`ALL_TRIGGERS`，沒有查業務列、執行 DDL/DML 或接 YMES PostgreSQL。精確檔案：

| Oracle 表 | 結構 | 交付檔 |
|---|---|---|
| `MESTEST.TBLWIPSWRBASIS` | 15 欄；`SWRNO VARCHAR2(20)` PK；`SWRTYPE NUMBER(1,0)`、`STATUS NUMBER(2,0)`、`CUSTOMERNO VARCHAR2(50)`、`OPNO VARCHAR2(20)`、`SWRDESC VARCHAR2(400)` 必填；`ATTACHFILE BLOB`；1 個 unique PK index；無 FK/trigger | `database/reference/mestest_wip_wp109_basis_source_ddl.sql`、`_source_indexes.sql`、`_metadata.txt` |
| `MESTEST.TBLWIPSWRDETAIL` | 2 欄；PK `(SWRNO, LOTNO)`；1 個 unique index；無 FK/trigger | `database/reference/mestest_wip_wp109_detail_source_ddl.sql`、`_source_indexes.sql`、`_metadata.txt` |
| `MESTEST.TBLSYSSERIALNO` | 2 欄；`FUNCTIONNAME VARCHAR2(20)` PK、`SERIALNO NUMBER(9,0)` 必填；1 個 unique index；無 FK/trigger | `database/reference/mestest_wip_wp109_serial_source_ddl.sql`、`_source_indexes.sql`、`_metadata.txt` |

PostgreSQL 空表 **CREATE-only 參考** 在 `database/reference/mestest_wip_wp109_create.sql`，依原始欄/PK/可空性、`BLOB→bytea`、`DATE→timestamp`；沒有臆造 FK、索引或 default。`TBLSYSSERIALNO` 是共用流水號表，家用端應先查 live schema/history，已存在則只核對，不重建。這個 SQL 不是已套用 migration，也不表示 live schema 缺表。Customer／OP／Lot 等 lookup 表沿既有主檔/WIP reference。

## Vue DEV 與家用端正式 API

`web/src/components/WipSwrBasis.vue` 只在 DEV preview 使用本機假資料，localStorage key `ymes-dev-mock:wip-swr-basis:state:v1`。實作七勾選篩選、四狀態、14 欄 JOIN 形狀 Grid、說明區、右側七按鈕、ADD/EDIT/Copy 表單、逐張核准/作廢、lookup/Customer-Lot 守門、假流水號與記憶狀態。DEV 的 lookup/Customer-Lot 對應是示意；附件只接受 PDF **檔名**，不存/下載檔案內容，沒有 SYS EventLog 或真 API 交易。為示意 `InputAbortLog=1`，DEV 作廢一律要求原因；正式版由 server 設定決定。

家用端應先核 PostgreSQL live schema/history/權限，再只對缺項寫 forward migration；新 API 需 `WP109` 功能 ACL、分頁查詢、七條件值陣列（Lot/OP）、單張明細及 lookup、預覽／配置流水號、Add/Edit/Copy、Approve、Void、附件 upload/download。建議查詢回傳一張 SWR 與其 Lot 陣列或明確 JOIN row ID，前端仍按原 14 欄展開；同 SWR 多選去重。命令由 server 提供 actor/時間，以資料庫 transaction + row lock/版本重查狀態、客戶 Lot 所屬、附件與序號；批次如沿逐筆模式，逐筆結果須揭露部分成功。作廢寫 SYS EventLog；若 Audit/EventLog provider 未就緒，不能用僅改狀態的成功回覆冒充完整交易。附件使用安全檔名、大小/類型上限與完整 bytes。正式 UI 不使用 DEV key/fixtures，實際 API/驗收由家用端負責。
