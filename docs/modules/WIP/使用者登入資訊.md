# WP106 使用者登入（上工）資訊

## 來源與定位

- 選單：在製品管理 → 在製品 → 使用者登入(上工)資訊；`FunctionNo=OPERATOR ONLINE`、`FunctionKey=WP106`、`WP_OperatorOnline.dll`。DEV 頁 `/YMES/WIP/OperatorOnline`。
- Form/Designer：`STD/MESWin/WIP/WP_OperatorOnline/frmOperatorOnline.vb`、`.Designer.vb`（ClientSize 784×562）。Service `STD/MESws_STD/wsSTD/wsWIP/wsWIP_OperatorState.cs::LoadOperatorState/ExecuteClockOut`；Core `STD/MESkc/kcWIP/clsOperatorState.cs::ShowOperatorState/ExecuteClockOut`。OP/Area/Equipment lookup 另走 `wsOP.LoadOPBasis`、`wsSMD.LoadAreaBasis`、`wsEQP.LoadEquipmentBasis`。
- 與 WP104 上工、WP105 下工共用 OperatorState/Log 交易，詳細下工 side effect 見 [WP105](使用者登出作業_下工.md)。WP106 並非純唯讀：預設會顯示 SignOut，可被其他 Form 用 `EnableSignOut=False` 呼叫成唯讀視窗。

## WinForms 畫面與行為

上方 Query 框縱向三列：OP No、Area No、Equipment No，均可直接輸入逗號分隔的多值，也可用 `...` 開共用 `frmCOMSearch_Multi` 多選。OP lookup 顯示 OPNo/OPName/OPType/PSNo，Area 顯示 AreaNo/AreaName/AreaType，Equipment 顯示 EquipmentNo/EquipmentType。Query 可完全不填，取得目前所有上工現況。`OPNo`、`AreaNo`、`EquipmentNo`、另有外部傳入的 `LotNo` property 最終合併為 **LoginPlaceNo IN 同一集合**；屬 OR/union，不是三個欄位相交。原 Form 把輸入內容拼成 SQL `AdditionalXml`（含原始引號），新 API 不得接受這種 SQL 片段。

Grid 預設灰底，查後 `CheckFlag` 全部重設 false；顯示七欄依序：CheckFlag、UserNo、UserName、ShiftNo、LoginDate、MultiOperatorMode、LoginPlaceNo，依 LoginDate/UserNo/MultiOperatorMode 升序。`MultiOperatorMode` 使用值清單顯示，行內仍保留 WorkDate/OPNo 等供下工。底部 SignOut、Close。`EnableSignOut=False` 時隱藏勾選欄、Query、三個 lookup、SignOut，三個輸入欄禁用；外部設定 OP/Area/Equipment/Lot property 仍會觸發查詢。

SignOut 至少勾一列，先彈確認對話框（來源預設 Cancel），然後**每列**以 UserNo、LoginPlaceNo、MultiOperatorMode、AP server LogoutDate 呼叫 `wsWIP_OperatorState.ExecuteClockOut`；一列失敗即停止，前面成功的列不回滾。Finally 只要曾成功便重讀 Grid。Core 依這三鍵讀現況，寫 `TBLWIPOPERATORLOG`（分鐘工時），刪 `TBLWIPOPERATORSTATE`，多人加工時還會同步 `TBLWIPLOTLOGINSTATE` 等下工副作用。不可把它簡化成只刪一筆 State。

## 資料表與 DEV 實作

直接 `TBLWIPOPERATORSTATE`、`TBLWIPOPERATORLOG` 的 Oracle source DDL/metadata/index/PG CREATE-only 已在 `database/reference/mestest_wip_wp104_*`；LotLoginState 沿 WP305，UserBasis 與 OP/Area/Equipment lookup 沿既有共用 reference。**WP106 無新直接表，沒有新的 CREATE SQL**。公司端本輪只核現有來源與程式，不查 Oracle 業務列、不寫 Oracle、不連 YMES PostgreSQL。

`web/src/components/WipOperatorOnline.vue` 在 DEV 共用 WP104/WP105 的 `ymes-dev-mock:wip-operator-clock-in:state:v1` 和 log key `ymes-dev-mock:wip-operator-clock-in:log:v1`；未寫入 key 時用兩筆與 WP105 同形狀的示意現況。提供三欄逗號輸入、多選 lookup、union 查詢、七欄表格、勾選及確認下工；每筆假下工移出 State、加入 Log。外部 `initialOpNo`/`initialAreaNo`/`initialEquipmentNo`/`initialLotNo` 與 `enableSignOut=false` 可示意其他 Form 嵌入唯讀。DEV 不執行真 User/Group privilege、真 lookup 資料、LotLoginState side effect；不與 server 做原子交易。

## 家用端正式 API

### 已完成的唯讀查詢（2026-11-27）

- 以 migration 0097 依 WP104／WP305 已核實的 Oracle source DDL，在 YMES schema 建立空的 OperatorState、OperatorLog、LotLoginState；ymes_app 目前只有 SELECT。遷移前備份、checksum、來源索引與權限回讀見資料庫連線紀錄。
- GET /YMES/API/api/wip/operator-online 僅要求登入，使用參數化 placeNos 值陣列，將 OP／Area／Equipment／外部 Lot 條件合併為 LoginPlaceNo 精確值聯集；預設 50、每頁最多 100，穩定排序並回傳 hasMore。空條件也只會取得一個有界頁面，不接收 AdditionalXml 或 SQL。
- 正式 /YMES/WIP/OperatorOnline 已接上唯讀 API，支援手動多值查詢與上一頁／下一頁；沒有讀寫 localStorage。正式表目前 0 列，因此只可驗證空結果，不能做有資料的正向查詢驗收。
- ymes_app 對三張新表的 INSERT／UPDATE／DELETE 均為 false。正式 lookup 按鈕與 SignOut 維持停用；來源 ExecuteClockOut 的 SID、工時欄位計算及多人加工副作用尚未在家用電腦核實前，不開放任何正式寫入。

SignOut command 需另檢功能操作權限、選取列可見與可下工權限。Server 端產生 LogoutDate，依 UserNo+Mode+Place 重查/鎖定 State，在**單筆**交易內寫 Log、刪 State、更新相關 LotLoginState，防止重複登出和並發；回傳逐筆結果與冪等狀態。若前端保留原 Form 的逐列送出，多筆中途失敗須明確顯示已成功、失敗與未處理列；不可只回籠統成功。不能把 client 傳來的 UserNo 或 LoginPlaceNo 直接當授權依據。家用端核 YMES PostgreSQL live schema/history，重用 WP104/WP305 migration/refs，接正式 API、部署和驗收。
