# WP605 成品庫帳務維護（FGD INV）

## 功能定位

- MES FunctionNo：FGD INV；程式：frmInventory_FGD／WP_Inventory_FGD.dll。
- 三層選單：在製品管理 → 包裝與庫房 → 成品庫帳務維護。
- 入口標題為 FGD Inventory，Form ClientSize 為 1008×661。
- 本頁管理成品庫別中的批號、儲位和數量，並提供人工調整、轉庫與 FGD In 入庫確認。

## WinForms 畫面與可見功能

主畫面上方只有成品庫編號欄位、… 庫房查詢和 Enter／查詢。查詢庫房時呼叫 wsSMD.LoadInventoryBasis，只傳 InventoryType=1。選取庫房後會載入該庫房資料；直接輸入編號後按 Enter 也會載入。

主區域是上下兩個 Grid，中間有可調整高度的 Splitter。上方成品庫存列按 ProductNo、LotNo、LocatorNo 排序，WinForms 將 LocQty 不等於 0 的資料顯示出來；Grid 顯示欄位如下：

| 順序 | 欄位 | 顯示名稱／格式 |
| --- | --- | --- |
| 1 | ProductNo | 產品編號 |
| 2 | MONo | 工單編號 |
| 3 | LotNo | 生產批號，允許換行 |
| 4 | LocatorNo | 儲位 |
| 5 | LocQty | Quantity，0.######、靠右 |
| 6 | UnitNo | 單位 |
| 7 | BelongToType | 0 轉為 MO，其他值顯示空白 |
| 8 | BelongToNo | 歸屬編號 |
| 9 | InputDate | yyyy/MM/dd HH:mm:ss |

選取上方資料列會即時清空並載入下方 Grid。先查 wsINV.LoadFGDInventoryComponent(InventoryNo, LotNo, LocatorNo)；有元件資料就顯示 ComponentNo、GoodQty、ScrapQty、UnitNo。沒有元件資料才呼叫 wsWIP.LoadGoodBinState(LotNo)，並依 wsSYS.LoadBin 回傳的 BinNo／BinOrder 動態建立欄位。Bin 資料與成品庫主列是兩個不同資料來源。

右側可見按鈕依序為 FGD In、Turn INV、Add、Del、Close。Designer 中 Edit 按鈕預設 Visible=False；程式仍保留 Edit handler，但一般操作畫面不應顯示它。沒有 Copy、Download 或 Print 按鈕。

## 操作與驗證規則

### Add／Edit

- Add 開啟 frmInventory_FGDDef；若主畫面已選庫房，帶入 InventoryNo。
- 定義窗欄位為 InventoryNo、ProductNo、LotNo、UnitNo、Quantity、LocatorNo、InputDate、BaseLotNo。BelongToType／BelongToNo 在 Form 中隱藏。
- InventoryNo 必須是 InventoryType=1 的有效庫房。
- LocatorNo 必須屬於所選 InventoryNo，且 IssueState=2。
- LotNo 必須能由 wsWIP.LoadLotBasisJoinState 找到，狀態為 11 或 99；查到後帶出 ProductNo、CurUnitNo、BaseLotNo。
- Quantity 必填、為數值且大於 0。
- Edit 模式將 InventoryNo、LotNo、LocatorNo 設唯讀並隱藏 lookup；但主畫面按鈕預設隱藏，因此 DEV 頁不顯示 Edit。
- Save 呼叫 wsINV.AdjustFGDInventory，以 (InventoryNo, LotNo, LocatorNo) 判斷是否存在：存在時更新數量及相關欄位，不存在時新增。這不是加總，而是覆寫該主鍵列的 LocQty。

### Del

- 對選取的多筆列逐筆呼叫 wsINV.DelFGDInventory；每筆錯誤個別呈現，最後重新載入資料。舊程式不是整批原子刪除。
- Core 的 DelFGDInventory 只刪 TBLINVFGDINVENTORY 主列，該方法沒有明確刪除元件列；Oracle 此次也未找到相關 Trigger 或 FK。正式 API 要先確認是否需保留舊孤兒列語意，不能假設資料庫會 cascade。

### Turn INV

- 必須先選取一筆上方庫存列，再開 frmInventory_FGDTurn。子窗可勾選多列，亦可掃描 LotNo 將符合列勾選。
- 可選目的庫別：WIP Inventory（型別 6）、SEMI Inventory（型別 2）、FGD Inventory（型別 1）。目的庫別與儲位都必填；Locator 必須屬於目的庫且已核准。
- wsINV.ChkLocatorStorage 依儲位 Capacity 檢查轉入總量；Capacity=0 代表不套用該限制。
- 確認後呼叫 wsWIP.Exe_FGDTurn。FGD→FGD 會更新 TBLINVFGDINVENTORY 的庫別、儲位和 InputDate，移動對應的 TBLINVFGDINVENTORYCOMPONENT，更新 LotSerial 並建立 Lot release log；此路徑不允許回復。
- FGD→SEMI／WIP 分支還會寫入不同庫存表、處理 Lot／Component 狀態及歷程，必須按 Oracle 交易邏輯在 API 端處理；只實作 UI 不等於正式轉庫完成。

### FGD In

- frmINVFGDInConfirm 清單呼叫 wsINV.LoadINVFGDInBasis(State=0)，再於前端排除 ToERP=1 並依 FGDInNo 排序。
- 選取單據後呼叫 wsINV.LoadINVFGDInDetailAndComponent，顯示單據基本資料、Lot 詳細資料及 Component 明細。Detail 會取得 ProductName；Component 查詢另帶 MinLifeGrade。
- Confirm 呼叫 wsINV.AddINVTransactionState，傳 Source=30（FGD In）、TicketNo=FGDInNo、Creator=登入者。
- Service 自動產生 TransactionID，新增 TBLINVTRANSACTIONSTATE，將 FGDInBasis 設為 State=1，再同步呼叫 ExeINVTransactionState。Source=30 會執行 ExeFGDIn、成功後將 Basis 設為 State=2，並把交易從 TBLINVTRANSACTIONSTATE 移入 TBLINVTRANSACTIONLOG。處理失敗時 Basis 設為 State=3；API 要保留完整庫存過帳、狀態、交易記錄與錯誤處理，不能只新增 queue row。
- ExeFGDIn 依單據明細調整成品庫存、儲位數量、Lot／Component 狀態與歷程；Source=1 的 FGD In 還會扣來源 SEMI/WIP 庫存。Service 同步呼叫外部 `iMESWIPReleaseLogHandler.dll`，Core 使用 `udWIP.clsWIP` 產生 LotSerial。這些跨模組 side effect 是 Production API 的相依工作。

## WinForms／Service／Core 證據

| 用途 | WinForms | Service／Core | 核實行為 |
| --- | --- | --- | --- |
| 成品庫清單 | frmInventory_FGD.vb | wsWIP.LoadFGDInventory → clsLot.LoadFGDInventory | 查 TBLINVFGDINVENTORY，left join TBLWIPLOTBASIS 取得 MONo；歷史出貨排除 SQL 已註解。 |
| Component／Bin | 同上 | wsINV.LoadFGDInventoryComponent → clsInventory.LoadFGDInventoryComponent；wsWIP.LoadGoodBinState → clsLot.LoadGoodBinState；wsSYS.LoadBin → clsSYSEng.LoadBin | Component 先查；沒有 Component 才顯示 Lot Bin。Bin 欄位取自 TBLSYSBIN。 |
| 人工調整／刪除 | frmInventory_FGDDef.vb、主 Form | wsINV.AdjustFGDInventory、DelFGDInventory → clsInventory | 以三欄主鍵 upsert；刪除只明確刪主列。 |
| FGD In | frmINVFGDInConfirm.vb | wsINV.AddINVTransactionState → clsInventory | Source=30，產生交易編號、更新 FGDIn Basis 狀態並執行庫存交易。 |
| 轉庫 | frmInventory_FGDTurn.vb | wsWIP.Exe_FGDTurn → clsLot.ExeFGDTurn | 驗容量、依目的庫型別走不同交易分支、寫 Lot 歷程。 |

## 資料表與 DDL

Oracle MESTEST DDL 由 Windows PowerShell 5.1、Oracle.ManagedDataAccess、本機受保護連線設定直連取得；僅讀 DBMS_METADATA.GET_DDL 和資料字典，沒有讀業務列、沒有執行 Oracle DDL/DML，沒有輸出連線秘密。

新增／本功能特有的來源表共六張：

| Oracle table | 主鍵 | 本頁用途 |
| --- | --- | --- |
| TBLINVFGDINVENTORYCOMPONENT | InventoryNo, LotNo, LocatorNo, ComponentNo | 成品庫批號的 Component 數量與轉庫連動 |
| TBLINVFGDINBASIS | FGDInNo | FGD In 單據表頭 |
| TBLINVFGDINDETAIL | FGDInNo, LotNo, LocatorNo | FGD In Lot 明細 |
| TBLINVFGDINCOMPONENT | FGDInNo, LotNo, ComponentNo | FGD In Component 明細 |
| TBLINVTRANSACTIONSTATE | TransactionID | 庫存交易確認佇列／狀態 |
| TBLINVTRANSACTIONLOG | TransactionID | 成功處理後保存的庫存交易記錄 |

六張表均只有 PK unique index；無 FK、額外 index 或 trigger。此結論已透過 Oracle `ALL_INDEXES`、`ALL_CONSTRAINTS`、`ALL_TRIGGERS` 核對。Oracle DDL 和 PostgreSQL CREATE-only 對照：

- [PostgreSQL CREATE-only](../../../database/reference/mestest_wip_wp605_create.sql)

## YMES API／DB 交接

家用電腦先比對 PostgreSQL live schema 與 migration history，再決定新增 migration；CREATE-only 僅為欄位對照，不可直接覆蓋既有物件。建議 API 依下列邊界實作：

1. 庫房清單只回 InventoryType=1；Lot 查詢接受庫別，回傳目前 WinForms Grid 欄位並保留 LocQty 不等於 0 的顯示條件與排序。
2. Component、Bin 是互斥的下方明細；Component 有資料時不再查 Bin。Bin columns 按 TBLSYSBIN.BINORDER 動態呈現。
3. Adjust API 以 (inventoryno, lotno, locatorno) 原子 upsert。服務端重查庫房型別、核准儲位、Lot 狀態和數量，不信任 UI 帶出的 ProductNo／UnitNo／BaseLotNo。
4. Delete API 接收明確主鍵列；保留舊程式逐筆回報部分失敗的回應語意。需與業務確認孤兒 Component 清理規則，不可以新增未經確認的 Cascade。
5. Turn API 應在交易中重查來源列、目的庫別／儲位、IssueState、容量和並發變更；FGD→FGD 及 WIP／SEMI 分支均需維持 Core 的 Lot、Component、庫存與歷程關聯。轉庫不可只改 UI 上的庫別字串。
6. FGD In 查詢條件為 State=0 且 ToERP 不等於 1；Confirm 使用 Source=30。伺服器產生 TransactionID，避免重複送出；交易內依序記錄 state、Basis 狀態、完整庫存／Lot 過帳，成功移至 TBLINVTRANSACTIONLOG，失敗把 Basis 設為 State=3。Source=1 還須扣來源 WIP／SEMI 庫存並保存 Lot release log。
7. 共用 SYS event log、Lot release／reverse log 與 system bin 資料須沿用既有資料模型。舊 Core 轉庫會呼叫外部 iMESWIPReleaseLogHandler.dll；本公司 checkout 未含該 DLL 原始碼，API 實作需另外核對家用端可用的歷程契約。

## 公司端 DEV 實作與簡化

- Vue 路徑：/YMES/WIP/FgdInventory；FunctionNo FGD INV 的 fallback menu 放在「在製品管理 → 包裝與庫房 → 成品庫帳務維護」。
- 假資料只存專屬 localStorage key：ymes.dev.wp605-fgd-inventory.v2，沒有呼叫 API 或資料庫。
- 已實作庫房查詢、主表排序與欄位、row selection、Component／Bin 切換、Add 驗證及三欄 upsert、逐列 Del、FGD In Source=30 確認、FGD／SEMI／WIP 目的庫選擇及容量檢查。
- Turn 的 FGD→FGD 假資料會移動主列及 Component；SEMI／WIP 只從 FGD 顯示清單移除並記 DEV movement，不模擬正式庫存表、Lot／Component 狀態和 release log 的全部 side effects。
- DEV Bin Grid 依假資料 BinOrder 動態排序欄位、每個 Lot 顯示一列 Bin quantity；Production UI 要依 TBLSYSBIN metadata 動態建立欄位，與 WinForms `funBuildBinTable`／`funLoadBinTable` 相同。
