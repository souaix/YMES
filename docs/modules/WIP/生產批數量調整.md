# WP907 生產批數量調整

- `LOT QTY ADJUST` 對應 `STD/MESWin/WIP/WP_LotQtyAdjustSelect/frmLotQtyAdjustSelect.vb`。依入口與三個內嵌 Designer／Form 核對。查 `wsWIP.LoadLotBasisJoinState` 固定排隊 Status=0 且 ShowPartialLot=false，可依區域、區段、作業站及批號查詢。單批調整先跑 `CheckLotPackage`，有 GoodBinState 優先進 Bin 表單，其次有 ComponentState 進元件表單，其餘進整批調整。
- 整批 `frmLotQtyAdjust` 讀 LotState、LotLog、Scrap、Cont_Error、LotLog_Report、Reason、Inventory。修改良品或逐站報廢／損失，不良數合計與報廢量須逐 LogGroupSerial 相等。良品大於零，至少選一個原因。投入量與最終合計不符時可確認繼續。依新舊良品差填 BonusQty 或 DeductionQty。
- Bin `frmLotQtyAdjust_Bin` 按 Bin 分良品／不良，增量與扣量不可同時有值，Bin＋報廢＋損失等於投入＋增量－扣量，良品 Bin 不可為零。送不良及報廢庫房，異常入口可指定 LogLotSerial。
- 元件 `frmLotQtyAdjust_Comp` 依元件列增補、扣除、復原扣除、切換合格並輸入良／廢數。至少一件合格、至少一個原因，不良元件要報廢庫房。批的良品量按合格元件筆數，增扣量按新增／扣除筆數。
- STD `wsWIP.Exe_LotQtyAdjust`、`Exe_LotQtyAdjust_Bin`、`Exe_LotQtyAdjust_Comp` 對應 `STD/MESkc/kcWIP/clsLot.cs` 三個同型 `UpdLotQtyAdjust*`。交易更新 LotState（目前量、系統量／單位、事件欄位）、相關 Scrap／FailBin／ComponentScrap／Error 與 AdjustLog／AdjustDetail。整批傳 LotStamp 並建回復資料，Bin／元件舊入口使用 LotSerial、可選 LogLotSerial，正式端統一加版本守門。
- [Oracle metadata](../../../database/reference/mestest_wip_wp907_metadata.txt) 唯讀取得兩張新表的欄位、PK 及索引。[CREATE-only](../../../database/reference/mestest_wip_wp907_create.sql) 保留 AdjustSerial 單／合成鍵；未見 FK，Oracle 字串為 BYTE 限制，預設值仍待核對。入出庫、Lot、Bin 與原因重用 WP101／WP201／WP603／WP605 等現有來源和 Core 所列依賴。

## DEV 與家用端

- `/YMES/WIP/LotQuantityAdjust` 提供四項過濾、分流、各自數量守門、原因、庫房與取消／確認。DEV-QTY001/002/003 是整批／Bin／元件，004 演示包裝阻擋。整批以單站代表原程式逐站與多不良碼，元件增補用手填代替實體元件 lookup，Bin 用兩個假 Bin。只有本頁假量和版本變更，庫房、原因、說明及回復稽核不落正式交易。
- 建議 WP907 ACL 的 `GET /api/wip/lot-quantity-adjustments/lots`、`GET /api/wip/lot-quantity-adjustments/{lotNo}` 及 `POST /api/wip/lot-quantity-adjustments/{lotNo}`。回傳批版本、分流、單位和模式專屬列，命令接受 mode、該版本、各組數量／明細、原因、說明與冪等鍵。在交易中重查排隊／部分站／包裝、批版本、模式及可用庫房，依原精度對帳並保持數量、庫存、原因、稽核及回復一致。合計異常的整批調整必須可追溯。
