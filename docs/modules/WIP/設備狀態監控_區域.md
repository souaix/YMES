# 設備狀態監控_區域（WIP WP307）

## 功能來源與範圍

| 項目 | 來源 |

| WinForms 主畫面 | `STD/MESWin/WIP/WP_AreaShow/frmAreaShow.vb`（`frmAreaShowWIP`） |

WP307 與 SMD SD108 共用 Base Area 選擇器、`TBLSMDAREARELATION` 區域配置圖、節點形狀及縮放/網格。SD108 的班別 CRUD 屬 SMD，不是 WP307 操作；WP307 在區域節點上提供登入登出、目前狀態、歷史紀錄。

## 主畫面互動

1. Base Area 選擇器只列已核准的基底區域；選取後載入該 Base Area 的 relation 節點。
2. 節點種類：0 區域矩形、1 庫房六角形、2 設備橢圓、3 設備類別圓角矩形、4 設備群組圓角矩形。只有 ObjectType=0 區域節點能執行 WIP 操作。
3. Toolbar 提供 100%、150%、75%、50% 縮放、Grid 與關閉。Grid 開啟共用 `frmCOMGridProperties`：Show Grid、Snap To Grid、Grid Color、Grid Style（Pixels/Lines/DottedLines）、Grid Size Width/Height；按 OK 套用，Close 捨棄。WP307 畫布在此功能中唯讀，Snap 設定保存於 UI 設定狀態，但沒有節點拖曳編輯可觸發吸附。
4. WinForms 只有 EnterpriseNo=`IMESTECH` 才顯示區域操作；區域節點右鍵選單為 Login/Logout、State、History；雙擊區域節點直接開 Login/Logout。Vue Production 依登入者 enterpriseNo 隱藏入口，DEV preview 保留互動範例。
5. Vue 沿用 SD108 的地圖元件，透過 `workAreaMode` 隱藏 SMD 班別編輯入口，改顯示 WP307 的三個選項。SMD SD108 路由仍使用原模式。

## Login / Logout 視窗

- 固定視窗 320×254，欄位 AreaNo、DepartmentNo、UserNo、ShiftNo、Comment；AreaNo/DepartmentNo 唯讀。按 Confirm 或 UserNo Enter/離開欄位時，UserNo 轉大寫並核對當前時段班別名單；ShiftNo 下拉列出合格班別並預選第一筆。
- `LoadAreaOperator_Current(AreaNo)` 以 AreaBasis DepartmentNo、AreaOperator UserNo/ShiftNo 及 `TBLUSRSHIFTBASIS` FromTime/ToTime 找目前班別。排班外的人員不會出現在候選；若不符合名單，`ChkAreaLogin(UserNo)` 判斷是否已登入同區或其他區，並顯示不同訊息。
- Login 必須有 AreaNo、DepartmentNo、ShiftNo、UserNo；成功呼叫 `ExeAreaLogin` 寫入 `TBLWIPAREAOPERATORSTATE`，LoginComment 可空。Core 使用伺服器目前時間。
- 登入狀態表以 UserNo 為唯一主鍵，因此同一 UserNo 同時只能登入一個區域。API 必須在交易中再次核對目前班別/排班與既有登入，不能只相信 Vue 的 Confirm 結果。
- Logout 先用 AreaNo、DepartmentNo、ShiftNo、UserNo 呼叫 `ShowAreaOperatorState` 檢查仍有登入資料，再呼叫 `ExeAreaLogOut(UserNo, LogoutComment)`。Core 從班別取得 ExceptionTime，刪除現況並新增歷史；WinForms 隱藏 ExceptionTime 輸入控制項，使用者不能自行指定。
- Vue DEV 假資料只寫 `ymes-dev-mock:wip-area-operator-state:v1`、`ymes-dev-mock:wip-area-operator-log:v1`；不使用正式資料，也不寫入 SD108 的假資料 key。

## State 視窗

- 由區域右鍵 State 開啟。AreaNo 與 DepartmentNo 由入口載入；ShiftNo、UserNo 各自有啟用核取方塊，可選擇性篩選；StartDateTime、EndDateTime 可選；開窗時不自動查詢，按 Query 才執行查詢，Close 關閉。
- ShiftNo 與 UserNo 文字框旁有 `...`。Shift 查詢呼叫 `wsUSR.LoadShiftBasis(IssueState=2, DepartmentNo)`，選擇欄位為 ShiftNo、ShiftName、FromTime、ToTime；User 查詢呼叫 `wsUSR.LoadUserSecurity(IssueState=2, DepartmentNo)`，顯示 UserNo、UserName。選取後自動勾選對應篩選條件。
- Service 呼叫 `LoadAreaOperatorState`，Core 查 `TBLWIPAREAOPERATORSTATE`，固定條件為 UserNo 非空，AreaNo/DepartmentNo 固定傳入；ShiftNo、UserNo、StartDate、EndDate 選填。Core 日期比較為 `LoginTime > StartDate` 及 `LoginTime < EndDate`（嚴格界值）。
- 狀態資料包含 AreaNo、DepartmentNo、ShiftNo、UserNo、LoginComment、LoginTime。Vue DEV 即時讀登入現況假資料並支援同等篩選；正式 API 應回傳有排序、受權限限制的分頁結果。

## History 視窗

- 由區域右鍵 History 開啟。AreaNo、DepartmentNo 固定；WinForms 分為 `Filter` 與 `DateFilter` 兩個 Tab。Filter 提供 ShiftNo、UserNo、ExceptionTime 核取篩選；DateFilter 讓 LoginStart/End、LogoutStart/End 各自核取並輸入。開窗時不自動查詢，按 Query 才執行，Close 關閉。
- Service 呼叫 `LoadAreaOperatorLog`，Core 查 `TBLWIPAREAOPERATORLOG`。AreaNo/DepartmentNo 固定傳入，ShiftNo、UserNo、LoginStartDate、LoginEndDate、LogoutStartDate、LogoutEndDate、ExceptionTime 可選。
- 表格欄位包含 AreaNo、DepartmentNo、ShiftNo、UserNo、LoginTime、LogoutTime、ExceptionTime、LoginComment、LogoutComment。Vue DEV 將完成登出寫入歷史 key，初始另有一筆只供展示的假歷程。

## Oracle 結構與 PostgreSQL CREATE-only

Oracle source DDL / metadata 以 Windows PowerShell 5.1、Oracle.ManagedDataAccess 及受保護的 MESTEST profile 直接唯讀查詢，沒有查業務資料列或執行 Oracle DDL/DML。

| Oracle 表 | WP307 用途 | 結構要點 |
|---|---|---|
| `TBLSMDAREARELATION` | 共用區域畫布 | PK `(BaseAreaNo,ObjectNo)`，另有 `(ContainAreaNo,ObjectType)` 非唯一索引。其 source DDL 與 PostgreSQL CREATE 已存在於 `mestest_equipment_group_smd_*` reference，不在本功能重複建表。 |
| `TBLWIPAREAOPERATORSTATE` | 目前登入狀態 | PK `(UserNo)`；無額外索引、FK、trigger。日期欄位 `LoginTime` 為 Oracle DATE。 |
| `TBLWIPAREAOPERATORLOG` | 登入登出歷史 | 無 PK、無索引、無 FK、無 trigger；不可自行杜撰唯一鍵或索引。 |

WP307 專用兩表完整 Oracle DDL、索引與欄位 metadata 在 `database/reference/mestest_wip_wp307_source_ddl.sql`、`mestest_wip_wp307_source_indexes.sql`、`mestest_wip_wp307_metadata.txt`。新增的 `mestest_wip_wp307_create.sql` 是 PostgreSQL 空表 CREATE-only：保留現況表的 UserNo PK；歷史表不加 PK/index。Oracle DATE 對應 PostgreSQL `timestamp without time zone`。家用端須先核對 YMES live schema/migration，缺表才建立 migration；CREATE reference 不代表已套用。

## Production API handoff（家用電腦）

正式端沿用 SD104/SD108 的 Base Area 與 layout API，WIP 操作另依下列契約實作。所有寫入需登入、WP307 權限與 IMESTECH 功能授權檢查，SQL 參數化；瀏覽器傳入的使用者、班別與時間都不是權威值。

| 方法 | 路徑 | 規則 |
|---|---|---|
| GET | `/api/wip/areas/{areaNo}/operators/eligible?userNo=` | 依目前伺服器時間核對 area department、AreaOperator、UserShift From/To；回傳 eligible、departmentNo、shiftNos（依來源順序）。若 user 已登入，回傳 active area/dept/shift 供阻止重複登入或允許同區登出。須處理跨日班別，這是新 API 對 Oracle Core 時段查詢缺口的明確修正。 |
| GET | `/api/wip/areas/{areaNo}/operators/filter-options?departmentNo=` | 供 State/History 的 `...` lookup 使用。回傳該部門已核准班別（含 ShiftNo、ShiftName、FromTime、ToTime）及已核准使用者（UserNo、UserName）；對應 WinForms `LoadShiftBasis(IssueState=2)` / `LoadUserSecurity(IssueState=2)`，不可只回 AreaOperator 當前排班成員。 |
| POST | `/api/wip/areas/{areaNo}/operators/login` | 接受 departmentNo、shiftNo、userNo、loginComment。伺服器重查有效班別及 operator assignment；transaction 插入 Current 狀態，時間由伺服器產生。UserNo 主鍵競爭回 409，不能同時在兩區登入。 |
| POST | `/api/wip/areas/{areaNo}/operators/logout` | 接受 userNo、logoutComment。伺服器鎖定該 UserNo 的 Current row、核對 AreaNo，再由 `TBLSMDAREASHIFT.ExceptionTime` 取得政策值；transaction 刪除 Current 並新增完整 History，時間由伺服器產生。缺少/不符登入狀態回 409。 |
| GET | `/api/wip/areas/{areaNo}/operators/current` | State 查詢：固定 AreaNo/DepartmentNo；可選 shiftNo、userNo、startDate、endDate。承接 WinForms 嚴格 `>` / `<` 日期界值，安全分頁與穩定排序。 |
| GET | `/api/wip/areas/{areaNo}/operators/history` | History 查詢：可選 departmentNo、shiftNo、userNo、loginStartDate、loginEndDate、logoutStartDate、logoutEndDate、exceptionTime；安全分頁、穩定排序。 |

登出需保證 Current 刪除和 History 新增原子性。歷史表來源沒有 PK；如 YMES API 需要識別回傳列，使用 response-local id 或獨立應用識別方案，不能把猜測的欄位變成資料庫唯一約束。

## 未遷移事項與邊界

- WP307 DEV 畫布重用 SD108；登入候選用 localStorage 的班別/人員假資料，班別時段用日/夜班樣例，正式端須依 `TBLUSRSHIFTBASIS` 的實際欄位和跨日規則查詢。
- 目前狀態與歷史使用共用資訊表格彈窗，State 的 Start/End 時間核取篩選、History 的 Filter/DateFilter tabs 與四個獨立登入/登出日期界線均已按 WinForms 規格提供；尚未逐像素比對 AddFlow 背景圖與 Infragistics Grid。
- 本功能沒有 WIP API 或 YMES migration 實作；資料庫 reference 為家用端建置依據。公司端不連 YMES PostgreSQL，不讀 Oracle 業務列。

## 正式模式保護（家用端整合）

在 `workAreaMode=true` 且非 DEV 假資料模式時，顯示「正式環境尚未開放此功能。」，停用 Base Area、WIP 人員／排班／資訊載入與 Login／Logout／Query／lookup，不呼叫未交付 provider、不讀寫 DEV localStorage。Grid／縮放只影響本頁顯示，Close 仍可使用。

保護條件只限新增的 WP307 work-area mode；共用元件原有 SD108 mode、既有 IMESTECH 顯示條件與 DEV 互動不變。相對路徑的 WIP 404 分類已修正。這不代表 WIP 人員服務已完成；完整建置與正式瀏覽器驗收另以實際發行紀錄為準。
