# WP403 外包回貨

- FunctionNo 為 `OS RETURN`，路由為 `/YMES/WIP/OutsourceReturn`。核對 `STD/MESWin/WIP/WP_OSUnReturn/frmWIPOSUnReturn.vb` 及 `frmWIPOSReturnLot.vb` 的 Form／Designer、`wsWIP.ExeOS_Return`、`kcWIP.clsLot.ExeOS_Return`。
- 主檔固定查 Status=1／10，原碼已註解 OSType 限制。除站、外包商、單號、建立人員及建立日外，可依出貨日查詢。選單後顯示明細。回貨窗可多選待回貨批，已回貨明細 Status=10 不可再選。欄位包括 InputQty、GoodQty、ScrapQty、OtherQty、UnitPrice、ReturnUnitNo。OtherQty = InputQty − GoodQty − ScrapQty。需有可操作 LotState，量與單價不可缺或為負。
- WinForms 的 Component 按鈕另讀元件狀態，服務接收回貨批與元件資料。Core 寫 OS Detail、可能寫 OS Detail Component、Lot／ComponentState、批流程、報廢庫及成本資源。部分回貨主檔為 10，全回貨為 11，並累加價格及於全回貨保存結案日期。
- 依 WFERPOutSouring 與 active ERP，回貨還可能走 E10ICD／TIPTOPICD 收料及 ERP 收貨識別，保留 ERP 與 MES 雙方結果及對帳。

## Oracle 與家用端交易

- PowerShell 5.1 + ODP.NET 唯讀取得 [原 Oracle DDL](../../../database/reference/mestest_wip_wp403_source_ddl.sql) 與索引，提供 [PostgreSQL CREATE-only](../../../database/reference/mestest_wip_wp403_create.sql)。`TBLWIPOSDETAIL_COMPONENT` 主鍵為 (OSNO, LOTNO, COMPONENTNO)，`TBLWIPCONT_RESOURCE` 主鍵為 (LOGGROUPSERIAL, RESITEM, EVENTTIME, USERNO)。
- 主檔與一般明細沿用 [WP401](外包單開立.md)，ERP 設定沿用 [WP402](外包單確認.md)。報廢庫、批狀態和流程等共用 references 依各站點分支再核對 live schema。
- 建議登入且具 WP403 的 `POST /api/wip/outsource-orders/{osNo}/receipts`。伺服器依輸入的多個批重查狀態、版本、計量及元件，核對數量守恆。主檔、明細、批、庫房與成本資料採一致鎖順序及原子交易。ERP 用具冪等鍵的 provider，兩邊中途單側完成時需補償、對帳或人工續作。

## DEV

- 沿 WP401／402 的本機資料，先確認外包單再回貨。採同單位直接做差、四位小數示範，單價與數量校驗後將所選批標記已回貨。可重開處理剩餘批，全部回貨後自待處理清單移除。
- 尚未在 DEV 展開元件回貨子窗、價格累加和結案時間展示、庫存／資源成本／ERP、流程轉站。這些正規業務資料由家用端接入。
