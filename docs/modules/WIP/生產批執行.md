## WinForms 畫面與操作

Form 以最大化批次操作畫面呈現，上方是執行區，中段是查詢條件與 Lot State Grid，下方為執行／關閉操作。

### Execute 區

- Employee No 必填，從登入者帶入但可修改；成功流程結束後清空。
- Password 只有系統參數 WIPChkPassword=1 時顯示並驗證。
- Lot No、Component No 為常用輸入；Carrier No 只在 AllowExecLotByCarrier=1 時顯示。
- Batch Serial 僅 Enterprise 為 SAMPLE 時顯示。掃描欄位 Enter 與 Execute 按鈕皆可啟動。
- 輸入優先序是 Lot No → Carrier No → Component No → Batch Serial。Carrier 對應多批時，先選執行中批次，再選 Queue，最後按載具位置；Component 的批次元件另走 Batch Check-In/Out 分支。

### 查詢條件

- Area No、PS No、OP No、Lot No、MO No；前四項各有查找按鈕，MO 使用已核准且 MOState=3 的工單。
- Query 至少要有一個條件；Clear 清空查詢欄位與 Execute 的 Lot No 輸入。
- 查詢呼叫 wsWIP.LoadLotBasisJoinState，條件包含 Status=0|1|2|3|4|5、LotState=1 及使用者輸入的篩選；排序 HotLot desc, Priority, LotNo。
- Area 查找 tblSMDAreaBasis，限制 AreaClass=0、IssueState=2；PS 查找 tblPRSProductionSegment、IssueState=2；OP 可依 PS 篩選；MO 查找 tblOEMOBasis、IssueState=2、MOState=3。

### Lot State Grid

依原始 Grid 欄位次序：

LotNo, MONO, HotLot, Priority, Status, ProductNo, ProductName, CustomerName, ProductVersion, AreaNo, PSNo, ProcessNo, OPNo, OPName, BRNo, CurQTY, CurUnitNo, SysQTY, SysUnitNo, OPGroupNo。

- 單擊 Grid 列會將該列 LotNo 帶入 Execute 的 Lot No；雙擊亦帶入並聚焦該欄。
- LotNo、MONO 欄有連結式按鈕，可開 Lot／MO 明細；WinForms 的 Lot detail、MO detail 是原有子視窗，DEV 目前以精簡明細視窗代替。
- Status 值：0 Queue、1 Running、2 Wait、3 Hold、4 Complete、5 OS。特殊狀態 11 Inventory、12 Scrap、31 Hold Bank、99 Closed 由執行 Service/Core 分支處理，不列在這張 Grid 的 0–5 查詢中。

## 執行流程與規則

1. Employee No 必填；WIPChkPassword=1 時先驗證使用者密碼。依欄位優先序解析 Lot；Carrier／Component／Batch Serial 先載入對應批次，Component 對應批次識別時可轉入 RunBatchCo。
2. 執行前做 client/server MES 版本一致檢查、LMS 檢查與 QTime 批次比較。QTime 會比較剩餘分鐘，必要時開 Lot QTime 選擇窗；部分舊版程式將 QTime 查詢例外 catch 後略過，正式 API 應明確回傳依賴失敗，不能靜默跳過。
3. 呼叫 wsWIP.ExecuteLot，由 Service/Core 檢查 AllowExecuteLot、員工有效性、批次狀態、NetFlow／Wait／Hold／庫存／結案／Hold Bank／Scrap／OS 等條件；狀態 4 還會進入 TransferLot 相關流程。
4. 成功回傳仍可能包含 hold_exceedtime、futurehold、futurewait、futureos、stopflag。前兩項會建立 ERF；Future Wait 顯示等待訊息；Future OS 導引至臨時外包；StopFlag 中止後續轉站。
5. 回傳 Lot State 若為 Complete 且 LinkName=HOLD，畫面會執行異常單補開／修復。Queue 且有多個未執行 Group OP 時先讓使用者選 OP，必要時以 LotStamp 更新目前 OP。
6. 再依 Business Rule 的 Run Method 分 Automatic／Manual。Automatic 由 Core 執行 TriggerOP、BR、TransferLot 等自動流程；Manual 依 BRNo 動態載入個別 BR DLL／Form，可能包含參數、設備、元件、QC／SPC、檢驗略過等分支。完成後重新查詢原條件，選取執行批次並清空輸入欄。

Service/Core 會檢查並改寫多張 WIP、MO、物料、流程、設備、SPC/QC、Lot Property、Component、Future Hold/Wait/OS、庫存與紀錄表。TriggerOP 是通用動態流程入口；其表集合會隨 BR、OP 屬性、產品、設備和工廠整合變化，不能只用一個固定 CRUD API 取代。

## 資料表與 Oracle DDL

主要畫面資料由 TBLWIPLOTSTATE、TBLWIPLOTBASIS、TBLWIPERFBASIS、TBLOPBASIS 組合；執行及狀態分支另涉及 QTime、異常等待、產品／流程／Business Rule、設備、QC/SPC、Component、MO 材料及庫存等共用資料。

- database/reference/mestest_wip_wp201_dependency_source_ddl.sql：TriggerOP 與主要動態分支的 25 張表 Oracle DDL。
- database/reference/mestest_wip_wp201_additional_source_ddl.sql：Wait／Scrap／FGD／Semi inventory 分支的 4 張表 Oracle DDL。
- database/reference/mestest_wip_wp201_unresolved_source_ddl.sql：其他 10 張查證到的 MESTEST 表 DDL；檔尾記錄無法解析的程式引用。
- database/reference/mestest_wip_wp201_create.sql：39 張 Oracle 表轉換出的 PostgreSQL CREATE-only 參考。39 張表的欄位數已逐表比對 Oracle ALL_TAB_COLUMNS；簡單預設值、PK 與 Unique Key 已轉換。
- CREATE-only 未轉換 Oracle Foreign Key／Check Constraint／secondary index／tablespace／storage；不可直接當正式 migration，也不可整份套用取代 YMES live schema。家用端先逐表比對 migration 與現況，缺少的才新增 forward migration。
- TBLQTIMELOT 是程式建立的 DataTable 別名，不是 MESTEST 實體表。
- 2026-11-19 直查 ALL_OBJECTS 與 ALL_SYNONYMS，TBLWIPECNLOTBASIS 與 VIEW_TBLWIPPACK_LOT 在 MESTEST/PUBLIC 均無物件或 synonym；沒有可提供的來源 DDL。要先確認實際客製 schema／替代物件，不能臆造 CREATE SQL。
- 查詢僅讀 Oracle metadata 與 DDL，沒有讀業務資料列、沒有在 Oracle 執行 DDL/DML、沒有輸出連線秘密。

## 家用端 API／Schema handoff

- 先比對 YMES PostgreSQL live schema 和 migration；39 張 CREATE-only 是來源參考，不代表要新增 39 張表。沿用 OE、WIP、PRS、EQP、QC、SPC、INV 已有共用表。
- 建議 read-only Lot 查詢與執行命令分離；執行須用 POST，不可用 GET 觸發生產狀態修改。查詢條件需限制至少一項，並套用 LotState/Status 規則及 server-side 權限。
- 執行 API 不可信任前端提交的 Lot Status、BRNo、OP、Employee 有效性、是否可跳過等狀態；後端須重新讀取鎖定批次並以 LotStamp／條件式更新處理併發。
- 將 ExecuteLot、TriggerOP／BR、TransferLot 的多步驟結果建模為明確命令結果，區分成功、Future Hold／Wait／OS、StopFlag、ERF 建立、SPC／QC 阻擋及部分成功；提供 request idempotency 與可追蹤的 operation log。
- Password 不寫 query string、log 或 localStorage；若 WIPChkPassword 保留，後端要驗證登入者／密碼並設速率限制。正式 UI 使用 server authenticated identity，不使用 DEV 的 EmployeeNo 假資料。
- 動態 BR／設備表單、QTime/LMS、OP Group、元件批次流程及客製物件缺口需先逐項決定 YMES 的 server implementation；缺少客製來源時應回傳明確 unsupported，不要假裝流程已完成。
