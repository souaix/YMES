# WP902 刪除已下線生產批

- FunctionNo 為 `DELETE RELEASED LOT`，對應 `STD/MESWin/WIP/WP_DelReleasedLot/frmDELReleasedLot.vb` 和內嵌 Designer。取批與輸入 Enter 都查 `wsWIP.LoadLotBasisJoinState`，條件 LotState=1、Status 0／1／4，可帶 LotNo。ReleaseOnly 勾選框隱藏，相關 AreaNo 過濾已註解。
- 批次 Grid 顯示 LotNo、OPNo/OPName、狀態、BRNo、數量/單位、BaseLotNo/OrgLotNo、急件/優先序、訂單/項次/客戶、工單、產品/版本、客戶批號、DeviceNo、WIPDate。次 Grid 讀 `wsWIP.LoadReverseHistory` 並顯示 ID、類型、站、批序號、提交狀態、說明、建立人與日期。
- Enter 查詢先用 `CheckLotPackage`。刪除經確認並比對目前批號與歷程；有歷程時傳 ReverseId=1，無歷程只送 LotNo，成功清資料。舊選批路徑未執行和 Enter 相同的包裝預檢，正式執行應在伺服器統一守門。
- `STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs::DelReleasedLot` 取原工單供 EventLog，對有回復請求的批檢查存在與未關結。服務呼叫 `STD/MESud/udReverse/clsReverse.cs::DeleteReleasedLot`，強制檢查分併批來源並記釋放稽核類型 7。
- Core 視 ReverseId 先執行 STD 回復，再依分支取消元件 Booking／Release、回補/卸除庫存與儲位、清流程和批狀態、載具、暫存及報工批紀錄，記錄用料返還。在沒有其他相同 BaseLotNo 批時刪除 LotBasis 並回補 MO 未下線量。庫位出庫分支另有狀態例外 1／11／12／99；該條件不是一律禁止刪除。舊程式註記重複上線批可能重算 UnReleaseQty，正式端需核對來源交易防重。

## DEV 與家用端

- 頁面 `/YMES/WIP/ReleasedLotDelete` 以輸入或候選批查詢，展示兩個 Grid、確認和清除結果。DEV-DEL001/002 分別展示無／有回復歷程，DEV-DEL003/004/005 展示包裝、分批與已提交。以記憶體移除假資料演示，重載重置。未模擬正式工單數量、元件用料、儲位、載具及 Replay。
- 建議有 WP902 ACL 的 `GET /api/wip/released-lots`、`GET /api/wip/released-lots/{lotNo}/delete-preview` 和 `POST /api/wip/released-lots/{lotNo}/delete`。預覽回傳批、歷程與版本，提交接受 lotStamp、選中的預覽版本與冪等鍵；伺服器重查包裝、狀態、分併批、CommitState 及受影響工單、物料、庫位和載具。
- 將回復及刪除做成受控交易，故障可對帳、可防重，勿於回復完成但刪除失敗後靜默重跑。維護元件、用料與工單数量守恆及稽核，特別核對舊載具按 CarrierNo 刪除的範圍。ReverseUpdateContent 只作來源證據或相容儲存，勿執行資料欄內任意 SQL。
- 批／元件及分併批沿用 [WP101](../../../database/reference/mestest_wip_wp101_create.sql)、[WP209](../../../database/reference/mestest_wip_wp209_create.sql)、[WP213](../../../database/reference/mestest_wip_wp213_create.sql)，回復沿用 [WP901](回復處理.md)。五張新增參考為 StockerDetailLog、OpGroupState、ReverseUpdateContent、MaterialDeductContent、MTLDeductCont_Comp。MESTEST [欄位、PK、索引](../../../database/reference/mestest_wip_wp902_metadata.txt) 與 [PG CREATE-only](../../../database/reference/mestest_wip_wp902_create.sql) 已整理，defaults 尚未比對。家用端逐分支確認剩餘既有 DDL 及 live schema。
