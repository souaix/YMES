## 清單畫面與條件

主視窗標題為 Lot Basis Create。WinForms 提供工單選擇／查找、簽核狀態篩選、批號查詢及新增、修改、刪除、複製、下線、關閉操作。清單只載入所選工單且 LOTSTATE=0 的批次。

可供選擇的工單需符合 MOState 為 3 或 6，且未下線量大於 0，或該工單仍有 LOTSTATE=0 的既有生產批。這讓使用者能繼續維護已開過批、但工單未下線量已用完的情況。新增仍必須有正的未下線量。清單的 IssueState 與在製批次 LOTSTATE 是兩個不同狀態欄位，不可合併。

批號查詢可依清單搜尋條件篩選；選取工單後才查該工單的待下線批次。WinForms 支援多選刪除及下線：逐筆處理，第一筆錯誤即停止；此前成功的批次不會被 UI 回報成整批回滾。

## 生產批定義窗

定義窗分為基本資料及三個頁籤。基本欄位包括批號、回廠單號、工單類別、工單／訂單與項次、產品及版次、工程編號及版次、客戶及客戶批號、投入量與單位、Hot Lot、優先序、說明與建立／修改稽核資料。部分欄位由所選工單帶入或唯讀。

- 流程：流程選取、流程順序、生產區段／製程編號與版本；可調整流程，且同一 PSOrder 最多選一筆。另有略過作業站清單。
- 元件：依工單／流程元件資料選取，可依條件篩選、TopN、全選／全不選；首個選取流程含元件時，所選元件筆數須符合投入量規則。
- Lot Property：顯示使用者輸入與系統屬性；依 TBLSYSLOTPROPERTYBASIS 的資料型別檢查值。TableType=0 的批次屬性寫入批次屬性表；TableType=1 的其他資料表更新延至下線階段。
- 操作模式：新增／修改／複製。複製會建立新批號並帶入可複製明細。確定保存並關閉；套用保存後留在定義窗。正式批號自動編碼依 SYS LOTNO 序號規則處理。

### 驗證

必填 RO No、Item No、MO No、Product No、Product Version、正數 Input Qty、Unit No、Priority；Priority 為 0–99。至少要選一個流程，同一流程順序不可選多個流程。首個選取流程有元件時，選取元件筆數需等於整數投入量。新增／複製需要合法且不重複的批號。屬性值依其 metadata DataType 驗證。

## 資料與來源寫入

新增／修改由 wsWIP.AddLotBasis／EditLotBasis 呼叫 clsLot 的 ArrayBinding 寫入。主要資料範圍如下：

| 表 | 用途 |
| --- | --- |
| TBLWIPLOTBASIS | 生產批基本資料 |
| TBLWIPLOTSTATE | 新批次起始站點狀態（新增時） |
| TBLWIPLOTPROCESS | 批次流程 |
| TBLWIPLOTNOTEXECUTEOP | 略過作業站 |
| TBLWIPCOMPONENTSTATE | 批次元件選取／狀態 |
| TBLWIPLOTPROPERTY_RECIVE | 批次屬性輸入暫存／接收資料 |
| TBLWIPLOTPROPERTY | 系統批次屬性 |
| TBLOEMOCOMPONENT.BookingFlag | 工單元件預約旗標，跨模組共用資料 |

Lot Property 的目標 table／column 由 TBLSYSLOTPROPERTYBASIS 的 TableType、TransferType、TableName、FieldName metadata 決定。正式 API 不可把 metadata 直接拼成任意 SQL；需做允許清單與欄位白名單，並把相關寫入放在同一交易。

刪除不是直接刪主表。Core 先取得批次 WIP 狀態，逐一呼叫 CloseLot（事件代碼 200），再清除接收屬性及批次主檔。API 必須保留 CloseLot 的狀態／關聯清理語意，並定義每一批次單獨的交易及失敗回報。

## 下線交易與並發要求

SetLotBasisLotState 由 0 轉 1 前呼叫 ChkLotBasisConfirm：重新確認工單未下線量足夠，並阻擋批次元件與已發放工單元件的衝突。成功路徑會設定工單元件用料旗標、扣除物料、StartLot 建立起始狀態、更新批次下線狀態及 WIPDate、處理其他資料表屬性；若工單未下線量歸零會清理委外庫存資料，並扣減工單數量及更新元件 Release 狀態。ECN 更新受版本設定影響。

下線後可能繼續自動 BR／OP／Phase／ExecuteBR／TransferLot。來源對自動企業邏輯段落採用錯誤捕捉，生產批已建立後的自動邏輯失敗不應誤報成所有前置寫入都已回滾。多筆下線為逐筆處理，遇錯停止，之前成功的列保留成功。

YMES API 建議每個批次各自交易；在交易內鎖定／重新讀取工單未下線量、批次狀態及元件預約，再以條件更新及影響筆數保護競態。每筆下線結果分別回報，禁止以讀取後無鎖的 qty 檢查避免超量開立。需要將可能失敗但不回滾的自動企業邏輯另訂提交後工作／錯誤紀錄策略。

## Oracle DDL 與 CREATE-only 參考

- Oracle 原始 DDL：database/reference/mestest_wip_wp101_source_ddl.sql
- PostgreSQL 空結構參考：database/reference/mestest_wip_wp101_create.sql
- 本次唯讀查得 7 張專屬 WIP 表；合計 30 個 Oracle 欄位 default、6 個主鍵、9 個非 PK 索引。TBLWIPLOTNOTEXECUTEOP 沒有 PK／索引。資料字典未發現這七張表的外鍵或 trigger。
- TBLWIPLOTBASIS 以 BASELOTNO 為 PK；TBLWIPLOTSTATE PK 為 (LOTNO, OPNO, STATUS)；TBLWIPCOMPONENTSTATE PK 為 (LOTNO, COMPONENTNO)；TBLWIPLOTPROCESS PK 為 (LOTNO, PROCESSORDER)；RECIVE 屬性 PK 為 (BASELOTNO, PROPERTYNO)；LOTPROPERTY PK 為 (LOTNO, PROPERTYNO)。
- CREATE-only 是空表結構參考。家用端先核對 YMES live schema、migration 與既有資料，只為確定缺少的物件新增 forward migration；不可重建或覆蓋共用表。工單、產品、流程、元件及 SYS 屬性 metadata 都是共用表，不在這兩份 WIP DDL 內另行建立。

## Vue DEV 實作狀態與邊界

頁面使用明確隔離的 localStorage key ymes.dev.wp101-lot-basis.v1，假資料均以 DEV 標記。已提供清單篩選、工單選擇器、新增／修改／複製、刪除確認、下線確認，以及基本資料、流程、元件、略過 OP、Lot Property 頁籤和欄位驗證。

此 DEV 頁沒有連 API／Oracle／PostgreSQL。它不模擬物料扣帳、StartLot 真正產生的流程狀態、CloseLot 關聯清理、metadata 動態目標表寫入、ECN、委外庫存或自動 BR／OP 執行；這些均由家用端正式 API 實作。批號序號目前以 DEV 手動輸入，不代表正式自動編碼。查詢條件及 demo MO 只用來演示，不作為真實工單條件來源。

## 家用端 API handoff

建議端點，實際命名依既有 YMES API 慣例：

- GET eligible manufacturing orders：工單狀態 3／6，未下線量大於 0 或仍有未下線批次。
- GET lot bases：依 MO、IssueState、LotState 與查詢條件分頁。
- POST lot bases：建立 lot basis、流程、元件、略過 OP、屬性與起始站資料；同步工單元件 booking。
- PUT lot bases/{baseLotNo}：交易內更新允許修改的批次與明細。
- DELETE lot bases/{baseLotNo}：檢查狀態，執行 CloseLot 等價清理，再移除批次屬性與主檔。
- POST lot bases/release：批次請求逐列處理，回傳每列成功／失敗與訊息；每列交易與下線競態保護獨立。

正式 API 還需重用 OE／PRD／PRS／OP／MTL／SMD／SYS 的正式 lookup 和序號來源，補上登入者 audit、權限、DataStamp 或等價 CAS、資料庫 constraint 與交易測試。發行前以 YMES 實際 DB 盤點來決定 migration；不得把 Oracle CREATE-only 檔直接整批執行。
