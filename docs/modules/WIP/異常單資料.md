# WP508 異常單資料（ERF BASIS）

## 來源與範圍

- WIP → 異常與等待 → 異常單資料，FunctionNo `ERF BASIS`、FunctionKey `WP508`、執行檔 `WP_ERFBasis.dll`，見 `docs/MES_MENU_FUNCTION_INVENTORY.md`。
- 主 WinForms `STD/MESWin/WIP/WP_ERFBasis/frmERFBasis.vb`（內嵌 Designer），Service `wsWIP.LoadERFBasisJoinLotBasis`、`wsWIP.Load8DBasisFactory`，Core `clsLot.LoadERFBasisJoinLotBasis`、`clsWIP.Load8DBasisFactory`。
- 此頁是**查詢/導覽**，沒有新增、修改、刪除 ERF 的主頁按鈕。`ERF Info` 實際以 `ObjectFileHandler.Execute("WP_ERFInformation", ERFBasis DataRow)` 開獨立只讀詳細資料表單；`8D` 依 QRSNo 轉開 `WP_8DMaintainDef` 或 `WP_8DBasis_Factory`，屬獨立 WP801 8D 工作流，不可把這頁當作 8D 全流程 CRUD。

## 查詢與 25 欄結果

原 Query 上半三列、下半兩列日期區。六個勾選文字欄：Lot No、OP No、Customer No、MClass No、Cur Group、ERF No。除 ERF No 外，OP/Customer/MClass/Cur Group 有 `...` 候選查找；Lot No `btnGet5` 在 Designer 設 `Visible=False`，原畫面不顯示。取消欄位勾選會清文字。Create Date 與 Release Date 各有勾選框及 From/To 日期時間。**至少一個有效條件**才呼叫 Service，以免無限制查詢。Form 固定 `ERFSource=0`，只取 WIP 異常單，不顯示 SPC/收料來源。可由外部傳 LotNo 開窗時自動勾該欄並立即查詢。Lot No 在 Core 以 `LIKE '%值%'` 比對：單批比 ERFBasis.LotNo，批次 ERF 則以 BatchLot 成員 LotNo 查；OP/Customer 於 batch 分支也比成員欄，其他條件比 ERFBasis。Core 對 batch／非 batch 兩路查詢做 `UNION ALL`，並左聯 LotBasis、LotState、Product、OP、Material、Vendor、Customer，得到顯示名稱、CustomerLotNo、Priority。正式 API 要保持 batch 成員查詢語義，但查詢與權限必須 server side、參數化、分頁；不可傳遞原 Core 的 SQL 字串。

Grid 固定 ERF No、Lot No 兩欄，總共依次顯示 **25 欄**：ERF No、Lot No、Product No、Product Name、Customer Lot No、Status、OPNo、CustomerNo、Customer Name、MClassNo、HoldDescription、CurGroupNo、DispDescription、RuleNo、CreateQty、Create Date、ERF Record Qty、CurQty、Release Qty、Release UserNo、Release Date、Cal Hold Time、Priority、BatchLot、QRSNo。`ERF Record Qty` 在 Form 無同名來源欄時由 `ScrapQty` 運算欄取得。`Cal Hold Time` 以建立至現在的分鐘數算，Status 12/21 則算至 ReleaseDate。狀態翻譯：0 Undisposition、1 Wait Disposition、2 Notice Customer and Wait Disposition、3 Waive、11 Wait Lot Disposition、12 Abort、21 Release、31 Hold Bank。Grid 只選 ActiveRow，右側上方 `ERF Info`、`8D`，右下 `Close (&X)`；底部狀態列顯示 UserNo、時間等。

## ERF Info 與 8D 分支

原 `WP_ERFInformation/frmERFInformation.vb` 的 ERFBasis 區含 ERFNo、LotNo、ProductNo、OPNo、CustomerNo、MClassNo、ERFType、RuleNo、CurGroupNo、ScrapQty、Creator/時間、說明；ERF Detail 五個分頁為 Create Hold Code、Hold Code Disposition、ERF Disposition、Lot Disposition、ERF Attach。詳細表單另呼叫 HoldReason、HoldReasonDisp、ERFDisposition、LotDisposition、ERF/OCAP 附件讀取 Service；正式移植要逐表按該獨立 Form 的查詢、欄位、附件授權及下載規則實作。

原 `8D` 按鈕：有 QRSNo 時先 `Load8DBasisFactory(QRSNo)`，無結果或 `IssueState=-1` 即不開窗；其他狀態以該 8D DataRow 開 `WP_8DMaintainDef`。沒有 QRSNo 時以目前 ERF DataRow 開 `WP_8DBasis_Factory` 建立；此流程會回寫 ERFBasis.QRSNo。主頁本身不直接建立 8D。公司端 DEV 僅保留入口並顯示關聯資訊/待接流程，沒有模擬 WP801 建立、簽核、維護或回寫；此簡化不得當成完成 8D 工作流。

## Oracle 結構與 PostgreSQL CREATE 交接

主查詢直接涉及 `TBLWIPERFBASIS`、`TBLWIPERFBATCHLOT`、`TBLWIPLOTBASIS`、`TBLWIPLOTSTATE`、`TBLPRDPRODUCTBASIS`、`TBLOPBASIS`、`TBLMTLMATERIALBASIS`、`TBLMTLMATERIALVENDOR`、`TBLENTCUSTOMERBASIS`；其 Oracle DDL/PG CREATE refs 均已在 QC409、WP101/WP201、WP501/WP503 與各主檔 reference。沒有必要重造這些表。8D 已連結分支直接讀 `TBLWIP8DBASIS_FACTORY`；公司端依受保護 profile 用 PowerShell 5.1/Oracle.ManagedDataAccess **唯讀**從 MESTEST 查 `DBMS_METADATA`、ALL_TAB_COLUMNS/CONSTRAINTS/INDEXES/TRIGGERS。新交付 `database/reference/mestest_wip_wp508_source_ddl.sql`、`mestest_wip_wp508_source_indexes.sql`、`mestest_wip_wp508_metadata.txt`，以及 PostgreSQL **CREATE-only** `mestest_wip_wp508_create.sql`：43 欄，PK `QRSNO`，沒有 FK/trigger，PK 隱含唯一索引。未查 Oracle 業務列，未執行 DDL/DML，未連 YMES PostgreSQL。8D 建立/維護還會使用其他表，不能因本批只交一張主表就推定完整 WP801 schema。

## 公司端 DEV 與家用端 API

Vue 頁 `/YMES/WIP/ErfBasis` 位於 `web/src/components/WipErfBasis.vue`。DEV 假資料提供一般、已解除、批次三種 ERF；可查六欄和兩段時間、batch member LotNo 包含搜尋、25 欄、狀態/耗時計算、ERF Info 五頁只讀摘要與 8D 入口說明。正式 non-DEV 不讀 fixture、不顯示假成功；公司端未執行 build/test/browser。ERF Info 五頁目前是**資料結構與操作預覽**，附件/處置 log 沒有真資料；完整 `WP_ERFInformation` 需另項移植。

家用端先比對 PostgreSQL live schema/history，缺項才 forward migration，不直接執行所有 CREATE-only。查詢 API 需登入與 WP508 Function ACL、至少一條件、上限/分頁、`ERFSource=0` 固定由 server 施加；Lot/OP/Customer 依 batch/member 規則，時間邊界與 StatusShow/ERFRecordQty/CalHoldTime 的語義同原窗。ERF Info 提供 ERFNo 精確查詢和五分頁資料/授權附件下載；8D 查詢依 QRSNo 鎖定、IssueState 判定，建立/維護/回寫交 WP801 API 並設 transaction/ACL，不由 browser 偽造 QRSNo 或 IssueState。API 完成後才接正式 Vue 並做資料量、批次查詢與跨模組驗收。
