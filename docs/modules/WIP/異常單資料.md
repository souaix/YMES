# WP508 異常單資料（ERF BASIS）

## 來源與範圍

- WIP → 異常與等待 → 異常單資料，FunctionNo `ERF BASIS`、FunctionKey `WP508`、執行檔 `WP_ERFBasis.dll`，見 `docs/MES_MENU_FUNCTION_INVENTORY.md`。
- 主 WinForms `STD/MESWin/WIP/WP_ERFBasis/frmERFBasis.vb`（內嵌 Designer），Service `wsWIP.LoadERFBasisJoinLotBasis`、`wsWIP.Load8DBasisFactory`，Core `clsLot.LoadERFBasisJoinLotBasis`、`clsWIP.Load8DBasisFactory`。
- 此頁是**查詢/導覽**，沒有新增、修改、刪除 ERF 的主頁按鈕。`ERF Info` 以 `ObjectFileHandler.Execute("WP_ERFInformation", ERFBasis DataRow)` 開獨立詳細資料表單；該表單的附件 Grid **可檢視及刪除部分附件**，因此不能稱為全頁只讀。`8D` 依 QRSNo 轉開 `WP_8DMaintainDef` 或 `WP_8DBasis_Factory`，屬獨立 WP801 8D 工作流。

## 查詢與 25 欄結果

原 Query 上半三列、下半兩列日期區。六個勾選文字欄：Lot No、OP No、Customer No、MClass No、Cur Group、ERF No。除 ERF No 外，OP/Customer/MClass/Cur Group 有 `...` 候選查找；Lot No `btnGet5` 在 Designer 設 `Visible=False`，原畫面不顯示。取消欄位勾選會清文字。Create Date 與 Release Date 各有勾選框及 From/To 日期時間。**至少一個有效條件**才呼叫 Service，以免無限制查詢。Form 固定 `ERFSource=0`，只取 WIP 異常單，不顯示 SPC/收料來源。可由外部傳 LotNo 開窗時自動勾該欄並立即查詢。Lot No 在 Core 以 `LIKE '%值%'` 比對：單批比 ERFBasis.LotNo，批次 ERF 則以 BatchLot 成員 LotNo 查；OP/Customer 於 batch 分支也比成員欄，其他條件比 ERFBasis。Core 對 batch／非 batch 兩路查詢做 `UNION ALL`，並左聯 LotBasis、LotState、Product、OP、Material、Vendor、Customer，得到顯示名稱、CustomerLotNo、Priority。正式 API 要保持 batch 成員查詢語義，但查詢與權限必須 server side、參數化、分頁；不可傳遞原 Core 的 SQL 字串。

Grid 固定 ERF No、Lot No 兩欄，總共依次顯示 **25 欄**：ERF No、Lot No、Product No、Product Name、Customer Lot No、Status、OPNo、CustomerNo、Customer Name、MClassNo、HoldDescription、CurGroupNo、DispDescription、RuleNo、CreateQty、Create Date、ERF Record Qty、CurQty、Release Qty、Release UserNo、Release Date、Cal Hold Time、Priority、BatchLot、QRSNo。`ERF Record Qty` 在 Form 無同名來源欄時由 `ScrapQty` 運算欄取得。`Cal Hold Time` 以建立至現在的分鐘數算，Status 12/21 則算至 ReleaseDate。狀態翻譯：0 Undisposition、1 Wait Disposition、2 Notice Customer and Wait Disposition、3 Waive、11 Wait Lot Disposition、12 Abort、21 Release、31 Hold Bank。Grid 只選 ActiveRow，右側上方 `ERF Info`、`8D`，右下 `Close (&X)`；底部狀態列顯示 UserNo、時間等。

## ERF Info 與 8D 分支

原 `WP_ERFInformation/frmERFInformation.vb` 的 ERFBasis 區含 ERFNo、LotNo、ProductNo、OPNo、CustomerNo、MClassNo、ERFType、RuleNo、CurGroupNo、ScrapQty、Creator/時間、說明；ERF Detail 五個分頁為 Create Hold Code、Hold Code Disposition、ERF Disposition、Lot Disposition、ERF Attach。表單載入 `LoadERFHoldReasonAndName`、`LoadERFHoldReasonDispAndName`、`LoadERFDisposition`、`LoadERFLotDispJoinNodeBasis`、`LoadERF_AttachFile`，原因資料第一筆有 OCAPNO 時再載 `LoadERFOCAP_AttachFile`。原因表以 Qty 顯示計算欄 `RECORDQTY`；Lot Disposition 以 `TBLWIPERFLOTDISPOSITION.NodeID` 左聯 `TBLPRSNODEBASIS`，帶出 OPNo、ProcessNo、ProcessVersion。正常 ERF Disposition Grid 顯示 DispOrder、GroupNo、DispDescription、ContactorName、NextDispType、NextGroupNo、Creator、CreateDate；有 OCAP 時欄位另有 OCAPNO、HoldItemNo、OCAPNodeNo、DispUserNo/DispDate 等分支，正式端須依資料組合選欄。

附件 Grid 的 `Attach File` 會讀 BLOB 檢視，`DelAttachFile` 會先確認，再依 ERF 或 OCAP 來源呼叫 `DelERF_AttachFile` / `DelERFOCAP_AttachFile`，成功後重載兩種附件。兩個 Grid 都會把檔名**不分大小寫包含 `CreateERFNo + "."`** 的異常單產生檔刪除鍵停用；按鈕 handler 也再次拒絕。另查 `wsWIP.DelERFOCAP_AttachFile`／`clsLot.DelERFOCAP_Attachfile` 發現舊呼叫只有 LotNo、ERFNo、AttachName，**沒有 OCAPNO**，Core DELETE 會命中同名的多個 OCAP 主鍵列；正式 API 必須強制使用完整 `(LOTNO, ERFNO, ATTACHNAME, OCAPNO)`，不可照搬舊刪除條件。server 還要重新核對來源、刪除權限及保護檔名，不能只信任前端 disable 或傳來的檔名。舊 WinForms 將 BLOB 寫進 `gAppPath\AttachName` 後 `Process.Start`；Web 改用授權的串流下載，清理 Content-Disposition 檔名，避免路徑注入，絕不把用戶端檔名拼接成伺服器本機路徑。

原 `8D` 按鈕：有 QRSNo 時先 `Load8DBasisFactory(QRSNo)`，無結果或 `IssueState=-1` 即不開窗；其他狀態以該 8D DataRow 開 `WP_8DMaintainDef`。沒有 QRSNo 時以目前 ERF DataRow 開 `WP_8DBasis_Factory` 建立；此流程會回寫 ERFBasis.QRSNo。主頁本身不直接建立 8D。公司端 DEV 僅保留入口並顯示關聯資訊/待接流程，沒有模擬 WP801 建立、簽核、維護或回寫；此簡化不得當成完成 8D 工作流。

## Oracle 結構與 PostgreSQL CREATE 交接

主查詢直接涉及 `TBLWIPERFBASIS`、`TBLWIPERFBATCHLOT`、`TBLWIPLOTBASIS`、`TBLWIPLOTSTATE`、`TBLPRDPRODUCTBASIS`、`TBLOPBASIS`、`TBLMTLMATERIALBASIS`、`TBLMTLMATERIALVENDOR`、`TBLENTCUSTOMERBASIS`；其 Oracle DDL/PG CREATE refs 均已在 QC409、WP101/WP201、WP501/WP503 與各主檔 reference。8D 已連結分支直接讀 `TBLWIP8DBASIS_FACTORY`；此前交付 `database/reference/mestest_wip_wp508_source_ddl.sql`、`mestest_wip_wp508_source_indexes.sql`、`mestest_wip_wp508_metadata.txt` 及 PG **CREATE-only** `mestest_wip_wp508_create.sql`：43 欄，PK `QRSNO`，沒有 FK/trigger。

補查 `WP_ERFInformation` 後發現 `TBLWIPERFLOTDISPOSITION` 尚無 source reference。公司端用受保護 profile、PowerShell 5.1/Oracle.ManagedDataAccess **唯讀**從 MESTEST 取得 `database/reference/mestest_wip_wp508info_source_ddl.sql`、`mestest_wip_wp508info_source_indexes.sql`、`mestest_wip_wp508info_metadata.txt`：16 欄，PK `(ERFNO, LOTDISPORDER)`、非唯一 `LOTSERIAL` 索引、無 trigger。PostgreSQL **CREATE-only** `mestest_wip_wp508info_create.sql` 包含此表與 OCAP 附件表。`TBLWIPERFOCAP_ATTACHFILE` 的 Oracle source 已在 `mestest_qc409_wip_disposition_dependencies_source_ddl.sql`，但先前沒有 PG CREATE；其主鍵 `(LOTNO, ERFNO, ATTACHNAME, OCAPNO)`。一般 `TBLWIPERF_ATTACHFILE` 的 PG CREATE 已在 WP501。`TBLPRSNODEBASIS` 沿用 PRS104 source/CREATE。未查 Oracle 業務列、未執行 Oracle DDL/DML、未連 YMES PostgreSQL；8D 建立/維護仍需另查 WP801 其他表。

## 公司端 DEV 與家用端 API

Vue 頁 `/YMES/WIP/ErfBasis` 位於 `web/src/components/WipErfBasis.vue`。DEV 假資料提供一般、已解除、批次三種 ERF；可查六欄和兩段時間、batch member LotNo 包含搜尋、25 欄、狀態/耗時計算。ERF Info 五頁顯示對應欄位的假處置列，以及 ERF/OCAP 假附件的 View、Delete；刪除需二次確認、保護異常單產生檔，只從記憶體假資料移除；View 不會產生真下載。8D 僅入口說明。正式 non-DEV 不讀 fixture、不顯示假成功；公司端未執行 build/test/browser。完整 `WP_ERFInformation` 的真資料、OCAP 差異與 BLOB API 仍由家用端實作。

家用端先比對 PostgreSQL live schema/history，缺項才 forward migration，不直接執行所有 CREATE-only。查詢 API 需登入與 WP508 Function ACL、至少一條件、上限/分頁、`ERFSource=0` 固定由 server 施加；Lot/OP/Customer 依 batch/member 規則，時間邊界與 StatusShow/ERFRecordQty/CalHoldTime 的語義同原窗。ERF Info 提供 ERFNo 精確查詢和五分頁資料；附件列表依 ERF/OCAP 分流。附件 View 用授權串流端點，Delete 用獨立端點，要求確認、刪除權限、重查完整複合鍵與保護檔名，記 actor/稽核，並以交易回報不存在/衝突；瀏覽器不可直接傳伺服器路徑。8D 查詢依 QRSNo 鎖定、IssueState 判定，建立/維護/回寫交 WP801 API 並設 transaction/ACL，不由 browser 偽造 QRSNo 或 IssueState。API 完成後才接正式 Vue 並做資料量、批次查詢與跨模組驗收。
