# WP629 在製品庫包裝作業（PACKING_MOLINE_INV）

## 功能定位

- 第一層：在製品管理。
- 第二層：包裝與庫房。
- 第三層：在製品庫包裝作業。
- Oracle 選單 FunctionNo：`PACKING_MOLINE_INV`；FunctionKey：`WP629`。
- WinForms Form：`frmBR_L_CO_Packing_MOLine_INV`；DLL：`BR_L_CO_Packing_MOLine_INV.dll`。
- Pack Config 對話窗：`frmMOLinePackConfig`，與 WP601 共用設定 Form。
- Vue DEV：`/YMES/WIP/PackingMOLineInv`，使用 WP601 共用包裝版面，但以獨立資料集、庫位欄位及 Status=11 驗證呈現本功能。

## 原始碼依據

- Form：`STD/MESWin/BR/BR_L_CO_Packing_MOLine_INV/frmBR_L_CO_Packing_MOLine_INV.vb`。
- Service：`Customer/Production/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `ExePacking`、`ExePacking_Close`、`ExePacking_Delete`、`LoadInvPackState`、`LoadWIPInventory_SEMI`。
- Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `ExePacking`、`ExePacking_Close`、`ExePacking_Delete`、`AddInvPackState`／`EditInvPackStateWithLevel`。
- 選單識別：[`MES_MENU_FUNCTION_INVENTORY.md`](../../MES_MENU_FUNCTION_INVENTORY.md)。

## 畫面與操作

主畫面沿用 WP601 的包裝站版型：上方 BarCode／批號資訊區；左側 Pack Set Content 與 Print Label；右側 Wait Close Box Content 與 Pack Accessory；底部 Pack Close、Combine、Unboxing、Delete、Pack Config 及 Close。WP629 的識別欄位顯示 `WIP INV NO`，不是 WP601 的 `OPNo`；掃描輸入仍為 LotNo 或包裝編號。Pack Config 依電腦設定工單、產線、包裝階層與印表機。

## WinForms 與 Core 業務規則

1. **Pack Config 必要**：先讀取本機電腦設定、產品包裝規則、有效階層與滿箱條件、配件及標籤規則。包裝階層可由 L1 至 L6；刷入品必須位於目前設定最小包裝階層的下一層，工單、產品、版本及包裝規則要吻合。
2. **單一 Lot 掃描**：Form 讀 `TBLWIPLOTSTATE`。本功能只接受 `Status=11` 的在製品庫批號；接著以 LotNo 查 `TBLINVWIPINVENTORY_SEMI`，取其 `InventoryNo` 顯示為 WIP INV NO。沒有庫存列即拒絕；同一包裝工作中的既有內容也必須在相同 InventoryNo。此查詢條件只有 LotNo，Core SQL 沒有 `ORDER BY`，Form 使用結果第 1 列；來源未定義同一 Lot 出現在多庫位時的確定選取順序。
3. **已包裝品掃描**：目前最小層級大於 L1 時，先查前一層 `TBLINVPACKSTATE`。被掃包裝必須已封箱、未被其他包裝使用，並展開其 From_PackingLevel=0 的所有 Lot；來源批號都要存在、仍為 Status=11，且屬於同一 InventoryNo。不得混入一般執行中的 Status=1 批號。
4. **成品入庫限制**：掃 Lot 或包裝前呼叫 `funCheckFGDIn`；已與成品入庫關聯的來源 Lot／包裝不得重複包裝、拆併。
5. **工單及庫位一致**：Form 讀取 MO、產品版本及包裝規則後，比對目前設定的 MO／階層。`funChkOPNo` 會找目前未封箱包裝中的批號；若發現一般 WP601 的 Status=1 批號，停用 Pack Close、Combine、Unboxing、Delete；若該批在不同 WIP InventoryNo，拒絕繼續包裝。
6. **數量與配件**：PackQty 不能超過可包數量及剩餘滿箱容量；有 Component 的批號不得沿用不允許的拆批路徑。L1 配件依產品包裝配件規則掃碼，全部 CheckFlag 完成後才執行包裝。滿箱箱數／數量達條件時，依 `Full Boxe Auto Closed` 設定自動封箱或詢問；手動 Pack Close 對選取層級以 `CloseFlag=2` 強制封箱。
7. **封箱／標籤**：不能越過未封箱的較低層級。封箱更新該層 `CloseFlag`、新增 `TBLINVPACKLOG` 並刷新現況。封箱成功後建立產品標籤資料並呼叫舊 Windows 標籤列印元件／印表機。
8. **在製品狀態**：Form 呼叫共用 `wsWIP.ExePacking`，明確傳 `InlinePackingFlag=1`。`clsLot.ExePacking` 在此分支要求 Status=11，從 `TBLINVWIPINVENTORY_SEMI` 取 InventoryNo，並以 InventoryNo 作包裝現況的 OPNo、NodeID=`N/A`；它寫入共用包裝階層、Detail、Relation、PackState／PackLog。共用 `ExePacking_Close` 最大層的完工轉態條件是 Lot `Status=1`；Status=11 批號不因 WP629 封箱變成 Status=4。
9. **Delete**：確認後依目前最小層級、包裝編號、批號／子包裝、PackQty 及是否移除最後一筆呼叫 `ExePacking_Delete`。Core 驗證層級 CloseFlag 與明細關係，再更新 Detail、Relation、PackState 和 PackLog；不能只從 Vue Grid 移除列。
10. **Combine／Unboxing**：主畫面分別呼叫 `ObjectFileHandler.Execute("INVMOPackingCombineDismantle", ...)`，`intTbgIndex=1` 為 Combine、`0` 為 Unboxing。這是外掛功能，外掛交易及完整 Core 副作用需依取得的契約實作，不能當作普通 CRUD。

## 資料表與 Oracle DDL

WP629 **沒有新增專屬表**，沿用 WP601 已查證的 L1–L6 包裝主檔／Detail、`TBLWIPMOLINEPACKRELATION`、`TBLINVPACKSTATE`、`TBLINVPACKLOG` 等共用包裝結構；另讀取既有 `TBLWIPLOTSTATE` 與 `TBLINVWIPINVENTORY_SEMI`。不可為 WP629 複製一套包裝表，也不可把動態前綴 `TBLWIPMOLINEPACKL` 當成單一 Oracle 物件。

- 包裝表 Oracle DDL、index／constraint 查證與 PostgreSQL CREATE-only 參考：[`WP601 包裝作業規格`](包裝作業.md) 及 `database/reference/mestest_wip_wp601_source_ddl.sql`、`mestest_wip_wp601_create.sql`。
- `TBLINVWIPINVENTORY_SEMI` Oracle DDL 已由 WP201 依賴查證：`database/reference/mestest_wip_wp201_dependency_source_ddl.sql`；既有 PostgreSQL CREATE-only 參考：`database/reference/mestest_wip_wp201_create.sql`。來源 PK 為 `(INVENTORYNO, LOTNO, LOCATORNO)`；`INVENTORYNO` 20 字元、LotNo 50 字元、LocatorNo 20 字元，Qty `NUMBER(14,6)`。不要另建 WP629 專用 CREATE SQL。
- `TBLWIPLOTSTATE` 與產品、MO、包裝／序號／配件／標籤規則均沿用既有 WP101、WP601 及 PRD/OE schema references。

家用端須先對 YMES PostgreSQL live schema、migration、資料及 grants 核對上述共用表。只有 live schema 確認缺少物件時才加 forward migration；Oracle DDL／CREATE-only 是比對材料，不直接套用、不重建、不複製 MES 業務資料。Oracle 來源為本機受保護唯讀設定；未在 Oracle 執行 DDL/DML。

## 家用端 API 與交易交接

- 重用 WP601 包裝 domain service 與資料表，不另造 WP629 包裝 schema。由登入者權限決定 inventory inline 模式；不得接受瀏覽器提交 `InlinePackingFlag`、可信任狀態、InventoryNo 或任意表名。
- 每次 Pack command 在交易內重查 Lot State=11、Inventory Semi row、MO/Product/Version、已包數量、Component、包裝關係／CloseFlag、容量與配件；每個包裝中的 Lot 必須同 InventoryNo，並與目前未封箱工作一致。InventoryNo 必須由服務端查得。
- `TBLINVWIPINVENTORY_SEMI` 的 PK 含 LocatorNo，同一 Lot 可有多筆庫位列；舊 Core 依 LotNo 查詢卻沒有排序，WinForms 取第一列。遇到多筆有效庫位要明確記錄為來源未定義，不可默默假設唯一或靠不穩定的 DB 回傳順序選庫位；正式 API 需以可稽核的唯一列／使用者明確選擇解決，待業務規則確認後再開放該情境。
- 保留 `TBLINVWIPINVENTORY_SEMI` 原庫存與 Lot Status=11；只依 Core 完成包裝資料、關係、PackState／Log。不得仿 WP601 將 Status=1 推到 4，也不應額外扣／轉 WIP 庫存，除非另有已證明的來源交易契約。
- Pack Close 保留 CloseFlag=1 自動、2 強制及內層先封規則；最高層封箱不改 Status=11。Delete／Combine／Unboxing 與 PackState／Log 的關聯更新需交易一致，並防止並發重複掃描／超量。
- 標籤仍需正式 label data、範本、列印工作及授權列印代理設計；不能在 API 伺服器上直接呼叫 WinForms COM。Combine／Unboxing 外掛契約未確認前，正式 API 應明確標示尚未支援，不可回成功假資料。
