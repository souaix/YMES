## 畫面與操作

- EmployeeNo 是可選的查詢篩選；輸入後 Form 嘗試讀取姓名／班別資料，但 `PasswordControl` 內讀取 `WIPChkPassword` 的程式目前註解掉，密碼列預設隱藏。員工欄位不作為 API 操作者身份，稽核操作者仍應取登入 session。
- Query Condition 有 LotStatus（預設 Running=1）、Clock Status（預設 Clocked In=1 且不可修改）、PSNo、OPNo lookup 與 Query。Form_Load 不自動查詢。
- Grid 欄序同批次上工，CheckFlag 初始全選。手動勾選／取消一列時，來源會同步切換相同 UserNo + LoginPlaceNo 的列。底部按鈕為 Clock Out、Close；Query 成功後 Clock Out 啟用。來源沒有下工前確認視窗。
- DEV 使用 WP104/WP105 共用 OperatorState／OperatorLog localStorage 與固定假 Lot；只示範篩選、同員工地點同步勾選、批次去重與假下工，不呼叫正式 API。

## 查詢與下工規則

1. Query 可選擇傳入 EmployeeNo 作 UserNo 篩選，另傳 LotStatus、ClockStatus、PSNo、OPNo。ClockStatus 固定為 1，因此只查 `LoginPlaceNo IS NOT NULL` 的已上工狀態；Core 仍以 Lot/OP 的 MultiOperatorMode、PartialMode、Area/Equipment/Group 與 TempEquipment mapping 組合候選列。結果按 PSNo、OPNo、LotNo 排序，CheckFlag 預設 True。
2. 勾選狀態以 UserNo + LoginPlaceNo 同步整批 Lot rows。送出前 Form 以選取列去重，根據 OP Basis 讀 MultiOperatorMode，轉成 UserNo、OPNo、LoginPlaceNo、Mode 批次資料。來源的去重條件是 UserNo + LoginPlaceNo；同一使用者／地點若掛在不同 OP 或 mode，可能只保留先遇到列的 mode，正式 API 應記錄此相容性差異並以 server 現況鍵避免誤下工。
3. Service 一次呼叫 `ExecuteClockOut_Batch`，傳登入操作者、AP Server LogoutDate 與彙整後資料。Core 對每組 operator/place/mode 寫入 OperatorLog、移除 OperatorState；多人加工啟用時由 `funSHR_CO_EMP_ClockOut` 同步 LotLoginState checkout side effects。批次成功後 Form 重設全部條件與 Grid。

## 資料表與家用端 API handoff

- 不新增 Oracle table。OperatorState／OperatorLog DDL 與 CREATE-only 沿用 WP104；LotLoginState 沿用 WP305。LotState、OP、Area、Equipment、Group、TempEquipment、User/Shift 等沿用共用 references。
- `GET /api/wip/lot-operator-clock-outs/lots` 需登入授權、參數化、分頁並依 Core mapping 查詢；固定 `ClockStatus=1`，EmployeeNo 若傳入只作允許範圍內的篩選。不要因 UI 可輸入任意 EmployeeNo 就開放查全廠人員狀態。
- `POST /api/wip/lot-operator-clock-outs` 只接選取 LotNo/key；server 重新查詢每列目前 OperatorState、OP mode/place 和權限，按使用者／地點安全彙整。LogoutDate 與 audit user 從 server session 產生；同一交易寫 Log、刪 State、同步 LotLoginState。加入冪等鍵、鎖與已下工／狀態競爭錯誤處理。
- 家用端先查 YMES PostgreSQL live schema/migrations；重用 WP104/WP305 refs，不重複 CREATE。公司端未連 PostgreSQL，未執行 Oracle DDL/DML、build、test 或 browser。
