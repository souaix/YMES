## 原始碼

- `REVERSE LOT` 對應 `Customer/Production/MESWin/WIP/WP_ReverseHistory_THEIL_BU1/frmReverseHistory.vb`，含內嵌 Designer。STD `wsWIP.LoadLotState` 查狀態 0、1、2、3、11、4 的候選批。Enter 或選取批號後呼叫 `LoadReverseHistory`，依 ReverseId 倒序顯示 ID／類型、OPNo、LotSerial、Description、Creator、CreateDate、CommitState 與 CommitDesc。
- 執行前比對輸入和載入的批號並要求確認。STD `CheckLotPackage` 呼叫 `kcWIP.clsLot`，跨分批關係查 `TBLINVPACKSTATE`。送入 LotNo、ReverseId、LotStamp、可空的 ReverseDescription 和 CreateDate。成功後保留較舊歷程，沒有較舊歷程時清畫面。
- `Customer/Production/wsTHEIL/wsWIP/wsWIP.cs::ExecuteReverse` 拒絕已關結批（99），記錄釋放稽核活動類型 8，委派 `Customer/Production/MEStc_THEIL/tcWIP/clsReverse.cs::ExecuteReverse`。Core 比對 CreateDate（如有）和 LotStamp。被回復歷程 CommitState=1 時拒絕；較新的分批、併批、批次關聯或改批號必須逐步回復。AllowReverseAlone 影響同站 LogGroupSerial 的回復邊界。
- Core 核對關聯批再按 ReverseType 倒序回放 LotState、Log、資源、庫存、異常／等待，登錄 ReverseLog 並清除對應 ReverseHistory／UnCommit。THEIL 報工分支以 LogGroupSerial 呼叫 `GetSAP_ZPPT0025x_Data(2, ...)` 準備 SAP 沖銷。

## 家用端 API 與 schema

- 建議有 WP901 ACL 的 `GET /api/wip/lot-reversals/lots`、`GET /api/wip/lot-reversals/{lotNo}/history` 及 `POST /api/wip/lot-reversals/{lotNo}/execute`。限制批次存取範圍。查詢回傳 LotStamp 和 CreateDate，執行接受 reverseId、lotStamp、createDate、reason 與冪等鍵。
- 鎖定並重讀受影響批、歷程及版本後，重新檢查狀態、包裝、關聯批、CommitState 及 LogGroupSerial。交易應處理跨批、逆向順序、稽核、SAP 重試與對帳。無法回放或未接齊 SAP 的分支應明確回應。將舊 Core 的 ConditionString 識別為資料契約，正式 API 避免將任意字串交由 SQL 執行。
- 主表沿用 [WP101 LotState](../../../database/reference/mestest_wip_wp101_create.sql)、[WP215 ReverseHistory](../../../database/reference/mestest_wip_wp215_create.sql)、[WP208 SYS Parameter](../../../database/reference/mestest_wip_wp208_create.sql)。[QC409 依賴](../../../database/reference/mestest_qc409_wip_disposition_dependencies_source_ddl.sql) 含 LotLog 原始 DDL。包裝與其他副作用表隨正式分支核對。
- 三張回復補表原始 DDL 兩次回 ORA-03135。已唯讀取得 [欄位、約束及索引 metadata](../../../database/reference/mestest_wip_wp901_metadata.txt) 並整理 [PostgreSQL CREATE-only](../../../database/reference/mestest_wip_wp901_create.sql)。ReverseLog 按 Oracle 保留 REVERSEDESCRIPTION 與 REVESEDESCRIPTION。補表未觀察到 PK／UK／FK，家用端比對 live schema、defaults 及文字長度語意。
