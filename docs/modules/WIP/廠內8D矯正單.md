- WIP → 8D 管理 → 廠內 8D 矯正單，FunctionNo `8D BASIS_FACTORY`、FunctionKey `WP801`、`WP_8DBasis_Factory.dll`，主表 `TBLWIP8DBASIS_FACTORY`。
- 主 WinForms `STD/MESWin/WIP/WP_8DBasis_Factory/frmWP8DBasisFactory.vb`；編輯表單 `frmWP8DBasisFactoryDef.vb`；Service `STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs`；Core `STD/MESkc/kcWIP/clsWIP.cs`、`STD/MESkc/kcBasis_UPD/clsBasis_UPD.cs`；流水號 `STD/MESkc/kcSYS/clsSYSEng.cs`。

## 主畫面

原窗上方共用查詢列：四個 IssueState `Unfrozen=0`、`Pending=1`、`Active=2`、`Unused=-1`；預設 0。搜尋欄只設 `QRSNo`。`LoadData` 將選定 IssueState 和可選 QRSNo 條件交 `wsWIP.Load8DBasisFactory`。Grid 依 `QRSNo` 升序、固定前兩欄，顯示 40 欄（QRSNo、QRSClass、QRSSummary 起，至 Creator/Createdate、Reviser/ReviseDate），完整順序見主 Form `iug8DBasisFactory_InitializeLayOut`；沒有在 Grid 直接編輯。右側 `ADD`、`EDIT`、`DEL`、`Copy`、`Approve`、`ERFINFO`，下方 `Close`。刪除與核准可多選，EDIT/Copy/ERFINFO 作用於 ActiveRow；Button 權限另受 `ExeGroupControlPriv`。

`EDIT` 限 `IssueState=0`。`Copy` 從所選列預填編輯表單，以新增方式取得新 QRSNo；來源表單可能保留 ERFNo，但僅從 ERF 資料列直接開建立表單時才送 `UpdateERFBasis=1`。`ERFINFO` 以 ERFNo 開 `WP_ERFInformation`；新的 Web 需先用 ERFNo 查主表，再開詳細頁，不能把 8D DataRow 直接當 ERF 資料。

## 編輯表單與建立交易

`QRSClass` 四選一：1 In Line QC、2 Off Line QC、3 WIPERF、4 Other。一般新增預設 Other/`CurStage=N/A`，預計結案日預設約七日後。當從 ERF 入口傳 `ERFBasis` DataRow 時，依 ERFSource/ERFType、屬性與計量 log 決定分類，從 LotState/工單/產品/設備/原因來源帶入 LotNo、ProductNo、OPNo、FactoryNo、AreaNo、CurQty、ScrapQty、SampleQty 等，除 HoldDescription 外，ERF 派生欄及分類不可手動改。已解除的 ERF 另以 ContLogGroupSerial 找回 Area/Factory/數量，找不到時用 N/A。QC 類的 SampleQty 取屬性或計量檢驗 log；WIP 類歸 0。正式 API 應由 server 查來源，不能相信 browser 預填值。

基本檢核：QRSClass、QRSNo、QRSSummary、FactoryNo、AreaNo、ProjectDepartment、ProjectManager、CurStage 不可空；LotQty/SampleQty/ErrorQty 空值改 0。建立/複製時若啟用自動流水號，表單先 `GetBasisFactoryQRSNo(False)` 預覽，送出前再比對最新並以 `True` 保留；來源規則是 `TBLSYSSERIALRULEBASIS/DETAIL` 的 `SERIALTYPE='8DNO_FACTORY'`，需啟用且有明細。正式 API 在交易內保留/消耗號碼與防重複，不能由 Web 模擬號碼當正式值。`Add8DBasisFactory` 插入 `TBLWIP8DBASIS_FACTORY`，IssueState=0；若從 ERF 建立，Core 在同一 `ExecuteSQLNoneQuery_UPD` 集合更新 `TBLWIPERFBASIS.QRSNO`。正式 API 應鎖定 ERFNo，確認 ERF 存在/尚未連 8D、型別及權限，插入與關聯原子提交。舊 Core 的動態 SQL 拼接不可直接移植。

`EDIT` 送 `IssueState=0`、原 DataStamp；Service 限未核准，交 `clsBasis_UPD.Edit8DBasisFactory` 修改並記 Reviser/ReviseDate。正式 API 應以 QRSNo + IssueState + DataStamp 做 CAS，並只接受可修改欄位；正式建立/修改記錄真正登入 actor。

## 刪除與核准

主 Form 選取多列逐筆呼叫 Service，因此來源可能前幾筆成功後一筆失敗；Web 可採整批預檢/交易，需向使用者清楚回應整批結果。`IssueState=0/-1`：`wsWIP.Del8DBasisFactory` 實體刪 8D Basis，`clsWIP.Del8DBasisFactory` 同批清除 `TBLWIPERFBASIS.QRSNO` 中引用該 QRSNo 的列。`IssueState=2`：轉 `-1`，資料留存；`Pending=1` 禁止刪除。主 Form 內「Active CurStage 非 N/A 不可刪」檢查雖被註解，實際 `clsBasis_UPD.Set8DBasisFactoryIssueState` **仍檢查 CurStage=N/A**，同時 DataStamp CAS。正式 API 刪除需重查狀態、關聯及版本；不應讓停用紀錄的 ERFNo 與建立狀態錯亂。

`Approve` 僅 0，可多選；主 Form 要求 ProjectDepartment、ProjectManager、PlanCloseDate 非空，Core 狀態更新另要求 CurStage=N/A 並檢 DataStamp。Service 以 Issue Job Map key **`8D BASIS FACTORY`** 查簽核配置：沒有 JobNo 或 JobDetail 直接轉 2；有流程則建立 Issue Master/ApproveSQL/RejectSQL，先轉 1，通知第一簽核群組，核准轉 2、退回 0。正式 API 要用現有權限/Issue 系統與郵件 outbox，避免重送建立重複 Issue；不得由前端選擇「直接核准」作正式決策。
