## 查詢與 Confirm

MO 查找只載 `MOState=3|6`；MONo 必選。查詢 `DataType=1`（撤派工）取 `TBLWIPLOTSTATE.STATUS=3`，接 `TBLWIPLOTBASIS.BASELOTNO` 的 MONo，另 LEFT JOIN `TBLWIPERFBASIS` 且 `LOTDISPTYPELIMIT='98'`，但沒有使用 ERF 欄作後續 WHERE，因此多筆 ERF 可能造成同 Lot 重複列。`DataType=2`（取消）取 `STATUS=99 AND EX_LOTSTATE1='Y'`；若 `TBLOEMOBASIS.MOSTATE=99`，Core 拒絕取消。另查產品名／OP 名。原查詢使用 SQL 字串拼接；新 API 應參數化、限制頁數與權限，對結果 LotNo 去重。取消時已關結 MO 應在 Confirm 當下再次檢查。

Confirm 要至少一列 Select，Form 把 LotNo 清單一次傳 Service：撤派工 `ProgramType=3`，取消撤派工 `ProgramType=4`。Service **逐 Lot** 呼叫 `GetSAP_ZPPT0025x_Data`，每筆成功再寫 SYS EventLog；一筆失敗即停止，先前成功 Lot 不會回滾。Form 只收到整次成功／失敗，不顯示先前成功清單；新 API 要明確回每筆結果並於失敗時重新查狀態。

SAP Core 先讀 `TBLSYSPARAMETER` 的 `SysInfo/LastEndTime`；當前時間超過它時 3/4 均拒絕。查所選 Lot `TBLWIPLOTLOG_REPORT.SAP_UPLOAD='Y'` 的 LogGroupSerial，逐筆產生 ZPPT0025A/B/C1：使用 `TBLOEMOBASIS.SAP_WERKS`、`XX_TBLOEMO_OS_BU1.VORNR`、Report 的 GoodQty/FailQty、`TBLWIPCONT_MATERIALLOT` 的物料批/`SAP_CHARG`。`ProgramType=3` 沿用 Report 的 SAP_RMZHL，`EXETYP='C'`；`ProgramType=4` 從 `TBLSYSSERIALCREATEMAX` 取新 RMZHL，`EXETYP='A'`，更新計數器。若 Report 查不到，來源仍會走後續 Lot 狀態更新；不能把「零筆 SAP 拋轉」自動當成已完成整套外部流程。資料送往 `THSAP.ZPPT0025A/B/C1@SAP_DBLINK`，由 `TBLSYSPARAMETER` 取 DBLink，並寫交易 Log；跨 DB link 與多筆操作有部分成功風險。

每個 Lot 的中間表處理後，Core 另外更新 `TBLWIPLOTSTATE`：3 撤派工→`STATUS=99, EX_LOTSTATE1='Y'`；4 取消→`STATUS=12, EX_LOTSTATE1=NULL`，再用 Lot 的 AreaNo 查 `TBLSMDAREAINVENTORY` 預設 InventoryNo，插入 `TBLINVWIP_SCRAP`（CurQty、LotSerial、OP、Unit、LogGroupSerial）。原 Update 只用 LotNo，沒有狀態/版本條件；正式 API 必須重查、鎖定並限定期望狀態，避免畫面查詢後 Lot 已改變仍覆寫。更不能只做上述兩個 `UPDATE` 而回覆 SAP 成功。

## Oracle 結構與 PostgreSQL CREATE-only

公司端用受保護 MESTEST profile、PowerShell 5.1、`Oracle.ManagedDataAccess.dll`，**唯讀**查六張新直接表的 `DBMS_METADATA.GET_DDL` 和 ALL_TAB_COLUMNS/CONSTRAINTS/INDEXES/TRIGGERS，未查業務列、未寫 Oracle 或連 YMES PostgreSQL。各表的原始 table/index DDL 與 metadata 在 `database/reference/mestest_wip_wp112_<table>_{source_ddl.sql,source_indexes.sql,metadata.txt}`：

| MESTEST 表 | 真實結構重點 |
|---|---|
| `TBLWIPCONT_MATERIALLOT` | 18 欄、**無 PK/FK/unique**，兩個非唯一 index：`(LOGGROUPSERIAL,MATERIALNO)`、`LOTSERIAL`；`CREATEDATE DATE DEFAULT sysdate NOT NULL`。`SAP_CHARG VARCHAR2(10 CHAR)`、`XX_REMARK VARCHAR2(50 CHAR)`；metadata DATA_LENGTH 為位元組 40/200，PG `varchar` 要按 DDL 字元長度。 |
| `TBLSYSSERIALCREATEMAX` | 6 欄，PK `(SERIALTYPE,SERIALSTRING,SERIALLENGTH,DECIMALTYPE)`，單一 PK index；無 trigger。 |
| `XX_TBLOEMO_OS_BU1` | 10 欄，PK `(MANDT,WERKS,AUFNR,VORNR)`；Oracle 欄為 `VARCHAR2(n CHAR)`，不可用 DATA_LENGTH 位元組數當 PG 字數；無 trigger。 |
| `ZPPT0025A` | 10 欄，PK `(MANDT,IDBSNO,WERKS,AUFNR,VORNR,RMZHL,RWKIND)`；無 trigger。 |
| `ZPPT0025B` | 8 欄，PK `(MANDT,IDBSNO,WERKS,AUFNR,VORNR,RMZHL,MATNR,CHARG)`；無 trigger。 |
| `ZPPT0025C1` | 10 欄，PK `(MANDT,IDBSNO,WERKS,AUFNR,VORNR,RMZHL,EXETYP)`；無 trigger。 |

`database/reference/mestest_wip_wp112_create.sql` 是上述 **MESTEST 本地表** 的 PostgreSQL CREATE-only 參考，包含原欄位/可空性/PK/兩個原 index/default，沒有臆造 FK。原交易真正寫 `THSAP.*@SAP_DBLINK`；**MESTEST 本地 ZPPT DDL 不能證明外部 THSAP 實體完全相同**，正式 provider 需由家用端另核整合契約。其他直接表沿現有 refs：LotBasis/State 在 WP101、ERFBasis 在 WP501、LotLog_Report/INVWIP_Scrap 在 WP201、SYSParameter 在 WP208、AreaInventory 在 SMD、MO/Product/OP/Process/SplitContent 在主檔/WIP references。CREATE-only 不是已套用 migration；家用端先核 live PG schema/history，只補真缺項。

## Vue DEV 與家用端 API

`web/src/components/WipUndoDispatch.vue` 使用獨立 DEV key `ymes-dev-mock:wip-undo-dispatch:state:v1`，示意 MOState 3/6、關結工單、兩種 Lot 查詢、13 欄 Grid、全選/取消全選、逐批 Confirm、狀態 3→99 或 99→12、部分成功後重查與假操作紀錄。它**沒有** SAP DB link、中間表、Report、SYS EventLog、Inventory/報廢實際寫入，也未和 WP101 假 Lot 自動同步；正式環境不允許以本地資料顯示交易成功。

家用端實作需登入與 `WP112` ACL、MOState 3/6 分頁 lookup、`GET /wip/undo-dispatch?moNo=...&mode=...` 類型化查詢（依原狀態、去重 Lot、可見範圍）、`POST /wip/undo-dispatch` 提交 `mode + LotNo[]`。Server 端從受授權 MO/可見 Lot 重查狀態、MO 是否關結、LastEndTime、Area→預設 Inventory、Report/ERP 前置值、數量/版本；不能信前端選取列數值。若 SAP/THSAP 連線與交易 Log provider 尚未具備，回明確未支援/不可提交，不得只更新 PG Lot 狀態並回成功。若採逐批提交，回逐筆狀態及跨系統失敗的重試/補償識別；並發須用 row lock/版本和冪等鍵處理，避免重送造成重複 ZPPT 與 Scrap。確切 SAP 契約、PG forward migration、正式 UI/API、部署/驗收交家用端。
