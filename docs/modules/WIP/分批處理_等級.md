# WP209 分批處理_等級（LOT SPLIT_BIN）

## 功能與原始來源

- 在製品管理 → 生產報工 → 分批處理_等級。原生 menu metadata：FunctionNo `LOT SPLIT_BIN`、FunctionKey `WP209`、Form `frmBR_LB_Split_FT`、DLL `BR_LB_Split_FT.dll`。
- WinForms：`STD/MESWin/BR/BR_LB_Split_FT/frmBR_LB_Split_FT.vb`，Form 標題 `Lot Split Have Bin`。Bin 分配對話框：`STD/MESWin/WIP/WP_LotSplit_BinAssign/frmLotSplit_BinAssign.vb`。
- Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `Exe_Manual_LotSplit_Bin`、`LoadLotBasisJoinState`、`LoadGoodBinState`；`wsSYS.LoadBin`、`GetSplitLotNo_Multiple`；`wsWIP.ChkLotStamp`。
- Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `BR_Manual_LotSplit_Bin`。Vue DEV：`/YMES/WIP/LotSplitBin`、`web/src/components/WipLotSplitBin.vue`。

## WinForms 版面與操作

Form 約 1008×589，`MLot` 群組在上方（約 976×151），含黃色 Lot No 輸入、母批 Grid 與 `Eletricbox M.Lot`。`Split` 群組約 976×370，包含 Split by Count／Split by Qty、Split Count / Qty、Include Mother Lot No（**No 預設，Yes 可選**）、`Split`、`Bin Assign`、`Change Routing`、`Eletricbox`；第一個 Grid 是 SplitLot，第二個 Grid 是目前選取子批的 SplitBin。底部 Confirm(&C)、Close(&X)。本 Form 的兩個靜電箱按鈕只在 `IC_FT_PKG` 啟用時顯示。Vue DEV 為獨立導覽增加明確 Query 按鈕。

一般模式的 SplitLot Grid 可見 SplitLotNo、SplitLotQty、Action、ProcessNo／Version、OPNo、ReturnType、ProductNo／Version。Action 0=Go、1=Jump OP、2=Jump Process，ReturnType 0=Not Return、1=Return to Current OP、2=Return to Next OP。Process／OP 由 Change Routing 返回；ProductNo cell 只有 `AllowLotProductChange` 非 0 才可按。WIP Inventory 宿主模式隱藏 Change Routing 及部分流程／Action 欄，不能把它當成選單預設模式。

`Lot Split Bin Assign` 對話框依 `wsSYS.LoadBin` 的 `BinOrder, BinNo` 動態排出每個 Bin 的 Good Bin、Remaining Bin、Split Bin。Remaining = 母批該 Bin - 其他子批已分配數量，包含目前子批可重編的原數量。Confirm 檢查 Split Bin 為數字且不超過 Remaining，再建立／更新該子批的 Bin 列；回主 Form 後用 Bin 加總更新 SplitLotQty。原碼未明確拒絕負數，Vue DEV 補上非負整數守門；正式 API 應自行驗證非負、精度與不超量。

## 查詢、確認與多表副作用

1. Form Load 先讀所有系統 Bin，若沒有 Bin 就停用 Confirm。`funLoadLotState` 傳 Status `0|1|4`、LotState=1、HaveLevel=1、ShowPartialLot=False、StockerLot=False；`funLoadGoodBinState` 取指定 Lot 的 GoodBinState。若 GoodBinState 不存在，提示改用一般 `BR_L_SPLIT_GEN`，清空母批並停用 Confirm。程式中未見 WP208 那種明確拒絕 Status=4 的分支；正式 API 應再核對 Core 規則，而不能從查詢 Status=4 推斷一定可執行。
2. Split 需有效 Lot、Count／Qty 正數與 IncludeMother 選項。Count 以整數均分，最後列吸收餘量；Qty 建立滿額列和最後餘量列。Yes 以母批號作首列，No 全新子批號。按 Split 清掉先前 Bin 分配及子批靜電箱排除清單。`GetSplitLotNo_Multiple(False)` 只是預覽；Confirm 前再核對最新號並用 `True` 保留。
3. Bin Assign 返回後重算每列 SplitLotQty。Confirm 對每列要求 SplitLotQty 非 0、有 Bin 列；Go／Jump OP 的 ReturnType 只能 0，Jump OP／Jump Process 必須有 NodeID。所有 SplitLotQty 合計要等於母批 CurQty。Form 呼叫 `ChkLotStamp` 防舊資料，傳 SplitLot、動態 SplitBin、SplitType、LotStamp、WIP Inventory 參數及可能的 `BindByMLotNo` 到 `Exe_Manual_LotSplit_Bin`。Core 再按 `TBLSYSBIN` 取得動態 Bin 清單，檢查每列 Bin 加總等於 SplitLotQty、全部子批合計等於原 CurQty，並更新 Lot、GoodBinState、Temp、庫存、報工、歷程、派工等。不能用固定三欄 Bin 或單表 CRUD 取代。
4. `Eletricbox M.Lot` 綁母批，`Eletricbox` 綁目前子批。子批各別綁定後不再列入從母批複製的名單；未個別綁定者透過 `BindByMLotNo` 由 Core 參照母批 `TBLWIPCARRIERSTATEDETAIL` 複製。`SplitMergeType=1` BR 宿主在成功後對 Go、未改產品／流程的子批再呼叫 `BRTransferLot`；選單直接開啟預設 SplitMergeType=0。這些後續動作有部分成功風險，正式 API 需要原子交易或可恢復的冪等階段。

## 公司端 DEV 與家用端 API 待辦

Vue DEV 固定兩筆有 GoodBin 的假 Lot、三個假 Bin `BIN001`–`BIN003` 與一筆無 GoodBin 拒絕案例。可操作 Count／Qty、母批 Yes／No、兩個 Grid、Bin Assign 對話框的 Original／Remaining／Split、路由／產品、兩個靜電箱入口、數量守恆與 Confirm。假資料視為 `IC_FT_PKG`、`AllowLotProductChange` 啟用，結果只存 `ymes-dev-mock:wip-lot-split-bin:*:v1`。DEV 只收整數、最多 100 列，並要求各 Bin 完全分配；正式系統依來源資料型別／系統 Bin 設定處理，不讀 DEV localStorage。未模擬真實序號鎖定、載具／靜電箱、WIP Inventory 宿主、ECN 流程、LED Sorter 或 BR TransferLot。

家用端需提供登入保護的指定 Lot／GoodBin／SysBin 查詢與 Product／Routing lookup；Server 只回合法 Lot 與可用 Bin。拆批 POST 在同一交易重讀 LotStamp、GoodBinState、庫存與動態 SysBin，驗證每列與每 Bin 守恆、Action／ReturnType／NodeID、產品與路由、權限和子批序號，再更新所有 Core 副作用。BR、Inventory、Electricbox 與 LED 模式須由可信 server 上下文判斷。`TBLWIPSORTERBINDATA` DDL 缺失前，LED_PKG 分支保持明確未交付；不能以不存在的表造 migration。若標準拆批與後續 TransferLot／載具綁定不能在同交易，提供可觀察、可重試且冪等的分段結果，避免重複 Confirm。

本輪家用端完成 PostgreSQL 0111／0112 source schema 與 catalog 核對；未讀 Oracle／YMES 業務資料列，未實作或部署 WP209 API，未授予 app 權限。

## 家用端正式隔離／主題整合備註
