# WP802 8D 矯正單維護作業（8D MAINTAIN）

## 範圍與來源

- 選單：WIP → 8D 管理 → 8D 矯正單維護作業。FunctionNo `8D MAINTAIN`、FunctionKey `WP802`、主 DLL `WP_8DMaintain.dll`；明細另由 `WP_8DMaintainDef.dll` 開啟。
- 主 Form：`STD/MESWin/WIP/WP_8DMaintain/frmWP8DMaintain.vb`；十頁明細：`STD/MESWin/WIP/WP_8DMaintainDef/frmWP_8DMaintainDefine.vb`，各 ADD/EDIT/Verify/Track 對話窗在同資料夾。Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs`；Core：`STD/MESkc/kcWIP/clsWIP.cs`。主單來源與 CREATE-only 沿 WP508 的 `mestest_wip_wp508_*`，WP801 建立/簽核由前一份規格接手。
- 本頁維護 8D D1–D8 及顯示 D9；結案申請、簽核與正式結案屬 WP803，不能把 D8 `8DReportAutoClose=N` 當已結案。

## 主畫面與入口

主窗 `Query` 有 QRSClass 四勾選（In Line QC、Off Line QC、WIPERF、Other），QRSNo、QRSSummary、FactoryNo、ProjectDepartment、ProjectManager 五個「勾選後才生效」文字條件，以及 Create Date、PlanCloseDate 起迄。來源 `funLoad8DBasis` 固定 `IssueState=2`，結果 DataView 再篩 `CloseDate is null`；「至少一條件」限制在原 Form 已註解，故允許空條件查詢。正式 API 仍應加分頁/上限。Grid 依 QRSNo 升序，原 `iug8DMaintain_iMESUltraGrid_InitializeLayOut` 顯示 38 欄（QRSNo/QRSClass/QRSSummary 起，至 CloseDate/Creator/CreateDate），不可行內編輯。選 ActiveRow 按 `Maintain` 以 `QRSDataRow` 開 `WP_8DMaintainDef`；關閉明細後重查並還原所選列。`Close` 關窗。

WP508 異常單 `btn8D_Click` 另有直接入口：有 QRSNo 則查主單，若不存在或 `IssueState=-1` 不開，其他狀態直接開 `WP_8DMaintainDef`，**不經 WP802 主窗的 Active 篩選**。無 QRSNo 走 WP801 ADD。Web 路由應以記憶體傳 QRSNo，由 API 重查狀態與權限，不能把整個 browser row 當成可信主單。

## 十頁明細與狀態

`CurStage=N/A` 預設 Basis；D1–D9 預設相應頁籤。十頁順序：Basis、Create Team、Problem Description、Immediate Action、Cause Analysis、Disposition、Execute Verification、Precausion（來源拼法）、Summary、8DClose。換頁時來源重新載入該頁資料、8D 主單及當前階段附件；D9 或 `QRSClose=1` 禁修改與附件新增/刪除。

| 頁籤 | 表與主要操作 | 來源守門/連動 |
| --- | --- | --- |
| Basis | 主單 `ProjectDepartment`、`ProjectManager/Name`、`PlanCloseDate`；Confirm、ERFINFO | `funConfirmApply` 只在三者與原列不同時呼叫 `Edit8DMaintainDef`；D9/已結案禁改。ERFINFO 以 ERFNo 開詳細。 |
| D1 Create Team | TeamMember ADD/EDIT/DEL | `QRSNO, MEMBERTYPE, MEMBERNO` 唯一；團隊存在是後續多頁前置條件，原表另有 PMFlag 預設 0。 |
| D2 Problem Description | Question ADD/EDIT/DEL，SequenceNo 自增 | 新增前需 D1；子 Form 有團隊成員判斷；新增後階段 D2。 |
| D3 Immediate Action | Action 與 ActionDetail 雙 Grid；兩組 ADD/EDIT/DEL/Verify | 需 D1；Action 鍵 `(QRSNO,MAINSN)`，Detail 鍵 `(QRSNO,MAINSN,SEQUENCENO)`；刪 Action 的 Service 同刪 Detail；驗證寫 ActionResult、QA actor、日期/備註。 |
| D4 Cause Analysis | RootCause ADD/EDIT/DEL、FishBone | 鍵 `(QRSNO,REASONNO)`，有 D5 處置時不可任意刪/改關聯原因；FishBone 涉及原因分類及魚骨圖。 |
| D5 Disposition | Disposition ADD/EDIT/DEL | 依 D4 原因，鍵 `(QRSNO,SEQUENCENO,REASONNO)`；連動 D6。 |
| D6 Execute Verification | QA ADD/EDIT/DEL | 依 D5 處置，Oracle PK **`(QRSNO,REASONNO,DISPOSITIONSN)`**，不是 SequenceNo；QAResult/Verifier/VerifyDate 等必填。 |
| D7 Precausion | Prevention 與 PreventionTrack 雙 Grid；ADD/EDIT/DEL、Track | Prevention 鍵 `(QRSNO,SEQUENCENO)`；Track 鍵 `(QRSNO,MAINSN,SEQUENCENO)`；對父筆操作追蹤。 |
| D8 Summary | SummaryDepartment/User、SummaryDescription、DispHour/Cost、OK | `funConfirmApply1` 要 QRSNo/QRSSummary、摘要部門/人員/說明；**D1 必須有資料，D3 必須有資料且每筆 ActionResult 非空**。原 D2 要件已註解。系統參數 `SysInfo.8DReportAutoClose=Y` 時 `Update8DSummary` 寫 ReleaseLog、CloseType=1、CloseDate、D9；`N` 時建 `TBLWIP8D_RELEASE` IssueState=0 並停 D8，供 WP803 申請/簽核。 |
| D9 8DClose | 結案與 Release 資訊只讀 | 實際手動結案屬 WP803；D9 只許檢視附件。 |

附件 `TBLWIP8D_ATTACHFILE` 以 `(QRSNO,STAGENO,ATTACHFILENAME)` 為 PK，原 Form 可從目前階段新增、View/下載、確認後多選刪除；來源 File dialog 允許 PDF/JPG/任意檔，BLOB 由 `Get8D_AttachFile` 另用 LOB connection 取。新 API 需對 View/Delete/Upload 各自驗 ACL、主單及階段、檔名長度/重複、大小/媒體類型、內容掃描與安全下載；不得接受瀏覽器傳任意本機路徑。

## Core 交易與新 API

- Core 各 ADD 依階段呼 `Update8DCurStage` 與 `Update8DLastUpdateDate`；`Update8DCurStage` 比較原 CurStage，只往前推。部分 Core 在新增主表資料前後**分別執行**階段/時間更新與實際 INSERT，舊流程有跨命令部分成功風險；新 API 應以同一交易鎖主單、驗前置狀態/ACL、寫子表、推進階段及 LastUpdateDate。不要直接移植字串拼 SQL。
- D1 團隊成員身份影響部分子 Form 可編輯權限；前端顯示守門外，API 必須用登入 actor 重查 TeamMember、Function ACL 與階段。明細序號應在主單鎖下配置，不能信 browser 預測值。所有編輯/刪除以 Oracle 真鍵及關聯守門執行，對併發/已刪/重複提供明確結果。
- D8 的 `Update8DSummary` 會跨主單、Release/ReleaseLog、階段與日期；新 API 應依 server 端 `8DReportAutoClose` 在單一交易處理，並讓 WP803 接續 Issue 流程。資料變動需記錄登入 actor/稽核，避免重送 D8 造成重複 ReleaseLog。
- 原 WinForms 部分多選刪除逐筆呼 Service，可能出現前幾筆成功後失敗；Web 需明確設計整批原子或回傳逐筆結果。來源 D7 `btnEdit7_Click` 讀 `funGetActiveRowsQA`/D5 資料，與 Precausion 頁語意不符，正式 API 應依 `Prevention` 主鍵及 Track 關係實作，不沿用該取列程式。

## DDL 與公司/家用分工

公司電腦用既有受保護 Oracle MESTEST 連線在 PowerShell 5.1 **唯讀**查 12 張直接 8D 子表 `DBMS_METADATA.GET_DDL`、`ALL_TAB_COLUMNS/CONSTRAINTS/INDEXES/TRIGGERS`，檔案在 `database/reference/mestest_wip_wp802_source_ddl.sql`、`_source_indexes.sql`、`_metadata.txt`。12 表均 MESTEST 可見、無 trigger，除了 TeamMember 外各有 Oracle PK。**TeamMember 只有三欄唯一索引 `(QRSNO,MEMBERTYPE,MEMBERNO)`，沒有 PK constraint**；CREATE-only `mestest_wip_wp802_create.sql` 保持相同差異。唯一來源 default 是 TeamMember `PMFLAG=0`。`TBLWIP8D_RELEASELOG` 的 Oracle PK 僅 QRSNO；不能假設可存多筆歷史。未查業務列、未寫 Oracle、未連 YMES PostgreSQL。
