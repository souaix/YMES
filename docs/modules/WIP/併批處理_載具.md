# WP214 併批處理_載具（LOT MERGE_CARRIER）

## 功能與原生來源

- 選單：在製品管理 → 生產報工 → 併批處理_載具；FunctionNo `LOT MERGE_CARRIER`、FunctionKey `WP214`、Form `frmBR_CL_Merge_GEN`、DLL `BR_CL_Merge_GEN.dll`。公司 Vue DEV 頁為 `web/src/components/WipLotMergeCarrier.vue`，路徑 `/YMES/WIP/LotMergeCarrier`。
- WinForms 主頁：`STD/MESWin/BR/BR_CL_Merge_GEN/frmBR_CL_Merge_GEN.vb`；有元件 Slot 視窗：同目錄 `frmCarrierMerge_Comp.vb`。Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `Exe_Manual_LotMerge_Carrier`，另使用 `LoadLotBasisJoinState`、`LoadWIPCarrierStateDetail`、`GetLotStateIncludeData`、`CheckLotIsOSbutNotReturn`、`ChkLotStamp`、`wsEQP.LoadCarrierState`／`LoadCarrierBasisJoinCarrierType`、`wsSYS` 的 `AllowDiffMOMerge`。Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `BR_Manual_LotMerge_Carrier`、`NewLot_Merge`、`SHR_Merge_Inherit` 等 helper。

## 主 Form 版面與查詢

原標題 `Manual Merge`，ClientSize 1008×591。上方 `Reference Carrier` 含 RefCarrier No、查找及 Query，下面的參考批 Grid 顯示 LotNo、CurQty、ProcessNo、OPNo、OPName、NodeId、BaseLotNo、OrgLotNo。`Merge Carrier` 有目標 Carrier No／查找、輸出 LotNo、Select All、UnSelect All、MO No 多選查找、Go／Assign、Process No／Version／OP No 路由查找、候選 Grid（Check、CarrierNo、LotNo、CurQty、MONo、NodeId）與選取量加總；參考批列黃色且固定選取。底部 Confirm(&C)、Close(&X)。BR 呼叫帶入批號時會隱藏一個查找並鎖定相應路徑；選單呼叫預設 MergeType=0。

頁面先載入可併批 Lot、Lot→Carrier 明細、可用空 Carrier 及 `AllowDiffMOMerge`。參考 Carrier 查詢後，以第一筆 Lot 為參考批，再由 `GetLotStateIncludeData` 判定 HaveComponent。若同一參考 Carrier 有多筆 Lot 且含元件，原 Form 明確拒絕。參考批查詢的 Status 範圍為 0／1／4／5、LotState=1、非 Partial／Stocker；HaveComponent／HaveLevel 限制在參考查詢已註解。無元件候選走 `LoadLotBasisJoinState`：HaveComponent=0、HaveLevel=0、LotState=1、同 OPNo／ProductNo／BRNo／Status／CurUnitNo、非 Stocker、必須有 CarrierNo。`AllowDiffMOMerge=0` 才限同 MONo；MO No 視窗可再縮小 Grid，參考批工單固定保留。有元件候選改 HaveComponent=1，且由 Slot 視窗選中的 LotNo 清單回填主 Grid，Check 禁止在主頁更動。Status=5 另限同一張已出貨未回貨 OS；原 Form 要求 Go。

## 有元件的 Slot 視窗

`frmCarrierMerge_Comp` 標題仍為 `Manual Merge`，ClientSize 980×655。`Reference Lot Info` 顯示參考 Lot／Current Carrier，左 Grid 依 CarrierLayer × CarrierCapacity 補上全部位置，顯示 CarrierPosition、LotNo、ComponentNo；參考元件灰色、新移入元件淡黃。右側 `Merge Lot` 有子批 Lot 查找、子批 Carrier 與 Slot Grid；中間 `>`、`>>`、`<`、`<<` 逐顆或全部移入／退回。移入必須先指定左側空位置，保留原 CarrierPosition 為 OrgCarrierPosition；退回只能退目前選中的子批元件。切換子批時，若尚有該子批未移入元件，原視窗詢問是否回復其配置。候選 Carrier 必須僅含一個 Lot，且子批元件數不可超過參考 Carrier 剩餘空位。子視窗 Confirm 要求至少一筆其他 Lot 被移入，且目前子批元件全部移入；回主頁後各參與批的 CurQty 必須等於 Slot 表中的元件列數。主頁 Select All／UnSelect All 在 HaveComponent 時明確拒絕。

公司 DEV 用同一個視窗完成參考 Slot 與子批元件搬移，支援逐顆／全部／退回、空位／容量守門。為避免無效預覽，確認 Slot 時要求**每個參與子批**都完整移入；原視窗只檢查目前子批，主 Form 最後才逐批比對 CurQty。DEV 候選 Lot 由選單取代原 `frmCOMSearch`；未模擬切換子批時的詢問回復及真實 CarrierType。這些差異在正式 API 以伺服器現況重讀判定。

## Confirm、Service 與 Core

主 Form 要求輸出 LotNo、目標 CarrierNo；目標若不同於參考 Carrier，必須在 `LoadCarrierState` 的可用 Carrier 清單。Assign 需要 Process No／Version／OP No 與 NodeId；參考批仍須在候選、至少兩筆批次、每筆 CurQty 非零；同 OP 不同 NodeId 會提示。原 Form 先查參考批 `ChkLotStamp`，送每筆 `LotNo/CurQty/LotStamp/CarrierNo`、RefLotNo／NewLotNo、RefCarrierNo／NewCarrierNo、MergeType、Action，Assign 另送 NodeId／OPNo，BR 帶 ShiftNo。元件模式另送 HaveComponent 與每個 Slot 的 CarrierNo／CarrierPosition／BCIP／ContentID／LotNo／ComponentNo／OrgCarrierPosition。Service 解析 XML／DataTable，轉交 `BR_Manual_LotMerge_Carrier`；沒有替瀏覽器重新決定 HaveComponent 或 Carrier 位置，正式 API 不能沿用信任邊界。

Core 建立新 LotSerial／Reverse、讀參考 Lot、逐來源累加 CurQty，關閉或更新來源、清來源 CarrierState／CarrierStateDetail，元件模式讀 ComponentState、建立合併元件與原／新 Slot 對應，並由 `SHR_Merge_Inherit` 記錄併批與 Reverse／派工／人員。Go／Assign 維持各自新批狀態；Status=5 調整 OSDetail。最後更新目標 CarrierState、輸出 LotState.CarrierNo；有元件時逐 Slot 插入 CarrierStateDetail 並更新 ComponentState.SlotNo，無元件時寫入一筆 position=1 的 Detail／DetailLog。每個來源都在 SQL collection 中做 `ChkLotStamp`，然後呼叫 `ExecuteSQLNoneQuery_UPD`。BR 宿主 Go 成功後，Form 關閉才呼叫 `BRTransferLot`；合併與後續轉站可能部分成功，需可查與冪等重試。Core 結尾註解也指出有時不繼續 Transfer、須人工處理，家用端應核實實際宿主呼叫鏈。

**來源缺陷，正式 API 要修正：** `funChkBeforeConfirm` 對 Status=5 呼叫 `funChkIsOSbutNotReturn(txtRefCarrierNo.Text)`，但該 helper 的參數名與 Service 契約是 `LotNo`；此處傳的是 CarrierNo。API 應按參考 **LotNo** 查 OS，不複製錯參數。Core 的同 OS 守門是 `if (!beSameOSNo && outsorucingLotCount != mergeLotCount)`；此條件只有兩項同時成立才拒絕。正式交易應分別拒絕不同 OS、以及參與來源未全部屬於同一張有效 OS。來源可見分支也未完整重查每個 Slot 唯一性／原歸屬，正式 API 必須以資料庫現況守門。

## Oracle DDL 與 PostgreSQL CREATE SQL

`BR_Manual_LotMerge_Carrier` 方法字面直接引用 11 張資料表：`TBLEMSDISPATCHSTATE`、`TBLWIPAUTOMERGE`、`TBLWIPCARRIERSTATE`、`TBLWIPCARRIERSTATEDETAIL`、`TBLWIPCARRIERSTATEDETAILLOG`、`TBLWIPCOMPONENTSTATE`、`TBLWIPCONT_EMPLOYEE`、`TBLWIPLOTBASIS`、`TBLWIPLOTSTATE`、`TBLWIPOSBASIS`、`TBLWIPOSDETAIL`。`tblCarrierDetailComp` 是 Core 在記憶體中 `new DataTable(...)` 的名稱，**不是** Oracle 表。11 張逐名核對 `database/reference/`，均已有 Oracle source DDL 與 PostgreSQL CREATE-only：Lot／Component 沿 `mestest_wip_wp101_*`，CarrierState 沿 `mestest_carrier_basis_dependencies_*`／`mestest_wip_wp302_*`，Carrier Detail／Log 沿 WP302，Dispatch／AutoMerge／Cont Employee／OS 沿 `mestest_wip_wp207_*`。Carrier Basis／Type 查找也沿主檔／WP210 refs。本功能沒有新缺失的直接表，因此**不重複建立 CREATE SQL**；Core helper 的間接表由家用端追查。既有 CREATE-only 不是 migration，更不能當作 live PostgreSQL 已有表的證據。

## 公司 DEV 與家用端 API handoff

DEV fixtures：`DEV-CAR-A` 是無元件；`DEV-CAR-CR` 是兩顆參考元件，搭配 `DEV-CAR-CC` 兩顆子批元件；`DEV-CAR-MIX` 示範同載具多批有元件拒絕；`DEV-CAR-OS1/OS2` 示範同 OS Go；另有 4／8／2 Slot 空載具可檢查容量。畫面可查 Carrier、勾選批、MO 多選、Go／Assign、選目標 Carrier、Slot 移動與 NodeId 提示。DEV 僅寫 `ymes-dev-mock:wip-lot-merge-carrier:records:v1`，不變更 MES。正式 non-DEV 禁用 fixture 與 Confirm；本輪依既有使用者約束未執行 build/test/browser。

家用端應提供登入保護的 Carrier→Lot／Slot／CarrierType capacity、候選 Lot、可用空 Carrier、MO、Route、OS／系統參數查詢。交易式 POST 至少傳參考批、輸出批號、來源 Lot 清單及版本、目標 Carrier、Action／目標路由、元件 Slot mapping；server 重新推導 HaveComponent、MergeType、actor、班別、可用 Carrier、OS 與元件歸屬。鎖定並重查每筆 LotStamp／CurQty／Status／Unit／OP／Product／BR／MO、原 CarrierState／Detail／ComponentState、目標 CarrierState／Type／容量、Slot 空位與唯一性；元件集合及數量必須完整且唯一，不能只信任瀏覽器送的 Slot 清單。Lot／Reverse／MergeContent／Carrier／Component／OS／Dispatch／Employee／History 等應同一交易提交，BR 後續轉站失敗可查、可冪等重試。先核 live PostgreSQL schema/migration history，確實缺欄或表才建立 forward migration；公司端未連 PG、未實作正式 API。
