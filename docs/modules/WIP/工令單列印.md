# WORKORDER PRINT 工令單列印

## 選單與來源

- 選單：WIP → 在製品 → 工令單列印；FunctionNo `WORKORDER PRINT`，Inventory 的 FunctionKey 欄空白，ExecutionFile `WP_WorkorderPrint_THEIL_BU1.dll`。
- 公司端 DEV 路徑：`/YMES/WIP/WorkorderPrint`。頁面只用固定 DEV 假資料，不呼叫 YMES API，不連 PostgreSQL。
- Form 與 Designer 控制項同在 `D:\iMES\CSiMES\Customer\Production\MESWin\WIP\WP_WorkorderPrint_THEIL_BU1\frmWP_WorkorderPrint_THEIL_BU1.vb`；ActiveReport 定義為同專案 `Reports\arWorkorderPring_THEIL_BU1.vb`。
- THEIL Service：`D:\iMES\CSiMES\Customer\Production\wsTHEIL\wsWIP\wsWIP.cs` 的 `LoadWorkorder`、`LoadMOTypeDesc`、`LoadLotDetail`。工單表頭另呼叫標準 `wsWIP.LoadMOBasis`。
- THEIL Core：`D:\iMES\CSiMES\Customer\Production\MEStc_THEIL\tcWIP\clsLot.cs` 的同名查詢方法；MO Type description 查 `TBLSYSMOTYPEBASIS`。

## Form 篩選與互動

- 初始不自動查詢。`MO No` 與 `MO Create Date` 兩個條件各有勾選框；必須勾至少一項。文字欄可直接輸入 MO No，旁邊的 MO 查找按鈕在 Designer 中 `Visible=False`。
- 建立日期預設為今天 07:30 到現在；若開啟時早於 07:30，起日改為前一天 07:30。只有勾選日期條件才把兩端時間傳給查詢。
- 查詢結果每列加 `CheckFlag`，支援 Select All／UnSelect All。Grid 顯示 Core 的批號、MO、狀態、產品與版次、流程／作業站、現況數量與 SAP 數量欄位。
- Print 只處理已勾選批號。沒有勾選時提示；若選取批號的 `MONO` 不同則拒絕。通過後重新讀該 MO 表頭、MO Type 說明及 Lot 屬性，建立一份 `arWorkorderPring_THEIL_BU1` ActiveReport 並交給報表檢視器；此 Form 沒有資料寫入。
- 報表表頭使用 `CreateDate`、`RONO`、`ProductNo`、`MONo`、MO Type description、`PLANFINISHDATE` 與 MO Description。批明細使用 `SAP_PCSQTY`（大片／PANELQTY）、`SAP_ARGQTY`（排片／LAYOUTQTY）、`SAP_PRDQTY`（數量／PIECESQTY）、`WIP_INSP_NO`（前工程檢驗單號）、`WIP_CIMLOTNO`（CIM_NO/備註）；三種 SAP 數量及批數另加總。表頭 CIM 備註取第一個選取批的 CIM 值。

## Service／Core 查詢規則與資料來源

- `LoadWorkorder` 接受可選 `MONo`、`MOCreateDateFrom`、`MOCreateDateEnd`，回傳 `WorkorderList`。Core 從 `TBLWIPLOTSTATE A` join `TBLWIPLOTBASIS B`、`TBLOEMOBASIS C`、`TBLPRDPRODUCTBASIS P`、`TBLOPBASIS O`，回傳批號、工單、狀態、產品／版次、PS／Process／OP、現況數量與 `SAP_PCSQTY`、`SAP_ARGQTY`、`SAP_PRDQTY`。條件為 `A.PSNO <> 'N/A'`，另按輸入 MO 與 MO 建立時間範圍篩選。SQL 沒有 `ORDER BY`。
- Core 註解寫「只抓已下線的批號」，但這段 SQL 沒有 `STATUS`／LotState 條件，實際只排除 `PSNO='N/A'`；Web 不應自行補狀態守門，正式 API 需由家用端確認業務定義。
- `LoadLotDetail` 以批號清單查 `TBLWIPLOTBASIS` 加 `TBLWIPLOTPROPERTY`，Form 只投影 `WIP_INSP_NO` 和 `WIP_CIMLOTNO`。ActiveReport 定義了 `PrePN` 欄，但目前 Form 沒有查詢或填入該欄，輸出保持空白。
- `LoadMOTypeDesc` 從 `TBLSYSMOTYPEBASIS` 讀 Description。Form 只有在 MO 文字欄非空時才把 `MOTypeNo` 加到這支 Service 的 XML；用日期條件查出批號、但 MO 文字欄留空時，Core 收到預設 MOTypeNo，可能拿不到報表分類說明。請家用端確認是否修復成用已讀取的 MO TypeNo。
- Legacy Core 將 MO、日期與 Lot 清單直接串接到 SQL。正式 API 必須用參數與 LotNo 陣列查詢，並在伺服器重讀 MO、批現況和所選 Lot 關係；不能信任瀏覽器傳入的 report header 或數量總計。
- 查詢會使用的結構都已有 repository Oracle reference：`database/reference/mestest_wip_wp101_source_ddl.sql`（Lot state/basis/property）、`mestest_oe_work_order_source_ddl.sql`、`mestest_prd_product_basis_source_ddl.sql`、`mestest_operation_and_system_source_ddl.sql`。本項只重用 DDL／metadata，沒有連 Oracle、查業務列或新增 CREATE-only；沒有新增資料表需求。

## Vue DEV 與家用端 handoff

- Vue DEV 提供 MO／建立日期勾選篩選、MO 查詢、列選取與全選／取消、同一工單守門、PF 生產工令單預覽、批次數量合計與假列印提示。DEV 沒有連 API 或印表機，正式非 DEV 不顯示假資料。
- 建議家用端提供登入授權的唯讀查詢與報表預覽：`GET /api/wip/workorder-print/lots?moNo=&createDateFrom=&createDateEnd=`，以及以所選 `lotNos[]` 重新查證後回傳報表 DTO／PDF 的唯讀預覽端點。兩者執行 FunctionNo `WORKORDER PRINT` 的授權檢查。
- 使用者可見 Menu inventory 未提供 FunctionKey；家用端需先確認此 FunctionNo 的正式 ACL 對應，不能臆造 `WPxxx` key。資料只讀既有工單、Lot、產品、OP、MO Type 與 Lot property 表，無需專屬 migration 或寫入 API。
- 回傳資料需在服務端檢查所有 Lot 屬於同一 MO、重讀工單與批明細、計算 `SAP_PCSQTY`／`SAP_ARGQTY`／`SAP_PRDQTY` 合計並映射兩個指定屬性。參數化所有條件，限制一次預覽批數，確認「只抓已下線」註解與實際 SQL 差異、日期查詢下 MO Type description 的空值行為，以及來源未填 `PrePN` 的欄位規格。
- 公司端未連 YMES PostgreSQL、未建 schema/migration、未實作或驗收正式 API、未 SSH／部署。
