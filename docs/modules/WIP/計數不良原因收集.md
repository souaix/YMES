# WP206 計數不良原因收集（IPQC）

## 功能識別

- 第一層：在製品管理（WIP）
- 第二層：生產報工（LOTEXECUTE）
- FunctionNo：`IPQC`
- FunctionKey：`WP206`
- Form／DLL：`frmIPQC`／`WP_IPQC.dll`
- 子視窗：`frmABPosition`
- Vue DEV 路徑：`/YMES/WIP/IPQC`

## WinForms 畫面

主 Form 約 1008×661，標題 `IPQC`。上方是 OP No 唯讀欄與 `...` 選取按鈕，第二列是可輸入 Lot No。中央 `gbxErrorInput` 內有可捲動的 `pnlAbnormal`，依所選 OP 動態建立異常項目；每項包含不可直接點選的核取方塊及異常名稱按鈕。群組底部另有可輸入 `Error No` 欄位。底端有 `Confirm(&C)`、`Close(&X)` 與四格 StatusBar；Form_Load 只在最右側 StatusBar 顯示當下時間。

`Error No` 在 Form 原始碼中沒有事件、沒有查詢或送出參數，是可輸入但未使用的欄位；DEV 保留其外觀與可輸入狀態並標記為 inert。畫面中殘留的 DataGridTextBoxColumn 欄位沒有加入任何 DataGrid，實際畫面是動態異常按鈕。

## 操作邏輯

1. 點 OP No `...` 時呼叫 `wsOP.LoadOPBasis(OPClass=1)`；Service 預設 `IssueState=2`。選取不同 OP 後，以該 OP 關聯的 `TBLQCABNORMALBASIS` 載入異常，按 `AbnormalName` 排序，並載入相關 Position。
2. 點沒有 Position 的異常名稱按鈕，切換該異常核取狀態。
3. 點有 Position 的異常名稱按鈕，開啟 `frmABPosition`。視窗逐列顯示 Position 與 checkbox，可多選；Confirm 更新選擇並關閉；全未選時會清除該異常；Cancel 不變更原選取。
4. 主 Form Confirm 蒐集所有 `Select=True` 的資料，傳送 LotNo、OPNo、AbnormalNo、LinkName、Priority、Position 到 `wsWIP.UpdIPQC`，成功顯示成功訊息並關閉來源視窗。

## 不良記錄寫入規則與來源差異

- `wsWIP.UpdIPQC` 解析 `AbnormalNo`、`LinkName`、`Priority`；Position 可省略。Service 的錯誤訊息提到 `AbnormalQty`，但 parser 並不要求它，Form 也沒有傳送它。
- `clsLot.UpdIPQC` 寫入 `TBLWIPCONT_ABNORMAL(LotSerial, OPNo, AbnormalNo, Position)`，以畫面 LotNo 原字串當作 LotSerial。`LinkName`、`Priority`、登入者、班別、LotNo 欄位、EventTime 都不在這支 Core insert 清單；`AbnormalQty` 由資料庫 default 0。
- Core 沒有查 LotState、沒有檢查 Lot 與 OP／不良項目的關聯、沒有既有異常去重，也沒有更新 LotState。它將每個選取列組成 insert SQL collection 後執行；重複送出可能新增重複異常列。
- Form 的 LotNo Enter 會呼叫 `LoadLotState`，但不傳查詢條件；Service/Core 因而讀取所有 LotState。舊的 Lot 選取 dialog 已整段註解，返回的 DataSet 未用來驗證或限制 LotNo。Vue DEV 不模擬全表載入；正式 API 應只驗證傳入 LotNo，避免延續無條件全表查詢。
- 來源 Form 沒有必填 LotNo／OPNo／至少一異常的明確驗證；Service 只要求 XML 欄位節點存在，空值仍可能傳至 Core。Vue DEV 為避免寫入空關聯資料，確認前會要求 OP、Lot No 與至少一個異常／位置。此項是明確的防呆差異，正式 API 也應在伺服器端驗證。

## Oracle 結構

PowerShell 5.1 使用本機受保護 Oracle profile、ODP.NET 直連 MESTEST，只讀取得四張表 DDL 與欄位／constraint／index／trigger metadata。沒有查業務資料列，沒有執行 Oracle DDL/DML：

| 表 | Primary Key／Index | Foreign Key／Trigger |
| --- | --- | --- |
| `TBLOPABNORMAL` | PK `(OPNO, ABNORMALNO)` | 無 FK／Trigger；PK index |
| `TBLQCABNORMALBASIS` | PK `(ABNORMALNO)` | 無 FK／Trigger；PK index |
| `TBLQCABNORMALPOSITION` | PK `(ABNORMALNO, POSITION)` | 無 FK／Trigger；PK index |
| `TBLWIPCONT_ABNORMAL` | 無 PK；只有 `LOTSERIAL` 非唯一 index `I_TBLWIPCONT_ABNORMAL_01` | 無 FK／Trigger |

`TBLOPABNORMAL` 的 CREATE-only 已由既有 `mestest_operation_and_system_create.sql` 提供，不重複建立。其餘三張 Oracle source DDL、index DDL、metadata 與 PostgreSQL CREATE-only 位於 `database/reference/mestest_wip_wp206_*`。CREATE-only 保留 `TBLWIPCONT_ABNORMAL` 無 PK 的來源結構；不得自行新增唯一鍵、FK 或 trigger。

## 公司端 Vue DEV

`web/src/components/WipIpqc.vue` 保留 OP lookup、Lot No、動態異常按鈕／checkbox、Position 多選視窗、Error No、Confirm／Close 與 StatusBar。DEV 假資料提供兩個 OP、無位置與多位置異常；選取後寫入 `ymes-dev-mock:wip-ipqc:abnormal-records:v1`，假記錄對應 Core 實際新增欄位並保持 `AbnormalQty=0`、UserNo／ShiftNo／EventTime 為 null。選取 OP 會清除前一個 OP 的異常狀態，避免複製舊 Form 多次載入而重疊動態控制項的來源 UI 瑕疵。

## 家用端正式 API

正式路由前綴 `/YMES/API`；各端點皆要求登入。公司端頁面仍以 DEV localStorage 假資料運作，正式頁面 API 串接交由 `todolist_officepc.md`。

| 方法與路徑 | 用途 |
| --- | --- |
| `GET /api/wip/ipqc/lookups/operations?keyword=&page=1&pageSize=50` | OPClass=1、IssueState=2 的作業站，依 OPNo 排序；搜尋與分頁皆由 server 執行，每頁最多 100 筆。 |
| `GET /api/wip/ipqc/lookups/operations/{opNo}/abnormalities` | 讀取 OP 關聯異常及各異常的位置選項；按 AbnormalName 排序。異常主檔不額外套用 IssueState 條件，與已追到的來源查詢一致。位置／異常列最多 2,000 筆。 |
| `POST /api/wip/ipqc/abnormal-records` | 以 JSON `{ lotNo, opNo, abnormalities: [{ abnormalNo, positions: [] }] }` 寫入；`Idempotency-Key` header 必須為非空 UUID。無 Position 的異常傳空陣列；有 Position 的異常需選一個以上。 |

POST 在單一 PostgreSQL 交易內鎖定已核准作業站、LotState 中該 Lot／OP 的現況列，以及所選異常關聯與 Position 設定，完成關聯驗證後寫入全部記錄。Lot 驗證採指定 LotNo + OPNo 的有限查詢；舊 WinForms 的 Enter 無條件載入全 LotState 不會重現。來源只確認此畫面沒有另外套用 Status allowlist，因此 API 不自行猜測狀態集合；若業務要求更嚴格的「可作業狀態」，公司端須先確認來源規則並回填。

寫入欄位維持舊 Core 行為：`LotNo` 寫入 `LotSerial`，`AbnormalQty` 省略以使用資料庫 default 0；`Position` 依選取列寫入；`LinkName`、`Priority`、`UserNo`、`ShiftNo`、`LotNo`、`EventTime` 不寫入。選取 OP、Lot、異常關聯或 Position 無效時整筆交易回滾。單次最多 100 筆；重送同一 Idempotency-Key 與相同帳號／內容會回傳原筆數，不再新增；同一 Key 用於不同帳號或內容回 409。不同 Key 的重複不良列仍按 MES source schema append，來源表沒有可用唯一鍵。

`database/migrations/0108_wip_wp206_ipqc.sql` 只建立 live schema 缺少的四張來源表及 YMES 專用 `ym_wp206_request` 冪等紀錄表。`TBLOPABNORMAL` 的結構重用 Operation/System source reference；因正式 YMES 查無 live table，所以由 0108 建立一次，不代表重複輸出 CREATE-only。`TBLWIPCONT_ABNORMAL` 保留來源無 PK／無 FK／無 Trigger 的設計，只建立 `LOTSERIAL` 非唯一 index；絕不補造來源唯一鍵。登入角色只獲得 lookup 表 SELECT、異常記錄 INSERT、冪等 ledger SELECT/INSERT；沒有為本功能新增資料列編輯權限。Rollback 會在任一來源／冪等表有資料時拒絕執行。
