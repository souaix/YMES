# WP213 併批處理_等級（LOT MERGE_BIN）

## 功能與原生來源

- 選單：在製品管理 → 生產報工 → 併批處理_等級；FunctionNo `LOT MERGE_BIN`、FunctionKey `WP213`、Form `frmBR_LB_Merge_FT`、DLL `BR_LB_Merge_FT.dll`。公司 Vue DEV 為 `web/src/components/WipLotMergeBin.vue`，路徑 `/YMES/WIP/LotMergeBin`。
- WinForms：`STD/MESWin/BR/BR_LB_Merge_FT/frmBR_LB_Merge_FT.vb`。Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `Exe_Manual_LotMerge_Bin`、`LoadLotBasisJoinState`、`LoadLotStateJoinGoodBin`／`LoadLotStateJoinGoodBin_INV`、`LoadGoodBinState`、`ChkLotStamp`，Bin 目錄用 `wsSYS.LoadBin`。Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `BR_Manual_LotMerge_Bin`、`AddMergeContent_Bin`、`SHR_Merge_Inherit`。

## WinForms 版面、查詢與動態 Bin

原視窗標題 `Manual Bin Merge`，ClientSize 1008×591。上方 `Reference Lot` 有 RefLot No 與參考批 Grid；`Merge Lot` 有輸出 LotNo、Select All、UnSelect All、在 `IC_FT_PKG` 模組才顯示的 Eletricbox、Go／Assign 與流程／版本／OP 查找，底部候選 Grid 的固定欄 Check、LotNo、CurQty、NodeID，之後按 `wsSYS.LoadBin` 的 `BinOrder` 逐個加只讀 Bin 欄及選取列加總。參考批列黃色且固定勾選。底部 Confirm(&C)、Close(&X)。**原頁沒有 MO 多選欄**；`AllowDiffMOMerge` 只在後端候選查詢判斷。

載入時先查系統 Bin 目錄，空目錄即不可繼續。參考批 `LoadLotBasisJoinState` 條件為 `Status=0|1|4`、`HaveComponent=0`、`HaveContainGoobinState=True`、`LotState=1`、非 Partial／Stocker；`HaveLevel=1` 參考條件已註解。指定批號時再 `LoadGoodBinState`，若無資料即提示改用 WP211 一般併批並停用 Confirm。一般候選走 `LoadLotStateJoinGoodBin`：`HaveComponent=0`、`HaveLevel=1`、`LotState=1`、同 OPNo／ProductNo／BRNo／Status／CurUnitNo、非 Stocker；`SysInfo/AllowDiffMOMerge=0` 才加同 MONo。WIP Inventory 宿主另走 `_INV` 查詢並隱藏 Transfer Type；其選單初始化沒有帶 MO 限制參數，正式 API 應核對部署行為，不能直接推定與一般模式相同。

## 確認與交易

- Confirm 要求輸出 LotNo；Assign 須有 Process No／Version／OP No 與 NodeID；參考批仍須在候選、至少兩筆含參考批、每筆 CurQty 非零；同 OP 但不同 NodeID 需提示。Form 先 `ChkLotStamp` 參考批，送每筆 `LotNo/CurQty/LotStamp` 加上**按 SysBin 目錄動態命名的各 Bin 數值**，及 RefLotNo、NewLotNo、MergeType、Action；Assign 另送 NodeID／OPNo，BR 送 ShiftNo，WIP Inventory 送 WIPINV／InventoryNo。手動選單 MergeType=0。BR 宿主 Go 成功後 Form 關閉再呼叫 `BRTransferLot`，須保留併批成功但轉站失敗的可恢復結果。
- Core 讀 `TBLSYSBIN` 生成新批各 Bin 欄，逐來源加總 CurQty／各 Bin，另以 `GetPassQtyByLotNo`／`GetFailQtyByLotNo` 取得良／不良量；建立新 Lot／Reverse／Log、關閉來源批、維護派工／AutoMerge／員工與庫房半成品，呼叫 `AddMergeContent_Bin` 記錄 From／To LotSerial、Bin1–8 與 Pass／Fail 快照，最後逐來源 `ChkLotStamp` 並執行 SQL collection。正式 API 必須交易內重讀 Bin 目錄與 GoodBinState、LotStamp、CurQty、Bin 餘量及 pass/fail 現況；不得信任瀏覽器送的 Bin 數值、總量、LotSerial、模式或 actor。Bin 正負與上限、各來源／輸出總量、精度及來源歸屬需要明確守門。原 Form 未明寫「每筆 Bin 總量等於 CurQty」硬規則，正式契約應以 Core helper 與真實資料核實再定，勿把 DEV fixture 當規則。
- Eletricbox 呼叫 `BR_L_Split_GEN_ElectricBox` 並以輸出 LotNo 作 RunCard；公司 DEV 僅呈現入口。正式權限／`IC_FT_PKG` 配置、綁定副作用及 BR 後續轉站由家用端串接。

## Oracle DDL 與 CREATE SQL

Core 方法字面直接引用八張表：`TBLEMSDISPATCHSTATE`、`TBLINVWIPINVENTORY_SEMI`、`TBLSYSBIN`、`TBLWIPAUTOMERGE`、`TBLWIPCONT_EMPLOYEE`、`TBLWIPLOTBASIS`、`TBLWIPLOTSTATE`、`TBLWIPMERGECONTENT_BIN`。前七張已有 Oracle source DDL／PostgreSQL CREATE-only reference，分別沿 WP101／WP201／WP207 與 PRD Bin refs。缺的 `TBLWIPMERGECONTENT_BIN` 已用公司端受保護 Oracle MESTEST profile、PowerShell 5.1／ODP.NET **只讀** `DBMS_METADATA.GET_DDL`、`ALL_TAB_COLUMNS`／`ALL_CONSTRAINTS`／`ALL_INDEXES`／`ALL_TRIGGERS` 查得：22 欄，`FROMLOTSERIAL varchar2(55)` 為單欄 PK，`FROMBIN1–8`／`TOBIN1–8`／四個 Pass/Fail Qty 均 `NUMBER(6,0) NOT NULL DEFAULT 0`，`TOLOTSERIAL varchar2(55) NOT NULL DEFAULT 'N/A'`，無 FK、trigger 或其他 index。來源表 DDL、index DDL、metadata 與 PostgreSQL CREATE-only 分別在 `database/reference/mestest_wip_wp213_source_ddl.sql`、`mestest_wip_wp213_source_indexes.sql`、`mestest_wip_wp213_metadata.txt`、`mestest_wip_wp213_create.sql`；22/22 欄已靜態核對。**CREATE-only 不是 migration**，家用端先核 live PostgreSQL schema/history，確實缺表才建 forward migration；Core helper 的間接表另查。未讀 Oracle 業務資料、未執行 DDL/DML，無憑證進 repo。

## 公司 DEV 與家用端 API handoff

公司 DEV 用 `DEV-BMERGE-001/002/003` 模擬含 GoodBin 同工單、跨工單及不同 NodeID，`DEV-BMERGE-NOBIN` 示範拒絕；Grid Bin 欄由 DEV 目錄排序生成，支援勾選、全選／取消、Go／Assign、輸出 LotNo、靜電箱入口、Bin 與 CurQty 加總、至少兩批及節點提示。假狀態只寫 `ymes-dev-mock:wip-lot-merge-bin:records:v1`，未更新 MES。正式 non-DEV 禁用假資料與 Confirm。

家用端提供登入保護的參考批、候選、SysBin／GoodBin、路由與功能模組配置查詢，並以交易式 POST 鎖定所有來源 Lot 與 GoodBin、重查部署參數、Bin 目錄、LotStamp、數量和輸出批號；寫入 Lot／Reverse／GoodBin／MergeContent／Inventory／Dispatch／歷程。跨 BR 轉站需可查、冪等重試。公司端未連 YMES PostgreSQL、未建正式 API/migration，依既有使用者約束未執行 build/test/browser。
