# 免檢批設定

## 功能範圍與來源

- 清冊名稱：`Skip Inspection Setting`／免檢批設定；分類「生產報工」。清冊沒有提供 FunctionKey，正式權限碼仍需由家用端對照現行 menu metadata。
- 主畫面：`D:\iMES\CSiMES\Customer\Production\MESWin\WIP\WP_SkipInspectionSetting_THEIL_BU1\frmWP_SkipInspectionSetting_THEIL_BU1.vb`（控制項配置與事件邏輯均在同一 VB 檔）。
- 新增視窗：同目錄 `frmSkipInspectionDef_THEIL_BU1.vb`；狀態視窗：`frmStatusChange_THEIL_BU1.vb` 與 `frmStatusChange_THEIL_BU1.Designer.vb`。
- Service：`D:\iMES\CSiMES\Customer\Production\wsTHEIL\wsWIP\wsWIP.cs`，核對 `LoadNoInspectionList`、`LoadLotList`、`AddSkipInspection`、`UpdSkipInspectionStatus`、`CheckSkipInspection`。
- Core：`D:\iMES\CSiMES\Customer\Production\MEStc_THEIL\tcWIP\clsLot.cs`，核對同名查詢／寫入及 `LoadSkipInspection`。
- WP201 執行流程：`D:\iMES\CSiMES\Customer\Production\MESWin\WIP\WP_LotSelect_THEIL_BU1\frmWIPLotSelect_THEIL_BU1.vb` 與 `frmSkipInspectionInf_THEIL_BU1.vb`；執行畫面會依目前 LotNo+OPNo 呼叫檢查，有 Status=0 的設定時顯示免檢原因。

## WinForms 行為

- 主查詢條件：LotNo、MO No. 子字串，OP 多選、狀態及可選建立日期區間；沒有必填查詢條件。狀態預設 `0=執行中`，另有 `1=解除`、`9=全部`。由 Lot 執行流程帶入 LotNo 開啟時，主表單會以預設狀態自動查詢。
- 結果以 LotNo+OPNo 為一列，顯示狀態、工單、產品、版次、建立人／時間及免檢／解除原因。主畫面提供新增與變更狀態，沒有刪除動作。
- 新增視窗可多選 Lot 與 OP，原因必填；建立每個 Lot×OP 組合，初始 Status=0，並由 Lot 資料帶入 MONo、Product、ProductName、Version。候選 Lot 的 Core 查詢條件為 `STATUS < 11`。資料表複合主鍵為 `(LOTNO, OPNO)`，任一重複都會使 Core 單次 `INSERT ALL` 失敗。
- 狀態變更作用於目前選取列，`0→1` 解除或 `1→0` 恢復執行；兩種方向都要求輸入原因，寫入 `RELEASE` 欄。來源服務另呼叫事件記錄，但更新與事件記錄未由同一交易保證。
- WP201 的 `CheckSkipInspection` 只查相同 LotNo+OPNo 且 Status=0 的設定；找到時顯示原因資訊。復刻端應保留這個明確的執行流程互動，不應把主檔 CRUD 當成獨立孤島。

## DEV 頁面

- Vue 元件：`web/src/components/WipSkipInspectionSetting.vue`；在 `App.vue` 的 WIP fallback menu 和 `/YMES/WIP/SkipInspectionSetting` 路由開啟。假資料限定 DEV 預覽，不呼叫正式 API、不持久化。
- 完成 Lot/MO/OP/狀態/日期查詢、Lot 與 OP 多選查找、Lot×OP 新增、必填原因、重複複合鍵錯誤、選取列狀態往返與解除原因，以及狀態／空結果提示。候選 Lot 依來源 `STATUS < 11` 限制。
- `initialLotNo` 可模擬 WP201 帶入 Lot 的入口；正式資料未連接時不展示假資料為真實結果。

## 資料結構與 DDL

- 直接表 `MESTEST.XX_TBLSPCWAIVE` 已在 `database/reference/mestest_wip_wp201_unresolved_source_ddl.sql` 有 Oracle source DDL，`database/reference/mestest_wip_wp201_create.sql` 已有對應 CREATE-only。欄位含 LOTNO、OPNO、STATUS、MONO、PRODUCT、PRODUCTNAME、VERSION、REASON、RELEASE、CREATOR、CREATDATE；PK `(LOTNO, OPNO)`。本項重用既有 DDL/metadata reference，沒有另查業務資料、沒有新增 CREATE SQL，也沒有連 YMES PostgreSQL。
- 無來源 DDL 缺項。若家用端 live schema 已含此表，不需新增 migration；先核對欄位、狀態 default、複合 PK 和既有擴充欄位。

## 家用端 API／schema handoff

- 先比對 `ymes.xx_tblspcwaive` live schema，保留既有擴充欄位；若已存在且結構相符，不新增 migration。
- 提供權限保護的篩選查詢、候選 Lot／OP 查找、批次建立、依 LotNo+OPNo 變更狀態，以及 WP201 執行流程查詢 Status=0 原因的 API。Lot 清單、OP 清單和批次資料都須由服務端重新驗證。
- 所有值以參數化 SQL 處理。建立時在交易內預先檢查／捕捉複合鍵衝突，明確回傳失敗 Lot×OP；保存 authenticated actor 和建立時間。狀態變更應要求預期舊 Status 作並發條件，並將原因、事件記錄與資料更新置於可靠的同交易／outbox 契約。
- 保留來源狀態值 `0/1/9` 的 UI 查詢含義，但 `9` 是查詢用「全部」，不可存成資料列狀態。WP201 execution check 僅回傳 Status=0 的有效項目與原因。

## 來源限制與差異

- Core SQL 以字串串接條件和值；正式 API 不可照搬。主查詢沒有穩定 `ORDER BY`；Service 解析了 Creator 條件但未傳給 Core；Lot 查找的 Service 雖解析 searchBy／keyword，呼叫 Core 時卻未傳入，Core 因此回傳全部符合 Lot 狀態的候選。
- Core 寫入一個涵蓋所有 Lot×OP 的 `INSERT ALL`，沒有逐筆重複預檢；CreateDate 由 Core 以目前時間重新產生，不採用 Service 傳入時間。狀態更新只以 LotNo+OPNo 定位，沒有舊 Status／版本條件。上述是來源觀察，正式端依前述原子性與並發契約實作並保留可追溯事件。
- 原生 menu metadata 未提供 FunctionKey；家用端須查實際 ACL 對應，不可自行假設數字權限碼。
