# WP506 預先異常解除（FUTURE HOLD RELEASE）

## 來源與定位

- 三層選單：WIP → 異常與等待 → 預先異常解除。FunctionNo `FUTURE HOLD RELEASE`、FunctionKey `WP506`、執行檔 `WP_FutureHoldRelease.dll`；來源選單見 `docs/MES_MENU_FUNCTION_INVENTORY.md`。
- WinForms `STD/MESWin/WIP/WP_FutureHoldRelease/frmFutureHoldRelease.vb`，包含內嵌 Designer；Service `STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `LoadFutureHold`／`DelFutureHold`；Core `STD/MESkc/kcWIP/clsLot.cs` 的同名方法。相關設定入口為 WP504。

## 畫面與操作

原 Form 上方 `Query` 框為兩列：Lot No、OP No；Hold Time Start/End、MClass No。各文字欄有勾選框；輸入內容會勾選該欄，取消勾選會清空文字。Hold Time 勾選後且選到 Start=`0` 或 End=`1` 才過濾。OP 與 MClass 有 `...` 查找，分別載入 OP Basis、MClass Basis；Lot No 的 `btnGet` 雖有查找程式，Designer `Visible=False`，原畫面不顯示。該隱藏 handler 選 Lot 後誤寫 `txtOPNo`，不能視為已可用功能。Query 可不輸入任何條件；原 Form 每次先重新 `LoadFutureHold` 全量讀取，再在本機 DataView 按勾選欄位篩選。正式端需改為授權、參數化、有限筆數或分頁查詢。

下方 `Future Hold Data` 框有九個可見欄位：Lot No.、MONo、ProductNo、OP No.、Hold Time（Start/End）、MClassNo、Hold Description、Creator、Create Date。Grid 僅目前 ActiveRow 為操作目標；右側上方 `Release`、右側下方 `Close (&X)`。載入資料由 FutureHold JOIN LotState/LotBasis 取得 MONo/ProductNo；只顯示在該 JOIN 找得到的資料，不應把不存在的孤立設定當成畫面列。Core `LoadFutureHold` 還接受 HoldDescription、Creator、日期、ModuleNo/Version 等參數，但此 Form 只用上述四種篩選。

## 解除語義及原始風險

Release 先檢查**選取列** `LockFlag=1`；已進入異常處置則拒絕。Form 實際送 Service 的參數只有 `LotNo`、`OPNo`、`HoldTime`。Service 雖可解析 ModuleNo/ModuleVersion，但 Form 未傳，沿用預設值；Core `DelFutureHold` 因而以 `(LotNo,OPNo,HoldTime)` 條件對 `TBLWIPFUTUREHOLD` 及 `TBLWIPFUTUREHOLDREASON` 發出兩個 DELETE，再由 `ExecuteSQLNoneQuery_UPD` 執行，Service 記事件。**條件不含 ModuleNo、ModuleVersion、FutureHoldSerial，也沒有 Core 的全範圍 LockFlag 再檢查。** 同鍵有多個 Module/Serial 時，原始按鈕可能刪除其他設定，甚至刪除畫面未選到、已鎖定的同鍵設定。這是來源風險，不把它寫成正確的正式行為。解除只刪未來設定及原因；不是立即解除已生效的 ERF/Hold，也沒有刪 FutureHoldLog。

## 資料結構與 CREATE SQL

主表 `TBLWIPFUTUREHOLD` Oracle DDL 見 `database/reference/mestest_wip_wp201_dependency_source_ddl.sql`，PostgreSQL CREATE-only 見 `mestest_wip_wp201_create.sql`；其六鍵 PK 為 `(LOTNO,MODULENO,MODULEVERSION,OPNO,HOLDTIME,FUTUREHOLDSERIAL)`，`LOCKFLAG` 可空、預設 0。原因表 `TBLWIPFUTUREHOLDREASON` 的 Oracle DDL／metadata 和 PostgreSQL CREATE-only 見 `mestest_wip_wp504_*`，原因表七鍵 PK 另含 HoldItemNo。LotState/LotBasis 與 OP/MClass 目錄的來源與 CREATE refs 均已在既有 WIP/QC/OP 模組。本功能**沒有新直接表**，不另造 CREATE SQL；家用端仍須核對 live PostgreSQL schema/history、部署資料和權限，確實缺表才建 forward migration。

## 公司端 Vue DEV 與家用端 API

Vue 頁 `/YMES/WIP/FutureHoldRelease` 位於 `web/src/components/WipFutureHoldRelease.vue`，共用 WP504 的 DEV localStorage `ymes-dev-mock:wip-future-hold-set:state:v1`。首次無 WP504 暫存資料時提供一筆可解除、一筆鎖定示範；OP/MClass 查找在 DEV 以假設定提供選項。四種勾選過濾、九欄 Grid、單列 Release/Close、WP504 Set 後再 Release 均為前端即時狀態操作。DEV 刪除範圍跟來源 Service 一樣是同 `(LotNo,OPNo,HoldTime)`，但會檢查**整個實際刪除範圍**的 LockFlag，任一鎖定就拒絕；也重新讀本機狀態以防選取已過期。此安全守門是 YMES 修正，非來源 Form 已具備。DEV 不更新真 MES；non-DEV 不讀假資料、不回報假交易。公司端依交接規則只做靜態核對，未執行 build/test/browser。

正式 API：登入與 `WP506` Function ACL、參數化分頁查詢及 OP/MClass 查找，server 解析可見範圍，提供完整複合鍵、LockFlag、版本及用於確認刪除範圍的資料。Release POST 須先決定業務意圖：**精確解除一個六鍵主設定及對應原因**，或保留舊式同 Lot/OP/HoldTime 批量解除。若採精確解除，傳全部鍵並鎖定、重查該設定及其原因；若採批量，明示影響筆數並鎖定/檢查範圍內每筆 LockFlag，任一鎖定即拒絕。兩種都需在單一交易刪主/原因、記錄 actor/事件、支援版本衝突與冪等，不能信任 browser LockFlag，不能用字串拼 SQL。已進入 ERFType3 的 FutureHoldLog/ERF 處置需另依完整生命週期處理，不能用此 DELETE 取代正式異常單解除。完成 PostgreSQL API 後接正式 Vue 並做端到端驗收。
