# WP507 預先等待解除（FUTURE WAIT RELEASE）

## 來源與選單

- WIP → 異常與等待 → 預先等待解除，FunctionNo `FUTURE WAIT RELEASE`、FunctionKey `WP507`、執行檔 `WP_FutureWaitRelease.dll`；目錄見 `docs/MES_MENU_FUNCTION_INVENTORY.md`。
- WinForms `STD/MESWin/WIP/WP_FutureWaitRelease/frmFutureWaitRelease.vb`（內嵌 Designer）；Service `STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `LoadFutureWait`／`DelFutureWait`；Core `STD/MESkc/kcWIP/clsLot.cs` 的同名方法。設定入口是 WP505。

## 原畫面與流程

上方 `Query` 框兩列：第一列 Lot No、OP No，各自有勾選框和文字欄；第二列 Wait Time 勾選框與 Start=`0`／End=`1` 單選。OP No 的 `...` 由 `LoadOPBasis` 查找。Lot No 的 `btnGet` 雖有程式，但 Designer 設 `Visible=False`；隱藏 handler 選 Lot 後又誤把 LotNo 寫到 `txtOPNo`，因此不是實際可用畫面功能。Query 可無條件；Form Load 時 `funLoadFutureWait()` 被註解，按 Query 才從 Service 全量重載，再以本機 DataView 的勾選欄位過濾。勾選 Wait Time 卻沒有選 Start/End 時不加時間條件。

下方 `Future Wait Data` 顯示六欄：Lot No.、OP No.、Wait Time（Start/End）、Description、Creator、Create Date。右側上方 Release、下方 Close (&X)；`Find (&F)` 設 `Visible=False`，handler 也被註解。Grid 的目前 ActiveRow 是唯一 Release 目標。Form 成功後重新載入並依原篩選再 Query。來源 Grid StatusBar 顯示資料筆數。

Release 從選取列取 LotNo、OPNo、WaitTime，呼叫 `wsWIP.DelFutureWait`；Service 解析三值、呼叫 `clsLot.DelFutureWait` 並記 EventLog。Core 將三值組成 DELETE 條件，刪 `TBLWIPFUTUREWAIT`。此表 PK 恰為 `(LOTNO,OPNO,WAITTIME)`，正常完整傳值只刪一筆；來源表沒有 LockFlag，此 Form 也沒有鎖定檢查。Core 的通用方法允許省略部分參數並動態拼條件，若其他呼叫方省鍵可能擴大刪除範圍；正式 API 必須強制三鍵全填、WaitTime 只接受 0/1、用參數化 SQL。此 Release 僅刪未來等待設定，不解目前已生效的 WaitBasis/Lot Wait 狀態，也不回滾已執行流程。

## 資料結構與 CREATE SQL

`TBLWIPFUTUREWAIT` 來源 Oracle DDL 在 `database/reference/mestest_wip_wp201_dependency_source_ddl.sql`，PostgreSQL CREATE-only 在 `mestest_wip_wp201_create.sql`：七欄，PK `(LOTNO,OPNO,WAITTIME)`，Description 可空。OP Basis 目錄沿既有 OP 模組 refs。WP507 沒有新直接表，無需再造 CREATE SQL；家用端需先核 live PostgreSQL schema/migration history，再補實際缺少的 forward migration。

## Vue DEV 與正式 API 交接

公司 Vue DEV 頁 `/YMES/WIP/FutureWaitRelease` 位於 `web/src/components/WipFutureWaitRelease.vue`，共用 WP505 localStorage `ymes-dev-mock:wip-future-wait-set:state:v1`。無 WP505 暫存資料時有兩筆示範；按 Query 以三種可選條件查詢、六欄 Grid，選一筆 Release 後本機刪除並刷新；成功後 WP505 再進頁可見同一份狀態。DEV 重新讀本機狀態，若建立時間或說明與選取時不同就要求重查，避免覆蓋剛修改的假資料。DEV 不呼叫 Oracle/PostgreSQL；non-DEV 禁用假資料與假 Release。公司端依交接規則只做靜態核對，未執行 build/test/browser。

家用端提供登入/`WP507` Function ACL 的三條件候選查詢與 OP lookup；雖然原 Form 允許無條件查全表，正式 API 應限制結果量／分頁和可見資料範圍。Release POST 收完整 LotNo、OPNo、WaitTime 及版本/冪等鍵；server 重查該複合鍵、權限與是否仍屬未來設定，在單一交易刪除、寫 actor/事件並回報不存在或版本衝突。不得相信 browser 顯示列、允許缺鍵造成廣域刪除，或用舊 Core 的字串拼 SQL。WP505 Set／`ChkFutureWait` 生效與 WP502 真 Wait 交易須在生命週期設計中分清楚；API 完成後再接正式 Vue、部署及驗收。
