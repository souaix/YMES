## 主畫面與查詢

Query 六個 checkbox+文字欄：Lot No、Customer No、OP No、MClass No、Cur Group、ERF No；除 Lot No 外各有 `...` lookup。按 Query 可無條件；Form 固定送 `Status=0|1|2|3|11` 及 `ERFSource=0`。Core 查 `TBLWIPERFBASIS A`，連 `TBLWIPLOTSTATE B`（`B.Status IN (3,31)`）、`TBLWIPLOTBASIS C`、`TBLOPBASIS D`、`TBLPRDPRODUCTBASIS E`（現行版）、`TBLENTCUSTOMERBASIS F`；當 Lot/OP/Customer 有條件時，額外搜尋 `TBLWIPERFBATCHLOT` 成員，命中任一成員即返回主 ERF。Lot No 為 contains，其他文字欄為 exact。Form 以 LotNo、ERFNo 排序。原 Core 以拼字串 SQL，正式版必須改參數化及設查詢上限。

Grid 依序 23 欄：Lot No、ERF No、Product No、Product Name、Customer Lot No、Status、OP No、OP Name、Customer No、Customer Name、MClass No、Hold Description、CurGroup No、Disp Description、Rule No、ERF Create Qty、ERF Record Qty、ERF Cur Qty、Cal Hold Time、Priority、Batch Lot、Creator、CreateDate。`ERF Record Qty` 取原 `ScrapQty`；`Cal Hold Time` 為 CreateDate 起至現在/ReleaseDate 的分鐘數。右側按鈕 ERF Disp、ERF Abort、ERF Create、ERF Info，另有 Close。

### 四個入口

- **ERF Disp**：一般單檢查登入人是否屬 `CurGroupNo`，逗號分隔的多群組可任一命中。OCAP 單先載入未完成 OCAP state，開 `WP_OCAPProcessShow`；And/Or 群組若有多子節點，再經 `WP_OCAPProcessDraw` 選節點。原 Form 於 2025 修改後將 `boolIsTheFinalGroup=True`，因此 Final Disposition radio 不再因主分類最後群組而禁用。
- **ERF Abort**：有 OCAP state 禁止作廢；檢查目前 `CurGroupNo` 的群組權限（原碼此處是**單一字串精確比對**，與 ERF Disp 的逗號處理不同），要求使用者確認。`ERFType=6` 呼叫 `wsWIP.Exe_ERF_Abort_Batch`，否則傳 `LotStamp` 呼叫 `wsWIP.Exe_ERF_Abort`。Complete Lot 可能再觸發 `BRTransferLot`。正式版應以可審核的 policy 明定多群組語義，並防止先 Abort 成功、後 Transfer 失敗卻誤報全成功。
- **ERF Create**：由所選 Lot/RuleNo 開 `WP_BRERFCreate`，固定 `ERFType=5`（ReCreate），原 Form 同樣以 CurGroupNo 精確比對。它不是複製一列 ERF；須由開單規則、流水號及 Hold 副作用處理。
- **ERF Info**：開 `WP_ERFInformation` 唯讀五頁。完整 Info 詳見 WP508「異常單資料」與其附屬 Form 規格。

## 處置子畫面

子畫面顯示 ERFBasis、Hold Item、附件及兩頁：`ERF Disposition`、`Lot Disposition`。狀態 **0/1/2/3** 可進 ERF Disposition，Lot Disposition 禁用；狀態 **11** 可進 Lot Disposition，ERF Disposition 禁用。ERF Disposition 需 Disp Description，選 `Next Group`（DispType=0，下一群組必填）、`Notice Customer`（1，聯絡人必填）、`Final Disposition`（2，Final Group 必填）；`Waive`（3）存在原始程式但畫面隱藏。OCAP 需另填處置結果、檢查節點/連結與最後節點，再呼叫 `THEIL.wsWIP_ERF.Exe_ERF_Disposition`；同時有 Hold Reason Disp、附件及可能的通知/OCAP狀態寫入。Next/Notice/Final 造成的下一狀態需依 Service/Core 判定；DEV 用 1/2/11 示意。

Lot Disposition 原畫面可見 14 種：Split、Merge、Back to ERFDisposition、Qty Adjust、Scrap、WithDrawWork、Go、Jump OP、Jump Main、Jump Process、Jump Module、Semi Inventory、Scrap Inventory、Process Tuning。`Change ENGNo` 原控制存在但隱藏。`ERFType=6` 隱藏 Scrap、WithDrawWork。ReleaseType：Go=0、Jump OP=1、Jump Process=2、Semi Inventory=3、Process Tuning=4、Jump Module=6、Scrap Inventory=7、Jump Main=8、Back=11、Split=12、Merge=13、Qty Adjust=14、Scrap=98、WithDrawWork=99；Split/Merge/QtyAdjust/Back 走各自子窗或 Service，不可當一般 ReleaseType=12/13/14 送解除。目標 Process/OP、返回 OP、Module/Version、Inventory 與 Release Disp 隨選項動態呈現，原 lookup 同時提供內部 NodeId/Version 等鍵。

`LoadDispPriv("ERF")` 從 `XX_TBLQCHOLDPRIV` 取目前使用者 `TBLUSRUSERGROUP` 的全部 GroupNo：各旗標任一列為 1 即允許對應選項，沒有權限列則全部禁用；Jump Process 再分 `JUMP_PROCESS_01`（不返回）與 `_02`（返回）。此外，`LotDispTypeLimit` 非空時按型別限縮；在 Module (`OPReference=1`) 或不在主 Process/Version 禁 Jump Process；Bin/Component 禁 Qty Adjust；`CreateERF=0` 禁 Back；OCAP 禁 Split/Merge/Back/Qty Adjust；Stocker Lot 禁 Split/Merge；`PartialMode=1` 的原 `funDisableControlForPartial` 只保留 Go（其他列舉控制被禁用，Back/Scrap/WithDrawWork 在該函式未列入，需與其他守門合併評估）。正式 API 每次 command 都要重查功能 ACL、群組權限、ERF/Lot state、LotDispTypeLimit 與目標路由，不能信前端 disabled。

一般解除依 `ERFType=6` 分 `wsWIP.Exe_ERF_LotRelease_Batch` 與 `THEIL.wsWIP_ERF.Exe_ERF_LotRelease`，執行 `clsLot_ERF.UpdERF_LotRelease`/批次 Core，寫 ERF Lot Disposition、ERF Basis/Batch、LotState/Log、Reverse/Inventory/路由和可能的 Transfer/ProductChange。Back 走 `wsWIP.Exe_ERF_BackToERFDisposition`。Qty Adjust 先開 `WP_LotQtyAdjust_{Bin,Comp,standard}`，再 `wsWIP.Exe_ERF_QtyAdjustLog`。Split/Merge 依 GoodBinState → Bin、否則 HaveComponent + CarrierNo → Carrier Split/Component，否則一般；Merge 無 Carrier 專窗。七個子窗有自己的數量、元件、Bin、Carrier、Lot/ERF 交易，不能由主頁單一數字框替代。

## Oracle DDL 與 PostgreSQL CREATE-only

本次公司端在 PowerShell 5.1 使用受保護 Oracle profile 與 `Oracle.ManagedDataAccess.dll`，只讀 `DBMS_METADATA.GET_DDL` 和 `ALL_TAB_COLUMNS`/`ALL_CONSTRAINTS`/`ALL_INDEXES`/`ALL_TRIGGERS`，直接查得 **`MESTEST.XX_TBLQCHOLDPRIV`**：18 欄、全部 NOT NULL、15 個 `NUMBER(1,0) DEFAULT 0` 權限旗標，`GROUPNO` 主鍵/唯一索引，無 FK/trigger。交付 `database/reference/mestest_wip_wp509_priv_source_ddl.sql`、`_source_indexes.sql`、`_metadata.txt`、`_create.sql`；後者為 PostgreSQL 空表 CREATE-only 參考，不是已套用 migration。主 ERF/Batch/Lot 表沿 WP508/QC409/WP501 的 Oracle/PG references；ERF LotDisposition 沿 WP508 Info，使用者群組沿設備工程群組。家用端先核 PostgreSQL live schema/history，再僅對缺項寫 forward migration。公司端未查 Oracle 業務列、未寫 Oracle、未連 YMES PostgreSQL，未提交連線秘密。
