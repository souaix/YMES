# WP916 生產批強制結批作業

- `CLOSE LOT FORCIBLY` 對應 `STD/MESWin/WIP/WP_CloseLotForcibly/frmWIPCloseLotForcibly.vb` 與內嵌 Designer。至少勾選產品、工單、作業站之一，以上任一勾選時必填。 `wsWIP.LoadLotBasisJoinState` 只取排隊 Status=0。結批僅允許一批，確認後先 `CheckLotPackage`，再傳 lotNo、status=301、OPNo、MONo、productNo、areaNo 至 `UpdCloseLotForcibly`。
- STD `wsWIP.UpdCloseLotForcibly` 以當下 LotSerial 呼叫 `kcWIP.clsLot.EndOP` 組合出站，接著 `clsLot.UpdCloseLotForcibly`，以同一 SQL 集合核對影響列數。Core 重查排隊及站別，更新 LotBasis.LotState=301，呼叫 `CloseLot` 清流程與暫存，解除載具及儲位、記 StockerDetailLog、回補 MO 的未下線量與物料，按元件／原料及來源分支記用料返還。最後檢查 LotStamp 和記事件。
- 主表依 [WP101](../../../database/reference/mestest_wip_wp101_create.sql)、[WP201](../../../database/reference/mestest_wip_wp201_create.sql)、[WP902](../../../database/reference/mestest_wip_wp902_create.sql) 等既有參考。[WP916 metadata](../../../database/reference/mestest_wip_wp916_metadata.txt) 與 [CREATE-only](../../../database/reference/mestest_wip_wp916_create.sql) 包含共有 CloseLot 尚未有 CREATE 的即時及歷史備份表。家用端應逐分支核實備份表啟用條件、欄位預設和 BYTE 語意，並核對 EndOP 依賴。

## DEV 與交接

- `/YMES/WIP/CloseLotForcibly` 提供三種勾選項、單批選擇、包裝守門、確認及移出排隊列表；DEV-CLOSE002 展示包裝阻擋。301 只標記假批，本頁不模擬工單、物料、庫存、出站及備份清理，重載復原。
- 建議 WP916 ACL 的排隊候選查詢、預覽與單批 `POST /api/wip/lots/{lotNo}/force-close`，重讀權限、包裝、批現況、OPNo、LotStamp 及受影響的工單、材料與載具。EndOP、301、清理、回補、稽核做成同一交易，防重避免二次回補，結果回傳已更新狀態及交易號。
