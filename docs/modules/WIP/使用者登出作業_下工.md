## WinForms 畫面與互動

- Form 標題 `Operator Clockout`。上方員工資訊區包含 EmployeeNo、Password、EmployeeName、ShiftNo、LogoutDate；EmployeeName／ShiftNo／LogoutDate 唯讀。Password 是否顯示由 `WIPChkPassword` 控制，啟用時透過 `wsUSR.ChkUserPassword` 驗證。
- Form_Load 初始化 Grid，並呼叫 `LoadOperatorState`（空 UserNo）先載入現況。輸入員工編號並按 Enter（密碼啟用時需先驗證）後，讀 User Security、刷新該員工現況，LogoutDate 設為 AP Server 時間。
- Grid 只顯示 CheckFlag、ShiftNo、LoginDate、WorkDate、OPNo、LoginPlaceNo；UserNo、UserName、MultiOperatorMode 等仍留在資料列供提交使用。CheckFlag 預設為 1，因此查得的列預設全部勾選；使用者可逐筆取消。
- 按鈕只有 SignOut、Close。SignOut 至少要有已載入員工和一筆勾選現況，先顯示確認對話框（預設 Cancel），確認後才逐列執行。執行成功後清除員工欄位，並以空 UserNo 重載現況清單。
- DEV 頁使用 WP104 共用的假員工、假密碼、假上工狀態與 localStorage；支援查看／勾選多筆現況、按員工篩選、下工前確認、模擬下工歷程。不呼叫 Production API 或更新真實狀態。

## 下工交易規則

- 每筆勾選資料各呼叫一次 `wsWIP_OperatorState.ExecuteClockOut`，參數為該資料的 UserNo、AP Server LogoutDate、LoginPlaceNo、MultiOperatorMode。Form 逐列依序呼叫，任一列失敗即停止；前面成功的列不回滾，Finally 依 Reload 狀態重讀現況。這是來源的部分成功行為。
- Core 依 `UserNo + LoginPlaceNo + MultiOperatorMode` 取現況。每筆寫入 `TBLWIPOPERATORLOG`（SID、登入／登出時間、WorkDate、OP、Mode、Place、WorkTime 等），WorkTime 以登入到登出的分鐘差計算；再刪除 `TBLWIPOPERATORSTATE` 現況列。
- 啟用多人加工時，`funSHR_CO_EMP_ClockOut` 找出該 UserNo + LoginPlaceNo 且尚未 Checkout 的 `TBLWIPLOTLOGINSTATE`。一般 mode 更新 CheckoutTime、COCreator、COCreateDate；mode 5 走 Lot Login state 的 `EditLotLoginState`，並可能 reverse 同次 OperatorLog。這是同一 Core SQL collection 的 side effect，不可只刪 OperatorState。
- WinForms LogoutDate 使用 AP Server 時間且唯讀；Production API 以伺服器時間產生日誌，不應接受 browser 端自行指定未來或回填時間。`ExecuteClockOut` 的一次呼叫只能處理指定使用者／Place／Mode，不能讓前端傳入任意 UserNo。

## 資料表與家用端 API handoff

- WP105 不新增資料表。`TBLWIPOPERATORSTATE` 與 `TBLWIPOPERATORLOG` 的 Oracle source／metadata／CREATE-only 已在 `database/reference/mestest_wip_wp104_*`；LotLoginState 的 Oracle source／metadata／CREATE-only 沿用 WP305 references。其他 User、Shift、OP、Group/Privilege、System Parameter 等沿用共用 schema。
- 與 WP104 共用密碼驗證 challenge。建議以登入保護 API 讀取 challenge 限定員工的 clock-in states，回傳 Grid 所需欄位與可用 key；不應提供讀取全廠所有員工現況的公開端點。
- 建議逐列 `POST /api/wip/operator-clock-outs/close`，body 僅送 challenge token 與已查得 state 的 key (`multiOperatorMode`,`loginPlaceNo`)；UserNo 由 challenge 確定。Server 在交易中重讀／鎖定狀態，新增 Log、刪除 State，並同步 LotLoginState side effects。
- 為維持來源行為，多筆選取可由 Vue 依序呼叫逐列 API，遇錯停止並顯示已完成／失敗／未處理筆數；前項成功不回滾。每一筆 API command 本身須原子、冪等並避免同一現況被併發重複下工。
- CREATE-only 不能直接當 migration。家用端先查 YMES PostgreSQL live schema/migration，重用 WP104／WP305 的現有 reference，不能重複 CREATE。
