# WP205 生產批選用生產設備

## 功能識別

- 第一層：在製品管理（WIP）
- 第二層：生產報工（LOTEXECUTE）
- 功能：生產批選用生產設備
- FunctionNo：`LOT CHOICE EQP`
- FunctionKey：`WP205`
- Form／DLL：`frmLotChoiceEqp`／`WP_LotChoiceEqp.dll`
- ExecutionMode：0
- Vue DEV 路徑：`/YMES/WIP/LotChoiceEquipment`

## WinForms 畫面與操作

來源為 `STD/MESWin/WIP/WP_LotChoiceEqp/frmLotChoiceEqp.vb`。表單標題 `Lot Choice EQP`，大小約 540×205，畫面只有一個 `Input Data` 群組及 Confirm／Close：

| 欄位／按鈕 | WinForms 行為 |
| --- | --- |
| Lot No | 可輸入；Enter 或離開欄位時查詢，文字轉大寫。查 `LoadLotBasisJoinState(LotNo, Status=1)`。 |
| EquipmentNo | 唯讀；`...` 多選可執行設備，`Area EQP` 只檢視該 Lot 區域全部設備與可用狀態。 |
| LoadPortPosition | 唯讀；`...` 只選空 Port，`LoadPort` 檢視所有 Port 及其 Lot。 |
| Confirm | Lot 通過可選機檢查後即啟用；點擊時再驗證至少有一台 Equipment，執行選用 Service 後關閉視窗。 |
| Close | 關閉而不執行選機。 |

表單載入時設備／Port／Confirm 操作均停用。只有 Lot 存在、`OPStatus=1`、Area 查得到設備且 Lot 尚無上機設備時才開放選機。若 Lot 已上設備、非站中或無區域設備，WinForms 顯示不可選機訊息。

設備選取視窗欄位為 EquipmentNo、Capacity、EQPLoadPort、AllowExecute、Description；只有 `AllowExecute=1` 的列能從設備選取器加入。2019-09 後可以多選設備，但多選時會清空且不提供 LoadPort。只選一台且 `EQPLoadPort>0` 才開啟 Port 查找。Port 編號依來源補出 `0` 至 `EQPLoadPort-1` 的空位；`...` 僅列 `LotNo IS NULL`，`LoadPort` 顯示空／占用狀態。LoadPort 是可選欄位，WinForms 註解明確表示不強迫選 Port。

## Service／Core 與資料流程

1. `wsWIP.LoadLotBasisJoinState` 以 LotNo、Status=1 取得 LotState，表單使用 `LotStamp`、`OPStatus`。
2. `wsWIP.LoadAvailableEquipment_All` 呼叫 `clsLot.ShowAvailableEquipment_All`，依 Lot 的 Area、產品／製程及設備條件列出設備，計算 `AllowExecute`。Core 包含設備核准／開關、狀態、Equipment Capability、Capacity（-1 表示不限）、目前設備負載及 LoadPort 容量等檢查；不可由瀏覽器自行判定正式可用性。
3. `wsWIP.LoadTemp_Equipment(LotNo)` 檢查 Lot 是否已有設備；另一個 `LoadTemp_Equipment(EquipmentNo)` 查設備上 Lot 與 LoadPort 占用狀態。
4. `wsWIP.Exe_LotChoiceEQP` 接收 LotNo、LotStamp 與一或多筆 `{EquipmentNo, LoadPort?}`。`clsLot.Exe_LotChoiceEQP` 讀取 LotState／Temp LotState，呼叫 `SHR_CIEquipment`，再呼叫 `clsOperatorState.SHR_CI_EMP`（Mode=1、MultiOperatorMode=5），最後用 `ChkLotStamp` 檢查版本並提交交易。

正式 API 必須在伺服器重新查 LotStamp、站中狀態、設備可用性、容量、LoadPort 空間及 Lot 是否已上機；在同一交易執行設備暫存指派與多人加工上工副作用。不能信任 Vue 傳回的 `AllowExecute` 或 port 空位，也不能將瀏覽器 localStorage 當正式狀態。

## 公司端 Vue DEV

`web/src/components/WipLotChoiceEquipment.vue` 以 WinForms 三列欄位、設備多選、Area EQP 檢視、Port 可用／占用清單及 Confirm／Close 呈現。Lot No 按 Enter 或離開欄位執行假查詢；提供三筆明確標示 DEV 的 Lot 例子，包含可選、非站中及已上機狀態。只選一台設備時才可查詢 Port；多選時移除 Port；Confirm 寫入 DEV 假指派並顯示結果。

假指派僅存在 `ymes-dev-mock:wip-lot-choice-equipment:assignments:v1`，不能作為 Production/API 資料。資料庫或 API 尚未由公司端更改。

## 資料表與 DDL

本功能沒有專用新表，不新增 Oracle source DDL 或 PostgreSQL CREATE SQL。流程重用 `TBLWIPLOTSTATE`、`TBLWIPTEMP_LOTSTATE`、`TBLWIPTEMP_EQUIPMENT`、Equipment／EMS 狀態、Area Equipment Relation／Equipment Group，以及產品 OP Capability 相關既有表。Lot／Temp LotState DDL 由 WP101／WP201 references 管理；設備、設備狀態及 `TBLWIPTEMP_EQUIPMENT` 以 WP204 已交付的共用 references 為準。家用端先核對 YMES PostgreSQL live schema 與 migration history，不為 WP205 重複建表。

## 家用端 API handoff

- 將 `LoadLotBasisJoinState`、`LoadAvailableEquipment_All` 與設備 LoadPort 現況整理成登入保護的唯讀查詢；範圍限制在使用者可操作的 Area。
- 建立登入保護的設備選用 POST command，請求包含 LotNo、讀取時的 LotStamp、EquipmentNo 清單及可選 LoadPort。Server 需在交易內重讀並驗證整個來源守門條件，再重用 WP201/WP204 的設備進站核心；成功才提交，任一步失敗都 rollback。
- 不新增 WP205 migration，除非 live schema 核對發現共用來源表確實不存在；也不新增臆測的唯一鍵。`TBLWIPTEMP_EQUIPMENT` 為多交易共用設備占用資訊，需在交易中鎖定或用等效方式避免並行搶占設備／Port。
- UI 權限以登入者可用的 WIP Function `WP205` 與 Area 權限控制，API 以參數化查詢、穩定回應及操作紀錄處理。`LotStamp` 必須做併發版本檢查。

## 本輪界線

只依 WinForms／Service／Core 原始碼完成公司端假資料互動與規格；沒有查 Oracle 業務資料列、執行 DDL/DML、連 YMES PostgreSQL、實作 Production API、執行 build/test 或開瀏覽器。WP205 未產生新的 CREATE SQL，因它只重用已存在的共用表。
