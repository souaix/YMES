# 批次作業員上工（Lot Operator Clockin）

## 功能身分與來源

| 項目 | 來源 |
|---|---|
| WinForms 標題 | `Lot Operator Clockin` |
| WinForms | `STD/MESWin/WIP/WP_LotOperatorClockIn/frmLotOperatorClockIn.vb`、Designer 同目錄 |
| Service | `wsOP.LoadOPBasis`、`wsPRS.LoadProductionSegment`、`wsUSR.GetParameter`／`LoadUserSecurity`／`LoadShiftBasis`／`ChkUserPassword`、`wsWIP_OperatorState.LoadOperatorStatejoinLotInfo`／`ExecuteClockIn_Batch` |
| Core | `STD/MESkc/kcWIP/clsOperatorState.LoadOperatorStatejoinLotInfo`、`ExecuteClockIn_Batch`、`CheckOPPrivileged`、`GetClockIn_AutoClockOut`、`funSHR_CI_EMP_ClockIn` |

WinForms 將 `PrivFunNo` 由外部載入，Form 原始碼未包含數值 FunctionKey 或完整 FunctionNo。App 的 fallback 目前使用標題推導的 `LOT OPERATOR CLOCKIN` 方便預覽；正式選單接線前須以實際 menu/function metadata 確認識別碼，不把推導值當成已核實的資料庫設定。

## WinForms 畫面與操作

- `Employee Info` 有 EmployeeNo、EmployeeName、Password、ShiftNo、WorkDay。EmployeeName／ShiftNo 唯讀；Password 由 `WIPChkPassword` 控制。WorkDay 依員工班別起訖時間預設，使用者可調整。
- `Query Condition` 有 LotStatus（預設 Running=1）、Clock Status（預設 All=0）、PSNo、OPNo、PS/OP `...` 查詢及 Query。OP lookup 在已指定 PSNo 時按 PSNo 篩選。Form_Load 不自動查詢；查詢需按 Query。
- Grid 預設將查回列全部勾選，可按 Select All／UnSelect All。欄序：CheckFlag、LotNo、Status、PSNo、OPNo、EquipmentNo、LoginPlaceNo、UserNo、UserName、LoginDate。底部按鈕為 Clock In、Close。
- DEV 使用 WP104／WP105 相同的員工、假密碼及 OperatorState／OperatorLog localStorage；查詢列是固定假 Lot。假頁只寫瀏覽器假資料，不呼叫 Production API。DEV 將自動下工參數固定為 0，未連 server 參數；正式 Core 會依 `CLOCKIN_AUTOCLOCKOUT` 執行模式 1/2 的自動下工。

## 查詢與批次上工邏輯

1. `LoadOperatorStatejoinLotInfo` 接收 LotStatus、ClockStatus、PSNo、OPNo。ClockStatus=0 不限；1 限 `LoginPlaceNo IS NOT NULL`；2 限 `LoginPlaceNo IS NULL`。結果依 PSNo、OPNo、LotNo 排序。Form 對每列附加 CheckFlag，預設 True。
2. Core 依 LotState 與 OP Basis 的 MultiOperatorMode、PartialMode 組查詢，並依 mode 0/1/2 展開作業站、Area、Equipment 上工地點。設備 mode 會使用 OP Area、Equipment/Group 與 `TBLWIPTEMP_EQUIPMENT` 關係。此查詢是 WinForms 實際 service/core 行為；不能以 Vue 假資料的簡化 join 取代正式 SQL。
3. 輸入員工編號後，依 `WIPChkPassword` 驗證密碼，讀取 User Security 與 Shift 起訖時間；只有員工、班別有效後 Clock In 才啟用。上工時間由 server 取得。
4. Clock In 僅提交勾選列。Form 先按 OP／登入地點彙整，不是每個 Lot 寫一筆 OperatorState。mode 0 轉成 `(OPNo, LoginPlaceNo)=(該 OP, 該 OP)`；mode 1 使用 Area 作為地點；mode 2 使用 Equipment 作為地點，兩者 OPNo 留空並由 Core 正規化為 `N/A`。同一員工已在相同 mode/place 上工的群組會略過；若沒有任何新群組則顯示已上工錯誤。
5. Service 一次呼叫 `ExecuteClockIn_Batch`，傳員工、AP Server LoginDate、WorkDate 及彙整後批次資料。Core 重新檢查 User／Shift、匿名 UserLevel=3、LoginDate 不可晚於 server time、OP privilege；依 `CLOCKIN_AUTOCLOCKOUT` 可能先產生下工 SQL，再為每個地點新增 OperatorState 並呼叫多人加工 `funSHR_CI_EMP_ClockIn`。
6. 成功後整個 Form 初始化，清除員工、WorkDay 與查詢結果。來源沒有額外的 WorkDay ±1 日檢核；正式 API 若新增限制，須明確列為行為修正並與舊系統確認。

## 資料表與 Oracle reference

- 本功能沒有新增專用資料表。OperatorState／OperatorLog 來源 DDL、欄位 metadata、PK/index 及 PostgreSQL CREATE-only 沿用 `database/reference/mestest_wip_wp104_*`；LotLoginState 沿用 WP305 references。
- 查詢及權限檢核重用 LotState、OP Basis／OP Area、Production Segment、Area/Equipment/Equipment Group、Temporary Equipment、User/Shift、Group/Privilege、System Parameter 等既有 MES 結構。家用端須先對照 YMES PostgreSQL live schema/migration，不可重複建表。
- Oracle `TBLWIPOPERATORSTATE` 已核對欄位沒有 `POSITIONNO`。本 Form 批次資料只傳 OPNo、LoginPlaceNo、MultiOperatorMode，Core `PositionNo` 為空，因此走不含 POSITIONNO 的 insert 分支；不要因 Core 同一方法另有可選工位分支而自行改造這張表。

## 家用端 API handoff

- `GET /api/wip/lot-operator-clock-ins/lots`：登入授權、參數化 LotStatus/ClockStatus/PSNo/OPNo 查詢，重現 Core 的 MultiOperatorMode、PartialMode、Area/Equipment/TempEquipment mapping，穩定排序並分頁。需由 server 限制使用者可見的 Lot/OP 範圍；不可把前端傳回的 lot row 當成權限或地點依據。
- 員工驗證沿用 WP104 的短效 challenge；`POST /api/wip/lot-operator-clock-ins` 只收 challenge、WorkDay 及選取的 LotNo。Server 重查 LotState、OP Basis、mode/place、現況、User/Shift、Privilege、System Parameter，從查詢結果彙整唯一登入地點，不接受 browser 自帶的 OPNo、mode、LoginPlace、UserLevel、ShiftNo 或 LoginDate。
- 同一 command 內依 `CLOCKIN_AUTOCLOCKOUT` 做必要下工、寫 OperatorLog/OperatorState 並同步 LotLoginState side effects；使用伺服器時間、交易、鎖與冪等鍵。需保留批次整體錯誤結果，不可回傳部分成功而忽略先前自動下工或多人加工副作用。
- 公司端尚未做 PostgreSQL/API；CREATE-only 不代表要新增表，本功能沿用 WP104/WP305 references。

## DEV 限制

Lot、OP、PS、班別與人員皆為固定假資料；DEV Clock In 依所選 Lot 對應的作業站模式彙整唯一 location，並和 WP104／WP105 共用假現況。上工系統參數在 DEV 不連 Server，無法驗證正式 `CLOCKIN_AUTOCLOCKOUT` 值；數值 FunctionKey 也需實際選單 metadata 核實。未連 YMES PostgreSQL、未執行 Oracle DDL/DML、build、test 或 browser。
