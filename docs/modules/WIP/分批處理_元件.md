# WP208 分批處理_元件（LOT SPLIT_COMP）

## 功能與原始來源

- 選單：在製品管理 → 生產報工 → 分批處理_元件；FunctionNo `LOT SPLIT_COMP`、FunctionKey `WP208`、DLL `BR_LC_Split_GEN.dll`，以 `docs/MES_MENU_FUNCTION_INVENTORY.md` 的原生 menu metadata 為準。
- WinForms：`STD/MESWin/BR/BR_LC_Split_GEN/frmBR_LC_Split_GEN.vb`，Form 類名 `frmBR_LC_Split_GEN`，標題 `Lot Split Have Component`。元件選取視窗：`STD/MESWin/WIP/WP_LotSplit_ComponentSelect/frmLotSplit_ComponentSelect.vb`。這是獨立於 WP207 `LOT SPLIT` 的 Form。
- Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `Exe_Manual_LotSplit_Component`；LotStamp 由 `ChkLotStamp` 檢查，預覽與保留批號用 `wsSYS.GetSplitLotNo_Multiple`。
- Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `BR_Manual_LotSplit_Component`。Vue DEV 路由 `/YMES/WIP/LotSplitComponent`，元件 `web/src/components/WipLotSplitComponent.vue`。

## WinForms 畫面

Form ClientSize `1008×661`。上方 `MLot` 群組位於 `(9,6)`、約 `989×186`，包含 Lot No 黃色輸入與主批 Grid。未由宿主傳入 LotNo 時，Load 不預先查全表；輸入 LotNo 按 Enter 讀取。一般模式 Grid 顯示 LotNo、CurQty、ProcessNo、OPNo、OPName、BaseLotNo、OrgLotNo、ProductNo／Version 等。Vue DEV 因可獨立導覽而加一個明確 Query 按鈕。

下方 `Split` 群組約 `989×405`，上列為 Split by Count／Split by Qty、Split Count / Qty，下列為 Include Mother Lot No（**No 預設，Yes 可選**）、`Split`、`Select Comp`、`Change Routing`。左側 SplitLot Grid 約 790 寬，右側 ComponentList Grid 約 168 寬，只列出目前選取子批的 ComponentNo；底部 `Confirm`、`Close`。SplitLot 可見欄位：SplitLotNo、SplitLotQty（唯讀）、Action、ProcessNo／Version（唯讀）、OPNo（唯讀）、ReturnType、ProductNo／Version。NodeID、ECNNo／Type、ToDeviceNo 是內部欄位。頂層 Change Product 按鈕 Designer 隱藏；真正產品選擇入口在 ProductNo cell，僅 `AllowLotProductChange` 非 0 時可按。

`Select Comp` 呼叫的 `Lot Split Component Select` 對話框有 CheckFlag、ComponentNo、Select All、Confirm、Close。WIP Inventory 宿主模式將 Change Routing／Change Product 隱藏，並將分批表的 Action／流程／OP／ReturnType 欄位隱藏；只讀取指定 InventoryNo 內元件。此宿主不是選單直接開啟時的預設模式。

## 查詢、拆批及元件分配

1. `funLoadLotState` 使用 `LoadLotBasisJoinState`，條件 Status `0|1|4`、HaveComponent=1、LotState=1、ShowPartialLot=False、StockerLot=False。查到 Status=4 Complete 時 Form 明確拒絕。`funLoadComponentState` 載入母批 ComponentState；WIP Inventory 宿主另依 `TBLINVWIPINVENTORY_COMPONENT.InventoryNo` 篩選。資料進暫存表時每件 `SplitLotNo='N/A'`、`CheckFlag=False`。
2. 按 Split 前檢查 Lot 存在、CurQty 不為 1、分批模式與正數。並檢查 Lot 是否在 CarrierState 或 CarrierStateDetail；若在載具中，轉用 `LOT SPLIT_CARRIER`。按 Split 會清掉舊元件分配。Count 模式以整數均分、最後一列吸收餘數；Qty 模式建立滿額列及餘數列。Yes 將母批號作第一列，No 全部使用新子批號。每列先預填 SplitLotQty，預設 Action=Go、ReturnType=Not Return、原產品／版次。子批號先由 `GetSplitLotNo_Multiple(False)` 預覽；正式 API 不可相信前端預覽序號。
3. 選定分批列後，右側 ComponentList 只顯示該列元件。Select Comp 對話框只列 `SplitLotNo=目前子批` 或 `N/A` 的元件；屬於其他子批者不可從此對話框直接搶走。Select All 只切換當前可見件。Confirm 拒絕「當前勾選數 = 母批 CurQty」。當前可見件：勾選者指派至目前子批，未勾選者改回 `N/A`；其他子批的元件不動。返回後用目前子批已指派件數覆寫其 SplitLotQty。Close 不改分配。
4. Action 0=Go、1=Jump OP、2=Jump Process。Change Routing 呼叫 `WP_LotSplitProcessDraw`（ECN active 時 `_ECN`）並回填 ProcessNo／Version、OPNo、NodeID；直接改 Action 會清空已選路由。ReturnType 0=Not Return、1=Return to Current OP、2=Return to Next OP；Go 與 Jump OP 必須為 0，Jump Process 可選 0／1／2。Jump OP／Process 需要 NodeID。產品變更依 `AllowLotProductChange` 與 MES／ERP 產品來源；變更後 `ReturnSelectProcess` 清 Action／路由／NodeID。來源 Core 已移除「母批列只能 Go」的舊限制，不能自行加回。
5. Confirm 要求每列至少一件，分配件數正好等於該列 SplitLotQty；Form 呼叫 `ChkLotStamp`，比較預覽批號與最新號，再用 `GetSplitLotNo_Multiple(True)` 保留，將 SplitType、LotStamp、各列及 `{splitLotNo,componentNo}` 對應傳入 Service。Core 再查原始 Lot、元件完整性、每子批至少一件與 SplitLotQty 合計等於母批 CurQty（Inventory 模式用該庫可拆數量）。**正式 API 應在交易內重查，避免元件跨子批重複、漏件、跨庫或舊 LotStamp。**
6. `SplitMergeType=0` 是選單手動模式；`1` 是 BR 宿主模式，Service／Core 改變狀態並在成功後對未改產品／流程的 Go 子批呼叫 `BRTransferLot`。手動模式若啟用 SEMI_Wafer 行業包，Form 另依每件 `S_BatchID`、母批 Running 與 `BRNo` 前綴 `LC_CI` 判斷是否更新子批狀態並 TransferLot。這些是標準拆批後的後續動作；家用端需評估部分成功、冪等與重試，不可只做主批 CRUD。Form 成功後會停用 Confirm 並關閉，避免同一 BR 重做。

## 資料表與 CREATE SQL

`BR_Manual_LotSplit_Component` 直接出現 27 張表：`TBLEMSDISPATCHSTATE`、`TBLINVWIPINVENTORY_COMPONENT`、`TBLINVWIPINVENTORY_SEMI`、`TBLPRDOPATTRIB`、`TBLPRDPRODUCTBASIS`、`TBLSYSFUNCTION`、`TBLSYSLOTPROPERTYBASIS`、`TBLSYSPARAMETER`、`TBLWIPAUTOMERGE`、`TBLWIPCOMPONENTPROPERTY`、`TBLWIPCOMPONENTSTATE`、`TBLWIPCONT_ATTRIB`、`TBLWIPCONT_COMPONENTATTRIB`、`TBLWIPCONT_EMPLOYEE`、`TBLWIPCONT_EQUIPMENT`、`TBLWIPLOTBASIS`、`TBLWIPLOTLOG`、`TBLWIPLOTLOG_REPORT`、`TBLWIPLOTOPECNRECORD`、`TBLWIPLOTPROPERTY`、`TBLWIPLOTSTATE`、`TBLWIPOSBASIS`、`TBLWIPOSDETAIL`、`TBLWIPTEMP_ATTRIB`、`TBLWIPTEMP_COMPONENTATTRIB`、`TBLWIPTEMP_EQUIPMENT`、`TBLWIPTEMP_LOTSTATE`。

靜態盤點發現 `TBLSYSPARAMETER` 原先只有模組文字說明，**缺少 SQL reference**。已用公司本機受保護 Oracle profile 與 PowerShell 5.1 唯讀查 MESTEST 的 `DBMS_METADATA.GET_DDL` 及 `ALL_TAB_COLUMNS`／`ALL_CONSTRAINTS`／`ALL_INDEXES`／`ALL_TRIGGERS`。原始 DDL、index DDL、metadata 與 PostgreSQL CREATE-only 新增於 `database/reference/mestest_wip_wp208_source_ddl.sql`、`mestest_wip_wp208_source_indexes.sql`、`mestest_wip_wp208_metadata.txt`、`mestest_wip_wp208_create.sql`。原表有 25 欄，`PARAMETERNO` 是單欄 PK，`PARAMETERTYPE`、`PARAMETERNO`、`PARAMETERVALUE`、`PARAMETERVISABLE` 為 NOT NULL；`PARAMETERVISABLE`、`PARAMETERORDER`、`ENCRYPTIONFLAG` 等有來源 default 0。無 FK、trigger 或非 PK index。這張表也被其他系統功能共用，家用端必須先查 live schema，不能因 WP208 新 reference 就重建已有表。

其餘 26 張 Core 直接表已有 Oracle source DDL／PostgreSQL CREATE-only refs，不複製出一套重複 SQL：

| 結構 | 已交付 reference |
| --- | --- |
| Lot／ComponentState 主體 | `database/reference/mestest_wip_wp101_*`、`mestest_wip_wp201_*` |
| ComponentProperty、Cont／Temp ComponentAttrib、Temp Equipment 等 | `database/reference/mestest_wip_wp201_*` |
| `TBLINVWIPINVENTORY_COMPONENT` | `database/reference/mestest_wip_wp603_*` |
| `TBLWIPCONT_EQUIPMENT` | `database/reference/mestest_wip_wp305_*`，原生無 PK／unique index |
| `TBLSYSPARAMETER` | **本輪新增** `database/reference/mestest_wip_wp208_*`；PK `PARAMETERNO` |
| 派工、AutoMerge、Cont Employee、Lot OP ECN、OS 主從六表 | `database/reference/mestest_wip_wp207_*`，其中 `TBLWIPCONT_EMPLOYEE` 原生無 PK／unique index |
| Process／Product／System 共用表 | WP201 與既有主檔、Operation/System references；依各表 metadata 查對 |

以上只確認 **Core 方法字面直接引用**；Core 呼叫的 helper 可能另觸及共用表，家用端移植交易時須逐層查。PostgreSQL live schema／migration 是否已具備，由家用端核對；reference CREATE-only 不是可直接重播的 migration。

## 家用端 Production API handoff

- 先比對 live PostgreSQL schema／migration history，沿用既有 WP101／WP201／WP305／WP603／WP207 的 Oracle source／CREATE-only，並核對本輪 `TBLSYSPARAMETER` reference；只為真正缺的表建 forward migration。不新增虛構 PK/FK，也不要重複建 WP207 六表。
- 建立登入與功能授權的指定 Lot 查詢、元件查詢、產品／路由 lookup。Server 依 Status／HaveComponent／LotState、載具、庫存範圍與權限篩選；InventoryNo、SplitType=1 等宿主模式只能來自可信 server 上下文。
- 提供拆批 POST command：LotNo、LotStamp、Count／Qty、IncludeMother、各子批 Action／ReturnType／NodeID／Product／Version／目標 Process／OP 與元件映射。Server 鎖定／重讀 Lot、ComponentState、Inventory，在同一交易內重驗數量、分配唯一性／完整性、路由／產品、序號及權限後建立子批、元件狀態／屬性、庫存、報工／歷程／委外／派工等副作用。不可沿用瀏覽器 localStorage 或 DEV 子批號。
- 核對 `BR_Manual_LotSplit_Component` helper 的其餘讀寫與 BR／SEMI_Wafer 後續 TransferLot。若後續呼叫無法置於同一交易，建立可觀察、可重試且冪等的完成狀態，避免拆批已成功後再整批 Confirm。

本輪做原始碼靜態追查、Vue DEV／規格及一張 Oracle 系統參數表的唯讀 DDL／metadata 查詢；沒有查 Oracle 業務資料列、沒有連 YMES PostgreSQL、沒有實作正式 API 或 migration，也未執行 build/test/browser。
