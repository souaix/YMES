# WP303 設備耗品現況

## 範圍與來源

- MES menu: WIP → 設備與載具 → 設備耗品現況；FunctionNo `EQP CONSUME STATUS`，WinForms `WP_EQPConsumeStatus.dll`。
- WinForms 主表單：`STD/MESWin/WIP/WP_EQPConsumeStatus/frmEQPConsumeStatus.vb`。
- 新增／編輯／複製：`frmEQPConsumeStatusDef.vb`。
- ConsumReset 外掛表單：`STD/MESWin/WIP/WP_EQPConsumeReset/frmEQPConsumeReset.vb`。主頁以 `ObjectFileHandler.Execute("WP_EQPConsumeReset", ..., { selected DataRow })` 開啟外掛。
- Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs`，呼叫 `LoadEQPConsumeStatus`、`AddEQPConsumeStatus`、`EditEQPConsumeStatus`、`DelEQPConsumeStatus`、`AddEQPConsumeLog`、`LoadEQPConsumeLog`；設備與耗品基準查詢走 `wsEQP.LoadEquipmentBasis`、`wsEQP.LoadEQPTypeConsumeBasis`。
- Core：`STD/MESkc/kcWIP/clsWIP.cs` 的設備耗品現況／歷程 SQL；設備耗品基準由 `STD/MESkc/kcEQP/clsEQPBasis.cs` 讀取；生產期間會由 `STD/MESkc/kcWIP/clsLot.cs` 更新耗品用量。
- YMES Vue DEV：`web/src/components/WipEquipmentConsumeStatus.vue`；入口由 `web/src/App.vue` 掛在既有三層選單。

## WinForms 畫面

### 主畫面

- `frmEQPConsumeStatus` 最大化；設計 ClientSize 784×561。主 UltraGrid 位於左側，約 666×537；右側為直向按鈕列。
- 不另設查詢列；載入時 `LoadEQPConsumeStatus` 未傳條件，顯示全部資料。
- 欄位與順序：EquipmentNo、ConsumeNo、ConsumeSeq、CurQty、CurPeriod、Creator、CreateDate、Revisor、ReviseDate。CurQty／CurPeriod 靠右，日期格式 `yyyy/MM/dd HH:mm:ss`。
- 按鈕及位置：ADD、EDIT、DEL、Copy 在右側上方；ConsumReset 與 Close 靠右下方。編輯及複製只取 ActiveRow；DEL 使用所有選取列。
- DEV 入口 `/YMES/WIP/EquipmentConsumeStatus`；本機假資料存於 `ymes.dev.wp303-consume-status.v1`，不呼叫 API，也不讀寫 Oracle。

### 新增／編輯／複製視窗

- `frmEQPConsumeStatusDef` ClientSize 371×326，置中父視窗；欄位置於 `EQP Cunsum Status` 群組。
- EquipmentNo、ConsumeNo、ConsumeSeq、CurQty、CurPeriod、Creator、CreateDate；EquipmentNo 透過 `...` 搜尋 IssueState=2 的設備，依 EquipmentType／EquipmentNo 排序。選設備後，ConsumeNo 下拉只列該設備類別的 `TBLEQPCONSUMEBASIS` 耗品。
- ADD 預設 CurQty=0、CurPeriod=0，Creator／CreateDate 為目前登入者與時間。Copy 會預填來源設備、耗品與耗品序號，但按 Add 規則新增；使用者需要選新設備／耗品組合才不會撞上主鍵。
- EDIT 鎖定 EquipmentNo、ConsumeNo，只能改 ConsumeSeq、CurQty、CurPeriod；Creator／CreateDate 保留原值。Core 的 Edit 不更新 Revisor／ReviseDate。
- CurQty 必填、數字、非負整數；CurPeriod 必填且須為數字，可有小數。EquipmentNo、ConsumeNo、ConsumeSeq 必填。相同 ConsumeNo 的 ConsumeSeq 若已出現在 `TBLWIPEQPCONSUMELOG`，表單拒絕儲存。來源檢查歷程，不檢查其他現況列上的相同序號；資料表主鍵另保護 EquipmentNo+ConsumeNo。
- Confirm 與 Apply 綁到同一儲存事件，成功後都關閉視窗；Apply 初始停用，欄位變更後啟用。

### ConsumReset 視窗

- 獨立 `WP_EQPConsumeReset` 外掛，ClientSize 638×310，置中父視窗。主頁要求先選取一筆現況資料。
- 顯示 EquipmentNo、ConsumeNo、可輸入的新 ConsumeSeq、Used Qty、Produced Hours、Remain Qty、Remain Period、Creator、Create Date、Revisor、Revise Date。除了 ConsumeSeq，其他值由選取資料、設備耗品基準及登入者帶入；Confirm 在序號變更時啟用。
- `Remain Qty = Quantity - CurQty`；不足／耗盡時來源改顯示 Quantity。`Period=-1` 表示不限週期；否則 `Remain Period = Period - CurPeriod`。來源不足時誤用 `ToleranceQty` 當 Remain Period 顯示值（不是 TolerancePeriod）。
- 若數量或週期已達基準上限，WinForms 會清空新 ConsumeSeq 並把 Used Qty／Produced Hours 歸零，提示更換耗品。這會影響之後寫入的 AccQty／AccPeriod；本 DEV 將此來源行為明確顯示，待決定是否另立功能修正。
- 確認時呼叫 `AddEQPConsumeLog`：新增舊序號的耗品歷程（Creator=目前使用者、CreateDate=現在、AccQty／AccPeriod=視窗 Used Qty／Produced Hours），再把現況序號換成新序號、CurQty／CurPeriod 歸零，更新 Revisor／ReviseDate。Core 對 log insert 與 status update 使用檢查列數的成組 SQL 執行。

## 資料表與 Oracle metadata

| Table | 用途 | 主鍵 | 來源 |
|---|---|---|---|
| `TBLWIPEQPCONSUMESTATUS` | 設備耗品目前序號、用量與稽核欄位 | EquipmentNo + ConsumeNo | 本功能新增 DDL reference |
| `TBLWIPEQPCONSUMELOG` | 更換／重置後的舊序號及累積使用量 | EquipmentNo + ConsumeNo + ConsumeSeq | 本功能新增 DDL reference |
| `TBLEQPCONSUMEBASIS` | 設備類別耗品之 Quantity、ToleranceQty、Period 等基準 | EquipmentType + ConsumeNo | 沿用設備類別資料 reference |
| `TBLEQPEQUIPMENTBASIS` | 設備 IssueState／EquipmentType 查詢 | EquipmentNo | 沿用設備主檔 reference |

- 兩張 WIP 專用表 DDL／metadata 由 Windows PowerShell 5.1、Oracle.ManagedDataAccess 直連 MESTEST 字典取得，文件在 `database/reference/mestest_wip_wp303_source_ddl.sql`、`mestest_wip_wp303_metadata.txt`。
- Status：9 欄、5 個 NOT NULL 欄位約束、複合主鍵及其 unique index；無 FK、額外索引或 trigger。
- Log：7 欄、3 個 NOT NULL 欄位約束、三欄複合主鍵及其 unique index；無 FK、額外索引或 trigger。
- YMES/PostgreSQL CREATE-only 對照為 `database/reference/mestest_wip_wp303_create.sql`。它不是 migration；家用端先比對 live schema 與 migrations，只在缺表時建立 forward migration。
- `database/reference/mestest_equipment_type_create.sql` 已含 `ymes.tbleqpconsumebasis`，不在本功能重複宣告。

## 家用端 API／資料庫交接

- 列表：登入保護的唯讀查詢所有 ConsumeStatus，支援分頁／排序；WinForms 原頁沒有查詢欄位或篩選條件。
- lookup：使用設備主檔只提供 IssueState=2 的設備；依 EquipmentType 查 `TBLEQPCONSUMEBASIS` 耗品基準。
- 新增、編輯、刪除：新增 Creator/CreateDate；編輯只改 ConsumeSeq、CurQty、CurPeriod；刪除依複合鍵。WinForms 多列刪除逐列送出，前面成功的列不會因後續失敗回復。
- Reset 必須是登入者授權的 POST command，伺服器於同一交易重查現況序號／基準、檢查歷程序號不得重複、寫舊序號 log，並 CAS 更新現況序號／用量／稽核欄位。不能採用前端提交的 AccQty／Period 或剩餘值作為資料真相。
- Oracle/DEV 的 ConsumeSeq 歷程檢查以 ConsumeNo 為範圍，不是設備範圍；資料表 PK 不保證跨設備的序號唯一。正式 API 需要在併發下提供等價的一致性檢查，不可單純依賴 client validation。
- `CurPeriod` 是 NUMBER(7,2)；Core 使用 decimal，但部分 legacy XML parameter type 標記 Integer。正式 API 以資料表精度為準，接受兩位小數。

## 已知來源瑕疵與 DEV 範圍

- Reset 不足時的 RemainPeriod 使用 `ToleranceQty`；耗盡時將輸入累積值清零後再寫 log。DEV 頁保留並提示，讓使用者之後決定是否修正。
- DEV 刪除假資料一次完成；正式 WinForms 是逐列 Service 呼叫，可能出現部分成功。正式 API／UI 應明確選定相容或原子化策略。
- WP304「設備耗品現況履歷」是另一個 menu function，不併入 WP303；之後依自己的 Form／Service／Core 復刻。
- 畫面資料全為明確標示的假資料，使用 localStorage 模擬新增、修改、複製、刪除與重置，不連線任何 DB/API。
