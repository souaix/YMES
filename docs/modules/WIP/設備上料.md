# WP301 設備上料

## 功能識別

- 三層選單：WIP → 設備與載具 → 設備上料
- FunctionNo：`EQP MOUNT MATERIAL`；FunctionKey：`WP301`；執行檔：`WP_EQPMaterialLoading.dll`
- WinForms：`STD/MESWin/WIP/WP_EQPMaterialLoading/frmEQPMaterialLoading.vb`
- Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP_Material.cs`
- Core：`STD/MESkc/kcWIP/clsMaterialHandler.cs`
- Vue DEV：`web/src/components/WipEquipmentMaterialLoading.vue`
- Vue 路由：`/YMES/WIP/EquipmentMaterialLoading`

## 畫面與操作

WinForms 視窗最大化。最上方選設備；其下是「批量上料區」，可選是否指定工單，再選物料、物料(元件)或半成品。下半部為三層 UltraGrid：上層依原物料、批號檢查、物料層級及投料點分組；中層列出上料序號、輸入物料、物料批號、數量與工單；需要元件的批次再展開元件編號、良品數與報廢數。右側按鈕為上移、下移、下料、關閉。

| WinForms 欄位／操作 | 行為 |
| --- | --- |
| 設備編號、`...` | 可手動輸入後按 Enter，也可開設備查找。候選設備需 `IssueState=2` 且 `EquipmentClass <> 'VIRTUAL'`。直接啟動且傳入 EquipmentNo 時隱藏查找按鈕。 |
| 指定工單、工單編號、`...` | 勾選後才可輸入／查找；候選工單狀態為 0、1、2、3、6。取消時工單重設為 `N/A`，並重新載入設備現況。 |
| 物料 | 輸入物料、批號及上料數量，數量欄按 Enter 執行。物料批號預設 `N/A` 且唯讀；`DocMatLot` 勾選才開放輸入。物料主檔 `CheckLotNo=1` 時必須提供批號。 |
| 物料(元件) | 輸入物料、物料批號與 ComponentNo；ComponentNo 按 Enter 執行，數量固定 1。基板／晶圓類物料才允許此模式，且 Core 會執行對應的元件／映射處理。 |
| 半成品 | 輸入 SemiProductLotNo 後按 Enter；先查 `WIPInventory_SEMI`，再查 MO Material State。成功時自動帶出產品編號與可用數量並執行上料。半成品批號必填。 |
| 上移／下移 | 僅選取中層上料明細有效；與相鄰明細交換 Seq，呼叫 `Exe_EQPMaterialStateSeqChange`。 |
| 下料 | 選取中層明細時移除該物料上料；選取元件列時只下料該元件並扣減數量。Core 還原投料點庫存，並可能依物料主檔設定清除 OpenDate、寫入 Raw Inventory Log。 |
| 關閉 | 關閉功能頁，不寫入資料。 |

## 查詢與業務邏輯

1. 設備查找呼叫 `tblEQPEquipmentBasis`，條件為設備編號存在、`IssueState=2`、非 VIRTUAL。選設備後驗證存在；勾選指定工單時也驗證 MO 存在且狀態符合查找條件。
2. `funRefreshGridData` 呼叫 `wsWIP_Material.LoadWIPEQPMaterialState`，傳 `EquipmentNo` 與 `NewType=1`；新版現況查詢不傳 MO，所以即使指定工單，Grid 仍顯示設備全部已上料資料。再呼叫 `LoadWIPEQPMTLState_Comp` 載入元件現況，建立父、子及元件三層關聯。
3. `LoadWIPEQPMaterialState` 讀 `TBLWIPEQPMATERIALSTATE`；工單指定過濾只在 `NewType=0` 舊邏輯中 JOIN MO 用料表。`LoadWIPEQPMTLState_Comp` 讀 `TBLWIPEQPMTLSTATE_COMP`。
4. 上料前由 WinForms 取得物料主檔／半成品庫存資訊，再呼叫 `CheckMTLForEQPMount`。Core 會驗證物料／產品有效、批號規則、膠類解凍時間、保存期限、上料順序與投料點；新版以 `MaterialLevel` 區分一般物料與半成品。
5. 上料命令為 `Exe_EQPMountMaterial`。有指定工單時投料點為 MO（3）；未指定工單時一般物料／元件走 WIP INV Raw（2），半成品走 WIP INV Semi（4）。Core 先扣投料點庫存，再新增或累加設備上料現況；元件模式另外維護 component／substrate map 狀態。
6. 下料命令為 `Exe_EQPUnmountMaterial`。一般列移除整筆設備上料；指定 ComponentNo 時可逐元件下料，Core 同步還原投料點庫存、元件／映射現況及相關歷程。
7. Seq 調整為 `Exe_EQPMaterialStateSeqChange`，傳交換後的兩筆 EquipmentNo、MaterialNo、InputMaterialNo、MaterialLotNo、PutInPlaceType 與 Seq。

## 資料表與 Oracle DDL

Core 直接使用或查詢的 17 張表均在 MESTEST `ALL_TABLES` 查到。四張已建立 WP301 專用 Oracle source DDL／PostgreSQL CREATE-only 參考；其餘 13 張重用既有 database reference：

| 表 | 用途 | DDL 交接 |
| --- | --- | --- |
| `TBLWIPEQPMATERIALSTATE` | 設備上料現況、序號、數量、批號、投料點與效期 | 本模組 source DDL、CREATE-only |
| `TBLWIPEQPMTLSTATE_COMP` | 設備物料逐元件現況 | 本模組 source DDL、CREATE-only |
| `TBL_BINKLESSMAPSTATE` | BGA／映射元件狀態 | 本模組 source DDL、CREATE-only |
| `TBL_BSUBSTRATEMAPSTATE` | 基板／晶圓映射元件狀態 | 本模組 source DDL、CREATE-only |
| `TBLINVWIPINVENTORY_RAW`, `TBLINVWIPINVENTORY_RAWLOG`, `TBLINVWIPINVENTORY_SEMI` | 投料點庫存、歷程及半成品批號查詢 | WP201 dependency DDL／CREATE-only |
| `TBLMTLMATERIALBASIS` | 物料 CheckLotNo、類型及 OpenDate 設定 | MTL master DDL／CREATE-only |
| `TBLOEMOMATERIALLIST`, `TBLOEMOMATERIALSTATE` | 工單 BOM／存料查詢與扣帳 | OE206／OE207 DDL／CREATE-only |
| `TBLOPAREA`, `TBLOPBASIS` | 工單投料點／區域資料 | Operation and System DDL／CREATE-only |
| `TBLSMDAREAINVENTORY`, `TBLSMDAREARELATION`, `TBLSMDSMTAREAEQPMAP` | 區域庫房與設備區域查找 | SMD area／equipment group DDL／CREATE-only |
| `TBLWIPLOTBASIS`, `TBLWIPLOTSTATE` | 半成品批次與在製狀態查詢 | WP101／WP201 DDL／CREATE-only |

Oracle source 與 metadata 由 Windows PowerShell 5.1、`Oracle.ManagedDataAccess.dll` 透過受保護 profile 直連 MESTEST 唯讀取得。未查業務資料列、未執行 Oracle DDL/DML，也未讀取 YMES PostgreSQL。

| Oracle 表 | 欄位 | Constraints | Index | Trigger | 複合 PK |
| --- | ---: | ---: | ---: | ---: | --- |
| `TBLWIPEQPMATERIALSTATE` | 20 | 12（11 欄 NOT NULL + PK） | 1 個 PK unique index | 0 | EquipmentNo、MaterialNo、InputMaterialNo、MaterialLotNo、MONo |
| `TBLWIPEQPMTLSTATE_COMP` | 13 | 10（9 欄 NOT NULL + PK） | 1 個 PK unique index | 0 | MONo、EquipmentNo、MaterialNo、InputMaterialNo、MaterialLotNo、ComponentNo |
| `TBL_BINKLESSMAPSTATE` | 18 | 6（5 欄 NOT NULL + PK） | 1 個 PK unique index | 0 | MaterialLotNo、ComponentNo、CoordinateX、CoordinateY |
| `TBL_BSUBSTRATEMAPSTATE` | 19 | 7（6 欄 NOT NULL + PK） | 1 個 PK unique index | 0 | MaterialLotNo、ComponentNo、CoordinateX、CoordinateY、SubstrateSubIndex |

四表沒有 FK、額外 index 或 trigger。Source DDL 保留 Oracle 原始型別／tablespace；家用端 CREATE-only 已轉為 PostgreSQL 型別，但不是 migration。家用端須先核對 PostgreSQL live schema／migration，僅對實際缺少的表新增 forward migration。

## Vue DEV 與已知限制

- 使用專屬 localStorage key `ymes.dev.wp301-eqp-material-loading.v1`，設備、工單、物料批號、半成品批號、庫存量與元件狀態均為 DEV 假資料；不呼叫 API 或資料庫。
- 畫面保留設備查找、MO 查找、三個上料模式、階層 Grid、序號交換、下料確認、關閉按鈕。所有修改僅模擬在瀏覽器儲存。
- Core 的部分批號查找只依 LotNo 讀取第一列，未固定排序；同批號跨 Inventory/Locator 有多筆時資料列可能不唯一。Production API 必須使用 InventoryNo／LocatorNo／MO 與完整鍵收斂，遇到歧義要回明確錯誤，不可依資料庫回傳順序選第一筆。
- 來源的動態物料屬性、膠類解凍／效期、Raw wafer map、元件拆扣及跨庫交易在 DEV 以可操作的示例流程呈現；正式校驗、交易隔離與差異錯誤碼由家用端依 Core 實作。

## 家用端 API handoff

- Lookup／查詢可使用登入保護的 GET：合格設備、合格 MO、設備上料現況及其元件列。設備條件和 MO 狀態由 server 重新查證；Grid 查詢維持來源的 `NewType=1` 語意。
- 上料、下料、序號交換均使用 POST command。建議命令包含 equipmentNo、指定 MO（可空）、mode、inputMaterialNo、materialLotNo、quantity 或 componentNo，以及前端看到的現況版本／DataStamp（若 live schema 能提供）。修改型操作不可使用 GET。
- Server 重新查 Material／Product 有效狀態、CheckLotNo、庫存可用量、投料點類型、MO BOM、設備可用狀態、半成品批號、元件可用狀態、效期／解凍／上料順序；不可信任前端送來的 MaterialLevel、PutInPlaceType、CheckLotNo 或庫存量。
- Mount 交易涵蓋投料點扣帳、設備現況新增／累加、開封／效期欄位、Component／map state 及 Raw log。Unmount 交易涵蓋設備現況刪除／扣量、庫存還原、ResetOpenDate 與 Raw log。交換序號以同一交易寫入兩列並確保兩列均屬該設備。
- API 需定義幂等鍵、並發鎖／CAS、跨表交易與部分錯誤回應。公司端未連 PostgreSQL、未建立 API／migration；本節 SQL 僅供 live schema 對照。
