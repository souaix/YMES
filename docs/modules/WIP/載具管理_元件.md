## WinForms 畫面與操作

主窗體設計尺寸 1008×732，最大化顯示。頂部查詢框含 CarrierType、CarrierNo 前綴及 Query；主區域左右並列 CarrierState 與 CarrierState Detail，右側垂直排列 Carrier In、Carrier Out、Change Carrier，底部 Close。主窗體的兩個 UltraGrid 都隱藏 GroupByBox。

| 區域／控制項 | 來源行為 |
| --- | --- |
| CarrierType | 可輸入類別；... 打開 CarrierType 清單，查詢時作完整相等條件。 |
| CarrierNo、%、Query | CarrierNo 使用前綴查詢；空白時不加條件。Query 呼叫 wsEQP.LoadCarrierState。 |
| CarrierState Grid | 顯示 CarrierType、CarrierNo、Carrier Status；狀態 0 顯示 Empty、1 顯示 In Use。選取主列後即時載入對應明細。 |
| CarrierState Detail Grid | 顯示 CarrierPosition、LotNo、ComponentNo。資料會補齊至 CarrierLayer × CarrierCapacity 個位置，空位置也可選取。 |
| Carrier In | 開啟約 655×460 的子視窗。CarrierNo/CarrierType 可沿用主畫面選取值，也可用 ... 選載具；輸入 LotNo 後按 Enter 檢核並把元件填入位置草稿。支援選列後 Up/Down、Confirm、Cancel。 |
| Carrier Out | 需有選取的 CarrierState Detail 列，且載具至少有一筆內容；確認後整個載具卸載，不是只移除選取的元件。 |
| Change Carrier | 主畫面載具狀態必須為 In Use，且需選取明細列。開啟約 832×460 子視窗，選原載具及空的新載具，將原內容載入新載具草稿，可掃入額外 Lot、調整位置後確認。來源 Designer 的子視窗標題字串是 CarrierIn，屬舊畫面命名殘留。 |
| 關閉 | 子視窗 Cancel 放棄草稿；主視窗 Close 回功能選單。 |

## 主要規則

### 查詢與畫面明細

1. 主畫面啟動時呼叫 wsEQP.LoadCarrierState。CarrierType 以 = 條件過濾；CarrierNo 以 Like '<輸入值>%' 前綴過濾。
2. 選取 CarrierState 列後呼叫 wsEQP.LoadCarrierStateDetail(CarrierNo)，再呼叫 wsEQP.LoadCarrierType(CarrierType)。
3. 顯示位置總數為 CarrierLayer × CarrierCapacity。Detail 中不存在的位置補一筆空白列；排序依 CarrierPosition 遞增。
4. CarrierStatus 是畫面為語系 ValueList 所使用的欄位名稱；來源將回傳的 CarrierState 欄位重新命名成 CarrierStatus。

### Carrier In

1. 載具可由主畫面帶入，或由 wsEQP.LoadCarrierBasis 選取。
2. 輸入 LotNo 後轉大寫，依序檢查：目前草稿未重複、wsINV.LoadStockerState 不在 Stocker、LotState 存在、Status 不大於 11、LotState.CarrierNo 為空、CarrierStateDetail 中沒有同批號、HaveComponent 不為 0、元件清單不為空。
3. 空位置數須大於或等於 Component 數。元件依 ComponentState.SlotNo 升冪處理；先嘗試指定 SlotNo，若不可用則落到最小空位置。LotNo、ContentID、ComponentNo、BCIP 及批次序號等值先留在畫面草稿。
4. Up/Down 只交換目前選取位置與相鄰位置的批號、ContentID、ComponentNo、Flag 等內容，不改 CarrierPosition。Confirm 只送出有 LotNo 的位置列；空草稿不送出。
5. wsWIP.ExecuteCarrierIn 由 Core 重讀載具明細及 LotState。已有的 Lot/Component 若位置不同，先刪舊明細並寫 DetailLog，再新增新位置；新元件直接新增。同步更新 ComponentState.SlotNo、LotState.CarrierNo，最後將 CarrierState 設為 1。Core 以 CarrierLayer × CarrierCapacity 再檢核送入列數。

### Carrier Out

1. 主畫面檢查目前選取 Detail 所屬 CarrierNo，並確認載具中至少有一筆 LotNo。
2. 使用者確認後呼叫 wsWIP.ExecuteCarrierOut(CarrierNo)。Core 對載具上的內容逐批取得 LotSerial/LogGroupSerial，寫入 TBLWIPCARRIERSTATEDETAILLOG，刪除載具 Detail、清除 LotState.CarrierNo，並將 CarrierState 設為 0。
3. Core 對 ComponentState.SlotNo 的清除 SQL 目前是註解，不會由 Carrier Out 清空元件 SlotNo；之後再 Carrier In 時會依原 SlotNo 嘗試放置，不可假設此操作已重設 SlotNo。

### Change Carrier

1. 主畫面只允許從 CarrierState=1 的載具進入。原載具清單 wsWIP.LoadInUseCarrierBasis 以 IssueState=2 且 Detail 有非空、非 N/A ComponentNo 為條件。
2. 新載具由 wsWIP.LoadEmptyCarrierBasis 或 LoadEmptyCarrierBasisWithLayer(UseLayer) 取得：IssueState=2，CarrierNo 尚無 Detail；多層類別再以 CarrierType.UseLayer 過濾。Core 的最後檢核也會確認新 CarrierNo 沒有 Detail。查詢並非只依 CarrierState=0 判空。
3. 新載具位置容量須可容納原載具綁定列數。來源修正過「更換到容量較小載具」問題；UI 依新載具容量重建所有位置，並保留原 CarrierPosition 仍可使用的列。
4. LotNo 掃描防止草稿重複；LotState 必須存在、Status ≤11、CarrierNo 為空、CarrierStateDetail 沒有同批號，且 HaveComponent 與元件列有效、空位數足夠。Change Form 的掃描程式沒有呼叫 Stocker 狀態檢核，與 Carrier In 不同。
5. Up/Down 交換新載具草稿中的內容。Confirm 需選好 NewCarrierNo 且至少有一筆有效 LotNo；送 OrgCarrierNo、NewCarrierNo 與新載具全部有效位置列至 wsWIP.ExecuteCarrierChange。
6. Core 先以原載具現況寫 DetailLog、刪除舊 Detail，清空原元件 SlotNo；在新 CarrierNo 插入所有送入列並更新新 SlotNo，更新 LotState.CarrierNo；最後原 CarrierState=0、新 CarrierState=1。Core 再確認新載具沒有既存 Detail，避免覆蓋非空載具。

## Service 與正式 API 契約交接

| 目的 | 舊 Service／參數 | YMES API 建議 |
| --- | --- | --- |
| 查詢載具現況 | wsEQP.LoadCarrierState；CarrierType exact、CarrierNo prefix | 登入保護的分頁 GET；由伺服器加入使用者可見範圍。 |
| 查詢載具位置 | wsEQP.LoadCarrierStateDetail(CarrierNo) | GET detail；回傳實際明細及依載具類別計算的位置容量。 |
| 查詢類別／可選載具 | wsEQP.LoadCarrierType、wsEQP.LoadCarrierBasis、wsWIP.LoadEmptyCarrierBasis、LoadEmptyCarrierBasisWithLayer(UseLayer)、LoadInUseCarrierBasis | GET lookup；空載具依無 Detail 與 IssueState 判斷，非僅讀 CarrierState。 |
| 載入元件 | wsWIP.LoadLotBasisJoinState、LoadComponentState、wsINV.LoadStockerState | GET 驗證查詢；回 LotState、Status、CarrierNo、HaveComponent、ComponentNo/SlotNo、Stocker/Locator。 |
| 載具放入 | wsWIP.ExecuteCarrierIn：CarrierNo + 多列 CarrierDetail（CarrierNo、CarrierPosition、LotNo、BCIP、ContentID、LotSerial、LogGroupSerial、ComponentNo） | POST command；交易內重讀 Carrier、Lot、Component、Stocker、Detail 與容量，寫 Detail/DetailLog、Component SlotNo、Lot CarrierNo、CarrierState。 |
| 載具卸載 | wsWIP.ExecuteCarrierOut：CarrierNo | POST command；重讀整載具內容、寫歷程、刪明細及清 Lot CarrierNo，更新 CarrierState。保留目前不清 Component SlotNo 的來源行為，若正式端要修正需另列行為變更。 |
| 更換載具 | wsWIP.ExecuteCarrierChange：OrgCarrierNo、NewCarrierNo + 新 CarrierDetail 多列 | POST command；交易內鎖定/檢核兩載具，防止 NewCarrier 有 Detail，記錄舊明細歷程，再原子轉移明細、Lot CarrierNo、Component SlotNo 與兩個 CarrierState。 |

上述命令不可用 GET 修改資料。家用端需定義登入者、角色/功能權限、併發鎖定或版本條件、冪等鍵、交易回滾、部分錯誤回覆及事件時間來源；不可把前端草稿當成已核實的 Lot/Component 狀態。

## Oracle 表與 DDL

WP308 沒有新增專屬 Oracle 表。Core 直接用到的表與既有查證來源：

| Oracle 表 | 用途 | 已有來源 reference |
| --- | --- | --- |
| TBLEQPCARRIERBASIS、TBLEQPCARRIERTYPE | 載具編號、IssueState、UseLayer、容量 | mestest_carrier_basis_source_ddl.sql、mestest_carrier_type_source_ddl.sql 及相應 CREATE-only |
| TBLWIPCARRIERSTATE | Empty/In Use 狀態 | mestest_carrier_basis_dependencies_source_ddl.sql 與 CREATE-only |
| TBLWIPCARRIERSTATEDETAIL、TBLWIPCARRIERSTATEDETAILLOG | 位置現況與卸載/換位歷程 | WP302 的 mestest_wip_wp302_source_ddl.sql、mestest_wip_wp302_metadata.txt、mestest_wip_wp302_create.sql |
| TBLWIPLOTBASIS、TBLWIPLOTSTATE、TBLWIPCOMPONENTSTATE | Lot 狀態、CarrierNo、ComponentNo 與 SlotNo | mestest_wip_wp101_source_ddl.sql、mestest_wip_wp101_create.sql |
| TBLINVSTOCKERSTATE | Carrier In 時判斷 Lot 是否在 Stocker | WP302 的 source DDL、metadata、CREATE-only |

公司端既有 Oracle DDL 是 Windows PowerShell 5.1 + Oracle.ManagedDataAccess 直接唯讀查 MESTEST 資料字典取得，未讀業務資料列、未執行 Oracle DDL/DML。WP308 重用已核對表，不重複產生 CREATE；家用端先比對 YMES PostgreSQL live schema/migration history，僅對缺表補 migration，不照 Oracle reference 全部重建。

## Vue DEV 與假資料

- Vue 主頁依 WinForms 以查詢框、左右雙 Grid、右側垂直按鈕呈現；Carrier In 與 Change Carrier 使用互動式子視窗，保留 LotNo Enter、Carrier lookup、位置表、Up/Down、Confirm/Cancel 與卸載確認。
- DEV 假資料共用 WP302 localStorage，能從 WP302 查看 Carrier In／Out／Change 後的同一份載具、Lot 與 Detail 狀態。假 lot 涵蓋多元件、無元件、Stocker、Status>11、可由 WP308（Status 6–11）管理的批次及空位不足情境。
- DEV 可改動假資料；Production/非 DEV 模式停用異動。沒有連正式 API。
- 假資料用 componentSlotMap 表達 ComponentState.SlotNo；真實 SlotNo、LotSerial/LogGroupSerial、資料庫交易與併發需由家用端 API 重新查證，不能將 localStorage 結構當正式 schema。
- DEV 換載具另阻止「舊明細位置超出新載具容量」以免假資料被重建時遺失；來源主要以明細列數比容量，這個邊界差異需在正式 API 實作前決定是否採用更嚴格位置檢核。
