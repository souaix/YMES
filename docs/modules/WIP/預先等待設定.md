# WP505 預先等待設定（FUTURE WAIT SET）

## 原始碼與選單

- WIP → 異常與等待 → 預先等待設定；FunctionNo `FUTURE WAIT SET`，WinForms `WP_FutureWaitSet.dll`。
- 主 Form/內嵌 Designer：`STD/MESWin/WIP/WP_FutureWaitSet/frmFutureWaitSet.vb`。Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `Exe_FutureWait_Set`、`CheckLotPackage`。Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `UpdFutureWait_Set`、後續生效判斷 `ChkFutureWait`。

## 畫面與操作

主畫面從上到下為 Query、Lot State、Wait Data，底部 Confirm/Close。Query：Area No、PS No、OP No、Customer No、Product No、LotNo 六欄，前五欄 `...` 查找；至少填一項，固定向 `LoadLotBasisJoinState` 傳 `ShowPartialLot=False` 與 `Status=0|1|4`。Lot Grid **六欄**：Check、LotNo、CurQty、Status、Product No、Customer No；Status 顯示 Queue/Running/Complete。`Selected Lot` 只過濾檢視已勾列，非 Select All；LotNo 掃描 Enter 會在目前查詢結果中勾選該批。

Wait Data：Wait Time Start=`0`、End=`1`；PS No 查找後載入該 PS 的 OP 清單，可勾多 OP；Description 為自由文字，**可空**。Confirm 要求選 Wait Time、至少一個 OP、至少一個 Lot；原 Form 沒有另外驗證 Description 非空或 PS No 本身非空（但正常流程選 OP 需先選 PS）。成功後清選 Lot/OP，Wait Time 回 Start，清 Description；保留 PS No。

原 Form 先把多筆 LotNo 逗號串成一個字串送 `CheckLotPackage`；Service 將整串當 `LotNoList` 唯一元素，有漏檢已包裝批風險。正式 API 和公司 DEV 均應逐批檢查，不承襲此缺陷。原 Form 的包裝檢查在空 Lot 選取的檢查之前，正式端應先驗選取再查包裝。

## 資料與生效語義

Service 解析 LotNo 清單、OPNo 清單、WaitTime、Description，呼叫 `UpdFutureWait_Set`。Core 對每個 Lot×OP，在同一 SQL 集合中按 `(LotNo,OPNo,WaitTime)` **刪舊 `TBLWIPFUTUREWAIT` 再插新**；Description 不等於預設空字串才加入欄位，Creator/日期由 Service/Core 取得。`ExecuteSQLNoneQuery_UPD` 執行集合，Service 成功後逐 Lot 寫事件 Log。Set 本身不改 Lot.Status、不建立 WaitBasis，也不立刻使 Lot 等待。後續 `ChkFutureWait` 以 LotNo、OPNo、WaitTime 查 FutureWait；未指定 OP 時由 `TBLWIPLOTSTATE` 的目前 OP 決定，命中時回傳 Description，由執行流程再作等待狀態處理。正式端需連同 WP502 的 WaitBasis/ReleaseLog 與 WP507 Release 設計生命週期。

Oracle `TBLWIPFUTUREWAIT` 來源 DDL 在 `database/reference/mestest_wip_wp201_dependency_source_ddl.sql`，PostgreSQL CREATE-only 在 `mestest_wip_wp201_create.sql`：七欄、PK `(LOTNO,OPNO,WAITTIME)`，Description `VARCHAR2(3000)` 可空。LotState/LotBasis 與 PS/OP/Area/Customer/Product lookup 表已有既存 source/CREATE refs；本功能**沒有新缺的直接表**，不重複建 CREATE SQL。家用端仍需核 live PostgreSQL schema/migration history 與後續等待流程依賴表。

## Vue DEV 與家用端 API

公司端 Vue 頁 `/YMES/WIP/FutureWaitSet` 位於 `web/src/components/WipFutureWaitSet.vue`，假資料 localStorage `ymes-dev-mock:wip-future-wait-set:state:v1`。Area A01 可查兩筆一般批及一筆已包裝批，Partial fixture 被排除；可查找、勾選/掃描、Selected Lot 過濾、PS/多 OP、Start/End、可空 Description、Confirm 假替換。DEV 額外用 LotStamp/狀態重查防止本機舊資料覆蓋，原 `UpdFutureWait_Set` Set 本身沒有 LotStamp CAS。DEV 不改真 Lot、不建 WaitBasis、不呼叫 Oracle/PostgreSQL；正式 non-DEV 不讀假資料、不回報假交易。PS/OP 清單為示範值，不可作正式碼表。公司端依交接規則只做靜態核對，未執行 build/test/browser。

家用端提供登入/Function ACL 的六欄候選與五類 lookup、PS→有效 OP 查詢，限制結果量；Set POST 收 Lot 清單、OP 清單、WaitTime、Description、版本/冪等鍵。後端對每批重查包裝、Status、Partial、權限、Lot/OP 真實性，server 給 Creator/日期。按複合鍵以參數化 SQL 交易替換 FutureWait；定義全批原子、並發與重送結果。原 Form 多批包裝預檢傳逗號字串的錯誤需修正。先核對 live schema/history，只對實際缺項做 forward migration；正式 API 上線後才接 Vue 正式查詢/提交及驗收。
