# WPP04 晶圓針測紀錄查詢

## 來源與入口

- FunctionKey WPP04，清冊功能 P_PROBING LOG，Form `frmProbingLog`，分類「芯片測試生產管理」。主 Form 與 Designer 同在 `D:\TP-iMes\iMES_THEIL_TP\IC_CP_PKG\MESWin_IC_CP_PKG\WIP\WP_P_ProbingLog\frmProbingLog.vb`；沒有獨立 Designer 檔。
- Form 查詢呼叫 `IC_CP_PKG\wsIC_CP_PKG\wsWIP\wsWIP.cs` 的 `LoadProbingLog_Ext`，Customer／OP lookup 分別呼叫 `wsENT.LoadCustomerBasis`、`wsOP.LoadOPBasis`。Service 轉送 Lot、OP、Customer、Component、MO、CurVersion、日期範圍及 AdditionalXml。
- Core：`MEStc_IC_CP_PKG\tcWIP\clsLot.cs` 的 `LoadProbingLog_Ext`，查詢 Wafer Bin Summary 與動態 Bin。一般 WIP Form 可傳入 Lot／OP／MO／Component 開啟此視窗；該呼叫路徑預設 History 並自動執行查詢。
- Vue DEV fallback：`/YMES/WIP/ProbingLog`。只使用虛構測試紀錄 fixtures，純唯讀查詢，不呼叫任何 Service/API，不連 Oracle／PostgreSQL。

## 查詢條件

- 一般畫面至少勾選 Customer No、Lot No、MO No 其中一項；每個已勾條件都必須有值。OP No 與 Component No 為額外可選條件，勾選時也需有值。
- Customer No 以唯讀欄位加單選 Customer lookup；Lot No、MO No、Component No 使用文字欄位；OP No 以唯讀欄位加多選 OP lookup，送入逗號分隔清單。查詢條件以 AND 組合。
- Customer No 對應 Lot Basis 的 CustomerNo；Lot No 以 Component State 子查詢匹配 LotNo；MO No 與 Component No 使用包含字串查詢；OP No 使用 `IN` 精確匹配多選值。
- `Final Result` 預設勾選並送 `CurVersion=1`；`History` 不傳 CurVersion，載入所有版本。EndTestTime 的 From／To 可各自啟用；To 若只有日期，Core 擴到當日 23:59:59。WinForms 未驗證 From <= To。
- 若從 WIP 呼叫，傳入的 Lot／OP／MO／Component 直接組成查詢，預設切換 History 並自動載入；一般篩選視窗與日期條件不參與該次初始查詢。

## 結果欄位與 Bin

- Core 以 `tbl_CPWIPWAFERBINSUMMARY` 左連 `tblWIPLotBasis`，表格另查 `tbl_CPSYSBin`。依 `tblSYSParameter.P_WAFERMAP_EXTTESTINFO` 是否為 Y 決定是否額外查 `tbl_PWIPWaferBin_Ext`，把 MultiplicativeNumber 層的 BIN 欄展開為 BIN101+ 等欄位。全零的 Bin 欄會移除。
- Form 將 `LASERMARK`、`JudgeResult`、`SLotNo`、`CreateDate` 衍生成 `P_LASERMARK`、`P_JUDGERESULT`、`P_WaferID`、`UploadTime`。Grid 依 MO、OP、CustomerLot、Slot、EndTestTime、CreateDate 遞增排序。
- 固定可見欄位為 MESComponentNo、P_LASERMARK、ProductNo、MONo、CustomerLotNo、P_WaferID、ProgramNo、ProgramVersion、MESLotNo、OPNo、CurVersion、TotalTestQty／PassQty／FailQty、Yield、StartTestTime、EndTestTime、UploadTime、P_JUDGERESULT；各 Bin 欄依資料動態增加。DEV 用固定資料模擬 Final／History、Customer／Lot／MO／OP／Component／時間篩選及 BIN101+。

## 來源差異與限制

- Core ComponentNo 條件的字串組裝為 `strCondition += strCondition + " And ..."`，會把之前累積的條件再複製一次；同時有其他查詢條件時可能造成重複條件或 SQL 不合法。DEV 按畫面意圖只套用一次 Component 條件，正式 API 應採參數化條件並修正此缺陷。
- Service／Core 以字串串接建立 SQL，Lot／MO／Component 使用 `%...%` 查詢且無明確資料範圍上限。正式 API 須以登入者授權限制 Customer／Lot／MO 範圍、參數化查詢並設合理結果上限。
- 本機受保護 Oracle attachment/profile 不存在，未查 MESTEST DDL／metadata、未查業務資料，未連 YMES PostgreSQL，也未猜欄位型別、PK、constraint、index 或 CREATE-only SQL。`tbl_CPWIPWAFERBINSUMMARY`、`tbl_CPSYSBin`、`tbl_PWIPWaferBin_Ext` 及使用到的 Lot／Component／SYS parameter references 均需家用端先唯讀比對 live schema／migration；缺少同版 Oracle DDL 時不得自行推導 CREATE SQL。
- DEV 只保留頁面記憶體中的搜尋結果與操作訊息；不寫匯出檔、不接報表／資料寫入。未執行 build、test 或 browser。
