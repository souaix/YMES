## WinForms 查詢畫面

- 查詢條件為 Setup List No、主設備編號、RunCard、OP、建立日期區間、結單日期區間及狀態；條件啟用後才傳入 Service。日期預設當日 07:30 至目前時間，啟用區間時起始必須早於結束。
- RunCard 欄位在畫面命名為 `RunCardNo2`，Service/Core 查詢參數仍是 `LotNo`。Core 以設備設置單、`tblOPBasis`、`tblPRSProductionSegment` 查詢，僅保留 `HaveComponent = 1` 的 OP。
- Grid 顯示九欄：Setup List No、Main Equipment No、RunCard、OP、Status、Creator、CreateDate、CloseDate、CloseUser。
- ADD 建立單；EDIT 僅允許 Status=0；Detail 為唯讀；Close Setup 僅允許 Status=1；主 Form 查詢成功後定位回新增／編輯／結單的單號。
- 主設備查詢依本分支設備類別使用 PROBER。Def Form 中 HANDLER 選項被隱藏；需要選一部主設備及至少一部 TESTER。

## 設置單流程與規則

| 動作／狀態 | WinForms／Service／Core 行為 |
|---|---|
| ADD | 單號由 `SFN` + 兩位年 + 十六進位月份 + 兩位日 + 三位流水號組成；先讀 `tblSYSSerialNo` 最大序號，寫入前再檢查並更新。必要欄位為 RunCard、OP、唯一主設備、至少一部 TESTER。Setup accessory release 依設備／產品／客戶／OP 等條件載入。 |
| 新建 Status=0 | Core 建立 `tblWIPEQPSetupBasis`、附屬設備 detail 與 accessory 設定；若需要新配件領用，建立 `TBLWIPEQPACCESSORYBASIS`／detail 供獨立 EMS 配件發料流程處理。沒有新配件申請時，Core 直接將設置單狀態改成 1。 |
| EDIT | 只有 Status=0 可編輯。Core 更新主檔，並先刪除該 Setup No 下的 detail／accessory 設定後重建；家用端需將更新限定在仍為新建狀態並以交易防止與發料競爭。 |
| 配件發料 Status=1 | 主畫面只提供結單；配件申請與發料由獨立 EMS 流程執行，WPP03 沒有直接的「發料」按鈕。 |
| CLOSE → Status=2 | 只接受 Status=1。Core 檢查主設備及每部 TESTER 未被 Lot 使用；解除同設備既有關聯，舊設置單改 Status=99 並結束關聯 Log；新增本單的 equipment Link State／Log，寫入 CloseDate／CloseUser，並依已勾選的現況配件更新 Setup accessory state、EMS 配件狀態與歷程。 |
| VIEW | 使用獨立唯讀 Form 顯示主檔、設備、附屬設備及配件內容。 |

Def Form 還會依 RunCard／OP 取得產品、Device、Area、ECN、OP 屬性（`CPProgramNo`）、允許設備／附屬設備及配件 release 限制。配件檢核包括每類數量、Accessory Release 允許型號或 `*`、配件現況與設置數量一致、配件選取數符合 Qty、Accessory/Site 不重複，以及 SOCKET 必須指定 Site Number。結單配件由人員逐筆實物確認，程式不會假設「設定單上有列」就代表現場已裝妥。

Status 值：`0` 新建、`1` 配件發料完成、`2` 已生效、`99` 歸檔。

## Service 與 Core 直接資料表

Core SQL 直接讀寫／查詢到的表名如下；下列清單是依可讀程式碼辨識，不代表已取得 MESTEST 的 schema metadata：

- WPP03 主／明細／配件：`TBLWIPEQPSETUPBASIS`、`TBLWIPEQPSETUPDETAIL`、`TBLWIPEQPSETUPACCESSORY`、`TBLWIPEQPSETUPACCESSORYSTATE`。
- 配件領用：`TBLWIPEQPACCESSORYBASIS`、`TBLWIPEQPACCESSORYDETAIL`。
- 設備關聯／使用守門：`TBLWIPEQUIPMENTLINKSTATE`、`TBLWIPEQUIPMENTLINKLOG`、`TBLWIPTEMP_EQUIPMENT`。
- EMS 配件狀態與控制：`TBLEMSEQPACCSTATE`、`TBLEMSACCESSORYSTATE`、`TBLEMSACCESSORYSTATELOG`、`TBLEQPACCSTATECONTROL`、`TBLEMSACCVIOLATESTATUSCHANGE`。
- 設備與配件查找／相容性：`TBLEQPEQUIPMENTBASIS`、`TBLPRDACCESSORYGROUP_SUB`；其他查詢資料由 Service 呼叫的 Lot、OP、PRS、設備 release、配件 release、ECN 與狀態 lookup 提供。
- 單號：`TBLSYSSERIALNO`，由 `GetMaxSerialNo`／`UpdateMaxSerialNo` 使用。

Repo 目前沒有 `TBLPRDACCESSORYGROUP_SUB` 與 `TBLEMSACCVIOLATESTATUSCHANGE` 的 source DDL／metadata reference；需用目標 MESTEST 版本確認替代配件判斷及禁止狀態轉換規則。

## Oracle DDL／家用端 handoff

桌機上已檢查筆電交接所記錄的受保護 attachment 路徑是否存在；檔案不存在，`Oracle.ManagedDataAccess` 也未載入目前 PowerShell 工作階段，沒有可用的桌機 Oracle profile。因此本次未連 Oracle MESTEST，也沒有讀業務資料或取得新的 source DDL／metadata。WPP03 專屬表 `TBLWIPEQPSETUPBASIS`、`TBLWIPEQPSETUPDETAIL`、`TBLWIPEQPSETUPACCESSORY`、`TBLWIPEQPSETUPACCESSORYSTATE`、`TBLWIPEQPACCESSORYBASIS`、`TBLWIPEQPACCESSORYDETAIL`、`TBLWIPEQUIPMENTLINKSTATE`、`TBLWIPEQUIPMENTLINKLOG`，以及 lookup `TBLPRDACCESSORYGROUP_SUB`、`TBLEMSACCVIOLATESTATUSCHANGE` 缺同版 source DDL／欄位／PK／index/default metadata；未產生推測的 PostgreSQL CREATE-only SQL。共用相依表可先核對 repo 已有 references：`TBLWIPTEMP_EQUIPMENT`（WP201）、`TBLSYSSERIALNO`（WP109）、EMS accessory state/control（accessory basis references）。家用端不得以 WinForms INSERT 欄位臆造正式 schema。

家用端正式 API／schema 工作建議：

1. 先對照 YMES live migration／schema 與 MESTEST 同版本 DDL，再決定上述共享或 WPP03 專屬表是否已存在、欄位版本及 constraints；不可因 DEV fixtures 建立新表。
2. 提供有登入者身分保護的搜尋、RunCard/OP/設備/配件 release lookup、ADD、EDIT(Status=0 only) 及 CLOSE(Status=1 only) API；參數化 SetupNo、設備、RunCard、OP、狀態和日期條件。ADD 以 `TBLsySSerialNo` 同步鎖／重查序號，EDIT 與 EMS 發料需避免競爭。
3. ADD／EDIT 需原子維護 Setup basis/detail/accessory 與配件申請資料；辨識已在設備上的主要／替代配件，維持 Core 的「沒有新領用則 Status=1」規則。
4. CLOSE 前重查所有主／附屬設備 Lot 使用狀態、目前設備綁定、產品 Accessory Release、Accessory Qty／序號與 Site；以一筆可恢復交易或明確 saga 更新舊／新設備關聯、歷程、Setup 狀態及 EMS 配件狀態。外部實物確認與每筆 accessory 選取需記錄登入者／時間。
5. 把失敗部分結果、並發關單／發料、設備仍在生產、被替代配件、重複 Site、受限狀態不得轉 Apply、配置有配件但實際數量不符等情境寫入 API acceptance criteria。
