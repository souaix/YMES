## WinForms 畫面

Form 標題為 **Batch Create Lot and Release**。選取工單後帶入工單類別、客戶、RO、項次、產品／版次、單位、未下線數及優先序；使用者輸入 Release Qty、Priority、Hot Lot 和 Description。初始分批模式為 **by Qty**。畫面包含：

- **Create Type**：by Count／by Qty，輸入 Lot Count 或 Lot Qty，按 Expand 展開批次。
- **Lots Grid**：BaseLotNo、InputQty 可編輯；自動序號模式下 BaseLotNo 唯讀。數量需大於 0。
- **BOM**：唯讀 BOM Grid，欄位顯示 MaterialNo（來源 NodeNo）與 OPNo。
- **Process**：核取要執行的流程，顯示 PSOrder、PSNo、ProcessNo、ProcessVersion；按鈕 Add、View、Tuning。
- 下方稽核欄 Creator/Create Date；Confirm 送出一次批次請求，成功即關閉 WinForm；Close 關閉不送出。

工單查找清單顯示 MO No、Customer No、RO No、Item No、Product No/Version、MO Qty、UnRelease Lot Qty、MO Unit。Form 以 wsOE.LoadMOBasis 查 MOState=3、IssueState 不限且 UnReleaseLotQty>0。Core 送出前再次確認工單存在、仍為狀態 3 且剩餘量足夠；此候選條件與 WP101 的 MOState 3 或 6 不同。

## 載入資料

選取工單後，Form 呼叫：

- wsSYS.LoadMOType：工單類別名稱。
- wsOE.LoadMOProcess：載入工單流程；預設全選並依 PSOrder 排序。
- wsPRD.LoadBOM(ProductNo, ProductVersion)：BOM 依 NodeNo、OPNo 排序，Grid 僅顯示 MaterialNo 與 OPNo。
- wsPRD.LoadProductProperty(ProductNo, ProductVersion, PropertyNo="LotBase")：取得產品 LotBase 預設分批量；查不到時預設 1。
- wsSYS.LoadSerialConfig(SerialType="LOTNO")：SerialMode 1/2/3 使用自動序號；0 為停用。Mode 4 表示沿用工單號碼，批次 Expand 不支援並停用。
- wsSYS.GetLotNo_Multiple：Expand 預覽時 ReserveSerialNo=False；Confirm 前重查最新號，首號不一致則要求重新展開；一致才 ReserveSerialNo=True。

## 操作及驗證

1. 按「...」選擇可下線工單；Release Qty 預設等於全部 UnRelease Qty、Lot Qty 預設為產品 LotBase，Create Type 預設 by Qty。
2. **by Count**：前 N−1 批取 floor(ReleaseQty / LotCount)，最後一批收差額；總和需等於 Release Qty。若展開零數量批，Confirm 會被每筆 InputQty > 0 擋下。
3. **by Qty**：以 Lot Qty 建立整批，尾數（至多四位小數）併入最後一批；整除時不建零批。
4. 展開後可改 BaseLotNo／InputQty（自動編碼時批號唯讀）。Confirm 檢查 MO 必填、Release Qty 為數字且不大於 UnRelease Qty、Priority 必填、Process 不可空、第一筆未過濾流程若 HaveComponent=1 則不支援、至少選一筆流程、同一 PSOrder 不可選多筆、批號非空、數量為正且加總等於 Release Qty。
5. Process Add 由 WP_LotBasisProcessDraw 取回流程；View 以 ProcessNo/Version 檢視；Tuning 呼叫 WP_ProcessTuning，取得新 ProcessNo/Version 後取代原列。送 Service 時按 PSOrder 排序，重編 ProcessOrder 1..N。
6. Confirm 一次呼叫 wsWIP.AddLotBasis_Batch，參數含 MO、Release Qty、Priority、Description、HotLot、BaseLots 與 LotProcess。自動序號先驗證再保留。

## Service／Core 寫入與交易

Service 從批次列建立 BaseLotNo/InputQty 及客製欄位 SAP_PCSQTY、SAP_ARGQTY、SAP_PRDQTY、Item、WIP_CIMLOTNO、WIP_INSP_NO、WIP_M_LOTNO。UI Grid 僅顯示批號與數量；客製 SAP／檢驗欄位由 Service 轉為批號屬性 WIP_BIGQTY、WIP_SORTQTY，以及可選 WIP_CIMLOTNO、WIP_INSP_NO、WIP_M_LOTNO。SAP 數量另更新 TBLWIPLOTBASIS.SAP_PCSQTY/SAP_ARGQTY/SAP_PRDQTY；三欄已在 WP101 Oracle DDL，無須另建表。

Service 在 Core 前將屬性寫入 TBLWIPLOTPROPERTY_TEMP；Core 依批號排序逐筆處理，批次建檔標記 DeviceNo=Batch，新增 lot basis/state/process，呼叫 StartLot 與 LotCreate 物料扣帳，將 LotState 由 0 改為 1，並以 MO 狀態及讀取到的 UnReleaseLotQty 條件扣減工單餘量。起始流程包含自動 BR 時，可能繼續 TriggerOP、TriggerPhase、ExecuteBR、TransferLot。Service 後續清理 TEMP／正式屬性舊列，再寫 TBLWIPLOTPROPERTY 和 SAP 欄位。

這不是可假定全有或全無的單一交易：客製 Core 逐批執行，Service 暫存、Core 批次及後處理分段呼叫 SQL 執行器。正式 API 必須逐筆回報成功／失敗，明確處理前批成功、後批失敗；不可謊稱整批回滾。建議同一 MO 鎖／交易內重查餘量並條件扣量，保留 LotState、DeviceNo、影響筆數檢查；序號保留與暫存清理要有失敗復原策略。API 不可直接接受未驗證的動態屬性目標表／欄位。

## 資料表與 SQL 交接

| 表 | WP102 用途 | 結構交接 |
| --- | --- | --- |
| TBLWIPLOTBASIS、TBLWIPLOTSTATE、TBLWIPLOTPROCESS、TBLWIPLOTPROPERTY | 建批、起始站、流程、正式屬性與狀態 | 共用 WP101；引用既有 DDL，不重複建立 |
| TBLOEMOBASIS | 工單狀態、餘量與扣量 | OE 共用表；不由 WP102 建立 |
| TBLWIPLOTPROPERTY_TEMP | Service/Core 間的客製屬性暫存 | WP102 新增 Oracle source DDL／PG CREATE-only |
| TBLOPBusinessRuleBasis、物料、產品、流程及序號表 | Core 查詢／執行業務規則 | 共用相依；不另建 |

- Oracle source DDL：database/reference/mestest_wip_wp102_source_ddl.sql。
- PostgreSQL CREATE-only：database/reference/mestest_wip_wp102_create.sql；僅含 WP102 新增需求 TEMP。永久 TBLWIPLOTPROPERTY 已在 WP101 CREATE-only，勿重複。
- TEMP 欄位：LOTNO NVARCHAR2(50) NOT NULL、PROPERTYNO NVARCHAR2(20) NOT NULL、PROPERTYVALUE NVARCHAR2(255) NULL、LOTSERIAL NVARCHAR2(55) NULL；PK (LOTNO, PROPERTYNO)。只有 PK unique index，無 FK／Trigger／其他 index。
- SQL 是來源／空表型別參考，不是可直接執行的 migration。家用端先查 live schema/migrations；只在確認缺少物件時新增 forward migration。

- 已做工單選擇、by Count/by Qty、批次 Grid、數量驗證、BOM/Process、Add/View/Tuning 假視窗、Confirm 假結果及本機假工單餘量扣減。

## 家用端 API handoff

建議提供候選工單與批次資料載入端點，以及一個批次命令，例如：

POST /api/wip/lots/batch-release

請求至少包含 MO No、Release Qty、Priority、HotLot、Description、各批輸入數量及選取流程（PSNo、PSOrder、ProcessNo、ProcessVersion、順序）。正式自動序號由 server 按 SYS LOTNO 規則驗證並原子保留，不可沿用瀏覽器 DEV 號碼。LotBase、MO type、BOM、流程及 serial mode 都須由 server 依工單／產品重查，不信任 UI 傳入的顯示欄位。

回應須逐批回報成功／失敗、錯誤碼與可安全重試資訊，附更新後 UnReleaseLotQty；餘量不足、序號競態需明確衝突，不可 HTTP 200 偽報全部成功。需評估以 transaction 取代 legacy TEMP；若沿用暫存表，失敗時清理並避免共用暫存鍵污染。
