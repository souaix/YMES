# WP604 半成品庫帳務維護（SEMI INV）

## 功能定位

- MES FunctionNo：`SEMI INV`；FunctionKey：`WP604`；Form：`frmInventory_SEMI`；執行檔：`WP_Inventory_SEMI.dll`。
- 三層選單：在製品管理 → 包裝與庫房 → 半成品庫帳務維護。
- 主畫面標題 `SEMI Inventory`，WinForms ClientSize `784×561`。
- 主畫面查詢半成品庫存，並提供 `SEMI In` 入庫確認與 `Turn Inv` 轉庫。沒有人工 Add/Edit/Delete。

## WinForms 主畫面

### 版面與按鈕

- 頂部只有 `Inventory No` 文字欄位與 `...` 查找。輸入後 Enter 會轉大寫並查詢；查找清單只載入 `InventoryType=2`。
- 上方主庫存 Grid 位於 GroupBox `gbxSEMIBasis`，位置約 `(8,36)`、尺寸 `672×327`；下方明細 Grid 約 `(8,363)`、尺寸 `672×190`。兩個 Grid 由主畫面選列連動。
- 右側三個按鈕：`SEMI In` `(688,40)`、`Turn Inv` `(688,80)`、`Close` `(688,520)`。點選 SEMI In 開啟 `frmINVSEMIInConfirm`；Turn Inv 必須先選一筆庫存列，再開 `frmInventory_SEMITurn`。
- 主 Form、Turn、SEMI In 的來源都在同一個 VB 檔內含 Designer 初始化程式碼，沒有獨立 `.Designer.vb`。

### 主 Grid

只顯示所選 Inventory 的庫存列，條件為 `InventoryNo` 相符、`LocQty > 0`，排序 `ProductNo, LotNo, LocatorNo`。可見欄位順序：

| 順序 | 欄位 | 顯示設定 |
| --- | --- | --- |
| 1 | ProductNo | 產品編號 |
| 2 | LotNo | Lot 編號 |
| 3 | LocatorNo | 儲位 |
| 4 | LOCQty | 數量，`0.######` 靠右 |
| 5 | UnitNo | 單位 |
| 6 | BelongToType | ValueList 僅明確映射 `0 → MO` |
| 7 | BelongToNo | 歸屬編號 |
| 8 | InputDate | `yyyy/MM/dd HH:mm:ss` |

選取主 Grid 列時清空下方 Grid，先呼叫 `wsINV.LoadSEMIInventoryComponent(InventoryNo, LotNo, LocatorNo)`。若有 Component，顯示 `ComponentNo, GoodQty, ScrapQty, UnitNo`；沒有 Component 才呼叫 `wsWIP.LoadGoodBinState(LotNo)`，依 `wsSYS.LoadBin` 的 `BinOrder` 動態產生 Bin 欄。Component 與 Bin 明細互斥。

## SEMI In 確認

- 子 Form：`frmINVSEMIInConfirm`，標題 `INV SEMI In Confirm`，ClientSize `680×510`。
- Basis 欄位：`SEMIIn No` 及 `...`、`Inventory No`、`Description`、`Creator`、`Create Date`；Detail 是階層 Grid，按鈕 `Confirm`、`Close`。
- `...` 呼叫 `wsINV.LoadINVSEMIInBasis(State=0)`，只提供未確認單據；選取後填 Basis 欄位並呼叫 `wsINV.LoadINVSEMIInDetailAndComponent(SEMIInNo)`。
- 主 Detail 欄位依序為 `ProductNo, LotNo, Qty, UnitNo, LocatorNo`；子 Component 欄位為 `ComponentNo, GoodQty, ScrapQty, UnitNo`。
- Confirm 必須有 SEMIInNo，呼叫 `wsINV.AddINVTransactionState(Source=20, TicketNo=SEMIInNo, Creator=登入者)`。這裡的交易 `Source=20` 是「半成品入庫交易」種類，與 `TBLINVSEMIINBASIS.Source` 不同。
- 入庫單 Basis 的 `Source`：Core 註解定義 `0=手動開立（外購）`、`1=From WIPInventory_SEMI`。Source=1 必須有 `FromInventoryNo`，且成功過帳會從來源 WIP/SEMI 庫扣除；不可將單據來源欄與交易狀態 Source 混為一談。
- 交易引擎狀態 `0=UnConfirm, 1=Handling, 2=Confirm, 3=Failed`。`wsINV.AddINVTransactionState` 建立/處理 `TBLINVTRANSACTIONSTATE`，呼叫 `clsInventory.ExeSEMIIn`，成功更新 Basis State=2 並將成功交易移入 `TBLINVTRANSACTIONLOG`；失敗狀態與錯誤記錄需沿用共用交易契約。
- `ExeSEMIIn` 會依明細檢核來源與目的儲位容量、寫入/合併 `TBLINVSEMIINVENTORY`、Component 資料，並更新 Lot/Component 狀態、數量與入庫 Lot release log（UserActiveId=13）。來源為 WIP/SEMI 時還會扣除來源庫存；存在 `SEMI_WAFER` 行業包與動態 Component Rule 分支。正式 API 必須處理完整交易與失敗回滾，不可只改 Basis 狀態或插入交易 queue。

## Turn Inv 轉庫

- Form：`frmInventory_SEMITurn`，標題 `SEMI Turn Inventory`，ClientSize `664×518`。必須從主畫面選取一筆庫存列後開啟；目前列會預先勾選。
- 可依 `LotNo` 精確掃描選取；亦可依 `ComponentNo` 查 Component State 並勾選關聯 Lot。使用者可在 Grid 多選。
- 轉出列載入所選 SEMI Inventory，主要欄位為勾選、LotNo、LocatorNo、ProductNo、BaseLotNo、LocQty、UnitNo。舊 Designer/初始化有重複設定 LocatorNo 顯示位置；Web 表格只顯示一次。
- 目的庫別為 WIP（InventoryType=6）、FGD（1）、SEMI（2）；各目的庫別有獨立 InventoryNo／LocatorNo 查找。轉入 SEMI 時不可選目前來源庫。轉入庫房與儲位必填，儲位須屬於目的庫且符合舊程式核准條件。
- 確認前依目的儲位 Capacity 檢查既有佔用量加本次總量；`Capacity=0` 代表不限制。確認呼叫 `wsWIP.Exe_SEMITurn` → `clsLot.ExeSEMITurn`。
- 正式轉庫可能搬動/合併 SEMI 庫存與 Component、轉至 FGD/WIP 庫表、更新 WIP Lot/Component State 及反向狀態、處理 `SEMI_WAFER` 與動態 `TBLWIPCOMPRULEMAP_*`／`TBLINVTemp_Component` 分支，並新增 Lot release log（UserActiveId=15）。這是跨表交易，不是單改 InventoryNo/LocatorNo。

## Oracle DDL 與資料表

使用公司端本機受保護連線，由 Windows PowerShell 5.1 + `Oracle.ManagedDataAccess.dll` 直連 MESTEST 只讀取得 `DBMS_METADATA.GET_DDL` 及資料字典；未讀業務資料列、未執行 Oracle DDL/DML、未保存連線秘密。

此次核實四張 SEMI 專用表；四表均有自己的 PK unique index，沒有額外索引、FK 或 Trigger。共用 `TBLINVTRANSACTIONSTATE/LOG` 已由 WP605 建立來源參考；`TBLINVSEMIINVENTORY` 已在 WP201 additional reference。不可重建共用表。

| Oracle table | 主鍵 | 用途 |
| --- | --- | --- |
| `TBLINVSEMIINBASIS` | SEMIINNO | SEMI In Basis 與交易狀態來源 |
| `TBLINVSEMIINDETAIL` | SEMIINNO, LOTNO, LOCATORNO | 入庫 Lot／儲位明細 |
| `TBLINVSEMIINCOMPONENT` | SEMIINNO, LOTNO, COMPONENTNO | 入庫 Component 數量 |
| `TBLINVSEMIINVENTORYCOMPONENT` | INVENTORYNO, LOTNO, LOCATORNO, COMPONENTNO | 半成品在庫 Component；WP201 additional DDL 未包含，於本項補查 |

## YMES API／DB 交接（家用端）

1. 先比對 live PostgreSQL schema 與 migrations。WP604 的 CREATE-only 是欄位參考，不是 migration；僅在逐表確認缺漏、保留現有資料並完成備份後補 forward migration。
2. 庫房 lookup 僅回 InventoryType=2。庫存查詢保留 `LocQty>0` 與 ProductNo/LotNo/LocatorNo 排序；row detail 先回 Component，無資料再回依 BinOrder 排列的 Good Bin。
3. SEMI In lookup 限 State=0；明細查詢同時回傳 Component 子列。Confirm API 需在單一交易內重查 ticket 狀態、來源、Lot、庫房/核准儲位、容量及目前數量，防止重複確認與競態。
4. 對外請求須明確攜帶 `SEMIInNo` 與登入使用者上下文；交易種類固定由 server 設為 Source=20，不能採信 UI 送入任意交易種類。ticket 的 Basis Source=0/1 由伺服器讀取，Source=1 扣來源庫存。
5. 成功/失敗需完整遵守交易 State/Log、Basis State、庫存、Component、Lot/Component State、release log 的原子性與既有錯誤回報。先沿用 WP605 共用交易表及狀態設計，不新增重複表。
6. Turn API 需驗證來源列仍存在且數量未變、目的 InventoryType、Locator 所屬及狀態、容量、lot/component 關聯；跨 SEMI/FGD/WIP 的庫存與狀態更新須同交易完成，並保護並發數量。歷程由既有 release-log contract 寫入。
7. `SEMI_WAFER`、`TBLWIPCOMPRULEMAP_*`、`TBLINVTemp_Component` 與外部 WIP release-log handler 是分支相依。正式接入前核對 home checkout 中可用 package/schema；缺失時回報具體相依，不可默認跳過或假稱等價。

## 公司端 Vue DEV 實作與限制

- 頁面 `/YMES/WIP/SemiInventory`；三層 fallback menu 為「在製品管理 → 包裝與庫房 → 半成品庫帳務維護」。
- DEV 使用專屬 localStorage key `ymes.dev.wp604-semi-inventory.v2`，包含庫房、庫存、動態 Bin、Component、SEMI In tickets 與轉庫紀錄；不呼叫 API／資料庫。非 DEV 環境不載入任何 seeded 假資料。
- 已有庫房查找、上方庫存 Grid、列選擇即時顯示 Component/Bin、SEMI In 單據選擇與假確認、Lot/Component 轉庫多選、目的庫/儲位與容量驗證。
- DEV 的 Turn/SEMI In 只更新假資料並提供回饋，不模擬 Oracle/Core 的完整跨表交易、Lot state、ERP、外部 release-log、SEMI_WAFER 或動態 package side effects；Production API 尚未接入。
- 依使用者目前工作規則，未連 YMES PostgreSQL，未執行 build、test 或 browser。
