# WP510 等待單資料

## 來源與範圍

- 選單：在製品管理 → 異常與等待 → 等待單資料，`FunctionNo=WAIT BASIS`、`FunctionKey=WP510`、`WP_WaitBasis.dll`。公司 Vue DEV 路徑 `/YMES/WIP/WaitBasis`，元件 `web/src/components/WipWaitBasis.vue`。
- 主 Form：`STD/MESWin/WIP/WP_WaitBasis/frmWaitBasis.vb`（含 Designer）；唯讀子窗：`STD/MESWin/WIP/WP_WaitInformation/frmWaitInformation.vb`。Service `STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `LoadWaitBasis`、`LoadWaitLotDispJoinNodeBasis`；Core `STD/MESkc/kcWIP/clsLot.cs` 同名方法。查找另由 `wsENT.LoadCustomerBasis`、`wsOP.LoadOPBasis` 提供。這個功能沒有變更等待單的 Confirm/POST。

## 原 WinForms 畫面與查詢

主窗標題 `WaitBasis`，ClientSize 1008×661。上方 Query 有 Lot No、Wait No、OP No、Customer No 四個勾選欄與 Create Date、Release Date 兩組勾選日期起訖；OP/Customer 旁有 `...` 查找。Lot No 的 `...` 控制在 Designer 設為 `Visible=False`，不用在 Web 畫面顯示。下方 Result Grid 有 15 欄，依序 Wait No、Lot No、Product No、Lot Serial、Status、OPNo、CustomerNo、Wait Description、RuleNo、CreateQty、Creator、Create Date、Release Qty、Release UserNo、Release Date；右側 Wait Info、Close，底部狀態列。

勾選文字欄且非空時才送條件；取消勾選會清空該文字。日期初值是目前時間往前七天到目前時間，但初始**沒有勾選**。所有有效條件皆無時，原 Form 阻止查詢；再固定送 `WaitSource=0`（WIP），此固定值不算使用者條件。`WaitNo`、OPNo、CustomerNo 用精確比對，LotNo 用包含查詢；建立/解除日期含起訖時間。Grid 將 Status 轉成 0=Wait Undisposition、1=Wait Wait Disposition、2=Notice Customer and Wait Disposition、3=Waive、11=Wait Lot Disposition、12=Abort、21=Release、31=Hold Bank。沒有啟動自動查詢。

Wait Info 需選取主 Grid 一列，將整筆 `WaitBasis` DataRow 傳給 `WP_WaitInformation`。子窗唯讀顯示 Lot No、Wait No 與一個 Wait Lot Disposition Grid：LotDispType、Description、Creator、CreateDate、OPNo、ProcessNo、ProcessVersion，依 CreateDate 由新到舊。LotDispType 使用原 ValueList：0 GO、1 Jump OP、2 Jump Process、3 WIP Semi Inventory、4 Process Tuning、5 Change ENGNo、6 Jump Module、7 WIP Scrap Inventory、8 Jump Main、11 Back To ERF Disposition、12 Split、13 Merge、14 Qty Adjust。此子窗其餘附件／ERF 區塊載入呼叫已在原碼註解，不列入復刻。

## Service/Core 查詢與 API

`clsLot.LoadWaitBasis` 只讀 `TBLWIPWAITBASIS`，基礎條件 `LotNo Is Not Null`，再組上述選填條件。`LoadWaitLotDispJoinNodeBasis` 從 `TBLWIPWAITLOTDISPOSITION A` 左連 `TBLPRSNODEBASIS B` 的 `A.NodeID=B.NodeID`，取 `B.NodeNo AS OPNo`、ProcessNo、ProcessVersion；子窗按 WaitNo 查明細。Oracle source `TBLWIPWAITBASIS` 已在 WP201，`TBLPRSNODEBASIS` 在 PRS104。原 Service/Core 直接拼接 SQL；正式 API 應採參數化、登入與 WP510 權限、至少一個有效條件、結果上限/分頁。不要接受 browser 傳任意 SQL Additional。日期用明確時區與含端點契約；未解除的 ReleaseDate 為 NULL，指定解除日期時自然排除。

正式 API 建議兩個唯讀 endpoint：分頁 GET `waits`（四個文字勾選值、兩日期區間；後端固定 WaitSource=0）、GET `waits/{waitNo}/dispositions`（核可見範圍，左連 NodeBasis，排序 CreateDate DESC）。回傳 Status 原數字及顯示字、15 欄主 Grid 與 Wait Info 七欄；查找 Customer/OP 需有權限和數量上限。`TBLWIPWAITLOTDISPOSITION` **沒有 PK/unique**，不能將 WaitNo 當處置列唯一鍵，也不能假定同一秒不會有重複事件；API/前端如需穩定 row id，須先調查 live 資料與正式契約，不可暗改源表約束。

## Oracle DDL 與 PostgreSQL CREATE-only

公司端使用 PowerShell 5.1 + 受保護 MESTEST profile + `Oracle.ManagedDataAccess.dll` 唯讀呼叫 `DBMS_METADATA.GET_DDL`、`ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_INDEXES`、`ALL_TRIGGERS`，新增來源表 `TBLWIPWAITLOTDISPOSITION`：13 欄、5 個 NOT NULL、**無 PK/FK/unique/trigger**，只有 `WAITNO` 的一個非唯一 index。檔案為 `database/reference/mestest_wip_wp510_disposition_source_ddl.sql`、`mestest_wip_wp510_disposition_source_indexes.sql`、`mestest_wip_wp510_disposition_metadata.txt`，對應 PG 空表與 index 參考為 `mestest_wip_wp510_disposition_create.sql`。它不是已套用的 migration。家用端先對 YMES live schema/history；只補實際缺少的表/欄/index，不重建已有表、不猜 PK/FK。主表 `TBLWIPWAITBASIS` 原 DDL/PG CREATE 沿 WP201，NodeBasis 沿 PRS104，不重複產 SQL。
