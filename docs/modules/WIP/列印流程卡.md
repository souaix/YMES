## WinForms 畫面

- 主視窗由上到下為 Query、SetUpPrinter、Lot State 與 StatusBar。Query 的六個輸入欄位：Area No、PS No、OP No、MO No、CustomerLotNo、Lot No；Area、PS、OP、MO 有 `...` lookup；Query 執行查詢。
- `In Inventory` 控制項在 Designer 存在，但 Form_Load 設為 unchecked 且 `Visible=False`，所以一般使用者查詢不包含庫存批。
- SetUpPrinter 的 PrinterName 欄位唯讀，`...` 從本機已安裝印表機選擇；選擇值存於 `%AppData%\iMESTech\MESSeries\RunCardPrinter.txt`。DEV 使用虛構印表機與獨立 localStorage 值，不呼叫本機或伺服器印表機。
- Lot State 上方選項為 Current Process（預設）、Current PS Processes、All Processes、Include Log（預設勾選）；左側 Grid 支援多選，右側按鈕為 Preview、Print、ShippingNO、Close。底部顯示查詢狀態。
- `ShippingNO` 按鈕仍在 Designer，但其 Click handler 已於 2020/07/15 註解，沒有執行功能；DEV 保留按鈕並提示來源現況。

## 查詢規則

1. Form_Load 載入 `RunCardStyle` 系統參數，沒有資料時預設 0；並讀取本機 PrinterName。表單不會在載入時自動查詢，需按 Query。
2. 一般查詢呼叫 `wsWIP.LoadLotBasisJoinState`，傳 `Status=0|1|4`（Queue、Running、Complete）及使用者填入的 AreaNo、PSNo、OPNo、LotNo、CustomerLotNo、MONo。Form 將文字轉大寫；Core 對 Area/PS/OP 做等值條件，MONo 與 CustomerLotNo 依傳入條件查詢，LotNo 支援以 `|` 分隔的多值。
3. Service/Core 對 LotBasis、LotState、Process/Product、OP、Customer 等既有資料作 join。回傳後 WinForms 再以 `LotState <> 0` 篩除，排序為 `HotLot DESC, Priority, LotNo`。`Status` 和 `LotState` 是不同欄位／用途。
4. Area、PS、OP、MO lookup 沿用既有 `LoadAreaBasis`、`LoadProductionSegment`、`LoadOPBasis`、`LoadMOBasis` 資料，不建立新 lookup table。

## 預覽與列印

- Preview 先要求作用列；若作用列尚未勾選，會自動加入選取集合。可對多筆所選 Lot 逐筆產生報表並合併預覽。
- RunCardStyle=0 使用 ActiveReports：先載入所選 Lot 的 RunCard Log（只有 Include Log 勾選時），再依 Lot 的 ProcessNo/Version、目前 OP/Node、Module 與 Process Segment 呼叫 `LoadRunCardData`；網狀製程改走 `wsWIP_NetFlow.LoadExpandProcess`。若有歷程，報表以 RunCardLog 為主，並將尚未完成的流程站接在後面。載入使用者定義 `Runcard` 報表範本並填入 Lot、Product、Customer、MO、數量、日期與版本欄位。
- Current Process、Current PS Processes、All Processes 分別傳 `IsAllProcess=2/1/0` 給 Core；Core 預設或無效值採 All Process。Include Log 只控制 ActiveReports 取得 RunCard Log。
- RunCardStyle 非 0 時走產品流程卡對應：載入 `tblPRDRunCardMap`，先找 Lot 的 ProductNo，沒有精確對應時採 `ProductNo='*'`；找不到 wildcard 時提示缺少產品流程卡。Preview 對每個選取 Lot 執行 `PD_Kit.clsPRDKit.funRunCardExecute(..., mode=0)`。
- Print 在 RunCardStyle=0 分支只處理作用列（SAMPLE Enterprise 不執行）；RunCardStyle 非 0 要求 PrinterName，對所選 Lot 逐筆執行 map，`mode=1` 並傳入印表機。
- DEV 預設使用 RunCardStyle=0 的假報表資料。Preview 可顯示所選 Lot；Print 只開啟作用列的模擬預覽，不送出實際列印工作。Custom RunCardMap/PD_Kit 是 Production 端須另外移植／提供相容報表 renderer 的客製分支，不可在 API 尚未具備時回報列印成功。

## 資料表與 DDL

WP103 沒有新增的專用業務表；讀取既有 Lot Basis/State、Process Node/Relation、OP、Product、Customer、RunCard Log、Product RunCard Map、User Defined Report 及 System Parameter 資料。公司端本輪不重複查 Oracle DDL，也不產生重複 CREATE-only。家用端應先核對 YMES PostgreSQL live schema/migration history，沿用既有 schema；若必要依賴表確實不存在，再補查該表 source DDL 並新增 forward migration。

## Vue DEV 實作

- 頁面採 DEV 假資料；無資料時需明確按 Query。查詢欄位、四個 lookup、Lot State Grid、選取狀態、三種流程範圍、Include Log、印表機選擇、Preview/Print/ShippingNO/Close 均對照 WinForms。
- DEV fake lots 使用 Status 0/1/4，另放入 Status 11 與 LotState 0 樣本以驗證預設查詢排除條件。排序保持 HotLot、Priority、LotNo。印表機值只存 `ymes-dev-mock:wip-run-card:printer:v1`。
- DEV 預覽用固定範例流程／歷程資料，呈現 RunCard 主要欄位與多筆預覽切換；不讀正式 API、不列印、不存放實際生產資料。

## 家用端 API handoff

下列為 API contract 草案；資料表和共用 lookup 先依 YMES live schema/API 確認，不新增重複 master schema。

| 方法 | 路徑 | 規則 |
|---|---|---|
| GET | `/api/wip/run-cards/lots` | 登入授權的批號查詢；接受 `areaNo`、`psNo`、`opNo`、`moNo`、`customerLotNo`、`lotNo`。預設狀態固定為 `0,1,4`，server 依來源排除 `LotState=0` 並排序 HotLot DESC、Priority、LotNo；Inventory 選項目前 WinForms 隱藏，不應由一般頁面預設開放。使用參數化查詢及分頁上限。 |
| GET | `/api/wip/run-cards/lookups/{kind}` | `kind` 僅允許 area、production-segment、operation、manufacturing-order；重用現有核准主檔／lookup API，不接受任意表名或 SQL。 |
| POST | `/api/wip/run-cards/preview` | body `{ lotNos, activeLotNo, processScope, includeLog }`；驗證 lot 都在使用者可查範圍。Preview 回傳單一合併 PDF 或明確定義的報表 DTO；`processScope` 對應 2/1/0，Include Log 對應 Log 載入。RunCardStyle=0 使用伺服器端 ActiveReports 相容範本／渲染器，保留網狀流程分支和 `Runcard` 使用者範本資料。 |
| POST | `/api/wip/run-cards/print-document` | body 沿用 Preview；RunCardStyle=0 相容 WinForms 僅輸出作用列，非 0 才處理選取列及產品對應精確／`*` fallback。回傳 PDF 供使用者瀏覽器列印；不得接受 client 指定 server printer 或伺服器印表機路徑。 |

Production 需要依登入者與 FunctionNo=`RUN CARD` 的 ACL 保護。RunCardStyle 必須由受控系統參數解析，不能由 browser 任意切換。RunCardStyle 非 0 的 `PD_Kit.clsPRDKit.funRunCardExecute` 是舊 WinForms/客製報表依賴；家用端需先確認可移植 renderer 及產品 RunCardMap 範本格式。若尚未移植，該模式應回傳明確不支援錯誤，不得返回空 PDF 或假成功。瀏覽器印表機由使用者在瀏覽器列印對話框選擇，不能重現 WinForms 對本機印表機名稱的 server API 呼叫。

公司端未連 YMES PostgreSQL，未實作 Production API/migration，未執行 build、test 或 browser 驗收。
