## WinForms 版面與互動

### Execute 區

- Employee No、Component No、Lot No 由左至右排列。Employee No 必填；Component No 與 Lot No 擇一即可。
- Employee No 按 Enter 會移至 Component No；Component No 或 Lot No 按 Enter 會執行。
- 若 Lot No 有值，優先使用 Lot No；只有 Lot No 空白時才以 Component No 查 `LoadComponentState` 並取回所屬 LotNo。查不到元件時顯示錯誤。
- 執行成功或流程正常結束後重新查詢，依 ComponentNo 定位已執行列，清空 Employee／Lot／Component 輸入並將焦點移回 Employee。

### Query 區

- 只有 Area No、PS No、OP No 三個條件，各有 `...` 查找按鈕與 Query。沒有 Lot No、MO No 或 Clear 按鈕。
- Query 只有在至少一項條件非空時才呼叫 `wsWIP.LoadComponentJoinLotState`。Area、PS、OP 條件會轉大寫；OP 查找清單在 PS 有值時依 PS 限縮。
- Area 查找呼叫 `wsSMD.LoadAreaBasis` 並帶 `AreaClass=0`；PS 查找呼叫 `wsPRS.LoadProductionSegment`；OP 查找呼叫 `wsOP.LoadOPBasis`。
- Core 對結果限制 `Status IN (0,1,4,5)`。完全沒有條件時 Core 另外附加 `ComponentNo IS NULL` 以免大量全表掃描；WinForms 不會在無條件時呼叫查詢。

### Component Grid

七個可見欄位及順序如下，其他 Service 回傳欄位隱藏，Group By Box 關閉，依 ComponentNo 排序：

1. ComponentNo（寬 130，凍結）
2. OPNo（100）
3. BRNo（130）
4. StatusShow（130）
5. BaseLotNo（100）
6. LotNo（100）
7. MoNo（100）

`StatusShow` 是畫面衍生欄：0=Queue、1=Running、4=Complete、5=OS。點選／啟用資料列會將 ComponentNo 帶入 Execute 區。Find 需要先選列，以目前 ActiveCell 欄位為查找欄，輸入完全相符值後選取對應列。

## 查詢資料與元件解析

`tcWIP_IC.clsLot.LoadComponentJoinLotState` 的查詢為：

```sql
SELECT C.MONO, B.COMPONENTNO, A.OPNO, A.BRNO, A.STATUS,
       A.BASELOTNO, A.LOTNO, A.LOTSTAMP
FROM TBLWIPLOTSTATE A,
     TBLWIPCOMPONENTSTATE B,
     TBLWIPLOTBASIS C
WHERE A.LOTNO = B.LOTNO
  AND A.BASELOTNO = C.BASELOTNO
```

查詢再套用 Status、OPNo、PSNo、AreaNo 條件。單一 Lot 可有多列 ComponentState，因此多個 ComponentNo 可以解析成同一 LotNo；實際 ExecuteLot 以 LotNo 為單位，成功狀態需同步反映到該 Lot 的元件查詢列。

## 資料表與 DDL

WP202 查詢直接讀取下列三表，不新增或修改表：

| 表 | 用途 | 已有來源參考 |
| --- | --- | --- |
| `TBLWIPLOTSTATE` | Lot 的目前 OP、BR、Status、Area、PS 與 LotStamp | `database/reference/mestest_wip_wp101_source_ddl.sql`、`mestest_wip_wp101_create.sql` |
| `TBLWIPCOMPONENTSTATE` | ComponentNo 與 LotNo 關聯及元件狀態 | 同上 |
| `TBLWIPLOTBASIS` | BaseLotNo 對應的 MONo | 同上 |

這三張表的 Oracle DDL、欄位與索引已於 WP101 由 MESTEST 唯讀查證；CREATE-only 也已提供家用端。WP202 不需要重複擷取 DDL 或產生重複 CREATE SQL。家用端仍須對照 YMES PostgreSQL live schema／migrations，未存在時才新增 forward migration。ExecuteLot 的大量共用讀寫依賴見 [WP201 規格](生產批執行.md)，不是本頁可由三張查詢表取代的簡單 CRUD。

## 家用端 API／Schema handoff

- 先讀本規格、[WP201 生產批執行](生產批執行.md) 與 [DATABASE_CONNECTION.md](../../DATABASE_CONNECTION.md)，核對 live schema／migrations。三張查詢表沿用 WP101；不因 WP202 再複製表或 schema。
- 查詢 API 可沿用 WIP lot-state query service，建議另提供 Component JOIN 查詢：AreaNo／PSNo／OPNo 至少一項、狀態固定 0／1／4／5、依 ComponentNo 排序，僅回傳必要七欄；使用參數化 SQL、分頁及登入者授權。
- Component lookup 需確認 ComponentNo 對應一個或多個 LotNo 的實際唯一性。若多個 LotNo 命中，正式 API 應回傳候選讓呼叫端明確選取，不能依資料庫未保證的列順序任取第一筆。
- Execute API 使用 POST command；若 LotNo 有值，維持 WinForms LotNo 優先，否則後端依登入者權限解析 ComponentNo → LotNo。不可信任前端提供的 Status、OPNo、BRNo、EmployeeNo 或 LotStamp；後端重新讀取與鎖定 Lot、驗證狀態及權限，再呼叫／重建 WP201 共用執行鏈。
- LotStamp/CAS、冪等鍵、狀態分支、TriggerOP／Manual BR／TransferLot 的交易邊界、部分成功、Future Hold／Wait／OS、StopFlag、ERF 及 operation log 均沿用 WP201 的 API handoff。WP202 頁只提供元件選取入口，不能另做一套簡化的 Lot 狀態寫 API。
- 本規格沒有新增 PostgreSQL migration 或 CREATE-only SQL；Production API 與 live schema 驗證由家用電腦處理。
