# WP601 包裝作業（PACKING_MOLINE）

更新：2026-11-19。此規格依 MES WinForms／Service／Core 原始碼及公司端唯讀 Oracle MESTEST metadata 整理。公司端 Vue 畫面只使用明確標示的 DEV 假資料；本檔所列 API 是家用端實作契約，尚未在公司端連 PostgreSQL。

## 功能位置與原始碼

- 三層功能選單：第一層「在製品管理（WIP）」→ 第二層「包裝與庫房」→ 第三層「包裝作業」。
- FunctionNo：`PACKING_MOLINE`；FunctionKey：`WP601`；Form：`frmBR_L_CO_Packing_MOLine`；DLL：`BR_L_CO_Packing_MOLine.dll`。
- WinForms 主畫面與 `InitializeComponent` 在 `STD/MESWin/BR/BR_L_CO_Packing_MOLine/frmBR_L_CO_Packing_MOLine.vb`；設定視窗及 Designer 在同資料夾的 `frmMOLinePackConfig.vb`、`frmMOLinePackConfig.Designer.vb`。
- Service：`Customer/Production/MESws_STD/wsSTD/wsWIP/wsWIP.cs`；Domain/Core：`STD/MESkc/kcWIP/clsLot.cs`。Standard Service 呼叫 `clsLot`，目前 checkout 未發現 THEIL 專屬的包裝交易覆寫。
- WP602「包裝標籤補列印」在功能清冊標為未掛入 MenuItem，因此不是 WP601 的第三層入口。

## WinForms 版面

主視窗 `ClientSize=1008×591`，固定工作區採左右兩欄、每欄上下分割，最下方為操作列：

| 區塊 | Designer 位置／尺寸 | 用途 |
| --- | --- | --- |
| BarCode | 上方，1008×126 外框區；GroupBox 992×83 | LotNo、配件條碼、OP、目前數量、MO、產品／版本、包裝層級、PackingNo、Unit、Pack Config、滿箱自動封箱 |
| Pack Set Content | 左上，626×233 區；GroupBox 612×224 | L1–L6 包裝層級、容量、目前箱號／數量／狀態 |
| Print Label | 左下，626×180 區；GroupBox 612×179 | 封箱後各 LabelType、列印工作與結果 |
| Wait Close Box Content | 右上，377×233 區；GroupBox 363×224 | 目前未封箱內容及 Lot／包裝明細 |
| Pack Accessory | 右下，377×180 區；GroupBox 363×180 | 產品規則要求的配件條碼檢查明細 |
| 操作列 | 底部 1008×47 | Pack Close、Combine、Unboxing、Close (&X) |

BarCode 顯示 LotNo、Accessory BarCode、Cur_LotQty、OPNo、MONo、ProductNo、ProductVersion、PackingLevelName、PackingNo、Unit。唯讀欄位由掃描批次與 Pack Config 載入；`Full Boxe Auto Closed` 在 Designer 預設勾選。另一個 `Print label, show continue ask dialog` 控制項在原始碼中隱藏且初始化為未勾選，不應當成可見操作。

Pack Set Content 依產品包裝規則呈現已啟用的連續層級，可設定 L1 至 L6。滿箱同時以箱數（`FullBoxBoxQty`）及數量（`FullBoxNumberQty`）判定。Print Label 不是任意檔案上傳：來源是產品包裝標籤規則、該電腦的印表機設定及本機 CodeSoft／BarTender 列印元件。

`Pack Config` 視窗為 `446×565`：唯讀 ComputerName、MONo、PackLevel Grid（Select／PackingLevel／PackingLevelName）、Label Printer Grid（LabelType／PrinterName）、`SetUpPrinter`、Confirm、Close。工單由輸入／查詢取得，PackLevel 及 LabelType 由工單產品的 packing rule/label rule 建立；列印設定以 ComputerName 保存。

## 操作與業務規則

1. **設定**：載入 `TBLWIPMOLINEPACKCONFIG`、該電腦的 label printer、MO／產品、產品包裝規則及標籤規則。L1–L6 選取需連續。若目前有未封箱包裝，檢查各層未封箱箱號、上下層 Relation 是否完整，避免更改設定後留下不一致關係。確認時更新工單／產線與六個 PackFlag，並保存各 LabelType 印表機。
2. **掃 Lot**：需要先有 Pack Config。Lot 必須存在、目前流程為 `L_CO_PACKING_MOLINE` 且狀態為 Running；拒絕已完成批、工單／產品／版本或 OP／流程不符合、同一包裝內重複 Lot、不可用數量不足及不符合已封裝狀態的條碼。若 Lot 在 WIP Inventory (`Status=11`)，舊流程提示改用 WP629 在製品庫包裝作業處理。
3. **掃已封箱包裝**：只有有效且已封箱的前一層 PackingNo 可加入外層；檢查是否已被其他外箱關聯，並由 L1Detail／各層 Detail 與 Pack Relation 展開來源 Lot。
4. **數量與滿箱**：比較加入後的箱數與數量；超出容量不接受。只有最小層級是 L1 時可依剩餘容量拆 Lot；包含 Component 的 Lot 不可用此路徑拆批。部分包裝保留原 Lot 數量語意並透過 Core 分批／關係記錄，不由 UI 自行改庫存。滿箱後 `Full Boxe Auto Closed` 勾選時以 `CloseFlag=1` 自動封箱；未勾選時提示人員選擇封箱。人員按 Pack Close 對選取層級以 `CloseFlag=2` 強制封箱。
5. **封箱順序與標籤**：外層不可先於其未封箱內層關閉。成功封箱建立對應標籤工作，使用產品標籤規則、printer 設定及本機列印軟體；瀏覽器無法直接重現舊客戶端 COM 列印。
6. **Delete**：只允許刪除可編輯的待封箱內容；若已有 FGD In 關聯則禁止。Core 需反向更新包裝 Relation、PackState、數量及相關批次記錄，不能只刪 Vue 明細。
7. **Combine／Unboxing**：主畫面按鈕呼叫外部 `ObjectFileHandler("INVMOPackingCombineDismantle")`；Service/Core 分別使用 `ExePackingCombine` 與 `ExePackingDismantle`，更新包裝階層、來源／目的明細、Lot 關係及 merge/dismantle log。此 COM 外掛契約未由本次 UI 假資料取代。
8. **完工**：最大包裝層封箱會依 Core 規則將所含 Lot 推進完工狀態。需保留 Core 的 PackState／PackLog、WIP Lot State、包裝 Relation、拆併批歷程與 FGD In 約束的交易副作用。

以上以原始碼為行為來源。不得把 Vue localStorage 的簡化數量或狀態當成正式 MES 權威資料。

## 資料表與 Oracle 證據

Oracle MESTEST 透過 Windows PowerShell 5.1 + `Oracle.ManagedDataAccess.dll`，讀取本機受保護的 `DatabaseConfigs.CS.Test.Mes.ConnectionString` 後直連，僅查 `DBMS_METADATA.GET_DDL` 與 `ALL_*` 字典資料；沒有讀業務資料列，也沒有執行 Oracle DDL/DML。連線字串、IP、帳號、密碼與 SID 不寫入 repo。

以下 19 個功能表在 MESTEST 均有物件且 CREATE 欄位數與 Oracle `ALL_TAB_COLUMNS` 相符：

| 群組 | Oracle 表 |
| --- | --- |
| 電腦包裝設定 | `TBLWIPMOLINEPACKCONFIG`、`TBLWIPMOLINEPACKLABELPRINTER` |
| 層級箱主檔 | `TBLWIPMOLINEPACKL1` 至 `TBLWIPMOLINEPACKL6` |
| 各層內容 | `TBLWIPMOLINEPACKL1DETAIL` 至 `TBLWIPMOLINEPACKL6DETAIL` |
| 包裝關係 | `TBLWIPMOLINEPACKRELATION` |
| 包裝狀態／歷程 | `TBLINVPACKSTATE`、`TBLINVPACKLOG`、`TBLINVPACKMERGELOG`、`TBLWIPSMSTATE` |

各層箱表與 Detail 表依 Oracle PK 原樣保留。`TBLWIPMOLINEPACKRELATION` 有 `TO_PACKINGNO`、`FROM_PACKINGNO` 兩個非唯一索引，沒有 PK；`TBLINVPACKMERGELOG` 沒有 PK／索引。其餘來源索引均為原有 PK unique index。這批表未查到 FK 或 trigger。不可為無 PK 表自行猜主鍵，也不可把通用字串前綴 `TBLWIPMOLINEPACKL` 當成已存在資料表：MESTEST 的 ALL_OBJECTS/ALL_SYNONYMS 無該物件；實際存在的是 L1–L6 與 Detail 表。

共用資料依賴由原始碼引用，應沿用 YMES 已有 schema/reference：`TBLWIPLOTSTATE`、`TBLPRDPACKINGRULEBASIS`、`TBLPRDPACKINGSERIALRULEBASIS`、`TBLPRDPACKINGSERIALRULEDETAIL`、`TBLPRDPRODUCTBASIS`、`TBLINVWIPINVENTORY_SEMI` 等。先對照既有 reference 和 live PostgreSQL schema；不要因本文件列出 Oracle 表就把所有 CREATE-only 一次執行。

- 原生來源 DDL：[`database/reference/mestest_wip_wp601_source_ddl.sql`](../../../database/reference/mestest_wip_wp601_source_ddl.sql)
- PostgreSQL 型別對照／CREATE-only 參考：[`database/reference/mestest_wip_wp601_create.sql`](../../../database/reference/mestest_wip_wp601_create.sql)
- 唯讀 Oracle 查證與憑證規範：[`docs/DATABASE_CONNECTION.md`](../../DATABASE_CONNECTION.md)

CREATE-only 是結構比對材料，不是 migration。家用端先核 live schema、migrations、既有 PK／nullable/default／資料後，只對缺少物件新增 forward migration。跨表交易需定義鎖定／CAS、防重與 idempotency，不可用簡化 CRUD 替代 `clsLot`。

## API／家用端實作契約

建議由登入者授權的 WIP Pack domain service 提供：

- 讀取目前使用者允許的 MO／產線、產品 packing rule、PackingLevel／滿箱條件、配件與 LabelType；不得信任瀏覽器傳回的規則或 ComputerName。
- 查詢目前電腦設定、印表機、各層未封箱箱號與關聯明細；查詢一律參數化、分頁並依來源唯一順序回傳。
- POST PackConfig、Scan/Pack Lot、Pack closed package、Pack Close、Delete content、Combine、Unboxing、Create/Retry label job。變更操作用 POST command；不以 GET 執行寫入。
- Pack command 伺服器重驗登入者、MO／PDLine、產品版本、LotStamp／狀態／流程、`Status=11` 庫存分流、Component、已包數量、同 Lot 重複關係、上下層容量、目前 CloseFlag／關聯與權限。並發採交易鎖定或條件更新；重要 command 支援 idempotency key，防止掃碼重送重複扣量。
- 一筆 package command 原子處理 Lot split、L1–L6 主檔與 Detail、Relation、PackState／Log、WIP Lot State、FGD In 關聯及拆併批記錄。任一必要 side effect 失敗須回滾或明確記錄可重試狀態。
- 標籤工作需採 server-side job/artifact 或經授權的列印代理；不得讓瀏覽器接任意路徑／printer 名稱，也不得把舊 Windows COM 當成 server API。說明 label data、範本檔、印表機與補印的授權及重試策略。

API DTO 應使用 PascalCase／camelCase 一致契約，不接受前端指定資料表名稱、任意 SQL、CloseFlag 權限或信任的 PackQty 結果。錯誤回傳具體業務碼（Lot 狀態變更、包裝已使用、超容量、未封內層、WIP Inventory 改走 WP629、列印尚未完成等）。

## 公司端 Vue DEV 現況與限制

Vue 路由 `/YMES/WIP/PackingMOLine`，第三層選單「包裝作業」。畫面重現 BarCode、Pack Set Content、Print Label、Wait Close Box Content、Pack Accessory、Pack Config 與 Pack Close／Combine／Unboxing／Delete／Close。只使用 `ymes.dev.wp601-packing-moline.v1` localStorage 假資料，包含掃碼驗證、L1/L2 層級、滿箱、數量拆分限制、設定 modal、待封箱提示與操作紀錄。

DEV 假資料目前僅一張 MO／產品、一組 L1/L2 規則；層級、容量及 LOT 不代表 Oracle 真實資料。Combine／Unboxing 是畫面上的簡化模擬；標籤只記錄假列印工作，絕不呼叫本機印表機；API、資料庫交易、COM 外掛與正式標籤均未接入。此畫面為可檢視的第一段復刻，不宣稱完成正式生產交易。
