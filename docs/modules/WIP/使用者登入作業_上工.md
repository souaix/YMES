## WinForms 畫面

- 主視窗標題 `Operator Clockin`。上方 `Login` 群組依序顯示 EmployeeNo、Password、ShiftNo；員工姓名唯讀顯示在 EmployeeNo 右側。Password 列由系統參數 `WIPChkPassword` 控制，為 1 時顯示並要求驗證，否則隱藏該列。
- `Login Data` 群組依序有 LoginOP、LoginPlace、WorkDay、LoginDate。LoginOP 可輸入或按 `...` 搜尋 OPNo／OPName／OPType／PSNo；LoginPlace 依多人加工模式選擇 Area 或 Equipment。WorkDay 預設依使用者班別與當前時間計算，LoginDate 唯讀使用 AP Server 時間。
- 底部按鈕為 Confirm、Clear、Close。初始 Confirm disabled；載入有效員工與班別資料後才啟用。Confirm 成功後重設員工認證欄位；Clear 也會清除 OP 與地點。
- DEV 頁沿用相同群組、欄位順序、按鈕與 KD 黃色可輸入欄位。只使用示範員工／作業站與瀏覽器 localStorage 的模擬現況；不呼叫正式 API、不產生真實上工。

## 輸入與檢核流程

1. Form_Load 依 `WIPChkPassword` 控制密碼列，載入 OP Basis，並讀 `CLOCKIN_AUTOCLOCKOUT`。EmployeeNo 輸入後轉大寫；需密碼時以 `wsUSR.ChkUserPassword` 驗證，再載入使用者及 Shift。
2. 使用者需存在且 DepartmentNo、ShiftNo 已設定；班別需存在並有 FromTime／ToTime。`LoginDate` 取 AP Server 時間。`WorkDay` 依班別是否跨午夜及目前時間預設今天或昨天，使用者可在表單調整。
3. OP Basis 的 `MultiOperatorMode=0` 表示直接上工至 OP，LoginPlace 等於 OP；`1` 表示 Area，`2` 表示 Equipment，兩者需選擇 LoginPlace。`5` 是批次 Lot 多人加工，Form 明確引導改用 `OPERATOR LOGIN_LOT`；其他未定義模式拒絕。
4. Confirm 必須有有效員工、班別、OP；mode 1／2 另需 LoginPlace。Core 禁止未來 LoginDate，依 `OPPRIV` 參數與使用者群組重新檢查 OP 權限，UserLevel=3 Anonymous 不可上工。
5. `CLOCKIN_AUTOCLOCKOUT` 的 Core 行為：`1` 自動下工該員 `WorkDate` 早於本次工作日的現況；`2` 自動下工該員其他 LoginPlace；`0` 表單先列出其他地點並詢問是否自動下工，MessageBox 預設 No。使用者回答 Yes 才把 `blnClockInAutoClockOut=true` 傳入交易。
   - 來源預設值有不一致：WinForms Form 讀取參數失敗時使用 `0`，Core `GetClockIn_AutoClockOut` 讀取失敗時使用 `1`。DEV 固定展示參數 `0` 的確認流程；正式 API 應明確定義唯一設定來源與 fallback，避免同一操作在表單/API 出現不同自動下工結果。
6. Core 新增 `TBLWIPOPERATORSTATE` 現況列。多人加工功能啟用時，`funSHR_CI_EMP_ClockIn` 還會依 mode 與正在加工的 Lot，新增 `TBLWIPLOTLOGINSTATE`（WP305 已查 DDL）；自動下工則搬移現況至 `TBLWIPOPERATORLOG`，更新相關多人加工 Lot Login state。這些副作用必須在同一交易範圍重現，不可以只插入現況表。

## Oracle DDL 與 PostgreSQL handoff

- WP104 新確認兩張表：`TBLWIPOPERATORSTATE`、`TBLWIPOPERATORLOG`。Oracle DDL、ALL_TAB_COLUMNS、constraints、indexes、trigger metadata 位於 `database/reference/mestest_wip_wp104_source_ddl.sql`、`mestest_wip_wp104_metadata.txt`、`mestest_wip_wp104_source_indexes.sql`；PowerShell 查詢腳本為工作區 `ymestage/wp104_fetch_metadata.ps1`。
- `TBLWIPOPERATORSTATE` 7 欄，PK `(USERNO, MULTIOPERATORMODE, LOGINPLACENO)`；`TBLWIPOPERATORLOG` 15 欄，PK `(SID)`。兩表均無 FK、Trigger、額外非 PK index。PostgreSQL CREATE-only 為 `database/reference/mestest_wip_wp104_create.sql`。表欄位、精度、預設值和 PK 按 Oracle dictionary 記錄，不推造新欄位或關聯。
- 重用 `TBLWIPLOTLOGINSTATE`（WP305 source DDL/metadata/CREATE）、`TBLWIPLOTSTATE`、OP／OP Area、Equipment、User、Shift、User Group／Privilege、System Parameter references。此頁沒有新的其他專用表。
- CREATE-only 不等於 migration。家用端須先比對 PostgreSQL live schema／migration；只有上述 OperatorState／OperatorLog 在 live schema 缺少時才新增 forward migration，並比對既有約束、欄位與索引。

## 家用端 API 建議與安全要求

- 以 TLS 登入保護的 `POST /api/wip/operator-clock-ins/verify` 驗證員工密碼並取得短效、綁定員工及登入 session 的 challenge；不可記錄或保存明碼密碼。登入端點需節流並避免將 request body 寫入一般 access log。若 `WIPChkPassword=0`，仍需由 server 查員工狀態與班別，不讓 browser 自行認定員工有效。
- `GET /api/wip/operator-clock-ins/context` 回傳伺服器時間、參數、可用 shift/OP lookup。Area／Equipment 清單由 `OPNo` 對應查回；不可接受任意 LoginPlace。
- `POST /api/wip/operator-clock-ins` 接短效 challenge、OPNo、MultiOperatorMode、LoginPlaceNo、WorkDay 與是否確認自動下工；不接受 client 的 UserLevel、OP 權限、ShiftNo、LoginDate 或登入者身份作為可信值。Server 重新讀 user/shift/OP、權限、現況與 System Parameter，使用 server time，並以交易／鎖完成 auto clock-out、OperatorLog、OperatorState、LotLoginState 及 reverse side effects。
- 以 idempotency key 防止重複送出；對 PK 衝突、並行上工、OP 權限變更、舊 WorkDay 清除、多人加工下 Lot 及部分失敗定義明確錯誤碼與 rollback 邊界。
