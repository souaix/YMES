# WP211 併批處理（LOT MERGE）

## 範圍與原生來源

- 選單：在製品管理 → 生產報工 → 併批處理；FunctionNo `LOT MERGE`、FunctionKey `WP211`、Form `frmBR_L_Merge_GEN`、DLL `BR_L_Merge_GEN.dll`。本頁為無元件、無 GoodBin、無載具的手動併批入口；元件／等級／載具另有 WP212–WP214，不能共用本頁命令。
- WinForms：`STD/MESWin/BR/BR_L_Merge_GEN/frmBR_L_Merge_GEN.vb`。Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `Exe_Manual_LotMerge`、`LoadLotBasisJoinState`、`ChkLotStamp`、`CheckLotPackage`、`CheckLotIsOSbutNotReturn`。Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `BR_Manual_LotMerge`。
- 公司端 Vue DEV：`web/src/components/WipLotMerge.vue`，路由 `/YMES/WIP/LotMerge`。此頁沒有正式過帳 API；假資料及 localStorage 不可作正式 MES 資料。

## WinForms 版面與查詢

主視窗標題 `Manual Merge`，約 1008×591。由上到下為 `Reference Lot`（RefLot No、查找、Query、參考批 Grid）、`Merge Lot`（MO No 多選查找、Select All、UnSelect All、候選批勾選 Grid、特定環境的 Eletricbox）、`Transfer Type`（Go／Assign、Process No／Version／OP No 查找、Merge LotNo），底部 Confirm(&C)、Close(&X)。參考批在候選 Grid 中固定勾選，且不能取消。原程式將候選列加 `CheckFlag`，MO 多選只改顯示範圍，並清掉不在新範圍的已選批；參考批工單固定保留。`Select All` 無 MO 篩選時全選候選，有篩選時先清除再選可見批；`UnSelect All` 留下參考批。

參考批 `LoadLotBasisJoinState` 傳 `Status=0|1|4|5`、`HaveComponent=0`、`NotContainGoobinState=True`、`LotState=1`、`ShowPartialLot=False`、`StockerLot=False`。原 `HaveLevel=0` 條件已註解，不能再據此排除所有等級批。若查得 GoodBinState，畫面提示走等級併批；有包裝現況的批號不得繼續。一般候選再以同 `OPNo`、`ProductNo`、`BRNo`、`Status`、`CurUnitNo` 篩選。系統參數 `SysInfo/AllowDiffMOMerge` 為 `0` 時加同 `MONo` 條件；不是前端自由選項。委外 Status=5 改走 `GetUnReturnLotsInSameOSWithRefLot`，只取得同一未回貨外包單的 Lot，並可附加同工單條件；確認前再查 `CheckLotIsOSbutNotReturn`。

## 確認、服務與交易

- Confirm 要求 Merge LotNo；Assign 須有 Process No／Version／OP No，並送 NodeID／OPNo；委外未回貨批只能 Go。重新確認參考批仍在可併清單、選取批無包裝現況，且每筆 `CurQty` 非零。相同 OP 但不同 NodeID 會逐筆提示。原先「至少兩筆」檢查已註解；不能把它記成來源硬限制。
- Form 對參考批呼叫 `ChkLotStamp`，送 `RefLotNo`、`NewLotNo`、`MergeType`、`Action` 與每筆 `LotNo/CurQty/LotStamp`；Assign 另送 `NodeID/OPNo`。必要時送 `NewLotSysQty`，BR 宿主送 ShiftNo，WIP Inventory 宿主送 WIPINV；手動選單預設 `MergeType=0`。Core 必須再驗證批次現況、版本戳、合法 Action／NodeID、數量、相容性與輸出批號，不以瀏覽器值當真。
- `BR_Manual_LotMerge` 涉及 LotBasis／LotState、Reverse／Log／OS、Dispatch／AutoMerge、員工紀錄及 WIP Inventory 分支。正式 API 應在同一資料庫交易中鎖定所有選取批及相依資料、重查條件與數量，更新合併結果及所有副作用；失敗回滾。BR 宿主 `MergeType=1` 且 Go 成功後，Form 關閉才另外呼叫 `BRTransferLot`，有「併批已提交、轉站失敗」風險，需可查詢與冪等重試，不得回報單一全成功。
- `Exe_Manual_LotMerge` 的登入身分、UserNo、ShiftNo、模式與時間由 server 決定。對外提供參考批查詢、同外包單／一般候選、工單與路由查找、併批命令、交易結果；錯誤要區分資料過期、包裝／GoodBin、委外、不同節點確認、輸出批號重複及部分完成。

## 資料表與 CREATE SQL

Core 方法字面直接引用八張：`TBLEMSDISPATCHSTATE`、`TBLINVWIPINVENTORY_SEMI`、`TBLWIPAUTOMERGE`、`TBLWIPCONT_EMPLOYEE`、`TBLWIPLOTBASIS`、`TBLWIPLOTSTATE`、`TBLWIPOSBASIS`、`TBLWIPOSDETAIL`。逐名核對 `database/reference/`，八張已有 Oracle source DDL 和 PostgreSQL CREATE-only 參考：Inventory Semi 沿 WP201、Dispatch／AutoMerge／Cont Employee／OS 沿 WP207、LotBasis／LotState 沿既有 WIP 參考。**WP211 無新缺表，不重複產生 CREATE SQL。** 共用 helper 可能讀寫額外表，家用端落地前仍須沿呼叫鏈核對；也須查 YMES PostgreSQL live schema 與 migration history，不能因 reference 存在便假定 live 表已建立。

## 公司 DEV 差異與交接

DEV 頁提供一般跨工單、同工單不同 NodeID、包裝拒絕與同外包單案例；模擬 Go／Assign、MO 多選、全選、靜電箱入口及確認，狀態只存 `ymes-dev-mock:wip-lot-merge:records:v1`。Fixture 的 `allowDiffMO` 僅用來模擬部署參數兩種情況，沒有寫入設定。靜電箱不建立真綁定；數量用簡化整數，未模擬原 Core 所有 Reverse／OS／派工 side effect。正式 non-DEV 禁用 DEV 業務資料及確認。

家用端先重用八張 source reference，核 live schema；實作有權限的查詢與原子 POST 命令，server 重新查 `AllowDiffMOMerge`、GoodBin／包裝、未回貨 OS、LotStamp／數量／節點與路由。追 Core helper 的間接表，建立可稽核結果與 BR 後續轉站補償。公司端未連 YMES PostgreSQL、未建 migration／Production API；依既有使用者約束未執行 build/test/browser。
