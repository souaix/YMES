## 主窗、條件與欄位

- MO 查詢呼叫 `wsWIP.LoadMOBasis`，限制 `MOState=3|6`；Form 加上「未下線量大於 0 或仍有 LotState=0 批次」條件，並以 `MOClass=PKG` 顯示 CP 工單。Form Load 不自動取清單；選 MO 後才呼叫 `LoadLotBasis` 查所選 MO 的 `LotState=0` 批次。
- Grid 的 19 個可見欄位依序為 BaseLotNo、OrgLotNo、RONo、ItemNo、ReturnNo、MONo、ProductNo、ProductVersion、ENGNo、ENGVersion、CustomerNo、InputQty、InputUnitNo、CustomerLotNo、Priority、HotLot、Description、Creator、CreateDate。Edit／Copy 用 ActiveRow；Delete／Release 讀多選列。
- 按鈕為 Add、Edit、Delete、Copy、Release、Close。新增須有 MO 且 `UnReleaseLotQty>0`；新增／編輯載入 `CheckIsWafer` 結果。強制挑片的 MO 領料未確認時阻止進入定義窗。
- 不強制挑片但有 wafer 料、MO 尚無元件且有領料現況時：啟用 `I_IDBINControl` 會先依 wafer summary 產生 MO 元件；未啟用則改叫 FT Lot Basis 子窗。`CheckIsWafer` 也拒絕強制挑片卻缺 MO 元件、wafer 料／領料現況不完整等狀況。

## 定義窗與驗證

基本欄位：BaseLotNo、ReturnNo、MO type、MONo、RONo、ItemNo、ProductNo／Version、ENGNo／Version、DeviceNo、CustomerNo／CustomerLotNo、InputQty／UnitNo、Priority、HotLot、Description、Creator／CreateDate。新增時 InputQty 預帶 MO 的 `UnReleaseLotQty`；BaseLotNo 由 `wsSYS.GetLotNo` 依序號設定取得，不可用 DEV 序號推斷正式規則。HotLot 為一般／急件／特急（0／1／2），Priority 0–99。

可見頁籤包含 Basic ECN、Process ECN、OP ECN、Component、Lot Property、Carrier。雖 Designer 建有 Process 頁，`frmLotBasisDef_CP_Load` 會執行 `TabPages.Remove(tbgProcess)`；流程由 MO 載入，Vue 只唯讀展示來源流程與 Not Execute OP，不提供編輯流程。新增／編輯定義窗提供 Apply（保存並留窗）與 Confirm（保存並關閉）。

Confirm 檢查 RO、Item、MO、Product、ProductVersion、正數數量、單位、Priority、CustomerLotNo；有元件的流程必須至少載入一筆，勾選筆數須等於 VB `CLng(InputQty)`，強制 wafer 選片時勾選元件須同 MaterialLotNo。Lot Property 依 `DataType` 驗值；Carrier 元件列必須全部綁定或全部不綁定。Form 載入目前批次時讀取 Basic／Process／OP ECN、Component、Property、Carrier；Release 前比對批次 ECN 與目前產品／工單／OP 資料。

## 操作與狀態

| 動作 | 來源行為 | DEV 頁行為 |
| --- | --- | --- |
| Add | 驗 MO 未下線量、wafer／領料條件後開 CP 或 FT 定義窗；新增批次 | 依 MO 開 DEV 表單，模擬序號與欄位驗證 |
| Edit | 作用列批次資料載入 CP／FT 定義窗 | 編輯作用列的假資料 |
| Copy | 作用列帶入定義窗，取得新序號後另存 | 複製假資料並重設批號／audit |
| Delete | 確認後逐筆呼叫 `IC_FT_PKG.wsWIP.DelLotBasis`；首筆錯誤停止，已成功列保留 | 逐筆 DEV 刪除；可模擬第二筆失敗及部分成功 |
| Release | 逐筆檢核 ECN，呼叫 `IC_CP_PKG.wsWIP.SetLotBasisLotState`；首筆錯誤停止，之前成功列保留 | 模擬 ECN／MO 數量檢核與 LotState 0→1；可模擬 Service 失敗 |

新增 Service 將 Lot Basis、LotState／LotSerial、流程、略過 OP、ComponentState／ComponentBasis、MO Component BookingFlag、Lot Property Receive／值、Lot OP ECN，以及可選 Carrier In SQL 收集後，以 `ExecuteSQL_ChkRowCount` 執行。自動下線參數 `IC_FT_PKG-LotCreateAutoRelease=1` 會在建立後另行呼叫下線流程。正式 API 必須核對目前 YMES migration／transaction 邊界，處理批號預約、工單元件預約、元件／載具和動態 Lot Property 寫入；不可把 DEV 成功視為正式交易已原子化。

刪除 Core 先用 BaseLotNo 找批次，對相關 Lot 呼叫 `CloseLot(..., 200)`，再清理 `TBLWIPLOTPROPERTY_RECIVE` 與 `TBLWIPLOTBASIS`。下線 Service 會重新檢查未下線量與元件衝突，啟動批次、扣料、更新 Lot／MO／MO Component 狀態；成功後還可能接續企業邏輯自動報工。這些副作用均未在 Vue DEV 執行。

## Oracle reference 與家用端 handoff

本功能沒有新增的專屬表 DDL。可重用 repo 內既有來源／空表參考：WP101 的 `TBLWIPLOTBASIS`、`TBLWIPLOTSTATE`、`TBLWIPLOTPROCESS`、`TBLWIPLOTNOTEXECUTEOP`、`TBLWIPCOMPONENTSTATE`、Lot Property；WP215 的 `TBLWIPCOMPONENTBASIS`；WP207 的 `TBLWIPLOTOPECNRECORD`；WP302 的 `TBLWIPCARRIERSTATEDETAIL`；OE work-order 的 `TBLOEMOCOMPONENT`。批號序號與 SYS Lot Property metadata 沿既有 SYS references。公司桌機未取得可用受保護 Oracle profile，這次沒有連 MESTEST，未查業務列，也未產生新的 CREATE-only SQL。

`TBLWIPLOTBASIS` reference 存在已知版本差異：Office TODO 記錄 8ff lookup 為 39 欄、DESCRIPTION 長度 400 且有 `XX_MARKING`；舊 WP101 source DDL 為 38 欄、DESCRIPTION 長度 255 且沒有該欄。家用端須以目標 YMES/MESTEST 版本確認所有共用表後再調整 schema；不得將舊 WP101 CREATE-only 當作 WPP01 的完備 schema。

家用端後續應依使用者與權限提供 CP MO／Lot／ECN／元件／Carrier／Lot Property lookup，以及新增、編輯、刪除、下線 API；每批次明確交易與部分成功結果。下線需鎖定／條件更新 MO 未下線量、重新檢核 ECN／元件預約與物料，再記錄 StartLot、CloseLot、載具、Property 動態欄位和提交後自動企業邏輯。動態 `TableName`／`FieldName` 必須映射到服務端允許清單，不能接受 browser 任意 SQL metadata。先核 YMES live schema／migration；共用表有差異時依目標版本 forward migration，不重建共用表。
