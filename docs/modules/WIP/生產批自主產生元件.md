## 主窗查詢與資格檢查

- Form Load 載入 MO 清單，MOState 僅取 `3|6`，並加條件：未下線批次數大於 0，或仍有 `LotState=0` 的 MO。MO 可用選擇器挑選，也可直接輸入後按 Enter。
- 以 MO 查 `LoadLotBasisJoinState`，限制 LotState=0；Lot No 可選作額外條件。結果按 HotLot 遞減、Priority、LotNo 遞增排列。
- Lot Grid 顯示 LotNo、MONo、HotLot、Priority、Status、Product／Customer／Version、Area／Process／OP、CurQTY／Unit 與 SysQTY／Unit。選取批次後載入 Component State；Component Grid 顯示 ComponentNo、GoodQty、WaferID（由傳回 SlotNo 欄改名）及 UnitNo。
- 按 `NEWCOMPONENT` 前，Form 先查該 Lot 的 Component State；若為空再查 Component Basis。任一已有資料就拒絕重複產生。接著載入產品流程，檢查 HaveComponent；EnterpriseNo 為 `SP` 或 `SET` 時不允許本功能建立。
- 來源流程迴圈在第一筆流程資料後即 `Exit For`，目前只判斷第一筆 HaveComponent。DEV 依各 fixture 的首筆流程設定模擬；正式 API 應與產品負責人確認要依首站或整段流程判斷，並在 server 端重新讀取。

## NewComponent 子窗

- 子窗帶入 MO、Lot、CustomerLotNo、ReleaseUnitNo（CurUnitNo）、SystemUnitNo、SysQTY，載入 Unit 與 SerialConfig。
- 選擇的 Component Unit 需與 Release Unit 不同且屬相同 UnitType。`LoadUnitTransferQty` 以 Product／Version 換算 Release Unit 到 System Unit，目標 SumQty 為 `SysQTY × 換算量`；選定 Component Unit 後，同樣換算每筆 GoodQty。
- Wafer ID Start／End 都必填，必須是數值且 Start 不得大於 End。按 `NewComponent` 產生每個 Wafer ID 一筆資料。ComponentNo 欄不可編輯，GoodQty 與 WaferID 可編輯；Clear 清空預覽列。
- COMPONENTNO SerialMode 啟用時，以 `GetComponentNo_Multiple(ReserveSerialNo=false, SerialCount=SYSQTY, MONo)` 取得序號清單，再用 `WaferID - 1` 作索引。未啟用時以 `MONo + '-' + 補零 WaferID` 組號，補零寬度依 SYSQTY 小於 100／1000／其他分別為 2／3／4 位。DEV 的序號只是假資料，不預約正式號碼。
- Confirm 驗證單位、起訖、總 GoodQty 必須等於 SumQty，再呼叫 CP `IC_CP_PKG.wsWIP.UpdComponent`，傳 MO、Lot、CustomerLotNo 與多筆 ComponentNo／GoodQty／ScrapQty=0／UnitNo／SlotNo。
- 原 Form `funBasicCheck` 只對第一筆檢查 GoodQty 與 WaferID 是否為數字，未逐筆驗證正數、重複 WaferID 或整體列數；DEV 加上逐列數值、正數、Wafer ID 唯一及數量守恆檢查，避免假資料產生不一致結果。

## Service／Core 寫入契約

`IC_CP_PKG.wsWIP.UpdComponent` 解析 Component 清單後呼叫 `clsLot.UpdComponent`。Core 每個元件建立三筆新增資料：

1. `TBLOEMOCOMPONENT`：MONo、ComponentNo、GoodQty、UnitNo、ReleaseState=1、SLOTNO。
2. `TBLWIPCOMPONENTBASIS`：ComponentNo、ComponentLotNo、SLotNo、P_WaferLot=CustomerLotNo、P_WaferId、P_BumpMergeStatus=1。
3. `TBLWIPCOMPONENTSTATE`：LotNo、ComponentNo、GoodQty、ScrapQty、UnitNo、ExecuteState=0、Status=0、SLotNo。

Service 對外回報 success／fail 並記錄事件。Core 以字串組 SQL，三張表的 Collection 寫入交易與失敗回復需由家用端在 YMES 實作前確認；正式 API 必須使用參數化 SQL、登入者與 MO／Lot 權限檢查、在同一交易內維持三表一致，並防止兩個請求同時對同批次產生元件。

## DEV 範圍

- App fallback 菜單 WPP08 與路由 `/YMES/WIP/LotComponentGen`。DEV 以固定虛構 MO／Lot／流程／Unit fixtures 模擬 MOState 3／6 查詢、LotState=0、HotLot／Priority 排序、Component State、ComponentBasis 重複阻擋、HaveComponent 流程資格、Enterprise 限制、兩種 ComponentNo 序號模式、Unit conversion、Wafer ID 範圍、逐列 GoodQty 編輯、SumQty 驗證及 Confirm／Clear。
- DEV 寫入只更新頁面記憶體中的虛構 Component State；不使用 localStorage，不呼叫 MES Service／API，不寫檔，不連 Oracle／YMES PostgreSQL，也不預約正式序號。
- DEV 以穩定 fixture 模擬轉換值；不代表任何真實 Unit、Product 或 SerialConfig。

## Oracle 參考與家用端交接

本功能沒有新增的專屬資料表。核心三表可沿用 repo 已存的 DDL／CREATE-only 參考：`TBLOEMOCOMPONENT`（OE201 工單資料）、`TBLWIPCOMPONENTBASIS`（WP215）、`TBLWIPCOMPONENTSTATE`（WP101）。MO、Lot Basis／State、Unit、Product Process、Serial rule 也屬共用來源，家用端需比對目標 YMES schema／migration 版本，不可因為舊 reference 存在就假設線上 schema 相同。

桌機受保護 Oracle profile 目前不可用，本次未連 MESTEST，未取得新的 Oracle metadata，未查業務資料，也未產生重複 CREATE-only。既有參考位置為 `database/reference/mestest_oe_work_order_*`、`mestest_wip_wp215_*`、`mestest_wip_wp101_*`。
