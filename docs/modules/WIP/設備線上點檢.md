## WinForms 畫面與操作

- Form ClientSize 為 1008×591，置中顯示；主 GroupBox 約 994×544。
- 上方欄位依序有 Equipment Type、EquipmentNo 及各自的 `...` Lookup；一般獨立開啟時另有 `Wait QC`、`Re QC`。
- 第二列是唯讀 `QCList Serial`、`QCList No`。點檢表不是直接鍵入，而是由 Wait/ReQC 候選載入。
- 中間 UltraGrid 約 977×268；欄位包含 QCOrder、Result、InputValue、可能出現的 D01–D10、CheckItem、InspectionMethod、InspectionStandards、StdValue、MiniValue、MaxiValue。不可編輯的設定欄位為灰色，輸入格依標準、範圍顯示綠／紅結果。
- 下方有 Description、Creator/Create Date、Reviser/Revise Date；底部按鈕為 Confirm、Close。
- Grid 沒有明細時 Confirm disabled。獨立模式新增成功會清除本次資料並留在 Form；由報工呼叫或編輯既有 Log 時，成功後關閉。

## 呼叫模式

1. **獨立新增**：Equipment Type/EquipmentNo 可 Lookup；兩者必須相符。Wait QC 會載入待點檢候選，Re QC 載入待補驗候選。挑選候選後讀取 QCList Basis/Detail 並產生新 QCListSerial。
2. **報工 Check-in 呼叫**：呼叫端傳 EquipmentNo、LotSerial、LogGroupSerial；設備欄位及 Lookup 鎖定、Re QC 隱藏。Wait QC 只依報工模式篩出當日、仍未驗、設備 QC 設定相符的任務，並取每張 QC List／檢驗頻率最近的 PlanQCTime。任一項未完成不可存檔。
3. **編輯既有 Log**：建構子以 EquipmentNo、QCListNo、QCListSerial 載入 Header/Detail；Wait QC/Re QC 隱藏，成功修改後關閉。此編輯入口通常由設備點檢歷程呼叫。

設備清單讀取 EquipmentType / Equipment Basis。Wait QC 在一般模式合併三類來源：設備 QCListSetup 關聯、設備主檔舊式 QCListNo、以及 QCTaskClass=1 且 Status=0 的任務；報工模式只看當日有效且與設備設定頻率相符的任務。多筆時讓使用者以 QCListNo、InspType、起始時間、QCTaskNo 選一筆。Re QC 只讀該 Equipment 的 QCTaskClass=1、Status=2 任務。Task status 定義為 0 待驗、1 已驗、2 補驗。

原 Core 的 `GetQCListSerial` 雖收到由 QCListNo 加日期組成的 lead string，現行實作改用 GUID Base64 字串並插入 001–999 的隨機數字；不應由家用端誤認為資料庫 Sequence 或依 lead string 建號。

## 點檢欄位規則

| QCType | WinForms 規則 | 儲存判定 |
| --- | --- | --- |
| 0 | 標準值；數值可填 InputValue 或多個 D01–D10 | 所有值等於 StdValue 才是 `QCResult=0 / Result=Y`，否則 `QCResult=1 / N` |
| 1 | 範圍；數值可填 InputValue 或多個 D01–D10 | 每個值都需在含端點的 MiniValue–MaxiValue 範圍；`*` 表示該端無界 |
| 2 | 操作者對訊息項目選 OK/NG | OK=`0`，NG=`1`；必須明確選擇 |
| 3 | 自由文字輸入，可用單一 InputValue 或多個 D01–D10 | 必須輸入；完成後 Result=Y 且 QCResult=0 |

- InputDataCount 決定單一 InputValue 或多個 D 欄；來源表最多定義 D01–D10。數值型不可輸入非數值，字串型允許文字。
- Log Detail 的 QCResult `-1` 表示未完成，`0` 表示 OK，`1` 表示 NG。整張表有未完成項時整體 QCResult 為 -1；沒有未完成項但有任一 NG 時為 1；全部 OK 為 0。
- 獨立模式尚有未完成項時 WinForms 詢問是否部分存檔；使用者拒絕則不送出。由 Check-in 呼叫不允許部分存檔。
- 每次結果與輸入值一併保存。修改模式更新 Header/Reviser、刪除該 Serial 的舊 Detail 後重寫明細。

## Service/Core 寫入與設備副作用

新增以一組 Service 呼叫寫入 Header `TBLWIPEQPQCLISTLOG` 與每個檢查項目 `TBLWIPEQPQCLISTDETAIL`；如帶 QCTaskNo，Core 將 Task Status 設為 1、寫入 QCSerialNo，並把 Task 的 InspType、ShiftNo、LotNo、InspStartTime、原 QCTaskStatus、BelongDate、PlanQCTime 複製到 Log。ReQC 任務亦依此完成狀態轉換。編輯會更新 Header 並替換同 Serial 的 Detail。

NG 時若 QCList Basis 的 UnValidAction 有設定，Core 不只保存點檢結果：會先把設備目前狀態寫入 `TBLEMSEQUIPMENTSTATELOG`，再更新 `TBLEMSEQUIPMENTSTATE`。如果設備目前為 WIP Tracking 的 CheckInConfirm 狀態，還會呼叫 `clsLot.SHR_COEquipment` 結算設備上的生產批，刪除 `TBLWIPTEMP_EQUIPMENT`，更新 `TBLWIPCONT_EQUIPMENT` 結束時間，並更新 `TBLWIPLOTLOGINSTATE` 的多人上工簽退欄位。這是生產交易副作用，不可由 Vue 直接更新幾張表來替代；家用端須確認與 WP201/WP204 設備下機流程共用同一原子交易或等價的交易邊界。

## 家用端 API 實作與目前邊界

- `.NET 9` 登入保護 API 已完成並已註冊正式 Repository：
  - `GET /api/wip/equipment-online-qc/lookups/equipment-types`
  - `GET /api/wip/equipment-online-qc/lookups/equipment`
  - `GET /api/wip/equipment-online-qc/candidates?equipmentNo=...&mode=wait|recheck`
  - `GET /api/wip/equipment-online-qc/lists/{qcListNo}?equipmentNo=...&mode=...`
  - `POST /api/wip/equipment-online-qc/records`
- Lookup 僅接受 IssueState=2 設備，候檢／補驗由伺服器依 QCTaskClass、Status、有效設備與點檢表設定篩選；候選有上限且穩定排序。所有 SQL 參數化，讀取使用唯讀交易及 30 秒 statement timeout。
- POST 只提供新增，沒有編輯既有 Serial 的 PUT。Server 從 QCList Detail 重新計算每項與整體結果；檢查輸入項目、數字、範圍、InputDataCount 與 D01–D10，不接受用戶端結果欄位。Header、Detail、Task 狀態／QCSerialNo、冪等鍵在同一交易；Task 使用 `FOR UPDATE` 與狀態條件更新。
- 獨立點檢可由使用者明確確認後部分存檔，保留 `QCResult=-1`。任務若仍連結目前 `TBLWIPTEMP_EQUIPMENT` 的在製設備批次，API 拒絕新增，避免把 Check-in 誤存成一般點檢。
- 報工 Check-in POST（`CheckIn=true` 或包含 LotSerial／LogGroupSerial）目前一律回 409，不執行任何資料寫入。NG 且 `UnValidAction` 有效值也在交易寫入前回 409。原因是 `clsLot.SHR_COEquipment`、設備狀態歷程、設備 Cont 歷程及多人上工簽退需要完整原生 source 與共用交易邊界；家用端尚未取得 helper 的完整來源，不能模擬或漏做副作用。
- migration `0105_wip_wp305_online_qc_dependencies.sql` 已依 source DDL 建立三張空表並只授予 SELECT。`0106_wip_wp305_online_qc_write.sql` 已先完整備份再套用，僅授予 Log／Detail INSERT、Task `status`／`qcserialno` 欄位 UPDATE，以及 YMES 冪等表 SELECT／INSERT；正式 catalog 回讀確認最小權限。
- migration `0107_wip_wp305_candidate_indexes.sql` 已建立兩個 YMES-only 部分索引，支援今日候檢與補驗候選；不改 Oracle source key，也不寫入業務列。
- `.NET 9` API 已部署至正式 `/YMES/API/`，正式 readiness 為 ready、匿名 lookup 回 401。app-browser 驗證 Equipment Type／Equipment 空清單、候檢與補驗的無效設備 404、無效 mode 與 page/pageSize 邊界 400、Check-in 缺少 Lot／LogGroup context 400，以及正式點檢頁唯讀預覽與 Close 返回主選單。正式 lookup／任務資料為空，沒有建立假點檢資料；因此沒有宣稱正向獨立點檢新增流程已以正式資料完成。
- 公司 Vue 頁仍為唯讀預覽，Production API 接線待公司端；原生 `clsLot.SHR_COEquipment`、設備狀態變更與多人簽退交易來源未交付前，Check-in 寫入及 NG+`UnValidAction` 仍由 API 拒絕。來源缺項與公司端 UI 接線請看 `todolist_officepc.md` WP305 handoff；部署與驗收追蹤在 `todolist_homepc.md`。
