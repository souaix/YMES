# WP210 分批處理_載具（LOT SPLIT_CARRIER）

## 功能與來源

- 在製品管理 → 生產報工 → 分批處理_載具。原生 menu metadata：FunctionNo `LOT SPLIT_CARRIER`、FunctionKey `WP210`、Form `frmBR_CL_Split_GEN`、DLL `BR_CL_Split_GEN.dll`。
- WinForms 主 Form：`STD/MESWin/BR/BR_CL_Split_GEN/frmBR_CL_Split_GEN.vb`，標題 `Lot Split Have Carrier`；元件 Slot 視窗：同目錄 `frmCarrierSplit_Comp.vb`，標題 `Manual Split`，主 Form 以 `WP_CarrierSplit_Comp` 開啟。
- Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `Exe_Manual_LotSplit_Carrier`，及 `LoadLotBasisJoinState`、`LoadWIPCarrierStateDetail`、`GetLotStateIncludeData`、`ChkLotStamp`；`wsEQP.LoadCarrierState`／`LoadCarrierBasis`、`wsSYS.GetSplitLotNo_Multiple`。
- Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `BR_Manual_LotSplit_Carrier`（無元件）與 `BR_Manual_LotSplit_Carrier_Component`（有元件）。公司 Vue DEV：`web/src/components/WipLotSplitCarrier.vue`，路徑 `/YMES/WIP/LotSplitCarrier`。

## WinForms 版面與載具查詢

主 Form 約 1008×591。上方 `Reference Lot` 群組含 Carrier No、`...`、Query 與母批 Grid；下方 `Split` 群組含 Split by Count／Qty、Split Count / Qty、Include Mother Lot No Yes／No、Split、Change Routing、Change Product 與 SplitLot Grid，底部 Confirm(&C)、Close(&X)。Grid 顯示 Split Lot No、Carrier No、Split Lot Qty、Action、Process／Version、OP No、Return Type；產品兩欄在原 Grid layout 隱藏，但 Change Product 按鈕存在。`funClearData` 預設 Count、Include Mother Yes。

選單手動模式先用 `wsEQP.LoadCarrierState(CarrierNo)`：載具須有現況且 CarrierState 非 0；再以 `LoadWIPCarrierStateDetail` 取得載具內的批次。參考載具須只有**一筆生產批**；0 筆或多筆皆拒絕。`LoadLotBasisJoinState` 以單一 LotNo、HaveLevel=0、LotState=1、ShowPartialLot=False 查詢；原程式把 Status 條件註解掉，但查到 2=Wait、3=Hold、4=Complete 時明確拒絕。Status=5 的委外未回件在 Confirm 時由 `CheckLotIsOSbutNotReturn` 判斷。`GetLotStateIncludeData` 決定 HaveComponent；不由畫面傳值決定。主 Form 預載 `LoadCarrierState(CarrierState=0)` 的空載具候選；BR 宿主指定 CarrierNo 的初始化另有唯讀欄位、隱藏查找與 SplitMergeType=1。

## 分批與元件 Slot 視窗

- 無元件批可選 Count 或 Qty。Count 以整數均分，最後一列吸收餘數；Qty 產生足額列與尾數列。Yes 保留原 LotNo 為第一列並預設原 CarrierNo；No 都用預覽新批號，須為各子批選載具。主 Grid 的 SplitLotQty 可編輯；恰好兩列時修改一列會把另一列改成 `CurQty - 本列`。Action 0=Go、1=Jump OP、2=Jump Process，ReturnType 0=Not Return、1=Return Current OP、2=Return Next OP。
- 有元件批在 Query 後固定 Count=2，Count／Qty 控制鎖定。按 Split 先預覽兩個批號，立即開啟 `frmCarrierSplit_Comp`。視窗約 980×655，顯示 Reference Lot Info、Current Carrier No，左右兩個子批 LotNo／CarrierNo／CarrierType／Slot Grid，中間右移／左移按鈕及每側上下移。來源載具明細先填左側；空 Slot 依載具 `CarrierLayer × CarrierCapacity` 建立。選右側空載具後，以選取的來源位置和目標空位置移動元件，保留原 CarrierPosition 用於 Core 更新；選擇其他載具時應檢查可用性、容量與已配置最高位置。子視窗 Confirm 要求兩批各至少一顆元件，並以各 Grid 有元件列數覆寫 SplitLotQty／CarrierNo。右側不能選左側同一載具。主 Form 重新開啟 Slot 視窗時保留暫時配置。
- `GetSplitLotNo_Multiple(False)` 只產生預覽。主 Confirm 重取預覽核對，然後用 `True` 保留序號。母批保留時 Core 只允許 Action=Go。主 Confirm 要求每列 Qty 非零、CarrierNo 非空且不同，使用選定的可用空載具／原載具、全列 Qty 合計等於母批 CurQty。Go／Jump OP 的 ReturnType 只能 0；Jump OP／Process 必須有 NodeID。`ChkLotStamp` 防過期資料，Service 再按 HaveComponent 分派 Core。

**來源差異與實作判斷：** `btnChangeProduct` 會改 Form 暫存列的 ProductNo／Version，Service 也可解析這兩個欄位，但主 Form Confirm 組裝 `splitlot` XML 時只送 SplitLotNo、SplitLotQty、Action、NodeID、ReturnType、CarrierNo、OPNo，**沒有送 ProductNo／Version**。原按鈕的選擇因此不會按該傳輸路徑改變 Core 產品。Vue DEV 保留按鈕與畫面預覽，正式 API 需由家用端決定是否明確停用產品變更或經業務確認後擴充，不能宣稱原生已生效。元件 Slot picker 的容量分支亦有條件／迴圈邊界可疑處，正式 API 依真實載具容量重新驗證，不能照搬有疑義的前端迴圈。

## Service/Core 副作用與資料表

`Exe_Manual_LotSplit_Carrier` 讀 LotStamp、MLotNo、SplitType、每列 SplitLotNo／Qty／Action／NodeID／ReturnType／CarrierNo／OPNo、MCarrierNo；HaveComponent=true 時另讀每顆元件的 CarrierNo／CarrierPosition／ContentID／LotNo／ComponentNo／OrgCarrierPosition。Service 驗證 Action、ReturnType、NodeID、號碼重複，再依 HaveComponent 呼叫兩個 Core 方法。兩個 Core 都在 `SHR_Split_GetReference` 後核對子批正數與總量、處理母批和子批 Lot／Log／Reverse／派工／委外／AutoMerge／CarrierState／CarrierStateDetail／DetailLog；元件分支還讀 ComponentState，要求所有來源元件至少出現在分配明細且每子批有元件，更新 ComponentState／Property、Temp／Cont ComponentAttrib、載具位置與 LotState CarrierNo。來源對未重複元件的檢查較弱，正式 API 應以集合相等、唯一性、來源歸屬與每載具位置唯一作更嚴格守門。BR 宿主 SplitType=1 成功後對 Go 子批另呼叫 `BRTransferLot`，須處理拆批已提交但後續轉站失敗的可恢復狀態。

兩個 Core 方法字面直接引用共 17 張表：`TBLEMSDISPATCHSTATE`、`TBLWIPAUTOMERGE`、`TBLWIPCARRIERSTATE`、`TBLWIPCARRIERSTATEDETAIL`、`TBLWIPCARRIERSTATEDETAILLOG`、`TBLWIPCOMPONENTPROPERTY`、`TBLWIPCOMPONENTSTATE`、`TBLWIPCONT_COMPONENTATTRIB`、`TBLWIPCONT_EMPLOYEE`、`TBLWIPCONT_EQUIPMENT`、`TBLWIPLOTBASIS`、`TBLWIPLOTLOG`、`TBLWIPLOTSTATE`、`TBLWIPOSBASIS`、`TBLWIPOSDETAIL`、`TBLWIPTEMP_COMPONENTATTRIB`、`TBLWIPTEMP_EQUIPMENT`。這 17 張都已有 YMES `database/reference/` SQL 參考：Carrier Detail／DetailLog 與 CarrierState 沿 WP302／設備 refs，Component 沿 WP101／WP201，Cont Equipment 沿 WP305，OS／AutoMerge／Dispatch／Cont Employee 沿 WP207，其餘 Lot 依 WP101／WP201。**本功能沒有新增缺失的直接表，不新增重複 CREATE SQL。** `TBLEQPCARRIERBASIS`／載具類別等查找屬共用表，亦沿既有主檔 refs。Core helper 可能再讀寫其他表，正式交易實作要逐層追查。

## 公司 DEV 與家用端 API 交接

公司 DEV 提供無元件載具 `DEV-CAR-101`、有四顆元件的 `DEV-CAR-202`、Hold 拒絕案例及三個空載具；無元件頁可編 Qty／載具／路由，元件頁提供固定 Count 2、雙 Slot Grid、左右移及上下移、容量與元件守恆。DEV 以整數 Qty 與最多 100 列簡化原 Double／Decimal 精度，僅存 `ymes-dev-mock:wip-lot-split-carrier:state:v1`，沒有操作真載具、Lot 或元件。正式 non-DEV 頁由框架禁用假資料與確認。

家用端先核對 YMES PostgreSQL live schema/migration history；17 張直接表與 Carrier Basis／Type 共用表若已存在就重用，不建立重複 migration。提供登入保護的指定 Carrier→唯一 Lot→Slot／Component 查詢、可用空載具及容量、Product／Route lookup，並由 server 判定 HaveComponent、LotStamp、Status／委外狀態與 BR 模式。拆批 POST 在同一交易鎖定 LotStamp、原載具／目標載具、Slot／Component、批號序號與資料庫現況；核對子批數量、每顆元件完整且唯一、目標位置可用且容量足夠、CarrierNo 不重複、Action／ReturnType／NodeID、權限與庫存／派工副作用。CarrierState／Detail／DetailLog、Lot／Component／Temp／Cont／Reverse／History／OS 的寫入須一致；若 BRTransferLot 無法同交易，回可查、可重試、冪等的部分完成結果。不得信任瀏覽器傳入 HaveComponent、SplitType、MCarrierNo、Slot 原歸屬、UserNo、ShiftNo 或預覽序號。

本輪公司端未連 YMES PostgreSQL、未建 migration／Production API；沿既有使用者約束未執行 build/test/browser。
