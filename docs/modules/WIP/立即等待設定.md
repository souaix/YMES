# WP502 立即等待設定

## 原生來源

- 選單：在製品管理 → 異常與等待 → 立即等待設定；`FunctionNo=IMMEDIATE WAIT SET`、`FunctionKey=WP502`、`WP_ImmediateWaitSet.dll`。公司 Vue DEV 頁 `web/src/components/WipImmediateWaitSet.vue`，路徑 `/YMES/WIP/ImmediateWaitSet`。
- 主 Form/Designer 同在 `STD/MESWin/WIP/WP_ImmediateWaitSet/frmImmediateWaitSet.vb`；Set 開 `WP_WaitDescription/frmWaitDescription.vb` 共用說明視窗。`WP_ImmediateWaitSet_RefLot` 是另一套 Reference Lot Form，不是此 menu 的 DLL，不能混同。
- Service `STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs`：`LoadLotBasisJoinState`、`CheckLotPackage`、`Exe_Wait_Set`。Core `STD/MESkc/kcWIP/clsLot.cs`：`SetLotStateToWait`（`WaitType=2`）。

## 版面、查詢與 Set

主 Form 標題 `Immediate Wait Set`，ClientSize 1008×730。上方 Lot Query 有 Area No、PS No、OP No、Customer No、Product No、MO No、LotNo 七欄；前六欄 `...` 查找、Query。下方 Lot 群組有 Select All、UnSelect All、掃描 LotNo（Enter 勾目前結果），15 欄 Grid：Select、LotNo、Status、LotSerial、AreaNo、PSNo、ProcessNo、OPNo、NodeID、BRNo、CurQTY、CurUnitNo、SysQTY、SysUnitNo、BaseLotNo；底部 Set/Close。欄位輸入和資料格在公司頁使用既有黃色系。狀態顯示 0 Queue、1 Running、4 Complete。

Query 至少有一個篩選，送 `Status=0|1|4`，另固定 `A.CurQty>0`。回傳後移除 `PartialMode=1 且 PartialType=0/1 且 Status>1`，以及 `Status=4 且 LinkName=WAIT/HOLD`；只顯示 `LotState<>0`。選取只作用於本次結果；掃描找不到不勾。Set 至少勾一筆，主 Form 將所選 LotNo 以逗號串起來呼叫 `CheckLotPackage`，再以**第一筆** Lot 資訊開共用 Wait Description 視窗。彈窗顯示 LotNo、CurQty、CurUnitNo，收可為空的 Description；Confirm 問是否繼續，回傳說明文字，不直接呼叫 Service。

主 Form 接著逐批呼叫 `wsWIP.Exe_Wait_Set`，傳 LotNo、OPNo、LotStamp、WaitDescription、CurQty、WaitSource=0、LotIsValid=1；若 PartialMode=1 另傳 IsPartial、pStatus、PartialType。第一筆回傳的 WaitNo 作後續各筆的 `BatchWaitNo`；每成功一筆就重新 Query。原先「Partial 只可 Queue」的 Set 檢查已整段註解，現行版本允許一般與網狀分量 Queue/Running；不能把舊註解當有效限制。任何一筆失敗會中止後續，先前成功的批不回滾，可能部分完成。

**包裝預檢缺陷：**主 Form 傳逗號連接的 LotNo，但 `wsWIP.CheckLotPackage` 將整個值放進只有一個元素的 `LotNoList`，沒有拆分。正式 API 必須對每筆所選 Lot 重查包裝與歸屬，不能沿用這個字串用法。公司 DEV 也逐筆拒絕已包裝批。

## Core 交易與正式 API

`Exe_Wait_Set` 呼叫 `clsLot.SetLotStateToWait(LotStamp,LotNo,WaitType=2,...)`。Core 先讀 LotState/LotBasis：已 Status=2 拒絕；Status=4 且 LinkName=HOLD 拒絕。Partial 分支按 OPNo、Status 定位；讀使用者部門；以 `funInitWaitNo()` 產 WaitNo，第一筆同時作 BatchWaitNo。WIP 來源另產新 LotSerial、處理站中/站間 LotLog、將 `TBLWIPLOTSTATE.Status=2`、`LinkName=WAIT`，保存原 Status 到 `GoStatus`，必要時更新 Temp_LotState；寫 `TBLWIPWAITBASIS`（Status=0、WaitType=2、WaitSource=0、WaitDescription 非空才寫欄、BatchWaitNo）。最後 `ChkLotStamp` 並執行成組 SQL，呼叫 ReleaseLog helper；插件 adapter 亦可加入 SQL。FutureWait branch 僅 `WaitType=3`，不屬 WP502。

正式 API 提供登入與 Function ACL 的七欄候選查詢、前六類查找及可勾選 Grid 資料；限制筆數/分頁，至少一個查詢條件。批次 Set POST 收選取的 LotNo/OPNo/版本、Description、冪等鍵。後端對所有批逐筆或整批鎖定重讀 LotStamp、CurQty、狀態、PartialType、LinkName、包裝、權限與來源；server 產生各筆 WaitNo 和共用 BatchWaitNo、使用者及時間。**交易政策需明定**：建議全批原子成功/失敗；若相容原逐批部分成功，則每筆結果、已成功清單、失敗位置與可重試鍵必須明確回傳，不能把部分完成當全批成功。不得信任 browser 送入的 CreateQty/WaitSource/LotIsValid/UserNo。SQL 參數化、版本衝突明確回應；追 Reverse、LotLog、ReleaseLog、Adapter 間接副作用。

## 資料表與兩端交接

Core 直接引用 `TBLWIPLOTSTATE`、`TBLWIPLOTBASIS`、`TBLWIPLOTLOG`、`TBLWIPTEMP_LOTSTATE`、`TBLWIPWAITBASIS`、`TBLUSRUSERBASIS`、`TBLWIPCOMPONENTSTATE`；包裝 helper 另有間接表。`TBLWIPWAITBASIS` 的 Oracle source DDL 在 `database/reference/mestest_wip_wp201_additional_source_ddl.sql`，PostgreSQL CREATE-only 在 `mestest_wip_wp201_create.sql`。LotBasis/State/Log/ComponentState 沿用 WP101 source/CREATE refs，Temp_LotState 沿用 WP201，USRUserBasis 有 QC409 source 與首批 CREATE 參考。本功能沒有新缺失的**直接**表，故不重複產生 Oracle DDL 或 CREATE SQL；家用端仍須核 live PostgreSQL schema/history、間接表與現存資料，只對確實缺項做 forward migration。

公司 DEV localStorage `ymes-dev-mock:wip-immediate-wait:state:v1`，含 Queue、Running partial、Packed、Complete+HOLD、已 Wait 五種示範 Lot。A01/MO-501 可查兩筆，Select All/掃描、Set、共用說明視窗、逐筆假 WaitNo 與 BatchWaitNo、Status=2、LotStamp 增量可操作；正式 non-DEV 不讀取假資料或送出假交易。DEV 不更新 MES/PostgreSQL、無實際 Reverse/ReleaseLog 或插件行為；本輪僅靜態來源核對，依現有交接未執行 build/test/browser。
