## 原 WinForms 畫面與操作

Query 區有 Customer No、Lot No、Product No、OP No、Wait No、MO No 六個勾選文字欄；Customer/OP/Product/MO 各有 `...` lookup。Create Date 的 From、To 各自勾選。Query 不要求使用者先填條件；Form 固定送 `Status=0`（Create／未處置）、`WaitSource=0`（WIP），不查 SPC Wait。Core 以 `A.LotNo LIKE '%...%'`，其他五個文字欄精確比對；Product/MO 用 LotBasis 當前值。Core Join `TBLWIPWAITBASIS A`、`TBLWIPLOTSTATE B`、`TBLWIPLOTBASIS C`、`TBLOPBASIS D`、`TBLPRSPROCESSBASIS E`，計算 `CalWaitTime` 分鐘；網狀製程同一 Lot 可能多站，Core 查後按狀態/站做去重。

Wait Lot 區有 Select All、UnSelect All、Lot No 掃描 Enter（精確比對後勾選）與 Grid。Grid 17 欄依序為 Select、Lot No、GoStatus、Wait No、Base Lot No、Product No、Customer No、OP No、Area No、PS No、Process No、Rule No、Wait CurQty、Unit No、Cal Wait Time、Priority、Batch WaitNo。選取列顯示 readonly Wait Description；勾選列才參與 Confirm。Lot Disposition 左為 Split/Merge，右為 Go、Jump OP、Jump Main、Jump Process、Jump Module、Inventory、Scrap Inventory、Process Tuning；Change ENGNo 控制在 Designer `Visible=False`，DEV 不顯示。右側選項切換 Jump OP/Process/Main/Module/Inventory/Process Tuning 專屬欄位，底部 Release Disp、Confirm、Close。目標 OP、Process、Module、Inventory 等欄位原為 readonly，以 `...` 選取並取得 NodeId 等內部鍵；不可只信 UI 文字。

## 權限與確認守門

`LoadDispPriv("WAIT")` 查 `XX_TBLWAITPRIV` 中使用者所屬 `TBLUSRUSERGROUP.GroupNo`；無列時禁用 Split、Merge、Go、Jump OP/Main/Process/Module、Inventory/Scrap、Process Tuning。有列時各權限欄任一列為 1 即開放。Jump Process 分成 `JUMP_PROCESS_01`（不回原流程）及 `_02`（返回原流程），Form 在選列時依兩種旗標開放 radio。這是 WinForms 的顯示邏輯；正式 API 必須以登入 user/group 在**每次 command**重查 `XX_TBLWAITPRIV` 與 Function ACL，防止直接呼叫 API 越權。

Confirm 至少需勾一個 Lot、選一個處置；禁止 PartialMode=1 與非部分過帳混選，部分過帳只准 Go/Jump OP/Jump Process/Process Tuning/Inventory/Scrap Inventory。IC PKG 的 ECN 啟用狀態須一致；ECN 批產品/版本須一致。Split/Merge 只允許單 Lot，並先排除貨架 Lot；依 GoodBinState → Bin、否則 HaveComponent + CarrierNo → Carrier Split／Component，否則一般子窗。Merge 的 Component 分支沒有 Carrier 專窗。Jump OP、Process Tuning 批次需同 ProcessNo；Jump Process 需同 PSNo 且不在 Module，選 Process/OP，若回原流程還要 Return OP。Inventory 與 Scrap Inventory 需 InventoryNo；Jump Module 需 Module/Version，原 UI 的 Return Main Process 預設勾選，Not Return radio 被隱藏，並需 Return OP；Jump Main 需 OP。目標路由和是否允許往前跳、版本/NodeId 必須用 server 端 PRS 資料重查。

處置類型：0 Go、1 Jump OP、2 Jump Process、3 Inventory、4 Process Tuning、5 Change ENGNo（來源隱藏）、6 Jump Module、7 Scrap Inventory、8 Jump Main；Split=12、Merge=13 由各自子窗服務負責。主 Form 一次勾選多 Lot 時**逐筆**呼叫 Service，可能前幾筆已成功、後面失敗。一般 Service/Core 用 LotStamp、LotNo、ReleaseType、NodeId/ReturnNodeId、InventoryNo、Module/Version 等執行；Core 寫 `TBLWIPWAITLOTDISPOSITION`，把 `TBLWIPWAITBASIS` 更新成 Status=21、ReleaseQty/ReleaseDate/Releaser，並透過 Reverse/WIP route、LotState、LotLog、Inventory 等共用交易更新。非 Partial 的 Go 在解除後可能追加 Transfer Lot 或產品變更；Partial 走 NetFlow 且可能產生 ReworkLotNo。這些副作用、並發與補償不能只靠前端模擬。

## Oracle DDL 與 PostgreSQL CREATE-only

公司端以 PowerShell 5.1、受保護 MESTEST profile 與 `Oracle.ManagedDataAccess.dll` **只讀** `DBMS_METADATA.GET_DDL`、`ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_INDEXES`、`ALL_TRIGGERS`，取得新發現的 `MESTEST.XX_TBLWAITPRIV` 原始資料：14 欄、全部 NOT NULL；`GROUPNO` 主鍵與唯一索引，無 FK/trigger，11 個處置旗標均 `NUMBER(1,0) DEFAULT 0`。來源檔：`database/reference/mestest_wip_wp511_priv_source_ddl.sql`、`mestest_wip_wp511_priv_source_indexes.sql`、`mestest_wip_wp511_priv_metadata.txt`。PostgreSQL 空表參考：`mestest_wip_wp511_priv_create.sql`；它不是已套用 migration，家用端須先核 live schema/history，僅對實際缺項做 forward migration。主 `TBLWIPWAITBASIS` 沿 WP201，處置紀錄 `TBLWIPWAITLOTDISPOSITION` 沿 WP510，`TBLUSRUSERGROUP` 沿設備工程群組、`TBLWIPLOTOPECNRECORD` 沿 WP207；其他 Lot/PRS/OP 共用表沿已有 reference，不重複造表。

## 公司 DEV 與正式 API handoff

DEV 元件 `web/src/components/WipWaitDisposition.vue`：六欄＋獨立日期查詢、17 欄 Grid、全選/掃碼、Wait Description、十種可見處置、條件欄位 lookup、批次同流程/同 PS/Partial/ECN 的假資料守門、逐筆解除記錄。本地 key `ymes-dev-mock:wip-wait-disposition:state:v1` 只存示意處置；WP510 讀取此 key 並顯示已解除狀態與 Wait Info 明細，WP502 建立的本機 Wait 亦可在此查詢。DEV 沒有真使用者群組資料，選項皆以示意權限開放；硬編碼目標路由不等於正式 NodeId。Split/Merge 子窗是單 Lot 的數量／相容批號**簡化示意**，尚未實作七種原始子窗的 Bin/Component/Carrier 明細、Carrier 容量、元件守恆、Lot 編號與庫存共用交易；WP502 localStorage 原 LotState 也不被 DEV 跨 key 原子更新。這些差異不可當成正式完成。

家用端 API：登入/`WP511` ACL 的分頁查詢（後端固定 Status=0、WaitSource=0，限制全表查詢結果），群組權限 read model；`POST /wip/waits/dispositions` 可採明確的單筆或批次契約。每 Lot 鎖定 Wait/LotState/LotStamp，重查狀態/權限/路由/ECN/Partial/庫存；同一資料庫交易更新 WaitBasis、WaitLotDisposition、Lot/Reverse/Log/Inventory，使用 idempotency key 與明確逐筆成功/失敗回報。Go 後續 Transfer/Product Change、Partial NetFlow/ReworkLot、Split/Merge 七種子窗業務交易需按 source Service/Core 分支逐一移植或封裝為 command，不可由 browser 提供任意 NodeId/SQL/角色。原 Core 以字串拼接 SQL；新 API 全部參數化。詳細 API/PG 交接列於 `todolist_homepc.md`。
