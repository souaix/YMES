# WP402 外包單確認

- 選單 FunctionNo 為 `OS CONFIRM`，路由為 `/YMES/WIP/OutsourceConfirm`。讀 `STD/MESWin/WIP/WP_OSConfirm/frmWIPOSConfirm.vb` 及內嵌 Designer、`wsWIP.ExeOS_Confirm`／`updERPNoOut`、`kcWIP.clsLot.ExeOS_Confirm`。
- 主查詢和雙 Grid 沿用 [WP401](外包單開立.md)，固定 Status=0、OSType=2，選單號、站、外包商、建立人員及日期。選超過一筆時，舊 Form 將選取縮回目前作用列，再由確認窗確認。
- Core 重讀外包單、外包項目、回貨節點及外包流程 START 的目標節點。逐批查 LotState，必須存在、Status=0（Queue），且 OPNo 等於外包站。以當時 CurQty 加總並保存出貨人員、時間及 Status=1。更新批狀態／流程、Reverse 與 LotLog；將 FutureOS 搬到 FutureOSLog。須保留回原流程和不回原流程的差異。
- `WFERPOutSouring=1` 時，舊 Form 先查 active ERP，依 E10ICD 或 TIPTOPICD 建請購單。MES 確認後另呼叫 `updERPNoOut`。外部成功但 MES 或 ERPNo 回寫失敗時需要補償及對帳。

## DDL 與家用端交接

- OS Basis／Detail／FutureOS、LotState、LotBasis、LotProcess、LotLog_Report、ReverseHistory 與 PRS 流程表有既有 references。
- PowerShell 5.1 + ODP.NET 唯讀取得 [TBLWIPFUTUREOSLOG DDL](../../../database/reference/mestest_wip_wp402_future_os_log_source_ddl.sql)，該表有 LOTNO 非唯一索引，未見 PK。另取得 [TBLSYSERPSETTING 欄位與鍵](../../../database/reference/mestest_wip_wp402_metadata.txt)，ERP_NAME 為主鍵；設定表參考由欄位和鍵重建，未查設定列及預設值。兩張的 [CREATE-only](../../../database/reference/mestest_wip_wp402_create.sql) 供 live schema 比對。
- 建議登入及 WP402 ACL 的 `POST /api/wip/outsource-orders/{osNo}/confirm`，用狀態與可空 DataStamp CAS，鎖主檔與所有涉及批號，在同一交易核對站點、批狀態、流程與更新三方。ERP 分支依正式設定走具冪等鍵的 provider 及對帳；若啟用但 provider 不可用，回報原因，不能只改狀態或用 DEV ERP 識別碼代填。

## DEV

- 與 WP401 共用單據。單筆確認會檢查固定批號的外包站相符，並記錄模擬出貨人及日期。批 fixture 視為排隊。確認後單據離開 Status=0 清單。DEV 不送 ERP，也不模擬流程搬移、Reverse 或報表歷程。正式資料及驗收交家用端。
