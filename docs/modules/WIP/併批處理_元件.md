# WP212 併批處理_元件（LOT MERGE_COMP）

## 功能與來源

- 選單：在製品管理 → 生產報工 → 併批處理_元件。原生 FunctionNo `LOT MERGE_COMP`、FunctionKey `WP212`、Form `frmBR_LC_Merge_GEN`、DLL `BR_LC_Merge_GEN.dll`。公司 Vue DEV 為 `web/src/components/WipLotMergeComponent.vue`，路徑 `/YMES/WIP/LotMergeComponent`。
- WinForms：`STD/MESWin/BR/BR_LC_Merge_GEN/frmBR_LC_Merge_GEN.vb`。Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `Exe_Manual_LotMerge_Component`、`LoadLotBasisJoinState`、`LoadComponentState`、`ChkLotStamp`；載具查詢用 `wsEQP.LoadCarrierState`／`LoadCarrierStateDetail`。Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `BR_Manual_LotMerge_Component`，其 User Define hook 為 `udWIP.clsWIP.BR_Manual_LotMerge_Component`。

## WinForms 版面與互動

原視窗標題 `Manual Component Merge`，ClientSize 1008×661。`Reference Lot` 有 RefLot No、查找與 Grid；`Merge Lot` 左上為 Select All／UnSelect All、MO No 多選查找，左側候選 Grid 欄位 Check、LotNo、CurQty、MONo、NodeID、CurUnitNo，右側 `Lot's component` Grid 欄位 ComponentNo、GoodQty、ScrapQty、UnitNo。點選候選列即用 LotNo 呼叫 `LoadComponentState` 更新右側 Grid，GoodQty／ScrapQty 分別加總。參考批列黃色且固定勾選。下方 `Transfer Type` 提供 Go／Assign、Process No／Version／OP No lookup 與輸出 LotNo；底部寫明同 OPNo／ProductNo／BRNo／Status／CurUnit 的規則，按鈕 Confirm(&C)、Close(&X)。

手動選單不預先載入全部 Lot。參考批查詢 `LoadLotBasisJoinState` 以 `Status=0|1|4`、`HaveComponent=1`、`LotState=1`、`ShowPartialLot=False`、`StockerLot=False`；原 `HaveLevel=0` 在參考批查詢被註解。輸入批號查找用 `BaseLotNo LIKE <input>%`；候選則 `HaveComponent=1`、`HaveLevel=0`、`LotState=1`、同 OPNo／ProductNo／BRNo／Status／CurUnitNo，且不在 Stocker。`SysInfo/AllowDiffMOMerge=0` 才加同 MONo。MO 多選篩選只留選中工單且固定保留參考批工單；全選／取消全選沿 WP211 方式。這頁沒有 WP211 的 OS 同外包單分支，原 Form 也未做 WP211 的包裝／GoodBin 查驗；不能直接複製 WP211 的條件。

## 確認與原生缺陷

- Confirm 要求參考批、輸出 LotNo，Assign 另需 Process No／Version／OP No 和 NodeID。參考批仍須在候選表，選中筆數**至少 2**（和 WP211 已註解的規則不同），每筆 CurQty 不能為 0；同 OPNo 不同 NodeID 時提示使用者。先 `ChkLotStamp` 參考批，再送 `RefLotNo`、`NewLotNo`、`MergeType`、`Action`、每筆 `LotNo/CurQty/LotStamp`；Assign 送 NodeID／OPNo。手動選單 MergeType=0，BR 宿主=1；WIP Inventory 宿主另送 WIPINV／InventoryNo／ShiftNo。
- Form 的載具防護意圖是每個選中批都查 `LoadCarrierState`／`LoadCarrierStateDetail`，若在載具中提示改用 `LOT MERGE_CARRIER`。**但原迴圈每次實際傳的是 `txtLotNo.Text`（輸出批號），沒有傳目前列 LotNo**。這是來源缺陷，不應照抄為正式 API。正式命令須對每個來源 Lot 分別檢查 CarrierState／Detail，且 server 再重查，避免載具元件被錯併。公司 DEV 依意圖逐筆拒絕，並以 `DEV-CMERGE-CARRIER` 示範。
- 原參考批 `HaveLevel=0` 條件註解、候選仍要求 0，因此參考批若有等級資料可能無法進入候選 Grid；不可臆測原 Form 一定可成功。家用端須保留明確錯誤，並與等級併批入口協調。BR 宿主 Go 成功後 Form 會關閉再呼叫 `BRTransferLot`；Core 末尾另有「一律手動 Transfer」註解，兩者不一致，正式流程按實際宿主模式分開處理，記錄可恢復的部分完成。

## Service/Core 與資料表

`Exe_Manual_LotMerge_Component` 解析 `MergeType` 0/1、Action、RefLotNo、NewLotNo、每列 LotNo／CurQty／LotStamp、NodeID／OPNo、可選 WIPINV／InventoryNo；Core 要求至少一列且 Action 只允許 Go／Assign，Assign 必須有 NodeID。正式 API 仍須以 Form 的至少兩筆為業務規則，不能只套 Core 的最小一筆。Core 以 Reference Lot 建 Reverse／LotSerial，逐來源收集 ComponentState 的 ComponentNo／GoodQty／ScrapQty／UnitNo／ExecuteState／Status，關閉來源 Lot、建立合併 Lot、更新元件現況、歷程及多人作業。`dtSHR_Component` 保留當下每顆元件數量，傳 `SHR_Merge_Inherit`；執行 User Define hook，末端逐批 `ChkLotStamp` 後將 SQL collection 一次送執行器。WIP Inventory 分支還核參考批及其他批在 InventoryNo 的 Semi／Component、跨庫房元件，更新／回補 Inventory 與 ComponentState；不能用手動畫面預覽取代庫房一致性守門。

Core 方法字面直接引用十張表：`TBLEMSDISPATCHSTATE`、`TBLINVWIPINVENTORY_COMPONENT`、`TBLINVWIPINVENTORY_SEMI`、`TBLWIPAUTOMERGE`、`TBLWIPCARRIERSTATE`、`TBLWIPCARRIERSTATEDETAIL`、`TBLWIPCOMPONENTSTATE`、`TBLWIPCONT_EMPLOYEE`、`TBLWIPLOTBASIS`、`TBLWIPLOTSTATE`。逐名核對 `database/reference/`，十張均已有 Oracle source DDL 與 PostgreSQL CREATE-only：Inventory Component 沿 WP603、Semi 沿 WP201、Carrier Detail 沿 WP302、CarrierState 沿既有載具主檔、Component／Lot 沿 WP101，Dispatch／AutoMerge／Cont Employee 沿 WP207。**本功能無新增缺表，不重複產生 CREATE SQL。** Service/Core helper 與 User Define hook 的間接表及實際部署實作仍須追查；reference 不能替代 PostgreSQL live schema/migration 核對。

## 公司 DEV 與家用端交接

公司 DEV 固定提供參考批、同工單批、跨工單且不同 NodeID 批、載具批與系統參數禁止跨工單案例；左側選取、右側點列更新元件與各 Qty 加總、MO 篩選、Go／Assign、至少兩批、載具拒絕和節點提示均可操作。資料只寫 `ymes-dev-mock:wip-lot-merge-component:records:v1`；未寫 MES、未執行 Reverse／Inventory／元件異動，且用簡化整數 Qty。正式 non-DEV 禁用假資料與過帳。

家用端先核對 live schema、helper/User Define hook，再提供有權限的參考批／候選批／元件明細／載具／路由查詢與原子併批命令。交易內依可信 server 現況鎖定所有來源 Lot、LotStamp、ComponentState、CarrierState／Detail、Inventory 及輸出 LotNo，核對元件歸屬與唯一、GoodQty／ScrapQty、CurQty／換算與跨庫房；寫入 Lot／Reverse／Component／Log／Inventory／Cont Employee 必須一致。拒絕重複提交，BR 後續轉站須可查與冪等重試；MergeType、InventoryNo、UserNo、ShiftNo 與 `AllowDiffMOMerge` 不能接受瀏覽器任填。公司端未連 YMES PostgreSQL、未建正式 API/migration，依既有使用者約束未執行 build/test/browser。
