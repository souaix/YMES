# WP603 在製品庫帳務維護（WIP INV）

## 功能定位與證據範圍

- FunctionNo：`WIP INV`；選單為「在製品管理 → 包裝與庫房 → 在製品庫帳務維護」；執行檔清冊記載 `WP_Inventory_WIP_THEIL_BU1.dll`。
- 清冊指定的 `frmInventory_WIP_THEIL_BU1` 分支 Form 原始碼未在目前 MES checkout 找到。可讀到的共用實作為 `STD/MESWin/WIP/WP_Inventory_WIP/frmInventory_WIP.vb`、`frmInventory_WIP_RawDef.vb`、`frmInventory_WIP_SemiDef.vb` 及同資料夾轉庫／重跑表單。本規格依該共用 Form、標準 Service/Core 和 Designer 記錄；THEIL DLL 專用差異尚無可讀來源，不能假定客製邏輯已被完整核實。
- Service 主要經 `wsSMD`、`wsSYS`、`wsWIP`、`wsINV`、`wsOE`、`wsPRD`；Core 主要是 `clsLot`、`clsInventory`、`clsMO`。Raw Lot Split 另透過 `ObjectFileHandler` 執行 `WP_Inventory_Raw_Split` 外掛。
- Form 標題 `Wip Inventory`，ClientSize 1008×591。Query 區、分頁 Grid、底部 Close 與使用者狀態列是共用主畫面。

## Query、預設值及分頁

- 啟動時呼叫 `wsSMD.LoadInventoryBasis(InventoryType=6)` 載入 WIP Inventory 編號，另呼叫 `wsSYS.LoadBin` 載入 System Bin。未傳入 InventoryNo 時不自動查清單；有傳入則選取並執行該編號。
- Query 欄位：InventoryNo；Lot No checkbox + 輸入；INVDate checkbox + From／To 日期時間；Query 按鈕。初始日期為一週前 00:00 至當日 23:59:59。Lot No 輸入會同步勾選 Lot No checkbox。
- Query 需先有 InventoryNo，然後一次載入 Raw、Raw_Comp、Scrap、Scrap Component、Fail Bin、Entrust、Return、Wait Incoming 與三種 SEMI 檢視；日期與 Lot 條件依各查詢呼叫傳入。日期條件關閉時不傳日期參數。
- Designer 宣告 11 頁籤，其中一般操作可見 8 個：`Raw`、`Raw_Comp`、`SEMI_Lot`、`SEMI_Comp`、`SEMI_BIN`、`Scrap`、`Scrap Component`、`Fail Bin`。`Return`、`Entrust`、`Wait Incoming` 的 UltraTab 預設 `Visible=False`；目前 Vue 不把這三頁當成標準可見功能。
- `SEMI_Comp` 與 `SEMI_BIN` 主列選取後立即載入下方明細。前者透過 `wsINV.LoadINVWIP_Raw_Component` 取得 Component；後者呼叫 `wsWIP.LoadGoodBinState`，再依 `TBLSYSBIN.BinOrder` 由小至大顯示資料表中存在的 Bin 欄位。
- `Scrap` Grid 有 Relation 子列，使用 `TBLWIPCONT_ERROR` 顯示錯誤明細；非 Component scrap 的 `Fail Bin` 直接呈現 BIN1–BIN8 欄。

## 各頁籤的資料與欄位

| 分頁 | 載入 Service／Core | WinForms 顯示欄位 |
| --- | --- | --- |
| Raw | `LoadWIPInventory_Raw_LeftJoinComp` → `clsLot.LoadWIPInventory_Raw` | MaterialNo、MaterialName、MaterialLotNo、LocatorNo、Qty、UnitNo、MaterialType、ManufactureDate、ExpireDate、GraceDate；依 MaterialNo／MaterialLotNo／LocatorNo 排序。 |
| Raw_Comp | `LoadWIPInventory_Raw_InnerJoinComp`，選列後 `LoadINVWIP_Raw_Component` | 主 Grid 同 Raw；下方 ComponentNo、GoodQty、ScrapQty、UnitNo。 |
| SEMI_Lot | `LoadWIPInventory_SEMIJoinLotBasisSplit`，BookingFlag=0、HaveComponent=0、HaveLevel=0 | ProductNo、ProductName、LotNo、LocatorNo、MONo、Qty、UnitNo、CustomerNo、InputDate。 |
| SEMI_Comp | 同一查詢，BookingFlag=0、HaveComponent=1 | 主 Grid 同 SEMI_Lot；下方 ComponentNo、GoodQty、ScrapQty、UnitNo。 |
| SEMI_BIN | 同一查詢，BookingFlag=0、HaveLevel=1 | 主 Grid 同 SEMI_Lot；下方依 TBLSYSBIN.BinOrder 動態顯示 BinNo quantity 欄。 |
| Scrap | `LoadWIP_ScrapByError` | LotNo、LocatorNo、LotSerial、MONo、OPNo、ScrapQty、LossQty、UnitNo、CustomerNo、ProductNo、ProductName、InputDate；初始條件 `ScrapQty>0 OR LossQty>0`、IncludeInvInLot=False。錯誤子列顯示 ErrorQty 等欄位。 |
| Scrap Component | `LoadWIP_ComponentScrap`，IncludeInvInLot=False | LotNo、LocatorNo、LotSerial、ComponentNo、OPNo、GoodQty、ScrapQty、UnitNo、BaseLotNo、InputDate。 |
| Fail Bin | `LoadWIP_FailBin` | LotNo、LotSerial、OPNo、UnitNo、BaseLotNo、InputDate、LocatorNo、BIN1–BIN8。 |

## 可見按鈕、操作及舊語意

### Raw／Raw_Comp

- Raw 可見 `ADD`、`EDIT`、`DEL`、`Scrap`、`Lot Split`、`Label Print`。Raw_Comp 顯示元件明細並有獨立 Label Print／Lot Split 操作。
- Raw Add/Edit 開 `frmInventory_WIP_RawDef`，`DefMode=0/1`。刪除可多選，但舊程式逐列呼叫 `wsWIP.DelWIPInventory_Raw`；遇到第一筆錯誤即停止，先前成功列不回滾，最後若已有成功才重載清單。
- Scrap 開 `frmErrorCollect_RawScrap` 並傳 InventoryNo、MaterialNo、MaterialLotNo、Qty；由該表單處理不良原因及報廢數量。Lot Split 呼叫外掛 `WP_Inventory_Raw_Split`。Label Print 讀取本機 Label 程式、資料檔、印表機設定；它不是單純瀏覽器列印。

### SEMI_Lot／SEMI_Comp／SEMI_BIN

- SEMI_Lot 可見 `ADD`、`EDIT`、`DEL`、`Re Run`、`Turn Inv`、`Merge Lot`、`Split Lot`；Add/Edit 開 `frmInventory_WIP_SemiDef`。`TransferBU`、`Create Lot`、`To ERP` 由 Designer 設為隱藏。
- SEMI_Comp 可見 `ADD`、`DEL`、`Re Run`、`Turn Inv`、`Merge Comp`、`Split Comp`。`EDIT`、`Transfer Inv`、`TransferBU`、`To ERP` 預設隱藏。
- SEMI_BIN 可見 `ADD`、`DEL`、`Re Run`、`Turn Inv`、`Merge Bin`、`Split Bin`。`EDIT`、`Create Lot`、`To ERP`、`TransferBU` 預設隱藏。
- Component／Bin 明細隨主列選取更新。`SEMI_WAFER` 產業包系統設定會設定 `blnSEMI_Wafer` 並影響特定轉庫行為；DEV 不模擬 Wafer 專用交易分支。

### Scrap／Scrap Component／Fail Bin

- Scrap 可見 `DEL`、`Re Run`；其 `Turn Inv` 與 `To ERP` 按鈕預設隱藏。刪除、重跑會走各自資料列及專用表單，不等同一般 lot 庫存 CRUD。
- Scrap Component 可見 `DEL`、`Re Run`、`Turn Inv`；Fail Bin 可見 `Re Run`、`Turn Inv`。
- `Re Run` 開啟對應 `frmReRun_*` Form；`Turn Inv` 進入庫存轉移流程，會影響 Lot、Component、Bin、庫房及歷程資料。不能只更新 Vue 列上的 InventoryNo。

### 隱藏頁籤

Return、Entrust、Wait Incoming 頁籤在 Designer 預設隱藏；程式碼仍有 Return→Entrust、Entrust Create Lot、Wait Incoming Release handlers。若 THEIL 的實際 DLL 有開啟這些頁籤，需補取該分支原始碼／部署設定後再認定是正式可見功能，本輪不在 Vue 顯示。

## Oracle 資料表與 DDL

Windows PowerShell 5.1 + `STD/MES_S_DLL/Oracle.ManagedDataAccess.dll` 從本機受保護 profile 直連 MESTEST，只讀查 DBMS_METADATA 與 dictionary。九張本功能查詢／維護表均在 MESTEST 找到，未查業務列、未執行 Oracle DDL/DML。

| Table | Primary Key | 本頁用途／metadata 重點 |
| --- | --- | --- |
| TBLINVWIPINVENTORY_COMPONENT | InventoryNo, LotNo, ComponentNo, LocatorNo | Lot／Component 在庫數量。另有獨立 unique index `(InventoryNo,LotNo,ComponentNo)`。 |
| TBLINVWIP_COMPONENTSCRAP | InventoryNo, LotSerial, ComponentNo, LocatorNo | Component 報廢；另有 BaseLotNo 非唯一索引。 |
| TBLINVWIP_FAILBIN | InventoryNo, LotSerial, LocatorNo | Fail Bin；固定 BIN1–BIN8；另有 BaseLotNo 非唯一索引。 |
| TBLINVWIP_INCOMING | LotSerial | 待入庫批資料。 |
| TBLWIPCONT_ERROR | 無 PK | Scrap Relation 錯誤明細；ReasonType NOT NULL DEFAULT 0；索引 `(LogGroupSerial,ErrorNo)` 與 `(LotSerial)`。 |
| TBLINVSCRINBASIS | ScrInNo | 報廢入庫單據表頭／狀態。 |
| TBLINVSCRINDETAIL | ScrInNo, LotSerial, Source | 報廢入庫 Lot 明細。 |
| TBLINVSCRINCOMPONENT | ScrInNo, LotSerial, ComponentNo | 報廢入庫 Component 明細。 |
| TBLINVSCRINFAILBIN | ScrInNo, LotSerial | 報廢入庫 Fail Bin 明細。 |

六張上述表只有 PK 索引；TBLWIPCONT_ERROR 無 PK、只有兩個非唯一索引；TBLINVWIPINVENTORY_COMPONENT 另有獨立 unique index，TBLINVWIP_COMPONENTSCRAP／TBLINVWIP_FAILBIN 各有 BaseLotNo 非唯一索引。九表均無 FK／trigger。`DBMS_METADATA.GET_DDL('INDEX',...)` 對額外 `PK_TBLWIPINV_COMPONENT` 回 ORA-31603；該索引及其他 standalone index 按 `ALL_INDEXES`／`ALL_IND_COLUMNS` 重建欄位與順序，SQL 參考檔中已標註來源。

- [Oracle MESTEST source DDL 與索引](../../../database/reference/mestest_wip_wp603_source_ddl.sql)
- [PostgreSQL CREATE-only 參考](../../../database/reference/mestest_wip_wp603_create.sql)

沿用既有，不重複建表：`TBLINVWIPINVENTORY_RAW`、`TBLINVWIPINVENTORY_SEMI`、`TBLINVWIP_SCRAP`（WP201 references）；`TBLWIPLOTBASIS`、`TBLWIPLOTSTATE`、`TBLWIPCOMPONENTSTATE`、`TBLWIPGOODBINSTATE`（WP101／WP201）；`TBLSYSBIN`（SYS/PRD references）；另含既有 Locator、Material、Product、Customer、MO、OP 與 QC reason lookup。

## 家用端 API／schema 交接

家用電腦先比較 PostgreSQL live schema、已部署 migrations、`first_phase` 與既有共享表，再決定是否建立 forward migration；CREATE-only 僅供欄位型別／PK／額外索引比對，禁止直接覆蓋現存表。建議分離查詢及 command API：

1. 庫房 lookup 僅回 InventoryType=6；查詢 DTO 應依上述八個可見分頁提供資料，不接受 UI 傳入自由 SQL／AdditionalXML。日期與 Lot 條件使用明確、參數化欄位，並核對 WinForms 各查詢預設條件及排序。
2. Raw Add/Edit 服務端驗證 Material／Lot／Inventory／Locator；Raw Delete 維持逐筆部分成功並逐筆回傳結果，不可包成宣稱原子回滾的批次刪除。
3. Raw Scrap、Scrap、ComponentScrap、FailBin、ScrIn 的狀態／庫存更新需在伺服器交易內重查數量及狀態。TBLWIPCONT_ERROR 無 PK，不能自行補唯一鍵或依想像刪明細。
4. SEMI Lot／Component／Bin 依既有 Lot 狀態與庫存 Core 規則處理 Add／Delete／Merge／Split／Turn Inv／Re Run；動態 Bin metadata 沿用 TBLSYSBIN.BinOrder。每條交易需要保存原 Form 的 Lot／Component／庫房／Bin／release-log side effects。
5. Wait Incoming／Return／Entrust 雖在本 Form Designer 隱藏，但若後續確認 THEIL DLL 會顯示，需另以 Service 原始碼核實 Release、To Entrust 和 Create Lot 交易後才實作；不要只因 handler 存在就當可見功能。
6. Label Print 原本依賴 client 安裝的外部程式、label binary／資料及印表機。Web 版需以正式 API 提供 label data／下載或另定列印方案；不可假裝 `window.print()` 等價於舊標籤列印。
7. SYSTEM `SEMI_WAFER` package 與 `WP_Inventory_Raw_Split` 外掛仍是分支相依。家用端不要自行補建對應表或把其行為併入 generic API；Source code／部署契約取得後再補。

## 公司端 Vue DEV 頁

- Vue 路由 `/YMES/WIP/WipInventory`，三層 fallback menu 在「在製品管理 → 包裝與庫房 → 在製品庫帳務維護」。
- 假資料只存 `ymes.dev.wp603-wip-inventory.v1`。目前重現 8 個 Designer 可見分頁、共用 query、Raw／SEMI／Scrap／Component／Fail Bin Grid、列選取、動態 Bin、Scrap Relation 明細，以及可見按鈕的 DEV modal。
- DEV Add/Edit/Delete、報廢數量、Turn Inv、Split／Merge 僅為可操作展示，不會送 API、不模擬完整 Core 交易、 ERP／label binary、Release Log、WIP Lot/Component 之所有 side effects。預設隱藏的 Button／三個頁籤不顯示。
