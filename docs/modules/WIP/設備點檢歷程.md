# WP306 設備點檢歷程

## 功能來源與範圍

- WinForms：`STD/MESWin/WIP/WP_EQPQCListLog/frmEQPQCListLog.vb`（表單於開啟時最大化；Designer 預設 ClientSize 784×561）。
- Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `LoadWIPEQPQCListLogBasis`、`LoadWIPEQPQCListDetail`。
- Core：`STD/MESkc/kcWIP/clsWIP.cs` 的 `LoadWIPEQPQCListLogBasis`、`LoadWIPEQPQCListLogDetail`。
- 功能目錄：WIP → 設備與載具 → 設備點檢歷程，FunctionKey `WP306`，FunctionNo `EQP QCLIST LOG`。
- Vue DEV 路徑：`/YMES/WIP/EquipmentQcListLog`。

本頁是點檢 Log 的查詢、明細檢視和未完成紀錄編輯入口。沒有新增資料表；Header/Detail 結構沿用 WP305 查證的 `TBLWIPEQPQCLISTLOG`、`TBLWIPEQPQCLISTDETAIL`。設備 Lookup 讀 `TBLEQPEQUIPMENTBASIS`，亦沿用既有設備主檔 reference。

## WinForms 畫面與操作

### Query 區

| 控制項 | 來源行為 |
| --- | --- |
| Equipment No | 大小寫自動轉大寫、最多 30 字元；可手動輸入精確設備編號 |
| `...` | 以設備主檔資料開啟共用 Search Form，依 EquipmentNo 排序選取 |
| Start Date | `yyyy/MM/dd HH:mm:ss` DateTimePicker，勾選框控制是否附查詢參數 |
| End Date | 同 Start Date |
| Query | 依 EquipmentNo / 建立時間查詢點檢單頭 |

表單開啟會載入 Equipment Basis，並以無條件呼叫 Load Log Header（因此來源可一次查詢所有點檢單）；使用者仍可按設備及日期縮小結果。正式 API 不應照搬無限制全表回傳，見家用端 handoff。

WinForms 原始碼在傳入 `EndDate` 時誤用了 `dtpStartDate.Checked` 作為判斷條件。結果是 End Date 單獨勾選不會套用；勾選 Start Date 時兩個日期都會送出，即使 End Date 自身未勾選。本 DEV 頁保留這個可觀察到的來源行為，規格明示為既有程式瑕疵；正式 API 應分別依兩個勾選狀態處理，並在 handoff 視為明確修正，不要意外複製成 API 缺陷。

### Header Grid 與編輯

上方點檢單頭 Grid 隱藏其他資料欄位並依 QCListSerial 遞增排序，顯示欄位順序如下：

`QCListSerial, EquipmentNo, QCListNo, LotSerial, LogGroupSerial, QCResult, Description, Creator, CreateDate, Reviser, ReviseDate`

QCResult 對照 -1=`N/A`、0=`OK`、1=`NG`；Description 可多行，CreateDate/ReviseDate 顯示至秒。選取 Header 列會依 QCListSerial 載入下方 Detail。

右側僅有 `Edit`。沒有選取資料或選到分組列時不動作；QCResult 為 Null 或不等於 -1 時顯示已完成提示並拒絕編輯。只有整張點檢單尚未完成（QCResult=-1）才會呼叫 `WP_EQPCheckQCList`，傳入 EquipmentNo、QCListNo、QCListSerial。編輯頁成功後重新查詢並重新選取原 Serial。Vue DEV 在本頁內嵌 WP305 編輯頁，完成後回讀共用假資料。

### Detail Grid

下方明細依 QCOrder 遞增排序，顯示：

`QCItem, QCOrder, InputDataCount, Type(QCType), InputValue, D01…Dnn, StdValue, MiniValue, MaxiValue, QCResult`

D 欄只顯示最大 InputDataCount 所需的欄位；Core 查詢同樣會依最大 InputDataCount 移除其後 D 欄。QCType 對照 0=`標準值`、1=`範圍`、2=`顯示訊息`、3=`輸入資料`；Detail QCResult 對照 -1=`N/A`、0=`OK`、1=`NG`。兩個 Grid 均隱藏 Group By Box、使用固定標題，明細量測數值靠右顯示。

沒有 Header 時清空 Detail，避免留下上次選取的明細。Close 關閉功能。

## Service/Core 查詢邏輯

### Header

`wsWIP.LoadWIPEQPQCListLogBasis` 解析 QCListSerial、EquipmentNo、QCListNo、LotSerial、LogGroupSerial、StartDate、EndDate，再呼叫 Core。此畫面只送 EquipmentNo 與日期。Core 以 `QCListSerial IS NOT NULL` 為基礎，為非空條件逐項加 `=`；StartDate 用 `CreateDate >=`、EndDate 用 `CreateDate <=`，含時間界值。資料回傳 DataSet/XML；前端 DataView 依 QCListSerial 排序。

來源 Core 使用字串串接 SQL。本功能的新 API 必須改用參數化查詢，不得照抄此實作方式。

### Detail

Service 只讀取 QCListSerial，呼叫 Core `LoadWIPEQPQCListLogDetail`。Core 以 `QCListSerial IS NOT NULL` 為基礎，若傳入 Serial 則加入精確等值條件；點選單頭時只讀該張點檢單。前端新增 `Type` 顯示欄位，其值等於 QCType；依 QCOrder 排序。沒有傳入 Serial 時來源 Core 可回傳全部 Detail，但 WinForms 的空 Header 流程清空明細；Vue DEV 同樣不在無選取 Header 時查明細。

## Oracle 結構與 CREATE SQL

WP306 沒有新 Oracle 表，也不需要重新 query Oracle metadata。來源 DDL/metadata 由 WP305 使用 PowerShell 5.1、Oracle.ManagedDataAccess 及本機受保護 profile 直連 MESTEST 唯讀取得：

- Header：`TBLWIPEQPQCLISTLOG`，PK QCListSerial。
- Detail：`TBLWIPEQPQCLISTDETAIL`，PK QCListSerial + QCItem。
- PostgreSQL 空表 Create-only 沿用 `database/reference/mestest_wip_wp305_create.sql`；此頁沒有自己的 CREATE-only 或 migration。
- Equipment lookup 使用既有 `TBLEQPEQUIPMENTBASIS` reference。

公司端未讀 Oracle 業務資料列、未執行 Oracle DDL/DML，亦未連 YMES PostgreSQL。

## Vue DEV 行為與範圍

- 依 WinForms 保留查詢框、Equipment Lookup、日期勾選、Query、上方 Header Grid、下方 Detail Grid、Edit、Close。
- 點檢記錄優先讀取 WP305 共用 localStorage `ymes.dev.wp305-equipment-online-qc.v1`；目前沒有已存點檢資料時顯示兩筆標記為 DEV 的 OK/NG 範例，方便檢視畫面。範例不寫入共用 storage。
- 只允許已存在共用 storage 且 Header QCResult=-1 的紀錄按 Edit；範例和已完成資料不可編輯。編輯表單沿用 WP305 元件，完成後即時回讀資料。
- 首次載入會顯示 DEV 查詢結果，這讓 Vue 頁進入後能直接查看 Grid；來源 WinForms 也在 Load 時呼叫無條件 Header 查詢。空結果選取會清空 Detail。
- 只提供假資料操作；不呼叫 API、不查 Oracle，也不把 localStorage 當正式資料來源。

## 家用端 API handoff

- 先 Pull 最新 main，閱讀本規格、WP305 點檢 Log 規格和 `docs/DATABASE_CONNECTION.md`。不新增 WP306 table/migration；先核對 WP305 `ymes.tblwipeqpqclistlog`、`tblwipeqpqclistdetail` 的 live schema。
- 提供登入保護、角色/廠區授權的唯讀分頁查詢，例如 `GET /api/wip/equipment-qc-list-logs`，支援 EquipmentNo、StartDate、EndDate；使用參數化條件、穩定排序（CreateDate + QCListSerial）、最大 page size。WinForms 的不帶條件全查須轉成安全分頁；前端逐頁載入或加上可清楚說明的預設範圍。
- 日期 API 應各自獨立：StartDate 視為 CreateDate 下界、EndDate 視為上界；時間界值含端點並使用固定時區/日期序列化。這是相對來源 Checkbox guard typo 的明確修正。
- 提供 `GET /api/wip/equipment-qc-list-logs/{qcListSerial}/details`，驗證使用者能讀取該 Header 後，以 Serial 查 Detail，依 QCOrder 排序；僅回傳 max InputDataCount 需要的 D01-D10 也可由 DTO 動態欄位處理。
- 編輯不由 WP306 建第二份寫入流程；只有 `QCResult=-1` 的點檢單能開 WP305 Edit。正式頁呼叫 WP305 `PUT` 更新 API，伺服器再次核對狀態與授權，在交易中更新 Header、替換 Detail、重新計算結果，處理 task 與 WP201/WP204 NG side effects 時遵守 WP305 規格。拒絕完成單修改，處理兩個操作者同時修改的競態。
- Grid 保留空結果、錯誤、載入狀態、選取單頭後取明細；不得用 URL query 暴露 Serial 作為授權依據，也不可假設前端隱藏 Edit 即足夠保護。
- WP306 不新增 Oracle DDL/PostgreSQL CREATE-only；任何 schema 調整以 WP305 source reference 和 YMES live schema/migration 核對結果為準。
