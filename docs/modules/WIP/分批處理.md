# WP207 分批處理（LOT SPLIT）

## 功能識別與來源

- 第一層：在製品管理（WIP）；第二層：生產報工（LOTEXECUTE）；第三層：分批處理。
- FunctionNo：`LOT SPLIT`；FunctionKey：`WP207`；來源 DLL：`BR_L_Split_GEN_THEIL_BU1.dll`。
- Form：`Customer/Production/MESWin/BR/BR_L_Split_GEN_THEIL_BU1/frmBR_L_Split_GEN_THEIL_BU1.vb`，Form 類名 `frmBR_L_Split_GEN`，標題 `Lot Split`。此 Form 同時可被 BR／WIP Inventory 宿主呼叫；選單直接啟動時 `SplitMergeType` 預設為 0（手動分批）。
- Service：`STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `Exe_Manual_LotSplit`、`CheckLotIsOSbutNotReturn`，`STD/MESws_STD/wsSTD/wsSYS/wsSYS.cs` 的 `GetSplitLotNo_Multiple`，以及 `Customer/Production/wsTHEIL/wsWIP/wsWIP.cs` 的 `UPD_SplitLot`。
- Core：`STD/MESkc/kcWIP/clsLot.cs` 的 `BR_Manual_LotSplit`，`Customer/Production/MEStc_THEIL/tcWIP/clsLot.cs` 的 `UPD_SplitLot`。
- Vue DEV 路徑：`/YMES/WIP/LotSplit`，元件 `web/src/components/WipLotSplit.vue`。

## WinForms 畫面與互動

Form ClientSize 約 1008×661，上方 `Reference Lot` 群組包含 `Lot No`、初始隱藏的 `Query` 及批次 Grid；下方 `Split` 群組包含 `Split by Count`／`Split by Qty`、`Split Count / Qty`、`Include Mother Lot No` Yes／No、`Split`、`Change Routing`、`Electricbox`、分批 Grid；右下為 `Confirm(&C)`、`Close (&X)`。兩個頂部 Change Product 按鈕在 Designer 中隱藏，真正可變更產品的入口是 Grid 的 ProductNo cell（取決於 `AllowLotProductChange` 系統參數）。`Electricbox` 只有啟用 `IC_FT_PKG` 模組時顯示。由 WIP Inventory 呼叫時 `Change Routing` 隱藏。

`Reference Lot` Grid 顯示 LotNo、CurQty／CurUnitNo、SysQty／SysUnitNo、ProcessNo、OPNo／OPName、BaseLotNo、OrgLotNo、ProductNo／Version、SAP_PRDQTY、SAP_PCSQTY、SAP_ARGQTY 等欄；DEV 頁保留操作判斷所需核心欄位，部分附加資訊未在假資料呈現。`Split` Grid 的可見欄位是 SplitLotNo、SplitLotQty、SplitSysQty、Action、ProcessNo／Version、OPNo、ProductNo／Version、UnitNo、SAP_PRDQTY、SAP_PCSQTY。`ReturnType` 仍在 Form 內部暫存表中，預設 0，但畫面未提供操作欄位。

直接啟動且沒有傳入 LotNo 時，舊 Form 不自動查全表、Confirm 為 disabled；`Query` 在 Designer 初始隱藏，主要由宿主提供 LotNo。DEV 網頁為了能獨立檢視此功能，提供 `Query` 作本地假 Lot 載入入口；此為明確的導覽差異。

## 載入、草稿與確認規則

1. 來源查批使用 `LoadLotBasisJoinState`，條件包含 Status `0|1|4|5`、`HaveComponent=0`、`NotContainGoodBinState=True`、`LotState=1`、`ShowPartialLot=False`、`StockerLot=False`。鍵入 Lot 時另外檢查 `CheckLotPackage`；已包裝 Lot 不可繼續。若已有 GoodBinState，Form 提示改用 `BR_LB_SPLIT_FT` 等級分批。正式 API 應只查指定 Lot、對所屬範圍與狀態重驗，不延續任意全表查詢。
2. `Split` 要求指定 Lot、選分批模式、Split Count／Qty 為正數。`funSplitByCount` 以整數均分，最後一批吸收餘量；`funSplitByQty` 先建立滿額列，餘量另列。Yes 會以母批號作第一列，No 在 Designer 中不可選。預覽子批號由 `GetSplitLotNo_Multiple(ReserveSerialNo=False)` 產生；按 Confirm 前再次比較最新序號，再以 `ReserveSerialNo=True` 正式保留。
3. 新建列的 `SplitLotQty`、`SAP_PRDQTY`、`SAP_PCSQTY` 初始留白，`SplitSysQty` 由單位換算填入。若 CurUnitNo 與 SysUnitNo 相同，Sys Qty 在舊 Grid 為唯讀；否則可調。編輯 SplitLotQty 會重算該列 Sys Qty。僅有兩列時，編輯 SplitLotQty、SplitSysQty、SAP_PRDQTY 會自動給另一列補數；`SAP_PCSQTY` 自動補數原始碼已註解，不連動。
4. `Change Routing` 傳 PSNo／ProcessNo／ProcessVersion 與當前 Action 到 `WP_LotSplitProcessDraw`，回寫 Action 1 Jump OP 或 2 Jump Process、ProcessNo／Version、OPNo、NodeID。Action 0 是 Go。產品選取依 `AllowLotProductChange` 參數從 MES 或 ERP 可用產品決定，變更 ProductNo／Version／UnitNo。DEV 只使用固定產品與兩條固定路由。
5. 每列 Lot Qty、Sys Qty、SAP_PRDQTY、SAP_PCSQTY 都須大於 0；Action 1/2 必須有 NodeID，ReturnType 不可大於 2，Go／Jump OP 要 ReturnType=0。母批列在來源程式中**沒有**被限制為 Go。合計 `SplitLotQty = 母批 CurQty`、`SplitSysQty = 母批 SysQty`、`SAP_PRDQTY = 母批 SAP_PRDQTY`、`SAP_PCSQTY >= 母批 SAP_PCSQTY`。Status=5 時另呼叫 `CheckLotIsOSbutNotReturn` 守門；不能用前端旗標取代。Form 再呼叫 `ChkLotStamp` 防舊資料。
6. 標準 Service `Exe_Manual_LotSplit` 把 SplitType、LotStamp、各列拆批／路由／產品資訊傳給 `BR_Manual_LotSplit`。Core 對 Lot Basis／State／Property、Process/OP、庫存、在製報工與 log 等多張表及 helper 做交易，不能以單表 CRUD 取代。`SplitMergeType=1` 的 BR 宿主在成功後，對未改產品／流程且 Action=Go 的列另行 `BRTransferLot`；不屬於選單直接啟動的預設手動模式。
7. 標準拆批成功後，Form **另外**呼叫 `THEIL.wsWIP.UPD_SplitLot`。客製 Core 更新 `TBLWIPLOTBASIS.SAP_PRDQTY/SAP_PCSQTY`、upsert `TBLWIPLOTPROPERTY` 的 `WIP_BIGQTY`，並按原始母批複製 `XX_TBLLOTMARITX_THEIL_BU1` 的 300 碼。這是標準拆批提交後的第二個呼叫；若客製呼叫失敗，Lot 可能已拆成功，Form 也不應重複執行 Confirm。家用端需設計同一交易或明確的可恢復／冪等補償流程，並回傳能區分標準成功與客製失敗的狀態。

## Oracle 結構與 CREATE-only

公司端使用 Windows PowerShell 5.1、本機受保護 MESTEST profile 與 `Oracle.ManagedDataAccess.dll`，只讀 `DBMS_METADATA.GET_DDL`、`ALL_TAB_COLUMNS`、`ALL_CONSTRAINTS`、`ALL_INDEXES`、`ALL_TRIGGERS`。本次補齊六張原本 YMES reference 未有的直接依賴表：

| 表 | Oracle PK | 額外 index／限制 |
| --- | --- | --- |
| `TBLEMSDISPATCHSTATE` | `(EQUIPMENTNO, DISPATCHORDER)` | 無額外 index |
| `TBLWIPAUTOMERGE` | `(FROMLOTNO)` | 無額外 index |
| `TBLWIPCONT_EMPLOYEE` | 無 | 三個非唯一 index：LogGroupSerial、LotSerial、LotNo+FunctionName+EventTime |
| `TBLWIPLOTOPECNRECORD` | `(LOTNO, OPNO)` | 無額外 index |
| `TBLWIPOSBASIS` | `(OSNO)` | 無額外 index |
| `TBLWIPOSDETAIL` | `(OSNO, LOTNO)` | 無額外 index |

六表均無來源 FK／trigger。原始 DDL、index DDL、欄位／約束 metadata、PostgreSQL 空表 CREATE-only 分別見 `database/reference/mestest_wip_wp207_source_ddl.sql`、`mestest_wip_wp207_source_indexes.sql`、`mestest_wip_wp207_metadata.txt`、`mestest_wip_wp207_create.sql`。`TBLWIPCONT_EMPLOYEE` 沒有 PK 或 unique index，不能為方便自行補造來源唯一鍵。

`BR_Manual_LotSplit` 的其餘直接引用表包括 `TBLINVWIPINVENTORY_SEMI`、`TBLPRDOPATTRIB`、`TBLPRDPRODUCTBASIS`、`TBLPRSNODEBASIS`、`TBLSYSFUNCTION`、`TBLSYSLOTPROPERTYBASIS`、`TBLWIPCONT_ATTRIB`、`TBLWIPLOTBASIS`、`TBLWIPLOTLOG`、`TBLWIPLOTLOG_REPORT`、`TBLWIPLOTPROPERTY`、`TBLWIPLOTSTATE`、`TBLWIPTEMP_ATTRIB`、`TBLWIPTEMP_LOTSTATE`；沿用 WP101／WP201 及主檔既有 references，不重複建立。Core 呼叫的 helper 可能觸及其他共用表，正式 API 設計時還須逐層追查。

## 公司端 Vue DEV 範圍

`WipLotSplit.vue` 用固定 Lot／產品／路由假資料提供查批、Count／Qty 草稿、母批保留、Grid 編輯、兩列補數、路由／產品 picker、Electricbox 示意、確認前驗證；結果只寫此瀏覽器 `ymes-dev-mock:wip-lot-split:records:v1` 與預覽序號 `ymes-dev-mock:wip-lot-split:sequence:v1`。假資料視為 `IC_FT_PKG` 已啟用，故顯示 Electricbox；正式可見性要由後端授權模組決定。DEV 額外限制最多 100 列、Split Qty 不可超過 CurQty，以免網頁產生過量列。DEV 使用固定單位倍率，未模擬正式 `LoadUnitTransferQty` 規則、完整流程圖／ERP 聯產品、真實子批序號鎖定、庫存／Lot 交易和 THEIL 300 碼更新。`localStorage` 不是權威資料，也無跨分頁原子性。
