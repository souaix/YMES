# 生產批作業員登入／登出（OPERATOR LOGIN_LOT）

## 功能身分與來源

| 項目 | 來源 |
|---|---|
| WinForms | `STD/MESWin/WIP/WP_OperatorLogin_Lot/frmOperatorLogin_Lot.vb`、Designer 同目錄 |
| Service | `wsWIP.LoadLotBasisJoinState`、`wsWIP.LoadOperatorStateJoinLotLoginState`、`wsUSR.LoadUserSecurity`、`wsWIP.ChkUserOP`、`wsWIP_OperatorState.ExecuteClockIn/ExecuteClockOut/AddWipOperatorState/DeleteWipOperatorState` |
| Core | `STD/MESkc/kcWIP/clsOperatorState` 與 `clsWIP`；`LoadOperatorStateJoinLotLoginState`、標準 Operator Clock In/Out、`funSHR_CI_EMP_ClockIn`／`funSHR_CO_EMP_ClockOut` |

Form 有 `CallType` 0/1/2/3，分別代表 menu、BR clock-in、BR clock-out、batch clock-in；CallType=0 明確支援從 MenuItem 開啟。`PrivFunNo` 由外部注入，正式 FunctionKey 未包含在 Form source；DEV fallback `OPERATOR LOGIN_LOT` 由 Form 標題推導，需實際 menu metadata 核實。

## 畫面與選單模式

- 784×561 WinForms Form，title `OPERATOR LOGIN_LOT`。Lot Sign In Operation／MO Sign In Operation 與 MONo controls 在 Form_Load 隱藏，目前只支援 Lot。
- 上方 LotNo 可輸入，按 Enter 載入 Lot、OPNo、OPName；OP 欄位唯讀。只允許 Lot status Queue(0)/Running(1)，且 OP Basis `MultiOperatorMode=5`（Lot）；不符合時停用登入／登出 group。
- 中段左右兩個 Group：User Check In Operation 與 User Check Out Operation。各有 Employee No、Employee Name、可勾選覆寫的 Check In/Out Time、Sign In／Sign Out；底部 Grid 顯示 UserNo、UserName、CheckIn/Out Time、CI/CO Creator/Date、TempFlag；頁尾 Creator、Create Date、Close。
- Form_Load 的 CallType=0 將建立者設為目前 MES 使用者、`DataSource=1`，日期選擇器未勾選；查詢 Lot 後自動載入 Lot 登入歷程，依 `CheckOutTime, CheckInTime, UserNo` 排序，選取第一列並帶出登出員工。
- DEV 只呈現 CallType=0；固定假 Lot／員工，歷程 localStorage 與 WP104/WP105 假 OperatorState/Log 共用。Check In 使用假 AP Server 時間；可勾選的 Check In Time 在 WinForms 傳入的是 WorkDate，而非取代 LoginDate。

## 簽入／簽出及呼叫端差異

1. 載入 Lot 使用 `LoadLotBasisJoinState(Status="0|1")`，帶出 BaseLotNo、OP、WIPDate、PreOPEndTime、Lot Status。OP 必須為 mode 5。Grid 由 `LoadOperatorStateJoinLotLoginState(LotNo)` 組合目前 OperatorState 與 LotLoginState 歷程，並加入前端 `TempFlag`。
2. User No 按 Enter 以 `LoadUserSecurity` 讀姓名及有效員工資訊；來源不在此畫面輸入密碼。Sign In 要求員工編號／姓名與 Lot 已載入。CallType=1/3 另經 `wsWIP.ChkUserOP` 檢查員工對 OP 權限；CallType=0/2 不走該 Form 分支。
3. Sign In 檢查所選/目前時間不得早於 `PreOPEndTime`（空值時用 WIPDate）、不得晚於目前時間；同員工的 Lot Login 區間不得重疊，已有未下工紀錄時要求先下工。CallType=0/2 直接呼叫 `ExecuteClockIn`；CallType=1/3 先維護暫存清單與 OperatorState，再執行 Lot clock-in。Mode=5、LoginPlaceNo=LotNo。標準 Core 寫 OperatorState，並由多人加工副作用同步 LotLoginState。
4. Clock-in 的可選 Check In Time 只用來傳 WorkDate；真正 LoginDate 取 Form 的 AP Server CreateDate。來源允許預登 Queue/Running Lot（狀態查詢固定 `0|1`）。
5. Sign Out 要有 EmployeeNo、姓名及選取非暫存 Grid row。若員工沒有有效 CI 時間：Queue Lot 或系統 `MultiOperator` 關閉時，呼叫 `DeleteWipOperatorState` 清除 mode 5 現況；其他情況要求先 CI。已登入紀錄檢查 Check Out 必須晚於 CI、不晚於現在、不與同員工歷程重疊且不跨入下一筆登入區間。勾選時間傳為 LogoutDate，未勾選時用 AP Server CreateDate；接著 `ExecuteClockOut` 寫 OperatorLog、刪 OperatorState，並更新 LotLoginState。
6. CallType=1/2 由 BR 以 Lot Info、時間、UserID 固定 Lot/OP；CallType=1 會累積暫存員工後建立 OperatorState/LotLoginState，CallType=2 執行指定 Lot 的簽出；CallType=3 用 BatchLot 與暫存人員列，不允許從暫存列簽出。未來 BR API 必須沿用同一 command/service contract，不把此共享對話框複製成每個宿主的獨立實作。

## 資料表與家用端 API handoff

- 沒有本功能專用的新表。重用 Oracle `TBLWIPOPERATORSTATE`／`TBLWIPOPERATORLOG`（WP104 source DDL/metadata/CREATE-only）及 `TBLWIPLOTLOGINSTATE`（WP305 references）；LotState、OP Basis、User Security 等也重用已核對共用 schema。沒有新增 Oracle DDL/Create-only。
- 建議 `GET /api/wip/lot-operator-logins/lots/{lotNo}` 限登入者可見範圍，server 查狀態 0/1、BaseLot、OP mode 5、前站時間及登入歷程。`POST .../clock-ins`、`POST .../clock-outs` 只接 UserNo/LotNo 或歷程 key 與允許覆寫的日期；server 重查使用者、OP privilege、Lot state、Mode=5、時間區間及目前狀態，不接受 client 提交 Creator、LoginPlace、Mode、LoginDate、LogoutDate、audit user。
- Sign In/Out 必須在交易內更新 OperatorState、OperatorLog、LotLoginState，呼叫等價多人加工 side effects；Queue 或 MultiOperator disabled 的特殊清除也需保留。對未登入／已被其他操作簽出、重複提交及區間衝突回傳明確錯誤。
- CallType 1/2/3 為 BR 共享用途，handoff API 應支援宿主傳入的已授權 Lot context、批次暫存模式及 OP privilege；不得信任前端可任意指定呼叫類型。
- 公司端只做固定假資料及直接選單模式；未連 YMES PostgreSQL、未執行 Oracle DDL/DML、build/test/browser。
