## 來源與規則

- `LOT OP AREA CHANGE` 對應 `STD/MESWin/WIP/WP_LotOPAreaChange/frmLotOPAreaChange.vb` 和內嵌 Designer。選批 `wsWIP.LoadLotState` 使用 Status=0／4；`LoadLotProcess` 提供批的流程樹，按流程編號、版本載入 `wsPRS.LoadProcess` 圖資、`wsOP.LoadOPAreaByProcess`（DefaultArea=1）、`LoadOPBasis` 及 `wsWIP.LoadLotOPArea`。
- 雙擊作業節點顯示流程／版本、作業站、預設區、變更區；雙擊子流程節點切到對應子流程。已刪除的節點不能變更。取區呼叫 `wsOP.LoadOPArea`，確認區號非空且不同於預設。變更暫以 LotNo／NodeId 識別，移除變更會清暫存 override。
- 儲存前原 Form 使用 `COM_ChkPassword.frmCOMChkPassword` 的 CheckIdentityOnly 確認操作人。送整批 overrides（nodeId、opNo、areaNo）至 STD `wsWIP.Exe_LotOPAreaChange`，記 EventLog。空集合代表清除該批所有 overrides。
- `STD/MESkc/kcWIP/clsLot.cs::UpdLotOPArea` 先查 LotState。只要批仍排隊且送入目前 NodeId 的不同 AreaNo，讀 AreaBasis.FactoryNo 並以 Status=0 與 LotStamp CAS 更新當前 AreaNo、FactoryNo、LotStamp。同一交易刪除並重建整批 `TBLWIPLOTOPAREA`。清除目前節點 override 時，舊 Core 沒有把現況 AreaNo 改回預設。
