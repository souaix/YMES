# WP804 8D 矯正單查詢（8D QUERY）

## 來源與畫面

- 選單：WIP → 8D 管理 → 8D 矯正單查詢；FunctionNo `8D QUERY`，FunctionKey `WP804`，`WP_8DQuery.dll`。
- 主 Form `STD/MESWin/WIP/WP_8DQuery/frmWP8DQuery.vb`；Service `STD/MESws_STD/wsSTD/wsWIP/wsWIP.cs` 的 `Load8DBasisFactory`；Core `STD/MESkc/kcWIP/clsWIP.cs` 的同名方法。`8DQuery` 子窗是 `WP_8DMaintainDef`，傳 `QRSDataRow`、`QRSClose=1`，即 [WP802 十頁唯讀明細](8D矯正單維護作業.md)。
- Query 上方顯示 QRSType 選項預設 0，**來源未把 QRSType 傳給 Service**，不能作正式篩選條件。可勾 QRSClass（In Line QC=1、Off Line QC=2、WIPERF=3、Other=4）、QRSNo、QRSSummary、FactoryNo、ProjectDepartment、ProjectManager、Create Date、PlanCloseDate、CloseDate，以及 CloseState 的 Closed／NotClose。QRSNo、QRSSummary 為包含查詢；FactoryNo、ProjectDepartment、ProjectManager 精確查詢。三組日期皆為 Basis 的欄位，尾日若僅日期按來源含 23:59:59。CloseState=0 表已結案（CloseDate 非空）、1 表未結案（CloseDate 為空），兩個選項都勾時不篩。勾 NotClose 會取消 CloseDate 日期條件；勾 CloseDate 會取消 NotClose。來源文字框有值時自動勾選對應條件，取消勾選會清欄。
- 沒有條件時 Form 顯示 `PLEASESELECTONECONDITION` 並停止查詢；Service 呼叫時 IssueState 傳 `defInteger`，因此**跨所有簽核狀態**查詢，不像 WP802 只查 Active/未結案。外部 ERF/SPC 查詢可先傳 `ERFNo8D`，Form Load 立即依 ERFNo 查。結果 Grid QRSNo 升序、固定首欄、不允許行內編輯，共 **39 欄**：QRSNo、QRSClass、QRSSummary、LotNo、LotQty、SampleQty、ErrorQty、FactoryNo、AreaNo、MONo、CustomerNo、ProductNo、ProductVersion、RONo、OPNo、EquipmentNo、ERFNo、HoldDescription、Description、ProjectDepartment、ProjectManager、ProjectManagerName、CurStage、PlanCloseDate、LastUpdateDate、SummaryDescription、DispHour、DispCost、SummaryDepartment、SummaryUserNo、SummaryUserName、CloseType、CloseDepartment、CloseUserNo、CloseUserName、CloseDate、IssueState、Creator、CreateDate。右側僅 `8DQuery`、`Close (&X)`。

`8DQuery` 沒有排除 IssueState=-1；Web 共用 WP802 明細時讓 WP804 的唯讀入口能檢視作廢單。WP508 `8D` 入口仍沿原規則拒絕 -1 的維護直達。

## 原始程式差異與正式查詢

`funLoad8DBasis` 的 QRSClass 拼接只有勾 In Line QC/Off Line QC 時才把 `chkClass` 設 True；**單獨勾 WIPERF 或 Other 會漏送類別條件**。Web DEV 採畫面意圖，四類任一勾選均有效，API 也應如此。若只勾 CloseState 但 Closed/NotClose 全勾，來源仍可能把 `defInteger` 當查詢條件而載入全表；Web 要求至少一個**有效**條件。Core 用字串拼接 SQL，正式 API 應用參數化查詢與分頁/上限，不能讓空字串或全部狀態造成無界大量資料。

建議 `GET /api/wip/8d-query` 接受 QRSClass 集合、五個文字條件、三組日期、`closeState=closed|open|all`、可選 ERFNo、page/pageSize/sort；server 查 `TBLWIP8DBASIS_FACTORY` 並執行登入/`WP804` 功能及資料範圍 ACL。`GET /api/wip/8d-query/{qrsNo}` 由 server 重新查主單與 WP802 十頁明細，按讀取權限回傳；不能信任 browser 傳整筆 Basis 或唯讀標記。唯讀路由不可授予 WP802 寫入 API。資料表 source DDL/index/metadata、PG CREATE-only 已在 `database/reference/mestest_wip_wp508_*`，本頁未引入新直接表；ERF/產品等欄位直接存於 8D Basis，無需新增 lookup DDL。
