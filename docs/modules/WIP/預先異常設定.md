## WinForms 畫面與查詢

標題 `Future Hold Set`。由上至下為 Query、Lot State、Hold Data；底部 Confirm/Close。Query 六欄 Area No、PS No、OP No、Customer No、Product No、LotNo，前五欄 `...` 查找。至少填一項才取 Lot；Service 查 `Status=0|1|4`、`ShowPartialLot=False`。Lot Grid 八欄：Check、LotNo、OPNo、OPName、CurQty、Status、Product No、Customer No；Status 顯示 Queue/Running/Complete。`Selected Lot` 是只顯示已勾列的檢視過濾，**不是全選**。LotNo 掃描 Enter 會勾選查詢結果中的該批；找不到不新增。

Hold Data 左區：Hold Time Start=`0`、End=`1`；PS No `...` 選擇後由該 PS 的 OP 清單勾多個 OP。右區：MClass No、SClass No、Hold Description 查找及可勾的 Hold Item 三欄 Grid（Check、HoldItemNo、HoldItemName）；HoldItemNo 掃描可勾目前清單項。MClass 變更清除次分類、說明與 Hold Item；SClass 變更重載 Hold Item。畫面欄位原服務實際傳 MClass、說明、Lot、OP、HoldReason、HoldTime；**SClass No 只作選項/必填守門，沒有直接送入 `Exe_FutureHold_Set`**。

Confirm 要求至少一批 Lot、一種 Hold Time、PS No、至少一個 OP、MClass、SClass、非空說明、至少一個 Hold Item。Form 對 `MClassNo` 查已簽核 `TBLQCFIRSTGROUP`：若沒有通用 `OPNo='*'`，對所選而無對應 First Group 的 OP 顯示可取消的確認，並非硬拒。原 Form 把多個 LotNo 逗號串成一字串呼叫 `CheckLotPackage`；Service 實際建立只有**一個元素**的 LotNoList，可能漏檢包裝。正式 API 和 DEV 都對每一筆所選 Lot 查包裝，不沿用逗號單值。成功後 Form 清除選批、HoldTime 回 Start、取消 OP/分類/說明/原因；保留 Hold PS No 供下一次操作。

## Set 交易及後續生效

`Exe_FutureHold_Set` 把 Lot、OP、HoldItem 解析成三個資料表，呼叫 `UpdFutureHold_Set`。此選單按 OP 設定，ModuleNo/ModuleVersion 預設 `N/A`。Core 對**每個 Lot × 每個 OP** 依 `(LotNo,OPNo,HoldTime,ModuleNo,ModuleVersion)` 刪既有 `TBLWIPFUTUREHOLD`，插入新主設定；再用相同條件刪既有 `TBLWIPFUTUREHOLDREASON`，為每個 HoldItem 插入原因。四類 SQL 先組成一組，再交 `ExecuteSQLNoneQuery_UPD` 執行；Service 成功後逐 Lot 寫事件 Log。來源刪除條件**沒有 `FutureHoldSerial`**，因此會覆蓋該鍵下不同 Serial 的舊記錄；新行使用 Oracle `FutureHoldSerial='N/A'` default。正式 API 須明確保留這個覆蓋範圍，或先由業務確認新契約，避免意外清掉客製 Serial。

Set 當下只排程 Future Hold，**不立刻把 Lot 改成 Status=3 或開 ERF**。後續報工時 `ChkFutureHold` 讀現行 LotState 的 OP/Module，匹配 `TBLWIPFUTUREHOLD` 的 Lot、OP、HoldTime 及 `ModuleNo IN ('N/A', current ModuleNo)`；成立後才進 ERF 流程。共用 `UpdERF_Create_Batch` 的 `ERFType=3` 分支會清原因/主設定，並從 FutureHold 寫 FutureHoldLog；標準版註解與客製 UD 行為可能不同，正式端需追實際部署 adapter。`TBLWIPFUTUREHOLDLOG.HOLDDESCRIPTION` 在 Oracle 為 NOT NULL，而 Core 插入只在來源非 DBNull 才加此欄，需於正式端檢查資料與失敗路徑。

## Oracle 表與 PostgreSQL CREATE-only

主設定 `TBLWIPFUTUREHOLD` 的 Oracle DDL 已在 `database/reference/mestest_wip_wp201_dependency_source_ddl.sql`，PG CREATE-only 已在 `mestest_wip_wp201_create.sql`；不可重建。公司端用受保護 Oracle MESTEST profile、PowerShell 5.1/ODP.NET **唯讀**查到兩張原缺表：

| 表 | 用途與結構 |
| --- | --- |
| `TBLWIPFUTUREHOLDREASON` | Set 直接寫；八欄、PK `(HOLDITEMNO,HOLDTIME,LOTNO,MODULENO,MODULEVERSION,OPNO,FUTUREHOLDSERIAL)`；ModuleNo/Version/Serial 預設 `N/A`；無額外索引或 trigger。 |
| `TBLWIPFUTUREHOLDLOG` | 後續 `ERFType=3` 生效流程使用；十欄，**無 PK/unique index**，只有 LotNo 非唯一索引；無 trigger。 |

原 Oracle DDL、index、資料字典在 `database/reference/mestest_wip_wp504_source_ddl.sql`、`mestest_wip_wp504_source_indexes.sql`、`mestest_wip_wp504_metadata.txt`；PostgreSQL **CREATE-only** 參考是 `mestest_wip_wp504_create.sql`。`TBLWIPLOTSTATE` 已有 WP101 refs；QC MClass/SClass/HoldItem/FirstGroup 與 PS/OP/Area/Customer/Product lookup 表沿用既有 refs。公司端未查 Oracle 業務列、未執行 Oracle DDL/DML、未連 YMES PostgreSQL，未輸出或提交密碼。
