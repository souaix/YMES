# WP607 列印盤點清冊

## 復刻範圍

公司端對照本機標準來源 `D:\iMES\CSiMES\STD\MESWin\WIP\WP_InvCountStatePrint\frmInvCountStatePrint.vb`。Designer 初始化程式內嵌於 Form，沒有獨立 `.Designer.vb`。Form 呼叫 `wsWIP.LoadInvCountStateWithDetail`，由 `clsINVCount.LoadInvCountStateWithDetail`、`LoadInvCountStateWithDetail_MTL` 或 `LoadInvCountStateWithDetail_PRD` 讀取盤點資料；此模組不寫入 MES 資料，只選取報表、排序資料並開啟 ActiveReport。

Function `INV COUNT PRINT`／WP607 未掛入正式 `MenuItem`。Vue DEV fallback 路由：`/YMES/WIP/InvCountStatePrint`。頁面只用假資料預覽，不連 Service、資料庫、ActiveReports runtime 或印表機。

## Form 操作與查詢

- 初始選取 `WIP`、`BarCode=True`；`Print` 初始停用。六種選項為 WIP、SEMIWIP、FGD、SEMI、RAW、MTLWIP。
- 按 Query 組合 `State=0` 和 `DataType`，不傳 CountSerial，因此會載入該類型所有已關帳盤點明細。WIP／SEMIWIP 呼叫一般 detail 查詢；RAW／MTLWIP 呼叫 `_MTL`；FGD／SEMI 呼叫 `_PRD`。Core 將 `TBLWIPINVCOUNTSTATE` 與相應 detail 依 CountSerial 連接，資料再由 Form 讀入 DataSet。
- 查詢前移除舊 DataTable 並停用 Print。成功後按類型排序並顯示資料；至少有一筆才啟用 Print。查詢空資料時保留空 Grid 並停用 Print。

## Grid 欄位及排序

| DataType | 顯示欄位（依來源順序） | 顯示排序 |
| --- | --- | --- |
| WIP | CountSerial、CountDate、LotNo、OPNo、CurQty、CurUnitNo、MONo、ProductNo、ProductVersion、InventoryNo | OPNo、ProductNo |
| SEMIWIP | CountSerial、CountDate、LotNo、CurQty、CurUnitNo、MONo、ProductNo、ProductVersion、InventoryNo | OPNo、ProductNo |
| RAW／MTLWIP | CountSerial、CountDate、MaterialNo、MaterialLotNo、CurQty、CurUnitNo、InventoryNo、LocatorNo | InventoryNo、MaterialNo |
| FGD／SEMI | CountSerial、CountDate、LotNo、CurQty、CurUnitNo、ProductNo、InventoryNo、LocatorNo | InventoryNo、ProductNo |

CurQty 以 `0.#` 格式右靠齊，CountDate 格式為 `yyyy/MM/dd HH:mm:ss`。DEV Grid 依以上欄位顯示，支援水平捲動。

## Print 版型

Print 將已載入 DataTable 綁定 ActiveReport 的 DefaultView：

| 類型 | BarCode 勾選 | 未勾選 | 排序／其他 |
| --- | --- | --- | --- |
| WIP／SEMIWIP | `arInvCount_General` | `arInvCount_General_NoBarCode` | OPNo、ProductNo；設定 `PrintGroupName` 為 WIP 或 SEMIWIP |
| RAW／MTLWIP | `arInvCount_MTL` | `arInvCount_MTL_NoBarcode` | InventoryNo、MaterialNo |
| FGD／SEMI | `arInvCount_PRD` | `arInvCount_PRD_NoBarcode` | InventoryNo、ProductNo |

條碼核取方塊預設勾選。傳入 WIP／SEMIWIP 報表時還帶 `PrintGroupName`；其他兩類不設定。DEV 只呈現選中的報表類別、條碼選項、盤點日期及排序後資料表，點「模擬列印」僅留下畫面提示，不產生 PDF／條碼影像，也不呼叫系統印表機。

## 靜態檢閱及交接

- 此 Form 和 WP608 調帳頁共用同一組盤點 state/detail query；沒有新的資料表或 DDL。四張盤點 state/detail 表 `TBLWIPINVCOUNTSTATE`、`TBLWIPINVCOUNTDETAIL`、`TBLWIPINVCOUNTDETAIL_MTL`、`TBLWIPINVCOUNTDETAIL_PRD` 的 Oracle DDL／metadata 在 repo references 中缺失，桌機無受保護 Oracle profile。家用端於 2026-11-22 經 PPK SSH 對遠端 `ymes` 做唯讀 catalog audit，確認四表均不存在且沒有可辨識的 migration-history table；未查業務資料、未執行 DDL/DML，migration 檔案存在不能代表已套用。結果詳 WP608 模組文件，取得精確來源後才能建立 migration／正式 Query API。WP607 不重複猜測 CREATE-only SQL。
- 報表設計類別來源在本機 WinForms Reports；`arInvCount_General` 位於 `WP_InvCountState` 共用報表專案。缺 ActiveReports runtime／WinForms viewer 的 Web DEV 不重製精確頁面尺寸、字型、欄寬、分頁、列印頁首／頁尾或真正條碼編碼；目前只重現類型分流、排序、BarCode 切換與報表欄位預覽。
- 家用端若要上正式 Web，先比對 PostgreSQL schema／migrations，沿用 WP608 的讀取 API，實作使用者／權限保護的報表資料端點。不要因 Web 預覽頁而在伺服器硬編碼 printer、ActiveReports 或安裝公司桌機 DLL；列印格式／條碼規格須由家用端確認部署方案與實際掃碼要求。
