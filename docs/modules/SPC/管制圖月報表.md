# SC303 管制圖月報表

## 功能識別

- FunctionNo：`MONTHLY CHART REPORT`
- FunctionKey：`SC303`
- 中文名稱：管制圖月報表
- WinForms：`frmQueryMnthVarChartRPT`，結果視窗 `frmRPTChartMnth`
- ExecutionFile：`SC_QueryMnthVarChartRPT.dll`
- Vue DEV 路由：`/YMES/SPC/MonthChartReport`
- 主要用途：依 Variable QC Item、控制圖、日期區間、Key Node 與 Collect Factor 彙整三期能力／不良指標。

## 畫面與操作

查詢 Form 包含 Month Report Code 唯讀欄與 `...` picker、QCItem 唯讀欄與多選 picker、From／End Query Date、`Key_Node` 下拉（I／C／N）、`CombineQCItem`、`Get Last Month`、Collect Factor Grid、Query、Close。QCDataType 控制項在 Designer 中隱藏；預設 SelectedIndex 不代表使用者可選的畫面條件。

表單預設起日為「目前日期 + 1 日，再減一個月」的日期 00:00:00，迄日為目前日期 23:59:59；`Get Last Month` 預設勾選。QC Item picker 最多接受 1,000 筆。選取項目後以 `LoadQCItemFactor` 建立 Factor 聯集，再以 MES Parameter 顯示名稱／型別與 table/function lookup 或自由輸入。

Month Report Code picker 從 SC302 的 `LoadMonthRPTCode` 摘要資料選 ReportNo，將該編碼的多個 QCItemNo、Main 與 FactorValue 填回查詢條件。選 Code 不會把 ReportNo 傳進 `LoadSPCChartMonthReport`；一般結果 Grid 不顯示 ReportNo。結果 Form 的 ReportNo 欄只在其他 group-query 呼叫者傳入 `dtRPT` 時顯示，這不是本 FunctionKey 的一般查詢路徑。使用者也可直接多選 QC Item。

勾選 `CombineQCItem` 並選多項時，Form 要使用者指定 Main QC Item，先呼叫 `ChkSampleSizeforMonthReport`（Service timeout 600,000ms）檢查合併條件，再執行查詢。Combine 時由 Main QC Item 決定控制圖／SampleSize，Core 以所選多 QC Item 的量測資料合併計算，結果 Form 將 QCItemNo 顯示成逗號串接的選項清單。未勾選 Combine 時各圖分別計算。

DEV 頁提供 Report Code picker、QC Item 多選、Combine／Main、日期、Key Node、Factor 多值條件、Get Last Month、Query 與結果 Grid。DEV 數值為固定假資料；不接正式 API、不執行 SPC 統計。普通與 Combine 查詢、Saved Report Code 帶值、日期驗證和 SampleSize 一致性均有可互動示意。

## 查詢與結果行為

`LoadSPCChartMonthReport` 的輸入含 From／End Date、QCItemNo 清單、隱藏 QCDataType 篩選、KeyNode、FactorNo／FactorValue／FactorOnLine、CombineQCItemNo、PPK-as-CPK 與 GetLastMonth。Form 在 `VISERA` 企業分支將 PPK-as-CPK 設為 true。

Core 以目前 FromQueryDate 所在月份為本期，往前計算兩個完整月份，再加 FromQueryDate 至 EndQueryDate 的選取期間；日期比較含起訖端點。GetLastMonth=false 時只計算本期。輸出資料只有本期 Run3 不為 NULL 的控制圖列；前兩月資訊由 `CPK1`／`Run1`（Grid caption `L2CPK`／`L2RUN#`）及 `CPK2`／`Run2`（`LCPK`／`LRUN#`）顯示。

主要資料來源為 IssueState=2 的 SPC Chart Basis、Variable QC Item、Variable Factor 與 Variable Detail Log；規格／管制線取 `TBLSPCQCCHARTDETAILLOG` 的 `SPCID=0` 歷程。RawData 將 Variable Detail Log 與 Variable Factor Log 依 SPCSerial 連接，`Excluded=0`，依期間、FactorSerial 與 Factor 條件取資料。`Run#` 為批數、`Data_CNT` 為本期量測數；結果顯示 QCItemNo／Name、ChartFactors、ChartTitle／Unit、Target／US／LS、RUN#／Data_CNT、OOS／OOC 數與比率、AVG／STD、CP／CPK、ERFQty、CPK Goal、前兩月 CPK／批數、Sponsor、Key Node、Data Type 和警示欄。

Core 計算 `PP`／`PPK`，但結果 Form 的這兩個欄位顯示程式碼已註解，Grid 不展示。`Run<20` 對本期批數小於 20 標 `*`，`Cpk<Goal` 對 CPK 低於目標標 `#`；`R1>25%`／`R2>20%` 欄位存在，但比較程式已註解，舊流程不填警示。

## 資料表與 DDL 狀態

SC303 沒有新增業務資料表；查詢依賴 QC302 Chart Basis／Detail Log、QC205 Variable Factor／Factor log、QC210 Variable Detail Log 等既有 SPC references。repo 中已有 QC302、QC205、QC210 Oracle source DDL／PostgreSQL CREATE-only 參考；SC303 沒有再產生重複 SQL。

Month Report Code 依賴 SC302 的 `TBLSPCMONTHRPTCODE`。該表的 Oracle DDL／metadata／PostgreSQL CREATE-only 在 repo 缺失；SC302 規格已記錄不可由 Core 查詢欄位猜測完整 schema。家用端須與 SC302 一併比對 YMES live schema，正式 Code picker 重用經驗證的 SC302 API。

本桌機受保護 Oracle MESTEST profile 不可用；未直連 Oracle，也未連 YMES PostgreSQL。既有 references 對照足以供 handoff，未新增或猜 DDL。

## 家用端 API／schema handoff

- 正式唯讀 API 依登入者 SC303 FunctionKey 權限，接收 From／End、QCItemNo array、KeyNode、Factor filters、CombineQCItemNo 與 GetLastMonth；所有值參數化。Saved Code picker 共用 SC302 的已驗證 API；服務端重新讀 Code 及 QCI／Factor 設定，不信任 client 傳入 Main／Factor metadata。
- Query 與 Combine SampleSize check 使用相同 QC Item／Factor／日期／KeyNode 條件及一致資料 snapshot；Combine 時以 Main QCI 找控制圖／SampleSize，套用被選 QCI 清單聚合量測，避免前端自行拼接欄名。
- FactorNo 是動態 SQL identifier，必須由所選 QC Item 的已核准 Factor metadata allowlist 對應到固定 schema／JSON key；不要沿用 Core 將 `B.{FactorNo}` 和逗號清單直接串 SQL 的做法。將多值 FactorValue 轉 array／table-valued parameter，參數化比較。
- 舊 RawData 固定 `Excluded=0`；不得在無決策下改成包括 Excluded／Isolated。Core 用 Chart Detail `SPCID=0`、最新 StartTime 填規格／界線；確認一個 FactorSerial 下的 limit 規則及當期變更處理。
- 保留兩個前月及目前指定區間、Run3 無資料時不顯示、GetLastMonth=false 只算本期、Run<20／Cpk<Goal 提示等舊語意；如調整，記錄產品差異。一般結果不輸出 ReportNo；如需將 Code 帶入 API audit/context，另定義唯讀來源。
- Service 設有 6,000,000ms timeout，Core 將完整 RawData 載入 DataSet，沒有日期跨度／資料列上限。正式 API 應限制日期區間、QC Item／Factor 數、量測資料量與計算時間，分批或由資料庫彙總，不能照搬長 timeout／全量載入。
- 取得 YMES live schema 後比對 QC302／QC205／QC210 現有 migration，避免重複建表；SC302 report-code 表缺 metadata，先依有可信來源的 schema 工作。
