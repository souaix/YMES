# SC311 製程能力報表_以要因查詢

## 功能識別

- FunctionNo：`CHART ALL CAPABILITY BY FACTOR`
- FunctionKey：`SC311`
- 中文名稱：製程能力報表_以要因查詢
- 查詢 Form：`frmQueryChartAllCapabilityByFactor`；ALL 結果 Form：`frmRPTChartCapability`
- ExecutionFile：`SC_QueryChartAllCapabilityByFactor.dll`
- 共用週／月／年結果物件：`SC_RPTChartYMWCapability`
- Vue DEV 路由：`/YMES/SPC/ChartAllCapabilityByFactor`
- 主要用途：不指定 QC Item，從所有 Variable QC Item 的 Collect Factor 中設定查詢值，再查看能力指標。

## 畫面與操作

查詢 Form 提供 Collect Factor grid、From／End Query Date、Report Type（ALL／WEEK／MONTH／YEAR）、Lot Report State（Normal／Excluded／Isolated）、Lot Result（Pass／Fail）、Chart Calculate Principle、Capability Type、Clear、Query、Close。Report Type 預設 MONTH；日期值為目前日期加一天後減兩個月的 00:00:00 至今天 23:59:59，但兩個日期勾選預設為 false。CalRule 預設為 `Cumulative Sample Size >= 25 Only`；三種 Lot State、Pass／Fail 及 PP／PPK／CP／CPK／CA／Mean／EstSd／Sd 預設全選。

來源 Form 的 QC Item label、QCItemNo／QCItemName 欄位及 `...` picker 在 Designer 設成 `Visible=False`，查詢時也沒有重新顯示。舊 picker／載入 QC Item 程式碼仍留在 Form，但一般操作流程是由 `funCreateControl()` 無 QCItemNo 呼叫 `wsQC.LoadQCItemFactor`，從回傳資料合併相同 FactorNo，只留下每種要因一列。MES Parameter type 0／1 的 FactorValue 為唯讀並開啟多選 lookup；type 2 可自由輸入，更新時轉為大寫。必須至少填一個 FactorValue 才能 Query；Clear 只清除 FactorValue 與 Name。

非 ALL 報表在日期未勾選時會詢問是否重新設定；選 Yes 會返回日期欄，選 No 則沿用目前顯示的日期值繼續。From／End 相同或起日晚於迄日會阻止查詢。ALL 分支只傳入已勾選的日期端點；週／月／年結果物件會傳入畫面上的兩個日期值。LotState 以 `0/1/2`、LotResult 以 `0/1` 傳遞；CalRule 為 `0`（累計批數 × SampleSize 至少 25 才算能力指標）或 `1`（全部計算）。

DEV 頁提供唯一 Factor 清單、MES Parameter 多選值／type 2 自由輸入、日期與勾選、四種 Report Type、Lot State／Result、CalRule、八種能力指標、Clear／Query、動態週期 Grid 及選列 Chart 視窗。QC Item 不可選，Factor／查詢結果均為假資料；能力指標使用固定樣本值，不重算正式 SPC 公式。

## Service／Core 行為

ALL 查詢由 `LoadChartCapabilityDataByFactor` 接收起訖時間、FactorNo／FactorValue／FactorOnLine、LotState、LotResult、CalRule；Service 要求 Factor 欄位存在並要求 CalRule。`LoadChartYMWCapabilityData` 另接 ReportType 與 show-QCItem-name 參數。兩個 Result Form 的 Service timeout 均為 6,000,000ms。

Core 先讀取所有 QC Item 的 ChartType／SpecLineType，再從 `TBLSPCQCCHARTBASIS`、`TBLSPCQCCHARTDETAIL` 與 `TBLSPCVARFACTORLOG` 取得 IssueState=2、SPCID=0 的圖表／FactorSerial 摘要。摘要查詢依日期、Factor 值、LotState 的 Excluded code 與 LotResult 的 Result code 篩選，並計算 LotCount。逗號分隔的同一 Factor 多值轉成 SQL `IN`；不同 Factor 條件以 AND 組合。FactorNo 被直接拼成 SQL 欄位名稱，FactorValue 也串入 SQL 字串。

ALL Core 再從 `TBLSPCVARDETAILLOG` 及 `TBLSPCVARFACTORLOG` 取量測點，依 SPCSerial 配對、按 FactorSerial／SPCSerial／SerialNo 排序，再按每組 FactorSerial 計算 Mean、Sd、EstSd、PP／PPK／CP／CPK／CA。能力指標受 CalRule、ChartType、SpecLineType、US／LS 與 SampleSize 影響；不足資料回傳「資料不足!」，沒有 LotCount 的圖表列移除。結果 Form 依 Capability Type 顯示所選指標，並可選列開啟週／月／年／ALL 能力趨勢。

舊 Core 的 ALL 摘要查詢使用 LotState／LotResult 條件計算 FactorSerial 的 LotCount；ALL RawData 卻固定 `Excluded=0`，沒有套用 LotState／LotResult。畫面上的狀態／結果因此可能影響列／批數，但不會以相同條件限制 ALL 能力指標。YMW Core 對每個區間重新查 RawData，SQL 先固定 `Excluded=0`，再套用 Factor、LotState 與 LotResult；因 Excluded 條件相交，選取僅 Excluded／Isolated 時會沒有 RawData，預設全選時實際仍只取 `Excluded=0`。兩個路徑的摘要／指標批次集合與篩選語意不一致，家用端 API 應明確統一並留下決策紀錄。

另有兩個需家用端核實的舊流程疑點：

1. 共用 YMW 結果 Form 的 `blnByFactor` 預設為 false；SC311 的 `ObjectFileHandler.Execute("SC_RPTChartYMWCapability", parameters)` 未傳入此值，因此會序列化隱藏且空白的 QCItemNo 欄位。Core 以 `QCItemNo != defString` 決定是否加條件；需核實空字串 sentinel 與舊執行結果。正式 API 應明確實作「依要因、不指定 QC Item」契約。
2. SC311 `funCreateControl()` 產生的 Factor row 沒有填入 `QCItemNo`，而共用 YMW Result Form 組合 Factor 顯示欄時，會依結果 QCItemNo 從 `dtFactor` 選列。該路徑可能無法為結果列還原 Factor 顯示值。

## 家用端 API handoff

- 依登入者 SC311 FunctionKey 授權，提供唯讀查詢。輸入 ReportType、可選日期端點、Factor filters、LotState、LotResult、CalRule、Capability 指標；不要求 client 選 QCItemNo。Factor metadata 由伺服器依有效 Variable QC Item 載入並限制在 allowlist。
- FactorNo 必須映射至固定欄位／JSON key，不可把 client 欄名拼入 SQL；FactorValue 以 array／參數化條件處理。對日期跨度、Factor 條件數、週期數、樣本列數、運算時間與輸出列數設上限，移除 6,000,000ms 長 timeout 與全量 DataSet 模式。
- 統一摘要列、LotCount 與 RawData 的日期、Factor、Lot State／Result 篩選及 snapshot。決定 Excluded／Isolated／Pass／Fail 如何進入能力指標，並以規格和資料驗收案例固定語意；不得讓摘要數和指標使用不同批次集合。
- YMW 路徑須明確傳達 by-factor mode；修正舊 `blnByFactor` 未傳入疑點與 Factor row 缺 QCItemNo 的顯示限制，或將差異記錄為正式 UX 決策。
- 以伺服器端 chart metadata／SampleSize／SpecLineType 計算能力指標，採用固定精度與零變異處理；對照 Cumulative Sample Size ≥25 規則，並記錄與舊 Core 的每組 FactorSerial／LotCount／圖表型態算法差異。
- 比對 YMES live schema／migrations 與 SC301 使用的 QC302／QC205／QC210 references；無新增表，不重複建立 schema。
