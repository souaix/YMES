# SC312 管制圖月報表_以要因查詢

## 功能識別

- FunctionNo：`MONTHLY CHART REPORT BY FACTOR`
- FunctionKey：`SC312`
- WinForms：`frmQueryMnthVarChartRPTByFactor`，結果視窗 `frmRPTChartMnth`
- ExecutionFile：`SC_QueryMnthVarChartRPTByFactor.dll`
- Vue DEV 路由：`/YMES/SPC/MonthChartReportByFactor`
- 主要用途：輸入日期、Key Node 與一個以上 Collect Factor 條件，查詢符合條件的月報控制圖。

- Core：`D:\iMES\CSiMES\STD\MESkc\kcSPC\clsSPC.cs`：`LoadSPCChartMonthReportByFactor`（約 37825），使用 `kcQC.clsQCBasis.ShowQCItemFactor_Multi(ChkColumnExist: true)` 取得 Factor metadata。

## 實際可見畫面與操作

Designer 將 `gbxQCItem`、`gbxMonthReportNo`、`cboQCDataType` 設為 `Visible=False`；本 Form 未找到重新顯示它們的程式。可見條件為 From／End Query Date、Key_Node（I／C／N）、Collect Factor Grid、Get Last Month、Clear、Query、Close。Get Last Month 預設勾選。起日預設「目前日期 + 1 日，再減一個月」的 00:00:00，迄日為目前日期 23:59:59。

Form Load 不帶 QCItemNo 呼叫 `wsQC.LoadQCItemFactor`（`ChkColumnExist=True`），由返回的有效 MES Parameter 建出所有 Factor 列。ParameterType=0／1 的 Value 為唯讀，使用 `...` 從 table／function lookup 多選；選值的代碼填入 Value、名稱填入 Name。ParameterType=2 可直接輸入，舊畫面會轉大寫。Clear 清空所有 Value／Name。按 Query 時至少要有一個 FactorValue，否則顯示「PLEASE INPUT QUERY CONDITION」並停止。

隱藏群組仍留有 Report Code、QC Item 多選及 Combine/Main 的舊程式碼；結果 Form 在 Combine 路徑會先呼叫 `ChkSampleSizeforMonthReport`（timeout 600,000ms）。一般使用者無法從目前畫面開啟這些控制，因此本 DEV 不展示或要求它們。`cboQCDataType` 也不可見；結果查詢沒有送出 `QCDataType`，Core 使用預設 `-1`，不作型別篩選。

DEV 頁重現可見條件與操作：Factor lookup 多選並填回代碼／名稱、ParameterType=2 自由輸入大寫及逗號多值、Clear、Key Node、日期驗證、至少一項 Factor 守門、Get Last Month 與月報結果 Grid。DEV 以固定假資料示範不同 Factor 條件的聯集結果；不連正式 API，也不計算 SPC 統計。

## Service／Core 查詢行為

結果 Form 將 From／End、FactorNo／FactorValue／FactorOnline、KeyNode、GetLastMonth 與 PPKasCPK 送至 `LoadSPCChartMonthReportByFactor`；日期與查詢 Service timeout 為 6,000,000ms。Form 在 `VISERA` 企業分支將 PPKasCPK 設為 true。直接查詢不傳 QCItemNo，Form 的 `frmRPT.QCItemNo = txtQCItemNo.Text` 指派也已註解。

Core 的 Chart Basis 查詢涵蓋全部 `IssueState=2` 的 Variable QC Item 控制圖，僅依可傳入的 QCDataType／KeyNode 過濾，沒有 QCItemNo 條件。RawData 將 `tblSpcVarDetailLog` 與 `tblSpcVarFactorLog` 依 SPCSerial 連接，涵蓋所有有效 Chart Basis FactorSerial，固定 `Excluded=0`，依區間和 Factor 條件取資料。每個非合併圖表列再按 FactorSerial 計算；逗號分隔的同一 Factor 值使用 OR (`IN`)，不同 Factor 條件以 AND 串接。結果的 `ChartFactors` 只合併該 QC Item `FactorOnLine=Y` 且非 `*` 的要因值。因而目前功能按要因篩選全體有效控制圖，不是限制在某個 QC Item 的要因結果。

與 SC303 相同，FromQueryDate 所在月份之前兩個完整月份加上目前選取區間；起迄端點均包含。Get Last Month=false 時只算目前區間；本期 Run3 無資料的圖表列最後移除。Chart Detail 只取 `SPCID=0`，依各期結束時間選當時最新的規格線。統計欄含當期 CP／CPK、Run／Data_CNT、OOS／OOC 與比率、平均／標準差、ERFQty、前兩期 CPK／Run 等；舊 Grid 隱藏 PP／PPK。Run<20 標 `*`、Cpk<Goal 標 `#`。SC312 Core 會比較 CPK1 與目前 CPK3，下降超過 20% 填 R2 `@`；比較 CPK2 與 CPK3，下降超過 25% 填 R1 `!`。這段警示在 SC303 的對應 Core 程式已註解。

## 資料表與 DDL 狀態

可見查詢依賴 QC302 Chart Basis／Detail Log、QC205 Variable Factor／Factor Log、QC210 Variable Detail Log 等既有 SPC references，沒有新增業務表。repo 已有這些 Oracle source DDL／PostgreSQL CREATE-only 參考。

隱藏的 Month Report Code 程式路徑會依賴 SC302 `TBLSPCMONTHRPTCODE`；repo 缺該表 Oracle DDL／metadata／PostgreSQL CREATE-only，SC302 規格已記錄不可從 Core 使用欄位猜完整 schema。此依賴不在本 FunctionKey 目前可見查詢流程。

本桌機的受保護 Oracle MESTEST profile 不可用；未連 Oracle 或 YMES PostgreSQL，也未猜補 DDL。家用端需沿用既有 references 並核對 live schema／migration。

## 家用端 API／schema handoff

- 建立登入及 SC312 FunctionKey 權限保護的唯讀查詢，輸入日期、KeyNode 與 FactorNo／多值條件；不接受 client SQL identifier。由服務端 Factor metadata 對照核准欄位／JSON path，FactorValue、日期及 KeyNode 全部參數化。
- 舊畫面沒有可見 QC Item 條件，Core 查詢實際涵蓋全部有效控制圖。正式 API 必須決定登入者可查的 QC Item 範圍，避免照搬全體 SPC 查詢造成越權或無意義的大型掃描；如加上權限範圍或 QC Item 篩選，記錄相對來源行為的差異。
- 限制日期跨度、可套用 Factor 數／值數、RawData 筆數及計算時間；改用分批或資料庫彙總，不能照搬 6,000,000ms timeout、全量 DataSet 或串接 SQL。保留 `Excluded=0`、目前三期時間邏輯和 limit 歷程規則，調整時記錄差異。
- 維持 R1／R2 與 SC303 的差異：SC312 來源 Core 有下降比例比較並填 `!`／`@`，不要因共用 Vue Grid 而抹除。
- QC Item／Month Report Code／Combine controls 目前隱藏。若產品要求重新開放，先重驗 SC302 code schema/API、SampleSize check、Main 合併範圍與交易快照，再明確定義正式頁面行為。
