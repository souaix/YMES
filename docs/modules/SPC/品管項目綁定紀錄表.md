## WinForms 條件與畫面

- Form Load 以 runtime ValueListProvider 載入 `TBLQCITEMBINDLOG.QCITEMTYPE`、`EXECUTESTATUS`、`INLINE` 選項；QC Item Type 有五類：Attribute、Variable、Variable Group、Attribute Order Group、PMI Group。此 Type ValueList 與其翻譯文字由執行環境提供。
- QC Item Type 與 ExecuteStatus 各有啟用 CheckBox。選取 Combo 值會自動勾選對應 CheckBox；Type 切換時清除已選 QC Item。Type Combo 尚未選取時 QC Item lookup 按鈕停用。
- QC Item lookup 依目前 Type 呼叫 Attribute／Variable／Variable Group／Attribute Order Group／PMI Group 對應的 `wsQC` lookup，只顯示 `IssueState=2`，不含 Stop `-1`。選取 QC Item／Group 後才可查詢；Type 條件啟用且有選 Type 時，若未選 QC Item／Group，Query 顯示必填訊息。未啟用 Type 條件可跨類型查詢。
- 日期 From／To 沒有啟用 CheckBox，永遠傳送。From 預設為 Now 往前 7 天的 00:00:00，To 預設 Now，Core 使用含端點的 `>= From`、`<= To`；Form 沒有起迄檢查。
- ExecuteStatus 條件只有在 CheckBox 勾選且 Combo 已選值時傳送。Core 寫入呼叫將 0 用於新增綁定、1 用於更新後的新綁定列、2 用於解除綁定列；DEV 以數字與簡要標籤呈現，正式顯示文字仍須遵循 runtime ValueList。
- Query 結果分成 Product、OP、Material Type、MaterialNo 四個頁籤，分別對應 `BINDTYPE=4/3/1/2`。切換 Tab 只改已載入 DataView 篩選，不重新呼叫 Service。每個 Tab 顯示父層 QC Item／綁定對象和展開後的執行歷程；Form 初始會展開所有資料。
- Product 與 OP 明細顯示 InLine、ExecuteOrder、INSPTYPE_FAI／IPQC／PQC、ExecuteStatus、ExecuteDate、Executor；Material Type／MaterialNo 明細僅顯示 ExecuteStatus、ExecuteDate、Executor。Form 為唯讀，沒有新增、修改、解除或匯出按鈕。`InLine_Show` 是 Form 加入的顯示欄位，值複製自 `InLine`。
- Form 將子表 DataView 依 ExecuteDate 升冪排序；Core SQL 沒有 `ORDER BY`，父層列順序未保證。

## Service／Core 查詢

- Form 永遠傳 FromQueryDate／EndQueryDate。只有 Type CheckBox 開啟且 Type 已選時才傳 QCItemType 與 QCItemNo；ExecuteStatus 依 CheckBox／Combo 狀態傳送。
- Service 解析 QC Item、QCItemType、ExecuteStatus、From／End 日期及 optional Additional XML，再呼叫 Core。Core 對 `TBLQCITEMBINDLOG A` 執行兩次查詢：第一個 `SELECT DISTINCT` 建父層，欄位為 QCItemType、QCItemNo、BindType、ProductNo、ProductVersion、OPNo、MTLType、MTLNo；第二個 `SELECT *` 建所有符合條件的子歷程。兩者都排除 QCItemNo 為 Null，並使用同一組日期／Type／Status／QC Item／Additional 條件。
- Core 在記憶體建立 `QCItemLogData` DataRelation。父子關聯欄位是 QCItemNo、BindType、MTLType、MTLNo、OPNo；ProductNo／ProductVersion 沒納入 relation key。若同 QC Item／OP／其他 key 有多個 Product／Version，子歷程可能被多個 Product 父列共用或重複顯示；家用端 API 應用明確的綁定對象唯一鍵組 parent-child，不要照抄這個 relation key。
- SQL 條件將日期格式化、QCItemNo 及 Additional XML 直接串入字串，沒有分頁或結果上限。正式 API 必須參數化、驗證 Type／BindType／Status enum、限制日期跨度及父子總列數，並使用穩定排序／分頁。

## DDL／metadata 與家用端 handoff

- `TBLQCITEMBINDLOG` 的 Oracle source DDL／metadata 在 `database/reference/mestest_mtl_qc_item_tables_source_ddl.sql`；PostgreSQL 空表 CREATE-only 在 `database/reference/mestest_mtl_qc_item_tables_create.sql`。來源欄位含 QCItemLogSerial、QCItemType、QCItemNo、BindType、MTLNo／MTLType、ProductNo／ProductVersion、OPNo、InLine、ExecuteOrder、三種 InspectType、ExecuteStatus、ExecuteDate、Executor；source PK 為 QCItemNo＋BindType＋QCItemLogSerial。
- 公司桌機受保護 Oracle profile 不存在，本次使用 repo 既有 reference，未直連 Oracle／YMES PostgreSQL，未新增或猜測 DDL。家用端先比對 live schema／已部署 migration；reference 不是 production migration。
- 正式 SC216 API 需 FunctionNo 權限、僅提供唯讀欄位、參數化時間與條件、保持 From／To inclusive，確認 type/status 的 ValueList 對照與群組種類。修正 Product／Version 被舊 DataRelation 遺漏的關聯缺陷時，記錄此行為差異。條件及回傳列數需有限制；父子結果使用同一個一致性 snapshot。
