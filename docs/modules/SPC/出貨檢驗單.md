- 選單識別：Module `SPC`、FunctionNo `OQC FORM`、FunctionKey `SC106`、Form `frmOQCForm`、ExecutionFile `SC_OQCForm.dll`，分類 `SPC管制`。
- WinForms 主 Form／inline Designer：`D:\iMES\CSiMES\STD\MESWin\SPC\SC_OQCForm\frmOQCForm.vb`；單據定義 Form／inline Designer：`frmOQCFormDef.vb`；QC Item Map picker／inline Designer：`frmOQCFormQCItemMap.vb`。
- Service：`STD\MESws_STD\wsSTD\wsSPC\wsSPC.cs` 的 `LoadOQCForm`、`AddOQCForm`、`EditOQCForm`、`DelOQCForm`、`SetOQCFormStatus`、Map CRUD 及 `funQC_Update`；表單另用 `wsPRD.LoadProductBasis`／`LoadPRDOP`／`LoadPRDQCItemLotValid`、`wsWIP.LoadLotBasisJoinState`、`wsSYS.GetOQCFormNo`。

## WinForms 狀態與互動

- 主 Form 五個 Status 頁籤：0 未確認、1 待檢、2 檢驗完成、3 已接收、4 已拒收。選單各頁支援 Copy；未確認可 Add／Edit／Copy／Delete／Confirm 及調整 QC Item Map；待檢頁選 QC Item 後開 `SC_OnlineControl` SPC 量測；檢驗完成可接收或拒收；終態頁保留查詢及 Copy。
- 定義 Form 要求 ProductNo、Qty>0、OPNo、ProductVersion；LotNo 可空白，若有輸入需通過 WIP 有效批號檢查。產品／工序／版本帶出 `LoadPRDQCItemLotValid` QC Item；文件欄為 `InspDocLink`。一般新增／複製的 Form 不帶 ERP CallBackType；ERP 來源識別及 `ERPSourceNo`／`ERPSourceSeq` 是回報流程用資料。單號依 `OQCFORMNO` serial rule 取得；OPTIVTECH 另有歷史特例。
- 未確認刪除只允許空 `CallBackType` 單據。待檢單的 Map 全部 Status=0（或沒有 Map）時才能處置：ERP 來源單呼叫 `SetOQCFormStatus(0)` 退回未確認；一般手開單則刪除 Header 與 Map。已有任一項開始後，待檢頁刪除停用。
- Confirm 透過 `SetOQCFormStatus` 設 Status=1。SPC 完成後更新每列 Map 的 Status／Result／SPCSerial；最後一列完成時 Core 自動將 Header 設為 Status=2 並寫 FinishTime。來源操作沒有先檢查 Map 數量，DEV 保留此行為。
- 接收／拒收分別更新 MES Status=3／4。CallBackType 為 TIPTOP 或 T100 時，WinForms 先呼叫 `wsSPC.funQC_Update`，外部成功後才改 MES 狀態；回報量分別為 AcceptQty=Qty 或 RejectQty=Qty，另一項及 ScrapQty 為 0。Service 將 MES Status 3／4 轉為 ERP 狀態 1／2，TIPTOP／T100 解析為 `TIPTOP_QC`／`T100_QC` 並使用 ERP callback。回報失敗會阻止本機狀態轉換。WFGP 分支依目前 WinForms 按鈕邏輯略過回報而仍更新本機狀態；不得把舊 `funResultCallBack` 工作流程當作目前有效路徑，Receive／Reject handler 中該呼叫已註解。
- SPC 檢驗後另讀 OP 的 `SPCInspAbnormalHoldLot`。此規則為 0 且所有 Map Result 已有值、任一 Result 非 0 時，WinForms 會開 `WP_BRERFCreate` 建 SPC 異常單並帶 SPC Serial；DEV 僅提示此副作用，不呼叫 ERF。
- OQC ItemType 支援 0 計數屬性、1 計量、2 群組、3 屬性順序群組。服務 `UpdOQCFormQCItemMapResult` 的 GroupNo 分支會把群組結果折算成 0／1（任一子項 Result 非 0 即 fail）。

## Vue DEV 頁與簡化界線

- 路由 `/YMES/SPC/OutgoingQCForm`，選單名稱「出貨檢驗單」；正式環境仍顯示未開放提示。
- DEV 提供五個狀態、關鍵字／建立日期篩選、Header 與 QC Item 清單。未確認可新增／編輯／複製／刪除／確認與調整 Map；待檢可逐列模擬 SPC 結果，全部完成後自動轉檢驗完成；ERP 來源待檢單在 Map 尚未開始時退回未確認，手開單則刪除；接收／拒收可切換模擬 ERP 成功或失敗。
- TIPTOP／T100 假回報成功才改 OQC Status；假回報失敗時保留檢驗完成。DEV 假 payload 顯示接收／拒收數量及 ScrapQty=0；不呼叫 sQMS、ERP、SPC 設備或 `WP_BRERFCreate`。WFGP 路徑依 WinForms 現況略過 ERP 回報。所有表單、Map、ERP 資料、serial、DataStamp 和狀態只存在記憶體。
- DEV 使用虛構 ERP 單號／文件參照與產品、批號、QC Item fixture；keyword 篩選是本機便利操作，不代表 WinForms Service 的查詢契約。產品／工序／批號資格、ERP source 權限、serial reservation 與 callback 僅可由正式 server 驗證。

## 資料表、Oracle metadata 與家用端 handoff

- Core header 表為 `TBLSPCOQCFORM`，Map 表為 `TBLSPCOQCFORMQCITEMMAP`。Header Load／Def 使用 ProductNo、ProductName、Qty、Status、LotNo、CustomerNo、Creator／CreateDate、OPNo、ProductVersion、`InspDocLink`、DataStamp、Reviser／ReviseDate、FinishTime、`CallBackType`，ERP callback 還讀 `ERPSourceNo`／`ERPSourceSeq` 等欄位；缺同版 Main DDL，欄位型別／PK／索引不得由 UI 或 SQL 字串反推。
- Map 的 Oracle source DDL 已在 `database/reference/mestest_qc216_spco_qc_item_map_source_ddl.sql`，PostgreSQL CREATE reference 在 `database/reference/mestest_qc216_variable_item_group_pmi_create.sql`，來源為共用 OQC Map table；不另產重複 CREATE。SC106 Header 的 Oracle DDL／metadata 與 PG CREATE-only 尚無 repo reference。桌機受保護 Oracle attachment/profile 不存在，本次未連 Oracle或猜 Header schema。
- Core `SetOQCFormStatus` 用 `QCFormNo + DataStamp` compare-and-set，更新 Reviser／ReviseDate 並遞增 DataStamp。家用端需參數化並限量查詢；明確定義 Header＋Map 新增、Edit Map 整組取代、Delete、Confirm、待檢退回／刪除、SPC 結果及最後項自動完成的交易邊界。`LoadOQCForm` 支援建立日期、Lot contains 及 Status filters。
- 正式 API 須驗證登入者與 ERP source ownership，建立／複製不可偽造 CallbackType／ERPSource keys；TIPTOP／T100 callback 要保存 idempotency key、request／response／ERP mapping、重試與人工對帳狀態，外部成功後才遞增 MES Status。WFGP 的目前 UI skip 行為及 service 支援分支需由家用端與 ERP owner 確認。`WP_BRERFCreate` 部分成功、ERP callback timeout 與本機 CAS 衝突都需明確補償流程。
- `clsSPC.UpdOQCFormQCItemMapResult` 目前在 `colSQL == null` 時先執行 Map update collection，之後又把 Map update collection 加上 Header 完成狀態 SQL 再次執行；家用端實作前需確認重複更新的交易／DataStamp／side effect，避免照搬重複執行。
- 公司桌機只交付 DEV UI 與 API／schema handoff，不連 YMES PostgreSQL、不實作或驗收正式 API/schema、不設定 `ConnectionStrings__YMes`。
