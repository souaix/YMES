## 畫面與互動

- Form 以 funLoadMESParameter 讀取 MES Parameter，funCreateControl 載入 FactorNo／FactorName／FactorOnline／FactorSpec 與 ParameterType。ParameterType 0／1 使用 lookup 多選；ParameterType 2 可自行輸入，離開欄位時轉大寫。Clear 只清 FactorValue／Name，不清查詢結果。
- Query 至少需一個 FactorValue。相同 Factor 的逗號分隔值以 IN 多選；不同 Factor 條件併用 AND。KeyNode 選項為空、I、C、N，透過結果 DataView 篩選。
- Form 中 QCItem label、文字欄位及 Get picker 都設為 Hidden。Form Designer 還定義一般 QCChart 與 ShortrunChart 兩個結果 Grid，但 ShortrunChart tab 在 Designer 設為 Visible=False；目前可見一般 Grid 的篩選條件為 IsShortrunChart=0 AND LotQty>0。
- 日期起訖的 DateTimePicker 各自預設未勾選；From／End 日期與 Query by Lot 的最新批數會傳給分析視窗。Query by Lot 關閉時欄位停用並清空；啟用後必須輸入大於 0 的數字。Show All Data 預設關閉、Show ERF Marks／Data in One Page／Show BarChart 預設開啟。
- 群組 Grid 顯示 FactorSerial、QCItemNo、在線 Factor 欄、FirstLotDate、LastLotDate、LotQty 與 KeyNode。雙擊或 Query Chart 開啟共用 SC_AnsLineBarChart；Query Data 與 Histogram 分別傳入檢視模式 0／2，Query Chart 為 1。明細由 FactorSerial 載入相應 QC Item、Factor、量測／統計與限制資料；圖型依 QC Item ChartType 呈現 X-R、X-S 或 X-Rm。共用明細規格參照 SC206 管制圖分析.md。

## Service／Core 實際查詢

- 主 Form 呼叫 wsQC.LoadQCItemFactor（ChkColumnExist=True），再呼叫 wsSPC.LoadControlChartDataByFactor，傳入可選 From／End 日期及 FactorNo、FactorValue、FactorOnLine。主群組查詢要求至少一個非空 FactorValue。
- wsSPC.LoadControlChartDataByFactor 解析 Factor 集合與日期，但沒有解析／轉送 QCItemNo；Core method 有 QCItemNo 參數，Service 呼叫時留空。因此目前 SC214 群組查詢涵蓋所有 QCItemNo IS NOT NULL 的 chart basis，並不以畫面中隱藏的 QCItem 欄位限制。
- kcSPC.LoadControlChartDataByFactor 從 TBLSPCQCCHARTBASIS 取 basis row，並以 FactorSerial 到 TBLSPCVARFACTORLOG 算首筆日期、末筆日期及筆數。FromQueryDate／EndQueryDate 的 SQL 條件在 Core 留為註解，因此日期不會縮小群組結果；日期是在使用者開啟共用圖表／資料／Histogram 時才套用。
- Core 以 FactorNo 動態組 SQL 欄位名稱，將逗號分隔值拼成 SQL IN 條件，沒有參數化。FactorOnLine 解析後沒有用於這段 Core 條件；目前結果查詢按傳入的每個已填 Factor 條件做比對。
- Core 在迴圈中累積 strConstrain 後反覆附加至 SQL，後續 Factor 會重複前面條件。這在一般 AND 語意下多半只增加冗餘條件，但也會膨脹 SQL；不應沿用字串組合實作。
- funLoadControlChartData 的通用 Catch 區塊為空；XML／DataSet 解析例外可能不顯示訊息並留下空或舊結果。正式 API 應回傳可辨識錯誤，不要仿效吞掉例外。

## 家用端 API handoff

- 提供登入與 SC214 Function ACL 保護的 QC Item／Factor metadata／MES Parameter lookup 與群組查詢 API。正式查詢應明確決定是否保持「跨 QC Item」的舊行為，或依授權 QCItemNo 收窄範圍；若修正，記錄行為差異。
- Query summary 的日期條件在舊 Core 無效。正式 API 應決定是否修正為 basis 記錄的日期條件，或只保留日期供 drilldown；介面與規格需一致，避免舊畫面讓使用者以為日期已套用。
- 對每個 FactorNo 使用授權 QC Item 的 metadata allowlist；值以參數傳入，逗號值轉成明確陣列。不要接受任意欄位名稱或拼接 SQL。維持跨 Factor AND、同一 Factor 多值 OR 的查詢語意。
- 群組 summary 以 QCChartBasis 與 FactorSerial 統計量測 log 的 First／Last CreateDate 及 LotQty。加查詢日期範圍、Factor 條件數、每項值數、回傳列數限制與固定排序／分頁。
- Drilldown 重用 SC206 的通用 chart analysis contract，限定 SC214 Function ACL 與所選 FactorSerial／QCItemNo；提供 Query Data／Query Chart／Histogram、可選日期或 LatestLots、ShowAllData／ERF mark 等條件及點選序號明細。正式 SPC 限值、Rule 與控制圖算法以共用 Core 規則為準。
- FactorValue 查詢可能包含產品或設備等大型 lookup，應提供已授權且限量的 lookup API，不要把所有 MES Parameter 參照表一次回傳到瀏覽器。
