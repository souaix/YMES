# SC302 管制圖月報表編碼

## 功能識別

- FunctionNo：`MONTHLY CHART REPORT CODE`
- FunctionKey：`SC302`
- 中文名稱：管制圖月報表編碼
- WinForms：`frmMonthRPTCodeBasis`／`frmMonthRPTCodeBasisDef`
- ExecutionFile：`SC_MonthRPTCodeBasis.dll`
- Vue DEV 路由：`/YMES/SPC/MonthRPTCodeBasis`
- 直接業務資料表：`TBLSPCMONTHRPTCODE`
- 本頁用途：維護月報表 ReportNo 與 Variable QC Item、主要 QC Item 及 FactorValue 的對應，供 SC303 月報表查詢使用。

## 畫面與操作

主畫面為月報表編碼資料 Grid，操作按鈕為 ADD、EDIT、DEL、Copy、Close。DEV 加上本機關鍵字篩選及明細檢視區，方便瀏覽一組編碼下的 QC Item 和 Factor。

ADD 開啟定義視窗：輸入 ReportNo，透過多選查找載入 Variable QC Item，並依所選 QC Item 合併 Factor 清單；ParameterType 0／1 的 Factor 可透過 MES Parameter lookup 查值，ParameterType 2 以文字輸入。若選擇多個 QC Item，可勾選合併，並從所選項目指定一個 Main QC Item。ReportNo 離開欄位時轉大寫；ReportNo 與 QCItemNo 為必填。

EDIT 從目前 ReportNo 載入資料；舊畫面將 ReportNo、QCItemNo 設為唯讀，不能重新選 QC Item，可調整 Factor 並重選 Main QC Item。儲存時先呼叫 `DelMonthRPTCodeBasis` 刪除整組，再呼叫 `AddMonthRPTCode` 重建。Copy 預載相同 QC Item／Factor，但可輸入另一個 ReportNo，並走新增流程。DEL 可多選；Form 對重複的 ReportNo 只呼叫一次整組刪除。

DEV 畫面提供新增、編輯、複製、勾選多筆刪除、合併 QC Item／選 Main、Factor 值輸入與明細展開。這些操作只修改頁面記憶體假資料；重新載入會還原固定樣本，不呼叫正式 API，也不代表資料已持久保存。DEV 固定 Factor catalog 只用來呈現 lookup 互動，正式 Factor 選項應來自 MES Parameter API。

## 資料與舊程式行為

`LoadMonthRPTCode` Core 由 `TBLSPCMONTHRPTCODE` 讀取 distinct ReportNo、ReportNo/QCItemNo/Main，以及 ReportNo/FactorNo/FactorValue 三組結果，將同一 ReportNo 的多個 QCItemNo 合併成逗號字串，再以 ReportNo 建立 QC Item 與 Factor 的 DataRelation。Factor 子資料僅按 ReportNo 關聯，沒有 QCItemNo；舊介面以共用 Factor 表現一個編碼的 Factor 條件。

`LoadMonthRPTCode` 可依 ReportNo、QCItemNo、FactorNo 和 Additional 條件讀摘要；Service 另以 `reportbasis=1` 呼叫 `LoadMonthRPTCodeBasis` 取得原始列。本主 Form 使用摘要模式。

Service `AddMonthRPTCode` 必須收到 ReportNo、QCItemNo，解析 FactorNo／FactorValue 清單、Main 及 Additional XML 後呼叫 Core。Core 先檢查 ReportNo 是否重複，再以逗號拆分 QCItemNo：有 Factor 時，逐一寫入每個 QC Item × FactorNo／FactorValue 組合；無 Factor 時，每個 QC Item 寫一列 `FactorNo='NA'`。符合 Main 的 QC Item 列附 `Main='1'`。Core 對每一列分別執行 INSERT，未在此方法中建立整組交易；舊 SQL 以字串串接條件與值。

Service 的 `DelMonthRPTCodeBasis` 只要求 ReportNo。Service 內 QCItemNo／FactorNo 的 XML 解析已註解，Form 編輯／刪除結果是刪除該 ReportNo 全部列。Core 依 ReportNo 組 DELETE，並將單一 SQL 交給 `ExecuteSQLNoneQuery_UPD`。舊 Form 編輯先刪後加，若後續新增失敗可能留下整組缺資料；多個 ReportNo 刪除亦逐組呼叫，可能部分成功。正式端應採單一交易的 aggregate replace/delete。

## 資料表與 DDL 狀態

目前在此 repo 的 `database/reference`、SQL／Markdown 參考及可讀來源中，找不到 `TBLSPCMONTHRPTCODE` 的 Oracle DDL、欄位 metadata 或 PostgreSQL CREATE-only。桌機的受保護 Oracle MESTEST profile 不可用，本次沒有連 Oracle，也沒有猜型別、長度、NULL、DEFAULT、主鍵、索引或 FK。

從可讀 Core SQL 僅能確認程式使用下列欄位：`ReportNo`、`QCItemNo`、`FactorNo`、`FactorValue`、`Main`。這只是程式讀寫線索，並非完整 schema。特別是 Main 在未命中主項時不一定寫入、FactorValue 對 `NA` 列不寫入，需用可信 DDL／metadata 確認實際 nullable/default 規則。

家用端先核對 YMES live schema 和既有 migrations；要求公司端以受保護 Oracle MESTEST 唯讀取得 `TBLSPCMONTHRPTCODE` 的原生 DDL、columns、constraints、indexes。可靠 metadata 到手前不建立猜測 migration／CREATE-only。不要將 Oracle 的動態 Additional 欄位機制照搬成任意 SQL 欄名。

## 家用端 API／schema handoff

- 先確認是否已有可用的 `TBLSPCMONTHRPTCODE` schema 與來源鍵／約束；比較時不得以此文件列出的使用欄位取代 Oracle DDL。
- 建議登入及 SC302 權限保護：`GET /api/spc/monthly-report-codes` 回 ReportNo、QC Item、Main、Factor；`GET /api/spc/monthly-report-codes/options/qc-items` 回 ChartControl=1 且 IssueState 為 2 或 -1 的 Variable QC Item；依 QCItemNo 提供 Factor metadata／參照值 lookup；`POST /api/spc/monthly-report-codes` 新增；`PUT /api/spc/monthly-report-codes/{reportNo}` 原子替換整組；`DELETE /api/spc/monthly-report-codes/{reportNo}` 整組刪除。
- POST／PUT 的伺服器驗證 ReportNo 唯一性、QC Item 存在及可用狀態、Factor 屬於所選 QC Item／有效 MES Parameter、Main 僅為所選 QC Item 之一；參數化所有值，FactorNo 只能由伺服器 metadata allowlist 解析，不接受用戶端傳 table／column／condition SQL。
- Factor 為空時，先確認正式 schema 是否仍使用 `FactorNo='NA'` sentinel；一個 ReportNo 下多 QC Item 的 Main／factor mapping 需由 aggregate 契約明確保存。用資料庫交易替換全部關聯，並保留 audit／concurrency 欄位（若來源 schema 有定義）。
- SC303 月報表須能讀取同一 ReportNo 的 QC Item、Main 和 Factor 條件；請與 SC303 一併確認查詢契約與多 QC Item 語意。
