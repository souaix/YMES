# SC401 未解除異常單（SPC）

## 來源與定位

- 選單：SPC 管制 → 未解除異常單（SPC）；`FunctionNo=SPC ERF UNRELEASED`、`FunctionKey=SC401`。Vue DEV 路徑 `/YMES/SPC/ErfUnreleased`。
- 標準主畫面：`D:\iMES\CSiMES\STD\MESWin\SPC\SC_ERFUnReleased\frmSPC_ERFUnReleased.vb`。Form 與 Designer 程式碼同檔；處置子畫面為同目錄 `frmSPC_ERFDisposition.vb`。此為標準 SPC 畫面，不是 WIP 的 THEIL 客製版。
- 查詢：`wsWIP.LoadERFBasisJoinLotBasis` → `kcWIP.clsLot.LoadERFBasisJoinLotBasis`。SPC 欄位 lookup 使用 `wsSPC.LoadERFFieldValue`／`LoadERFLotNo` → `kcSPC`；另外由 `wsQC`、`wsMTL`、`wsOP`、`wsENT` 載入分類、材料、供應商、作業站、客戶和處置群組。
- 處置子畫面呼叫共用 `wsWIP.Exe_ERF_Disposition`、`Exe_ERF_BackToERFDisposition`、`Exe_ERF_LotRelease` 及 `LoadERF*` 方法；核心交易在 `kcWIP.clsLot`。ERF Info 由 ObjectFileHandler 開啟共用 `WP_ERFInformation`。

## 主畫面與查詢

畫面有 Query、Result、狀態列與 Close。九組條件均以 checkbox 啟用：Lot No、Customer No、OP No、MClass No、Cur Group、ERF No、Material No、Vendor No、Product No。Lot No 沒有有效 lookup；其他欄位可用 `...` 開啟對應清單。沒有日期條件。Form 固定傳 `Status=0|1|2|3|11` 與 `ERFSource=1|2`，也就是 SPC 異常單和收料異常單；主查詢不限制 ERFType。

Core 查 `TBLWIPERFBASIS`，左聯 `TBLWIPLOTBASIS`、`TBLWIPLOTSTATE`、`TBLPRDPRODUCTBASIS`、`TBLOPBASIS`、`TBLMTLMATERIALBASIS`、`TBLMTLMATERIALVENDOR`、`TBLENTCUSTOMERBASIS`，並對批次異常拆成有／無 `TBLWIPERFBATCHLOT` 的兩段 `UNION ALL`。Lot No 對一般 ERF 和 BatchLot 成員都做 contains；OP、Customer、ERF、MClass、Product 為 exact。LotState 是左聯，這支 SC401 查詢沒有 WP509 的 `LotState.Status IN (3,31)` 條件。Oracle 與非 Oracle 的 ProductName 版本聯結條件也不同；家用端應採 YMES 正式 schema 的明確版本鍵。

Form 會送 MaterialNo、VendorNo，但 `wsWIP.LoadERFBasisJoinLotBasis` 沒有解析這兩個 XML 欄位，也沒有傳給 Core；所以舊版查詢實際忽略這兩個條件。SC401 DEV 仍依畫面意圖套用 Material/Vendor 篩選，頁面提示與本規格記錄此差異。ProductNo 則有傳入 Core；Form 的條件誤檢查 checkbox 標籤文字而非輸入值，勾選後即送欄位，空值在 Core 不形成篩選。

Core 將查詢條件直接串接 SQL，沒有列數上限或分頁。家用端應參數化文字條件、限制可查範圍與回傳筆數，並明確保留批次異常以任一成員命中的語義。

### Result Grid

可見欄位依序為：ERF No、Lot No、Customer Lot No、ProductNo、ProductName、Status、OPNo、OPName、CustomerNo、MClassNo、MaterialNo、MaterialName、VendorNo、VendorName、HoldDescription、CurGroupNo、DispDescription、RuleNo、CreateQty、ScrapQty、Cal Hold Time、Priority、Attach File。CustomerName、CreateDate 等 Core 欄位在原 Form layout 中隱藏；預設依 ERFNo 升冪。Status 顯示文字為 ERF Undisposition（0）、ERF Wait Disposition（1）、Notice Customer and Wait Disposition（2）、Waive（3）、Wait Lot Disposition（11）。

每列 Attach File 按鈕以 `ERFNo.pdf` 呼叫 `wsWIP.GetERF_AttachFile`，限定附件 `Status=1` 後開啟檔案。DEV 只提供附件入口提示，沒有讀取或保存真實檔案。

## 主畫面按鈕與處置

- **ERF Disp**：選一列後開標準 `frmSPC_ERFDisposition`。一般 ERF 檢查登入者是否屬於目前 CurGroupNo；逗號分隔群組有任一個符合即可。OCAP ERF 先載入未完成 OCAP state；And/Or 群組可再選節點。主 Form 會載入最後處置群組狀態並傳入子畫面。
- 子畫面在 Status 0/1/2/3 啟用 ERF Disposition、停用 Lot Disposition；Status 11 則相反。一般可選 Next Group、Notice Customer、Final Disposition；Waive 預設隱藏，來源只在 VISERA 客製分支顯示。確認前要求 Disp Description，Next Group/聯絡人/最後群組依類型必填，然後呼叫 `wsWIP.Exe_ERF_Disposition`。Hold Reason、附件、OCAP 結果和群組流程會隨選項一併處理。
- Status 11 的標準 Form 只提供 Back to ERFDisposition、Go、Go Scrap Inventory 三種單選；Go Scrap Inventory 必須選 Inventory。`CreateERF=0` 或有 OCAP state 時 Back 不可用。Go／Scrap Inventory 由 `wsWIP.Exe_ERF_LotRelease` 處理，Back 走 `Exe_ERF_BackToERFDisposition`。收料來源 `ERFSource=2` 會以 MO Component 清單選元件；其他來源在 Lot 已有現況時載入 Lot Component。VISERA 會把 Go/Scrap Inventory 文字改成 Accept/Reject。
- **ERF Info**：開共用 WP_ERFInformation 五頁資料；細節沿用 [異常單資料](../WIP/異常單資料.md)。
- **ERF Abort**：Designer 設為 `Visible=False` 且 `Enabled=False`；Form 沒有 ERF Create 按鈕。隱藏的 Abort handler 雖組出 request，呼叫服務的程式碼仍被註解，之後直接解析舊 `OutXml`。此入口目前不是可用流程，不納入 DEV。
- **Close**：關閉功能頁。

## 正式端第一階段：唯讀查詢

- Migration `0070_spc_erf_unreleased_read.sql` 依 repo 既有 MES 來源 DDL 建立空的 `TBLWIPERFBASIS`、`TBLWIPERFBATCHLOT`、`TBLWIPLOTBASIS`、`TBLWIPLOTSTATE`、`TBLMTLMATERIALVENDOR`，只授予 `ymes_app` SELECT。migration 前先做 PostgreSQL custom-format 備份並用 `pg_restore --list` 驗證；migration 已於 2026-11-24 套用，欄位目錄與 SELECT-only 權限已讀回。未匯入 MES 業務資料。
- API：`src/YMes.Api/Quality/Qc401SpcErfUnreleasedController.cs`，`GET /api/spc/erfs/unreleased`（正式完整路徑 `/YMES/API/api/spc/erfs/unreleased`）。控制器要求登入；伺服器固定 `ERFSOURCE IN (1,2)`、`STATUS IN (0,1,2,3,11)`，九個條件都以參數傳入，Lot No 可命中一般 ERF 或任一 BatchLot 成員。查詢使用 Repeatable Read／READ ONLY snapshot，預設每頁 100 筆且上限 100 筆；排序依 ERFNo。
- Vue：沿用本元件，正式環境使用 `apiBaseUrl` 呼叫 API；條件勾選、Query、分頁及結果列選取可用。正式頁只支援查詢；ERF Disp、ERF Info 與附件檔案操作仍停用，不能將 DEV localStorage 假資料當作正式交易。
- 目前正式 API 使用全站登入保護；FunctionNo/角色 ACL 尚未接入此端點。遠端來源表目前是空結構，因此正向有資料列結果要等有核准測試資料後補驗。
- Lot Basis 以 ERF LotNo 對應 `BASELOTNO`，產品名稱依該 Lot 的 ProductNo／ProductVersion 查找；這個第一階段欄位映射尚待有資料列時與原 MES 查詢結果逐欄比對。

## Schema 與家用端 API handoff

SC401 沒有專屬新業務表。查詢所需主 ERF／BatchLot／Lot／產品／OP／材料／供應商／客戶表已有 repo 共用來源或 PostgreSQL CREATE-only references：QC409、WP101、PRD、OP、MTL、Customer refs；附件與 Lot Disposition 沿用 WP501、WP508Info。`TBLWIPERFDISPOSITION` 已有 Oracle source DDL（`database/reference/mestest_qc409_wip_disposition_dependencies_source_ddl.sql`），repo 原先缺 PostgreSQL CREATE-only，本次補 `database/reference/mestest_wip_erf_disposition_create.sql`。它只作結構參考，不代表 YMES PostgreSQL 已建立；家用端先核 live schema 與 migration history。

建議正式端提供：

- 受 `SPC ERF UNRELEASED` Function ACL 保護、有限筆數且可分頁的 `GET /api/spc/erfs/unreleased`；伺服器固定範圍為 ERFSource 1/2、Status 0/1/2/3/11。支援畫面九欄條件並在參數化查詢中修復 Material/Vendor Service 漏傳問題。
- `GET /api/spc/erfs/{erfNo}/disposition-context` 取 ERF、批次成員、Lot/Component、OCAP、目前群組與最後群組判定。每次寫入時由伺服器重新檢查登入者群組、Function ACL、ERFSource/Status、LotStamp、OCAP 節點及 CreateERF。
- 將 `POST /api/spc/erfs/{erfNo}/dispositions`、`POST /api/spc/erfs/{erfNo}/lot-release`、`POST /api/spc/erfs/{erfNo}/back-to-disposition` 明確分開；Lot Release 只接受本標準畫面的 Go 0／Scrap Inventory 7，附件和 Hold Reason 使用受限大小的專用 API。ERFInfo 可沿用 WP508 shared read API。
- Core 以 SQL 字串串接且缺查詢上限；Lot／ERF／Disposition／Hold Reason／附件更新需由家用端核 live schema 後用參數化查詢、expected state/row lock、冪等鍵和單一交易實作。涉及 OCAP 或外部通知時，回覆需區分資料交易與通知成敗，不能回報假成功。

處置／Lot Release／Back、Hold Reason、OCAP、ERF Info 與附件下載仍需按來源規格逐項核對現有 YMES schema 與副作用後實作；禁止以 DEV 假操作取代正式交易。它們不屬於已交付的唯讀查詢範圍。
