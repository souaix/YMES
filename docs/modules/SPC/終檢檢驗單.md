# SC104 終檢檢驗單（FQC FORM）

## 選單與來源

- 選單識別：Module `SPC`、FunctionNo `FQC FORM`、FunctionKey `SC104`、Form `frmFQCForm`、ExecutionFile `SC_FQCForm.dll`，分類 `SPC管制`。
- 主 Form／inline Designer：`D:\iMES\CSiMES\STD\MESWin\SPC\SC_FQCForm\frmFQCForm.vb`；新增／編輯／複製定義 Form／inline Designer：`frmFQCFormDef.vb`；另核對 `frmFQCFormQCItemMap.vb`。
- Service：`STD\MESws_STD\wsSTD\wsSPC\wsSPC.cs` 的 `LoadFQCForm`、`AddFQCForm`、`EditFQCForm`、`DelFQCForm`、`SetFQCFormStatus`、`LoadFQCFormQCItemMap`、`AddFQCFormQCItemMap`、`UpdFQCFormQCItemMap`、`DelFQCFormQCItemMap` 與 `funQC_Update`；定義畫面另呼叫 `wsPRD.LoadPRDQCItemLotValid`、`wsWIP.LoadLotBasisJoinState`、`wsPRD.LoadPRDOP`、`wsSYS.GetFQCFormNo`。
- Core：`STD\MESkc\kcSPC\clsSPC.cs` 的 `LoadFQCForm`、主單 CRUD、QC Item Map CRUD 與 `UpdFQCFormQCItemMapResult`；`STD\MESkc\kcBasis_UPD\clsBasis_UPD.cs` 的 `SetFQCFormStatus` 以 `DataStamp` 條件更新並更新 `Reviser`／`ReviseDate`。

## WinForms 狀態與互動

- 主 Form 以 Status 分成 5 個頁籤：0 未確認、1 待檢、2 檢驗完成、3 允收、4 拒收。各頁有對應單據清單及 QC Item 明細；清單顯示終檢單號、批號、產品、產品名稱、版本、工序、數量、客戶、檢驗文件及建立／修改欄位。查詢視窗可勾選建立日期並指定起訖時間；Service 的 `LoadFQCForm` 還支援單號、批號、產品、工序、客戶、版本等篩選參數。
- 未確認頁可 Add／Edit／Copy／Delete／Confirm，並維護 QC Item Map。Def Form 欄位包括 QCFormNo、ProductNo／ProductName、OPNo、ProductVersion、LotNo、CustomerNo、Qty、InspDocLink；依產品／版本／工序載入產品 QC Item，輸入 Lot 時可查 Lot 狀態並帶入產品、工序、版本、客戶及數量。`wsSYS.GetFQCFormNo` 使用 `FQCFORMNO` 序號類型；新增及編輯呼叫 FQC 專屬 Service。
- Confirm 前必須有 QC Item，且只可確認目前 Status=0 的單據；狀態更新帶 `DataStamp`。待檢頁選取尚未完成的 QC Item 後可進入 SPC 檢驗，寫回 Item 結果、SPC Serial 與完成狀態。所有 Map Item 完成時 Core 將主單 Status 設為 2 並寫 FinishTime。待檢頁的 `Del` 僅在尚無 Map Item 開始檢驗時啟用，執行的是刪除主單及 Map，不是退回未確認；已開始檢驗後不能刪除。
- 檢驗完成頁可 Receive／Reject；Workflow 使用 `funResultCallBack`，TIPTOP／WFGP／T100 等 `CallBackType` 分支會呼叫 `funQC_Update`，以 FQC 類型、ERP 來源單號／序號、產品及允收／拒收數回寫外部系統。外部成功後才更新 MES Status 為 3 或 4。此 Form 的 callback 分支會按全數 Qty 允收或拒收，沒有在 FQC 主畫面輸入拆分數量。
- 五個狀態頁均提供 Copy 入口。`Reviser`／`ReviseDate` 是 `SetFQCFormStatus` 狀態異動時由 Service 寫入的稽核欄位；WinForms 沒有獨立的複判按鈕，Vue 不可自行新增該狀態操作。

## Vue DEV 頁與簡化界線

- 路由 `/YMES/SPC/FinalQCForm`，選單名稱「終檢檢驗單」；正式環境只顯示未開放提示。
- DEV 提供五個 Status 頁籤、關鍵字及建立日期篩選、單據清單、FQC 欄位明細與 QC Item Map。未確認單可新增、編輯、複製、刪除、確認，以及加入／移除 QC Item；以 DEV Lot fixture 帶入產品、工序、版本、客戶、Qty 和該產品預設 QC Item。單號為假序號。
- 待檢頁可選取一項 QC Item 模擬 SPC 判定（合格／不合格／警示）、備註及 SPC Serial；全項完成後自動進入檢驗完成。尚未開始任何 QC Item 才可刪除待檢單；狀態不會退回未確認。檢驗完成可模擬允收／拒收；狀態轉換會更新 DEV 的 `Reviser`／`ReviseDate` 稽核欄位。
- DEV 主單、產品／工序／Lot／QC Item、DataStamp、SPC Serial、ERP callback 與回寫結果皆為本頁記憶體假資料；不呼叫 MES Service/API、SPC 量測、Oracle／PostgreSQL、WIP、ERP 或 Workflow。Keyword 篩選為本機便利功能；WinForms 主畫面實際查詢條件主要由勾選的建立日期範圍傳入。DEV callback 只提示模擬成功，不表示外部交易完成。
- DEV 對 DataStamp、狀態及 Qty 僅作 UI 範例檢查，不代表 server 驗證或交易保證。未實作 ERP serial reservation、產品／工序／Lot 有效性查核、產品 QC Item eligibility、SPC rule／儀器、ERP／sQMS callback、timeout 對帳、重送及跨服務補償。

## 資料表、Oracle metadata 與家用端 handoff

- `clsSPC.LoadFQCForm` 直接查 `TBLSPCFQCFORM`，另 Left Join `TBLENTCUSTOMERBASIS` 取得客戶名稱及 `TBLWIPLOTBASIS` 取得工單資料；QC Item 對應使用 `TBLSPCFQCFORMQCITEMMAP`。結果更新會寫 Map 的 Status／Result／SPCSerial，最後一個待檢 Map 完成時更新主單 Status／FinishTime。
- repo 有 `database/reference/mestest_qc216_spcf_qc_item_map_source_ddl.sql` 及 `database/reference/mestest_qc216_variable_item_group_pmi_create.sql` 的 Map source／PG CREATE reference；Map 欄位含 QCFormNo、QCItemNo、QCItemName、QCItemType、Status、Result、SPCSerial，複合主鍵為 QCFormNo／QCItemNo。家用端先比對 live schema／migration 再沿用，不重複建表。`TBLSPCFQCFORM` 主表沒有同版 Oracle DDL／metadata 或 PostgreSQL CREATE-only reference。
- 桌機受保護 Oracle attachment/profile 路徑不存在；本次未連 MESTEST、未以 Core SQL 推測 FQC 主表欄位／鍵，也沒有產生主表 CREATE SQL。家用端 Pull 後先核對 live schema／migrations；取得同版 Oracle dictionary metadata 後才建立必要的 CREATE-only schema，並逐項確認主表欄位、主鍵、索引、FK、DataStamp 及 callback 欄位。
- 正式 API 需由 server 驗證登入／FunctionNo 權限、產品／工序／產品版本／Lot 狀態、QC Item 適用性、FQC 單號配置與 DataStamp compare-and-set；使用參數化且限量的查詢。新增主單與初始 Map、編輯、刪除主單及 Map、Confirm／退回、逐項 SPC 結果與最後項目自動完成，需明確交易邊界。Receive／Reject 的 ERP callback 不應與 MES transaction 假設原子；保存 idempotency key、callback request／response／狀態與重試／對帳結果，只有確認外部成功後才改 MES 狀態。
- 公司桌機只交付 DEV UI 與 API／schema handoff，不連 YMES PostgreSQL、不實作或驗收正式 API／schema、不設定 `ConnectionStrings__YMes`。
