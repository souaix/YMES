## WinForms 條件與畫面

- Form Load 預設 `rdoQCVariable.Checked=True`；Variable／Attribute 兩個 RadioButton 都設為 `Visible=False`，所以目前畫面實際可操作的類型是 Variable。Attribute lookup、Grid 與事件程式仍存在，但在此 Form 的目前 UI 不可達；DEV 只呈現 Variable，若正式要開放 Attribute，應列為明確的行為變更。
- QC Item、Product、Customer、Material、Vendor 均由 lookup 選擇。QC Item lookup 使用 Variable QC Item，選取清單限 `IssueState=2` 或 `-1`。其他 lookup 於 Form Load 載入 Product／Customer／Material／Vendor basis，選擇清單同樣限 2 或 -1。畫面欄位顯示名稱，傳給 Service 的是選取項目代碼。
- 每個 lookup 前的 CheckBox 用來清除該條件的顯示值；選擇 lookup 時會勾選並填入名稱。查詢是否帶條件是依文字欄位是否空白判斷，不是直接讀 CheckBox。
- From Query Date 預設為兩個月前再加一天的 00:00:00；End 預設為當日 23:59:59。初始化時先勾後取消，故兩個日期條件預設都不啟用。日期只在資料重建後由 Form 篩選。
- Query 不要求必填條件、不檢查日期起迄先後，也沒有結果筆數上限。Close 關閉頁面。

## Service／Core 查詢與歷程重建

1. Form 的 `funLoadQCChartBasis` 僅在文字欄位非空時，把 QCItemNo、ProductNo、CustomerNo、MaterialNo、VendorNo 傳給 `wsSPC.ShowControlChartLineData`。雖然 Service 能解析 `FromDate`／`EndDate`，此 Form 沒有把日期送入 XML。
2. Service 將條件傳入 `kcSPC.ShowControlChartLineData`。Core 先讀 `TBLSPCQCCHARTBASIS` 欄位，再以 `TBLSPCQCCHARTBASIS A JOIN TBLSPCQCCHARTDETAILLOG B ON A.FACTORSERIAL=B.FACTORSERIAL` 取管制圖及歷程，最後只依 `STARTTIME` 排序。條件以字串串接 SQL。
3. Product、Material、Vendor 條件會先確認 Basis 有 `PRODUCT`、`MATERIAL`、`MTLVENDOR` 欄位再套用。Customer 分支檢查欄位 `CustomerNo`，但 QC302 source DDL 的 Basis 欄位是 `CUSTOMER`；在該 schema 下檢查不成立，Customer 條件不生效。若另有特定環境欄位差異，需以其 metadata 確認。
4. Form 依 FactorSerial 組織歷程；只處理 `US/CS/LS/UCL/CL/LCL` 至少一個非 Null 的列。它逐列呼叫 Core `Load_Check_StartTime`，查同一 FactorSerial 是否有更早的 `STARTTIME`。沒有較早資料時標為「新增」，並顯示該列的規格／管制線值。
5. 有較早資料時，Form 將目前列與迴圈中的前一列比較：`US/CS/LS` 差異產生「規格修改」，`UCL/CL/LCL` 差異產生「管制線修改」。同一個 snapshot 可產生兩種結果。舊程式的 `Old_ROW` 沒有依 SPCID 配對，且遇到多 SPCID 同時間或跨圖別時可能比較到不同圖的上一列；Core 的排序也沒有 tie-breaker。正式實作需決定是否保留此舊差異，或按 FactorSerial＋SPCID＋STARTTIME 穩定比較並記錄修正。
6. SPCID 顯示名稱為 0 Trend、1 Xbar、2 R、3 S、4 Rm。結果列以 Creator、StartTime、Product／Customer／Material／Vendor 名稱、線上 Factor 欄位、QC Item、圖別、變更值與 Memo 組成；Grid 隱藏 FactorSerial。Factor 欄位由 `wsQC.ShowQCItemFactor` 的 `FACTORONLINE='Y'` 欄位動態建立，Variable 分支略過名稱為 MEMO 的 Factor。
7. `funCheckTime` 在歷程重建完成後用嚴格 `RecordDate > FromDate`、`RecordDate < EndDate` 篩選。日期不影響 Core 查詢，也不是含端點條件；無日期時回傳來源可查到的完整歷程。

## Vue DEV 頁

- 路由：`/YMES/SPC/ChartLineEditLog`；選單鍵：`function:SPC:CHART LINE EDIT LOG`。
- 以 DEV fixtures 模擬 Variable QC Item／Product／Customer／Material／Vendor lookup、來源預設日期、勾選日期、Query、按新增／規格／管制線類別重建的唯讀 Grid。支援 FactorOnline 欄位展示；FactorSerial 仍在結果 Grid 隱藏。
- 為避免將錯誤的跨 SPCID 比較偽裝成正確業務規則，fixture 每個 FactorSerial 只放一種 SPCID；因此沒有示範舊程式在多 SPCID 歷程的比較缺陷。畫面資料、查詢與變更重建都只在記憶體執行，不呼叫 Oracle、Service、正式 API 或 YMES PostgreSQL。
- DEV lookup 是固定清單，不代表實際登入者可用的 lookup；沒有新增 Attribute 選擇、修改、刪除、匯出或列印流程。

## YMES 正式 API 與頁面

- `GET /api/spc/chart-line-edit-log` 是登入保護的唯讀端點；頁面依目前環境的 API base URL 呼叫，使用 cookie session，沒有直接連資料庫。查詢條件為 QCItemNo、ProductNo、CustomerNo、MaterialNo、VendorNo、FromDate、EndDate、Page、PageSize。主檔條件輸入代碼；空白代表不限制。
- 查詢用固定 SQL 與參數讀取 Basis、QC Item 名稱及 Product／Customer／Material／Vendor 名稱。Customer filter 對應 `TBLSPCQCCHARTBASIS.CUSTOMER`。Factor 欄位只從該 QC Item 的 `TBLQCITEMFACTOR.FACTORONLINE='Y'` metadata 取允許清單；從 `factorvalues` JSONB 取值，不把 FactorNo 串成 SQL 識別字。
- 每次依 `(FactorSerial, SpcID, StartTime)` 排序，按 `(FactorSerial, SpcID)` 保存前一筆 snapshot。首筆非空界限列為「新增」；US／CS／LS 變動列為「規格修改」；UCL／CL／LCL 變動列為「管制線修改」，同一 snapshot 可產生兩列。此處修正舊 Form 沒依 SPCID 配對的錯誤，並保留日期嚴格排除端點的舊行為。
- 日期先在伺服器完成歷程重建後過濾，再按穩定排序分頁；前一筆 snapshot 不受頁碼或日期條件影響。限制為 250 組 chart、30,000 筆 timeline、366 天（雙端都有日期時）、20,000 筆結果、每頁最多 100 筆；超限回傳明確錯誤，避免回傳不完整或分類錯誤的結果。
- 正式頁以唯讀表格呈現；QCItemNo、ProductNo、CustomerNo、MaterialNo、VendorNo 欄位輸入代碼，日期條件預設關閉，按 Query 才呼叫 API。分頁由 API 回傳總筆數與頁數。
- API 套用全域登入驗證。現有 YMES API 專案尚未提供可共用的 FunctionNo ACL 驗證服務；權限角色不在本次交接範圍內。
