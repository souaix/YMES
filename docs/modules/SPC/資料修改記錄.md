# SC203 資料修改記錄

## 範圍與來源

- Function：`DATA EDIT LOG`，FunctionKey `SC203`，Form `frmQueryDataEditLog`，ExecutionFile `SC_QueryDataEditLog.dll`。
- WinForms／inline Designer：`D:\iMES\CSiMES\STD\MESWin\SPC\SC_QueryDataEditLog\frmQueryDataEditLog.vb`。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsSPC\wsSPC.cs`，`LoadSPCDataHistory`。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcSPC\clsSPC.cs`，`LoadSPCDataHistory`；歷程寫入由 `AddSPCVarDataEditLog`／`AddSPCAttDataEditLog` 執行。

## WinForms 查詢規則

- 先選 QC Type：Attribute 或 Variable；QC Item 為單選且可空白，lookup 只列 IssueState 2 或 -1。From／End Date 各自可勾選，初始值為近兩個月區間但預設未啟用。Editor 可空白，lookup 依 QC Type 從相應 edit log 表取 distinct USERID。
- Query 送 `QCItemType` 必填；QCItemNo、FromCreateDate、EndCreateDate、Editor 為選用條件。無結果時顯示提示；有資料時將回傳 DataHistory 綁到唯讀 Grid。
- 計數查詢讀 `TBLSPCATTEDITLOG`，計量查詢讀 `TBLSPCVAREDITLOG`。Core 篩選 `QCItemNo IS NOT NULL`，支援 QC Item、RecordDate 範圍、USERID，並依 SPCSerial／RecordDate 排序。Editor lookup 以 `UserQuery=1` 只取 distinct USERID。
- Grid 顯示資料表欄位並特別格式化 `RECORDDATE`。記錄包含 UserID、RecordDate、SPCSerial、QCItemNo、LotSerial、OriginalValue、NewValue、Description、LogGroupSerial。SC201 的修改／刪除流程透過 AddSPC*DataEditLog 記下原值、新值、描述、批次 LogGroupSerial；刪除記錄的 NewValue 可為空。這個 Function 本身不寫入，也沒有編輯／刪除操作。
- 來源 SQL 沒有分頁或結果上限，也以字串串接使用者條件；正式 API 必須改用參數化查詢與結果限制。

## 特定企業分支

- 當 EnterpriseNo 為 `VISERA`、QC Type 為 Attribute 且 QCItemNo 是 `IQC`／`IPQC`／`OQC` 時，Form 改呼叫 `LoadSPCDefectCodeLog`，並停用 Editor 選擇；這不是兩張 edit log 表。Core 查 `tblWIPCont_DefectcodeOld` 並 join `TBLSPCATTBASISLOG`，依 SPCSerial、QC Item、CreateDate 排序。
- 公司端 DEV 只做一般計量／計數 edit log。VISERA 專用舊缺陷碼畫面未在目前公司端環境驗證，正式支援前需先確認該企業分支、table DDL／metadata 及所需欄位；其中 WIP Cont 缺表也記於 [SC201 規格](SPC資料維護.md)。

## Vue DEV 頁

- 路由：`/YMES/SPC/DataEditLog`，選單鍵 `function:SPC:DATA EDIT LOG`。
- 以頁面記憶體中的 DEV fixtures 模擬 QC Type、Issue／Stop QC Item、Editor、可選日期區間、Query、歷程 Grid 與唯讀前後值明細。切換 QC Type 會清除 QC Item／Editor／既有結果；條件修改後要再次按 Query 才重新套用。
- 日期起迄同時啟用時，DEV 額外檢查起始值不得晚於結束值。DEV 不呼叫 Service、Oracle、YMES API 或資料庫；離開頁面後資料重置。

## DDL／metadata 與家用端 handoff

- 計數 Oracle source DDL／metadata：`database/reference/mestest_qc_item_attributes_source_ddl.sql`，`TBLSPCATTEDITLOG`。本次依既有 source DDL 產生 PostgreSQL CREATE-only handoff：`database/reference/mestest_qc_attribute_data_edit_log_create.sql`。此 SQL 未套用；原始 DDL 未見 PK、FK 或 secondary index。
- 計量 Oracle source DDL／metadata：`database/reference/mestest_qc205_variable_dependencies_source_ddl.sql`，`TBLSPCVAREDITLOG`；既有 PostgreSQL CREATE-only 在 `database/reference/mestest_qc210_variable_measurement_log_delete_create.sql`，不重複建立。
- 家用端先核對 YMES live schema／migration，只有缺表時再整理單一 forward migration；不得將 CREATE-only reference 當 migration 重跑。查詢 API 使用登入者 FunctionNo 授權、QC Type 白名單選擇兩表、參數化 QC Item／Editor／日期條件、分頁／最大筆數及穩定排序；Editor lookup 只回傳登入者可查的 distinct UserID，不暴露其他敏感欄位。
- 保留唯讀語意。確認 SC201 寫入的 `LogGroupSerial`、刪除時 OriginalValue/NewValue 空值約定及既有資料 nullable 行為；VISERA 舊缺陷碼查詢需另核其表來源與授權，不能直接納入通用 edit-log endpoint。
- 公司端未連 PostgreSQL、未建 migration／schema、未實作或驗收正式 API。
