## WinForms 狀態與互動

- 主畫面分七個狀態頁：0 未確認、1 待驗、2 檢驗完成、3 已接收、4 已拒收、5 特採、6 作廢。查詢使用建立日期起迄，可用 QCFormNo 條件；清單可檢視物料、進貨單、供應商、原供應商／批號、材料批號、數量及文件連結。
- 未確認可新增、編輯、複製、刪除及 Confirm。定義 Form 維護 QCFormNo、Material、Vendor、IncomingNo、MaterialLotNo、OriVendor／OriVenLot、InspDocLink、Qty；新單號依 `INCOMINGQCFORMNO` serial rule 取號。新增／編輯需物料且 Qty > 0。Copy 產生新手開單並重設建立者／建立時間；ERP CallbackType 不是由使用者建立表單帶入。
- Confirm 前必須有 Qty 筆元件明細，且元件號不得重複；成功後狀態由 0 轉 1。元件清單僅能在未確認維護。Excel 首頁以 `ComponentNo` 欄名定位；CSV 依來源資料欄次讀取；Paste 由剪貼簿填入。載入會取代當前未確認單的本機明細。儲存呼叫 `UPDIQCFormCompnentDetail`，Core 以 SQL collection 刪除該 QCFormNo 原明細後重插傳入元件號。
- QC Item Map 可依物料已核准 QC Item 選取，項目型態包含計數、計量及群組。待驗頁選取尚未完成項目後，以 QCFormNo 作 LotNo、Qty 作 LotCurQty、OPNo=`IQC`、SenderName=`IQCFORMCOMPONENT` 開啟 `SC_OnlineControl`；完成結果回寫 Map。最後一個 Map 完成後，Core 自動將 Header 設為 Status 2 並填 FinishTime。
- 待驗單只在全部 Map 尚未開始時可退回未確認；任一項目已開始則拒絕。未確認刪除只允許空 CallbackType 的手開單。來源可批次選取，本 DEV 以單筆選取操作。
- 檢驗完成可 Receive、Reject 或 Concession。依 ERP 設定顯示允收／退回數量時，兩數合計須等於 Qty。外部 callback 成功後才更新本機狀態 3／4／5；callback 失敗阻止本機轉態。`funQC_Update` 依 ERPQCFormType 分一般進料與 OS 流程，讀 CallBackType、ERP source、Material／Vendor／Lot 與數量；ERP 型態包含 TIPTOP、WFGP、T100、TIPTOPICD、E10ICD 等，狀態與來源分支應由正式端逐一核實。
- 檢驗完成後來源另依 OP 參數 `SPCInspAbnormalHoldLot`、QC Item 結果判斷是否呼叫 `WP_BRERFCreate` 建立異常單。這是 SPC／WIP 副作用，不由本 DEV 頁呼叫。Receive／Reject／Concession 的歷史單可 Revise；外部 callback 成功後寫複判日期並返回 Status 2。作廢頁只供查詢；本 Form 未找到將狀態設為 6 的操作。

## Vue DEV 行為及限制

- 完成 `/YMES/SPC/IncomingQCFormComponent` DEV 頁：七狀態、QCFormNo／建立日期篩選、Header Add／Edit／Copy／Delete／Confirm、元件清單 CSV／XLSX／貼上與逐筆維護、QC Item Map、SPC 假結果、收貨／驗退／特採 callback 成敗及 Revise。所有假單、DataStamp、元件號、Map、結果和 callback 都只存在頁面記憶體。
- DEV XLSX 解析沿用 `materialImportWorkbook` 的第一工作表 helper；CSV 取欄名 `ComponentNo`，無標頭時依元件欄位位置取值。原生 `.xls` 由舊 WinForms／Service 支援，但 DEV 不解析。Paste 簡化成每行一個元件號（或表格文字中的 ComponentNo 欄），不模擬舊 RTF 剪貼簿分支。
- DEV 用小數量 fixtures 展示 Qty 與元件筆數相等的守門；資料、單號、serial reservation、物料／供應商有效性、Map、SPC、ERP／sQMS callback、ERF 均不呼叫服務或資料庫。此頁不是生產交易驗收。

## 資料表、Oracle metadata 與家用端 handoff

- Core 使用三張直接表：`TBLSPCIQCFORMCOMPONENT`（Header）、`TBLSPCIQCFORMCOMPQCITEMMAP`（QC Item 對應）、`TBLSPCIQCCOMPONENT`（元件序號明細）；Header 查詢另 Left Join `TBLMTLMATERIALVENDOR`。本 repo 尚無這三張表的同版 Oracle source DDL、欄位／約束／索引 metadata 或 PostgreSQL CREATE-only reference。公司桌機受保護 Oracle profile 不存在，本次未連 MESTEST；不依 SQL 字串猜欄位型別、PK／FK／索引或產生 CREATE SQL。
- `DelIQCFormComponent` 的 Core SQL collection 刪 Header 與 QC Item Map，來源未見同時刪除 `TBLSPCIQCCOMPONENT` 明細，正式端需核對刪單是否留下孤兒明細並在 API 交易中明確清理。
- `UpdIQCFormComponentQCItemMapResult` 在 Core 對 Map update collection 執行後，再將 Header 完成 SQL 加入同一 collection 並再次執行；正式移植前確認 collection helper 行為，避免重複執行 Map 更新。狀態 Service 走 `clsBasis_UPD`，SQL 有 QCFormNo + DataStamp 條件並遞增 DataStamp；家用端需確認實際 affected-row／CAS 衝突回報。
- 家用端先從 YMES PostgreSQL live schema／migration 核對三張表及共用 QC／MTL／SPC 表；可靠 DDL 取得前不得建立猜測 CREATE。正式 API 需有登入與 SC108 Function 授權、限量日期／單號查詢、server 端 serial reservation、參數化 Header／Map CRUD、DataStamp CAS、元件明細原子整組取代、去重及 Qty 守門。Header／Map／元件明細的新增、刪除與 Confirm 需定義交易邊界；刪除時處理 component orphan。
- SPC 結果寫 Map 並將最後完成項目與 Header Status 2／FinishTime 原子化。ERP callback 要保存 idempotency、request／response、重試／對帳；外部成功但本機 CAS 失敗需補償。涵蓋 Receive／Reject／Concession、Revise、ERP incoming／OS 分流，以及 `SPCInspAbnormalHoldLot` → `WP_BRERFCreate` 的部分成功與補償。桌機只負責 DEV UI／規格，不連 YMES PostgreSQL、不實作或驗收正式 API/schema。
