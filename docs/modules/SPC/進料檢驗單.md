# SC103 進料檢驗單（INCOMING QC FORM）

## 選單與來源

- 選單識別：Module `SPC`、FunctionNo `INCOMING QC FORM`、FunctionKey `SC103`、Form `frmIncomingQCForm`、ExecutionFile `SC_IncomingQCForm.dll`，分類 `SPC管制`。
- 主 Form 及 inline Designer：`D:\iMES\CSiMES\STD\MESWin\SPC\SC_IncomingQCForm\frmIncomingQCForm.vb`；新增／編輯／複製定義 Form 及 inline Designer：`frmIncomingQCFormDef.vb`。另核對 `frmIncomingQCFormQCItemMap.vb` 與 `frmIncomingQCFormComponent.vb`；元件專用表單是獨立 SC108，本次不混併。
- Service：`STD\MESws_STD\wsSTD\wsSPC\wsSPC.cs` 的 `LoadIncomingQCForm`、`AddIncomingQCForm`、`EditIncomingQCForm`、`DelIncomingQCForm`、`SetIncomingQCFormStatus`、`SetIncomingQCFormQCRejudgeDate`、`LoadQCFormQCItemMap`、`UpdQCFormQCItemMap`、`DelQCFormQCItemMap`、`funQC_Update`；另用 `wsMTL` 物料／供應商／物料 QC Item、`wsSYS` 序號規則／ERP 設定、`wsOP` 工序與 QC Item lookup。
- Core：`STD\MESkc\kcSPC\clsSPC.cs` 的 Incoming QC Form 主表與 QC Item Map 查詢／新增／整組更新／刪除、檢驗結果回寫；`STD\MESkc\kcBasis_UPD\clsBasis_UPD.cs` 的 `EditIncomingQCForm`、`SetIncomingQCFormStatus` 以 DataStamp 參數更新資料。量測流程連動 `LoadLotSPCMeasureData`、SPC Serial 與 QC Item Map Result。

## WinForms 狀態與互動

- 主畫面按 Status 分為 7 個頁籤：0 未確認、1 待驗、2 檢驗完成、3 已收貨、4 已驗退、5 特採、6 作廢；每個主檢驗單列可顯示對應 QC Item 子清單。查詢可依檢驗單、來料單、物料、物料批號、供應商及建立日期範圍載入。
- 未確認頁支援 Add／Edit／Copy／Delete／Confirm 與 QC Item 對應維護。定義視窗可輸入檢驗單號、IncomingNo、物料、數量、供應商、原供應商／批號、物料批號、檢驗文件連結；物料 lookup 可載入該物料 QC Item，Vendor lookup 載入物料可用供應商。OPTIVTECH 有特定序號格式，其他環境可使用 Serial Rule 產號。由 ERP 回拋的單據禁止編輯／刪除。
- Confirm 將未確認狀態轉為待驗並帶 DataStamp 檢查。待驗頁依選取 QC Item 呼叫 SPC 量測；每一項完成後更新 QC Item Map 狀態、SPCSerial 與結果，所有項目完成後主單進入檢驗完成。若尚無 QC Item 完成，可退回未確認；已開始檢驗則不能退回。
- 檢驗完成頁可 Receive／Reject／Concession。若來源 CallBackType 要回報 ERP／sQMS 合格與驗退數，總數須等於檢驗 Qty；外部 callback 成功後才改主單狀態。收貨、驗退、特採頁提供 Revise 複判，另有作廢記錄查閱。ERP Workflow／TIPTOP／WFGP／T100／E10ICD 等分支各有不同 payload 及 callback 順序。
- `btnSPC` 會檢查選取 QC Item 狀態後開 SC101／SC102 類量測流程；`LoadLotSPCMeasureData` 顯示既有收集資料。ERP callback、ERP 設定、ERF 與回寫結果不屬單純表單狀態更新。

## Vue DEV 頁與簡化界線

- fallback 路由 `/YMES/SPC/IncomingQCForm`，位於品質資料／SPC 管制；正式環境只顯示未開放提示。
- DEV 頁可用 7 個狀態頁籤查假檢驗單，輸入搜尋字與建立日期、建立／編輯／複製／刪除未確認單、套用物料 fixture 帶出 QC Item、加入／移除 QC Item、確認到待驗、逐項模擬 SPC 完成、退回尚未開始的待驗單、輸入 ERP fixture 數量並模擬收貨／驗退／特採、記錄複判時間。
- DEV 的主單刪除／確認與資料列操作採單筆；WinForms 批次選取只在原 Form 支援處保留於規格，沒有在本頁模擬。
- 主單、QC Item Map、DataStamp、SPC Serial、供應商、ERP CallBackType 及狀態全為本頁 fixture；操作只變更記憶體資料，不呼叫 Service/API、Oracle／PostgreSQL、ERP／sQMS、SPC 量測、ERF 或 WIP。數量守恆／DataStamp 僅示範基本 UI 守門，不等同 server 驗證或正式交易結果。
- DEV 不實作各 ERP callback、sQMS、ERP serial reservation、客戶別 Additional XML、Material QCItem／Vendor eligibility、WIP lock／Lot，亦不重現 ERP timeout 對帳及跨服務部分成功補償。量測資料仍應由已交接 SC101／SC102 正式 API 流程處理。

## 資料表、Oracle metadata 與家用端 handoff

- Core 直接使用 `TBLSPCINCOMINGQCFORM` 主單及 `TBLSPCINCOMINGQCFORMQCITEMMAP` 品管項目對應；Load 另 Join `TBLMTLMATERIALVENDOR` 取得供應商名稱。物料／供應商／物料 QC Item lookup 及量測／回寫還有其自身的 Master、SPC、ERP／WIP 相依，家用端須沿 callback 與量測分支逐一盤點。
- repo 有 `database/reference/mestest_qc216_incoming_qc_item_map_source_ddl.sql` 和對應 QC216 PostgreSQL CREATE reference，可沿用作為 Map table 參考，先比對本功能欄位用途；沒有 `TBLSPCINCOMINGQCFORM` 同版 Oracle source DDL／metadata 或 CREATE-only。桌機受保護 Oracle attachment/profile 檔不存在，因此沒有執行 Oracle 查詢；未依 Core SQL 猜主表欄位、PK、索引或 FK，也未產生主表 CREATE SQL。
- 家用端 Pull 最新 main 後先比對 live YMES schema／migrations。取得可信主表 DDL／dictionary metadata 後才建缺表；對 Map table 先核對已存在 QC216 reference 與 live schema，不重複建立。正式 API 要驗登入與 FunctionNo 權限、物料／供應商／來料來源、ERP-owned flag、檢驗單狀態、QC Item eligibility、Qty、DataStamp 與伺服器序號規則，SQL 全部參數化並限制查詢筆數。
- Add 主單與初始 QC Item Map、Edit、批次 Delete、Confirm／退回、量測結果更新與 Receive／Reject／Concession 必須定義原子邊界。ERP／sQMS callback 不可與 MES 資料庫同交易時，保存 callback idempotency key、請求／回應／狀態與可重試步驟；未收到 ERP 成功回覆不可把 MES 狀態提前完成。稽核 DataStamp 需在服務端 compare-and-set，主單與 QC Item Map 不得信任瀏覽器送入的結果或 SPCSerial。
- 公司端只交付 DEV UI 和 API/schema handoff，不連 YMES PostgreSQL、不實作或驗收正式 API/schema、不設定 `ConnectionStrings__YMes`。
