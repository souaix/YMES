# IV306 在製貨架查詢作業

更新日期：2026-11-25。公司端核對 WinForms／Service／Core 並完成 Vue DEV 假資料頁；未連 YMES PostgreSQL、未實作正式 API/schema，Oracle MESTEST profile 不在本機，因此沒有新 DDL／metadata 或 CREATE SQL。

## 功能與入口

- 選單 FunctionNo／功能代碼：`STOCKER STATE`／IV306；Form `frmINVStockerState`，執行檔 `IV_StockerState.dll`。
- Vue DEV FunctionKey `function:INV:STOCKER STATE`，路由 `/YMES/INV/StockerState`，位於庫存管理／在製品庫。
- 功能查詢目前在製貨架上架內容，選取一筆後顯示該 Stocker 的格位；「Stocker In/Out」帶 StockerNo 開啟 IV305。

## WinForms 查詢與顯示規則

- Form 開啟時不自動查詢。StockerNo、AreaNo、LotNo、CarrierNo 初始皆不勾選；使用者可以按 Query 不帶條件讀取全部符合 Join 的現況列。
- StockerNo／AreaNo 由 Lookup 選取；舊 Lookup 以無條件 `LoadINVstockerStateJoinQtyLimit` 結果取 distinct 值，所以只列出目前有 Stocker State 的貨架／Area，空貨架不會出現在 Lookup。
- 條件只有「勾選且文字非空」才送 Service。StockerNo、AreaNo、CarrierNo 是精確比對；LotNo 用 Core `LIKE '%LotNo%'` 包含比對。欄位輸入非空時會自動勾選；取消勾選會清空欄位。按 Enter 將焦點移往下一欄。
- Core 查詢 `TBLINVSTOCKERSTATE A JOIN TBLINVSTOCKERBASIS B ON B.STOCKERNO=A.STOCKERNO`，只取 `A.STOCKERNO IS NOT NULL`；輸出 AreaNo、ContentNo、StockerNo、LocatorNo、LotNo、CarrierNo、CreateDate、QtyLimit。Form 將 CreateDate 欄名改成 `INVSTOCKERDATE`，客戶端排序 `StockerNo, LocatorNo`；Core 只排序 StockerNo。
- 選取結果列後，Form 另以無條件 Query 載入目前 State 供格位染色，並按 StockerNo 讀 `TBLINVSTOCKERDETAIL`。格位圖按 Detail 的 VerticalPosition／HorizontalPosition 放置按鈕：有內容為藍色、內容數達 QtyLimit 為紅色、目前選取 Locator 為綠色。
- 舊格位按鈕的 click handler 未掛接（`AddHandler` 及 handler 均註解），所以格位圖唯讀。格位內容／容量顏色基於全域現況資料，不受列表 Lot／Area 等篩選後的子集合影響。
- `Stocker In/Out` 在有選取資料列時呼叫 `ObjectFileHandler.Execute("IV_StockerManager")` 並傳 StockerNo。IV305 返回後會重新 Query，嘗試用 StockerNo、LocatorNo、ContentNo 找回列。

## 舊程式風險與 DEV 範圍

- Core SQL 將 StockerNo、LotNo、AreaNo、CarrierNo 以字串串接；查詢沒有分頁、列數上限或最小條件。舊 UI 可不帶條件拉完整現況。
- LotNo 用前後 `%` 包含搜尋，且 SQL 欄位未限定別名；Core 預設依 StockerNo 排序，無穩定的 Locator／Content 次排序。
- Stocker／Area Lookup 讀整份狀態 Query 後才 distinct；空貨架／空 Area 不能 Lookup。Detail 圖則讀獨立 `TBLINVSTOCKERDETAIL`，不只顯示查詢結果中已佔用的格位。
- Vue DEV 提供四項可選條件、查全部／清除、結果列選取、容量格位圖及 IV305 導頁；DEV 假資料包含空格與已佔用格位。IV305 導頁帶 StockerNo，讓管理畫面預選原貨架。
- DEV 只在本頁使用固定記憶體資料，不呼叫正式 API／資料庫；格位圖為唯讀。格位編號及維度是明示的展示 fixture，不能代替正式 Stocker Detail 查詢。未 build、test 或 browser 驗收。

## 資料表、Oracle references 與 Create SQL handoff

| 表 | 用途 | DDL／metadata 狀態 |
|---|---|---|
| `TBLINVSTOCKERSTATE` | 當前 Stocker／Locator／ContentNo、Lot／Carrier、建立時間 | 沿用 WP302 `mestest_wip_wp302_source_ddl.sql`、metadata 與 Create-only reference；以家用端 live schema 再核對 |
| `TBLINVSTOCKERBASIS` | AreaNo、QtyLimit 與貨架設定 | IV103 已標示可信同版 Oracle DDL／metadata 缺失；本機 Oracle profile 不存在，未猜 CREATE |
| `TBLINVSTOCKERDETAIL` | LocatorNo 與格位座標 | 可信同版 Oracle DDL／metadata 缺失；不從 Form 欄位推測 CREATE |

沒有新增表，因此本模組不提供 PostgreSQL CREATE SQL。家用端先核 PostgreSQL live schema／migration、IV103 reference 及 WP302 現況複合鍵；不可直接採用 IV103 中標為推測的 Basis／Detail schema。

## 家用端 API handoff

- 提供登入／Function ACL 保護的列表 API：StockerNo、AreaNo、CarrierNo exact filter，LotNo contains filter；伺服器參數化所有條件，空條件查詢預設加入列數上限／分頁，不允許無界全表回傳。
- 回傳排序應固定為 StockerNo、LocatorNo、ContentNo；日期使用 DB 時區／精度一致的 UTC 或明確時區契約。DEV / WinForms 的 `CreateDate` → `INVSTOCKERDATE` 顯示別名不應改變 API 欄位名稱。
- Stocker／Area Lookup 應使用權威 Basis／Detail API，能否包含空貨架與沒有上架內容的 Area 應由產品權限／範圍決定；不要以現況 Query 的 distinct 結果假裝完整貨架清單。
- 選列後應以 StockerNo 讀取 Detail 格位定義，與 State 內容作集合合併，包含空格；容量來源需確認 Basis／Locator 的正式欄位及限制語意後再提供。
- IV305 導頁只帶 StockerNo 作 UI 初始選擇；IV305 仍需 server 端重新載入 Stocker、Locator 與目前狀態，不把查詢頁選中的值視為授權或資料真相。
- Stocker State 可沿用 WP302 PostgreSQL schema reference；Basis／Detail 在 Oracle DDL／metadata 未核實前不新增 migration／CREATE。SQL 必須參數化且限制資料量。
