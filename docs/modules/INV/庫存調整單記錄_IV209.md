# IV209 庫存調整單記錄

更新日期：2026-11-25。公司端交付範圍：WinForms／Service／Core 行為核對、Vue 3 DEV 唯讀查詢及家用端 API handoff；未連 YMES PostgreSQL，未實作正式 API。

## 功能與入口

- 選單 FunctionKey：`MATERIAL ADJUST LOG`，功能代碼 IV209；舊 Form 為 `frmINVMaterialAdjustLog`，執行檔 IV_MaterialAdjustLog.dll。
- Vue DEV 路由 `/YMES/INV/MaterialAdjustLog`，只查庫存調整單記錄，不提供新增、修改、刪除或確認。
- IV204 是草稿維護；實際庫存調整仍由 IV201 Source=3 執行。IV209 的 `INV Date` 查的是該 Source=3 交易時間，不等於單純 Basis.ConfirmDate 欄位條件。

## 舊畫面與行為

### 查詢條件

- Form 啟動時只載入全體 MaterialAdjustNo 作為單號 Lookup，以及 `InventoryType=0` 的庫房清單；不會自動 Query，使用者按 Query 後才載入 Basis。
- 條件包含 MaterialAdjustNo 精確單號、InventoryNo、State（0 未確認、1 處理中、2 確認、3 失敗）、From／End CreateDate、From／End INV Date。日期控制項預設未勾選；只勾一側時 Core 以 2000-01-01 或 3000-01-01 補另一側，End 若只有日期則延伸至當日 23:59:59。
- `CreateDate` 篩 Basis.CreateDate。`INV Date` 以 `TBLINVTransactionLog` 中 `Source=3` 且 TicketNo 等於 MaterialAdjustNo 的 CreateDate 篩單；該欄位不是 Basis.ConfirmDate 的同義條件。
- 舊 Core 基礎查詢從 `TBLINVMATERIALADJUSTBASIS` 讀取 `MaterialAdjustNo Is Not Null`，其餘條件皆可不傳；沒有排序、分頁或筆數上限。FORM 的單號 Lookup 也先取全體 Basis。
- 單號及庫房按鈕開啟 `frmCOMSearch`。畫面只有 Query／Lookup／Close，沒有寫入或確認操作。舊 Grid 可自行排序／分組；Vue 為 DEV 可讀性將結果按單號排序。

### Basis、Detail 與 Component

- Basis Grid 顯示 MaterialAdjustNo、InventoryNo、ADJUSTTYPE、State、ConfirmDate、Description、Creator、CreateDate。ADJUSTTYPE 使用資料字典 ValueList；規格沿用 IV204：0 調帳、1 儲位調撥。
- 選取 Basis 後呼叫 `LoadINVMaterialAdjustDetail(MaterialAdjustNo)`。Detail 查詢左連目前有效且已發行的 `TBLMTLMaterialBasis`（`IssueState=2`）取 MaterialName，但 Form 隱藏 MaterialName。
- Detail Grid 顯示 MaterialNo、MaterialLotNo、LocatorNo、FinalLocatorNo、UnitNo、OrgQty、FinalQty、DiffQty；數量以小數格式呈現。元件展開列顯示 ComponentNo、DEV_CassetteNo、DEV_SlotNo。
- 舊 Core 的 Component SQL 以父單號過濾（若有傳入），會讀 MaterialLotNo、B_CASSETTENO、ComponentNo、SlotNo；但 DataRelation 僅以 MaterialNo 關聯明細與 Component。相同 MaterialNo 在同一單有多批號／儲位時，子列可能錯掛或重複顯示。
- Core 與 Service 的 Detail 單號參數可省略。若呼叫空單號，SQL 只保留 `MaterialAdjustNo Is Not Null`，會載入全體調整明細與元件；舊 Form 選取主檔時正常傳單號，但群組列或 Query 無 Basis 結果時會呼叫 `LoadDetail("")`，因此有實際全表讀取路徑。

## Vue DEV 復刻

- App 選單 FunctionKey `function:INV:MATERIAL ADJUST LOG`、路由 `/YMES/INV/MaterialAdjustLog`，原物料倉下接在 IV204 後。
- Query 面板提供單號／原料庫房 Lookup、State、CreateDate 與 INV Date 範圍；明確按 Query 才顯示結果，Clear 會清空條件並移除已載入結果。
- Basis 可選列載入 Detail；點選 Detail 顯示該列 Component snapshot。Fixture 覆蓋 0–3 四種狀態、調帳／儲位調撥、沒有交易日及 Source=3 交易日。
- DEV 以調整單號精確隔離 Detail 與 Component，不重現舊 Core 空父單號讀取全表，也以單據／料號／批號／儲位組成明細 key，避免舊 DataRelation 僅靠 MaterialNo 的錯掛。結果依單號排序是畫面簡化，不代表舊 SQL 有固定排序。
- 唯讀頁只使用虛構 fixture，不呼叫正式 API、不寫 localStorage，也不改庫存狀態。DEV 預覽未執行 build、test 或 browser 驗收。

## 家用端 API handoff

- 建立登入與 Function ACL 保護的唯讀列表 API，支援 MaterialAdjustNo、InventoryNo、State、CreateDate 範圍、Source=3 INV transaction date 範圍。日期端點只傳一側時由 API 明確補界限，End date inclusive；以參數化條件避免舊 Core 字串串接風險。
- 舊 Form 無條件 Query 會讀全部 Basis，Lookup 也會載入全部單號；正式 API 應要求至少一個條件，或設定安全預設、最大日期跨度、穩定排序及 bounded paging。
- Detail API 必須要求有效 MaterialAdjustNo，回傳 404／空集合語意固定，禁止空值查全表；Component 必須用 live PostgreSQL 複合主鍵／外鍵與父單號、料號、批號、儲位完整關聯，不照抄只用 MaterialNo 的 DataRelation。
- API 對外清楚區分 Basis.ConfirmDate 與 Source=3 TransactionLog.CreateDate；MaterialName 若要提供，標記為目前 master 名稱，不可當作建立單據時的名稱快照。
- IV209 不提供寫入、確認或庫存異動端點。家用端應先比對 live PostgreSQL schema／migrations，不能由本文件推定缺失表的 CREATE 欄位或 PK。
