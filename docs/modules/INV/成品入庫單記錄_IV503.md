# IV503 成品入庫單記錄

更新日期：2026-11-26。公司端已交付 WinForms／Service／Core 行為核對與 Vue 3 DEV 唯讀查詢；家用端已新增登入保護的 PostgreSQL 唯讀 API，部署 image `ymes-api:iv503-log-20261126-a1`。正式站有界日期查詢回 HTTP 200；目前沒有入庫資料列，因此無法以正式資料驗證 Detail 正向結果。

## 功能與入口

- 選單 FunctionKey：`FGD PRODUCT IN LOG`／IV503，另有 `SEMI PRODUCT IN LOG`／IV405；兩者共用舊 Form `frmINVProductInLog`、執行檔 IV_ProductInLog.dll。
- Vue DEV 路由 `/YMES/INV/ProductInLog`，IV503 與 IV405 入口共用此頁，只提供記錄查詢，不提供建立／編輯／作廢或庫存過帳。
- 查詢同時讀 FGD In (`ProductInType=0`) 和 SEMI In (`ProductInType=1`) Basis。`All`、`FGD INV`、`SEMI INV` Radio 是本機結果列篩選；Form 沒有 Source 篩選。

## 舊畫面與行為

### 查詢條件

- Form 啟動時預設 `All`；按 Query 才呼叫 `wsINV.LoadINVSEMIInAndFGDIn`。Radio 只對已載入的聯合結果套 `ProductInType=0/1`，依 `ProductInNo` 排序。
- `ProductInNo` 同時送 `SEMIInNo` 和 `FGDInNo`，Core 對兩個 UNION branch 各自做精確單號比對。其他查詢條件為目的 `InventoryNo`、來源 `FromInventoryNo`、State、CreateDate 範圍及 InputDate 範圍；UI 沒有 Source 條件，因此會查不同 Source 的單據。
- 目的庫房 Lookup 呼叫 `wsSMD.LoadInventoryBasis(InventoryType="1|2|6")` 後只顯示 `InventoryType<>6`（FGD／SEMI）；來源 Lookup 只顯示 `InventoryType=6`（WIP Semi）。
- CreateDate 與 InputDate 由各自 Checkbox 啟用；預設日期為最近一年至當日。Core 使用 `Between`，若 End 只有日期就擴為當日 `23:59:59`；若只傳入單側界限，Core 以 2000-01-01／3000-01-01 補另一側。
- State ValueList：0 UnConfirm、1 Handling、2 Confirm、3 Fail、-1 VOID。Form 以 `cboState.SelectedIndex` 當 State 傳給 Service；選到第 5 個 VOID 時 SelectedIndex 是 4，並非值 -1，舊查詢會錯送 State=4，因而查不到 VOID。Vue DEV 以實際值 -1 查 VOID；家用端 API 也應按狀態值，不複製 index bug。

### Basis、Detail 與 Component

- Core 將 `TBLINVSEMIINBASIS` 與 `TBLINVFGDINBASIS` UNION 成同一個 `SEMIInAndFGDIn` Dataset，加入 `ProductInType`（SEMI=1／FGD=0）、ProductInNo、InventoryNo、InputDate、State、Description、Source、FromInventoryNo、Creator／CreateDate、Reviser／ReviseDate、DataStamp。FGD Branch 另外有 ToERP、ERPNo、CANCELUSER、CANCELDATE；SEMI Branch 以 NULL 補欄位。
- Form 把 `InputDate` 改名為 `ConfirmDate` 並顯示。Basis Grid 顯示 ProductInType、ProductInNo、InventoryNo、State、ConfirmDate、Description、FromInventoryNo、Creator、CreateDate、Reviser、ReviseDate。只在 FGD INV 類型顯示 ToERP、ERPNo、CANCELUSER、CANCELDATE。
- 選取 Basis 後依 ProductInType 呼叫 FGD 或 SEMI `Load...DetailAndComponent`。Detail Grid 顯示 ProductNo、ProductName、LotNo、Qty、UnitNo、LocatorNo；ProductName 由目前有效且已發行的 ProductBasis 查得，不是單據建立時的名稱快照。FGD Component SQL 另讀 `TBLWIPCOMPONENTPROPERTY.MinLifeGrade`，但此 Form Grid 隱藏該欄。
- 展開 Detail 可看 ComponentNo、GoodQty、ScrapQty、UnitNo。此記錄畫面沒有 IV502 維護 Form 補上的 PackingNo／PackingName 欄位，也沒有 Print／CRUD 按鈕。

## 重要資料風險與家用端修正要求

1. 舊 Core `LoadINVFGDInDetailAndComponent`／`LoadINVSEMIInDetailAndComponent` 的 ProductInNo 參數是可選；空值時只用 `...Detail where ProductInNo is not null`，會回傳整張明細表與 Component 表。WinForms 正常由已選 Basis 傳單號，不能當作 API 的安全限制。正式 Detail API 必須要求已存在的單據編號與類型、以父單號同時限定 Detail／Component；空值一律 400，不可回全表。
2. 舊查詢使用字串組 SQL，沒有分頁、最大列數或日期跨度限制；正式 API 應使用參數化條件、穩定排序與 bounded paging。聯合列表若預設無條件會掃描兩種 Basis，需設定安全預設／最大列數或要求至少一個限制條件。
3. FGD Detail Oracle PK 為 `(FGDINNO, LOTNO, LOCATORNO)`，但舊 DataRelation 僅用 `(FGDInNo, LotNo)` 關聯 Component；若同張單同一 Lot 有多 Locator 明細，元件可能關聯不唯一或重複呈現。家用端需依正式 PostgreSQL PK／資料語意決定一對多關聯，並以真實複合鍵處理；SEMI Detail 亦需對照 WP604 主鍵。
4. InputDate 在舊 Form 改名為 ConfirmDate；不可把 CreateDate、State 或 UI 欄名誤當同一欄位。VOID 查詢要用 `State=-1`，不要複製舊 `SelectedIndex` 傳值錯誤。
5. Core 依目前 ProductBasis 取得 ProductName。若正式需求要還原當時顯示名稱，須先確認資料庫是否存有快照欄；不可從目前名稱推定歷史名稱。

## Vue DEV 復刻

- 接 App 選單 FunctionKey `function:INV:FGD PRODUCT IN LOG` 與 `function:INV:SEMI PRODUCT IN LOG`，共用路由 `/YMES/INV/ProductInLog`；fallback menu 列在各自的成品庫／半成品庫分類。
- Query 會套用精確 ProductInNo、目的／來源庫房、State、CreateDate、InputDate 條件；State VOID 使用 -1；日期 To 含當日。按 Query 才顯示 fixture rows；類型 Radio 可在結果中切 All／FGD／SEMI。
- Basis 有狀態、ConfirmDate、描述、庫房、建立／修改人及時間；FGD 類型顯示 ERP／取消欄。選列載入 Lot Detail，選 Lot 後顯示 Component 子列。DEV 頁唯讀，不呼叫 API、不寫入正式資料。
- 查詢欄位在窄視窗使用兩欄、輸入元件不得撐寬 grid；Clear／Query 控制換行且保持可見。視窗縮放驗收時保留此版面要求。
- Fixture 包含 FGD／SEMI、Source=0／1、草稿／處理中／確認／失敗／作廢，以及有／無 Component 的情境。

## 家用端 API handoff

- API 目前使用共用登入 Cookie（`[Authorize]`）。尚無可核實的 FunctionKey→角色／權限映射來源，故不宣稱已實作 Function ACL，也不猜測角色規則；取得來源後再評估細部授權。唯讀列表涵蓋 `ProductInType`、ProductInNo、InventoryNo、FromInventoryNo、State（含 -1）、CreateDate 範圍、InputDate 範圍；日期只含日期時 To inclusive。使用參數化 SQL、限制日期跨度、穩定排序、分頁／最大列數；Form 無 Source 篩選，若另提供 Source 需是明確 API 能力，不可改變既有預設語意。
- Detail API 必須要求 ProductInType 與有效 ProductInNo，將 Detail／Component 查詢限制在同一單據；以 live PG 主鍵確認 Component 關聯，避免只靠 LotNo 在多 Locator 情況重複元件。可在單一讀取 snapshot 載入 Basis／Detail／Component，保持內容一致。
- 保留 FGD 的 ToERP／ERPNo／CancelUser／CancelDate，SEMI 不適用者回 null；InputDate 對外可明確命名 `inputDate`，Web 顯示標籤才稱 ConfirmDate，避免 API 將來源欄位語意改寫。
- 不提供 IV503 寫入端點。State 標籤、商品名稱、來源分類及日期邊界均由 server 明確映射，不使用 EF／SQL 的預設 enum 或資料庫 session 時區推測。

## 家用端唯讀 API（2026-11-26）

- 列表：`GET /YMES/API/api/inventory/product-in/logs`。使用共用登入 Cookie（`[Authorize]`）；目前沒有可核實的 FunctionKey→角色授權資料，沿用已記錄的登入授權範圍，不臆造角色規則。
- 可選條件：`productInType`（0 FGD／1 SEMI）、`productInNo`（精確單號）、`inventoryNo`、`fromInventoryNo`、`state`（-1／0／1／2／3）、`createDateFrom`／`createDateTo`、`inputDateFrom`／`inputDateTo`、`page`、`pageSize`。`Source` 保留在結果中供顯示，但不作為篩選條件，符合舊畫面。
- 至少需提供單號、庫房、狀態或一組完整日期範圍；日期起訖必須成對，結束日含當天，單組範圍最多 366 個日曆日。PageSize 最大 100，排序固定為 CreateDate 與單號／類型；FGD／SEMI UNION、count 與列表在 Repeatable Read 同一 snapshot。
- 明細：`GET /YMES/API/api/inventory/product-in/logs/{productInType}/{productInNo}/details`。先確認同類型父單存在，再以完整父單號查 Detail／Component；最多 2,000 筆 Detail 與 5,000 筆 Component，超量回 413；空單號回 400，不會退化成全表查詢。
- FGD 顯示 ToERP／ERPNo／CancelUser／CancelDate；SEMI 對應欄位回 null。明細含 ProductName（目前 ACTIVE 且 current 的 ProductBasis）、來源欄位 InputDate／FromInventoryNo；Component 仍以單據＋Lot 扁平回傳，不依舊 Core 有歧義的 Lot-only relation 強行分配至 Locator。
- Schema 以可信 WP605／WP604 CREATE-only references 及 migration `0074_inv_product_in_draft_schema.sql` 為準，未新增 DDL／migration。API Release 與 Web `vue-tsc`／Vite build 成功；正式 API 已部署，Demo 登入後於 app-browser 驗證同日及 366 日 CreateDate 範圍查詢均回 HTTP 200、合法 JSON、`totalCount=0`。舊登入票證初次回 401，重新按 Demo 後查詢成功。正式庫沒有入庫單，Detail 的正向資料列仍無法驗證；未建立測試資料或寫入正式業務資料列。DEV 預覽頁仍使用假資料且不呼叫正式 API。
