# IV403 開立半成品出庫單

更新日期：2026-11-25。公司端已核對 WinForms Form／inline Designer、Service、Core，完成 Vue DEV 假資料互動。公司端未連 YMES PostgreSQL、未建立 schema／migration、未實作正式 API。桌機目前沒有可用的受保護 Oracle MESTEST profile，未讀取新 metadata，也未猜測 CREATE SQL。

## 功能與入口

- FunctionNo：`SEMI OUT`／IV403；Form `frmINVSEMIOut`，執行檔 `IV_SEMIOut.dll`。
- Vue DEV FunctionKey：`function:INV:SEMI OUT`；路由 `/YMES/INV/SemiOut`；選單「庫存管理 → 半成品庫 → 開立半成品出庫單」。
- IV403 建立與維護未確認的半成品出庫草稿。半成品庫房資料頁的 SEMI Out 按鈕會另外開 `frmINVSEMIOutConfirm`；草稿建立與出庫確認是兩個流程。

## 查詢與畫面

- Form Load 呼叫 `wsINV.LoadINVSEMIOutBasis`，固定傳 `State=0`，另帶表單搜尋條件。搜尋欄只有 `SEMIOutNo`；Core 支援單號、庫房、State、開單日及入庫日條件，但 IV403 主頁未提供日期篩選。
- 單頭 Grid 依 `SEMIOutNo` 排序，顯示 `SEMIOutNo`、`InventoryNo`、`State`、`Description`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`。狀態 ValueList 為 0 UnConfirm、1 Handling、2 Confirm、3 Fail；目前查詢只回傳 0。
- 選取單頭後立即以 `SEMIOutNo` 呼叫 `LoadINVSEMIOutDetail`。Core 回傳 Detail 與 `TBLINVSEMIOutComponent`，用 `(SEMIOutNo, LotNo)` 建 DataRelation；畫面明細依 `SEMIOutNo, LotNo, LocatorNo` 排序。ProductName 由目前版且已核准的 Product Basis 左連取得。
- 單頭 ADD 固定建立 State=0；欄位為 SEMIOutNo、InventoryNo、Description。InventoryNo 由半成品庫房 Lookup 選取，EDIT 不允許改 InventoryNo；Copy 只開新單頭，明細要另建。單號可依 Serial Rule 自動取得或手動輸入，取決於系統規則設定。
- 單頭 EDIT、DEL 與明細 ADD／EDIT／DEL／Copy 只允許 UnConfirm。單頭修改主要更新 Description，EDIT 送 DataStamp／State=0 條件；Core 以受影響列數檢查衝突。刪除單頭會移除單據明細，並將所關聯 Component 的 `BookingFlag` 解除。
- 明細欄位包括 ProductNo、LotNo、LocatorNo、PutInPlaceType、PutInPlaceNo、UnitNo、Qty。PutInPlaceType：2=WIP Inventory、3=MO、4=Unproductive、5=Material Return；4／5 的 PutInPlaceNo 固定為 `N/A`。
- 編輯明細時 ProductNo／LotNo／LocatorNo 為唯讀。Service 對 2／3 等一般目的地呼叫 `ChkINVSEMIOutDetailValid`；類型 4／5 跳過該驗證。MO 類型會載入工單用料清單；若主料有多筆，舊 Form 要求使用者選取，並要求 SubstituteMaterialNo、Level、Qty。
- 若 LotState 的 `HaveLevel=1` 或 `HaveComponent=1`，舊 Form 鎖定 Qty。若存在半成品 Component，明細 Service 將所有 Component key（InventoryNo、LotNo、LocatorNo、ComponentNo）隨 `TurnData` 一起送出；Form 沒有逐 Component 勾選功能，出庫時整批帶入。
- Print 呼叫 `arSEMIProductOut`；單據沒有 Detail 時會顯示錯誤，不列印。

## Vue DEV 行為與簡化處

- 使用本機假資料模擬 State=0 單頭查詢、單頭新增／修改／複製／刪除，選列載入明細、明細新增／修改／複製／刪除、刪除確認、Component 顯示及列印預覽。假資料僅存在頁面記憶體，不呼叫 API、MES 或資料庫。
- 假資料模擬目前庫房、來源 Lot／Locator、庫存量、Component、目的類別及單據狀態。明細數量不能大於假庫存；有 Component／Lot 層級的批次數量鎖定為整批量，預約只在 DEV 頁面假資料內更新。
- DEV 單號採 `SO-DEV-26NNNN`；未連正式 Serial Rule。MO 假資料只接受 MO 編號格式，沒有載入真實工單用料／替代料；WIP／MO Lookup 以手動 DEV 欄位代替。列印為本機預覽，不呼叫 ActiveReports 或印表機。
- 舊 Form 支援多選刪除；DEV 只操作目前選取的單頭／單筆明細。DEV 刪除會先詢問確認。DEV 查詢使用單號包含比對，正式 API 應按既有搜尋欄語意確認服務端規則。
- DEV 沒有模擬 Confirm／過帳；這由 `frmINVSEMIOutConfirm` 對應的確認流程負責，不應在 IV403 草稿操作內直接扣庫存。

## 表格、DDL 與 PostgreSQL handoff

| 表 | 用途 | DDL／metadata 狀態 |
|---|---|---|
| `TBLINVSEMIOutBasis` | 半成品出庫單頭 | repo 尚無可信同版 Oracle DDL／metadata |
| `TBLINVSEMIOutDetail` | 半成品出庫明細 | repo 尚無可信同版 Oracle DDL／metadata |
| `TBLINVSEMIOutComponent` | 出庫單 Component 關聯 | repo 尚無可信同版 Oracle DDL／metadata |
| `TBLINVSEMIInventory` | 庫存 Lot／Locator／數量 | 既有 WP201 reference；須由家用端核 live PostgreSQL schema 與出庫條件 |
| `TBLINVSEMIInventoryComponent` | 可出庫 Component 與 BookingFlag | 既有 WP604 reference；須核 live key、BookingFlag 與預約規則 |
| `TBLWIPLotState` | `HaveLevel`／`HaveComponent` 判斷 | 沿 WP101 既有 Lot State 參考；版本與 Join key 需核 live schema |
| `TBLPRDProductBasis` | ProductName／目前版／核准版 | 沿既有 Product master reference |
| MO／WIP Lookup tables | WIP Inventory、MO、MO Material List | 由相應既有 WIP／OE handoff 及家用端 live schema 核對 |

公司端沒有受保護 Oracle MESTEST profile 可用，沒有以聊天或文件中的帳密另行連線；因此未新增 Oracle metadata 證據，也未產生猜測性的 PostgreSQL CREATE SQL。家用端應先核 live PostgreSQL 是否已含出庫三表及 WP604／WP101 共用表；若三張出庫表缺少，再由家用端依 live schema 產生 PostgreSQL CREATE-only migration，先確認唯一鍵、DataStamp、預約／索引及外鍵，再實作 API。

## 家用端 API 實作 handoff

- 建議提供單頭分頁查詢、單頭 CRUD、以 `SEMIOutNo` 限定的明細查詢／CRUD；預設只允許讀寫 State=0。所有 SQL 參數化、套用 Function／Inventory ACL、bounded paging，拒絕任意 XML Additional 條件。
- 明細新增／修改應用原子交易驗證來源 Inventory／Lot／Locator、LotState、可用量、目的類別、工單用料與替代料；帶 Component 時用完整複合鍵，原子更新 BookingFlag 並處理重複預約。避免只在 UI 檢查數量或 State。
- 單頭／明細 EDIT 使用 DataStamp 或資料列版本；刪單應原子解除 Component booking 並刪除明細／Component 關聯。無論成功或失敗皆須回傳真實交易結果及可追蹤事件。
- IV403 只維護待確認草稿。出庫確認及庫存扣帳在 IV401 的 SEMI Out 確認功能處理；兩個流程須共用一致的單據狀態與冪等交易規則。
