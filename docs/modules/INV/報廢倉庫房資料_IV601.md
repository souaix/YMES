# IV601 報廢倉庫房資料

## 功能範圍與來源

- Oracle 選單 FunctionNo：SCR INVENTORY；FunctionKey：IV601；Form：frmINVSCRInventory。
- Form／inline Designer：D:\iMES\CSiMES\STD\MESWin\INV\IV_SCRInventory\frmINVSCRInventory.vb。
- 同專案 SCR In 確認視窗：frmINVSCRInConfirm.vb；另見獨立入庫維護功能 IV602 的 IV_SCRIn\frmINVSCRIn.vb，兩者不是同一畫面。
- Service：STD\MESws_STD\wsSTD\wsINV\wsINV.cs 的 LoadSCRInventory、LoadSCRInventoryComponent、LoadSCRInventoryFailBin、DelSCRInventory、LoadINVSCRInBasis、LoadINVSCRInDetailAndComponent/FailBIN、AddINVTransactionState。
- Lookup Service：wsSMD.LoadInventoryBasis（InventoryType=3）及 wsSYS.LoadBin。
- Core：STD\MESkc\kcINV\clsInventory.cs 的三個 LoadSCRInventory* 查詢及 DelSCRInventory。

## WinForms 畫面與互動

- 輸入或選擇 InventoryNo 後查詢；搜尋清單由 LoadInventoryBasis(InventoryType=3) 提供，主表以 InventoryNo 精確查詢。
- 主 Grid 顯示 LotNo、LotSerial、OPNo、ScrapQty、LossQty、UnitNo、BaseLotNo、InputDate；可多選後按 DEL，先詢問確認。
- 選取主列後先以 (InventoryNo, LotSerial) 查 Component；無 Component 時再查 FailBin。兩者皆無時，主列本身就是 General SCR Inventory，不另載子表。
- Component Grid 顯示 ComponentNo、GoodQty、ScrapQty、UnitNo。FailBin Grid 依 wsSYS.LoadBin 的 BinOrder 顯示在 FailBin 資料表中存在的動態 Bin 欄。
- SCR In 按鈕開啟 frmINVSCRInConfirm：挑選未確認 SCR In 單據，顯示單頭及 Component／FailBin 明細；確認時呼叫 AddINVTransactionState(Source=40, TicketNo, Creator)，再逐筆呼叫 SetReverseCommitState(LotNo, LotSerial)。成功後由父 Form 重新載入 SCR 庫存。此畫面排入交易，Core 實際入庫由下游交易處理。

## 資料與舊版行為

- 主表：TBLINVSCRINVENTORY；Component：TBLINVSCRINVENTORYCOMPONENT；動態 Bin 明細：TBLINVSCRINVENTORYFAILBIN。父子與刪除使用 InventoryNo＋LotSerial；LotNo 作顯示／輔助欄位。
- 庫房主檔為 TBLINVINVENTORYBASIS，以 InventoryType=3 選擇；FailBin 動態欄位依 TBLSYSBIN.BinOrder。
- Core 查詢只以 InventoryNo Is Not Null 起始，其他欄位都是可選條件。Form 會傳 InventoryNo，但沒有排序、分頁或筆數上限；Core 以 SQL 字串串接參數。
- Core 刪除以 CollectionSQL 依序刪 Component、FailBin、主表，主表條件為 InventoryNo＋LotSerial；沒有核對庫存狀態、被預約／引用狀態或預期列數。Service 每個選取列各呼叫一次，遇首筆失敗就停止，先前成功的多列不會自動回復。
- SCR In 確認採非同步交易佇列；AddINVTransactionState 成功後再逐筆設定 Lot reverse commit state。它不是 frmINVSCRIn 的新增／編輯功能，也不直接在此 Form 呼叫 ExeSCRIn。
- TBLINVSCRINVENTORY、TBLINVSCRINVENTORYCOMPONENT、TBLINVSCRINVENTORYFAILBIN 的可信同版 Oracle DDL／欄位、索引與約束 metadata 尚缺。公司桌機目前沒有可用的受保護 Oracle profile；未連 Oracle、未猜 CREATE SQL。上述三表在 WP622／WP619 handoff 也列為待取得項目。沒有新增表或 SQL。

## 家用端 API／schema handoff

- 先核對 PostgreSQL live schema 與既有 migrations；三張 SCR Inventory 表的 Oracle DDL／metadata 未取得前不可由 DEV 欄位臆造 CREATE-only SQL。
- Lookup 限定授權的 InventoryType=3 庫房。主表 API 必須要求 InventoryNo，採參數化查詢、穩定排序及 bounded paging；不要暴露任意 XML Additional condition。
- Component／FailBin API 必須由授權主列 (InventoryNo, LotSerial) 限定，Bin 欄位依正式 schema／metadata 驗證，不能固定採用 DEV 的 BIN01–BIN03。
- DELETE 使用完整父鍵，在同一交易內鎖定／重查父列及預約、交易引用後刪除兩種子表與主列；如已確認或被引用則拒絕。若 live schema 有版本欄位再採樂觀併發檢查，不假設存在 DataStamp。
- SCR In 確認要維持 Source=40 的非同步命令語意；用登入者取 Creator、做授權與冪等重複提交保護，並逐一管理 Lot reverse lock。交易入庫由 worker 執行，成功後刷新讀模型；不可把排程成功當庫存已入帳。
