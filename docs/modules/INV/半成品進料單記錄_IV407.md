## 功能與入口

- FunctionNo：`SEMI IN LOG`／IV407；Form `frmINVSEMIInLog`，執行檔 `IV_SEMIInLog.dll`。
- Vue DEV FunctionKey：`function:INV:SEMI IN LOG`；路由 `/YMES/INV/SemiInLog`；選單「庫存管理 → 半成品庫 → 半成品進料單記錄」。
- 此頁只查詢 Source=0 外購半成品進料單及其 Detail／Component，不提供新增、修改、刪除或確認。

## 查詢與畫面

- 查詢條件：`SEMIInNo`、`InventoryNo`、State、From／End CreateDate、From／End InputDate。Inventory Lookup 呼叫 `wsSMD.LoadInventoryBasis` 並傳 `InventoryType=2`。Form 對 `LoadINVSEMIInBasis` 固定傳 `Source=0`，代表只查外購來源。
- `SEMIInNo` 與 `InventoryNo` 是精確條件。State 選項為 0 UnConfirm、1 Handling、2 Confirm、3 Fail；畫面 ValueList 另有 -1 Scrap。
- 日期起訖各自帶入，不要求兩端都選。Core 對 CreateDate 將未提供的另一端展開至 2000-01-01／3000-01-01，並將只有日期的 EndCreateDate 延到當日 23:59:59。InputDate 的 From／End 獨立套用，只有日期的 EndInputDate 同樣延到當日結束。Form 將資料欄 `InputDate` 改名顯示為 `ConfirmDate`。
- 舊 Core SQL 沒有 `ORDER BY`、分頁或上限；單號／庫房／日期條件全未填時，Source=0 可能查出大量資料。SQL 使用字串組合。正式 API 應使用參數化查詢、Function／Inventory ACL、穩定排序與 bounded paging，並釐清單邊日期與時區邊界。
- Basis Grid 顯示 `SEMIInNo`、`InventoryNo`、`State`、`Description`、`Creator`、`CreateDate`、`ConfirmDate`；InputDate 為空時仍依資料顯示空白。選取單頭後以 SEMIInNo 載入 Detail／Component。
- Detail Grid 顯示 ProductNo、LotNo、Qty、UnitNo、LocatorNo；Component 子列顯示 ComponentNo、GoodQty、ScrapQty、UnitNo。Core 以 `(SEMIInNo, LotNo)` 建 DataRelation；Component 另查 WIP Component Property 的 `MinLifeGrade`。ProductName 使用目前版且已核准的 Product Basis。
- 可見 Component relation 未包含 LocatorNo；正式 API／資料模型不可據此假設完整主鍵，須由家用端 live PostgreSQL schema 確認唯一鍵與 join 條件。

## 家用端 API handoff

- 沿用 IV404 的外購進料讀取模型；Basis API 僅回傳 Source=0 並允許 SEMIInNo、InventoryNo、State、CreateDate／InputDate 篩選。所有查詢參數化、受登入與 Function／Inventory ACL 保護、具穩定排序及頁面大小上限；空條件不可無界回整表。
- Detail API 必須由授權的父單號載入 Detail 與 Component，不能接受任意空父單號而回全表。依 live schema 明確定義 Component join key；舊 WinForms relation 僅用 `(SEMIInNo, LotNo)`，不得當成資料庫 PK 證據。
- 將資料欄 InputDate 在 UI DTO 映射為 ConfirmDate；保留真實欄位意義，不以 CreateDate 代替確認時間。日期 API 明確採企業時區與半開區間 `[from, to+1 day)` 或等價規則，避免字串日期與毫秒精度差異。
- IV407 唯讀；過帳／狀態變更留在 IV401 確認交易，草稿新增／編輯留在 IV404。家用端以 IV404 的表格與 API handoff 作為 schema source of truth。
