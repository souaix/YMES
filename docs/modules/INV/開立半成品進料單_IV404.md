# IV404 開立半成品進料單

更新日期：2026-11-25。公司端已核對 WinForms Form／inline Designer、Service、Core，完成 Vue DEV 假資料互動。公司端未連 YMES PostgreSQL、未建立 schema／migration、未實作正式 API。桌機沒有可用的受保護 Oracle MESTEST profile；本次未取得新 metadata，也未猜測 CREATE SQL。

## 功能與入口

- FunctionNo：`SEMI IN`／IV404；Form `frmINVSEMIIn`，執行檔 `IV_SEMIIn.dll`。
- Vue DEV FunctionKey：`function:INV:SEMI IN`；路由 `/YMES/INV/SemiIn`；選單「庫存管理 → 半成品庫 → 開立半成品進料單」。
- IV404 建立外購半成品進料的未確認草稿。實際確認與庫存入帳由 IV401 的獨立 `frmINVSEMIInConfirm`／`ExeSEMIIn` 流程執行。

## 查詢與畫面

- Form Load 將搜尋欄設為 `SEMIInNo`，呼叫 `LoadINVSEMIInBasis`；固定加 `State=0`、`Source=0`（Core 註解為只取外購進料），再加使用者搜尋條件，按單號排序。狀態對照為 0 UnConfirm、1 Handling、2 Confirm、3 Fail。
- 單頭 Grid 顯示 `SEMIInNo`、`InventoryNo`、`State`、`InputDate`、`Description`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`；`FromInventoryNo` 不顯示。選取單頭後呼叫 `LoadINVSEMIInDetailAndComponent`。
- 明細依 `SEMIInNo, LotNo, LocatorNo` 排序。Core 將 `SEMIInDetail` 與 `SEMIInDetail_Comp` 以 `(SEMIInNo, LotNo)` 建 DataRelation；ProductName 由目前版且已核准的 Product Basis 左連取得。Component 顯示 `ComponentNo`、`GoodQty`、`ScrapQty`、`UnitNo`，並查 `MinLifeGrade`。
- 單頭新增時 SEMIInNo 由使用者輸入，離開欄位轉大寫；InventoryNo 透過 `LoadInventoryBasis` 以 InventoryType=2 查半成品庫房。Service／Core 固定 Source=0、State=0。編輯時 SEMIInNo／InventoryNo 鎖定，僅更新 Description 並帶 DataStamp／State 條件。主 Form 只允許未確認單編輯／刪除。
- 明細輸入 ProductNo、CustomerLotNo、Qty；CustomerLotNo 離開欄位轉大寫，Service 將它當 LotNo，Core 新增時 BaseLotNo 預設同 LotNo。Locator 預設 `N/A`，也可用所選半成品庫房的 Locator Lookup；Product 的目前版 UnitNo 作為明細 UnitNo，單位欄位由 Lookup 載入。
- 編輯明細時 ProductNo、CustomerLotNo／LotNo、LocatorNo 鎖定；Qty 與 Component 列可改。Core 編輯會先重建該 Lot 的 Component rows，再更新 Detail Qty 並遞增 DataStamp。刪除明細會刪同單號／Lot 的 Component 與明細列。
- ComponentNo 為手動輸入並轉大寫，同一明細不可重複。Component Unit 由該 Product UnitType 的 Unit 清單選擇；Form 呼叫 `wsWIP.LoadUnitTransferQty(OrgUnitNo=Product UnitNo, ToUnitNo=Component UnitNo, OrgQty=1, ProductNo, ProductVersion)`，換算結果成為每筆 GoodQty，ScrapQty=0。若有 Component rows，舊 Form 以 VB `CInt(Qty)` 比較 Component row count；不符合即拒絕儲存。
- Source=0 Core 會讀 Product 目前版次，寫入 `TBLINVSEMIInDetail` 的 ProductVersion、LotNo、LocatorNo、ProductNo、Qty、UnitNo、BaseLotNo，並依輸入寫入 `TBLINVSEMIInComponent`。外購草稿新增不做 WIP 來源倉 Booking。
- 單頭刪除會刪該單號所有 Component、Detail、Basis。Form 只對 State=0 開放維護；確認後庫存入帳與 State 轉換由 IV401／`ExeSEMIIn` 處理。

- 完成 `/YMES/INV/SemiIn`：Source=0／State=0 單頭查詢、單頭 ADD／EDIT／DEL、選單頭載入明細、明細 ADD／EDIT／DEL、Component 子列維護、刪除確認。資料只在頁面記憶體，不呼叫 MES、正式 API 或資料庫。
- DEV 假資料提供半成品庫房、Locator、Product、Unit 與單位換算；單號手動輸入並轉大寫。Component 仍採手動輸入，並模擬重複檢查、單位換算、GoodQty／ScrapQty 與 VB CInt 筆數限制。
- 未確認單才可維護；已確認範例不出現在本頁查詢結果。DEV 只處理目前單頭／明細，沒有舊 Form 多選刪除互動。Product／Locator／Unit 是假 Lookup，換算數值是 fixture，不代表真實單位設定。
- 不模擬 `ExeSEMIIn`、庫存寫入、IV401 確認、正式序號或即時服務端 DataStamp；DEV 樣本只展示表單操作與狀態。正式入帳仍須由家用端實作確認交易。

## 表格、DDL 與 PostgreSQL handoff

| 表 | 用途 | DDL／metadata 狀態 |
|---|---|---|
| `TBLINVSEMIInBasis` | 半成品進料單頭 | repo 未找到可信同版 Oracle DDL／metadata；桌機受保護 profile 不可用 |
| `TBLINVSEMIInDetail` | Lot／Product／Locator／數量明細 | repo 未找到可信同版 Oracle DDL／metadata；桌機受保護 profile 不可用 |
| `TBLINVSEMIInComponent` | 外購進料 Component 與單位數量 | repo 未找到可信同版 Oracle DDL／metadata；桌機受保護 profile 不可用 |
| `TBLPRDProductBasis` | 目前 Product Version／ProductName | 重用既有 Product master reference；家用端核 live schema |
| `TBLINVInventoryBasis`／Locator lookup | InventoryType=2 半成品庫房及 Locator | 由 IV401／既有 Inventory handoff 核 PostgreSQL live table 與 Lookup ACL |
| `TBLSYSUnit`／Unit Transfer | Unit／Product UnitType／換算 | 家用端核既有 SYS/WIP Product schema、換算服務及 version key |

公司端沒有可用的受保護 Oracle MESTEST profile，因此未以聊天或文件帳密連線、未取得進料三表的 Oracle DDL／metadata，也沒有猜測性 PostgreSQL CREATE SQL。家用端先檢查 PostgreSQL live schema／migrations；只有三表確實缺少時才新增 CREATE-only migration。由 Core SQL 可辨認的欄位僅作為調查線索，不等同已確認欄位型別、nullable、PK、index、FK 或 default。

## 家用端 API 實作 handoff

- 提供有 Function／Inventory ACL 的單頭 bounded query 與 CRUD、以 `SEMIInNo` 限定的明細／Component CRUD。IV404 查詢固定 `Source=0 AND State=0`；SQL 使用參數、穩定排序與分頁，不接受任意 XML Additional 條件。
- 單頭建立固定 Source=0／State=0，驗證 SEMIInNo 唯一、InventoryType=2 且可用、Description 與 Actor 權限。修改需比較 DataStamp／State=0；單頭刪除在單一交易刪 Component、Detail、Basis，並處理外鍵與併發狀態。
- 明細交易須驗證父單為 Source=0／State=0、Product 目前有效版本、LotNo／Locator／Inventory 關係、數量及 Unit Transfer。外購流程不可誤套 WIP Inventory Booking；ComponentNo 大小寫／重複、GoodQty／ScrapQty／UnitNo 與 `CInt(Qty) == Component count` 規則要明確實作，並依 live schema 確認 Component 的鍵是否含 LocatorNo。
- Edit Detail 只允許更新 Qty 與 Component，應使用 Detail DataStamp 並原子替換 Component rows；刪除按 live PK／FK 限定 Component 與 Detail。由 Core DataRelation 可見舊畫面按 `(SEMIInNo, LotNo)` 顯示子列，但不據此推定 PostgreSQL 唯一鍵。
- IV404 只維護待確認草稿。IV401／`ExeSEMIIn` 負責正式確認、庫存入帳、InputDate 與 State 轉換；兩頁需共用狀態／版本檢查及冪等交易，不能在 IV404 儲存明細時提早增加庫存。
