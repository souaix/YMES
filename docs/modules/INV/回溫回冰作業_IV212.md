- 清冊 FunctionKey：`INV_RAW_ACCLIMATION`，功能代碼 IV212；Form 為 `frmINVRaw_Acclimation`，執行檔 `IV_Inventory_Raw_Acclimation.dll`。

## WinForms 查詢與顯示

- 啟動時讀系統參數 `GumMaterialType` 和 `MATERIALMULTITIMECTRL`。庫房 lookup 用 `wsSMD.LoadInventoryBasis(IssueState=2, InventoryType=6)`；Material lookup 只顯示 `GumMaterialType` 內、IssueState=2 的料號。
- 查詢條件為 InventoryNo、MaterialNo、膠類狀態、MaterialLotNo 前綴（勾選且非空才送）。Form 固定傳 `ContainsExpired=false`，額外條件為 `MaterialType in GumMaterialType`。Core 預設只查 `Qty>0`；過期排除條件為 `ExpireDate is null or ExpireDate > now`。
- Query 讀取 `TBLINVWIPINVENTORY_RAW` 後加入本機勾選欄、SeqNo 與 ExpireDateFlag。依 `TBLMTLMATERIALBASIS.ExpireDateFlag` 設定效期管理標記；製造日、效期、入庫日空值在排序前以 9999-12-31 替代。
- 畫面欄位依序為 Select、InventoryNo、MaterialNo、MaterialLotNo、UnitNo、Qty、MaterialType、GUMTYPESTATUS、AcclimationDate、AccTimes、Executor；`MATERIALMULTITIMECTRL=1` 時再顯示 FrozenDate／FrozenTimes。LocatorNo、日期排序欄位與 ExpireDateFlag 不顯示。
- 畫面為未回溫批計算每料號 SeqNo，排序鍵是 ManufactureDate、ExpireDate、InputDate；SeqNo 本身未顯示，也未在 Warm Up 前檢查，因此來源程式沒有強制 FIFO 的阻擋規則。
- `MATERIALMULTITIMECTRL=0` 時隱藏 Cool Down 按鈕、ValueList 移除狀態 2，並隱藏 FrozenDate／FrozenTimes 欄位。DEV 假設多次回冰控制開啟，以展示完整流程；正式顯示須由 system parameter 決定。

## Warm Up 規則

1. 僅對勾選列逐筆檢查物料類別是否 IssueState=2；類別未核准者略過。
2. `GUMTYPESTATUS=1`（已回溫）不可再次回溫。若有 FrozenDate，依 `TBLMTLTYPEACCLIMATION.FROZENMIN` 檢查 `FrozenDate + FROZENMIN hours <= now`；首次回溫沒有 FrozenDate，直接略過時效檢查。找不到設定列或 FROZENMIN 為 null 時也不阻擋。
3. 通過者批次呼叫 `Edit_IVN_Raw_Split`。Core 對同一鍵先將 null `ACCTIMES` 初始化為 0，再設 `ACCLIMATIONDATE=now`、`EXECUTOR=user`、`GUMTYPESTATUS=1`、`ACCTIMES=ACCTIMES+1` 並清空 `FROZENDATE`；之後將更新後狀態快照寫入 RawLog，`EVENTTIME` 取 AcclimationDate。
4. 不合格列收集原因並略過；其餘有效列仍可一起執行。完成後重新載入清單。

## Cool Down 規則

1. `MATERIALMULTITIMECTRL=1` 才顯示回冰操作。對每一勾選列查 `ShowWIPEQPMaterialState(MaterialNo, MaterialLotNo)`；設備狀態有 QTY>0 時表示尚有上料，略過。
2. 物料類別必須 IssueState=2；`GUMTYPESTATUS=0`（尚未回溫）及 `=2`（已回冰）均略過。
3. 有 `TBLMTLTYPEACCLIMATION` 設定列且 `REFROZENFLAG=0` 時不允許回冰；`FROZENTIMES >= REFORZENTIMES` 時達到上限。沒有設定列或上限為 null 時，舊程式不以這兩項阻擋。
4. 通過者批次呼叫 `SetInventoryRawFrozen`。Core 將 null `FROZENTIMES` 初始化為 0，再設 `FROZENDATE=now`、`EXECUTOR=user`、`GUMTYPESTATUS=2`、`FROZENTIMES=FROZENTIMES+1` 並清空 `ACCLIMATIONDATE`；之後將更新後狀態快照寫入 RawLog，`EVENTTIME` 取 FrozenDate。完成後重新載入清單。

## DEV 復刻與來源落差

- `/YMES/INV/RawAcclimation` DEV 提供 Inventory／Material／Lot 前綴／狀態查詢、膠材 Lookup、批次勾選、三狀態顯示與 Warm Up／Cool Down 本機模擬；包含過期批、設備仍有上料、未達 FROZENMIN、回冰次數已滿與禁止回冰等情境。
- DEV 模擬選定 `GUMTYPESTATUS` 與回溫／回冰計數變化；同料號／批號跨不同 Inventory／Locator 的列以 Oracle 複合鍵分開更新。
- 舊 Form 只把 InventoryNo、MaterialNo、MaterialLotNo 傳至兩個更新 Service；Core UPDATE 條件也只含這三欄。原生 Raw 主鍵是 `(INVENTORYNO, MATERIALNO, MATERIALLOTNO, LOCATORNO)`，故一批多 Locator 時會更新該批所有 Locator，重複勾選可能重複更新。正式 API 必須以完整鍵、單一更新命令、狀態前置條件及併發版本保護定位一筆庫存列。
- `LoadMaterialGumType` 會同時查物料專屬 `MaterialNo` 與通用 `'*'` 規則，但未指定排序；若兩列並存，Form 取第一列，實際套用規則有不確定性。正式 API 應定義「專屬設定優先、否則通用設定」並用一個 server-side 規則解析。
- 原始程式只有回冰最短時效 `FROZENMIN`、`REFROZENFLAG`、`REFORZENTIMES` 檢查；`TBLMTLTYPEACCLIMATION` 的 `REACCLIMATEFLAG`、`REACCMIN`、`REACCMAX` 欄位在 IV212 Form 流程未使用，不可宣稱此畫面會依再次回溫設定阻擋。
- Core SQL 以字串串接條件，批次操作沒有傳 DataStamp／LocatorNo／狀態版本。正式 API 必須參數化，以完整主鍵重讀庫存與設備狀態，驗證目前狀態後在單一 transaction 更新 Raw 與 RawLog；同一批多列操作要回報逐列成功／失敗，避免部分成功被一個 batch success 隱藏。

## 家用端 API／schema handoff

- 以登入與 IV212 Function ACL 保護 GET lookup／query 和 POST warm-up／cool-down；query 須限制 `InventoryType=6`、系統允許的 GumMaterialType、`Qty>0` 及未過期列，可用庫房／料號／批號前綴／狀態篩選，採參數化查詢與 bounded paging。
- options API 回傳 `GumMaterialType`、`MATERIALMULTITIMECTRL`、IssueState=2 的材料類別／Lookup，並依權限載入 WIP 庫房。正式端不得把 DEV fixture 參數當真實參數。
- 操作 DTO 必須包含完整 Raw PK `(InventoryNo, MaterialNo, MaterialLotNo, LocatorNo)`、operation ID 與預期狀態／RowVersion；server-side 重讀 TBLMTLTYPEACCLIMATION（專屬規則優先）及設備上料 QTY，交易內做 compare-and-set，並同交易追加 RawLog。列表按鍵穩定排序；重送 operation ID 不可重複加計數或追加日誌。
- 原生 RawLog DDL／metadata 缺失會影響正式 schema／欄位長度、精度、索引與歷程儲存設計。家用端先 pull，核 live PostgreSQL 及 migration；在取得可信 DDL 前不要根據 Core 欄位清單另建 RawLog CREATE。記錄所需欄位、PK/index 與權限差異後再決定 migration。
- 對多筆批次操作逐列回傳結果；任一列失敗是否整批回滾要明確決策。不可沿用無 locator、無狀態條件、字串串接的舊 Core 更新行為。
