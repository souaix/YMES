# IV101 庫房工程群組

## 功能範圍

- MES 選單：庫存管理 → 庫房設定 → 庫房工程群組。FunctionNo=`INV ENGINEER GROUP`、FunctionKey=`IV101`、Form=`frmINVEngineerGroupBasis`、ExecutionFile=`IV_EngineerGroupBasis.dll`。
- Vue DEV 路徑：`/YMES/INV/EngineerGroups`；功能鍵 `function:INV:INV ENGINEER GROUP`。
- 這是庫房工程群組主檔及成員配置，不是設備工程群組。桌機來源在 `D:\iMES\CSiMES\STD\MESWin\INV\IV_EngineerGroupBasis`。
- DEV 假資料儲存鍵：`ymes.dev.inv.engineer-groups.v1`。不呼叫 MES／YMES API，不連資料庫。

## WinForms 畫面與互動

- 主 Form ClientSize 為 1008×591。上方 `Engineer Group Basis` Grid 提供 Add、Edit、Delete、Copy；下方 `Engineer Group's User` 以左右清單維護使用者，含移入／移出、輸入 UserNo 後 Enter、雙擊移動、Confirm、Close。
- 主 Grid 欄位：EngineerGroupNo、EngineerGroupName、Description、Creator、CreateDate、Reviser、ReviseDate。載入後依 EngineerGroupNo 排序；Issue／簽核欄位在此 Form 隱藏。
- 啟動時呼叫 `wsINV.LoadINVEngineerGroupBasis` 及 `wsUSR.LoadUserSecurity(IssueState=2)`；選取群組時再呼叫 `wsINV.LoadINVEngineerGroupDetail`。Form 只顯示 `tblUSRUserGroup` 中 `GroupType=3` 且 `AgentOf='NA'` 的直接成員，系統衍生代理人列不顯示。
- 群組定義窗為 `frmINVEngineerGroupBasisDef`，欄位為群組編號、名稱、多行描述。編號與名稱必填；編輯時編號唯讀，編號離開欄位時轉大寫。Creator/CreateDate 由主檔呈現；編輯時顯示 Reviser/ReviseDate。Add／Edit／Copy 可用 Apply 留在窗內，Confirm 儲存並關閉。
- Copy 以來源群組為樣板，輸入新編號／名稱／描述；Service 建立主檔後複製來源成員，並為成員建立代理人關聯。
- Delete 可多選。Form 依序逐一呼叫刪除服務，首筆錯誤即停止；先前成功列不會由 Form 還原，因此多選刪除可能部分完成。
- 成員 Confirm 會送出整個目前清單與所選主檔 DataStamp。空清單代表清空成員，不是忽略更新。

## Oracle DDL／schema 狀態

- `TBLINVENGINEERGROUPBASIS` 是直接主檔。Core 使用欄位 `EngineerGroupNo`、`EngineerGroupName`、`Description`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`、`DataStamp`。目前 repo 的 `database/reference/mestest_first_phase_create_tables.sql` 有同名 CREATE，但欄位型別／長度是未核實推測，且註解宣稱來自 MESTEST，不能據此當作來源 DDL。
- 本桌機的受保護 Oracle profile 檔案不存在，因此本次沒有執行 PowerShell 5.1／ODP.NET 查詢；`TBLINVENGINEERGROUPBASIS` 的 Oracle `DBMS_METADATA.GET_DDL`、欄位 nullable/default、PK/index/FK 與 PostgreSQL CREATE-only 仍缺。不得沿用上述推測 CREATE SQL 上正式環境。
- 共用 `TBLUSRUSERGROUP` 的 Oracle source DDL 與 PostgreSQL reference 已於 2026-11-16 查證，位於 `database/reference/mestest_equipment_engineer_group_member_source_ddl.sql`、`database/reference/mestest_equipment_engineer_group_member_create.sql`；本功能重用，不另建表。

## 家用端 API／schema handoff

1. 先以家用端 live schema 比對 `tblinvengineergroupbasis`；在取得可驗證 Oracle DDL 或明確核對現況前，不要沿用 `mestest_first_phase_create_tables.sql` 的推測欄位定義。若需建立表，補正式 source DDL／metadata 後再提供 CREATE-only。
2. 主檔 API 需提供受授權的群組列表／單筆、Add、Edit、Copy、Delete；以參數化 SQL 實作，編號正規化大寫。Edit 使用 DataStamp compare-and-swap，成功遞增版本並更新修訂者／時間。
3. 成員查詢需依 GroupType=3 取群組成員，回傳直接成員 `AgentOf='NA'` 供 UI 顯示；使用者 lookup 限定 IssueState=2。
4. 成員 Confirm 是「替換完整集合」，必須允許空集合清除。使用交易鎖定／CAS 主檔 DataStamp；交易內刪除舊 GroupType=3 直接與代理人列、插入新的直接成員並維持 `AddUserAgentToGroup` 等價規則，任何錯誤全部回滾。
5. Copy 應在同一交易新增主檔、複製直接成員及代理人關聯；刪除應在同一交易刪 GroupType=3 關聯與主檔，並以單一 API 保證原子性。多選刪除的 API 回應需明確呈現每筆結果；正式 UI 不應把舊 Form 的部分成功隱藏。
6. 不要把舊 Core 的串接 SQL 帶入新 API；群組編號、使用者編號及集合條件都採參數化查詢，並驗證使用者狀態、群組權限、重複鍵與併發版本。
