## 原程式畫面與查詢

上方為 Query 條件區，下方依序為 MaterialOut Basis 與 MaterialOut Detail Grid。Form 開啟時初始化 MaterialOutNo 與 InventoryNo 查找資料，但不執行主檔查詢。Query 條件的 CheckBox 預設不套用；使用者按 Query 才載入主檔。選取主檔列後呼叫 Detail Service。操作包含 Query、MaterialOutNo／InventoryNo 查找及 Close，沒有資料異動或列印按鈕。

查詢條件是精確 `MaterialOutNo`、`InventoryNo`、`PreOrderNo`、State，以及各自可選用的 From／End CreateDate 和 From／End MaterialOut Date。State ValueList 為 0–3。日期控制項預設顯示最近 14 日到今日，但對應 CheckBox 未勾選時不會送出條件。Service 將有勾選的值送至 Core `LoadINVMaterialOutBasis`。

Basis Grid 顯示 `MaterialOutNo`、`InventoryNo`、`PreOrderNo`、`State`、`ConfirmDate`、`Description`、`Creator`、`CreateDate`、`ConfirmUserNo`。Detail Grid 顯示 `MaterialNo`、`MaterialLotNo`、`LocatorNo`、`PutInPlaceType`、`PutInPlaceNo`、`UnitNo`、`Qty`；`Qty` 顯示最多六位小數。Core 回傳的 `MaterialName` 被 Form 隱藏。Detail 以 DataRelation 顯示元件子列；Form 顯示 `DEV_SLOTNO`（Core projection alias `DEV_SLotNo`）、`ComponentNo`、`DEV_CassetteNo`，隱藏關聯鍵及其餘元件欄位。

Core Basis 查詢從 `TBLINVMATERIALOUTBASIS` 取資料，對單號、庫房、預訂單、State 使用相等條件；CreateDate 以主檔 `CreateDate` 範圍比對。MaterialOut Date 不是 `ConfirmDate`，而是子查詢 `TBLINVTRANSACTIONLOG` 的 `Source=1`、`TicketNo`、`CreateDate`，用符合日期的 TicketNo 篩主檔。起日或迄日可單獨指定；缺少的一側由 Core 補 `2000/01/01` 或 `3000/01/01`，日期型迄日加到當日 `23:59:59`。Detail Core 讀 `TBLINVMATERIALOUTDETAIL` 並 left join `TBLMTLMATERIALBASIS`，限制 `IssueState=2`；元件由 `TBLINVMATERIALOUTCOMPONENT` 依單號、物料及批號查回，再以 `MaterialNo + MaterialLotNo` 建 DataRelation。

來源 SQL 沒有明確 `ORDER BY`、分頁或最大筆數。查詢日欄位分別是 Basis.CreateDate 和 TransactionLog.CreateDate；呈現的 ConfirmDate 是另一欄，不可拿它取代出庫交易日期篩選。

## 空單號明細風險

按 Query 後若主檔為零筆，Form 會呼叫 `funLoadDetail("")`。Service 把空字串傳給 Core；Core 只有在單號不等於預設空值時才加 `MaterialOutNo` 條件。因此空單號會查詢全部領料明細與全部元件，不能將此舊行為複製到 Web API。DEV 預覽在沒有作用中主檔時不載入明細；正式 API 必須要求有效 `MaterialOutNo`，查無主檔時回傳空集合。

## Vue DEV 頁

- `web/src/components/InvMaterialOutLog.vue` 是路由入口；僅 Vite DEV 且 `developmentPreview=true` 時載入 `InvMaterialOutLogDevPreview.vue`，正式環境顯示尚未開放提示。
- 固定假資料模擬精確單號／庫房／預訂單／State、建立日與出庫交易日篩選；按 Query 後顯示主檔，選列後顯示明細與元件子列。MaterialOutNo 和 InventoryNo 提供 DEV lookup；PreOrderNo 可直接輸入。
- DEV 初始不載入主檔結果，日期欄空白代表不套用條件；建立日比對假主檔 CreateDate，出庫日期比對假 `Source=1` 交易 CreateDate，與 Core 篩選欄位分開。單選主檔更新下方明細。
- 頁面只有固定 fixtures，不使用 localStorage，不呼叫 MES、Oracle、YMES PostgreSQL 或正式 API；不執行庫存異動、交易確認、分頁、報表或實際 `frmCOMSearch`。Fixture 順序不是 Core 排序保證，假元件只展示 Form 顯示欄位。

## 資料表、DDL 與 Oracle 查證

本功能查詢 `TBLINVMATERIALOUTBASIS`、`TBLINVMATERIALOUTDETAIL`、`TBLINVMATERIALOUTCOMPONENT`、`TBLMTLMATERIALBASIS`、`TBLINVTRANSACTIONLOG`；Lookup 使用原料 Inventory Basis。Repo 未找到本版本 MaterialOut Basis／Detail／Component 的 Oracle source DDL／metadata 或可信 PostgreSQL CREATE-only。`TBLINVTRANSACTIONLOG` 可沿用 WP605 已有來源 DDL 與 CREATE-only reference。公司桌機受保護 Oracle profile／attachment 不存在；本輪未使用 PowerShell 5.1／ODP.NET 查 MESTEST，未查業務資料，也未猜 CREATE SQL。

## 家用端 API／schema handoff

- 先 pull 最新 `main` 並核對 YMES PostgreSQL live schema／migrations。確認三張 MaterialOut 表欄位、key、型別及關聯；無可信來源時不得從 Core `SELECT *` 或投影欄位猜 DDL。Transaction Log 優先重用 WP605 reference 並核 live schema。
- 提供登入與 `IV208` Function ACL 保護的唯讀 Basis 查詢，精確支援 MaterialOutNo、InventoryNo、PreOrderNo、State、CreateDate 範圍及出庫交易日範圍。使用參數化條件、穩定排序、分頁與伺服器端上限；一側日期可以省略，date-only 迄日應含完整當天。
- 出庫交易日條件關聯 `TBLINVTRANSACTIONLOG.Source=1`、`TicketNo=MaterialOutNo`、TransactionLog `CreateDate`；不可用 Basis `ConfirmDate` 替代。回傳欄位依 WinForms 顯示投影，不代表可寫入。
- Detail endpoint 必須以路由 `MaterialOutNo` 作必要條件，例如 `GET /api/inventory/material-out/logs/{materialOutNo}/details`；無主檔或無明細回傳空陣列，禁止空單號全表查詢。元件查詢限同一單號並關聯 MaterialNo／MaterialLotNo；遵守 Form 的顯示白名單。
- Core 以字串串接 SQL 和 `AdditionalXml`，不可直接移植。公司端未連 YMES PostgreSQL、未實作正式 API/schema，缺可信 DDL 前不新增 CREATE-only。
