# IV204 開立庫存調整單

更新日期：2026-11-25。公司端交付範圍為 MES WinForms／Service／Core 核對、Vue 3 DEV 假資料 UI 與家用端 API／schema handoff；未連 YMES PostgreSQL，未實作正式 API。

## 功能與入口

- FunctionKey：`MATERIAL ADJUST`，功能代碼 IV204；舊 Form `frmINVMaterialAdjust`，執行檔 `IV_MaterialAdjust.dll`。
- Vue DEV 路由 `/YMES/INV/MaterialAdjust`。此功能建立／維護原料庫房庫存調整草稿，分為 Adjust（數量調帳，AdjustType=0）與 LocatorAdjust（儲位調撥，AdjustType=1）。
- IV204 不含確認／過帳按鈕。實際庫存異動從 IV201 原物料倉庫房資料的 MaterialAdjust Confirm 流程執行，交易來源為 Source=3。

## 查詢與主檔

- 啟動及 Query 都呼叫 `LoadINVMaterialAdjustBasis`，Form 固定傳 `State=0` 再加 Query Template 條件；`SetSearchFieldName` 僅指定 `MaterialAdjustNo`。畫面主 Grid 顯示單號、InventoryNo、AdjustType、State、Description、Creator／CreateDate、Reviser／ReviseDate，依 MaterialAdjustNo 排序。
- State 顯示值：0 未確認、1 處理中、2 已確認、3 失敗。IV204 清單只載入 State=0；選取主檔後才載入其明細。
- 新增／Copy 主檔要求 MaterialAdjustNo、InventoryNo、AdjustType。Inventory Lookup 呼叫 `LoadInventoryBasis(IssueState=2, InventoryType=0)`，只選有效原料庫房。系統 `MATERIALADJUSTNO` Serial Rule 可開啟 `GetMaterialAdjustNo` 取號；表單也保留單號欄位。
- 新增主檔由 Core 初始寫入 State=0。Edit 只允許 State=0，MaterialAdjustNo、InventoryNo、AdjustType 鎖定，只編輯 Description 並帶 DataStamp。
- Copy 主檔將單號清空、沿用 InventoryNo／AdjustType／Description；主 Form 沒有複製明細的呼叫，因此 Copy 結果是空明細草稿。
- 刪除只接受 State=0。Core 在同一 CollectionSQL 先刪 `TBLINVMATERIALADJUSTDETAIL` 再刪 Basis；沒有刪 `TBLINVMATERIALADJUSTCOMPONENT` 的語句，舊資料可能留下孤兒 Component。

## 明細查詢與維護

- Detail Grid 依 MaterialAdjustNo、MaterialNo、MaterialLotNo、LocatorNo 排序，顯示 MaterialNo／Name、Lot、來源 Locator、FinalLocatorNo、UnitNo、OrgQty、FinalQty、DiffQty、建立／修改人與時間。MaterialName 從目前 IssueState=2 MaterialBasis 查得，不是單據名稱快照。
- 新增與 Copy 可由 `LoadRawInventoryLoc(InventoryNo)` 選來源庫存批，候選欄位包含 Inventory／Locator／Material／Name／Lot／LocQty／InputDate／Vendor／效期與製造日；UnitNo 另由 `LoadRawInventory(InventoryNo)` 依 MaterialNo 取值。Edit 鎖定來源 Locator／Material／Lot，只能改調整值或目的 Locator。
- AdjustType=0 的來源 Lookup 加條件：`MaterialNo not in (Select MaterialNo from tblINVRawInventoryComponent)`，表單要求 FinalQty 為數字且大於 0，計算 `DiffQty = FinalQty - OrgQty`，FinalLocatorNo 固定為來源 Locator。
- AdjustType=1 的來源 Lookup 排除出現在 State=0 MaterialOut Detail 的 MaterialNo。目的 Locator Lookup 限定同 InventoryNo 且 IssueState=2；FinalLocatorNo 必填且不得等於來源 Locator。表單送 FinalQty=0、DiffQty=0；過帳以 OrgQty 移轉數量。
- Service 新增明細前呼叫 `ChkMaterialAdjustDuplicate(InventoryNo, LocatorNo, MaterialNo, MaterialLotNo)`。Core 以相同庫房／來源儲位／料號／批號查任何 `State<>2` 的調整單；因此 State=0／1／3 的既有列都會阻擋再新增，包含同一草稿已存在的列。Edit 不呼叫該重複檢查。
- AdjustType=1 新增明細時，Core 另從 RawInventoryComponent 複製 ComponentNo、可用時的 CassetteNo／SlotNo 到 MaterialAdjustComponent。Edit、Detail Delete 與 Basis Delete 均未見相應 Component 清理／重建語句。

## IV201 Source=3 過帳邏輯與風險

- IV201 的 `frmINVMaterialAdjustConfirm` 只列 State=0 單據。過帳由通用庫存交易確認流程呼叫 `ExeMaterialAdjust`；成功／失敗狀態及 Transaction Log 由 IV201 Service 流程處理。IV204 僅維護草稿。
- AdjustType=0：Core 以每筆 DiffQty 更新 Raw Inventory 的 CurQty 及 Raw Inventory Loc 的 LocQty；查不到既有彙總／儲位列時該段不新增，也沒有在這個函式中重驗來源數量、OrgQty 或鎖定版本。Formal API 應在一次交易重讀並驗證庫存，再原子更新彙總與儲位。
- AdjustType=1：Core 先查是否有未確認領料單；任何明細料號出現在任一 State=0 MaterialOut Detail 即拒絕調撥，查詢範圍沒有以庫房、Lot 或 Locator 收窄。之後檢查目的 Locator 容量，再扣來源 Locator 的 OrgQty、刪除變成 0 的來源列，並將 OrgQty 加到或新增至目的 Locator。
- 舊容量檢查只讀取第一筆符合的列，將 OrgQty、Capacity 轉成整數後比較，沒有把目的儲位現有 LocQty 加總，也沒有完整批次加總；正式 API 必須依目的儲位現有量與整批移入量核算可用容量，並在交易內防止並行超賣。
- Core 以字串串接 SQL 條件。Basis／Detail Edit 的更新條件、Component 關聯與複合鍵在缺少本版 DDL 時無法完整確認；不能據猜測新增 schema 或 CREATE SQL。

## Vue DEV 復刻

- 已接 App FunctionKey `function:INV:MATERIAL ADJUST`、路由 `/YMES/INV/MaterialAdjust`，提供查詢、主／明細雙 Grid、State=0 草稿 CRUD、Copy、原料批及目的 Locator 假 Lookup、數量 Diff 即時計算、刪除確認與 Component 子列。
- DEV 假資料包含數量調帳、儲位調撥、不同 Locator 的同料號／Lot、Component 候選、未確認領料排除、停用目的儲位與已確認隱藏歷史列。操作只保存在瀏覽器 localStorage，不呼叫正式 API、不過帳。
- Copy 主檔不帶明細；Copy 明細會建立新列；編輯明細保留來源鍵。DEV 子列依 MaterialNo／Lot 精準呈現，避免重現舊 DataRelation 只以 MaterialNo 關聯造成跨 Lot Component 混列的風險。
- DEV 單號產生器只模擬 serial rule，不連 MES 的序號服務。DEV 為刪除草稿同步清除畫面內 Component 子列；舊 Core 未清理 Component 的落差已列於上文與家用端 handoff。

## 家用端 API／schema handoff

- 家用端先以 live PostgreSQL／已提交 migrations 核對上述 Basis、Detail、Component、Raw Inventory、Raw Component、MaterialOut 與 Transaction Log 的欄位長度、數值精度、PK／FK、索引及既有 state semantics；未知 DDL 不可由舊 SQL 自行補猜。
- 提供登入與 IV204 Function ACL 保護的有限量查詢，以及 State=0 Basis／Detail 新增、編輯、刪除端點。查詢使用 MaterialAdjustNo、State 與庫房授權範圍的參數化條件、穩定排序和 bounded paging；Detail 端點必須要求有效父單號。
- Basis Copy 只建立空草稿。以 server side serial service 取號／檢查唯一性；新增固定 State=0。Edit 維持 InventoryNo／AdjustType／MaterialAdjustNo 不可改，只更新 Description，並用 RowVersion／DataStamp compare-and-set。
- Detail DTO 使用已核實的完整複合鍵與版本欄位；來源庫存應由 server 依 InventoryNo／LocatorNo／MaterialNo／LotNo 重讀，UnitNo、OrgQty、DiffQty 不信任 client。數量調帳要求 FinalQty>0 並在 server 由當下 LocQty 推導 DiffQty；調撥要求有效、不同的目的 Locator。
- 保留舊候選規則但加上庫房／批號範圍：數量調帳排除 Component 料；儲位調撥檢查待領料佔用。調撥新增時的 Component 快照、明細更新／刪除與主檔刪除須在同一交易正確同步刪除子表，不能重現孤兒 Component。
- 過帳仍由 IV201 Source=3 的正式交易 API 負責：重驗單據 State、Raw CurQty／LocQty、未確認 MaterialOut 與目的 Locator 容量，使用參數化 SQL，在單一交易內更新庫存、Component／交易記錄及 Basis 狀態；對重送使用 idempotency key，對平行修改用版本／row lock，回傳實際逐單結果。
- 家用端不得直接套用 IV204 的原生 CREATE-only SQL（本輪未取得）；以已核實 live schema／正式來源 DDL 決定 migration。公司端不連 PostgreSQL、不實作／驗收正式 API。
