## 原程式畫面與操作

主畫面有 MaterialOut Basis 與 MaterialOut Detail 兩個 Grid。Form 開啟及 Query 時固定傳 `State=0`，並依 `MaterialOutNo` 升冪顯示；搜尋欄只設定 `MaterialOutNo`。開啟後自動選取第一筆並載入明細。Core 查詢支援更多條件，但主畫面沒有顯示 Inventory／PreOrder／日期等篩選欄。

Basis Grid 顯示 `MaterialOutNo`、`InventoryNo`、`PreOrderNo`、`State`、`ConfirmUserNo`、`Description`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`。Detail Grid 顯示 `MaterialNo`、`MaterialName`、`MaterialLotNo`、`LocatorNo`、`PutInPlaceType`、`PutInPlaceNo`、`UnitNo`、`Qty`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`；Quantity 顯示到小數六位。資料依單號、物料、批號、Locator、PutInPlaceType、PutInPlaceNo 排序。Detail Grid 以關聯資料顯示 `TBLINVMATERIALOUTCOMPONENT` 元件列。

- 單頭提供 ADD、EDIT、DEL、COPY、PRINT。ADD／COPY 建立 State=0；EDIT／DEL 只允許 State=0。Copy 會帶原庫房、PreOrderNo、Description，但新單號清空，**不複製原單明細**。EDIT 鎖定單號與庫房，只改 PreOrderNo／Description 並傳 DataStamp。Delete 可多選；WinForms 逐張呼叫 Service，若中途失敗，先前刪除不會自動回復。
- `MATERIALOUTNO` Serial Rule 啟用時，單號由 `wsSYS.GetMaterialOutNo` 取號並保留，欄位鎖定；停用時使用者可輸入單號。正式端由伺服器套用取號規則及防重。
- PRINT 對選取單據產生 `arMaterialOut`，會逐筆處理多選列。Vue 只預覽目前作用中單據，不連印表機、不輸出正式報表，也未模擬多選列印。
- 明細提供 ADD、EDIT、DEL、COPY；只有目前單頭 State=0 可操作。EDIT 鎖定物料／批號／Locator，修改數量及領料去向等欄位並傳 DataStamp。Detail Copy 以原列開新列，需重新確認 component 選取。

## 預訂單、物料與去向規則

- Basis 的 PreOrderNo 可空白；選擇時 Form 依 InventoryNo 載入同庫房 `State=2` 預訂單。Core 新增單頭固定 `State=0`，並寫單號、庫房、可選 PreOrderNo、Description、Creator、CreateDate。
- 明細物料由該原料庫房的 `LoadRawInventoryLoc` 查找，帶入 MaterialNo、MaterialName、MaterialLotNo、LocatorNo、VendorNo、UnitNo；MaterialNo／批號／Locator／Unit 在明細 Form 鎖定，由庫存批號查找選取。
- PutInPlaceType 對應 `0=EQP`、`1=OP`、`2=WIP INV`、`3=MO`、`4=Unproductive`。Core 驗證 Qty>0；Service 對 0–3 呼叫 `ChkINVMaterialOutDetailValid`，檢查 EQP／OP／WIP Inventory／MO 目標狀態。Type=4 由 Service 略過該 Core 目標檢查。MO 去向另讀工單 Material List，要求所選物料或 Substitute Material 對應工單需求；多筆替代料時需使用者挑選對應料號／層級。
- 建立領料草稿時不檢查原料目前可領數量。`ChkMaterialOutQty` 在 IV201 的 Source=1 確認流程檢查明細彙總、預訂與單位換算後的可用量；未預訂與有預訂單走不同分支。此時才會執行實際扣庫存，不可在 IV203 提前扣帳或把「建立單據成功」顯示成「已出庫」。
- 若所選庫存 lot 帶元件資料，明細 Form 展開 Component Grid。至少選一筆；Form 以 `CInt(Qty)` 和所選元件筆數比較，小數數量可能先轉整數再比較。新增元件明細會另外寫 `TBLINVMATERIALOUTCOMPONENT` 並把 `TBLINVRAWINVENTORYCOMPONENT.BookingFlag` 設為 1；刪除時清除元件關聯並把預約旗標復原。Service 分開呼叫明細與元件 Core；家用端應以同一資料庫交易保護明細、元件和 BookingFlag，避免部分成功或重複預約。
- 單頭刪除 Core 同時處理明細、Basis、元件及元件 BookingFlag；正式端需先重讀 State、以交易依相依次序刪除並復原預約，不可只刪主檔。原始 SQL 字串串接與 `AdditionalXml` 條件不應沿用到正式 API。

## 資料表、DDL 與 Oracle 查證

Core 直接使用 `TBLINVMATERIALOUTBASIS`、`TBLINVMATERIALOUTDETAIL`、`TBLINVMATERIALOUTCOMPONENT`、`TBLINVRAWINVENTORYCOMPONENT`，並依賴 `TBLINVRAWINVENTORY`／`TBLINVRAWINVENTORYLOC`、`TBLINVPREORDERBASIS`／`TBLINVPREORDERDETAIL`、核准物料及 EQP／OP／WIP／MO 主檔與工單物料清單。IV201 確認另使用共用 `TBLINVTRANSACTIONSTATE`／`TBLINVTRANSACTIONLOG`。

Repo 沒有可核對本版本 `TBLINVMATERIALOUTBASIS`、`TBLINVMATERIALOUTDETAIL`、`TBLINVMATERIALOUTCOMPONENT`、`TBLINVRAWINVENTORYCOMPONENT`、`TBLINVPREORDERBASIS`、`TBLINVPREORDERDETAIL` 的 Oracle source DDL／metadata 或專屬 PostgreSQL CREATE-only；`TBLINVRAWINVENTORY`／`TBLINVRAWINVENTORYLOC` 的 DDL 缺項已記在 IV201 handoff。桌機受保護 Oracle profile／attachment 不存在，本輪未使用 ODP.NET 查 MESTEST，未查業務資料。共用 Transaction State／Log 沿用 WP605 references；不從 Core INSERT／SELECT 欄位推測其餘表型別、nullable、default、PK/FK/index，也不產生猜測 CREATE SQL。

## 家用端 API／schema handoff

- 先 pull 最新 `main` 並核 PostgreSQL live schema／migration。若任何 Basis、Detail、Component、RAW Component、PreOrder 表或必要欄位缺失，先以可信 Oracle DDL／metadata和既有 migration 核實後再設計 forward migration；共用 transaction state/log 沿用 WP605 refs。
- 提供登入及 IV203 Function ACL 保護的 State=0 單頭查詢、建立／修改／刪除及明細查詢／維護 API。所有 mutation 伺服器端重讀單頭 State=0；header Edit 限 PreOrderNo／Description 並 DataStamp compare-and-swap；Delete 需在同交易清除明細／元件並釋放 component BookingFlag。
- `MaterialOutNo` 由伺服器 serial service 產生或驗證。`InventoryNo` 必須是 InventoryType=0。PreOrderNo 可空白；若指定，須重查同庫房且 State=2 並核對預訂品項／數量／單位。不可信任瀏覽器傳入 Creator、State、DataStamp 成功狀態或任意 AdditionalXml。
- 明細建立／修改時確認單頭、庫存批號、Vendor／Unit／Locator、PutInPlace target、MO material/substitute 規則與 Qty>0；明細加上 component row、RAW Component BookingFlag 更新須單一交易且具唯一／鎖定保護。以 component row selection 數量比對明細 Qty。
- 草稿 CRUD 不扣 `CurQty`。IV201 Source=1 確認需鎖定單據／庫存，呼叫或重建 `ChkMaterialOutQty` 的預訂分支、單位換算、可用量檢查，並以同一交易更新交易狀態／Log、單據狀態、RAW inventory／Locator 與元件副作用，提供冪等鍵及可恢復失敗結果；確認尚未部署前，IV203 API 不可回報已出庫。
- 原 Core SQL 以字串組合條件；正式 API 全部使用參數化 SQL、明確排序與合理分頁。新增 API 前先確認 live schema，缺可信 DDL 的表不提交 CREATE-only。
