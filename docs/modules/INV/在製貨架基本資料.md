# IV103 在製貨架基本資料

## 功能範圍

- MES 選單：庫存管理 → 庫房設定 → 在製貨架基本資料。FunctionNo=`STOCKER BASIS`、FunctionKey=`IV103`、Form=`frmINVStockerBasis`、ExecutionFile=`IV_StockerBasis.dll`、ActiveModule=`WIP`。
- Vue DEV 路徑：`/YMES/INV/StockerBasis`；功能鍵 `function:INV:STOCKER BASIS`。
- 功能包含貨架主檔 CRUD／簽核、由 V/H 尺寸配置的 Locator 明細、逐格 LocatorNo 編輯，以及選取主檔時載入下方明細表。
- 假資料鍵：`ymes.dev.inv.stocker-basis.v1`；只存瀏覽器 localStorage，不呼叫正式 API。

## WinForms 主畫面

- 來源 `frmINVStockerBasis` ClientSize 1008×591。啟動時載入 CapacityCtrl ValueList、查詢欄設為 `StockerNo`、狀態預設 IssueState=0。
- 主 Grid 欄位：StockerNo、FactoryNo、AreaNo、VNumber、HNumber、CapacityCtrl、Description、QtyLimit、Creator、CreateDate、Reviser、ReviseDate；IssueState 留在資料列供狀態判斷，畫面隱藏。
- 下方 Locator Grid 顯示 StockerNo、LocatorNo、VerticalPosition、HorizontalPosition，依 LocatorNo 排序；切換主列會呼叫 `LoadINVStockerDetail(StockerNo)`。
- 主按鈕 Add／Edit／Delete／Copy／Approve／Close。Edit 僅允許 IssueState=0。Delete、Approve 依選取列逐筆呼叫 Service，遇到失敗即停止，先成功的列不會回滾。

## 貨架編輯與 Locator 配置

- `frmStockerBasisDef` ClientSize 880×429。欄位 StockerNo、AreaNo、VNumber、HNumber、CapacityCtrl（QtyLimit checkbox）、QtyLimit、Description；另有動態 Locator 配置面板。
- Area 由 `wsSMD.LoadAreaBasis` 的 Area lookup 選擇，選取結果同時提供 FactoryNo；不是讓使用者任意輸入 FactoryNo。
- StockerNo 必填，離開欄位時 trim 並轉大寫。AreaNo 必填。VNumber、HNumber 必須是正整數；輸入尺寸變動後重建所有格位。
- CapacityCtrl=1 時 QtyLimit 必填、須為正整數。舊錯誤訊息提到 1–999，但實際驗證只檢查正整數下限，沒有 999 上限；CapacityCtrl=0 時編輯送出不帶 QtyLimit，Core 將 QtyLimit 清空。
- Locator 格位按鈕為 50×50。VNumber 是水平排列的欄數（VerticalPosition）；HNumber 是垂直排列的列數（HorizontalPosition）。預設編號序號為 `(HorizontalPosition - 1) × VNumber + VerticalPosition`，LocatorNo=`StockerNo + 序號`。舊版註解的略過 I／O 字元演算法已不在目前執行程式中。
- 點格位可開 `frmINVLocatorNoEdit` 自訂 LocatorNo；視窗只檢查不可空白，沒有程式端重複值檢查。若尺寸改變，全部 LocatorNo 重建為預設序號；尺寸不變時保留已載入的自訂名稱。
- Add 建立未簽核主檔及全部格位。Copy 帶入來源欄位和 Locator 明細；StockerNo 初始仍是來源值，使用者改編號時依舊 Form 的 Leave 行為重建預設 LocatorNo。未改編號就送出時可能因既有鍵或資料庫限制失敗，實際約束待 metadata 確認。Copy 不帶入貨架現況／上架內容。
- Edit 僅未簽核資料可用。`DataStamp` 用於主檔 CAS 更新；舊 Service 先更新主檔，再刪除該 StockerNo 的全部 detail 並逐格新增新清單。

## Service／Core 來源與狀態

- WinForms：`D:\iMES\CSiMES\STD\MESWin\INV\IV_StockerBasis\frmINVStockerBasis.vb`、`frmINVStockerBasisDef.vb`、`frmINVLocatorNoEdit.vb`。Form 與 Designer 初始化位於同一 `.vb`，沒有獨立 `.Designer.vb`。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsINV\wsINV.cs`：`LoadINVStockerBasis`、`LoadINVStockerDetail`、`AddINVStockerBasis`、`EditINVStockerBasis`、`DelINVStockerBasis`、`ApproveINVStockerBasis`；Area lookup 使用 `wsSMD.LoadAreaBasis`。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcINV\clsInventory.cs` 與 `D:\iMES\CSiMES\STD\MESkc\kcBasis_UPD\clsBasis_UPD.cs`。
- IssueState=0／-1 刪除會物理移除 `TBLINVSTOCKERBASIS` 與 `TBLINVSTOCKERDETAIL`；IssueState=2 只將主檔改成 -1 並更新 DataStamp／Reviser／ReviseDate，保留明細；IssueState=1 拒絕。
- Approve 目前執行 `SetINVSTockerBasisIssueState(..., 2, DataStamp, ...)` 直接核准。舊 IssueManagement `INVStocker BASIS` 分支為註解，Service 本身沒有建立簽核工作。
- Core SQL 使用字串串接。Service 的 Add 先新增主檔再逐格新增 detail；Edit 先 CAS 更新主檔、刪除全部 detail 再逐格新增。這些階段不是同一個交易；正式 API 必須參數化並以交易保護主檔與明細替換。

## Oracle DDL／schema 狀態

- 直接資料表為 `TBLINVSTOCKERBASIS`、`TBLINVSTOCKERDETAIL`。`database/reference/mestest_first_phase_create_tables.sql` 的 Stocker Basis CREATE 明確標記欄位為推測，不能作為 Oracle 來源 DDL；repo 沒有已核實的 Stocker Detail CREATE／metadata。
- 本桌機受保護 Oracle profile 不存在，本次未連 Oracle。兩表仍缺 Oracle `DBMS_METADATA.GET_DDL`、欄位 default/nullability、主鍵／索引／FK metadata 及正式 PostgreSQL CREATE-only。未提交推測 SQL。
- `TBLINVSTOCKERDETAILLOG` 的既有 WP902 DDL／metadata 是歷程記錄表，不是本功能的 Stocker Detail，不能替代。

## 家用端 API／schema handoff

1. 先比對 live `tblinvstockerbasis`、`tblinvstockerdetail`；第一階段 CREATE 對主表是推測，detail DDL 尚缺。確認欄位長度、numeric precision、PK、FK 和既有資料後，才新增 PostgreSQL CREATE-only／migration。
2. API 提供依 StockerNo／IssueState 查詢主檔與明細、Area lookup、Add、Edit、Copy、逐筆 Delete／Approve。Edit 要用 DataStamp CAS 並明確檢查更新筆數。
3. 主檔 Add 與 detail insert、Edit 主檔更新／明細整組 replace、狀態 0／-1 的主檔與明細實體刪除都應放入同一交易，避免舊 Service 分階段失敗留下半套資料。
4. 狀態語意依來源：0／-1 實體刪除；2 軟刪為 -1、保留 detail；1 拒絕。Approve 現行 Service 直接從 0 更新至 2；舊 IssueManagement 分支已註解，正式端需確認目前簽核需求再決定是否保留直接核准。
5. Area lookup 應回傳 AreaNo 與 FactoryNo；stockerno、locatorno、格數與數量欄位限制須以 Oracle metadata 和 live schema 為準，不沿用 first-phase 猜測長度。
