更新日期：2026-11-25。公司端已核對 WinForms inline Form／Designer、`wsINV`、`clsInventory` 及 IV403 草稿／IV401 確認流程，完成 Vue DEV 唯讀查詢。公司端未連 YMES PostgreSQL、未建立 schema／migration、未實作正式 API。桌機沒有可用的受保護 Oracle MESTEST profile，未查新 metadata 或猜測 CREATE SQL。

## 功能與入口

- FunctionNo：`SEMI OUT LOG`／IV406；Form `frmINVSEMIOutLog`，執行檔 `IV_SEMIOutLog.dll`。

## 查詢與畫面

- Form 初始化時先載入 SEMIOutNo 清單與 InventoryType=2 半成品庫房清單，供查找視窗使用。查詢條件為 `SEMIOutNo`、`InventoryNo`、State、From／End CreateDate、From／End INVDate；Source 未提供為使用者條件。
- SEMIOutNo、InventoryNo 精確比對。State 選項 0 UnConfirm、1 Handling、2 Confirm、3 Fail；預設不選狀態。
- CreateDate 與 INVDate 各自的 From／End 日期勾選框可以單獨使用。Core 將缺少的日期界線展開為 2000-01-01／3000-01-01，日期型 End 延伸至當天 23:59:59。
- INVDate 並非 Basis.ConfirmDate：Core 以單號查 `TBLINVTransactionLog`，條件為 `Source=21` 及交易 Log 的 CreateDate 區間。Form Basis Grid 顯示 `SEMIOutNo`、`InventoryNo`、`State`、`ConfirmDate`、`Description`、`Creator`、`CreateDate`。
- 舊 Core SQL 沒有 `ORDER BY`、分頁或筆數上限；使用者可不填任何條件而查整批出庫資料。SQL 以字串串接。正式 API 應使用參數化條件、Function／Inventory ACL、穩定排序及 bounded paging。
- 選取單頭後以 SEMIOutNo 呼叫 `LoadINVSEMIOutDetailAndComponent`。Detail Grid 顯示 ProductNo、LotNo、LocatorNo、PutInPlaceNo、UnitNo、Qty；PutInPlaceType 與其他欄位隱藏。Component 子列顯示 ComponentNo、GoodQty、ScrapQty、UnitNo。
- Core 以 `(SEMIOutNo, LotNo)` 建立 Detail／Component DataRelation。這是舊 Grid 的展開鍵，不足以證明資料庫唯一鍵；正式端要依 live schema 確認 Component 複合鍵及 Locator 關係。

## Vue DEV 行為與簡化處

- 完成 `/YMES/INV/SemiOutLog` 唯讀 DEV 頁，模擬精確單號／Inventory／State、CreateDate 與 INV Date 查詢、Basis 選列、Detail／Component 展開與數量合計。
- DEV 的 INV Date fixture 代表 `TBLINVTransactionLog` Source=21 的記錄時間；它不由 ConfirmDate 推導。資料只在頁面記憶體，不呼叫 MES、API 或資料庫。
- DEV fixture 保留固定順序，沒有模擬原 Core 可能回傳的大量結果、無排序查詢、真實權限與交易日誌 join。頁面沒有編輯、刪除、確認或扣庫存動作。

## 表格、DDL 與 PostgreSQL handoff

| 表 | 用途 | DDL／metadata 狀態 |
|---|---|---|
| `TBLINVSEMIOutBasis` | 出庫單頭、State／ConfirmDate | 沿 IV403；repo 未找到可信同版 Oracle DDL／metadata，桌機 profile 不可用 |
| `TBLINVSEMIOutDetail` | Lot／Locator／目的地／Qty | 沿 IV403；repo 未找到可信同版 Oracle DDL／metadata，桌機 profile 不可用 |
| `TBLINVSEMIOutComponent` | 出庫單 Component 關聯 | 沿 IV403；repo 未找到可信同版 Oracle DDL／metadata，桌機 profile 不可用 |
| `TBLINVTransactionLog` | INV Date 依 Source=21 的出庫過帳紀錄篩選 | 沿 WP605／IV403 家用端 references 核 live schema、TicketNo／Source key 與日期型別 |
| `TBLINVSEMIInventory`／Component | 出庫來源庫存 | 沿 WP201／WP604；本頁只讀查詢，家用端核 live schema |

沒有取得 Basis／Detail／Component 的可信 Oracle DDL／metadata。IV406 是唯讀頁，沿用 IV403 的出庫表與既有 TransactionLog，不新增資料表或 migration；不要從舊 SELECT 推測 constraints。

## 家用端 API handoff

- 沿用 IV403／IV401 的授權表與狀態定義，提供可分頁的出庫單查詢 API。支援 SEMIOutNo、InventoryNo、State、CreateDate 與 INVDate；空條件仍需受 ACL 範圍與筆數上限保護。
- INVDate 必須從 `TBLINVTransactionLog` 以 `Source=21` 和 TicketNo 關聯篩選。使用 EXISTS 或去重 join，避免單號有多筆 Log 時重複 Basis rows；不可把 ConfirmDate 當 INVDate。
- Detail／Component 由授權父單號限定，參數化並穩定排序。確認 Component 的 live key；WinForms relation 僅 `(SEMIOutNo, LotNo)`，未包含 LocatorNo。
- 日期採企業時區及明確的含結束日契約；舊程式 `23:59:59` 在毫秒精度資料庫可能漏資料，正式 API 可用半開區間 `[from, to+1 day)`。
- IV406 僅查詢。IV403 草稿維護及 IV401 過帳是獨立寫入路徑，不能在 log API 內變更 State 或庫存。
