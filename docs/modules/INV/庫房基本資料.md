# IV102 庫房基本資料

## 功能範圍

- MES 選單：庫存管理 → 庫房設定 → 庫房基本資料。FunctionNo=`INV BASIS FOR INV`、FunctionKey=`IV102`、Form=`frmInventoryBasis`、ExecutionFile=`IV_InventoryBasis.dll`。
- Vue DEV 路徑：`/YMES/INV/InventoryBasis`；功能鍵 `function:INV:INV BASIS FOR INV`。
- 主畫面包含庫房主檔、Property 子畫面及 Locator 子畫面。Property 是本功能整合管理；Locator 共用儲位基本資料功能。
- DEV 庫房與 Property 假資料儲存鍵：`ymes.dev.inv.inventory-basis.v1`。Locator 以既有 `/YMES/SMD/LocatorBasis` DEV storage 保存；均不呼叫正式 API。

## WinForms 主畫面

- 來源 `frmInventoryBasis` ClientSize 1008×591。IssueState 四狀態篩選，預設未簽核；查詢欄僅設 `InventoryNo`。清單按 InventoryNo 排序。
- Grid 顯示 InventoryNo、InventoryName、InventoryType、InventoryClass、FactoryNo、EngineerGroupNo、Description、Creator、CreateDate、Reviser、ReviseDate。IssueState、DataStamp 等欄位留在資料列但不顯示。
- 操作按鈕：Add、Edit、Delete、Copy、Approve、Property、Locator、Close。Edit 僅允許 IssueState=0；Approve 僅允許未簽核。Delete 多選逐列呼叫，簽核中列拒絕；先前成功的列不回滾。
- Inventory 定義窗欄位：InventoryNo、InventoryName、InventoryType、InventoryClass、FactoryNo、EngineerGroupNo、Description。InventoryNo、InventoryName、InventoryType、FactoryNo 必填；編號離開欄位時轉大寫。Add／Edit／Copy 使用同一套欄位；Copy 透過 Add service 建立新的主檔資料，不複製 Property／Locator 子資料。
- InventoryClass=0 為 System Define、1 為 User Define。InventoryType 由 `TBLINVINVENTORYBASIS.INVETORYTYPE` 值清單提供；畫面隱藏 ORDER(5) 與 PARK(8)，CORR(10) 只有符合特定 ActiveModule 條件才顯示。DEV 僅呈現一般可見類型，未模擬 module-specific CORR。
- FactoryNo 從 Factory Basis lookup，EngineerGroupNo 從 `wsINV.LoadINVEngineerGroupBasis` lookup；工程群組對應 IV101。

## Property 子畫面

- 主畫面選取庫房後開啟 `frmINVProperty`，四種 IssueState 篩選，預設未簽核。Grid 顯示 InventoryNo、PropertyNo、DefaultValue、PropertySequence、Description、Creator、CreateDate、Reviser、ReviseDate；操作 Add／Edit／Copy／Delete／Approve／Close。
- `frmINVPropertyDef` 編輯 PropertyNo、DefaultValue、PropertySequence、Description。PropertyNo 透過 PropertyType=8 定義查找（`wsSMD.LoadINVPropertyDefine`），不可自由輸入；新增與 Copy 由定義清單選擇。Edit/Copy 僅接受未簽核資料；新增／修改必須有 InventoryNo 與 PropertyNo。
- Add 建立 IssueState=0。Edit 使用 `(InventoryNo, PropertyNo, DataStamp)` 更新 DefaultValue／Sequence／Description 及 Reviser／ReviseDate，並遞增 DataStamp。Approve 的 IssueNo 為 `INV PROPERTY`；沒有 IssueManagement mapping 時直接設為 Active，有 mapping 時提交簽核流程。
- Delete 對未簽核／不使用資料實體刪除；已簽核資料改為 IssueState=-1 並更新稽核欄位／DataStamp；簽核中資料拒絕。多選逐筆處理，可能部分成功。

## Locator 子畫面

- `frmINVLocatorBasis` 收到主畫面選取的 InventoryNo，並以該庫房查詢；內容沿用 `docs/modules/SMD/儲位基本資料.md` 與 Vue `LocatorBasisMaster`。IV102 DEV 以 `initialInventoryNo` 鎖定目前庫房，不另造第二套 Locator 模型。
- Locator 共用已核對的 `TBLINVLOCATORBASIS` Oracle source DDL／PostgreSQL CREATE-only；IV102 不重複產生 SQL。

- WinForms：`D:\iMES\CSiMES\STD\MESWin\INV\IV_InventoryBasis\frmInventoryBasis.vb`、`frmInventoryBasisDef.vb`、`frmINVProperty.vb`、`frmINVPropertyDef.vb`、`frmINVLocatorBasis.vb`、`frmINVLocatorBasisDef.vb`。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsSMD\wsSMD.cs`（Inventory／Property）及 `D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsINV\wsINV.cs`（Locator）。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcSMD\clsINVBasis.cs`、`D:\iMES\CSiMES\STD\MESkc\kcBasis_UPD\clsBasis_UPD.cs`、`D:\iMES\CSiMES\STD\MESkc\kcINV\clsInventory.cs`。
- `clsINVBasis.DelInventoryBasis` 以 SQL collection 刪除 `tblINVInventoryBasis`、`tblINVInventoryProperty`、`tblINVLocatorBasis` 三表。Service 對 IssueState=0 或 -1 呼叫此物理刪除；IssueState=2 則使用版本更新將主檔標成 -1，不刪子資料。IssueState=1 被拒絕。
- `ApproveInventoryBasis` 使用 IssueNo=`INV BASIS`。無設定 IssueManagement mapping 時直接核准到 IssueState=2；若有 mapping，先改成 Pending 並建立簽核作業。Property 同理，IssueNo=`INV PROPERTY`。DEV 為可操作假資料，只模擬直接核准；沒有執行簽核引擎或 Email。
- Core 舊 SQL 將輸入值直接串入 SQL；新 API 必須改用參數化 SQL。多筆 Delete／Approve 是 Form 逐列呼叫，不是整批原子交易。

## Vue DEV 已模擬

- InventoryNo 查詢、四狀態篩選、Grid、Add/Edit/Copy/Delete/Approve、稽核欄位、DataStamp 假遞增與 factory／工程群組選擇。
- Delete 依舊 Service 規則：IssueState 0／-1 從假資料移除，2 改為 -1，1 拒絕。物理刪除也會清除 DEV Property 與既有 Locator storage 的對應假列。
- Property 有獨立四狀態 Grid、Add/Edit/Copy/Delete/Approve。舊 Form 以定義查找窗選 PropertyNo；DEV 用選單簡化，查找選項是明確標註的 fixtures。
- Locator 在子畫面重用 `LocatorBasisMaster`，帶入並鎖定所選 InventoryNo，仍使用該頁 DEV localStorage。離開 IV102 不會寫入後端。
- DEV InventoryType 選單未呈現舊 Form 隱藏的 ORDER、PARK、CORR；IssueManagement 設定、簽核任務和通知未模擬。

## Oracle DDL／schema 狀態

- `TBLINVINVENTORYBASIS` 和 `TBLINVInventoryProperty` 是本功能直接資料表。Repo 的 `database/reference/mestest_first_phase_create_tables.sql` 有 `tblinvinventorybasis` 推測 CREATE，但沒有可核實的 Oracle source DDL；`tblINVInventoryProperty` 也沒有對應的已查證 CREATE-only。
- 本桌機受保護 Oracle profile 不存在；本次未透過 PowerShell 5.1／ODP.NET 查詢。上述兩表仍缺 Oracle `DBMS_METADATA.GET_DDL`、欄位 nullable/default、主鍵／索引／FK metadata 及正式 PostgreSQL CREATE-only；不可把 first-phase 欄位推測當作來源結構。
- `TBLINVLOCATORBASIS` 已有 `database/reference/mestest_smd_locator_basis_source_ddl.sql`、`database/reference/mestest_smd_locator_basis_create.sql` 和 metadata reference。本功能沿用，不重複建表。

## 家用端 API／schema handoff

1. 先比對 live `tblinvinventorybasis`、`tblinvinventoryproperty`。主檔與 Property 缺可信來源 DDL；依 live schema 或取得正式 Oracle metadata 後補 schema，不複製 first-phase 推測型別。Locator 沿用已驗證 schema。
2. Inventory 主檔 API 提供受授權的查詢、Add、Edit、Copy、逐筆 Delete／Approve；查詢支援 InventoryNo 與 IssueState，並以分頁及參數化 SQL 限制結果。Edit 使用 DataStamp CAS，限制狀態 0，更新修訂資料。
3. Add／Edit lookup 提供合法 Factory、IV101 EngineerGroup 及目前 ActiveModule 可用的 InventoryType。型別值應由正式 value-list metadata 定義，不在 API/UI 另造 enum。
4. Property API 依 `(InventoryNo, PropertyNo)` 鍵與 IssueState 提供查詢／CRUD／簽核；PropertyNo options 來自 `PropertyType=8` 定義。刪除語意須保留 0／-1 實體刪除、2 軟刪為 -1、1 拒絕。IssueManagement 要沿用既有 `INV PROPERTY` workflow。
5. Inventory 主檔 0／-1 實體刪除時，在同一交易移除 Property 和 Locator；狀態 2 只軟刪主檔為 -1 並保留子資料；狀態 1 拒絕。正式端應先核對其他模組引用與 live FK，避免被使用中的庫房遭物理刪除。
6. Approve 依 `INV BASIS`／`INV PROPERTY` IssueManagement mapping 決定直接 Active 或 Pending+簽核工作；使用 server-side 權限、狀態及 DataStamp 驗證。舊 Form 的逐列批次可能部分完成，正式 API 應明確回傳每筆結果。
