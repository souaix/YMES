# IV210 預訂單記錄（Material PreOrder Log）

- FunctionKey：`IV210`；FunctionNo：`MATERIAL PREORDER LOG`；表單：`frmINVPreOrderLog`；分類：原物料倉。
- DEV 頁：`/YMES/INV/PreOrderLog`，Vue 功能鍵 `function:INV:MATERIAL PREORDER LOG`。
- 範圍：依條件唯讀查詢預訂單單頭，選取單頭後查看物料明細；此頁沒有新增、編輯、刪除、確認或庫存異動操作。

## 查證來源

- 主畫面與 inline Designer：`D:\iMES\CSiMES\STD\MESWin\INV\IV_PreOrderLog\frmINVPreOrderLog.vb`。
- Service：`D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsINV\wsINV.cs` 的 `LoadINVPreOrderBasis`、`LoadINVPreOrderDetail`。
- Core：`D:\iMES\CSiMES\STD\MESkc\kcINV\clsInventory.cs` 的同名 Basis／Detail 查詢。
- Lookup：Service 載入所有預訂單供 `PreOrderNo` 搜尋視窗使用；`wsSMD.LoadInventoryBasis(InventoryType=0)` 載入原物料庫房供 `InventoryNo` 搜尋視窗使用。State 顯示由 `TBLINVPREORDERBASIS.STATE` ValueList 提供。

## 原程式畫面與查詢

Form Load 初始化兩個 Grid 與 State ValueList，載入預訂單／原物料庫房搜尋資料；沒有自動執行結果查詢。Query 條件為精確 `PreOrderNo`、精確 `InventoryNo`、State，以及兩組可分別勾選的日期界限：CreateDate 和 INV Date。PreOrderNo、InventoryNo 可手動輸入或由搜尋視窗挑選。State ValueList 使用代碼 0–4；Form 內的舊註解依序列出 UnConfirm、Handling、Confirm、Fail、Used。

Basis Grid 顯示 `PreOrderNo`、`InventoryNo`、`State`、`ConfirmDate`、`Description`、`Creator`、`CreateDate`。`Description` 多行顯示；CreateDate／ConfirmDate 格式為 `yyyy/MM/dd HH:mm:ss`。Detail Grid 僅顯示 `MaterialNo`、`UnitNo`、`Qty`；Qty 右靠齊、最多六位小數。選取 Basis row 後以該 PreOrderNo 載入 Detail。

Core 從 `TBLINVPREORDERBASIS` 查單頭，欄位條件以 AND 串接；CreateDate 界限以單頭 CreateDate 篩選，缺任一端時 Core 補成 2000-01-01 或 3000-01-01，結束日期含當日 23:59:59。INV Date 的 SQL 是 `PreOrderNo IN (SELECT TicketNo FROM TBLINVTRANSACTIONLOG WHERE Source=4 AND CreateDate BETWEEN ...)`，因此應以 Source=4 的交易建立時間判斷；不可改用單頭 ConfirmDate。日期只有一端時 Core 會套用另一端預設界限。

Core 查詢沒有明確 `ORDER BY`、分頁或筆數上限。舊 Grid 支援使用者 layout，但正式 API 必須自行提供穩定排序與上限。點選群組列會呼叫 Detail 空單號；查詢後若沒有 Basis row，Form 也會呼叫 `LoadINVPreOrderDetail("")`。Core 在 PreOrderNo 空白時不加單號條件，會回傳全部 Detail。DEV 頁在無結果或未選單頭時維持空白明細；家用端 Detail API 必須要求有效 PreOrderNo，不可複製全表查詢行為。

## Vue DEV 頁

- `web/src/components/InvPreOrderLog.vue` 是路由入口；僅 Vite DEV 且 `developmentPreview=true` 時載入 `InvPreOrderLogDevPreview.vue`。
- 固定假資料覆蓋 State 0–4；支援 PreOrderNo／InventoryNo 假 Lookup、State、單號、CreateDate 與 Source=4 INV Date 篩選、Query／Clear、選取單頭載入唯讀明細。
- 起訖日期按日包含；DEV 的 INV Date 只檢查預置的 Source=4 假交易日期。頁面不呼叫 MES、Oracle、YMES PostgreSQL 或正式 API，沒有 CRUD／確認／庫存副作用。
- 空查詢結果安全地清空明細，不模擬 Legacy 空單號回傳全表的缺陷。

## 資料表、DDL 與 Oracle 查證

查詢直接使用 `TBLINVPREORDERBASIS`、`TBLINVPREORDERDETAIL` 與 Source=4 的 `TBLINVTRANSACTIONLOG`。PreOrder Basis／Detail 欄位型別、鍵、索引、關聯及完整 Oracle DDL／metadata 在 repo 中缺少可核實的同版來源；公司桌機受保護 Oracle profile 不存在，本輪未用 PowerShell 5.1／ODP.NET 連 MESTEST，也未猜 CREATE SQL。TransactionLog 沿用 WP605 已有 Oracle source DDL 與 PostgreSQL CREATE-only reference。

## 家用端 API handoff

- 提供登入及 IV210 Function ACL 保護的唯讀 Basis 查詢；參數化 PreOrderNo、InventoryNo、State、CreateDate 範圍和 Source=4 TransactionLog CreateDate 範圍。日期界限各自可選且按日包含；明確定義時區，避免資料庫／瀏覽器日期偏移。
- 先核對 YMES live schema／migrations。Basis／Detail 缺失或欄位／索引不符時先取得可信 DDL／metadata，不由 `SELECT *` 或 WinForms 條件反推欄位型別與鍵；共用 TransactionLog 先核 live schema 並沿用 WP605 reference。
- 回傳 Basis 欄位依 WinForms 可見欄位投影，State label 以明確代碼表呈現；提供穩定排序、分頁與最大筆數。Detail endpoint 要求有效 `PreOrderNo`，確認父單存在後只回傳該單明細，無明細回空陣列。
- Source=4 INV Date 使用交易 Log `TicketNo` 關聯預訂單號與 `CreateDate`；不得用 `ConfirmDate` 取代。所有 SQL 使用參數，不接任意 AdditionalXml 條件字串。
- IV210 為只讀查詢，不新增任何狀態或庫存寫入；預訂建立仍由 IV205，真正確認／庫存預約仍由 IV201 負責。
