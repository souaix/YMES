# IV502 開立成品／半成品入庫單

更新日期：2026-11-24。公司端交付範圍：WinForms／Service／Core 行為核對、Vue 3 DEV 假資料互動與家用端 API／schema handoff；未連 YMES PostgreSQL，未實作正式 API。

## 功能與入口

- 選單 FunctionKey：`FGD PRODUCT IN`，功能代碼 IV502；舊程式使用共用 `IV_ProductIn.dll`。此 Form 同時處理 FGD In（`ProductInType=0`）和 SEMI In（`ProductInType=1`），啟動預設選 FGD INV；IV502 對應預設的 FGD 分支，IV402 對應 SEMI 分支。
- Vue DEV 路由掛在既有選單 FunctionKey：`/YMES/INV/ProductIn`。DEV 假資料保存在瀏覽器 `localStorage`，Reset DEV 可還原；沒有接正式 API。
- 此功能只開立／編輯／作廢入庫草稿。真正庫存過帳由 IV501 成品庫確認及其 Source=30 交易流程處理，不可在 IV502 建單時直接增加目的庫存或扣除來源數量。

## 舊畫面與行為

### 主查詢、明細與列印

1. Form 載入時讀 `LoadINVSEMIInAndFGDIn(State=0, Source=1)`，合併未確認的線上入庫草稿；依 `ProductInType=0/1` 切換 FGD／SEMI Grid，並以 `ProductInNo` 排序。`InputDate` 在畫面欄位改名為 `ConfirmDate`。
2. Basis 列顯示 ProductInNo、InventoryNo、State、ConfirmDate、Description、FromInventoryNo、Creator／CreateDate、Reviser／ReviseDate。狀態 ValueList 包含 0 UnConfirm、1 Handling、2 Confirm、3 Fail、-1 Scrap；主清單查詢本身僅載 State=0、Source=1。
3. 選取單頭後按 `ProductInType` 呼叫 `LoadINVFGDInDetailAndComponent` 或 `LoadINVSEMIInDetailAndComponent`，載入 Lot／Component 關聯。Form 再用 WIP MO-Line Packing Relation 找最高層 PackingNo，並用 ProductNo／ProductVersion 查 `ProductPackingRuleBasis` 顯示 PackingName。
4. 明細欄包含 ProductNo／ProductName、LotNo、Qty、UnitNo、LocatorNo、PackingNo／PackingName；展開可看 ComponentNo、GoodQty、ScrapQty、UnitNo。
5. Print 依 FGD／SEMI 類型讀取對應 Detail 後交 `arProductIn`。DEV 僅提供預覽，沒有接舊報表引擎。

### 新增與編輯

- FGD／SEMI 由 RadioButton 切換，新增預設 FGD。取號依各自的 serial rule；選目的庫房時，FGD 查 InventoryType=1，SEMI 查 InventoryType=6。來源欄是 WIP 半成品庫房（InventoryType=6），來源 Lot 由 `LoadWIPInventory_SEMI(InventoryNo, BookingFlag=0)` 載入，Core 查詢同時限制 `Qty>0`。
- 每筆所選 Lot 送入 `TurnData`：LotNo、ProductNo、UnitNo、Qty、LocatorNo；`LoadInventory_Component` 的 Component rows 送入 `TurnComp`：LotNo、ComponentNo、GoodQty、ScrapQty、UnitNo。目的 Locator 由選取庫房可用的 Locator lookup 指定；未傳 Locator 時 Service 以 `N/A` 作預設。
- 儲存前要求入庫類型、單號、目的庫房、來源 WIP 半成品庫房及至少一個所選 Lot。若選 SEMI INV，任何有 PackingNo 的 Lot 都不允許開立；成品入庫可帶包裝，但必須選取最高層包裝，且該包裝的所有子 Lot 都已勾選。Form 重新載入包裝關係做檢查：不能選仍屬於更高層包裝的中間節點；選取的 To_PackingNo 必須是頂層且其所含 Lot 全部勾選。
- Add 呼叫 `UpdINVFGDIn` 或 `UpdINVSEMIIn`；Core 建立 State=0、Source=1 Basis 與 Lot／Component 明細，設定來源庫房及描述。指定 Lot 及所選 Component 會在來源 `TBLINVWIPINVENTORY_SEMI`／`TBLINVWIPINVENTORY_COMPONENT` 上設 BookingFlag=1，避免另一張單重複占用；Component 齊備後才會將 Lot 主列 BookingFlag 設為 1。Core 另將 `TBLWIPREVERSEHISTORY.CommitState=1`、CommitDesc=`INVFGDIn`，並建立 Lot 庫房變更歷程。
- Edit 只允許 State=0。Form 鎖住單號、類型及來源／目的庫房，允許調整描述與 Lot 明細；Service 傳 DataStamp。Basis 更新以 `ProductInNo + DataStamp + State=0` 作條件並遞增 DataStamp。Core 先解除舊 Lot／Component BookingFlag，再刪除並重建草稿明細，重新套用本次選取的來源預約。
- UI 支援 Copy mode 的共用維護對話框，但主清單沒有 Copy 按鈕；不把它當成一般 IV502 主流程。

### 作廢與確認界線

- Delete 可多選，但選列必須仍是 State=0；呼叫 `DelINVFGDIn`／`DelINVSEMIIn` 並帶 DataStamp。Core 將 Basis 設為 State=-1（Scrap），不物理刪除單頭或 Detail／Component 明細，僅解除 WIP Semi Lot／Component BookingFlag，保留歷史單據與內容。家用端應保留這個語意。
- IV502 沒有確認庫存的動作。後續 IV501 FGD Inventory 的待確認視窗處理 Source=30，才執行來源扣量、目的庫存新增及 Lot／Component 過帳。草稿 API 不得執行任何這些正式帳務效果。

## Vue DEV 復刻

已接 App 選單 FunctionKey `function:INV:FGD PRODUCT IN` 與 `/YMES/INV/ProductIn`：

- 主 Grid 顯示 State=0、Source=1 的目前類型草稿，可切 FGD／SEMI、以 ProductInNo 查詢；選列載入 Lot 明細與 Component 子列。

### 家用端 API／資料交易要求

1. 以登入身分及 Function ACL 保護列表、明細、建立、編輯、作廢端點；列表參數化 `ProductInType`、State、Source、InventoryNo、FromInventoryNo、ProductInNo，要求穩定排序、分頁及最大列數。IV502 預設 `ProductInType=0`，只顯示 State=0、Source=1。
2. Detail／Component 必須以父單號和入庫類型限定，禁止空父單號回全表。新增 request 傳入來源／目的庫房、描述及 LotNo／LocatorNo 清單；伺服器自行從 WIP 半成品庫重讀 Qty、Product、Unit、Lot／Component，忽略用戶端回傳數量作為帳務依據。
3. Create 用單一交易重驗目的庫房類型、來源 Lot `Qty>0 && BookingFlag=0`、Lot/Component 狀態與包裝最高層／完整子 Lot 規則；建立 Basis／Detail／Component、設定 BookingFlag、reverse history 與必要 Lot release log 同時成功或全部回滾。使用 idempotency key 防止重送建立重複草稿。
4. Edit 在交易中以 State=0 + DataStamp compare-and-swap 保護；重讀並鎖住舊／新來源 Lot 和 Component，解除舊預約、更新 Description／Detail、預約新集合並遞增 DataStamp。舊 Form 將單號、入庫類型、來源／目的庫房設唯讀，正式 API 需維持此不可變契約，除非後續有來源證據改變。
5. Delete 是作廢命令：以 State=0 + DataStamp 原子地設 State=-1、解除來源預約並保留 Basis／Detail／Component。不要物理刪除，也不要在 IV502 同時過帳庫存。確認由 IV501 Source=30 API 負責。
6. 請特別追查舊 Core `AddINVFGDInDetail_ArrayBinding` 對「有元件／部分元件」及 main Lot BookingFlag 的條件；API 需依實際 Component 完整性決定預約狀態，避免 Lot 已被部分預約時又被另一單挑走。
