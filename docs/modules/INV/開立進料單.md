# IV202 開立進料單（Material In）

- FunctionKey：`IV202`；FunctionNo：`MATERIAL IN`；表單：`frmINVMaterialIn`；分類：原物料倉。
- DEV 頁：`/YMES/INV/MaterialIn`，Vue 功能選單鍵 `function:INV:MATERIAL IN`。

## 原程式畫面與操作

主畫面上下兩個 Grid。查詢欄只套用 `MaterialInNo`；WinForms 傳 `State=0`，按單號升冪顯示，選取單頭後載入同單號明細。單頭顯示 `MaterialInNo`、`InventoryNo`、`VendorNo`、`State`、`Description`、`Creator`、`CreateDate`、`Reviser`、`ReviseDate`。明細按 `MaterialInNo, MaterialNo, MaterialLotNo, LocatorNo` 升冪，顯示 `MaterialNo`、`MaterialName`、`MaterialLotNo`、`LocatorNo`、`UnitNo`、`Qty`、`QCFormNo`、`ExpireDate`、`ManufactureDate`、`GraceDate` 及建立／修改者與日期；`LimitTime` 有資料欄位但 Grid 隱藏。

- 單頭按鈕：ADD、EDIT、DEL、COPY、PRINT。EDIT 與 DEL 限 `State=0`；單頭 EDIT 只改 `Description`，傳 `DataStamp`。COPY 建立新單頭，不複製原單明細。DEL 可多選逐張刪除，確認每張連結的 Incoming QC 均為 `Status=0`；舊 Form 逐張呼叫 Service，後續失敗時先前刪除不會自動復原。
- PRINT 使用 `arMaterialIn`，可列印選取單據。Vue 只提供 DEV 預覽，沒有連印表機或產生正式報表。
- 明細按鈕：ADD、EDIT、DEL、COPY。只有目前單頭 `State=0` 可操作。EDIT 鎖定物料、批號與 Locator，只修改數量、日期等欄位；若連結的 Incoming QC 已非 `Status=0`，禁止修改或刪除。COPY 以原明細帶值建立新列，Key 欄位可調整。
- `Close` 關閉視窗；重新查詢會重載單頭與目前單據明細。

## 單頭與明細規則

### 單頭

- ADD/COPY 必填單號、庫房、供應商；新增時 Core 固定寫 `State=0`。`InventoryNo` picker 呼叫 `LoadInventoryBasis(InventoryType=0)`，代表原料庫房，呼叫參數沒有明確帶 `IssueState`。`VendorNo` picker 使用 `LoadMaterialVendor(IssueState=2)`。
- `Description` 使用多行 RichTextBox；來源 Designer 沒有設定 MaxLength，Oracle 欄位長度也尚未取得，DEV 不自行限制長度。
- 單號依 `MATERIALINNO` 序號規則處理。若設定自動取號，欄位鎖定，新增前會檢查號碼並預約；未啟用自動取號時可手動輸入。正式 API 應由伺服器套用相同序號規則與防重，不採瀏覽器自行產生的流水號。
- EDIT 僅送單號、Description、State 與 DataStamp；庫房、供應商與單號不會由編輯動作更換。Core 以 DataStamp 附加條件更新。
- DEL 的 Core 會刪除明細與單頭；系統參數開啟 Incoming QC 時也會清理待檢 QC 表。舊 Core 的 SQL 集合先排明細／單頭刪除，再以明細子查詢清理 QC，家用端需確認 `ExecuteSQLNoneQuery_UPD` 順序及實際資料庫結果，並在正式 API 先取得 QC 關聯、用單一交易按相依順序刪除，避免孤兒資料。

### 明細

- 物料 picker 使用單頭供應商呼叫 `LoadMaterialBasis(VendorNo, IssueState=2)`；UnitNo 從物料主檔帶入且唯讀。Locator 依單頭 InventoryNo 查詢；庫房沒有 Locator 時使用固定值 `N/A`。
- `Qty` 必填、數值且大於 0。物料 `CheckLotNo=1` 時批號必填且不可為空白或 `N/A`；不追蹤批號的物料預設 `N/A`。若物料 `ExpireDateFlag=1`，ExpireDate 必填。
- 日期檢查程式拒絕 `ExpireDate < GraceDate`、`ExpireDate < ManufactureDate`、`GraceDate < ManufactureDate`；所以實際允許日期相等，雖然程式註解以 `>` 描述。
- 若庫房有 Locator，LocatorNo 必填且從該庫房選取；沒有 Locator 時使用 `N/A`。Core 編輯時另讀該 Locator 的 Capacity，數量不可超過容量；若指定非 `N/A` Locator 而查不到 Locator，會拒絕更新。新增明細的容量與資料庫限制仍須家用端依 live schema 核對。
- `LimitTime` 未顯示在主 Grid，但舊 Detail Form／Service 仍會在有值時傳送及保存；正式 API 不應因 UI 隱藏而遺失既有值。
- `MaterialInGenerateQCForm=1` 時，新增明細會讀該物料 QC Item，依 QC 類別從 Attribute、Variable 或 Group 主檔取得名稱，建立 `TBLSPCINCOMINGQCFORM` 及其 Item Map，並把 QCFormNo 寫入明細。沒有物料 QC Item 時不建立 QC。編輯既有明細時若 QC 待檢，Core 同步更新 QC 數量；刪除待檢明細會刪除其 QC Map 與 QC Header。這些寫入須與明細同一交易。
- Core 明細更新／刪除使用 `(MaterialInNo, MaterialNo, MaterialLotNo, LocatorNo)` 定位。這是目前可從 Service/Core 確認的操作條件，不能代替 Oracle DDL 對實際 PK／唯一索引的查證。

## 資料表、DDL 與 Oracle 查證

程式直接使用 `TBLINVMATERIALINBASIS`、`TBLINVMATERIALINDETAIL`、`TBLINVLOCATORBASIS`、`TBLMTLMATERIALBASIS`、供應商／物料 QC Item 資料及 Incoming QC Header／Item Map。Repo 搜尋沒有找到可核對此版本 `TBLINVMATERIALINBASIS`、`TBLINVMATERIALINDETAIL` 或 `TBLSPCINCOMINGQCFORM` 的 Oracle source DDL／metadata；受保護 Oracle attachment 在桌機不存在，本輪沒有連 Oracle，也沒有推測欄位或產生 CREATE SQL。`TBLSPCINCOMINGQCFORMQCITEMMAP` 已有 QC216 Oracle source DDL 與 PostgreSQL CREATE-only 參考：`database/reference/mestest_qc216_incoming_qc_item_map_source_ddl.sql`、`database/reference/mestest_qc216_variable_item_group_pmi_create.sql`，家用端先比對 YMES live schema 後沿用。

## 家用端 API／schema handoff

- 先查 PostgreSQL live schema、migration、現有 INV／MTL／SPC API；本輪沒有新增 Oracle CREATE-only。缺少主表 DDL 時不要由 DEV fixture 或 Core 欄位使用方式推測欄位長度、NULL/default、PK/FK/index。
- 提供受登入及 `MATERIAL IN` Function ACL 保護的單頭查詢／State=0 清單、單號條件、明細查詢，以及 InventoryType=0 庫房、IssueState=2 Vendor 與該 Vendor 核准物料、InventoryNo Locator lookup。查詢使用參數化條件、明確排序與合理列數限制。
- 單頭新增使用伺服器序號服務；編輯限 Description 並用 DataStamp compare-and-swap。刪除重讀單頭 State，檢查所有 Incoming QC 狀態並在同一交易刪除待檢 QC Map／Header、Detail、Basis；保持明確、可恢復的失敗結果。
- 明細建立／更新／刪除須重驗供應商物料、Unit、Lot、Locator、ExpireDateFlag、Qty、Locator Capacity、單頭未確認狀態和 Incoming QC 狀態。更新 DataStamp；QC Form／Item Map 與 Detail 寫入同一交易。不要從瀏覽器接受任意 `AdditionalXml`、Vendor／Creator／State 或可信 QC 狀態。
- IV202 只建立待確認進料單，不直接增加 `TBLINVRAWINVENTORY`。IV201 的 Source=0 確認流程負責單位換算與庫存過帳；需確認成功狀態、防重複、併發鎖與 transaction state/log 後才回報已入庫。
- 正式報表需另接授權的 `arMaterialIn` 相容輸出；不能將 DEV 列印預覽視為已完成報表。
