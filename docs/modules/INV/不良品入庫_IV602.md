# IV602 不良品入庫

## 功能與來源

- Oracle FunctionNo：SCR PRODUCT IN；FunctionKey：IV602；Form：frmINVSCRIn（inline Form／Designer）。主要定義窗：frmINVSCRInDef.vb。
- WinForms：D:\iMES\CSiMES\STD\MESWin\INV\IV_SCRIn\frmINVSCRIn.vb、frmINVSCRInDef.vb。
- Service：D:\iMES\CSiMES\STD\MESws_STD\wsSTD\wsINV\wsINV.cs 的 LoadINVSCRInBasis、LoadINVSCRInDetailAndComponent、LoadINVSCRInDetailAndFailBin、UpdINVSCRIn、EditINVSCRIn、DelINVSCRIn；取號由 wsSYS.GetSCRInNo。
- Core：D:\iMES\CSiMES\STD\MESkc\kcINV\clsInventory.cs 的 LoadINVSCRInBasis、兩種明細載入、UpdINVSCRIn、EditINVSCRIn、DelINVSCRIn、ExeSCRIn。
- IV601 frmINVSCRInConfirm 是獨立確認入口；IV602 建立／維護草稿，IV601 把未確認單據排入 Source=40 非同步交易。Source=40 是交易來源，不是 IV602 Basis 的 Source 欄位；Basis.Source 保存 TurnType 0／1／2。

## WinForms／Service／Core 行為

- 主 Form 初始化時呼叫 LoadINVSCRInBasis(State=0)，把結果按 SCRInNo 排序。UI 將 Basis.InputDate 改名為 ConfirmDate，欄位包含 SCRInNo、目標 InventoryNo、State、ConfirmDate、Description、FromInventoryNo、Creator、CreateDate。
- 點選單據先載入 Detail＋Component；Component 無資料時再載 Detail＋FailBin。資料依種類呈現；TurnType 0 是一般 Scrap Lot，無 Component／FailBin 子表。
- 新增時以 wsSYS.GetSCRInNo(ReserveSerialNo=True) 取號。目標庫房 Lookup 限 InventoryType=3，來源 WIP 半成品庫限 InventoryType=6。必填單號、來源與目標庫房，並至少選一筆來源。
- TurnType 0「線邊 WIP Scrap Lot」：來源 LoadWIP_Scrap，只列 BookingFlag=0 且 ScrapQty>0 Or LossQty>0；單據明細含 LotNo、LotSerial、OPNo、BaseLotNo、UnitNo、ScrapQty、LossQty。
- TurnType 1「WIP Component Scrap」：來源 LoadWIP_ComponentScrap，只列 BookingFlag=0 且 ScrapQty>0 Or GoodQty>0；Basis Detail 按 LotSerial 彙總，Component 子表逐列保存 ComponentNo、GoodQty、ScrapQty、UnitNo。編輯可載入本單已預約來源。
- TurnType 2「WIP FailBin」：來源 LoadWIP_FailBin，按 SYS Bin 的 BinOrder 動態顯示 FailBin 數量欄；Detail 為 Lot，FailBin 子表保存各 Bin 數量，總 ScrapQty 由 Bin 數量相加。編輯時也載入本單的來源列。
- 修改只允許 State=0；Def Form 將單號、目標庫房、來源庫房及 TurnType 鎖定，說明欄唯讀，只能調整已選來源列。新增／修改送 FromInventoryNo、ToInventoryNo、SCRInNo、Description、TurnType 及多筆來源資料。
- 刪除支援多選但只處理 State=0。Core 先將 Basis.State 設 -1，再依 TurnType 解除對應來源的 BookingFlag；Basis 與歷史 Detail／Component／FailBin 保留。Basis 作廢更新在來源解除的 CollectionSQL 執行前，失敗時可能留下已作廢但來源仍預約的部分狀態。多選由 Service 逐張呼叫，失敗可能部分完成。
- ExeSCRIn 是後續實際過帳：依 Basis 與 TurnType 把來源 Scrap／Component／FailBin 移入 SCR Inventory 並更新來源狀態。IV602 儲存草稿不等於庫存入帳；IV601 的 Source=40 排程也不等於下游已成功過帳。
- 舊 SQL 多處以字串串接單號、庫房、LotSerial。Component 編輯 Form 以 ComponentNo 搜尋，可能跨 LotSerial 撞到重複 ComponentNo，並存在用外層迴圈索引 drSel(i) 套回列的錯列風險；正式 API 應按完整鍵 (InventoryNo, LotSerial, ComponentNo) 綁定。

## 資料表與 Oracle metadata

- Basis：TBLINVSCRINBASIS，PK SCRInNo；State、Description、Creator、CreateDate、目標 InventoryNo、InputDate、Source、FromInventoryNo 等欄位。Source 為 TurnType。
- Detail：TBLINVSCRINDETAIL，PK (SCRInNo, LotSerial, Source)；保存 Lot／數量／單位、來源與日期。
- Component：TBLINVSCRINCOMPONENT，PK (SCRInNo, LotSerial, ComponentNo)。
- FailBin：TBLINVSCRINFAILBIN，PK (SCRInNo, LotSerial)，來源參考含 Bin1–Bin8 數量欄。
- 上述四表的唯讀 MESTEST source DDL／metadata 及 PostgreSQL CREATE-only 參考已收錄於 database/reference/mestest_wip_wp603_source_ddl.sql、database/reference/mestest_wip_wp603_create.sql（來源檔記載 2026-11-19 以 PowerShell 5.1 + Oracle.ManagedDataAccess + DBMS_METADATA／資料字典唯讀取得；無 Oracle 業務資料讀取或寫入）。本功能沿用既有參考，不新增表或臆測欄位。
- TBLINVSCRINVENTORY、Component、FailBin 是入庫目標讀寫表，屬 IV601 的 DDL 缺項；本桌機受保護 Oracle profile 目前不可用，沒有再查取或推測這三表的 DDL。

## Vue DEV

- App FunctionKey function:INV:SCR PRODUCT IN → /YMES/INV/ScrIn；入口僅 DEV 載入 InvScrInDevPreview.vue。
- 使用本機 DEV 假資料完成 State=0 草稿列表／單據選取與明細檢視、新增取號、單頭新增／修改、三種來源切換與勾選、BookingFlag 預約／解除、State=-1 作廢確認及 localStorage 持續保存。
- 編輯鎖定兩個庫房與 TurnType；Component Detail 按 LotSerial 彙總，FailBin 欄位依 DEV BinOrder 呈現。固定 BIN01–BIN03 僅是 DEV 資料，不代表正式 Bin 清單。
- 此 DEV 頁不呼叫正式 Service/API、不連 PostgreSQL、不做入庫過帳。確認及交易排程仍在 IV601 模擬。

## 家用端 API／schema handoff

- 對照 database/reference/mestest_wip_wp603_create.sql 和 PostgreSQL live schema／migration 後再決定是否需要 migration；不要因參考 CREATE 存在就重建既有表。確認四張單據表的型別、預設值、PK 與來源表複合鍵。
- 提供限量、穩定排序且需授權的 State=0 單據查詢，以及由 SCRInNo 限定的 Detail／Component／FailBin 讀取。不要暴露任意 AdditionalXml 條件。
- 來源 Lookup 必須驗證來源庫房 InventoryType=6、目標庫房 InventoryType=3；候選列由 TurnType 決定，強制 BookingFlag=0，編輯時只豁免該單目前持有的來源鍵。
- 新增／修改／作廢以單一資料庫交易鎖定單據及來源列，重驗 State、來源數量與 BookingFlag 後寫 Basis／子表並設定或釋放來源預約。API 從登入身分取 Creator，保護號碼保留的唯一性及並行預約；使用完整複合鍵，修正舊 ComponentNo-only 回選問題。
- 作廢以 State=-1 保留歷史，並原子解除正確來源表的 BookingFlag；重送要冪等。IV601 Source=40 command／worker 和 ExeSCRIn 過帳是獨立流程，需另做冪等、狀態轉移、併發鎖與失敗補償；不得把建立草稿回應當成已入帳。
- 正式 ExeSCRIn 會讀寫 IV601 所列的 SCR Inventory 三表。家用端必須先核 live PostgreSQL schema 與 IV601 缺失的可信來源 DDL，再實作過帳；不得套用 DEV BIN 欄位集。
