# IV307 在製貨架歷程查詢

更新日期：2026-11-25。公司端核對 WinForms／Service／Core 並完成 Vue DEV 假資料查詢；未連 YMES PostgreSQL、未實作正式 API/schema，Oracle MESTEST profile 不在本機，未執行即時 metadata 查詢。

## 功能與入口

- 選單 FunctionNo／功能代碼：`STOCKER HISTORY`／IV307；Form `frmIV_StockerHistory`，執行檔 `IV_StockerHistory.dll`。
- Vue DEV FunctionKey `function:INV:STOCKER HISTORY`，路由 `/YMES/INV/StockerHistory`，位於庫存管理／在製品庫。
- 只讀查詢 Stocker 上架／下架歷程；舊畫面沒有新增、刪除、匯出或單筆明細頁。

## WinForms 查詢流程與欄位

- 開啟 Form 不自動查詢；StockerNo、LotNo、CarrierNo 初始不勾選，TimeInterval 初始也不勾選。所有條件可全不選，按 Query 會查歷程全表。
- 起訖時間欄位初始顯示當日 07:30 至現在；如果目前早於 07:30，起始時間改為前一日 07:30。只有勾選 TimeInterval 才傳日期。兩個日期欄位為必填控制項但無 query 前的起訖順序驗證。
- StockerNo 透過 `LoadStockerNo` Lookup；Core 從 `TBLINVSTOCKERBASIS` `SELECT DISTINCT StockerNo`，不限定 IssueState，所以包含 basis 中非空的貨架。輸入非空 Stocker／Lot／Carrier 會自動勾選，取消勾選會清空條件；LotNo／CarrierNo 離開欄位時轉大寫。
- Query 條件：StockerNo exact、LotNo exact、CarrierNo exact；StartEventTime 使用 `CreateDate >= start`，EndEventTime 使用 `CreateDate <= end`。如果結束值恰為當日 00:00:00，Core 會展開到當日 23:59:59；其他時間則使用精確上限。
- Service 另支援解析 `LogGroupSerial`，但 Form 沒有欄位，也未送此參數；Core 中 LogGroupSerial 的 SQL 條件已註解，因此目前不生效。Service 也接收 XML `additional` 再交給 Core 附加條件。
- Core 從 `TBLINVSTOCKERDETAILLOG` LEFT JOIN `TBLWIPLOTSTATE`（LotNo）取得 OPNO。結果欄位包括 StockerNo、DesStockerNo、SrcLocatorNo、DesLocatorNo、ContentNo、ContentQty、OPNo、AreaNo、Status、Creator、CreateDate、LotNo、CarrierNo；Stocker／Locator／OPNo 為 `N/A` 時轉顯示空白。
- Form 有條件將回傳的 EVENTTIME 改名為 PROCESSDATE1，但目前 Core SELECT 使用 CreateDate，因此這個改名不影響實際欄位；結果按 CreateDate DESC 排序，Grid 以固定順序顯示上述 13 欄，CreateDate 格式 `yyyy/MM/dd HH:mm:ss`。
- `ContentQty` 沿用 IV305 Core 語意，是該格位上架內容列數的前／後數量，不是 Lot 的 CurQty；目前歷程表欄位名稱容易誤導。

## Vue DEV 復刻與舊程式限制

- `/YMES/INV/StockerHistory` DEV 預覽包含 Stocker Lookup、精確 Lot／Carrier、可選時間範圍、當班 07:30 起始日期預設和 13 欄歷程 Grid；未查詢前不顯示結果。
- 假資料展示 Lot／Carrier 的 IN／OUT、來源／目的格位、OPNo、ContentQty、Area、建立者與事件時間；列表按 CreateDate 新到舊排列，日期驗證阻擋 Start 晚於 End。所有假資料只存在頁面記憶體。
- 預設不勾 TimeInterval，DEV 將展示所有 fixtures，對應舊 UI 可無日期條件查全量。DEV 沒有為使用者預先套用日期，避免把畫面上未啟用的日期欄誤當成查詢條件。
- Core SQL 將 StockerNo／LotNo／CarrierNo／日期以字串組 SQL，無分頁／最大列數／最小條件；XML `additional` 可額外串入條件。無條件或廣日期區間可能載入龐大歷程。
- Core 對 Lot State 只按 LotNo LEFT JOIN；若 LotNo 在狀態表不是唯一，歷程可能重複。排序依賴 Form 客戶端而非 SQL 穩定排序，只有 CreateDate，等時間列順序未定。
- 舊畫面沒有防護 end before start，服務收到反向範圍後只照字面組合兩條條件而回空資料；DEV 加了使用者友善的順序提示，屬於前端防呆補強。
- 未 build、test 或 browser 驗收。

## 家用端 API handoff

- 提供登入及 `STOCKER HISTORY` Function ACL 保護的 read-only history endpoint，預設日期範圍與最大回傳筆數由 API 設定明確規定；不可把空條件直接展開成無限全表。
- 使用參數化 StockerNo／LotNo／CarrierNo exact filter、`CreatedAt >= start`／`<= end` 區間，拒絕起始晚於結束；如保留午夜日期查詢語意，應明確在 API 契約中轉換成半開區間 `[start, next day)`，不要依字串拼接 `23:59:59`。
- 穩定排序使用 CreateDate DESC 並附 LogGroupSerial／實際 PK 作 tie-breaker；以 cursor 或 page/pageSize 限制結果，回應包含 total／next cursor 等所需資訊。
- OPNO Join 必須核 live PostgreSQL 的 LotState 唯一鍵，避免只用 LotNo 造成重複；必要時以可定義的 Lot State current row 或 scalar lookup 取一筆。
- `LogGroupSerial` 若要供查詢需確認是唯一識別／群組識別後另定 API 欄位；不得宣稱舊程式已能過濾。不要接受任意 SQL/XML additional 條件。
- 使用已驗證 WP902 CREATE-only 參考對照 PostgreSQL live schema／migration，核複合鍵、時間精度、空字串及索引。Stocker Basis 尚無同版 Oracle DDL／metadata，不新增推測 migration；Lookup 若需包含空貨架，要以家用端核實後的 Basis／ACL API 提供。
