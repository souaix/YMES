# IV401 半成品庫庫房資料

更新日期：2026-11-25。公司端核對 WinForms／Service／Core，完成 Vue DEV 假資料查詢與選列明細；未連 YMES PostgreSQL，未實作正式 API/schema。Oracle MESTEST 受保護 profile 不在本機，未執行新 metadata 查詢。

## 功能與入口

- FunctionNo／功能代碼：`SEMI INVENTORY`／IV401；Form `frmINVSEMIInventory`，執行檔 `IV_SEMIInventory.dll`。
- Vue DEV FunctionKey `function:INV:SEMI INVENTORY`，路由 `/YMES/INV/SemiInventory`，位於庫存管理／半成品庫。
- 此頁查詢目前 SEMI Inventory 現況；按 SEMI In／SEMI Out 會開獨立確認 Form，真正交易不在 IV401 查詢頁內完成。

## Form 初始化與查詢

- Form Load 初始化兩個 Grid、先載入 Bin Basis，再呼叫 `LoadInventoryBasis` 傳 `InventoryType=2`；Service 預設 `IssueState=2`，所以 InventoryNo Lookup 只包含已核准半成品庫房。Form 開啟不會自動查 SEMI 庫存。
- InventoryNo 可由 Lookup 選取；選取新值立即查詢。文字欄按 Enter 也查詢，空字串不會執行查詢。舊畫面沒有可見 Query 按鈕；Designer 中 `Find` 按鈕隱藏。
- Core `LoadSEMIInventory` 查 `TBLINVSEMIINVENTORY`，條件固定 `InventoryNo IS NOT NULL AND LocQty > 0`；另可選傳 InventoryNo、LotNo、LocatorNo、ProductNo、UnitNo。IV401 只送 InventoryNo。左連 Product Basis 的 `ProductNo`，同時限制 `CurVersion=1`、`IssueState=2` 取得 ProductName。
- 主 Grid 顯示 ProductNo、ProductName、LocatorNo、LotNo、LocQty、UnitNo、BelongToTypeShow、BelongToNo、InputDate、SEMIInNo；舊標題將 ProductNo／ProductName 誤標為 `Product In No`／`Product In Name`。LocQty 使用最多 4 位小數顯示。
- Form 加入計算欄 `BelongToTypeShow`：只有 `BelongToType=0` 顯示 `MO`，其餘值皆為空白；不顯示原始 BelongToType 數字。

## 選列明細與交易入口

- 主列 AfterRowActivate 以 `(InventoryNo, LotNo, LocatorNo)` 呼叫 `LoadSEMIInventoryComponent`，不傳 BookingFlag，因此 Component loader 不限制 BookingFlag。Component Grid 只顯示 ComponentNo、GoodQty、ScrapQty、UnitNo，其餘欄隱藏。
- 若該庫存列沒有 Component rows，Form 才以 LotNo 呼叫 `wsWIP.LoadGoodBinState`。GoodBin State 查詢只用 LotNo；畫面先 `LoadBin`，依 BinOrder 排序，只顯示有在 Bin Basis 中定義且出現在 GoodBin row 的 Bin 欄，其他動態欄位隱藏。若無 Component／GoodBin row，Detail Grid 清空。
- SEMI In 按鈕開 `frmINVSEMIInConfirm`，SEMI Out 開 `frmINVSEMIOutConfirm`；確認 Dialog 關閉後若 `gReturnKeyValue` 非空，重新載入目前 InventoryNo。這些模組分別由 IV404／IV403 清冊功能承接；IV401 本身不直接執行寫入。
- Vue DEV 按選項會讀取該 InventoryNo 的假庫存，輸入值按 Enter 可精確查詢；選列時以完整 InventoryNo／LotNo／LocatorNo key 讀 Component，空 Component 才按 LotNo 顯示 GoodBin，依 BinOrder 呈現動態 Bin 欄。SEMI In／Out 按鈕顯示它們會進入獨立交易功能，不在本頁變更假庫存。
- DEV 僅用固定 fixture，全部存在頁面記憶體；未呼叫正式 API／資料庫，不會改變 LocQty、Component、GoodBin 或交易紀錄。未 build、test 或 browser 驗收。

## 舊程式限制與正式 API 規格

- InventoryNo、LotNo、LocatorNo、ProductNo、UnitNo 條件都以字串串接 SQL；API 必須用參數化查詢並以使用者可見 Inventory ACL 限定範圍。
- Core 主庫存固定 LocQty>0；若查無資料需回空清單，不可由 UI 自己補產品／Lot 狀態。
- Component Detail 已傳完整 `(InventoryNo, LotNo, LocatorNo)`；正式 API 應維持此父列 key，避免只用 LotNo 將其他 Inventory／Locator 的元件合併進來。BookingFlag 未被 IV401 傳入，不可默默只回未預約元件。
- GoodBin loader 依全域 LotNo 查詢。頁面只在該父列 Component 為空時呼叫；正式 API 仍需確認 Lot 授權及庫存 Lot 對應，再回傳 GoodBin，不能以任意 LotNo 擴大查詢。
- `TBLPRDPRODUCTBASIS` 的 ProductName 只取 current version 且 IssueState=2；若沒有符合資料，舊畫面可能顯示空白 ProductName，但仍顯示原 ProductNo。
- 結果無分頁或 row limit；即使由單一 InventoryNo 限定，也需 bounded paging。動態 Bin 欄應由核准 Bin Basis 決定並以 allowlist 回傳，不能將任意 DB 欄位名稱直接插入 UI/API。
- 入庫／出庫的命令及確認規則由 IV404／IV403 各自手冊決定；本頁按鈕只能導航，不可直接修改 SEMI Inventory。
